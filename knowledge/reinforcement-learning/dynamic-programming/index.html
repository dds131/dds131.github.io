动态规划（dynamic programming）在有限表格型、模型可枚举的设定下做精确期望 backup。它提供最清晰的压缩映射与策略改进分析，但不是唯一的已知模型方法，也不是唯一有收敛定理的 RL 方法；后续 MC、TD、Sarsa、Q-learning 在各自条件下同样有理论保证。

本页重点：精读策略评估的压缩证明、策略提升定理，以及“精确 PI”与“阈值截断实现”的边界。算法页同时固定联合转移—奖励分支、termination mask、标准 CliffWalking 合同和 Bellman residual 检查；这些条件决定证明能否落到代码。

本章要解决什么问题

上一页把机器人与环境的交互形式化成了马尔可夫决策过程，并写出了贝尔曼方程。但写出方程不等于解出方程。本章要回答的是最基础的一问：给定一个 MDP，怎么算出它的最优策略。

经典 value-based 方法常把 prediction 与 control 交错组织；后续还会出现直接策略优化、模型预测与分层决策等其他视角。本页先解决两个基础子问题：

  • 预测（prediction），也叫策略评估：给定策略 \(\pi\)，求它的状态价值 \(V^{\pi}\)。这是一个「测量」问题，不涉及改进。
  • 控制（control）：求最优策略 \(\pi^{*}\) 与最优价值 \(V^{*}\)。这是一个「优化」问题。

动态规划给出的答案是：把控制问题拆成「评估 + 改进」的循环，而每一次评估又是一个可以迭代求解的不动点问题。

为什么必须能查询环境模型

动态规划把 Bellman 右端作为可枚举的期望：

\[V^\pi(s) = \sum_a\pi(a\mid s) \sum_{s',r,d} p(s',r,d\mid s,a) \left[ r+\gamma(1-d)V^\pi(s') \right].\]

所以算法必须能枚举每个动作的全部后继分支、概率、即时奖励和真正终止标志。这里的奖励位于分支内；若先写 \(r(s,a)\)，必须明确它已经对 \((s',r)\) 取过条件期望。

维度 动态规划 MC / TD 样本方法

full backup 与 sample backup 的差别在“期望如何得到”，不是“DP 没有误差、TD 一定有偏”的无条件二分。对固定当前价值函数，单步转移可成为 Bellman backup 的条件无偏样本；但 bootstrap 目标本身又依赖当前估计。

动态规划是有限 MDP 精确规划的基础方法，不是唯一的 model-based 方法；线性规划、树搜索、MPC、Dyna 与学习模型后的规划也属于模型方法。

动态规划成立的两个结构性前提

动态规划这个名字来自 Bellman，它适用于同时满足两条性质的问题：

  • 最优子结构：全局最优解可以由子问题的最优解拼出来。在 MDP 里这一点由贝尔曼最优方程保证——最优价值满足「一步最优动作 + 后继状态的最优价值」的递归形式。
  • 重叠子问题：同一个子问题会被反复用到。在 MDP 里，同一个状态的价值会被它的所有前驱状态用到，因此用一张表把它存下来（表格型方法）就能避免重复计算。

这两条性质决定了本章方法的适用边界：状态数必须小到能开一张表。悬崖漫步的 48 个状态可以，围棋的状态数不可以。

形式化定义：分支模型与 Bellman 算子

完整任务合同见MDP 页。本页额外要求状态、动作有限，\(0\le\gamma<1\)，奖励有界，并能枚举

\[p(s',r,d\mid s,a),\]

其中 \(d=1\) 表示真正 termination。用零价值吸收态延拓时可省略显式 \(d\)，但必须与代码保持一种语义。

定义固定策略算子

\[(\mathcal T^\pi V)(s) = \sum_a\pi(a\mid s) \sum_{s',r,d} p(s',r,d\mid s,a) [r+\gamma(1-d)V(s')],\]

最优算子

\[(\mathcal T_*V)(s) = \max_a \sum_{s',r,d} p(s',r,d\mid s,a) [r+\gamma(1-d)V(s')].\]

\(V^\pi\) 与 \(V^*\) 分别是两个算子的唯一固定点。若写简化形式

\[r(s,a)+\gamma\sum_{s'}P(s'\mid s,a)V(s'),\]

则 \(r(s,a)\) 必须是与同一分支模型相容的条件期望奖励，且终止后的 continuation 已由模型处理。

度量与压缩前提

价值表空间使用 sup norm：

\[\|V-W\|_\infty = \max_s|V(s)-W(s)|.\]

在有限状态空间上该空间完备。概率加权不会放大 sup norm，而 bootstrap 项只保留 \(\gamma\) 倍差异，因此

\[\|\mathcal T^\pi V-\mathcal T^\pi W\|_\infty \le \gamma\|V-W\|_\infty,\] \[\|\mathcal T_* V-\mathcal T_* W\|_\infty \le \gamma\|V-W\|_\infty.\]

第二式还用到 \(|\max_a f_a-\max_a g_a| \le\max_a|f_a-g_a|.\) 后续收敛与误差界都依赖这些默认条件；有限时域、\(\gamma=1\) 或近似投影需要单独定理，不能直接套用。

重点一：策略评估的收敛性证明

策略评估要解决的是：给定策略 \(\pi\)，求 \(V^{\pi}\)。

为什么不直接解线性方程组

贝尔曼期望方程对固定的 \(\pi\) 是一组关于 \(V^{\pi}\) 的线性方程。写成矩阵形式，令 \(r^{\pi}\) 为分量是 \(\sum_a \pi(a \mid s) r(s,a)\) 的列向量，\(P^{\pi}\) 为分量是 \(\sum_a \pi(a \mid s) P(s' \mid s,a)\) 的转移矩阵，则

\[V^{\pi} = r^{\pi} + \gamma P^{\pi} V^{\pi} \quad \Longrightarrow \quad V^{\pi} = (I - \gamma P^{\pi})^{-1} r^{\pi}\]

矩阵 \(I - \gamma P^{\pi}\) 必然可逆：\(P^{\pi}\) 是随机矩阵，谱半径为 1，故 \(\gamma P^{\pi}\) 的特征值模长均不超过 \(\gamma < 1\)，1 不可能是它的特征值。所以解析解存在且唯一。

但求逆的代价是 \(O(\lvert \mathcal{S} \rvert^{3})\)。状态数上千时这条路就走不通了，何况策略迭代要反复做很多次评估。因此实践中一律改用迭代法。

迭代式

取任意初值 \(V_0\)（通常全零），反复作用贝尔曼期望算子：

\[V_{k+1}(s) \;=\; \sum_{a} \pi(a \mid s) \left[ r(s,a) + \gamma \sum_{s'} P(s' \mid s, a)\, V_{k}(s') \right]\]

写成算子形式就是 \(V_{k+1} = \mathcal{T}^{\pi} V_k\)。要证的命题是：无论 \(V_0\) 取什么，\(V_k\) 都收敛到 \(V^{\pi}\)，且收敛速度是以 \(\gamma\) 为公比的几何速率。

引理：贝尔曼期望算子是 \(\gamma\)-压缩

命题　对任意两张价值表 \(V_1, V_2\)，有

\[\lVert \mathcal{T}^{\pi} V_1 - \mathcal{T}^{\pi} V_2 \rVert_{\infty} \;\le\; \gamma \, \lVert V_1 - V_2 \rVert_{\infty}\]

证明　固定任意状态 \(s\)，直接展开算子的定义。注意 \(r(s,a)\) 这一项在两式中完全相同，相减时被消掉，这是第一步的关键：

\[(\mathcal{T}^{\pi} V_1)(s) - (\mathcal{T}^{\pi} V_2)(s) \;=\; \gamma \sum_{a} \pi(a \mid s) \sum_{s'} P(s' \mid s, a) \bigl[ V_1(s') - V_2(s') \bigr]\]

两边取绝对值，用三角不等式把绝对值移进求和号（这一步成立是因为 \(\pi(a \mid s) \ge 0\) 与 \(P(s' \mid s,a) \ge 0\)，权重非负，绝对值不会因为符号抵消而变大）：

\[\bigl\lvert (\mathcal{T}^{\pi} V_1)(s) - (\mathcal{T}^{\pi} V_2)(s) \bigr\rvert \;\le\; \gamma \sum_{a} \pi(a \mid s) \sum_{s'} P(s' \mid s, a) \bigl\lvert V_1(s') - V_2(s') \bigr\rvert\]

再把每一项的 \(\lvert V_1(s') - V_2(s') \rvert\) 放大成它在所有状态上的最大值，也就是无穷范数。放大之后被加权的量与求和变量无关，可以提到求和号外：

\[\bigl\lvert (\mathcal{T}^{\pi} V_1)(s) - (\mathcal{T}^{\pi} V_2)(s) \bigr\rvert \;\le\; \gamma \, \lVert V_1 - V_2 \rVert_{\infty} \sum_{a} \pi(a \mid s) \sum_{s'} P(s' \mid s, a)\]

最后用两处归一化：\(\sum_{s'} P(s' \mid s,a) = 1\)，以及 \(\sum_{a} \pi(a \mid s) = 1\)。双重求和整体等于 1，于是右端就是 \(\gamma \lVert V_1 - V_2 \rVert_{\infty}\)。由于 \(s\) 任取，对左端取 \(s\) 上的最大值即得命题。证毕。

这段证明里真正做功的只有三件事：奖励项相消（所以常数项不影响压缩性）、概率非负（所以三角不等式不损失结构）、概率归一（所以加权平均不会放大最大值）。收缩因子恰好等于 \(\gamma\)，一分不多一分不少——这解释了为什么 \(\gamma\) 越接近 1 收敛越慢，也解释了为什么 \(\gamma = 1\) 时这条证明彻底失效。

定理：迭代策略评估收敛到 \(V^{\pi}\)

由巴拿赫不动点定理，完备度量空间上的压缩映射有唯一不动点，且从任意初值出发的迭代序列收敛到它。这里 \((\mathbb{R}^{\lvert \mathcal{S} \rvert}, \lVert \cdot \rVert_{\infty})\) 完备（有限维赋范空间必完备），\(\mathcal{T}^{\pi}\) 是 \(\gamma\)-压缩，故：

  • \(\mathcal{T}^{\pi}\) 的不动点存在且唯一。而 \(V^{\pi}\) 按定义满足贝尔曼期望方程，即它是一个不动点，所以它就是那个唯一的不动点。这一步同时证明了「贝尔曼期望方程的解唯一」。
  • 迭代序列收敛到该不动点。

收敛速率可以显式写出来。反复用压缩性质：

\[\lVert V_k - V^{\pi} \rVert_{\infty} \;=\; \lVert \mathcal{T}^{\pi} V_{k-1} - \mathcal{T}^{\pi} V^{\pi} \rVert_{\infty} \;\le\; \gamma \lVert V_{k-1} - V^{\pi} \rVert_{\infty} \;\le\; \cdots \;\le\; \gamma^{k} \lVert V_0 - V^{\pi} \rVert_{\infty}\]

这就是几何收敛：误差每轮至少乘以 \(\gamma\)。要把误差压到 \(\varepsilon\) 以下，所需轮数是 \(O\bigl(\log(1/\varepsilon) / \log(1/\gamma)\bigr)\) 量级。\(\gamma = 0.9\) 时每轮误差乘 0.9，约 22 轮降一个数量级；\(\gamma = 0.99\) 时约 230 轮降一个数量级——这是折扣因子在计算代价上的直接体现。

停止条件与它的误差含义

代码里不可能知道 \(V^{\pi}\)，所以停止条件用相邻两轮的最大变化量：

\[\Delta_k \;=\; \lVert V_{k+1} - V_{k} \rVert_{\infty} \;<\; \theta\]

这个量与真实误差之间有一条可用的桥。由三角不等式与压缩性质，

\[\lVert V_{k+1} - V^{\pi} \rVert_{\infty} \;\le\; \sum_{i \ge 1} \lVert V_{k+i+1} - V_{k+i} \rVert_{\infty} \;\le\; \sum_{i \ge 1} \gamma^{i} \Delta_k \;=\; \frac{\gamma}{1 - \gamma}\, \Delta_k\]

所以 \(\Delta_k < \theta\) 只保证真实误差小于 \(\gamma\theta / (1-\gamma)\)，而不是小于 \(\theta\)。\(\gamma = 0.99\) 时这个放大倍数接近 100。把停止阈值直接当成精度用，是这一章最常见的误解。

重点二：策略提升定理的完整证明

评估解决了「这个策略有多好」，还差一步：怎么保证改出来的新策略确实不比旧的差。这就是策略提升定理，它是策略迭代能够单调上升的全部依据。

定理陈述

策略提升定理　设 \(\pi\) 与 \(\pi'\) 是两个策略（\(\pi'\) 取确定性策略即可，写成 \(\pi'(s)\) 表示它在状态 \(s\) 选的动作）。若对所有状态 \(s\) 都有

\[Q^{\pi}\bigl(s,\, \pi'(s)\bigr) \;\ge\; V^{\pi}(s)\]

则对所有状态 \(s\) 都有

\[V^{\pi'}(s) \;\ge\; V^{\pi}(s)\]

前提与结论的差别值得盯一眼：前提里的 \(Q^{\pi}\) 是只在第一步用 \(\pi'\)、之后仍按 \(\pi\) 走的价值；结论里的 \(V^{\pi'}\) 是从头到尾都按 \(\pi'\) 走的价值。定理说的是「只改第一步就不亏」能推出「一直改也不亏」，这正是它不平凡的地方。

证明

先把 \(Q^{\pi}\) 按定义展开成一步展开式：

\[Q^{\pi}\bigl(s, \pi'(s)\bigr) \;=\; \mathbb{E}\bigl[\, r_t + \gamma V^{\pi}(s_{t+1}) \;\big\vert\; s_t = s,\; a_t = \pi'(s) \,\bigr]\]

把前提代进去，得到第一个不等式：

\[V^{\pi}(s) \;\le\; \mathbb{E}_{\pi'}\bigl[\, r_t + \gamma V^{\pi}(s_{t+1}) \;\big\vert\; s_t = s \,\bigr]\]

下标 \(\pi'\) 表示动作由 \(\pi'\) 选出。关键一步：前提对所有状态成立，所以它对下一时刻的状态 \(s_{t+1}\) 同样成立，即 \(V^{\pi}(s_{t+1}) \le Q^{\pi}\bigl(s_{t+1}, \pi'(s_{t+1})\bigr)\)。把这个不等式代入右端的 \(V^{\pi}(s_{t+1})\)。代入是合法的，因为 \(\gamma > 0\)，乘一个正数不改变不等号方向；而期望是非负加权和，逐点的不等式取期望后仍成立（期望的单调性）：

\[V^{\pi}(s) \;\le\; \mathbb{E}_{\pi'}\bigl[\, r_t + \gamma\, Q^{\pi}\bigl(s_{t+1}, \pi'(s_{t+1})\bigr) \;\big\vert\; s_t = s \,\bigr]\]

再把里层的 \(Q^{\pi}\) 按同样的一步展开式打开，并用全期望公式把两层期望合并成一层（两层的动作都由 \(\pi'\) 选，转移都由环境给，所以合并后就是沿 \(\pi'\) 走两步的期望）：

\[V^{\pi}(s) \;\le\; \mathbb{E}_{\pi'}\bigl[\, r_t + \gamma r_{t+1} + \gamma^{2} V^{\pi}(s_{t+2}) \;\big\vert\; s_t = s \,\bigr]\]

这一步与上一步的结构完全相同，因此可以无限重复。重复 \(n\) 次后得到

\[V^{\pi}(s) \;\le\; \mathbb{E}_{\pi'}\left[\, \sum_{k=0}^{n-1} \gamma^{k} r_{t+k} \;+\; \gamma^{n} V^{\pi}(s_{t+n}) \;\bigg\vert\; s_t = s \,\right]\]

最后取 \(n \to \infty\)。这里需要交代两件事，否则极限过程站不住：

  • 余项消失。奖励有界（\(\lvert r \rvert \le R_{\max}\)）时，任何策略的价值也有界，\(\lvert V^{\pi} \rvert \le R_{\max}/(1-\gamma)\)。于是 \(\lvert \gamma^{n} V^{\pi}(s_{t+n}) \rvert \le \gamma^{n} R_{\max}/(1-\gamma) \to 0\)。这里第二次用到 \(\gamma < 1\)，与压缩性质用的是同一个条件。
  • 求和项收敛。\(\sum_{k} \gamma^{k} r_{t+k}\) 被 \(R_{\max}/(1-\gamma)\) 一致控制，可以用控制收敛定理把极限移进期望号。

取极限后右端恰好是「从 \(s\) 出发一直按 \(\pi'\) 走」的折扣回报期望，也就是 \(V^{\pi'}(s)\)：

\[V^{\pi}(s) \;\le\; \mathbb{E}_{\pi'}\left[\, \sum_{k=0}^{\infty} \gamma^{k} r_{t+k} \;\bigg\vert\; s_t = s \,\right] \;=\; V^{\pi'}(s)\]

证毕。

整段证明其实只是把同一条前提沿着时间轴反复往后代：每代入一次，就把「按 \(\pi'\) 走」的时间往后延长一步，同时把「按 \(\pi\) 走」的部分往后推一步。\(\gamma\) 严格小于 1 保证被推到无穷远的那部分权重趋于零，于是「只改第一步」的局部改进累积成了「全程都改」的全局改进。

贪婪策略满足前提

定理只是说「若前提成立则结论成立」，还需要构造一个一定满足前提的 \(\pi'\)。取对 \(Q^{\pi}\) 的贪婪策略：

\[\pi'(s) \;=\; \arg\max_{a \in \mathcal{A}} Q^{\pi}(s, a)\]

它满足前提，因为最大值不小于任何加权平均：

\[Q^{\pi}\bigl(s, \pi'(s)\bigr) \;=\; \max_{a} Q^{\pi}(s,a) \;\ge\; \sum_{a} \pi(a \mid s)\, Q^{\pi}(s,a) \;=\; V^{\pi}(s)\]

最后一个等号就是 \(V\) 与 \(Q\) 的关系式。所以贪婪化永远不会让策略变差，这是策略迭代每一轮都敢直接取 max 的依据。

什么时候停：精确评估下的结论

若当前策略 \(\pi\) 对自己的精确价值 \(V^\pi\) 已经贪婪，则

\[\mathcal T^\pi V^\pi = \mathcal T_*V^\pi = V^\pi.\]

所以 \(V^\pi\) 是最优算子的固定点；由唯一性，\(V^\pi=V^*\)。注意“策略不变”可推出价值不变，反向不成立：多个策略可能因动作平局而具有相同价值。

经典有限终止结论还要求每轮得到精确 \(V^\pi\)，并使用固定的确定性 tie rule。此时策略若改变就严格改进，有限个确定性策略不可能无限重复。

本页代码按 \(\Delta<\theta\) 提前停止评估，属于 iterative/modified policy iteration。它得到的是 \(\hat V^\pi\)，不自动继承精确策略迭代的有限终止和单调改进保证；必须结合评估误差、action gap 与稳定容差验证。

策略迭代与价值迭代：算法流程与对比

前两节证明了两块地基：评估一定收敛，贪婪化一定不变差。把它们交替起来就是策略迭代。

伪代码如下，方括号内为对应的公式。

输入: 转移概率 P, 奖励 r, 折扣 gamma, 收敛阈值 theta

1  初始化 V(s) <- 0 对所有 s
2  初始化 pi(a|s) <- 1/|A| 对所有 s, a          # 均匀随机策略
3  repeat
4      # ---- 策略评估：解 V^pi ----
5      repeat
6          delta <- 0
7          for 每个状态 s do
8              v_old <- V(s)
9              对每个动作 a 计算 Q(s,a) <- r(s,a) + gamma * sum_{s'} P(s'|s,a) V(s')
10             V_new(s) <- sum_a pi(a|s) * Q(s,a)                # 贝尔曼期望算子
11             delta <- max(delta, |V_new(s) - v_old|)
12         end for
13         V <- V_new                                            # 同步更新
14     until delta < theta
15     # ---- 策略提升：贪婪化 ----
16     pi_old <- pi
17     for 每个状态 s do
18         对每个动作 a 重新计算 Q(s,a)
19         pi(.|s) <- 在 argmax_a Q(s,a) 上均匀分布       # 平局时全部保留
20     end for
21 until pi == pi_old                                            # 策略不再变化
22 返回 V, pi

第 13 行的「同步更新」是一个可选设计：先把整轮的新值算完再整体替换（Jacobi 式），还是算一个换一个（Gauss-Seidel 式，就地更新）。两者都收敛，就地更新通常更快，因为后面的状态用上了本轮刚更新的值；但就地更新的结果依赖状态遍历顺序，复现时要注意。

价值迭代：把策略评估截断为一步

策略迭代的代价集中在内层：每做一次策略提升，就要把策略评估跑到收敛。但直觉上这很浪费——评估到一半时贪婪策略往往就已经定型了，把剩下的几十轮跑完只是在精修一个马上要被替换掉的价值表。

价值迭代把这个直觉推到极端：每轮策略评估只做一次扫描，然后立刻贪婪化。把「一次评估扫描 + 一次贪婪化」合并写成一个式子，就是

\[V_{k+1}(s) \;=\; \max_{a \in \mathcal{A}} \left[ r(s,a) + \gamma \sum_{s'} P(s' \mid s, a)\, V_{k}(s') \right]\]

也就是 \(V_{k+1} = \mathcal{T}^{*} V_k\)：直接迭代贝尔曼最优方程，中途根本不显式维护策略。策略只在最后收敛时提取一次。

价值迭代直接反复应用 \(\mathcal T_*\)，可在广义策略迭代视角下理解为“评估与改进高度交错”的端点。它与“一轮近似评估后检查策略稳定”的代码流程相关，但不能把精确策略迭代简单设 \(m=1\) 就无条件得到同一个终止逻辑。

收敛性同样由压缩映射保证，只需补证 \(\mathcal{T}^{*}\) 也是 \(\gamma\)-压缩。相比期望算子，这里多用一条关于最大值的不等式：

\[\left\lvert \max_{a} f(a) - \max_{a} g(a) \right\rvert \;\le\; \max_{a} \bigl\lvert f(a) - g(a) \bigr\rvert\]

它的证明只有两行：设 \(a_1\) 是 \(f\) 的最大点，则 \(\max_a f - \max_a g \le f(a_1) - g(a_1) \le \max_a \lvert f - g \rvert\)；把 \(f\) 与 \(g\) 互换得到另一侧。有了它，对固定的 \(s\) 把 \(\mathcal{T}^{*}V_1\) 与 \(\mathcal{T}^{*}V_2\) 相减，奖励项照样相消，剩下的部分与上一节的推导逐字相同，最终得到

\[\lVert \mathcal{T}^{*} V_1 - \mathcal{T}^{*} V_2 \rVert_{\infty} \;\le\; \gamma \, \lVert V_1 - V_2 \rVert_{\infty}\]

于是 \(V_k \to V^{*}\)，误差仍以 \(\gamma^{k}\) 的速率下降。注意价值迭代的中间量 \(V_k\) 一般不是任何策略的真实价值，它只是收敛路上的一张表，这一点与策略迭代不同。

还有一条实用结论：若停止时 \(\lVert V_{k+1} - V_{k} \rVert_{\infty} < \theta\)，则贪婪提取出的策略 \(\pi_k\) 满足

\[\lVert V^{\pi_k} - V^{*} \rVert_{\infty} \;\le\; \frac{2\gamma}{1 - \gamma}\, \lVert V_{k+1} - V_{k} \rVert_{\infty}\]

也就是说价值表的误差会以 \(2\gamma/(1-\gamma)\) 的倍数传导到策略性能上。\(\gamma\) 越大，同样的阈值换来的策略质量保证越弱。

两者的对比

维度 策略迭代 价值迭代
外层轮数 少，通常个位数到十几轮 多，与价值传播所需的步数同量级
每轮代价 高，内层要把评估跑到收敛 低，只做一次扫描
单次扫描的复杂度 \(O(\lvert \mathcal{S} \rvert^2 \lvert \mathcal{A} \rvert)\) 与左列相同
中间量的含义 每轮结束时 \(V\) 是某个真实策略的价值 中间的 \(V\) 一般不对应任何策略
终止性质 精确 PI 在固定 tie rule 下有限终止；阈值版本需额外验证 价值表渐近收敛，工程上按 residual/阈值停止
是否显式维护策略 是，每轮都更新 \(\pi\) 否，收敛后一次性提取
何时更划算 动作数多、评估收敛快 状态数大、只关心最优价值

两者都属于广义策略迭代（generalized policy iteration）的思想：价值估计与策略改进以不同频率交错。固定做若干评估扫描的 modified policy iteration 位于两端之间；\(m=1\) 与价值迭代在特定更新安排下关系紧密，但停止条件和中间策略语义仍要明确。Actor-Critic 则把这一思想推广到采样与函数逼近场景。

策略评估：把压缩映射写成代码

class PolicyIteration:
    """策略迭代。P 为转移表，格式同 Gymnasium toy_text。"""

    def __init__(self, P, n_state, n_action, gamma=0.9, theta=1e-5):
        self.P, self.n_state, self.n_action = P, n_state, n_action
        self.gamma, self.theta = gamma, theta
        self.v = np.zeros(n_state)                            # 价值表 V，初值全零
        self.pi = np.ones((n_state, n_action)) / n_action     # 均匀随机策略
        self.eval_sweeps = 0          # 累计策略评估扫描次数
        self.improve_rounds = 0       # 累计策略提升轮数

    def _q_values(self, s):
        """对状态 s 算出所有动作的 Q(s, a)，即贝尔曼算子方括号里的那一项。"""
        q = np.zeros(self.n_action)
        for a in range(self.n_action):
            for prob, ns, r, terminated in self.P[s][a]:
                # (1 - terminated) 把终止之后的回报置零，对应公式里的截断
                q[a] += prob * (r + self.gamma * self.v[ns] * (1.0 - float(terminated)))
        return q

    def policy_evaluation(self):
        while True:
            delta = 0.0
            new_v = np.zeros(self.n_state)
            for s in range(self.n_state):
                q = self._q_values(s)
                new_v[s] = np.dot(self.pi[s], q)              # 按 pi 加权：贝尔曼期望算子
                delta = max(delta, abs(new_v[s] - self.v[s]))
            self.v = new_v                                    # 同步更新（Jacobi 式）
            self.eval_sweeps += 1
            if delta < self.theta:                            # 停止条件
                break

逐项对照前面的公式：

  • _q_values 里的 r + gamma * v[ns] 对应贝尔曼算子方括号内的 \(r(s,a) + \gamma \sum_{s'} P(s'\mid s,a) V(s')\)，外层的 for prob, ns, ... 循环就是对 \(s'\) 求和，prob 就是 \(P(s' \mid s,a)\)。确定性环境下这个内层循环只有一项，但写成循环才能兼容随机环境。
  • np.dot(self.pi[s], q) 对应 \(\sum_a \pi(a \mid s) Q(s,a)\)，也就是把 \(Q\) 按策略加权成 \(V\)。整个 policy_evaluation 的一次外层 while 迭代，就是把算子 \(\mathcal{T}^{\pi}\) 作用一次。
  • delta 记录的是 \(\lVert V_{k+1} - V_k \rVert_{\infty}\)，正是收敛性证明里用到的无穷范数。它单调趋零由压缩性质保证。

三处常见错误：其一，无意中混用同步与就地更新。其二，屏蔽了 terminal transition 的即时奖励；正确做法是始终保留 reward_next，只把终止后的 bootstrap 置零。truncated 通常仍要 bootstrap。其三，把 theta 当成真实价值误差；它只是相邻扫描差，必须通过残差界换算。

策略提升与外层循环

    def policy_improvement(self):
        new_pi = np.zeros_like(self.pi)
        for s in range(self.n_state):
            q = self._q_values(s)
            best = int(np.argmax(q))              # 固定的最小索引 tie-break
            new_pi[s, best] = 1.0
        stable = np.array_equal(new_pi, self.pi)
        self.pi = new_pi
        self.improve_rounds += 1
        return stable

    def run(self):
        while True:
            self.policy_evaluation()              # 内层：解 V^pi
            if self.policy_improvement():         # 外层：贪婪化
                break
        return self.v, self.pi

policy_improvement 就是 \(\pi'(s) = \arg\max_a Q^{\pi}(s,a)\) 的直接实现，返回值 stable 对应上一节证明的终止条件。两个细节：

算法内部使用固定的最小索引 tie-break，使策略是 one-hot 数组并可做精确稳定性比较。若可视化需要展示所有近似最优动作，应在展示层用声明过容差的 np.isclose 另算 action set，不要让显示容差改变算法终止条件。

价值迭代：只改一行

class ValueIteration(PolicyIteration):
    """价值迭代。与策略迭代共用 _q_values，差别只在于每轮取 max 而不是按 pi 加权。"""

    def run(self):
        while True:
            delta = 0.0
            new_v = np.zeros(self.n_state)
            for s in range(self.n_state):
                new_v[s] = self._q_values(s).max()          # 唯一的差别：max 取代加权求和
                delta = max(delta, abs(new_v[s] - self.v[s]))
            self.v = new_v
            self.eval_sweeps += 1
            if delta < self.theta:
                break
        for s in range(self.n_state):                       # 收敛后一次性提取贪婪策略
            q = self._q_values(s)
            best = int(np.argmax(q))
            self.pi[s, best] = 1.0
        self.improve_rounds = 1
        return self.v, self.pi

把这段与 policy_evaluation 并排看，差别只有一行：np.dot(self.pi[s], q) 换成 q.max()。这正是前面「价值迭代是策略评估轮数取 1 的策略迭代」这句话在代码里的样子——贪婪策略把概率全压在最大动作上，加权求和退化成取最大，于是策略变量在循环里彻底消失，只在最后提取一次。

注意最后的提取步骤不能省。循环中的 self.pi 一直是构造函数里的均匀随机策略，与 self.v 毫无关系；忘记提取就会打印出一张与最优价值不匹配的随机策略，这是复现时最常见的一处错。

打印与主程序

打印函数只负责展示；标准 CliffWalking 的悬崖格不是 terminal state，但可作为特殊格标成 ####，目标格标成 GOAL。

def print_agent(agent, nrow, ncol, action_chars, special_states=(), goal_states=()):
    print("状态价值：")
    for y in range(nrow):
        print("".join(f"{agent.v[y * ncol + x]:7.3f}" for x in range(ncol)))
    print("策略：")
    for y in range(nrow):
        line = []
        for x in range(ncol):
            s = y * ncol + x
            if s in goal_states:
                line.append("GOAL")
            elif s in special_states:
                line.append("####")
            else:
                line.append("".join(action_chars[a] if agent.pi[s][a] > 0 else "o"
                                    for a in range(len(action_chars))))
        print(" ".join(line))

实验与验证：先验证合同，再比较算法

标准 CliffWalking 的最小夹具

同一任务上的 DP、Sarsa、Q-learning 与 Dyna-Q 必须共享以下断言：

  • start + right：奖励 \(-100\)、回到 start、terminated=False；
  • 只有进入 goal 才 terminated=True；
  • 动作编号为上、右、下、左；
  • 训练时若另加外部步数上限，该事件记为 truncated，不改变原 MDP 的 termination；
  • 评估指标同时报告 episode return、到达 goal 的步数、跌崖次数与成功率。

这组合同不通过时，不应比较页面间的路径或回报。

DP 求解器的数值断言

价值迭代结束后，不依赖预先抄写的价值表，而直接检查最优 Bellman residual：

def optimality_residual(agent) -> float:
    backed_up = np.array(
        [agent._q_values(s).max() for s in range(agent.n_state)]
    )
    return float(np.max(np.abs(backed_up - agent.v)))


assert optimality_residual(vi_agent) <= 1e-4

截断评估的策略迭代实现还应单独计算当前策略的 Bellman residual，并验证最终贪婪策略在声明容差内与价值迭代一致。两者的扫描数可以比较，但必须同时报告 \(\theta\)、同步/就地更新、tie rule 与任务版本。

与原书 Sarsa/Q-learning 对照的边界

标准环境的最优策略倾向走最短、贴近悬崖的路径；这可作为 Q-learning greedy evaluation 的理论参照。Sarsa 在固定 \(\epsilon\) 行为策略下可能学到更安全路线，是因为它评估包含探索动作的行为，而不是环境换了规则。

这一结论必须在同一环境合同、相同动作编号和独立 greedy evaluation 下验证。训练期回报包含探索代价，不能与 DP 的最优价值直接混成同一个数字。

随机转移对照

FrozenLake 可用于验证 full backup 会对所有分支及其奖励求期望。使用 env.unwrapped.P 时仍要逐分支读取 reward_next 与 terminated；目标转移的 \(+1\) 必须保留，只把终止后的 continuation value 清零。它与 CliffWalking 的动作编号、奖励和终止集合不同，不能复用字符表或硬编码状态而不注明地图版本。

任何“算法 A 扫描若干轮、算法 B 更快”的数值都应来自实际运行产物并随代码保存；本页只保留可复核断言，不发布未由当前代码生成的固定结果表。统计性实验的记录格式见评估与可复现页。

关键参数配置与原因

本章的参数很少，但每一个都直接连着前面的证明。

折扣因子 gamma

  • 取值：本页取 0.9。表格型任务常用 0.9–0.99，必须严格小于 1。
  • 为什么：\(\gamma\) 在本章身兼三职。一是保证无限时域求和收敛；二是它就是压缩因子，误差每轮乘 \(\gamma\)，所以它同时决定了算法要跑多少轮；三是它出现在两条误差界 \(\gamma/(1-\gamma)\) 与 \(2\gamma/(1-\gamma)\) 里，决定停止阈值能换来多强的保证。取 0.9 时误差约 22 轮降一个数量级，在 48 个状态上很快；取 0.99 则要 230 轮左右。
  • 配错了会怎样：在本页的无限时域压缩证明中，\(\gamma=1\) 不满足压缩条件；但有限 episodic 或 proper policy 的无折扣问题可用其他定理处理，不能一概说价值必然发散。较小 \(\gamma\) 会压缩远期差异、可能改变一般任务的最优策略；在标准 CliffWalking 中，任何有限安全到达路径仍优于每步 \(-1\) 的无限拖延，不能声称 \(\gamma=0.5\) 会让最优策略不再朝目标前进。

收敛阈值 theta

  • 取值：本页取 \(10^{-5}\)。
  • 为什么：它控制的是相邻两轮价值表的最大变化量 \(\lVert V_{k+1} - V_k \rVert_{\infty}\)，而不是与真值的距离。由前面证过的界，真实误差可能是它的 \(\gamma/(1-\gamma)\) 倍；\(\gamma = 0.9\) 时是 9 倍，\(\gamma = 0.99\) 时接近 100 倍。所以 \(\theta\) 要按 \(\gamma\) 一起选，\(\gamma\) 越大 \(\theta\) 要越小。
  • 配错了会怎样：取得过大（例如 0.1）时，评估远未收敛就退出，策略提升拿到的是一张不准的 \(Q\) 表，贪婪化可能选错动作，策略迭代的单调上升性质在实践上被破坏，外层循环可能在两个策略之间来回震荡而不终止。取得过小（例如 \(10^{-12}\)）时，扫描次数大幅增加而策略早已不再变化，纯属浪费；浮点精度到底时甚至永远达不到阈值。

初始价值表

  • 取值：全零。
  • 为什么：压缩映射定理保证从任意初值出发都收敛到同一个不动点，所以初值不影响正确性，只影响收敛快慢。全零最简单，且在本章的负奖励环境里它天然是一个乐观初值（真实价值都是负的），有利于价值从目标处向外传播。
  • 配错了会怎样：初值离真值越远，需要的轮数越多，因为误差是从 \(\lVert V_0 - V^{\pi} \rVert_{\infty}\) 开始按 \(\gamma^{k}\) 衰减的。若把终止格的初值设成非零，而代码里又漏了 (1 - terminated) 因子，这个非零值会被永久保留并污染所有邻格——这是初值与实现细节耦合出错的典型情形。

同步更新与就地更新

  • 取值：本页用同步更新（先算完整轮再整体替换）。
  • 为什么：同步更新与本页公式逐字对应，\(V_{k+1} = \mathcal{T}^{\pi}V_k\) 里的右端全部取自第 \(k\) 轮，因此结果与状态遍历顺序无关，便于复现与验算。
  • 配错了会怎样：改成就地更新后算法仍然收敛（且通常更快，因为后面的状态用上了本轮刚更新的值），但迭代序列不再是 \(\mathcal{T}^{\pi}\) 的幂次，中间轮的数字与本页对不上；更麻烦的是结果依赖遍历顺序，换一个顺序数字就变，排查问题时容易误判成 bug。若在同一个循环里一半状态用新值、一半用旧值（例如把 new_v 和 self.v 写混），则两种语义混杂，行为不可预测。

策略评估的轮数

  • 取值：策略迭代取「跑到 \(\Delta < \theta\)」，价值迭代取 1。
  • 为什么：这个数就是广义策略迭代里的 \(m\)。\(m\) 大则每轮策略更准、外层轮数少；\(m\) 小则每轮便宜、外层轮数多。两个极端各自的代价在前面的对比表里。
  • 配错了会怎样：评估扫描过多会浪费计算；过少时，基于近似 \(\hat V^\pi\) 的贪婪动作可能在小 action gap 上翻转。此时不能沿用精确 PI 的“策略稳定即最优”证明，应监控 Bellman residual、设置最大外层轮数，并采用固定 tie rule。

平局处理与终止判定

  • 取值：保留全部取到最大值的动作，概率均分；终止判定用 np.allclose。
  • 为什么：悬崖漫步的上两行普遍存在两个等价最优动作，保留全部才能看出「向下与向右等价」这一结构。终止判定比较的是浮点数组，必须容忍误差。
  • 配错了会怎样：只取 np.argmax 时，等价动作被固定偏好掩盖，打印出的策略看不出等价路径；更隐蔽的是，当两个动作的 \(Q\) 值因评估误差在极小范围内互换大小时，argmax 会跟着翻转，导致「策略不变」永远不成立。用 == 严格比较浮点策略数组也会引发同样的不终止问题。

小结与下一章的衔接

本章可以压缩成四句话：

  • 把贝尔曼方程看成算子，求解 MDP 就变成了求算子的不动点。
  • 贝尔曼期望算子与贝尔曼最优算子都是无穷范数下的 \(\gamma\)-压缩，因此不动点唯一、迭代必然收敛，误差以 \(\gamma^{k}\) 的速率下降。
  • 策略提升定理保证贪婪化不会让策略变差；配上策略数有限，策略迭代在有限步内终止于最优。
  • 价值迭代是把策略评估截断为一步的特例，两者是广义策略迭代这一族的两个端点。

本章方法的两条硬边界

  • 必须已知模型。每次更新都要遍历 \(P(s' \mid s,a)\) 的全部条目，而真实机器人上拿不到这张表。绕开的办法是用采样代替求和，即蒙特卡洛与时序差分。
  • 状态数必须可枚举。每轮扫描的代价是 \(O(\lvert \mathcal{S} \rvert^{2} \lvert \mathcal{A} \rvert)\)，状态空间维度一高就爆炸。绕开的办法是用函数逼近代替表格，即 DQN 及其之后的所有深度方法。

两条边界分别指向后面两个方向。去掉模型假设的直接后果是：期望不能再算，只能采样估计；而一旦改用采样，「一次更新看到全部后继状态」就退化成「一次更新只看到实际走到的那一个后继状态」，随之而来的是采样方差，以及蒙特卡洛与时序差分之间的偏差-方差权衡。

去掉表格假设的后果更重：价值不再是一张可以逐格更新的表，而是一个带参数的函数，压缩映射的证明在函数逼近下不再成立（投影步骤会破坏收缩性），这就是深度强化学习里训练不稳定的根源之一。

下一章要做的事

下一步应先读蒙特卡洛方法，理解“不用模型、完整回报、不 bootstrap”；随后进入时序差分，把完整回报换成一步或多步 sample backup。TD 仍保留表格表示时，其一步形式为

\[V(s) \;\leftarrow\; \sum_{a} \pi(a \mid s)\left[ r(s,a) + \gamma \sum_{s'} P(s' \mid s,a) V(s') \right]\]

换成一次真实交互的采样形式

\[V(s) \;\leftarrow\; V(s) + \alpha \bigl[\, r + \gamma V(s') - V(s) \,\bigr]\]

两处变化一目了然：求和号变成了单个采样，直接赋值变成了带学习率 \(\alpha\) 的增量更新。方括号里的量就是时序差分误差，它是后面 Sarsa、Q-learning、DQN 乃至 Actor-Critic 的共同核心。届时会用本章在悬崖漫步上算出的这张最优价值表，去对照两个无模型算法各自学到了什么。

若想保留模型带来的样本效率、又不要求模型事先已知，可以看Dyna-Q：它一边与环境交互一边学一个模型，再用学到的模型做本章这样的规划更新。函数逼近这一条线则从DQN开始。整条主线的脉络见强化学习总览。
