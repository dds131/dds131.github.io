DDPG 的一次学习更新不是一个联合 loss 的单次反向传播，而是三个不同操作： 先把 Critic 拉向缓慢变化的 Bellman target，再把 Actor 沿当前 Critic 的动作梯度上推， 最后把两个 target 向在线网络移动一小步。三步的参数集合、梯度边界和时间尺度都不同。

本页重点。第二节的终止掩码、第三节的半梯度、第四节的 Actor 负号、 第六节的 Polyak 两套记号，以及第七节彼此独立的训练调度量。网络与张量形状见 子页 ②； 可复制代码见 子页 ⑤。

一、一条 transition 的准确语义

现代 Gymnasium 中，调用 env.step(a_t) 返回

\[\left(s_{t+1},r_t, \mathrm{terminated}_t, \mathrm{truncated}_t, \mathrm{info}_t\right).\]

ReplayBuffer 再把调用前后的信息组织成 transition

\[\left(s_t,a_t,r_t,s_{t+1}, \mathrm{terminated}_t, \mathrm{truncated}_t\right).\]
  • terminated：到达 MDP 定义的终止状态，如任务成功、失败或机器人倒下。
  • truncated：由 MDP 外部条件中止，如包装器的最大交互步数。
  • episode 重置条件通常是二者的或；bootstrap 屏蔽条件却不能不加区分地使用二者的或。

若时间限制本身属于有限时域 MDP，剩余时间应进入观测，时间耗尽可以是终止； 若只是为了控制采样长度的外部 TimeLimit，截断后的真实状态仍有未来价值，应保留 bootstrap。

“是否重置环境”与“是否令 target 停止 bootstrap”是两个问题。 外部截断要求重置采样器，但通常不应把未来价值强制设为 0。

二、Bellman target：用两个目标网络定义缓慢标签

2.1 下一动作

\[a'=\mu_{\bar\theta}(s').\]

下一动作来自目标 Actor，而不是 replay 中下一步曾执行的行为动作，也不是带探索噪声的动作。 DDPG 学的是确定性目标策略的 Q，因此 target 中查询目标策略本身。

2.2 下一动作的价值

\[q'=Q_{\bar\phi}(s',a').\]

目标 Critic 与目标 Actor 同时位于 no-grad 区域。它们的输出参与数值计算， 参数不接收本次 loss 的梯度。

2.3 终止掩码

令

\[m_{\mathrm{term}} = \mathbb 1\{\mathrm{terminated}\}.\]

一步 target 为

\[y = r+\gamma(1-m_{\mathrm{term}}) Q_{\bar\phi} \left( s',\mu_{\bar\theta}(s') \right). \tag{1}\]

当真正终止时，\(m_{\mathrm{term}}=1\)，target 只剩即时奖励；外部截断时 \(m_{\mathrm{term}}=0\)，使用最终观测继续 bootstrap。 数学上 \(m_{\mathrm{term}}\) 是 0/1 数值掩码；若实现保存的是布尔张量，应先显式转成 浮点类型再计算 \(1-m_{\mathrm{term}}\)，不要假设所有张量库都允许对 bool 直接做减法。

2.4 常见错误

# 错误：把任何 episode 结束都当成 MDP 终止
done = terminated or truncated
target = reward + gamma * (1.0 - done) * next_q

# 正确的通用外部 TimeLimit 口径
target = reward + gamma * (1.0 - terminated) * next_q

向量环境还要保存截断时的真实 final observation；若 wrapper 在返回时已经把 next_obs 替换成 reset 后的新回合初始状态，拿它 bootstrap 会跨回合串接价值。

三、Critic：固定 target 的半梯度回归

3.1 损失

\[L_Q(\phi) = \mathbb E_{\mathcal D} \left[ \left( Q_\phi(s,a)-y \right)^2 \right]. \tag{2}\]

实现用 mini-batch 平均。当前 Q 使用 replay 中实际执行动作 \(a\)； target \(y\) 由式 (1) 计算并视为常量。

3.2 为什么叫半梯度

“半梯度”表示更新在线 Critic 时把 bootstrap target 当作固定标签，只对当前估计 \(Q_\phi(s,a)\) 求导。在 DDPG 中，\(y\) 使用独立参数 \(\bar\theta,\bar\phi\)， 因此它本来就不依赖本次被更新的在线参数 \(\phi\)：

\[\frac{\partial y}{\partial\phi}=0.\]

no_grad 的作用是避免为目标参数构图和累积无用梯度，并明确目标参数不由本损失优化。 如果改用同一个在线 Q 同时构造 target，并让梯度穿过等式两侧，才会得到 residual-gradient 一类不同目标；如果反而用 Critic loss 更新独立目标参数，则形成另一个非标准耦合系统。 这两种做法都不是标准 DDPG。

\[\nabla_\phi L_Q = 2\, \mathbb E \left[ \left(Q_\phi-y\right) \nabla_\phi Q_\phi \right].\]

目标网络本来就不属于在线 Critic optimizer；no-grad 进一步避免构图、节省显存并明确语义。 它不是“半梯度成立”的唯一原因，参数分离本身已经使 \(y\) 对在线 \(\phi\) 为常量。

3.3 MSE、Huber 与权重衰减

  • 原始 DDPG 的核心形式是平方 TD error。
  • Huber loss 可降低异常大 TD error 的梯度影响，是工程变体，不应写成原始算法组件。
  • 原论文实验对 Critic 使用 L2 weight decay；现代实现未必保留。是否使用必须记录， 不能把“无 weight decay”或“必有 weight decay”当算法定义。

3.4 Critic loss 小不等于 Q 准确

Critic 可能准确拟合一个已经高估或低估的 target。若 target 与当前 Q 共同漂移， 训练 MSE 甚至可以下降而环境回报恶化。评价 Critic 需要结合：

  • Q 与蒙特卡洛回报的校准；
  • held-out replay 的 TD error；
  • Q 的均值、极值与奖励尺度；
  • 确定性策略的独立评估回报。

详细诊断见子页 ⑥。

四、Actor：最小化负 Q

4.1 目标

令 \(\widehat d_{\mathcal D}\) 表示 ReplayBuffer 中状态的经验分布。固定当前 Critic 参数 \(\phi\) 与该经验分布时，Actor 使用的代理目标为

\[J_{\mathrm{sur}}(\theta;\phi,\mathcal D) = \mathbb E_{s\sim\widehat d_{\mathcal D}} \left[ Q_\phi \left( s,\mu_\theta(s) \right) \right].\]

深度学习 optimizer 默认执行梯度下降，因此实现写成

\[L_\mu(\theta) = -J_{\mathrm{sur}}(\theta;\phi,\mathcal D) = -\mathbb E_{s\sim\widehat d_{\mathcal D}} \left[ Q_\phi \left( s,\mu_\theta(s) \right) \right]. \tag{3}\]

负号不是奖励为负，也不是 Q 必须为负；它只是把最大化转换为最小化。

4.2 梯度路径

\[\nabla_\theta J_{\mathrm{sur}} = \mathbb E \left[ \nabla_\theta\mu_\theta(s) \nabla_aQ_\phi(s,a) \big\vert_{a=\mu_\theta(s)} \right].\]

Actor step 的状态来自 replay，动作必须由当前 Actor 重新生成。若误用 replay action， \(Q_\phi(s,a_{\mathrm{replay}})\) 与 \(\theta\) 无计算依赖，Actor 梯度为 0。 上式只是在固定 \(\phi\) 和当前经验分布时的代理梯度；它不等于原始 on-policy 性能目标的 无条件无偏梯度，理论边界见子页 ①。

4.3 为什么 Actor step 不更新 Critic

Critic 在本阶段充当固定的可微目标。若 Actor optimizer 包含 Critic 参数， 优化器会让 Critic 自己把输出抬高，而不是迫使 Actor 找到更好的动作。 常用实现临时关闭 Critic 参数梯度，减少计算；但不能对整个 Critic 前向使用 no-grad， 否则 \(\nabla_aQ\) 也被切断。

4.4 Actor loss 的解释边界

Actor loss 越负，只表示当前 Critic对当前 Actor 动作给出更高 Q。 它不是环境回报，不同训练步的 Critic 标尺也在变化，因此 Actor loss 通常不适合跨实验直接比较。

五、一次更新的顺序

采样。从 ReplayBuffer 取 obs, action, reward, next_obs, terminated。
构造 target。在 no-grad 区域运行目标 Actor 与目标 Critic，得到式 (1)。
更新 Critic。最小化式 (2)，只执行 Critic optimizer step。
更新 Actor。用最新在线 Critic 计算式 (3)，只执行 Actor optimizer step。
更新目标网络。对 Actor 和 Critic 的目标副本做同一次 Polyak 插值。

Critic 先、Actor 后是 DDPG 的常见实现：Actor 使用刚完成一步更新的 Critic。 这不是“交换顺序后数学上绝不可能训练”的定理，但复现时应固定并报告，不要在无记录情况下改变。

六、Soft Update 的两套记号

6.1 以新参数注入比例 τ 表示

\[\bar\psi \leftarrow (1-\tau)\bar\psi+\tau\psi, \qquad 0<\tau\ll1. \tag{4}\]

这里 \(\psi\) 可代表 Actor 或 Critic 在线参数。\(\tau\) 越小，目标越慢。

6.2 以旧目标保留比例 ρ 表示

\[\bar\psi \leftarrow \rho\bar\psi+(1-\rho)\psi, \qquad \rho\lesssim1. \tag{5}\]

两式满足

\[\tau=1-\rho.\]

Spinning Up 的参数名 polyak 使用第二种语义，默认值靠近 1； 许多库的 tau 使用第一种语义，默认值靠近 0。

把 \(0.995\) 当作式 (4) 的 \(\tau\)，目标网络每次几乎完全复制在线网络； 把 \(0.005\) 当作式 (5) 的 \(\rho\)，结果同样如此。名称不能代替公式。

6.3 软更新是低通滤波

连续展开式 (4)：

\[\bar\psi_t = (1-\tau)^t\bar\psi_0 + \sum_{k=1}^{t} \tau(1-\tau)^{t-k}\psi_k.\]

目标参数是历史在线参数的指数加权平均。它减少单步跳动，却会引入滞后： \(\tau\) 太小，target 过时；太大，target 与在线网络几乎同步，稳定作用减弱。

七、训练调度的六个独立量

7.1 环境交互计数

每次与环境交互生成一条 transition。记总数为 env_steps。

7.2 纯随机探索长度

start_steps 决定前多少个环境步完全从动作空间随机采样。它控制初始数据覆盖， 不是学习器是否允许更新的开关。

7.3 学习启动阈值

update_after 或 learning_starts 决定 buffer 至少积累多少数据后开始梯度更新。 它不一定等于“随机动作持续多久”的 start_steps。

7.4 Learner 触发频率

train_freq 或 update_every 决定隔多少环境步触发一轮 learner。

7.5 每次触发的梯度步数

gradient_steps 决定一次触发做多少个 mini-batch step。常用数据比是

\[\mathrm{UTD} = \frac{\text{gradient updates}} {\text{new environment transitions}}.\]

每 50 个环境步集中更新 50 次与每步更新 1 次都给出 UTD≈1，但数据新鲜度、 目标更新节奏与计算吞吐不同。

7.6 Target 更新间隔

target_update_interval 决定每多少个梯度步执行一次目标更新。原始 DDPG 和 Spinning Up 的常见实现是在每个主网络更新后更新目标参数；其他框架可以暴露独立间隔。 它与 Polyak 系数共同决定目标移动速度：相同 \(\tau\) 若更新得更稀疏，按环境步观察的目标响应更慢。

参数 控制对象 不能与什么混淆
start_steps 何时停止纯随机行为 何时开始训练
update_after 何时允许第一次梯度更新 每次更新多少步
update_every / train_freq learner 触发间隔 target 的 Polyak 系数
gradient_steps 每次触发的批更新数 batch size
tau / polyak target 每次移动幅度 target 多久更新一次
target_update_interval target 每隔多少梯度步更新 每次移动幅度

八、优化器与超参数

8.1 两个独立 optimizer

Actor 与 Critic 的目标和梯度尺度不同，应使用独立 optimizer 与清梯度流程：

  • Critic optimizer 只持有 \(\phi\)；
  • Actor optimizer 只持有 \(\theta\)；
  • 目标参数不属于任何 optimizer。

8.2 学习率并非必须相同

原论文低维实验报告 Actor 学习率 \(10^{-4}\)、Critic 学习率 \(10^{-3}\)； Spinning Up 教学实现默认两者均为 \(10^{-3}\)。这说明学习率属于实现配置， 不是 DDPG 身份判据。复现实验必须以对应仓库和环境版本为准，不能跨来源拼默认值。

8.3 原论文与教学实现参数只作出处化参考

项 DDPG 原论文低维实验 Spinning Up PyTorch 默认 解读
\(\gamma\) 0.99 0.99 长期折扣相同
mini-batch 64 100 工程选择
Actor lr \(10^{-4}\) \(10^{-3}\) 不应跨实现直接替换
Critic lr \(10^{-3}\) \(10^{-3}\) 仍依奖励尺度而变
target 记号 \(\tau=10^{-3}\) \(\rho=0.995\) 两套定义，不能只比数值

8.4 可选工程措施

  • 梯度裁剪：可抑制异常批次，但也可能掩盖 Q 爆炸的根因。
  • Huber loss：降低极大 TD error 影响，需标注为变体。
  • 状态 / reward 归一化：有助于尺度，但训练与评估统计必须一致。
  • 权重衰减：原论文对 Critic 使用；现代实现差异很大。

这些措施都应作为实验变量报告，不能在没有消融时声称必然改善稳定性。

九、知识重点、优化创新与边界

9.1 必须掌握的优化逻辑

  1. Critic 回归、Actor 改进和目标参数复制是三个不同操作，不是一个联合 loss 的一次 backward。
  2. terminated 决定是否屏蔽 bootstrap；terminated or truncated 通常只决定采样器是否重置。
  3. Actor 最大化的是固定当前 Critic 后的 replay 代理目标，不是直接观测到的环境回报。
  4. Polyak 系数和 target 更新间隔共同决定目标响应；参数名本身不能替代更新公式。

9.2 机制来源与 DDPG 的优化组合

  • DPG / Actor-Critic 已有基础：确定性策略梯度给出 Actor 的动作梯度方向； 价值评估与策略改进本来就是两个交替问题，并非 DDPG 首创。
  • DQN 提供的稳定化基础：经验回放和滞后目标网络提高数据复用率、减慢 bootstrap 目标变化。
  • DDPG 的关键组合：用目标 Actor 稳定下一动作、目标 Critic 稳定该动作的估值，并以软更新 同步两端；再把这一 target 与深度确定性 Actor、off-policy Critic 和 replay 训练闭环连接起来。

所以，DDPG 的贡献重点在连续动作深度 Actor-Critic 中的组合与稳定化，而不是分别发明 Actor-Critic、确定性策略梯度、经验回放或目标网络。

9.3 不能越界的结论

  • 目标网络降低移动目标的速度，但不保证 Q 无偏、训练收敛或策略性能单调上升。
  • Critic loss 下降、Actor loss 变负都不是环境回报改善的充分条件。
  • Critic 先于 Actor、每步更新 target、特定学习率和 UTD 都是需记录的实现选择，不是普适定理。

十、概念伪代码

batch = replay.sample(batch_size)

with torch.no_grad():
    next_action = target_actor(batch.next_obs)
    next_q = target_critic(batch.next_obs, next_action)
    terminated = batch.terminated.float()
    y = batch.reward + gamma * (1.0 - terminated) * next_q

# 1. Critic
q = critic(batch.obs, batch.action)
critic_loss = mse(q, y)
critic_optimizer.zero_grad(set_to_none=True)
critic_loss.backward()
critic_optimizer.step()

# 2. Actor
set_requires_grad(critic, False)
actor_loss = -critic(batch.obs, actor(batch.obs)).mean()
actor_optimizer.zero_grad(set_to_none=True)
actor_loss.backward()
actor_optimizer.step()
set_requires_grad(critic, True)

# 3. Target networks（按配置的 target_update_interval 触发）
with torch.no_grad():
    soft_update(target_actor, actor, tau)
    soft_update(target_critic, critic, tau)

这段只表达一次 update 的数学顺序；环境交互、warm-up、动作缩放、日志和评估在实现页给出。

十一、更新级自检

  1. 目标张量是否 requires_grad=False？
  2. Actor step 前后 Critic 参数是否逐项不变？
  3. Critic step 是否使用 replay action，Actor step 是否使用当前 Actor action？
  4. terminated 与 truncated 是否分开存储与处理？
  5. 截断时的 next_obs 是否为真实 final observation？
  6. tau 的公式语义是否与配置值一致？
  7. Target Actor 与 Target Critic 是否在同一规定时刻更新，间隔是否单独记录？
  8. start_steps 与 update_after 是否分开配置？
  9. UTD、batch size、train frequency 是否分别记录？
  10. reward、Q、target 是否同 shape，未触发广播？
  11. 日志是否同时包含 deterministic evaluation，而不只看 loss？
