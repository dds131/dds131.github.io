子页 ④ 把 ACT 的网络结构讲到「decoder 里有两种注意力，一种让 action query 之间互相可见，一种从 memory 取信息」这一层；子页 ⑨ 则拆解 DETRVAE 的装配结构。严格按 PyTorch 的直接子项统计，DETRVAE 有 14 个具名子模块和 1 个持久化缓冲区；若继续展开容器内部，表格行数会更多，因此不宜把“表格行数”称为模块总数。本页覆盖两者之间剩下的最后一层——每一层 Transformer 内部逐行发生了什么。

本页的覆盖范围就是官方仓库 detr/models/transformer.py 这一个文件的 314 行。它定义了五个类：Transformer、TransformerEncoder、TransformerDecoder、TransformerEncoderLayer、TransformerDecoderLayer，以及三个工具函数。ACT 里的三个 Transformer 容器全部由这五个类构造。

本页最需要记住的三条：在每次注意力调用处，源码把位置编码显式加到 query 与 key，没有把原始位置编码直接加到 value；第一层 decoder self-attention 在关闭 dropout 时会给所有 query 位置相同的输出，但训练态的注意力 dropout 与残差 dropout 会破坏这种逐样本的精确相等；各层由 deepcopy 得到独立参数，不过当前源码最终取 hs[0]，动作头只消费第 0 个 decoder 层的结果。

二、张量布局约定：seq-first

读 ACT 的 Transformer 源码之前必须先确认一件事：所有序列张量都是 seq-first 布局，即 \((\text{序列长度},\ \text{批大小},\ \text{特征维})\)，而不是更常见的 batch-first。

原因在构造函数里：

self.self_attn = nn.MultiheadAttention(d_model, nhead, dropout=dropout)

nn.MultiheadAttention 的 batch_first 参数没有被传入，取默认值 False，因此它要求输入形状为 \((L,\, N,\, E)\)。

2.1 六处关键的布局或批维处理

位置 代码 切换前 切换后
主干视觉特征 src.flatten(2).permute(2, 0, 1) \((B,\, 512,\, 15,\, 80)\) \((1200,\, B,\, 512)\)
主干位置编码 pos_embed.flatten(2).permute(2,0,1).repeat(1, bs, 1) \((1,\, 512,\, 15,\, 80)\) \((1200,\, B,\, 512)\)
action query query_embed.unsqueeze(1).repeat(1, bs, 1) \((H,\, 512)\) \((H,\, B,\, 512)\)
两个额外 token torch.stack([latent_input, proprio_input], axis=0) 两个 \((B,\, 512)\) \((2,\, B,\, 512)\)
额外位置编码 additional_pos_embed.unsqueeze(1).repeat(1, bs, 1) \((2,\, 512)\) \((2,\, B,\, 512)\)
CVAE encoder 输入 encoder_input.permute(1, 0, 2) \((B,\, H+2,\, 512)\) \((H+2,\, B,\, 512)\)

读码口诀：见到 .permute(2, 0, 1) 或 .permute(1, 0, 2)，就是在切换到 seq-first。上表同时列出 repeat、unsqueeze 与 stack，它们处理批维或序列维，但不都属于“布局切换”。在本页跟踪的 Transformer 序列路径里，CVAE encoder 在 permute 之前及最终 hs.transpose(1, 2) 之后使用 batch-first；视觉骨干、动作头等外围网络还会出现其他布局，不能把“两处”推广到整个模型前向。

2.2 repeat 与广播的差别

主干侧的位置编码显式做了 repeat(1, bs, 1)，而 CVAE 侧的 pos_embed 保持 \((H+2,\, 1,\, 512)\) 不做 repeat，靠广播与 \((H+2,\, B,\, 512)\) 相加。

两者的位置编码都先以批维为 1 的形式产生：PositionEmbeddingSine 的输出批维为 1（见子页 ⑨ 网络模型逐模块拆解 第 4.6 节），pos_table 也带一个长度为 1 的批维。主干源码选择用 repeat 显式复制到批大小 \(B\)；CVAE encoder 则在 with_pos_embed 的加法中依赖广播。由于 \((S,1,d)\) 可以广播到 \((S,B,d)\)，显式 repeat 并不是 nn.MultiheadAttention 的严格要求；这里只能把差异解释为两处源码的实现选择，不能反推其设计动机。

三、nn.MultiheadAttention 的接口与内部

ACT 不自己实现注意力，三处注意力全部调用 PyTorch 的 nn.MultiheadAttention。

3.1 构造与参数构成

构造时只传了三个参数：d_model、nhead、dropout。其余全部取默认值，其中 bias=True、add_bias_kv=False、batch_first=False。

参数名 形状 数量 说明
in_proj_weight \((3d,\, d)\) \(3 \times 512 \times 512 = 786{,}432\) Q、K、V 三个投影矩阵打包成一个张量
in_proj_bias \((3d,)\) 1,536 同样打包
out_proj.weight \((d,\, d)\) 262,144 多头拼接后的输出投影
out_proj.bias \((d,)\) 512  
合计   \(4d^2 + 4d = 1{,}050{,}624\)  

in_proj_weight 的打包是读 state_dict 时最容易困惑的一点：模型里看不到 q_proj、k_proj、v_proj 三个独立张量，只有一个 \((1536,\, 512)\) 的矩阵，前 512 行对应 Q、中间 512 行对应 K、最后 512 行对应 V。

3.2 返回值与 dropout 的位置

src2 = self.self_attn(q, k, value=src, attn_mask=src_mask,
                      key_padding_mask=src_key_padding_mask)[0]

返回的是一个二元组 (attn_output, attn_output_weights)，ACT 一律取 [0] 丢弃权重。need_weights 与 average_attn_weights 都保持 PyTorch 2.0.0 的默认值 True：内部按头计算的权重可视为 \((B,h,L_q,L_k)\)，返回前对头求平均，所以调用者实际得到的第二项是 \((B,L_q,L_k)\)。丢弃返回值不等于省略内部打分与 softmax 计算。

构造时传入的 dropout=0.1 作用在 softmax 之后的注意力权重上，它与层里显式创建的 self.dropout1、self.dropout2、self.dropout 是不同的几处。统计 dropout 处数时必须说明口径：

口径 encoder layer decoder layer
只数显式 nn.Dropout 模块 3 处（dropout1、FFN 内 dropout、dropout2） 4 处（dropout1、dropout2、FFN 内 dropout、dropout3）
加上注意力内部的权重 dropout 4 处 6 处

注意力的数学定义、为什么要除以 \(\sqrt{d_k}\)、多头为什么有用，见深度学习基础主线的注意力机制页，本页不重复。

四、with_pos_embed：为什么 q、k 加而 v 不加

这是本页最值得记住的一节。TransformerEncoderLayer 与 TransformerDecoderLayer 各自定义了一份完全相同的方法（是复制而非继承）：

def with_pos_embed(self, tensor, pos: Optional[Tensor]):
    return tensor if pos is None else tensor + pos

函数本身只有一行加法，关键在它被调用的位置。

4.1 三处调用的完整对照

调用点 query key value
encoder 的 self-attention src + pos src + pos src（不加）
decoder 的 self-attention tgt + query_pos tgt + query_pos tgt（不加）
decoder 的 cross-attention tgt + query_pos memory + pos memory（不加）

第三行是三者中唯一 query 与 key 加的不是同一套编码的：query 加的是 action query 的位置嵌入，key 加的是视觉与状态 token 的位置编码。这与两者来自不同序列是一致的。

4.2 为什么 value 不加

注意力打分发生在线性投影之后。对第 \(r\) 个头，准确的未归一化 logit 是

\[\ell_{ij}^{(r)} = \frac{ \left(W_Q^{(r)}(x_i+p_i)+b_Q^{(r)}\right)^\top \left(W_K^{(r)}(x_j+p_j)+b_K^{(r)}\right) }{\sqrt{d_h}} .\]

若只为观察内容项与位置项的来源而暂时省略偏置、缩放，并令 \(M_r=(W_Q^{(r)})^\top W_K^{(r)}\)，则可展开为：

\[(x_i+p_i)^\top M_r(x_j+p_j) = \underbrace{x_i^\top M_r x_j}_{\text{内容—内容}} +\underbrace{x_i^\top M_r p_j}_{\text{内容—位置}} +\underbrace{p_i^\top M_r x_j}_{\text{位置—内容}} +\underbrace{p_i^\top M_r p_j}_{\text{位置—位置}} .\]

四项说明内容与位置都可以影响注意力打分；由于中间还有可学习的非对称矩阵 \(M_r\)，第一项不应简单等同于普通余弦式“纯语义相似度”。位置编码加在 query 与 key 上，直接作用于这个打分过程。

value 路径不同：注意力输出是 \(\sum_j\alpha_{ij}v_j\)，当前调用没有把原始 pos 或 query_pos 直接加到 value。位置仍会通过权重 \(\alpha_{ij}\) 间接改变取出的加权内容；而在深层网络中，src、tgt 或 memory 本身也已受先前位置相关计算影响。因此，准确结论是“本次调用不向 value 直接注入原始位置编码”，而不是“value 永远是纯内容”或“位置不决定取什么”。

4.3 每层都重新加一次

pos 与 query_pos 是作为参数传进每一层的，每层的 forward_post 都会重新调用一次 with_pos_embed。因此在 7 层 decoder 中，query_embed 一共参与了 7 次 self-attention 打分与 7 次 cross-attention 打分。

这与只在输入端相加一次的写法有结构差别：逐层注入使每一层的 Q/K 投影都能直接访问同一套原始位置编码。至于位置影响是否会“稀释”、这种写法是否一定更优，不能仅由源码推出，需要专门的消融或表示分析。

五、encoder layer 内部逐行

官方默认配置与公开训练命令没有启用 --pre_norm，因此 normalize_before=False，forward 转发到 forward_post。源码保留了 --pre_norm 开关；用户显式启用后会改走 forward_pre，所以“恒为 False”不是类实现本身的约束。默认 post-norm 路径的核心计算如下：

def forward_post(self, src, src_mask=None, src_key_padding_mask=None, pos=None):
    q = k = self.with_pos_embed(src, pos)
    src2 = self.self_attn(q, k, value=src, attn_mask=src_mask,
                          key_padding_mask=src_key_padding_mask)[0]
    src = src + self.dropout1(src2)
    src = self.norm1(src)
    src2 = self.linear2(self.dropout(self.activation(self.linear1(src))))
    src = src + self.dropout2(src2)
    src = self.norm2(src)
    return src

以真机主干 encoder 为例，序列长度 \(S = 1202\)、\(d = 512\)、\(f = 3200\)。

步 操作 输出形状 该步参数量
1 q = k = src + pos \((1202,\, B,\, 512)\) 0
2 self_attn(q, k, value=src) \((1202,\, B,\, 512)\) 1,050,624
3 src + dropout1(src2) \((1202,\, B,\, 512)\) 0
4 norm1(src) \((1202,\, B,\, 512)\) 1,024

5.2 两个子层共用同一个骨架

第 2 到 4 步与第 5 到 7 步是同一个模式：

\[x \;\leftarrow\; \mathrm{LN}\big( x + \mathrm{Dropout}(f(x)) \big)\]

第一次 \(f\) 是多头自注意力，第二次 \(f\) 是前馈网络。归一化在残差相加之后，这就是 post-norm，详见第八节。

5.3 FFN 的具体形状

self.linear1 = nn.Linear(d_model, dim_feedforward)   # 512 到 3200
self.dropout = nn.Dropout(dropout)
self.linear2 = nn.Linear(dim_feedforward, d_model)   # 3200 到 512
self.activation = _get_activation_fn(activation)     # activation 默认 "relu"，返回 F.relu

顺序是 linear1 到 relu 到 dropout 到 linear2。ACT 把 dim_feedforward 设为 3200 而不是 DETR 默认的 2048，扩张比为 \(3200/512 = 6.25\)，高于标准 Transformer 常用的 4 倍。FFN 因此成为单层里参数量最大的部分，占 4,333,184 中的 3,280,512，即 75.7 percent。

_get_activation_fn 返回的是 F.relu 这个函数而不是模块，因此它不出现在 state_dict 里，也不计入参数量。

forward_pre 在源码里同样存在；官方默认配置不启用 --pre_norm，所以复现实验走 forward_post。若用户显式传入该开关，执行路径会改变。

六、decoder layer 内部逐行

decoder 层比 encoder 层多一个注意力子层，共 11 步：

def forward_post(self, tgt, memory, tgt_mask=None, memory_mask=None,
                 tgt_key_padding_mask=None, memory_key_padding_mask=None,
                 pos=None, query_pos=None):
    q = k = self.with_pos_embed(tgt, query_pos)
    tgt2 = self.self_attn(q, k, value=tgt, attn_mask=tgt_mask,
                          key_padding_mask=tgt_key_padding_mask)[0]
    tgt = tgt + self.dropout1(tgt2)
    tgt = self.norm1(tgt)
    tgt2 = self.multihead_attn(query=self.with_pos_embed(tgt, query_pos),
                               key=self.with_pos_embed(memory, pos),
                               value=memory, attn_mask=memory_mask,
                               key_padding_mask=memory_key_padding_mask)[0]
    tgt = tgt + self.dropout2(tgt2)
    tgt = self.norm2(tgt)
    tgt2 = self.linear2(self.dropout(self.activation(self.linear1(tgt))))
    tgt = tgt + self.dropout3(tgt2)
    tgt = self.norm3(tgt)
    return tgt
cross-attention 的 key 与 value 来自哪里

这段四路观测正是 memory 的来源：图像经主干与 encoder 之后成为 1202 个 token，7 层 decoder 的 cross-attention 每一层都从这同一份 memory 重新投影出 key 与 value，memory 本身在整个解码过程中不再更新。

6.2 三条容易被忽略的事实

memory 在 7 层中从不更新它由 encoder 一次算出，作为同一个张量传给全部 7 层。decoder 只读不写，序列长度 1202 在解码全程恒定。
没有 KV cache每一层的 cross-attention 都要把这 1202 个 token 重新投影一次 key 与 value。7 层就投影 7 次。自回归生成中常用的 KV 缓存在这里不适用，因为不存在逐步生成。
self-attention 的 value 始终是 tgt 本身不是加了 query_pos 的版本。这一点在第七节的零值推演中是关键。

6.3 数据流图

七、第一层 decoder 的零值传播：eval 的严格结论与 train 的修正

tgt = torch.zeros_like(query_embed) 使第一层 self-attention 的所有 value 在序列维相同；但“所有位置的输出完全相同”还需要关闭 dropout。下面把确定性的代数结论与训练态随机性分开。

7.1 共同前提：第一层的 value 相同

对第 \(r\) 个头、query 位置 \(i\) 与 key 位置 \(j\)：

\[q_i^{(r)}=W_Q^{(r)}e_i+b_Q^{(r)},\qquad k_j^{(r)}=W_K^{(r)}e_j+b_K^{(r)},\qquad v_j^{(r)}=W_V^{(r)}\mathbf 0+b_V^{(r)}=b_V^{(r)},\]

其中 \(e_i=\text{query\_pos}_i\)。Q/K 因位置嵌入而不同，但每个头的所有 value 都等于同一偏置。由此还有一个容易漏掉的梯度事实：第一层 self-attention 的 \(W_V\) 始终乘零输入，其 \(512\times512=262{,}144\) 个标量的任务梯度为零；\(b_V\) 仍可学习。由于 Q/K 与 V 打包在同一个 in_proj_weight 参数中，不能仅看整个参数的 .grad 是否非零来判断这个 V 子块。

7.2 eval 或关闭 dropout：所有位置严格相同

令

\[\alpha_{ij}^{(r)} = \operatorname{softmax}_j\!\left( \frac{(q_i^{(r)})^\top k_j^{(r)}}{\sqrt{d_h}} \right).\]

当注意力 dropout 关闭时，\(\sum_j\alpha_{ij}^{(r)}=1\)，所以

\[o_i^{(r)} =\sum_j\alpha_{ij}^{(r)}b_V^{(r)} =b_V^{(r)}.\]

拼接各头并做输出投影后，

\[y_i=W_O\,\operatorname{Concat}_r(b_V^{(r)})+b_O,\]

它与位置 \(i\)、query embedding 及 Q/K 权重无关。eval 模式下外部的 dropout1 也关闭，因此经过零残差和逐位置 LayerNorm 后，所有位置仍相同。这个结论只说明第一层 self-attention 不能在确定性前向中制造位置之间的内容差异；它仍可贡献一个共享的学习向量。

PyTorch 2.0.0 把 MHA 的 in_proj_bias 与 out_proj.bias 初始化为零，而 ACT 的 _reset_parameters 只重新初始化维度大于 1 的参数。因此刚初始化时 \(b_V=b_O=0\)，上式输出为零；训练更新偏置后，它在 eval 中可以成为非零共享向量。

7.3 train 模式：两处 dropout 会破坏逐位置精确相等

训练时，MHA 在 softmax 后对每个权重做 dropout。令 \(m_{ij}^{(r)}\sim\operatorname{Bernoulli}(1-p)\)，则

\[\widetilde{\alpha}_{ij}^{(r)} =\frac{m_{ij}^{(r)}}{1-p}\alpha_{ij}^{(r)},\qquad o_i^{(r)} =\left(\sum_j\widetilde{\alpha}_{ij}^{(r)}\right)b_V^{(r)}.\]

单次随机前向中，\(\sum_j\widetilde{\alpha}_{ij}^{(r)}\) 通常不等于 1，且可随头与 query 位置变化；随后独立的 dropout1 还会再次引入逐元素差异。虽然注意力 dropout 对未归一化加权和保持无偏，但 LayerNorm 是非线性的，不能据此断言归一化后的期望相同。训练态出现的这种差异是随机正则化效应，不应解释为部署时确定性的 action-query 内容交互；初始化全零偏置的特例下，这两处 dropout 也无法从零值制造差异。

7.4 cross-attention、后续层与 hs[0]

eval 模式下第一次 cross-attention 的 query 为

\[q_i=c+\text{query\_pos}_i.\]

不同的 query_pos 使各位置可以形成不同的注意力分布，并从 memory 取回不同的条件化表示；“可以”不等于数学上保证不同，因为退化参数仍可能给出相同结果。原始 7 层栈内部，第 2 层开始接收到已条件化的 tgt，其 self-attention 因而具备建模 query-query 依赖的能力。

但固定提交中的 DETRVAE.forward 使用 self.transformer(...)[0]。这里的 [0] 选择 return_intermediate_dec=True 所堆叠结果的第 0 个 decoder 层，而不是“取二元组第一个元素”。所以第 2–7 层虽然仍执行并消耗算力，其结果不进入动作头和任务损失，也不能解释当前实现的动作块连贯性；这些层没有来自动作损失的任务梯度，优化器的权重衰减仍可能更新其参数。

eval 的严格结论第一层 self-attention 只能加入各位置共享的学习向量；位置分化主要来自 query_pos 参与的 cross-attention。
train 的随机修正两处 dropout 可让单次训练前向在位置间不同，但这种随机差异不能等同于确定性的跨 action-query 信息交换。
实现边界后续层在完整栈内具备 query-query 建模能力，但固定源码的动作输出只读取第 0 层。
自查时应先调用 model.eval() 并使用 torch.no_grad()，再给 decoder.layers[0].self_attn 注册 hook；MHA 的 hook 输出是二元组，应检查 output[0]。此时各位置应相同。若切回 train()，不能再把逐位置精确相等作为断言。观察索引 1 的层可以验证其内部表示已具备位置差异，但还需结合 hs[0] 才能判断它是否影响最终动作。

八、post-norm 与 pre-norm：ACT 的取值与三个连带事实

8.1 取值来源

normalize_before 一路来自命令行参数 --pre_norm：

parser.add_argument('--pre_norm', action='store_true')

store_true 的默认值是 False，而官方 README 给出的训练命令没有传这个开关，imitate_episodes.py 的 policy_config 也没有覆盖它。因此，官方默认复现实验的三个 Transformer 容器全部走 post-norm；这不是不可更改的架构常量，显式传入 --pre_norm 后会执行 forward_pre。

8.3 三个连带事实

由 normalize_before = False 可以直接推出三处 norm 的取值：

容器 末尾 norm 的构造语句 取值 是否生效
主干 encoder nn.LayerNorm(d_model) if normalize_before else None None 否
CVAE encoder 同上（build_encoder 里的同一行） None 否
主干 decoder decoder_norm = nn.LayerNorm(d_model)，无条件 LayerNorm 是

两个 encoder 的末尾都没有额外的归一化——TransformerEncoder.forward 里那句 if self.norm is not None 判假，循环完直接返回。这与 transformer.py 文件头注释所说的「extra LN at the end of encoder is removed」一致。

decoder 那边则不同：decoder_norm 是无条件创建的，而且由于 return_intermediate=True，它在循环中对每一层的输出都作用了一次（见第十二节）。

8.4 与学习率设置的证据边界

官方配置同时采用 post-norm、\(10^{-5}\) 的恒定学习率，并且没有调度器（见子页 ⑥ 训练目标与超参 第 8.5 节）。这些设置确实在同一次训练方案中共同出现，但论文没有对归一化位置与学习率做联合消融，不能据此推出“小学习率是专为 post-norm 选择”或该组合优于其他方案。

本页不判断哪种归一化位置更好；这依赖模型规模、层数、数据量与优化器设置，不能从源码本身得出。

九、多头切分与注意力矩阵形状

9.1 切分

nheads = 8、hidden_dim = 512，因此每个头的维度是

\[d_{\text{head}} = \frac{512}{8} = 64, \qquad \frac{1}{\sqrt{d_{\text{head}}}} = \frac{1}{8} = 0.125\]

in_proj_weight 的形状 \((3d,\, d)\) 与头数无关：投影仍然是一次 512 到 1536 的线性变换，之后才把 512 维切成 8 段 64 维分别做注意力，最后拼回 512 维过 out_proj。这就是第十一节要说的「nheads 不改变参数量」的原因。

序列长度由相机数决定

与上一段是同一个任务的第三人称视角。真机用四路相机意味着 encoder 的序列长度是 1202，而自注意力矩阵按序列长度的平方增长，这是长序列部署时最直接的压力来源。

9.2 四处注意力的内部逐头矩阵形状

在固定的 PyTorch 2.0.0、need_weights=True 路径中，内部把批维与头维折叠，逐头 score / softmax 权重张量的形状可写成 \((B \cdot \text{nheads},\, L_q,\, L_k)\)。这不是调用者收到的返回形状：默认 average_attn_weights=True 会对头求平均，返回 \((B,L_q,L_k)\)，随后被 ACT 的 [0] 丢弃。

注意力 \(L_q\) \(L_k\) 内部逐头形状（\(B = 8\)） fp32 名义容量
主干 encoder 自注意力 1202 1202 \((64,\, 1202,\, 1202)\) 352.7 MiB
decoder 自注意力 90 90 \((64,\, 90,\, 90)\) 1.98 MiB
decoder 交叉注意力 90 1202 \((64,\, 90,\, 1202)\) 26.4 MiB

9.3 这个量级意味着什么

按表中“显式物化、fp32、逐头”口径，主干 encoder 单层的 score / 权重张量名义容量为 352.7 MiB。训练时，autograd 可能让多层的反向所需中间量同时存活到 backward；不能描述为每层结束后立即释放，也不能把单层数字简单乘以层数当作峰值。论文报告在 11 GB RTX 2080 Ti 上训练，只是硬件事实，不能用来验证或反推出该实现的实际峰值显存。

口径声明：上表按 B 乘 nheads 乘 L_q 乘 L_k 个 fp32 元素计算的是内部逐头张量的名义容量。PyTorch 2.0.0 在本页固定的 need_weights=True 分支会显式计算权重；但表中仍未计入 Q/K/V、softmax 与 dropout 中间量、其他激活、反向缓存、参数、梯度及优化器状态，因此既不是总显存，也不是通用的显存下界。实际峰值必须在固定软件版本、模式与批配置下测量。

自注意力的 \(O(n^2)\) 复杂度、以及各类降低该复杂度的方法，见深度学习基础主线的注意力机制页。

在上表追踪的 attention mask 实参中，只有 CVAE encoder 的 src_key_padding_mask 非 None。它的前两列被强制置为 False，保证 CLS 与 qpos 两个位置不被这个 padding mask 屏蔽（见子页 ⑨ 网络模型逐模块拆解 第 6.5 节）。

10.3 两类掩码的语义差别

attn_mask按 query 与 key 的位置对屏蔽，形状为 (L_q, L_k) 或带批与头维。因果掩码属于这一类：它屏蔽掉每个位置对其右侧全部位置的注意。
key_padding_mask按 key 的位置屏蔽，形状为 (B, L_k)，对所有 query 一视同仁。它用于屏蔽 padding 出来的无效 token。

两者在 PyTorch 中的布尔语义一致：True 表示该位置被屏蔽。ACT 里 is_pad 的 dtype 正是 bool，值为 True 的位置是补齐出来的无效动作。

10.4 为什么这里没有因果掩码

tgt_mask 在 decoder 调用中从未被传入，取默认值 None，因此 \(H\) 个 action query 在自注意力里彼此完全可见，没有任何方向性约束。这是 ACT 能并行产生整段动作、而不是逐步自回归生成的结构前提。这一结论的完整论证、以及与自回归式 VLA 的分界，见子页 ④ DETR-style Transformer 第十一节；本节给的是形参级的取值追踪。

十一、_get_clones 的深拷贝语义与初始化

11.1 每一层的参数都是独立的

def _get_clones(module, N):
    return nn.ModuleList([copy.deepcopy(module) for i in range(N)])

TransformerEncoder 与 TransformerDecoder 的 __init__ 都用它来生成各层。copy.deepcopy 会完整复制参数张量，因此 4 层 encoder 是 4 组互不相干的参数，7 层 decoder 是 7 组。

反证很直接：若各层共享参数，4 层 encoder 只需 4,333,184 个参数；实际是 17,332,736，正好是 4 倍。

11.2 初始化路径的差异

Transformer.__init__ 的最后一步是：

def _reset_parameters(self):
    for p in self.parameters():
        if p.dim() > 1:
            nn.init.xavier_uniform_(p)

它在 _get_clones 之后执行，遍历的是 Transformer 对象下的全部参数，因此主干 encoder 与 decoder 的各层在重置后彼此不同。

而 CVAE encoder 由 build_encoder() 在 Transformer 之外单独构造，不经过这次重置。它的 4 层来自同一个 TransformerEncoderLayer 实例的深拷贝，因此在初始化时刻逐位相同；训练开始后，各层收到的梯度不同，参数随之分化。

本页只如实记录这条源码事实，不评价它是否为有意设计。

11.3 dim > 1 这个条件的边界

xavier 重置只作用于维度大于 1 的参数，这把两类参数排除在外：

参数 维度 是否经 xavier 实际初始化
in_proj_weight、out_proj.weight、linear1.weight、linear2.weight 2 是 xavier uniform
上述各层的 bias 1 否 PyTorch 默认
LayerNorm.weight 与 LayerNorm.bias 1 否 全 1 与全 0

Transformer 对象之外的模块同样不受影响：三个 nn.Embedding（query_embed、cls_embed、additional_pos_embed）用的是默认的标准正态初始化，与 xavier 的量级不同；各个 nn.Linear 投影层用的是 PyTorch 默认初始化。还需注意，CVAE encoder 中的 MultiheadAttention 保留其自身的混合默认初始化：in_proj_weight 为 Xavier，in_proj_bias 与 out_proj.bias 为零，而 out_proj.weight 沿用 Linear 的默认初始化，不能概括成“所有二维权重均为 Kaiming”。

自查方法：比较 model.transformer.encoder.layers[0].linear1.weight 与 layers[1].linear1.weight，二者应当不同；再比较 model.encoder.layers[0] 与 model.encoder.layers[1] 的同名参数（注意这里的 model.encoder 是 CVAE encoder），在未训练的模型上二者应当逐位相同。

十二、两个容器类的循环与 return_intermediate

12.1 TransformerEncoder.forward 

output = src
for layer in self.layers:
    output = layer(output, src_mask=mask,
                   src_key_padding_mask=src_key_padding_mask, pos=pos)
if self.norm is not None:
    output = self.norm(output)
return output

极简：循环 4 次，self.norm 为 None 故末尾什么都不做。注意 pos 是同一个张量被传给每一层，与第 4.3 节说的「每层重新加一次」一致。

12.2 TransformerDecoder.forward 

output = tgt
intermediate = []
for layer in self.layers:
    output = layer(output, memory, tgt_mask=tgt_mask, ...,
                   pos=pos, query_pos=query_pos)
    if self.return_intermediate:
        intermediate.append(self.norm(output))
if self.norm is not None:
    output = self.norm(output)
    if self.return_intermediate:
        intermediate.pop()
        intermediate.append(output)
if self.return_intermediate:
    return torch.stack(intermediate)
return output.unsqueeze(0)

三段逻辑：

段 做了什么 说明
循环内 每层输出都过一次 self.norm 后 append 7 个元素全部是归一化后的值
循环后 对最终输出再过一次 self.norm，然后 pop 掉末位、append 新值 净效果是把末位替换为一个等值重算的结果
返回 torch.stack(intermediate) 形状 \((7,\, H,\, B,\, 512)\)

最后那个 else 分支同样值得注意：return_intermediate=False 时返回的是 output.unsqueeze(0)，前面照样补了一个长度为 1 的维。这解释了为什么调用方无论如何都可以写 [0] 而不报错。

十三、逐层参数量与计算量的解析推导

本节给推导过程与算量，模块级的参数量结果表在子页 ⑨ 网络模型逐模块拆解 第十三节。

13.1 参数量

记 \(d = 512\)、\(f = 3200\)。多头注意力的四个参数张量已在第 3.1 节列出：

\[P_{\mathrm{MHA}} = \underbrace{3d^2 + 3d}_{\text{in\_proj}} + \underbrace{d^2 + d}_{\text{out\_proj}} = 4d^2 + 4d = 1{,}050{,}624\]

前馈网络两层：

\[P_{\mathrm{FFN}} = (df + f) + (fd + d) = 2df + f + d = 3{,}280{,}512\]

LayerNorm 的 weight 与 bias 各 \(d\) 维：

\[P_{\mathrm{LN}} = 2d = 1{,}024\]

encoder layer 有一个注意力、一个 FFN、两个 LayerNorm：

\[P_{\text{enc-layer}} = P_{\mathrm{MHA}} + P_{\mathrm{FFN}} + 2 P_{\mathrm{LN}} = 4{,}333{,}184\]

decoder layer 多一个注意力与一个 LayerNorm：

\[P_{\text{dec-layer}} = 2 P_{\mathrm{MHA}} + P_{\mathrm{FFN}} + 3 P_{\mathrm{LN}} = 5{,}384{,}832\]

三个容器合计包含两个 4 层 encoder、一个 7 层 decoder，以及 decoder 容器末尾的共享 LayerNorm：

\[P_{\text{3 containers}} =8P_{\text{enc-layer}}+7P_{\text{dec-layer}}+P_{\mathrm{LN}} =72{,}360{,}320,\]

约占整个 83.9M 参数模型的 86.2 percent。

13.2 计算量

按乘加（MAC）计。记 encoder 序列长 \(S\)、decoder query 数 \(H\)。

encoder 单层：

\[C_{\text{enc}} = \underbrace{4Sd^2}_{\text{四个投影}} + \underbrace{2S^2 d}_{\text{打分与取值}} + \underbrace{2Sdf}_{\text{FFN}}\]

decoder 单层：

\[C_{\text{dec}} = \underbrace{\big(4Hd^2 + 2H^2 d\big)}_{\text{自注意力}} + \underbrace{\big(2Hd^2 + 2Sd^2 + 2HSd\big)}_{\text{交叉注意力}} + \underbrace{2Hdf}_{\text{FFN}}\]

交叉注意力那一项的构成：query 与输出投影各作用在 \(H\) 个位置上，key 与 value 投影作用在 \(S\) 个位置上，打分与取值各是 \(HSd\)。

encoder 单层：投影 0.317 G 1.260 G
encoder 单层：注意力矩阵 0.093 G 1.479 G

13.4 一条反直觉但可验证的结论

把视觉主干的算量放进来对比：ResNet-18 在 224×224 输入下约 1.814 GMAC（公开的标准口径），480×640 的像素数是它的 6.12 倍，因此单路约 11.11 GMAC，四路合计约 44.4 GMAC。注意这个 1.814 与上表 CVAE encoder 那一行的 1.81 G 只是数值接近，两者是彼此无关的两个量。

\[44.4\ \mathrm{GMAC}\ (\text{四路 ResNet-18}) \;>\; 35.0\ \mathrm{GMAC}\ (\text{主干 4 层 encoder 加 7 层 decoder})\]

在这个只比较“四路 ResNet-18”与“主 Transformer”的解析口径下，视觉主干约为后者的 1.27 倍，是较大的单一计算类别，但两者仍处于同一数量级；这不能直接等同于端到端耗时占比。参数量的分布则相反：Transformer 占 86.2 percent，主干约占 13.3 percent。参数多与算量大是两件事，前者取决于权重规模，后者还取决于权重被复用的次数。

口径声明：以上全部为按结构的解析核算，按乘加计，不含 LayerNorm、softmax、激活函数、dropout 这类逐元素算子的开销，也不含框架调度与内存搬运。ResNet-18 的 1.814 GMAC 取自公开的标准口径（torchvision resnet18 在 224×224 下的常见报告值）。右端 35.01 G 统计固定源码实际执行的 4 层主干 encoder 与 7 层 decoder；即使第一层 V 输入为零、后 6 层不影响 `a_hat`，普通稠密算子也不会自动跳过这些计算。CVAE encoder 仅在传入目标动作的前向中执行。实际吞吐依赖硬件与实现，本页不给实测耗时。
