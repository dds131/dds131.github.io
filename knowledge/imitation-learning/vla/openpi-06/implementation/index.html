本页的知识点、创新点与重点

6 个阶段采集、价值、优势、策略、部署、再采集
201 bins价值网络的分类输出
N = 50后训练期优势前瞻
30%优势条件随机丢弃
4 个入口本页逐文件对照的社区工程
0 个官方 π0.6 / π*0.6 公开检查点

前七页回答「模型是什么、为什么这样做」；本页回答「如果从公开的 openpi π0.5 出发，代码应该分成哪些模块，模块之间传什么，以及怎样证明它们接对了」。这两个问题不能混在一起：论文定义算法，社区仓库提供实现参考，自己的机器人项目还需要独立完成数据、动作空间与部署适配。

先给结论。截至 2026-10-08，Physical Intelligence 官方 openpi README 仍只列出 π0、π0-FAST 与 π0.5；issue #789（发布 π0.6）与 #857（支持 RECAP 训练）仍为开放状态。因此不存在可以逐行讲解的「官方 π0.6 源码」。工程上风险较低的路线是：保留已经跑通的 openpi π0.5 数据与策略栈，单独补上价值网络、优势标注、优势条件、迭代控制与验证门禁，并把结果准确称为 以 π0.5 为底座的 RECAP 实现；只有逐项对齐论文定义后，才适合进一步说明复现程度。

一、先划清三层实现边界

层级 可以确认的内容 不能越界的说法
官方论文与模型卡 算法、模型规格、损失形式、数据闭环、部分训练细节 不能声称已获得官方训练代码、完整超参数或 π0.6 权重
社区实现 可运行的文件组织、字段约定、训练脚本与设备适配 不能把仓库默认值写成论文默认值，也不能仅凭配置名认定底座
自己的机器人项目 动作维度、相机映射、归一化统计、成功判定、介入设备、部署频率 不能跳过闭环验证，仅用训练 loss 证明策略有效

本页的代码映射只做两件事：指出每个论文模块在社区仓库中通常落在哪类文件；给出一套不依赖特定仓库命名的接口契约。具体公式分别让渡给 ④ 分布式价值函数 与 ⑤ 优势估计与优势条件策略，避免在源码页重复推导。

二、工程依赖图：哪一步必须等哪一步

flowchart LR
  A[专家演示与已有 SFT 数据] --> B[统一 episode schema]
  C[自主 rollout] --> B
  D[人工纠正] --> B
  B --> E[回报与 value_label]
  E --> F[训练 201-bin Value VLM]
  F --> G[逐帧推理 V]
  B --> H[N 步奖励]
  G --> I[计算 Advantage]
  H --> I
  I --> J[任务分位数阈值]
  J --> K[adv_ind: positive / negative]
  D --> L[纠正帧强制 positive]
  L --> K
  K --> M[优势条件策略训练]
  A --> M
  C --> M
  D --> M
  M --> N[推理固定 positive 或做中等 CFG]
  N --> C

依赖顺序不能随意交换。没有统一 episode 与终止标签，就无法定义回报；没有价值模型，就没有论文意义上的优势；没有 adv_ind，策略只是在做普通 SFT；没有重新部署与采集，就不是 RECAP 的迭代闭环。

论文 Algorithm 1 的另一个关键约束是：第 k 轮价值函数从预训练价值检查点 Vpre 重新训练，策略从预训练策略检查点 πpre 重新训练，只是使用累积到当前轮的数据集。若直接从上一轮权重续训，可以是合理工程实验，但已经不是论文给出的算法。

三、先固定数据契约，再写训练代码

社区仓库字段名并不完全相同，但最小语义可以统一成下表。形状只表示接口角色；批量维、动作块长度、动作维与图像布局由具体实现决定，不是论文公开的固定值。

字段 粒度 语义 产生阶段 主要消费者
observation.images frame base / wrist 等相机图像 采集 策略、价值网络
observation.state frame 关节、夹爪与必要本体状态 采集 策略；价值网络是否使用取决于实现
action frame 或 chunk 机器人动作监督 演示、rollout、纠正 策略训练
task / prompt episode 或 frame 任务语言与 metadata 数据准备 策略、价值网络
source_type episode 或 segment demo、autonomous rollout、human correction 等数据来源 采集/合并 标签规则、数据审计
success episode 最终是否完成任务 评测/人工标注 回报构造
human_correction / intervention frame rollout 中该动作是否为人工纠正；不要与整条专家演示混为同一语义 采集 纠正帧强制正标签、数据审计
reward / reward_label frame 稀疏终局结果与用于 N 步累加的奖励 数据准备 价值目标、优势计算

adv_ind frame positive、negative；必要时 none 只作待标占位 优势标注 策略 tokenizer 与训练

3.1 四个必须做的 schema 检查

  1. episode 边界不能错。 N 步窗口不得跨 episode，失败代价与终止奖励只能落在本 episode 内。
  2. 动作与观测必须同一时间语义。 对齐错误会让 Value 看似收敛，却把 Advantage 标在错误动作上。
  3. 原始数据与重标数据分开。 adv_ind 重写应针对副本或可追溯 sidecar，不能覆盖唯一原始数据。
  4. 纠正段必须可定位，并与初始演示区分。 论文把 rollout 中的人类纠正动作强制标为正；初始演示仍有自己的预训练优势估计。若一个字段同时把所有 demo 与纠正帧都记成 intervention=true，标签代码就必须再依据 source_type 区分，不能把全部演示静默强制为正。

四、六个核心模块分别负责什么

4.1 Value VLM：从 (observation, language) 到 201 档分布

论文把价值模型描述为单独训练的约 670M VLM，而不是在策略输出后临时接一个标量 head；它把归一化回报离散成 201 个 bins，并用交叉熵训练：

\[z_t = f_{\phi}(o_t, \ell) \in \mathbb{R}^{201},\qquad p_{\phi}(V\mid o_t,\ell)=\operatorname{softmax}(z_t)\]

实现至少要拆成四层职责：ValueDataset 读取 frame 与 value_label；ValueTokenizer/Transform 处理图像与任务文本；ValueModel 输出 201 logits；train_value 负责交叉熵、验证集与检查点。把 value_label 直接做单标量 MSE，属于另一个实现选择，不能称为复现论文的分布式价值函数。公开材料没有完整说明价值模型与策略是否复用了任何初始化参数；工程上把它们做成参数和优化器均独立的模型最容易审计，但应标作实现决定，而不是论文逐字要求。

4.2 Advantage 标注器：先保存连续值，再二值化

对距离 episode 末尾至少 50 步的样本，后训练期核心计算是：

\[\operatorname{Adv}_t= \sum_{t'=t}^{t+49} r_{t'} + V(o_{t+50}) - V(o_t)\]

代码应先写出连续 advantage，再按任务阈值生成 adv_ind。episode 尾部不足 50 步时，必须明确截断奖励窗口、终止后不再 bootstrap，或采用何种 padding/mask；奖励与价值还必须使用同一归一化尺度。这样才能审计价值误差、分位数与标签比例。

预训练期不能简单写成一个无歧义的 horizon="episode"：论文附录把它称为 N=T，但印出的求和从 0 到 T，而一般 N 步式从当前 t 开始。两者在原始 episode 坐标下并不等价。官方代码公开前，复现应把所选的“整段回报”或“从 t 起的 return-to-go”约定写进配置与单元测试。

4.3 Advantage tokenizer：条件位置比字符串更重要

论文主文使用确切文本 Advantage: positive 与 Advantage: negative，并把它放在高层子任务 ℓ̂ 之后、离散与连续动作之前；按这一叙述，只有动作似然受条件影响，子任务预测不应读取这个未来评价信号。附录 C 的一个分解式却在形式上也让子任务项以优势为条件。公开材料没有解释两者差异，本页采用更具体的主文序列描述，并要求用位置与 attention mask 测试把这一选择固定下来，而不是把条件随手拼到用户任务 prompt 的开头。

4.4 Policy loss：三项基座目标加条件路由

策略训练仍然包含三路信号：子任务文本 token 的交叉熵、FAST 动作 token 的交叉熵、连续动作的 flow-matching loss。优势条件改变的是动作条件分布，不是把负样本权重直接乘成零。对给定的条件状态 \(c\in\{\text{positive},\text{negative},\varnothing\}\)，单个样本的基座目标可概括为：

\[\mathcal{L}_{\text{policy}}(c) =\mathcal{L}_{\text{subtask}} +\mathcal{L}_{\text{FAST}} +\frac12\mathbb{E}_{\eta,\omega} \left[\alpha_\eta\left\|\omega-a-f_\theta(a^{\eta,\omega},\mathcal I,o,\ell,\hat\ell,c)\right\|^2\right]\]

其中 \(\mathcal I\) 表示图像输入，\(c\) 才是优势条件。论文正文只说 \(\alpha_\eta\) 可以依赖噪声，没有公开训练时的实际函数；\(e^{-\eta/2}\) 出现在附录 C 的连续动作对数似然下界推导中，不能反推为基座或 RECAP 训练的已公开默认权重。30% 条件丢弃决定每个样本走条件还是无条件输入；它与论文 Eq. 3 的显式双项目标只在相应采样假设下具有期望目标上的对应关系，单步梯度并不相同。

知识隔离仍然成立：连续动作专家的 flow 梯度不回到 VLM 主干；主干继续从文本、FAST 与网络多模态共训练中更新。冻结整个 VLM 只是一种社区工程简化，不等于官方 KI。

4.5 Condition dropout 与推理

训练时以 30% 概率丢弃优势条件，得到同一网络的条件与无条件两种路径。至少需要三组单元测试：同一 batch 中条件/无条件样本数量符合随机路由；负样本在非丢弃时确实读到 negative；推理固定 positive 时不会走训练期随机丢弃。

默认推理可直接条件为 positive，对应论文中的 β=1。CFG 是可选增强，不是 RECAP 成立的必要条件；高引导强度可能把动作推向分布边界并产生激进行为。

4.6 Iteration controller：只编排，不隐藏状态

控制器应显式记录：本轮输入数据集合、Value 起始检查点、Policy 起始检查点、阈值统计样本、正负标签比例、部署检查点、采集 episode 列表。一个只打印「collect → value → label → train」的脚本是编排骨架，不等于完整闭环。

5.1 ybpy/pistar：适合顺着论文模块读代码

其 README 给出 demo → rollout → merge → Value → relabel → policy 的闭环顺序，并把 --lookahead 50、adv_ind 重写与 Value 脚本串起来。阅读时应同时记住底座来自公开的 pi05_base；而 README 的示例是继续微调已有实验，不等同于论文 Algorithm 1 每轮从 πpre 重训。这里可借鉴模块与数据流，不能把命令顺序直接当成论文逐步复现。

5.2 Destiny000621/RECAP：适合看真机数据怎样穿过六个阶段

README 把采集、转换、π0.5 SFT、策略微调、Value 训练、优势重标与完整 RECAP 分成 Stage 0–6，并明确列出 intervention、reward、reward_label、value_label、adv_ind 五个字段。它还强调优势重标会原地改数据，因此要求先复制数据集。需要额外留意：README 允许 Stage 6 从 Stage 3 检查点继续训练，多轮说明也允许延续项目检查点；这与论文每轮从 πpre / Vpre 重训不同，复现时必须主动改回论文初始化规则或明确标为变体。

5.3 RLinf/RLinf：适合看分布式价值推理与一条 CFG 变体

RLinf 文档给出 SigLIP2-So400m + Gemma3-270M 的 201-bin 价值模型、分布式价值推理、连续优势 sidecar 与 π0.5 策略训练。但默认 positive_only_conditional=true：负样本始终作为无条件输入，只有正样本成为 positive 条件，其中再以 unconditional_prob=0.1 丢弃。这不同于论文为正、负样本分别写入二值条件并以 30% 概率丢弃条件的配方。因此它适合学习工程接口，却应明确标作 RECAP/CFG 变体，而不是逐式等价实现。

5.4 hzm8341/pi0.6：适合看最小模块拆分与边界声明

README 把 config、observation 字段、tokenization、loss 路由、离线 sidecar、dataloader 合并与迭代 CLI 分开列出，并主动声明「不是完整论文复现」「完整视觉语言 Value backbone 未接入」。它适合学习接口，但不能把 proxy value 与 CLI skeleton 当成论文级闭环。

同一模块最好用两个仓库交叉阅读：一个看数学如何落到张量，一个看数据与真机生命周期。复制整套仓库反而容易把不适合自己机器人的动作定义、相机键名、归一化统计与默认超参数一并带入。

六、从已跑通的 openpi π0.5 出发，按什么顺序实现

6.1 冻结一条可复现实验基线

先固定当前 π0.5 SFT 检查点、数据版本、norm stats、相机键、动作的 delta/absolute 口径、推理频率与评测脚本。没有这条基线，就无法区分收益来自 RECAP，还是来自数据转换或部署参数被改了。

6.2 只增加数据字段，不先改策略网络

在 LeRobot 或现有 episode schema 上加入来源类型、成功、人工纠正、回报、价值、优势与 adv_ind。先用小数据跑通 round-trip：保存 → 加载 → 合并 → 再保存，确认类型、长度与 episode 边界不变；特别检查 demo 与 rollout 中 correction 没有被一个含义含混的 intervention 值合并。

6.3 独立完成 Value 训练与可视化

训练 Value VLM 后，不要只看交叉熵。抽取成功、失败、发生错误、发生恢复四类 episode，把预测价值画成时间曲线。按每步 −1 的成功回报，成功轨迹在接近完成时通常应趋近 0；错误后下降、恢复后回升是有用的诊断现象，但不是每帧都必须单调，也不是论文给出的充分正确性判据。还应检查回报校准、成功/失败排序和分任务误差；若这些诊断没有意义，就不应进入优势标注阶段。

6.4 先离线计算连续 Advantage，再决定阈值

保存每帧 V_t、N 步奖励、V_{t+N} 与连续 Advantage。按任务画分布，再选使目标比例为正的阈值；不要用全任务共享的固定 0 阈值替代论文的任务相关分位数。

6.5 把优势条件接进 tokenizer 与 loss mask

用合成 batch 验证条件的位置与 mask：若按主文实现，子任务 token 的 loss 不应依赖优势条件，FAST 与连续动作应依赖；30% dropout 只移除条件，不应丢掉样本本身。若选择按附录 C 的形式让子任务也条件化，必须显式标记为另一种解释并单独做消融。

6.6 第 0 轮只做离线回归与 A/B 部署

用同一批示范与 rollout 训练：普通 SFT 基线、优势条件策略两组。部署时两组使用相同观测、归一化、去噪步数与动作执行器。先验证 positive 条件不降低安全性，再进入人工介入采集。

6.7 每轮累积数据，但从预训练检查点重训

把 D_0 ∪ … ∪ D_k 作为第 k 轮数据，Value 从 Vpre、策略从 πpre 初始化。保存每轮数据 manifest 与阈值；这样才能复现实验，也能在某轮异常时回退。

七、接近代码的训练骨架

下面是结构伪代码，用于检查模块与数据依赖，不是可直接运行的官方实现：

# pre-training / initialization
V_pre = train_value(
    init=value_pretrained_vlm,
    data=D_demo,
    bins=value_bins_from_explicit_project_config,  # bounds are not published
)
D_demo = attach_pretraining_advantage_labels(
    data=D_demo,
    value_model=V_pre,
    return_convention=declared_and_tested_convention,
    # Paper says N=T but prints sum_{t'=0}^{T}; do not hide this ambiguity.
    threshold=per_task_quantile(
        D_demo,
        positive_fraction=pretrain_fraction_by_task(default=0.30),
    ),
)
pi_pre = train_policy(
    init=pi05_or_available_base,
    data=D_demo,
    condition_dropout=0.30,
    losses=(subtask_ce, fast_ce, flow_matching_with_declared_alpha_eta),
    knowledge_insulation=True,
)

for task in tasks:
    D_task = demonstrations_for(task)

    for k in range(num_iterations + 1):
        # Paper Algorithm 1: restart from pre-trained checkpoints.
        V_k = train_value(init=V_pre, data=D_task)

        threshold_k = estimate_task_threshold(
            data=D_task,
            value_model=V_k,
            target_positive_fraction=task_specific_fraction,
        )
        D_labeled = attach_advantage_labels(
            data=D_task,
            value_model=V_k,
            horizon=50,
            episode_tail_rule=declared_and_tested_tail_rule,
            threshold=threshold_k,
            force_human_corrections_positive=True,
            correction_field="human_correction",
        )

        pi_k = train_policy(
            init=pi_pre,
            data=D_labeled,
            condition_dropout=0.30,
            losses=(subtask_ce, fast_ce, flow_matching_with_declared_alpha_eta),
            knowledge_insulation=True,
        )

        if k == num_iterations:
            break

        new_episodes = deploy_and_collect(
            policy=pi_k,
            inference_condition="positive",
            keep_successes=True,
            keep_failures=True,
            allow_human_corrections=True,
        )
        D_task = union_with_manifest(D_task, new_episodes)

这段骨架刻意不填 learning_rate、batch_size、C_fail、分箱边界与动作块长度，因为这些量没有在 π0.6/π*0.6 官方材料中完整公开。把社区仓库的默认值填进去可以形成实验配置，但配置文件必须标明来源是哪个仓库、哪个 commit，而不是写成「论文参数」。

九、实现完成前必须通过的验证门禁

数据门禁

episode 长度、frame 数、介入区间、成功标签与动作对齐；重标只写副本或 sidecar。

Value 门禁

201 logits、交叉熵可下降；分任务校准与成功/失败排序可解释；曲线无跨 episode 泄漏。

Advantage 门禁

N=50 窗口正确；连续值可复算；每任务阈值与正样本比例可追溯；纠正帧全部为正。

条件门禁

positive、negative、dropout 三路都有样本；条件位于子任务之后；推理不发生随机丢弃。

梯度门禁

flow loss 不更新策略 VLM 主干；文本/FAST/共训练仍能更新主干；若 Value 采用独立模型，检查参数与优化器无意外别名。

闭环门禁

每轮数据 manifest、初始化检查点、阈值、策略版本与部署结果一一对应，可回退且可复跑。

9.1 不要只盯着一个总 loss

训练日志至少分开记录 value_ce、subtask_ce、fast_ce、flow_loss、正负样本数、条件/无条件路由数、Value 预测熵与 Advantage 分位数。总 loss 下降并不能证明：价值排序正确、条件被模型使用、KI 的 stop-gradient 生效或部署行为变好。

9.2 最小 A/B 矩阵

组别 训练数据 条件 用途
A 原示范 无 π0.5 SFT 基线
B 累积数据 无 区分「更多数据」本身的收益
C 累积数据 positive/negative 训练，推理 positive RECAP 条件收益
D 与 C 相同 推理无条件 检查模型是否真的使用条件
E 与 C 相同 中等 CFG 只在 β=1 稳定后评估附加收益与激进行为

十、五种常见的“看似完成、实际缺模块”

  1. 只有 adv_ind 字段，没有 Value VLM。 若标签来自 success 或人工规则，只能称为启发式条件训练。
  2. 只有 Value loss，没有逐帧曲线与排序检查。 201 类交叉熵下降不等于动作排序可用。
  3. 只训练 positive 数据。 这会退化为筛选后的行为克隆，丢失 RECAP 对失败数据的利用方式。
  4. 冻结整个 VLM 并称为 Knowledge Insulation。 官方 KI 只截断连续动作专家到主干的梯度，主干仍从其他目标更新。
  5. 循环脚本能跑完，但每轮续训上一轮权重。 这是可研究的变体，不是论文 Algorithm 1。

十一、与本站现有项目的接口建议

对已经跑通的自定义双臂 openpi π0.5 项目，最稳妥的迁移单位不是「换整个仓库」，而是六个窄接口：

接口 保留现有项目 新增内容
数据转换 相机键、状态/动作维、norm stats、delta/absolute 约定 episode 结果、介入段、value/advantage 字段
策略 已验证的 π0.5 checkpoint 与动作解码 advantage token、dropout 与 loss mask
Value 图像与 prompt 预处理可复用 建议独立管理的 201-bin 网络、优化器与训练脚本
标注 episode 索引与时间戳 N 步优势、任务阈值、强制纠正为正
部署 policy server、控制周期、安全限幅 固定 positive 条件；可选 CFG
实验管理 现有日志与 checkpoint 每轮 manifest、Vpre/πpre、阈值与数据版本

这样做能把 RECAP 风险限制在新增模块中；任何性能变化都可以追溯到某个接口，而不是同时更换底座、数据格式、动作定义与部署栈。
