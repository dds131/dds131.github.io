openpi-RLT ③：实机运行架构与代码映射

拆解冻结特征服务、在线 Actor-Critic、Replay、Rollout、控制端与 VR 接管的进程隔离、数据契约、动作形状和相对源码映射

总览 三阶段 RL-Token 运行架构 E-2 / F / G L4 在线训练 工程修复 结果与归因
Frozen feature serviceOnline learnerSingle robot owner

大模型、在线学习与真机控制分成三条隔离泳道；它们只通过有形状、有单位、有来源语义的接口通信。

三条硬边界

ROBOT

唯一连臂进程

其他服务不能绕过控制端直接发动作，安全状态与夹爪状态才有单一真相源。

VR

唯一 SDK 初始化者

避免手柄状态、相机所有权和接管状态被多个进程争用。

ENV

数值依赖进程隔离

控制域与 OpenPI/JAX 域的数值库版本不同，使用协议隔离而不是强行混装。

一条在线数据闭环

读取观测

三路相机、七关节和夹爪状态组成当前观测。

冻结特征服务

冻结 VLA 产生 50×8 reference，冻结 RL-Token encoder 产生 z_rl[2048]；decoder 不在请求路径上。

Actor 生成动作

输入 z_rl、八维 proprio 和 reference，直接输出完整 10×8 动作块，不做显式残差相加。

安全执行

Rollout 先做动作整形；唯一控制端再负责状态机、夹爪、动作是否落地和人工接管。

构建 Replay

先保存逐步观测、实际动作、source、reward 与 next observation；episode 结束后组装 transition，并补算接管期缺失特征。

在线更新

Learner 采样 Replay 更新 Actor 与 Twin Critic，再向 Actor Service 发布带版本号的参数；rollout 同步记录所用版本。

数据契约

接口 / 字段 形状 / 值 语义不变量
state / proprio 8 七个关节角 + 夹爪观测；夹爪与关节不是同一物理量
z_rl 2048 冻结 Stage-1 encoder 输出
ref_chunk 50 × 8 冻结 VLA 的完整参考动作
actor chunk 10 × 8 在线 Actor 的完整候选动作，不是 reference + residual
action representation 7 delta + 1 absolute 七关节相对同一当前状态；夹爪是绝对指令档位
source BASE / HUMAN / MIXED 按逐步实际控制权归因；混合 chunk 不伪装成纯策略样本
reward / done step reward ∈ {0,1} 首次成功步为 1；成功、失败、手动结束或超限均可终止 episode

三个时钟不能混用

时钟 频率 / 周期 控制什么
控制端内环 110 Hz 从单槽取目标、平滑下发、状态机与 VR 仲裁
Rollout 动作步 10.5 Hz 每个 action step 的请求、执行记录与观测对齐
10 步执行块 名义 $10/10.5\approx0.952$ s 一次 actor chunk 的执行 horizon
项目实测 chunk 周期 约 1.03 s 在名义时长上叠加推理、通信、调度与观测重取

因此，1.03 秒是运行记录中的 wall-clock 测量，不是用 10.5 Hz 直接换算出的理论值。跨进程 /step 只提交目标，动作是否真正落地还必须由控制端回传的状态确认；否则格式正确的 $(s,a,s’)$ 也可能因果错误。

推理耗时：只比较同一测量边界

探针 样本数 min / p50 / p95 / max 测量边界
基础 VLA 内存探针 60 101.0 / 103.7 / 106.4 / 108.3 ms 已加载模型的一次 VLA 推理；不含相机、网络和机械臂

10 步 Actor chunk 配置 10 步 × 10.5 Hz，名义 0.952 s 执行 horizon，不是神经网络推理耗时

L2 验收时记录的显存峰值是 12,697 / 16,376 MiB。该值证明当次服务能在目标显存内运行；它不能预测并发 Learner、控制 IK 或其他 JAX 进程加入后的资源竞争。

动作块如何插值和执行

action_chunk.py 不是把 10 个点在 110 Hz 下逐点硬切换，而是使用时间索引

\[i(t)=(t-t_0)\times 30\times0.35=(t-t_0)\times10.5.\]
参数 当前值 作用
fps 30 reference waypoint 的基础时间尺度
speed_scale 0.35 把动作时间尺度降到 10.5 action-step/s
Actor chunk 长度 10 名义执行 horizon 为 0.952 s
控制内环 110 Hz 在两个相邻关节 waypoint 之间持续取样并下发

对七个关节，执行器先取 $i(t)$ 左右相邻的 waypoint，再按小数部分做线性插值；超过 chunk 尾部后保持最后一个目标。夹爪不做连续线性插值，而是选最近 waypoint 后量化到 {0, 0.5, 1}，避免在开合语义上产生没有训练含义的中间漂移。随后目标还要经过软限位、限速、加速度限制与 EMA；完整顺序见工程修复记录。

验证命令：先假链路，再真特征服务

本节命令都不连接机械臂：L1 使用假特征与假机器人，L2 只加载冻结模型并验证服务。变量名表示本地路径或解释器，网页不公开机器地址、容器名和私有绝对目录。只有完成这些层级，才进入 E-2 真机采集。

离线单测与 L1 全假链路

bash "$RLT_ONLINE/tools/run_offline_tests.sh"
bash "$RLT_ONLINE/control_side/run_control_side_selftest.sh"
bash "$RLT_ONLINE/tools/run_l1_fake_chain.sh" 4
命令 / 参数 作用 通过时能证明什么
run_offline_tests.sh 运行项目离线测试集；完成记录的口径为 243 项通过。 数据契约、补丁和工具的离线回归通过；不证明模型或真机有效。
run_control_side_selftest.sh 检查策略代理、三点动作块、安全闸、超时、关闭与控制 HTTP 契约。 控制侧接口在假后端上自洽；不覆盖真实编码器与物理反馈。
run_l1_fake_chain.sh 4 用假 Machine A、假机器人跑 4 条 episode。末尾位置参数就是 episode 数。 Replay、四类 source、drop、Learner 更新和进程退出均能连通；该次训练结果不保留。

L2 冻结特征服务

cd "$RLT_ONLINE/openpi_side"

# 快速配置自检：不加载权重、不占显存、不起服务
PYTHONPATH="$OPENPI_SITE_PACKAGES" \
JAX_PLATFORMS=cpu \
CUDA_VISIBLE_DEVICES= \
"$OPENPI_PYTHON" serve_rm75_rlt_policy.py \
  --ckpt "$RLT_CKPT" \
  --selftest \
  --noise-seed 1234

# 完整 L2 验收：脚本自己依次启动、验证并停止 :8901 / :8903
bash "$RLT_ONLINE/tools/run_l2_verify.sh"

PYTHONPATH="$OPENPI_SOURCE/src:$OPENPI_SOURCE/packages/openpi-client/src:$OPENPI_SITE_PACKAGES" \
"$OPENPI_PYTHON" "$RLT_ONLINE/tools/compare_vla_weights.py" \
  --rlt-ckpt "$RLT_CKPT" \
  --bc-ckpt "$BC_CKPT"

run_l2_verify.sh 自己管理两趟服务的端口、PID 和显存释放。运行它之前不能预先常驻 serve_rm75_rlt_policy.py：验证脚本发现本项目推理服务仍在运行时会拒绝启动。完整 L2 通过后，如需进入长期服务阶段，再单独运行：

cd "$RLT_ONLINE/openpi_side"
PYTHONPATH="$OPENPI_SITE_PACKAGES" \
XLA_PYTHON_CLIENT_PREALLOCATE=false \
"$OPENPI_PYTHON" serve_rm75_rlt_policy.py \
  --ckpt "$RLT_CKPT" \
  --port "$FEATURE_PORT" \
  --mem-fraction 0.74

这是一条前台常驻命令，会持续占用当前终端和指定端口；停止该服务并确认显存、端口释放后，才能重新运行 L2 验收。

参数 / 环境项 作用 预期效果或边界
PYTHONPATH 把 OpenPI 源码、client 包与对应 site-packages 放入当前进程导入路径。 只影响这一条命令；不能把控制域与 OpenPI 域合并成同一常驻进程。
JAX_PLATFORMS=cpu + 空 CUDA_VISIBLE_DEVICES 强制自检走 CPU 且看不到 GPU。 自检不会抢占训练卡；也不测 GPU 推理时延。
--ckpt 指定含 vla 与 rlt_module 的 Stage-1 checkpoint。 路径错时应在启动期失败，不能静默回落到通用底模。
--selftest 只检查上游常量补丁、配置派生、norm stats 与噪声构造。 它不加载权重、不执行真实推理、不启动服务，因此不能代替完整 L2。
--noise-seed 1234 固定噪声构造种子。 selftest 只验证噪声能够按该种子构造；真正的跨服务输出比较由 L2 脚本完成。
XLA_PYTHON_CLIENT_PREALLOCATE=false 关闭 JAX 默认一次性预占显存。 给同机 Actor 等进程留下显存；不等于禁止 JAX 使用 GPU。
--port 绑定冻结特征服务的本地端口。 必须与客户端配置一致，并保证没有第二个进程占用。
--mem-fraction 0.74 把该服务的显存使用比例限制为 0.74。 本项目实测约占 12.7 GiB；该值是当前设备口径，不是跨硬件常数。
run_l2_verify.sh 依次检查 z_rl 非零且不塌缩、ref_chunk 与现役 VLA 对齐、显存余量和推理延迟。 脚本自己启动并停止两趟服务；通过只表示 Machine A 满足这四项，不表示 Actor 已安全上机。
compare_vla_weights.py 用 --rlt-ckpt 与 --bc-ckpt 逐张量比较两份 VLA 权重。 必须阅读 [cmp] 汇总；该工具用于归因，不应只凭退出码当作自动放行闸。

长期服务就绪的关键日志是 z_rl=(2048,)、ref_chunk=(50, 8) 与 Creating RLT server 三项同时出现。只看到端口可连接而没有形状证据，不能判定模型契约正确。

为什么用运行时补丁

三个补丁分别负责七维 delta、七维 delta 正则和人工接管段回溯丢弃。它们在进程启动时加载，减少对上游底层源码的修改范围，也更容易回退。

这种做法也引入新的风险：开关漏设时，程序可能仍能启动却悄悄退回六维口径。因此“补丁已加载”和“delta_weight 偏差 0.00%”必须作为启动期证据，而不是依赖操作者记忆。

快照一致性边界

项目曾同时存在训练活跃副本和较早的部署快照。页面中的每个实测结论都绑定实际使用的 checkpoint、配置与运行记录；不能因为目录同名，就假设两份代码逐字一致。

本页只公开相对模块职责，不公开私有工作副本、内部端点或运行命令。公开仓库结构与本项目使用快照可能随时间演化，复现时应先完成版本审计。

训练与控制为什么分开

接管期清空旧 plan、暂停 planner，并在交还后保留冷却窗口，避免陈旧块回放或特征推理干扰控制端的 110 Hz 内环。逐步观测与人工实际动作仍被保存；episode 结束后再由冻结服务补算缺失的 z_rl 与 reference。这让“人工控制实时性”和“Replay 字段完整性”同时成立，但前提是交接窗口、未落地动作和显式丢弃段不进入 Replay。
