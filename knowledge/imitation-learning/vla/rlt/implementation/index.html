RL Token / Stage 1 等价性审计

论文 Eq. (1)/(2) 的等价性不是“都有 MSE”。必须逐项追踪 z_{1:M}、learned e_<rl>、encoder 输出 z_rl、decoder prefix [z_rl, stopgrad(z_{1:i-1})]、teacher forcing、因果 mask、逐 token reconstruction、reduction/normalization、可选 VLA loss α、optimizer groups、冻结参数和 checkpoint/resume 内容。

RLinf issue #1391 于 2026-07-17 针对 commit 5769c6ebaa2c86e9ab37cc6ceb0d6b7168f67d70 报告：decoder 使用 learned prefix queries，且 attention 未提供 causal mask；维护者回复实现与论文没有完全对齐并计划比较。2026-10-16 公开页面仍显示 open。它是可信的公开风险报告，但不是本站独立确认的 bug，也不能证明目标快照 fccbb19... 已修复或仍相同；本页状态因此是 open-risk / target-snapshot re-audit required。

Yyshadow 与 yknxh README 均声称有 RL-token/Stage 1 路径；这只支持 C0。要升到 C1，必须在固定提交确认 token 源、attention/mask、teacher forcing、stop-gradient、loss reduction、α、updated/frozen 集合、norm/data/action manifest 和 checkpoint receipt。若实现采用 parallel query、masked MSE 或 non-autoregressive reconstruction，应标 implementation-variant，不能用“目标都是重建”抹平差异。

Actor-Critic、Replay、人工与发布审计

Stage 2 必须把 actor 的 z_rl/proprio/reference、Gaussian mean/std 与 sample/mean inference、direct/residual/latent parameterization，和 critic 的 Twin-Q、target actor/critic、smoothing、chunk return、gamma^L/gamma^C、terminal/bootstrap、actor Q aggregation 分开。论文未指定的 actor aggregation 或 target details 属于 implementation-defined，不同仓库的 gamma=0.96/0.99 只属于各自配置，不能写成官方 RLT 参数。

Replay 的 Bellman truth 必须是实际执行动作，而非计划动作或原始 reference。审计还需同时保存 raw/commanded/safe/executed、original/condition/BC references、reward revision 与 label event、termination/bootstrap cause、policy/feature/action/safety versions、parent trajectory、overlap/split group、content hash 和 lifecycle pending/committed/quarantined/invalidated。README 写有 ReplayBuffer 不证明这些字段存在或 round-trip 成立。

human reward、corrective intervention、phase switch 和 safety stop 是不同事件与角色。第三方 progress +0.5 只能标 extension/non-paper 和新 reward revision；不得与论文稀疏终局奖励结果混报。键盘映射不是安全授权。checkpoint save 也不是发布：candidate/active、不可变 hash、性能与安全 gate、chunk-boundary activation、worker ack、rollback pointer、incident quarantine 缺一都必须显示 gap。

  X --> R["versioned Replay"]
  R --> L["critic / actor learner"]
