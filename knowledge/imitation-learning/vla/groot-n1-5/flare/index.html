FLARE 问题定义与 Future Token 机制

FLARE让策略继续输出动作，同时用额外token的内部表示预测未来观测的紧凑视觉语言表示，而不是让动作主干直接生成高保真未来像素。未来图像仍是target encoder输入，像素没有从数据链消失；精细接触、透明/反光物体、遮挡和微小几何仍可能依赖局部细节。因此“降低生成负担、聚焦任务变化、提供隐式世界建模信号”是设计动机，不是未经消融的速度或普遍收益结论。

flowchart LR
  O[当前观测与状态] --> P[策略编码器]
  S[状态 token] --> D[动作 DiT]
  P --> D
  F[M=32 learned future tokens] --> D
  A[带噪动作 token] --> D
  D --> H[内部层 future 表示 B×M×D]
  H --> PP[两层策略投影器]
  N[未来图像 + 文本] --> T[EMA target encoder]
  T --> TP[目标投影器]
  PP --> C[逐 token 余弦对齐]
  TP --> C

文本回退：策略侧把状态、learned future tokens和带噪动作送入DiT，从显式内部层切出B×M×D的future表示，经两层投影；目标侧把未来图像和文本送入EMA teacher并投影；两侧按对应token做余弦对齐。future token既不是未来图像输入，也不是像素输出，没有公开“第m个token=固定未来时刻/对象”语义；策略与目标token数必须匹配。

内部层、余弦对齐与总损失

论文从DiT内部层L的全序列 H^(L)∈R^{B×Q×D} 切出 H_f^(L)∈R^{B×M×D}，不是默认取最终输出；两层策略投影器和目标投影器把对应token映到同一宽度K。论文主实验在8层DiT取第6层；N1.5是8个cross+8个self交替block，不能用6/8=12/16把论文第6层映射成公开第12层。Training/Source Code必须显式登记hidden-state index、future slice start/length和target width。

L_align = mean_valid[1 - cosine(z[b,m], stop_gradient(g[b,m]))]
L_total = L_fm + lambda * L_align,  lambda = 0.2

上式的mean-valid只是实现性展开，不冒充论文唯一reduction；实现还必须定义norm epsilon、valid-token mask、sample-loss mask、有效分母和空分母行为。1−cos在忽略epsilon时只约束方向而非范数，对z正比例尺度不变，梯度与z正交；改成−cos只差常数1、梯度相同，但日志零点和阈值不同，不能无说明混用。

FLARE论文与N1.5官方预训练/后训练都给λ=0.2，只证明系数值一致，不证明reduction、batch mixture、target encoder、EMA、hidden layer或optimizer相同。Training须分别记录L_fm和L_align有效分母后再组合。

Flow Matching 符号冲突与查询切片

论文定义 A_τ=τA+(1−τ)ε，解析导数是 A−ε；正文主公式却写 ε−A，而附录Algorithm 1和公开N1.5源码使用 A−ε。这是论文内部符号不一致，不能静默修正，也不能归因于FLARE辅助项；复现必须把interpolation、velocity target和Euler update作为同一方向合同。

论文叙述query为state→action→future；公开N1.5实际为state→future→action。设state token数S、future数M，公开future slice只能写 [:, S:S+M]；[:,1:1+M]只在S=1时成立，[-M:]会落到动作段。实现应以命名offset生成区间，并验证三段不重叠与总长度守恒。

对象 已知 未知/门禁
论文层 8层DiT；主设定第6层 不能比例映射N1.5
公开block 8 cross + 8 self 论文层到block类型映射未知
hidden list index0为DiT输入；index L为第L个block后 公开return_all_hidden_states=false且注释not using flare now

动作感知 Target Encoder 与数据口径

目标编码器以SigLIP2-Large-Patch16-256为视觉语言底座，输入未来图像和文本；视觉/文本token经过4层fusion Transformer，再由32-query Q-former压成32个目标token。它称为action-aware，是因为预训练附接8层动作DiT任务，使表示保留控制相关变化；每次FLARE目标编码不必执行该动作DiT。策略视觉语言编码器由预训练目标模型初始化；目标侧在当前反向中stop-gradient并作为EMA teacher慢速更新，不能简写成普通冻结SigLIP2。

256×256输入配合patch16，名义视觉token为16²=256；文本补齐32，名义fusion序列288，再由32个learned query压缩。该算术假设没有额外special token；Q-former深度、宽度、头数、位置编码和完整投影未披露，不能用BLIP-2默认值填空。

目标编码器预训练时长在论文本身有冲突：主文约2,000小时，附录分项合计2,989.5小时/169.5M frames，差989.5小时，附录合计约为主文概数1.49475倍。两者都保留；2,989.5不能冒充去重后精确有效时长。训练报告256张H100、global batch8192、150,000 steps，派生名义样本呈现1,228,800,000；这不是唯一视频/帧数，也不能反推per-device batch、墙钟或GPU小时。

消融、EMA、层选择与伪代码边界

成功率与相对无FLARE的绝对百分点
目标表示 成功率 提升
无FLARE 43.9 基线
SigLIP2原始256 token 49.6 +5.7 pp
2×2平均池化64 token 50.9 +7.0 pp
action-aware 32 token 55.0 +11.1 pp；较池化+4.1 pp

表只支持“通用目标也有效，特定协议下action-aware最好”；约7%应读为约7个百分点，不是相对百分比，更不能外推所有任务普遍最优。

EMA意图为 θ_target ← ρ θ_target + (1−ρ) θ_policy。论文比较ρ∈{0.99,0.995,0.999,1.0}，0.995最好并用于实验；1.0即teacher冻结仍优于无FLARE，0.99最差，作者归因更新过快不稳定。只能称慢速目标有稳定作用，不能称已证明防坍塌。实施时先完成当前batch前向/反向和policy optimizer step，再在no_grad中EMA一次；teacher不进optimizer、不累积梯度，checkpoint需保存policy、teacher、ρ和EMA步数。

论文Algorithm 1是说明性草图：target自加载自身state dict为空操作、漏写EMA、最终输出切future与正文内部层L冲突、future embedding未显式batch扩展，并有hiddem_dim/prioprioceptive拼写、state/proprio命名和M歧义。可保留正确的A−ε、1−cos和双损失控制流，但不能用修正版伪代码填补mask、归约、Q-former深度或N1.5层映射。

FLARE策略实验是32张H100、global batch1024、80,000 steps，名义样本呈现81,920,000；target encoder预训练则是另一套256 H100/8192/150,000配方，AdamW β=(0.95,0.999)、eps=1e-8、weight decay1e-5、warmup0.05。两套配方不能拼成一次运行；N1.5 Research只公开λ，不公开L、ρ、target encoder或sample routing。

无动作人类视频：Loss Mask 与外推边界

机器人样本有action、proprio和未来帧，可计算Flow Matching与alignment；人类第一视角视频只有当前/未来视觉和文本语义，没有机器人动作/本体状态，只能计算alignment。实现必须使用逐样本flow-sample-mask与alignment-sample-mask，禁止给人类视频伪造零动作后送入Flow MSE。

仍未知的接口包括：query占位、missing proprio编码、视频/机器人视角对齐、帧率到future gap映射、robot/video采样比、source loss weight和文本模板。Training必须对这些字段fail closed，不能用默认猜测补齐。

论文实验含5个新对象，每对象150条人类示范，共750条；机器人示范最多每对象10条，共最多50条。每对象1条机器人轨迹时报告最高60%，加入人类视频并使用每对象10条机器人轨迹时80%，作者描述为roughly doubles baseline。60%与80%对应不同机器人数据量，不能相减为纯人类视频因果增益，也不能外推“人类视频普遍替代机器人动作数据”。

N1.5 公开结构、专用 Loss 缺失与补全门
