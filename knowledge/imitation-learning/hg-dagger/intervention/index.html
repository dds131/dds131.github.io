专题总览 1 Foundations 2 Intervention 3 Risk 4 VLA Pipeline

“人看到要出错就接管”还不是可执行协议。系统必须分别记录接管请求、底层控制权确认、实际执行来源、恢复区间和归还确认；任何一步无法确认时，都不能假设人或策略已经安全接管。

风险边界：人工接管是数据采集与风险缓解机制，不是安全保证。本页状态机是工程模板，实际系统仍需独立安全层、平台级验证和人工授权。
必需先修：Foundations——gate、允许集与恢复数据

干预信号与职责：谁发现问题，谁真正控制

原论文事实与工程扩展

原始 HG-DAgger

novice 先运行；人观察到不允许状态后取得排他控制，连续恢复至安全稳定区域，再主动归还；恢复期间收集专家动作。

本站工程协议

请求/确认、过渡态、队列取消、稳定窗口、时钟同步、日志、异常停止和低层 authority 是落地扩展，不是原论文固定 API。

原论文明确提醒：若人不能快速识别并响应不安全情况，方法不适合直接用于相应真实领域。人工监督不能替代独立限位、急停、碰撞监控或平台已验证的安全功能。

干预信号的来源与语义

信号 发出者 意义 方法身份 协议处理
human_takeover_request 人类操作者 要求立即取得控制 概念上对应原始人工 gate 最高优先级正常接管请求
human_return_request 人类操作者 认为已恢复，可准备归还 概念上对应人工归还 只进入准备态，不等于已归还
emergency_stop 人或独立安全装置 要求进入平台安全停止 工程安全层 抢占全部普通状态
safety_monitor_trip 独立监控器 超限、碰撞、通信或硬件故障 工程扩展 进入安全降级，不定义 HG 标签
model_risk_signal 策略或风险模型 代理风险或不确定度 不是原始人工 gate 只作辅助信号，规则留给 Risk
episode_end / reset 环境或操作员 终止回合或要求重置 通用系统事件 封闭片段并记录原因

风险分数触发规则不在本页制定。任何触发器若要改变控制权，都必须通过同一个 authority 协议并记录来源。

责任分解

组件 / 角色 主要责任 明确不负责
人类监督者 观察、请求接管/归还、执行恢复、必要时急停 不保证零延迟、全状态可见或永不漏判
操作界面 / 输入适配器 采集按钮与遥操输入，显示请求和确认 不能单独决定执行器实际 authority
Authority Arbiter 仲裁来源、生成 transition ID、等待底层确认 不生成任务动作，不推断训练标签
Policy Executor 产生策略动作、管理 chunk / 缓存、响应取消 接管后不得继续提交旧计划
Human Command Adapter 把设备输入映射到约定动作空间 不丢弃原始命令或标定版本
Low-level Controller 执行仲裁动作，反馈实际来源与状态 不能把收到请求当作已经切换
Independent Safety Layer 限位、故障处理、急停与安全降级 不能由 imitation loss 或 uncertainty 取代
Logger / Recorder 同一时基记录观测、请求、确认、执行与版本 不能推测缺失的 authority 或时间戳

控制优先级只是工程模板

概念优先级为：emergency / independent safety > confirmed human control > validated novice control。这是 fail-safe 仲裁模板，不是原论文公式，也不能代替具体平台安全分析；已有经验证的仲裁与停止契约应覆盖本模板。

控制权状态机：请求、确认、恢复与异常路径

六态定义

状态 允许的主控制者 HG 专家标签 正常出口
NOVICE_CONTROL novice，经独立安全层约束 否 接管请求、故障、回合终止
TAKEOVER_PENDING 平台验证的过渡策略；逐帧记录来源 默认否 人控确认、取消、超时或故障
HUMAN_RECOVERY 已确认的人类动作通道 满足契约时是 归还请求、急停、回合终止
RETURN_PENDING 默认保持人控或平台安全保持 默认否 策略恢复确认、取消、超时或故障
SAFE_STOP 平台验证的停止 / 保持机制 否 人工复位后新回合或终止
TERMINATED 无任务动作 否 新回合需重新初始化

两个 pending 状态不绑定固定控制器：平台可能继续人控、制动或 hold。必须逐样本记录 executed_source，不能根据状态名推断实际来源。

状态转换表

当前状态 事件 / 守卫 必做动作 下一状态 失败处理
NOVICE_CONTROL 人触发接管 冻结提交、取消未执行计划、分配 intervention ID TAKEOVER_PENDING 无确认则 SAFE_STOP

任意活动态 成功、不可恢复失败或人工结束 记录终止原因，封闭 episode TERMINATED 缺失终止记录视为数据错误

  participant P as policy queue

  participant R as logger

  A->>R: event request + transition_id
  A->>P: invalidate pending policy actions
  P-->>A: queue invalidated
  A->>L: request authority = HUMAN
  L-->>A: confirmed source = HUMAN

  A->>R: authority_confirmed_ts
  H->>L: canonical human action
  L-->>R: executed_source + execution_ack

图 2｜接管请求—确认时序。 策略队列取消与底层 authority 确认是两种确认；首条专家标签只有在实际执行来源可证明后才有效。实现可以并行降低延迟，但不能合并事件语义。

状态机不变量

  • 每次迁移有唯一 transition_id、请求者、原因、请求时间、确认时间和结果。
  • 重复请求幂等，不因网络重试产生并行 intervention。
  • 同一执行周期至多一个 authoritative action source。
  • control_authority、selected_action_source 与 executed_source 不一致时触发错误。
  • 每个 pending 状态都有来自平台验证配置的超时出口。
  • 人工接管和急停始终可以抢占普通冷却、自动归还与策略恢复。

迟滞、冷却与退出：避免边界抖动和错误交还

接管与交还必须非对称

维度 接管 交还
决策倾向 更敏感，允许提前 更保守，需要持续稳定
主要责任 人类 gate；其他信号按系统协议辅助 人主动请求并确认
状态依据 趋势、任务语义、环境和可恢复性 稳定、故障清除、观测新鲜、策略就绪
时间要求 尽量低延迟 稳定窗口与协议确认
失败默认 SAFE_STOP 或平台验证保持 继续人控或 SAFE_STOP

“更敏感 / 更保守”只是方向，不是固定阈值。距离、速度、时间和次数都要在目标平台验证并版本化。

交还守卫

归还 novice 前至少核对：

  1. 人主动发出 return request 且未撤销。
  2. 连续稳定窗口内满足可继续条件。
  3. 无急停、硬件、通信、碰撞、限位或 watchdog 故障。
  4. 策略旧动作与旧 chunk 已全部失效。
  5. 最新观测处于 freshness budget，输入同步有效。
  6. 新策略输出满足当前 I/O contract 的 shape、unit、frame、range 和 validity。
  7. 底层可以原子切换，人收到可感知确认。

任一条件失败就保持人控或进入 SAFE_STOP，不能为完成回合自动降低门槛。

迟滞、稳定窗口与冷却

  • 状态迟滞：接管与交还用不同条件，避免同一边界来回切换。
  • 时间迟滞：交还条件连续满足经验证的稳定窗口，不以单帧为准。
  • 交还冷却：最短恢复阶段内禁用自动归还，但不禁止急停或人继续控制。
  • 恢复后观察窗：策略恢复后加强监控，但不阻止人再次接管。
  • 重复干预计数：短时间反复接管达到配置门槛后停止或重置，不无限尝试。

页面不提供通用秒数或阈值；所有参数使用命名配置并记录 config_version。

过早、过晚与不可恢复

过晚可能已经碰撞、掉落或不可恢复，日志可用于诊断但不自动构成有效恢复示范；过早会减少风险暴露，也可能减少 novice 分布覆盖并增加人力。显示延迟可能让人看到旧状态，必须记录呈现时间；不可恢复时应终止或停止，不强行续成“成功恢复段”。任务语义已经错误但几何尚安全时也可干预，reason code 要与物理风险分开。

评估至少报告干预率、首次接管提前量、持续时间、再次接管率、不可恢复率、接管确认延迟和归还确认延迟。Risk 页可以分析这些结果，却不能反向覆盖状态机真值。

数据记录与监督标签：以实际执行来源为准

三段式 intervention window

[pre-context] [takeover pending] [confirmed human recovery] [return pending] [post-outcome]
  诊断上下文       默认非标签           核心专家标签区          默认非标签       结果评估
  • pre-context 从环形缓存解释为何接管，保留策略动作和系统状态，不伪装成人类标签。
  • confirmed human recovery 从底层确认人控开始，到核心恢复区关闭为止；只有动作契约与时间有效时进入监督标签。
  • post-outcome 判断恢复结果、再次接管与任务完成，不自动进入专家标签。
  • pending 区逐样本记录来源；若能证明人工动作已执行，可作为候选样本单独审核。

前后窗口长度是工程配置，不属于原始 HG-DAgger 定义。

最小日志 schema

字段组 最小字段 用途
身份 episode_id, rollout_id, intervention_id, step_id 保留回合、干预和时序边界
策略 / 数据版本 policy_id, checkpoint_hash, dataset_version, robot_config_id, io_contract_hash 重建产生样本的系统版本
时间 clock_domain, observation_capture_ts, operator_presented_ts, command_ts, authority_confirmed_ts, execution_ts 分离采样、呈现、决策、确认和执行
控制状态 fsm_state, transition_id, requested_authority, confirmed_authority, executed_source 以底层事实切片，不猜测控制者
策略动作 policy_action, policy_action_id, chunk_id, chunk_index, valid_until 分析模型意图和旧计划
人类动作 human_command_raw, input_device_id, calibration_version, human_action_canonical 保留原始意图与映射标签候选
实际执行 selected_action, executed_action, controller_mode, saturation_flags, execution_ack 对齐真实物理后果
观测 / 任务 observation_ref, observation_validity, task_instruction, history_ref 指向模型与人当时可用信息
干预 request_event, reason_code, return_event, recovery_outcome, label_valid 切分、审核和统计恢复质量
安全 / 终止 safety_event, fault_code, termination_reason, reset_id 区分恢复、失败、停止与新回合

示例不得出现真实主机、账户、内部地址、密钥、设备序列号或人员身份。

四条动作通道不能合并

  1. policy_action：策略原本想执行的动作，用于分析模型偏差。
  2. human_command_raw：输入设备原始命令，用于重建人类意图和设备问题。
  3. human_action_canonical：经版本化映射进入模型目标空间的动作，是常见标签候选。
  4. executed_action：经仲裁、限幅、滤波、逆解或低层控制后真正生效的动作，用于物理后果和安全审计。
if confirmed_authority != HUMAN:
    label_valid = false
elif observation invalid or action mapping invalid:
    label_valid = false
elif model target space == canonical human command space:
    label = human_action_canonical
elif model target space == executed action space and contract explicitly says so:
    label = executed_action
else:
    label_valid = false

不能因为 executed_action 最接近物理真值就无条件作为训练目标，也不能把设备摇杆值直接喂给预测关节增量的模型。

时间对齐与因果关系

  • t_capture：传感器采集观测。
  • t_present：该观测真正呈现给操作者。
  • t_command：操作者产生命令。
  • t_confirm：authority 切换获底层确认。
  • t_execute：动作实际进入执行器。

监督输入应对应操作者形成命令时可见的信息，通常满足 t_capture ≤ t_present ≤ t_command。动作物理后果只会在 t_execute 后出现，不能把执行时刻或之后才出现的画面作为该命令的因果输入。

所有时间戳必须声明 clock domain 并记录同步质量；对齐策略版本化，原始时间戳不被离线重采样覆盖；显示、输入、网络和执行器延迟分开统计；无法可靠重建时设 label_valid=false，不以最近帧静默填充。

数据质量检查

  • 同一时刻是否出现多个 confirmed authority。
  • HUMAN_RECOVERY 中是否仍有 policy 动作被执行。
  • takeover / return request 是否都有 terminal result。
  • intervention ID 是否跨 episode 或 reset。
  • 时间戳是否倒序、跨 clock domain 未同步或超出有效窗。
  • 人类映射版本、单位和 frame 是否与契约一致。
  • 核心恢复段是否缺起点、终点或 outcome。
  • 旧 chunk 在 invalidation 后是否仍有执行确认。
  • 是否把失败或急停片段误标为成功恢复。

每项输出“通过 / 失败 / 无法判断”，缺失信息不得默认为通过。

Action Chunk / VLA 扩展：旧计划取消与最新观测恢复

明确扩展身份

方法迁移 / 工程建议：原始 HG-DAgger 的自动驾驶实验没有规定 VLA token、动作块、队列、历史窗口或异步推理。以下内容是把控制权协议迁移到块状动作策略时的系统设计。

ACT Action Chunking解释预测时域、执行时域和滚动重预测；它是扩展阅读，不是 HG-DAgger 的必需先修。

动作块的四个时间量

量 含义 不得混淆
H_pred 一次推理预测的动作步数 不等于一次实际执行完的步数
H_exec 采用预测后计划执行的步数 不等于整个任务时域
f_policy 策略重新推理频率 不等于低层控制频率
f_ctrl 执行器消费动作的控制频率 不等于相机或日志频率

协议还必须知道每条排队动作的 chunk_id、chunk_index 和失效时间。

takeover 时的块取消顺序

flowchart LR
  A[人触发接管] --> B[停止发布新 chunk]
  B --> C[标记未执行 policy action 失效]
  C --> D[底层确认不再消费旧动作]
  D --> E[切换并确认 human authority]
  E --> F[记录首条实际人类动作]
  C -. 无法确认取消 .-> S[SAFE_STOP]

图 3｜接管时旧计划失效。 “立即失效”是语义要求；实际停止延迟必须测量。队列若无法确认取消，进入 SAFE_STOP，不能只修改 UI 状态。

return 时的新鲜推理顺序

flowchart LR
  A[人请求归还] --> B[关闭核心恢复标签区]
  B --> C[清空接管前策略缓存]
  C --> D[获取最新有效观测与历史]
  D --> E[按当前任务重新推理]
  E --> F[检查 action contract 与时效]
  F --> G[人确认加底层原子切换]

图 4｜归还前重新推理。 不得恢复播放接管前剩余 chunk；人类恢复已经改变物理状态和任务阶段，旧计划通常失去因果有效性。

VLA 特有数据注意点

  • 保存模型实际输入的图像集合、相机顺序、历史窗口和语言指令版本。
  • operator view 与 policy observation 分开引用，因为人和模型看到的画面可能不同。
  • 人工动作映射必须覆盖 absolute / delta、joint / Cartesian、frame、unit、rotation、gripper 与 chunk mask。
  • 接管可能发生在 chunk 中间；窗口不能跨 reset，也不能把接管前 policy 动作填入 expert target。
  • 恢复段长度不固定；padding 与 mask 配方留给 VLA Pipeline。
  • 异步 policy server 的响应必须携带 request / chunk ID，接管后到达的旧响应直接作废。

本页收束

  • 原始论文事实：人按需取得连续、排他的控制，恢复段动作进入数据，稳定后主动归还。
  • 协议不变量：请求不等于确认；标签由实际 authority 与动作契约决定；异常不能靠猜测继续。
  • VLA 工程扩展：动作块取消、最新观测重推理、历史与时间对齐需要额外实现和验证。
