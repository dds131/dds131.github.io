RLHF-VLA/三分支架构/Reward Model/PPO-RLHF

RM_PPO branch · training · objective · system

PPO-RLHF 不是一个 clipped loss，而是一份关于谁采样、对哪个动作算概率、用哪版奖励和价值目标更新、何时停止与谁有发布权限的迭代合同。

只有当 policy 对同一 MDP action、context、support、base measure 与 mask 提供可审计 log-prob，且 RM、converter、Reference、Critic、环境与安全配置均可冻结时，标准 PPO 公式才有定义。

rm_ppo branch completed here16 versioned contractstarget training/evaluation: not-run

角色快照、先修能力与迭代时钟

进入本分支前，Reward Model handoff 必须为 ready 或带可执行 limits 的 ready-with-limits；RM、converter 与 total reward composition 必须可固定。policy log-prob capability 只能是 exact-tractable | tractable-by-decomposition | estimated-with-receipt。surrogate-objective-only | unavailable | unsupported | unknown 不进入标准 PPO；不能因为模型能采样动作就假定能计算同一 measure 下的密度。

还需同时固定 Critic 的 reward/discount/termination/horizon 绑定、rollout environment 与 reset、安全 fallback、独立 task evaluator 和 release approver。缺一项都 fail closed，而不是补默认值。

role 唯一目的 何时变化 sealed batch 内
current πθ 被优化的 numerator optimizer step 后 updating
behavior πb 实际生成 rollout segment 前绑定 receipt 内冻结
old πold PPO ratio denominator batch seal 前绑定 所有 epochs 冻结
reference πref KL/行为锚点 独立 refresh policy optimization stage 冻结
Reward Model / converter preference score 与 reward 转换 独立 promotion 冻结且无 Actor gradient
Critic 指定 reward chain 下的 value Critic optimizer target 生成快照冻结
safety / evaluator / approver 执行限制、独立证据、发布授权 各自 authority 不被 optimizer 接管

behavior 与 old 即使暂时指向同一 hash，也不能合并 role ID；若二者不同，必须声明 freshness 和 correction。requested policy 不是 loaded behavior 的证据，只有实际加载收据能证明谁生成了动作。

flowchart LR
  A[select current] --> B[snapshot old · bind reference]
  B --> C[bind RM · converter · critic · env · safety]
  C --> D[authorize rollout]
  D --> E[collect immutable receipts]
  E --> F[seal PPO batch]
  F --> G[fixed rewards · returns · advantages]
  G --> H[multi-epoch updates]
  H --> I[independent evaluation + gates]
  I --> J[promote · reject · rollback]

无脚本等价顺序是：选择候选 → 快照角色 → 绑定固定制品 → 授权采样 → 收集收据 → 封存 batch → 生成固定 targets → 多 epoch 更新 → 独立评估 → promotion/reject/rollback。每个事件带 monotonic iteration ID、时间、owner、artifact hashes 与成功/失败 receipt。状态集合为 prerequisite-missing | unauthorized | collecting | sealed | optimizing | early-stopped | aborted | evaluating | promoted | rejected | rolled-back | stale | unknown；aborted 不抹除已经发生的物理与数据事实。

MDP action、概率密度与 VLA policy family

ratio 前先定义随机变量：它是 single command、whole chunk/macro-action、latent 还是 token sequence；作用域是 generated、selected prefix、commanded、post-safety 还是 executed；条件包含哪个 observation/history/prompt revision。contract 还必须绑定 support、base measure、units、frame、normalization、transform/Jacobian、tokenizer/decoder/noise/path/sampler、factorization 与 stop/pad/dimension/horizon/executed masks。numerator 与 denominator 任一字段不同，ratio 无定义。

若 macro-action 是 token 序列：

\[\log \pi_\theta(a_t\mid c_t) =\sum_{k\in\mathcal M_t} \log p_\theta(u_{t,k}\mid c_t,u_{t,<k}),\]

其中 $\mathcal M_t$ 只含属于该 MDP action 的有效 factors。token joint probability 是离散 measure 下的量；它不自动成为 decode 后连续 action 的 Lebesgue density。

若 $z\sim\mathcal N(\mu,\sigma^2)$ 且 $a_{phys}=scale(\tanh z)+offset$：

\[\log\pi(a_{phys}\mid c) =\log\mathcal N(z;\mu,\sigma^2) -\sum_i\log(1-\tanh^2z_i) -\sum_i\log|scale_i|.\]

必须保存 latent、pre/post transform action、稳定 inverse、boundary policy 与 hard clip 状态。硬 clip 是 many-to-one，不能把 clipped action 直接代回未截断 Gaussian density。mixture/hierarchical policy 还要保存 sampled mode、mode probability、conditional density 与 termination option；丢失 mode 往往不能无歧义重算 joint density。

policy family 可接受能力证据 不可直接推出
categorical / autoregressive token factor receipts、joint sum、有效 masks decode 后连续密度
squashed Gaussian latent、transform、两类 Jacobian、round-trip hard-clipped action 的原 Gaussian 密度
mixture / hierarchy mode 与 conditional joint receipt 只凭最终 action 重建 sampled mode
diffusion 固定 final-action estimator/path/error/cost receipt noise-prediction MSE 等于负 log π
flow 固定 density/path estimator 与变量映射 vector-field loss 等于 final-action log-prob

兼容性检查包括：相同 artifact 时 current/old log-prob 差在 tolerance 内为 0、ratio≈1；同一 serialized action/context/mask 可重算；token sum 等于 factor receipt；Gaussian sample→transform→inverse→log-prob 往返一致；masked/padded/unexecuted factors 贡献为 0；support violation、NaN/Inf 和数值上下溢 fail closed。

rollout receipt、sample freshness 与 batch seal

每条 transition/decision receipt 保存 episode/segment/decision/iteration IDs；requested、loaded、behavior、old、reference、RM、converter、Critic、environment 与 safety hashes；observation/context 和 adapter revisions；latent/token、generated chunk、selected prefix、commanded、post-safety、executed action；三类 policy log-prob receipt；reward components；终止/中止/接管/reset 原因；event/inference/command/execution/reward/ingest times；以及 OOD、intervention、near-miss、invalid flags。

episode 内 hot swap 必须在 decision boundary 切段并重绑 policy/context state；未记录切点时整段为 unknown。freshness 同时看 iteration distance、wall-clock age、behavior/current divergence、environment/schema revision 和 reward-chain compatibility。历史数据不能靠 PPO clipping 自动变成 on-policy；如无另立的 off-policy correction 合同，不进入该 batch。

seal 后以下内容不可变：

类别 sealed fields
决策事实 actions、contexts、valid/executed masks、factorization
denominator behavior/old log-probs、old/value snapshot outputs
学习信号 raw components、converted rewards、termination/bootstrap
targets returns、advantages、sample weights
审计 content hash、counts、slices、drop reasons、freshness、privacy authorization

partial/invalid rollout 必须保留原因：natural terminal 按 task definition；time limit 由 continuing-state semantics 决定；safety abort 独立记录；human takeover 默认在边界截断 policy credit；collector crash/sensor loss 在 next context 不可信时不可盲目 bootstrap；reset 前后不连接；delayed/censored reward 在 seal 前解决或标 unavailable，不能静默填 0。

reward chain、Reference KL 与固定目标

总奖励必须按分项保存，而不是只留一个总数：

\[r_t^{total}=\alpha r_t^{pref}+\beta r_t^{task} -\sum_j\eta_jc_{j,t}-r_t^{KL}+r_t^{other}.\]

每项带 source artifact、raw value、normalization、coefficient、weighted value、scope、mask、delay、missing behavior 与 veto semantics。critical cost 可以阻断 rollout/promotion，不能被正 reward 抵消。preference component 必须消费第 50 页固定 RM、input contract、score semantics、calibration scope 与 converter hash；out-of-support、unknown、stale、revoked 按 handoff 做 abort、exclude 或 human review，不能把 raw score 当 reward。

若 rollout 来自 behavior $\pi_b$：

\[k_t^{sample}=\log\pi_b(a_t\mid c_t)-\log\pi_{ref}(a_t\mid c_t), \qquad r_t^{KL}=\lambda_{KL}k_t^{sample}.\]

单个 $k_t^{sample}$ 可以为负；只在 $a\sim\pi_b$ 且 action/context/measure 一致时，条件期望才对应 forward KL。另一类设计把 $D_{KL}(\pi_\theta\Vert\pi_{ref})$ 或其 estimator 加到 Actor loss，梯度经过 current policy。两者的 timing、credit 和 gradient path 不同；diagnostic approx KL 又是第三种，不参与 loss。

KL 状态必须是 reward-only | actor-loss-only | both-intentional | none。both-intentional 显示两项系数、总 effective pressure、gradient paths 与消融，否则阻断。Reference refresh 独立于 Old refresh；替换 Reference 会改变 objective/reward semantics。RM、converter、task/cost、KL mode/reference/coefficient、discount、termination 或 credit allocation 任一变化，都产生新 reward_chain_revision，旧 Critic、returns 和 advantages 默认 stale。

termination、bootstrap、return 与 GAE

不能用一个 done 混合所有结局。每条 transition 至少有 natural_terminal | time_limit_truncated | safety_abort | human_takeover | external_reset | collector_failure | invalid_transition | bootstrap_allowed。

原因 常见 bootstrap 合同必须判断
absorbing success/failure 0 task 是否真正吸收
time limit 1 或 0 截断后状态是否可延续
safety abort contract-defined 是否是 terminal cost state
human takeover 通常在边界截断 next state 是否由 policy action 导致
collector/sensor failure 0 / invalid next context 是否可信
batch horizon cut 1 frozen value snapshot 是否可用
external reset 0 禁止跨 reset 连接

令 $b_t\in{0,1}$ 为 bootstrap mask，$m_t$ 为 valid/credit mask，且 $V_{old}$ 是生成 targets 时冻结的 value snapshot：

\[\delta_t=m_t\left(r_t+\gamma b_tV_{old}(c_{t+1})-V_{old}(c_t)\right),\] \[\hat A_t=\delta_t+\gamma\lambda b_tm_{t+1}\hat A_{t+1}, \qquad \hat R_t=\hat A_t+V_{old}(c_t).\]

episode/chunk boundary、invalid step 与 reset 截断递推。$\gamma$、$\lambda$、reward scale、horizon 和 bootstrap policy 都属于 target revision。advantage normalization 必须记录 population（global/per-task/per-robot/per-chunk/none）、valid mask、mean/std/epsilon/clip；per-task normalization 会改变任务间梯度权重，不是显示变换。sealed batch 的 $\hat A$、$\hat R$、old values、rewards、bootstrap 与 masks 固定并 detach。

PPO Actor clipped objective 与多 epoch 更新

对同一 serialized action、context、factor mask、transform、support 和 base measure：

\[\rho_t(\theta)= \exp\!\left(\log\pi_\theta(a_t\mid c_t) -\log\pi_{old}(a_t\mid c_t)\right).\]

clipped surrogate 为：

\[\mathcal L_{clip}(\theta)= -\frac{\sum_t m_tw_t\min\!\left[ \rho_t\hat A_t, \operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t \right]}{\sum_tm_tw_t}.\]

contract 固定 $\epsilon$、mask、sample weight、reduction denominator、advantage normalization、detach 与 log-ratio numerical policy。$\epsilon$ 既不是 physical action clip，也不是 KL threshold。若 MDP action 是 whole chunk，先对有效 factors 求 joint log-ratio，再 clip joint ratio；逐 token clip 后求和/平均是另一 objective，只有 token 真正成为独立 decision/credit unit 时才可使用。

multi-epoch receipt 包含 epoch count、shuffle seed、minibatch size、drop-last、reuse count、gradient accumulation、mixed precision、optimizer steps 与 early stop。epochs 中只有 current Actor/Critic 按 ownership 更新；Old、Reference、RM、converter、rewards、returns 与 advantages 保持不变。

优化诊断报告 approx KL 的方向/estimator、clip fraction、ratio/log-ratio 分位数与 max、objective 前后、entropy、gradient norm、NaN/Inf、effective samples/factors 及 task/robot/action-dimension slices。target KL、ratio limit 或 numerical failure 可以停止 epochs，但不是 task/safety release approval。entropy、Actor KL、BC anchor、cost advantage 和 auxiliary loss 均需单独列 source、sign、coefficient、mask、gradient path 与 owner。

Critic、参数/梯度/optimizer 所有权

Critic 估计指定 policy、reward、discount、termination 与 horizon 下的 $V(c)$，或另行声明的 $Q(c,a)$；RM 预测 preference proxy。二者即使都有 scalar head 或用 RM 权重初始化，也不语义等价。

\[\mathcal L_V(\psi) =\frac{1}{2} \frac{\sum_tm_tw_t\left(V_\psi(c_t)-\operatorname{stopgrad}(\hat R_t)\right)^2} {\sum_tm_tw_t}.\]

value clipping、Huber、return normalization 或 ensemble 是独立可选项；value clipping 的 old snapshot 和 range 不从 Actor $\epsilon$ 自动推出。Critic 必须绑定 policy family/behavior distribution、reward chain、$\gamma/\lambda$、termination/bootstrap、observation history、horizon、normalization 与 task population；上游变化即 stale。

action chunk、重规划与 executed credit

同时区分 decision index d（前向/重规划）、chunk factor k（生成内 slot）和 environment step t（真实 transition/reward），并保存 $d,k\rightarrow t$ execution mapping。三种 MDP 定义不可无 tag 混在同一 batch：

  1. macro-action：whole chunk 是一个 action，用 joint log-prob 和 chunk reward/discount。
  2. factorized-decisions：每个 factor 真正拥有独立 context/transition/credit。
  3. receding-horizon-prefix：生成 $H$、只执行 $m$，suffix 不参与 ratio/return。

每个 factor 状态为 generated | selected | queued | commanded | safety-modified | executed | skipped | cancelled | superseded | late | unknown，并记录 scheduled/actual time、overlap resolution、replan cause、controller acknowledgment 与 transition IDs。新 chunk 可 replace/blend/append/ignore 旧 queue；这项 queue policy 决定哪个 factor 产生后果。blend 后的 executed action 若不是原 policy 的随机变量，不能用任一原 chunk density 解释。

安全改写有且只有两种一致语义：若 MDP action 是 pre-safety command，ratio 对 command，controller 属于 environment transition；若 MDP action 是 executed action，必须建模 policy+filter 的诱导分布，projection/clipping 的 many-to-one 结构不能沿用 command density。numerator、denominator、reward 和日志不能跨这两种语义漂移。

credit allocation 可为 terminal、sum、discounted、event-based 或 learned attribution，但需绑定 horizon、mask、normalization 与 assumption。生成 16、执行 4 时 effective factors 只能是执行前缀或显式 joint prefix；replan 替换后旧 suffix mask 为 0；takeover 后、reset 后和未执行 suffix 的 credit 为 0；chunk boundary 的 discount/bootstrap 要通过 off-by-one test。

约束、稳定性监控与独立安全门

约束优化是一种训练机制，不是硬件安全替代。以 $\nu_j$ 区分 GAE 的 $\lambda$：

\[\max_\theta\min_{\nu_j\ge0} J_R(\theta)-\sum_j\nu_j(J_{C_j}(\theta)-d_j), \qquad \nu_j\leftarrow[\nu_j+\eta_\nu(\hat J_{C_j}-d_j)]_+.\]

每个 cost 保存 definition、unit、exposure denominator、delay/censoring、discount、cost critic/advantage、budget、dual optimizer、projection、update frequency 与 uncertainty。collision、force、workspace、speed、jerk、near-miss、intervention 可以是 cost；但有限样本、估计偏差和非凸优化意味着它们不能替代 limits、interlock、watchdog/heartbeat/timeout、E-stop、human takeover、rollout authorization、independent release gate 和 incident process。zero-tolerance event 直接 abort/gate，不能被均值 reward 抵消。

分支完成、验证与 Online System 交接

验证阶梯依次是：schema/hash/role/capability 静态检查；fixed-batch log-prob/ratio invariants；reward/termination/GAE analytic toy；Actor/Critic gradient ownership；chunk execution/credit replay；numerical/staleness/unknown failure injection；policy-level task/OOD/safety evaluation；release/rollback authority review。当前页面只定义这些 protocol，没有运行训练、模型、评测、仿真、SIL/HIL 或机器人流程。

最小不变量：

  • identical current/old → ratio≈1；zero advantage → Actor contribution 为 0。
  • invalid mask → reward/GAE/loss/stat contribution 为 0；batch seal 后 hash 不变。
  • reward revision 变化 → Critic/targets stale；terminal/bootstrap 按 environment contract。
  • unexecuted suffix credit 为 0；Actor loss 不更新 RM/Old/Reference/fixed targets。
  • unsupported density、OOD unknown 或 unauthorized rollout fail closed。
  • high reward 或 low KL 不能绕过 critical safety gate。

一手来源与迁移边界

  • PPO v2：sampling 与 multiple-epoch minibatch surrogate；Atari/模拟 locomotion 来源域，不是 VLA 安全证明。
  • GAE v6：value-based advantage estimator 与 bias–variance；来源域为模拟连续控制。
  • Deep RL from Human Preferences v4：trajectory preference reward + RL；不提供本页 VLA receipt/safety contract。
  • InstructGPT v1：RM/PPO/KL 的语言模型 bandit 实现；其系数和 RM→value initialization 不是 VLA 默认。
  • Soft Actor-Critic v2：continuous squashed policy 变量变换参考；SAC 是 off-policy maximum-entropy 方法，不是 PPO。
  • Constrained Policy Optimization v1：特定假设和 simulated locomotion 下的约束研究；不证明有限样本 VLA 真机安全。
  • Flow Matching v2：conditional probability path 上的 vector-field regression；不自动给 final-action log-prob。
  • π₀ v4：flow-matching VLA policy family 实例；不代表所有 flow policy 都具备 PPO density。
  • VLP v1：标题为 Vision-Language Preference Learning for Embodied Manipulation；仅作 embodied preference 相关证据，不改称“VLA-RL”，也不作为 PPO/真机验证。
