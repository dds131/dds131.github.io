一、先给结论：标准损失，关键在表示与训练系统

OpenVLA 没有设计新的机器人损失函数。它把连续动作量化为语言模型 token，再用标准因果语言模型交叉熵进行全量微调。真正关键的设计在于：

  1. 把动作向量表示为有顺序的离散 token 序列；
  2. 复用预训练视觉—语言主干和 next-token prediction 接口；
  3. 在 64 卡、全局 batch 2048 下联合微调视觉塔、投影器和语言主干；
  4. 用 FSDP、BF16 计算、FP32 梯度规约和激活检查点控制显存与通信。
2e-5固定学习率
64 × 32全局 batch 2048
27论文报告的数据遍历轮数
95%+论文报告的训练动作 token 准确率
21,500论文报告的 A100 小时

本文把三类结论分开：

  • 论文事实：论文明确报告的目标、超参数、训练规模与实验观察；
  • 实现事实：固定源码版本中可以逐行确认的行为；
  • 工程解释：由前两者推导出的影响，明确标为分析而不是官方保证。

页面的逐文件引用固定到 OpenVLA 官方仓库提交 c8f03f48，对应依赖包括 PyTorch 2.2.0 与 Transformers 4.40.1。另需说明：本地辅助源码快照记录为 2026-09-16 从 main 抓取，却没有保存可用的提交 SHA；它可辅助定位代码，不能单独证明与该固定提交逐文件相同。涉及版本语义时，应以本页链接的固定修订为复核基准。

二、从连续行为克隆到离散 token 目标

2.1 连续动作行为克隆

令 \(x=(o,\ell)\) 表示视觉观测与语言指令，专家动作是 \(A\)。连续行为克隆通常写成

\[\mathcal L_{\mathrm{BC}}(\theta) = -\mathbb E_{(x,a)\sim\mathcal D} \log p_\theta(a\mid x).\]

OpenVLA 没有直接参数化这个连续密度。它先用确定性的量化器 \(Q\) 把每个动作维映射为离散 token：

\[W=Q(A)=(w_1,\ldots,w_N).\]

因此，OpenVLA 优化的是由 \(Q\) 诱导出的离散标签分布，不是与原连续密度完全相同的目标。量化会引入分位数裁剪、分箱误差和标签别名，详见动作 token 化与量化误差。

2.2 token 序列的链式分解

在离散变量 \(W\) 上，链式法则给出

\[p_\theta(w_{1:N}\mid x) = \prod_{j=1}^{N} p_\theta(w_j\mid x,w_{<j}).\]

这是精确的概率分解，不要求各动作维独立。论文所描述的动作目标可以写成

\[\mathcal L_{\mathrm{action}} = -\mathbb E \sum_{j=1}^{N} \log p_\theta(w_j\mid x,w_{<j}).\]

它说明 OpenVLA 的创新重点不是损失函数本身，而是把机器人动作转换为预训练语言模型能够直接建模的符号序列。

2.3 当前实现还默认监督 EOS

数据管线默认 predict_stop_token=True，因此监督集合不仅包含 \(N\) 个动作 token，还包含序列终止符。对 batch 中第 \(b\) 个样本，记非忽略目标位置集合为 \(S_b\)，实际损失是

\[\mathcal L_{\mathrm{impl}} = -\frac{1}{\sum_b|S_b|} \sum_b\sum_{i\in S_b} \log p_\theta(y_{b,i}\mid x_b,y_{b,<i}).\]

Transformers 4.40.1 会先把 logits 与 labels 错开一位，再用默认 CrossEntropyLoss 对所有非 \(-100\) 目标求均值。标准七维 OpenVLA 配置中，每个样本默认有 7 个动作目标加 1 个 EOS，共 8 个监督目标。

论文口径与实现口径应同时保留。 论文把目标概括为“只在动作 token 上计算交叉熵”；发布实现默认还监督 EOS。前者是算法抽象，后者是可复核的工程行为，不能用一个公式混写。

三、训练样本、标签与三个指标口径

3.1 prompt 和标签

官方数据变换把语言指令转为小写，并构造两轮对话：

human: What action should the robot take to {lang}?
gpt:   {action_token_string}

动作 token 先被解码为字符串，放入 assistant 回答，再对完整 prompt 重新分词。因此复现时还应验证：

\[\operatorname{encode}(\operatorname{decode}(\text{action ids})) = \text{action ids}.\]

labels 最初复制 input_ids，随后把动作回答以前的位置设为 \(-100\)。标签不在数据侧手工右移；右移由 Llama 的 forward(labels=...) 完成。标准七维配置下默认保留 8 个目标位置，但动作维数应以目标数据集统计量为准，不应把 \(N=7\) 写成所有 OpenVLA 衍生模型的永久约束。

3.2 损失、准确率与 L1 不是同一口径

量 覆盖范围 是否反向传播 正确解释
交叉熵 默认 7 个动作 token + EOS 是 唯一训练目标
动作 token 准确率 label > action_token_begin_idx 的位置 否 动作类别 argmax 准确率，不含 EOS
bin-center L1 全词表 argmax id 与真值 id 经反向映射、裁剪后的分箱中心 否 启发式在线诊断量；非法预测也会被折叠到端点

准确率掩码在标准 tokenizer 下会选择动作 id 31744–31999，但源码只检查下界，没有检查上界。正常训练标签满足这个契约；若改造 tokenizer，建议显式断言合法范围。

bin-center L1 并没有先把预测限制在动作词表。记全词表 argmax 得到的预测 id 为 \(\hat t_m\)，源码先计算

\[\tilde k_m=\operatorname{clip}(V-\hat t_m-1,0,254),\]

再记录

\[\mathrm{L1}_{\mathrm{bin}} = \frac1M \sum_{m=1}^{M} |c_{\tilde k_m}-c_{k_m}|,\]

其中 \(c_k\) 是 \([-1,1]\) 内的分箱中心，真值位置由合法动作标签掩码确定。若预测的是普通语言 token 或补齐行，它不会被计为“非法”并报错，而会经裁剪折叠到首、末端中心。这里也没有使用 unnorm_key，没有按各数据集的 \(q_{01},q_{99}\) 还原到米、弧度或夹爪开度。因此不应称为“实际物理动作误差”。更严格的监控应另报非法动作 id 比例，或先把 logits 限制到合法动作 id 区间再计算距离。

交叉熵也不利用类别之间的顺序距离：它取决于模型分给真值类别的概率，而不是 argmax 与真值相差一档还是一百档。bin-center L1 补充了这种“错了多远”的信息，但只使用 argmax，仍不反映完整概率分布。

3.3 发布代码日志不是完整训练集评估

action_accuracy 和 L1 在每个 rank 的本地 batch 上计算，没有执行分布式 all_reduce。VLAMetrics 默认 window_size=1，而 push() 只在 rank 0 执行，因此发布代码记录的是 rank 0 当前本地 batch 的指标。

逐数据集指标也只来自 rank 0 当前 batch，并且只有该 batch 同时出现多个数据集时才更新。它适合在线发现异常，但稀有数据集曲线可能很噪，不能当作完整训练集或全局 batch 2048 的严格统计。

论文报告“训练动作 token 准确率超过 95% 时，真机性能仍持续提升”。这是重要的经验观察；但在没有原始训练日志与聚合脚本时，不能断言论文的 95% 与发布代码某一步的 rank-0 本地 batch 数字完全同口径。

四、训练并行、推理自回归：不要混为七次完整前向

动作 token 的联合分布按维度自回归分解，但训练和推理的计算方式不同：

阶段 已知 token 计算方式 主要特点
训练 完整真值序列作为输入；每个位置因果地只看见真值前缀 teacher forcing；一次前向并行产生所有位置 logits 各位置损失可并行计算，但不存在“看见未来真值”
推理 只有已生成前缀 逐 token 解码 后一维条件依赖前面已生成维度
独立分类头基线 不使用动作前缀 一次产生各维类别 明确假设给定观测后各维条件独立

因此，“七个动作维需要七次完整视觉—语言前向”不准确。在没有提前 EOS 且完整生成七维动作时，需要七个顺序解码步骤；首次包含 prompt/视觉前缀处理，后续通常复用 KV cache。max_new_tokens=7 只给上限，发布包装器仍假定实际生成了七个动作 token。实际延迟还受视觉编码、7B 语言主干、缓存实现和部署框架影响。

自回归分解在理论上可以表达离散动作各维的任意联合分布，但不保证有限模型一定学到所有相关性。teacher forcing 与推理时使用自身历史预测之间也存在分布差异；前面维度预测错误可能影响后续维度。这是自回归动作表示的能力与代价，而不是“完全消除不合理动作组合”的保证。

五、正式训练配置：事实与解释分开

正式 OXE Magic Soup+ 配置继承 Exp_SigLIP_224px_Bridge 的优化参数，并覆盖训练规模。

项目 固定版本配置 可确认的含义
训练范围 视觉塔、语言主干均不冻结 全量微调，而非只训练投影器
优化器 AdamW 代码未覆盖的默认值为 \(\beta_1=0.9,\beta_2=0.999,\epsilon=10^{-8}\)
学习率 \(2\times10^{-5}\) 论文扫过多个数量级后选出的最好值
调度 constant 每个优化步骤保持固定学习率
warmup 0 论文报告未观察到收益
weight decay 0 配置事实；论文没有给出充分机制解释
梯度裁剪 全局范数 1.0 FSDP 专用 clip_grad_norm_ 在每步更新前执行
单卡 batch 32 每个 rank 的本地样本数
world size 64 训练入口会断言实际进程数等于 64
全局 batch 2048 \(64\times32\)
学习率步骤 每次 optimizer step 后 constant 调度下数值不变

参数会被分成 decay/no-decay 两组，但 weight_decay=0，所以两组实际都不衰减。分组代码在这套配置中是空操作；改为非零权重衰减后才产生差异。

论文只报告并支持“这套学习率扫描中，固定 \(2\times10^{-5}\) 且不 warmup 的结果最好”。不能进一步推出：

  • 余弦衰减必然与长训练冲突；
  • 预训练权重不需要正则化；
  • 所有 OpenVLA 微调都不应 warmup。

AdamW 的矩状态在 VLA 训练开始时仍从零初始化。预训练参数提供了更好的模型起点，但不会自动预热新优化器的矩估计；关于无 warmup 的机制解释只能作为假设，不能代替论文的经验结果。

六、batch、step、epoch 与停止机制

6.1 没有梯度累积

训练策略计算

\[\text{grad accumulation} = \frac{\text{global batch}} {\text{per-device batch}\times\text{world size}} = \frac{2048}{32\times64}=1.\]

而正式 OXE/FSDP 入口 vla-scripts/train.py 调用的 VLA 循环还显式断言累积步数必须为 1。因此，这条正式训练路径不支持仅靠修改配置引入梯度累积。仓库另一个 vla-scripts/finetune.py 入口支持梯度累积，但它采用独立的 HF/DDP 微调流程与默认超参数，不能据此推断论文最终训练路径也支持同样设置。

若沿用正式 FSDP 入口，卡数不足时要保持全局 batch 2048，需要修改训练循环，包括 loss 缩放、FSDP no_sync()、梯度裁剪、optimizer step、指标与 step 计数。也可以使用更小的全局 batch，但这会改变随机梯度噪声和更新动力学，学习率应重新验证；它并不改变行为克隆目标函数本身。

6.2 epochs=1000 不会自动停止无限数据流

RLDS 数据流隐式 repeat()，VLA 循环直接执行：

for batch in dataloader:
    ...
    epoch = (global_step + 1) // steps_per_epoch

循环没有“达到 epochs 就退出”的判断。因此：

  • epochs=1000 用于进度条与名义训练步数计算，不是自动停止上界；
  • max_steps 非空时才会触发代码内的自动退出；
  • 正式配置中 max_steps=None；
  • 代码没有“准确率达到 95% 自动停止”的逻辑。

论文明确报告最终训练遍历数据 27 轮，并观察到真机性能持续提升直到训练动作 token 准确率超过 95%。发布代码根据全局步数和数据集规模在线估算 epoch；但它没有完整编码论文最终作业的停止流程。因此最稳妥的表述是：27 轮与 95% 是论文报告的运行结果和经验关联，不是仓库默认配置中的自动停止条件。

配置注释还提到包含 DROID 的两阶段采样变化，而单个 dataclass 没有完整表达最终训练作业的全部阶段。严格复现需要保存明确的总步数、数据混合阶段、恢复点和停止方式，不能只依赖 epochs=1000。

七、FSDP：名称、分片范围与混合精度

7.1 fsdp-full-shard 实际映射为 HYBRID_SHARD

配置字符串经解析后传入 full-shard，源码把它映射到 PyTorch ShardingStrategy.HYBRID_SHARD：

PyTorch 策略 节点内行为 节点间行为 关键差异
FULL_SHARD 在整个分片组切参数、梯度和优化器状态 取决于分片组范围 前向后重新分片，反向前再次 all-gather
HYBRID_SHARD 节点内执行 FULL_SHARD 节点间复制并同步 昂贵的 all-gather/reduce-scatter 限制在节点内
_HYBRID_SHARD_ZERO2 节点内执行 SHARD_GRAD_OP 节点间复制并同步 前向后保留完整参数到反向结束，省去反向前 all-gather

_HYBRID_SHARD_ZERO2 并不是“参数完全不切”。参数在计算过程之外仍为分片状态，只是不会在前向结束后立即重新分片。

OpenVLA 没有显式传入进程组；PyTorch 2.2 会为混合分片构造节点内分片组和节点间复制组。若实际集群是每节点 8 卡，则持久状态按节点内 8 卡切分，并在不同节点复制；“8 节点 × 8 卡”只是可能的部署拓扑，不是论文明确报告的事实。

7.2 BF16 计算、FP32 规约与 FP32 梯度

源码配置为：

项 dtype 准确含义
param_dtype BF16 前向和反向计算期间使用的参数 dtype
reduce_dtype FP32 reduce-scatter/all-reduce 的梯度通信 dtype
buffer_dtype FP32 模块 buffer 在首次前向后保持的 dtype；buffer 不由 FSDP 分片
keep_low_precision_grads 默认 false 反向后把梯度恢复为全精度，供优化器更新

FP32 规约是 OpenVLA 为数值稳定选择的配置，不是所有 BF16 分布式训练都必须遵守的定理。BF16 通信也可以运行，只是累加精度更低。网页应说明权衡，而不是断言小梯度必然被系统性吞掉。

八、激活检查点与显存账

8.1 只检查点化语言 Transformer 层

固定版本使用 PyTorch checkpoint_wrapper 的 NO_REENTRANT 模式，只包装语言主干 Transformer 层。源码注释明确说这是基于“语言模型激活占主要部分”的工程假设。

这里应注意：

  • 激活显存由 batch、token 数、隐藏维、注意力实现和保存的中间张量决定，不能仅凭参数量判断；
  • 该仓库没有对视觉塔应用同样的激活检查点；
  • “不能直接使用 HF 开关”是这一固定 PyTorch/Transformers/FSDP 组合的实现约束，不应推广成所有版本的普遍结论；
  • 没有公开证据证明错误用法一定会“静默算错”，应避免这种未经验证的故障描述。

8.2 持久训练状态的合理下界

设可训练参数量为 \(P=7{,}541{,}237{,}184\)。在默认 keep_low_precision_grads=False、AdamW 状态为 FP32 的前提下，完整模型的持久训练状态近似为：

\[\underbrace{4P}_{\text{FP32 参数}} + \underbrace{4P}_{\text{FP32 梯度}} + \underbrace{8P}_{\text{Adam 一、二阶矩}} = 16P\ \text{字节}.\]

数值约为

\[16P\approx120.66\ \text{GB} \approx112.37\ \text{GiB}.\]

这约 112.37 GiB 的持久状态已经超过论文所用 A100 的 40/80 GB 单卡显存，因此在该硬件上不分片无法容纳，更不用说激活与临时张量。这个结论针对论文硬件与上述 dtype/优化器假设，不应扩张成“任何未来大显存单卡都绝不可能”。若 HYBRID_SHARD 的节点内分片组大小为 \(S=8\)，持久状态的理想均分下界约为

\[\frac{16P}{8}\approx15.08\ \text{GB/卡}.\]

但这不是峰值显存。实际还包含：

  • 每个 FSDP 单元临时 all-gather 得到的 BF16 完整参数；
  • 当前单元与预取单元的重叠峰值；
  • 视觉塔与语言主干激活；
  • 未分片 buffer；
  • CUDA allocator、通信缓冲和算子 workspace。

因此不能从 15.08 GB 推导“单卡 batch 32 正好用满 80GB”。论文也没有报告 A100 的显存规格或训练峰值。准确数值需要在目标拓扑与软件版本上用显存 profiler 实测。

九、训练监控、算力与可解释边界

9.1 一次训练步的实际顺序

flowchart TB
  A["rank 本地 batch<br/>标准配置每卡 32"] --> B["BF16 前向<br/>teacher forcing"]
  B --> C["模型内部 shift labels<br/>动作 token + EOS 交叉熵"]
  C --> D["loss.backward"]
  D --> E["FP32 梯度规约<br/>FSDP 混合分片"]
  E --> F["全局梯度范数裁剪 1.0"]
  F --> G["AdamW step<br/>固定学习率 2e-5"]
  G --> H["constant scheduler step"]
  C -.-> I["rank-0 本地 batch 指标<br/>准确率与 bin-center L1"]
  I -.-> J["可选逐数据集诊断<br/>非全局聚合"]

L1 在 loss.backward() 之后由脱离计算图的 NumPy 数组重建，因此不会产生梯度。原始 OpenVLA 的训练目标只有交叉熵；OpenVLA-OFT 后续引入的连续动作回归目标属于另一套方法。

9.2 论文报告的算力只能证明算术一致

论文报告 64 张 A100、14 天和约 21,500 A100-hours：

\[64\times14\times24=21{,}504\ \text{A100-hours}.\]

这说明三个报告数字在取整精度内一致，但不能进一步推出：

  • GPU 一直满负载；
  • 没有停机、检查点或数据等待；
  • 训练实际 FLOPs 等于理论峰值；
  • 不同硬件可以按 A100-hours 线性换算时间。

A100-hours 是资源占用量，不是硬件无关的计算量。跨系统比较还需要吞吐、利用率、精度、通信拓扑和有效训练步数。
