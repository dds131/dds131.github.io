一、方法定位

在线策略（on-policy）的 Actor-Critic 强化学习，算法是 PPO 的裁剪代理目标版本。 策略结构走 RMA（快速运动自适应）范式：教师直接使用特权观测训练， 同时用历史编码器与状态估计器为后续蒸馏出可部署的学生做准备。 外面再套一层地形难度自动课程。

没有专家数据集，全部靠自己在仿真里试错。

1.1 用了哪个算法，没用哪些

算法 类别 本项目是否使用 说明
PPO（裁剪版） 在线策略 AC ✅ 全程使用 唯一的策略优化算法，从第一版到最终版没有换过
行为克隆 BC 监督学习 ⚠️ 仅用于热启动 给旧模型加装新分支时用过一次，不产生新能力，见第十一节
DAgger 交互式模仿 ⚠️ 仅用于估计器 只用来训练那个「从本体感受估计特权观测」的辅助头，不参与产生动作
SAC 离线策略 AC ❌ 未使用 见下方原因
DDPG / TD3 离线策略确定性 AC ❌ 未使用 同上
DQN 系 离散动作值函数 ❌ 未使用 动作空间是 12 维连续量，不适用

为什么是 PPO 而不是 SAC。 这不是「哪个算法更先进」的问题， 而是被仿真吞吐量和课程学习两件事共同决定的。

第一，采样极其便宜，样本效率不再是瓶颈。 SAC、TD3 这类离线策略算法的核心卖点是样本效率——用经验回放池反复利用旧数据， 在真机采样昂贵的场景里这是决定性的。但本项目是 2048 个环境并行的 GPU 仿真， 一次更新就能采到 98,304 条转移，约 21 至 26 秒。 样本不值钱，值钱的是墙钟时间和训练稳定性。 PPO 每次更新只用刚采的这一批、用完就丢，没有回放池， 显存开销和实现复杂度都低得多，在这种吞吐量下反而是更合适的选择。

第二，课程学习会让 MDP 本身持续变化。 每个环境的地形难度都在随成绩升降，也就是说环境的转移函数与奖励函数一直在漂移。 离线策略算法依赖回放池里的旧数据，而这些旧数据来自已经不存在的那个 MDP—— 它们描述的是几百轮之前那个更简单的地形。 在线策略算法天然规避了这个问题：每一批数据都来自当前策略、当前难度分布。

第三，奖励结构极度复杂，需要可预测的更新步长。 本项目有 29 项基础奖励再加两段包装层整形，其中不少项之间存在相互制衡 （比如超速惩罚与跨沟助跑补偿）。PPO 的裁剪机制把单次更新的策略变化限制在一个信任域内， 使得「改一个奖励权重 → 观察行为变化」这个调试回路是可归因的。 SAC 的熵温度自动调节再叠加这套奖励，会让归因变得极其困难。

第四，RMA 范式与在线策略天然契合。 教师阶段需要一边训练策略、一边用同分布的数据训练状态估计器与历史编码器。 在线策略的数据流本来就是「当前策略产生的轨迹」， 这正是估计器与历史编码器需要的训练分布。

为什么不用行为克隆直接学。 项目早期用行为克隆训过一次带环状图的模型， 结果是新增分支完全没有学到任何东西——这是「主线全部走 PPO」最直接的实证依据， 实测数据与成因见第 3.3 节。

1.2 算法实现的继承链

底层用的是开源强化学习库的官方 PPO 实现，项目在其上逐版本派生：

PPO（库自带的裁剪代理目标实现）
  └─ 加入状态估计器与特权正则
      └─ 加入熵系数退火、逐轮更新计数、日志节流、高程图双侧自监督重建
          └─ 加入环状图分支诊断（隐变量标准差、残差占比、塌缩计数）
              └─ 加入策略噪声上限退火 + 塌缩告警        ← 最终 A/B 模型用的就是这一层
                  └─ 追加环状图双侧自监督重建（为从零训练准备）

每一层只做加法，核心的 PPO 更新逻辑始终没有改动。 启动时有硬断言检查「当前用的是哪一层」，防止续训时接错。

二、PPO 是怎么工作的

这一节把 PPO 在本项目里的完整运转拆开讲。

2.1 一次更新的完整流程

步骤 内容 本项目的具体数字
① 用当前策略在所有并行环境中跑固定步数，记录状态、动作、对数概率、奖励、价值 2048 环境 × 48 步 = 98,304 条转移（0.96 s 仿真时长）
② 从后往前递推计算 GAE 优势与回报 γ = 0.995，λ = 0.95
③ 对整批优势做标准化 在整批上做，不是逐小批做
④ 把这批数据切成小批，反复过若干遍，每次做一步梯度下降 5 遍 × 8 小批 = 40 次梯度更新，每小批 12,288 条
⑤ 用这批数据实测的 KL 散度调整下一轮的学习率 目标 KL = 0.01
⑥ 夹持策略噪声标准差，丢弃这批数据，回到 ① 一轮总耗时 21 至 26 秒

这就是「在线策略」的含义：第 ④ 步反复使用的那批数据， 是第 ① 步用当前策略采的；一旦更新完成、策略变了，这批数据就作废，不会存起来复用。

2.2 优势估计：GAE(λ)

优势函数回答的是「这一步做的这个动作，比该状态下的平均水平好多少」。 直接用蒙特卡洛回报方差太大，直接用单步时序差分偏差太大，GAE 在两者之间做指数加权：

δ_t = r_t + γ · V(s_{t+1}) · (1 − done_t) − V(s_t)          单步时序差分误差
A_t = δ_t + γ · λ · (1 − done_t) · A_{t+1}                  从后往前递推
R_t = A_t + V(s_t)                                          价值函数的回归目标
参数 值 含义
γ（折扣） 0.995 有效视野约 200 个控制步 = 4 秒——足够覆盖「助跑加起跳加落地」的完整动作序列
λ（GAE） 0.95 偏差与方差的折中；λ = 0 退化成单步时序差分，λ = 1 退化成蒙特卡洛

式子里的 (1 − done) 就是「真终止没有价值自举」的实现： 摔倒时 done = 1 且不标记为超时，V(s_{t+1}) 被整体乘 0； 回合走到时间上限时标记为超时，仍然做价值自举。

这一个布尔量决定了整个奖励结构的可行域，推导见第 8.1 节。

2.3 裁剪代理目标：PPO 的核心

设新旧策略在同一个状态动作对上的概率比为

ratio = exp( log π_new(a|s) − log π_old(a|s) )

朴素的策略梯度目标是 ratio × A，但它有一个致命问题： 当优势为正时，优化器会把 ratio 推到无穷大—— 一次更新就把策略推出了「这批数据还能代表的范围」，重要性采样失效，训练发散。

PPO 的做法是给这个目标加一个裁剪的悲观下界：

L_clip = − E[ min( ratio · A ,  clip(ratio, 1 − ε, 1 + ε) · A ) ]

当优势为正（这个动作是好的）

ratio 增大到 1 + ε 之后，第二项被卡住不再增长， min 选中它，梯度归零。

效果：好动作的概率最多提高 20%，不许一次性推满。

当优势为负（这个动作是坏的）

ratio 减小到 1 − ε 之后同理被卡住。

效果：坏动作的概率最多降低 20%。但如果 ratio 已经跑到 1 + ε 之外，min 会选未裁剪那一项，梯度依然存在——这是刻意的「亡羊补牢」通道。

本项目取 ε = 0.2，也就是说单次更新里策略的概率比不允许偏离 1 超过 ±20%。 这个信任域是 PPO 稳定性的来源，也是它在这个复杂奖励系统里可调试的根本原因。

2.4 价值函数也要裁剪

价值损失同样用裁剪版本，防止价值网络在一次更新里跳得太远：

V_clipped = V_old + clip( V_new − V_old , −ε , +ε )
L_value   = E[ max( (V_new − R)² , (V_clipped − R)² ) ]

注意这里是 max 而不是 min——取两者中更大的那个误差， 构成一个悲观的上界，其效果是把单次更新对价值估计的修正幅度限制在 ε 之内。

2.5 策略分布与探索

策略是各向同性的高斯分布：

π(a|s) = N( μ = actor(s) ,  σ )

关键点：σ 是与状态无关的 12 维可学习向量，不是网络的输出。 初值 0.6，运行期被硬夹持在 [0.15, σ_max(轮数)] 之间，上限从 0.60 线性退火到 0.50。

为什么 σ 与状态无关：状态相关的 σ 会给策略提供一条「在难地形上把噪声调小以避免摔倒」 的捷径——那是在回避探索，不是在学会通过。固定 σ 强制策略在所有地形上保持同等探索强度。

2.6 学习率不是调出来的，是被 KL 牵着走的

实测 KL > 2 × 0.01   →   学习率 ÷ 1.5   （学太猛，减速，下限 1e−5）
实测 KL < 0.01 / 2   →   学习率 × 1.5   （学太保守，加速，上限 1e−2）

初值 2.0e−4，但训练过程中它一直在被 KL 目标 0.01 拉扯。 这带来一条重要的判读经验：训练健康度必须把学习率与价值损失放在一起看。

项目中期出现过一次崩坏，链条是这样的：

噪声标准差顶到上限焊死 1700 轮
  → 碰撞增加 71%、角速度增加 75%
  → 价值损失从 0.1 涨到 2.7（峰值 10.8）
  → 实测 KL 超标
  → 31% 的迭代学习率被砍到下限 1e−5
  → 代理目标归零甚至转正（意味着这批更新在把策略变差）

单看奖励曲线完全看不出问题，必须看学习率被砍的比例与价值损失的绝对值。

2.7 一个容易忽略的细节：优势标准化的范围

配置里「逐小批标准化优势」是关闭的，也就是在整批 98,304 条上做一次标准化。 这一点在课程学习下很重要：不同环境处在不同难度等级上， 逐小批标准化会把「简单地形上的小优势」和「困难地形上的大优势」各自拉到同一尺度， 抹掉难度之间的相对信息。整批标准化保留了这个差异。

另外，观测本身不做经验归一化（配置里显式关闭）—— 因为高程图与环状图都已经在观测函数内部做了各自的归一化与裁剪， 再套一层滑动统计的归一化反而会引入训练前期的分布漂移。

三、损失函数一共有哪些

本节讲的是有哪些损失项、各自的目标是什么。四项损失的完整表达式、系数取值，以及它们分别由哪个优化器施加，见 网络结构与训练细节。

总损失由四项主损失构成，另有三类辅助损失独立更新各自的网络头。

3.1 主损失

L = L_clip  +  1.0 · L_value  +  c_ent(轮数) · L_entropy  +  c_priv(轮数) · L_privreg
损失项 形式 系数 作用
① 裁剪代理损失 − min(ratio·A, clip(ratio,1−ε,1+ε)·A)，ε = 0.2 1.0（固定） 策略优化的主目标，把优势为正的动作概率往上推、为负的往下压
② 裁剪价值损失 max((V_new−R)², (V_clipped−R)²) 1.0 训练价值函数逼近 GAE 回报，为优势估计提供基准
③ 熵正则 − H[π]，即负的策略熵 0.01 → 0.005，3000 轮线性退火 前期鼓励探索、防止过早收敛到单一步态；后期收紧以求稳定
④ 特权正则 压制 Actor 主干对特权隐变量编码的依赖 0 → 0.1，第 2000 至 3000 轮线性升起 逼 Actor 逐步不依赖特权信息，为蒸馏学生做准备

熵系数退火的实测校验：第 1720 轮时日志记录的系数是 0.0072， 按公式 0.01 + min(1, 1720/3000) × (0.005 − 0.01) 算得 0.00713，吻合。

一个关于熵系数的反面教材，值得单独记住。 项目中期为治崩坏，曾提出「把熵退火从 3000 轮拉长到 8000 轮」。这是错的。 把式子代进去算：拉长分母只是把下降直线拉平， 第 4500 轮时系数反而从 0.005 升到 0.00719（高了 44%）， 恰好在崩坏区间加大了熵压力。 要走这条路必须同时下调终值。 教训：改一个退火参数之前，先把公式代进去把两个端点和中间点都算一遍。

3.2 辅助损失（独立更新各自的网络头，不进主损失）

辅助损失 输入 → 目标 更新方式 为什么需要它
状态估计器损失 53 维本体感受 → 9 维特权观测（主要是机体线速度） DAgger 风格，每 20 次更新一轮 教师阶段它不参与产生动作，纯粹是在为学生阶段预训练这条通路
高程图自监督重建（两份） 高程隐变量 32 → 重建 132 维高程图 独立回归头，Actor 与 Critic 各一份 给高程编码器一个与策略回报无关的稳定学习信号，防止它只学到「当前回报用得上的那点信息」
环状图自监督重建（两份） 环状隐变量 32 → 重建 720 维环状图 同上，前 50 轮只训解码器（编码器截断梯度） 见下

环状图的两个重建头曾经缺失了整整十个版本。

更早的分支本来有这两个头，后来重建高程图主线时随环状图一起去掉了； 再后来把环状图输入加回来，却忘了把自监督头也加回来。

热启动时这个缺口不致命——门控层已经强迫环状分支必须干活， 模型 A 实测隐变量标准差从 0.068 增长到 1.77。 但从零训练时就不够了：隐变量从第 100 轮起恒为 0，连续死亡 505 轮以上，告警 86 次。 补上重建头之后才恢复正常。

这说明自监督重建在这里的真实作用是冷启动期的信号兜底： 在策略还没学会用这张图之前，重建损失先为编码器提供有效梯度。

一个容易搞错的细节：环状图重建的目标归一化系数是 1.0 而不是更早版本用的 3.0—— 因为环状图观测从某一版起已经在观测函数里归一化到了 0 至 1， 沿用旧系数会让重建损失的量级差三倍。

3.3 行为克隆损失（只在热启动阶段用过）

给旧模型加装环状图分支时用过一次，形式是最朴素的动作均值 L2：

L_bc = mean( ‖ 旧模型输出的动作均值 − 新模型输出的动作均值 ‖₂ )

没有 KL 项，没有价值蒸馏。数据以在线策略方式收集： 用新模型的均值动作推进环境（不采样、不加噪声），旧模型在同样的状态上给出均值作为监督。 默认冻结全部继承层，只训环状图编码器与融合网络，可训练参数约 38 万。

如前所述，这个损失全程恒为 0.000000，因为融合末层零初始化保证了初始行为逐位相同， 而旧模型不含环状图、无法为新分支提供任何梯度信号。 这正是「必须靠强化学习」的实证。

一个附带结论：若打开「训练整个 Actor」的开关，动作误差会从 0.000018 单调发散至 1.07，随后回落到 0.64。 原因是继承层没有任何锚点、行为克隆又提供不了有效学习信号， 优化器只是在放大浮点噪声。热启动阶段就该冻结继承层。

3.4 各项损失的量级参照

调试时最有用的不是绝对值，而是相对于稠密前进奖励的量级。 本项目所有奖励量级的参照物是「稠密前进奖励」，实测约 0.0587 每步。 后面奖励一节里所有「满额 0.040 每步 = 0.68 倍参照物」这类表述，都是以它为基准的。

判读训练健康度时，这几个量要一起看：

指标 健康区间 异常时说明什么
价值损失 0.1 量级 涨到个位数说明回报分布在剧烈变化，通常伴随崩坏
实测 KL 在 0.01 附近波动 长期超标会导致学习率被反复砍到下限
代理损失 负值 转正意味着这批更新在把策略变差
学习率被砍到下限的比例 低 超过三成就要停下来查
策略噪声标准差被夹比例 0.5 至 1.0 正常 长期焊死在上限说明策略在顶天花板
环状图隐变量标准差 明显大于 0 归零就是分支塌缩，且会自我锁死

4.2 指令：只给方向，不给距离

命令本体是三维，但只有前进速度这一维进观测：

  • 前进速度在 0.3 至 0.8 m/s 之间采样，每 6 秒重采一次；
  • 侧移速度恒为 0；
  • 转向速度由一个航向比例控制器实时算出，不进观测。

途径点的距离不进观测，只给方向角。距离信息完全通过奖励间接传递。 这是刻意的：逼机器狗从两张感知图里自己判断「还有多远、前面是什么」。

奖励侧的耦合方式很讲究：

奖励 = min(朝途径点方向的投影速度, 命令速度) / 命令速度

命令给速率上限、途径点给方向。取最小值封顶意味着超速的边际收益为零—— 这一条后来成了防止「冲下楼梯」的第一道闸。

4.3 历史里为什么要抹掉航向误差

历史缓冲每步左移一格、最新帧塞末尾，被一个一维卷积编码器压成 20 维。 但存进历史之前，第 6、7 位（两个航向误差）被故意置零。

不置零的话，历史编码器会走「航向捷径」——直接从历史里读方向信息， 而不去学「从本体感受的时序里反推地形与自身状态」。 那样蒸馏到学生时，这条通路就是废的。

历史编码器在 RMA 范式里的职责是从本体时序反推特权信息。 航向误差是当前帧就已经显式给出的量（第 6、7 位另有一个专用编码器处理）， 若历史里也保留它，最省力的解就是「复读航向」，学生策略继承到的会是一条空通路。

这和后面要讲的环状图门控是同一类设计思想：用输入裁剪堵死捷径，而不是依靠损失函数间接引导网络。

六、网络结构

本节讲的是网络为什么这样分支、门控为什么必须存在。逐模块的维度、激活函数与值域、梯度回传路径，以及两个变体的完整结构图，见 网络结构与训练细节。

6.1 两个变体：残差式与并排式

项目最终产出两个模型，它们共享全部前端分支，只在「两张图怎么融合」这一处不同：

模型 A · 残差式（主干输入 130 维）

环状图只提供一个修正量：

融合 = 高程隐变量 + 融合网络(环状隐变量)

主干输入 = 本体 53 + 融合 32 + 特权 9 + 历史 20 + 航向 16 = 130。 注意进入主干的是 9 维特权观测原值，特权编码器输出的 20 维隐变量主要用于正则项。

融合网络末层零初始化，所以刚接上时行为与不带环状图的旧模型逐位相同，热启动零冲击。

Actor 参数量 646,782。

模型 B · 并排式（主干输入 162 维）

两路隐变量各占独立通道，直接并排送进主干：

主干输入 = [本体 | 高程 32 | 环状 32 | 特权 | 历史 | 航向]

没有融合网络。从旧模型迁移时主干首层按分段做零扩展。

Actor 参数量 658,974。

两个模型的权重不可互换。 主干首层的输入维度不同（130 与 162）， 交叉加载会直接报维度不匹配；而且模型 B 根本不存在融合网络这一组参数。 加载时必须显式指定变体。

两者共用同一个主干拓扑：512 → 256 → 128 → 12，激活函数 ELU。

6.3 那个门控层为什么必须存在

模型 A 早期的融合式子是 融合 = 高程隐变量 + 融合网络(拼接[高程, 环状])，其中存在一条捷径： 融合网络仅凭高程隐变量就能产出有用的残差，一步到位； 而「从 720 维稀疏图中提取信息」需要先学会解读整张图才有回报。 在早期训练阶段，梯度会优先沿这条方向下降。

这条捷径的实际后果是环状图分支完全不被使用： 它的隐变量在正式训练的第 12 轮归零，之后 2988 轮全程恒为常数， 而同期实测输入本身跨环境的标准差有 0.080——输入是有信息的，是网络主动学会了忽略它。 隐变量变成常数后流经编码器的梯度也接近零，该状态会自我锁死。 （完整的取证过程，包括一次因冒烟规模不足而误判「已修复」的经历，见 工程问题记录的问题卡十二。）

修法是一个无参数的门控层：在融合网络内部把拼接输入的前 32 列（高程那一半）物理切除， 使残差只能由环状图隐变量驱动。捷径不复存在，网络没有别的选择。 配套增加了一条「连续 50 轮隐变量标准差低于阈值即告警」的监控。

修复后，模型 A 与模型 B 在正式训练中的环状图隐变量标准差分别稳定在 1.42 与 1.01，全程零塌缩。

6.4 Critic 不接收原始感知图

Critic 输入 = [本体 53 | 高程隐变量 32 | 环状隐变量 32 | 特权 9 | 特权隐变量 29] = 155 维

价值函数不需要那么细的空间信息，从 1473 压到 155 显著降低方差与显存。 一个容易忽略的细节：Critic 有自己独立的高程与环状编码器，与 Actor 完全不共享。 这样在「冻结 Actor 主干、只训环状分支」的过渡阶段，价值函数仍有自主学习的感知通路。

7.2 零误伤的步态惩罚判据

要罚掉兔跳（前两腿或后两腿同时腾空）与溜蹄（同侧两腿同时腾空）， 同时绝不能误伤正常的对角小跑。做法是：

兔跳项 = (两前腿都腾空) + (两后腿都腾空)                  取值 0 / 1 / 2
溜蹄项 = [(左侧两腿都腾空) + (右侧两腿都腾空)] × (非四脚全腾空)   取值 0 / 1

十六种接触组合全部穷举验证过：

步态 四足接触状态 兔跳项 溜蹄项
对角小跑（两种相位） 1001 / 0110 0 0
溜蹄 0101 / 1010 0 1
兔跳 0011 / 1100 1 0
四足齐腾空 0000 2 0
站立 1111 0 0

正常对角小跑时两项恒为 0，不产生任何惩罚。

方法论：去找一个「正确行为恒为 0、错误行为必然非零」的量， 而不是「给正确行为加分」——后者一定会引入刷分空间，前者不会。

末尾那个「非四脚全腾空」的因子是去重用的：溜蹄门控的 7 类地形与兔跳门控的 4 类有重叠， 不去重的话一次四脚腾空会被罚两份，把快速换步瞬间的正常短暂腾空罚死。

7.3 包装层的两段整形

防刷分这一段的机制：

机制 作用
后退惩罚 罚「朝途径点反方向移动」，堵死来回横跳刷推进分

7.4 沟沿同步起跳：四项纯正奖励

跨沟对步幅与助跑速度的要求在九类地形中最高（实测步幅为全地形最大）。 这四项奖励实现在包装层，不计入 7.1 的 29 项基础奖励，因此不受底层非负裁剪的影响。

在第 30 版之前，策略在沟前采用的是能耗最优的对角小跑：四条腿依次蹬地、前后左右分别发力。 这种步态在其余八类地形上完全够用，但在沟沿处会导致两个后果——起跳时机分散使推力无法叠加， 以及机身在腾空段发生侧向偏移，落地时后半身落入沟内。

这四项做成正奖励而不是去取消既有的步态惩罚，依据是： 跨沟本来就不受任何「强制左右不同步」的约束，策略不并脚只是因为没有信号鼓励它并脚。 代码核对的经过见 工程问题记录 问题卡十一。

沟沿检测器

四项奖励只应在沟沿附近生效，因此先要判断「机器人此刻是否正对着一条够宽的沟」。 检测器的数据源是 132 维高程图，不引入任何新传感器：这张图策略本身就看得见， 因此由它导出的门控量对策略而言是可学习的，而不是一个从外部凭空出现的开关。

核心判据是差分，而不是绝对高度：

drop(ix) = h[ix] - h_ref
         = (base_z - g_ahead - 0.3) - (base_z - g_under - 0.3)
         = g_under - g_ahead

机身高度 base_z 在相减时被完全消掉，因此 drop 的含义是 「前方地面相对身下地面的下陷深度」，与机身当前的高度和俯仰角无关。 这一点是必需的：机器人跃起时整张高程图看起来都会「地面变低」， 任何基于绝对阈值的判据都会在腾空瞬间误触发，而差分判据对此免疫。

在此之上设三道门，全部满足才认定为有效沟沿：

门 判据 作用
身下是实地 身前最近四格的下陷深度均小于阈值 排除走道两侧深坑侵入视野造成的误判
前方有深坑 第四格以外存在某格下陷深度超过阈值 定位沟的前沿
沟足够宽 沟宽不小于下限 窄沟一步迈过即可，不应触发

下陷深度阈值取 0.35 m。这个取值的信噪比很高：楼梯单级约 0.15 m、 台阶类障碍下沿约 0.30 m，都过不了这道门；而沟深 2.2 至 2.6 m， 即使观测被截断到 1.0 m，算出的下陷深度也约为 0.95 m，远超阈值。

检测器另配一个保持窗，时长 0.45 s。原因是起跳之后机身越过沟沿， 前视窗口随即看到对岸，原始判据会立刻归零；而腾空段与落地段恰恰是最需要同步约束的阶段。 保持窗按环境逐个计时衰减，使奖励窗口覆盖完整的起跳到落地过程。

四项奖励

接触量不取布尔值，而取连续值：把每只足的接触力除以 30 N 的参考力后截断到 0 至 1 之间。 这样「同时发力」而不只是「同时触地」也能被度量，梯度更平滑。

项 度量的行为 针对的错误形态 权重
左右同相 窗口内前两足接触状态一致、后两足接触状态一致 左右腿分别蹬地 2.0
齐蹬起跳脉冲 前后足真正齐蹬离地的那一帧给一次事件型脉冲 起跳时机分散 0.15
腾空里程 四足全腾空且机体向前时，按前向位移累计 跳跃距离不足、后半身落入沟内 1.5
助跑补偿 沟前允许超出指令速度的那部分前向速度 助跑不足 2.0

四项全部是正奖励，没有一项是惩罚。左右同相一项把「四足同时着地」也计入， 这是刻意为之：如果只奖励「腾空时左右同相」，策略可以靠原地跳跃拿满这一项。

助跑补偿一项存在的理由是它要抵消一条既有的全局惩罚。项目中有一条全局超速惩罚， 在沟前会阻止策略加速助跑。两者的量级经过校核：以超出指令 0.5 m/s 计， 全局惩罚给出每步 −0.015，助跑补偿给出每步 +0.020，合计为净正， 因此沟前允许助跑，而在其余时刻超速仍照罚。

防止刷分的两道护栏

这一版训练中途出现过一次典型的奖励刷分：策略发现只要在沟沿前高频抖腿， 就能反复触发齐蹬起跳脉冲，实测步频一度达到 24 Hz，而机器人并没有真的跳过去。

护栏 取值 作用
前向速度门控 门全开阈值 0.7 m/s，平方律 前向速度不足时四项奖励按平方衰减
脉冲不应期 0.15 s 齐蹬起跳脉冲在不应期内不重复计分

门控用平方律而非线性，是因为线性门控实测衰减不足。 两道护栏加上之后步频回到 5 Hz 量级并长期稳定； 逐存档读数与那次对照实验见 工程问题记录 问题卡一。

奖励权重另设 100 轮的爬升期，起始权重为额定值的 20%，之后线性拉满。 作用是避免在续训时奖励尺度突变，把已经收敛的策略打散。
速度门控与爬升期都是面向热启动的设计，从零训练时会反过来变成门槛。 续训策略在沟上的前向速度约 0.87 至 1.09 m/s，速度门全开，四项奖励正常生效； 从零训练早期只有约 0.71 至 0.93 m/s，门几乎关闭，四项奖励拿不到分。 爬升期同理：续训时第 0 轮就已经会走路，100 轮之后正好开始学跳； 从零训练的前 100 轮还在学站立，这段信号被浪费掉了。

上述改动生效后，跨沟地形出现稳定的并脚起跳行为。逐格通过率与并脚起跳率的量化结果见 结果与视频画廊。

八、那道硬地板：必须有，又会坏事

整个奖励链的最后一步是 奖励 = max(奖励, 0)。这一行代码同时是必需的和有害的。

下面讨论的都是末端那道硬地板。

8.1 为什么必须有

要理解这道地板，先要看清「摔倒」在这个环境里的数学含义。

摔倒被标记为真终止而不是超时截断，因此第 2.2 节那个 (1 − done) 因子会把 V(s_{t+1}) 整个乘掉——摔倒之后不再产生任何回报，终止状态的价值恒等于 0。

在此前提下，比较同一个状态上的两种选择。设从当前状态起， 每继续走一步的整步奖励都是 −c（c > 0）：

选择一 · 立刻摔倒终止      G = 0
选择二 · 继续走 k 步再摔倒  G = −c · (1 + γ + … + γ^(k−1))
                              = −c · (1 − γ^k) / (1 − γ)   < 0

对任意 k ≥ 1，选择二的折扣回报都严格小于选择一。 而策略梯度只朝回报更高的方向更新，因此最优解就是尽快终止—— 训练出来的机器狗会主动摔倒，因为在当前的奖励结构下那确实是最优行为。

要点不在于「负奖励本身有害」，而在于终止状态的回报被固定在 0， 构成了一个无需付出任何代价就能取得的下界。

在没有真终止的环境里（例如摔倒只扣分、回合继续），负奖励完全没有问题； 一旦存在一个零回报的吸收态，任何长期为负的整步奖励都会把这个吸收态变成最优目标。

奖励 = max(奖励, 0) 消除的正是这个不等式：整步奖励恒为非负之后， 选择二的回报永远大于等于 0，与立刻终止持平或更优，主动终止的动机随之消失。 代价是惩罚只能把当步收益削减到 0，无法使其为负。

对付这个问题的标准手段是存活奖励——每存活一步给一个正的常数， 把「继续走」的回报整体抬到 0 以上。它在本环境里不适用： 整体存活率只有约三成，「原地不动、稳定拿满整个回合的存活奖励」的期望回报， 会严格高于「向前推进、但有约七成概率中途摔倒终止」， 于是训练出的是原地滞留的策略。

8.2 为什么会坏事

加性惩罚一旦把当步奖励压到 0，梯度就直接归零了，再加多少惩罚都没有区别。 这是「用加性惩罚去治某个行为」这条路的结构性上限。

这个上限在下楼梯上暴露得最彻底：实测该地形有六成以上的步被地板削平、 梯度归零，因而出现了「惩罚加得越多、下楼梯反而越差」这一反直觉现象。 诊断指标的设计、对照组的取法与完整读数见 工程问题记录的问题卡五。

解法是只对下楼梯这一类地形取消非负裁剪，其余八类由包装器补回； 配套的四道护栏与实测读数见问题卡五。

⚠️ 有一条铁律：从零训练绝对不能带这个开关。 从零训练时有 57% 至 90% 的步本来就是净负的（热启动只有 13% 至 19%）， 取消地板就是直接教出自杀策略。

九、贯穿全项目的一条设计律

奖励的门控，必须与策略的感知同源。

展开有三层含义：

其一，判定用的量与策略看到的量必须来自同一份数据。 132 维高程图不是俯视真值，而是雷达点云栅格化的结果。 因此判断「机器狗是不是正好站在沟沿」的检测器，必须读同一份 132 维高程图， 而不能去读地形几何真值。否则就会出现「奖励在奖惩一个策略根本看不见的事件」—— 策略无法建立因果关联，那个梯度就只是噪声。

其二，判定用的锚点必须与感知用的锚点一致。 高程图的高空剔除、环状图的高度分层、奖励里的站高与净空门控， 全部锚在同一个姿态无关的参考点上。 若奖励用机身高度、感知用参考点，趴行时两者会系统性错位。

其三，同一物理事件在不同模块里必须用同一阈值。 最典型的是接触力阈值：观测侧的触地标志用 2.0 N， 而所有步态类奖励统一用 1.0 N。这两个口径是刻意不同的， 但在奖励侧内部必须保持一致——用错就与步态惩罚不同口径， 两条曲线再也对不上，诊断闭环就断了。

10.1 噪声上限退火：唯一为「防训练后期退化」而加的机制

第二节讲过一次崩坏链条，起点就是策略噪声标准差顶到上限焊死 1700 轮。 修法是给它加一条与熵系数同步的线性退火：0.60 → 0.50，3000 轮， 每次更新之后硬夹持。

实测校验：第 460 轮时日志记录 0.5847， 按公式 0.60 − 0.10 × 460/3000 算得 0.5847，吻合。

这个机制的定位要说清楚：它只能防退化，抬不高天花板。 那次崩坏的深层原因是课程在 1000 轮就打满、没有更难的地形可爬， 夹住噪声只是保证「到了能力天花板不会再掉下来」。 配套的诊断指标是「被夹持的比例」，实测在 0.5 至 1.0 之间。

10.2 域随机化的内容，正是特权隐变量的内容

时机 随机化项

重置时 出生位姿扰动；关节初始角扰动；机身外力与力矩

这些被随机化的量，正好就是那 29 维特权隐变量的内容。 教师直接知道答案，学生要靠历史反推——这就是 RMA 范式的核心闭环。

10.3 续训时的计数重置

读上面这张超参表时必须记住一件事：所有「按更新轮数退火」的机制—— 噪声上限、熵系数、各类预热——在续训开新目录时会从 0 重新计数、从头再走一遍。 上一版末期的策略是在满额强度下平衡的，续训初期却会回到弱强度， 因此续训的前若干轮不能与上一版末期直接比较。

这类「改了等于没改、而且不报错」的问题在本项目中出现过多次， 成因与防范见工程问题记录的问题卡十六。
