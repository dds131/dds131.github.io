转换、聚合与训练闭环

OpenPI RTC + DAgger RM75 的传输、转换、聚合、版本化训练与权重回传命令及参数作用

项目概览 RTC 复现与接管 纠正数据 数据与训练 安全与验证 工程迭代 论文与路线
TRANSFERAGGREGATIONFULL FINETUNE

保留原始证据，再把“数据变多”变成可复现的训练输入。

采集端只负责稳定记录；训练端负责转换、重建索引与统计量、筛除无完整未来窗口的起点、执行有限步优化，并把 checkpoint 连同配置和数据血缘一起回传。

一、为什么拆成采集/部署域与训练域

采集/部署域直连机器人、三相机、夹爪和 VR，首要约束是控制周期稳定、依赖面可控；训练域拥有 LeRobot 数据栈、原始训练集、多卡资源和基线 checkpoint。把转换放到训练域不是“采集端功能不全”，而是故意隔离实时控制与高依赖数据处理。

因此采集端保留原始 frames.npz + mp4 + meta。它既是转换输入，也是可回放证据：若字段映射、图像预处理或数据集版本后来修正，可以从同一原始记录重新生成纠正库，不必重新做真机接管。前提是原始包、转换器版本和参考 schema 的摘要都被记录；只保留转换结果无法复现转换过程。

二、六步闭环与每一步的停止条件

归档与摘要

冻结完整 session 清单，归档后计算 SHA-256；接收端先写临时文件，摘要不一致立即停止。

原始记录转换

读取参考集 schema，把状态、最终下发命令、三路图像、任务和 intervention 写入新的纠正库。

纠正库独立验证

先验证字段、图像身份、逐帧长度、时间戳和 intervention，再允许进入聚合。

有身份的物理聚合

保留每条 episode，重建 episode/frame/task 索引和全局统计；不能把复制目录当作完成聚合。

有限步全参续训

记录起点 checkpoint、可训练参数数、配置、随机种子和步数；训练输出是一次有限优化结果，不是全局最优解。

回传、验证与重部署

权重、配置、归一化统计和摘要一起回传；独立加载成功后停服切换，再显式重启 RTC。

任一步失败都应停在当前临时产物：转换失败不能污染聚合集，聚合失败不能启动训练，checkpoint 独立加载失败不能替换部署版本。

三、物理聚合不是普通集合并集

普通集合并集符号会暗示重复元素被去重，而示教数据中的相似帧仍是不同时间、不同 episode 的样本。更准确的写法是保留来源身份的不交并/串接：

\[D_i^{\mathrm{agg}} = D_0\uplus D_1^{\mathrm{corr}}\uplus\cdots\uplus D_i^{\mathrm{corr}} .\]

聚合至少要完成：重新编号 episode 与 frame、合并任务词表、校验 feature/fps/robot_type、修正视频和 Parquet 分片引用、重新汇总统计量，并保留每条 episode 的来源轮次。文件能被打开，不代表这些语义已经正确。

训练权重也不能只用原始帧数推断。令 $\mathcal W_s$ 为数据源 $s$ 中经过动作块尾部过滤后可作为训练样本的窗口集合，$M_s=\lvert\mathcal W_s\rvert$。若加载器对全部有效窗口均匀采样，则

\[\mathcal W_i = \mathcal W_0\uplus\mathcal W_1^{\mathrm{corr}}\uplus\cdots\uplus\mathcal W_i^{\mathrm{corr}}, \qquad w_{\mathrm{corr}} = \frac{\sum_{k=1}^{i}M_k}{M_0+\sum_{k=1}^{i}M_k}.\]

这里的 $M$ 是有效窗口数，不是原始帧数 $N$。episode 等概率采样、source-balanced sampler、重复采样或分布式 sampler 都会改变 $w_{\mathrm{corr}}$；“物理聚合”本身不会自动确定纠正权重。最一般的分源目标可写成

\[\mathcal L_{\boldsymbol\alpha}(\theta) = \sum_{s=0}^{i} \frac{\alpha_s}{M_s} \sum_{z\in\mathcal W_s}\ell_\theta(z), \qquad \alpha_s\ge0,\quad\sum_{s=0}^{i}\alpha_s=1 .\]

均匀有效窗口采样对应 $\alpha_s=M_s/\sum_r M_r$。当纠正窗口很少时，失败边界会被稀释；过度提高 $\alpha_s$ 又可能过拟合少数恢复路径并损伤旧任务。权重选择必须同时看纠正保持集、原任务保持集与真机 A/B，不能由 intervention 字段自动推出。

四、有限步续训不等于求得 argmin

原页面把训练结果写成 $\arg\min$，容易让人误以为有限步非凸优化已经得到全局最优。实际产物更接近

\[\theta_i = \operatorname{Train}_{K_i} \!\left( \theta_i^{\mathrm{start}}, D_i^{\mathrm{agg}}, c_i, \xi_i \right),\]

其中 $K_i$ 是优化步数，$c_i$ 是学习率、batch size、冻结策略等配置，$\xi_i$ 包含随机种子和 batch 顺序。它只表示可复现的训练过程输出；是否更好必须由验证集与闭环评测证明。

大规模纠正集也不能把“基础权重”当作防过拟合开关

对规模较大、覆盖多类失败的 LeRobot RTC + DAgger 聚合集，优先从经过大规模预训练的 VLA foundation/base 权重开始适配通常比随机初始化更合理：视觉—语言—动作表征已有良好起点，小学习率续训也更容易保持通用表征。但“从基础权重启动”只决定初始参数 $\theta_0$，不会自动约束训练后的 $\theta$ 仍靠近它，更不能单独保证不对恢复集过拟合。

起点还要由任务关系决定：若现有任务 checkpoint 已在同一机器人、相机、动作语义和任务上稳定验证，短程续训它可能更好地保留当前任务能力；若聚合集覆盖更广、现有 checkpoint 已对窄任务形成明显偏置，或需要建立干净、统一的新训练基线，则从 foundation/base 权重重训更合适。两条路线应在同一留出集和真机协议下对比，而不是只看训练 loss。

可以把抗遗忘目标写成

\[\mathcal L(\theta) = \alpha\,\mathcal L_{\mathrm{new}}(\theta) + (1-\alpha)\,\mathcal L_{\mathrm{replay}}(\theta) + \lambda\,R(\theta,\theta_0).\]

$\mathcal L_{\mathrm{new}}$ 学习恢复数据，$\mathcal L_{\mathrm{replay}}$ 在原始/通用示教上做 replay，$R$ 可选择参数距离、特征保持或输出蒸馏等正则。这个式子是设计模板，不是保证：$\alpha$、$\lambda$、数据覆盖和优化步数都需要验证。实际控制至少包括较小学习率与有限步数、按失败簇划分而不是随机逐帧划分的验证集、旧任务保持集、早停，以及可选的分阶段冻结/LoRA；只有“新失败修复提升且旧任务退化未越过阈值”的 checkpoint 才能进入部署候选。

“全参数”也必须由实际优化器参数集证明。至少记录 freeze_vision_encoder、train_expert_only 等冻结选项以及 trainable/total parameter count；脚本名含 full 不能证明每个模块都在更新。若部署使用 EMA 目录，还要记录 EMA 衰减、更新步数和“训练权重 → EMA 权重 → 部署目录”的映射，不能只凭目录名认定来源。

五、schema 相同之后，还要重建统计与索引

LeRobot 数据集不仅包含样本文件，还包含 episode 边界、task 索引、视频时间戳和全局 feature 统计。聚合后至少检查：

  • 索引：episode_index、frame_index 和 task_index 连续且指向正确来源，episode 边界没有跨文件串接；
  • 时间：每个 episode 内时间戳单调，视频帧与传感/动作采样在容差内对齐；
  • 统计：按聚合集重新计算训练实际使用的 state/action 统计，或明确记录为何冻结旧统计；
  • 预处理：rename_map、relative action、夹爪排除维和图像 resize 的顺序与 checkpoint 配置一致；
  • 采样：动作块尾部过滤后，每个 episode 的有效窗口数大于零，并输出原始帧数到有效窗口数的变化；
  • 血缘：聚合 manifest 记录每个输入库摘要、转换器版本、schema 摘要、episode/帧/有效窗口数量。

归一化统计不是附属文件。统计变化会改变模型看到的 state/action 尺度；checkpoint 回传时若漏掉与本轮训练匹配的配置和统计，即使权重文件能加载，部署输出仍可能系统性偏移。

六、PyTorch 与 JAX：先固定框架边界，再谈速度

本项目现有工作流以 LeRobot/PyTorch 训练和 PyTorch RTC 部署为基线。同一框架能减少权重布局、归一化和策略处理器的跨实现差异。本轮找到 JAX 与 PyTorch 的完整历史训练日志后，可以量化各自条件下的吞吐，但两次运行使用 8 张与 4 张 GPU，不能把聚合速度差直接归因于框架。

OpenPI 上游目前同时提供 JAX 与 PyTorch 训练入口。其官方 README 在本次核对时说明：JAX 训练默认使用混合精度，而 PyTorch 路径使用全 bf16 或全 fp32；PyTorch 路径尚未具备与 JAX 完全相同的混合精度、FSDP、LoRA 和 EMA 能力。实现能力不对称可以解释部分吞吐差异，但上游会变化，最终仍以锁定 commit 的实测为准。

聚合吞吐比为约 2.08×，但 GPU 数量也是 2×；按 GPU 数量粗归一后 JAX 只高约 4.1%。两侧的混合精度、实现、并行、GPU 拓扑、日期和系统负载也不同，所以这些日志只支持“现有条件下的历史运行表”，不支持“JAX 框架本身快 2.08×”。

因此，“JAX 会快很多”应落成一条决策规则：只有当稳定吞吐和端到端训练时长的提升足以覆盖编译、调试、权重转换与双框架维护成本，且固定输入与闭环回归通过时，才采用 JAX 训练；否则保留 PyTorch 闭环。大数据规模会放大稳态吞吐的价值，小规模快速迭代则可能被首次编译与转换成本抵消。

如果选择 JAX 路径而部署仍是 PyTorch，需要额外证明：

  • 参数树、转置规则、dtype 与张量布局逐层对应；
  • 归一化统计、tokenizer、图像和 relative-action 预处理相同；
  • 固定输入下中间特征、损失与动作输出在预定容差内；
  • 离线 rollout、RTC 动作块和低速真机回归通过。

在这些证据完成前，保留原生 PyTorch 闭环是风险控制，不是对任一框架速度的先验判断。

七、摘要、原子切换与回滚分别解决什么

SHA-256 在“参考摘要可信”时能发现传输损坏；它不证明数据语义正确，也不是对恶意替换的身份认证。需要防篡改时，应从可信通道获得摘要或使用签名。断点续传只解决传输效率，不改变这些边界。

安全接收顺序为：临时文件 → 摘要校验 → 解包到临时目录 → manifest/结构检查 → checkpoint 独立加载 → 正式切换。所谓“原子切换”还要求临时目录与正式目录位于同一文件系统，并使用原子 rename 或经过验证的版本化链接切换；跨文件系统移动不能直接声称原子。

文件切换也不等于运行中模型热更新。本项目需要显式停止旧 RTC 服务、把已验证版本设为新启动目标，再重启并检查启动日志。旧 checkpoint、配置、统计和启动命令应作为一个回滚单元保留。

每轮最低验收

  • 纠正库独立 verify 通过
  • 聚合集 episode、帧与有效窗口计数闭合
  • 短训练无 NaN/Inf，参数确实发生预期更新
  • 新 checkpoint 在独立进程加载并完成固定输入推理
  • 纠正保持集与旧任务保持集都报告结果

仍不能由冒烟推出

  • 完整规模一定收敛
  • 纠正样本权重最优
  • 策略真机成功率提高
  • 旧技能没有灾难性遗忘
  • RTC 执行满足真机安全要求

base_dataset 本轮要保留能力的原始示教库 换基集会改变 replay 分布与归一化统计 摘要、schema、episode/有效窗口数明确
correction_datasets 一个或多个已独立验证的纠正库 增加来源会改变有效窗口权重 每个输入保留 round、collection_mode、failure_type 与摘要
aggregate_output 重建索引、统计和 manifest 的新聚合集 是新的训练输入，不是目录复制结果 计数闭合、索引连续、视频引用有效、统计重算或冻结理由明确

8.3 基础训练的已核实命令与参数

下面只保留训练入口、公开参数和值；内部绝对路径和进程清理命令不放入网页。

# JAX 0828：计划 100k，实际完成 75,610 optimizer steps
<JAX_PYTHON> -u scripts/train.py pi05_rm75_rawact_3cam \
  --exp-name rm75_3cam_pi05_0828 --num-train-steps 100000 \
  --lr-schedule.warmup-steps 2000 --lr-schedule.peak-lr 2.5e-5 \
  --lr-schedule.decay-steps 100000 --lr-schedule.decay-lr 2.5e-6 \
  --log-interval 10 --save-interval 1000 --keep-period 1000 \
  --num-workers 32 --fsdp-devices 8 --batch-size 256 \
  --no-wandb-enabled --overwrite --checkpoint-base-dir <OUTPUT_ROOT>

# PyTorch 0924：4 GPU，MB=32，梯度累积 K=2
bash scripts/train_full.sh 32 2 <RUN_NAME>
参数 实际值 作用 调整后的主要影响
JAX --batch-size / --fsdp-devices 256 / 8 global batch 与 FSDP 设备数；每卡约 32 样本 增 batch 增显存与每步样本，吞吐和优化动态需重新测
JAX warmup / peak / decay LR 2,000 / 2.5e-5 / 2.5e-6 先升后降的学习率日程 过高可能破坏基座表征，过低可能在预算内学不充分
JAX save / keep period 1,000 / 1,000 steps 保存和长期保留 checkpoint 频率越高，保存长尾和存储量越大；本次 75 个约 3.1 TB
PyTorch MB / K 32 / 2 有效 global batch = 4×32×2=256 K 同时改变 micro-step 与 optimizer-step 的换算
PyTorch precision BF16；gradient checkpointing 开；compile 关 控制数值格式、激活重算与编译路径 影响显存、速度与数值对齐，不能脱离条件比较
PyTorch LR / EMA 5e-5→5e-6；EMA 0.99 参数更新日程与部署 EMA 轨迹 EMA 权重和普通权重必须分别留档与评估
PyTorch seed / workers 1000 / 8 随机性与数据加载并发 改值会改变批次顺序或加载行为，应进入 run manifest

8.4 两条 DAgger 训练命令不能混为同一版本

<PROJECT_SHELL> scripts/train_dagger_full.sh \
  --policy.path=<BEST_TASK_CHECKPOINT>/pretrained_model \
  <需由锁定版本核验的 CLI/环境输入：聚合数据、步数、batch、优化器、输出>

<PROJECT_SHELL> scripts/train_dagger_from_base.sh
<需由锁定版本核验的 CLI/环境输入：foundation 权重、聚合数据、训练配方、输出>
命令或参数类别 作用 增大 / 改变后的效果 必须保存的证据
scripts/train_dagger_full.sh 2026-10-08 基线：从大规模任务后训练的最佳 checkpoint 做有限步全参续训 继承当前任务能力，减少从头适配成本；仍可能遗忘或过拟合 脚本摘要、完整解析配置、起点 checkpoint 摘要
--policy.path=<...>/pretrained_model 留存记录明确的权重 + checkpoint 配置加载入口 改路径会同时改变起点权重和随 checkpoint 保存的配置 路径对应不可变 artifact；首批 feature 与统计匹配
steps 参数类别 控制优化更新次数；基线文档记录约 5k–20k 更多步通常拟合更充分，也提高过拟合、遗忘和训练成本 实际完成步数、学习率曲线、早停原因；不要把区间写成默认值
aggregate_dataset 参数类别 选择聚合后的训练输入 换数据会改变样本分布和统计 manifest 摘要、episode/帧/有效窗口数
batch / gradient accumulation 参数类别 决定每次更新的有效样本量与显存占用 有效 batch 增大通常降低梯度噪声，但更占显存并可能要求重调学习率 单卡 batch、卡数、累积步数及最终有效 batch
optimizer / learning rate 参数类别 决定参数更新规则与步幅 学习率过大可能破坏已有能力，过小可能在预算内学不到纠正 优化器、调度器、峰值/末值学习率、梯度范数
freeze / trainable scope 参数类别 决定哪些参数参与优化 冻结更多可省显存并减小漂移，但限制适配能力 trainable / total 参数数；脚本名 full 不是证据
output 参数类别 隔离 run 配置、日志与 checkpoints 换目录不改变算法，但决定可追溯与回滚能力 run manifest、配置、统计、普通/EMA 权重与摘要
scripts/train_dagger_from_base.sh 2026-10-09 后续路线：从 foundation 权重启动 更接近统一重训基线，预算更大；不是 10-08 已执行事实 单独版本、单独结果，不能与续训日志合并

env/rm75_dagger_env.sh 是留存记录中的路径/数据集/checkpoint/GPU 变量文件，但现有证据没有说明训练脚本是 source 它、子进程读取它，还是由外层作业注入变量。因此页面只记录其配置职责，不给出未经核验的 source env/... 命令。最终命令记录应保存变量名和值的脱敏快照，并说明命令行、环境变量与默认值的优先级。

8.5 回传与重部署只确认了一个真实参数

<TRANSFER_BACK_WITH_DIGEST> <ROUND_N_ARTIFACT_BUNDLE>
<RTC_SERVER_ENTRY> --ckpt <ROUND_N_CHECKPOINT>/pretrained_model_ema

ROUND_N_ARTIFACT_BUNDLE 应把权重、config、归一化统计、运行清单和摘要作为一个版本单元；--ckpt 是原始需求明确留下的 RTC 服务参数，改变它会改变服务端加载模型。pretrained_model_ema 是留存记录指定的部署子目录，但目录名本身不能证明 EMA 衰减、更新步数或文件配套。正确顺序是：摘要通过 → 临时解包 → 独立加载/固定输入推理 → 停止旧服务 → 指向新 --ckpt → 显式重启 → 检查启动日志；失败则回到上一整套 artifact，而不是只替换权重文件。

命令完整性边界：训练侧私有脚本及帮助输出不在当前网页工作区，所以上述内容详细解释了每个输入类别的作用与效果，但没有把类别名称伪装成真实 flags。若后续取得只读源码，应先记录实际 --help，再逐条替换占位符，并用微型数据集复跑转换、验证、聚合和两步训练。

九、知识点、重点与工程创新

知识点

  • 数据不交并与样本身份
  • 有效窗口分布与隐式采样权重
  • 有限步优化、过拟合与灾难性遗忘的区别
  • JAX/PyTorch 的等条件吞吐与数值对齐
  • schema、索引、统计与 checkpoint 的共同契约

本页重点

  • 转换前后都有独立质量闸
  • 版本化区分 checkpoint 续训与 foundation 启动
  • 基础权重、replay、正则和早停共同控制遗忘风险
  • 训练清单记录起点、配置、随机性和参数范围
  • 部署切换必须可加载、可追溯、可回滚

工程创新点在于把一次 DAgger 迭代定义为带血缘的事务：原始包摘要、转换 manifest、有效窗口统计、训练 run manifest 与部署 artifact manifest 首尾相接。这样“哪个 episode 影响了哪个 checkpoint”可以追踪；这是本系统的工程可审计设计，不是新的优化理论。

十、相对源码与证据边界

相对模块 职责 本轮内容审计能确认的边界
tools/xfer_serve.sh / xfer_fetch.py 归档、摘要、临时服务与断点续传 需求文档记录端到端摘要一致；本轮未复跑跨机传输
convert/record_to_lerobot.py 原始记录转 LeRobotDataset 需求记录参考 schema 转换通过；本轮未读取目标容器外的原实现
convert/verify_dataset.py 字段、样本与 intervention 校验 页面给出应验项目；不能把旧日志当作新数据已通过
scripts/aggregate_dataset.py 原始集与纠正集物理聚合 需求记录微型集冒烟；不证明完整集索引/统计均正确
scripts/train_dagger_full.sh 从任务 checkpoint 继续训练 需求记录两步更新与保存；不证明收敛、泛化或真机提升

外部实现边界参考 LeRobot π₀.₅ 文档、LeRobotDataset v3 文档、OpenPI PyTorch 训练入口 与 OpenPI 数据加载器。上游主分支会变化；项目实际行为必须锁定依赖版本、命令与生成配置，不能由当前网页反推旧环境。

可核验性说明：本轮已只读核对基础数据管线、JAX/PyTorch 正式训练日志、训练脚本与 checkpoint 配置，因此这些基础指标已从“待核验”升级为 C 级历史运行证据。DAgger 私有转换、聚合和再训练脚本仍只有需求记录，不能用基础训练结果替代；完整 checkpoint—数据集—配置—trial 绑定也仍缺统一不可变 manifest。
