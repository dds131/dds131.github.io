网络结构设计

冻结深度基础模型主干、以本体感受为查询的交叉注意力、GRU 时序头与三个自监督解码头的逐层规格，32 维瓶颈为什么是整个设计的枢纽，以及参数量的三重独立校验

← 项目主页 ·感知与观测 ·网络结构设计 ·损失、优化器与训练机制 ·工程演进与问题记录 ·结果与视频画廊

一、三个设计选择

本页把单目 RGB 感知网络与 Actor / Critic 拆到模块一级：每一层吃进什么、输出多少维、用什么激活、 有多少参数、由谁训练。全部层规格与参数量都经过三重独立校验（结构反推、checkpoint 逐前缀实测、 运行时日志），校验过程放在第七节。

结构上可以概括为：这套感知网络是一个冻结的深度基础模型主干，外加约 90 万参数的可训练外壳 （编码器主干可训练量 897,794，不含三个自监督重建解码头）。外壳的职责是把主干输出的图像 token 序列 压成 32 维的视觉潜变量；而这 32 维独占地承担「地形几何信息进入策略」的全部通道 —— 雷达版本里由真高程图与真环状距离图走的那条特权通路，在本项目的 actor 侧被整体旁路。

本节先自讲三个概念（站内知识点板块尚无对应页面）：深度基础模型主干、交叉注意力、GRU 递推； 其中 GRU 递推是子页③讲 截断式随时间反向传播（BPTT）的前提。随后回答三个设计问题。

概念一：深度基础模型主干是什么

主干是 Depth-Anything-V2 的度量深度版本，规格为 ViT-S/14（下称深度基础模型主干；源码语境下写作 DA-V2）。 它的构成与本项目的用法如下。

  • 它怎么把一张图变成 token。输入 112 × 112 的 RGB 图，按 14 × 14 的 patch 切分， 得到 112 // 14 = 8，即每帧 8 × 8 = 64 个 patch。每个 patch 经线性投影成一个 384 维 token， 再补一个全局 CLS token，共 65 个 token 送入 12 层 Transformer block。
  • 本项目只取中间层。逐 block 前推，在索引 3 / 7 / 11（即 12 层里的第 4 / 8 / 12 层） 各截取一次 tokens[:, 1:]（丢掉 CLS），得到三份 [B, 64, 384]。 取三个不同深度的层，是为了同时拿到偏低层的边缘与纹理、偏高层的语义与布局。
  • 从不产出深度图。权重文件里还带着一个度量深度回归头（features = 64、 out_channels = [48, 96, 192, 384]、max_depth = 20.0），它随权重一并加载、 一并计入 24,785,089 的参数量，但前向路径只包含 patch 嵌入与 12 个 Transformer block， 深度回归头不参与计算。本项目全程不生成任何深度图，也不把深度图当作策略输入。
  • 为什么它的中间层特征自带几何先验。该主干的预训练任务就是单目度量深度估计： 要从单张图回归出每个像素的米制深度，中间层表征必须把表面布局、相对远近、边缘与遮挡关系编码进去 —— 这正是四足运动策略需要的那部分信息。复用这份表征，等于把「从像素里恢复几何」交给一个 已经在大规模数据上学过的模型，强化学习的样本预算不必再花在这上面。
  • 三重冻结。① 全部参数 requires_grad = False； ② 常驻 eval 模式（编码器重写了 train()，把主干重新钉回 eval，训练循环调用 train() 也翻不动它）； ③ 前向整段包在无梯度上下文里 —— 连中间激活都不保存，因此既省显存也不可能有梯度泄漏。
  • 冻结一个 ViT 不需要担心归一化统计量。实测该主干是 239 个张量、0 个 buffer： ViT 用 LayerNorm 而非 BatchNorm，没有随前向更新的统计量，所以「冻结」只需管住 requires_grad 与 eval 两件事，不存在卷积网络里「参数冻住了但统计量仍在被污染」的坑。

这一条是设计前提，不是本项目验证过的结论（推测）：「深度预训练主干的中间层比同规格的随机初始化主干 或分类预训练主干更适合本任务」这一判断，本项目没有做过消融。可验证的下一步是保持其余部分 逐位不变、只替换主干（随机初始化 ViT-S/14 一档、分类预训练主干一档）各训一档做对照； 代价是每档一次完整量级的重训（本项目单档计划 30000 轮）。

概念二：交叉注意力 —— 用本体感受去检索图像

注意力机制的一般形式（推导见知识点板块的注意力机制页）：

attn(Q, K, V) = softmax(Q Kᵀ / sqrt(d_k)) V

自注意力里 Q、K、V 来自同一个序列；交叉注意力的区别只有一点：Q 来自另一路输入。 本项目的用法是：

query = q_proj(prop)        [N, 1, 64]      本体感受 53 维投影成 1 个查询向量
key   = value = tokens      [N, 192, 96]    3 帧 × 64 patch 的图像 token（同一张量）
out   = cross_attn(query, tokens, tokens)   [N, 1, 64]

语义是：以当前的运动状态为条件，去图像里检索相关的区域。查询向量携带的是 「我现在的姿态、指令与速度是这样」，注意力权重由它与 192 个图像 token 的相似度算出， 输出是这 192 个 token 各自经值投影之后的一次凸组合（再过一层输出投影），不是 token 原值的加权平均。 机器人向右转时，注意力可以自行把权重挪到画面右侧的 patch 上； 机身俯仰变化时，可以挪到画面近端。同一组权重能表现出随运动状态变化的读图方式 —— 这是把 patch 拍平接 MLP 做不到的（下一小节展开）。

概念三：GRU 递推

GRU（门控循环单元）的全部内容可以压成一行递推：

h_t = f(h_{t−1}, x_t)

即：当前隐状态由上一步的隐状态与当前输入共同决定。展开成两个门与一个候选状态（σ 为 sigmoid）：

r_t = σ(W_ir x_t + b_ir + W_hr h_{t−1} + b_hr)                    重置门
z_t = σ(W_iz x_t + b_iz + W_hz h_{t−1} + b_hz)                    更新门
n_t = tanh(W_in x_t + b_in + r_t ⊙ (W_hn h_{t−1} + b_hn))         候选状态
h_t = (1 − z_t) ⊙ n_t + z_t ⊙ h_{t−1}                             线性插值

最后一行是关键：新隐状态是候选状态与旧隐状态的逐元素线性插值，插值系数由更新门给出。 更新门接近 1 时旧状态几乎原样保留，信息可以跨越很多步不衰减；接近 0 时则被新观测整体覆盖。 重置门、更新门与候选状态各需一套输入权重与一套隐状态权重，所以隐藏宽度 512 的单层 GRU， 其权重矩阵有 3 × 512 = 1536 行 —— 这直接决定了它的参数量（第二节给出逐张量拆解）。

对本项目有两个直接后果，都要留到子页③才能展开：

  1. 梯度必须沿递推链回传。第 t 步的输出依赖于本回合从起点以来的全部输入， 要让更早的观测收到梯度，就必须沿 h_t ← h_{t−1} ← … 反传，这就是截断式随时间反向传播（BPTT）的由来。
  2. 隐状态在采样与训练之间是连续滚动的，一个回合内只在 done 时清零。 于是「训练时用的隐状态」与「推理时实际滚出来的隐状态」可能不是同一个分布 —— 训练分布与使用分布不一致（regime mismatch）的问题就出在这里。

选择一：为什么用交叉注意力，而不是把图像特征拍平接 MLP

主干每帧输出 64 个 patch token，3 帧就是 192 个 token；经分组池化与三层拼接后每个 token 是 96 维。 若把它们直接拍平，得到的是 192 × 96 = 18,432 维的向量。

方案 第一层的形状 第一层参数量 对运动状态的条件性
拍平接 MLP Linear(18432, 512) 约 944 万 无。不管当前指令是直行还是右转，都用同一组权重去看同样的 patch
以本体感受为查询的交叉注意力 q_proj + cross_attn + output_proj 26,272 有。注意力权重由本体感受查询与图像 token 的相似度算出

交叉注意力本体（cross_attn）只有 20,736 个参数，比拍平方案的第一层小 455 倍； 把查询投影 3,456 与输出投影 2,080 一并算上也只有 26,272。而且拍平方案的 944 万还只是第一层， 后面还要接若干层才能到可用宽度。

换句话说，交叉注意力在这里同时带来两点收益：参数量低两个半数量级， 以及读图方式可以随运动状态改变。

选择二：为什么要 GRU，而不是纯前馈

单目 RGB 恢复几何是欠定问题。一张图里「远处的宽沟」与「近处的窄沟」在像素上可以完全一样 —— 这是单目视觉固有的尺度歧义：在纯几何意义上，单帧无法判定绝对尺度。 前馈网络能做的是依靠训练中学到的先验（物体的典型尺寸、纹理梯度、地面假设）做统计意义上的定标 —— 本项目使用的度量深度主干正是这样工作的，但它的先验来自室内场景，对跑酷地形的凹陷并不对症。 因此本设计另外补上一条与先验互补、且在几何上确定的线索：运动视差 —— 自身运动时，近处的物体在画面上移动快，远处的移动慢。

利用运动视差需要两件事，本设计各配了一件：

多帧输入 —— 提供瞬时视差

编码器一次吃 T = 3 帧，覆盖 t / t−0.5 s / t−1.0 s。 帧间隔为 25 个控制步，控制周期 20 ms，故 25 × 0.02 s = 0.5 s。 三帧同时进入注意力，网络可以在同一次前向里比较同一空间位置在三个时刻的表现。

时序记忆 —— 累积跨百步的信念

GRU 隐藏宽度 512，隐状态在一个回合内只在 done 时清零。 回合上限 40 s，控制步 0.02 s，即上限 2000 个控制步（实际因提前终止更短）。 所以它承载的不只是最近 3 帧，而是「这一路走过来对周围地形的累积理解」。

代价也在这里：隐状态跨越上千步连续滚动，训练时如何取到与推理时同分布的隐状态、 反传截断到多长，都成了必须专门处理的问题。这部分属于 子页③。

选择三：为什么 32 维瓶颈是整个设计的枢纽

output_mlp 把 512 维隐状态压到 34 维，其中前 32 维就是视觉潜变量。 在 actor 那一侧，只有一行赋值：把这 32 维直接当作 fused，与本体感受 53 维拼成 85 维， 整体旁路掉雷达版本原有的「真高程图经 scan_encoder、再经 fusion_mlp 与雷达特征融合」这条特权通路。

由此得到一条结论：地形几何信息到达 actor 的通道，有且仅有这 32 维。

  • 好处：actor 在训练时与推理时看到的外部感知输入完全一样（都是这 32 维）， 感知侧不存在训练与部署之间的输入分布落差。
  • 代价：这 32 维必须靠自己变好。PPO 这条路径上，编码器输出在进入 actor 之前 被无梯度上下文与 detach 双重切断，PPO 对编码器的梯度恒为 0； 自监督重建是编码器唯一的梯度来源。它不是附加的辅助项，它是编码器的全部。

32 这个宽度是怎么定下来的：它并不是为 RGB 单独调出来的超参， 而是取自雷达版本 scan_encoder 输出宽度配置 [128, 64, 32] 的最后一项。 保持这个宽度，actor 的输入拼接宽度就与特权教师版本逐位一致， 两边的权重可以互相加载与续训 —— 这也是第五节里那三条「被绕过但保留」的支路的同一个理由。

自监督重建的损失口径、系数、优化器与梯度边界属于 子页③； 本页只负责结构。

二、编码器逐层规格

编码器由两段组成：主干（从 RGB 到 32 维视觉特征的那一段）与时序头（融合、GRU、输出投影）。 两段合起来的可训练量是 897,794；再加上第四节的自监督重建解码头，才是一档的编码器可训练全量。

v6 相对上一版只替换了编码器类名，主干类沿用上一版；权重的键与形状逐键相同， 上一版的权重可以直接续训。这一点在第四节还会再出现一次（末层有界激活是无参改动）。

2.3 交叉注意力的 20,736 参数拆解

nn.MultiheadAttention 在 kdim == embed_dim 时会把三个投影合并成一个 in_proj_weight； 本项目 kdim = vdim = 96 而 embed_dim = 64，PyTorch 因此改用三个独立投影：

张量 形状 参数量
q_proj_weight 64 × 64 4,096
k_proj_weight 64 × 96 6,144
v_proj_weight 64 × 96 6,144
in_proj_bias 192 192
out_proj.weight / out_proj.bias 64 × 64 与 64 4,160
合计   20,736

这个判断不是纸面推理：checkpoint 里 cross_attn 前缀下实测就是 6 个张量， 与三独立投影的形态吻合（第七节校验项 3）。

图 1 · 交叉注意力内部。查询只有一个 token（当前时刻的本体感受）， 键与值是 192 个图像 token。因为 kdim 与 embed_dim 不相等， 三个投影矩阵无法合并成一个大矩阵，在 state_dict 里表现为 6 个独立张量。

GRU 的 838,656 拆解（两个门与候选状态各一套权重，故权重矩阵有 3 × 512 = 1536 行）：

张量 形状 参数量
weight_ih_l0 1536 × 32 49,152

一个张量占掉大半个网络。 weight_hh_l0 单个张量就是 786,432 个参数， 按 A 档编码器可训练全量 1,289,430 计，占 61%；整个 GRU 占 65.0%（A 档口径） 或 53.1%（B 档口径，分母换成 1,579,538）。三个百分比的分母不同， 引用时必须带口径。权重变化率实测中，GRU 是编码器内部变化最大的模块；全模型范围内还需同时报告状态估计器， 后者在最近 500 轮的相对变化率更高。

2.5 两处「零参数」设计

分组均值池化为什么不带权重。三层各 384 通道、拼起来是 1152 维； 按 12 个通道一组求均值压到 32 通道，三层拼接后得到 96 维 token。 这是在进入注意力之前先做一次无参降维：若把 1152 维直接当键与值， cross_attn 的 kdim 就是 1152，其 k_proj_weight 与 v_proj_weight 会各自涨到 64 × 1152， 参数量翻十二倍。用无参池化换掉这部分参数，代价是通道内的细粒度区分被平均掉。

combination_mlp 为什么把 85 维压回 32 维。两个理由：

  1. 算力。GRU 的计算量主要是 O(hidden²)，输入宽度只影响 weight_ih（形状 1536 × input）。 把输入从 85 压到 32，weight_ih 从约 13 万降到 49,152。
  2. 更重要的是表示上的。它强迫视觉与本体感受在进入时序记忆之前先融合， 而不是把 85 维原样丢给 GRU、让 GRU 自己去分辨「这 85 维里哪些是图像、哪些是关节角」。 进入递推的是一个已经融合过的 32 维向量。

2.6 激活与初始化

全网只用两种激活：ELU 出现在 output_proj 与 combination_mlp 的中间层， Tanh 只出现在 output_mlp 的末层；q_proj 与 combination_mlp 末层是纯线性； GRU 内部的 σ 与 tanh 由门结构自带、不可配置；三个解码头的末层用的是有界版本（第四节）。

末层这个 Tanh 值得单独一提：它使视觉潜变量天然有界，下游 actor 拿到的永远是 −1 至 +1 的量， 不需要额外归一化；代价是存在饱和风险 —— 「饱和率」这个诊断量就是为它准备的， 实测值见子页③。

初始化方面：编码器各模块未见自定义初始化设置的记录；构造完成后对 rnn 调用了一次 权重扁平化，使 GRU 的权重在显存里连续排布以便 cuDNN 走快路径 —— 这是内存布局操作，不改变数值。 本项目里唯一有记录的零初始化出现在 fusion_mlp 的末层，而该模块在本项目中被整体旁路（第五节）， 其设计意图属于雷达版本，见 雷达项目 · 网络结构与训练细节。

3.1 第 11 至 12 步：帧序编码为什么必要

第 12 步把 [N, 3, 64, 96] 摊成 [N, 192, 96]，192 个 token 被平等地丢进注意力。 而注意力本身是置换不变的：打乱这 192 个 token 的顺序，输出完全不变。

如果不加帧序编码，网络就无法区分「这个 patch 来自当前帧」还是「来自 1 秒前」。 但运动视差恰恰依赖于区分哪一帧在前、哪一帧在后 —— 视差的符号与大小都由时序决定。 加上 nn.Embedding(3, 96) 这 288 个参数之后，同一空间位置在不同时刻的 patch 被加上了不同的偏置向量，注意力才能把「同一处地形在三个时刻的样子」区分开来，视差信息才可用。

288 个参数占编码器可训练量的 0.02% 量级，但它是第二节「选择二」那条论证能否成立的必要条件： 没有它，多帧输入退化成三张互相无法区分的图。

4.2 五条必须讲清楚的事实

① 末层有界激活没有改变任何权重形状。 上一版的解码头末层是裸 nn.Linear（无激活）； v6 不改前向、不改权重形状，只在取辅助预测的接口里套了一个无参激活。 后果是 state_dict 的键与形状与上一版逐键相同，上一版权重可以直接续训。

② 为什么必须留越界余量。 有界 sigmoid 的写法是 1.05 · σ(x) − 0.025， 即输出区间在 0 至 1 的两端各外扩 0.025、合计比目标区间宽 5%（常量 0.05 指的是总宽度比例， 不是单端余量）。高程图那一路的 1.05 · tanh(x) 则是两端各外扩 0.05。理由是环状距离图的目标里 约 90% 是端点哨兵值 —— 超出量程时填的固定值 0 或 1。若用纯 sigmoid， 输出永远够不到 0 与 1（只在自变量趋于正负无穷时逼近）， 损失为了逼近端点会把权重一路推大，这是典型的饱和发散。 留出余量后，端点变成可以真正达到的内点，梯度恢复正常。

σ_b(x) = 1.05 · sigmoid(x) − 0.025        有界 sigmoid，余量 0.05
tanh_b(x) = 1.05 · tanh(x)                有界 tanh，同样的余量思路

③ 为什么高程图头用 tanh、另外两个用 sigmoid。 只是目标值域不同： 高程图归一化到 −1 至 1（对称），故用 tanh；环状距离图与深度图归一化到 0 至 1（单侧），故用 sigmoid。

④ B 档为什么是「冻结」而不是「删掉」地形解码头。 B 档把 terrain_decoder 整体 requires_grad_(False)，它仍留在 parameters() 里，只是被辅助优化器的「只收可训练参数」过滤掉。 选择冻结而非删除的理由是权重互操作性：续训走的是允许键不匹配的宽松加载， 如果把这个头删掉，state_dict 会少 6 个键，将来 A 档从 B 档的 checkpoint 续训时 会静默丢掉一个已经训了两万轮的解码头，日志里只留下一句「跳过 N 个不兼容张量」。 保留键就是保留互操作性。附带收益是省下这部分的优化器状态（约 0.47 MB）。

⑤ 解码头必须是子模块。 代码里有硬断言拦截：若解码头没有注册为编码器的子模块， 它就不会出现在 encoder.parameters() 里，也就进不了辅助优化器 —— 表现为「训了两万轮但权重一动不动」。 这类失效是静默的，所以用断言在构造期就拦下来。B 档的训练日志里能看到对应的自检输出： 两个解码头均属于 encoder.parameters()、有界激活已开启且数值自检通过、terrain_decoder 处于冻结状态。

重建损失的具体形式（方差归一化的 MSE、系数 0.20、预热轮数、决定系数（R²）的两种口径）、 辅助优化器与梯度边界，全部属于 子页③ 损失、优化器与训练机制； 两档在策略表现上的对照与其显著性判断属于 子页⑤ 结果与视频画廊。

5.3 v6 对 actor 前向的两处改动

改动一：一行赋值旁路掉整条特权感知通路。 原本的路径是 「真高程图 → scan_encoder → 与雷达特征经 fusion_mlp 融合 → fused」； v6 把 fused 直接赋成外部传入的视觉潜变量。后果是 scan_encoder、lidar_encoder、fusion_mlp 三个模块在本任务中完全不参与梯度计算，它们的梯度是 None，优化器遇到就跳过。

旁路不等于漏训。 这三个模块合计 405,024 个参数，实测权重变化率 0.0000% —— 这是设计使然而非配置疏漏。保留它们是为了与特权教师版本的权重保持互操作： 键集不变，两个方向的续训与对拍都还能做。只有当外部没有传入视觉潜变量时才会走回父类的原路径 （用于可视化与特权对拍），训练时永不触发。

改动二：屏蔽 base[:, 188:194]。 这一处需要连同勘误一起写，否则会传播一个错误说法。

5.4 动作与动作分布

主干输出 12 维（Go2 的 12 个自由度），末层无激活。动作先与一个可学的标准差组成正态分布并采样， 再乘缩放系数 0.25 作为关节角增量叠加到默认关节角上，由 50 Hz 的 PD 控制器执行。 动作语义、指令定义与关节顺序的完整说明属于雷达项目的 强化学习方法页。

标准差是 nn.Parameter（每个关节一个标量，初值 0.6），不是网络输出。 选择全局参数而非状态相关标准差的理由是：状态相关的标准差允许策略在高惩罚状态下增大动作方差 以降低期望惩罚，这是一种刷分行为；全局标量加上限退火，可以保证探索量只随训练进度单调下降， 不被状态操纵。夹持区间与退火表属 子页③。

雷达版本的双编码器、门控设计、五个优化器与梯度饥饿问题都属于 雷达项目 · 网络结构与训练细节页， 本页不重复。

一个容易被简化掉的事实：actor 的外部感知虽然只剩 RGB，但它仍然直接读取显式特权量与特权潜变量 （第 2、3 段）。因此本项目的 actor 仍是特权观测教师策略，不是可以直接上机的学生策略。 第 3 段的插槽已经准备好了替换路径（历史编码器），第六节提到的状态估计器也是为替换第 2 段做准备， 但把它们接成一个完整的可部署学生策略并部署到实体机器人，是尚未执行的独立阶段。

六、Critic

Critic 完全沿用雷达版本的特权 critic（RingSlimCritic），本项目一个字节都没有改。 它不是基类那个吃 1473 维裸观测的大 MLP，而是先用两个自己独立的编码器 把真高程图与真环状距离图各压成 32 维，再与其余三段拼接。

两个要点：

  • critic 的 scan_enc / ring_enc 与 actor 的 scan_encoder / lidar_encoder 完全独立， 不共享任何权重。actor 侧那两个已经被旁路，critic 侧这两个照常训练并直接吃真值。
  • critic 持有的 actor 引用被放进普通 Python 列表，不注册为子模块。 这样 critic.parameters() 不会把 actor 的参数再数一遍，也不会让同一批参数 重复进入优化器 —— 这是同时持有对方引用的两个模块之间的标准写法。

6.2 非对称 Actor-Critic：为什么 critic 可以特权而 actor 不行

这是一个标准的非对称 Actor-Critic 结构（算法背景见知识点板块的 Actor-Critic 与 PPO）：

Critic 只在训练时存在

它的输出只用来算价值与优势，训练结束后整个模块被丢弃，不参与任何部署形态。 因此「它读了什么」不构成任何部署约束。给它全部特权信息，价值估计更准， 优势函数的方差更小，PPO 的更新更稳。

Actor 的每一路输入都是一笔负债

actor 将来要以某种形式跑在机器人上，它读的每一路量都必须在那时有可获取的替代来源。 所以加一路特权输入，蒸馏阶段就多一路要替换的东西。

这条边界在本项目里是这样划的：

特权信息 actor 能不能读 理由
真高程图 132 维、真环状距离图 720 维 不能 真机上既无法直接获取也难以可靠估计，因此整条通路换成单目 RGB 的 32 维视觉潜变量
显式特权量 9 维（有效的是机体系线速度） 暂时读 可由状态估计器从本体感受推断，替换路径已在训练中并行准备
特权潜变量 29 维（质量、质心、摩擦、刚度、阻尼） 暂时读 可由历史编码器从 10 帧本体感受推断，替换路径同样已在准备

所以「critic 特权、actor 不特权」这句话的精确版本是： critic 可以永久特权；actor 只在那些存在可替换路径的段上暂时特权， 而在没有可替换路径的地形几何这一段上被彻底换成了 RGB。

6.3 相关模块：状态估计器

状态估计器不属于 actor 也不属于 critic，但它出现在参数总账里，且与上面的边界划法直接相关： Linear(53,128) ELU Linear(128,64) ELU Linear(64,9)，共 15,753 个参数， 输入是本体感受 53 维，监督目标就是 actor 第 2 段读到的那 9 维显式特权量。

一个必须写明的缺陷：监督目标那 9 维里只有前 3 维携带信息（机体系线速度乘 2.0）， 后 6 维恒为 0，因此状态估计器有 2/3 的输出在学习「预测常数 0」，这部分不产生有效监督信号。 实测它的权重变化率是全场最高之一（5.7% 至 5.9%），说明它确实在学， 但有效学习内容只有 3 维线速度。本轮训练中 actor 第 2 段读的是真值，估计器的输出不进 actor； 它的独立反传、独立裁剪与独立更新属 子页③。

前两步都基于「读文件」。第三步来自训练进程自己在构造辅助优化器时打印的统计， 它反映的是运行时真正生效的状态。两档日志的实际输出（去掉了与本页无关的标记）：

A 档：
[PPOWithExtractorRgb] DA-V2 可训练参数张量 0/239(档次1 期望 0=全冻);
                      编码器可训练(含 terrain_decoder)张量 33, aux_optimizer 训练之

B 档：
[PPOWithExtractorRgb] DA-V2 可训练参数张量 0/239(档次1 期望 0=全冻);
                      编码器可训练(含 terrain_decoder)张量 27, aux_optimizer 训练之
[rgbgap][encoder]     2 个解码头均属于 encoder.parameters(); 有界激活 = 开(数值自检通过);
                      terrain_decoder = 冻结(B 档死参数)

这四个数字同时锁死三件事：

观察 证明了什么
0/239 冻结主干的 239 个张量没有一个可训练。而 239 这个数是从 checkpoint 独立统计出来的 —— 两个来源互不依赖却完全吻合
A 档 33 个可训练张量 274 总键 − 239 冻结主干 − 2 归一化 buffer = 33。可训练张量数与 state_dict 键数的差额被完全解释，没有遗漏的键
B 档 27 个，比 A 档少 6 地形解码头恰好 6 个张量（3 层各 weight 与 bias）。这证明「B 档冻结地形解码头」在运行时确实生效，而不只是代码里写了

三条由实测澄清的细节：

  1. 冻结主干是 239 键、0 个 buffer。 ViT 用 LayerNorm 而非 BatchNorm， 没有随前向更新的统计量，所以冻结只需管住 requires_grad 与 eval 模式， 不存在「参数冻住但统计量被污染」的隐患。
  2. 主干前缀下那 2 个键、6 个参数是 ImageNet 均值与标准差（各 [1,3,1,1]）， 注册为 buffer —— 会进 state_dict，但不是可训练参数。这正是 274、239、33 三个数能对上的关键。
  3. cross_attn 实测是 6 个张量，印证了 2.3 节的判断： kdim 与 embed_dim 不等时 PyTorch 使用三个独立投影，而不是一个合并的 in_proj_weight。

7.7 其余结构侧校验

除上述三重校验外，还逐项核对了：维度累加（53+132+9+29+530=753，753+720=1473； actor 53+32+9+20+16=130；critic 53+32+32+9+29=155）、 两个模块的拼接顺序（5.2 与 6.1，顺序错位不会报错但会让主干读到错乱输入）、 history_encoder 的逐层形状链（5.1）、yaw_encoder 的输入切片、 屏蔽操作是否污染原张量（先克隆，不污染）、以及那个被判定为空操作的屏蔽（5.3）。 结果均已写在对应小节里，此处不再重复列表。 控制频率、相机内外参与地形生成属于环境侧，其校验见 子页① 感知与观测。

本页的边界：本页只讲结构。梯度从哪来、往哪去、在哪里被截断，四个优化器各管哪些参数， 截断式随时间反向传播（BPTT）的窗口怎么取，重建质量用什么口径衡量 —— 这些全部属于子页③ 损失、优化器与训练机制。 这套结构在演进过程中踩过的坑与对应的修复记录属于 子页④ 工程演进与问题记录。
