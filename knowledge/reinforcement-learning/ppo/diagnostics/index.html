PPO 的许多故障会共享相似表象：回报不升、突然崩溃或种子差异巨大。有效诊断不能从“调小学习率”开始，而应先判断是环境语义、数据管线、策略分布、Critic、优化强度还是评估协议出了问题，并用最小实验否证错误假设。

先语义环境与 Storage 正确性
再数值Shape、NaN、尺度、梯度
后优化KL、clipfrac、Epoch、LR
多种子区分偶然与系统性问题

诊断模板： 症状 → 可观测证据 → 至少两个竞争假设 → 一次只改变一个因素的短实验 → 预测结果 → 结论。不预先声明预测结果的参数试验无法形成可复用证据。

1. 总体诊断树

flowchart TB
  A["回报不升 / 崩溃 / 高方差"] --> B{"NaN、Inf 或 Shape 异常?"}
  B -->|是| C["冻结 Batch，检查分布、GAE、广播、梯度"]
  B -->|否| D{"随机策略与零动作的环境指标合理?"}
  D -->|否| E["查奖励、终止、动作映射、观测坐标与 wrapper"]
  D -->|是| F{"Critic 能解释 Return?"}
  F -->|否| G["查 Bootstrap、Return 尺度、Value 结构与更新"]
  F -->|是| H{"KL / clipfrac / ratio 异常?"}
  H -->|是| I["查 LR、Epoch、Mini-batch、优势尺度、std"]
  H -->|否| J{"训练好但评估差?"}
  J -->|是| K["查 eval 动作、归一化、随机化与泄漏"]
  J -->|否| L["检查探索、奖励可识别性、任务难度与容量"]

任何分支都先在短预算、小环境、固定 Seed 上复现。长训练只会让错误更昂贵。

2. 最小观测面板

层 必备指标 回答的问题
环境 Return、成功率、Episode 长度、终止原因、各奖励项 策略性能是否真实提升，是否利用奖励漏洞
数据 obs/reward/return/advantage 分布，terminated/truncated 计数 输入和目标是否有合理尺度与边界
Actor KL、clipfrac、ratio 分布、entropy、逐维 std、动作饱和率 策略移动多快、探索是否健康
Critic Value Loss、explained variance、value/return 散点或分布 基线是否学习到可用信号
优化 学习率、梯度范数、更新次数、KL 早停位置 更新强度和数值是否可控
系统 FPS、显存、推理/采样/更新耗时、版本与 Seed 性能变化是否来自系统配置差异

同名指标必须绑定公式、方向、聚合范围和计算时点。例如 approx_kl 至少有两种常见近似，entropy 可能按动作维求和或平均，value_loss 可能含 \(1/2\) 或价值裁剪；梯度范数还要说明是裁剪前还是裁剪后，explained variance 要说明使用 Rollout 时旧 Value 还是更新后重算的 Value。不要用不同定义或不同快照时点的历史阈值交叉告警。

policy_loss 为负是否异常？

常见最小化口径为 \(L_{actor}=-\operatorname{mean}(L^{CLIP})\)，所以负值只表示当前有限 Batch 上的裁剪代理目标均值为正，不等于“损失小于零就是正确”，也不等于回报必然上升。若优势在整批上去均值，首个 Epoch 的 Loss 常接近 0；后续正负还会受策略更新、切批与日志时点影响。最小检查是同时打印最大化代理项、代码 Loss、优势均值和优化方向，再与 KL、回报共同解读。

3. KL 突增或持续过高

竞争假设

  1. 学习率、Epoch 数或每批更新步数过大。
  2. 优势尺度过大或出现极端离群值，使同一学习率下的 Actor 梯度过强；是否标准化本身不是对错判据。
  3. 连续动作标准差很小，均值微小变化也产生大 KL。
  4. old_log_prob 被覆盖、没有 detach，或动作/观测错位。
  5. Mini-batch 太小，KL 估计波动大。

可否证实验

  • 冻结模型参数、预处理统计、分布模式与输入 Batch 后重算：ratio 应在浮点容差内为 1，KL 为 0；否则优先查数据契约。Dropout/BatchNorm 模式或状态相关噪声变化也会破坏该恒等检查。
  • 将学习率临时降一个数量级：若首个 Mini-batch 仍产生巨大 KL，问题更可能在 ratio/Shape/分布。
  • 画逐维 log_std 与动作均值变化，查是否某一维支配 KL。
  • 固定 Batch，只执行一次 Actor 更新；逐步记录每个 Optimizer Step 后 KL，定位突变步。

确认是更新过激后，再考虑降低学习率或 Epoch、增大 Mini-batch、启用更严格 KL 早停；不要在契约错误未排除时靠 Clip 系数遮掩。

4. clipfrac 很高或几乎为零

clipfrac 高表示很多样本的 ratio 离开 \([1-\epsilon,1+\epsilon]\)，不等于这些样本全部零梯度，也不自动等于训练失败。它还是 Batch、Epoch 与日志时点相关的有限样本比例，不是策略空间距离。

现象 可能解释 验证
首个 Mini-batch 前就非零 新旧策略量不一致 禁用更新，重算 ratio
随 Epoch 快速升高且 KL 同升 批内策略漂移过大 画每个 Epoch 曲线，减少更新强度
clipfrac 高但 KL 中等 大量轻微越界、KL 聚合/方向差异或高维分布效应 同时看 ratio 直方图、逐维分布参数与具体 KL 公式
长期接近零、回报不动 更新太弱或优势信号弱 查梯度、优势方差、LR、奖励可识别性

目标不是把 clipfrac 调成某个脱离任务的“标准值”，而是理解它如何随训练阶段、回报和 KL 共同变化。

5. Entropy 或连续动作方差塌缩

症状

  • log_std 快速下降，某些维度接近数值下限；
  • 训练回报早期上升后停滞，确定性动作几乎不变；
  • 不同 Seed 收敛到不同局部行为；
  • 边界命中率突然升高。

验证顺序

  1. 逐维记录 std，而不是只看总熵。
  2. 区分“均值策略已确定”与“动作经硬裁剪后都相同”。
  3. 固定 Actor 均值，用不同 std 做离线动作分布检查。
  4. 检查熵的求和/平均口径和熵系数符号。
  5. 对比随机评估与确定性评估，观察探索是否仍贡献性能。

可能修复包括调整熵系数或调度、提高初始 std、使用更稳定的 std 参数化、改善奖励信号、减缓策略更新。若策略含 tanh/缩放，先确认日志记录的是未变换高斯熵、Monte Carlo 变换后熵还是其他代理；若动作被大面积硬裁到边界，先修动作分布契约。

6. Value Loss 很大、振荡或 explained variance 为负

Value Loss 绝对值依赖奖励尺度与归约方式，不能跨任务直接比较。Explained variance 只比较残差方差与 Return 方差；Return 方差接近 0 时它会数值不稳定，负值也只说明该方差口径下的残差更大，不能单独定位原因。

首先排除数据错误

  • 时间截断是否从真实末状态 Bootstrap；
  • reset 后初态是否错误接入前一 Episode；
  • returns = advantage + old_value 是否使用同一旧值口径；
  • reward/return 是否出现极端值或符号错误；
  • Critic 观测是否与时间步错位；
  • new_value=[B,1] 与 returns=[B] 是否广播成了错误的 [B,B]；只接受 [B] 或确认后的 [B,1]，再断言形状完全一致。

再检查优化问题

  • Return 方差和均值是否随 Curriculum 漂移；
  • Critic 容量、学习率、更新次数是否合适；
  • 共享骨干是否被 Actor/Entropy 梯度干扰；
  • 价值裁剪区间是否相对奖励尺度过小；
  • 观测归一化是否更新/冻结错误。

可做的最小实验：冻结一批 (critic_obs, returns)，固定归一化统计与模型模式，只训练 Critic，看它能否过拟合这批数据。如果不能，问题在网络/优化/数据 Shape；如果能，只能证明该静态批的表示与优化容量足够，在线失败还要区分目标非平稳、采样边界、数据覆盖和共享梯度冲突。

7. 回报突然崩溃

先对齐崩溃发生点的所有指标，不要只看 Return：

  • KL 或梯度范数是否先出现尖峰；
  • std/entropy 是否突然变化；
  • Value/Return 是否越界；
  • Curriculum 或随机化范围是否切换；
  • Episode 终止原因是否改变；
  • Checkpoint、归一化统计或环境配置是否被热更新。

保存崩溃前后的模型、优化器、混合精度 Scaler、归一化统计、RNG 状态、配置和触发 Batch，再在离线模式重放一次更新。若同 Batch 可稳定复现，分别对 Actor/Value/Entropy 项求梯度并比较参数集合与范数，避免简单“关闭一项”同时改变共享网络语义；若无法复现，查非确定算子、异步数据竞争和外部配置变更。

8. 动作长期处于边界饱和

可能原因

  • 策略均值本身过大或 std 过大；
  • 无界高斯采样后被环境硬裁剪，执行动作与 log-prob 失配；
  • 奖励鼓励最大输出，却缺少能耗/平滑/约束指标；
  • 动作缩放、Offset、单位或底层控制器增益错误；
  • 观测缺少使策略区分状态的关键信息。

需要同时画的量

raw_action、变换后动作、环境实际动作、逐维边界命中率、Actor mean/std、底层执行器输出。只画环境动作无法判断饱和发生在哪一层。

若改用 Tanh 分布，必须同步 log-prob 雅可比修正；不能只在网络输出后加 tanh 就认为问题解决。

9. 训练指标好，评估却差

动作模式不同

训练是随机采样，评估常用分布参数导出的确定性动作；两者性能可能不同。对 tanh 等变换分布，变换后的均值参数通常既不等于动作期望，也不保证是变换后密度的众数，必须说明库的具体规则并分别报告。

归一化不一致

评估未加载训练统计、仍在更新统计，或字段顺序/裁剪不同。

分布移位

训练随机化、初态、命令或传感器与评估不同。建立逐项对照而非一次全换。

信息泄漏

Actor 在训练时意外访问特权状态，部署时不可得；检查模型图和输入构造。

评估脚本本身应有回归测试：同一 Checkpoint、同一 Seed 与同一协议下，保存—加载前后结果一致。训练与评估应使用彼此独立的环境实例，并逐项核对 Wrapper 顺序、奖励缩放、Episode 统计和自动重置；若训练记录的是归一化奖励、评估报告的是原始任务回报，必须明确区分，不能把两种曲线直接比较。

推理期反常现象速查

现象 高优先级假设 区分性检查
deterministic=False 但连续动作长期重复 使用 gSDE 等状态相关噪声，却未在推理期按期望频率重采样噪声 显式调用库的噪声重置接口，对比普通高斯策略；核对所用版本文档
训练时随机策略回报高，均值动作评估反而差 任务性能依赖随机性，或动作均值落在低质量/边界区域 同一组初态分别跑随机、确定性评估并报告分布
模型加载后立刻退化 未加载观测/奖励归一化统计，评估模式或 Action Wrapper 不一致 保存前后对同一原始观测比较预处理张量、分布参数和最终动作
单环境正常，向量评估异常 Batch 维、终止后自动 reset、final_observation 或隐藏状态索引错误 用两个可区分固定环境逐步记录 env-id、obs、action、boundary
长 Episode 后行为逐渐漂移 RNN 隐藏状态未在 Episode 边界重置，或推理时仍更新归一化统计 固定输入重复推理；分别冻结统计、周期重置隐藏状态
可视化动作正常但硬件/环境执行异常 日志记录的是 raw/normalized action，不是缩放、裁剪和控制器后的实际命令 同步记录策略原始动作、变换后动作、环境动作与执行器命令

截至 2026-10-18，Stable-Baselines3 master PPO 文档仍特别指出：启用 gSDE 后，model.predict() 不会自动按训练期的 sde_sample_freq 重置噪声；即使 deterministic=False，推理也可能表现为确定性，需要按期望频率显式调用 model.policy.reset_noise(env.num_envs)。该现象属于具体版本的实现语义，其他库不能直接类推。

10. NaN / Inf 定位协议

启用逐层有限值检查，定位第一个非有限量：

obs → actor mean/log_std → action/log_prob → reward/value
→ delta/advantage/return → log_ratio/ratio → each loss
→ gradients → parameters

操作顺序：

  1. 保存触发前的 Checkpoint、配置、Batch 和 RNG 状态。
  2. 在单进程、关闭混合精度条件下重放。
  3. 对每个边界加 isfinite 断言和 min/max/mean/std。
  4. 若 exp(log_ratio) 溢出，先追溯为什么 log-prob 差巨大，而非直接把 ratio 任意 Clamp。
  5. 若梯度先非有限，分项反向 Actor/Value/Entropy，定位来源。
  6. 修复后把该 Batch 变为回归测试。

常见来源包括观测除零、极端奖励、std 接近 0、错误 log(0)、优势标准化空/单样本、价值目标越界和混合精度溢出。单样本优势若使用无偏标准差会得到未定义结果；即使改用总体标准差，标准化后也只会得到零信号，因此应验证有效样本数，而不是只加 epsilon。混合精度下应在反缩放梯度后检查并裁剪；跳过异常步时还要清空梯度，不能让非有限值遗留到下一步。

在机器人仿真中，NaN 常常最先产生于无效 Reset 状态或不稳定物理仿真，而不是 PPO Loss。应先用无训练的随机/零动作复现，并检查关节初态、速度、物体位姿、驱动器增益与限制、动作缩放、碰撞几何、质量/惯量、异常接触冲量、物理步长和求解器参数；不要用全局 Clamp 掩盖第一个无效状态。

11. 种子差异巨大

强化学习本身具有随机性，但大差异也可能揭示脆弱性。

  • 先确保所有随机源和环境实例都有独立且可记录的 Seed；
  • 用相同环境步预算比较，而不是相同 wall-clock；
  • 报告所有预先声明的 Seed，不挑最好结果；
  • 画均值与离散度/分位数并保留全部单种子曲线；若给置信区间，说明样本量和估计方法，少量 Seed 下不要制造虚假的高精度；
  • 检查是否只有早期探索导致分叉，以及 Curriculum 是否放大分叉；
  • 做分层消融：固定初始化、固定环境随机序列、固定 Mini-batch 顺序，定位主要随机源。

不要把一个好 Seed 当作算法有效，也不要用一个坏 Seed 直接断言实现错误。

12. 并行环境增多后学习变差

先把同时变化的量写成一张账：单 rank 环境数 \(N\)、Rollout 长度 \(T\)、全局 Batch \(B\)、Mini-batch \(M\)、Epoch \(K\)、world size，以及相同环境样本对应的更新次数。若保留尾 Mini-batch，每迭代优化器步数为 \(K\lceil B/M\rceil\)；若丢弃尾批则为 \(K\lfloor B/M\rfloor\)，还要记录被丢弃样本的抽样方式。同步数据并行下若每 rank 保持 \(N_{rank}\)，全局 Batch 通常随 world size 增长为 \(B=world\_size\times N_{rank}\times T\)。

对照 固定什么 改什么 能回答什么
A 全局 \(B\)、\(M\)、\(K\)、学习率 增大 \(N\)、按比例减小 \(T\) 轨迹长度/Bootstrap 与环境多样性的影响
B \(T\)、每样本复用次数、总环境步 增大 \(N\) 与全局 \(B\) 大 Batch、策略刷新频率和梯度统计的影响
C 每 rank \(N,T\) 与硬件 增大 world size 吞吐、同步和全局 Batch 一起变化的系统效应
D \(N,T,B,M,K\) 只改变随机化/重置实现 环境独立性、Seed 相关和边界实现是否退化

每组对照还要冻结奖励/观测归一化、Curriculum 进度、评估频率和总环境步预算。若无法固定所有量，结论应写成“这一组配置组合更差”，而不是“并行环境越多越差”。

本页的诊断创新点是“先守不变量，再做因果对照”： 先用 ratio 恒等、手算 GAE、静态批过拟合和保存—加载一致性验证实现不变量；再用带预测的单因素实验区分竞争假设。这样不会把参数调优暂时掩盖的契约错误误判为修复。

13. 约 15 分钟的最小分诊流程（不是完成诊断）

“15 分钟”只表示优先级明确的快速分诊目标，实际耗时取决于环境启动与复现成本；完成这些步骤也只会缩小假设空间，不构成正确性证明。

  1. 关闭长训练，切到小环境、小网络、短 Rollout、固定 Seed。
  2. 运行随机策略与零动作，验证环境指标、动作范围和终止原因。
  3. 禁用优化器，采一批后重算：ratio≈1、KL≈0、log-prob 一致。
  4. 用人工轨迹测试 terminated/truncated 与 GAE。
  5. 固定 Batch，分别过拟合 Critic 和执行一次 Actor 更新。
  6. 打开完整更新，记录每个 Mini-batch 的 KL、clipfrac、梯度范数。
  7. 用 3–5 个短 Seed 检查修复方向是否一致；这只是调试信号，不足以替代预先设计的正式多种子评估。
