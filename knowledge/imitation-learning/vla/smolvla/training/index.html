SmolVLA 的训练分成两段：论文先从 Hugging Face 社区数据中筛选 481 个 SO100 数据集做机器人数据预训练，随后在具体仿真或真机任务上微调。官方已公开基座权重 lerobot/smolvla_base。本页沿着「数据 → 可训练参数 → 优化配置 → 预训练证据 → 下游微调」展开，并明确区分三类内容：论文报告的正式配方、固定版本 LeRobot 源码的默认值、基于优化机制的排查建议。

本页把证据固定到三个可复查版本：论文 arXiv v1、LeRobot 提交 8c920c4，以及公开基座 checkpoint 的 config.json@d9f33c9；核对日期为 2026-10-05。下文分别标注“论文配方”“源码类默认值”和“checkpoint 保存值”，避免把三者混成同一套配置。

损失的定义见③ Flow Matching 与损失，推理与部署见⑥ 推理、动作块与异步执行，本页不重复。

一、社区数据的筛选与标准化

1.1 为什么是社区数据

与按统一协议采集的学术数据集相比，社区数据池天然包含更多采集者、控制方案、相机视角、任务与真实环境。论文的判断是：其中虽有噪声示范和异构环境，却也更能反映真实世界的复杂性，因而具有预训练价值。这里说的是候选社区数据池的多样性；经过本体筛选后，SmolVLA 实际用于预训练的 481 个数据集都来自 SO100，不能据“社区数据”推断它做过跨本体预训练。

与私有机器人数据相比，公开的 LeRobot 社区数据提高了可检查性与复现便利性，论文附录也列出了入选数据集。但“公开可访问”不自动保证各数据集许可证彼此兼容，也不保证数据版本永久不变；实际复用时仍应逐项核查许可、版本与可用性。

1.2 规模与筛选

论文从 Hugging Face 上按本体类型、episode 数量、整体数据质量、帧覆盖度四项筛出 481 个数据集：

数据集数 episode 数 帧数
481 22.9K 10.6M

这个规模比典型 VLA 训练用量至少小一个数量级。论文在局限一节直接给出了对照：SmolVLA 用约 23K 条轨迹，而 OpenVLA 用了约 100 万条。

数据集多，不等于机器人本体多。481 是独立社区数据集的数量，而不是机器人类型数量；论文的局限一节明确写明预训练数据均由 SO100 采集。论文在 SO101 上的结果来自后续微调，能说明迁移到另一种相近本体的可行性，但不能当作跨本体预训练的证据。

一处论文笔误需要注意。Table 1 的表注写作「At ∼10M episodes, our pretraining set stands at least one order of magnitude smaller than other state-of-the-art」，但表格本身给出的是 22.9K episodes 与 10.6M frames。10M 是帧数而非 episode 数，表注把两个量写混了。引用时应以表内数值为准。

官方博客对同一规模的表述是「不到 3 万条 episode」，与表内的 22.9K 一致。

但数据集的个数两处对不上：论文正文与 Table 1 都写 481 个社区数据集，而官方博客写的是「我们整理了一个 487 个高质量数据集的集合」。两处相差 6 个，论文与博客均未解释原因。本页统一采用论文的 481；引用博客时应保留 487 的原始口径。

1.3 一轮筛选与两项标准化

这里包含不同层级的三项工作：先筛选数据集，再统一任务文本和相机视角。把它们都叫“清洗”容易掩盖人工标准化的成本。

问题 具体表现 处理
任务标注噪声 出现 task desc 这类占位符；出现 Hold、Up 这类过于笼统的指令；部分数据集完全没有指令 用现成 VLM（Qwen2.5-VL-3B-Instruct）自动重新生成任务描述：对每个数据集采样代表性帧，连同原指令一起送入，要求产出一句简短的、以动作为导向的描述
相机命名不一致 同一个键名（例如 images.laptop）在不同数据集里可能指顶视、侧视或腕部视角 人工把每路相机映射到标准视角类型，按顶视、腕部、侧视的优先级重命名为 OBS_IMAGE_1、OBS_IMAGE_2、OBS_IMAGE_3；多余视角保留顺序但在训练时丢弃
质量参差 episode 数过少、帧覆盖不足、本体不匹配 在选取 481 个数据集时按四项标准过滤

论文直接报告：相机命名不一致会损害预训练，而在该数据规模下保持顺序一致有益。一个合理但未经单独消融验证的解释是：相机 token 的位置与物理视角若反复错配，模型需要额外学习消除这种置换不确定性。应把这项机制解释与论文观察区分开，不能把它当作已验证因果链。

对自采数据，可靠要求是：同一相机键应稳定对应同一物理视角。若希望最大程度沿用基座权重的先验，可优先对齐论文采用的 top / wrist / side 顺序；但论文没有给出下游微调阶段不同排序的独立对照，因此不能把某一种顺序称为普遍唯一正确的方案。

二、训练哪些参数、冻结哪些参数

2.1 默认配置

论文第 4.3 节的表述是：只训练动作专家模块，保持 VLM 冻结。固定版本 LeRobot 用下面三个开关实现冻结策略；在实现中，动作输入/输出投影与时间融合 MLP 没有冻结开关，状态投影由 train_state_proj 单独控制。论文没有逐项列出这些 VLM 外部投影，因此不能把一句“只训练动作专家”机械解释成只有 expert decoder 参数更新：

配置项 默认值 作用
freeze_vision_encoder True 冻结 SigLIP 视觉编码器
train_expert_only True 冻结整个 VLM（视觉塔与语言塔都在内）；不冻结动作专家及 VLM 外部投影层
train_state_proj True 状态投影层参与训练

注意 train_expert_only 比 freeze_vision_encoder 更强：前者为真时，整个 VLM 被置为 eval 模式且全部参数 requires_grad = False，此时视觉编码器是否单独冻结已无影响。模型还重写了 train()：外层训练模式切换后会再次把整个 VLM 设回 eval，避免 dropout 等训练态行为被意外恢复。论文引言中“end-to-end”一词也不能解释为全参数训练；第 4.3 节对正式训练配方的说明更具体，即 VLM 冻结。

因此在源码类默认值 num_vlm_layers=16、num_expert_layers<=0、train_state_proj=True 下，③ Flow Matching 与损失里会获得梯度并更新的是：动作专家 16 个 decoder layer 及末端 norm、动作输入/输出投影、时间融合的两层 MLP，以及状态投影。SmolVLA 的 get_optim_params() 返回完整 self.parameters()；AdamW 的参数组因而包含冻结参数，但这些参数没有梯度，不会执行更新，也不会创建逐参数优化器状态。公开基座保存的是 num_expert_layers=0，与“非正数表示使用与 VLM 相同层数”这一分支一致。

2.2 冻结主干的收益与边界

冻结主干同时带来三点：减少需要保存的参数梯度与优化器状态、保留视觉语言预训练表征、把有限下游数据主要用于适配动作侧。它通常能降低显存，但并不会自动消除 VLM 的全部前向激活：状态投影仍需通过冻结主干获得梯度时，反向传播仍要穿过相应计算图。小数据下解冻主干会增加过拟合或遗忘预训练表征的风险，但论文没有给出“解冻后换场景归零”之类的对照实验。因此，冻结是当前论文配方与稳健的默认选择，不应被写成对所有数据规模都成立的定律。

2.3 解冻主干时的一个非显然细节

当 train_expert_only = False（即允许训练 VLM 的一部分）时，实现也不是简单地放开全部参数。视觉塔仍由独立开关 freeze_vision_encoder 控制；保持默认 True 时视觉塔继续冻结。语言侧则额外冻结 lm_head、text_model.norm.weight，以及主干实际使用的最后一层（层号 num_vlm_layers - 1）。

源码注释给出的理由是「避免分布式训练下的 unused params 问题」。这个理由值得展开：

最终 VLM prefix 输出被训练调用丢弃，text_model.norm 的结果没有进入动作损失，lm_head 也未参与这条前向路径；这些末端参数没有损失消费者。不过，不能进一步推成“最后一个 VLM layer 整层都没有梯度”：在最后一个配对层里，动作专家仍可能查询该层产生的 K/V，因而其中部分投影可以影响动作损失，同时只服务最终 VLM 输出的分支可能未被使用。

源码注释只明确给出“避免分布式训练中的 unused params”这一理由。实现采取的是保守的粗粒度处理：冻结整个末层；当 expert 层数与 VLM 层数不同且二者能整除时，再冻结倒数第二层。这个条件是固定源码采用的规则，不足以证明任意层数比下恰好只有这些层无消费者。

其动机属于分布式训练工程约束，但冻结整层也会把其中原本可能获得梯度的参数排除在训练之外，实际改变可训练容量。因此应把它理解为“为稳定训练采用的保守冻结规则”，而不是与模型适配能力完全无关的纯实现细节。

三、优化器与学习率调度

3.1 取值对照

论文第 4.3 节与固定提交中的 LeRobot 配置有五项共同取值一致，warmup 不同；其余项目只有源码给出，不能称为“一致”或“不一致”：

项 论文第 4.3 节 LeRobot 默认值 是否一致
优化器 AdamW AdamW 是
\(\beta_1,\ \beta_2\) 0.9, 0.95 0.9, 0.95 是
峰值学习率 1e-4 optimizer_lr = 1e-4 是
学习率下限 2.5e-6 scheduler_decay_lr = 2.5e-6 是
调度形状 余弦衰减 余弦衰减 是
warmup 步数 100 scheduler_warmup_steps = 1000 否
衰减步数 未给出 scheduler_decay_steps = 30000 论文未报告
\(\epsilon\) 未给出 optimizer_eps = 1e-8 论文未报告
权重衰减 未给出 optimizer_weight_decay = 1e-10 论文未报告
梯度裁剪 未给出 optimizer_grad_clip_norm = 10 论文未报告

不要擅自解释 warmup 差异。论文正式预训练配方是 100 步；固定提交中的通用配置默认 1000 步，并另设 30000 步衰减。官方资料没有说明差异来自版本变化还是使用入口。复现论文预训练应采用论文值；运行当前训练脚本时则应检查命令行、checkpoint 配置与默认值合并后的最终配置。

固定提交还有一层运行时语义：若总训练步数 \(N<30000\)，调度器按比例设置

\[W=\left\lfloor\frac{1000N}{30000}\right\rfloor,\qquad D=N.\]

因此官方 20K 步命令实际使用 \(W=666\)、\(D=20000\)，而不是直接执行字段表面的 1000/30000。warmup 阶段的倍率从 \(1/(W+1)\) 近似线性升至 1；随后源码用全局步数 \(s\) 而非 \(s-W\) 计算余弦倍率：

\[m(s)=\alpha+(1-\alpha)\frac{1+\cos(\pi\min(s,D)/D)}{2}, \qquad \alpha=\frac{2.5\times10^{-6}}{10^{-4}}=0.025.\]

所以“衰减步数为 \(D\)”表示余弦曲线在全局 step \(D\) 到达下限，并不是 warmup 结束后再完整衰减 \(D\) 步。还要注意，分支条件是 s < W：最后一个 warmup 点是 \(s=W-1\)，到 \(s=W\) 时直接切到上式。由于余弦式使用全局步数，边界会出现很小的向下跳变；在默认比例 \(W/D=1/30\) 下，切换点倍率约为 \(0.9973\)，而不是精确的 1。它通常不是主要训练风险，却是逐步精确复现时不能忽略的实现语义。

3.2 三项取值的精确作用与证据边界

β₂ = 0.95 而非默认 0.999 AdamW 的 β₂ 控制二阶矩指数移动平均的记忆长度。按时间常数 \(1/(1-\beta_2)\) 粗略估算，0.95 约为 20 步，0.999 约为 1000 步；前者会更快响应梯度平方尺度变化。论文只报告取值，没有给出 β₂ 消融，因此“更快响应”是算法性质，不等于已经证明它是该模型最优选择。

权重衰减 1e-10 在学习率不超过 \(10^{-4}\) 时，AdamW 每步的解耦收缩因子约为 \(1-10^{-14}\)；即使粗略按 200K 步上界累计，收缩量也只有约 \(2\times10^{-9}\)，数值效果近似关闭。参数权重衰减并不等同于直接惩罚速度场输出，源码和论文也没有解释为何保留这个非零值。

梯度裁剪 10 配置将梯度范数上限设为 10；只有裁剪前的全局范数超过阈值时才会改变更新。没有训练日志或梯度范数分布，就不能断言它只在异常批次触发，也不能由“只训练动作专家”推出梯度必然稳定。

3.3 输入输出的归一化

模态 归一化方式 为什么
视觉 IDENTITY 不使用数据集统计量做通用归一化；模型内部仍会 resize/pad，并把像素从 \([0,1]\) 映射到 SigLIP 所需的 \([-1,1]\)
状态 MEAN_STD 按训练数据统计量的均值和标准差处理各维，有利于减小量纲差异并改善线性投影的数值条件
动作 MEAN_STD 使不同动作维的尺度更可比，并让动作与标准高斯噪声的典型尺度更接近，避免大尺度维度主导逐元素 MSE

动作归一化不是 Flow Matching 成立的数学前提：任意有限尺度的数据仍可定义线性概率路径。关闭归一化会改变优化条件与各维损失权重，通常需要重新选择噪声尺度、学习率或损失权重，不能简单地照搬当前配置。

固定提交把状态和动作补零到 max_state_dim = max_action_dim = 32。动作损失先裁到数据集声明的真实动作维数，episode 尾部 padding 再由 action_is_pad 屏蔽，最终按有效的“时间步 × 动作维”元素数求平均；因此人工补出的动作维和 episode padding 均不参与最终标量损失。不过，32 维的带噪动作仍作为动作专家输入，补出的坐标不是“从计算图彻底删除”，只是对应输出不计入损失。状态补零维也会经过状态投影参与条件表示。

四、预训练与微调的具体配置

4.1 论文的三组训练设置

阶段 步数 批量 说明
社区数据预训练 200,000 256（全局） 在全部 481 个数据集上训练，产出基座权重
仿真基准微调 100,000 64 LIBERO、Meta-World
真机任务微调 200,000 — SO100 / SO101 真机任务

预训练名义上处理了 \(200000\times256=51.2\)M 个样本位置。若只用 10.6M 帧作分母，它相当于约 \(4.8\) 次数据遍历；这只是便于理解训练量级的“名义 epoch”。每个样本还构造未来动作块，且论文没有公开 481 个数据集之间的精确采样权重，因此不能把 4.8 解释成每个源数据集都被均匀完整遍历 4.8 次。

论文同时给出一条定性观察：实践中使用远少于表中步数，也能保持接近的性能。但论文没有提供“更少”对应的统一步数、学习曲线或跨任务阈值，因此它只能支持“应按验证表现提前停止”，不能支持任意缩短训练。

4.2 三项训练效率优化

除了模型本身紧凑、token 数少之外，论文还用了三项工程优化：

  1. bfloat16 精度。
  2. torch.compile()，把 PyTorch 计算图编译成优化内核。论文实验使用了它；固定提交中的 compile_model 默认却是 False，只有显式启用后 compile_mode 才默认取 max-autotune。
  3. 形状处理要区分论文、源码类默认值与公开 checkpoint。论文称其训练保持固定序列长度和 batch size，并丢弃 episode 中不能组成完整 batch 的剩余帧；固定提交的 DataLoader 却使用 drop_last=False，不会丢尾批，episode 末尾的未来动作通过边界钳制、action_is_pad 与损失 mask 处理。源码类默认 pad_language_to="longest"，语言长度可能随 batch 变化；但公开 smolvla_base 的固定版本配置保存的是 pad_language_to="max_length"，官方 --policy.path=lerobot/smolvla_base 微调入口通常继承后者。稳定形状有利于减少 torch.compile 重编译，但不是编译成立的前提；也不能据论文描述推导当前 DataLoader 会按 episode 丢弃短尾段。

4.3 预训练实际用了多少算力

「单卡可训」是模型具备的性质，不等于论文的预训练就是单卡跑完的。论文第 4.3 节给出了两个常被略过的数字：

项 论文原文给出的值 说明
预训练所用 GPU 数 4 张 原文说明是为了容纳大批量（全局批量 256）；同一句同时指出「由于模型很小，它可以轻松地在单张 GPU 上训练」
整个项目消耗的算力 约 30k GPU 小时 原文为 the project consumed approximately 30k GPU hours，指整个项目而非单次预训练

30k GPU-hours 不是最终训练配方的单次成本，也不是复现最终权重所需成本。原文只说整个研究项目累计约 30k GPU-hours，没有拆分社区预训练、下游实验、消融、开发探索或失败运行各自的用量。能确定的只有最终预训练使用 4 张 GPU；单次预训练耗时与 GPU-hours 均未报告，不能从项目总量反推。

五、微调实操

5.1 官方推荐的数据量

LeRobot 官方文档给出了一组面向 SO100 pick-and-place 的实践经验：

  • SmolVLA 是基座模型，要在自己的数据上微调才能在自己的场景里达到理想性能。
  • 起步建议录制约 50 条 episode。
  • 数据集里对每一种变化因素（例如立方体在桌面上的位置）都要有足够的示范。
  • 论文所用的参考数据集结构是：5 个不同的立方体位置，每个位置采 10 条 pick-and-place 示范，合计 50 条。文档明确指出这种「每种变化重复若干次」的结构帮助模型泛化得更好。
  • 文档称一个类似的 25-episode 数据集表现较差。

这不是跨机器人、跨任务成立的最低样本数。更可靠的原则是：先列出部署时希望覆盖的变化因素，再让每类变化获得重复示范。把 50 条都集中在单一位置通常难以支持位置泛化，但官方文档没有做“50 条单位置”这一对照，不能写成必然失败。

5.2 训练命令

官方文档给出的微调命令：

cd lerobot && lerobot-train \
  --policy.path=lerobot/smolvla_base \
  --dataset.repo_id=${HF_USER}/mydataset \
  --batch_size=64 \
  --steps=20000 \
  --output_dir=outputs/train/my_smolvla \
  --job_name=my_smolvla_training \
  --policy.device=cuda \
  --wandb.enable=true

三点说明：

  • --policy.path=lerobot/smolvla_base 加载完整 SmolVLA checkpoint，包括已保存的模型配置与权重。它不能与构造新模型时的 load_vlm_weights 简单画等号：后者只控制是否从 vlm_model_name 加载预训练 SmolVLM2 主干。用完整 checkpoint 时无需手工覆盖该开关；若新建模型却令 load_vlm_weights=False 且保留 train_expert_only=True，会冻结随机初始化的 VLM，通常不是合理方案。公开基座配置中的 load_vlm_weights=True 是保存时的构造字段，不表示加载完整 checkpoint 时还会用主干权重覆盖已加载的 VLM。
  • 文档建议 batch size 从小开始，在显存允许且数据加载不成为瓶颈时逐步增加；20K 步只是示例，不是固定收敛步数。
  • 同一份文档估计 20K 步在单张 A100 上约需 4 小时。该数字依赖 GPU、batch size、编译与数据管线，只能作为所述硬件环境下的量级参考；20K 步还会触发上一节说明的调度器自动缩放。

六、预训练到底带来了多少

论文 Table 5 提供三组结果，可做两次有条件的成对比较；由于缺少“单任务训练 + 社区预训练”这一格，它不是完整的 \(2\times2\) 因子实验，无法独立估计两因素的主效应与交互作用。论文正文据此称多任务微调带来额外收益，但表中严格能支持的多任务比较只发生在“无预训练”条件下：

训练方式 社区预训练 Pick-Place Stacking Sorting 平均
单任务训练 否 55 45 20 40.0
多任务训练 否 80 40 35 51.7
多任务训练 是 75 90 70 78.3

表中可以直接计算的两组条件差异是：

无预训练条件下：多任务比单任务 +11.7 个百分点 平均成功率从 40.0 到 51.7。它支持“在这组三任务和该训练协议下，多任务训练的表中数值更高”，但不能说明加入预训练后仍会得到同样的 11.7 点增益。

多任务条件下：社区预训练对应约 +26.7 个百分点 按三个任务的整数成功率先求差，平均增益为 \((75-80+90-40+70-35)/3=26.7\) 个百分点（四舍五入到一位小数）；若直接用表中已四舍五入的均值相减，则是 \(78.3-51.7=26.6\)。该对比保持多任务设置不变，主要差异是是否使用社区预训练；论文未报告多随机种子方差，因此它是该次评估的观测差异，而不是带置信区间的总体效应估计。

6.1 能说明什么、不能说明什么

在论文的 450M 模型、SO100 三个下游任务和多任务微调设置下，社区预训练与更高的平均成功率相对应。这是预训练有效性的直接证据；但实验没有改变模型容量或预训练数据规模，因而不能据此断言 450M 是最优容量、更多数据一定优于更多参数，或同样数据训练 7B 模型必然过拟合。

6.2 增益的分布不均匀

在多任务条件下逐项比较，Stacking 为 \(40\rightarrow90\)（+50），Sorting 为 \(35\rightarrow70\)（+35），Pick-Place 为 \(80\rightarrow75\)（−5）。这说明收益在本次评估的三个任务间不均匀。

论文没有报告多随机种子方差，也没有在这里给出任务难度或长时程依赖的控制变量。因此 −5 不能单独证明负迁移，+50/+35 也不足以建立“任务越难，预训练越有价值”的普遍规律。可靠结论应止于表中条件和观测数值。

七、配置变化的影响与排查边界

下面区分“配置直接改变了什么”和“可能观察到什么”。论文没有逐项做故障注入实验，因此症状栏只能作为排查方向，不能用于反向确诊。

任何配置实验都应同时记录训练损失、梯度范数、独立验证集指标与闭环 rollout；只看训练损失无法区分过拟合、归一化错误和控制执行问题。

改动 直接影响 建议检查
train_expert_only=False 增加可训练主干参数；默认 freeze_vision_encoder=True 时视觉塔仍冻结 与冻结基线比较训练/验证差距，并检查跨背景、光照和视角的 rollout
学习率高于 1e-4 偏离论文峰值与源码默认值，更新幅度增大 损失曲线、梯度范数、是否出现 NaN；“动作抖动”不是学习率过高的唯一解释
warmup 设为 0 从第一步直接进入调度器给出的较高学习率 训练初期的损失和梯度；没有论文证据表明一定会在固定步数内失稳
权重衰减设为 1e-2 比源码默认值高 \(10^8\) 倍，产生不可忽略的参数收缩 验证性能和参数范数；不能仅凭动作幅度推断是权重衰减所致
相机键与物理视角错配 破坏论文刻意建立的视角顺序一致性 抽样可视化每个 image key，核对 top / wrist / side 元数据
关闭动作 MEAN_STD 改变动作/噪声尺度与各维 MSE 权重，但不破坏 Flow Matching 定义 动作统计量、归一化逆变换、逐维损失与噪声尺度
使用约 25 条示范 官方文档中的一个相似 pick-place 数据集表现较差，并非通用下限 变化因素覆盖、独立评测集和增加数据后的学习曲线
示范集中在单一位置 缺少位置变化的训练覆盖 在未见位置评测；结果只能判断该数据分布下的泛化能力

八、本页要点回顾

数据 论文口径是 481 个 SO100 数据集、22.9K episode、10.6M 帧；博客写 487 个数据集。筛选、VLM 任务重标注和相机视角标准化是三个不同层级的步骤。

训练什么 源码类默认与公开基座均冻结整个 VLM，训练动作专家、动作/时间投影与状态投影；train() 会维持 VLM 的 eval 状态。解冻时为规避部分 unused-parameter 问题而保守冻结整个末层，这会同时改变可训练容量。

优化器 论文与源码共同使用 AdamW、β=(0.9, 0.95)、峰值 1e-4 和下限 2.5e-6；论文 warmup 100 步，固定提交默认 1000 步，官方没有解释差异原因。

预训练的价值 Table 5 只支持两个条件比较：无预训练时多任务比单任务 +11.7 点，多任务时预训练按逐任务原值计算约 +26.7 点；缺少第四格和多种子方差，不能把二者当作可独立相加的普遍效应。

自己微调 官方以 SO100 pick-and-place 为例建议约 50 条起步，并覆盖任务变化；相似 25 条数据集表现较差，但这不是跨任务通用下限。训练步数应由独立验证和闭环评测决定。
