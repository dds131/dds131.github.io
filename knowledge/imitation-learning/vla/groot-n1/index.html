GR00T N1 是 NVIDIA 于 2025 年 3 月发布的通用机器人基础模型，目标重点是通用人形机器人，但训练与架构同时覆盖单臂、双臂和灵巧手等多类本体。理解它可以抓住三个系统级选择：视觉语言理解与连续动作生成分成两个模块，不同本体只在输入输出边界使用专属参数而共享动作主干，以及把真实机器人、仿真、人类视频和生成视频组织成数据金字塔。

本页只建立整体地图、证据边界与阅读入口。公式推导、完整参数、逐项实验和源码细节分别下沉到七个子页，避免在枢纽页重复。

初代 N1固定版本：n1-release
2.2B总参数；其中 VLM 为 1.34B（论文）
16动作块长度 H
2视觉语言主干与动作生成主干

本页区分四类证据：论文描述设计与训练实验；固定在 commit 755876a9... 的 n1-release 说明公开实现；发布 config.json 说明 checkpoint 的实际构造参数；数学推导只用于检查这些材料是否相互一致。来源冲突时并列呈现，不把推断伪装成官方结论。

NVIDIA 发布了初代 N1 的权重、n1-release 代码、部分仿真数据和论文。这些材料足以研究架构、运行推理和开展微调，但不足以原样复现论文的全部预训练：完整训练语料、预训练本体到槽位的映射，以及论文辅助检测分支的完整公开训练实现都存在缺口。

二、GR00T N1 要解决什么

论文的出发点可以拆成三个互相牵制的约束。

本体接口异构单臂、双臂、人形与灵巧手的状态和动作维度、语义、量纲不同。直接共享同一接口会混合这些语义，N1 选择用按本体边界层做适配。
连续动作需要联合建模N1 一次生成长度 16 的动作块，在块内联合建模连续动作，并让部署端可以降低策略调用频率；是否执行整块或提前重规划取决于控制策略。这也不等于 Flow Matching 自动保证动力学可行。
真机数据获取昂贵论文把自采约 88.4 小时遥操作数据视为规模瓶颈，因此引入人类视频、神经轨迹和仿真轨迹扩展监督来源。

它们对应 N1 的三项主要工程选择：按本体分组的输入输出边界层、共享 DiT 上的 Flow Matching 动作块生成、把多种有标签或伪标签数据接入统一训练的数据金字塔。这是一组系统设计选择，不是从问题到方案的唯一逻辑结论。

创新边界。 Flow Matching、DiT、adaLN、交叉注意力、逆动力学伪标签和仿真扩增都不是 N1 首创。N1 的贡献更适合表述为：把双系统调用、按本体边界接口、潜在动作和大规模异构数据组织成一套可扩展的通用策略训练系统。

三、双系统：为什么把理解与运动拆开

论文借用了认知科学的快慢系统命名。这里不把它当作认知机制证明，而从工程调用关系理解。

3.1 两件事的最优结构不同

视觉语言主干负责把图像和指令编码成语义条件；动作主干学习训练数据中的连续动作分布。N1 选择让两类任务由不同模块承担，再通过交叉注意力连接。该结构有明确分工，但论文没有证明“单一联合模型一定做不好”，Flow Matching 也不会自动保证轨迹满足真实动力学。

3.2 两件事的更新频率不同

每次生成一个动作块时，VLM 前向执行一次；动作头在同一视觉语言条件上做 \(K\) 次速度场求值，然后输出动作块。源码证明的是这种单次主干前向、多次动作积分的调用关系，而不是任意部署中都必然采用固定的“低频 VLM、高频 DiT”调度。

3.3 拆开之后需要一个明确的接口

拆开的代价是必须定义两者如何通信。GR00T N1 的选择是：System 2 只输出一组视觉语言 token，System 1 通过交叉注意力去读它们，而不是把它们拼进自己的序列。

这个选择的含义是：动作端的自注意力序列里只有状态与动作，视觉语言 token 作为交叉注意力条件。动作查询序列长度不会随图像 token 数量增长，但交叉注意力计算仍随条件长度变化；动作 token 也不会反向写回 VLM 表征，因此是单向条件化。n1-release 只是在积分循环外计算一次 VLM 输出张量；每一步仍重新执行注意力投影，没有显式 K/V cache。

与把动作 token 和视觉语言 token 放进联合序列的路线相比，这种接口让两个主干在调用图上更清楚地解耦。跨模型比较见 VLA 总览。

六、动作生成的一页纸

本节只保留时间方向和接口，完整推导见子页 ②。

给定真值动作块 \(A_t\)、噪声 \(\epsilon\sim\mathcal N(0,I)\) 与流时间 \(\tau\)，源码使用噪声—动作插值

\[A_t^{\tau}=\tau A_t+(1-\tau)\epsilon\]

因此 \(\tau=0\) 为噪声端、\(\tau=1\) 为数据端。动作头学习条件速度场

\[V_\theta\!\left(A_t^\tau,\tau;\varphi_t,q_t\right),\]

其中 \(\varphi_t\) 是视觉语言条件，\(q_t\) 是机器人状态。源码回归目标为

\[\frac{\mathrm d A_t^\tau}{\mathrm d\tau}=A_t-\epsilon,\]

对每个采样配对 \((A_t,\epsilon)\)，上式给出监督速度；在总体平方损失下，网络的最优解是条件期望

\[V^*(x,\tau,c) =\mathbb E\!\left[A_t-\epsilon\mid A_t^\tau=x,\tau,c\right],\]

而不是对所有可能配对输出同一个确定向量。推理从高斯噪声出发，以正步长做前向 Euler 积分。

实现审计边界。 论文式 (1) 写成 \(\epsilon-A_t\)，与上述插值导数和源码 actions - noise 符号相反；源码的训练目标与正向积分彼此一致。这里能确定的是“论文公式与公开实现冲突、源码内部自洽”，不是把源码当作论文全部数学陈述的替代品。

论文正文报告 \(K=4\) 可用，发布配置默认 num_inference_timesteps=16；它们对应不同来源和运行设置，引用时必须注明。动作头每一步都会基于更新后的动作重新估计速度，但循环中不重新采样或重加噪。

七、数据金字塔的一页纸

本节只给结构与动机，各类数据的动作标签与生成方法放在子页 ③。

论文把训练语料组织成一个金字塔：越往下数据越多、与机器人本体的关系越弱；越往上数据越少、越接近真实部署。

论文 Table 7 把实际训练语料分为四类；“金字塔”描述的是动作监督可靠性、与真实本体距离和规模之间的取舍，不是严格的三行数据表：

数据来源 Table 7 时长 进入动作训练的监督信号
真实机器人数据 3,288.8 小时 真值机器人动作；预训练还可使用从视频学得的潜在动作
仿真数据 1,742.6 小时 仿真器动作真值；论文 Table 1 也把潜在动作标为适用
人类第一视角视频 2,517.0 小时 从视频提取的潜在动作，作为独立的 LAPA embodiment
神经生成视频 827.3 小时 潜在动作，或由逆动力学模型生成的伪动作；依训练阶段与数据集而定

不要把“数据类别”误读为“唯一标签类型”。 上表列的是论文允许的监督路径，并不表示每条样本同时具有全部标签。论文训练细节明确写到：机器人数据可同时把真值动作和学得的潜在动作作为 Flow Matching 目标；神经轨迹则可使用潜在动作或 IDM 伪动作，并把不同伪动作接口当作不同 embodiment 处理。

关键不是把视频只当视觉预训练数据，而是给不同数据源构造动作或伪动作标签：各本体通过自己的状态/动作边界层进入共享 DiT，并使用同一类 Flow Matching 目标。潜在动作被当作 LAPA embodiment，使无机器人动作标签的人类视频也能参与动作主干训练。

Table 7 的“进入训练语料时长”和生成流程产生的总轨迹量不是同一统计口径。例如论文另报告仿真在预训练与后训练阶段合计生成 780,000 条、约 6,500 小时。生成流程、筛选步骤、成本和演示视频见 ③ 数据金字塔、动作标签与合成数据。

八、训练配置速查

这里只保留决定训练规模与冻结范围的项目；完整超参、公共脚本默认值和复现边界见子页 ④。

项目 预训练 后训练 来源/边界
学习率 / 优化器 1e-4 / AdamW 同左 论文 Table 6
全局批量 16,384 128 或 1024 不是公共脚本的每设备默认批量
梯度步数 200,000 20,000–60,000 论文配方
视觉编码器 / DiT 参与训练 / 参与训练 同左 论文配方

论文解释后训练使用较小批量是为了降低数据受限场景中的过拟合风险。Table 6 原文写“Backbone’s text tokenizer frozen”，但 tokenizer 通常不是可训练网络权重；论文正文和发布配置对应的是语言组件冻结，代码开关为 tune_llm=false。这不等于冻结整个 System 2：默认配置仍训练视觉塔、mlp1 与后续投影。公共微调入口虽然暴露 LLM 开关，但 backbone setter 存在单向冻结的不对称实现，因此切换后应直接检查 requires_grad，不能只看标志值。

训练损失并非只有流匹配一项。论文附录 F 给出完整形式：

\[L=L_{fm}+L_{det}\]

其中 \(L_{det}\) 用 OWL-v2 标注目标物体框，以归一化中心坐标监督视觉语言表示。它不直接监督 DiT 的速度输出，但可能通过共享表示间接影响策略。公开 n1-release 动作头没有完整呈现论文描述的检测训练分支，因此论文完整训练目标与公共微调入口必须分开理解。

十、实验结论摘要

完整数字、统计口径和逐任务表见子页 ⑤；枢纽页只保留可由实验直接支持的边界：

  • 在论文报告的三个仿真集合与真机 GR-1 任务中，完整 N1 系统的汇总结果高于作者选择的 BC-Transformer 与 Diffusion Policy 从零训练基线；但比较同时改变预训练、架构、容量和数据，差值不能全部归因于某一个因素。
  • 真机汇总中，N1 使用 10% 后训练数据时平均成功率为 42.6%，接近 Diffusion Policy 使用 100% 数据时的 46.4%。这是样本效率证据，不是“所有低数据任务都单调占优”的证明。
  • GR-1 三档实验呈现预训练优势随后训练数据增多而收窄；不能把这一趋势无条件外推到全部三个仿真集合。
  • 神经轨迹在论文测试的设置中带来正增益，但作者将其称为 preliminary results；真机只测试了低数据档，因此它支持“在这些设置中有效”，不证明合成数据在所有任务中都必需。
  • 平滑、抓取准确和 Diffusion Policy 起始帧不动来自作者的定性观察，不能替代统计评测。

十一、与其他 VLA 对照时看什么

不同论文的模型规模、数据、任务和评测协议并不统一，本页不维护容易失真的横向大表。比较 GR00T N1 与其他 VLA 时，优先看三个结构轴：

  1. 视觉语言条件与动作 token 是联合建模，还是用交叉注意力连接两个主干；
  2. 跨本体差异由统一补齐空间、按本体边界层，还是软提示等机制处理；
  3. 动作训练只用机器人真值，还是同时吸收潜在动作、逆动力学伪标签和仿真真值。

按统一口径整理的入口见 VLA 总览。Flow Matching 的时间方向约定也不能只看“都使用流匹配”这一标签，GR00T N1 的具体口径见子页 ②。

十二、四个容易误解的点

下面四条一旦被压缩成一句话就很容易失真；应始终保留变量定义与证据来源。

12.1 时刻不服从 Beta(1.5, 1)

常见简写「\(\tau\sim\mathrm{Beta}(1.5,1)\)」不符合论文记号，也不符合源码。若令 \(u\sim\mathrm{Beta}(1.5,1)\)，论文记号按变量变换反解为

\[\tau=s(1-u),\]

而源码明确实现为

\[\tau=\frac{s-u}{s},\qquad s=0.999.\]

两式并不相等。对 \(u\in[0,1]\)，它们的逐点差值绝对值至多约为 \(1.001\times10^{-3}\)；论文变换的支持区间是 \([0,s]\)，源码变换的支持区间则是 \([(s-1)/s,1]\)，因而源码存在约到 \(-0.001001\) 的极小负尾部。共同点是都把采样重心移向 \(\tau\approx0\) 的噪声端。精确密度与负尾部的实现影响见子页 ②。

12.2 速度场目标的符号

论文式与源码式相反；对噪声—动作插值求导可确认源码目标与其正向 Euler 更新内部一致。应称为“论文—实现冲突与源码自洽”，而不是笼统写成“所有源码数学都正确”。

12.3 推理步数

论文正文称 \(K=4\)，发布权重的配置是 16。两者都不算错——\(K\) 是可在推理时调整的参数，源码也提供了覆盖接口——但引用时应说明取的是哪一层来源。

12.4 「取第 12 层」实际是截断计算

论文说使用中间层而非末层表示。实现上并不是算完 24 层再取中间输出，而是在构造时只保留 12 个 Transformer 层，同时把语言模型头替换为恒等映射，因此确实省去后续层计算。实验事实、证据边界与可能解释见子页 ⑥。
