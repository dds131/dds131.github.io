可靠的 PPO 实现不是把论文公式翻译成几行 Tensor 运算，而是把数据契约贯彻到采样、Storage、优势、分布、更新、日志与评估。最有效的阅读方法是先写下每个张量的语义和 Shape，再沿一次迭代追踪哪些量冻结、哪些量重算。

4 套源码教学、框架、组件、机器人

阅读源码的主线： environment.step → storage.add → compute_returns/advantages → evaluate_actions → ratio → actor/value/entropy loss → optimizer.step → 日志。任何库都可以沿这条链映射。

1. 先定义张量契约

以下以前馈连续动作策略为例，B=T×N：

名称 Rollout 形状 更新形状 dtype 梯度 语义
obs [T,N,O] [B,O] float 无 Actor 观测
critic_obs [T,N,C] [B,C] float 无 Critic 观测，可与 obs 相同
policy_action [T,N,A] [B,A] float 无 必须能被同一策略分布重新评估的随机变量
env_action（可选） [T,N,A] 通常不进 Loss float 无 实际送入环境的有界动作，用于核对变换/裁剪
rewards [T,N] [B] float 无 单步标量奖励
old_log_prob [T,N] [B] float 无 采样动作的联合旧对数概率
old_value [T,N] [B] float 无 采样时 Critic 值
next_value [T,N] 构造 GAE 后可丢弃 float 无 真实后继观测的旧 Critic 值
advantage [T,N] [B] float 无 固定 GAE，可另存标准化版本
returns [T,N] [B] float 无 固定价值目标
terminated/truncated [T,N] 通常不进 Loss bool 无 环境边界事实
bootstrap/trace_mask [T,N] 构造 GAE 后可丢弃 float/bool 无 是否 Bootstrap、是否延续 GAE 递推

Storage 可以在 CPU 或 GPU，但送入同一次计算的模型参数、观测、动作和目标必须位于兼容设备且 dtype 合理。表中所有 Rollout 字段都应脱离采样计算图；更新时只有重新计算的 new_log_prob、Entropy 与 new_value 需要梯度。

在代码入口处用断言把契约写死，比长时间训练后再从异常曲线反推广播错误更高效。

assert old_log_prob.ndim == advantage.ndim == returns.ndim == 1
assert obs.shape[0] == actions.shape[0] == old_log_prob.shape[0] == returns.shape[0]
assert obs.device == actions.device == old_log_prob.device == returns.device
frozen = (old_log_prob, old_value, advantage, returns)
assert all(not x.requires_grad for x in frozen)
assert all(torch.isfinite(x).all() for x in frozen)

2. 一个可审计的连续动作模型

import torch
from torch import nn
from torch.distributions import Normal

def mlp(in_dim, hidden, out_dim):
    layers, last = [], in_dim
    for width in hidden:
        layers += [nn.Linear(last, width), nn.Tanh()]
        last = width
    layers.append(nn.Linear(last, out_dim))
    return nn.Sequential(*layers)

class ActorCritic(nn.Module):
    def __init__(self, obs_dim, act_dim, hidden=(64, 64)):
        super().__init__()
        self.actor = mlp(obs_dim, hidden, act_dim)
        self.critic = mlp(obs_dim, hidden, 1)
        self.log_std = nn.Parameter(torch.zeros(act_dim))

    def distribution(self, obs):
        mean = self.actor(obs)
        std = self.log_std.exp().expand_as(mean)
        return Normal(mean, std)

    @torch.no_grad()
    def act(self, obs):
        dist = self.distribution(obs)
        action = dist.sample()
        log_prob = dist.log_prob(action).sum(-1)
        value = self.critic(obs).squeeze(-1)
        return action, log_prob, value

    def evaluate_actions(self, obs, action):
        dist = self.distribution(obs)
        log_prob = dist.log_prob(action).sum(-1)
        entropy = dist.entropy().sum(-1)
        value = self.critic(obs).squeeze(-1)
        return log_prob, entropy, value

这段代码刻意不处理有界动作：action 是原始 Normal 样本。若环境前需要硬裁剪或 tanh 变换，必须把“用于重算 Log Probability 的策略随机变量”和“实际执行动作”同时纳入契约；不能只保存执行动作后再假装它来自未变换 Normal。详见 网络与动作分布。

act 位于 no_grad 中，因此这里使用 sample() 不影响 PPO 的梯度；更新梯度来自对已存动作调用 evaluate_actions。生产实现还应监控或约束 log_std，防止指数运算产生极端方差。

3. GAE：把边界语义显式传入

@torch.no_grad()
def compute_gae(reward, old_value, next_value,
                bootstrap_mask, trace_mask, gamma, gae_lambda):
    # 所有输入 [T, N]；next_value[t] 必须对应 transition t 的真实后继状态
    advantage = torch.empty_like(reward)
    gae = torch.zeros_like(reward[-1])
    for t in reversed(range(reward.shape[0])):
        delta = reward[t] + gamma * bootstrap_mask[t] * next_value[t] - old_value[t]
        gae = delta + gamma * gae_lambda * trace_mask[t] * gae
        advantage[t] = gae
    returns = advantage + old_value
    return advantage, returns

这里没有使用单一 done。真终止通常令 bootstrap_mask=0, trace_mask=0；由环境外部时间上限等原因造成的截断，应令 bootstrap_mask=1, trace_mask=0；普通非边界转移为 1,1。是否 Bootstrap 由边界语义决定，而不是由末观测是否容易取得决定：如果本应 Bootstrap 却缺少真实末观测，说明采集契约不完整，应修复采集器、丢弃该条目标计算，或明确记录近似方案，不能静默把它当作真终止。

VectorEnv 自动重置后，next_value[t] 必须来自该转移的真实末观测，不能来自重置后的新 Episode 首观测。不同版本或封装可能把它放在 info["final_obs"]、final_observation 或 terminal_observation；实现必须按实际 API 做一次集成测试，不能仅凭字段名猜测。完整边界表见 Rollout、GAE 与批数据。

4. 更新函数：冻结旧量、重算新量

下例中的 batch.actions 对应前表的 policy_action；若另存 env_action，它不能替代前者参与未变换分布的 evaluate_actions。本例选择在完整 Rollout 上只标准化一次 Actor 优势，并把原始优势保留给诊断与 Return 构造：

adv_all = storage.advantage
storage.advantage_for_actor = (
    adv_all - adv_all.mean()
) / (adv_all.std(unbiased=False) + 1e-8)

def ppo_minibatch_loss(model, batch, clip_coef, vf_coef, ent_coef):
    new_log_prob, entropy, new_value = model.evaluate_actions(
        batch.obs, batch.actions
    )

    # 只接受每样本一个标量：[B] 或显式标量头 [B, 1]
    batch_size = batch.old_log_prob.shape[0]

    def scalar_per_sample(x, name):
        if x.shape == (batch_size, 1):
            x = x[:, 0]
        if x.shape != (batch_size,):
            raise ValueError(f"{name} must be [B] or [B, 1], got {tuple(x.shape)}")
        return x

    new_log_prob = scalar_per_sample(new_log_prob, "new_log_prob")
    entropy = scalar_per_sample(entropy, "entropy")
    new_value = scalar_per_sample(new_value, "new_value")
    assert batch.advantage_for_actor.shape == batch.old_log_prob.shape
    assert batch.returns.shape == batch.old_value.shape == batch.old_log_prob.shape

    log_ratio = new_log_prob - batch.old_log_prob
    if not torch.isfinite(log_ratio).all():
        raise FloatingPointError("non-finite PPO log-ratio")
    ratio = log_ratio.exp()

    advantage = batch.advantage_for_actor

    pg_unclipped = ratio * advantage
    pg_clipped = ratio.clamp(1.0 - clip_coef, 1.0 + clip_coef) * advantage
    actor_loss = -torch.minimum(pg_unclipped, pg_clipped).mean()

    value_loss = 0.5 * (new_value - batch.returns).square().mean()
    entropy_mean = entropy.mean()
    total_loss = actor_loss + vf_coef * value_loss - ent_coef * entropy_mean

    with torch.no_grad():
        # expm1 在 log_ratio 接近 0 时比 exp(x) - 1 更准确
        approx_kl = (torch.expm1(log_ratio) - log_ratio).mean()
        clipfrac = ((ratio - 1.0).abs() > clip_coef).float().mean()
    metrics = {
        "actor_loss": actor_loss.detach(),
        "value_loss": value_loss.detach(),
        "entropy": entropy_mean.detach(),
        "approx_kl": approx_kl.detach(),
        "clipfrac": clipfrac.detach(),
        "ratio_mean": ratio.mean().detach(),
        "log_ratio_abs_max": log_ratio.abs().max().detach(),
    }
    return total_loss, metrics

外层优化循环

stop = False
for epoch in range(update_epochs):
    for batch in storage.minibatches(minibatch_size, shuffle=True):
        optimizer.zero_grad(set_to_none=True)
        loss, metrics = ppo_minibatch_loss(
            model, batch, clip_coef, vf_coef, ent_coef
        )
        if not torch.isfinite(loss).item():
            raise FloatingPointError("non-finite PPO loss")

        # 当前前向发生在本次 step 之前；越界时不再应用这个 Mini-batch
        if target_kl is not None and metrics["approx_kl"].item() > target_kl:
            stop = True
            break

        loss.backward()
        grad_norm = nn.utils.clip_grad_norm_(
            model.parameters(), max_grad_norm, error_if_nonfinite=True
        )
        optimizer.step()

    if stop:
        break

这是结构示例，不是可直接替换所有库的生产实现：它没有价值裁剪、学习率调度、分布变换、混合精度、分布式同步和 RNN 序列切分。

本例把优势在完整 Rollout 上标准化一次并冻结；若选择“每个 Mini-batch 标准化”，必须明确它会让结果依赖切批与打乱。上面的 KL 是旧策略样本下 \(D_{KL}(\pi_{old}\Vert\pi_{new})\) 的非负样本估计；expm1 改善了接近 0 时的精度，但极端正 log_ratio 仍可能溢出，因此有限性检查和异常批次诊断仍不可省略。检查发生在当前 Mini-batch 的步进前，仍有采样噪声。若需要更稳定的安全阀，可在固定全批上于声明的检查点重算，代价是额外前向。

5. 一次迭代的模块边界

flowchart TB
  ENV["VectorEnv / Simulator"] -->|obs, reward, boundaries| COL["Collector"]
  MOD["ActorCritic"] -->|action, old_log_prob, old_value| COL
  COL --> STO["RolloutStorage"]
  STO --> ADV["GAE + Return Builder"]
  ADV --> BAT["Mini-batch Iterator"]
  BAT --> LOSS["PPO Loss"]
  MOD --> LOSS
  LOSS --> OPT["Optimizer + grad clip + KL stop"]
  OPT --> MOD
  OPT --> LOG["Metrics + checkpoint metadata"]

推荐把边界处理、GAE、分布评估和 Loss 分成独立纯函数或小模块。这样可用手工张量测试，而不必启动仿真器才能验证核心数学。

本页的工程创新点不是发明新 PPO 目标，而是把公式升级为可执行契约： 每个字段都有语义、Shape、设备、梯度属性和冻结时点；每个模块都有可单测的不变量；每个外部框架都按同一调用链映射。这样，差异能被定位到数据、分布、目标或优化层，而不是笼统归因于“随机性”。

6. 四套官方/主流实现如何阅读

实现 定位 适合学习什么 阅读入口
CleanRL 单文件研究实现 一次迭代的完整控制流、日志与复现实验 cleanrl/ppo.py、ppo_continuous_action.py
Stable-Baselines3 稳定通用库 RolloutBuffer、策略抽象、回调、序列化、接口边界 stable_baselines3/ppo/ppo.py 与 common/buffers.py

RSL-RL GPU 机器人训练 高吞吐并行 Rollout、ActorCritic、OnPolicyRunner、机器人扩展 rsl_rl/algorithms/ppo.py、runners/on_policy_runner.py

CleanRL：控制流审计

单文件把环境创建、网络、Storage、GAE 和更新放在一起，适合建立端到端地图。阅读时区分 Atari/离散动作版与连续动作版，不要把特定环境 wrapper 当成 PPO 通用定义。

Stable-Baselines3：看抽象边界

沿 OnPolicyAlgorithm.collect_rollouts、RolloutBuffer.compute_returns_and_advantage、PPO.train 追踪。SB3 的 Normalization、Policy 类、Callbacks 与 VecEnv 语义是工程价值所在；默认参数和终止处理需绑定版本理解。

TorchRL：看组件组合

重点观察 SyncDataCollector、GAE、ClipPPOLoss 和 TensorDict Key 如何连接。当前官方教程在每个 Epoch 内重算优势，而本页参考骨架选择在 PPO 更新前计算一次并冻结；这是目标更新口径的明确差异，复现时不能混为同一实现。TorchRL 还可能在训练期间保持模块为 eval 模式，同时由探索上下文控制是否采样，因此“模块 train/eval 模式”与“动作随机/确定模式”也必须分开记录。

RSL-RL：看 GPU 机器人路径

沿 OnPolicyRunner.learn、RolloutStorage、PPO update、ActorCritic 追踪。重点核对观测组、特权 Critic、动作标准差、KL 自适应学习率和多 GPU 同步，不把机器人特化配置误当成通用 PPO。

7. 37 项实现细节如何归类

与其背诵清单，不如按失效边界归类：

环境接口

Episode 统计、终止/截断、自动 reset、观测与奖励 wrapper、随机种子。

网络与分布

初始化、激活、共享/独立网络、动作裁剪、标准差、log-prob 求和。

优势与目标

GAE、优势标准化、Return、价值裁剪、奖励尺度与 Bootstrap。

优化与调度

Epoch、Mini-batch、Adam epsilon、学习率退火、梯度裁剪、KL 早停。

可复现性

全链路种子、确定性开关、版本、硬件、日志、Checkpoint 与评估协议。

任务特化

Atari Frame Stack、MuJoCo 动作范围、机器人特权观测与 GPU 并行。

算法公式相同，不代表实现等价。任何对照实验都应先列出上述六类差异。

8. 日志最小集合

每次 PPO 迭代至少记录：

  • 性能：Episode Return、Episode Length、成功率及多种子聚合；
  • 采样：环境步/秒、更新步/秒、Batch 大小、Episode 边界计数；
  • Actor：Actor Loss、ratio 的均值/标准差/极值、approx KL、clipfrac；
  • Critic：Value Loss、Return/Value 均值与标准差、explained variance；
  • 探索：Entropy、连续动作逐维标准差、动作边界命中率；
  • 优化：学习率、梯度范数、提前停止的 Epoch/Mini-batch 位置；
  • 数值：NaN/Inf 计数、观测与奖励极值。

日志应绑定全量配置、代码版本、依赖版本、随机种子、模型 train/eval 模式、探索模式和归一化统计。仅保存权重不足以可靠复现推理。

Checkpoint 最小契约

可继续训练的 Checkpoint 至少应保存：

  • Actor、Critic 及所有可学习的分布参数；
  • 优化器、学习率调度器，以及启用混合精度时的 GradScaler 状态；
  • 观测/奖励归一化统计、训练步数、更新次数和预算进度；
  • Python、NumPy、PyTorch 及适用时 CUDA 的随机数状态；
  • 完整配置、代码/依赖版本和动作变换语义。

若要求逐步一致地续训，还可能需要环境或仿真器状态、Collector 状态和当前未消费完的 Rollout。无法恢复这些状态时，应明确标注为“参数续训”或“仅评估”Checkpoint，不能宣称精确恢复了同一训练轨迹。

9. 分层测试策略

L1 · 纯数学单元测试

  • 四个手工 ratio/advantage 样本验证裁剪分段；
  • 两条含真终止/时间截断的人工轨迹验证 GAE；
  • 相同参数下 act 保存的 log-prob 与 evaluate_actions 一致；
  • 每个动作维 log-prob 求和后 Shape 为 [B]；
  • ratio 全为 1 时，非负 KL 估计为 0；任意有限正 ratio 下每项不小于 0；
  • 有界动作同时核对策略变量、执行动作和 Jacobian 修正，不能只测动作是否落在范围内。

L2 · 数据管线集成测试

  • 小型 VectorEnv 采一个 Rollout，验证 Storage 所有字段对齐；
  • 分别覆盖 Next-Step、Same-Step 等实际启用的自动重置模式，并验证真实末观测不被重置观测替换；
  • 多 Epoch 中旧量不变、新 log-prob 改变；
  • RNN 模式下序列块不跨 Episode；
  • CPU/GPU 或 Collector/模型设备不同时，批量迁移不改变字段对齐、dtype 和冻结属性。

L3 · 可学习性冒烟测试

  • 在小型经典控制环境上固定短预算，并预先规定最低回报阈值或相对随机基线的改进阈值；单个 Seed 的一次上升不能称为统计显著；
  • 在已声明确定性设置与同一 Seed 下重跑，结果应在预设容差内一致；不能把 GPU 非确定算子下的逐点曲线差异直接判为算法错误；
  • 冻结参数、预处理统计和模型模式后，原 Rollout 的 ratio 应恒等于 1 或只出现浮点误差。

L4 · 回归与性能测试

  • 固定版本与配置，多种子比较回报分布；
  • 吞吐、GPU 显存、采样/更新占比设回归阈值；
  • 在相同环境种子、归一化统计、模型模式和动作选择规则下，Checkpoint 保存—加载—评估结果一致。
