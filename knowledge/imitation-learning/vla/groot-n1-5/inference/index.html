ARTIFACT ACCEPTANCE · EULER RUNTIME · OBSERVATION HANDOFF

一次 get_action 不是“模型前向后直接控机器人”：先验收车道化制品，再执行 transform、主干、随机动作初始化与 K 步动作 DiT，最后由外部控制器消费动作块并承担时序和安全。

H=16 · Dmax=32预测动作块与共享上限；32不是每个本体的物理自由度。
K=4N1.5 checkpoint和服务默认；类默认是None，运行时仍可覆盖。
约0.15%公开训练时间分布的负尾概率；静态派生，不是已证明的性能bug。
7 requests多seed、K-sweep、clip、重训消融、backend parity、chunk策略与安全指标均交给Experiments。

边界、证据与 Training 制品验收

本页消费唯一入站合同groot-n1-5.training-to-inference.v1，保留运行时现象解释，把结果表、K-sweep和消融交给⑤Experiments，把逐文件完整调用图交给⑥Source Code。固定源码为n1.5-release提交4af2b622892f7dcb5aae5a3fb70bcb02dc217b96，checkpoint revision为869830fc749c35f34771aa5209f923ac57e4564e；Research、checkpoint、源码、FLARE v1与N1 v2各自回答不同问题，浮动main不得倒灌。

Policy 七阶段、Transform 与动作键绑定

flowchart LR
  O[原始观测] --> X[复制/补batch + apply transforms]
  X --> B[Eagle backbone]
  B --> V[vlln + 4层VL self-attention + state encoder]
  V --> N[采样高斯动作块 A0]
  N --> D[K次 action encoder + DiT + decoder + Euler]
  D --> U[FP32/CPU + unapply + 反归一化 + 按键切分]
  U --> C[外部动作块 consumer]

文本回退：Gr00tPolicy.get_action依次复制输入并补batch、应用输入变换、运行Eagle主干、执行vlln/VL-SA与状态编码、采样[B,H,Dmax]高斯动作、循环K次动作编码/DiT/解码/Euler，再转FP32/CPU并执行逆变换，最后把动作块交给外部consumer；Policy不执行机器人、碰撞检查或安全停止。

apply_transforms处理图像、文本和state，并用checkpoint metadata归一化；ConcatTransform.unapply按action key切分统一宽度输出，再反归一化和逆变换。推理动作头不读取训练action_mask，所以必须固定camera keys及顺序、text key、state/action keys、statistics version、relative/absolute语义、单位/夹爪和missing-modality policy。形状合法不等于物理语义正确，任何补零都必须来自processor合同。

每块一次、每步一次与 Euler 形状合同

每个动作块只执行一次Eagle backbone、process_backbone_output中的vlln/VL-SA、state encoder和初始高斯采样。每个Euler步都重新执行action/time encoder、future token expand与拼接、16层DiT、全序列action decoder和更新。处理后的VL token会复用，但公开PyTorch路径没有跨步显式cross-attention K/V cache；DiT投影仍逐步重算，所以“主干一次”不等于“所有视觉语言相关计算均已缓存”。

A0 ~ Normal(0, I), shape [B,H,Dmax]
repeat k = 0..K-1:
  action_tokens <- encode(Ak, time_bucket)
  queries <- concat(state, future, action)
  velocity <- decode_last_H(DiT(queries))
  Ak+1 <- Ak + (1/K) * velocity

所有步保持[B,H,Dmax]、dtype与device不变。decoder处理全序列，但速度只取末H个action位置；future位置不直接输出给机器人。若改变state→future→action顺序，必须同步更新slice并重训、验收，不能只改concat。

每动作块一次与每Euler步一次
频率 计算 缓存边界
once/chunk Eagle、vlln+VL-SA、state encoder、initial gaussian processed VL tokens复用
once/step action/time encoder、future expand/concat、16-layer DiT、full-sequence decoder、Euler update 无显式cross-attention K/V cache

训练时间负尾、推理网格与显式随机起点

训练采u~Beta(1.5,1.0)并令t=(0.999−u)/0.999，所以支持集为(-1/999,1)而非严格[0,1]。P(t<0)=1−0.999^1.5≈0.001499625，约0.1499625%；公开代码不clip，小负数乘1000再转整数时因向零截断进入0桶。这只是静态派生现象，性能影响unknown，不能称已证明bug。

推理不采Beta时间，而用t_k=k/K、Δt=1/K。K=4时连续时刻为0,0.25,0.5,0.75，1000桶为0,250,500,750，最后推进到t=1。setter没有正整数校验：K=0除零，K<0不进入循环并返回初始噪声，非整数不能交给range；部署binding必须要求K∈N_{>0}。

每次get_action都会用torch.randn重采A0，同观测/权重/K不保证同输出；eval()和inference_mode()不会取消显式采样，公开API也没有per-call generator/seed参数。复现实验至少记录RNG state、设备/dtype、库/内核/backend和精确输入字节；固定seed仍不能让真实闭环传感器与时序确定。

K 的优先级、四层证据与 Euler 误差边界

K有四层来源：动作头类默认None、N1.5 checkpoint默认4、inference_service.py CLI默认4并传给Policy、构造参数或setter的运行时覆盖。有效优先级是runtime > service > checkpoint > class；必须记录effective K并要求backend遵守相同规则，不能统称“模型固定值”。

4步历史与发布配置必须分开
来源 K 允许结论
N1论文 4 论文称4步足够
N1 checkpoint 16 发布制品默认16
FLARE v1 4 实验沿用N1论文口径
N1.5 checkpoint 4 发布配置从N1的16变为4；不是N1.5首次发现

官方没有N1.5的1/2/4/8/16成功率—延迟消融，也没有改为4的因果理由。对同一光滑速度场，显式Euler局部截断误差为O(Δt²)、固定区间全局离散误差为O(Δt)=O(1/K)；K4到K16在渐近区间内只让这一离散项约变为四分之一，不包含学习场误差、随机初值、数值精度或控制执行，更不能换算成成功率或“4倍端到端加速”。

固定配对(ε,a)的(1−t)ε+ta确为直线，targeta−ε不随t变化；学习场却是给定中间状态/条件后的条件平均，多配对混合、逼近误差与conditioning使单条ODE轨迹不保证直线。这只支持少步动机，不证明4步与16步等价，也不允许笼统断言传统diffusion总是曲率更大。

Future Token 的结构成本与运行时作用

每步序列长度是L=S+32+H，S不是结构恒定为1。仅在S=1、H=16的说明性假设下，N1.5为49；无future token对照为17。self-attention矩阵元素比49²/17²≈8.31；再比较K4与K16，局部整块比4·49²/(16·17²)≈2.08。这些只是attention矩阵元素的结构比，不是端到端FLOPs、显存或实测延迟；两代宽度、block、主干、kernel和cache均不同。

future位置不直接下发机器人，但16个DiT block中的self-attention使其与action交互，因此可影响末H位置输出。普通公开微调中future token还能从Flow loss获得间接梯度；LoRA通常冻结基础future embedding，但选中的Q/K/V adapter仍能改变交互。源码不证明token学到了何种语义；删除它会改变序列与注意力分布，必须重训并做消融，“纯开销”“不影响输出”和“可无损删除”均为false。

FLARE 运行边界与能力归因

Research称内部训练使用FLARE；固定公开代码有32个future token与hidden-state接口，但公开微调没有target encoder、projector、cosine alignment或EMA teacher。推理既不计算alignment loss，也不运行teacher，只消费已经训练的policy参数与结构token。发布权重可能承载内部FLARE效果，但单次公开推理不能证明效果来源；只把hidden开关设为true也不能补全FLARE，公开缺口原因仍unknown。

官方同时改变Eagle2.5/grounding、VLM freeze、connector/normalization、FLARE和DreamGen data，未给freeze-only消融。因此“冻结VLM导致提升”not-proven，“冻结减少语义漂移”只是hypothesis。公开下游仍可在vlln、VL-SA、future token、state/action modules与DiT适配，具体取决于freeze/LoRA；官方文字与公开LayerNorm张力回链Architecture，不在本页强行调和。

能力数字只作为Experiments入站观察：新物体zero-shot N1.5为15.0%，人类视频后训练为55.0%；DreamGen 12新动词为38.3%，N1为13.1%，但它们显式使用生成轨迹训练，不是完整zero-shot。数字必须携带protocol、sample count、training exposure与source；不能由一次推理链推出任意新指令可靠。

无 Action Mask、动作块消费与闭环时序

训练mask只定义loss有效维；推理先生成Dmax，再靠metadata与unapply截取。action key、拼接顺序、dimension、normalization statistics或relative/absolute mode错位都可能产生“张量形状合法、物理语义错误”的控制量。送机器人前应静态核对per-key shape/range/unit、反归一化有限值、gripper sign与transform round-trip；本阶段没有执行这些验证。

H=16只表示预测长度，不等于客户端必须执行16步。执行全部、只执行前n步、每tick重规划或异步覆盖由外部控制器决定；必须记录control frequency、inference latency、executed prefix length、observation timestamp、queue replacement policy、stale action policy、replanning trigger和safety stop。字段缺失时，模型延迟不能冒充闭环延迟，成功率也不可比较；本页不指定唯一consumer策略。

ZMQ、HTTP、TensorRT 与生产安全边界

公开样例服务提供ZMQ与HTTP封装，最终都调用Gr00tPolicy.get_action；TensorRT路径要求预构建engine，是另一backend制品。相同Policy语义不保证序列化、batch、dtype、K override或数值逐位一致。parity矩阵至少记录transport、backend、model revision、effective K、precision、input schema和output schema；本页不提供启动命令。

样例服务不是生产服务。生产至少需要authentication/authorization、payload shape/size validation、safe deserialization、timeout/cancellation、concurrency/backpressure、bounded queue、health/readiness、model version、structured errors与redacted logging。模型动作还必须经过joint position、velocity/acceleration、workspace/collision与emergency stop约束；独立安全监督器必须位于模型/网络返回之后。本页不声称已观察任何运行事故。
