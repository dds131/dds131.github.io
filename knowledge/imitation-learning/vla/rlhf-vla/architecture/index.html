ActorReferenceRewardCritic

RLHF-VLA 的核心不是“再加一个网络”，而是让多个网络在不同阶段承担不同职责

Actor 产生动作，Reference 限制长期漂移，Reward Model 评价行为，Critic 预测未来回报；PPO 的 Old Policy 则保存本轮行为策略。这里的“模块”是数学职责，不一定对应五份完全独立的物理网络；参数所有权和冻结边界决定 Loss 是否真的成立。

一、条件输入与动作输出

将策略条件写成：

\[c_t=(I_{t-k:t},q,s_t,h_t)\]

其中 $I$ 是单帧或多帧视觉，$q$ 是任务语言，$s_t$ 是本体状态，$h_t$ 是动作或状态历史。VLA Actor 的输出可能是：

  • 自回归 Action Tokens：OpenVLA 类模型按 token 预测离散化动作。
  • 连续动作分布：高斯 Actor 直接给均值、方差或其参数。
  • Diffusion/Flow 动作块：π0 类模型通过多步生成得到连续 action chunk。

这三种输出是否能对训练样本中的同一动作计算一致且可微的 $\log\pi(a\mid c)$，决定可以直接使用哪些偏好或 RL Loss。能生成动作不等于暴露了可用的归一化 log-prob 接口。

二、经典 RM + PPO 的五个对象

flowchart LR
  C[图像 · 语言 · proprio] --> O[行为策略 π_old rollout]
  O --> T[固定轨迹与动作]
  T --> OL[保存 old log-prob]
  T --> CP[Current Actor 重算 log-prob]
  OL --> RT[PPO ratio]
  CP --> RT
  T --> R[冻结 Reward Model 评分]
  T --> RF[冻结 Reference log-prob]
  OL --> K[采样 reference log-ratio / KL penalty]
  RF --> K
  R --> S[shaped reward]
  K --> S
  T --> V[Critic 预测]
  S --> G[Return targets + GAE Advantage]
  V --> G
  RT --> AL[Actor clipped surrogate]
  G --> AL
  G --> VL[Critic target / value loss]
  AL --> P[更新 Current Actor]
  VL --> VC[更新 Critic]

rollout 结束后，轨迹、动作、old log-prob 与奖励目标在一个 PPO batch 内保持固定；Current Actor 在每个优化 epoch 对同一动作重新计算 log-prob。Reference 也不能单独“输出 KL”：精确 KL 需要两边分布，常见实现则用行为策略与 Reference 在采样动作上的 log-ratio 形成惩罚估计。

2.1 Current Actor $\pi_\theta$

从多模态条件生成动作，是最终部署的策略模型。它可在 BC、PPO、DPO、KTO、APO 或 TPO 阶段更新；实际执行动作仍可能被安全层和低层控制器改写。

2.2 Old Policy $\pi_{old}$

本轮 PPO rollout 的冻结快照，用来计算：

\[\rho_t(\theta)=\frac{\pi_\theta(a_t\mid c_t)}{\pi_{old}(a_t\mid c_t)} =\exp\!\left[ \log\pi_\theta(a_t\mid c_t)-\log\pi_{old}(a_t\mid c_t) \right]\]

$a_t,c_t$ 来自 $\pi_{old}$ 的固定 rollout，分子由 Current Actor 在更新阶段重新计算。更新若干 PPO epoch 后再刷新 Old。它是短期采样基准，不是长期能力锚点；实现可以保存完整快照，也可以保存足以重建分母的 old log-prob。

2.3 Reference Policy $\pi_{ref}$

通常由 SFT/BC 策略复制，用来计算 KL 或 log-ratio。Reference 至少在一个优化阶段内冻结；它可以跨多轮保持不变，也可以像 HAPO 那样在新一轮部署—优化循环开始时重置为上一轮策略，但必须记录刷新时点和 checkpoint。

2.4 Reward Model $R_\phi$

输入通常包含任务/观测条件以及动作片段或完整轨迹，输出偏好分数或逐步 reward。监督可来自人类、AI 或规则生成的偏好；在经典策略优化阶段通常冻结。

2.5 Critic $V_\psi/Q_\psi$

在给定当前策略和 shaped reward 定义下，预测从当前条件继续执行的未来回报；监督来自 rollout return 或 TD target，不直接拟合人类 pair 标签。策略或奖励定义改变后，旧 Critic 的数值语义也随之失效。

三、Reward Model 与 Critic 为什么不能互换

项 Reward Model Critic
问题 这段行为符合偏好吗 从这里继续能获得多少回报
输入 任务/观测条件 + 轨迹、片段或动作 状态/历史，或状态动作
标签 人类比较、评分 Return、TD target
数据 偏好数据集 当前 rollout 或 replay
更新 RM 阶段或按版本周期更新 通常随 RL 迭代更新
推理部署 通常删除 通常删除

即使二者都用 Transformer 加 scalar head，目标不同仍会导致不同表征。Reward Model 可能对已完成轨迹打分；Critic 必须在任务尚未结束时预测未来。

四、VLA 内部模块怎样接入

模块 输入 输出 偏好后训练常见处理
Vision Encoder 单/多视角图像 visual tokens 可冻结、LoRA 或微调；逐模型记录
Language/VLM Backbone 视觉与语言 融合表征 可冻结、LoRA 或低学习率微调
Proprio Encoder 关节、末端、力 state tokens 可训练或冻结，取决于基座与数据量
Action Head 融合表征 token logits/连续动作场 重点更新
Value 模块 状态表征 $V$ 或 $Q$ PPO/SAC 路线训练；可为独立网络
Reward 模块 条件化轨迹表征 标量/逐步 reward RM 阶段训练；可为独立网络

基础结构可直接参照OpenVLA 网络专题和π0 架构专题；本页只讨论人类反馈后训练新增模块。

五、三条路线的计算图差异

5.1 Reward Model + PPO

  • Actor rollout。
  • RM 给 reward；行为/当前策略与 Reference 共同形成 KL 或采样 log-ratio 惩罚。
  • Critic 估计 return/advantage。
  • 更新 Actor 与 Critic，冻结 RM 与 Reference。

5.2 DPO / KTO / APO

flowchart LR
  D[带偏好标签的数据] --> P[Current Policy log-prob]
  D --> R[Frozen Reference log-prob]
  P --> Z[policy/reference log-ratio]
  R --> Z
  Z --> L[DPO / KTO / APO Loss]
  L --> U[只更新 Policy]

没有独立 Reward Model 和 Critic。在相应 KL 正则化推导下，policy/reference log-ratio 可解释为隐式的相对 reward 参数化；它不是经过环境标定的绝对奖励，也不应脱离推导假设单独解释。

5.3 轨迹偏好 / TPO

TPO 逐时间步累加轨迹 log-ratio，再比较相同任务与初始条件下的 chosen/rejected trajectory；其 loss 只要求可信的轨迹排序。GRAPE 进一步用阶段分解、VLM/视觉关键点、时空 cost、self-reward 与成功指示器自动形成排序，这些属于偏好生成管线，不是所有 TPO 的必需网络，也不参与 TPO loss 的反向传播。

六、参数共享：节省显存，也引入耦合

Actor、Critic 和 Reward Model 可以从同一预训练视觉/VLM backbone 初始化，也可以缓存固定特征，甚至在严格约束下共享参数，但需要回答四个问题：

  1. 哪些参数接收哪一个 Loss 的梯度？
  2. 是否对某条分支 stop-gradient？
  3. 是否由一个优化器更新，还是使用独立参数组和学习率？
  4. “共享”指同一可变参数对象、独立 checkpoint，还是同一份冻结特征？

共享能减少计算，却可能产生表示非平稳和梯度冲突。尤其当 Actor 更新同一份共享视觉编码器时，只冻结 RM head 并不能冻结 RM 的完整函数：其输入表征仍在变化。要让“RM 冻结”真正成立，应使用独立的 frozen snapshot、同时冻结共享干路，或在表征变化后重新训练/校准 RM；Critic 也要随策略与奖励分布更新。

七、阶段生命周期

阶段 Actor Old Reference RM Critic
BC/SFT 更新 无 无 无 无
RM 训练 不接收 RM 梯度；可供样 无 可选且冻结 更新 无
PPO rollout 当轮不更新并复制为行为策略 采样并保存 old log-prob 冻结并计算 ref log-prob 冻结评分 只前向预测
PPO update 更新 冻结 冻结 冻结 更新
DPO/KTO/APO 更新 无 优化阶段内冻结；轮间可按规则刷新 无 无
部署推理 保留 删除 通常删除 通常删除 通常删除

八、离散 Action Token 与连续生成动作

OpenVLA 将动作映射到离散 token，因此可对已知动作计算序列 log-prob。为避免与机器人环境步 $t$ 混淆，用 $s\in[0,1]$ 表示生成路径时间；Flow Matching 的典型训练目标写成：

\[\mathcal L_{flow} =\mathbb E_{c,a_0,a_1,s} \left\|v_\theta(a_s,s,c)-u_s(a_s\mid a_0,a_1)\right\|_2^2.\]

$a_s$ 是噪声 $a_0$ 与数据动作 $a_1$ 之间概率路径上的样本，$u_s$ 是对应目标向量场。该回归损失不是 $-\log\pi(a\mid c)$。连续流在额外光滑性和数值积分条件下可以通过概率流与散度积分估计密度，但这不是 π0/OpenPI 训练接口中可直接替换 token log-prob 的廉价量。若偏好算法依赖 log-ratio，必须另行推导可计算的密度/路径目标，或采用 reward-weighted vector-field、residual policy 等不同目标；不能把 APO 的 token Loss 原样复制到 OpenPI。

九、安全层不是 Loss 的副产品

真实部署仍需独立的工作空间限制、速度与力矩阈值、碰撞检测、人工接管和急停。安全层可以修改最终执行动作，因此必须同时记录 policy action 与 executed action。

边界：KL、PPO clipping 或 preference alignment 只能限制统计意义上的策略变化，不能替代硬件安全约束，也不能证明策略在所有状态安全。

十、知识点、重点与创新点

10.1 知识点

  • Actor、Old、Reference、RM、Critic 的监督和生命周期。
  • VLA backbone、Action Head 与 Value/Reward 模块的连接方式。
  • 参数共享、冻结与 stop-gradient。

10.2 重点

  • Old Policy 不等于 Reference Policy。
  • Reward Model 不等于 Critic。
  • Flow Matching Loss 不等于动作 log-likelihood。

10.3 创新点

  • 经典 RLHF 把偏好评价、策略改进与方差降低拆成 Reward Model、Actor 和 Critic 三类职责。
  • 直接偏好方法在特定推导下，用 policy/reference log-ratio 消去显式 RM 训练和 Actor-Critic RL 内环；Critic 是不再需要，不是被 log-ratio “表示”。
  • GRAPE 把轨迹级 log-ratio 目标与自动多阶段偏好生成组合，但两部分可以、也应当分别审计。
  • VLA 的动作生成头决定是否存在可用 log-prob，离散 token 与连续 vector field 不能共用未经推导的 Loss。
