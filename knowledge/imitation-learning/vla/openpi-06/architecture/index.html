本页的知识点、创新点与重点

4 路预训练期图像输入，每路 448 × 448
3 段注意力划分：图像双向、文本因果、动作双向
3 类训练输出：子任务文本、FAST 离散动作、连续动作
860M动作专家，层数与主干相同
50 Hz动作块内关节角与夹爪指令的采样频率
63 ms5 步去噪、3 路相机、单张 H100

本页要建立的判断有四条。其一，π*0.6 论文显式列出的三项改进是数据扩充和模型扩容；模型卡还补充了 prompt 设计与注意力掩码的变化，不能把「论文列出的三项」误读成 π0.6 的全部设计差异。其二，至多四路相机各有明确角色，第四路是移动操作平台可选的后置相机。其三，三段注意力决定了不同 token 可以读取哪些上下文，是理解文本自回归生成与动作块并行生成的关键。其四，两种动作表示在计算图上分别预测：动作专家不读取 FAST 动作 token，但两路都依赖共同的观测、语言和预测子任务；这里的「独立」不是统计意义上的无条件独立。

一、本页在专题中的位置

π0.6 的骨架沿用 π0 与 π0.5：一个视觉-语言主干，外挂一套独立权重的动作专家，动作以动作块的形式由流匹配生成，高层先预测语言子任务再生成低层动作。这些机制本身已在前两个专题讲过，本页不重讲：

沿用自 机制 去哪一页看
π0 两套权重共享一个 Transformer 的双专家形态、KV cache、动作块 π0 专题子页 ① 网络架构与双专家
π0 流匹配的加噪插值、速度场目标与去噪采样 π0 专题子页 ② Flow Matching 动作生成
π0.5 高层语言子任务先于低层动作的分层设计 π0.5 专题子页 ⑤ 分层推理与长时程执行
π0.5 图像 token 之间使用双向注意力这一选择 π0.5 专题子页 ② 网络架构与结构差异

本页只讲 π0.6 自己的部分：改了哪三项、输入端怎么构成、序列怎么分段、输出端三路各是什么、推理耗时由什么决定。

本页只描述结构，不讲训练。三项联合训练目标的形式、流匹配项的权重、知识隔离的梯度落点、FAST 分支存在的理由，全部放在子页 ②。本页出现「FAST 离散动作 token」时只说明它是一路输出，不解释它为什么存在。

二、论文列出的三点改进

论文第五节 A 小节列出了 π0.6 相对 π0.5 的改进，原文的三点是：预训练数据集增补了来自多个机器人平台的额外数据；基座 VLM 换成 Gemma 3 的 4B 模型；动作专家的规模增加到 860M 参数。

# 改动 性质 直接后果
i 预训练数据集增补多个机器人平台的数据 数据 提高训练分布的跨平台覆盖，是「开箱即用」能力的数据基础
ii 基座 VLM 换为 Gemma 3 4B 规模 主干参数容量增大；视觉编码器仍为 SigLIP 400M
iii 动作专家增至 860M 规模 与更大的主干匹配；模型卡另注明其层数与主干相同

论文列出的三项确实都属于数据或规模调整；但这只是论文第五节 A 小节的改进清单，不是全部架构差异。模型卡另外写明了两处设计变化：

  • prompt 中可选的 metadata（见第三节）。模型卡第 1 节把这一代的改动概括为涉及「预训练 VLM 主干与 prompt 设计」以及训练数据，metadata 属于后者中的 prompt 设计。
  • 文本 token 之间用因果注意力（见第五节与第八节）。π0.5 论文把 prompt token 与图像、本体状态一起放在使用完全注意力的前缀中；模型卡写 π0.6「保持图像 token 之间的双向注意力（与 π0.5 相同），但文本 token 之间用因果注意力」。模型卡没有说明这样改的原因。

这一点值得单独强调：π0.6 保留 π0.5 的分层设计和 Knowledge Insulation，论文没有再提出一套新的策略学习范式。模型卡把「不做任务特定微调仍显著更强」归因于多样训练数据与丰富 metadata 条件化；更大的主干和动作专家则是论文明确列出的扩容项。这里能确认的是作者给出的归因，不能据此断言某一项单独贡献了多少提升。

需要注意规模数字的换代。前两个专题记录的是 PaliGemma 3B 主干加约 300M 动作专家，那是 π0 / π0.5 那一代的配置；本代是 SigLIP 400M 加 Gemma 3 4B 主干、动作专家 860M。两组数字不能混用，引用时必须说明属于哪一代。

三、输入端：观测、语言与 metadata

论文把模型写成

\[\pi_{\theta}\!\left(a_{t:t+H},\ \hat{\ell} \mid o_t,\ \ell\right)\]

其中观测与语言两项的构成是这样的：

\[o_t = \left[X^1_t,\ \dots,\ X^n_t,\ q_t\right], \qquad \ell = \ell_t + s\]

逐项解释：

  • \(X^i_t\)：第 \(i\) 路相机在 \(t\) 时刻的图像。预训练期最多四路，每路分辨率 448 × 448。
  • \(q_t\)：机器人的构型，即本体状态（proprioception）。模型卡写明它以 token 化的形式与图像 token、语言 token 拼接。
  • \(\ell_t\)：整体任务的提示词，论文给的例子是「make me an espresso」。
  • \(s\)：额外的语言输入，即 metadata，用来进一步调制任务的执行方式。这一项是可选的。
  • \(\hat{\ell}\)：模型自己预测出的下一个子任务的文本表示，论文给的例子是「pick up the coffee cup」。

四路相机各自的角色

模型卡明确给出了四路图像的分工，这不是任意的四个视角：

路数 角色 模型卡的写法
1 base 相机（机身主视角） a base camera
2–3 腕部相机 up to two wrist cameras，至多两路
4 后置相机 可选，仅用于移动操作平台

模型卡明确把第四路写成移动操作平台可选的后置相机，因此能确认的是：它不是所有平台的必需输入。模型卡给 63 ms 推理耗时时采用三路相机；论文的 RECAP 实验平台也恰好使用一台 base 相机和两台腕部相机，但两份材料都没有说明延迟测试是否就是在该实验平台上完成，因此不把这两个「三路」进一步等同。

metadata 是这一代的一个显式设计点

模型卡把 metadata 单独列出来，并在第 3 节把它与「不做任务特定微调」直接关联：π0.6 之所以能在不做任务特定后训练的情况下取得更强表现，模型卡归因于多样的训练数据与丰富的 metadata 条件化这两件事。

metadata 在架构上的位置很简单：它就写在 prompt 里，和任务指令同处语言通路。本站的理解是，它在方法论上的意义在于：一部分「同一个任务在不同场合应该怎么做」的信息，可以不必靠任务特定微调写进权重，而改由输入端指定。模型卡没有展开 metadata 的具体内容，这一层只是依据其措辞做的解读。

这条通路在 π*0.6 / RECAP 扩展中被直接复用：优势条件被写成文本 token 注入，仍走语言通路，VLA 主体结构不需要新增数值条件分支。详见子页 ⑤。

4.2 逐模块拆解

下表按数据流向逐个模块列出。第四列是本节的重点——每个模块在整套系统里解决什么问题；第五列给出这样设计的理由与替代方案的代价。

模块 输入 → 输出 规模 作用 为什么这样设计
视觉编码器 SigLIP 至多四路 448 × 448 图像 → 图像 token 400M 把像素编码成可送入多模态序列的表示 SigLIP 提供图文预训练过的视觉表示；模型卡确认其输出 token 会与语言、本体状态 token 拼接，但没有公开中间投影层和维度，不能把「拼接」理解为原始 SigLIP 输出无需任何适配即可直接进入 Gemma
文本 token 化 任务指令 + 可选 metadata → 语言 token 未单独计 把「做什么」与「怎么做」都编码进序列 模型卡只写「token 化的语言 prompt」，未说明分词器细节。关键在于两者走的是同一条既有语言通路，因此 metadata 这类新条件不需要任何结构改动就能注入——这一点后来被 π*0.6 的优势条件直接复用
本体状态 token 化 机器人构型 \(q_t\) → 状态 token 未公开 让模型知道机器人此刻的姿态 token 化之后与图像、语言同处一条序列，注意力可以直接在三者之间建立关联，不需要单独的融合模块；模型卡只写 tokenized，具体方式未公开
视觉-语言主干 Gemma 3 4B 三类 token → 隐状态，并自回归产生离散输出 4B 语义理解、世界知识、高层决策 这一代相对 π0.5 的两项规模改动之一；主干承担的是「理解场景与指令、决定下一步做什么」，而不是精细运动控制
子任务文本输出头 主干隐状态 → 下一子任务文本 \(\hat{\ell}\) 主干词表 高层决策的显式载体，同时成为后续动作生成的语义条件 写成自然语言而非隐向量，使高层意图可读、可审计；论文没有说明用户是否能在运行时直接改写该文本。其生成频率低于动作生成，因此自回归开销可以跨多个动作块摊销
FAST 离散动作输出 主干隐状态 → FAST 动作 token 具体词表扩展未公开 给主干提供动作监督；论文明确说它在训练时作为 KI 配方的一部分被预测 它与连续动作在计算图上分别预测，作用与知识隔离直接相关，完整论证见子页 ②；官方没有逐项公布推理服务是否仍计算并返回这一路
动作专家 噪声动作 + 可读取的主干激活 → 速度场 860M，层数与主干相同 预测连续动作流的速度场 独立权重让连续控制表示与主干语义表示分开，并允许对两部分施加不同的反向传播规则
流匹配去噪循环 初始噪声经多步积分 → 连续动作块 模型卡的延迟口径按 5 步 用学得的速度场把噪声变成动作块 增加积分步通常会近似线性增加动作专家计算，但总延迟还包含视觉编码、主干和调度开销，不能把端到端延迟写成与步数严格成正比
连续动作输出 积分结果 → 动作块 块内样本对应 50 Hz 控制 论文实验中实际送往机器人的关节角与夹爪指令 以动作块而非单步动作输出，一次生成可覆盖多个控制周期，从而为下一次推理留出时间

★ 关于「离散动作那一路在推理时起什么作用」，官方材料只支持有限结论。

模型卡把 π0.6 概括为同时使用流匹配和 token 化离散输出；图 1 也分别画出 discretized actions 与 continuous actions。论文进一步澄清：

  • 连续动作块 \(a_{t:t+H}\) 由专门的动作专家通过流匹配产生，块内是 50 Hz 的关节角与夹爪指令；
  • FAST 动作 token 在训练时作为 KI 配方的一部分被预测；
  • 动作专家不接收 FAST 动作 token，因此连续动作不是先生成 FAST、再把 FAST 解码或细化得到；
  • 预测子任务 \(\hat{\ell}\) 位于两类动作之前，两类动作都以它作为共同条件。

因此最稳妥的表述是：FAST 是主干的离散动作训练目标，连续动作块是动作专家的流匹配输出；两者共享上游条件，但不存在 FAST → 动作专家的依赖边。论文没有逐项描述部署服务是否仍计算或返回 FAST token，所以本页不把「推理时完全不运行 FAST 分支」写成官方事实。

下面四个小节展开表中几个最容易被一句话带过的模块。

4.3 为什么视觉编码器与语言主干要分开计

官方给规格时写的是「SigLIP 400M + Gemma 3 4B」，两个数字分开列，而不是合成一个「4.4B 的 VLM」。这不是记法习惯，两者承担的职责确实不同：

  视觉编码器 SigLIP 语言主干 Gemma 3
处理对象 单帧图像 整条多模态序列
输出 该帧的图像 token 隐状态与离散输出
每次前向的调用次数 按图像路数，一路一次 一次
相机路数变化时 计算量随之线性变化 序列变长，注意力开销随之变化

这个区分在解释延迟时用得上：模型卡给的 63 ms 是按三路相机计的，换成四路时增加的不只是主干那一侧的序列长度，还有视觉编码器多跑一路的开销。相关讨论见本页第七节。

4.4 「动作专家的层数与主干相同」意味着什么

模型卡专门写了这一句。它的含义是：动作专家不是挂在主干末端的一个小头，而是一套与主干逐层对应的权重。

这正是 π0 那一代确立的双专家形态：两套权重共享同一个 Transformer 的计算结构，序列中不同区段的 token 走不同的权重。动作 token 在第 \(k\) 层用动作专家的参数，图像与文本 token 在第 \(k\) 层用主干的参数，两者在同一层内通过注意力交互。

机制本身已在 π0 · 网络架构与双专家 讲过，本页不重讲。本页只指出两点差异：其一，规模上，π0 论文给的动作专家口径是约 300M（本站 π0 专题按公开源码核算为约 311.4M，两者是论文口径与源码核算口径的差别），本代是 860M；其二，本代模型卡明确写了「层数与主干相同」这一约束，这使得逐层对应的关系是确定的。

「逐层对应」还解释了动作专家为什么能拿到各层的语义信息，而不是只拿到主干最后一层的输出——这与在主干顶端接一个动作 MLP 是完全不同的两件事。

4.5 动作专家怎么读到主干的信息

论文第五节 A 小节的表述是：动作专家是一套专门用于动作生成、以流匹配训练的独立权重，但它可以注意到模型其余部分的激活。

也就是说，动作专家不是只读取主干末层的一根汇总向量：其动作 token 可以通过注意力读取主干其余部分的激活。图中那条标着「主干激活」的箭头画的是这种跨区段的信息读取。

由此可以得到两条推论：

  • 可确认的方向是动作专家读取主干。 π0.6 材料没有单独重述反方向掩码；「主干 token 不读取动作 token」来自前两代的明确设计——π0.5 论文附录 E 写的是「没有任何 VLM embedding 注意动作专家」（见 π0.5 · 网络架构与结构差异第五节）。因此图中把反方向画成不可读，是有继承依据的结构解释，而不是 π0.6 材料的新原句。
  • 这条通路是前向的，与梯度无关。 训练时动作专家的梯度不回流主干（知识隔离），但这不妨碍前向计算照常读取主干激活。前向与反向在这里是两回事，容易混淆，完整讨论见子页 ②第四、五节。

4.6 去噪循环在整张图的哪个位置

图里的动作专家框内写着「流匹配去噪循环」，这一步在时间上是反复执行的：一次动作块生成要在动作专家内部跑若干个去噪步，每一步都要做一次动作专家的前向。

需要分清三个量：

量 连续动作去噪阶段中的次数 说明
固定图像与 prompt 编码 1 次并缓存 固定条件不随积分时间变化，可复用前缀键值
自回归离散解码 视生成 token 数而定 子任务文本以及训练或服务若需要的 FAST token 仍需逐 token 生成，不是一次前向
动作专家前向 去噪步数次 每步都要重算随噪声动作和时间变化的动作 token；模型卡延迟口径为 5 步

这个划分解释了为什么连续动作去噪不必在每个积分步重算固定视觉前缀和全部主干条件：缓存的是不随积分时间变化的条件，反复计算的是随噪声动作变化的动作专家部分。但 63 ms 是端到端测量值，官方没有给出各模块耗时占比，不能把它完全归因于缓存。

★ 这张表的来源需要说明。π0.6 的模型卡与论文都只给出「5 个去噪步、3 路相机、单张 H100 上 63 ms」这一个延迟数字，没有说明去噪循环内外各算什么。上表的固定前缀缓存依据 π0 已确立、π0.6 沿用的双专家流匹配结构——本站 π0 专题依据公开源码记录：不随积分时间变化的前缀键值可以供多个积分步复用。严格说，这是从 π0 公开实现迁移来的实现解释，不是 π0.6 材料对服务代码的逐行说明；表中因此把自回归离散解码单独列出，避免把「缓存前缀」误写成整个 4B 主干只做一次矩阵计算。

顺带一提，两代的去噪步数口径也不同：π0 专题依据源码记录的是 10 步欧拉积分，而 π0.6 模型卡给延迟时用的是 5 步。

流匹配本身的加噪插值、速度场目标与采样过程见 π0 · Flow Matching 动作生成，本页不重推。

五、序列结构与三段注意力

模型卡第 2 节给出的拼接方式是：视觉编码器输出的图像 token，与 token 化的语言 prompt、token 化的本体状态拼接成一条序列。注意力则分三段处理。

为什么图像用双向、文本用因果

这两段注意力的形式不同，原因在于两类 token 的生成方式不同。

图像 token 是一次性全部给定的，不存在先后。 一帧图像被视觉编码器切成若干 token 之后，它们描述的是同一个时刻的同一个场景，彼此之间没有因果顺序。强行施加因果掩码意味着靠前的图像 token 看不见靠后的，而「靠前靠后」只是展平顺序造成的人为次序，与内容无关。因此双向注意力是自然选择，模型卡也明确写这一点与 π0.5 相同。

要被自回归生成的文本 token 必须单向。 主干需要逐 token 地生成子任务文本 \(\hat{\ell}\) 与离散动作 token，生成第 \(k\) 个 token 时只能依赖前 \(k-1\) 个，否则训练时就会看到答案，推理时无法复现。这是自回归语言模型的基本约束。

prompt 部分是一处与前两代不同的地方。上面的理由只覆盖「要生成的」文本。输入的 prompt 是给定的，并不需要生成；在 π0 与 π0.5 中，prompt 与图像同属使用双向（完全）注意力的前缀——π0 是「图像与语言合为第一块、块内双向」（见 π0 · 网络架构与双专家第六节），π0.5 论文附录 E 写的是「对图像、prompt token 与本体状态使用完全前缀掩码」（见 π0.5 · 网络架构与结构差异第五节）。而 π0.6 模型卡写的是「文本 token 之间用因果注意力」，并用「但」字与图像 token 的双向注意力对照写出。两处材料对照，prompt 部分的注意力形式在 π0.6 发生了变化；模型卡没有说明这样改的原因，本站不作推测。

动作专家内部用双向，理由与图像同类。 一个动作块里的各个时间步是同时被生成出来的，流匹配一次输出整块，而不是逐步自回归。既然整块同时出，块内各步之间就没有必须单向的理由，双向注意力让块内各步可以互相协调。

Q/K/V、缩放点积与掩码的定义见注意力机制；token 在序列中的先后次序如何被模型感知见位置编码。

六、输出端：三路输出，两路动作

π0.6 的一个训练样本或决策周期涉及三类输出，其中两类是动作表示。它们不是由一次神经网络前向同时完成：文本与 FAST token 是自回归预测，连续动作还需要多步流匹配积分。

输出 由谁产生 形式 作用
子任务文本 \(\hat{\ell}\) 主干，自回归 自然语言短句 高层决策，为后续动作提供语义条件
FAST 离散动作 token 主干，自回归 由 FAST 分词器得到的离散 token 让主干也获得动作层面的监督（训练作用见子页 ②）
连续动作块 动作专家，流匹配 块内按 50 Hz 采样的关节角与夹爪指令 论文实验中实际下发给机器人执行的量

三者的顺序关系是确定的：先出子任务文本，动作在其之后生成。论文对此的表述是，由于动作在 \(\hat{\ell}\) 之后生成，动作生成实际上是以这个预测出的子任务为条件的，从而获得高层指引。这正是 π0.5 分层设计的延续。

一个容易被忽略的结构事实：两路动作独立预测

论文第五节 A 小节有一句话决定了这一代的结构性质：动作专家不接收 FAST 离散动作 token 作为输入，因此两种动作表示在给定共同上下文后分别预测。

这句话排除了一种很自然的猜测——「主干先用离散 token 粗略定出动作，动作专家再以 FAST token 为输入细化」。实际不是这样。两路都依赖观测、语言和先生成的子任务文本，但不存在 FAST token → 动作专家的依赖边；这里的 independent 描述计算路径，不表示两个随机变量在不加条件时统计独立。

由此可以推出两条后果：

  • 连续控制不必等待 FAST token 才能开始。 既然动作专家不依赖 FAST token，部署实现可以跳过或异步处理这一路；不过官方材料没有公开服务代码是否仍返回 FAST token，因此这是由计算图得到的工程可行性，不是对官方运行时的逐行描述。离散分支的训练作用在子页 ② 展开。
  • 这是「离散训练、连续推理」得以成立的结构前提。 上一代 π0.5 论文附录 E 对同一设计给出的理由是避免两种动作表示之间的信息泄漏（见 π0.5 · 网络架构与结构差异第五节）。它与知识隔离的梯度截断一起，构成了两路分工的完整安排，梯度落点见子页 ②。
需要和 π0-FAST 区分开。π0-FAST 是只有离散动作这一路的自回归模型，动作由 FAST token 解码得到；π0.6 是两路都有，且实际执行用的是连续那一路。把 π0.6 描述成「π0-FAST 与 π0 的合并」是不准确的，它们的离散分支承担的职责不同。

子任务预测的运行频率更低

论文明确写道，子任务预测的运行频率低于动作生成。这条看似琐碎，实际上是分层设计能够落地的工程条件：高层语义（「现在该去拿杯子了」）可以跨多个动作块保持不变；低层控制器则按 50 Hz 消耗动作块中的样本。两者解耦后，不必在每个动作块都重新生成完整子任务文本，自回归文本解码的开销可以摊薄。

七、推理耗时：63 ms 与它的前提

模型卡给出了一个明确的延迟数字：在 5 个去噪步、3 路相机输入的条件下，单张 H100 GPU 上产出一个动作块需要 63 ms。

这个数字必须连同前提一起引用，因为三个前提每一个都直接影响它：

前提 取值 改变它会怎样
去噪步数 5 流匹配积分次数；通常近似线性增加动作专家计算，但端到端耗时还含固定开销
相机路数 3 图像 token 数随之变化，影响视觉编码与序列长度；增加一路通常会增加计算量
硬件 单张 H100 换用其他加速卡时不宜简单按算力线性折算

把 63 ms 与块内 50 Hz 采样率放在一起，可做一个只用于容量估算的换算：机器人每 20 ms 消耗一个动作样本，63 ms 对应 \(63/20=3.15\) 个采样间隔。离散样本数必须取整数，因此在忽略通信、排队和控制安全裕量的理想流水线里，至少要预留 4 个动作样本的覆盖时间，下一块才可能在当前缓冲耗尽前生成。实际系统还要留裕量，所需缓冲通常会更长；论文未公开动作块长度 \(H\) 与调度策略，本页不据此反推它们。

这正是动作块这一设计的主要用意之一——用一次推理换取一段时间的动作供给，从而容忍推理延迟。该机制本身见 π0 专题；若要了解动作块在执行期如何与实时控制对接，见 π0 专题关于时间方向约定与推理期现象的子页。

九、本页留下的问题

本页只回答了「结构长什么样」，三个与结构直接相关但属于训练范畴的问题留给下一页：

  1. 三路输出各自对应什么损失项，它们怎么加起来。
