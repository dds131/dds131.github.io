DQN 枢纽页 讲的是为什么需要经验回放与目标网络。本页讲的是另一件事：这套算法在 Atari 上到底是怎么落地的——像素怎么变成网络输入、网络长什么样、哪些地方做了看似不起眼却关乎成败的工程处理。

这些细节容易被当作「实现琐事」略过，但其中至少有一条被广泛混淆（两种裁剪），还有一条是 2013 与 2015 两版之间的实质差别。

84 × 84 × 4网络输入的确切形状
3 + 1三层卷积加一层全连接
5000 万帧Nature 版训练量，约 38 天游戏经验
4 – 18各游戏的有效动作数范围
16 项已完整转写的超参数
本页重点。必须精读的是两节：「两种裁剪」——奖励裁剪与误差裁剪是两件不同的事，后者等价于对区间外的误差使用绝对值损失（也就是今天常说的 Huber 损失），二者常被混为一谈；「两版对照」——2013 版与 2015 Nature 版网络容量、预处理方式、跳帧规则都不同，引用「DQN 的网络结构」时必须说清是哪一版。

本页另完整转写了 Nature 论文的 Extended Data Table 1（16 项超参的取值与逐条释义），它是复现 Nature 版 DQN 的完整口径，见「完整超参表」一节。

原始输入有多难处理

Atari 2600 的原始帧是 210 × 160 像素、128 色调色板的图像。直接拿它训练，在计算与内存两方面都很吃力。所以第一步是降维——但 Nature 版的预处理不只是降维，它还要处理模拟器本身的一个伪影。

预处理管线

四个步骤各司其职：取最大解决闪烁，取 Y 通道把三通道彩色压成单通道亮度，缩放降维，堆叠补回时间信息。注意第二步与第三步的顺序——先在彩色帧之间取最大，再提取亮度。

为什么要「与前一帧逐像素取最大」

这一步是 Nature 版特有的，理由与画质无关：

在一些游戏里，有的物体只在偶数帧出现，另一些只在奇数帧出现——这是 Atari 2600 一次能显示的精灵数量有限所造成的伪影。若只取单帧，画面上会出现闪烁，某些物体会周期性消失。

把当前帧与前一帧逐像素取最大值，两拨交替出现的物体就同时留在了同一张图上。这是一个针对硬件限制的补丁，而不是一个针对学习算法的技巧。

为什么堆叠四帧

单张静止画面能告诉网络球在哪里，却告诉不了球往哪儿飞。把最近 \(m\) 帧堆起来，网络才能从相邻帧的位移中间接读出速度与方向这类短期运动信息。

论文取 \(m = 4\)，并补了一句：算法对不同的 \(m\) 值是鲁棒的，例如取 3 或 5 也可以。

网络结构

一个先于结构的设计决定

论文先讨论了怎么把 \(Q\) 参数化。由于 \(Q\) 把「历史-动作」对映射成标量，一种自然做法是把历史和动作都作为网络输入。论文指出它的主要缺点：

这样每个动作都需要单独一次前向，代价随动作数线性增长。

因此 DQN 采用的是另一种：只把状态表示作为输入，每个可能动作对应一个独立的输出单元。好处是一次前向就能算出给定状态下所有动作的 Q 值。

Nature 版的确切配置

层 配置
输入 \(84 \times 84 \times 4\)
卷积 1 32 个 \(8 \times 8\) 滤波器，步长 4，ReLU
卷积 2 64 个 \(4 \times 4\) 滤波器，步长 2，ReLU
卷积 3 64 个 \(3 \times 3\) 滤波器，步长 1，ReLU
全连接 512 个 rectifier 单元
输出 全连接线性层，每个有效动作一个输出

论文注明：所考虑的游戏中，有效动作数介于 4 到 18 之间。

目标网络与经验回放各自解决什么，见 DQN 枢纽页，本页不重复。

两种裁剪，不是一回事

这是本页最需要讲清的一节。DQN 里有两处都叫「裁剪」的操作，作用对象完全不同。

其一：奖励裁剪

只在训练时改变奖励结构（评估时用的是未修改的游戏）：

把所有正奖励裁剪为 1、所有负奖励裁剪为 −1，0 保持不变。

理由：各游戏的分数量级差异极大，这样做限制了误差导数的尺度，使得在多个游戏上使用同一个学习率更容易。

代价（论文自己点明）：智能体无法区分不同量级的奖励。

有一个直接后果常被忽略：因为奖励被裁剪，训练曲线上的 Q 值也是被缩放过的。论文在训练曲线的图注里专门说明了这一点。因此读 DQN 的平均 Q 值曲线时，纵轴的绝对数值不能直接对应到游戏原始分数。

其二：误差裁剪

这一条作用在损失上，与奖励无关：

论文发现，把更新式中的误差项 \(r + \gamma \max_{a'} Q(s', a'; \theta^{-}) - Q(s, a; \theta)\) 裁剪到 \([-1, 1]\) 之间是有帮助的。

论文紧接着解释了它的等价形式：

由于绝对值损失 \(\lvert x \rvert\) 对所有负的 \(x\) 导数为 \(-1\)、对所有正的 \(x\) 导数为 \(+1\)，把平方误差裁剪到 \([-1,1]\) 之间，等价于对落在 \((-1,1)\) 区间之外的误差使用绝对值损失。论文说这种形式的误差裁剪进一步改善了算法的稳定性。

这正是今天常说的 Huber 损失在 DQN 中的由来——在原点附近是平方的、在远处是线性的。论文本身没有使用「Huber」这个词，而是从导数的角度直接描述了它。

名称 作用对象 做什么 目的
奖励裁剪 环境给出的奖励 正奖励取 1、负奖励取 −1、0 不变 统一各游戏的分数量级，便于共用学习率
误差裁剪 TD 误差项 裁到 \([-1,1]\)，区间外转为线性损失 限制大误差的梯度，进一步提升稳定性

跳帧

智能体每 \(k\) 帧才看一次画面并选一次动作，被跳过的帧上重复上一个动作。

理由：让模拟器前进一步的计算量，远小于让智能体选一次动作。因此这个技巧使智能体能多玩大约 \(k\) 倍的游戏而不显著增加运行时间。

Nature 版对所有游戏取 \(k = 4\)；2013 版则是除 Space Invaders 外取 \(k = 4\)。

训练与评测的口径

训练

项目 Nature 版取值
优化器 RMSProp，小批量大小 32
行为策略 \(\varepsilon\)-贪心
\(\varepsilon\) 调度 前 100 万帧从 1.0 线性退火到 0.1，之后固定 0.1
训练总量 5000 万帧（约 38 天游戏经验）
回放池 最近 100 万帧
回合终止 有生命计数的游戏，用剩余生命数在训练时标记回合结束

评测

训练好的智能体在每个游戏上玩 30 次，每次最多 5 分钟，使用不同的初始随机条件（即 no-op 起始），并采用 \(\varepsilon = 0.05\) 的 \(\varepsilon\)-贪心策略。

论文说明这样做是为了尽量减少评估阶段过拟合的可能性。

随机智能体作为基线，以 10 Hz（即每 6 帧）选一次随机动作，中间帧重复上一动作。论文给的理由很具体：10 Hz 大约是人类玩家能够按下 fire 键的最快速度，把随机基线设成这个频率可以避免虚假的比较结果。

min squared gradient 0.01 加在 RMSProp 更新分母的平方梯度上的常数
initial exploration 1 \(\varepsilon\)-贪心里 \(\varepsilon\) 的初值
final exploration 0.1 \(\varepsilon\)-贪心里 \(\varepsilon\) 的终值
final exploration frame 1000000 \(\varepsilon\) 由初值线性退火到终值所跨越的帧数
replay start size 50000 学习开始前先以均匀随机策略跑这么多帧，用产生的经验填充回放池
no-op max 30 回合开始时智能体最多执行多少个「什么都不做」动作

三处最容易被忽略、却直接影响复现的地方：

  • action repeat 与 update frequency 是两个不同的 4，容易被当成同一件事。前者是「一个动作重复几帧」（跳帧），后者是「选几个动作做一次梯度更新」。两者相乘意味着每 16 个原始模拟器帧做一次参数更新。后者也正是 replay ratio 的来源：每 4 个动作一次更新即 0.25，这个量与回放容量正交，见反常现象诊断。
  • target network update frequency 的单位是参数更新次数，不是环境步、也不是帧。 这一条表里写得很明确（「measured in the number of parameter updates」），但转述时极易漂移成「每一万帧」。
  • replay start size = 50000 与 replay memory size = 1000000 不是一回事。 前者是「开始学习前先用随机策略铺多少数据」，后者是池子容量。两者相差二十倍，混用会让前期行为完全不同。

★ 还有一处比上面三条更隐蔽：「帧」在 DQN 的文献里有两种含义，混用会把更新次数算错好几倍。

本表里 action repeat 说的是原始模拟器帧——Atari 2600 以 60 Hz 输出画面（这一点见 2013 版论文对 ALE 的描述：「210 × 160 RGB video at 60Hz」）。

但训练规模那句「5000 万帧（约 38 天游戏经验）」里的「帧」不是原始帧，而是智能体步（跳帧后的决策步）。用论文自己给的「38 天」就能反推出来：
· 若 5000 万是原始帧：\(5\times10^{7} \div 60\,\text{Hz} \approx 9.6\) 天，与论文对不上；
· 若 5000 万是智能体步：\(5\times10^{7}\times4 = 2\times10^{8}\) 原始帧，\(\div\,60\,\text{Hz} \approx 38.6\) 天，与论文吻合。

因此「5000 万 ÷ 16」不是参数更新次数。正确的算法是：5000 万智能体步 \(\div\) update frequency 4 \(=\) 1250 万次参数更新；再 \(\div\) target network update frequency 10000 \(\approx\) 1250 次目标网络同步。引用「DQN 训练了多少帧」时，务必先确认对方说的是哪一种帧。

这张表的取数方式要说明，因为它与本页其余内容不同。该表在 PDF 里是位图而非文本层，pdftotext 取不到任何表内数值——这也是本页此前长期声明「不转写表内数值」的原因。本轮改用把该页渲染成图像通读的方式取数，并做了三次独立读取——300 dpi 彩色整表、450 dpi 放大「名称 + 数值」两列与表尾、600 dpi 灰度且换一处裁剪边界——三次逐值一致才写入本页。

此外，表中 16 个值里有 12 个能与其他已独立核实的材料互相印证，分四类：

① 见于 Nature 正文（8 项）：minibatch 32、replay memory 1000000、agent history 4、\(\gamma\) 0.99、action repeat 4、初值 1、终值 0.1、退火 1000000 帧。
② 与 Double DQN 论文吻合（1 项）：target network update frequency 10000——该文调参版「把目标网络拷贝间隔从 10,000 提到 30,000」。
③ 与 Rainbow 论文吻合（1 项）：learning rate 0.00025——「DQN uses a learning rate of α = 0.00025」。
④ 与 Fedus 等吻合（1 项）：update frequency 4——「每 4 个环境步更新一次，replay ratio 为 0.25」。
⑤ 与 Dueling 论文吻合（1 项）：no-op max 30——「we start the game with up to 30 no-op actions」。

★ no-op max 这一项要特别说明，它极易被错记成「见于 Nature 正文」。Nature 正文里确实有一个 30，但那是评测的回合数（「playing each game 30 times for up to 5 min each time」），不是 no-op 的上限；而且正文在提到 noop 时明确把该项推给了本表（「with different initial random conditions (‘noop’; see Extended Data Table 1)」）。因此 Nature 正文不构成这一项的独立佐证，真正的旁证来自 Dueling 论文。

其余 4 项（gradient momentum、squared gradient momentum、min squared gradient、replay start size）只有图像这一个来源，本页如实标注这一点。

论文自己的诚实说明

超参是怎么选的

Extended Data Table 1 的说明写道：所有超参数的取值是通过在 Pong、Breakout、Seaquest、Space Invaders、Beam Rider 这几个游戏上做非正式搜索选定的，由于计算成本高昂没有做系统的网格搜索，「尽管可以想见，通过系统地调节超参数取值有可能得到更好的结果」。

正文 Methods 的 Training details 一段有几乎相同的一句，但结尾不同——那里说的是这些取值随后被固定用于其余全部游戏，并未提「系统调参可能更好」。两处都在，引用时按需取用即可；上面那句自我保留只出现在表的说明里。

换句话说，这套被后来无数工作沿用的超参，本身并不是被穷尽优化过的，而且论文自己就把这一点写在了超参表底下。

论文自己做了消融

Extended Data Table 3 报告了经验回放与独立目标网络的效果：智能体在开关回放、用不用独立目标网络的全部组合下，配合三种不同学习率，各训练 1000 万帧；每 25 万训练帧评估一次，每次评估 13.5 万验证帧，报告最高平均回合分数。

注意口径差异：这组消融用的是 1000 万帧，而主结果（Extended Data Table 2）用的是 5000 万帧。

小结与出口

  • 预处理四步：两帧取最大（消除精灵闪烁）→ 取 Y 亮度通道 → 缩放到 84×84 → 堆叠 4 帧。堆叠是为了补回运动方向这一单帧无法提供的信息。
  • 网络是三层卷积加一层 512 全连接，每个动作一个输出单元——这样一次前向就能得到所有动作的 Q 值。
  • 2013 版与 2015 版不同：卷积从两层变三层、通道数翻倍、全连接 256 变 512、预处理由「裁剪」改为「取最大加缩放」、跳帧取消了 Space Invaders 的例外、并新增了目标网络。
  • 两种裁剪要分清：奖励裁剪统一分数量级（代价是分不出奖励大小，且使 Q 值被缩放）；误差裁剪等价于对大误差使用绝对值损失，也就是 Huber 损失。
  • 完整超参表已转写（Extended Data Table 1，16 项）。其中三处最易错：action repeat 与 update frequency 是两个不同的 4；target network update frequency = 10000 的单位是参数更新次数；replay start size = 50000 与 replay memory size = 1000000 不是一回事。
  • 超参来自在 5 个游戏上的非正式搜索，论文明说未做系统网格搜索。
