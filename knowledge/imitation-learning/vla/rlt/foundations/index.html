RLT 不是让 VLA 重新学会任务，而是让它在已有能力附近更快、更准

它把“通用感知与初始行为”留给冻结 VLA，把“关键阶段的局部策略改进”交给小型在线 RL。理解这条职责分界，才能避免把 RLT 误解成 Action Token、全模型 RL，或普通 residual policy。

一、为什么“会做”仍然不够

行为克隆型 VLA 学习的是示范分布。若人类示范在接触前经常减速、停顿、后退再试，最大似然训练会把这些动作也视为正常目标。模型可以完成任务，却可能在最关键的数毫米内反复试探；而精密装配的成功又常由这一小段决定。

RLT 原论文选择的四项任务正好暴露这种差距：拧 M3 螺丝、扎带穿孔、Ethernet 插入和充电器插入。它们的前段——抓取、移动、粗定位——适合由大 VLA 完成；后段则涉及接触、摩擦、顺应性和亚毫米级误差，单靠离线示范难以覆盖。

\[\underbrace{\text{大范围任务知识}}_{\text{VLA 已经擅长}} \quad+\quad \underbrace{\text{接触阶段局部最优行为}}_{\text{在线 RL 继续发现}}\]

强化学习的价值不只是“纠错”。它优化回报而非模仿相似度，因此可能发现示范中没有的、更快或更稳的动作序列。

二、三个直接方案为何都不完整

方案 保留 VLA 先验 改进阶段更新规模 对真机小数据的适配性 主要问题
对完整 VLA 做在线 RL 是 十亿级或更大 更新和采样代价较高 小数据下还要处理稳定性与遗忘风险
从头训练小型视觉 RL 策略 否或很弱 小 更新轻，但要重新学状态表征 没有直接利用 VLA 的任务与行为先验
只继续监督微调 VLA 是 大 依赖持续获得高质量动作标签 训练目标仍是复现标签，没有显式优化任务回报
RLT 是 小型 actor + critic 复用冻结表征与 replay 需要 Stage 1 接口、人工奖励/介入与系统集成

RLT 不是在四项方案中“折中取平均”，而是重新划分计算图：VLA 负责产生稳定的任务表征和参考动作，在线 RL 只训练能读取该接口的小网络。

flowchart LR
  O["图像 · 语言 · proprio"] --> V["冻结 VLA"]
  V --> K["通用任务知识"]
  V --> Z["RL token<br/>紧凑状态"]
  V --> R["reference chunk<br/>行为先验"]
  Z --> A["小型 Actor-Critic"]
  R --> A
  A --> L["关键阶段局部改进"]

三、为什么不能随便抽一层 embedding 给 RL

Transformer VLA 的内部表示既有许多 token，也有很高维度；不同层混合的视觉、语言和动作信息也不同。直接把整段 embedding 展平给小型 critic 会带来三类问题：

  1. 维度与样本规模不匹配。 真机只有分钟到小时级数据，critic 很难在高维状态上可靠拟合价值。
  2. 信息选择没有监督。 任意池化可能保留表面视觉差异，却丢失接触阶段需要的任务结构。
  3. 在线计算与更新耦合。 若为了价值学习同时调整大 VLA，代价又回到全模型 RL。

RLT 用 encoder-decoder 重建目标训练一个专门的读出接口：单个 $z_{\mathrm{rl}}$ 必须支持重建 VLA token embedding。它因此成为一个学习到的信息瓶颈，而非手工选择的层或普通 ImageNet 特征。

谨慎表述：重建目标鼓励 $z_{rl}$ 保留 VLA 内部信息，但并不从理论上保证它是环境的 Markov 充分状态。部分可观测、相机遮挡或接触力缺失仍可能限制 critic。

完整结构见RL Token 表征页。

四、RLT 的职责分工

VLA

编码图像、语言与机器人状态，提供任务相关 hidden states，并生成可执行的参考动作块。

RL-token 模块

把高维 token 序列压成紧凑状态。Stage 1 学习，Stage 2 冻结。

Actor

同时读取 $z_{rl}$、proprio 与 reference，输出改进后的动作块分布。

Twin Critic

估计状态—动作块价值，用 replay 的 chunk transition 训练。

Replay Buffer

复用 VLA warmup、RL rollout 与人工纠正数据，支撑高 UTD 更新。

Human Supervisor

给终局奖励、必要时接管，并标记关键阶段切换；不应被省略成“全自主”。

五、六项设计形成一条因果链

下面把论文中的核心创新拆成六项相互依赖的设计选择，而不是声称论文正式提出了“六个彼此独立的创新”。其中 RL token、动作块、BC 正则和 reference pass-through 是论文消融直接检验的四个组件；冻结接口与 reference dropout 则是使这套训练机制可用的重要配套设计。

1. 学习一个 RL 接口

问题是 VLA 内部表示不适合直接做低数据在线 RL；解法是训练 $z_{rl}$，把大模型知识转成小网络可消费的状态。

2. 在线阶段冻结大模型

固定 VLA 与 RL-token encoder，避免少量在线数据改写 Stage 1 表征；在线更新只落在 actor 与 critic 上。这里的“避免破坏”是设计动机，不是对灾难性遗忘的形式化保证。

3. 在 action chunk 上做价值学习

若机器人以 50 Hz 控制，单步策略需要跨数百步传播稀疏成功信号。RLT 把 $C$ 个底层动作当作一个决策，显著缩短有效时域。

4. 把 VLA 动作直接传给 actor

Actor 不必从全动作空间猜测一个合理起点，而是看到“VLA 当前建议”，再决定保持还是修改。

5. 用 BC 正则限制搜索区域

小数据 critic 可能对 replay 分布之外的动作产生不可靠估值。$\beta|a-\tilde a|^2$ 把 actor 拉回 VLA reference 邻域，缩小搜索范围；“缓解价值外推误差”是这项正则的合理机制解释，而不是论文给出的误差上界。

6. 用 dropout 防止过度依赖先验

只靠 pass-through 与 BC，actor 可能学成复制器。训练时随机遮蔽 reference，迫使网络保留独立生成能力；当 critic 变得有信息后，actor 才能在有收益时主动偏离参考。

这条链中，BC anchor 与 dropout 看似相反：一个要求靠近，一个要求不要依赖。它们实际解决不同问题——前者限制输出搜索半径，后者避免输入通路退化。

六、与相邻方法的严格边界

方法 在线阶段更新什么 动作层级 如何利用 VLA 与 RLT 的关键差别
RECAP / π0.6* 以离线 RL 目标迭代重训完整 VLA 原生 action chunk VLA 本身就是待改进策略 RLT 在线阶段冻结 VLA，只训练小网络
PPO 类 VLA RL 大模型策略参数 依实现 直接对 VLA 分布做策略优化 RLT 使用 off-policy replay，更新规模更小
HIL-SERL 小 actor-critic 典型为单步 通常不用 VLA hidden/reference RLT 将 VLA 同时作为表征器和行为先验
PLD 冻结 VLA 上的 residual policy 单步 residual 把修正量加到基座动作 RLT actor 对完整 reference chunk 条件化，不要求固定 residual 形式
DSRL latent/noise policy VLA 生成空间 选择扩散噪声以 steering VLA RLT 直接在 action chunk 上做显式 actor-critic
DAgger 监督微调策略 依基座 聚合专家/介入标签 目标是复现纠正动作，没有直接优化回报或速度

RLT 与这些方法并非简单优劣关系。强约束 latent steering 往往更稳定，却可能限制超越 VLA 的幅度；全模型 RL 表达力更强，但需要更多算力与数据；RLT 选择的是“在冻结 VLA 附近进行高效、显式的动作块价值优化”。

七、三个常见误解

RL Token ≠ Action Token。Action Token 表示要执行什么动作；RL token 是从 VLA hidden states 压缩出的状态表示，用于 actor 与 critic 的输入。
局部改进 ≠ 固定残差相加。论文 actor 直接输出动作块高斯分布，并把 reference 作为条件与正则中心；显式 residual 只是某些实现可以采用的参数化。
轻量 Actor-Critic ≠ 标准 SAC。论文采用 TD3 风格 target 与 twin critic，并以 BC 正则为核心；RLinf 当前 `rlt_ac` 文档也明确说明它不是标准 maximum-entropy SAC。

八、适用前提与局限

RLT 最适合“基座已会大部分任务，只需改进关键阶段”的场景。若 VLA 无法识别目标、连粗定位都做不到，局部动作改进不足以弥补根本能力缺失；若奖励不能可靠反映成功，critic 也不会自动得到正确方向。

还需满足：Stage 1 数据覆盖任务中有代表性的状态与行为；在线系统能稳定生成 reference 与 $z_{rl}$；动作、状态与奖励严格时间对齐；存在人工或自动安全边界。论文实验中每个任务使用固定语言指令，因此 Stage 1 重建时省略了语言 embedding；这不等于方法原则上不支持语言条件。RLT 降低了探索范围，但不是形式化安全算法。
