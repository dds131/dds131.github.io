DexGraspVLA 把语义规划与低层控制分开：规划器把语言目标转成目标物体掩码，控制器不再接收语言，而是根据头部 RGB、腕部 RGB、目标掩码和 13 维关节状态生成动作块。本页只分析主抓取配置的控制器，并把论文结论、源码事实和合理解释分开。

37 × 37 = 1369每幅图的 patch token 数
2739 × 1024观测条件序列
2740 × 1024加入扩散步后的条件序列
64 × 13输入/输出动作块形状
12 层 / 8 头动作扩散 Transformer
约 163M论文报告的可训练参数量
本页形状对应论文的灵巧抓取主配置。论文的非抓取式扩展实验使用不同设置：两路视觉编码器均为 ViT-B/14、动作时域为 100、可训练参数约 106M，不能与本页数字混用。

一、先明确模型边界

论文将低层策略写成

\[\pi_\theta\!\left(\mathbf A_t \mid \mathbf I_t^{\mathrm h},\mathbf I_t^{\mathrm w}, \mathbf m_t,\mathbf s_t\right), \qquad \mathbf A_t\in\mathbb R^{64\times13}.\]

其中：

输入 含义 论文/配置中的形状
\(\mathbf I_t^{\mathrm h}\) 头部相机第三视角 RGB 原始相机帧记为 \(640\times480\times3\)；模型输入为 \(3\times518\times518\)
\(\mathbf I_t^{\mathrm w}\) 腕部相机第一视角 RGB 同上
\(\mathbf m_t\) 目标物体二值掩码 原始掩码记为 \(640\times480\times1\)；模型输入为 \(1\times518\times518\)
\(\mathbf s_t\) 机器人本体状态 13 维：7 个机械臂关节角与 6 个手部关节角
\(\mathbf A_t\) 目标关节位置动作块 64 步，每步 13 维

配置把头部 RGB 与掩码打包为四通道 rgbm，编码时再拆成前三个颜色通道和最后一个掩码通道。这样做的直接作用是维持二者在数据管线中的像素对齐；它并不表示掩码被当成普通颜色通道送入 DINOv2。

1.1 “单帧观测”不等于整个系统没有记忆

官方配置为 n_obs_steps: 1，且注明当前不支持多帧观测。因此，低层神经控制器每次只显式编码当前时刻的一组观测，没有把历史图像或历史状态堆叠成输入。

但不能据此把整个 DexGraspVLA 系统称为“严格无记忆”：

  • 目标掩码由 Cutie 进行视频目标跟踪，跟踪器本身利用时间信息；
  • 上层规划器保存初始图像、任务目标与执行阶段；
  • 部署采用滚动时域控制，过去动作会通过当前机器人状态与新图像间接影响下一次预测。

准确说法是：控制器网络的显式观测窗口为一帧；系统级状态并不只由这一帧决定。

二、从四路输入到 2739 个观测 token

分支 编码与融合 输出
头部 RGB 冻结 DINOv2 ViT-B/14 \(1369\times768\)
目标掩码 可训练 patch embed + 4 层 Transformer \(1369\times768\)
头部融合 同位置 token 沿特征维拼接，再经 head_net \(1369\times1024\)
腕部 RGB 冻结 DINOv2 ViT-L/14，再经 wrist_net \(1369\times1024\)
关节状态 state_net \(1\times1024\)
总观测 三路沿 token 维拼接 \(2739\times1024\)

2.1 为什么每幅图是 1369 个 token

两路 RGB 和掩码最终都按 \(14\times14\) 的 patch 网格组织。输入边长为 518，因而

\[518/14=37,\qquad 37\times37=1369.\]

这说明 518 与 patch size 14 精确整除；论文与源码没有进一步证明“为什么必须选 518”。因此不应把“接近 512”或其他经验性说法写成作者动机。

两路 DINOv2 均被冻结并置于评估模式，前向还位于 torch.no_grad() 中。源码调用 get_intermediate_layers(n=1)[0]，得到最后一个所取中间层的 patch token，不使用单个全局 CLS token。冻结模型仍然占用模型参数和推理计算，但不计入可训练参数。

2.2 头部 RGB 与目标掩码：先对齐 patch，再融合通道

主配置中：

  • 头部 RGB 使用 DINOv2 ViT-B/14，输出 \(1369\times768\)；
  • 掩码使用随机初始化、可训练的掩码编码器，输出同样为 \(1369\times768\)；
  • 对应位置的 RGB token 与掩码 token 沿最后一维拼接，得到 \(1369\times1536\)；
  • head_net 再把每个融合 token 投影为 1024 维。

可写为

\[\mathbf z_i^{\mathrm{hm}} = \operatorname{HeadMLP} \!\left( \left[ \mathbf z_i^{\mathrm h}; \mathbf z_i^{\mathrm m} \right] \right) \in\mathbb R^{1024}, \quad i=1,\ldots,1369.\]

这里的重点是同一 patch 位置的特征融合。它保留了 RGB 与掩码的一一对应关系。说它“必然优于交叉注意力”或“消除了所有对齐学习”都超出了论文证据；论文没有提供对应消融。

2.3 掩码编码器的确切结构

公开源码中的掩码分支为：

  1. Conv2d(1, 768, kernel_size=14, stride=14)；
  2. 展平并转为 \(B\times1369\times768\)；
  3. LayerNorm(768)；
  4. 4 层 TransformerEncoderLayer，每层 8 头、FFN 维度 3072、GELU、pre-norm、dropout 为 0。
“4 层是因为二值图信息简单”“dropout 为 0 是为了防止定位损失”都只是事后猜测，论文和源码没有给出这些因果解释。可以确认的只有结构本身以及该分支参与训练。

2.4 腕部与状态分支

腕部 RGB 使用冻结的 DINOv2 ViT-L/14，输出 \(1369\times1024\)，随后通过同维度的 wrist_net。头部用 ViT-B/14、腕部用 ViT-L/14 的组合来自论文所说的初步模型选择；论文没有给出理论论证，因此不应把“腕部需要更精细几何”等直觉写成已验证原因。

状态分支为

\[13 \xrightarrow{\text{Linear}} 256 \xrightarrow{\text{LN+GELU+Dropout}} 1024 \xrightarrow{\text{LN}},\]

最终形成 1 个状态 token。token 数量少并不意味着它必然被视觉信息“淹没”：注意力对 token 加权，信息影响不能由 token 数量直接推断。

2.5 三路拼接

三路投影后沿 token 维拼接：

\[\tilde{\mathbf z}^{\mathrm{obs}}_t = \left[ \mathbf z_t^{\mathrm{hm}}; \mathbf z_t^{\mathrm w}; \mathbf z_t^{\mathrm s} \right] \in\mathbb R^{(1369+1369+1)\times1024} = \mathbb R^{2739\times1024}.\]

应区分两次“拼接”：

  • 头部 RGB 与掩码：同一位置，沿特征维拼接；
  • 头部、腕部与状态：不同观测来源，沿 token 维拼接。

2.6 图像预处理的工程边界

两路 RGB 在送入 DINOv2 前都会：

  • 从 BGR 调整为 RGB；
  • 训练期应用 ColorJitter：亮度、对比度、饱和度 0.3，色调 0.1；
  • 使用 ImageNet 均值和标准差归一化。

BGR→RGB 是公开代码根据真机输入约定执行的通道重排；如果自己的数据已经是 RGB，不能无条件再交换一次。ColorJitter 是论文所述的训练期域随机化，但其单独贡献没有被独立消融，不能声称它必然带来某一项泛化提升。

三、条件序列与动作 token

3.1 扩散时间步作为条件 token

扩散步 \(k\) 先经过 256 维正弦编码，再通过两层 MLP 映射到 1024 维：

\[\tilde{\mathbf z}^{\mathrm d}_k\in\mathbb R^{1\times1024}.\]

它被追加到观测序列末尾：

\[\tilde{\mathbf z}_t = \left[ \tilde{\mathbf z}^{\mathrm{obs}}_t; \tilde{\mathbf z}^{\mathrm d}_k \right] \in\mathbb R^{2740\times1024}.\]

随后加上形状为 \(1\times2740\times1024\) 的可学习条件位置编码。扩散步不是直接加到每个动作 token 上，也不是通过经典 DiT 的 adaLN 调制注入。

3.2 动作侧

加噪动作块为 \(\mathbf x_k\in\mathbb R^{64\times13}\)。线性层 Linear(13,1024) 将其升维，再加形状为 \(1\times64\times1024\) 的可学习动作位置编码：

\[\mathbf X^{(0)} = \operatorname{Linear}(\mathbf x_k)+\mathbf P_{\mathrm a} \in\mathbb R^{64\times1024}.\]

两套位置编码都是可学习参数。它们为固定长度的动作位置和条件位置提供区分，但网页不应进一步声称它们已经学成了特定“抓取阶段”，除非有专门分析支持。

四、12 层 RDTBlock 如何更新动作序列

每个 block 都只更新 64 个动作 token；2740 个条件 token 作为交叉注意力的键和值。省略 dropout 后，第 \(\ell\) 层可写为

\[\begin{aligned} \mathbf U^{(\ell)} &= \mathbf X^{(\ell)} + \operatorname{SelfAttn}\!\left( \operatorname{RMSNorm}(\mathbf X^{(\ell)}) \right),\\ \mathbf V^{(\ell)} &= \mathbf U^{(\ell)} + \operatorname{CrossAttn}\!\left( \operatorname{RMSNorm}(\mathbf U^{(\ell)}), \tilde{\mathbf z}_t \right),\\ \mathbf X^{(\ell+1)} &= \mathbf V^{(\ell)} + \operatorname{MLP}\!\left( \operatorname{RMSNorm}(\mathbf V^{(\ell)}) \right). \end{aligned}\]
子层 查询（Q） 键/值（K/V） 可确认的作用
双向自注意力 动作 token 动作 token 允许 64 个动作位置联合交互，不使用因果掩码
交叉注意力 动作 token 条件 token 将两路视觉、目标掩码、状态和扩散步引入动作表示
MLP 每个动作 token — 逐 token 非线性变换

双向注意力与整块扩散生成相容，因为 64 步不是自回归地逐步输出。它允许跨时间位置协调，但不能仅凭结构就说它“保证轨迹连贯”或是连贯性的唯一来源。

4.1 Cross-attention 与经典 adaLN-Zero 的区别

原始 DiT 常把全局条件转换为归一化层的缩放、偏移和门控参数。DexGraspVLA 的公开实现保留 2740 个条件 token，并在每层使用 cross-attention。这样可以直接让动作查询访问各空间 patch，代价是每层都要计算一次长序列交叉注意力。

这是实现差异，不是二选一的理论定理：adaLN 可以与其他空间条件通路组合，cross-attention 也不自动保证利用到正确区域。论文没有做“cross-attention 对 adaLN”的隔离消融，因此适合写成架构选择及其计算后果，而非“唯一可行方案”。

4.2 RMSNorm：实现事实与证据边界

源码参考 RDT，以 RMSNorm 代替 block 和输出端的 LayerNorm，并在 Q/K 上启用 RMS 归一化。忽略数值稳定项和可学习权重时：

\[\operatorname{RMSNorm}(\mathbf x) = \gamma\odot \frac{\mathbf x} {\sqrt{\frac1d\sum_{i=1}^d x_i^2+\varepsilon}}.\]

与 LayerNorm 相比，它不减去特征均值。源码注释给出的理由是：中心化可能造成 token/attention shift，并影响时间序列的对称性。这个表述源自所参考的 RDT 设计，DexGraspVLA 论文没有针对 RMSNorm 做消融，也没有给出严格数学证明。

因此应避免三种过度结论：

  • 不能说 LayerNorm 一定会破坏动作时序；
  • 不能说 RMSNorm 完全“保持方向”，因为逐维可学习权重 \(\gamma\) 仍可能改变方向；
  • 不能把这一实现注释升级为对所有动作模型普遍成立的设计原则。

4.3 FFN 只有 1 倍宽

公开实现的 MLP 为 \(1024\rightarrow1024\rightarrow1024\)，而不是常见的 4 倍中间维度。源码与论文都未解释原因。其可计算后果是：相较 \(1024\rightarrow4096\rightarrow1024\)，12 层合计约少 75.5M 参数。可以讨论这一参数影响，但不能反推作者一定是为了“把预算让给注意力”。

4.4 可选的模态掩码默认关闭

CrossAttention 实现了四种训练期条件掩码，抽样概率为 \([0.1,0.1,0.1,0.7]\)：

模式 被屏蔽的条件 token 概率
0 头部段 1369 个 token 0.1
1 腕部段 1369 个 token 0.1
2 头部与腕部两段共 2738 个 token 0.1
3 不屏蔽 0.7

状态 token 与扩散步 token 不在上述屏蔽范围内。还需注意：

  • 只有 use_attn_mask=True 且处于训练模式时才启用；
  • 官方主配置为 use_attn_mask: False，所以不能把它描述为论文结果所依赖的训练技巧；
  • 代码在每次 CrossAttention 调用中抽取一个掩码索引，同一次调用的整个 batch 共享该模式；12 层会各自抽样，并非每个样本独立抽样。

4.5 输出是什么

12 层之后，动作表示经过最终 RMSNorm 与 Linear(1024,13)，输出

\[\hat{\boldsymbol\epsilon}_\theta \in\mathbb R^{64\times13}.\]

主配置的预测类型为 epsilon，所以这里预测的是加入动作块的噪声，而不是最终动作本身。训练损失与 DDIM 采样过程见③ 扩散建模与 Immiscible Diffusion.

五、完整张量追踪

以下省略 batch 维 \(B\)，并按配置 \(T_{\mathrm{obs}}=1\)：

阶段 操作 输出形状
头部输入 从 rgbm 拆出 RGB 与掩码 \(3\times518\times518\)；\(1\times518\times518\)
头部 RGB 冻结 ViT-B/14 patch token \(1369\times768\)
掩码 patch embed + 4 层 Transformer \(1369\times768\)
头部融合 按 patch 拼接 \(1369\times1536\)
头部投影 head_net \(1369\times1024\)
腕部 RGB 冻结 ViT-L/14 \(1369\times1024\)
腕部投影 wrist_net \(1369\times1024\)
状态 state_net \(1\times1024\)
观测序列 三路沿 token 维拼接 \(2739\times1024\)
条件序列 追加扩散步 token + 位置编码 \(2740\times1024\)
动作序列 64×13 线性升维 + 位置编码 \(64\times1024\)
DiT 主干 12 个 RDTBlock \(64\times1024\)
输出头 RMSNorm + Linear \(64\times13\)

两个关键算式是

\[1369=37^2=(518/14)^2, \qquad 2739=1369_{\mathrm{head}}+1369_{\mathrm{wrist}}+1_{\mathrm{state}}.\]

扩散步 token 只在条件侧再增加 1，因此 \(2739\rightarrow2740\)；它不改变 64 个动作 token 的长度。

六、参数量：论文数字与源码推导

论文报告主控制器约有 163M 个可训练参数。按公开源码中的层定义逐项计算，可得 163,712,269，与论文的取整数字一致：

可训练模块 参数量
掩码 patch embed + 4 层 Transformer 28,504,320
head_net 2,627,584
wrist_net 2,103,296
state_net 269,312
动作输入投影与两套位置编码 2,885,632
扩散步嵌入 MLP 1,312,768
12 个 RDTBlock 125,995,008
最终 RMSNorm 与输出头 14,349
合计 163,712,269

该拆分采用源码对应版本的 PyTorch/timm 层定义：线性层含偏置，LayerNorm 含 weight 与 bias，timm RMSNorm 只含 weight，Q/K 归一化作用于每头 128 维。它是本站根据实现推导的核对结果，不是论文原表；依赖库实现若改变，精确个位数也可能改变。

两个容易混淆的口径：

  1. 冻结的 DINOv2 仍是模型参数，但 requires_grad=False，不属于上述可训练参数；
  2. 源码对 obs_encoder.parameters() 的日志统计没有过滤 requires_grad，因此那条日志会把两个冻结编码器也算进去，不能直接当作“可训练参数量”。

从分布看，12 个 RDTBlock 约占可训练参数的 77%，掩码编码器约占 17%。这是定量事实；模型效果由哪个模块“主要贡献”仍需消融实验判断。

七、源码边界与复现风险

7.1 条件长度被硬编码

ObsEncoder.output_shape() 固定返回

(1, 2739, feature_dim), [1369, 1369, 1]

控制器据此创建长度 2740 的条件位置编码，并构造可选注意力掩码的分段边界。若只修改输入分辨率或 patch 划分而不更新这里，实际 token 数与模型配置会不一致，可能在加位置编码时直接产生形状错误；某些配套修改不完整时也可能造成掩码分段错位。它不是“必然静默退化”，而是一个需要同步维护的硬编码耦合。

7.2 注意力可视化存在论文—公开代码口径差异

论文附录说明 Figure 4 的头部注意力图对所有扩散步、DiT 层、注意力头和动作 token求和后归一化。当前公开 CrossAttention.forward 在 gen_attn_map=True 时却只保存：

attn_weights = attn_weights[:2, :, 0, :]
# 前两个样本、每层各头、仅第一个动作 token

控制器确实会收集各层、各去噪步返回的结果，但这个公开路径已经在动作 token 维取了索引 0。因此，仅凭当前代码不能复现论文所述的“对全部动作 token 聚合”；可能存在未公开的可视化脚本、版本差异或论文发布后的代码改动。复现时应显式保留 \(B\times H\times64\times2740\) 的权重，再按论文口径聚合。

此外，注意力权重可以描述模型在该层如何分配读出权重，但不能单独证明因果重要性。论文 Figure 4 是四种环境下的定性案例，不等于对域不变性或泛化机制的严格验证。

7.3 不要把架构事实写成因果结论

  • 冻结 DINOv2 与泛化性能相关，但现有消融同时改变了训练自由度与优化问题，不能只归因于“保持预训练分布稳定”。
  • 头部 ViT-B/14、腕部 ViT-L/14 是模型选择结果，不是论文证明的视角分工定律。
  • 一个状态 token 不代表状态信息天然弱于 2738 个视觉 token。
  • cross-attention 提供 patch 级访问路径，但注意力图不等于模型解释。
  • RMSNorm、1 倍 FFN 和 4 层掩码编码器均缺少针对该选择的隔离消融。

八、知识重点与真正的创新点

8.1 需要掌握的架构知识

  1. 两种拼接语义不同：RGB—掩码按 patch 沿特征维融合；头部—腕部—状态沿 token 维组成条件序列。
  2. 条件与生成变量分离：条件序列作为 K/V，64 个带噪动作 token 作为被更新的查询。
  3. 时间步也是条件 token：2739 个观测 token 加 1 个扩散步 token，构成 2740 个条件 token。
  4. 块状动作不是自回归序列：动作位置间使用双向自注意力，最终一次预测整块噪声。
  5. 参数口径要分清：163M 指可训练部分，不包含被冻结但参与前向的 DINOv2 参数。

8.2 这套架构的核心创新应怎样表述

更准确的创新表述不是“发明了 DINOv2、DiT 或 cross-attention”，而是以下组合：

  • 用上层语言规划得到的目标掩码作为对象级控制条件，使低层策略不必直接处理语言；
  • 将掩码 patch 与头部 RGB patch 在相同空间网格中融合，同时保留腕部近场视角与本体状态；
  • 用冻结视觉基础模型提供视觉表征，再训练掩码对齐分支、投影层和动作扩散 Transformer；
  • 以长条件序列驱动整段连续动作的扩散生成，并通过滚动执行闭环重预测。

这些部件单独并非全新；贡献在于它们围绕“开放词汇目标指定 + 单域示范 + 跨环境灵巧抓取”形成了可训练、可部署的分层系统。至于每个部件分别贡献多少，需要以论文消融为准，不能从架构图直接推断。
