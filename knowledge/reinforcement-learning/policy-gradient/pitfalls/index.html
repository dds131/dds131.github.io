策略梯度训练日志里，同一种表象往往对应多个原因：回报不涨可能是估计方差、实现错位、目标口径或评估噪声；熵下降可能是正常收敛，也可能是过早失去覆盖。诊断的目标不是给曲线贴标签，而是用最小实验逐个排除竞争性假设。

本页每条模式都按四步展开：观察现象 → 列出可能原因 → 找可证伪判据 → 选择不超出证据的修复。

7诊断主题
8建议同步记录的信号组
2先过的正确性门禁
证据链不凭曲线形状猜原因
排查顺序。第一道门禁是实现正确性：回报方向、时间对齐、张量形状、log-prob、梯度路径和终止语义。第二道门禁是目标一致性：折扣、时域、熵正则与评估策略是否和你声称的目标相同。两道门禁通过后，才讨论学习率、批量和网络规模。

“没有报错”只证明程序能执行，不证明估计量正确；“一条曲线看起来合理”也不证明算法有效。

失效模式总表

编号 观察到的现象 不能直接下的结论 最先补的证据
① actor loss 下降而评估回报不涨 “优化器坏了”或“策略一定在变好” 固定批次内变化、独立评估回报、策略 KL
② 复用旧数据后变差 “on-policy 数据数学上只能看一次” 行为/目标策略版本、概率比、KL、支持覆盖
③ 性能突然崩塌 “一定是熵坍缩” 崩塌前后的 KL、梯度、优势尺度、环境状态
④ 回报平台且熵很低 “低熵就是故障” 随机/确定性评估、动作覆盖、尺度边界命中率
⑤ 接近时限时停滞 “truncated 一律要 bootstrap” 时限属于任务还是仅为采集截断
⑥ 改 $\gamma$ 后行为剧变 “$\gamma$ 只是方差旋钮” 声明的目标、$G_t$、外层 $\gamma^t$ 是否一致
⑦ 换种子后排序反转 “区间重叠就没有差异” 预注册种子、独立评估、聚合统计与不确定性

高方差、奖励平移和基线的正式分析在子页 ②；本页只把它们作为竞争性假设纳入诊断。

① actor loss 在降，评估回报不涨

先分清三个不同的量

设批次 \(\mathcal D_k\) 由 \(\pi_{\theta_k}\) 采集。固定该批次时，

\[L_{\mathcal D_k}(\theta) = -\frac1N\sum_{i,t} \operatorname{stopgrad}(w_t^{(i)}) \log\pi_\theta(a_t^{(i)}\mid s_t^{(i)})\]

在 \(\theta=\theta_k\) 处提供所需的局部梯度。由此可分出：

  1. 固定批次的替代目标。 在同一批数据和同一权重下，它的变化能说明优化器是否在拟合该局部目标。
  2. 跨迭代记录的 actor loss。 \(\mathcal D_k\)、权重尺度、轨迹长度和策略都在变，绝对值通常不可横向解释。
  3. 策略性能。 应由独立评估得到的期望回报、成功率、约束代价等任务指标描述。

因此“替代损失完全没有任何意义”也过头了；准确说法是：它的首要用途是构造梯度，跨批数值不是性能度量。

随机计算图中的上界结论还有明确前提，包括代价符号和参数是否经确定性节点影响代价；它不是任意深度策略梯度的单调改进保证，也不应与 TRPO 的性能界混写。

最小验证

  • 在参数更新前后，用同一固定批次、同一权重重算替代目标，确认优化方向和梯度符号。
  • 用不参与更新的环境实例与种子周期性评估，报告原始每回合结果及跨种子区间。
  • 同步记录新旧策略 KL；它回答“这一步走多远”，不回答“策略有多好”。
  • 检查回报、优势和 loss 的缩放是否因轨迹长度或批量归一化方式改变。

滑动平均可以显示趋势，但不是方差、置信区间或性能指标本身。训练采样回报也不等于独立评估回报。

缓解

这通常不是靠“让 loss 降得更快”解决。先确认 loss 符号和固定批局部变化，再把调参依据移到独立评估、KL、熵、梯度和优势统计。若同一批次上 loss 不按预期变化，查优化器与计算图；若固定批正常而评估变差，查更新幅度、估计噪声与目标错配。

完整的局部梯度匹配见子页 ④。

② 旧策略数据：能否复用取决于采用了什么校正

两层分布不匹配

状态—动作形式的策略梯度含有目标策略的折扣状态占用与动作分布：

\[\nabla J(\theta) \propto \mathbb E_{\substack{s\sim d^{\pi_\theta}\\a\sim\pi_\theta(\cdot\mid s)}} \left[ \nabla_\theta\log\pi_\theta(a\mid s) A^{\pi_\theta}(s,a) \right].\]

行为策略 \(\mu\) 生成的数据一般同时在两层失配：

  • 条件动作分布可用 \(\rho(s,a)=\pi_\theta(a\mid s)/\mu(a\mid s)\) 修正；
  • 只乘单步 \(\rho\) 并不会自动把 \(d^\mu\) 变成 \(d^{\pi_\theta}\)。

但“状态层修不动、比值算不出来”也是错误结论。至少有三类路线：

路线 能处理什么 主要代价
完整轨迹 / per-decision 重要性采样 在相同动力学和支持覆盖下，策略比率连乘可校正目标轨迹分布；环境转移在比率中抵消 长时域乘积方差可能很大，零支持无法补救
占用密度比或 emphatic weighting 从样本估计状态分布相关权重 新的估计误差、方差和函数逼近问题
近策略约束的局部替代目标 让目标策略保持接近行为策略，减小失配 通常是近似且可能有偏，不是精确状态修正

Off-PAC 选择按行为策略状态分布定义目标，并在推导中省略涉及策略参数对 \(Q\) 影响的一项，得到实用近似；原论文的理论范围与后续勘误必须按表格条件理解。后来的 emphatic policy-gradient 工作给出了另一种权重。它们说明这里是估计难题与目标选择，不是数学上的绝对不可能。

PPO 能说明什么，不能说明什么

PPO 在固定旧批次上使用动作概率比，并用裁剪或 KL 控制更新幅度。它允许有限轮次复用，但：

  • 优势和状态样本仍来自旧策略；
  • clipping 主动引入偏差；
  • 多轮数、学习率和 KL 共同决定旧批次失配程度；
  • 它不是“把同一个 REINFORCE loss 原样多跑几步”。

vanilla REINFORCE 的无校正估计器在行为参数处成立，所以最清楚的实现是一批新数据做一次 actor 更新。若要复用，应明确写出校正或受约束替代目标，而不是把“一次”宣称为所有 on-policy 算法的绝对定律。

flowchart LR
  D["行为策略 mu 采集旧数据"] --> Q{"准备怎样复用？"}
  Q --> NONE["无概率比、无约束"]
  NONE --> BAD["不再是目标策略的 vanilla on-policy 梯度"]
  Q --> IS["轨迹或 per-decision IS"]
  IS --> VAR["可校正，但检查支持覆盖与长时域方差"]
  Q --> DR["密度比 / emphatic weighting"]
  DR --> EST["引入额外估计器与误差"]
  Q --> PPO["PPO / TRPO 局部替代目标"]
  PPO --> LOCAL["有限复用；监控 KL、比率和裁剪比例"]

最小验证与缓解

  • 给每批数据记录行为策略版本；确认 log-prob 分母确实来自采样时策略。
  • 画概率比的中位数、分位数、极值与 PPO clip fraction，而不只看均值。
  • 在同一批状态上估计新旧策略 KL，并观察它随 epoch 的增长。
  • 检查支持覆盖：行为策略概率为零的动作，任何有限重要性比率都无法恢复。
  • vanilla 实现重新采样；PPO/TRPO 按各自目标和停止规则运行；离策略方法使用其完整推导，不混搭一行比率。

重要性采样和信赖域分别见 TRPO 与 PPO。

③ 性能突然崩塌：先还原时间线

曲线形状不是根因

“先涨后崩”至少可能来自以下几类原因，不能只凭形状判成熵坍缩：

竞争性假设 崩塌前后应看到的伴随信号
单步更新过大 KL、梯度范数或参数更新范数出现尖峰
优势 / 奖励尺度突变 return、advantage 分位数同步突变，KL 随之增大
critic 瞬时失真 value loss、解释方差、优势均值同时恶化
策略覆盖丢失 熵或连续动作尺度下降，成功样本率先下降
数值问题 logits、log-prob、ratio、梯度出现非有限值
环境或数据管线变化 observation/reward 范围、wrapper、终止比例在同一步改变
评估噪声 训练健康信号未变，仅少量评估回合突然变差

正反馈回路是可能机制，不是必然定律

策略产生自己的训练分布，因此确实可能形成：

flowchart TB
  STEP["一次过大的或方向噪声很强的更新"] --> PERF["当前策略性能下降"]
  PERF --> COVER["成功状态 / 动作的采样覆盖减少"]
  COVER --> SIGNAL["稀疏任务中的有效学习信号更少、方差更高"]
  SIGNAL --> STEP
  CHECK["密集奖励、足够随机性、外部数据或更大批量"] -.-> BREAK["可能打断回路"]
  BREAK -.-> COVER

需要保留两个限定：

  • 当前策略数据即使表现差，标准 on-policy 估计量仍可对当前策略保持正确；“数据差”不会自动使梯度有偏。真正恶化的常是成功事件覆盖和信噪比。
  • 经验回放也不保证价值方法一定恢复；陈旧分布、外推误差或错误自举同样可能造成崩塌。

TRPO 的单调改进分析依赖精确优势和满足约束等理论条件。深度实现、采样估计与近似求解下，它提供设计原则而不是每次运行都不下降的保证。

最小验证

围绕崩塌点保存前后若干次更新的时间对齐快照：

  1. 独立评估回报与成功率；
  2. 新旧策略 KL、PPO ratio / clip fraction；
  3. 裁剪前梯度范数与 advantage 分位数；
  4. 策略熵、各动作概率或每维 log-scale；
  5. value loss 与 explained variance（若有 critic）；
  6. observation、reward、terminated、truncated 的统计。

只有“回报跌 + KL 尖峰”才支持大步长假设；“回报跌 + 熵早已低”只是支持覆盖不足，仍需排除 critic 和环境问题。

缓解

  • 对应 KL / 梯度尖峰：减小学习率、增大批量、检查优势尺度，并考虑信赖域、KL 早停或比率裁剪。
  • 对应 critic 失真：分开检查 value target、学习率、裁剪与共享主干的梯度干扰。
  • 对应覆盖不足：调整熵目标、探索机制或数据来源，而不是盲目加大学习率。
  • 对应数值问题：先修非有限值和分布参数约束；调参不能修复错误计算图。
  • 保留训练检查点有助于复现实验与定位第一次异常更新，但回退不是因果诊断本身。

④ 回报平台与低熵：相关不等于因果

低熵何时正常

在标准、完全可观测、无熵正则的 MDP 中，常存在确定性最优策略，因此熵下降可以是正常收敛结果。POMDP、约束、博弈、多峰行为或显式最大熵目标则可能需要随机策略。判断“坍缩”的依据应是过早失去有用覆盖并伴随性能受限，而不只是熵数值小。

离散策略的边界

Categorical 策略在主导动作概率趋近 1 时，主导动作样本的得分 \(e_a-\pi\) 变小；稀有动作的条件得分并不一定小，只是它们越来越少被采到。于是平均学习信号可能衰减，但“熵为零 ⇒ 所有样本梯度严格为零”不是普遍等式。

要同时看：

  • 每个动作的概率分位数，而不只看总熵；
  • 稀有动作是否仍有支持；
  • 随机采样策略与 argmax 策略的独立评估；
  • 优势是否仍能区分动作。

连续高斯策略的边界

对角高斯中，log-scale 方向的得分为 \(z^2-1\)。期望更新由它与优势的协方差决定，尺度既可能收缩也可能扩张；不能从“均值附近优势更高”之外泛化出单向坍缩定律。尺度很小时，均值方向的条件得分含 \(1/\sigma\)，但最终梯度方差是否增大仍由优势与状态分布共同决定。

诊断应记录每维 log_std 的最小值、中位数、最大值，以及动作落在边界的比例。只看所有维度平均熵会掩盖单维饱和。

熵 / 尺度 回报 更合理的下一步
下降，评估已稳定达到目标 高 可能是正常收敛，不要只为“好看”强行增熵
很早下降，成功覆盖同步消失 低 检查初始化、步长、熵目标和奖励稀疏性
长期很高且策略不分化 低 检查熵系数、优势尺度和 actor 是否真正更新
单维尺度触底，动作大量饱和 不稳 检查有界动作参数化、尺度约束和该维奖励信号
熵正常但梯度接近零 低 查 detach、张量广播、优势是否全零，不要怪熵

缓解的边界

  • 熵正则改变优化目标。固定、衰减或自适应系数都需结合任务验证，不能由“高斯熵对 log-scale 的某个坐标导数为 1”推出固定系数普遍合理。
  • 硬裁剪 log_std 可防止数值越界，但在裁剪饱和区可能产生零梯度；平滑有界参数化或明确的分布约束更易解释。
  • 小输出层增益能让某些离散策略初始接近均匀，但效果依赖网络结构与输入尺度，不是普遍处方。
  • 已经变尖的策略并非数学上绝对无法恢复；恢复概率取决于剩余支持、奖励信号、优化步长和额外探索来源。

分布几何与有界动作细节见子页 ③；最大熵目标与温度学习见 SAC。

⑤ terminated、任务时域与人工截断必须分开

同一个 truncated=True 不替你定义目标

Gymnasium 把环境内终止 terminated 与环境外的 truncated 分开返回，目的是让算法知道二者来源不同。但“遇到 truncated 一律 bootstrap”或“一律把尾值置零”都不正确；先回答：时间上限是任务定义，还是仅为采集方便？

情形 目标中的时限 尾部处理
环境内真实终止 任务在该状态结束 后续回报为 0
固定有限时域任务 时域 $T$ 就是任务定义 $T$ 后回报为 0；若剩余时间影响最优决策，应把时间纳入状态
持续任务的人工 TimeLimit / rollout 切片 底层任务本应继续 直接置零会漏掉尾部；可跨片段保留轨迹或从 $V(s_T)$ 自举
随机故障、外部中断 取决于要评估的部署目标 不能只依据 API 布尔值，需记录中断原因

CartPole-v1 的 wrapper 在 500 步给出 truncation。若目标就是官方“最多 500 步”的基准回报，把 500 步作为有限时域终点是自洽选择；若研究的是无限期平衡杆、500 步只为训练采集方便，则应把它当人工切片并处理尾部。两种实验可以都合理，但优化的不是同一个任务。

对继续型目标，若在 \(T\) 处错误令尾值为零，则从 \(t\) 开始的 reward-to-go 少了

\[\gamma^{T-t}V^\pi(s_T).\]

它在接近切点时通常权重更大，但 \(V^\pi(s_T)\) 本身依赖状态，不能仅凭指数断言每条轨迹误差单调变化。

REINFORCE 的选择

  • 保持纯蒙特卡洛：跨固定步数缓冲保留未完成轨迹，直到目标回报段结束。
  • 明确定义有限时域目标：在任务时域处结束，并在需要时把剩余时间加入观测以恢复 Markov 性。
  • 在人工切点用 \(V(s_T)\) 补尾：可以立即使用片段，但引入自举，算法进入 Actor-Critic / 截断回报家族。
  • 直接丢弃未完成轨迹：会浪费样本，还可能偏向短轨迹。

最小验证

记录每个回合的 terminated、truncated、实际长度和具体 wrapper 原因；把“任务时域”写进实验配置。然后做两种口径的对照：有限时域置零与继续型尾部处理。只有目标先固定，才能把差异称为偏差而不是任务变更。

Pardo 等 2018 对“有限时域任务”和“继续任务的训练时限”分别给出处理原则；Gymnasium 的 time-limit 文档给出对应 API 语义。

⑥ 折扣因子：目标、估计量与代码必须同口径

对从起始分布定义的折扣目标

\[J(\theta)= \mathbb E\left[\sum_{t=0}^{T-1}\gamma^t r_t\right], \qquad G_t=\sum_{k=t}^{T-1}\gamma^{k-t}r_k,\]

严格的因果 REINFORCE 权重含外层因子：

\[\sum_t \gamma^t G_t \nabla_\theta\log\pi_\theta(a_t\mid s_t).\]

不少实现只用 \(G_t\)。当 \(\gamma=1\) 时两者相同；当 \(\gamma<1\) 时，Nota 与 Thomas 说明这种常见更新方向一般不是任何标量目标的梯度。

两个常见误判

  • “漏掉外层因子只是对远期回报产生一点偏差。” 不准确；它改变了各时间步得分项的权重，整体向量场一般不再对应声明的折扣目标。
  • “此时 $\gamma$ 只剩方差作用。” 也不准确；\(\gamma\) 仍决定每个 \(G_t\) 内未来奖励的相对权重和有效信用时域，同时影响更新尺度、方差与最终向量场。

最小验证与缓解

  1. 在文档中写出 \(J\)、\(G_t\) 和 actor 权重三行定义。
  2. 用三步玩具轨迹手算，例如奖励全为 1 时检查 \(G=[1+\gamma+\gamma^2,1+\gamma,1]\)，再检查外层 \([1,\gamma,\gamma^2]\)。
  3. 比较实现时同时报告“严格起点折扣”还是“省略外层的常用更新”，不要把二者实验混成同一算法。
  4. 扫描 \(\gamma\) 可以研究敏感性，但不能根据曲线差异反推出唯一机制；\(\gamma\) 同时改变目标时域和估计统计。

完整证明与不同目标口径见子页 ①。

⑦ 随机种子与实验结论

单次运行回答不了算法比较

初始化、动作采样、环境随机性、并行调度和评估回合都会影响结果。单种子排序只是两个随机样本的比较，不是两个算法分布的比较；但“两个置信区间重叠，所以没有差异”同样不成立，是否支持差异需要与实验设计匹配的估计或检验。

最小可信协议

  • 预先固定种子集合、环境步数预算、评估频率和主统计量。
  • 各方法使用相同种子集合可形成配对设计，降低部分环境随机性；报告时说明配对方式。
  • 训练种子与评估种子分开，评估环境不参与梯度更新。
  • 报告每种子的原始数据、均值或中位数以及 bootstrap 置信区间；说明聚合选择。
  • 横轴优先使用环境交互步数，另外报告墙钟时间和更新数据比。
  • 滑动平均只用于趋势可视化；阴影必须来自跨种子或评估回合的不确定性，而不是平滑窗口。
  • 训练时采样策略与评估时 argmax 策略是两个策略。若都关心就分别报告，不能假设 argmax 必然更高。
  • 固定 NumPy、PyTorch、环境 reset 与 action-space 随机源；同时承认硬件和并行算子可能仍非完全确定。

从“能复现”到“能归因”

若改进只在一个环境、一个调参预算或一个聚合指标上出现，结论只能限定在该设置。比较基线、熵或裁剪等机制时，应做单因素消融并直接记录它声称改变的中间量，例如梯度方差、熵或 KL，而不只看最终回报。

Henderson 等 2018 说明了深度强化学习评估对实现、超参数和随机性高度敏感；这类证据支持“需要更完整报告”，不支持先验断言策略梯度一定比所有价值方法更不稳定。

八组建议同步记录的诊断信号

单看回报或 loss 都不足以定位问题。以下信号应使用分位数或分布，而不是只打一个均值；“健康范围”由任务、参数化和算法决定，不存在跨任务统一阈值。

信号组 建议记录 能回答的问题
独立评估 每种子回报、成功率、约束代价、轨迹长度 性能是否真的变化，还是训练采样噪声
策略分布 熵、离散动作概率、每维 log-scale、边界命中率 覆盖是否变化，哪一维先饱和
权重统计 reward、return、advantage 的均值与分位数 奖励尺度、异常轨迹或全零优势
策略变化 KL、importance ratio 分位数、clip fraction 更新是否离开旧策略太远
梯度健康 裁剪前全局范数、非有限比例、两半批次余弦 爆炸、NaN 与方向噪声；余弦无通用阈值
critic 健康 value loss、target 范围、explained variance 基线是否提供信息，是否出现自举或尺度问题
边界语义 terminated / truncated / 外部中断比例与长度 尾部处理是否对应任务目标
可复现元数据 seed、环境步数、更新数、数据复用率、版本 两次运行是否真的可比较

“优势标准差除以绝对均值”不适合作为通用健康指标：好基线会让优势均值接近 0，使该比值发散。更直接的是记录 advantage 分位数、baseline explained variance，以及在同一参数快照上重复采批得到的梯度方差。

PyTorch 的 clip_grad_norm_ 返回裁剪前总范数，可用于日志；若每次都触发裁剪，先检查回报尺度、广播和学习率，而不是只提高阈值。

先写单元测试，再看长训练曲线

下面几项能在几秒内拦住一大类“能运行但估计量已变”的错误：

# 1. 三步玩具回报：r = [1, 1, 1], gamma = 0.9
expected_returns = torch.tensor([2.71, 1.90, 1.00])
actual_returns = torch.as_tensor(
    returns_to_go([1, 1, 1], 0.9), dtype=torch.float32
)
assert torch.allclose(actual_returns, expected_returns)

# 2. 禁止 (T,) 与 (T, 1) 静默广播成 (T, T)
assert log_probs.shape == advantages.shape == discounts.shape == (T,)

# 3. actor 关键张量必须有限
for tensor in [logits, log_probs, returns, advantages, actor_loss]:
    assert torch.isfinite(tensor).all()

# 4. 每个状态至少有一个合法动作
assert valid_action_mask.any(dim=-1).all()

# 5. 一次更新后 actor 参数应变化；纯 value loss 不应更新 actor

还应验证：

  • 采样并交给环境的动作，与记录并用于 log_prob 的动作是同一个随机变量；
  • 价值基线进入 actor 权重时已 detach，而 value loss 仍能更新价值网络；
  • 采样时可以 no_grad，但更新时必须重新前向建立 actor 计算图；
  • 多轨迹损失先逐轨迹时间求和，再按轨迹平均，除非明确采用每步目标；
  • 行为 log-prob 与策略版本一起保存，不能更新后用新策略伪造旧分母。

按症状排查的实现错误清单

症状 优先检查 准确边界
回报持续下降 actor loss 负号、奖励符号、评估方向 曲线形状不是证明；优势可正可负时不一定单调
几乎没有学习信号 动作—状态—回报时间对齐、倒序 $G_t$、actor 是否更新 正序历史和会加入无关过去奖励噪声，不必然等于“只看即时奖励”
结果与声明的折扣目标不符 外层 $\gamma^t$ 是否存在 漏掉它可能仍能学习，但不再是所声明起点目标的严格梯度
loss 张量尺寸异常或数值却“正常” $(T,)$ 与 $(T,1)$ 广播、batch / action 轴 广播到 $(T,T)$ 常不报错
更新后立刻失配 optimizer.step() 是否放进旧轨迹的时间循环 针对现代整轨迹 estimator；历史 REINFORCE 家族还有其它在线形式
value 越训越怪 actor 权重中的 $V$ 是否 detach、value target 是否误自举 共享主干时还要明确两种 loss 如何汇合
单样本标准化 NaN torch.std 的默认 correction 小批可用 correction=0 并加数值下限；标准化仍是随机缩放
离散动作 NaN 所有动作都被 mask、logits 非有限、手写 log(softmax) 在 logits 上屏蔽并保证至少一个合法动作；-inf 是否安全取决于后续实现
连续动作贴边 动作变换、环境 clipping、log-prob 所对应的变量 若保留潜变量 $u$，score estimator 可用 $\log p(u)$ 优化 $R(\operatorname{clip}u)$；不要把 clip 后值伪装成原采样值
tanh 策略的 ratio / entropy 错 是否漏了变换雅可比 对执行动作密度、ratio 和 entropy 必须使用一致的 transformed distribution
Normal 策略均值梯度异常 sample() 与 rsample() 是否混用 REINFORCE score loss 通常用不可重参数化样本或 detach；pathwise 目标才沿动作路径反传
接近时间上限异常 先界定任务时域还是人工截断 finite-horizon 置零与 continuing-task bootstrap 都可能正确
旧批次多轮后崩 行为 log-prob、ratio、KL、clip fraction 无校正 vanilla 与 PPO/TRPO 不是同一更新规则
熵项方向相反 最小化 loss 时应写 - beta * entropy 若代码最大化 objective，符号随整体约定反转

高收益排查顺序。先用玩具轨迹检查回报和形状，再检查 action 与 log-prob 对齐、loss 符号和梯度路径；随后核对 terminated / truncated 与折扣目标；最后才调学习率、批量、熵系数和网络宽度。

小结

  • actor loss 在行为参数处匹配所需梯度；固定批内可检查局部优化，跨批绝对值不是性能。
  • 旧数据并非数学上绝对不可复用。轨迹重要性采样、占用比估计和局部替代目标各有支持、方差与偏差代价。
  • 性能崩塌、低熵和回报平台都是现象，不能单独锁定学习率、探索或 critic；需要还原时间对齐的中间信号。
  • truncated 只说明结束来自环境外机制，不替你决定目标。有限任务时域与继续任务的人工切片必须分开。
  • \(\gamma\) 首先定义目标和信用时域；省略外层 \(\gamma^t\) 后的常用更新一般不是声明折扣目标的梯度。
  • 多种子、独立评估、原始数据与不确定性是算法比较的最低证据；平滑线和单次排序都不够。
  • 最有效的调试顺序是：玩具单元测试 → 计算图和形状 → 目标与边界语义 → 过程诊断 → 超参数。
