SmolVLA 的感知侧要在有限计算预算内，把多路相机图像、自然语言指令和机器人本体状态编码成动作专家可读取的条件特征。本页只回答五个问题：主干由什么构成，文本塔为何只保留前 16 层，每帧 64 个视觉 token 如何得到，三种模态如何组成 prefix，以及状态 token 放在 prefix 或 suffix 会产生什么差异。

阅读时需要始终区分三层证据：论文最终模型说明作者实际报告了什么；固定提交下的 LeRobot 类默认值说明不带 checkpoint 新建配置时会得到什么；checkpoint 自带配置与权重才决定某个已发布模型真正运行多少层、是否载入预训练权重以及采用何种 padding。三者大部分字段一致，但不能互相替代。下文凡写“论文最终模型”或“类默认值”都只指对应层次。

证据基线（核对于 2026-10-05）。论文采用 arXiv 2506.01844v1；实现结论固定到 LeRobot 8c920c4；公开基座配置固定到 lerobot/smolvla_base@d9f33c9；主干结构与权重形状固定到 SmolVLM2-500M-Video-Instruct@7b375e1。后续版本可能改变默认值，因此本页不会用持续更新的 main 证明历史实现。

一、主干：SmolVLM2-500M 由什么构成

SmolVLA 的主干不是从零设计的机器人视觉网络，而是建立在预训练小型视觉语言模型上。论文最终模型采用 SmolVLM2；固定版本 LeRobot 配置类的 vlm_model_name 默认指向 HuggingFaceTB/SmolVLM2-500M-Video-Instruct。但类字段只说明构造入口：类默认 load_vlm_weights = False 时按主干配置随机构造，公开 smolvla_base checkpoint 的配置则把该字段保存为 True，构造时会先读取预训练 SmolVLM2 权重，随后再由外层策略恢复 SmolVLA checkpoint 参数。因此，类默认值不等于发布权重的运行配置，更不能单凭“False 且 train_expert_only = True”推断论文训练流程。主干由两部分串联：

SigLIP 视觉编码器（视觉塔） 这是一个基于 SigLIP 改造的视觉编码器：它先把图像切成 patch，再用视觉 Transformer 编码。SigLIP 预训练提供了图文关联的良好起点，但它对齐的是自身的图像与文本分支；视觉特征要进入 SmolLM2 的 token 空间，仍需经过 connector 和 SmolVLM 的多模态训练。

SmolLM2 语言解码器（文本塔） 一个小型自回归语言模型。在 SmolVLA 中不使用其文本生成头输出答案，而是把前 16 层作为多模态融合骨架，让视觉、语言和状态 token 按指定掩码交换信息。

两侧的具体规格如下，取自该模型卡的配置与权重形状，后面几节的推算都建立在这几个数字上：

部件 层数 隐藏维 其他
视觉塔（SigLIP） 12，全部照跑 768 patch 尺寸 16×16，输入 512×512，位置嵌入共 1024 个位置
连接器 1 个线性层 — 把 12288 维投到 960 维，承担 pixel shuffle 之后的模态投影
文本塔（SmolLM2） 32，只用前 16 960 前馈中间维 2560，查询头 15、键值头 5、每头 64 维

固定版本的类默认值和公开基座配置有两处关键差异：

字段 LeRobot 配置类默认值 smolvla_base@d9f33c9 直接影响
load_vlm_weights False True 构造阶段是否读取预训练 SmolVLM2 权重
pad_language_to "longest" "max_length" 语言序列按批内最长补齐，还是固定补到 48
num_vlm_layers 16 16 最终保留的文本层数
add_image_special_tokens False False 每路相机是否额外加入图像起止 token
train_expert_only True True 是否冻结整个 VLM；状态投影另由 train_state_proj 控制

“500M”是基础主干的型号名，不是截断后 SmolVLA 的精确总参数量。论文报告最终 SmolVLA 约 450M 参数，其中动作专家约 100M；这是文本塔只保留 16 层并加入动作专家后的整机口径。模型名、完整 SmolVLM2 参数量与最终 SmolVLA 参数量不应混为一谈。若 checkpoint 覆盖了层数或专家宽度，应以其实际配置重新统计。

表中「只用前 16」正是下一节的静态截断。需要先排除一个常见误解：当前实现只截断文本塔，视觉塔的 12 层全部执行。这是源码事实；至于视觉塔是否也能安全截断，论文没有给出对应消融，不能由当前设计反推出一般结论。视觉侧采用的降本方式是取消图像 tiling、只保留全局图像，并在视觉塔之后压缩 token 数。

1.1 为什么用现成 VLM 而不从零训练

三条理由依次收紧了选型空间：

  1. 机器人数据与多模态预训练覆盖的目标不同。 SmolVLA 的社区机器人预训练集包含 481 个数据集、约 22.9K 条轨迹和 10.6M 帧，重点是动作与控制。论文没有用受控实验证明这些数据“必然不足”，但也没有证据表明它们可以替代更广泛的图文预训练；复用 VLM 是在有限机器人数据与训练预算下的工程选择。
  2. 现成 VLM 已完成关键的跨模态训练。 SmolVLM2 不只是把一个视觉塔和一个语言模型机械拼接起来；connector 与多模态训练已经学会把视觉证据送入语言模型的表示空间。SmolVLA 因而可以把有限的机器人训练预算集中到控制能力上。
  3. 紧凑主干服务于明确的部署目标。 论文将单卡训练和消费级 GPU/CPU 部署作为定位，因此主干规模、视觉 token 数和保留层数必须共同受控。本页没有给出 CPU 延迟实测，不把这一定位改写成任意 CPU 都能实时运行的保证。

1.2 论文自己指出的选型隐患

论文在第 5.1 节列出七项局限，其中一项专门讨论主干选择：所依赖的现成 VLM 主要在文档阅读与 OCR 类任务上预训练，这类 VLM 是否适合真实世界的机器人交互场景尚不清楚。

这条自陈指出了一个结构性风险：通用 VLM 的预训练目标与机器人控制所需的表示并不完全一致。文档与 OCR 任务强调文字、版面和细粒度符号；操作任务还需要物体位置、可抓取区域、接触关系与动作后果。二者有交集，但不能据此假定所有 VLM 特征都同样适合控制。

二、文本塔截断：只保留前 16 / 32 层

2.1 机制：静态截断，不是提前退出

文本塔不跑完全部 \(L\) 层，而是只保留前 \(N\) 层；动作专家按层读取这 \(N\) 层产生的键值表示（见第 4.1 节）。论文采用

\[N = \frac{L}{2}\]

LeRobot 的配置为 num_vlm_layers = 16。文本塔原有 32 层，因此 \(N=16=L/2\)。当前代码在模型构造过程中对 text_model.layers 做切片；切片完成后，后 16 层不再属于最终模块树，也不参与训练或推理。

需要精确区分「最终不保留」与「启动时从未读取」：load_vlm_weights=True 时，当前实现先调用 from_pretrained，再切片层列表，所以构造阶段可能短暂读取完整 VLM；稳态模块、参数占用和前向计算则只保留前 16 层。具体代码见⑤ 官方源码剖析第 7.1 节。

这里必须区分两个容易混淆的概念：

  动态提前退出（early exit） SmolVLA 的静态截断
停止位置 推理时根据样本或退出分数动态决定 训练前固定为第 \(N\) 层
后半层权重 通常仍保留，困难样本可能使用 切片后不在最终模块树中
额外机制 需要退出头、阈值以及相应训练或校准 不需要退出判据
批处理与延迟 不同样本路径可能不同，平均开销低但调度更复杂 所有样本路径一致，延迟和显存更可预测
稳态参数与缓存 通常不减参数；缓存取决于各样本退出位置 文本层参数与按层 prefix KV 缓存近似减半

动态提前退出并非必然造成训练—推理不一致；经过专门训练也可以保持二者匹配。SmolVLA 选择静态截断的直接收益是结构简单、批处理路径一致，并能同时降低稳态参数、计算和按层 KV 缓存。代价是所有样本都使用同一深度，不能让简单样本更早退出或让困难样本继续计算。

2.2 已知证据与可能解释

论文引用既有研究作为“最佳下游特征未必来自最后一层”的动机；SmolVLA 自身的直接证据是 Table 8：在 SmolVLM2-500M 与 LIBERO 的组合上，前 16 层给出了作者采用的速度—性能折中。计算则近似随保留层数线性增长，在异步推理中会影响动作块的生成周期（见⑥ 推理、动作块与异步执行）。

一种与结果相容、但论文未直接验证的解释是：中间层已经形成了足够的视觉—语言条件表示，而更深层继续优化原 VLM 的文本建模目标，对控制任务的边际收益较小。这里不能进一步断言深层必然丢失空间信息，也不能把 \(N=L/2\) 当成其他主干或任务上的固定规律。

2.3 三种降本方式的正面对照

论文在 LIBERO 上比较了连续保留前 \(N\) 层、隔层采样和改用更小 VLM 三条路线。这组数据回答的是「在该消融条件下，哪种结构取得了更好的任务分数」；论文没有同时报告三者的精确 FLOPs、延迟或显存，因此不能把它们描述成严格等计算量对照。

配置 Spatial Object Goal Long 平均
前 8 层（N = 8） 77 88 86 49 75.0
前 16 层（N = 16，最终采用） 88 91 91 44 78.5
前 24 层（N = 24） 86 97 86 49 79.5
全部 32 层（N = 32） 89 94 85 53 80.3
隔层采样（Skip % 2） 84 90 83 45 75.5
换用更小的 VLM-256M 86 83 75 59 75.8

这些数字取自论文 Table 8。该消融的基线配置并非最终发布模型：论文第 4.7 节说明，所有消融都在 LIBERO 上进行，除非特别说明，模型从零训练、不做任何机器人数据预训练，主干冻结、只训练动作专家。

因此表中 80.3 这一行与 SmolVLA 正式报告的 LIBERO 成绩 87.3 不可直接混用。需要注意的是，不能把差距简单归因于机器人预训练——论文 Table 2 显示正式模型在 LIBERO 上的 VLA Pt. 列同样标注为 No，表注写明“只从 VLM 初始化”。80.3 这组四项分数 89/94/85/53 还原样出现在 Table 9 的专家宽度 ×0.50、Table 10 的 Flow Matching、Table 11 的 Prefix+CA、Table 12 的 chunk 50 和 Table 13 的执行 1 步中，强烈表明这些行复用了同一套消融基线。由此可以跨表推断该共同点包含纯 CA、宽度 ×0.50、32 层等设置；但论文没有用一张表明确列出这套联合配置，不能把推断写成论文逐项声明的事实。最终模型采用 CA+SA 交错、宽度 ×0.75 与 16 层。由于 80.3 与 87.3 之间没有逐项受控，页面只能列出已知差异，不能断言其中某一项解释了全部提升。完整的八张消融表与跨表分析见⑦ 消融实验与反直觉现象第一节。

从这张表可以可靠读出三点：

  1. 截断并非无损。 在该次消融中，前 16 层的平均成功率为 78.5，完整 32 层为 80.3，数值上低 1.8 个百分点。论文未报告方差或显著性检验，因此这里不使用「显著下降」或「几乎无损」。
  2. 16 层是经验折中，不是单调定律。 平均值从 8 层的 75.0 提高到 16 层的 78.5，继续增加到 24 和 32 层时收益变小；但各子任务并不单调，例如 Long 在 16 层时低于 8 层。
  3. 连续保留前 16 层在该表中数值更高。 78.5 高于隔层采样的 75.5 和 VLM-256M 的 75.8。这个结论只适用于该消融设置，不能自动推广到其他主干、任务或严格等算力条件。

三种做法改变的结构不同，这为结果提供了一个合理但尚未由论文单独验证的解释：

省法 结构变化 可以谨慎提出的解释
前 \(N\) 层截断 保留一个连续的浅层—中层前缀 保留层之间仍是预训练时的相邻连接；但机器人输入与掩码仍会造成分布变化
隔层采样 每隔一层跳过一层 某层直接接收非原始相邻前驱的输出，层间接口发生更大改变
换更小的 VLM 宽度、深度或整体容量按小模型配置改变 表示容量与预训练模型本身同时变化，无法只归因于「更窄」或某一个单独因素

因此，更准确的总结是：连续截断、隔层采样和缩小模型并不是等价操作。Table 8 支持「连续保留前 16 层在该实验中数值最好」，而层间拓扑是否是主要原因仍需受控实验验证。它没有证明小模型的表示必然更粗糙，也没有证明连续截断后各层输入分布与预训练时完全一致。

N = L/2 不是普适常数。它是论文在 SmolVLM2-500M 与 LIBERO 设置下选出的经验值。更换主干、输入分辨率、任务分布或训练方式时，应重新扫描保留层数，并同时报告任务分数、端到端延迟、峰值显存和缓存大小，而不是只比较成功率。

三、视觉 token：从图像到每帧 64 个 token

3.1 压缩路径

论文在 SmolVLA 中关闭 SmolVLM2 的图像 tiling，只使用每路相机的全局图像；随后把视觉塔输出压缩为每帧 64 个 token。公开 smolvla_base@d9f33c9 的 input_features 为三路相机各声明 3×256×256，这是 checkpoint 的输入特征规格，不是视觉塔最终执行的分辨率。prepare_images 会把实际输入按比例缩放并补边到配置指定的 512×512，再送入主干。因此源相机无需原生输出 512×512，也不能用输入规格中的 256 代替下面的 token 推算。这个数字可由配置、固定源码与权重形状逐步核实：

步骤 做了什么 得到什么 依据
预处理 保持长宽比缩放，在左侧和上侧以 0 补边至 512×512，再由 [0,1] 映射到 [−1,1] 512×512×3 固定源码 resize_with_pad 与配置项 resize_imgs_with_padding
patch 切分 SigLIP 以 16×16 为一个 patch 做卷积 32×32 = 1024 个 patch，每个 768 维 视觉塔的 patch 卷积核为 16×16、输出 768 通道
视觉塔编码 12 层 Transformer，序列长度不变 仍是 1024 个，每个 768 维 视觉塔位置嵌入的形状恰为 1024 个位置
空间到通道重排 每 4×4 个相邻 patch 的特征堆进通道维；源码称 pixel_shuffle 8×8 = 64 个，每个 768×16 = 12288 维 主干配置项 scale_factor = 4
线性投影 把 12288 维投到文本塔隐藏维 64 个视觉 token，每个 960 维 connector 权重形状为 960 行、12288 列

令输入边长为 512、patch 边长为 16、空间压缩因子为 \(s=4\)，则

\[N_{\text{patch}}=\left(\frac{512}{16}\right)^2=32^2=1024, \qquad N_{\text{visual}}=\frac{1024}{s^2}=64.\]

重排后每个位置拼接 \(4^2=16\) 个 768 维特征：

\[d_{\text{rearranged}}=768\times4^2=12288, \qquad W\in\mathbb{R}^{960\times12288}.\]

源码把这一重排函数命名为 pixel_shuffle；但它执行的是空间尺寸减小、通道数增加，按常见视觉术语更接近 space-to-depth / pixel unshuffle。本页保留源码名，同时明确其数学方向。

于是，每路有效相机输入固定产生 64 个 960 维位置。这 64 个位置出现在视觉塔之后、文本塔之前；视觉塔本身仍处理 1024 个 patch，其中包括补边区域对应的位置，当前 embed_image 没有用 patch 级 mask 把它们提前删除。若用 empty_cameras 补齐缺失相机，代码仍可形成对应的 64-slot 嵌入，但相机级 img_mask 会令这些位置在 prefix 注意力中无效；“每路 64 个位置”不等于每路都有 64 个有效观测 token。

两点容易混淆的地方。其一，被截断到 16 层的是文本塔，不是视觉塔：视觉塔共 12 层，全部照跑，num_vlm_layers = 16 只作用于文本塔的 32 层（见第二节）。其二，当前类默认的 freeze_vision_encoder = True 只直接冻结视觉塔；connector 与文本塔在默认 train_expert_only = True 下才随整个 VLM 一起冻结。若关闭后一个开关，不能再由“视觉塔冻结”推出 connector 也不更新，应检查实际 requires_grad 与优化器参数组。

3.2 复杂度收益：140 倍究竟指什么

对文本塔而言，单层计算不只有注意力矩阵。可用下式理解主要量级：

\[C_{\text{layer}}\approx aSd^2+bS^2d,\]

其中 Q/K/V/O 投影和 MLP 主要随序列长度 \(S\) 线性增长，与 \(QK^\top\)、softmax 和 \(AV\) 有关的部分随 \(S^2\) 增长；常数 \(a,b\) 吸收了头数、分组查询比例、MLP 展开倍数和具体 kernel 等实现因素。视觉 token 通常是 prefix 中最长的一段，因此压缩它对文本塔的平方项尤其重要。

以公开 smolvla_base@d9f33c9 的配置为例：pad_language_to="max_length"、tokenizer_max_length=48、add_image_special_tokens=False。若使用两路有效相机和 1 个状态 token，则语言段固定占 48 个槽位：

\[S_{\text{uncompressed}}=2\times1024+48+1=2097, \qquad S_{\text{compressed}}=2\times64+48+1=177.\]

因此，文本塔单层中与密集注意力矩阵相关的理论计算比为

\[\left(\frac{2097}{177}\right)^2\approx140.3.\]

约 140 倍不是端到端加速比。它只描述上述固定配置中密集注意力的 \(S^2\) 项，不包括视觉塔、线性投影、MLP、connector、内存访问和 kernel 调度。视觉塔仍要处理 1024 个 patch。若改用配置类默认的 pad_language_to="longest"，式中的 48 应替换为该批次实际补齐后的语言长度，比例也会随之变化。文本层数从 32 减到 16 会继续降低文本塔与专家的按层开销，但不能据此宣称整个模型获得 280 倍加速；真实收益应以端到端延迟和显存实测为准。

3.3 重排并非无损压缩

空间到通道的重排只是重新排列元素，单独看是可逆的；但 connector 随后执行

\[\mathbb{R}^{12288}\rightarrow\mathbb{R}^{960}.\]

这个线性映射的秩最多为 960，远小于输入维度 12288，因此整体 connector 一般不可逆。准确的说法是：所有 4×4 空间块都参与了可学习投影，没有像裁剪那样直接删除某些位置；代价是每个块被压成一个 960 维 token，细粒度信息可能在降维中损失。

做法 直接丢弃的位置 主要代价
裁剪 视野边缘 被裁区域完全不可见
传统插值下采样 不直接删整块 高频细节会被插值或平均
space-to-depth + 投影 不删空间块 重排可逆，但 12288→960 投影是有损瓶颈

因此，这条路径的价值不是“无损”，而是把每个局部 4×4 区域的全部 patch 特征送入一个可学习投影，在覆盖完整全局视野的同时把文本侧序列从 1024 缩到 64。还要区分继承机制与 SmolVLA 的选择：space-to-depth/pixel shuffle 与 connector 来自 SmolVLM2，SmolVLA 没有发明这套重排；它针对控制效率作出的明确取舍是关闭 tiling、只使用全局图像，并把得到的 64-token 接口接入动作系统。是否影响细小目标定位取决于任务和训练结果，论文没有提供专门的小目标消融，页面不应把“精细定位一定先失败”写成已验证结论。

四、prefix：三种模态如何拼成一条序列

4.1 拼接顺序与序列结构

LeRobot 的 embed_prefix 按固定顺序拼接三类 token：

flowchart LR
  subgraph PFX["prefix 序列（同一观测下预填充一次，默认 10 步去噪复用）"]
    direction LR
    I["视觉 token<br/>每相机 64 个<br/>att_mask = 0"]
    L["语言 token<br/>上限 48 个<br/>att_mask = 0"]
    S["状态 token<br/>1 个<br/>att_mask = 1"]
    I --> L --> S
  end
  IMG["多路相机图像"] --> SIG["视觉塔编码 + space-to-depth + 投影"] --> I
  TXT["语言指令"] --> TOK["SmolLM2 词嵌入"] --> L
  ST["机器人本体状态"] --> SPJ["state_proj 线性投影"] --> S
  PFX --> BB["SmolLM2 文本塔前 16 层"]
  BB --> FEAT["16 层各自写入 prefix K/V<br/>CA 层读取；SA 层临时拼入 suffix 后再裁回"]

图最后一步需要特别说明：动作专家读到的不是只有文本塔最后一层的单个输出张量。推理预填充时，每个文本层都用“进入该层的 prefix 隐状态”投影并写入本层 K/V；去噪阶段的 CA 层读取对应层的固定 prefix K/V，SA 层则把本步 suffix K/V 临时追加到该层缓存，使动作 token 按掩码进行联合注意力，随后把缓存裁回 prefix 长度供下一去噪步复用。因此“逐层接口”不等于每一层都执行同一种 cross-attention。它保留了不同深度的条件表示，但论文没有证明浅层一定更偏视觉或局部几何。交错注意力与缓存实现见② 动作专家与交错注意力第 3.4 节。

三处实现细节值得注意：

  1. 图像和语言嵌入的幅度缩放。 当前源码把两者都乘以 \(\sqrt{960}\)，状态投影没有做相同缩放。这是可直接核实的实现事实，但论文没有提供相应消融，也没有证明其作用是让三种模态完全同尺度；因此本页不把源码注释中的 Normalize 扩展成确定机理。
  2. 语言内容长度和张量槽位数不是一回事。 tokenizer_max_length = 48 是截断上限，pad_language_to 决定补齐方式。 配置类默认 "longest"：张量长度等于该批次最长指令经 48 截断后的长度，较短样本的补位由 padding mask 屏蔽；仅调大上限不会让短指令自动变长。 公开 smolvla_base@d9f33c9 则保存为 "max_length"：即使任务指令远短于 48，语言段也固定占 48 个槽位，补位无效但仍占张量与计算空间。 源码最终读取 lang_emb.shape[1]，所以后续 prefix 长度跟随实际 padding 结果；分析显存或延迟时必须先查看所用 checkpoint 配置，不能只看类默认值。
  3. 状态先归一化，再投影成 token。 默认配置对状态使用 mean/std 归一化；短于 max_state_dim = 32 的状态向量补零后，由 state_proj 从 32 维映射到文本塔的 960 维隐藏空间。投影的核心作用是统一维度并学习可供控制使用的状态表示，不能简单解释为修正原始物理量纲。

4.2 块掩码：谁能看见谁

序列里每个 token 带一个 att_mask 标志：0 表示延续当前块，1 表示从该位置开始新块。设累计块编号为

\[c_i=\sum_{k\le i}m_k,\]

并令 \(p_i\in\{0,1\}\) 表示位置 \(i\) 是否有效（不是 padding），则位置 \(i\) 能读取位置 \(j\) 的精确条件为

\[A_{ij}=\mathbf{1}[p_i=1]\,\mathbf{1}[p_j=1]\,\mathbf{1}[c_j\le c_i].\]

因此，同块有效 token 双向可见；后续块能读取当前块和更早的块，而更早的块看不见后续块。无效的 query 或 key 都被 padding mask 屏蔽。

由此得到 prefix 的可见性结构：

块 组成 2D mask 允许读取 2D mask 屏蔽
块 1 全部视觉 token + 全部语言 token 块 1 内部全部 状态 token、动作 token
块 2 状态 token 块 1 与块 2 动作 token
块 3 起 动作 token（在 suffix 里，见子页②） 全部 prefix 与自身之前的动作 token 自身之后的动作 token

上式与表格描述的是 make_att_2d_masks 生成的允许关系，不是每一层都实际建立这些连接。CA 层不会把 prefix 与 suffix 当成同一条方阵序列重新做 self-attention；它以动作专家表示生成 query，以缓存中的 prefix 表示生成 key/value，并使用矩形掩码。只有 SA 层实现动作 token 之间的因果读取。两条路径共享“suffix 不得反向改写 prefix”这一约束，但计算图并不相同。

这个结构应从「模态融合」和「缓存」两个层面分别理解：

  • 图像与语言同处一块并双向交互。 这让视觉表示在文本塔内读取指令，语言表示也能读取图像；状态 token 位于后续块，因此它可以读取图像与语言，而较早的图像、语言 token 不反向读取状态。
  • 缓存成立的条件是 suffix 不能影响 prefix。 同一观测下，图像、语言和状态在默认 10 个去噪步中保持不变，变化的是动作 suffix。只要所有 prefix 表示都不依赖 suffix，逐层 prefix K/V 就能复用。视觉和语言能否读取状态并不是缓存的必要条件；进入下一控制时刻、图像或状态更新后，prefix 必须重新计算。

五、状态该放 prefix 还是放动作专家

5.1 两种做法与论文数据

本体状态既可以像上一节那样投影成 token 拼进主干的 prefix，也可以直接交给动作专家（即放进 suffix 一侧）。论文对这两种做法做了消融，并且同时改变注意力类型：

状态位置 注意力 Spatial Object Goal Long 平均
Prefix（进主干） CA 89 94 85 53 80.3
Suffix（进专家） CA 86 82 78 47 73.3
Prefix（进主干） SA 62 74 57 20 53.3
Suffix（进专家） SA 80 92 80 47 74.8

5.2 论文正文与该表之间的一处不一致

论文正文对这张表的结论是：把状态信息放进 VLM（即 prefix）对 CA 与 SA 两种变体都带来显著更好的性能。

这一表述与表格自身的第三、四行不符。 在 SA 变体下，Prefix 得 53.3，Suffix 得 74.8，Suffix 反而高出 21.5 个百分点。正文成立的只有 CA 那一半。

本页按表中数字陈述，不替论文调和：在 CA 条件下，Prefix 比 Suffix 数值上高 7.0 个百分点；在 SA 条件下，Suffix 反而高 21.5 个百分点。因此，状态位置与注意力结构存在明显交互，表格不支持「状态总应放在 prefix」的普遍结论。

固定提交的默认配置确实把状态放入 prefix，但不能把它直接等同于表中的纯 CA 行：虽然 attention_mode = "cross_attn"，默认配置还设有 self_attn_every_n_layers = 2，会周期性插入因果自注意力层，形成 CA+SA 交错结构。Table 11 没有单独报告这个最终交错结构下的 prefix/suffix 对照。

5.3 可以推断什么，不能推断什么

Table 11 只能证明状态位置与注意力类型在该消融中存在交互，不能单独确定机理。一种可能解释是：CA 依赖 VLM 提供条件 K/V，把状态放入 prefix 可以让状态先读取视觉与语言；SA 中把状态放在 suffix 可能缩短它到动作 token 的信息路径。但这两点都未被论文直接验证。

尤其不能仅凭「视觉 token 数量多」就断言状态会被注意力稀释：softmax 可以把权重集中在少数 token，token 多并不必然削弱状态影响。若要验证机理，应在固定注意力结构与训练配方后只改变状态位置，并结合以下检查：

  1. 遮蔽或替换状态 token，测量成功率与动作误差变化；
  2. 比较动作输出对状态的梯度或 Jacobian 敏感度；
  3. 检查逐层状态表示和动作查询，但不把平均注意力权重直接当作因果解释；
  4. 在最终 CA+SA 交错结构下补做 prefix/suffix 对照。

六、核心知识点与创新边界

完整的多模态主干 SmolVLM2-500M 由改造后的 SigLIP 视觉编码器、connector 与 SmolLM2 文本塔组成。视觉—语言能力来自完整多模态预训练，不是视觉塔天然对齐到 SmolLM2。

文本塔静态截断 最终模块只保留前 16 / 32 层；视觉塔 12 层全部执行。Table 8 中 16 层比 32 层数值低 1.8 个百分点，但论文未报告显著性。

64-token 视觉接口 每帧 1024 个 patch 经 space-to-depth 重排为 64 个 12288 维位置，再投影到 960 维。重排可逆，降维投影有损；该 connector 继承自 SmolVLM2，SmolVLA 的关键选择是关闭 tiling、只保留全局图像并复用这一紧凑接口。

复杂度边界 两相机示例中的 140.3 倍只对应文本塔密集注意力的 \(S^2\) 理论项，不代表视觉塔、完整 Transformer 层或端到端延迟获得同等加速。

prefix 与缓存 图像和语言同块双向可见，状态在后续块读取二者。缓存成立的关键是动作 suffix 不能反向影响固定 prefix；CA 读取固定 prefix K/V，SA 临时追加并在每步后裁回。新观测到来后必须重算缓存。

状态位置没有普适答案 Table 11 中 CA 偏向 Prefix，SA 偏向 Suffix；固定提交的默认配置是状态进 prefix 的 CA+SA 交错结构，不能直接等同于表中的纯 CA 行。
