一、四终端启动命令

这里只记录当时的实际部署方式，不在当前网页构建过程中执行。终端 3 必须打印 READY 后才能启动终端 4；终端 4 是唯一连接机械臂的进程。
D="/path/to/ruierman_robot"
W="$D/openpi_rlt_projection/openpi_ruierman_robot_deploy"
S="$D/openpi_rlt_projection/openpi_ruierman_robot_deploy_move_smooth/chunk_blend_smooth"
PY="/path/to/rm75_vr_pyroki/bin/python"
HEAD_DEV="usb:..."
ARM_DEV="usb:..."
THIRD_DEV="usb:..."

cd "$W"
RM75_CKPT_3CAM_STEP=40000 source openpi_env_3cam_0828.sh

# 终端 1：夹爪动作
cd "$D/vr_teleop_rm75_gripper"
bash run_gripper_daemon.sh --sync-on-start

# 终端 2：夹爪连续实测开口，提供 state[7]
cd "$D/data_collection"
bash run_gripper_state_pub.sh

# 终端 3：HTTP policy server；$OPY 由环境脚本设置
cd "$W"
"$OPY" serve_rm75_policy.py \
  --ckpt "$RM75_CKPT_3CAM" \
  --config-name pi05_rm75_rawact_3cam \
  --host 0.0.0.0 --port 8901 \
  --prompt "$RM75_PROMPT_3CAM" \
  --data-home "$OPENPI_DATA_HOME" \
  --mem-fraction 0.85 --warmup 2 --n-samples 1

# 终端 4：观测、异步推理、融合和 110 Hz 下发
cd "$S"
CUDA_VISIBLE_DEVICES= "$PY" run_smooth.py \
  --home-from-current \
  --head-dev "$HEAD_DEV" --arm-dev "$ARM_DEV" --third-dev "$THIRD_DEV" \
  --prompt "$RM75_PROMPT_3CAM" \
  --rate 110 --speed-scale 0.35 \
  --chunk-exec-steps 25 --chunk-overlap-steps 10 \
  --smooth-mode blend --blend-curve smootherstep \
  --blend-max-jump-deg 2.0 \
  --infer-latency-steps auto --lat-round ceil \
  --record --record-tag real_blend_0828_ss035

二、关键参数为什么这样取

参数 值 作用与风险
--ckpt step 40,000 使用验收汇总中表现最好的已实测 checkpoint
--config-name pi05_rm75_rawact_3cam 与训练保持相机键、state/action 变换和 norm stats 一致
--warmup 2 READY 前完成预热；旧部署记录曾见首次 JIT 约 10.5 s，0828 本轮未单独计时
--n-samples 1 每个观测只采样一次，避免推理耗时随样本数近似成倍增长
--rate 110 标称周期约 9.0909 ms
--speed-scale 0.35 30×0.35=10.5 模型步/s，只缩放时间轴
--chunk-exec-steps 25 计划执行步数 E
--chunk-overlap-steps 10 融合窗 V；触发点 E−V=15
--infer-latency-steps auto 每块按实际耗时计算已经过期的模型步数
--lat-round ceil 宁可多跳一步，不少跳一步造成速度反向
CUDA_VISIBLE_DEVICES= 空 控制端不占推理服务 GPU 显存

按平均间隔换算，接受动作块有效频率为 0.7055 Hz；按中位间隔换算约 0.7315 Hz。最大 15.4511 s 包含暂停或长间隔，会拉低平均值。

policy.infer()包含策略变换、JAX 推理和输出变换，不是纯 JAX 内核时间；剩余链路是时间戳差的混合项，现有日志不足以继续拆成图像预处理、传输和解包。

五、状态新鲜度与防自激

ACTIVE qpos_age P50 P95 P99 max
关节读数年龄 10.5 ms 26.1 ms 44.2 ms 138.1 ms
  • stale_req=336：重复推理触发被防自激守门拦下，不是服务端失败。
  • 推理失败、请求拒绝、动作块过期：均为 0。
  • 三路相机断流阈值：third/arm 0.3 s，head 0.5 s。
  • 关节读数陈旧判据：0.2 s。
  • 主控按启动后只接受晚于启动时刻的新图像，防止回位缓存帧进入首次推理。

六、为什么必须异步

同步读取关节角的 TCP 往返曾实测中位 6.5 ms、P95 13 ms、最大 22 ms，已经可能超过 110 Hz 的约 9 ms 周期。最终结构使用后台 arm_poll 约 50 Hz 更新缓存，下发线程只读内存。

推理线程同样不阻塞下发：触发推理后 send 继续消费旧块；新块返回、通过安全闸后原子替换。若旧块先用尽则保持末帧，默认超过 1 s 仍未接上才进入故障态。

一句话回答：系统的关键不是把推理优化到 9 ms，而是把约 120 ms 的异步推理与 9.09 ms 的周期下发解耦，同时记录动作块频率、周期抖动和 qpos 新鲜度证明链路没有静默失控。
