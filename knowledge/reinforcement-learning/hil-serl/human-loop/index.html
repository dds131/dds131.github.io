总览架构接管与数据Loss奖励与控制训练与源码现象诊断研究路线
Intervention · Executed Action · Dual Replay

人类不是替机器人做完，而是在最有信息量的地方短暂改写行为

接管的价值来自“当前策略真正会犯的错”。HIL-SERL 将纠正片段同时作为在线经验和人类先验重用，但仍让策略自主探索并根据任务奖励优化。因此接管是数据路由协议，不只是一个遥操作按钮。

1. 接管门控的数学语义

令 $a_t^{RL}$ 是策略建议动作，$a_t^H$ 是人类遥操作动作，$I_t\in{0,1}$ 表示是否接管，则环境真正执行

\[a_t^{exec}= \begin{cases} a_t^H, & I_t=1,\\ a_t^{RL}, & I_t=0. \end{cases}\]

对纯连续向量，这也可写成 $(1-I_t)a_t^{RL}+I_ta_t^H$；对含 open/close/stay 的离散夹爪动作，应理解为“二选一”，不能把算术式误解为动作插值。一段接管可持续若干连续环境步，同一条轨迹可发生多段接管。关键不是门控公式本身，而是 transition 的动作字段必须保存 $a_t^{exec}$：

\[(s_t,\;a_t^{exec},\;r_t,\;s_{t+1},\;d_t).\]

若存成被覆盖的 $a_t^{RL}$，Critic 会误以为策略建议动作导致了人的结果。其 TD 目标再精确也会学习错误的状态–动作因果对应。

官方 `examples/train_rlpd.py` 的 actor 循环在 `info` 中发现 `intervene_action` 后，用它覆盖动作，再构造 transition。这一顺序是复现 HIL-SERL 数据语义的硬门槛。

2. 三类数据如何进入两个 Buffer？

数据来源 RL Buffer Demo Buffer 作用
训练前成功示范 否 是 让稀疏奖励任务从可达成功轨迹附近启动
机器人自主执行 是 否 反映当前策略真实的成功、失败与状态占据
在线接管的实际动作 是 是 既属于在线行为分布，又是高信息密度恢复先验

“同时进入两池”会提高接管样本的期望抽取次数，但不能简单说成“固定加倍”。设当前两池大小为 $N_D,N_R$，每池均匀、有放回抽取 $B/2$ 条；同一接管转移在两池各有一份时，它在一个 batch 中的期望出现次数为

\[\mathbb E[C_{itv}]=\frac{B}{2N_D}+\frac{B}{2N_R},\]

而只在 RL Buffer 中的自主转移为 $B/(2N_R)$。因此重权强度会随两池大小变化；这是双写与分池采样共同产生的结果，不是一个恒定权重超参数。接管通常位于当前策略的困难状态，但它是否真是“高价值纠正”，仍要由后续任务回报与 TD 学习检验。

3. 50/50 采样到底改变了什么？

若总 batch 为 $B$：

\[\mathcal B=\mathcal B_{demo}\cup\mathcal B_{RL},\qquad |\mathcal B_{demo}|=|\mathcal B_{RL}|=\frac B2.\]

它与“把两个 Buffer 合并后均匀抽样”完全不同。若 Demo 只有几千条而 RL Buffer 持续增长，合并均匀抽样会让示范比例迅速接近零；分池等量采样则保持稳定的先验压力。

这带来三种同时存在的效应：

  • 启动效应：每个更新都从 Demo Buffer 取样，增加看到成功或恢复路径的机会，但不保证每个 batch 都含非零即时奖励；
  • 重用效应：少量 demo 被高频重复，提高真实交互数据的复用强度；
  • 偏差风险：若 demo 很窄、动作次优或奖励标注错，它也会被反复放大；因此必须分开监控两池 TD error 和 Q 分布。
梯度路径要分清：混合 batch 会送入 Critic、Actor 与 Temperature 更新，但三者使用字段不同。Critic 用存储的 $(s,a^{exec},r,s')$，因此人类动作直接进入 TD 回归；Actor 在 batch 的状态 $s$ 上重新采样 $a\sim\pi_\theta(\cdot|s)$，并不对存储的人类动作做监督拟合；Temperature 也主要由策略采样动作的 log-probability 决定。50/50 是状态/转移来源配比，不是 50% 的 BC loss。

4. 为什么这不是默认行为克隆？

以确定性连续动作为例，行为克隆可写成

\[\mathcal L_{BC}=\mathbb E_{(s,a_H)} \left[\|\pi_\theta(s)-a_H\|^2\right];\]

随机策略更常用负对数似然。两者的局部语义都是“让策略输出更像人的动作”。HIL-SERL 原版核心 Actor 更新则是

\[\mathcal L_\pi= \mathbb E_{s\sim\mathcal B,\,a\sim\pi_\theta(\cdot|s)} \left[\alpha\log\pi_\theta(a|s)-\frac{1}{K}\sum_{k=1}^{K}Q_{\phi_k}(s,a)\right].\]

它的语义是“在混合 batch 覆盖的状态上，以熵正则约束策略，同时选择平均 Critic 认为价值高的动作”。若人类动作之后确有较好回报，Critic 的 TD 回归会提高相应状态–动作的估值，Actor 才可能间接受益；这不是对每个人类动作无条件加分。两者区别决定了策略是否保留超越人类的通道：

  • BC 会持续惩罚偏离教师，即使新动作更快；
  • RL 只要新动作带来更高回报，就允许偏离示范；
  • 人类示范仍影响 Q 的支持区域，因此不是“完全没有模仿效果”，只是这个效果经价值学习中介。

本站已经在 HG-DAgger 专题讲过交互式模仿学习，本页不重复其完整推导。

5. 什么样的接管最有价值？

不可恢复之前

机器人即将碰撞、掉落物体或离开任务可恢复区域时，用短动作把状态拉回。

局部最优附近

策略反复卡在相同接触或对准状态时，给出跨过瓶颈所需的最小纠正。

新失败分布上

策略进步后访问到初始示范没有覆盖的状态，人类补充当前分布需要的恢复动作。

尽快归还控制

纠正后让策略自己连接剩余过程，才能验证它是否真正利用了新状态。

论文与 LeRobot 教程给出的操作经验是：让策略保留自主探索，只在必要处给出具体纠正，并随能力提高逐步减少接管。接管率常应呈下降趋势，但是否能接近零取决于任务风险、终止条件和操作者策略；这不是算法保证，也不能用“低接管率”单独代替自主成功率。

6. 为什么“接管越多”可能越差？

直觉上，更多正确动作似乎总是更好；off-policy 自举与函数近似使这个结论并不成立。论文明确报告“持续、较长且最终把任务救到成功”的接管会造成价值过估计，尤其在训练早期。下面五步是对这一观察的机制分解，不是论文给出的形式化定理：

  1. 接管后的末端转移带来稀疏成功奖励；
  2. Bellman backup 把高值向前传播到接管片段；
  3. 函数近似又把高值泛化到接管动作附近的策略动作；
  4. Actor 追逐这些 Q，即使它还不能稳定进入或维持这些状态；
  5. 新数据可能验证不了高值，训练出现震荡或 Q 膨胀。

问题可以拆成三层：

  • 动作可达性：策略分布是否覆盖人的恢复动作？
  • 状态占据：部署时策略是否会到达人类维持的状态？
  • 自举半径：成功奖励通过 Q 泛化传播到了多远？
论文明确提醒：训练早期应避免持续、较长且最终把任务救到成功的接管，因为作者观察到这会造成价值函数过估计与训练不稳定。更稳妥的操作原则是给出具体、短促的必要纠正并尽快归还控制；这是一条经验准则，不是“接管超过固定步数就必然失败”的阈值定律。

7. HIL-SERL、HG-DAgger 与 RLIF 的边界

方法 人类信息 任务奖励 主要优化 策略超越人类的通道
HG-DAgger 纠正动作 不必有 监督拟合纠正动作 受教师质量与覆盖限制
HIL-SERL 初始示范 + 纠正动作 论文多数任务为成功分类器；Jenga 例外 off-policy RLPD/SAC 自主探索发现更高 Q 动作
RLIF 接管事件/介入反馈 接管信号构造奖励 从介入反馈做 RL 不要求接管动作本身最优

三者都可能出现“人拿回控制”的界面，但训练信号完全不同。把接管事件设成负奖励不等于把接管动作同时送入 Demo/RL Buffer，也不等价于给 Actor 加 BC loss。

8. 知识点、重点与创新边界

知识点

门控决定执行谁的动作；双写决定转移出现在哪些数据源；50/50 决定每批的数据源配比；Loss 决定这些字段如何产生梯度。四层语义必须分开。

检查重点

先查 transition 是否保存实际动作，再查接管步是否双写，最后查 Actor 是否错误加入了 BC 项。只看最终成功率无法定位数据协议错误。

创新边界

HIL-SERL 的贡献是把在线纠正纳入 RLPD 真机训练闭环并验证其效果；50/50 prior/online 采样来自 RLPD，接管界面也有 HG-DAgger/RLIF 先例，不能把每个零件都称为本文首创。

9. 需要持续记录的指标

接管率接管步 / 环境步
接管段次数与平均持续步数
恢复率接管后归还控制仍成功
  • 每回合接管段数，不只看接管总步数；
  • 从归还控制到下一次接管的自主保持时间；
  • Demo/RL Buffer 大小、样本年龄与重复采样次数；
  • 两池各自的 TD error、Q 均值、Q 上分位数；
  • 无纠正性接管评估回合的成功率和周期时间；若安全接管不能关闭，应单列而不能计作自主成功；
  • 接管率、成功率和周期时间是否形成“接管下降、性能上升”的联合趋势。

仅看 episodic reward 会掩盖“人完成了大部分回合”的假进步；仅看接管率下降也可能是操作者疲劳。三个指标必须联读。

10. 数据语义单元测试

最小玩具环境应验证：

  1. 无接管时 transition action 等于策略动作，只进 RL Buffer；
  2. 接管第一步立刻记录人类动作；连续接管的每步同时进入两池；
  3. 归还控制后的第一步不再进入 Demo Buffer；
  4. batch 为奇数时采样大小有明确规则；官方代码两侧都用 batch_size // 2，奇数会使拼接后的实际大小少 1，因此复现配置最好显式断言 batch 为偶数；
  5. checkpoint 恢复后两池内容与采样器状态不混淆；
  6. 自主成功率统计排除任何发生接管的评估回合。
