VLA 总览/DexGraspVLA/观测编码器与 DiT 架构

③ ARCHITECTURE · 2739→2740 CONDITIONS · 64 ACTION TOKENS

Planner 产生目标与 bbox，Perception 产生同帧二值 mask；Architecture 从处理后的 rgbm、腕部 RGB 和 13 维状态开始，将观测组织成 2739 个 token，再追加扩散步形成 2740 个条件 token，由 12 层 RDTBlock 预测 64×13 的 epsilon。

返回专题总览上一知识点：② 目标感知与跟踪下一知识点：④ 扩散建模与 Immiscible Diffusion
one-frame observation12 × RDTBlockepsilon predictionstatic accounting

这不是“把四路输入送进一个视觉 backbone”的架构。头部 RGB 与 mask 分别编码后在同 patch 的特征维融合；腕部 RGB 走另一冻结 DINOv2；状态成为一个 token。动作侧的 64 个查询 token 只在 RDTBlock 中更新，条件 token 作为 cross-attention 的 K/V 保持不变。

27391369 头部 + 1369 腕部 + 1 状态
2740观测序列追加 1 个扩散时间步 token
64 × 13带噪动作容器与 epsilon 输出形状
163,712,269按固定层定义静态核算的可训练参数

责任边界。 本页只陈述静态结构、形状和 trainability。SAM/Cutie 如何得到 mask 归 ② Perception；如何加噪、匹配、训练 epsilon loss 和做 16 步 DDIM 归 ④ Diffusion。精确参数表是本站静态推导，不覆盖论文“约 163M”的取整口径。

一、固定证据、入站合同与页面起止边界

论文事实固定为 arXiv:2502.20900v5，首次提交 2025-02-28、v5 修订 2025-11-15；实现事实固定到官方 commit 0144c7928817c5149ae836da2682291360828a21。关键锚点是 ObsEncoder、MaskEncoder、CrossAttention、RDTBlock、TransformerForDiffusion、DexGraspVLAController 与主配置。本站只根据这些固定定义复算 shape 和参数，不生成运行时证据。

Page112 应交付同帧 head RGB 与二值 mask、腕部 RGB、13 维关节状态以及 frame/generation provenance。固定代码处理后的核心 tensor 是 rgbm: T×4×518×518、wrist: T×3×518×518、state: T×13；显式 frame/generation id 在固定实现中缺失，所以它们是目标合同，不是已实现功能。

Architecture 的起点是处理后的观测 tensor，终点是当前扩散档位的 64×13 噪声预测。Planner 只保留为 related 快捷阅读，不能越过 Perception 成为本页顺序前驱。

读这一页时要持续区分三类证据。论文负责说明总体设计、约数参数规模和实验语境；固定提交中的源码负责确定层、宽度、拼接方向和默认开关；本站只在二者给定的定义上做可复算的形状与参数推导。静态推导可以回答“按这些层定义应有多少参数”，不能替代一次真实前向、显存测量或成功率实验。凡是固定材料没有给出的性能结论、因果归因和部署保证，本页都不补写。

二、首屏数据流：四路输入到 epsilon 输出

flowchart LR
  PT[Perception: aligned head RGB + mask] --> RGBM[rgbm 4×518×518]
  RGBM --> H[DINOv2-B/14 RGB tokens]
  RGBM --> M[trainable mask encoder]
  H --> HF[patch-wise feature concat + head_net]
  M --> HF
  W[wrist RGB 3×518×518] --> WE[DINOv2-L/14 + wrist_net]
  S[joint state 13] --> SE[state_net: one token]
  HF --> OBS[2739×1024 observation tokens]
  WE --> OBS
  SE --> OBS
  K[diffusion step k] --> TE[one 1024-d time token]
  OBS --> COND[2740×1024 condition tokens]
  TE --> COND
  A[noisy action 64×13] --> AT[64×1024 action tokens]
  COND --> RDT[12 RDTBlocks]
  AT --> RDT
  RDT --> O[RMSNorm + Linear → epsilon 64×13]

文本回退： 对齐 head RGB/mask 分别进入冻结 ViT-B/14 与可训练 mask encoder，并按同一 37×37 patch 位置融合为 1369 个头部 token；腕部 RGB 经冻结 ViT-L/14 产生 1369 个 token，13 维状态产生 1 个 token。三者拼成 2739 个观测 token，追加扩散步 token 得 2740 个条件 token。64×13 带噪动作投影为 64 个动作 token，经 12 层自注意力/交叉注意力/MLP 后输出 64×13 epsilon。

这张图强调两种拼接：头部 RGB 与 mask 沿 feature 维拼接；头部、腕部和状态沿 token 维拼接。把两者混写会同时破坏 1536 特征宽度和 2739 token 数。

还要区分“条件序列”和“动作序列”。前者把当前观测与扩散时间步提供给 cross-attention，后者承载正在去噪的动作块；二者虽然同为 1024 维，但长度、位置编码和更新规则不同。RDTBlock 只迭代动作表示，不能据图把 2740 个条件 token 理解成也经过十二层共同更新。最后的 64×13 仍是 epsilon 预测，只有后续采样过程才能把多次网络调用组合为动作样本。

三、输入分辨率、单帧边界与预处理

原始头部/腕部帧为 640×480×3，mask 为 640×480×1；模型输入才是 head rgbm: 4×518×518、wrist 3×518×518 与 13 维状态。518 是 resize 后模型边长，不是相机原生分辨率。动作语义是 7 个机械臂与 6 个手部目标关节位置组成的 64×13 块。

固定配置 n_obs_steps: 1，当前不支持多步观测，因此神经控制器显式窗口是一帧。但整个系统并非无记忆：Cutie 保留跟踪 memory，Planner 保留任务状态，滚动执行通过新观测与物理状态承接历史。T_obs=1 不能与动作 horizon 64 混为一类时间长度。

ObsEncoder.forward 将 rgbm 的通道 0–2 作为头部 RGB，通道 3 作为 mask。两路 RGB 按固定真机约定执行 BGR→RGB；训练期使用 ColorJitter(0.3,0.3,0.3,0.1)，再做 ImageNet mean/std 归一化。mask 不进入 RGB 归一化或 DINOv2；若上游已是 RGB，不能机械地再交换通道。

因此，输入审查不能只看最终 tensor shape。四通道尺寸正确，也可能出现颜色通道语义颠倒、mask 与 RGB 来自不同帧、mask 被连续值插值污染，或状态顺序与训练定义不一致。Architecture 默认消费的是已经满足入站前置条件的 tensor；它没有在编码器内部重新验证 frame id，也不会从像素内容恢复跟踪 generation。相关一致性应在 Perception→Architecture 交接处显式验证，而不是期待 backbone 自动吸收接口错误。

原始传感器、模型输入与时间窗口必须分开
对象 形状/配置 语义边界
head / wrist 原始 RGB 640×480×3 相机口径，不是 518
target mask 640×480×1；二值 由 Perception 产生并与 head 同帧
模型输入 rgbm 4×518×518；wrist 3×518×518；state 13 T_obs=1
动作容器 64×13 64 个位置；13=7 arm + 6 hand

四、头部 RGB 与 mask：同 patch 的特征融合

头部 RGB 走冻结 DINOv2 ViT-B/14，输入 3×518×518、特征宽 768。eval()、requires_grad=False 与 torch.no_grad() 三项共同冻结前向；get_intermediate_layers(n=1)[0] 返回 patch token，而不是只取 CLS。唯一保留的网格推导是 518/14=37，所以 37²=1369，输出 1369×768。冻结不等于没有参数、显存或计算成本。

mask 分支从 1×518×518 开始，Conv2d(1,768,kernel_size=14,stride=14) 产生同一个 37×37 网格；展平为 1369×768，先经 LayerNorm，再过 4 层 TransformerEncoderLayer。每层 8 头、FFN 3072、GELU、dropout 0、batch_first=True、norm_first=True，整条 mask encoder 可训练。论文没有隔离证明“四层”是最佳深度。

同一 patch 索引上的 RGB 768 维特征与 mask 768 维特征沿 feature 轴拼成 1369×1536；head_net 用 1536→1024→1024，中间为 LayerNorm、GELU、Dropout 0.1，末端 LayerNorm，得到 1369×1024。这不是把两组 1369 token 前后相接，也没有证据证明 feature concat 必然优于 cross-attention。

这里的空间对应关系来自相同的 518 输入边长、14 像素 patch 步长与展平顺序。若只替换 mask 分支的 stride、padding 或 token 排列，即使两侧都恰好输出 1369 个 token，也可能把不同空间位置误配到一起。静态变更审查至少要同时核对网格尺寸、展平次序、feature concat 轴和 head_net 的 1536 输入宽度；本页没有把“长度相等”当成“空间对齐已证明”。

头部 RGB 与 mask 共享 patch 索引
阶段 输出 训练状态
DINOv2 ViT-B/14 1369×768 eval + no-grad + frozen
mask patch + 4-layer encoder 1369×768 trainable
feature concat 1369×1536 同 patch，feature 轴
head_net 1369×1024 trainable

五、腕部与状态分支

腕部 RGB 使用冻结 DINOv2 ViT-L/14，输入同为 3×518×518，产生 1369 个 1024 维 patch token。它同样是 eval、no-grad、requires_grad=False；随后通过可训练 wrist_net: 1024→1024→1024，中间 LayerNorm/GELU/Dropout 0.1、末端 LayerNorm，输出仍是 1369×1024。论文把 B/L 组合作为初步模型选择，不足以建立“头部永远用 B、腕部永远用 L”的视角定律。

状态是 7 个机械臂关节角与 6 个手部关节角，共 13 维；state_net: 13→256→1024，在 256 维中间层后使用 LayerNorm、GELU、Dropout 0.1，末端 LayerNorm，最终只产生 1×1024 token。一个状态 token 不表示它一定比 2738 个视觉 token 重要性低；token 数是结构长度，不是贡献度量。状态语义也不应扩写为速度、力矩或触觉。

冻结视觉 backbone 与可训练投影层的边界也应逐层阅读。冻结只说明这些参数不参与梯度更新；视觉特征仍参与后续计算，且其输出分布决定投影层所见输入。反过来，wrist_net 和 state_net 可训练，也不意味着页面能推断它们分别贡献了多少成功率。若要回答模态贡献，仍需要固定数据划分、明确遮蔽协议与独立消融结果，这些都不在本页静态证据范围内。

六、2739 观测 token 与 2740 条件 token

三路输出宽度均为 1024，沿 token 轴拼接：

\[1369_{\text{head}}+1369_{\text{wrist}}+1_{\text{state}}=2739.\]

分段是 head [0,1369)、wrist [1369,2738)、state [2738,2739)，固定 segment lengths 为 [1369,1369,1]。这些边界不仅用于解释，也被 output_shape() 与可选 attention mask 使用。

扩散步标量 k 先生成 256 维正弦嵌入，再经 Linear→SiLU→Linear 投影到 1024 维，作为一个 token 追加在观测末尾：2739+1=2740。条件序列加可学习位置编码 1×2740×1024。它不是 adaLN conditioning，也不是把时间嵌入逐个加到动作 token。

分段索引适合作为实现核对清单：前 1369 个位置必须属于头部融合特征，接下来的 1369 个属于腕部特征，第 2739 个观测位置才是状态；扩散时间 token 追加为条件序列最后一个位置。这个顺序同时影响位置编码和可选 cross-attention mask。若调整拼接顺序却沿用旧的 segment lengths，代码可能仍能运行，但屏蔽语义会悄然指向错误模态，因此不能只依赖 shape check。

条件长度与位置编码

七、64 个动作 token 与 12 层 RDTBlock

动作侧输入是同一扩散档位的 x_k∈R^{64×13}。Linear(13,1024) 逐位置投影，并加可学习动作位置编码 1×64×1024，形成 64 个动作查询 token。它们不是自回归逐个生成；64 个位置可以在双向 self-attention 中联合交互。

每个 RDTBlock 只更新动作流，固定顺序是：

  1. RMSNorm → 双向 self-attention → residual；
  2. RMSNorm → cross-attention → residual；
  3. RMSNorm → MLP → residual。

配置共 12 层、8 头、每头 128 维，总宽 1024。cross-attention 用动作 token 作 Q、2740 条件 token 作 K/V，Q/K 使用 RMSNorm；条件序列不会被 block 反向写回。结构允许整块协调和 patch 级读取，但不保证轨迹必然连贯，也不能把 attention 当成因果解释。

block MLP 是 1024→1024→1024 的 1× FFN，不是常见 4×。若用 4096 作为 4× 参考宽度，12 层静态参数差为 75,534,336。源码来源可以解释结构出处，却没有隔离消融 RMSNorm、1× FFN 或 mask encoder 深度，不能据此反推作者的预算动机或效果贡献。

自注意力与交叉注意力承担的职责也不同：双向 self-attention 让 64 个动作位置在同一层交换信息，cross-attention 再让每个动作查询读取当前条件。由于这里不是因果 mask，自注意力看到整个动作块并不等于“未来真值泄漏”；它看到的是同一去噪步中的带噪动作表示。另一方面，能读取全部条件也不保证模型一定使用了某个模态，单次 attention 权重更不能直接当作因果贡献。

八、输出头与 Diffusion 边界

12 层后动作表示仍为 64×1024，经最终 RMSNorm 与 Linear(1024,13) 得到 64×13。主配置 prediction_type: epsilon，所以该 tensor 是当前扩散时间步的噪声估计 ε̂θ，不是已经反归一化、可以直接下发机器人的动作。

Architecture 在这里停止。前向加噪、epsilon MSE、Immiscible batch matching、scheduler、16 步 DDIM 逆过程与最终动作反归一化全部由 Diffusion 页面解释。把架构输出称为“64 步最终轨迹”会同时混淆神经网络输出语义与采样完成状态。

接口验收时应同时保存原始带噪动作、扩散时间步、条件 token 与 epsilon 输出的 batch 对齐关系。只验证末端 64×13 形状，无法发现时间步错配、条件来自另一观测或 action horizon 切片错位。固定公开实现没有在 tensor 内嵌这些 provenance 字段，所以这里记录的是跨页合同要求，而不是声称现有模型自动携带完整追踪元数据。

两个 DINO backbone 都是 frozen/eval/no-grad；可训练模块包括 mask encoder、head/wrist/state nets、action input projection、action position embedding、condition position embedding、timestep MLP、12 个 RDTBlock 和 final output head。冻结 backbone 仍占 checkpoint、内存和计算。源码打印 obs_encoder.parameters() 总数时没有过滤 requires_grad，不能把该日志直接当成可训练参数数。

这份 ledger 还给出了快速逆向核对方法：若观测总长度不是 2739，先分别检查两个 37×37 网格和单个状态 token；若条件长度不是 2740，再检查时间 token 是否恰好追加一次；若动作侧长度不是 64，则检查 horizon 与动作位置编码，而不要改动视觉分段来“凑齐”维度。该方法只用于定位静态接口差异，不表示实际数值有限、无 NaN 或语义顺序正确。

精确总数与论文约数并不冲突：前者是指定实现假设下逐项相加，后者是论文层面的规模表达。若库版本改变 RMSNorm 参数化、Linear bias 设置或 attention 内部投影，静态精确数就需要重算；不能保留旧总数并仅更新文字。两个冻结 DINO 也不计入“可训练参数”表，却仍属于完整部署资源的一部分，因此该表不能被当成模型文件大小或峰值显存表。

十一、形状耦合、可选 mask 与证据缺口

ObsEncoder.output_shape() 硬编码 (1,2739,feature_dim) 与 [1369,1369,1]，控制器据此创建 2740 长 condition position embedding 和可选 attention mask；action position embedding 长度固定为 64。改变 resize、patch size、backbone width、观测步数或 action horizon 时，必须联合审查投影层、segment lengths、两套位置编码、mask 边界、配置与 checkpoint。只改一处可能得到 shape error、错误 segment mask 或不兼容 checkpoint。

CrossAttention 实现训练期四种屏蔽模式：head 0.1、wrist 0.1、head+wrist 0.1、none 0.7；state/time token 不被这些模式屏蔽。它只在 use_attn_mask=True 且 training 时启用，主配置为 False。每次 cross-attention 调用为整个 batch 抽一个模式，12 层可分别抽样；不是逐样本独立。

论文附录称 Figure 4 聚合所有 denoising steps、DiT layers、attention heads 与 action tokens；固定公开 gen_attn_map 却取前两个样本并使用 attn_weights[:2, :, 0, :]，只保留首动作 token。状态应记为 UNRESOLVED_VERSION_OR_SCRIPT_GAP，不能声称当前脚本直接复现论文图，attention 也不是因果证明。

非抓取变体使用双 ViT-B/14、action horizon 100、约 106M 可训练参数，属于另一配置，不得混入主抓取 ledger。页面不新增装饰图片，以数据流、账本和明确文本为主；表格在窄屏横向滚动，状态不只靠颜色表达。

变更门应以依赖闭包为单位：分辨率或 patch size 变化会触及两个视觉网格、head 融合、条件长度和位置编码；action horizon 变化会触及动作容器、位置编码、训练切片与下游采样；状态维度变化会触及 state_net 输入和 13 维动作/状态语义核对。任何一类变更都需要重新生成 tensor ledger、参数 ledger 与跨页合同，并确认 checkpoint 是否兼容。当前页面只描述固定版本，不把这些可能修改写成已经支持的动态能力。

静态验收还要把“存在”与“启用”分开记录。可选 attention mask 的代码存在，并不等于主配置已启用；可视化脚本存在，也不等于它与论文图的聚合口径一致；另一变体存在，更不等于主抓取配置可以直接切换。对这些分支，本页保留开关值、适用条件和未解决状态，拒绝用可能性语言替代当前事实。后续若固定提交、论文版本或主配置改变，应先更新证据锚点，再重跑形状、参数和接口检查，不能把旧结论自动迁移到新版本。

页面结论仅适用于这里明确固定的论文、源码提交和主配置，未覆盖未来版本。
