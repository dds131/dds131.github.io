OpenVLA 总览/网络架构/动作 Token 化与量化误差

REPRESENTATION · FIXED BASE-7B RELEASE

物理动作 → `q01/q99` 归一化 → `[-1,1]` 均匀离散 → 动作 token ID → Llama 完整词表生成 → 中心值 → 反归一化。

固定实现有 256 个边界点、256 个合法动作 token ID，却只有 255 个不同解码中心。动作映射以基准词表 32,000 计算，语言模型输出宽度则是 32,064；这两个口径不能互换。

256 boundaries255 centers256 legal IDs · 31744…31999最高两个合法 ID 同中心invalid ID 当前会静默裁到端点

统计量、维度顺序、单位、坐标系和 unnorm_key 绑定必须由下一页 OXE Data 提供；缺少这些字段时，本页只能解释数值映射，不能形成可部署 policy I/O。

上一知识点：网络架构与 Prismatic 主干下一知识点：OXE 数据与配方筛选

一眼看懂：连续动作如何进入语言词表

  1. 物理动作 `a`
  2. `q01/q99` 归一化
  3. `digitize` 得标签 `d`
  4. `t=32000-d`
  5. LM 生成 token
  6. 索引裁剪后取中心 `c_k`
  7. 按统计量反归一化为 `â`

编码与解码使用三种不同整数：d 是离散标签，t 是词表 token ID，k 是中心数组索引。它们的固定关系是：

encode: a --normalize--> y --digitize--> d --(32000-d)--> t
decode: t --(32000-t-1)--> k --clip[0,254]--> c_k --unnormalize--> â

架构页交给本页的是 32,064 维完整词表 logits，而不是动作词表硬 mask。因此“LM 生成了一个有限 ID”不等于“该 ID 是合法动作 token”；合法性必须单独验证。

source_page_id: openvla-architecture
target_page_id: openvla-action-tokenizer
navigation_relation: next-knowledge
creates_prev_edge: true
accepted_architecture:
  lm_hidden_width: 4096
  lm_vocab_width: 32064
  output_interface: full-vocabulary-logits
  decoding_family: autoregressive-next-token
  hard_action_vocab_mask: false

数据先决条件：统计量、维度和 unnorm_key

Tokenizer 只定义通用数值映射。一个可解释动作向量至少依赖：dataset_key、action_dimension_order、每维 coordinate_frame 与 units、q01、q99、mask、min、max、统计计算范围与版本 provenance，以及推理时 unnorm_key 到统计注册表的绑定。本页不填任何具体 OXE 数据集数值，也不假定动作一定是 7 维。

固定 HF 实现的 _check_unnorm_key 只支持两种情况：未显式给 key 时注册表恰好只有一个选项；或显式给出的 key 确实存在。它不会“猜测最相似的数据集”。

为什么下一页必须是 OXE Data，而不是 Training？没有数据集统计、维度顺序、单位、坐标系和 key 绑定，token 无法恢复为可解释的物理动作，训练标签也缺少可审计来源。下一页将提供这些字段及其血缘。
必需字段 Owner 缺失时的后果
dataset key / unnorm_key binding Data 不能选择反归一化统计
action dimension order Data token 后缀位置没有物理语义
coordinate frame / units Data 解码值不可解释或组合
q01 / q99 / mask Data 无法执行匹配的正反归一化
min / max Data 无法识别常量维
statistics provenance Data 无法审计统计与 checkpoint 是否匹配

归一化：q01/q99、mask 与常量维

对第 j 维，记 L_j=q01_j、H_j=q99_j、R_j=H_j-L_j、ε=1e-8。当 mask_j=true：

y_j = clip(2(a_j-L_j)/(R_j+ε)-1, -1, 1)。

自然语言等价：把 q01 映到约 -1、q99 映到约 1，然后把尾部值裁进 [-1,1]。当 mask_j=false，上游输出 y_j=a_j；但 ActionTokenizer 随后仍会把它裁到 [-1,1]，所以 false 不表示无限范围原样穿透。

schema: openvla.normalization-contract.v1
inputs:
  action: a
  lower_quantile: q01
  upper_quantile: q99
  mask: per-dimension-boolean
epsilon: 1.0e-8
masked_true:
  formula: clip(2*(a-q01)/(q99-q01+epsilon)-1,-1,1)
masked_false:
  formula: a
tokenizer_postcondition:
  formula: clip(y,-1,1)
constant_dimension_handling:
  owner: rlds-data-pipeline
  behavior: set-normalized-value-to-zero
evidence: [G4, G2]
情况 数据管线输出 Tokenizer 后续
mask=true 且非退化 q01/q99 映射后裁剪 再裁到 [-1,1]
mask=false 原值 仍裁到 [-1,1]
metadata min==max 数据管线显式置零 落入零附近的离散标签

常量维必须单列：仅靠 R+ε 不会自动给出安全行为，反而可能放大噪声。解码时，mask=true 使用 â_j=0.5(c_j+1)(H_j-L_j)+L_j；mask=false 保留中心 c_j，不做 q01/q99 反映射。mask 长度与动作维数的一致性验证由 Deployment 负责。

256 个边界点如何产生离散标签

固定实现以 np.linspace(-1,1,256) 生成含端点的边界：

b_k=-1+2k/255，k=0,…,255。

因此边界点数为 256、相邻间距 Δ=2/255≈0.0078431373、相邻区间数为 255。相邻平均得到 255 个中心：c_k=-1+(2k+1)/255，k=0,…,254。这就是“256 boundary points”与“255 center values”的来源。

schema: openvla.uniform-boundary-contract.v1
normalized_domain: [-1, 1]
linspace:
  num_points: 256
  endpoint: true
  boundary_formula: b_k=-1+2k/255
spacing: 2/255
adjacent_interval_count: 255
center_count: 255
center_formula: c_k=-1+(2k+1)/255
center_index_domain: [0, 254]
evidence: [G2, N1]

固定调用 np.digitize 没有传 right，所以采用 NumPy 1.26 的 right=False。递增边界的一般规则为 bins[d-1] ≤ y < bins[d]，而输入在调用前已裁进 [-1,1]。

归一化值 digitize 标签 d token ID t=32000-d 解码中心索引
y=-1 1 31999 0
-1≤y<b_1 1 31999 0
b_k≤y<b_{k+1} k+1 31999-k k，其中 k=1,…,254
y=1 256 31744 原始 255，裁为 254

端点是 off-by-one 的关键：y=1 得标签 256，而不是 255；y=-1 得标签 1。浮点打印差异不代表多了一层离散级别。

动作 token ID 与 32,000/32,064 双口径

固定训练仓库的 tokenizer 基准词表是 V=32000；固定 HF 配置的语言模型输出宽度是 32064，并按 64 对齐，pad_token_id=32000。动作 ID 使用前者计算：t=32000-d，其中 d∈{1,…,256}。

  1. `0…31743` 普通或非动作候选区
  2. `31744…31999` 合法动作 ID
  3. `32000` PAD
  4. `32001…32063` padding 后输出行

31743 是开阈值，不是合法动作 ID；31744 对应 d=256，31999 对应 d=1。ID 与离散标签反向排列，所以 token ID 较大不表示物理动作较大。32,001…32,063 也不是“额外 63 个动作 token”。

schema: openvla.action-token-id-contract.v1
tokenizer_base_vocab_size: 32000
lm_output_vocab_width: 32064
pad_to_multiple_of: 64
pad_token_id: 32000
discrete_label_domain: [1, 256]
encode_formula: token_id=32000-discrete_label
legal_action_token_id_domain: [31744, 31999]
open_threshold: 31743
predicate: token_id>31743 and token_id<32000
padded_or_special_rows: [32000, 32001..32063]
evidence: [G2, H2, H3]

所有动作维共享同一组 256 个 ID。维度语义来自后缀中的位置与 Data schema：第一个 token 不天然代表 x，最后一个 token 也不天然代表夹爪；同一 ID 位于不同动作维时可以对应不同物理量。

论文—实现术语差异（未消解）：论文描述每维 256 bins / 最后 256 个词表 token；固定实现使用 256 个 boundary points、255 个 center values 与 256 个合法 ID。本站同时保留两种证据，不把实现称为论文错误，也不猜测作者为何使用不同的 “bin” 粒度。

训练路径：字符串回环与后缀一致性

固定 RLDSBatchTransform 的链路不是把整数 ID 直接塞进已完成的 prompt：上游先规范化动作，ActionTokenizer(action) 计算 ID，基础 tokenizer 把这些 ID decode 为 token 字符串，动作字符串被拼入完整 prompt，最后基础 tokenizer 再编码整个 prompt。Training 随后拥有 label 前缀遮罩、EOS 与 loss 细节。

  1. normalized action
  2. expected action IDs
  3. decode 成 token string
  4. 渲染完整 prompt
  5. 重新 encode
  6. 提取末尾 D 个 ID
  7. 逐项核对 ID 与顺序
schema: openvla.training-roundtrip-contract.v1
path:
  - normalized-action
  - action-tokenizer-ids
  - base-tokenizer-decode-to-string
  - render-full-prompt
  - base-tokenizer-encode-full-prompt
required_invariant:
  suffix_length: equals-action-dimension
  suffix_token_ids: equals-expected-action-token-ids
  order: equals-data-action-dimension-order
context_requirement: verify-on-fully-rendered-prompt
insufficient_checks:
  - encode-decode-on-isolated-token-list-only
  - decoded-string-visual-inspection
  - action-token-count-without-id-equality
training_ownership_excluded: [label-prefix-mask, eos-supervision, loss-reduction]
evidence: G3

孤立地验证 encode(decode(ids))==ids 不够：prompt 边界空格、特殊 token 策略和上下文切分都可能改变完整样本的后缀，文本长度还影响 label 切片位置。合格检查必须在完整渲染 prompt 上提取末尾 D 个 ID，逐项验证长度、值和 Data 定义的维度顺序；EOS 是否监督由 Training 决定。

推理路径：生成、后缀切片与反量化

fixed HF predict_action 先按 unnorm_key 取得统计，从 q01 长度得到动作维数 D，再调用 generation，取返回序列最后 D 个 token ID，映射到中心，并按 mask 反归一化。

schema: openvla.inference-detokenization-contract.v1
action_dimension_source: norm_stats[unnorm_key].action.q01.length
generation:
  max_new_tokens: D
  semantic: upper-bound-not-exact-length-proof
selection:
  expression: generated_sequence[-D:]
token_to_center:
  raw_index: 32000-token_id-1
  clipped_index: clip(raw_index,0,254)
  output: center[clipped_index]
unnormalization:
  mask_true: 0.5*(center+1)*(q99-q01)+q01
  mask_false: center
evidence: H3

max_new_tokens=D 表示最多生成 D 个新 token，不证明一定得到恰好 D 个。若 EOS 或其他停止条件使 generation 提前结束，fixed code 仍切最终 D 个序列 ID，因而可能把 prompt 尾部混入动作后缀。这是从切片逻辑得到的 site-derived risk，不是本地运行观察。

固定部署脚本的 do_sample=false 可以描述为每步确定性贪心选择，但不等于全序列 MAP，不保证 ID 落入动作范围，也不保证时间平滑或控制安全。

归一化输出不会恰好达到 ±1：c_0=-1+1/255，c_254=1-1/255。在 mask=true 且只看区间几何时，物理端点内缩 R/510；最高两个合法 ID 都解码到最大中心。

图中阶梯只示意中心量化，不按像素逐一画出 255 级，也不表示数据分布或出现频率。虚线是理想 ŷ=y，实线是中心近似；两端是输入裁剪区。

令精确归一化中的 y=2(a-L)/(R+ε)-1、解码中心为 c，而反归一化使用 R=H-L，则非裁剪区：

â-a = R(c-y)/2 - ε(y+1)/2。

第一项是均匀中心近似，第二项来自归一化分母 R+ε 与反归一化使用 R 的口径差。保守界为 |â-a|≤R/510+ε。若进一步假设区间内均匀、忽略 ε 和尾部/别名效应，教学近似为 MSE≈(R/255)^2/12；它不是论文或本地评测结果。

非法输出、夹爪和安全边界

mask=false 只表示不做 q01/q99 正反映射，不自动表示该维是夹爪、二值、无裁剪、无量化误差或无需单位。数据 transform 可能执行相对转绝对、符号翻转、二值化和维度重排；Tokenizer 只看到最终数值向量。

“末维是夹爪且正值表示闭合”不是 ActionTokenizer 的通用合同；必须查目标数据集 transform 与 Data 页 action schema。
