openpi-RLT ④：E-2、F、G 离线数据流水线

从纯 VLA 加人工接管的 E-2 数据采集，到 Actor-Critic 离线预训练和原始动作安全闸，解释数据口径、过拟合判据与上机准入

总览 三阶段 RL-Token 运行架构 E-2 / F / G L4 在线训练 工程修复 结果与归因
E-2 collectF offline trainG safety gate

先采到有来源语义的真机 Replay，再离线把 Actor 训到可控范围，最后检查原始输出是否具备上机资格。

阶段漏斗

E-2 · 真机采集

冻结 VLA 为主，人类在跑偏时接管；保存逐步实际动作、BASE / HUMAN / MIXED 来源、奖励和完整 step trace。

数据质量闸

检查规模、成功 episode、BASE 比例、退化动作和夹爪档位。

F · 离线预训练

Actor 在 BASE chunk 贴住 reference，在 HUMAN / MIXED chunk 学习记录的实际动作；Twin Critic 同步训练。

G · 动作准入闸

在安全整形前检查 Actor 原始输出的三项硬条件；100% 通过才具备进入 L4 的必要资格。

E-2：数据不是“40 条成功演示”

40episodes
2,811写入 transitions
2,443BASE transitions
368HUMAN transitions
246采集期 drop，未写入
33 / 40含人工接管的成功

82.5% 只说明这 40 条采集 episode 在允许人类接管的条件下有 33 条被判为成功。它不能回答纯 VLA 或 RLT actor 单独完成任务的概率。

这里还有三个不能相加的计数：246 条在采集期因 drop_transition 没有写入 journal；后验数据质量闸对已写入数据的结论是 40/40 episodes 通过、额外剔除 0 条；Replay 中有 32 条 episode 带正奖励。最后一个数字与 33 条 success 相差 1，说明“运行时成功标志”和“可用于训练的 +1 奖励”必须分别审计。

数据密度与构成

派生指标 数值 计算与含义
采集候选 transition 3,057 2,811 写入 + 246 采集期 drop
写入率 / 采集期 drop 率 91.95% / 8.05% 分母为 3,057；不含后验质量闸，因为后验额外剔除为 0
每 episode 写入均值 70.3 2,811 / 40；是均值，不代表固定 episode 长度
BASE / HUMAN 构成 86.91% / 13.09% 2,443 / 368，占已写入 transition
source=all 划分 train 2,671 / val 140 95% / 5%
source=base 划分 train 2,321 / val 122 只从 BASE 子集形成
含人工接管的完成率 82.5% 33 / 40；只能评价这次采集流程，不能当自主成功率

这些比例只描述 E-2 数据资产。特别是 BASE 占 86.91% 不等于“86.91% 的 episode 无人工接管”，因为 source 是逐 transition 归因；同一 episode 可以同时包含 BASE、HUMAN 或 MIXED 段。

质量闸

判据 准入线 为什么
Transition 总数 ≥ 600 满足 warmup 最小 replay
成功 episode ≥ 1 需要至少一条正奖励链
BASE 占比 ≥ 50% 防止数据被人工动作完全主导
动作退化 七关节 |action − proprio| 的 p95 < 0.01° 排除动作块退化成当前状态拷贝
夹爪覆盖 每条 episode 不能恒定；全局三档 {0, 0.5, 1} 均出现 避免没有真实闭合动作或缺少必要档位

E-2 采集与质量闸命令

以下是已验证的终端编排说明，不是无人值守脚本。e2_control.sh 会连接真实机械臂，并要求操作者现场输入大写确认；必须由受训人员在清场、急停可达、夹爪与相机就绪后人工执行。网页仅保留仓库相对命令和变量，不包含机器地址或私有绝对路径。

先在每个终端约定本地变量：

RLT_ONLINE=<OPENPI_RLT_ONLINE_RM75_DIR>
RUN="$RLT_ONLINE/tools_e2"
ROBOT_ROOT=<RM75_ROBOT_PROJECT_DIR>
ARTIFACTS=<RM75_RLT_ARTIFACT_ROOT>
PY_OPENPI=<OPENPI_PYTHON>
PY_CONTROL=<CONTROL_PYTHON>

尖括号是占位符，不是可直接执行的字面路径。E-2 必须按下表顺序启动，并等待“就绪证据”后再开下一项。

终端 命令 作用与等待条件
0 bash "$RUN/e2_cleanup.sh" --orphans && bash "$RUN/e2_cleanup.sh" --verify-only && bash "$RUN/e2_pre.sh" 只清本项目孤儿进程，随后检查端口、相机、GPU、共享内存并运行 E-2 前置闸；任一项失败时停止。
1 cd "$ROBOT_ROOT/vr_teleop_rm75_gripper" && bash run_gripper_daemon.sh 启动夹爪 daemon；它是控制端处理夹爪动作的硬前置。
2 cd "$ROBOT_ROOT/data_collection" && bash run_gripper_state_pub.sh 发布真实夹爪开口状态；必须等到已定位 gripper_joint，否则 state 第八维不可信。
3 bash "$RUN/e2_machine_a.sh" 启动冻结 VLA + RL-Token 特征服务；等待服务创建完成，通常约 75 秒。
4 bash "$RUN/e2_control.sh" 唯一连接机械臂的控制端；现场确认后才允许动作，负责 VR 接管、三闸与实际执行动作回传。
5 bash "$RUN/e2_replay.sh" E-2 只启动 Replay Manager，不启动 Actor/Learner；rollout 因而回退到 VLA reference，形成 BASE 数据口径。
6 MAXCHUNK=300 EPS=20 bash "$RUN/e2_rollout.sh" 最多采 20 条 episode，每条最多 300 个 chunk；绑定运行信号并写 Replay journal。
7 "$PY_CONTROL" "$RUN/e2_console.py" 键盘裁判台；s / f 是成功或失败奖励语义的唯一来源，x + d 用于作废坏 episode。
8 "$PY_CONTROL" "$RUN/e2_monitor.py" 汇总进程、episode、source 和写盘状态；只监视，不产生奖励。
9 "$PY_CONTROL" "$RUN/e2_cam_watch.py" 独立检查三路相机健康，避免把断流误写成策略失败。
参数 作用 为什么不能随意改
--orphans 只清理本项目识别出的孤儿进程；默认不动夹爪。 不能替换成宽泛的 pkill -f，后者可能命中无关任务。
--verify-only 只做收工/开跑前检查，不启动任何服务。 它通过不代表机械臂区域已清场，现场安全检查仍由操作者负责。
MAXCHUNK=300 每条 episode 的 chunk 上限。 脚本默认是 40；本任务通常需要 65–85 个 chunk，因此必须显式改为 300，避免尚未完成就被截断。
EPS=20 本次 rollout 最多处理 20 条 episode。 是运行预算，不是训练 epoch；可提前人工结束。
不启动 Actor/Learner 保持 E-2 的动作来源为冻结 VLA，加人工接管纠正。 若误起 Actor，BASE 样本就不再是纯 VLA reference 口径。

采集完成后，先审计原 journal，再另写 clean 版本：

JOURNAL="$ARTIFACTS/e2_base/replay/replay_journal.pkl"
"$PY_OPENPI" "$RLT_ONLINE/tools/check_base_data_quality.py" \
  --replay-path "$JOURNAL" \
  --write-filtered "$ARTIFACTS/e2_base/replay/replay_journal.base_clean.pkl"

--replay-path 指定只读检查的输入 journal；--write-filtered 把通过硬闸的整条 episode 写到新文件，不覆盖原始证据。逐 episode 硬闸检查 NaN/Inf、|action − proprio| 的七关节 p95、夹爪是否恒定；整体准入再检查 transition 总数、正奖励 episode、BASE 占比，以及三档 {0, 0.5, 1} 是否都出现。后一个判据只证明必要档位有覆盖，并不检查所有夹爪值都严格落在三档网格上。本次 40 条 episode、2,811 条 transition 全部通过该闸。

F：真正部署的是 source=all

种子生成、冒烟与正式训练

export PYTHONPATH="$RLT_ONLINE/openpi_side:$OPENPI_SOURCE/rlt_online_rl/src:$OPENPI_SOURCE/packages/openpi-client/src:$OPENPI_SITE_PACKAGES"
export RM75_DELTA_DIMS=7

TASK="$ARTIFACTS/f_offline_<RUN_ID>"
"$PY_OPENPI" "$RLT_ONLINE/tools/rm75_make_task_seed.py" \
  --config "$RLT_ONLINE/configs/rm75_pick_cube/online_rl_f7.yaml" \
  --task-dir "$TASK" \
  --replay "$ARTIFACTS/e2_base/replay/replay_journal.pkl"

STEPS=300 TASK="$TASK" bash "$RLT_ONLINE/tools/run_f_offline_train.sh"
TASK="$TASK" bash "$RLT_ONLINE/tools/run_f_offline_train.sh"

第一条训练命令只跑 300 步冒烟；确认 snapshot、损失和诊断输出正常后，第二条不设置 STEPS，按脚本正式预算训练。两条命令不需要 Machine A、VR 或机械臂。

参数 / 环境项 作用 本项目约束
PYTHONPATH 同时暴露本项目补丁、上游在线 RL 源码、OpenPI client 与既有依赖。 缺任一段可能在生成 snapshot 或反序列化配置时才失败。
RM75_DELTA_DIMS=7 把上游六关节 delta 口径运行时扩成七关节。 漏设时程序可能仍能跑，但关节 7 的动作与正则语义会静默错误。
--config ...online_rl_f7.yaml 指定 RM75 七关节度制配置。 它写入 delta_weight=0.014415；换回旧配置会把不适用的 10.0 带进 snapshot。
--task-dir 建立标准 task 目录和 actor_snapshot 种子。 上游训练会从 replay 路径上溯寻找 snapshot，目录层级不能任意改平。
--replay 指定 E-2 原始 journal。 该路径决定训练数据，不应误指向 L4 追加后的 journal。
STEPS=300 仅覆盖本次冒烟训练步数。 300 步结果只验证链路，不作为可上机模型。
TASK 把生成种子与两次训练绑定到同一 task。 冒烟通过后正式训练仍需核对输出目录，避免把临时结果当 bundle。
脚本默认 DIMS=7 / DW=0.014415 固定七维正则切片与度制权重。 启动日志必须显示权重自洽、偏差 0.00%。

Actor 的 BC target 是条件目标：

bc_target = recorded action_chunk   if source_chunk ∈ {HUMAN, MIXED}
bc_target = VLA ref_chunk           otherwise

MIXED 的 action_chunk 是逐步实际执行动作组成的混合块，不应全部改称“纯人类动作”。因此部署模型必须看包含 HUMAN / MIXED 的 source=all 结果；只看 BASE 子集会丢掉学习纠正动作的目标。

此处 fit 也不是训练时的条件 BC loss，而是在原始物理单位上度量 Actor 均值与冻结 VLA reference 的平均绝对偏差：

\[\operatorname{fit}(D) =\frac{1}{|D|\cdot10\cdot8} \sum_{x\in D}\left\lVert a_{\mathrm{actor}}(x)-a_{\mathrm{ref}}(x)\right\rVert_1, \qquad \operatorname{gap}=\frac{\operatorname{val\_fit}-\operatorname{train\_fit}}{\operatorname{train\_fit}}.\]
口径 train / val n train_fit val_fit gap 正确用途
source=all 2,671 / 140 0.5003 0.4879 −2.5% 部署模型主要视角
source=base 2,321 / 122 0.3457 0.3395 −1.8% “是否贴住 VLA”子集诊断
项目早期汇总常引用 0.3395 / −1.8%，但它是 BASE 子集。完整呈现必须先报告 source=all 的 0.4879 / −2.5%，再用 BASE 解释 reference 拟合情况。负 gap 只表示本次切分中验证误差略低于训练误差，不表示“负过拟合”或策略优于 reference。

为什么旧阈值不适用

上游曾使用 val_fit 小于 0.02，但该值来自弧度动作口径。本项目关节使用度制，18 次历史训练均在约 0.55–0.94 量级，不可能靠同一阈值验收。

本项目采用：

val_fit < 0.5
gap = (val_fit - train_fit) / train_fit < 15%
val_max < 5.0
val_joint8 < 0.125
seeds >= 4

这些是本项目基于度制历史 run 制定的工程闸门，必须在相同 source、切分和推理模式下比较；它们不是跨机器人通用常数。

从 787 条到 2811 条

787 · BASE gap+38.5%–+43.9%
2811 · ALL gap−2.5%
2811 · BASE gap−1.8%

早期小数据 run 同时存在弱正则、seed 不稳和小验证集问题；图中的 +38.5%～+43.9% 是四个 source=base 历史 run。扩充到 2,811 条后，本次切分不再出现正的 train/validation gap；但验证集仍只有 source=all 140 条、source=base 122 条，且来自同一轮采集。因此它只能支持“这次切分未见原来的大 gap”，不能证明跨场景泛化，也不保证动作比 VLA 平滑。

G：检查整形前的原始 Actor

准入命令与退出语义

"$PY_OPENPI" "$RLT_ONLINE/tools/eval_chunk_safety.py" \
  --replay-path "$ARTIFACTS/e2_base/replay/replay_journal.pkl" \
  --model-dir <F_STAGE_MODEL_DIR> \
  --fail-under 100.0
参数 作用 效果
--replay-path 提供代表真实 E-2 状态分布的评估集。 闸门结论只对这批状态与当前采样方式成立，不能外推到所有场景。
--model-dir 指向 F 段 Actor 输出目录。 应核对模型版本与计划上机的 bundle 完全一致。
--fail-under 100.0 要求通过率不得低于 100%。 任一非有限值、首步偏差或块内跳变违规都会令命令非零退出，从而阻止后续上机步骤。

该工具评估的是 Actor 的确定性均值原始输出，不先经过运行时安全整形。这样才能发现“整形后看似安全、模型本身已经漂移”的情况。命令通过只是必要条件，不覆盖软限位、奇异区、夹爪三值和任务成功率。

GATE 01

数值有限

任何 NaN 或 Inf 都直接阻止上机。

GATE 02

首步关节偏差闸

Actor 第一帧的七关节不能离当前关节状态超过 10°。

GATE 03

块内关节跳变闸

动作块内部七关节的相邻帧跳变不能超过 10°。

L4 种子 bundle 在 2,811 条 E-2 Replay 状态上的确定性均值输出通过率为 100%。在线训练后的对应评估曾下降到 99.75% 和 99.90%；这说明 G 闸不只是一次性准入，也能暴露在线策略漂移。不同评估集或采样模式之间不能只比较百分比而忽略分母。

安全整形器能让最终下发动作落在硬阈值内，但它可能掩盖 Actor 本身已经恶化。G 闸必须检查整形前的原始输出，且准入线是严格 100%。该 100% 只覆盖有限性、关节首步偏差和关节块内跳变；软限位、关节 4 奇异区和夹爪非三值只做诊断统计，更不证明任务会成功。

两种低质量人工数据处理

第七路 · 三态自动判据

chunk 内存在人工控制、整块没有握住 Grip 且七关节变化小于 0.3° 时命中。默认 log 只统计；显式切到 drop 后才丢弃“挂着接管模式但没有示范”的空块。

丢段键 · 人工语义

操作员发现刚才纠正做错时，可回溯标记该段。它处理的是算法无法仅凭位移判断的“动作有变化但质量差”。

第七路先以 log 模式观察误杀，再转 drop；项目验证轮中 drop 模式命中的 39/39 个 chunk 均未进入 Replay。它仍不能判断“动作有变化但语义上做错了”，所以需要丢段键补上人工判断。
