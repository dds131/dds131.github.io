本页要建立的核心认识只有一句：论文中的 π0.5 完整训练/推理配方，大于当前 openpi 的公开 pi05=True 路径。当前代码直接覆盖流匹配动作头、π0.5 的状态 token 格式和 AdaRMS 结构，但不包含论文的 FAST 交叉熵训练与高层文本解码。README 明确写了前一项的范围，仓库贡献者又在 issue #647 确认当前只支持动作解码；判断依据是函数入口与官方项目材料，而不是关键词检索。
措辞说明。本页把三种情况分开：① 公开范围缺失（FAST 组合损失、高层解码）；② 实质等价但记号相反（流匹配时间）；③ 数值确实不一致（注意力查询头数）。范围不同不自动等于缺陷，也不等于公开仓库能复现论文全部实验；每条结论都注明证据边界。

一、本页在专题中的位置

本页是专题的对照与勘误页：把散落在各页的「论文与实现对不上」集中收口，并把 π0.5 特有的反直觉现象连同成因整理成一张可查的清单。

与兄弟页的分工。本页只做清单与核验，不重复各页已经做过的成因分析。凡已在别处深讲的现象，本页只给一句话结论与跳转：V-E 的两个反直觉结果在 ⑤ 第七节，WD 消融方向不一致在 ① 第七节，时间方向代换在 ③ 第七节，代码走向在 ⑥。

二、官方明确说明了什么

openpi 官方 README 把仓库里的 π0.5 介绍为使用知识隔离训练的升级版，并明确限定：π0.5 的训练与推理目前都只支持流匹配头。

这一句同时给出了两条关键信息：

信息 意味着什么
仓库把 π0.5 描述为以知识隔离训练的升级版 公开模型不应直接等同于 2025 年 4 月论文的原始训练运行；README 没有给出二者逐 checkpoint 的对应关系
本仓库对 π0.5 只支持流匹配头 论文配方中依赖离散动作 token 的那部分（FAST 交叉熵）不在公开训练路径上

下面六条里，损失/分词器由 README 与源码共同证明，高层解码还得到维护者答复；其余三条分别来自 checkpoint 说明、结构配置与等价时间换元。

三、六条可核验的差异

3.1 compute_loss 中没有交叉熵项

论文怎么说 源码是什么 怎么核验
IV-B 的 Eq. (1) 是交叉熵项加 \(\alpha\) 倍流匹配项；IV-D 给出后训练 \(\alpha=10.0\) pi0.py 的 compute_loss() 只返回沿动作维求均值的流匹配平方误差 直接检查函数返回值，并与 README“只支持流匹配头”的范围说明交叉核验

函数末尾只有：

v_t = self.action_out_proj(suffix_out[:, -self.action_horizon:])
return jnp.mean(jnp.square(v_t - u_t), axis=-1)

该函数没有产生文本 logits，也没有计算 FAST 动作 token 的交叉熵。返回值仍保留 batch 与动作时域维，外层训练器再聚合；“只有流匹配”不等于这里已经返回一个标量。

3.2 FAST 分词器只服务于 PI0_FAST，不服务于 PI05

论文怎么说 源码是什么 怎么核验
IV-B 写明模型用 FAST 分词器把动作表示成离散 token 来训练 training/config.py 的 ModelTransformFactory 中，ModelType.PI05 分支用的是 PaligemmaTokenizer；FASTTokenizer 只出现在 ModelType.PI0_FAST 分支 阅读 ModelTransformFactory 的三个 case 分支即可直接看到

这解释了一个高频困惑：pi05=True 的训练路径里看到 PaliGemma 分词器，不是配置配错了，而是这条路径本来就不经过 FAST。PI05 分支的分词器调用还多传了一个 discrete_state_input 参数，用于决定是否把状态离散化后拼进 prompt——它与 FAST 是两件不同的事。

3.3 高层子任务解码在仓库中没有实现

论文怎么说 源码是什么 怎么核验
IV-A 与 IV-B：推理时先自回归解码子任务文本，再以它为条件生成动作块 sample_actions() 编码观测、prompt 与状态后直接进入动作专家积分 README 的流匹配头范围；检查 sample_actions()；仓库贡献者在 issue #647 确认当前只支持 action decoding

issue #647 已由仓库 contributor 明确答复并关闭：当前 openpi 只支持动作解码。这个证据比关键词检索更可靠，因为实现可以使用任意命名，而入口函数和项目贡献者答复直接界定了能力。要复现论文分层流程，仍需实现高层文本生成、终止规则、用预测子任务重建低层 prompt，以及两层调度；不能简单把子任务追加到原指令。详见 ⑤ 第九节。

3.4 公开 checkpoint 对应的不是论文里的原始训练算法

论文怎么说 官方仓库是什么 怎么核验
IV-C 与 IV-D：280k 步离散预训练 + 80k 步联合后训练 README 把仓库中的 π0.5 统称为以知识隔离训练的升级版；pi05_droid 又明确写为以知识隔离在 DROID 上微调 阅读 README 的模型介绍与 checkpoint 表；注意 README 未披露 pi05_base 的逐阶段训练日志
「原始 π0.5」与后续知识隔离改进不能当成同一次训练运行。因此公开权重不能被当作原论文 checkpoint 的逐位复刻；但 README 也没有公开足够信息，让我们反推出 base checkpoint 是否沿用了原配方的哪些阶段。能确定的是方法版本不同，不能确定的训练细节不应补猜。时间线与方法差异见 ④ 知识隔离与梯度干扰。

3.5 注意力头数：论文写 18，源码写 8

论文怎么说 源码是什么 怎么核验
附录 A-E：{width=2048, depth=18, mlp_dim=16,384, num_heads=18, num_kv_heads=1, head_dim=256}，动作专家除 width=1024、mlp_dim=4096 外相同 gemma.py 的 get_config：gemma_2b 与 gemma_300m 均为 num_heads=8，num_kv_heads=1，head_dim=256 阅读 get_config 中两个变体的返回值

除查询头数外，页面所列的 width、depth、mlp_dim、num_kv_heads、head_dim 与当前源码配置一致。

不能仅用 num_heads × head_dim 是否等于 width 来判定论文笔误：当前动作专家本身也允许查询投影维度不同于残差宽度。这里能确定的只有“论文表述为 18，当前配置为 8”。加载公开权重时必须使用与 checkpoint 匹配的源码配置；研究论文原始运行时则应保留这一未消解差异。

3.6 时间变量方向相反，但可通过换元等价

论文怎么说 源码是什么 怎么核验
\(\mathbf{a}^{\tau,\omega}=\tau\mathbf{a}+(1-\tau)\omega\)，即 \(\tau=1\) 是真实动作、\(\tau=0\) 是纯噪声 x_t = time * noise + (1 - time) * actions，即 time=1 是纯噪声 对比论文 IV-B 的插值式与 compute_loss 的实现

源码注释也明确说明：实现取 \(t=1\) 为噪声、\(t=0\) 为目标分布，与 π0 论文的时间方向相反。

代换 \(\tau = 1-t\) 后，插值点与目标速度只差随变量方向变化产生的符号约定；两者描述同一条路径，不是算法行为冲突。完整推导见 ③ 第七节，π0 侧讨论见 π0 · 时间方向约定与推理期现象。

3.7 两个 issue 的证据等级不同

Issue 内容 截至 2026-10-08 的状态 能证明什么
#647 询问论文的高层/低层推理代码在哪里 已关闭；仓库 contributor 明确回复当前只支持 action decoding 直接支撑 3.3 的公开实现边界
#816 询问为何 PI05 用 PaliGemma tokenizer、组合损失在哪里 仍开放、无评论 只能说明其他读者遇到同样疑问，不能充当 3.1/3.2 的证明或官方解释

证据优先级应是：README 的范围声明与实际函数入口 > 维护者/贡献者明确答复 > 未获回复的用户提问。#816 可以帮助定位常见困惑，但“另一个人也这样问”不等于独立验证；3.1 与 3.2 仍以源码和 README 为依据。

四、如何解释这些范围差异

六条差异并非同一性质：3.1–3.3 是公开能力范围，3.4 是模型版本，3.5 是未消解的配置数值差异，3.6 则只是等价记号。下面只对公开范围作工程解释，不能用一个“仓库更偏部署”的理由替所有差异定性。

论文明确描述 当前仓库明确公开
280k 离散预训练 + 80k 联合后训练 可下载的 base / fine-tuned checkpoints 与流匹配微调示例
FAST 动作 token 交叉熵 + 连续流匹配 Pi0.compute_loss() 的连续流匹配路径
先生成高层文本，再以子任务为条件生成动作 直接由 observation + prompt 生成动作块
六类内部数据与 HL / VI 标注流程 面向用户数据集的转换、归一化、微调与部署工具

README 说明 base checkpoints 在超过 1 万小时机器人数据上预训练，但没有发布能从当前代码反推出完整 280k + 80k 过程的训练日志、数据混合或 checkpoint 对应表。因此不能断言“论文的离散阶段已经原样发生，收益已固化在公开权重里”，也不能断言缺失组件对微调没有价值。

能作出的工程判断更有限：当前仓库支持从现有 checkpoint 出发做流匹配微调与动作推理；若要复现论文完整配方，FAST 动作监督、高层文本监督、数据混合和调度都需要额外实现/数据。这个范围足以做很多下游实验，但不构成论文全配方的开源复现。

五、反直觉现象清单及底层成因

下表把 π0.5 相关的反直觉现象集中收口。「来源」一栏区分两类：论文实验报告的结果，与本站从源码推出的行为。

1 完整 π0.5 的实验均值超过了作者预设为 “oracle upper bound” 的 human HL 基线；它不是数学上界 论文 V-E ⑤ 第 7.1 节

5.1 连续训练时间与默认 10 个推理节点

这一条从源码可以直接推出，但必须带上默认条件：当 num_steps=10 时，推理不在 \(t<0.1\) 处求值；修改步数后，节点集合也会改变。

训练侧的时间采样（openpi 约定，\(t=1\) 为噪声）：

time = jax.random.beta(time_rng, 1.5, 1, batch_shape) * 0.999 + 0.001

变换后的支持区间为 \([0.001,\,1.0]\)；除端点的测度问题外，内部连续覆盖。Beta(1.5,1) 的密度随 \(t\) 增大，因此更偏向噪声端 \(t\approx1\)。

推理侧的循环（默认 num_steps=10，故 \(dt=-0.1\)）：

dt = -1.0 / num_steps
...
def cond(carry):
    x_t, time = carry
    return time >= -dt / 2
x_0, _ = jax.lax.while_loop(cond, step, (noise, 1.0))

从 \(t=1.0\) 出发，每次先在当前 \(t\) 处求一次速度场再把 \(t\) 减 0.1，循环条件是 \(t \ge 0.05\)。于是实际被求值的时刻只有十个：

\[t \in \{1.0,\;0.9,\;0.8,\;0.7,\;0.6,\;0.5,\;0.4,\;0.3,\;0.2,\;0.1\}\]

\(t=0.0\) 不满足循环条件，不再求值；\((0,\,0.1)\) 区间内的任何时刻也从不被查询。

该怎样理解这组节点。

  • 对单个配对样本，监督目标 \(\epsilon-A\) 不显含 \(t\)；但最优的条件速度场是给定当前 \(x_t\)、观测和 \(t\) 后的条件期望，通常仍会随 \(t\) 改变。不能据此声称模型在低 \(t\) 处的估计质量不重要。
  • 连续时间训练允许推理时改变 num_steps；默认 10 步只查询十个网格点。增大步数会进入 \((0,0.1)\)，这些位置有训练覆盖，只是采样密度较低。
  • 论文在 \(\tau\) 记号下排除 \(\tau>s=0.999\)，并说明只要积分步长 \(\delta>1-s=0.001\) 就不会查询被排除区间，因而最多容纳约 1000 步。对应到源码 \(t=1-\tau\)，训练支持从 \(t=0.001\) 开始；若把步数提高到 1000 以上，就会触及支持区间之外，不能再沿用论文的保证。

顺带说明一处容易搞反的地方：论文与源码都把采样质量放在噪声端，两者并不矛盾。论文说采样分布「强调低时间步」，用的是论文约定（\(\tau\) 小即接近噪声）；源码的 beta(1.5, 1) 质量集中在接近 1.0 处，用的是源码约定（\(t\) 大即接近噪声）。按 \(\tau = 1 - t\) 代换后，两者指的是同一端。

5.2 prompt 超长不报错

PaligemmaTokenizer.tokenize 在超长时的处理是：

if len(tokens) > self._max_len:
    logging.warning(
        f"Token length ({len(tokens)}) exceeds max length ({self._max_len}), truncating. "
        "Consider increasing the `max_token_len` in your model config if this happens frequently."
    )
tokens = tokens[: self._max_len]

只记录 warning，然后从尾部截断。π0.5 尤其需要检查截断位置，因为它的 prompt 把状态串放在指令之后：

Task: {指令文本}, State: {状态整数串};\nAction:

状态整数串本身就有 action_dim 个整数（默认内部宽度 32），数字经过 SentencePiece 后会占用多个 token。发生溢出时，从尾部截断会先破坏末尾的 Action: 标记，再逐步切掉状态串；warning 本身不阻止样本进入模型。若实现论文的分层推理，应以预测子任务重建低层 prompt，而不是无条件追加原指令；无论采用哪种接口，都要重新检查 token 长度。

实践建议：在数据管线里统计截断率，并对关键评测/部署输入选择显式报错或断言，而不是只依赖 warning。π0.5 的 max_token_len 默认是 200，但它只是固定上限，不保证任意指令与状态都完整保留。

六、论文自陈的局限

论文 VI 讨论部分自己列出的问题，按性质分三类。

类别 论文写明的具体问题
仍会犯错 某些环境持续构成挑战（如抽屉上不熟悉的把手、机器人物理上难以打开的橱柜）；部分可观测性带来的困难（如手臂遮挡了本该擦拭的污渍）；高层子任务推理有时容易被带偏（如收纳物品时反复开关同一个抽屉）
提示复杂度受限 模型处理的提示相对简单，能接受的提示复杂度由训练数据决定；要支持更复杂的偏好与指令，需要更精细多样的标注
上下文与记忆有限 模型使用的上下文相对有限；在部分可观测性更强的场景（如需要在不同房间之间移动、或记住物品存放位置的任务）中，更丰富的上下文与记忆会显著提升能力
第一类里的第三项值得与 ⑤ 第二节 对照读：按论文的条件独立结构，低层不读取原始指令，因而不能用它核对高层子任务是否违背整体目标；但低层仍可能因场景不一致而失败，后续高层也可能重规划。论文报告的“反复开关同一抽屉”说明高层会受干扰，不能仅凭这一例断言内部一定在两个固定子任务间振荡。论文提出的方向包括更丰富标注、上下文与记忆；把执行结果用于再训练则是 π0.6 与 RECAP 的主题。
