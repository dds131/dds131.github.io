PPO（Proximal Policy Optimization，近端策略优化）是一类 on-policy 随机策略梯度方法，实践中通常采用 Actor-Critic 结构。一次迭代先冻结行为策略 \(\pi_{old}\) 采集 Rollout，再让学习策略在这批数据上更新。它要处理的核心矛盾是：环境交互昂贵，希望充分使用同一批样本；但更新越多，学习策略越远离生成数据的 \(\pi_{old}\)，基于旧数据的代理目标越可能失真。

PPO-Clip 用采样策略作固定参照，通过概率比、逐样本悲观裁剪目标与有限 Epoch，在数据复用与分布偏移之间建立可操作的平衡；常见工程实现还会增加 KL 监控、早停或自适应学习率作为额外防线。它抑制部分继续远离旧策略的更新激励，但不对参数距离、所有动作的概率比或 KL 施加硬约束。

PPO 在策略优化路线中的位置

方法 用什么估计改进方向 如何控制一次更新 同批数据如何使用
REINFORCE 轨迹回报加权的 Log Probability 梯度 主要依赖学习率 通常一次或少量更新
Actor-Critic 方法族 Critic 提供价值/优势或 TD 信号 取决于具体算法 可为 on-policy 或 off-policy，不能作为单一算法比较
TRPO 新旧策略代理目标 KL 约束的局部二阶近似与线搜索 一批数据求解一个受约束步
PPO 新旧策略概率比加权的优势 裁剪代理目标、有限 Epoch、KL 监控 一个迭代内多 Epoch Mini-batch 复用

策略梯度定理、基线无偏性与 REINFORCE 已在策略梯度专题详解；Actor/Critic 的职责和价值学习见 Actor-Critic 专题；信任域理论、自然梯度、共轭梯度和线搜索见 TRPO 专题。本专题只在用到时回顾结论，不重复已有推导。

一次完整 PPO 迭代

flowchart TB
  OLD["固定采样参照 theta_old"] --> ROLL["N 个并行环境各采集 T 步"]
  ROLL --> STORE["存储 obs、policy/env action、reward、终止/截断、old_log_prob、old_value 与 Bootstrap 信息"]
  STORE --> GAE["沿时间轴逆序计算 GAE 和 Return"]
  GAE --> FLAT["展平或组织为循环序列 Mini-batch"]
  FLAT --> EPOCH["K 个 Epoch：每轮重新打乱"]
  EPOCH --> EVAL["重算 new_log_prob、new_value、entropy"]
  EVAL --> LOSS["Clip Actor Loss + Value Loss - Entropy Bonus"]
  LOSS --> STEP["反向传播、梯度裁剪、Optimizer Step"]
  STEP --> CHECK["KL、clipfrac、entropy、explained variance"]
  CHECK -->|"继续当前批次"| EPOCH
  CHECK -->|"达到 Epoch 或触发早停"| DROP["丢弃整批 Rollout"]
  DROP --> OLD

on-policy 不等于“每个样本只用一次”。 准确说法是：数据由本轮冻结的行为策略 \(\pi_{old}\) 产生，在同一 PPO 迭代中可被多 Epoch、多 Mini-batch 复用；更新结束后整批丢弃，不像 off-policy Replay Buffer 那样跨很多迭代长期使用。

采样时冻结什么

  • old_log_prob：采样策略对 policy_action 的对数概率；若还存在缩放/裁剪后的 env_action，两者必须分字段保存。
  • old_value 与片段末端的 next_value：采样时 Critic 预测，用于 GAE、Return 和可选价值裁剪。
  • advantage 与 return：本专题默认的“冻结目标 PPO”在采样完成后构造一次，同一迭代的多 Epoch 中不随新 Critic 改变。

少数框架/配置会在 Epoch 间重算优势。那是另一种明确的数据—目标契约，不能与“固定优势”描述混用；无论是否重算，行为策略的 old_log_prob、动作表示、有效 mask 和历史条件都必须保持采样语义。

更新时重算什么

  • 当前策略对已存动作的 new_log_prob。
  • 当前 Critic 的 new_value。
  • 当前策略的熵或随机性统计；必须注明是动作变换前还是变换后、按维求和还是求均值。

四条公式串起整个算法

1. 新旧策略概率比

\[\rho_t(\theta) = \frac{\pi_\theta(a_t\mid s_t)}{\pi_{\theta_{old}}(a_t\mid s_t)} = \exp\!\left(\log\pi_\theta(a_t\mid s_t)-\log\pi_{old}(a_t\mid s_t)\right).\]

分母是采样时的固定参照，分子随更新变化。实现用对数概率差取指数，避免小概率直接相除；两项必须对应同一状态/历史、同一实际采样动作表示、同一合法动作支撑集和同一动作变换，否则 ratio 没有预期语义。

2. 裁剪代理目标

\[L^{CLIP}(\theta) = \mathbb E_t\!\left[ \min\!\left( \rho_t(\theta)\hat A_t, \operatorname{clip}(\rho_t(\theta),1-\epsilon,1+\epsilon)\hat A_t \right) \right].\]

min 与 clip 取消某些“朝改善方向走得过远”的额外目标收益，但保留恶化方向的纠错梯度。正/负优势时完整分段形状见近端目标与裁剪机制。

3. GAE 逆序递推

\[\delta_t=r_t+\gamma m_t V_{old}(s_{t+1})-V_{old}(s_t), \qquad \hat A_t=\delta_t+\gamma\lambda c_t\hat A_{t+1}.\]

m_t 控制 Bootstrap，c_t 控制 GAE trace 是否穿过 Episode 边界。真终止、时间截断、环境自动 reset 和 Rollout 片段末端不能用一个含糊 done 简单合并，详见 Rollout、GAE 与批数据。

4. 梯度下降中的常见组合 Loss

\[L_{total}=L_{actor}+c_vL_{value}-c_eH(\pi_\theta).\]

在“优化器最小化 Loss”的口径下，通常取 \(L_{actor}=-L^{CLIP}\)；因此日志中的 policy_loss 正负本身不代表策略变好或变坏。\(L_{value}\) 的归约方式、\(H\) 的分布域/动作维聚合、价值裁剪、共享/独立网络与 KL 惩罚都会改变具体尺度。

这只是常见总式，不是所有实现的数值恒等式；比较系数前必须先统一各分项的符号、均值/求和范围和单位，详见 Loss、优化与更新流程。

PPO 的创新和它付出的代价

创新/价值 解决什么 不能保证什么
一阶近端更新 不用 TRPO 的共轭梯度和线搜索，可用 Adam 和 Mini-batch 不保证严格满足信任域
裁剪代理目标 取消某些过度改善方向的额外激励 不保证 ratio 最终留在裁剪区间
同批多 Epoch 优化 比朴素单步策略梯度更充分使用 Rollout 不能像 off-policy 数据那样跨迭代无限重用
策略+价值+熵组合优化 更新策略、训练 Critic 以改善后续估计并调节探索 同批冻结优势不被新 Critic 回写；共享表示可产生梯度冲突
固定长度并行 Rollout 适配高吞吐仿真和统一 Batch 优化 环境越多不等于样本质量越高

Clip 的边界。 它裁剪的是采样动作概率比对代理目标的贡献，不是参数移动、整个动作分布或 KL 的硬边界。多样本共享网络参数，Critic/Entropy 也可改变共享特征，因此 PPO 仍需监控 KL、clipfrac、熵和动作分布。

训练突然崩溃或增加并行环境后变差 异常诊断 先守实现不变量，再用控制变量实验定位原因
想换成 PPG、MAPPO、RPO、APPO、DPPO 或离开 PPO 改进与研究 已证实基础 PPO 正确，并区分在线交互、数据复用与硬约束需求

专题的共同方法： 公式给出对象，存储契约保证语义，诊断不变量排除实现错误，控制变量实验才支持因果结论。不要用“换算法”绕过尚未核对的数据、动作与评估契约。

适用边界

PPO 的优势是实现相对直接、与随机离散/连续策略兼容、适合并行环境，并在许多基准上形成了成熟工程生态。但它仍是 on-policy：如果真实环境交互非常昂贵，或主要数据来自历史日志/离线数据，标准 PPO 不会因为“稳定”就自动成为合适选择。此时应进入改进与研究页的退出 PPO 决策，与 SAC/TD3、行为克隆或 offline RL 做匹配预算的基线比较。

PPO 解决的是随机策略的更新问题，不自动解决奖励定义、部分可观测、非法动作、探索、硬安全约束或仿真到现实偏差。机器人系统中的限位、急停、碰撞监测和控制器保护应形成独立安全链，不能把 Clip 或较小 KL 当成安全认证。

不保证事项： PPO-Clip 不保证真实回报每次更新后单调上升；不保证 KL 必然低于阈值；不保证价值裁剪、共享网络或更多并行环境总会提高性能；不保证仿真奖励提升可直接转化为真机安全与泛化。
