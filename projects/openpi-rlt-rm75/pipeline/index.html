openpi-RLT ①：三阶段流水线与接口契约

从三相机示范、π0.5 行为克隆、RL-Token 表征到在线 Actor-Critic，逐段说明输入、训练对象、冻结边界、动作口径与验收条件

总览 三阶段 RL-Token 运行架构 E-2 / F / G L4 在线训练 工程修复 结果与归因
BC 基座RL 表征在线策略

三个阶段训练三类对象：先让 VLA 会做任务，再学习紧凑状态接口，最后只在线更新小网络。

把“训练成功”拆成三层，才能避免用 Stage-1 的重建 MSE 替代任务成绩，或用 BC 的 92% 替代 RLT 链路基线。

阶段 主要输入 被训练的参数 明确冻结的参数 本阶段只能证明什么
① π0.5 SFT 三相机示范、语言、八维状态与动作 π0.5 全参数 无 基座已具备长流程任务能力
② RL-Token 基座产生的 prefix hidden tokens RL-Token encoder/decoder π0.5 紧凑表征能够重建本项目选定的 hidden tokens
③ 在线 RL RL token、proprio、VLA reference、奖励与介入数据 Actor、Twin Critic π0.5、RL-Token encoder 小策略可在冻结 VLA 周围进行在线优化

这里的“阶段完成”不是同一个事件：阶段②的 MSE 不能证明机器人成功，阶段③的训练稳定也不能证明策略优于 VLA。只有同口径、零接管的真机 A/B 才能回答最终任务是否改善。

上游只复用，不重复制造

本项目继承两套已经稳定的能力：

  • VR 遥操作与示教数据采集：三相机、七关节与夹爪的同步示范，以及模型失败时的人工接管。
  • π0.5 训练、部署与动作平滑：LeRobot 数据转换、三相机后训练、检查点选择、真机推理和块间融合。

RLT 项目不重写这些系统，而是接收两个稳定输入：动作语义与归一化口径固定的示范数据，以及已经具备任务能力的 step 40000 检查点。

阶段 ①：π0.5 全参后训练

项 本项目口径
数据 1393 episodes，859,154 帧，三相机，八维 state/action
图像槽位 头部、腕部、第三视角；每路 224×224
状态 七关节加连续夹爪，共八维；分位数归一化后离散为文本前缀
动作 前七维相对当前 state 的 delta；第八维夹爪为绝对量
模型输出 action_dim 32，真机使用前八维；action_horizon 50
训练 batch 256，八卡 FSDP；实跑 75,610 步
选择 真机相对较好区间 30000–50000；本项目选 step 40000

设观测时刻为 $t$，未来第 $k$ 步的示范目标由关节角命令和夹爪命令组成；关节编号 $j=1,\ldots,7$。本项目进入策略网络的动作表征为

\[\Delta q_{t+k,j}=q^{\mathrm{cmd}}_{t+k,j}-q_{t,j}, \quad j=1,\ldots,7; \qquad g_{t+k}=g^{\mathrm{cmd}}_{t+k}.\]

关节 delta 均相对同一个观测锚点 $q_t$，不是相邻预测步之间的差分；第八维夹爪仍是绝对量。训练、离线 Replay、在线 Actor 和安全闸必须使用同一表征与同一组归一化统计。模型张量预留的 action_dim 为 32，但本任务只有前八维有效，不能把预留维度误当成机器人自由度。

为什么选 40000

项目记录显示 step 40000 在既有动作平滑链路中取得 92% 真机成功率，并位于 30000–50000 的较优区间。更后期训练的 loss 更低，真机效果却更差，因此 loss 最低不是检查点选择准则。

92% 的试验次数、置信区间和完整条件没有在本轮 RLT 记录中重新建立；本页只把它作为“VLA 已具备任务能力”的前置证据，不把它外推成严格基线或普适结论。

阶段 ②：RL-Token 表征学习

三路图像一共对应 768 个图像位置 hidden tokens，每个 2048 维。它们是 π0.5 前缀经过 PaliGemma 主干处理后的最终层表示，不是原始图像 patch。令 $H\in\mathbb{R}^{B\times768\times2048}$，本项目实际实现为

\[\begin{aligned} \bar H &= \operatorname{sg}(H),\\ z_{\mathrm{rl}} &= E_\phi(\bar H)\in\mathbb{R}^{B\times1\times2048},\\ \widehat H &= D_\phi(z_{\mathrm{rl}})\in\mathbb{R}^{B\times768\times2048},\\ \mathcal L_{\mathrm{RM75}} &=\frac{1}{B\cdot768\cdot2048}\lVert\widehat H-\bar H\rVert_F^2. \end{aligned}\]

代码以 mask=None 调用 RL-Token 模块，decoder 使用非因果 cross-attention，因此这里是全元素重建 MSE。官方论文的式 (2) 则让 decoder 在位置 $i$ 同时读取此前的真实 embedding，采用自回归重建；两者不能写成完全相同的算法。本项目只更新 RL-Token encoder/decoder，配置 $\alpha_{\mathrm{VLA}}=0$，π0.5 完全冻结。训练后只保留 encoder 生成的 $z_{\mathrm{rl}}$ 供在线 RL 使用；decoder 与重建 MSE 都不直接参与真机控制。

重建 MSE 只回答“一个 token 能否保留这些 hidden tokens 的信息”，不回答“这些信息是否足以区分任务阶段”，也不等于成功率、价值估计精度或策略质量。

阶段 ③：在线 Actor-Critic

只读推理侧

  • 冻结的 π0.5 感知与动作先验
  • 冻结的 RL-Token encoder
  • 输出 z_rl[2048] 与 reference[50,8]

在线更新侧

  • 约 230 万参数的 Actor
  • Twin Critic 与 target network
  • Actor 输出完整 action_chunk[10,8]

Actor 并非从零学任务。它以 $z_{\mathrm{rl}}$、八维 proprio 和 50 步 VLA reference 为条件，直接输出完整的 10×8 动作块：

\[a^\theta_{1:10} =\pi_\theta\!\left(z_{\mathrm{rl}},s^{\mathrm p},\widetilde a^{\mathrm{VLA}}_{1:50}\right).\]

这里的“局部编辑”描述的是条件输入与损失约束，不是把一个残差机械地加到 reference 上。人类接管的步以真实执行动作作为 BC target；非接管步以 VLA reference 作为 BC target。Actor 同时接受 Critic 项与动作变化正则，因此人工纠正是否集中在真正困难的插装末段，直接影响它能否学到超越 reference 的信息。

预测 horizon 与执行 horizon

VLA 预测 50 步

冻结服务生成完整 reference chunk，提供任务先验和后续趋势。

Actor 生成 10 步

读取 z_rl、八维 proprio 与 50 步 reference，输出完整的十步动作块。

执行后重新规划

名义执行时长为 10/10.5≈0.95 秒；项目日志中的实际 chunk 周期约 1.03 秒，差值来自推理、通信与调度开销。

预测 horizon $H=50$、RL chunk 长度 $C=10$ 和实测重规划周期是三个不同概念。$H$ 决定 VLA 提供多长的动作先验，$C$ 决定一次 TD transition 与开环执行覆盖多少步；实际周期则必须以运行日志测量。对 2–4 mm 容差的插装任务，约一秒才重新观测一次会限制误差修正速度。
