GR00T N1.5 是 NVIDIA 在 GR00T N1 基础上发布的升级版本，官方 Research 页标注日期为 2025 年 6 月 11 日，副标题为「An Improved Open Foundation Model for Generalist Humanoid Robots」。它沿用 N1 的双系统骨架——视觉语言模型负责理解，扩散 Transformer 负责生成连续动作——但在四个方向上形成可核验增量：视觉语言主干换代并按官方训练口径冻结、关闭 pixel shuffle 使每个 $224\times224$ 视觉 tile 的 token 从 64 增至 256、动作头前增加视觉语言适配结构、官方训练说明加入 FLARE 未来潜在表征对齐目标。动态 tiling 两代都支持，不能把“多 tile”本身算作 N1.5 创新。最后一项还必须与公开训练代码区分：n1.5-release 的可执行损失仍只有流匹配 MSE。

本页是 GR00T N1.5 专题的总览与枢纽。凡 N1 已经讲透的内容，本专题不重复，一律指回 GR00T N1 专题。本页把增量主线讲通，每个知识点的完整展开放在七个子页。

3B发布模型的名义规模（N1 论文报告 2.2B）
256每个 224×224 tile 的视觉 token（N1 为 64）
4推理欧拉步数（N1 为 16）
0.2FLARE 损失权重
本页的事实来源分四层，正文每处都标明出自哪一层，不混用。 层一NVIDIA 官方 Research 页 research.nvidia.com/labs/gear/gr00t-n1_5/，这是 N1.5 的主要官方发布说明，但不是论文；层二FLARE 论文 arXiv:2505.15659v1 与 DreamGen 论文 arXiv:2505.12705v2，是 N1.5 两项核心创新的原始出处；层三官方源码 github.com/NVIDIA/Isaac-GR00T 的 n1.5-release 标签；层四发布权重 huggingface.co/nvidia/GR00T-N1.5-3B 的 config.json 与模型卡。 底座是 GR00T N1 论文 arXiv:2503.14734，本专题视为已在 N1 专题讲过。

一、开源地址、两份许可证与版本边界

1.1 「没有官方专属论文链接」与「没有公开资源」是两件不同的事

这两件事极易混为一谈。截至 2026-10-04，官方 Research 页、n1.5-release README 与模型卡都没有链接一篇以 N1.5 为主题的专属论文；仓库的 “Paper” 与 BibTeX 仍指向 N1 论文 arXiv:2503.14734。这个证据支持“官方材料未提供 N1.5 专属论文”，但不应扩写成对所有出版渠道的绝对不存在证明。与此同时，代码仓库和权重文件均可公开访问，只是许可证不同。

内容 是否公开 出处
GR00T N1 主论文 是 arXiv:2503.14734，N1.5 的架构底座
N1.5 官方专属论文链接 未提供 截至核验日，官方页、README 与模型卡均未提供；仓库 Paper/BibTeX 仍指向 N1 论文
N1.5 官方技术说明 是 官方 Research 页（层一）
N1.5 源码 是 n1.5-release 标签（层三）
N1.5 模型权重 是 GR00T-N1.5-3B（层四）
微调与推理代码 是 scripts/gr00t_finetune.py 等
完整原始预训练数据 未提供 官方页只列出五类混合并明确包含内部 GR-1 数据；公开数据源或公开子集不能证明训练所用完整快照、比例与内部数据已发布
内部完整预训练配方 否 官方页给出主要超参，但 FLARE 部分未在代码中实现

由此得到两条结论。其一，可以下载代码与权重，并在各自许可证允许的范围内使用；“文件可访问”不等于“许可条件相同”。其二，不能只靠一篇论文把网络、损失与训练伪代码一次读完，必须把 N1 论文、N1.5 官方页、FLARE 论文与固定版本源码合读——这也是本专题把来源分成四层的原因。

1.2 代码与权重是两份不同的许可证

这一处最容易出错，且后果直接：仓库代码的 Apache-2.0 允许商业使用；公开权重许可证只授予非商业用途，商业使用需另行取得相应许可。 部分二手资料把权重许可写成「NVIDIA Open Model License」，与固定版本模型卡和仓库内 LICENSE 不符。这里只概括发布文件的许可文本；依赖、数据及具体产品合规仍需分别核对。

对象 许可证 商用 实测依据
代码 n1.5-release Apache License 2.0 允许 仓库 LICENSE 文件首行即 Apache License；源码文件头亦为 Apache 声明
权重 GR00T-N1.5-3B NVIDIA One-Way Noncommercial License（22 Mar 2022） 不允许 模型卡原文 This model is ready for non-commercial use.，许可链接指向 NVIDIA-OneWay-Noncommercial-License-22Mar2022.pdf

因此描述 N1.5 时不应笼统写成「开源」。准确的说法是：代码以 Apache-2.0 开源，权重以 NVIDIA 单向非商业许可发布。

1.3 版本边界：源码层必须锁定 n1.5-release

截至 2026-10-04，Isaac-GR00T 远端可见 n1-release、n1.5-release、n1.6-release、n1.6.1-release、n1.7-release 五个发布标签，main 分支已是更高版本。n1.5-release 当前解析到 commit 4af2b622892f7dcb5aae5a3fb70bcb02dc217b96。研究 N1.5 时若直接读 main，很容易把后续版本的实现误当成 N1.5 的事实。

本专题所有源码层结论一律以 n1.5-release 标签为准。官方微调教程写于 N1.5 发布时期，使用时也应搭配该标签，不要把当前 main 分支的脚本与教程命令混用。

二、N1.5 要补 N1 的哪三个缺口

理解 N1.5 的改动，最有效的入口是先看 N1 在官方评测里暴露的三个短板。这三个数字全部出自层一，都是官方自己给出的 N1 基线。

缺口 N1 的表现 说明
语言指令跟随不可靠 46.6% 真机 GR-1 语言跟随率。近半数情况下模型不按指令所指的对象行动
scratch 语言基准成绩较低 52.8% Language Table 的从零训练架构对照，不是发布权重成绩
对未见过的物体零样本失效 0% 在该次新物体零样本评测中未观察到成功

三个异质实验共同提示 N1 的语言条件利用、语义接地与新物体泛化仍有改进空间，但它们不是同一协议下的诊断矩阵，不能共同“证明”单一故障位置。其中 Language Table 数字来自 scratch 对照，新物体 0% 只是未报告试验次数条件下的点估计。能确认的是，N1.5 的公开结构改动主要集中在感知侧及感知—动作接口，而动作侧的流匹配主体基本沿用 N1；这些结果不足以证明动作生成不存在瓶颈。

本页据此归纳出一条理解全部改动的主轴：冻结主干、换代语言模型、把视觉 token 提到四倍、在动作头前加一段视觉语言自注意力——四件事都指向同一个目标，即让语义信息以更高的保真度进入动作专家；FLARE 与 DreamGen 则从训练目标与数据两侧补充泛化能力。这是本页的归纳而非官方结论。官方的表述有两处：冻结主干与简化连接器这两项修改「极大改善了语言跟随与泛化」；讨论部分把 N1.5 的整体改进归因于接地能力的提升、FLARE 损失与 DreamGen 数据三项。两处都没有给出拆分各项贡献的消融。完整实验数字见 ⑦ 实验结果与横向对比。

三、N1 到 N1.5 的改动总表

本节是全专题的口径基准。下面两张表的每一行都经过层三源码与层四发布配置逐字段实测，并与 N1 侧的同名字段对照。

3.1 按侧归类的改动总览

感知侧语言模型由 SmolLM2-1.7B 换成 Qwen3-1.7B；关闭 pixel shuffle，每个 224×224 tile 的视觉 token 由 64 增至 256；连接器由两层 MLP 简化为单层 Linear。动态 tiling 并非 N1.5 新增。
接口侧主干输出不再投影到 1536，保持 2048；DiT 交叉注意力键值维由等于查询维改为显式 2048；动作头前新增 LayerNorm 与四层视觉语言自注意力。
训练侧官方说明新增 FLARE 对齐损失（权重 0.2），发布结构含 32 个可学习 future token；但公开 forward 没有计算 FLARE，只返回流匹配 MSE。微调脚本默认冻结视觉塔。
数据侧引入 DreamGen 神经轨迹，预训练混合扩展为五个来源。
推理侧发布配置的欧拉步数由 N1 权重的 16 改为 N1.5 权重的 4；N1 论文本身已报告 4 步可用，不能称为 N1.5 首次提出。

3.2 逐字段实测差异

位置 字段或结构 N1（GR00T-N1-2B） N1.5（GR00T-N1.5-3B） 性质
感知侧 语言模型 SmolLM2-1.7B-Instruct，llama 结构，24 层，词表 49164 Qwen3-1.7B，qwen3 结构，28 层，词表 151680 换代

表中「每个 $224\times224$ tile 的视觉 token 由 64 增至 256」是官方页没有提及的一项（官方只说连接器被简化，二者的关系见 ① 第 3.2 节）。它使单个 tile 经语言模型并供 DiT 交叉注意力读取的视觉 token 数变为四倍；一帧若被动态切成多个 tile，总视觉 token 还要乘实际 tile 数，而动态 tiling 本身两代都支持。官方页并未把任何一项实验收益单独归因于这项改动：官方的说法是主干「由 Eagle 2.5 出发，针对接地能力与物理理解做了调校」，并报告 N1.5 主干在 GR-1 接地基准上 IoU 为 40.4——对照的是 Qwen2.5-VL-3B 的 35.5，而不是 N1 主干（官方未给出 N1 主干在该基准上的成绩）。逐层拆解与代价分析见 ① 架构增量与 VL 接口重建。

3.3 明确没有改动的部分

只看差异表容易产生「N1.5 几乎全换了」的错觉。实际上动作侧的主体结构与流匹配机制原样保留，下面这些字段两代逐一相同。

位置 字段 两代共同取值
动作侧 DiT 层数 / 注意力头数 / 每头维度 16 / 32 / 48
动作侧 DiT 工作宽度（头数 × 每头维度） 1536
动作侧 input_embedding_dim 1536
动作侧 动作头 hidden_size 与 DiT output_dim 1024
动作侧 norm_type / interleave_self_attention ada_norm / true
动作侧 action_horizon / action_dim / max_state_dim 16 / 32 / 64
动作侧 按本体分组的状态编码器、动作编码器、动作解码器 结构与分组方式一致
训练侧 Beta 时刻采样 alpha / beta / s 1.5 / 1.0 / 0.999
训练侧 流匹配加噪式与速度场目标 (1 - t) * noise + t * actions，目标 actions - noise

最后两行需要一起理解。N1.5 的公开源码沿用 N1 的插值、速度目标与 sample_time 实现，因而也继承两条论文—源码边界：其一，源码目标 actions - noise 与自身从噪声到动作的正向积分一致，但和 N1 论文式 (1) 的速度符号相反；其二，源码先取 $U\sim\mathrm{Beta}(1.5,1)$，再用 $t=(0.999-U)/0.999$，这不是论文自然 Beta 变换的等价改写。源码没有裁剪 $t$，故约 $1-0.999^{1.5}\approx0.15\%$ 的样本会得到略小于 0 的连续时间，下界约为 $-0.001001$。完整推导见 GR00T N1 · Flow Matching、损失与时间方向。

五、官方训练目标一页纸（与公开脚本分开）

5.1 总损失

官方 Research 页称 N1.5 训练在 N1 的流匹配损失之外加入未来潜在表征对齐损失，系数为 0.2；官方页没有给出合并公式，按其文字可记为

\[\mathcal L=\mathcal L_{\mathrm{FM}}+\lambda\,\mathcal L_{\mathrm{FLARE}},\qquad \lambda=0.2\]

其中 $\lambda=0.2$ 在官方所述预训练与后训练阶段使用同一取值。枢纽页与 ④ 用 $\mathcal L_{\mathrm{FM}}$、$\mathcal L_{\mathrm{FLARE}}$ 指称这两项；② 页为便于与论文原式对照，沿用 FLARE 论文的 $\mathcal L_{fm}$、$\mathcal L_{align}$，二者一一对应。第一项沿用 N1：对真值动作块 $A$ 与噪声 $\epsilon\sim\mathcal N(0,I)$ 构造中间轨迹，回归速度场

\[A^{\tau}=(1-\tau)\epsilon+\tau A,\qquad v^{*}=A-\epsilon\]

这一项的完整推导已在 N1 专题给出，本专题不重复，见 GR00T N1 · Flow Matching、损失与时间方向。第二项按 FLARE 方法把 DiT 中间层的 future token 表示投影后，与未来观测经目标编码器得到的潜在表征做余弦对齐。这是官方训练口径和 FLARE 论文方法，不是公开 n1.5-release 的可运行损失路径：公开 forward 设置 return_all_hidden_states=False，只计算并返回流匹配 MSE。 完整方法推导、目标编码器的滑动平均更新及公开实现缺口见 ② FLARE 未来潜在表征对齐。

还要注意，余弦损失约束的是潜在向量方向而非逐元素重建或向量模长；数值系数 0.2 只有在损失的归约方式、层数与 token 聚合尺度一致时才可比较。把 0.2 原样搬到另一套实现而不核对这些尺度，不能视为复现官方权重。

5.2 两类数据走两条不同的路径

按官方训练说明与 FLARE 方法，没有动作标签的数据也能通过未来表征对齐参与训练。下表描述的是该方法的目标路径，而非公开微调脚本当前能够直接执行的分支。

数据类型 可得的量 能算流匹配损失 能算对齐损失 实际参与的损失项
机器人示范（遥操作、仿真） 当前观测、动作、未来观测 能 能 $\mathcal L_{\mathrm{FM}}+\lambda\mathcal L_{\mathrm{FLARE}}$
人类第一视角视频 只有当前观测与未来观测 不能 能 仅 $\mathcal L_{\mathrm{FLARE}}$

因此人类视频只经由对齐损失参与训练。判定依据与人类视频在训练中的具体作用，见 ② FLARE 未来潜在表征对齐 第七节。

八、八处最容易读错的地方

以下八条同时覆盖常见二手误读和官方说明—公开实现之间的边界；此处只给正确口径，机制分析见对应子页。

  • DiT 的隐藏维不是 1024，是 1536。部分二手资料把动作头的 hidden_size 当成 DiT 工作宽度。DiT 宽度由 32 头乘每头 48 维得到 1536，且这一取值 N1 与 N1.5 相同，不是本次改动。详见第六节。
  • 64→256 是每个视觉 tile 的变化，不是动态 tiling 的首次引入。N1 与 N1.5 都能把一帧切成多个 tile；N1.5 关闭 pixel shuffle，使每个 224×224 tile 保留 256 个 token。把“每 tile 四倍”写成“每帧恒定 256”会在多 tile 输入下低估序列长度。
  • 4 步是两代发布配置的差异，不是 N1.5 首次证明可行。N1 权重配置为 16，N1.5 权重配置为 4；但 N1 论文已明确称 4 步在各本体上工作良好。N1.5 没有公布步数消融或改值原因。详见 ⑤ 推理流程与反常现象。
  • 官方训练使用 FLARE，不等于公开脚本实现了 FLARE。README 与官方页都宣布 FLARE；但固定版本的模型 Python 路径中没有目标编码器、投影头、余弦对齐损失或 EMA 教师，动作头还明确写着 not using flare now，最终只返回流匹配 MSE。原先“全仓库只命中一处 flare”的说法不准确，因为 README 和词表也会命中；真正有判别力的是可执行模型路径与损失字典。因此不能靠公开仓库完整复现官方预训练。完整含义见 ⑤，需要补哪些部件见 ⑥。
  • 官方所说的“LLM 输入归一化”不是公开动作头的 vlln。前者位于视觉/文本 embedding 进入 LLM 之前；后者位于截断 LLM 输出之后。固定公开代码没有显式呈现前者的两套 LayerNorm，证据边界见第 4.2 节。
  • 相同 Beta 参数不代表论文采样式与源码等价。N1.5 延用 t=(0.999-U)/0.999，会产生约 0.15% 的轻微负连续时间；这是源码复现细节，不是模型新增创新，见第 3.3 节。
  • 动作维变化时的“部分复制”不能直接相信日志描述。固定脚本的特殊键名条件与当前参数注册名不匹配，受维度影响的动作输入／输出张量不会复制重叠维，而会保留随机初始化；应核对 copied/random 统计与 state-dict。详见 ⑥ 官方源码剖析。
  • 「开源」要分代码与权重两说。仓库代码为 Apache-2.0；公开权重受 NVIDIA 单向非商业许可约束，商业使用需另行获得许可。两者不是同一份协议，见第 1.2 节。
