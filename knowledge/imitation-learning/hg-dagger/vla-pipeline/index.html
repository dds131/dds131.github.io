专题总览 1 Foundations 2 Intervention 3 Risk 4 VLA Pipeline

本页不是 HG-DAgger 原论文的标准管线，而是 VLA 工程迁移方案。人工恢复数据只有在控制权、时间、动作语义和版本可追溯时才能成为训练样本；候选模型只有在独立安全层与分级门禁通过后，才可以进入明确范围内的监督发布。

  • 原论文事实：人类门控、连续恢复、聚合数据、重新训练。
  • 方法迁移：多相机与语言输入、动作 token / chunk、原生模型目标、逐步 mask 与 action adapter。
  • 工程建议：L0–L5 数据治理、E0–E6 评估、独立安全层、G0–G6 release gate、运行监控和完整回滚。

HG-DAgger 原论文验证的是自动驾驶中的人类门控数据聚合，并没有规定上述 VLA 结构与发布治理。依赖目标任务实验的效果结论只能标为待验证假设；只有能定位到明确版本或提交的代码行为才可称为官方实现事实。

数据与日志：从原始 episode 到可训练窗口

完整管线总图

flowchart LR
  A["受控 rollout<br/>policy bundle r"] --> B["人工接管 / 风险 / 系统事件"]
  B --> C["不可变原始日志 L0"]
  C --> D["同步、标定、authority 重建 L1"]
  D --> E["干预切片与质量标签 L2"]
  E --> F["训练窗口与 split manifest L3/L4"]
  F --> G["候选训练 bundle r+1"]
  G --> H["离线 → SIL/HIL → 受限闭环评估"]
  H --> I["独立安全层验证"]
  I --> J{"release gates 全部通过？"}
  J -- "否 / 证据不足" --> K["blocked / 修复 / 回滚 / 再采集"]
  J -- "是" --> L["限域发布 + 监控"]
  L -->|"新 episode 绑定 bundle r+1"| A
  K -. "新版本重新取证" .-> C

图 1｜可审计 VLA 闭环。 数据、训练、评估、安全与发布是五种不同责任；任何失败或证据不足都有明确出口。图只描述治理结构，不表示本站已经运行训练、SIL/HIL、真机评估或发布。

流程有八条不变量：原始日志不被覆盖；派生层均有版本与 hash；split 不泄漏；窗口可回溯 authority；评估绑定冻结 bundle；安全层先于发布门禁；缺证据为 blocked；回滚恢复完整 bundle 而不是只换 checkpoint。

六类原始记录

数据类 最小内容 主要用途 不得误用
demo 专家名义任务轨迹、成功与终止 初始与名义行为监督 默认假设包含恢复分布
correction confirmed human recovery 的观测与契约匹配动作 恢复行为监督 把 pending 或 policy 动作伪装成人工标签
event takeover、return、reset、abort、success、failure 切片、统计、状态机重建 直接当连续动作标签
risk 原始信号、阈值版本、告警与有效性 风险评估与提前量 当真实失败概率
outcome 任务结果、恢复结果、失败类型与严重度 闭环评测与数据分层 用事后结果污染因果输入
system 传感器、网络、控制时延、fault、authority 与执行确认 重建真实运行与安全事件 仅留均值而丢失尖峰和事件

原始层同时保留 policy_action、human_command_raw、human_action_canonical 与 executed_action。它们分别回答策略想做什么、人输入了什么、映射后的监督目标是什么、机器人实际执行了什么；数组形状相同也不能互换。

L0–L5 数据血缘

层级 制品 允许操作 必须记录
L0 Raw 原始 episode、设备与事件日志 追加、封存，不覆盖 content hash、采集 bundle、时钟、设备与配置版本
L1 Aligned 同步后的多模态 timeline 对齐、标定映射、validity 标记 转换代码/参数 hash、时钟误差、映射版本
L2 Segmented demo、correction、context、outcome 片段 切片、质量分类、排除原因 intervention ID、authority、边界、审核版本
L3 Windowed 模型输入与目标窗口 resize、tokenize、chunk、pad、mask processor、normalization、action contract、window config
L4 Split train、calibration、validation、test manifests 分组划分、抽样、加权 group key、seed、去重报告、leakage check
L5 Report 训练与评估输出 汇总、签名、审批 bundle hash、协议、指标、失败样本引用

一条训练窗口的静态血缘应能沿 window → segment manifest → aligned timeline → raw episode → collection bundle 反查。任何修正都产生新版本与新 hash；所谓清洗只能在派生 manifest 中排除并留下原因，不能把 L0 原地“洗干净”。

最小 episode 与 intervention schema

Pipeline 消费的是契约组，不靠目录名猜标签：

  • 身份：episode、rollout、intervention、step、任务、场景与会话。
  • 版本：policy/checkpoint、dataset、processor、normalization、robot config、I/O contract、risk/threshold 与 safety config。
  • 多模态输入：相机引用及顺序、深度、本体、力觉、语言、历史窗口和 validity。
  • 动作：四条动作通道、frame、unit、absolute/delta、controller mode、频率、chunk ID/index。
  • 控制权：FSM state、request/confirm、actual authority 与 executed source。
  • 结果：success/failure/recovery outcome、终止原因、风险/安全事件和 reset。
  • 时间：capture、present、command、confirm、execute 与 clock domain。

页面示例只能使用合成 ID。真实内部路径、人员身份、主机地址和设备序列号不属于可发布网页资产。

干预切片与动作块窗口

pre-context | takeover pending | confirmed human recovery | return pending | post-outcome
  诊断/历史      默认非专家标签          correction 核心区          默认非标签       结果验证

观测历史可以跨控制权边界作为上下文，但监督 action mask 只能覆盖可证明的人类控制区。接管前 policy action 不填入 expert target；固定长度模型只有在架构与 loss 真正支持逐步 mask 时才可 padding，否则只能从连续人工恢复区内部抽取完整目标窗口。

reset、episode end、时钟断点或 robot config 变化禁止跨窗。原始上下文、被排除样本和原因仍留在 L0/L2。控制权确认、队列失效和动作块边界的细节见 Intervention。

分组划分与泄漏检查

split 的最小分组单位是完整 episode；任务需要时，还应按会话、场景、物体实例、任务模板、操作者或时间段分组。同一 intervention 的前后帧、同一动作块、同一时刻的多相机画面和近重复图像不得跨 split。

risk threshold 的 calibration、validation、test 与 policy 训练 split 分开登记。闭环 test episode 在当轮发布决定完成前不得回流训练；若进入下一轮，必须形成新 dataset version，此后旧 test 不再是该后续版本的独立证据。

leakage report 应覆盖近重复、语言模板改写、多相机同帧和派生窗口，不只记录随机 seed。数据许可、隐私、人员可识别画面与外部来源分别标记；不能公开的原始资料不进入网页或 release 公开资产。

训练与版本化：沿用 VLA 原生目标，冻结完整候选

HG-DAgger 不规定新的 VLA Loss

数据层面可写成保留来源与重复样本的多重集：

\[\mathcal D_{\mathrm{train}} =\mathcal D_{\mathrm{demo}}\uplus\mathcal D_{\mathrm{corr}}.\]

若 batch 以比例 $\lambda$ 从 correction 分布采样：

\[q_\lambda=(1-\lambda)q_{\mathrm{demo}}+\lambda q_{\mathrm{corr}}, \qquad \mathcal L(\theta)=\mathbb E_{z\sim q_\lambda} \left[\ell_{\mathrm{native}}(\theta;z)\right].\]

sampling ratio 决定样本进入 batch 的概率，per-sample weight 改变每条样本对 loss 的贡献，loss-component weight 调节多目标模型中的不同 loss 项。即使三者写出同一个数，优化效果也不必等价。$\lambda$ 没有 HG-DAgger 通用默认值，必须通过独立评估选择。

动作形式适配

模型动作形式 correction 处理 必须保持 禁止
连续回归 沿用 demo 的 L1/MSE/NLL 或模型原目标 frame、unit、normalization、action mask 把示例 MSE 写成统一 HG Loss
离散 action token 用冻结 tokenizer/quantizer 转换人工动作，沿用 CE 与 mask tokenizer version、bin/statistics、decode contract 对 token ID 做连续 MSE
CVAE 沿用条件、latent、reconstruction/KL 路径 input、target 与 mask 语义 为纠正段跳过必需条件
Diffusion 动作块走相同加噪与去噪目标 noise schedule、prediction type、mask 对 padding 或非人工步计算动作 loss
Flow Matching 动作块走相同插值和 velocity target time sampling、normalization、mask 用干净动作冒充不同目标的等价输入
多头/多任务 缺失标签头显式 mask 每头 label availability 用默认零值制造伪监督

OpenVLA、π0 与 ACT 只说明 VLA 动作目标可以不同，不表示本站要求采用这些模型，也不支持发明一个跨模型统一的 HG Loss。

采样、覆盖与灾难性遗忘

可审计的策略包括固定 demo/correction batch 配比，按接管原因、任务、场景、严重度与恢复结果分层，以及为稀有但有效的恢复类型保留最低覆盖。训练和验证应分别报告 demo/correction loss，并用闭环结果监控名义任务退化、动作变慢、过度保守和“只会恢复不会完成”。

不得只删除模型学不会的困难恢复起点，不得靠重复单一 intervention 伪造样本量，也不得只按 correction loss 选择采样比或 checkpoint。失败后的慌乱动作、authority 不明、标定失效或动作契约不一致的样本应保留原因，但不自动成为高价值专家监督。

更新模式与在线更新边界

模式 优点 风险 必须记录
warm-start 成本低，保留上一轮能力 延续偏差、遗忘、optimizer state 不透明 parent checkpoint、optimizer 是否恢复、scheduler step
fixed-base retrain 轮次更易比较 成本高，可能丢失上轮适应 base hash、完整数据与随机种子
partial / PEFT update 降低训练成本 容量边界与冻结层共模错误 trainable/frozen parameter manifest
online update 理论上快速适应 训练部署竞态，未验证权重进入控制 本页默认禁止；需独立系统设计和审批

默认闭环是“收集一轮 → 冻结数据 → 离线训练 → 完整评估 → 再发布”，不是在同一真机 episode 中边接管边更新。此页不会启动任何训练或在线学习流程。

Ensemble 与 Risk 的版本一致性

若 Risk 依赖 ensemble，每个成员都要有独立 checkpoint hash、初始化/训练 seed、数据顺序与配置。共享 backbone、只训练小头或完全相同的确定性流程可能造成高度相关的共模错误，必须披露。

成员集合、动作标准化或模型结构一旦改变，旧 threshold artifact 可能失效。训练候选与评估候选不得使用不同成员；单成员部署若已不能生成原 risk signal，bundle 必须标记该监控不可用并重新通过门禁。

离线与闭环评估：按证据阶梯逐级增加风险

E0–E6 评估阶梯

层级 环境 主要验证 不能证明
E0 数据/制品静态检查 无执行 schema、hash、mask、split、范围、契约一致性 策略闭环行为
E1 离线 held-out 固定未见数据 action loss、token accuracy、分组退化、风险信号判别 真实闭环稳定性
E2 日志回放/数字仿真 可重复环境 时序、队列、状态机、典型扰动 sim-to-real 与硬件故障全貌
E3 SIL/HIL 软件或硬件控制链 延迟、频率、adapter、watchdog、fault injection 真实任务泛化
E4 受限硬件 dry run 低能量、受保护场景 方向、frame、限幅、急停、authority 目标范围性能
E5 监督真机闭环 固定小范围任务 自主成功、干预、恢复、风险事件 未测试场景与扩大范围
E6 扩展验证 预先批准的新场景或难度 scope expansion 的增量证据 无限开放世界安全

每一层的输入都必须是冻结候选 bundle。上一层表现优秀不能替代下一层的不同责任，也不能据此跳过安全审批。本页只定义证据结构，不执行这些评测。

离线完整性与回归

E0/E1 至少检查输入和目标的 shape、dtype、frame、unit、frequency、normalization 是否符合 I/O contract；action mask 是否跨 authority、reset 或 episode；时间戳是否单调；缺帧和无效输入是否显式标记；split leakage report 是否通过。

报告还要按 demo/correction、任务、场景、失败类型与机器人分层，并单列相对上一已验证 bundle 的名义能力回归。离线错误可沿血缘定位到原始 episode，但公开页面不展示敏感样本。离线 loss 下降只能支持离线拟合改善，不能单独支持发布。

闭环指标与分母

维度 指标示例 必须报告的分母或上下文
自主能力 success、partial completion、time-to-complete trials、任务/难度、seed、超时定义
人工负担 interventions、human-control duration 每回合、每分钟自主时间、每控制步
恢复质量 recovery success、return-to-success、re-intervention intervention 数、原因与严重度
风险/安全 near-miss、collision、abort、e-stop、limit trip 暴露时长、距离/步数、严重度
系统实时性 observation age、inference/network/control latency、jitter percentile、deadline、超时策略
数据学习 demo/correction loss、coverage、forgetting split/version、sample count
风险监控 precision/recall、false alarms、miss severity、lead time event window、threshold version、exposure

“干预率下降”只有在自主成功、暴露量与风险结果不恶化时才可能是进步。更早失败、操作者停止认真监控或接管日志丢失都会造成虚假下降。

Assisted 与 autonomous 分离

assisted rollout 衡量受监督人机系统完成任务的能力；autonomous segment 衡量 novice 独立控制期间的表现；recovery outcome 衡量人接管后的恢复与归还。经批准的 pure autonomous test 也必须单列环境、安全配置和停止条件。

不能把人工完成的后半段计入模型 autonomous success，也不能删除接管后失败的 episode。一次回合可以同时贡献“人机系统成功”“自主段失败”“人工恢复成功”三种不同事实，报告需要保留这种结构。

冻结测试协议与统计口径

测试开始前冻结任务集合、初始状态、物体/场景、语言模板、trial 数、随机化、终止与成功规则。报告应包含 trial/seed、点估计、分布或置信区间，以及失败案例，不能只选最好一次。

ID/OOD 维度分别登记视觉、对象、背景、语言、任务组合、初始姿态、本体和相机变化。新旧 bundle 只有在协议一致时才可直接比较；协议变化时必须披露差异。测试数据一旦回流训练，就应建立新版本或保留严格未触碰集合，不能继续把旧结果当独立证明。

独立安全层：先验证保护系统，再谈发布门禁

四层责任边界

层 主要职责 不能替代
VLA policy 根据观测和指令产生候选动作 硬实时安全控制或 authority arbiter
HG intervention / risk 人工恢复数据、风险提示与接管请求 底层确认、硬件急停或形式安全证明
Independent safety layer 约束动作、监测故障、执行经验证的停止或保持 策略的任务能力与语义判断
Release governance 证据审查、范围授权、监控与回滚 运行时毫秒级保护

任一层失效都不能由另一层的高成功率抵消。人工接管不是硬实时安全控制器，risk score 不是安全证明，release checklist 也不是工业安全认证。

Policy I/O contract

每个真实 release bundle 必须引用可解析、带版本与 hash 的契约：

contract_id + semantic_version + content_hash
observation modalities/order/shapes/dtypes
camera calibration/frame/color/resize/crop
state/history timestamps and max age
language prompt/template semantics
action representation/frame/unit/range
absolute/delta/relative convention
rotation and gripper convention
prediction horizon / execution horizon / replanning rate
normalization + tokenizer/processor artifacts
controller mode + control frequency
timeout / invalid / NaN behavior
authority and queue-cancellation interface
compatible robot/safety config versions

本页是通用模板，所以自身 policy_io_contract_id=null；真实候选若仍为空、不可解析或与 robot/safety config 冲突，则门禁状态必须是 blocked。

独立保护能力

目标平台应分别验证并版本化：工作空间与关节限制；速度、加速度、力/力矩和接触限制；碰撞、自碰撞与禁止区域；observation/action freshness；通信超时、watchdog 与 heartbeat；action adapter 的 frame/unit/range/NaN/shape 检查；动作块取消、迟到响应丢弃和队列上限；authority arbiter、人工接管确认与急停；已验证的 hold/stop/retreat；电源、控制器、传感器和网络故障下的确定行为。

这是一组通用能力类别，不是具体实现、默认阈值或安全认证要求。实际限制来自目标平台的风险分析、硬件能力和验证记录。

Fault injection 与最坏情况

覆盖项至少包括：相机冻结、黑帧、乱序、时间戳跳变和模态缺失；policy server 超时、迟到、重复响应、错误 shape、NaN/Inf 和越界动作；网络抖动、断连、队列堆积、控制频率下降；authority request/confirm 不一致、操作者设备断连和急停；robot config、normalization、动作 frame 或单位错配；risk monitor invalid、threshold artifact 不匹配或信号冲突；checkpoint/processor/config 部分更新造成版本撕裂。

每个注入项记录检测信号、检测延迟、状态机迁移、实际执行动作来源、停止结果，以及恢复是否要求人工复位。未检测或结果无法判断都是失败，不能因为一次“没有碰撞”就判定通过。本页只定义测试证据，不实际注入故障。

真机前置条件

进入任何真机门禁前，至少应有证据表明：

  1. 急停和人工接管在目标控制频率与最坏延迟下可用；
  2. invalid/stale 输入不会被解释为正常低风险；
  3. 旧动作块和迟到响应能够确定失效；
  4. I/O contract 与 robot/safety config 完全匹配；
  5. 日志能重建 authority、动作来源、风险与停止全过程；
  6. rollback bundle 已安装或可按批准流程恢复，并完成批准的最小 smoke test。

任一必需证据缺失、相互矛盾或无法判定时，状态都是 blocked/not validated，不能凭经验默认通过。

图 3｜Gate 阶梯。 每级逐步增加执行风险，并保留 fail/blocked 出口；它不是一路向前的自动发布流水线。

Gate 主要检查 通过后允许 失败或缺证据
G0 Artifact Integrity bundle hash、来源、依赖、契约完整 进入静态检查 blocked，不得事后猜配置
G1 Data Quality L0–L4 authority、时间、mask、split、排除与泄漏 启动候选训练/评估 修复派生层或重新采集
G2 Offline Regression E0/E1 名义、恢复、OOD、遗忘与风险指标 进入回放或仿真 fail/blocked，不得调测试集掩盖
G3 SIL/HIL & Faults E2/E3 时序、adapter、队列、状态机和 fault injection 进入受限硬件 修复系统或降级，不跳级
G4 Restricted Hardware E4 低能量方向、frame、限位、急停和 authority 进入小范围监督真机 停止、回滚或重新验证
G5 Supervised Limited Rollout E5 固定任务、干预、恢复、风险和延迟 限域候选发布 不扩大范围，回滚或补数据
G6 Scope Expansion E6 新场景、任务、速度、对象的差异风险 只扩大已批准维度 保持原范围，不默认泛化

gate 状态只能是 pass、fail、blocked 或有理由的 not_applicable。not_applicable 必须记录责任人、依据和影响，不能作为静默豁免。

Release bundle 版本矩阵

制品 当前候选 已验证基线 一致性规则
code/environment commit + lock hash baseline hashes 构建可重现

任何“只替换 checkpoint”的热更新仍要生成新的完整 release ID，并重新核验依赖矩阵，避免 processor、normalization、threshold 或 safety config 与权重发生版本撕裂。

限域发布与运行监控

发布范围至少声明机器人、任务、物体/场景、语言、相机、速度或能量模式、操作者要求、时间窗口与最大 rollout 数。运行中联合监控：任务结果与暴露量；intervention、human-control duration、re-intervention、recovery outcome；collision、near-miss、abort、e-stop、limit trip；observation age、latency、jitter、queue、timeout、invalid 输入；risk signal 分布、告警、漏报代理、threshold drift；bundle/version mismatch、日志缺失与数据质量错误。

telemetry 缺失不是“没有事件”，必须显示 telemetry unavailable，并按 gate 规则停止扩量、降级或阻断。

回滚触发

下列类别触发回滚或立即停止扩量：严重安全事件或未解释的 constraint trip；相对批准基线的明显性能、干预或延迟退化；authority、动作来源、队列取消或日志无法重建；bundle hash、I/O contract、robot/safety config 不匹配；risk monitor 长期 invalid、阈值失效或发现严重共模漏报；训练/测试泄漏、评估协议错误或关键证据被推翻；操作者无法按协议及时接管或停止。

具体数值由目标平台 release policy 冻结，本通用页面不提供可跨机器人复制的速度、力矩、延迟、成功率或风险阈值。

完整 bundle 回滚语义

触发停止/回滚
  → 阻止新 episode 和范围扩张
  → 将当前活动回合按平台安全协议结束
  → 保存完整日志与候选 bundle 身份
  → 激活已验证完整 rollback bundle
  → 验证 hash、I/O contract、robot/safety config
  → 执行批准的最小 smoke test
  → 仅在授权后恢复旧批准范围
  → 隔离失败数据供下一轮分析，不污染当前基线

不能只回退 checkpoint 而保留不兼容的新 normalization、processor、risk threshold 或 safety config。回滚也不是删除失败证据；所有 episode、事件和审批记录继续保留。

HG-DAgger 专题完成与后续路线

HG-DAgger 专题完成。 现在可以把四页责任串成一条可复核链路：

方法定义 → 人工接管协议 → 风险信号与阈值 → VLA 数据/训练/评估/发布

下一步不是固定专题：可以返回模仿学习总览选择 ACT、生成式动作或其他数据路线；也可以进入 VLA 总览继续公共基础或具体模型；或者回到 HG-DAgger 总览复查专题边界。VLA 是交叉入口，不改变本专题的结构父级。

证据边界回顾： 人工门控、连续恢复、数据聚合与下一轮重训是原论文事实；把多相机、语言、动作 token/chunk 和原生 VLA loss 接入该闭环是方法迁移；L0–L5、E0–E6、独立安全层、G0–G6 与 bundle rollback 是本站工程建议，均需在目标平台验证。
