VLA·Harness VLA·横向比较与研究路线
  • 不是排行榜：跨论文通常只能做 identity/mechanism comparison；只有同协议、同 task/seed/budget/authority 的 row 才能进入受控数值比较。
  • 双分支汇合：必须同时接收 EvaluationEvidenceBundle 与 ImplementationEvidenceBundle；缺 key 返回 not joinable。
  • 当前证据：外部方法均为 reported-only；Harness VLA fixed implementation 为 code-mapped/not-rerun；本站没有 component 或 rerun evidence。
  • 组合边界：RTC 是动作块时序层，RLT 是权重更新层；它们可组合但不是 Harness 的后继版本。
  • 无普适赢家：先硬约束，再瓶颈与 authority，最后才看 Pareto 软目标。

双分支证据汇合

flowchart LR
  E["EvaluationEvidenceBundle"] --> G["ComparabilityGate"]
  I["ImplementationEvidenceBundle"] --> G
  G -->|joinable| S["synthesis"]
  G -->|missing/conflict| N["not joinable · preserve reason"]

merge_policy: all：任一 bundle 未到，只显示未完成汇合，不生成推荐、优劣结论或完成收据。固定 join keys 包括 protocol_id、treatment_id、result_snapshot_id、source_revision_id、dependency_resolution_id、model_artifact_id、memory_snapshot_id、asset_manifest_id、benchmark/task/initial-state/seed/trial-budget 与 native_success_authority_id。模型展示名、自然语言任务或日期接近都不能代替 join。

receipt field rule
runtime / engineering received 都必须 true
joinable count 只计全部 keys 一致
not-joinable / conflict 不得丢弃，列原因
recommendation enabled 两 bundle 到达且问题字段完整
completion enabled 导航完整且无 blocking conflict

  merge_policy: all
  joinable_record_count: <integer>
  not_joinable_record_count: <integer>

  recommendation_enabled: true | false

可比性资格门

L0 只比较 identity；L1 比较 owner/interface/state/update/safety mechanism；L2 才允许同协议受控 treatment 数值差。

flowchart TD
  Q["same question + protocol?"] -->|no| M["mechanism-only / not-comparable"]
  Q -->|yes| H["task, embodiment, observation/action, seed, budget exact?"]
  H -->|no| N["not-comparable"]
  H -->|unknown| U["unresolved"]
  H -->|yes| A["success + safety authority exact?"]
  A -->|no| B["blocked-by-authority"]
  A -->|yes| P["provenance bound?"]
  P -->|no| V["blocked-by-provenance"]
  P -->|yes| C["comparable-within-protocol"]

Gate 还要求 benchmark/version、task weighting、hardware/simulator、initial states、retry/timeout、training scope、online update、base model、Memory、aggregation 与 evidence state。unresolved 不是 0、失败或相同；not-comparable 数字不得出现在同一排序列、bar/radar chart 或胜负句。paper/current 必须分 snapshot；同 model name 不同 artifact 默认不同 treatment；frozen VLA 不说明 Planner/Memory/tool/safety 是否可写。

record_type: ComparabilityGate
ComparabilityGate:
  question_id: <id>
  hard_identity_fields: <exact-map>
  controlled_factor: <field-or-null>
  evidence_state: <state>
  outcome: comparable-within-protocol | mechanism-only | not-comparable | unresolved | blocked-by-authority | blocked-by-provenance
  reasons: [<reason>]

固定轴：problem layer、decision owner/granularity、executor、base-weight update、external state/write timing/adaptation channel、real-time profile、data loop、safety/success authority、evidence state、resources/license。unknown、not-applicable、not-resolved、conflicting-sources 分开，不能用 0/空/false 代替。

六条路线同构卡片

每张卡都显示 identity、problem、owner/executor、update/Memory、realtime/data、authorities、evidence、适用/禁用条件、composition 与 sources。

  • Harness VLA：macro primitive orchestration 与 recovery；evaluation read-only / exploration write 必须分 treatment；本站 code-mapped/not-rerun。可接 K1 tools、RTC runtime 或 RLT-trained policy，但每次组合产生新 treatment。
  • Show-Harness：VLM 逐步选择 discrete semantic units，interpreter ground actions；frontier zero-shot 与 small-model fine-tuning 是两个 treatments。per-step latency 或 interpreter ambiguity 超门则停。
  • K1：calibrated depth、persistent anchors、measurements、grasp hypotheses 是 evidence tools；107 teacher episodes 只属于 student treatment。grasp hypothesis 不是 collision-free trajectory 或 safety permit。
  • Guava：shared harness 上 distill frontier teacher 到 compact student；arXiv v3 是 fewer than 2K trajectories，project page 当前措辞为 just over 2,000，保留冲突来源，不制造精确统一数。
  • Memory-Driven RoboHarness：orchestrate heterogeneous VLA/WAM/RL/TAMP 与 handoff；无需 joint retraining 不等于 policy/harness 永不演化。
  • Memory-Augmented RoboHarness：frozen VLA + Dual-Memory RAG + attribution/intervention；offline consolidation 更新 external Memory，不是 VLA fine-tuning。

所有外部路线结果只标 reported-only。

Harness 与 RTC 的组合

flowchart TD
  H["Harness Planner · task/primitive"] --> A["analytic primitive"]
  H --> V["vla_act"]
  V --> R["RTC policy/runtime · chunk stitching"]
  A --> C["controller"]
  R --> C
  S["independent Safety stop authority"] --> C

RTC 可以在 vla_act 内处理 latency 下的 action queue/chunk continuity；Harness 仍决定何时、对哪个对象调用、retry 与 task stop。组合需新增 RTC method/revision、checkpoint/action contract/horizon、latency/frequency、queue/executed-prefix/cancel、stale threshold、state owner、budget/timeout、authority 与 artifacts。RTC 不自动改善 task decomposition，Harness 不自动满足 control deadline，组合增益不保证相加，旧 treatment 结果不可复用。

record_type: PairwiseRelation
PairwiseRelation:
  left_method_id: harness-vla-paper-v5
  right_topic_id: rtc
  relation: composable_not_substitute
  interface: vla_act_runtime
  new_treatment_required: true
  required_revalidation: [latency, continuity, safety, task_success]

Harness 与 RLT 的边界

Harness 主要更新 external orchestration/Memory；RLT 更新 actor/critic/target/checkpoint。external Memory write ≠ gradient update；prompt/context adaptation ≠ checkpoint update；routing ≠ learning；trace collection ≠ successful RL training；frozen base VLA ≠ frozen entire system。

RLT policy 可作为 vla_act executor，Harness traces 可成为候选训练数据；任一 weight update 后都要新 treatment_id、model artifact、policy I/O hash、training data/replay/optimizer provenance、safety qualification、rollback target 和 result snapshot。RTC/RLT 只在 related_topic_ids，不是 next。

约束优先选型树

先列 hard constraints → 确认 failure layer → check observability/authority → 最小机制 → new treatment → small validation → composition。task decomposition/binding/recovery 可候选 Harness；semantic cross-embodiment 候选 Show；calibrated geometry 候选 K1；teacher compression 候选 Guava；multi-policy handoff 候选 Memory-Driven；OOD attribution/intervention 候选 Memory-Augmented；chunk discontinuity 候选 RTC；environment interaction weight update 候选 RLT。

每条 recommendation 必须写：“若瓶颈且先决条件成立，可试最小机制；除非禁用条件。先以可证伪测量验证，过 release gate 后扩大。”组合会增加 owners、versions、latency、permission surface 与 sample need；不是默认答案。

ConditionalRecommendation:

  prerequisites: [<condition>]
  minimal_mechanism: <candidate>
  contraindications: [<condition>]
  falsifiable_measure: <metric>
  release_gate: <gate>
  evidence_state_required: <state>

多目标与证据工作台

Safety stop、deployable license、control deadline、hardware budget、secret redaction、auditable success 与 rollback 是 hard constraints；未满足即 infeasible。soft goals 才包括 success/recovery、latency/jitter、resource/cost/energy、data/human cost、safety events、generalization、reproducibility 和 maintenance。

工作台默认 axis cards，不显示总分；只有 L2 comparable rows 可画 numeric charts；每数值带 protocol/snapshot/N/uncertainty/source；missing 不归零；权重变化导致排名变化必须警告。本页默认只做 mechanism comparison，不产生冠军、排序 bar 或 radar area。

可证伪研究路线

研究卡必须含 evidence/unknown、treatment/control、单一 primary intervention、fixed identities、primary/secondary/safety metrics、seed budget、support/falsifier、abort/rollback 与 evidence transition。

  • Calibrated verifier：同 Planner/VLA/Memory 下组合 object motion/contact/native predicate/uncertainty；否证为 success 不增且 latency/false rejection 超门，或收益仅来自更多 retry。
  • Harness + RTC：同 plan/checkpoint 下测 deadline miss、jitter、chunk discontinuity、primitive/task success；低层改善却 task/safety 变差即否证。
  • Recovery distillation：固定 schema 和 budget，增加 traceable recovery branches；若只因 task leakage 或常规/safety 退化则否证。
  • Memory confidence/TTL：加 provenance/version/applicability/counterexample；若治理不降污染或过拒绝有效经验则否证。
  • Policy handoff：用 target-policy success region 对比 fixed boundary；若收益来自更长 budget/retry 则否证。

局限、冲突与漂移

六条路线没有 common protocol；部分 code/data/weights/episodes 不完整；arXiv、project page、repository main 与 closed models 会漂移；real-robot 受 hardware/calibration/operator/safety 影响。本站未运行外部方法，跨方法结果全是 reported-only。

Guava trajectory wording 是已知 conflicting-sources：并列 arXiv v3 与 current project wording，不平均、不四舍五入、不选更好看的数。监控 arXiv revision、project content hash、repo commit、license/release/assets、benchmark/success definition；drift 只生成 review item，不自动覆盖。

公开页面不含 secret、private IP、signed URL、device credential 或未批准绝对路径；外链 HTTPS 且带 owner/title/version。
