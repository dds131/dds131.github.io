SAC 是学习器，不是完整机器人安全系统

Off-policy 与连续随机策略让 SAC 适合研究真机控制，但实时调度、动作平滑、安全限幅、暂停恢复和数据治理必须由系统层补齐。本页把算法能力与系统责任分开。

SAC 枢纽 ← PyTorch 实现 异常诊断 →

机器人需求与 SAC 能力的对应关系

机器人约束 SAC 提供的能力 仍需系统层解决
真机采样昂贵 Replay 重用历史经验 数据质量、覆盖、旧策略与当前策略偏移
连续控制 Squashed Gaussian 直接输出 Box 动作 动力学可行域、混合约束、接触安全
反复调参代价高 自动 alpha 减少固定温度调节 奖励、UTD、学习率、target entropy 仍需验证
扰动与多解 随机策略与熵正则 单高斯表达限制与最坏情况安全
实时闭环 Actor 前向通常可做成低延迟 最坏时延、硬实时线程、通信、watchdog、低层控制

最大熵训练可以提高策略在动作邻域中的覆盖，但不能推出“策略天然安全”“动作天然平滑”或“任意扰动都鲁棒”。这些性质必须通过系统设计和针对性评估证明。

BAIR 的三个真实机器人案例

UC Berkeley BAIR 2018 年文章展示了：

Minitaur 四足运动

策略输出腿部摆动角与伸展量，再由底层 PD 跟踪；观测包括电机角度和机体姿态。文章报告该任务约 2 小时真机经验。

三指灵巧手

9 自由度手旋转物体；视觉版本直接使用 RGB 观测。文章报告视觉版本约 20 小时、提供物体状态的版本约 3 小时。

Sawyer 堆叠积木

7 自由度机械臂输出各关节力矩，观测包含关节位置、关节速度与末端力；文章报告约 2 小时经验。

这些数字只描述该文章的具体硬件、任务、观测、奖励和实现，不能当作其他机器人任务的预期训练时长。更有价值的是文章列出的工程需求：异步采样、停止/恢复与动作平滑。

控制分层

SAC 可以输出关节目标、末端增量、速度或力矩，选择取决于硬件与任务。越靠近执行器，策略越直接，却越需要动力学、延迟和安全约束。把 Actor 输出交给低层 PID/阻抗控制，是许多真机系统降低高频风险的常见方式，但不是算法强制结构。

时间与延迟

  • 记录观测时间戳、策略推理时刻、动作发送与生效时刻。
  • Actor 与 learner 异步时，Replay 中每条数据最好带策略版本。
  • action repeat 或控制周期改变一个 RL step 的物理时长；相同 gamma 的实际有效时间视野随之变化。
  • Learner 的 GPU 峰值负载不应阻塞实时控制线程。

若希望折扣对应固定的连续时间衰减率 \(\lambda>0\)，可写成

\[\gamma(\Delta t)=\exp(-\lambda\Delta t),\qquad \gamma_{\mathrm{new}}=\gamma_{\mathrm{old}}^{\Delta t_{\mathrm{new}}/\Delta t_{\mathrm{old}}}.\]

这只校正折扣时间尺度；控制周期改变后，每步奖励是瞬时量、时间积分还是区间平均也必须重新定义，否则总回报仍不可比。抖动控制周期还应记录真实 \(\Delta t_t\)，固定 gamma 只是近似。

安全外壳

最少包括关节位置/速度/力矩限制、工作空间、碰撞与接触力阈值、watchdog、急停、人工接管和安全 reset。安全层修改动作时，不能用一句“Replay 一律存执行动作”处理，必须先固定 MDP 的动作语义：

  • 命令动作合同：Actor 输出命令 \(u_t\)，安全层是环境的一部分，执行 \(a_t^{\mathrm{exec}}=F(s_t,u_t,h_t)\)。此时 \(Q(s_t,u_t)\) 应使用 Replay 中的命令动作；执行动作、限幅原因与安全层内部状态 \(h_t\) 另行记录。若 \(h_t\) 会影响转移却不在观测中，学习器面对的是部分可观测问题。
  • 可执行动作合同：若投影/限速器被纳入策略路径，Actor 与 Critic 都以 \(a_t^{\mathrm{exec}}\) 为动作，Replay 也存执行动作；可微投影可参与策略梯度，不可微投影则需要代理梯度、残差策略或其他专门方法。

最危险的混搭是：Critic 用执行动作训练，Actor 更新却把未经安全层变换的命令直接送入 Critic。这样 \(Q\) 的动作坐标与策略输出不一致。无论选哪种合同，都应同时日志化 commanded_action、executed_action、干预标志与干预原因。

为什么随机策略不等于时间平滑

标准 Gaussian Actor 在给定各时刻状态后通常独立抽取噪声。即使相邻状态很接近，采样扰动也可能快速换符号，引起执行器抖动。最大熵目标关心每个状态上的动作分布，并不直接约束相邻时刻的动作差。

可选机制：

  • 输出较低频高层目标，由低层控制器插值。
  • 速率限制或低通滤波；训练时也应建模这层动态。
  • 在奖励中加入动作差分，或按明确物理量定义 jerk 惩罚；注意不要压倒任务奖励。
  • 使用时间相关探索或状态相关探索。
  • 显式把上一动作纳入状态，减少部分非马尔可夫性。

一种离散平滑代理是

\[r'_t=r_t-\lambda_v\left\|\frac{a_t-a_{t-1}}{\Delta t}\right\|_2^2 -\lambda_a\left\|\frac{a_t-2a_{t-1}+a_{t-2}}{\Delta t^2}\right\|_2^2.\]

它惩罚的是动作的一阶/二阶差分；只有结合“动作代表位置、速度还是力矩”后，才能把它解释成速度、加速度或 jerk 的代理。改变控制频率时必须保留 \(\Delta t\) 的尺度，并检查平滑奖励是否掩盖任务奖励。

滤波器必须在训练环境中建模，或在状态与 Replay 合同中显式体现；仅在部署时突然加滤波会产生训练—部署差异。Replay 具体存命令还是执行动作，遵循上一节的两种一致合同，而不是无条件只存滤波后动作。

视觉 SAC：表示学习才是瓶颈

SAC+AE

Improving Sample Efficiency in Model-Free Reinforcement Learning from Images 研究用自编码器辅助视觉表示。这里的困难不要求环境奖励严格“稀疏”：即使每步有标量奖励，RL 梯度相对高维像素仍可能弱、噪声大且非平稳。SAC+AE 用像素重建提供密集表征信号，并通过两项关键选择稳定联合训练：把随机 VAE 改为带潜变量 L2 正则的确定性 AE，以及截断 Actor 对共享卷积层的梯度；共享卷积仍可受 Critic 与重建 Loss 更新。关键不只是“多一个 decoder”，而是：

  • encoder 与 actor/critic 是否共享；
  • 哪些 Loss 可以更新 encoder；
  • 重建目标是否保留与控制有关的信息；
  • 辅助 Loss 的尺度是否干扰价值学习。

DrQ

DrQ 使用图像增强对价值学习做正则化，提高视觉 RL 的样本效率。它不只是笼统地“给图片做增强”：原始论文分别对 target Q 的 \(K\) 个 next-observation 增强和当前 Q 的 \(M\) 个 observation 增强取 Monte Carlo 平均。用 SAC 记号可概括为

\[y=r+\gamma(1-d_{\mathrm{term}})\frac1K\sum_{k=1}^{K} \left[\min_i\bar Q_i(f_{\nu'_k}(o'),a'_k) -\alpha\log\pi(a'_k\mid f_{\nu'_k}(o'))\right],\]

其中 \(d_{\mathrm{term}}\) 只标记阻止 bootstrap 的真实终止，纯时间上限截断通常不应置 1；\(a'_k\sim\pi(\cdot\mid f_{\nu'_k}(o'))\)。Critic loss 再对 \(M\) 个 \(f_{\nu_m}(o)\) 求平均。增强应保留任务语义：同一帧堆叠内部通常使用一致的空间变换，避免制造假运动；current 与 next 的随机增强不必强行使用同一参数，应服从所实现算法的采样定义。

必须区分：原始 DrQ 使用 SAC 风格的基础学习器；DrQ-v2 改用 DDPG 风格。DrQ-v2 可用于学习视觉正则与高效控制思想，但不是“给 SAC 加几个模块”的直接版本。

视觉流水线检查

  1. 相机时间同步、帧堆叠和延迟。
  2. train/eval 的 resize、crop、颜色与归一化一致。
  3. 帧堆叠内部的增强是否一致；current/next 是否按算法独立采样，而非误以为必须同裁剪参数。
  4. encoder 接收哪些 Loss 的梯度。
  5. Replay 存原图还是压缩/特征，是否影响复现。
  6. 部署相机曝光、背景与视角漂移的压力测试。

Off-policy 不等于 Offline RL

标准 SAC 可从旧策略数据学习，但通常仍持续与环境交互，使数据分布随策略扩展。纯 offline RL 只能使用固定数据集；Actor 可能选择数据从未覆盖的动作，而 Critic 对这些动作只能外推，虚高 Q 会被 Actor 反复利用。

flowchart TB
  ON["标准 SAC<br/>持续在线交互"] --> ORB[("在线 Replay")]
  MIX["RLPD<br/>先验数据 + 新在线数据"] --> DB[("双来源采样")]
  OFF["CQL<br/>固定离线数据"] --> CREG["Bellman loss + 保守 Q 正则"]
  ORB --> SAC["SAC learner"]
  DB --> SAC2["对称采样 + Critic LayerNorm<br/>sample-efficient ensemble learner"]
  CREG --> OP["Offline policy"]

RLPD：已有数据加速在线学习

RLPD 是“带先验数据的在线 RL”，不是先做纯离线预训练再微调。论文的 symmetric sampling 在每个 batch 中各取 50% 在线 Replay 与 50% 固定先验数据；50/50 是论文给出的稳健起点，不是所有任务的定律。其关键组合还包括 Critic LayerNorm、sample-efficient ensemble 方法，以及在适合的任务上提高 UTD。LayerNorm 在该论文中的角色是抑制灾难性价值外推，并不等价于显式行为约束。

UTD 应写清分母：

\[\mathrm{UTD}=\frac{\text{本轮参数更新次数}}{\text{本轮新增真实环境 transition 数}}.\]

先验数据被反复抽样不会增加分母。高 UTD 能多次利用昂贵真机数据，但同时提高过拟合、Q 外推和墙钟延迟风险。离线与在线数据的奖励定义、终止语义、观测处理、动作坐标和传感器标定都必须对齐。

CQL：纯离线的保守价值学习

CQL 在 Bellman 学习之外加入保守正则。连续动作下常见的 CQL(H) 形式可概括为

\[L_Q^{\mathrm{CQL}}=L_Q^{\mathrm{Bellman}} +\eta_{\mathrm{CQL}}\,\mathbb E_{s\sim\mathcal D} \left[\log\int\exp Q(s,a)\,da -\mathbb E_{a\sim\mathcal D(\cdot\mid s)}Q(s,a)\right].\]

方括号惩罚“广泛候选动作的 Q 相对数据动作 Q 过高”；最小化它会压低候选动作或相对抬高数据动作。连续积分在实现中用 uniform、当前策略等 proposal 采样并做相应密度修正。论文保证讨论的是特定假设下策略期望价值的下界，不是每个状态动作点都必然保守。CQL 可采用 SAC 风格 Actor-Critic，但核心贡献是处理 offline distribution shift 的保守 Q 目标，不是“把 SAC 的 buffer 冻结”。

MBPO：用短模型轨迹辅助 SAC

MBPO 学习动力学模型，从真实 Replay 的状态出发生成短 rollout，并把模型数据交给 SAC 类 policy learner。

flowchart LR
  ENV["真实环境"] --> REAL[("真实 Replay")]
  REAL --> MODEL["动力学 ensemble"]
  REAL --> START["采样真实起点"]
  MODEL --> ROLL["短模型 rollout"]
  START --> ROLL
  ROLL --> MBUF[("Model Buffer")]
  REAL --> MIX["真实 + 模型批量"]
  MBUF --> MIX
  MIX --> POLICY["SAC policy update"]

核心不是“生成越多数据越好”：rollout 越长，模型误差越容易累积。MBPO 从真实 Replay 状态分支，以短 horizon \(k\) 生成许多模型 transition；Policy batch 再按约定比例混合真实与模型数据。模型数据增加的是计算生成的训练样本，不应计作新增真实环境样本；模型更新后还要控制旧 Model Buffer 的失效数据。短轨迹是在数据复用与模型偏差之间做的结构性折中，原论文实验甚至显示单步 rollout 是很强的基线。本站已有MPC 与 MBPO页面，完整模型推导不在此重复。

不要把“数据效率”压成一个数字

至少同时报告四个分母：达到目标性能所需的真实环境 transition、梯度更新次数、墙钟时间和硬件风险/磨损成本。高 UTD、视觉增强和模型 rollout 可能减少真实步数，却增加计算、延迟与过拟合；离线数据还应单列其采集成本和覆盖。只有环境步更少，不能单独证明整体系统更高效。

研究问题

  1. 随机性与时间相关性。如何让策略保留探索，同时避免高频动作抖动？
  2. 命令—执行不一致。安全层究竟属于环境还是策略？怎样让 Replay、Critic 与 Actor 梯度使用同一个动作合同？
  3. 环境样本与计算预算。高 UTD 降低真机步数，却可能提高墙钟和过拟合风险。
  4. 多模态技能。单高斯在多个可行动作模式间的均值陷阱，是否需要 mixture/flow policy？
  5. 视觉与动力学漂移。部署期光照、摩擦和负载变化应由增强、在线适应还是系统辨识处理？

本页重点与创新视角

  • 知识点：SAC 解决连续随机策略学习；实时性、安全、执行器约束和故障恢复属于完整控制系统。
  • 最关键合同：先定义 commanded_action 与 executed_action 谁是 MDP 动作，再统一 Actor、Critic、Replay 与安全层；“一律存执行动作”并不正确。
  • 方法边界：SAC+AE/DrQ 处理视觉表征，RLPD 处理先验数据辅助在线学习，CQL 处理固定数据集的外推风险，MBPO 以短模型 rollout 交换真实样本与模型偏差；四者解决的问题不同。
  • 创新视角：把真实步数、更新次数、墙钟和硬件风险并列为四本账，并把命令—执行差值作为可观测、可诊断的数据对象，而不是隐藏在 wrapper 中。
