VLA/后训练与对齐/RLHF-VLA

Preference method family · three parallel branches

把反馈变成可追溯信号，而不是把所有方法压成一个 Loss

method family ≠ single model/loss；feedback source ≠ feedback structure ≠ optimizer。共同主线之后有 RM+PPO、直接偏好/可取性、轨迹偏好/连续策略 三条并行分支；proxy score ≠ task success ≠ safety。

3 parallel branches4 evidence layersunknown capability → blocked

方法族定义与命名边界

RLHF-VLA 是把人类或其他评价者对机器人 action、chunk、segment、trajectory 或 task result 的反馈，转换为可追溯学习信号的一组方法。它不是单个模型、固定 Reward Model、特定 PPO 流水线或一条由旧到新的算法阶梯。一个方法的身份至少由五项共同决定：feedback producer/authority、feedback structure/granularity、derived label/reward revision、optimization graph、policy/action interface。

名称 最小定义 不自动意味着
narrow RLHF human feedback → learned/derived reward → RL update PPO 是唯一优化器
preference alignment comparison/desirability/trajectory feedback 直接或间接更新 policy 反馈一定来自真人
RLAIF AI system 产生评价或偏好 标签正确、独立或安全
RLIF-style intervention decision 派生 reward，off-policy RL 模仿 corrective action
RLVR/verifier reward rule/environment/verifier 产生可验证 signal human preference
interactive imitation correction/demonstration 聚合 reinforcement learning

经典 human-preference RL、PPO、InstructGPT、DPO/KTO 的结果分别属于 simulated control 或 language model 来源域；它们只定义方法或经典流水线，不是任意 VLA 已验证证据。APO v3、GRAPE v2 与 RLIF v2 有机器人实验，但各自绑定特定任务、action interface 和 protocol，也不能外推到所有 VLA。页面因此只说“用于优化被定义、记录且独立验证过的目标”，不承诺必然提升成功率、安全或泛化。

共同输入、反馈事件与派生视图

原始 feedback event 是事实记录，不应被后续 reward、pair、desirability 或 ranking 覆盖。它至少绑定 episode/segment/action IDs，start/end/event timestamps 与 clock domain，producer type、pseudonymous identity、role/authority，feedback structure/value、tie/abstain/unknown、confidence、response latency，以及实际 behavior policy、observation/action receipt、task/robot/environment revision、query policy、consent、PII 和 retention 状态。

反馈结构不能用“四类 KPI”代替。pairwise/listwise comparison、binary desirability、scalar/attribute/keypoint/language、intervention decision、corrective action/demonstration 与 verifier outcome 有不同随机变量和 authority。人类、rule、VLM/AI、environment/verifier 是 producer/source；它们不决定数据一定是 pair、reward 或 trajectory，也不决定采用 PPO、DPO、TPO 或 off-policy RL。

derived view 必须保存 parent_event_ids、transform name/version/config、label/reward semantics、producer、created time、content hash、supersedes 与 validation status。同一 intervention event 可以派生 APO-style desirability 与 RLIF-style reward，但两者必须是不同 revision：前者不是后者，corrective action 也不是 intervention decision 本身。

每个方法都必须同时显示 producer、feedback structure、optimization graph、policy interface 和 evidence domain；过滤任意一轴不能隐藏另外三轴。一个笼统的 “RLHF” badge 无法表达这些合同。

Producer / authorityhuman · rule · VLM/AI · environment · mixed；来源不等于正确性或 release authority。

Optimization graphlearned RM+RL · direct preference · trajectory preference · feedback-as-reward RL · SFT。

method coordinate feedback / graph source domain target evidence state

不可变事实到候选发布的共享闭环

flowchart LR
  B["Behavior / Champion rollout"] --> F["immutable facts"]
  H["human · rule · VLM · environment feedback"] --> E["feedback events"]
  F --> E --> V["versioned derived views"]
  V --> T["selected branch trainer"]
  T --> C["candidate artifact"]
  C --> Q["independent task evaluation"]
  Q --> S["independent safety approval"]
  S --> P["staged activation + worker ack"]
  P --> R["rollback pointer"]

共享闭环只有四条不可让步的不变量：facts immutable；每个 sample 可追到 behavior、processor、normalization、action/safety 和 feedback revision；training labeler/proxy reward 不单独决定 release；硬安全 authority 不依赖 policy、RM 或 critic 正确。Candidate 还必须有 immutable hash、parent、data/feedback view、branch trainer、evaluation manifest、safety review、activation window、worker acknowledgement 与 rollback pointer，缺项即 blocked。

“online”必须拆成四个独立字段：online environment collection、online human/AI feedback、相对 current policy 的 on-policy data、online/continual parameter update。任一项为真都不能替代另外三项，也不能用 online: true 隐藏 policy staleness、feedback delay 或 train/eval leakage。

RM+RL、直接偏好、轨迹偏好与 RLIF 边界

Learned Reward + RL 先由 comparison/scalar feedback 学 proxy reward，再由 PPO/SAC 等更新 policy；RM 不是 ground truth，PPO 也不是 RLHF 定义本身。Direct preference/desirability 的 DPO/KTO/APO 可以不使用独立 RM/Critic，但仍需要方法匹配的 feedback structure、reference/current score 与同一 action random variable；no RM 不等于没有 proxy、过拟合或安全风险。

Trajectory preference 的 policy-only ratio 能否约去环境项，取决于 current/reference 是否共享 condition、initial-state distribution、dynamics 与 action variable。trajectory objective 仍面临 length normalization、termination、partial observability、credit assignment 和 selection bias。RLIF-style 则把 intervention decision 派生为 reward，并用 off-policy RL；它不是 pairwise preference，也不等于模仿 corrective action。

同一 source event 不代表同一训练语义。APO 的 binary action desirability、RLIF 的 intervention reward、HG-DAgger 的 corrective demonstration 可以共享事实记录，但 derived view、counterfactual assumption、optimizer 和 evidence 必须分别版本化。

Token/Gaussian/Diffusion/Flow 的可用接口

每个 checkpoint/adapter 必须声明 action random variable、conditioning/history、support/measure、exact/estimated/surrogate score、normalization、transform/Jacobian、token/step/chunk mask、horizon/executed prefix、noise schedule、gradient path、reference compatibility 与 test evidence。current/reference 的变量、units、frame、normalization、mask、chunk、condition 或 estimator 任一不一致，ratio objective 即 incompatible。

policy interface 可用量 禁止假设
autoregressive token teacher-forced token/sequence log-prob 未执行 suffix 等于 executed action
squashed Gaussian pre-squash density + transform Jacobian hard-clipped action 仍是同一 density
diffusion denoising/path quantities 或经证明 estimator denoising loss = environment action log-prob
Flow/CNF velocity objective；满足额外条件时估 density Flow Matching MSE = -log π(a\|h)
deterministic/residual regression、critic 或 residual objective 可凭空生成 exact log-prob

proposed、sampled、commanded、safe、executed action 必须保留 lineage。一个仓库同时支持 π₀ flow path 与 π₀-FAST autoregressive path，也不意味着同一 adapter 或 checkpoint 同时拥有两种 capability；目标能否启用由锁定 artifact 与证据决定，不由仓库名决定。

一手来源与版本边界

  • Deep RL from Human Preferences v4：human pairwise trajectory segments；Atari/simulated locomotion，不是 VLA 结果。
  • PPO v2：通用 on-policy surrogate optimizer，不是 RLHF 定义。
  • InstructGPT v1、DPO v3 与 KTO / ICML 2024：语言模型来源域，迁移到 VLA 需独立证据。
  • APO v3：机器人 intervention-derived binary desirability；NeurIPS 2025，绑定其 action-token 设计。
  • GRAPE v2：VLA trajectory preference 与自动时空约束；自动信号不标作真人反馈。
  • Uni-RLHF v2：多反馈平台、数据和 offline baselines，不是全部 VLA 分支验证。
  • RLIF v2：intervention signal as reward + off-policy RL；不是 pairwise preference。
  • Reward Model Overoptimization v1：proxy/gold 风险原则；定量不外推机器人。

所有来源事实都绑定 version、domain 和 evidence label。链接可达、项目页声明、固定实现可复现、目标机器人可部署是四个不同结论；Implementation 页再审计 commit、license 与 capability。
