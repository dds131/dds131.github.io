Dyna-Q 不是本主线第一个基于模型的方法——前面的动态规划已经使用给定模型。它的新意是把模型学习、直接 TD 更新与规划更新放进同一在线循环：模型由真实经验估计，真实与模型样本共享同一个 Q-learning 更新算子。

1990Dyna 架构提出年份
n每步真实交互后的规划次数
1更新公式的数量（真实与虚拟共用）
表格本章的值函数表示形式

本页重点。精读规划预算 \(n\)、模型误差与 Dyna-Q+ 三节；特别检查联合模型是否保存 termination、标准 CliffWalking 合同是否一致，以及结论是否来自环境步、backup 与墙钟三种资源口径。参数只给演示配置，不冒充通用范围。

本章要解决什么问题

动态规划使用给定模型做全期望 backup；TD 控制直接用环境样本更新。无模型并不等于“每条经验只能使用一次”：experience replay、离线数据和多步重用都可以复用真实转移。Dyna-Q 的区别是额外学习一个模型，并从模型产生规划样本。

  • 无模型方法不显式预测奖励与后继状态，但仍可重放数据；它避免显式模型偏差，却不自动获得低样本复杂度。
  • 有模型方法使用给定或学得的动力学/奖励模型进行预测、搜索或规划；它能把计算用于未再次发生的转移组合，但性能取决于模型覆盖与保真度。
  • 动态规划的模型是给定的；Dyna-Q 的模型由在线交互更新，并把单步规划与直接 Q-learning 交织执行。

本页因此回答：模型未知时，怎样统一真实更新、模型学习和规划更新；怎样处理 termination；规划预算何时有用，何时只会强化模型误差。

本页的符号沿用主线约定：\(s\) 为状态，\(a\) 为动作，\(r\) 为奖励，\(\gamma\) 为折扣因子，\(\pi\) 为策略，\(V\) 与 \(Q\) 为状态值与动作值函数，\(\alpha\) 为学习率。本章新增两个符号：\(M\) 表示学到的环境模型，\(n\) 表示每步真实交互后执行的规划次数。

形式化定义：联合模型、规划与直接更新

沿用主线任务合同 \(\mathcal M=(\mathcal S,\mathcal A,p,\gamma,\rho_0)\)，其中联合核 \(p(s',r,d\mid s,a)\) 同时描述后继、奖励与真正终止标志 \(d\)。Dyna-Q 维护表格 \(Q\) 和估计模型 \(\hat M\)。

  • 分布模型给出 \(\hat p(s',r,d\mid s,a)\)，可采样，也可对所有分支做期望 backup。
  • 采样模型被查询时返回 \((r,s',d)\sim\hat M(s,a)\)。
  • 本页的确定性字典模型保存最近观察到的三元组：
\[\hat M(s,a)=(r,s',d).\]

终止标志是模型输出的一部分；遗漏它会使规划从不存在的终止后继继续 bootstrap。外部 truncation 不属于该 MDP 转移的 termination，通常不写成 \(d=1\)；若采样器自动 reset，还必须保存 final observation。

环节 输入来源 更新对象 主要限制
直接 RL 真实环境转移 \(Q\) 环境交互与覆盖
模型学习 真实环境转移 \(\hat M\) 统计误差、错配、漂移
规划 \(\hat M\) 的样本或期望 \(Q\) 计算预算与模型支撑集

经典 Dyna-Q 的直接更新和规划更新共享算子

\[Q(s,a)\leftarrow Q(s,a)+\alpha \left[ r+\gamma(1-d)\max_{a'}Q(s',a')-Q(s,a) \right].\]

“共享算子”不表示真实数据与模型数据同样可靠；工程实现可以区分步长、采样比例或不确定性权重。模型至少有三个审计维度：覆盖（哪些 \((s,a)\) 可查询）、校准/保真（联合输出是否正确）和新鲜度（非平稳环境中多久未被真实刷新）。

算法推导：Dyna 架构如何统一真实经验与虚拟经验

本节是全页重点之一。其中「规划步数 \(n\) 的作用机理」与「为什么收益会递减」两小节需要逐行读，它们解释了 Dyna-Q 唯一的新旋钮到底在换什么。

起点：一条 Q-learning 更新

Q-learning 的单步更新写成带 termination mask 的形式：

\[Q(s,a) \leftarrow Q(s,a)+\alpha \left[ r+\gamma(1-d)\max_{a'}Q(s',a')-Q(s,a) \right].\]

对应 TD error 为

\[\delta=r+\gamma(1-d)\max_{a'}Q(s',a')-Q(s,a).\]

更新需要五元组 \((s,a,r,s',d)\)。真实环境和模型都能提供它，但两者的统计可信度不同；共享更新算子不等于可以忽略模型偏差。

Dyna 架构：一次真实交互，\(n+1\) 次更新

经典 Dyna-Q 每与环境交互一步按以下顺序执行：

  1. 直接强化学习：用真实五元组 \((s,a,r,s',d)\) 更新一次。
  2. 模型学习：写入 \(M(s,a)\leftarrow(r,s',d)\)。
  3. 规划：重复 \(n\) 次，从已有键采样并取出 \((r_m,s'_m,d_m)\)，用同一 mask 公式更新 \(Q\)。

于是一步真实交互带来 \(n+1\) 次 \(Q\) 更新。\(T\) 步真实交互后，\(Q\) 表累计被更新

\[N_{\text{update}} = T \, (n + 1)\]

次，而消耗的环境交互仍然只有 \(T\) 步。\(n = 0\) 时第三步不执行、模型写了也不用，算法逐字退化成 Q-learning——这是后文实验里 \(n=0\) 这条对照曲线的由来。

下图画出这三件事之间的数据流。实线为真实数据通路，虚线为模型生成的虚拟数据通路，两条通路汇入同一个 \(Q\) 更新算子。

flowchart TB
  POL["行为策略 epsilon-greedy 基于 Q 表"] -->|"动作 a"| ENV["真实环境"]
  ENV -->|"真实五元组 s, a, r, s_next, terminated"| SPLIT["一次真实交互的产物"]
  SPLIT -->|"通路一：直接强化学习"| UPD["同一条 Q-learning 更新算子<br/>Q 增量等于 alpha 乘以 TD 误差"]
  SPLIT -->|"通路二：模型学习，写入字典"| MODEL["环境模型 M<br/>键为 s 与 a，值为 r、s_next 与 terminated"]
  MODEL -.->|"随机抽取已访问过的键，重复 n 次"| SIM["虚拟五元组 s_m, a_m, r_m, s_next_m, term_m"]
  SIM -.->|"通路三：规划"| UPD
  UPD --> Q["Q 表"]
  Q --> POL

读图要点：真实交互每步只发生一次，而虚线回路每步循环 \(n\) 次；三条通路的终点是同一个更新算子与同一张 \(Q\) 表，Dyna 架构没有为规划另设一套值函数。

规划步数 \(n\) 的作用机理

为什么多做 \(n\) 次「重放已知转移」的更新会有用？表面上模型里没有任何新信息——它存的每一条都来自已经发生过的真实交互。真正被加速的不是信息的获取，而是信息在状态图上的传播。

看清这一点需要回到表格型 Q-learning 的一个结构性限制：一次更新只把值信息沿一条边反向传递一步。设终点附近某个状态 \(s_G\) 的 \(Q\) 值刚被奖励修正，那么它的前驱状态要等到「智能体再次访问该前驱并执行指向 \(s_G\) 的动作」时，才能通过 \(\gamma \max_{a'} Q(s_G, a')\) 这一项分到这份信息。要把信息从终点传回长度为 \(L\) 的路径起点，至少需要 \(L\) 次按正确顺序排列的更新。

在下面这种固定起点、按路径前向访问且在线更新的走廊例子中，无模型 Q-learning 需要重复访问前驱，值信息每个回合至多按访问顺序反传有限层；一般任务中的传播速度还取决于访问顺序、回放与多步目标。Dyna-Q 的规划循环把额外更新搬进内存：模型里已经存着路径边时，随机抽样若形成合适的反向次序，信息可能在不新增真实交互的情况下继续回传。用一句话概括机理：

\[\text{真实交互负责发现转移，规划负责把已发现的转移反复利用，直到 } Q \text{ 与模型自洽}\]

由此可以给出 \(n\) 的准确含义——它是一个计算换样本效率的兑换率：

  • 每个环境步的计算量与 \(n+1\) 成正比；
  • 在模型较准且规划更新有效时，增大 \(n\) 可能减少达到给定性能所需的真实环境步数，但该关系不保证单调；
  • 总成本取决于环境步、规划计算与模型误差。真机交互昂贵会提高规划的潜在价值，但错误模型也可能让更大的 \(n\) 伤害策略；应报告环境步、墙钟时间和最终性能，而不是只按 \(n\) 排序。

还有一个容易忽略的细节：规划时从所有已访问条目中均匀随机抽样，意味着大量抽样落在与当前值传播无关的条目上，这些更新的 TD 误差接近零，等于空转。优先扫描（prioritized sweeping）正是针对这一点的改进——维护一个按 TD 误差大小排序的队列，优先更新那些「前驱值刚发生变化」的条目，用同样的 \(n\) 换来更多有效更新。Dyna-Q 本身不做这件事，它的随机抽样是一个刻意选择的简化。

一个手算例子：值信息如何在一个回合内回传

上面的机理用一个最小例子就能算清楚。为了让数字干净，这里临时换一个奖励设定（与本页实验用的悬崖漫步无关）：一条四状态的走廊 \(x_0 \to x_1 \to x_2 \to G\)，动作只有「向右」，中途奖励为 0，走到终点 \(G\) 得 \(r = 1\) 并终止。取 \(\gamma = 0.9\)，为便于手算取 \(\alpha = 1\)，\(Q\) 全零初始化。

无模型的 Q-learning。第一个回合里，智能体依次经过三条转移，但只有最后一条带来非零 TD 误差：

\[Q(x_2, \text{右}) \leftarrow 1 + \gamma \cdot 0 = 1\]

前两条转移更新时，后继状态的 \(Q\) 还全是 0，更新量为零。第二个回合才轮到 \(x_1\)：

\[Q(x_1, \text{右}) \leftarrow 0 + 0.9 \times \max_{a'} Q(x_2, a') = 0.9\]

第三个回合才轮到 \(x_0\)，得到 \(0.81\)。结论：值信息每个回合只前进一层，走廊有多长就需要多少个回合。

Dyna-Q。同样在第一个回合、同样只与环境交互三步，但每步之后额外做 \(n\) 次规划。走完最后一条转移时模型里已经存有全部三条边，若规划恰好按 \((x_1,\text{右})\)、\((x_0,\text{右})\) 的顺序各抽到一次，则

\[Q(x_1, \text{右}) \leftarrow 0 + 0.9 \times 1 = 0.9, \qquad Q(x_0, \text{右}) \leftarrow 0 + 0.9 \times 0.9 = 0.81\]

第一个回合结束时，整条走廊的 \(Q\) 值就已经与三个回合后的 Q-learning 完全一致，而消耗的真实交互步数只有三步。

这个例子还顺带说清了两件事：

  • 顺序决定效率。若规划先抽到 \((x_0,\text{右})\) 再抽到 \((x_1,\text{右})\)，第一次抽样的 TD 误差为零，纯属空转，需要更多次抽样才能凑出正确顺序。均匀随机抽样意味着凑齐一条长度为 \(L\) 的正确顺序所需的期望抽样次数远大于 \(L\)，这正是优先扫描要改进的地方。
  • 规划不会凭空造值。三条边都是真实走过一次之后才进入模型的。规划做的全部工作，是把这三条已知的边按合适的顺序重新组合，把终点的奖励沿链条推回起点。

为什么收益会递减

\(n\) 增大时的收益不是线性的，而是很快趋于饱和。原因可以从不动点角度写清楚。

模型 \(M\) 连同已访问的状态-动作集合，本身定义了一个「估计出来的 MDP」，记作 \(\hat{\mathcal{M}}\)。规划循环所做的，正是在 \(\hat{\mathcal{M}}\) 上做异步价值迭代。它的不动点 \(\hat{Q}^{*}\) 满足

\[\hat{Q}^{*}(s,a) = \hat{r}(s,a) + \gamma (1-\hat d) \max_{a'} \hat{Q}^{*}(s', a'), \qquad (\hat{r}, s', \hat d) = M(s,a)\]

于是有三条直接结论：

  • 存在天花板。无论 \(n\) 取多大，规划最多把 \(Q\) 推到 \(\hat{Q}^{*}\)。一旦 \(Q\) 与模型自洽，所有虚拟更新的 TD 误差都接近零，继续增加 \(n\) 只是在做无效计算。
  • 天花板由模型的覆盖度决定。\(\hat{Q}^{*}\) 与真实最优 \(Q^{*}\) 的差距，取决于模型里有没有存下通往高回报区域的那些边。这些边只能靠真实交互去发现，规划无法凭空造出来。因此探索的价值不会被 \(n\) 替代：\(n\) 加速的是已知信息的利用，不是未知区域的发现。
  • 递减的拐点与模型规模和采样结构相关。若要用均匀有放回抽样至少覆盖 \(\lvert M \rvert\) 个条目一次，经典 coupon-collector 期望是约 \(\lvert M \rvert\log\lvert M \rvert\) 次；值传播还取决于前驱结构、TD 误差和抽样顺序，不能只用状态数给出统一阈值。应通过学习曲线与规划 TD 误差判断收益是否饱和。

一个实用诊断是同时比较环境步曲线、墙钟曲线和规划 TD 误差。若把 \(n\) 翻倍后环境步曲线不再改善且规划 TD 误差已接近零，说明当前模型上的规划接近饱和；若误差仍大，则瓶颈也可能是抽样顺序、步长或计算预算。不能仅凭“曲线没有左移”唯一归因于模型覆盖度。

模型不准时的失效模式

本节是全页另一个重点。上一节说明了模型准确时 \(n\) 能换来什么；本节说明模型不准时 \(n\) 会放大什么。这一组对照，是 Dyna-Q 与后续所有基于模型深度方法的共同主题。

真实样本与模型样本的误差来源不同

真实转移是环境核的样本，但单个样本的 TD 更新不保证“方向必然正确”。只有在任务平稳、访问覆盖充分、步长满足相应条件且表示/算法满足定理假设时，随机误差才可能在长期平均中消退。

模型样本还叠加了模型估计误差和支撑集偏差。规划会提高模型样本相对于真实样本的更新权重，因此持久的模型偏差可能主导 Q；影响通常随规划比例增大，但不应写成严格“与 \(n\) 成比例”的普遍定律。真实再访问、模型更新、递减步长和采样分布共同决定纠错速度。

flowchart TB
  DATA["真实转移"] --> MODEL["估计模型"]
  MODEL --> PLAN["n 次规划采样"]
  PLAN --> Q["Q 更新"]
  Q --> POLICY["行为策略与访问分布"]
  POLICY --> DATA
  ERR["模型偏差或陈旧"] --> MODEL
  Q -.->|"低估可能减少再访问"| POLICY

随机环境：最近样本模型不是分布模型

确定性覆盖写入 \(\hat M(s,a)=(r_{last},s'_{last},d_{last})\)。在两次真实刷新之间，规划 target 固定为

\[Y_{last} = r_{last} + \gamma(1-d_{last}) \max_{a'}Q(s'_{last},a'),\]

而环境核对应的期望 target 是

\[\mathbb E_{(s',r,d)\sim p(\cdot\mid s,a)} \left[ r+\gamma(1-d)\max_{a'}Q(s',a') \right].\]

反复规划会暂时把估计推向最近一次随机结果，造成相关更新与高方差；但若每个状态—动作持续被真实访问、最近样本随时间重新抽取且步长递减，不能武断断言它必然收敛到永久错误的不动点。更稳健的做法是维护后继—奖励—终止的经验分布，规划时重新采样或直接做期望 backup；也可以降低模型更新权重或用不确定性限制规划。

失效模式二：环境非平稳，模型记住的是过去的世界

环境变化后，旧模型可能描述已经不存在的转移。被封闭的旧通路会因规划而持续高估；新出现的捷径若从未真实尝试，则不在普通 Dyna-Q 的模型支撑集中。

Dyna-Q+ 不只是给已有条目加奖金。对已经访问过的状态，它还把尚未尝试的动作纳入模型，常用默认模型为“奖励 0、回到同一状态”，并在规划时使用

\[r^+(s,a)=\hat r(s,a)+\kappa\sqrt{\tau(s,a)},\]

其中 \(\tau(s,a)\) 是距上次真实尝试的时间；从未尝试动作从被纳入模型起累计时间。这样规划奖金才有机会提高未尝试动作的 Q 并触发真实验证。若只在普通 Dyna-Q 已有键上加奖金，未尝试动作仍不会被规划抽到，无法复现 Dyna-Q+ 的探索机制。

与后续深度方法的分野

把上面两条失效模式抽象一层，就得到基于模型方法的核心矛盾：模型误差会沿规划的自举链条累积，规划得越深、重放得越多，累积得越厉害。 深度时代的基于模型方法基本都是在这条矛盾上做文章：

  • 限制 rollout 长度。MBPO 一类方法承认学出来的神经网络模型只在短时域内可信，因此只用模型生成很短的分支轨迹（常见是个位数步），其余部分仍交给真实数据。这与 Dyna-Q 的单步模型在思想上一致——Dyna-Q 的模型 rollout 长度恰好是 1，这也是它虽然简单却相对稳健的原因。
  • 量化模型不确定性。用集成模型的分歧度作为模型误差的代理量，误差大的地方少用甚至不用虚拟数据。
  • 用模型做滚动时域在线优化。MPC 通常仍依赖给定或学得的动力学模型，但每个控制周期重新优化有限动作序列，不一定训练一个长期策略；详见 MPC。

反过来看，本主线接下来的 DQN走的是另一条路：干脆不建模型，把精力全部放在「如何用函数逼近处理巨大的状态空间」上。两条路线在深度强化学习里长期并存。

算法流程

方括号内为该步骤对应的公式或前文小节。

输入: 学习率 alpha, 折扣 gamma, 探索率 epsilon, 规划步数 n

1  初始化 Q(s, a) 为零表, 初始化空模型 M
2  for episode = 1, 2, ... do
3      重置环境, 得到初始状态 s
4      repeat
5          # ---- 与真实环境交互 ----
6          a <- epsilon-greedy(Q, s)
7          执行 a, 观测 r, s_next, terminated
8          # ---- 步骤一: 直接强化学习 ----
9          若 terminated 则 max_next_q <- 0, 否则 max_next_q <- max_a' Q(s_next, a')
10         td_target <- r + gamma * max_next_q                  [Q-learning 更新式]
11         Q(s, a) <- Q(s, a) + alpha * ( td_target - Q(s, a) )
12         # ---- 步骤二: 模型学习 ----
13         M(s, a) <- (r, s_next, terminated)                   [确定性模型, 覆盖写入]
14         # ---- 步骤三: 规划, 重复 n 次 ----
15         for i = 1 .. n do
16             (s_m, a_m) <- 从 M 已有的键中均匀随机抽取         [随机抽样, 非优先扫描]
17             (r_m, s_next_m, term_m) <- M(s_m, a_m)
18             用第 9-11 行的同一条公式更新 Q(s_m, a_m)          [与真实更新共用算子]
19         end for
20         s <- s_next
21     until terminated 或达到步数上限
22 end for

三处最容易写错的地方：

  • 第 13 行必须在第 11 行之后、第 15 行之前。先做真实更新再写模型，再开始规划；若把规划放在模型写入之前，当前这条最新的转移就参与不了本轮规划，信息传播慢一拍。
  • 第 16 行只能从已有的键里抽，不能对整个状态-动作空间均匀抽样。模型里没有的条目意味着从未访问过，凭空规划等于编造转移。
  • 第 9 行的 termination mask 在规划里同样适用。模型条目必须保存 terminated；在标准 CliffWalking 中踏崖不是终止，只有到达目标才令 bootstrap 为 0。

代码实现

实现直接使用 Gymnasium 的标准 CliffWalking-v1，避免自定义环境把“踏崖”错误写成 termination。标准合同中，踏崖得到 \(-100\)、回到起点且 episode 继续；只有到达目标才终止。

第一段：依赖、配置与环境合同

import gymnasium as gym
import numpy as np
import matplotlib.pyplot as plt

SEED = 0
ALPHA = 0.1
GAMMA = 0.9
EPSILON = 0.01
N_EPISODES = 300
MAX_STEPS = 500
N_PLANNING_LIST = [0, 2, 20]
N_RUNS = 10


def make_env():
    return gym.make("CliffWalking-v1")


contract_wrapped = make_env()
contract_env = contract_wrapped.unwrapped
# 起点状态 36 向右：-100、回到起点、非终止。
assert contract_env.P[36][1] == [(1.0, 36, -100, False)]
# 目标左侧状态 35 向下：到目标 47、奖励 -1、终止。
assert contract_env.P[35][2] == [(1.0, 47, -1, True)]
contract_wrapped.close()

动作顺序由标准环境定义为上、右、下、左。确定性字典模型在这个环境合同下可以精确表示已访问转移，但“已访问转移精确”不等于覆盖整个状态—动作空间。MAX_STEPS 是外部 truncation，只结束当前采样片段，不写成模型中的 termination。

第三段：DynaQ 类的初始化与动作选择

class DynaQ:
    """表格型 Dyna-Q。n_planning = 0 时逐字退化为 Q-learning。"""

    def __init__(self, n_state, n_action, alpha, gamma, epsilon, n_planning, rng):
        self.q_table = np.zeros((n_state, n_action))   # Q(s, a)，初始化为全零
        self.n_action = n_action
        self.alpha, self.gamma, self.epsilon = alpha, gamma, epsilon
        self.n_planning = n_planning                   # 即公式里的 n
        self.model = {}                                # 环境模型 M：键 (s, a)，值 (r, s_next, term)
        self.model_keys = []                           # 与 model 同步维护，供 O(1) 随机抽样
        self.rng = rng

    def take_action(self, state: int) -> int:
        """epsilon-greedy 行为策略。"""
        if self.rng.random() < self.epsilon:
            return int(self.rng.integers(self.n_action))
        return int(np.argmax(self.q_table[state]))

两处值得说明。其一，model 与 model_keys 必须成对维护：规划需要「从已有条目中均匀随机抽一个」，而 Python 字典无法按下标随机访问，每次调用 list(self.model.keys()) 会让规划循环的复杂度变成 \(O(n \cdot \lvert M \rvert)\)，在 \(n=20\) 时开销明显。单独维护一个列表，把抽样降到 \(O(1)\)。其二，\(Q\) 表初始化为全零。在本环境里所有奖励都是负的，全零初始化天然是一种乐观初始化，未访问过的动作看起来比访问过的更好，这本身就提供了一部分探索，因此 \(\varepsilon\) 可以取得很小。

第四段：单步 Q 更新（核心，逐行讲）

    def q_learning(self, s, a, r, s_next, terminated):
        """Q-learning 的单步更新。真实经验与虚拟经验共用这一个方法。"""
        # 终止转移之后没有任何后续回报，自举项必须置零
        max_next_q = 0.0 if terminated else float(np.max(self.q_table[s_next]))
        td_target = r + self.gamma * max_next_q          # 对应公式 r + gamma * max Q(s', a')
        td_error = td_target - self.q_table[s, a]        # 即 TD 误差 delta
        self.q_table[s, a] += self.alpha * td_error      # 沿 TD 误差方向移动 alpha 倍

这一段直接对应推导一节的第一条公式，变量名与符号一一对应：max_next_q 是 \(\max_{a'} Q(s',a')\)，td_target 是 \(r + \gamma \max_{a'} Q(s',a')\)，td_error 是 \(\delta\)。四处容易写错的地方：

  • terminated 分支不能省。在标准 CliffWalking 中只有到达目标切断 bootstrap；踏崖会回到起点并继续，因此 \(-100\) 转移仍包含从起点继续的未来价值。
  • terminated 与截断必须分开。因 MAX_STEPS 触发的截断不是真终止，此时应当照常自举；如果把截断也当作终止传进来，等于告诉 \(Q\) 表「这条路走到这里就没有未来了」，这与 DDPG页里强调的是同一件事。
  • np.max 而不是 np.argmax。这里要的是最大值本身，不是取到最大值的下标。二者混淆时 \(Q\) 表会被填进动作编号，量级完全错乱。
  • 更新是增量式的，不是赋值式的。写成 self.q_table[s, a] = td_target 就变成了学习率恒为 1 的更新，在随机环境里会让 \(Q\) 完全跟着最近一个样本跳动。

方法名之所以叫 q_learning 而不是 update，是为了在代码层面体现推导一节的核心主张：规划与直接强化学习共用同一个更新算子。下一段的规划循环调用的就是这个方法，一个字符都不改。

第五段：模型写入与规划循环（核心，逐行讲）

    def update(self, s, a, r, s_next, terminated):
        """一次真实交互对应的完整处理：直接强化学习 + 模型学习 + n 次规划。"""
        # 步骤一：直接强化学习，用真实转移样本更新一次
        self.q_learning(s, a, r, s_next, terminated)

        # 步骤二：模型学习。确定性模型，后写覆盖先写
        if (s, a) not in self.model:
            self.model_keys.append((s, a))               # 新键才追加，避免列表出现重复
        self.model[(s, a)] = (r, s_next, terminated)

        # 步骤三：规划。重复 n 次，每次从已访问过的条目里随机取一条重放
        for _ in range(self.n_planning):
            idx = int(self.rng.integers(len(self.model_keys)))
            s_m, a_m = self.model_keys[idx]              # 只从模型已有的键中抽，不外推
            r_m, s_next_m, term_m = self.model[(s_m, a_m)]
            self.q_learning(s_m, a_m, r_m, s_next_m, term_m)   # 与真实更新完全相同的算子

这十几行就是 Dyna-Q 的全部。逐条对应算法流程里的编号步骤：

  • 推荐顺序是先做真实更新、再写模型、最后规划，使最新转移立即参与本轮规划；换序会改变更新时序，但“必然明显拖慢”需要实验支持。
  • if (s, a) not in self.model 这个判断不能省。确定性模型对已有键是覆盖写入，键的总数不变；若无条件 append，model_keys 里会积累大量重复项，抽样分布就从「在已访问条目上均匀」变成「按访问频次加权」。这不一定更差，但它已不再是本页采用的“在已访问状态—动作键上均匀抽样”的经典最小实现，而变成按访问频次加权的规划采样变体；同时列表会随交互步数无界增长。
  • 抽样必须限定在 model_keys 内。规划的合法性完全建立在「这条转移真实发生过」之上。若改成在整个状态-动作空间上随机抽，模型对没访问过的键根本没有值，程序会直接报错；即使补上默认值，也等于用编造的转移训练 \(Q\)。
  • term_m 必须与 \(r,s'\) 一起存储。否则真正目标转移会被错误 bootstrap；标准环境中的踏崖条目则应保存 False。
  • 规划循环里没有任何环境调用。这是「用计算换样本效率」这句话在代码上的确切含义：整个 for 循环只访问内存，环境交互步数与 \(n\) 无关。

一个实现细节：self.rng 贯穿动作选择与规划抽样，全部随机性都由外部传入的同一个生成器控制，因此给定种子后整次运行可复现。把 np.random 的全局函数与 rng 混用，是复现失败的常见原因。

第六段：训练循环与对照实验（样板，从简）

def run_one(n_planning: int, seed: int):
    """训练一组配置，返回每回合的累计回报序列。"""
    rng = np.random.default_rng(seed)
    env = make_env()
    agent = DynaQ(env.observation_space.n, env.action_space.n,
                  ALPHA, GAMMA, EPSILON, n_planning, rng)
    returns = []
    for ep in range(N_EPISODES):
        state, _ = env.reset(seed=seed + ep)
        ep_return, steps = 0.0, 0
        while True:
            action = agent.take_action(state)
            next_state, reward, terminated, truncated, _ = env.step(action)
            steps += 1
            truncated = truncated or steps >= MAX_STEPS      # 截断，不是真终止
            # 只把 terminated 传给算法，truncated 不切断自举
            agent.update(state, action, reward, next_state, terminated)
            ep_return += reward
            state = next_state
            if terminated or truncated:
                break
        returns.append(ep_return)
    env.close()
    return np.array(returns)


def moving_average(x, window=9):
    kernel = np.ones(window) / window
    return np.convolve(x, kernel, mode="valid")


if __name__ == "__main__":
    plt.figure(figsize=(7, 4.2))
    for n in N_PLANNING_LIST:
        curves = np.stack([run_one(n, SEED + k) for k in range(N_RUNS)])
        mean_curve = moving_average(curves.mean(axis=0))
        plt.plot(mean_curve, label=f"n_planning = {n}")
    plt.xlabel("episode")
    plt.ylabel("episode return (moving average)")
    plt.title("Dyna-Q on Cliff Walking")
    plt.legend()
    plt.tight_layout()
    plt.savefig("dynaq_cliffwalking.png", dpi=150)

示例图只展示跨 seed 均值的平滑曲线，不能据此给出不确定性结论；正式报告还需保留原始曲线、区间与环境步/backup/墙钟三种横轴。truncated 仅结束采样，真正的 bootstrap mask 仍由 terminated 决定。

实验与结果分析：用资源曲线验证规划价值

页面不预先宣称 \(n=20\) 一定最好，也不把“掉崖更少”“最终策略相同”写成未运行的结果。规划次数只是一项处理，实验必须同时控制环境合同、\(\alpha\)、探索日程、环境步预算和 seed 集合。

最小实验矩阵

维度 至少包含 主要问题
规划预算 \(n=0,2,20\) 与更密的局部扫描 是否存在收益递减或反转
模型 精确确定性、最近样本、经验分布 规划收益来自模型还是样本复用
环境 标准确定性、随机滑移、训练中途改变 保真度与新鲜度如何影响结果
横轴 环境步、Q backup 数、墙钟时间 区分样本效率与计算效率
指标 behavior return、greedy evaluation、成功率、踏崖次数、Bellman residual 避免单曲线口径替代全部结论

对每个 seed 保存原始 episode 长度与回报、累计环境步、累计规划 backup、模型键数和评估检查点。曲线应展示 seed 区间；平滑只能用于可视化，统计量必须从未平滑数据计算。完整规范见评估与可复现页.

可以检验、不能预设的命题

在标准确定性 CliffWalking 中，增加适量规划通常会更快传播已访问转移的信息，这是合理假设，不是无需数据的结论。收益是否从 \(n=2\) 到 \(n=20\) 递减、踏崖次数是否单调下降、不同 \(n\) 是否达到同一 greedy policy，都要由多 seed 结果、覆盖度与残差验证。

随机环境中，最近样本模型会带来相关规划 target；更大的 \(n\) 可能提高方差或放大短期模型误差，但只凭这一点不能推出渐近偏差必然单调增大。非平稳环境则要报告变化后的恢复时间，并把普通 Dyna-Q 与正确实现的 Dyna-Q+ 对照。

若给真实环境步和一次 Q backup 分别赋成本 \(c_{env}\)、\(c_{upd}\)，达到预注册阈值所需环境步为 \(T(n)\)，可用

\[C(n)=T(n)\,[c_{env}+(n+1)c_{upd}]\]

比较总成本。这里的最优 \(n\) 取决于实测 \(T(n)\)、硬件和模型误差；“真实交互越贵，\(n\) 必然越大”并不成立，因为错误模型可能使更多规划反而增加真实交互。

参数与实现检查表

项目 作用 联合检查
\(n\) 每个真实步后的规划 backup 数 模型误差、\(\alpha\)、墙钟预算
\(\alpha\) 每次真实/规划 target 的吸收强度 是否共享步长、重复采样相关性
\(\gamma\) 任务的时间偏好 termination、奖励尺度、任务时标
\(\epsilon\) 真实覆盖 乐观初始化、衰减日程、Dyna-Q+ 奖金
MAX_STEPS 采样预算 truncation final observation 与 bootstrap
seed / 运行数 不确定性估计 环境、算法、评估随机流分离

本页的 0.1、0.9、0.01、0/2/20、500 和 10 次运行都只是演示配置，不是通用范围。调参顺序应为：先锁定环境与边界合同；用 \(n=0\) 验证 Q-learning 基线；再扫描 \(n\) 与 \(\alpha\)；最后检查随机/非平稳模型下的稳健性。\(\gamma\) 若属于任务定义，不应为改善曲线随意调节。

规划与真实更新共享同一 \(\alpha\) 是经典最小实现，不意味着始终最佳。规划样本高度相关或模型不准时，可分离步长或降低规划权重，但必须明确这已是变体。探索也不能由 \(n\) 替代：普通 Dyna-Q 只规划已有键；Dyna-Q+ 才通过未尝试动作默认模型和时间奖金扩大真实探索。

小结与下一章衔接

  • Dyna-Q 联合直接 Q-learning、模型学习和模型内规划；它的模型必须包含奖励、后继和 termination。
  • \(n\) 提高的是模型信息的复用强度，不创造模型支撑集之外的真实证据。
  • 最近样本模型在随机环境中产生相关、高方差 target；非平稳环境还会产生陈旧模型。影响取决于覆盖、刷新、步长与规划比例，不能概括成严格线性放大。
  • Dyna-Q+ 的关键不仅是时间奖金，还包括把已访问状态的未尝试动作纳入模型。

后续一条路线把表格模型扩展为学习动力学并进行短 rollout 或滚动优化，见 MPC；另一条路线用函数逼近扩展无模型 Q-learning，见 DQN。DQN 的 replay 是真实数据复用，不应与 Dyna 的模型生成样本混为一谈。
