PPO 更新通常同时承担三件事：按优势信号调整已采样动作的相对概率、让 Critic 拟合固定的 Return 目标、用熵项调节随机性。稳定性来自一套相互配合的机制——冻结 Rollout 参考量、有限次复用数据、监测策略偏移并约束梯度——而不只是一条裁剪公式。

Actor裁剪代理目标
Value回归固定 Return
Entropy调节探索压力
KL / Grad观察与限制步长

先固定符号： 本页采用梯度下降口径，最小化 $L_{total}=L_{actor}+c_vL_{value}-c_eH$。原论文中的 $L^{CLIP}$ 是要最大化的目标，因此代码里的 actor_loss 通常是它的负数。

Loss 的正负或绝对大小不能直接代表回报好坏。判断一次更新是否健康，至少要同时看回报、KL、clipfrac、价值诊断和梯度统计。

1. 组合 Loss

常见实现为

\[L_{total}(\theta,\phi)= -\mathbb E_t\left[ \min\left(\rho_t\hat A_t, \operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t\right) \right] +c_vL_{value}(\phi)-c_e\mathbb E_t[H(\pi_\theta)].\]

这里的期望均对当前 Rollout 中的有限样本取平均；old_log_prob、优势、Return 与可选的 old_value 都是该轮更新的冻结量。三个系数与网络是否共享密切相关：独立 Actor/Critic 时，价值系数只改变 Critic 的优化尺度；共享骨干时，它会直接改变共享层的合成梯度方向。不同代码若采用 sum、mean 或不同维度归约，Loss 数值也不能直接横比。

项 直接训练对象 主要信号 常见失效方式
$L_{actor}$ 策略参数 固定优势与新旧 ratio KL 突增、Clip 平台过多、优势噪声
$L_{value}$ Critic 参数 固定 Return 尺度巨大、过拟合单批、边界 Bootstrap 错
$-c_eH$ 动作分布 分布熵 方差塌缩或长期过随机

2. Actor Loss：同批数据上的近端更新

更新时用当前策略重新评估旧动作：

ratio = (new_log_prob - old_log_prob).exp()
loss_unclipped = -advantage * ratio
loss_clipped = -advantage * ratio.clamp(1.0 - clip_coef, 1.0 + clip_coef)
actor_loss = torch.maximum(loss_unclipped, loss_clipped).mean()

这与“先对目标取 minimum，再整体加负号”等价。若代码把已经带负号的两个 Loss 再取 minimum，会反转悲观选择。

详细分段行为见 近端目标与裁剪机制。

3. Value Loss 与可选价值裁剪

最基本的价值回归是

\[L_{value}=\frac12\mathbb E_t[(V_\phi(s_t)-\hat R_t)^2].\]

这里 $\hat R_t$ 在 Rollout 后构造，并在本次 PPO 更新的多个 Epoch 中保持固定。实现中应将它与优势视为监督目标并切断梯度；否则梯度可能错误地流回构造 GAE/Return 的旧价值预测。

部分实现模仿策略裁剪，限制新价值相对旧价值的变化：

\[V_{clip}=V_{old}+\operatorname{clip}(V_\phi-V_{old},-\epsilon_v,\epsilon_v),\] \[L_{value}^{clip}=\frac12\mathbb E_t\left[ \max\left((V_\phi-\hat R)^2,(V_{clip}-\hat R)^2\right) \right].\]

其中 $V_{old}$ 是采样时保存并在本轮更新中冻结的价值预测。这里裁剪的是“新价值相对旧价值的移动”，不是裁剪 Return，也不是把 $V_\phi$ 强行限制在区间内；max 选择的是两种误差中更大的一个，以免裁剪分支给出过于乐观的损失。

这是常见工程选项，并非 PPO-Clip 定义中的必需项，也不保证总是更好：它可能抑制本来有益的大幅价值修正。其效果还对奖励尺度敏感——同一个 $\epsilon_v$ 在奖励缩放变化后代表完全不同的价值步长，因此应把“开/关价值裁剪”作为消融变量，而不是默认把它视为更安全。

explained variance

常用诊断量：

\[EV=1-\frac{\operatorname{Var}(\hat R-V)}{\operatorname{Var}(\hat R)}.\]

接近 1 表示残差方差很小，0 表示残差方差与 Return 方差相当，负值表示残差方差更大。把 0 简称为“常数预测水平”只是在该方差定义下的直观比较，并不说明预测偏差、校准或控制性能良好。若 Return 方差几乎为 0，该指标会失去解释性，应同时记录分母、MSE 与原始分布。

4. 熵：不是越大越好

熵奖励通过 $-c_eH$ 鼓励策略保持随机性。对未变换的对角高斯，解析熵只由标准差决定；均值朝哪个动作移动并不会直接提高熵。若执行分布经过 tanh 和动作缩放，真实动作空间中的熵还包含变换 Jacobian，未变换高斯熵只能作为明确标注的代理量，不能悄悄当作执行策略的精确熵。

熵下降过快

可能是熵系数过小、学习率过高、初始标准差过小、优势信号过于尖锐，或某些动作维先行塌缩。

熵长期过高

可能是熵系数过大、奖励信号弱、Actor 没学到有效方向，或评估仍在随机采样。

不同动作维度或不同动作空间的熵量纲与范围不可直接横比。迁移超参数时，先核对熵是求和、平均还是按维归一化。

5. 梯度到底流向哪里

结构 推荐更新语义 最容易出现的错误
Actor/Critic 完全独立 分别构造 Loss、清梯度、反向并步进各自优化器 把 Critic 参数放入 Actor 优化器，或让价值系数被误解为会改变 Actor
共享编码器、独立头 对组合 Loss 一次反向，或显式合并共享参数的梯度 对共享计算图连续 backward 却未正确保留/重建图；同一参数被两个优化器重复步进
部分共享且需特殊权重 明确每组参数接受哪些项，并记录参数组学习率 随手 detach 共享特征，意外切断某一任务的学习信号

old_log_prob、old_value、优势与 Return 必须冻结；new_log_prob、当前熵和 $V_\phi$ 必须保留通向当前参数的梯度。是否共享参数是模型设计选择，代码应以参数集合测试确认，而不能只凭模块名称推断。

6. 多 Epoch 与 Mini-batch

一批 $B=N T$ 样本通常被重复训练 $K$ 个 Epoch，每轮随机打乱并切为大小 $M$ 的 Mini-batch。若能整除，每个迭代执行

\[K\times\frac{B}{M}\]

次优化器步进；不能整除时，保留尾批则为 $K\lceil B/M\rceil$，丢弃尾批则为 $K\lfloor B/M\rfloor$。实现必须声明是哪一种，避免样本被长期遗漏。

flowchart LR
  B["固定 Rollout B"] --> E1["Epoch 1 shuffle"]
  E1 --> M1["Mini-batches"]
  M1 --> E2["Epoch 2 reshuffle"]
  E2 --> M2["Mini-batches"]
  M2 --> EK["... Epoch K"]
  EK --> STOP["丢弃 Rollout"]

增大 $K$、减小 $M$ 或提高学习率都会增加一批数据上的优化强度，但影响方式不同：更多 Epoch 增加重复暴露，小 Mini-batch 增加梯度噪声，学习率直接放大每步参数变化。不能只用一个“总步数”完全等价替换。

7. KL 估计、检查时点与早停

PPO-Clip 本身不保证 KL 在某个范围内。常见防线是在每个 Epoch 或 Mini-batch 后估计 KL，若超过目标阈值则停止当前 Rollout 的后续更新。

with torch.no_grad():
    log_ratio = new_log_prob - old_log_prob
    ratio = log_ratio.exp()
    # old-policy 样本下，对 KL(old || new) 的非负样本估计
    approx_kl = ((ratio - 1.0) - log_ratio).mean()
if target_kl is not None and approx_kl > stop_factor * target_kl:
    stop_current_update = True

注意：

  • 在旧策略样本上，$-\operatorname{mean}(\log\rho)$ 也估计 $D_{KL}(\pi_{old}\Vert\pi_{new})$，但有限批次结果可能为负；上面的 $(\rho-1)-\log\rho$ 逐样本非负，通常更适合作为阈值监控。两者都不是对所有状态和动作的精确积分；
  • 阈值必须与 KL 方向、估计式、归约维度及采样范围一起记录，不能只复制一个 target_kl 数字；
  • 用当前 Mini-batch 检查成本低，但方差大且受打乱顺序影响；在固定 Rollout 全批或固定监控子集上重算更稳，却增加计算量；
  • 若检查使用的是优化器步进前的前向结果，它看不到刚执行的那一步；需要更强保护时，应在步进后重新评估再决定是否继续；
  • 早停只阻止当前 Rollout 的后续更新，已执行的优化器步不会回滚，也不代表终止整个训练。

有些机器人 PPO 实现根据 KL 自适应学习率：KL 过高降低学习率，过低则提高。它是控制器式启发法，应记录上下限、更新频率和公式。

8. 梯度裁剪与数值稳定

全局梯度范数裁剪：

\[g\leftarrow g\cdot\min\left(1,\frac{g_{max}}{\lVert g\rVert_2+\varepsilon_{num}}\right).\]

它限制的是组合 Loss 的参数梯度范数，与 PPO ratio 裁剪不是一回事。应在 backward() 后、optimizer.step() 前执行；PyTorch 的 clip_grad_norm_ 返回裁剪前范数，正适合作为日志。若 Actor/Critic 使用独立优化器，应分别说明裁剪的参数集合，而不是含糊地称为“全局”。

数值稳定检查包括：

  • log_prob、ratio、advantage、return、value、entropy 全部有限；
  • exp(log_ratio) 前观察 log_ratio 极值；
  • 优势标准化分母加数值 epsilon；
  • log_std 有合理参数化或范围监控；
  • 混合精度下关键分布运算与归一化保持足够精度；
  • 发生非有限 Loss 或梯度时，清空该步梯度、跳过步进并保留可复现 Batch，而不是静默继续污染参数；混合精度下应先反缩放梯度再检查/裁剪。

9. 学习率与调度

令 $p\in[0,1]$ 为已完成训练预算的比例，线性衰减可写为

\[p=\operatorname{clip}\left(\frac{x}{X_{total}},0,1\right), \qquad \alpha(p)=\alpha_0(1-p).\]

这里 $x$ 可以是环境步、PPO 迭代或优化器步，但三种计数不能混用：环境步调度更贴近样本预算，优化器步调度会随 Epoch 和 Mini-batch 数改变。实现还应声明更新发生在迭代开始还是结束，避免首步或末步的 off-by-one。

线性衰减假设训练预算已知，并让后期步长减小。也可使用常数、自适应 KL 调节或其他调度，但比较实验时必须保持总环境步数、Batch 和更新次数一致。

Adam 的 eps、权重衰减、参数组和框架默认值也会影响结果。复现时不能只记录一个学习率数字。

本页的关键方法论： Clip、有限 Epoch、KL 监测、梯度裁剪和学习率调度构成分层安全网。Clip 改变样本级代理目标；KL 观察整体策略偏移；梯度裁剪限制参数空间中的异常梯度。三者作用对象不同，任何一个都不能单独保证回报单调提升或策略“绝对安全”。

10. 推荐调参顺序

1 先验证数据语义。 终止/截断、GAE、动作缩放、奖励与观测单位错误时，调超参数只是掩盖问题。

2 建立可学习基线。 小环境、固定种子、无复杂随机化，确认回报能上升。

3 控制更新幅度。 同时观察 KL、clipfrac、ratio 极值和梯度范数，再调整学习率、Epoch、Mini-batch、clip 系数。

4 改善 Critic。 检查 Return 尺度、explained variance、价值裁剪和网络容量，而不是只盯 Value Loss 绝对值。

5 再调探索。 看逐维标准差、熵、边界命中率与评估协议，调整熵系数和方差参数化。

6 多种子复验。 至少报告均值与离散程度，不以单个最好种子下结论。

11. 一个最小更新骨架

for epoch in range(update_epochs):
    for mb in minibatches(storage):
        # mb.old_log_prob / mb.advantage / mb.returns 是冻结量
        new_log_prob, entropy, new_value = agent.evaluate(mb.obs, mb.actions)
        ratio = (new_log_prob - mb.old_log_prob).exp()

        pg1 = -mb.advantage * ratio
        pg2 = -mb.advantage * ratio.clamp(1 - clip_coef, 1 + clip_coef)
        actor_loss = torch.maximum(pg1, pg2).mean()
        value_loss = 0.5 * (new_value - mb.returns).square().mean()
        entropy_mean = entropy.mean()
        total_loss = actor_loss + vf_coef * value_loss - ent_coef * entropy_mean

        optimizer.zero_grad(set_to_none=True)
        total_loss.backward()
        # 返回值是裁剪前范数；实际代码还应先处理非有限梯度
        grad_norm = torch.nn.utils.clip_grad_norm_(agent.parameters(), max_grad_norm)
        optimizer.step()

这是共享参数/单优化器情形的教学骨架，不包含价值裁剪、KL 早停、优势标准化、混合精度、RNN 序列、变换分布修正和非有限值处理。若 Actor/Critic 独立，应改为两个参数集合与各自的优化步骤，而不是机械复用组合 Loss。完整可测试结构见 PyTorch 实现与源码映射。
