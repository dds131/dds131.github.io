02 · ARCHITECTURE

五类模块、三条数据流、四道梯度边界

现代 SAC 看似只是 Actor 与双 Critic，真正容易出错的是“当前还是目标网络、动作处于哪种尺度、这一步允许梯度流向谁”。本页用张量合同把所有接口对齐。

SAC 枢纽 ← 理论基础 Loss 与梯度 →

现代连续动作 SAC 的模块清单

随机 Actor

状态 → mu, log_std → 可微采样 → tanh → 环境动作；同时返回修正后的 log density。

在线 Critic × 2

(state, action) → scalar Q。独立初始化，在 Critic 与 Actor 两类目标中使用。

Target Critic × 2

在线 Q 的慢速副本，只构造 TD target，不参与梯度下降。

Replay Buffer

存储行为数据；随机抽样降低相邻转移的时序相关，并重复利用历史转移，但不保证样本严格 i.i.d.

温度 log_alpha

一维可学习参数，经 exp 得正温度；有独立优化器。

早期 SAC 还显式训练 V 与 Target V；本页采用当前主流的无独立 V、双 Target Q 结构。版本差异见理论基础页。

Actor：从状态到有界随机动作

设 batch 大小为 \(B\)，状态维数 \(d_s\)，动作维数 \(d_a\)。

阶段 张量 形状 作用
输入 obs [B, d_s] 可先经过归一化或 encoder
共享特征 h [B, hidden] MLP trunk
两个 head mu, log_std [B, d_a] 高斯位置与对数尺度
噪声 epsilon [B, d_a] 与参数无关的标准正态
压缩前样本 u=mu+std*epsilon [B, d_a] rsample() 路径
归一化动作 z=tanh(u) [B, d_a] 限制到 [-1,1]
环境动作 a=z*scale+bias [B, d_a] 映射到 Box 上下界
对数密度 log_prob [B,1] 各动作维求和；Jacobian 项与所选动作坐标一致

为什么要输出 log_std 而不是 std

标准差必须为正。预测 log_std 后取 exp 可保证正值，也适合跨数量级调整；但 exp 对大输入增长很快，因此需要限制范围。常见实现采用 clamp，或把无界 head 先经 tanh 再线性映射到区间。区间是工程默认，不能脱离实现当作 SAC 定理。

重参数化路径

\[\epsilon\sim\mathcal N(0,I),\qquad u_\theta(s,\epsilon)=\mu_\theta(s)+\sigma_\theta(s)\odot\epsilon.\]

Normal.rsample() 生成的 \(u\) 对 \(\mu,\sigma\) 可导。改用 sample() 会切断动作对 Actor 参数的路径梯度，使 Q 项无法经 \(\partial Q/\partial a\) 更新 Actor；这并不是说所有 score-function 估计器都不存在，而是说它不再实现标准连续 SAC 所采用的重参数化梯度。

Tanh 与动作缩放：两级变量变换

对 \(z=\tanh(u)\)，变量变换公式给出

\[\log\pi_Z(z\mid s) =\log\mathcal N(u;\mu,\sigma) -\sum_{j=1}^{d_a}\log(1-\tanh^2(u_j)).\]

若选择把策略密度定义在环境动作坐标，再映射 \(a_j=s_jz_j+b_j\)，其中

\[s_j=\frac{a_{\max,j}-a_{\min,j}}{2},\qquad b_j=\frac{a_{\max,j}+a_{\min,j}}{2},\]

则环境动作密度还需减

\[\sum_j\log|s_j|.\]

该 affine 项是与策略参数无关的常数。固定 \(\alpha\) 时，它不改变 Actor 参数梯度；自动温度时，它会平移 log_prob，因此目标熵必须使用同一坐标口径。也可以把策略密度、Replay 和 Critic 全部定义在归一化坐标 \(z\in[-1,1]^{d_a}\)，只在 env.step 前映射到环境坐标；此时 Actor loss 使用归一化密度，不应再混入环境 scale Jacobian。

多维、非对称与有限动作空间。每一维的高斯 log density 与 tanh Jacobian 都要在动作维求和，最终保持 [B,1]；若使用环境动作密度，再计入 scale Jacobian。非对称 Box 的 bias 不能省，且上述映射要求每一维边界有限并满足 high > low。

数值稳定

当 $$ u \(很大，\)\tanh(u)\(接近\)\pm1$$，直接计算 log(1-z^2) 可能得到 log(0)。两类常见实现：
  1. 对 1-z.pow(2) 加小 epsilon。
  2. 使用由 softplus 得到的代数等价稳定形式。

两者可在非饱和区与 TransformedDistribution 做数值对照。错误做法是对已经 tanh 的动作再做一次 tanh。

双在线 Critic

每个 Critic 接收拼接向量：

\[Q_{\phi_i}(s,a)=f_{\phi_i}([s;a])\in\mathbb R.\]

两个实例应独立初始化，输出均为 [B,1]。q2 = q1 或复制 Python 引用会让两者完全相同，min(Q1,Q2) 失去偏差控制意义。共享视觉 encoder 是否合理取决于具体算法；一旦共享，误差相关性会提高，必须在页面或实验配置中说明。

Critic 同时承担两种角色：

  • Critic step：对 replay 动作做 TD 回归。
  • Actor step：对当前策略动作提供 \(\partial Q/\partial a\)。

第二种角色要求“冻结 Critic 参数，但不 detach Q 输出”。

Target Critic

初始化时硬复制在线 Q：\(\bar\phi_i\leftarrow\phi_i\)。训练中采用 Polyak：

\[\bar\phi_i\leftarrow(1-\tau)\bar\phi_i+\tau\phi_i, \qquad \tau\ll1.\]

Spinning Up 常写 \(\bar\phi\leftarrow\rho\bar\phi+(1-\rho)\phi\)，其中 \(\rho\) 接近 1。两种记号满足 \(\tau=1-\rho\)；只写“0.995 的软更新系数”而不写公式会产生相反理解。

Target Critic 不加入 optimizer，target 前向置于 no_grad。它的作用是降低 bootstrap 目标变化速度，不是提供第二套可训练价值函数。

Replay Buffer 的接口合同

先确定一份动作坐标合同：可以存环境尺度动作，也可以存归一化动作。无论选哪一种，Replay 动作、Critic 输入和 Actor 为 Critic 生成的动作必须同一口径；发送给环境和评估时的转换必须唯一且一致。

标准条目至少包含：

obs          [d_s]
action       [d_a]   # 与 Critic 输入同一尺度
reward       [1]
next_obs     [d_s]
terminated   [1]
truncated    [1]     # 或保留足够信息构造 bootstrap mask

纯时间上限 truncated=True 通常不代表任务吸收终止，仍可 bootstrap；真正的环境终止才把折扣后项清零。还要检查 VectorEnv 的 autoreset 模式：部分版本在结束步返回的是 reset 后观测，真正的末端观测位于 final_observation 或 final_obs；若把 reset 观测误存为 next_obs，即使 mask 正确，transition 语义也已损坏。具体键名和 reset 时机必须以所用 Gymnasium 版本为准。

三条数据流

1. 环境采集流

flowchart LR
  O["obs"] --> W{"warm-up?"}
  W -->|是| U["动作空间均匀采样"]
  W -->|否| A["Actor 随机采样"]
  U --> ENV["env.step"]
  A --> ENV
  ENV --> TR["obs, action, reward,<br/>next_obs, term/trunc"]
  TR --> RB[("Replay Buffer")]

2. Critic target 流

flowchart LR
  NS["next_obs"] --> CA["当前 Actor"]
  CA --> NAL["next_action + next_log_prob"]
  NAL --> T1["Target Q1"]
  NAL --> T2["Target Q2"]
  T1 --> MN["min"]
  T2 --> MN
  MN --> SV["min Q - alpha log pi"]
  SV --> TD["reward + discount * mask * soft value"]

“当前 Actor + Target Critic”是刻意的组合：target 要评估当前策略下一步的行为，但价值网络采用慢速副本稳定回归。

3. Actor 与温度流

Actor 在当前状态重新采样动作，在线 Q 提供价值；alpha 反馈使用 detach 的 log-prob。不能为了复用 Critic target 的 next action 而混淆 s 与 s'。

四道梯度边界

  1. TD target 边界：next action、next log-prob 与 Target Q 的整条路径不建立梯度图。
  2. Critic 边界：TD 回归只更新 Online Q，不更新 Actor、Target Q 或温度。
  3. Actor 边界：更新 Actor 时冻结 Online Q 参数，但保留 \(\partial Q/\partial a\)。
  4. 温度边界：log_prob 与 Actor 参数 detach，只更新 log_alpha。
阶段 Actor Online Q Target Q log_alpha
构造 TD target 不更新；整段 no_grad 不参与 只前向 作为常量
Critic loss 不更新 更新 不更新 不更新
Actor loss 更新 参数冻结，但保留 dQ/da 不参与 alpha detach
Alpha loss log-prob detach 不参与 不参与 更新
Polyak 不参与 作为源 原地加权复制 不参与

一个 batch 的形状检查

obs, next_obs           [B, obs_dim]
action                  [B, act_dim]
reward, bootstrap_mask  [B, 1]
new_action              [B, act_dim]
log_prob                [B, 1]
q1, q2, target_q, y     [B, 1]
alpha                   scalar or [1]

如果 done 是 [B] 而 target Q 是 [B,1]，PyTorch 可能广播成 [B,B] 而不报错。这是最危险的静默实现错误之一。

结构性权衡

结构 收益 代价
双 Q 降低正偏差被 Actor 利用的风险 两倍 Critic 计算、可能低估
Target Q 降低移动目标速度 价值目标滞后
Replay 样本复用、打破时序相关 数据分布与当前策略偏移
tanh Gaussian 随机、可导、有界 Jacobian、饱和、单峰表达限制
自动 alpha 熵反馈自适应 多一个优化器与目标熵口径

实现前检查清单

  1. Q1/Q2 是独立实例。
  2. Target 初始硬复制在线 Q。
  3. Target 参数不在 optimizer。
  4. Actor 使用 rsample()。
  5. log_std 有界且未双重 exp。
  6. 多维 log-prob 在动作维求和。
  7. tanh 修正使用压缩前样本或压缩后动作一次。
  8. 动作 scale 与 bias 注册为 buffer。
  9. Replay、Critic 与 Actor 更新使用同一内部动作坐标；环境映射唯一且一致。
  10. reward/done/Q 均为 [B,1]。
  11. terminated/truncated 与 VectorEnv 末端观测语义明确。
  12. Actor step 未 detach Q。
  13. Alpha step detach log-prob。
  14. 评估所用确定性代理也经过 tanh 与 scale；它一般不等于分布动作均值。
