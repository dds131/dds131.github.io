本页把前面几页的公式与结构落到 LeRobot 的具体实现上。原理不重复展开；需要概念背景时，可分别回到① 主干、② 动作专家与③ Flow Matching。

证据边界。本页逐行核对 LeRobot 提交 8c920c4270460851cedd2737657584586d3dc66f（短哈希 8c920c4），并固定核对公开 lerobot/smolvla_base 配置修订 d9f33c9、SmolVLM2-500M 主干配置修订 7b375e1与 SmolVLA 论文 arXiv v1；复核日期为 2026-10-05。后续上游实现可能变化。文中的“源码事实”以这些固定版本为准，而不是不带版本的 main；论文主张、类默认值与公开检查点保存值也会明确分开。

一、文件地图

SmolVLA 的实现不止于模型文件，还依赖 processor 与共享工具。下面列出本页实际追踪的主要文件；这不是整个包的穷举清单。

文件 职责 规模
policies/smolvla/configuration_smolvla.py SmolVLAConfig 数据类：全部超参与默认值、输入校验、优化器与调度预设 约 160 行
policies/smolvla/modeling_smolvla.py SmolVLAPolicy（LeRobot 接口层）与 VLAFlowMatching（模型本体）：嵌入、掩码、训练前向、损失归约、采样 约 810 行
policies/smolvla/processor_smolvla.py 输入/输出 processor：文本换行与分词、批量维、设备迁移、归一化与动作反归一化 约 80 行
policies/smolvla/smolvlm_with_expert.py 主干与动作专家的装配：层截断、交错层分派、cross 层投影改写、两类注意力的前向。逐段剖析见第七节 约 570 行
policies/common/flow_matching.py 共享：Beta 时刻采样、噪声采样、欧拉积分循环（含 RTC 钩子） 约 140 行
policies/common/vla_utils.py 共享：块掩码、位置/时间编码、向量补齐与图像 resize-with-pad 约 240 行
policies/rtc/configuration_rtc.py / modeling_rtc.py 共享：RTC 配置与推理期引导实现 约 60 / 300 行

一处值得注意的架构演进。流匹配的采样原语现在位于 policies/common/flow_matching.py，其文档字符串说明：这些是 openpi 派生策略（pi0、pi05、smolvla、eo1）历史上各自持有一份拷贝的规范版本，函数全部无状态，采用它们不影响已有 checkpoint。

这条注释的准确含义是：SmolVLA 与 π0 等策略共用噪声采样、Beta 时刻采样和 Euler/RTC 积分原语。训练插值 x_t、速度目标 u_t 与 MSE 仍写在各策略的模型文件中，不能把“共享工具函数”扩大解释成整套 Flow Matching 前向完全共用；这属于后续工程重构，也不是论文创新。

二、两层类结构

  SmolVLAPolicy VLAFlowMatching
基类 PreTrainedPolicy nn.Module
角色 LeRobot 的策略接口层 速度场网络与采样本体
关心什么 批次准备、动作队列、维度补齐/裁剪、有效位损失归约、RTC 处理器装配 嵌入、掩码、注意力、逐元素速度损失、采样
关键方法 forward、select_action、predict_action_chunk、prepare_images、prepare_state embed_prefix、embed_suffix、forward、sample_actions、denoise_step

这是一条实用的阅读分工，而不是绝对边界：VLAFlowMatching.forward 产生逐元素 MSE，SmolVLAPolicy.forward 随后裁掉补齐的动作维、屏蔽 episode 末尾补帧并完成归约；输入/输出归一化则由 LeRobot 的 processor 管线负责。修改生成动力学主要看右列，修改训练权重口径和策略接口还必须看左列。

2.1 processor 才是模型前后的数据契约

make_smolvla_pre_post_processors 的可执行顺序与函数文档字符串列出的自然语言顺序并不相同，应以列表代码为准：

输入：rename_observations → add_batch_dim → NewLineTaskProcessorStep
    → TokenizerProcessorStep → to_device → normalize
输出：unnormalize → to_cpu

分词器取自 config.vlm_model_name，使用右侧 padding，tokenizer_max_length 默认 48；是否补到批内最长文本或固定 48，则由 pad_language_to 决定。归一化和反归一化使用传入 processor 工厂的 dataset_stats。由此得到一条重要接口边界：低层直接调用 SmolVLAPolicy 不会自动补任务文本换行、分词、按数据集统计量归一化，也不会把预测动作反归一化；常规 LeRobot 工作流由 processor 在 Policy 外完成这些步骤。

2.2 类默认值不等于公开基座的保存值

SmolVLAConfig() 的数据类默认值主要服务于“新建配置”；SmolVLAPolicy.from_pretrained("lerobot/smolvla_base") 则先读取检查点保存的配置。两者不能混称“默认配置”：

字段 数据类默认值 公开 smolvla_base 保存值 实际含义
pad_language_to "longest" "max_length" 前者补到当前批次最长文本，后者固定补到 48
prefix_length -1 0 当前代码只在 seq_len < prefix_length 时补 prefix；这两个值都等价于“不额外强制补长”
num_expert_layers -1 0 当前构造逻辑中两者都属于 <= 0，专家层数随截断后的 VLM 层数
load_vlm_weights False True 新建策略默认随机构造 VLM；公开基座实例化时先加载基础 VLM，随后还会加载完整策略权重

上表的公开值来自固定配置修订 d9f33c9。其中 -1 与 0 的等价只针对这两个字段在当前提交中的条件判断，不应推广成所有整数字段的一般规则。

三、训练前向：速度目标如何落到代码

VLAFlowMatching.forward 用不到 40 行完成“采样噪声与时刻—构造插值点—预测速度—返回逐元素 MSE”。把③ Flow Matching 与损失的式子与代码并排：

数学量 固定提交中的代码
\(\epsilon \sim \mathcal{N}(0, I)\) noise = self.sample_noise(actions.shape, actions.device)
\(t \sim 0.999\,\mathrm{Beta}(1.5,1)+0.001\) time = self.sample_time(actions.shape[0], actions.device)
\(x_t=t\epsilon+(1-t)A\) x_t = time_expanded * noise + (1 - time_expanded) * actions
\(u_t=\epsilon-A\) u_t = noise - actions
条件编码 \(o\) prefix_embs, prefix_pad_masks, prefix_att_masks = self.embed_prefix(...)
含噪动作与时刻编码 suffix_embs, suffix_pad_masks, suffix_att_masks = self.embed_suffix(x_t, time)
速度场 \(v_\theta\) v_t = self.action_out_proj(suffix_out)
逐元素 \(\bigl(v_\theta-u_t\bigr)^2\) losses = F.mse_loss(u_t, v_t, reduction="none")

这里返回的还不是最终标量损失：动作维裁剪、episode 补帧屏蔽和有效元素归约位于 SmolVLAPolicy.forward，详见第九节。这个边界若忽略，容易误以为补齐维和补齐时间步也参与优化。

三处细节：

  1. time_expanded = time[:, None, None]。时刻是每个样本一个标量，广播到（批量、块长、动作维）——同一样本的整块动作共享同一个 \(t\)；\(t\) 不是动作块内的离散步号。
  2. use_cache=False。训练时不建 KV 缓存，因为 prefix 与 suffix 在同一次前向中处理，没有跨去噪步复用的需求；这不等于“所有层都走联合注意力”，层级分派仍由第 7.3 节的条件决定。
  3. suffix_out[:, -chunk_size:] 与 float32 上溯。 suffix_out 已经是专家侧的独立输出，代码再保留最后 chunk_size 个位置；随后在输出投影前把它转为 float32。源码只注明该写法继承自 openpi，并未给出更具体的数值动机。

四、embed_prefix：条件侧的嵌入与块划分

这个函数把图像、语言、状态三路输入拼成一条序列，并同时产出两种掩码。

4.1 逐段

段 做了什么 掩码标志
图像 对每一路相机调用 embed_image，随后乘以 img_emb_dim ** 0.5 att_masks += [0] * num_img_embs
语言 embed_language_tokens(lang_tokens)，随后乘以 math.sqrt(lang_emb_dim) att_masks += [0] * num_lang_embs
状态 state_emb = self.state_proj(state)，必要时补出序列维 att_masks += [1] * states_seq_len

标志为 0 表示「与前一个 token 同属一块」，为 1 表示「另起一块」。因此图像与语言落在同一块内（互相双向可见），状态单独成块（能看见图像与语言，反之不能）。源码中这两处的注释分别写明：设置注意力掩码使图像与语言输入不能注意到状态或动作。

上表描述默认路径：add_image_special_tokens=False。若显式开启，每路图像前会插入两个语言词表中的图像起始 token，末尾再插入一个结束 token；这些特殊 token 的 pad_mask 恒为真。它们与视觉 token 同属条件块，但在“空相机”情况下不会随视觉 token 一起被屏蔽，因此不能把非默认路径概括成“整路空相机完全不可见”。

设计意图见① 主干与多模态 token第四节，本页不重复。

4.2 两个返回值容易混淆

函数返回三样东西，其中两种掩码作用完全不同：

pad_masks 标记哪些位置是真实 token、哪些是补齐出来的空位。它同时被用来算位置编号。

att_masks 标记块的边界。它与 pad_masks 一起送进 make_att_2d_masks，由累加和展开成二维可见性矩阵。

make_att_2d_masks 还对 pad_masks 做 query/key 两个方向的外积，所以补齐位置既不能作为 Key 被读取，也不会作为有效 Query 参与注意力。这个掩码与训练损失里的 action_is_pad 不是同一个概念，后者见第九节。

4.3 嵌入缩放：记录事实，不臆测动机

源码分别把图像和语言嵌入乘以各自隐藏维的平方根；固定配置下两者隐藏维相同，所以缩放因子相同。状态投影没有执行同样的缩放。源码注释把前两步称为“Normalize”，但没有解释设计动机；因此不能据此断言它在统一三种模态的尺度，或状态分支为何采用不同处理。

五、embed_suffix：动作侧的嵌入与因果掩码

flowchart LR
  XT["含噪动作块 x_t<br/>(B, 50, 32)"] --> AIP["action_in_proj"]
  TIME["时刻 t<br/>(B,)"] --> SIN["create_sinusoidal_pos_embedding<br/>min_period 4e-3 · max_period 4.0"]
  SIN --> EXP["广播到 (B, 50, d_expert)"]
  AIP --> CAT["在特征维拼接"]
  EXP --> CAT
  CAT --> M1["action_time_mlp_in"] --> SILU["silu 即 swish"] --> M2["action_time_mlp_out"]
  M2 --> OUT["suffix 嵌入<br/>att_masks 全为 1"]

对照③ Flow Matching 与损失第六节的三步（标量转向量、与动作拼接、过两层 MLP），代码是一一对应的。

因果掩码只有一行：

att_masks += [1] * self.config.chunk_size

每个动作 token 各开一块，配合累加和展开后即得到「第 i 步看不到第 i 步之后」的下三角结构。源码注释写明：设置注意力掩码使图像、语言与状态输入不能注意到动作 token。

这一行同时承担了两件事——让动作 token 整体不被 prefix 看见（保证缓存可复用），以及让动作 token 之间成为因果。理由见② 动作专家与交错注意力第五节。

六、位置编号的构造

训练时：

position_ids = torch.cumsum(pad_masks, dim=1) - 1

位置编号由 pad_masks 的累加和给出，而不是简单的 arange。因此补齐位置不推进编号：同一批次即使被补到共同长度，suffix 仍紧接各自最后一个有效 prefix token；真实语言长度的差异则会正常反映在后续位置索引中。

推理时多一步偏移：

prefix_offsets = torch.sum(prefix_pad_masks, dim=-1)[:, None]
position_ids = prefix_offsets + torch.cumsum(suffix_pad_masks, dim=1) - 1

因为推理时只把 suffix 送进前向（prefix 已在缓存里），初始位置索引要手动加上 prefix 的有效长度，才能与训练时的一次性序列对齐。这个“续接”结论直接适用于 self 路径；cross 层随后还会把专家 Query 的位置重新平移到 0 起点，不能把此处的初始编号当作所有层最终使用的编号，详见第 7.6 节。

七、smolvlm_with_expert.py：装配与两条注意力路径

前面几节讲的都是 modeling_smolvla.py：如何把输入变成序列、如何算损失、如何迭代。但序列送进去之后究竟发生了什么，全部在 smolvlm_with_expert.py 里。这个文件承担了整个专题里结构性最强的那部分逻辑——层截断、交错分派、两条注意力路径、KV 缓存的读写。设计意图见② 动作专家与交错注意力，本节只讲实现。

7.1 构造期的三步装配

SmolVLMWithExpertModel.__init__ 做的事可以归成三步。

第一步，截断主干。

if num_vlm_layers > 0:
    self.get_vlm_model().text_model.layers = self.get_vlm_model().text_model.layers[:num_vlm_layers]
self.num_vlm_layers = len(self.get_vlm_model().text_model.layers)

这是对 nn.ModuleList 的直接切片赋值，被丢掉的层连同参数一起从模块树上消失。所以它不是「前向时提前退出」，而是这些层根本不存在——这正是①第二节所说「静态截断」在代码上的形态。默认 num_vlm_layers = 16，主干原有 32 层。

第二步，从主干配置派生出动作专家的配置。

lm_expert_config = copy.deepcopy(config.text_config)
hidden_size = lm_expert_config.hidden_size
lm_expert_config.hidden_size = int(hidden_size * expert_width_multiplier)
lm_expert_config.intermediate_size = get_intermediate_size(int(hidden_size * expert_width_multiplier))
lm_expert_config.num_hidden_layers = self.num_vlm_layers
self.lm_expert = AutoModel.from_config(lm_expert_config)
...
self.lm_expert.embed_tokens = None

三点值得注意：

  1. 是 deepcopy 之后只改三个字段。 注意力头数、键值头数、每头维度都原样继承，没有随宽度缩放。这就是②第六节那张维度表的由来，也是专家与主干的键值宽度同为 num_key_value_heads × head_dim 的原因。
  2. 前馈中间维走的是 get_intermediate_size 而不是按比例缩放：先取隐藏维的三分之二，再乘 4，最后向上取整到 256 的倍数。
  3. embed_tokens 被显式置为 None。 动作专家由语言模型配置构造，原本会带词表嵌入层，但实际输入来自动作投影，因此该层不会参与前向。移除它会减少无用参数；至于具体分布式训练影响，源码没有给出进一步说明。

第三步，改写 cross 层的键值投影。

if "cross" in attention_mode:
    for layer_idx in range(len(self.lm_expert.layers)):
        if self.self_attn_every_n_layers > 0 and layer_idx % self.self_attn_every_n_layers == 0:
            continue
        self.lm_expert.layers[layer_idx].self_attn.k_proj = nn.Linear(
            config.text_config.num_key_value_heads * config.text_config.head_dim,
            lm_expert_config.num_key_value_heads * lm_expert_config.head_dim,
            bias=lm_expert_config.attention_bias,
        )
        # v_proj 同理

这段是整个文件里最容易读错的地方，②第三节已经详述：新线性层的输入与输出维度都是键值宽度，而不是主干隐藏维。取模为 0 的层被 continue 跳过，保持标准结构——这一行同时也就是交错排布的定义处。

7.2 主干层与专家层如何配对

get_model_layers 把两边的层拉成等长的两列：

multiple_of = self.num_vlm_layers // self.num_expert_layers
for i in range(self.num_vlm_layers):
    if multiple_of > 0 and i > 0 and i % multiple_of != 0:
        expert_layer = None
    else:
        expert_layer_index = i // multiple_of if multiple_of > 0 else i
        expert_layer = models[1].layers[expert_layer_index]

数据类默认的 num_expert_layers = -1，以及公开基座保存的 0，都使专家层数等于主干使用层数；此时 multiple_of = 16 // 16 = 1，i % 1 != 0 恒为假，每一个主干层都配一个专家层，一一对应。

若显式减少专家层数，multiple_of 会大于 1，映射函数让部分主干层对应的 expert_layer 为 None；构造期只校验两侧层数整除。但固定提交还有一处更具体的索引不一致：构造期按专家层号决定哪些层改成 cross K/V 投影，前向分派却按主干层号决定 self/cross 路径。

以 num_vlm_layers=16、num_expert_layers=8、self_attn_every_n_layers=2 为例，专家层 1 会被改成接收键值宽度的 cross 投影，却在主干层 2 被映射并走 self 路径。对固定主干配置而言，该层的隐藏宽度为 \(960\times0.75=720\)，改写后的 K/V 投影输入宽度却是 \(5\times64=320\)；self 路径会把 720 维隐藏状态交给只接收 320 维的线性层，发生矩阵形状不匹配。

结论边界。这是固定提交中“减少专家层数 + 当前交错 cross 模式”的实现缺陷，不应写成可直接使用的受支持配置。公开 smolvla_base 保存的是 num_expert_layers=0，实际走 16↔16 等深路径，不受这个 16→8 示例影响。若要支持非等深专家，应让“层映射、self/cross 分派、K/V 投影改写”基于同一组主干—专家对应关系，并增加非等深前向测试。

7.3 前向按什么条件分派

fill_kv_cache = use_cache and past_key_values is None
for layer_idx in range(num_layers):
    if (fill_kv_cache
        or "cross" not in self.attention_mode
        or (self.self_attn_every_n_layers > 0 and layer_idx % self.self_attn_every_n_layers == 0)):
        att_outputs, past_key_values = self.forward_attn_layer(...)
    else:
        att_outputs, past_key_values = self.forward_cross_attn_layer(...)

三个条件是“或”的关系；use_cache=False 只会让 fill_kv_cache 为假，并不会关闭奇数层的 cross 分支。默认 16 层、每 2 层一个 self 层时，实际分派如下：

阶段 偶数层（self 路径） 奇数层（cross 路径）
训练，use_cache=False prefix 与 suffix 联合注意力，不写缓存 现场计算主干 prefix 的自注意力与 K/V，专家 Query 对 prefix 做 cross-attention，不写缓存
推理 prefix 预填充 因 fill_kv_cache=True，所有层都只处理 prefix 并写入各层缓存 不进入 cross 函数
推理每个去噪步 专家 suffix K/V 临时追加到同层 prefix 缓存，关注 prefix 与因果 suffix 只读同层 prefix 缓存，专家只关注 prefix
attention_mode 不含 cross 所有层都走 self 路径 cross 分支被整体关闭

必须区分训练与预填充。预填充阶段没有 cross 分支，因为 16 层都要生成 prefix 缓存；训练和去噪阶段都按奇偶层交错，只是训练现场计算 prefix K/V，而去噪读取已填好的缓存。

7.4 两条路径到底差在哪

同一个函数在训练、预填充和去噪时接收的输入不同，不能用一张静态“Query/K/V 来源表”概括。按阶段追踪更准确：

调用阶段 forward_attn_layer forward_cross_attn_layer
训练 拼接主干 prefix 与专家 suffix 的 Q/K/V；不调用 cache update 主干 prefix 先做本层自注意力；专家 Query 再关注现场生成并经专家投影的 prefix K/V
prefix 预填充 只有主干 prefix；每层调用 update 首次写入缓存 不调用
去噪的 self 层 只有专家 suffix 的新 Q/K/V；update 临时把 suffix K/V 追加到同层 prefix 缓存并返回全量 K/V 不调用
去噪的 cross 层 不调用 只读同层 prefix 缓存；K/V 经专家的 k_proj/v_proj 后供专家 Query 使用，不写缓存

默认配置下，每个去噪步只有 self 层的缓存临时增长 chunk_size，cross 层始终保持 prefix 长度。步末统一执行 crop(prefix_len)，把发生增长的层恢复后再进入下一步。

7.5 缓存里存的是什么

预填充时每层都经 forward_attn_layer 写入缓存。执行代码先对 Q、K 调用 apply_rope，再把 K 与 V 交给 past_key_values.update；因此缓存保存的是已施加 RoPE 的 K 与未旋转的 V。源码注释虽然简写为“post-RoPE K/V”，但 V 实际没有经过 apply_rope，这里以可执行语句为准。

由此得到一个关键结论：②第 3.4 节所说的条件缓存不是单一特征张量，而是 16 份按主干层号保存的 K/V；在默认 16↔16 一一映射下，专家第 \(i\) 层读取主干第 \(i\) 层对应的那一份。非默认专家深度不能沿用这句简化描述。

7.6 一处位置编号上的不对称

这是只有顺着运算顺序阅读代码才会注意到的一点。

在 cross 层里，专家的查询位置编号被显式平移到从 0 开始：

expert_position_id = (
    expert_position_id - torch.min(expert_position_id, dim=1, keepdim=True).values
)  # start from 0

与之相对，主干 K 先按 prefix 的位置索引应用 RoPE，再经过专家层改写后的 k_proj；得到的 expert K 不会再做第二次 RoPE。于是两侧的位置处理不是常规的“同一原点下对 Q/K 同时旋转”：

层类型 Query 的位置索引 Key 的处理
self 路径 训练时使用整条序列索引；去噪时 suffix 索引接在有效 prefix 之后 同一次 apply_rope 使用对应位置索引
cross 路径 专家 Query 的索引减去本行最小值，从 0 起算后应用 RoPE 主干 K 已按 prefix 索引旋转，随后再经专家 k_proj，不做第二次 RoPE

源码只用 # start from 0 注释 Query 的重编号，论文也未解释其动机。由于 cross 路径的 Key 还经历了“先 RoPE、后专家线性投影”，不能直接套用标准 RoPE 中“只由 Q/K 位置差决定”的解释。可靠结论仅限于：self 与 cross 路径采用了不同的位置处理顺序；进一步把它解释为距离度量或设计优势，都属于未经源码或论文证实的推测。

7.7 残差与前馈是手写展开的

每一层算完注意力之后，两侧各自过残差与前馈，这段没有复用 transformers 的 DecoderLayer，而是在循环里手写：

out_emb = layer.self_attn.o_proj(att_out)
out_emb += hidden_states
after_first_residual = out_emb.clone()
out_emb = layer.post_attention_layernorm(out_emb)
out_emb = layer.mlp(out_emb)
out_emb += after_first_residual

当前实现用同一段残差循环兼容两种返回形式：self 路径产生一份拼接后的 att_output，需按 start:end 切给主干与专家；cross 路径则返回主干与专家各自的注意力结果。两侧随后使用各自的 o_proj、残差和 MLP。由于这种跨模块协调无法直接原样复用标准 DecoderLayer，源码选择手动展开，但这不意味着其他封装方式在原则上不可能。

这也是读这个文件时的一条实用提示：不要按 transformers 的标准层结构去推断它的行为，注意力、残差、前馈三段在这里是被拆开重组的。冻结策略也写在该文件中：默认 train_expert_only=True 时整个 VLM 冻结并保持 eval；否则仍冻结 VLM 的 lm_head、最终 norm 和最后一层（特定非等深配置再冻结倒数第二层）。代码还会冻结专家中名称含 lm_head 的参数（若所构造的基础模型实际提供该参数）；state_proj 是否训练则另由 train_state_proj 控制。这里的冻结是参数更新规则，不等于“该层输出没有任何下游使用”；默认配对下，专家仍可能读取冻结主干层产生的 K/V。设计取舍详见④ 训练配方第 2.3 节。

八、推理链

8.1 三层调用

flowchart TB
  SA["VLAFlowMatching.sample_actions"] --> EP["embed_prefix<br/>一次性算好条件"]
  EP --> KV["vlm_with_expert.forward<br/>inputs_embeds = [prefix, None]<br/>use_cache=True<br/>得到 past_key_values"]
  KV --> EI["euler_integrate<br/>（共享模块）"]
  EI --> DS["denoise_step<br/>每步调用一次"]
  DS --> ES["embed_suffix(x_t, timestep)"]
  ES --> FW["vlm_with_expert.forward<br/>inputs_embeds = [None, suffix]<br/>复用 past_key_values"]
  FW --> CROP["past_key_values.crop(prefix_len)"]
  CROP --> VT["action_out_proj → v_t"]
  VT --> EI
  EI --> RES["最终动作块"]

三层的分工是：sample_actions 只做一次条件编码并把 KV 缓存交出去；euler_integrate 管迭代与积分；denoise_step 管单步的速度场计算。

默认 cross-attention 推理依赖 use_cache=True。缓存不只是提速手段，也是去噪时把固定 prefix 条件送入专家的实现通道。固定提交没有为 attention_mode="cross_attn" 且 use_cache=False 提供等价的无缓存推理路径，因此不要把该开关当成可随意关闭的纯性能选项。

8.2 欧拉积分

共享模块里的循环：

dt = -1.0 / num_steps
x_t = noise
for step in range(num_steps):
    time = 1.0 + step * dt
    ...
    x_t = x_t + dt * v_t

其文档字符串写明：这是从 \(t=1\)（噪声）到 \(t=0\)（动作）的前向欧拉积分。它与训练插值 \(x_t=t\epsilon+(1-t)A\) 使用同一时间约定和速度定义，但遍历方向相反：训练路径随 \(t\) 增大由动作走向噪声，推理以负步长由噪声走回动作。

默认 num_steps=10 时，速度场求值点为 1.0、0.9、…、0.1；不会在 \(t=0\) 再求一次速度，而是最后从 0.1 积分到 0。这是前向欧拉离散化的正常端点处理。

九、损失归约：两类补齐都要排除

SmolVLAPolicy.forward 拿到逐元素损失后做了三步处理：

步骤 固定提交中的代码 作用
裁到真实动作维 losses[:, :, :action_feature.shape[0]] 排除补到 max_action_dim=32 的尾部维度
屏蔽 episode 补帧 losses * (~actions_is_pad).unsqueeze(-1) 排除 episode 末尾不足完整动作块而补出的时间步
有效元素归约 losses.sum() / num_valid 分母为有效时间步数乘真实动作维数，并以 1 为下限防止全 padding 时除零；不是完整张量元素数

action_is_pad 是 MSE 生成之后的 loss mask：embed_suffix 给全部 chunk_size 个动作槽位的 suffix_pad_masks 都置 1。因此 episode 尾部补动作仍参加 Transformer 的 suffix 注意力，只是不计入最终损失；不要把它与第 4.2 节的 attention padding mask 混为一谈。

若对屏蔽后的完整张量直接取 mean()，置零的补帧仍进入分母，靠近 episode 末尾、有效动作较少的样本会被额外降权。实现用 sum() / num_valid 避免这种稀释。

代码之后还执行 losses[:, :, :max_action_dim]。在真实动作维不大于 32 的正常配置中，前一步已经裁得更窄，因此这通常不再删除元素，更像兼容性保护。loss_dict 的三个字段记录的是各阶段张量的普通均值；其中掩码后的普通均值包含已置零位置，仅用于诊断，不等同于最终有效元素均值。

此外 forward 支持 reduction="none"，返回逐样本损失（形状为批量大小），源码注明用于 RA-BC 加权——即按样本重要性重新加权的行为克隆变体。这条路径对标准 SmolVLA 训练不起作用，但说明该接口被其他算法复用。

10 compile_model=True 只编译内层 sample_actions 与 forward，并设置 float32 matmul precision 为 high Policy 队列、processor、checkpoint I/O 没有整体编译；该开关默认关闭，编译模式默认 max-autotune
11 use_delta_joint_actions_aloha=True 在配置构造期抛 NotImplementedError 该开关在此提交尚未移植，不能因字段存在就判定可用；adapt_to_pi_aloha 是另一条已实现的状态/动作变换路径

10.1 load_vlm_weights 不等于“是否加载完整策略 checkpoint”

构造 SmolVLMWithExpertModel 时，load_vlm_weights=True 会对基础 VLM 调用 from_pretrained；为假时只读取 AutoConfig 并随机构造 VLM。这个开关描述的是策略实例化阶段的基础 VLM 初始化，不是完整 SmolVLA checkpoint 的最终状态。

调用 SmolVLAPolicy.from_pretrained(...) 时，通用基类会先按检查点保存的策略配置实例化对象，再加载完整 model.safetensors，随后迁移到目标设备并切到 eval。因此，任意检查点即使保存了 load_vlm_weights=False，完整权重加载完成后也不能据此推断 VLM 仍是随机初始化；该字段只控制实例化阶段是否先从基础 VLM 仓库取权重。固定核对的公开 smolvla_base 实际保存的是 load_vlm_weights=True。通用接口还默认 strict=False：缺失或多余键会记录日志而非必然中止。若用自定义配置加载旧 checkpoint，必须检查 missing/unexpected keys，不能只看函数是否返回成功。

十一、三种执行模式在代码中的位置

这是 SmolVLA 最容易被混淆的一处，本页只标清代码位置，机制对比见⑥ 推理、动作块与异步执行。

模式 入口 队列在哪 何时重新推理
策略自带的同步队列 SmolVLAPolicy.select_action 策略内部的 deque，长度 n_action_steps 队列为空时；实际执行的是配置的 n_action_steps，不一定等于完整 chunk_size
论文的异步推理栈 lerobot/async_inference/ 的客户端与服务端 客户端进程内 队列余量低于阈值 \(g\) 时
RTC（实时分块） predict_action_chunk，经 rtc_processor.denoise_step 钩入欧拉积分 调用方管理 由调用方决定，并把上一块的余量作为条件传入

predict_action_chunk() 始终返回完整的 chunk_size；只有 select_action() 在内部队列为空时才生成整块、截取前 n_action_steps 入队，并逐个 popleft()。环境 reset 时调用方还必须执行 policy.reset() 清空动作队列，否则上一个 episode 未执行完的动作会残留到新 episode。

RTCConfig 的默认值为：enabled = True、mode = "guided"、execution_horizon = 10、max_guidance_weight = 10.0、前缀注意力调度为线性。其文档字符串说明 RTC 把块生成当作图像修复（inpainting）问题，用前缀约束处理相邻动作块的重叠时间步；guided 模式在推理期通过自动微分得到修正项并限制最大引导权重。通用 RTC 还定义了需要兼容训练 checkpoint 的 trained 模式，但固定提交中的 SmolVLA 用默认 trained_mode_supported=False 构造处理器；若启用 RTC 且设置 mode="trained"，初始化会直接抛错。因此不能把它写成 SmolVLA 当前可用模式。

注意 SmolVLAConfig 里 rtc_config 的默认值是 None，而 RTCConfig 自身的 enabled 默认是 True。含义是：不传 RTC 配置就完全不启用；一旦传入配置对象，默认即为开启。init_rtc_processor 还留了一条路径——即使 RTC 未启用，只要配置存在就仍然创建处理器，用于记录去噪过程的调试数据。

十二、创新点、工程实现与证据边界

阅读源码时要避免把“论文方法”“当前实现”和“后来接入的功能”都称作 SmolVLA 创新：

层级 本页对应内容 应如何表述
论文采用的系统组件/训练目标 截断 VLM、轻量动作专家、交错 self/cross 注意力、条件 Flow Matching 轻量结构与交错注意力是 SmolVLA 设计重点；Flow Matching 沿袭 π0 路线，不应表述为 SmolVLA 发明
固定提交的实现机制 ModuleList 切片、块掩码、按层 KV cache、每步 crop、有效元素损失归约 是提交 8c920c4 的可核验源码事实，不保证其他版本不变
后续工程重构 多个 openpi 派生策略共用 common/flow_matching.py 是 LeRobot 代码复用改进，不是 SmolVLA 论文贡献
外部扩展 RTC 配置与去噪钩子 来自独立 RTC 方法，不属于 SmolVLA 原始架构创新

12.1 要点回顾

文件分工 配置、processor、模型与装配文件，加上共享掩码、流匹配和 RTC 模块。流匹配原语已抽出为 pi0 与 smolvla 共用，不再各存一份。

训练前向 模型本体用短前向返回逐元素 MSE；Policy 层再处理有效动作维、episode 掩码和归约。float32 上溯继承自 openpi，具体动机未写明。

两种掩码 pad_masks 管真实与补齐并决定位置编号，att_masks 管块边界。因果掩码在代码里只有一行。

装配与两条路径 层截断直接修改 ModuleList。训练与去噪按奇偶层交错，prefix 预填充则在所有层走 self 路径；等深 16↔16 已核实，非等深专家存在层索引与投影改写不一致。

缓存的代价 缓存按层保存已旋转的 K 与未旋转的 V。去噪 self 层临时追加 suffix K/V，必须在每步末裁回 prefix 长度。

损失归约 动作维补零与 episode 边界补帧都要排除，分母使用有效元素数，避免靠近 episode 末尾的样本因补帧较多而被额外降权。
