四个平面组成一个闭环

平面 主要对象 主要责任 不能替代
Control Plane task/session、Planner、Harness runtime、Registry 配置、选择、预算、turn、权限与 lifecycle controller 与 safety loop
Execution Plane Toolkit/Executor、analytic primitive、VLA service、Environment/controller 受控执行与物理或模拟状态变化 task semantics
Evidence Plane observations、ToolResult、EnvState、trace、transcript、verdict、artifacts 记录看见、调用、结果与判定 actuator authority
Safety Plane independent limits、watchdog、fault manager、operator permit、inhibit、safe state、re-arm Planner goal optimization 
flowchart LR
  C["Control Plane<br/>task · Planner · Registry · budget"] -->|PrimitiveCall| E["Execution Plane<br/>Toolkit · VLA · controller"]
  E -->|observation · ToolResult| V["Evidence Plane<br/>trace · verdict · artifacts"]
  V -->|fresh evidence| C
  S["Safety Plane<br/>limits · watchdog · fault owner"] -->|permit / inhibit / safe state| E
  E -->|fault / state| S

图 1｜四平面闭环。 等价文本：Control 选择版本化调用，Execution 只执行获准请求，Evidence 保存关联证据并把新状态反馈给 Control，Safety 对执行授权和异常停止拥有独立 authority。Evidence 可以记录安全与任务判定，但不能自行驱动 actuator。

稳定闭环要求 task/config/registry/policy/Memory revision 在 run 开始时冻结；任何平面变更都进入 trace。Planner 不能以目标优化覆盖 Safety，controller 也不应从 Planner 文本推断 task success。

从配置到 cleanup 的生命周期

主状态机与错误旁路

flowchart TD
  D[DISCOVER] --> VC[VALIDATE_CONFIG]
  VC --> PM[PREPARE_MEMORY]
  PM --> BP[BUILD_PLANNER_AND_PROMPTS]
  BP --> IR[INIT_RUNTIME]

图 3｜Run lifecycle。 任一阶段失败都进入 fail-safe/finalize；finalization 或 cleanup 的次生错误追加到原始 incident，不能覆盖 root cause。进程退出不等于机器人 safe state。

owned、borrowed 与 shared

  • owned：当前 scope 创建，结束时只清理自己创建的资源。
  • borrowed/shared：由外部或 Session 提供，TaskRun 仅释放引用，不无条件终止服务。
  • cleanup 必须幂等，重复调用不能终止新 owner 的进程。
  • safe stop 由 Safety/controller owner 在普通 cleanup 前请求并确认。
  • abnormal exit 仍保存最小 incident/lifecycle record；录像失败不能隐藏动作故障。

图 4｜Primitive turn。 一个 Planner turn 可包围许多 controller tick、action chunk 和 service request；外层等待 ToolResult 不代表内部同步，更不代表 hard real-time。

Correlation 与 freshness invariants

  • 每个 PrimitiveCall 有唯一 call_id，ToolResult 必须回指它。
  • observation 绑定 observation_id 与 captured-at monotonic timestamp。
  • PlannerDecision 记录实际使用的 observation、Memory receipt 与 registry version。
  • VLA call 记录 policy/checkpoint/processor/action contract ID。
  • controller command/ack 记录 controller sequence；GoalVerdict 记录 predicate version 与 evidence refs。
  • duration 使用 monotonic clock；UTC 只用于跨日志展示。
  • 任一 ID 断链，因果归属降级为 inconclusive。

primitive 结束后必须取得符合 adapter 规则的新证据。若下一轮继续使用 pre-action observation，却未显式声明 open-loop replay，就不能声称闭环；freshness 需要 sensor/controller sequence、timestamp 与 physical state 一致推进，不是“文件名变了”。

图 6｜Transport 边界。 文件是论文中的可审计协议实例；in-process、RPC、MCP 或其他 service transport 只要表达同一身份、版本、ack/cancel 与证据语义，也可实现相同上层 contract。

中性 envelope 至少包含 protocol/message type、run/session/episode/turn/call IDs、producer/consumer、schema/registry/contract versions、monotonic creation、deadline、payload/artifact refs、status/error、ack/cancel semantics，以及持久化内容 hash。本页不声称 current RPent 各 robot integration 使用相同 transport、重试或 exactly-once 语义。

状态、参数与产物的所有权

对象 run 前 run 中 run 后 默认持久化
Frozen VLA parameters checkpoint 固定 不更新 不因 Harness 自动改变 checkpoint 由外部管理
Planner model parameters provider/backend 固定 inference，不由 Harness 训练 不更新 provider 管理
Planner context/history 初始化 每 turn 变化或裁剪 transcript 保留 按审计策略
Registry/tool specs 版本冻结 不临时扩展类型 manifest 保留 是
Runtime state 空或初始化 in-flight、budget、health、turn closed 仅摘要/trace
Memory corpus revision 冻结或 exploration workspace eval 只读；explore 受控 draft/commit revision/merge result 是
Environment/physical state reset/人工准备 动作改变 final state/safe state 作为 evidence，不是可直接复播状态
EnvState/evidence 创建 append state/tool/artifact records finalize 是
Service cache/process state init/borrow backend-specific close/reuse 通常不作为方法 Memory

图 7｜StateAndParameterMatrix。 表格本身是文本等价图：参数、上下文、运行状态、Memory、物理状态和证据各有不同 owner、生命周期与持久化规则，不能用“可训练 Harness”一词合并。

具体 Loss 更新对象和 checkpoint 来源归Training/Loss 页。LIBERO、RoboCasa、RoboTwin 或真实机器人可有不同 RobotSpec、toolset、observation adapter、verifier 与 service topology，但必须输出相同上层 typed semantics；adapter 不能授权 Planner 创造未注册 primitive 或绕过 Safety Plane。

失败、取消、finalize 与 cleanup

阶段 失败示例 必须保留 立即动作
config/memory 参数无效、revision 缺失 validation errors 不启动 Execution Plane
init runtime service 未 ready、部分进程启动 owned/borrowed list、health cleanup owned；不杀 shared
build toolkit schema/handler mismatch registry snapshot 关闭已创建资源
planning backend timeout/invalid call decision/request trace 不 dispatch；按 budget/owner 决定
execution timeout/cancel/fault call/result/controller ack safety stop/typed fault
verification unknown/证据不足 predicate/evidence 不标 success
finalize result/video/audit 写入失败 primary outcome + finalizer errors 不覆盖 root cause
cleanup process 不退出/close failure lifecycle record escalation；禁止误杀 shared

主终止状态使用稳定枚举：success、goal_false_budget_exhausted、planner_stop_without_success、safe_stop、cancelled、execution_fault、infrastructure_fault、verification_unknown、finalization_partial、cleanup_incomplete。primary terminal status 可与 secondary finalization/cleanup errors 并存；退出码 0 不能覆盖 task failure，视频写入失败也不能改写已发生的 safety fault。
