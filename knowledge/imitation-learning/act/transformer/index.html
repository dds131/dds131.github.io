前两个子页回答的是「学什么」与「怎么表达多样性」：② 动作分块把输出改成一整段动作，③ CVAE 让模型能区分同一观测下的多种合理动作模式。本页回答的是第三个问题——用什么网络结构把这一整段动作一次算出来。

ACT 的答案是借用 DETR 的 encoder-decoder 骨架，把它的 object query 换成 action query。这个改造看起来只是换了个名字，实际上涉及视觉主干、多相机融合、位置编码与解码方式四处具体设计，本页逐一展开。

ResNet-18视觉主干，所有相机共享一个
4 / 7encoder 层数 / decoder 层数
512hidden_dim
8注意力头数
4 套位置编码，分工各不相同

本页最需要记住的三条：ACT 的 action query 不是 decoder 的输入 token，它是加在每层注意力 query 上的位置嵌入，decoder 的初始输入其实是全零张量；多相机特征是沿「宽度」维拼接成一条长序列，而不是各自过一个独立分支；ACT 实际用了四套位置编码，来源与可学习性各不相同。

一、这一层在 ACT 中的位置

在 ACT 的四层设计里，前两层规定了问题的形状，这一层负责把它算出来：

层 决定了什么 对本层提出的要求
① 动作分块 输出是一段 \(H\) 步动作，而不是单步 网络必须能一次产生 \(H\) 个输出；\(H\) 达到 90 时还要满足 50 Hz 的实时预算
② CVAE 除观测外还有一个 latent \(\mathbf{z}\) 作为条件 网络必须能接受一个额外的、与图像和本体状态不同模态的条件输入
③ 本层 Transformer 用什么结构满足上面两条 ——

这两条要求并不意味着其他网络在数学上不可行，而是形成了几种不同的工程取舍：

CNN 加 MLP 头也能一次输出 H × 14 个数，并可借助共享隐藏表示学习动作间的统计相关性；但它没有显式的逐时刻槽位交互结构。官方仓库中的 CNNMLP 是这类对照基线。
RNN 或 GPT 式自回归把联合分布按时间顺序分解，推理时需要串行生成 H 个位置，延迟会随 H 增长，并会形成块内误差传播链；实际是否超出实时预算仍取决于模型规模与硬件，不能只凭 H=90 断言“不可行”。
DETR 式 query 解码用 H 个可学习槽位并行读取同一份上下文，一次前向给出全部 H 个动作；槽位之间还能通过 self-attention 交换信息。这是 ACT 采用的结构。

选择 Transformer 还便于统一融合异构输入：多路 RGB 特征、14 维关节状态和 32 维 latent 都可投影为同维 token，再在一条序列中做注意力。但这是一种方便的结构选择，并不表示 CNN 或 MLP 无法完成多模态融合。

需要先澄清一点：ACT 借用的是 DETR 的架构，不是它的损失框架。原论文把 DETR 的核心归纳为两样东西——通过二分图匹配强制唯一预测的集合级全局损失，以及 Transformer encoder-decoder 架构。ACT 只继承了后者；前者连同类别与框回归头、「无物体」类别一并没有沿用。两者真正的共同点是「用一组可学习 query 并行产生固定数量的输出」这一条。下一节把这条以及它与匹配损失的关系讲清楚。

二、DETR 的两个核心思想

DETR（End-to-End Object Detection with Transformers）有两个核心成分：集合级匹配损失与 Transformer encoder-decoder。ACT 继承的是后者，以及“固定数量的可学习 query 并行产生输出”这一结构思想；它没有继承前者。

2.1 集合预测：一次输出固定数量的结果

传统检测器的输出数量是不确定的：先产生大量候选框，再靠非极大值抑制筛掉重复的。DETR 换了个思路——固定输出 \(N\) 个结果，\(N\) 取一个大于图中可能物体数的常数（原论文在 COCO 上建议 100）。模型一次给出这 \(N\) 个预测，多余的槽位预测为「无物体」。

但仅仅固定输出数量并不能消除重复预测。真正做到这一点的是配套的损失设计：DETR 用二分图匹配在 \(N\) 个预测与真值之间求一个一一对应，再按这个对应计算集合级损失。一一对应这个约束意味着每个真实物体只能由一个预测负责，多余的槽位必须给出「无物体」——重复预测会在损失上直接受罚。原论文摘要把这两件事并列为 DETR 的两大核心成分：通过二分图匹配强制唯一预测的集合级全局损失，以及 Transformer encoder-decoder 架构。非极大值抑制之所以可以去掉，根源在前者。

ACT 把“\(N\) 个候选物体槽位”改造成“\(H\) 个未来时间槽位”，但并非把 DETR 的集合预测机制原封不动搬过来：动作槽位有固定时序对应，因此不需要匹配与“无物体”类别。原因见第 2.3 节。

2.2 object query：固定数量的可学习输出槽位

支撑集合预测的是一组可学习参数，DETR 称为 object query。可以把它理解成 \(N\) 个输出槽位：每个槽位负责从图像上下文里读取信息，并产出一个检测结果。

这里有一个几乎所有二手介绍都会讲得含糊、而源码里非常明确的点：

object query 不是 decoder 的输入 token，它是加在注意力 query 上的位置嵌入。 decoder 的实际输入张量初始化为全零，query embedding 通过 query_pos 参数在每一层的 self-attention 与 cross-attention 中被加到 query 上。这一点在第八节会结合 ACT 源码逐行展开。

由此可以理解这组参数的作用：它们为 \(N\) 个槽位提供不同的身份与检索方向。某些 query 可能形成稳定的类别或空间偏好，但这不是结构保证；query 本身不携带当前样本的内容，样本信息由 cross-attention 从 encoder memory 中读取。

2.3 ACT 没有继承的部分

为了避免把 DETR 的其他机制误安到 ACT 头上，这里明确列出不相关的部分：

DETR 的机制 ACT 是否沿用 说明
集合预测 + query 并行解码 沿用 本页第三、八节
encoder-decoder 骨架与注意力实现 沿用 ACT 的 transformer.py 由 DETR 改写而来
ResNet 主干 + 2D 正弦位置编码 沿用，但改造了多相机部分 本页第四、五节
二分图匹配与集合级损失 不沿用 检测的真值是无序集合，需要匹配来强制一一对应、消除重复；ACT 的真值是有序序列，第 \(i\) 个 query 按定义对应第 \(t+i\) 个时刻
类别分类头与框回归头 不沿用 ACT 只有一个线性动作头
「无物体」类别 不沿用 动作块的每个位置都必须输出一个动作
各层辅助损失 不沿用 DETR 对 decoder 每一层输出都计损失；ACT 的 policy.py 只对一个输出计 L1，见第十节

第一条差异尤其值得注意，它是两者输出结构不同的直接体现，而不是 ACT 「省掉了一个麻烦」。

检测任务的真值是一个无序集合：图里有哪些物体是确定的，但它们没有编号，也就谈不上「第 3 个真值」。DETR 的 \(N\) 个预测同样是一组无序槽位。要计算损失，必须先在两个集合之间确定一个一一对应，DETR 用匈牙利算法求总代价最小的那个匹配，代价由分类概率与框的 L1、GIoU 共同构成；匹配确定后才按它计算最终损失。

这一步的意义不只是「让损失能算出来」。一一对应本身就是一条硬约束：每个真值物体只能被一个预测认领，任何重复预测都必然与「无物体」配对而受罚。 按原论文的说法，正是这个基于集合的全局损失通过二分图匹配强制了唯一预测，非极大值抑制才得以去掉。

ACT 的情形完全不同。它的真值是一个有序序列——\(a_t,\, a_{t+1},\, \dots,\, a_{t+H-1}\) 本来就带着时间下标。第 \(i\) 个 query 对应第 \(t+i\) 个时刻，这个对应由问题定义给出，不需要求解，损失直接逐位置计算即可。

所以准确的说法是：两者的输出对象类型不同——一个是集合，一个是序列——因此损失的构造方式不同。 说「ACT 比 DETR 简单」会掩盖这一点：如果 ACT 的动作块也是无序的，它同样需要匹配；反过来，若检测任务的物体天然带编号，DETR 也不必做匹配。

三、从 object query 到 action query：类比的边界

「object query 换成 action query」是理解 ACT 结构最有用的一句话，但它只在一定范围内成立。把边界划清楚，比记住这个类比本身更重要。

3.1 类比成立的部分

都是可学习参数源码中同为一张嵌入表：DETR 是 nn.Embedding(num_queries, hidden_dim)，ACT 是完全一样的写法，只是 num_queries 的含义从「最多检测多少物体」变成「动作块长度 H」。
都不携带样本信息query 是全局共享的固定参数，对任何输入样本都一样。当前样本的信息全部通过 cross-attention 从 encoder 的输出里读取。
都是并行解码N 个或 H 个输出在一次前向中同时产生，彼此通过 decoder 的 self-attention 互相可见。
都需要位置信息才能区分若不给 query 加以区分，它们是对称的、无法分工。区分靠的就是 query embedding 本身各行不同。

3.2 类比不成立的部分

维度 DETR 的 object query ACT 的 action query
槽位的语义 「第几个物体」，无内在顺序，哪个 query 对应哪个物体由匹配决定 「第几个未来时刻」，有严格时序，第 \(i\) 个 query 就是 \(t+i\) 时刻
输出之间的关系 训练目标要求互斥：不同 query 不应重复同一物体 时间槽位通常需要协同，但结构本身不保证轨迹连续或平滑
数量的含义 容量上界，允许有大量「无物体」空槽 精确长度，每个槽位都必须产出有效动作
与真值的对应 需要匈牙利匹配 按下标直接对应
数量改变的后果 改 \(N\) 只影响能检测的物体数上限 改 \(H\) 同时改变模型输出长度、监督标签截断长度、CVAE encoder 的位置编码表长度（见子页 ②）

第二行的差异最值得体会：DETR 的匹配损失要求不同槽位不要重复认领同一物体；ACT 的监督则要求每个槽位拟合相应未来时刻。decoder self-attention 让槽位之间能够交换信息，但仅凭这一结构不能保证去重、连续或平滑。

需要说准的是谁在提供约束：DETR 的不重复由一一匹配与集合级损失显式约束；ACT 的 L1 损失逐坐标、逐时刻比较预测与示范，并不是速度或加速度意义上的平滑正则。ACT 的块内连贯性主要从示范轨迹的时间相关性中学习，执行期的 temporal ensembling 还会进一步平滑相邻预测。

这也解释了 ACT 为什么不需要匹配这一步：顺序信息不是学出来的，而是由 query embedding 的行序与损失的逐位置对应共同规定死的。 训练时第 5 个 query 的输出永远与第 5 个真实动作算 L1，它别无选择，只能学会「我负责块内第 5 步」。这是一条比匈牙利匹配更强的约束——匹配允许对应关系随样本变化，而 ACT 的对应关系恒定不变。

3.3 一个常见的误读

有资料把 action query 描述成「上一步动作的嵌入」或「decoder 逐步生成时的输入」。这与源码不符：

self.query_embed = nn.Embedding(num_queries, hidden_dim)   # 可学习参数表，与样本无关
...
hs = self.transformer(src, None, self.query_embed.weight, pos, latent_input, proprio_input,
                      self.additional_pos_embed.weight)[0]
a_hat = self.action_head(hs)                               # 一次作用于全部 H 个位置

self.query_embed.weight 是一张固定的参数表，直接整张传进 Transformer，前向过程中没有任何位置把预测出的动作回喂给模型。关于「ACT 不是自回归」这一点，子页 ② 已从动作分块的角度论证过，本页第八节会从结构侧再给出源码依据，两处角度不同、不重复。

四、视觉主干：一个被所有相机共享的 ResNet-18

ACT 的视觉侧基本沿用 DETR 的做法：ResNet 主干提特征，1×1 卷积投影到 Transformer 的隐维度。但有几处配置值得逐条核对，因为它们直接影响复现结果。

4.1 主干的五个关键配置

配置 取值 源码依据 说明
网络 ResNet-18 imitate_episodes.py 中 backbone = 'resnet18' 官方配置事实；现有资料未给出与更大主干的受控消融
预训练 ImageNet backbone.py 中 pretrained=is_main_process() 源码加载 ImageNet 预训练权重；输入也按 ImageNet 均值与方差归一化

冻结 BatchNorm 这一条值得多说一句。FrozenBatchNorm2d 不读取当前 mini-batch 的统计量，其均值、方差、缩放与偏置都作为固定 buffer 使用，所以训练和推理执行同一个固定仿射变换。小 batch 下避免批统计波动是采用它的常见动机，但 ACT 作者没有把这点写成经过消融验证的结论；源码甚至保留了 TODO do we want frozen batch_norm??，因此不应把动机当成论文事实。

4.2 所有相机共享同一个主干

这是一处容易看漏、但影响很大的实现细节：

for cam_id, cam_name in enumerate(self.camera_names):
    features, pos = self.backbones[0](image[:, cam_id])    # HARDCODED
    ...

注意索引是写死的 self.backbones[0]，源码里就跟着 # HARDCODED 这条注释。也就是说，尽管 self.backbones 是一个 nn.ModuleList，实际参与计算的永远是第 0 个。四路相机轮流通过同一个 ResNet-18。

这个选择有明确的取舍：

好处参数量不随相机数增长，各视角共同更新同一组卷积权重；这是一种参数共享。它是否等价于提高有效样本量、对少量示范有多大帮助，官方资料没有给出消融证据。
可能的代价固定相机与腕部相机在视野、尺度和运动模式上存在分布差异，共享主干需要同时适配这些视角；专用主干是否更好仍需消融验证。
相机身份的边界主干不接收 cam_name；每路 2D 正弦位置编码又从相同坐标重新开始，因此原实现没有显式 camera-ID embedding。模型只能从图像内容和固定视角的视觉统计中间接推断来源，不能把“序列分段”本身当作相机标签。

4.3 投影到隐空间

ResNet 输出 512 通道，Transformer 的 hidden_dim 也是 512（官方命令 --hidden_dim 512）。两者虽然数值相同，源码仍然显式加了一层 1×1 卷积：

self.input_proj = nn.Conv2d(backbones[0].num_channels, hidden_dim, kernel_size=1)

保留这一层的意义在于解耦：主干换成 ResNet-50（2048 通道）或 hidden_dim 改成其他值时，这一行不需要动。1×1 卷积在空间维上不做任何混合，等价于对每个空间位置独立地做一次线性变换——正是「把特征图变成 token」这一步所需要的操作。

4.4 主干用单独的学习率

优化器把参数分成两组：

param_dicts = [
    {"params": [p for n, p in model.named_parameters() if "backbone" not in n and p.requires_grad]},
    {"params": [p for n, p in model.named_parameters() if "backbone" in n and p.requires_grad],
     "lr": args.lr_backbone},
]
optimizer = torch.optim.AdamW(param_dicts, lr=args.lr, weight_decay=args.weight_decay)

主干参数使用 lr_backbone = 1e-5，其余部分使用命令行参数 lr。这种分组允许给预训练主干更小的步长，但是否更小取决于 lr 的实际取值：官方 README 的仿真示例同样设置 --lr 1e-5，此时两组学习率相等。只要 lr_backbone > 0，主干就没有被冻结。

更深一层：本节各模块的类型与权重形状、FrozenBatchNorm2d 为什么不计入参数量、train_backbone 为什么不产生冻结行为，以及优化器参数组的确切划分依据（input_proj 为什么没有落入 lr_backbone 组），见子页 ⑨ 网络模型逐模块拆解 第四节与第 10.4 节。

五、多相机特征如何变成一条 token 序列

这是 ACT 相对 DETR 最实质的一处改造。DETR 只处理单张图，ACT 要同时处理四路相机，而它选择的融合方式非常直接：把各路特征图沿「宽度」维首尾相接，拼成一张超宽的特征图，再统一展平成一条 token 序列。

all_cam_features, all_cam_pos = [], []   # 源码分两行各自初始化，此处合并以便阅读
for cam_id, cam_name in enumerate(self.camera_names):
    features, pos = self.backbones[0](image[:, cam_id])   # HARDCODED
    features = features[0]                                 # 只取 layer4
    pos = pos[0]
    all_cam_features.append(self.input_proj(features))
    all_cam_pos.append(pos)
...
# fold camera dimension into width dimension
src = torch.cat(all_cam_features, axis=3)
pos = torch.cat(all_cam_pos, axis=3)

源码里那行注释 # fold camera dimension into width dimension 把意图说得很清楚：相机这一维不单独保留，而是被折叠进宽度维。

5.1 维度上发生了什么

按真机配置（输入 480×640，ResNet 下采样 32 倍，四路相机）逐步推算：

步骤 张量形状 说明
单路输入图像 \((B,\, 3,\, 480,\, 640)\) 官方真机为 4 路 480×640 RGB
经 ResNet-18 layer4 \((B,\, 512,\, 15,\, 20)\) 空间尺寸缩小 32 倍
经 input_proj 1×1 卷积 \((B,\, 512,\, 15,\, 20)\) 通道投影到 hidden_dim，空间不变
四路沿 axis=3 拼接 \((B,\, 512,\, 15,\, 80)\) 宽度由 20 变成 4 × 20 = 80
flatten(2).permute(2,0,1) \((1200,\, B,\, 512)\) \(15 \times 80 = 1200\) 个视觉 token

这里必须区分“拼接顺序”与“可被模型读取的相机身份”。每一路都单独计算 2D 正弦编码，坐标在各视角中重新从原点开始，因此同一行列位置满足

\[\mathbf{P}_{c,r,s}=\mathbf{P}_{r,s},\]

其中 \(c\) 是相机编号。原实现没有为 \(c\) 增加独立 embedding；而无位置标记的自注意力对 token 排列是置换等变的，所以“位于拼接后的第几段”本身不是可靠的 camera ID。模型仍可能根据图像内容和固定视角的统计差异识别来源。若增加 camera embedding，那是合理扩展，但不属于原版 ACT。

5.2 为什么是拼接，而不是别的融合方式

对照几种常见方案，可以更准确地理解序列拼接所采用的归纳偏置：

融合方式 做法 主要取舍
ACT：序列拼接 各路特征首尾相接，再由全局自注意力建立联系 不显式规定跨视角几何对应；保留每个空间 token，但序列与注意力开销随相机数增长
通道拼接后卷积融合 同索引位置的多路特征沿通道叠加 引入较强的固定位置对应假设；能否适用取决于视角关系与后续网络设计
逐路池化后求和或取平均 每路先压成全局向量再合并 计算量较低，但池化会压缩细粒度空间位置；这不等于所有独立分支方案都必然丢失空间信息
显式几何投影融合 借助内外参把多视角特征投到公共坐标系 可注入几何先验，但依赖标定质量、投影表示与遮挡处理；不能脱离具体系统断言一定更准确或不可靠

源码能够确认 ACT 使用了简单的序列拼接；现有官方材料并没有把“外参不准确”写成选择该方案的决定性原因，也没有给出上述融合方式的对照消融。因此，本节只说明结构差异，不把可能的工程动机写成作者结论。

5.3 开销与它的边界

这个方案的代价是序列长度。encoder 的自注意力复杂度随序列长度平方增长，而序列长度正比于相机数：

\[L_{\text{visual}} \;=\; N_{\text{cam}}\,h_f\,w_f \;=\; 4 \times 15 \times 20 \;=\; 1200 .\]

加入 latent 与 proprio 后，encoder 总长度为 \(L_{\text{enc}}=L_{\text{visual}}+2=1202\)。标准全局自注意力的分数矩阵计算量主要为 \(O(L_{\text{enc}}^2d)\)，注意力矩阵存储量为 \(O(L_{\text{enc}}^2)\)。在特征尺寸不变时，相机从 4 路增至 8 路会使视觉 token 从 1200 增至 2400，因此二次项约增至 4 倍。标准 ResNet-18 与 ResNet-50 的 layer4 通常都具有 32 倍下采样，输入尺寸相同时空间 token 数相同；更深主干会增加卷积计算和通道投影开销，但不能据此解释 ACT 为什么选择 ResNet-18。

Open Cup：策略实际看到的多路观测

这是送进网络的图像流。判断某个关键状态能否被网络感知时，应以这类视角为准。

Thread Velcro：腕部视角提供接触细节

穿魔术贴需要毫米级对准，腕部相机的近距视角对此最直接。四路相机的分辨率是相同的（均为 480×640），差别在视角而不在分辨率；哪一路更有用是本站基于任务性质的解读，官方未对各路相机的分工作说明。

Slide Ziploc：固定视角提供全局关系

拉封口袋需要两臂的相对位置与物体整体姿态，固定视角对此更有利——同样是本站的解读，官方未作此说明。

固定相机通常更容易提供全局布局与双臂关系，腕部相机通常更容易呈现局部接触细节，因此多视角具有互补信息。不过，官方资料没有给出单相机消融，不能据此断言任意一路单独使用都必然不足。

六、四套位置编码的分工

不带位置信息的自注意力是置换等变的：若以同一置换重排 token，输出也只会相应重排。加入位置编码后，只有把内容与其位置编码一起重排才保持这种等变性；若位置编码留在原位，输入含义已经改变。ACT 共有四套位置编码，它们的来源、可学习性与作用范围不同。

编号 用在哪里 源码 类型 是否可学习 长度
① CVAE encoder 的输入序列 register_buffer('pos_table', get_sinusoid_encoding_table(1+1+num_queries, hidden_dim)) 1D 固定正弦表 否（register_buffer） \(H + 2\)
② 视觉 token PositionEmbeddingSine(hidden_dim // 2, normalize=True) 2D 正弦 否 随特征图尺寸，真机为 1200
③ latent token 与 proprio token additional_pos_embed = nn.Embedding(2, hidden_dim) 可学习嵌入 是 2
④ decoder 的 action query query_embed = nn.Embedding(num_queries, hidden_dim) 可学习嵌入 是 \(H\)

6.1 为什么视觉用 2D 正弦

视觉 token 的位置是二维的：一个 token 既有行坐标也有列坐标。源码的做法是把 hidden_dim 对半分，行列各占一半：

N_steps = args.hidden_dim // 2                       # 512 // 2 = 256
position_embedding = PositionEmbeddingSine(N_steps, normalize=True)

行方向生成 256 维正弦编码，列方向生成 256 维，拼接为 512 维。频率按 temperature = 10000 的经典设置变化，与原始 Transformer 的正弦编码同源。固定正弦编码无需维护给定尺寸的可学习查找表，并能按新尺寸直接计算；但“能够计算”不等于模型一定能对未见分辨率泛化。连续坐标结构是理解这一选择的合理归纳偏置，不是 ACT 论文单独验证过的因果结论。

6.2 为什么 latent 与 proprio 用可学习嵌入

这两个 token 与视觉 token 不同：它们只有两个，顺序只是接口约定，并不表示几何距离或时间间隔。两行可学习向量在功能上充当模态标记，使注意力能区分 latent 与 proprio；这是一种直接的参数化选择，并不意味着固定编码在数学上不可用。

源码里这两套编码是拼接起来的，顺序必须与 token 的拼接顺序一致：

additional_pos_embed = additional_pos_embed.unsqueeze(1).repeat(1, bs, 1)   # (2, bs, dim)
pos_embed = torch.cat([additional_pos_embed, pos_embed], axis=0)           # 两个额外编码在前
 
addition_input = torch.stack([latent_input, proprio_input], axis=0) # (2, bs, dim)
src = torch.cat([addition_input, src], axis=0) # 两个额外 token 在前

当前实现中，两处 cat 的顺序对应：位置编码第 0 行加到 latent，第 1 行加到 proprio，之后才是视觉 token。对一个已有 checkpoint，只改 token 顺序而不相应交换两行 embedding 会改变模型行为；但从头训练时，这两行本来就是自由参数，整体交换其编号只是参数重标记，不能断言会导致“把 latent 当作 proprio”或收敛变慢。

6.3 为什么 action query 用可学习嵌入

第 ④ 套为 decoder 的每个输出槽位提供身份和检索方向。第八节会说明 decoder 的初始 tgt 是全零张量，因此第一层注意力的 query 由 query_embed 区分；但当前样本的内容来自 cross-attention 读取的 encoder memory，不能把 query embedding 称为 decoder 唯一的“内容”来源。

可学习 query 能为每个时间槽位提供直接、灵活的参数化，既可编码相对位置，也可形成数据驱动的检索偏好。固定正弦 query 同样能区分位置，并非原则上“做不到”；二者只是归纳偏置与参数化方式不同。ACT 采用前者，但官方资料没有提供两者的对照消融。

七、Transformer encoder：融合什么

encoder 的职责是把三种异构信息融合成一份统一的上下文表示，供 decoder 检索。

7.1 输入序列的组成

addition_input = torch.stack([latent_input, proprio_input], axis=0)   # (2, bs, 512)
src = torch.cat([addition_input, src], axis=0)                        # (2 + 1200, bs, 512)

序列共 1202 个 token，分三段：

第 0 位：latent token来自 CVAE 的 z 经 latent_out_proj 投影。训练期是重参数化采样的结果，推理期是该层的偏置向量（详见子页 ③ 第 6.5 节）。
第 1 位：proprio token当前 14 维关节位置经 input_proj_robot_state 投影到 512 维。它是唯一的本体状态入口。
第 2 位起：1200 个视觉 token四路相机特征拼接展平的结果，按相机顺序分成四段。

注意一个不对称：本体状态只占 1 个 token，视觉占 1200 个。 这意味着从 token 数量上看视觉信息占绝对多数。这不必然导致本体信息被淹没——注意力权重是学出来的，一个 token 完全可以获得很高的权重——但它确实是 ACT 结构上的一个特点，也是后续工作（例如把本体状态展开成多个 token）可能改进的方向。

7.2 encoder 在做什么

四层标准 Transformer encoder，每层是自注意力加前馈网络。由于所有 token 在同一条序列里，自注意力可以建立三类关联：

可建立的关联 结构上允许的信息交换 边界说明
视觉与视觉（跨相机） 任一路视觉 token 都可关注其他视角的 token 允许学习跨视角对应，不代表一定学到几何一致的同物体匹配
视觉与本体状态 视觉 token 与关节状态 token 双向交换信息 可联合表示场景与当前构型，但“图像—关节对齐”仍需从示范中学习
latent 与其余 风格变量可影响视觉、本体与后续 decoder 所见内容 latent 的具体语义由 CVAE 目标与数据共同形成，不是预先指定的标签

encoder 的输出称为 memory，形状与输入相同，仍是 \((1202,\, B,\, 512)\)。它会被 decoder 的每一层 cross-attention 反复读取。

一个实现细节：ACT 调用时 mask 传的是 None（self.transformer(src, None, ...)），即 encoder 侧不做任何 padding 掩码。这与 DETR 不同——DETR 需要掩码是因为批内图像尺寸不一需要 padding，而 ACT 的相机分辨率固定，所有样本的视觉 token 数完全相同，不需要掩码。CVAE encoder 那一侧则相反，它有 src_key_padding_mask=is_pad，因为动作序列长度会在 episode 尾部不足。

八、Transformer decoder：action query 如何并行产生动作

这一节是全页最容易被误解的部分。核心在于：decoder 的输入不是 action query，而是一个全零张量；action query 是以位置编码的身份参与每一层注意力的。

8.1 初始输入是零张量

tgt = torch.zeros_like(query_embed)                         # 全零，形状 (H, bs, 512)
memory = self.encoder(src, src_key_padding_mask=mask, pos=pos_embed)
hs = self.decoder(tgt, memory, memory_key_padding_mask=mask,
                  pos=pos_embed, query_pos=query_embed)      # query_embed 走 query_pos 通道

query_embed 没有作为 decoder 的输入张量传进去，而是通过 query_pos 这个参数传入。它在每一层里的用法如下：

def with_pos_embed(self, tensor, pos):
    return tensor if pos is None else tensor + pos
 
# TransformerDecoderLayer.forward_post 的主体，逐行照录：
 
        q = k = self.with_pos_embed(tgt, query_pos)
        tgt2 = self.self_attn(q, k, value=tgt, attn_mask=tgt_mask,
                              key_padding_mask=tgt_key_padding_mask)[0]
        tgt = tgt + self.dropout1(tgt2)
        tgt = self.norm1(tgt)
        tgt2 = self.multihead_attn(query=self.with_pos_embed(tgt, query_pos),
                                   key=self.with_pos_embed(memory, pos),
                                   value=memory, attn_mask=memory_mask,
                                   key_padding_mask=memory_key_padding_mask)[0]
        tgt = tgt + self.dropout2(tgt2)
        tgt = self.norm2(tgt)
        tgt2 = self.linear2(self.dropout(self.activation(self.linear1(tgt))))
        tgt = tgt + self.dropout3(tgt2)
        tgt = self.norm3(tgt)
        return tgt

三处 with_pos_embed 调用里，self-attn 的 q 与 k 都加 query_pos、value=tgt 不加；cross-attn 的 query 加 query_pos、key 加 pos、value=memory 不加。三个残差块都是先加残差再 norm，即 post-norm 结构。

两个值得记住的规律：

位置编码只加在 query 与 key 上，不加在 value 上位置信息决定「谁该关注谁」，即注意力权重的计算；而取出来的内容应当是纯粹的特征本身。这是 DETR 系结构的统一约定。
query_pos 在每一层都重新加一次不是只在输入端加一次。这样即使经过多层变换，每个槽位仍始终带着「我是第几个」的标记。

8.2 第一层实际发生了什么

把 tgt = 0 代入，并先看关闭 dropout 的评估模式，可以清楚地追踪信息来源：

步骤 结果 说明
self-attn 的 \(q = k\) \(\text{query\_pos}\) 注意力权重可因槽位而异
self-attn 的 value 零输入经线性投影后，各位置都是同一偏置 \(b_V\) softmax 权重逐行和为 1，因此加权和仍为 \(b_V\)
self-attn 的输出 每个槽位得到同一常量 没有观测相关信息，也没有形成确定性的槽位差异
经 norm1 后 每个槽位仍为同一向量 \(c\) 此结论针对 dropout 关闭时
cross-attn 的 query \(c + \text{query\_pos}\) query embedding 在这里使不同槽位采用不同检索方向
cross-attn 的输出 从 memory 读取当前样本的内容 观测、proprio 与 latent 的样本相关信息在此进入 decoder

因此，第一层 self-attention 不引入样本相关的 value 内容；第一层 cross-attention 才从 memory 注入当前样本信息，后续层的 self-attention 再在已含样本信息的槽位之间交换内容。训练模式下 attention dropout 会破坏“每次前向严格相等”的代数结论，但不会改变其 value 不含观测信息这一事实。

8.3 两种注意力各自负责什么

cross-attention：读取条件信息每个时间槽位以自己的 query 表示去 1202 个 memory token 中检索。不同槽位可以形成不同关注模式，但“第几个 query 必然关注哪个阶段或区域”不是结构预设，需要通过训练与可视化才能判断。
self-attention：允许槽位交互H 个时间槽位彼此可见，因此后续层可以协调不同未来时刻的内部表示。它提供的是信息通道，不是平滑保证；逐位置 L1 也不是显式时间平滑项。轨迹连贯性来自数据、模型学习与执行期 temporal ensembling 的共同作用。
更深一层：这两种注意力在一层里按什么顺序发生、各自的 query 与 key 与 value 分别来自哪个张量、第一层为什么自注意力输出与 query 无关（代数推演），见子页 ⑩ Transformer 层内实现 第六节与第七节。

8.4 动作头

decoder 输出经过一个线性层直接得到动作：

self.action_head = nn.Linear(hidden_dim, state_dim)   # 512 -> 14
...
a_hat = self.action_head(hs)                          # 一次作用于全部 H 个位置

没有任何分阶段或逐步的结构——hs 的形状是 \((B,\, H,\, 512)\)，线性层在最后一维上作用，一次产出 \((B,\, H,\, 14)\)。这就是「并行输出整段动作」在代码上的全部内容。

模型里还有一个 is_pad_head = nn.Linear(hidden_dim, 1)。在当前官方 policy.py 中，is_pad_hat 被接收后丢弃，没有参与训练损失或策略输出，因此该头得不到任务损失的梯度。它为何保留，官方没有说明；把它断言为 DETR 遗留结构缺乏直接依据。

十、一处值得留意的源码细节

第 9.1 节第 14 步的那个 [0]，其语义与原版 DETR 里同样位置的 [0] 并不相同。这一节把事实链完整列出，供复现时核对。

10.1 事实链

项 原版 DETR ACT
Transformer.forward 的返回 二元组：return hs.transpose(1, 2), memory.permute(1, 2, 0).view(bs, c, h, w) 单个张量：return hs

return_intermediate_dec=True 在 build_transformer 中是硬编码的，因此 decoder 返回的是各层输出的堆叠：

for layer in self.layers:
    output = layer(output, memory, ...)
    if self.return_intermediate:
        intermediate.append(self.norm(output))
if self.norm is not None:
    output = self.norm(output)
    if self.return_intermediate:
        intermediate.pop()

十一、与自回归式策略的分界

“自回归”首先描述的是条件分布的分解方式，而不是动作采用连续值还是离散 token。典型时间自回归模型满足

\[p(\mathbf{a}_{t:t+H-1}\mid \mathbf{o}_t) =\prod_{i=0}^{H-1} p(\mathbf{a}_{t+i}\mid \mathbf{a}_{t:t+i-1},\mathbf{o}_t),\]

所以生成第 \(i\) 步时需要此前动作。ACT 则用一组时间槽位直接计算整个块，可概括为 \(\hat{\mathbf{a}}_{t:t+H-1}=f_\theta(\mathbf{o}_t,\mathbf{q}_t,\mathbf{z})\)；它没有把本块较早的真实动作或已预测动作作为较晚位置的输入。

源码提供了三条相互印证的证据：

tgt = torch.zeros_like(query_embed)             # 不输入真实动作或已生成动作
hs = self.decoder(tgt, memory, ..., query_pos=query_embed)
# tgt_mask 默认为 None；随后 action_head 同时作用于全部 H 个位置
  • tgt 为全零张量，不存在 teacher forcing 的动作 token；
  • tgt_mask=None，\(H\) 个槽位在 self-attention 中双向可见；
  • 动作头一次接收全部 \(H\) 个槽位，不按时间位置循环回馈预测。

因果掩码是判断并行训练的 Transformer 自回归解码器的重要证据，但不是跨架构的唯一判据：RNN 可以用显式循环保证因果顺序而无需注意力掩码，定制算子也可能用其他方式限制依赖。最终仍应检查概率分解、输入依赖和实际生成流程。

比较项 典型自回归策略 ACT
块内依赖 第 \(i\) 步条件于较早动作 每个槽位共同条件于同一份 encoder memory
Transformer 因果掩码 并行 teacher forcing 时通常需要 None，槽位双向可见
decoder 动作输入 真值历史或已生成历史 全零 tgt，没有动作历史
块内生成 推理通常按位置串行 一次 decoder 调用并行给出 \(H\) 个位置
块内 exposure bias teacher forcing 模型通常存在 不存在“真值历史—预测历史”落差
完整模型的训练/推理路径 取决于具体模型 不完全相同：latent 路径与 dropout 状态不同

最后一行是必要边界：ACT 的动作 decoder 在训练和推理时都不回馈块内动作，因此没有块内 teacher-forcing 暴露偏差；但完整模型并非“训练与推理完全一致”。训练时 CVAE encoder 使用真实动作构造后验并采样 \(z\)，推理时跳过该 encoder 并令 \(z=0\)；训练期 dropout 通常开启，评估期关闭。

动作表示与生成分解是两个独立维度：离散动作 token 可以被并行预测，连续动作也可以自回归生成。Diffusion Policy 或 flow-based action expert 通常对整段动作做多步去噪或数值积分；它们可以是非自回归的块生成，但并不等于“一次普通网络前向就完成”。因此不能只凭“离散/连续”“有没有 causal mask”或“论文称为 action expert”给模型分类。
