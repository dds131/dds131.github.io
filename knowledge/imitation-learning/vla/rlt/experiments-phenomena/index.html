RLT 枢纽· ← ⑥ 开源实现· ⑦ 实验与现象

RLT 的关键证据不是“能完成任务”，而是能否在少量在线数据下同时提高成功率与吞吐

成功率、关键阶段时间、完整任务成功率和训练失败数回答的是不同问题。正确解读实验必须保持任务、阶段与比较口径，不把“最高 3×”外推成所有场景的固定收益。

一、实验设置：先固定口径

RLT 原论文以 Physical Intelligence 的 $\pi_{0.6}$ 为基座，在四项真实机器人精密操作上评估。论文和附录披露的主要设置如下：

项目 论文设置 解释边界
控制频率 50 Hz 具体硬件环路，不是 RLT 固定频率
视觉输入 2 个腕部相机 + 1 个基座相机 用于生成 RL token；不是算法固定相机数
VLA horizon $H=50$，约 1 秒 实际通常只执行前缀后重规划
RL chunk $C=10$ 论文任务配置，不是通用最优
动作维度 每步 14 维，RL chunk 共 140 维 说明为何无约束搜索困难；不是通用机器人维数
RL state RL token + 任务相关 proprio Proprio 在不同任务中可不同
任务时长 完整任务约 30–120 秒；关键阶段约 5–20 秒 不可把关键阶段提速直接换算为全任务同倍提速
受控评估 每个 agent、每项任务 50 个关键阶段 episode 与完整任务评估分开
Actor 固定小方差 Gaussian MLP 三项任务两层 256；螺丝三层 512
Critic 两个 Q 网络 Target 取较小值降低过估计
Reward 人工终局成功 +1，失败 0 论文核心口径是稀疏二值奖励
Stage 1 每任务约 2,000–10,000 梯度步 与任务数据规模相关
示范数据 每任务约 1–10 小时遥操作 用于任务 VLA 与 RL token 适配
在线训练 约 400–1,000 回合 难度不同，回合数不同
真机数据 约 15 分钟至 5 小时实际机器人数据 不含 reset 与部分系统开销

论文附录还说明，对最终策略报告时收集约 5 小时数据；正文的 15 分钟至 5 小时范围反映不同任务与实验阶段。两种表述不能被压成一个统一训练时长。

二、四项任务为什么难

任务 关键阶段 主要困难 RLT 需要学到什么
拧 M3 螺丝 批头与螺丝头对齐并旋入 亚毫米误差、长工具放大角度偏差、关键视觉来自另一腕相机 对齐、稳定接触、决定性下压/旋入
扎带穿孔 柔性尾端穿过狭窄锁扣 双臂协同、柔性物体、只靠腕相机定位 末端与孔位的协同微调
Ethernet 插入 姿态对准并越过端口阻力 连接器卡壳、接触动力学、犹豫导致反复试探 更果断的插入与利用顺应性
充电器插入 插脚与插座对齐 插脚可见性差、部分可观测、易反复 probing 减少无效试探并保持可靠性

共同点不是物体外观，而是：大 VLA 已完成粗技能，决定成败的阶段很短、精度高、奖励稀疏，且真实接触动力学难从离线示范完全学习。

三、主要结果怎样读

最高约 3×关键阶段执行速度提升
20% → 65%论文列举的困难螺丝任务成功率
约 2× 更少步骤Ethernet 相对基座的平均完成步数
5 分钟关键数据Ethernet 消融图中超过替代策略；总实验约 40 分钟

关键阶段评估

隔离精密接触阶段后，RLT 在四项任务上都提升了成功率或速度。对本来已较可靠的充电器和 Ethernet，最显著变化是关键阶段约 3× 更快；对更难的扎带与拧螺丝，成功率提升更明显。

完整任务评估

完整任务还包含抓取、抬起、移动等前段误差，整体成功率自然更低。论文称 RLT 在完整任务上仍使拧螺丝成功率提高 40%、扎带提高 60%。原文没有在该句中改写为“百分点”，因此这里保留论文的提升表述，不自行换算。

Ethernet 吞吐

RLT 在保持基座高成功率的同时，把平均完成步数相对基座约降低 2×。论文 Fig. 9 进一步报告：关键插入阶段有一半 RL episodes 比所有遥操作示范都快；这是 Ethernet 上的分布观察，不应外推为每项任务或每次 rollout 都超过人类。

“关键阶段”与“完整任务”不能混报。前者隔离 RLT 直接优化的控制片段；后者还受基座前段错误与切换入口分布影响。局部提速不自动等于整条任务同倍提速。

四、与替代方法的比较

论文在 Ethernet 上比较四类基线：

基线 核心接口 实验现象 机制解释
HIL-SERL 单步小策略 + 人在回路 该长时稀疏任务上学习困难 数百单步决策使 reward 传播过长
PLD 冻结 VLA 上的单步 residual 表现较弱 单步 residual 仍面临长时信用分配
DSRL 在 VLA latent/noise 空间 steering 成功率高但吞吐落后 强先验约束稳定，却限制动作改进幅度
DAgger 用介入数据监督微调 可保持较好成功率但速度提升有限 目标没有直接优化回报或速度，实验中受纠正数据行为影响

RLT 的优势来自组合而非单一模块：VLA 表征、动作块、reference conditioning 和 BC anchor 同时改善早期探索与长时信用分配。

五、四项消融各证明什么

flowchart TD
  FULL["完整 RLT"] --> T["去 RL token<br/>换 ImageNet ResNet-10"]
  FULL --> C["去 Chunk<br/>C = 1；同时换 ResNet-10"]
  FULL --> B["去 BC 正则<br/>β = 0"]
  FULL --> P["去 Pass-Through<br/>Actor 不看 reference"]
  T --> TR["吞吐约下降 50%"]
  C --> CR["难以匹配基座表现"]
  B --> BR["最大单项性能下降"]
  P --> PR["更慢、早期失败更多"]

1. w/o RL token

用冻结 ImageNet ResNet-10 替代 RL token 后，论文报告吞吐下降约 50%。这表明 VLA 内部任务表征比普通视觉分类特征更适合精密操作价值学习；但它不证明 RL token 在所有任务上优于所有视觉编码器。

2. w/o Chunk

论文把 $C$ 改为 1 后，任务重新变成数百步的稀疏奖励问题；但由于 50 Hz 查询 VLA 不可行，作者还同时把 RL token 换成冻结的 ResNet-10。该版本不能可靠达到基座性能，说明这一组合方案明显较弱，却不能把全部差距严格归因于 chunk 单变量。

3. w/o BC Regularizer

令 $\beta=0$ 造成最大单项下降。没有 VLA 锚点，Actor 只能依赖小数据 critic 在完整高维动作块空间中搜索，更容易利用 Q 外推误差。

4. w/o Pass-Through

Actor 不再直接看到 reference。论文在较简单的 Ethernet 上观察到它最终可追上，但早期漂移、失败和退化行为更多。这支持 pass-through 改善该任务的学习速度与早期稳定性；不构成跨任务的安全性证明。

六、五个反直觉现象与底层原因

1. 基座成功，却很慢

成功率只检查终局；行为克隆会保留示范中的减速、退回和重复对准，没有动力主动压缩完成时间。

2. RLT 比专家示范更快

RL 不优化逐帧相似度；当 $\gamma<1$ 时，更早获得终局成功奖励具有更高折扣回报。有效探索进入 replay 后可被重复学习。

3. RLT 首次失败后仍施压并 wiggle

策略在真实接触中发现机械顺应性可帮助插入；该动作来自在线探索，不是示范复制。

4. 无 Pass-Through 最终也能追上

在较容易的 Ethernet 上，$z_{rl}+proprio$ 足以让该消融最终追近；这不是充分状态的普遍证明，且早期搜索代价更高。

5. 关键阶段很好，完整任务仍掉点

前段抓取与移动改变 RL 入口分布；局部策略不能修复在更早阶段已经发生的失败。

Ethernet 的 probing 与 wiggle 是论文直接观察；其余工程诊断必须结合日志验证，不能仅凭视频做因果断言。第三方 openpi-RLT 对比视频见开源实现页。

七、训练与推理异常诊断矩阵

症状 首要证据 优先检查 可能根因
Actor 永远复制 reference actor-reference MSE 近零 dropout mask、$\beta$、Q action-gradient Critic 信号弱或 BC 占优
Actor 很快饱和/撞限 动作饱和率、Q 分布 归一化、裁剪、twin Q、BC Q 对分布外动作过估计
Q 上升但成功率不变 Q-return 校准、TD error terminal、reward、$\gamma^C$ Bootstrap 语义错误
训练好、评估差 训练/评估输入 diff reference、norm stats、dropout mode 推理分支不一致
Chunk 内平滑、边界抖动 时间戳与动作队列 replan 延迟、缓存清理 新旧 chunk 错位
人介入后性能更差 replay 字段抽样 executed/ref/human action 把错误 reference 当纠正标签
固定初态好、全任务差 RL 入口状态分布 切换点与前段扰动 关键阶段训练分布过窄
UTD 提高后发散 replay age、Q gap 学习率、最新数据比例 对陈旧 replay 过拟合

诊断顺序应是：先验证数据和时序，再检查 critic，最后调整 actor 超参数。若 replay 中动作/奖励语义错误，调学习率或网络规模只会让错误拟合得更快。

八、哪些结论还不能得到

  • 四个精密操作任务不能证明 RLT 对所有长时、开放世界任务都同样有效。
  • 重建式 RL token 不能保证捕获所有接触物理量。
  • 人工 reward、介入和切换仍是系统的一部分；论文没有证明完全自主持续改进。
  • 最高 3× 是关键阶段的最大观察，不是固定平均收益。
  • 第三方 π0.5 复现的成功不能替代 π0.6 原实验，反之亦然。
  • BC anchor 降低探索风险，但不是形式化安全约束。

论文提出的未来方向包括用奖励模型与进度预测自动化部分监督，以及发展更自主的改进闭环。

九、如何设计自己的评估

至少同时报告：

  1. 关键阶段成功率；
  2. 完整任务成功率；
  3. 成功回合完成时间/底层步数；
  4. 训练中失败与人工介入次数；
  5. 实际机器人交互时间，而非只报 wall-clock；
  6. Actor-reference 距离与动作饱和；
  7. 不同入口状态扰动下的鲁棒性；
  8. 固定 VLA baseline、完整 RLT 与关键消融。

若只报告最终成功率，就会漏掉 RLT 最重要的速度收益和训练过程安全代价。
