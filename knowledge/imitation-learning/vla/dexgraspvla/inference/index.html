⑥ INFERENCE · H=64 · K=6 · n_obs=1

Inference 从 Training 接收 checkpoint、normalizer 与 processor，生成 64×13 动作块，却只把前 6 项依次写入目标后重新观测。20 Hz、0.3 秒、7/1/16 调用数和三个 VLM False 属于不同计量单位，不能互换成公开实现的实测频率或评测尝试数。

先给边界。 论文描述 20 Hz、执行 6 项后重规划；公开 Python 循环遍历前 6 项，却没有 sleep、时间戳、动作队列或消费完成确认。因此只能确认“依次写入六个目标”，不能确认每个目标保持 50 ms、六项全部被消费、0.3 秒完成一轮或真实重规划为 3.3 Hz。

一、证据分层、页面职责与制品入站

本页固定 DexGraspVLA arXiv:2502.20900v5、官方仓库 commit 0144c7928817c5149ae836da2682291360828a21 与官方项目页。证据分为论文事实、源码事实、可观察现象、机制假设和待运行指标；视频只证明项目页展示了相应现象，不证明频率、延迟、成功率或因果。

Inference 拥有 runtime loop、动作前缀写入、thread state、termination、重抓与目标移动的机制边界。Planner 与 Perception 分别拥有高层状态机和 SAM/Cutie 内部合同；Diffusion 拥有采样数学；Training 拥有制品；Experiments 拥有结果表、消融和置信区间；Source Code 拥有逐文件调用图。相邻页只通过合同交接，不在本页复制整表。

二、三类计数、Ours@k 与评测单位

H=64 是策略联合预测的动作长度，K=6 是本轮采用的动作前缀，n_obs_steps=1 是低层策略的显式观测窗口。论文的 20 Hz 是实验设置；若六项严格按 20 Hz 消费，纯执行时间为 6/20=0.3 s。这四个量都不是公开实现的实测吞吐。

Ours@k 的 k∈{1,2,3} 是外部评测最多尝试数，Ours@1 报告 90.8%。单次评测尝试内发生的重抓不另算新尝试；论文成功判据是物体抬离桌面 10 cm 并保持 20 s。源码里的 consecutive_failed_attempts≥3 则是同一次 execute_grasping 内三个 VLM False，既不是三次动作尝试，也不是 Ours@3。

三、理想滚动时域、名义跨度与真实周期

第 j 次重规划读取头部 RGB、目标 mask、腕部 RGB 与关节状态，形成当前观测 o_j；以新高斯初噪声生成 A_j=g_θ(o_j,ε_j)∈R^{64×13}。理想 receding-horizon 只采用索引 0–5，然后重新观测并生成新块。后 58 项是本轮未采用尾部，不是开环执行承诺。

在论文 20 Hz 口径下，64 步名义覆盖 64/20=3.2 s，6 步前缀名义覆盖 6/20=0.3 s。联合建模 3.2 秒时间结构，不代表控制器承诺开环执行 3.2 秒。完整周期还包含 policy、publish、low-level 和 schedule 延迟：严格串行时近似求和，充分流水时近似最大值；公开代码没有时间戳，真实 f_replan=1/T_cycle 必须测量，不能静态断言 3.3 Hz。

四、公开前缀循环与调用次数账本

公开策略输出 64×13，主线程只遍历前 6 项；后 58 项不进入该循环。六次循环没有 sleep、时间戳、动作队列或低层完成确认。每次迭代刷新缓存、覆盖臂目标并调用手部动作，因此准确表述是“依次写入六个目标”，而不是“六个动作已按 20 Hz 完整执行”。主线程若快于低层线程，中间目标可能在消费前被覆盖。

一次外层迭代调用 predict_action 1 次、观测编码器 1 次、DiT 16 次。外层首次读取加六步内层刷新，使 get_state、get_mask、get_obs 各调用 7 次；臂目标写入与手部 execute_action 各 6 次。1/1/16/7/6 是调用次数，不是独立新帧数、实际消费数，也不能换算成 23 Hz、3.3 Hz 或实测吞吐。

条件 token 在一次策略调用内只编码一次，并在 16 个 DDIM timestep 复用；DiT 前向 16 次，视觉编码器不重复运行。该结构减少重复计算，但真实延迟、吞吐和显存仍为 NOT_RUN。

调用账本还要与帧语义分开。三类 getter 被调用七次，只能说明主线程七次读取共享缓存；缓存可能没有在相邻调用间更新，因此不能自动得到七帧新图像。类似地，六次 setter 调用只证明 Python 层覆盖了六次目标变量，不能推出硬件侧接收、排队或完成了六段运动。若要把调用数升级为运行指标，至少需要 frame ID、单调时间戳、目标序号与低层 acknowledgment 四类记录。

五、控制回路、异步VLM终止与统一reset

flowchart TB
  O[当前RGB / mask / 关节状态] --> P[predict_action: ObsEncoder一次 / DiT十六次]
  P --> A[依次写入前六个动作目标]
  A --> O
  V[VLM核验线程] --> F[in_post_run]
  T[超时或键盘线程] --> F
  F --> X[退出 execute_grasping]
  X --> R[right_finish_reset]
  R --> C[planner模式 check_complete]

文本回退： 策略主循环持续读取观测、生成动作并写前缀目标；VLM 后台线程只判断终止，不生成动作；超时与键盘线程也能写入同一 in_post_run 标志；退出后统一执行 right_finish_reset，planner 模式随后再调用 check_complete。

VLM 线程每轮先做同步阻塞请求，请求返回后才 sleep(0.1)，还包含本地处理。因此实际核验间隔至少是 T_VLM+0.1 s+T_local，0.1 秒不等于固定 10 Hz，cadence 为 NOT_RUN。reset_flags 清零失败计数；每个 VLM False 加一，同一 execute_grasping 连续三个才终止，页面称其为“连续负面核验”。

高度门条件包含 current_height>height_threshold，但公开 height_threshold 初始化为 0 且未从配置读取；坐标系、单位和实际 z 范围没有固定。阈值 0 不能当作论文离桌 10 cm 成功判据，校准状态是 UNKNOWN。

VLM 成功、三个 False、超时和回车都可把同一个布尔值置真，主线程无法从该值恢复精确结束原因；四种路径之后都统一 reset。把结束原因改成枚举是工程建议，不是当前实现保证。

统一 reset 可以让控制流收敛到同一收尾路径，却也压缩了诊断信息：从 in_post_run=True 不能区分抓取成功、连续负面核验、超时还是人工回车。如果下游只看到 reset，便不能把该事件直接计为成功或失败；planner 模式的 check_complete 是 reset 后的另一项检查，也不能反向恢复先前终止原因。实验统计若需要分因，必须先补充不可混淆的结束原因记录。

六、失败后重抓：现象、解释与结构条件

论文与官方项目页展示失败后再次接近物体的现象。论文提出三类可能因素：基础视觉表征提供语义感知，模仿学习让策略覆盖成功轨迹中的不同阶段，扩散模型能够从多模态动作分布采样。公开材料没有对重抓逐项消融这三项贡献，因此它们只能写成可能条件，不能证明模型具有人类式失败理解，也不是充分因果解释。

重抓展示：chocolate官方定性视频；证明可观察现象，不测量重规划频率、成功率或单项机制贡献。
重抓展示：clock同一证据层级；不能由画面推断隐藏状态、扩散模态数量或失败理解。

源码提供三个必要结构条件：外层 while 持续反馈，使新观测影响后续动作；每次 conditional_sample 从新高斯初噪声开始；Cutie 在一次尝试内维护目标身份。反馈、随机采样和身份保持使恢复成为可能，但不证明某次动作是在“理解失败”后有目的地产生。

低层控制器 n_obs_steps=1，没有显式历史序列或循环隐状态；完整系统却不是无记忆：Cutie 保存视频分割记忆，planner、后台计数器与开始时间保持软件状态，关节和手部状态还包含物理历史。2094 条成功演示的 75 步轨迹覆盖成功过程多个阶段，pad_after=63 让 75 个时刻都可作为窗口起点；滑落、翻转、遮挡、卡手等失败仍可能超出成功分布。只有失败观测接近成功轨迹的中间状态时，恢复才可能合理。

七、目标移动跟随与人为干扰的五环链路

目标移动后继续跟随需要五个环节连续成立：相机产生新帧；Cutie 在新帧上维持目标身份且不漂移或串换；更新后的 RGBM 在下一策略调用前可见；控制器针对新位置生成可行动作；低层及时消费新目标。任何一环断裂都能产生失败，因此能力不能单归因于 Cutie、扩散或策略网络。

人为干扰展示：cola官方定性视频；不提供 frame ID、线程时间戳、低层确认或独立机制消融。
人为干扰展示：tea展示系统现象，不是跟踪频率、延迟、成功率或充分因果证据。

重抓属于低层闭环可能行为；长程任务中的换目标属于 planner；人为移动后的跟随由 Perception、观测更新、策略和执行共同完成。把三类现象都称为“扩散涌现”会抹掉责任链，也无法定位首个故障环节。

八、扩散随机性、名义horizon与变体隔离

eta=0 的 DDIM 在初始噪声、观测、模型参数和数值算子固定时条件确定；但每次 conditional_sample 都新建高斯初噪声，因此重复调用一般不保证相同动作。不同初噪声“可能”产生不同轨迹，不保证对应不同语义模态。Ours@2/3 的累计提升也不能全部归因于扩散多模态或有目的恢复，因为外部尝试改变了观测、接触与系统状态。

64 步联合建模的名义跨度是 3.2 秒，本轮只写前 6 项的名义跨度是 0.3 秒；后 58 项不进入本轮六次循环。这是预测容器与采用前缀的区别，不是 58 项无意义，也不是 64 项都将开环执行。

非抓取变体使用 1029 条专门演示、32 种物体、双 ViT-B/14、horizon 100 与 200 epochs。其训练分支与抓取主模型不同，非抓取结果不证明原抓取权重能零样本获得新技能；相关结果数字属于 Experiments，而不是本页的机制证据。

九、异步快照、动作范围与运行失效

图像线程持续覆盖共享状态，公开实现没有统一锁、frame ID 或单调时间戳；RGB、mask 与关节状态可能来自不同时刻。原子时间戳快照是裁决需求，不是当前保证。Cutie 漂移后，同次尝试不重新由 SAM 播种；漂移、目标串换或异步错位都可能污染策略条件。

反归一化后的臂动作在 scale 前没有先 clip 到 [-1,1]。越界生成值可能映射到配置关节限位之外；硬件驱动是否二次限幅没有公开，不能假定。finite、range 与 joint-limit guard 是建议，不是当前实现。系统也没有触觉输入，功能性抓取质量和后续操作不在本页保证范围。

VLM 误判和缺少全局 deadline 还可能错误推进或无限推进 planner 循环；快速覆盖可能让六个中间目标未被消费。公开代码不足以把这些风险量化为发生率，状态均为 NOT_RUN。

安全检查的顺序应当是：先验证输入有限性，再验证归一化范围，再完成反归一化，最后核对每个关节的配置限位与硬件合同。任一步失败都应停止目标发布，而不是依赖下游驱动“也许会限幅”。这套顺序是页面提出的 fail-closed 验收要求，并非声称公开实现已经具备对应 guard。对快照一致性同理：只有 RGB、mask、state 共享同一 frame/时间身份后，策略输出才能归因于一个确定观测。

十一、验证矩阵、可说边界与媒体证据

若要裁决闭环、跟踪、随机性和历史机制，需要另行执行四类消融；时序记录应给图像、mask、策略输出和低层目标加单调时间戳，消费确认要记录六个目标实际消费数；失败状态数据集要区分滑落、推移、遮挡和手型错误。当前全部为 NOT_RUN，本页不补造数值。

允许说“论文展示闭环重抓”，不允许说“模型具有人类式失败理解”；允许说“低层策略单帧”，不允许说“完整系统完全无记忆”；允许说“公开循环遍历前 6 项”，不允许说“严格 20 Hz 完整执行”；允许说“每轮三类观测函数各调用 7 次”，不允许写成 23 Hz 或失败分布已覆盖。

四个视频均来自 dexgraspvla.github.io，保留 controls、muted、loop、playsinline 与 preload="metadata"，不下载、不重编码。它们是定性展示，不是时钟、延迟、成功率、消费确认或因果测量。

验证矩阵应从“首个可观察分歧”出发，而不是只比较最终成功率：闭环消融比较重复观测与固定长块，跟踪消融比较身份保持和重新播种，随机性消融固定或改变初噪声，历史消融分别关闭 Cutie、planner 与计数状态。每项仍需相同任务、checkpoint、normalizer、processor、线程记录和硬件安全条件；本页没有执行这些对照，也不预设结果方向。
