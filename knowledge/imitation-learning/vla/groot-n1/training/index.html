一、本页在专题中的位置

本页回答「GR00T N1 怎么训练」：论文提出的损失如何组合，公开实现实际计算什么，哪些模块更新或冻结，主要优化参数如何设置，以及预训练、后训练与单卡微调有什么差别。

流匹配损失本身的推导不在本页，见 ② Flow Matching、损失与时间方向；训练用的数据从哪来不在本页，见 ③ 数据金字塔、动作标签与合成数据。

本页严格区分三类证据：

标记 含义 能回答什么
论文 GR00T N1 v2 正文与附录 作者报告的训练目标、主要超参数和实验设置
公开实现 Isaac-GR00T 的 n1-release 固定版本 开源微调代码实际执行的损失、冻结和优化逻辑
机制分析 根据公式与代码作出的解释 帮助理解设计取舍，但不能冒充消融结论

论文只公开了“重要超参数”，没有给出全部数据混合权重、检测分支实现和大规模预训练代码。因此，本页不会把公开微调脚本等同于完整的千卡预训练系统。

二、论文目标与公开实现不是同一件事

论文正文主要介绍流匹配，附录 F 又给出一个辅助目标检测损失。论文所述总目标是：

\[\mathcal L=\mathcal L_{fm}+\mathcal L_{det}.\]

这里两个显式系数都是 1，但不能据此称两项“贡献相等”：它们的数值尺度、归约方式和梯度范数都没有公开。n1-release 的公开动作头只实现了 (\mathcal L_{fm})，没有实现 (\mathcal L_{det})。因此应把“论文训练目标”和“公开微调代码可复现的目标”分开阅读。

2.1 公开实现中的流匹配目标

设动作块为 (A)、高斯噪声为 (\epsilon)、流时刻为 (\tau)，公开代码构造：

\[A_\tau=\tau A+(1-\tau)\epsilon, \qquad v^\star=A-\epsilon, \qquad k=\operatorname{trunc}(1000\tau).\]

对固定的 ((A,\epsilon))，(v^\star) 正好是直线路径 (A_\tau) 对 (\tau) 的导数。带动作掩码的代码目标可写成：

\[\mathcal L_{fm}^{\mathrm{code}} = \frac{ \sum_{b,h,d}M_{bhd} \left[V_\theta(\phi,q,A_\tau,k)_{bhd}-(A-\epsilon)_{bhd}\right]^2 }{ \sum_{b,h,d}M_{bhd} }.\]

其中连续 (\tau) 用于构造插值点，离散 (k) 才是公开网络实际收到的时间条件；把二者都写成 (\tau) 会掩盖源码中的时间离散化。

论文与源码存在符号冲突。 论文 Equation 1 把目标印成 (\epsilon-A)，但相同插值路径的正向导数是 (A-\epsilon)；论文后面的 Euler 更新又使用正号。公开源码采用 (A-\epsilon)，与“从 (\tau=0) 的噪声端走向 (\tau=1) 的数据端”自洽。复现时应遵循源码，并把论文中的反号视为公式不一致，而不是另一套可直接混用的约定。完整推导见 ② Flow Matching、损失与时间方向。

2.2 辅助目标检测损失

论文附录 F 描述了四步：

  1. 对轨迹片段中的每一帧，用 OWL-v2 为语言指令涉及的目标物体生成边界框标注。
  2. 取边界框中心并除以图像宽、高，得到 (c_{gt}=(c_x,c_y))。
  3. 在最终视觉语言 token 之上增加线性预测头，输出 (\hat c=(\hat c_x,\hat c_y))。
  4. 使用平方欧氏距离：
\[\mathcal L_{det} =\|\hat c-c_{gt}\|_2^2 =(\hat c_x-c_x)^2+(\hat c_y-c_y)^2.\]

设计目的很清楚：动作损失只间接约束视觉表示，而检测目标直接要求表示保留“指令所指物体在哪里”的信息。这可能改善语言—物体—空间位置的对齐，但论文没有去掉 (\mathcal L_{det}) 的消融，因此不能断言它一定阻断捷径或带来多少性能提升。

附录没有说明如何从整段 token 聚合出二维坐标、多帧和多视角如何归约、同类多目标如何选择、OWL-v2 漏检时如何处理，也没有公开检测头代码。因此，公式说明了监督意图，却不足以完整复现该分支。

2.3 两项损失的梯度边界

损失 直接监督 可能更新的共享模块 对动作策略的影响
(\mathcal L_{fm}) 动作速度场 DiT、按本体编解码器、位置嵌入、backbone 输出投影，以及解冻的视觉模块 直接
(\mathcal L_{det}) 检测头输出的二维中心 检测头及未被 detach 的可训练视觉语言上游 不直接监督 DiT，但改变共享条件特征后可间接影响动作

“语言模型参数冻结”只表示这些参数不更新，并不自动等于梯度不能经过其运算传到更早的可训练视觉模块。由于检测分支未开源，本页只给出标准计算图下的边界，不把具体 detach 位置当作已知事实。

三、损失在代码里的确切形式

flow_matching_action_head.py 的 forward 只计算流匹配一项：

action_mask = action_input.action_mask
loss = F.mse_loss(pred_actions, velocity, reduction="none") * action_mask
loss = loss.sum() / action_mask.sum()

这三行表达的是“对全部有效动作标量求均值”，而不是“对 batch 中每个样本等权求均值”：

补位不计入损失公开配置把动作统一填充到最多 32 维。掩码使不存在的动作维度既不进入分子，也不进入分母；否则模型会把容量浪费在无机器人语义的“噪声到零填充值”流上。
每个有效坐标等权分母是 action_mask.sum()。这消除了补位造成的稀释，但不保证每个样本或本体等权：自由度较高的样本仍包含更多有效标量。若需要本体均衡，还要在样本或采样器层面显式重加权。

掩码只乘在最终误差上，不会从前向计算中删除补位维度：32 维加噪动作仍完整进入 action_encoder。第一层动作投影又是从完整 32 维到隐藏维的稠密映射，因此补齐位置的噪声可能混入共享隐藏表示并间接影响有效维预测。掩码解决的是“哪些输出误差直接参与监督”，不是从输入计算图中隔离无效维。

该实现默认训练样本至少有一个有效动作标量；若整个 batch 的 action_mask.sum() 为零，分母将为零。数据管线必须在进入动作头前为人类视频或神经轨迹补上潜在动作/伪动作，不能把完全无动作的样本直接送入这个损失。

发布配置保留了 load_pretrained_det_decode_layer_path 与 load_pretrained_det_eagle_path 两个检测相关字段，默认均为 null。其中公开 backbone 只实现了后者的权重加载；仅凭字段名无法推出检测头结构或内部训练代码。因此，论文的检测目标目前只能在论文层面核验。

四、什么在训、什么冻着

4.1 四个开关

公开微调入口暴露四个布尔开关，但它们并没有覆盖所有可训练参数：

开关 脚本默认 n1-release 中实际控制的模块
tune_llm false Eagle-2 的 language_model
tune_visual true Eagle-2 的 vision_model 与多模态投影 mlp1
tune_projector true 动作头的状态编码器、动作编码器、动作解码器和位置嵌入
tune_diffusion_model true 动作头 DiT

发布配置还令 projector_dim=2048，因此 EagleBackbone.linear 是一个实际的 (2048\to1536) 输出投影。该层不受以上四个开关控制，默认保持可训练；原页面把它漏出了更新清单。

论文正文明确说预训练和后训练都冻结 VL backbone 的语言组件、微调其余部分。Table 6 却写成 “text tokenizer frozen”；tokenizer 是文本预处理器，通常没有待优化的神经网络参数。结合正文和源码，这里应理解为冻结语言模型，而不是把 tokenizer 当成可训练模块。

公开实现的开关有一个不对称边界。 动作头每次设置前会先把自身参数恢复为可训练，因此两个动作头开关可以双向切换；EagleBackbone.set_trainable_parameters 只在开关为 false 时执行冻结，却没有在开关为 true 时重新设置 requires_grad=True。发布 checkpoint 的配置已用 tune_llm=false 构造语言模型，因此仅在命令行改成 --tune-llm true 不能可靠地重新解冻它。若确需训练语言模型，应显式检查并恢复参数的 requires_grad 状态，而不能只相信打印出的开关值。

4.2 一个容易被忽略的配套处理

backbone 与动作头都在 forward 开头调用 set_frozen_modules_to_eval_mode。这是因为 requires_grad=False 只阻止参数更新，不会自动改变模块的训练/评估行为。

"""
Huggingface will call model.train() at each training_step. To ensure
the expected behaviors for modules like dropout, batchnorm, etc., we
need to call model.eval() for the frozen modules.
"""

eval() 会关闭冻结模块中的 dropout、stochastic depth，并阻止 BatchNorm 一类模块继续更新运行统计量；LayerNorm/RMSNorm 本身没有这类运行统计量。发布配置中 DiT 的 dropout 为 0.2，但默认 tune_diffusion_model=true，所以 DiT 仍处于训练模式并保留 dropout。只有显式冻结 DiT 时，这个方法才会把其 dropout 关闭。

4.3 为什么语言侧要冻着

论文没有给出冻结语言组件的消融或原因。一个合理但未经验证的解释是：机器人指令规模较小且措辞较模板化，冻结语言模型可降低覆盖预训练语言能力的风险；视觉域却与互联网图像存在机器人视角、夹爪和工作台等差异，因此允许视觉侧适配。相应代价是语言组件无法针对机器人语料更新。这里是机制分析，不是论文已经证明的因果结论。

lr_scheduler_type cosine 一致
bf16 true 论文未提
gradient_accumulation_steps 1 论文未提
batch_size 16 每设备 batch，不是论文全局 batch
max_steps 10,000 公共脚本默认值，低于论文后训练区间

脚本中的有效全局 batch 为：

\[B_{\mathrm{global}} =B_{\mathrm{per\ device}} \times N_{\mathrm{GPU}} \times N_{\mathrm{grad\ accumulation}}.\]

脚本默认 batch_size=16、gradient_accumulation_steps=1；只有单 GPU 运行时全局 batch 才是 16。论文的 16,384 是预训练全局 batch，不能直接和脚本的每设备值比较。论文另称训练系统单模型最多使用 1024 张 GPU，但没有说明 GR00T-N1-2B 的 200k 步始终使用 1024 张卡。

n1-release 公开入口使用单一本体数据集，默认 lora_rank=0，且不包含论文的检测损失与多源预训练数据管线。启用 LoRA 后，PEFT 会重新决定可训练参数集合；此时不能只根据四个 tune_* 开关判断哪些参数进入优化器，应检查包装后的 named_parameters()。

5.3 各超参数能确定到什么程度

项 可以确定的语义 证据边界
(\beta_1=0.95) (m_t=0.95m_{t-1}+0.05g_t)；相比 0.9，历史记忆更长、更新方向更平滑，对新梯度变化响应更慢 论文没有与 0.9 对比，不能声称谁收敛更快
(\beta_2=0.999) 对平方梯度作长时间尺度的指数平均；减小它会提高对近期尺度变化的响应，同时也可能增大估计波动 没有 N1 专属消融
权重衰减 1e-5 AdamW 对衰减组使用较弱的解耦权重衰减 不能从该数值推出“主要正则来自 dropout 或数据多样性”
warmup 0.05 公开脚本在前 5% 更新中逐步升高学习率 论文没有报告去掉 warmup 是否发散
cosine 调度 warmup 后按 cosine 逐步降低学习率 与“最后 5 个 checkpoint 取最大分数”的评测规则是两件事，不能建立未验证的因果
预训练 batch 16,384 论文报告的全局 batch 未公开跨数据源、跨本体在 batch 内的抽样比例，也没有 batch 消融
后训练 batch 128 / 1024 论文明确说明后训练在数据受限时使用更小 batch 以降低过拟合风险 不能进一步断言 16,384 必然“迅速过拟合”

5.4 参数分组：两组，区别只在权重衰减

公开 gr00t/experiment/trainer.py 覆写了 create_optimizer：

decay_parameters = get_parameter_names(opt_model, ALL_LAYERNORM_LAYERS)
decay_parameters = [name for name in decay_parameters if "bias" not in name]
optimizer_grouped_parameters = [
    {"params": [... if (n in decay_parameters and p.requires_grad)],
     "weight_decay": self.args.weight_decay},
    {"params": [... if (n not in decay_parameters and p.requires_grad)],
     "weight_decay": 0.0},
]

get_parameter_names(..., ALL_LAYERNORM_LAYERS) 排除被 Transformers 识别为 LayerNorm 类的层，再排除名称含 bias 的参数。因此公开微调实现将参数分为“应用权重衰减”和“不应用权重衰减”两组；两组继承同一个全局学习率，没有显式分层学习率。

分组时都带 p.requires_grad 过滤，所以被冻结参数不会进入优化器，也不保存 Adam 的一阶矩和二阶矩。这里能确认的是公开微调 Trainer 的默认非 SageMaker 路径：启用 SageMaker Model Parallel 时函数直接调用父类实现；调用方若预先传入优化器，也不会重新建立这两组。论文没有公开千卡预训练所用的完整参数分组代码，不能把“无分层学习率”扩大为内部预训练的已证事实。

六、一步训练里发生了什么

把公开 forward 的动作分支串成一条完整链路，并用虚线标出论文描述但未开源的检测分支：

flowchart TB
  D["采一批轨迹片段"] --> V["图像与指令 → Eagle-2 → 视觉语言 token φ"]
  D --> Q["状态 q → state_encoder（按本体）"]
  D --> A["真值动作块 A"]
  A --> N["采噪声 ε；u~Beta(1.5,1)，τ=(0.999−u)/0.999"]
  N --> NA["构造加噪动作 Aτ = τA + (1−τ)ε"]
  N --> VEL["构造回归目标 A − ε"]
  NA --> AE["action_encoder（按本体，含整数时刻 k）"]
  Q --> CAT["拼接：state 1 个 token + action 16 个 token"]
  AE --> CAT
  CAT --> DIT["DiT 16 块：偶数交叉读 φ，奇数自注意力，adaLN 用整数时刻 k 调制"]
  V --> DIT
  DIT --> DEC["action_decoder（按本体）→ 取末 16 个 token"]
  DEC --> LFM["Lfm：按 action_mask 加权并除以有效标量数"]
  VEL --> LFM
  D -. "论文：OWL-v2 目标中心伪标注" .-> DETGT["归一化中心 c_gt"]
  V -. "论文检测头，n1-release 未公开" .-> DETP["预测中心 ĉ"]
  DETGT -.-> LDET["Ldet：二维平方距离"]
  DETP -.-> LDET
  LFM --> BP["反向传播；公开代码只有 Lfm"]
  LDET -. "论文总目标中以系数 1 相加" .-> BP
  BP --> OPT["AdamW 两组参数，cosine 调度，warmup 0.05"]
  OPT --> UPD["默认更新：视觉塔、mlp1、backbone.linear、DiT、三个按本体模块与位置嵌入；LLM 参数冻结"]
实线是公开代码可以逐行核对的路径，虚线只表达论文附录 F 的最小描述。检测头接在哪个具体 token、是否经过 backbone.linear、怎样对多帧归约，公开资料均不足以确认。

七、预训练与后训练的差别

7.1 差在哪

维度 预训练 后训练
数据 跨本体混合真实机器人、人类视频、仿真与神经轨迹 单一本体的下游任务数据，可加入神经轨迹
动作监督 机器人数据可用真值动作与潜在动作；人类视频用潜在动作；神经轨迹用潜在动作或 IDM 伪动作 原始有动作轨迹的动作标签；加入神经轨迹时使用潜在动作或 IDM 伪标签
批量 16,384 128 或 1024
步数 200,000 20,000 – 60,000
冻结策略 语言侧冻结 同样冻结
目标 从异构数据中学习可迁移的视觉—语言—动作表示 适配单一本体及其下游任务分布

不同动作表示不能被理解为直接混合在同一个数值空间中：模型通过 embodiment_id 选择对应的状态/动作接口，再由共享 DiT 学习跨本体结构。论文对后训练的表述是：在对应单一本体的数据集上微调预训练模型，并与预训练一样冻结 VL backbone 的语言组件、微调其余部分。

7.2 与神经轨迹共训的采样比

论文明确给出：在“使用神经轨迹的后训练”中，把原始有动作轨迹与神经生成轨迹按 1:1 的采样比共同训练。

1:1 描述的是抽样比例，不表示两个数据集样本总数相等，也不表示每条轨迹被看到相同次数。实机低数据实验只使用完整远操作数据的 10%；仿真实验则使用每任务 30、100 或 300 条演示，不能把“10% 真机数据”概括为所有 1:1 实验的背景。论文没有比较其他混合比例，因此迁移时应把伪标签质量、原始数据量和生成数据分布偏移作为待验证变量。

7.3 后训练的默认配置

论文第 4.3 节给的实验配置是：默认全局批量 1024、训练 60k 步；只有 DexMimicGen 跨本体套件因为每个本体任务少、数据总量小，把 GR00T-N1-2B 的批量降到 128。

后训练不总是带来提升。 论文第 4.5 节记录了一个预训练 checkpoint 能完成而后训练 checkpoint 反而失败的例子。这属于反常现象，机制分析放在 ⑥ 反常现象、证据边界与可能机制，本页只提示后训练配方本身带有这种风险。

项 取值

8.2 单卡微调的可行配置

论文同时给出了在单张 A6000 上的实测口径：

微调范围 可用批量上限
只调 adapter（状态与动作编码器、动作解码器）与 DiT 200
同时调视觉编码器 16

冻结参数可以省去参数梯度和 Adam 的一阶、二阶状态；是否还能省去某个冻结模块的全部反向激活，要看它之前是否仍有可训练模块。默认 tune_visual=true 时，损失需要经过固定语言模型回传到视觉侧，因此“LLM 冻结”不等于整段语言计算都无需反向。若视觉塔也冻结，SigLIP 的 27 层不再需要参数梯度；在标准自动微分中，这通常是 batch 上限提高的重要来源之一，但论文没有给出显存分项，不能把 200/16 的全部差异归因于单一模块。

显存优先时可以考虑冻结视觉塔与 mlp1，但这会放弃视觉域适配。论文只报告了 A6000 上的 batch 上限，没有给两种微调范围的成功率对照；实际可用 batch 还受视角数、序列长度、精度、LoRA、梯度累积和软件版本影响，不能把 200/16 当作所有任务的固定保证。

论文把第一种范围概括为“adapter 与 DiT”。若在公开 n1-release 中仅通过 tune_visual=false 实现，backbone.linear 仍然可训练；论文的模块分类与公开开关不能机械地画等号。

九、重点、贡献与结论速查

9.1 哪些才是本页应强调的设计

内容 定位 不应夸大的地方
跨本体共享 DiT + 按本体状态/动作接口 GR00T N1 统一训练异构机器人的核心结构 不代表不同机器人的动作数值可以直接混合
流匹配动作学习 + 有效维度掩码 支持连续、多峰动作并适配不同动作维度 掩码是工程实现，不保证本体级等权
语言冻结、视觉与动作侧适配 论文采用的关键训练配方 不是新优化算法，也没有冻结策略消融
辅助目标中心预测 论文采用的空间定位监督 分支未开源，实际增益无消融
预训练后再做单本体后训练 把跨本体表示迁移到下游任务 后训练可能遗忘预训练行为，并非总是提升
AdamW、cosine、warmup、bias/被识别的 LayerNorm 不衰减 常规优化与公开微调实现细节 不属于 GR00T N1 的核心创新

GR00T N1 的训练贡献主要在于把跨本体异构数据、按本体接口、共享流匹配策略、分模块冻结和大规模训练组织成统一配方，而不是提出新的 AdamW 或学习率调度器。
