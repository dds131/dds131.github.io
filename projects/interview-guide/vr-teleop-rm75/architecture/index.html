面试深挖 · 系统架构与实时控制链

用面试问答方式解释 VR 遥操作系统的多进程架构、频率预算、启动命令和参数作用

这页回答面试中的架构问题：为什么控制、夹爪、采集和界面不能放进一个 Python 进程，以及 110 Hz、50 Hz、30 Hz 三种节拍怎样协同而不互相阻塞。

110 HzCAN-FD 控制与目标下发
9.09 ms110 Hz 理论周期
50 Hz关节后台轮询与夹爪回读
30 Hz三相机 episode 时间轴
128 B控制到采集的定长状态包

一句话回答

系统把“必须连续发送的控制热路径”和“允许异步完成的 IK、相机编码、HDF5 写盘”拆开：110 Hz 主循环只消费最新有效结果并负责唯一的真机下发；50 Hz 后台线程维护真实状态缓存；30 Hz 记录器只订阅状态和选帧，不反向调用机械臂或 VR SDK。

一、四个进程分别负责什么

进程 输入与输出 频率 / 关键约束 为什么隔离
VR 控制进程 VR 位姿 → PyRoki → 安全关节命令 → CAN-FD 主循环 110 Hz 唯一真机发送者，不能被编码或写盘阻塞
夹爪命令进程 UDP 三档命令 → ROS 2 夹爪动作 独立 ROS 2 环境 ROS 2 链与 JAX/PyRoki 的 NumPy 版本不同
夹爪状态进程 /joint_states → 连续实测开口 50 Hz 记录真实开口；失联不能用期望值冒充
采集进程 128 B 状态包 + 三路图像 → HDF5/MP4 30 Hz 视频编码和磁盘写入不进入控制热路径

二、不同频率怎样衔接

信号 生产节拍 消费方式 语义
VR 手柄位姿 到达率不固定 110 Hz 读取最近有效样本 新样本未到时零阶保持，不凭空生成手柄运动
PyRoki 关节解 异步、非固定频率 主循环取最新且未过期的结果 超过 0.1 s 的陈旧解拒绝使用
关节与夹爪实测状态 50 Hz 加时间戳缓存，控制和记录端只读缓存 速度必须按真实测量时间差计算
相机图像 3 路 30 fps 每路进入 15 帧环形缓冲 记录时按状态测量时刻选最近帧
episode 行 30 Hz 从 110 Hz 状态流抽样 30 Hz 是记录时间轴，不参与真机控制

VR 遥操作没有做 30 Hz → 110 Hz 线性插值

VR 链路在 110 Hz 主循环中读取最近有效手柄样本；两次新样本之间保持最近值，再依次经过输入低通、异步 IK、关节 EMA 和安全约束。因此这里的“升频”是最新样本保持 + 最新有效 IK 结果缓存，不是在两个未来已知路点之间做线性插值。

恢复运行中的 VLA 动作块具备完整的未来路点，才会使用墙钟线性插值。两种机制的前提不同，详见数据与恢复执行页。

四、四终端启动命令

# 终端 1：夹爪 UDP 命令转 ROS 2
cd "$D/vr_teleop_rm75_gripper"
bash run_gripper_daemon.sh

# 终端 2：50 Hz 回传夹爪真实开口
cd "$D/data_collection"
bash run_gripper_state_pub.sh

# 终端 3：VR、PyRoki、安全链、110 Hz CAN-FD 与状态广播
cd "$D/data_collection"
"$PY" teleop_pub.py --tcp-len 0.195 \
  --source vr --backend canfd --port 8766 --rate 110 --follow \
  --safety pyroki --scale 1.5 --traj-mode 2 --radio 500 \
  --ema 0.25 --input-lp 0.3 \
  --max-accel 1000 --homing-accel 400 --homing-speed 25 \
  --no-viz --no-log

# 终端 4：30 Hz HDF5 与三路 MP4
cd "$D/data_collection"
"$PY" record_collector.py --dataset-name pick_cube --max-steps 3000 \
  --head-dev "$HEAD_DEV" --arm-dev "$ARM_DEV" --third-dev "$THIRD_DEV" \
  --preview-port 9001

五、控制命令参数怎样解释

参数 当前值 作用与取舍
--tcp-len 0.195 m 将法兰到夹爪尖端偏置纳入正逆运动学
--backend canfd 真机高跟随输出；首次验证可用 dryrun，只计算不驱动真机
--rate 110 Hz 主循环和发送时钟；不是 PyRoki 求解完成频率
--scale 1.5 手移动 10 cm 对应末端目标 15 cm；越大越灵敏，也越易限速或拒解
--traj-mode 2 控制器滤波模式；0 透传、1 曲线拟合、2 滤波
--radio 500 模式 2 的滤波强度，范围 0–999；更大更平滑但滞后更明显
--input-lp 0.3 IK 前一阶低通的当前输入权重
--ema 0.25 IK 后关节目标 EMA 的当前目标权重
--max-accel 1000 °/s² 正常遥操作的关节加速度上限
--homing-speed 25 °/s 回位速度上限，与正常遥操作限速独立
--homing-accel 400 °/s² 回位加速度上限
--no-viz 开启 关闭逐帧渲染，把预算留给实时控制
--no-log 开启 关闭高列数逐帧日志；诊断断流时单独启用 --send-gap-csv

六、面试追问

为什么不把 IK 也固定成 110 Hz？ 因为 110 Hz 是发送约束，不是求解器完成频率。将求解和发送解耦后，主循环不会因一次慢解停止发送，同时通过时间戳和 0.1 s 新鲜度门控阻止旧解重新进入控制链。

为什么记录器崩溃不影响真机？ 因为记录器没有机械臂连接权，只消费控制进程广播的状态。退出或重启采集进程不会改变唯一发送者。

证据边界：上表是三次历史真机运行的发送间隔统计，不代表所有运行；最大值包含暂停或模式切换。稳定运行期 PyRoki 完成频率与结果年龄分布当前没有完整统计，本页不补写。
