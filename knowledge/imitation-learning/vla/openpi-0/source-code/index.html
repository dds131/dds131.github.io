配置装配锚点

配置装配与模型构建链

TrainConfig.model持有Pi0Config，Pi0Config.create()构建模型；ModelTransformFactory读取model_type/max_token_len/action_dim/discrete_state_input装配数据表示。Pi0Config同时改变参数shape与数据变换，任何改动都必须两侧一起审计。

权重布局只路由后端，不识别模型家族
条件 固定行为 不能推出
根目录有model.safetensors 优先选择PyTorch。 这一定是π0而非其他family。
否则读取params/ 尝试JAX/Orbax恢复。 所有shape都兼容。
两者同时存在 PyTorch优先。 优先级代表推荐后端。
两者都缺 后续加载失败。 自动下载或修复。
docstring写model.safensors 不作合同；实际检查名为准。 拼写别名被支持。

family仍由train_config.model、配置类、model_type与pi05判定，并用checkpoint shape/loader交叉验证。通用load_pytorch()构造PI0Pytorch，不能据此虚构π0-FAST可用PyTorch后端；norm stats默认从同一checkpoint的assets/<asset_id>读取。

训练调用链锚点

训练调用链

  1. train入口解析named TrainConfig。
  2. 数据支路依次经过data loader → repack → platform data transforms → Normalize → model transforms → batch。
  3. 初始化支路由config进入init_train_state、optimizer与weight loader。
  4. 两支在train_step汇合，进入compute_loss → preprocess(train=True) → prefix/suffix → Flow loss。
  5. 外层完成gradient/update/EMA，再写checkpoint。

补零发生在model_transforms数据侧；模型内部preprocess仍负责shape、mask与训练增强。optimizer、EMA、log属于外层训练脚本，noise、time、velocity与loss属于compute_loss。数学责任分别回到Flow与Training页面，本页不复制公式。

推理调用链锚点

推理/Policy调用链与计时边界

  1. robot client调用websocket policy server。
  2. 服务进入Policy.infer并执行input transforms。
  3. 形成batch，按配置路由backend。
  4. Observation.from_dict建立模型输入。
  5. sample_actions生成动作块。
  6. 结果回host并unbatch。
  7. output transforms依次完成模型逆变换、反归一化、平台输出语义与真实维裁剪。
  8. 动作返回robot；本页不提供服务或真机接口命令。

Policy.infer允许传入可选noise；二维noise会补batch维。固定noise可作为复现审计工具，但本站没有运行。训练与推理复用核心transform定义，但repack、训练增强与输出逆变换使两条路径不逐项完全相同。

infer_ms只包围sample_actions，不含input/output transforms、host/device搬运与网络。JAX计时前没有block_until_ready()，可能只计入异步派发；PyTorch循环中的设备标量可能隐式同步。代码本身不能确定偏差方向，正式benchmark需各后端分别预热与同步，本站保持NOT_RUN。

函数合同锚点

Pi0函数I/O与JAX/PyTorch差异

固定JAX接口与PyTorch归约边界
symbol 输入 输出/责任 边界
embed_prefix 图像、语言及mask。 VLM tokens、input mask、ar mask。 不直接生成动作。
embed_suffix state、含噪action、time。 action-expert tokens与masks。 π0/π0.5分支不同。
compute_loss RNG、observation、actions [B,H,D]。 JAX在D维均值，返回[B,H]。 补零维没有loss mask。
sample_actions RNG、observation、N、可选noise。 [B,H,D]。 时间循环回到Time页。
PyTorch forward(reduction="none") batch tensors。 [B,H,D]逐元素loss。 外层再归约，不与JAX同shape。

联合序列只在位置、mask与投影后的Q/K/V语义上联合，不是不同width hidden state直接拼接。QKV/cache/shape回到Architecture，Flow loss回到Flow Matching，time/Euler回到Time Convention。补零动作维在固定提交中仍有噪声与训练目标，不能写成被loss排除。

模型家族判别锚点

π0/π0.5与π0-FAST判别

π0与π0.5共用Pi0Config/Pi0类，以pi05切换；π0-FAST使用独立Pi0FASTConfig、pi0_fast.py与gemma_fast.py。同仓库不等于同实现，配置名含pi0也不是family证据。

先看配置类，再看model_type/pi05并用shape交叉验证
家族 权威判据 状态与动作表示
π0 Pi0Config、pi05=False、model_type=PI0。 连续state token在suffix；连续Flow动作块。
π0.5 Pi0Config、pi05=True、model_type=PI05。 通常离散state进prompt；时间经adaRMSNorm；连续Flow动作块。
π0-FAST Pi0FASTConfig与独立实现。 离散动作token，自回归解码。

判别四步是：先看config类；若为Pi0Config再看model_type/pi05；用checkpoint shape/loader交叉验证；不要用名称或action_dim分类。action_dim也不能识别机器人真实自由度。

固定pi05_libero同时设置pi05=True, discrete_state_input=False：tokenizer不接state，suffix也跳过π0 state_proj；除外围shape用途外，state不作为模型条件。它不会自动回退π0连续state通路，且该结论只绑定此命名配置与commit。

数据管线锚点

数据变换、checkpoint与部署资产

四段外部变换后，模型内部仍会preprocess
顺序 字段 责任
1 repack_transforms 数据集键重排。
2 data_transforms 平台动作语义。
3 Normalize 读取norm_stats。
4 model_transforms 缩放、分词、补零；FAST则token化。
模型内部 preprocess_observation resize、mask与训练增强类别。

默认π0/π0.5要求base_0_rgb/left_wrist_0_rgb/right_wrist_0_rgb三键存在；缺视角由adapter创建零图并设置mask false。Observation.from_dict要求image_mask字典存在，只有字典内缺少某个已有图像键的mask时才默认true。FAST按实际图像键列表，不能套用固定三键。JAX/PyTorch preprocess覆盖相同类别，但随机数与算子不同，不保证逐像素等价。

shape正确不等于平台语义正确
资产组 必须静态核对
配置/数据 唯一config名、dataset键repack、相机与mask。
控制语义 state/action order、frame、unit、绝对/增量。
模型shape action_dim、horizon、family、variant、checkpoint shape。
统计/后端 normalizer asset_id/stats、weight layout与backend。
输出 output inverse transforms与真实动作维裁剪。
