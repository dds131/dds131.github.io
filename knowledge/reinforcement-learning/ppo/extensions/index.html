PPO 不是一条单线算法，而是一个研究分岔点。原论文自身包含 Clip 与自适应 KL Penalty 两类目标；后续工作又分别处理近端性、表示冲突、部分可观测、多智能体、稀疏奖励、非法动作、分布式吞吐和复杂策略分布。RLHF 则是把 PPO 风格更新迁移到 Token 序列的相邻应用。选择路线时应从可复现的失败模式出发，而不是把“更新的缩写”视为自动升级。

近端性Clip 是否真的控制策略偏移
表示策略与价值是否互相干扰
信息记忆、多智能体与动作约束
规模探索、异步与偏好学习

选择规则： 先用诊断证据确认瓶颈，再选择只改变必要机制的扩展，并与调优后的基础 PPO 在相同环境步数、梯度步、模型容量、算力和评估协议下比较。

阅读边界： 本页是“问题—机制—代价—证据”地图，不是方法排行榜。论文在特定任务上优于其基线，不等于在新的任务、预算或实现上必然优于 PPO。

1. 研究地图总览

flowchart TB

  PPO --> SCALE{"吞吐/异步?"}
  PPO --> PREF{"偏好优化?"}
  PPO --> GEN{"复杂生成式动作?"}
  PROX --> PEN["PPO-Penalty / KL 控制"]
  PROX --> TPPO["Truly PPO / Rollback"]
  REP --> PPG["PPG 辅助阶段"]
  INFO --> RPPO["Recurrent PPO"]
  INFO --> MAPPO["MAPPO"]

  EXP --> RND["PPO + RND"]

这些路线可以组合，但每增加一个机制都会扩大实现和归因难度。先做正交消融，再做组合实验。

2. PPO-Penalty：先区分原论文内部方法族

PPO 原论文同时讨论了裁剪目标和自适应 KL 惩罚目标。后者可写为

\[L^{\mathrm{KLPEN}}(\theta) =\mathbb E_t\!\left[r_t(\theta)\hat A_t -\beta\,D_{\mathrm{KL}}\!\left(\pi_{\theta_{old}}(\cdot\mid s_t)\,\|\,\pi_\theta(\cdot\mid s_t)\right)\right].\]

更新后再把实测平均 KL 与目标 $d_{targ}$ 比较：KL 明显过大时增大 $\beta$，明显过小时减小 $\beta$。因此它提供的是软惩罚和反馈调节，不是逐样本 ratio 硬约束，也不是严格的信任域求解。

改了什么

主要改变策略目标及 beta 的更新状态；Rollout、GAE 和 Critic 可与同一 PPO 基线保持一致。

第一个消融

在相同数据、网络和优化预算下比较 Clip、固定 KL Penalty、自适应 KL Penalty；同时报告回报、真实 KL、beta 轨迹和早停次数。

原论文在其报告的实验中最终更偏好 Clip 变体；这不是“Penalty 普遍较差”的证明。若基础问题只是单次更新过强，还应先比较降低学习率、减少 Epoch、KL 早停或自适应学习率。

不同项目里的 “PPO1 / PPO2” 命名并不统一。讨论算法时应写清 Clip、KL Penalty、早停或学习率控制的实际机制，不能仅靠版本号推断目标函数。

3. Truly PPO 与 TR-PPO-RB：更直接地处理“并不真的近端”

PPO-Clip 只改变代理目标，ratio 仍可能越界，策略 KL 也可能过大。Truly Proximal Policy Optimization 分析了裁剪目标的局限，并提出 Trust Region-based PPO with Rollback（TR-PPO-RB）：用信任域条件触发裁剪，并在偏移过大时引入回滚方向，使策略偏移过大时不仅停止奖励，还提供拉回方向。

这里的“信任域条件”和“回滚压力”是该论文目标的结构，不应被改写成任意深度网络训练都获得单调改进保证。理论结论依赖论文给出的假设、距离定义与优化条件；有限样本、近似 KL 和不完全优化都可能使实际运行偏离条件。

维度 PPO-Clip Truly PPO 路线
判断依据 样本动作 ratio 与优势符号 更直接利用策略分布 KL/回滚条件
超界处理 过度改善侧进入平台 偏移过大时可产生回滚压力
代价 简单、主流库广泛支持 需额外 KL 计算与超参数，复现生态较小

适合的证据：PPO-Clip 在相同批次中反复出现 KL 失控、ratio 长尾，而简单降低学习率或更新次数又损害学习效率。第一个消融应固定 Rollout 和优化预算，比较 PPO-Clip、只换 trust-region trigger、再加入 rollback，并与“PPO-Clip + KL 早停/自适应学习率”公平比较。

4. PPG：把策略阶段与辅助表示学习拆开

Phasic Policy Gradient 将训练分为策略阶段和周期性辅助阶段。原论文的策略阶段使用 PPO，并让策略网络与主价值网络分离；辅助阶段再用策略网络上的辅助价值头学习表示，同时约束策略不要偏离辅助阶段开始前的快照。

辅助阶段最小化的联合损失可概括为

\[L^{joint}=L^{aux}+\beta_{clone}\,\mathbb E_s\!\left[D_{\mathrm{KL}}\!\left(\pi_{pre\text{-}aux}(\cdot\mid s)\,\|\,\pi_\theta(\cdot\mid s)\right)\right].\]

KL 的参照是辅助阶段开始前重新冻结的策略，不是若干策略阶段之前采样时保存的旧 Log Probability；$L^{aux}$ 在原论文中是辅助价值回归，目标在该辅助阶段保持固定。

它针对的不是单纯“Clip 不够强”，而是策略表示难以从价值目标中充分获益，同时又不希望策略阶段直接承受共享梯度干扰。

潜在收益

更充分训练价值与共享特征，同时把策略更新和辅助学习分相位组织。

工程代价

需要跨策略阶段保存辅助数据、额外 Epoch 与蒸馏/克隆约束；训练日程更复杂。

若基础 PPO 已使用完全独立 Actor/Critic 且价值拟合良好，PPG 的收益来源需要重新验证。

5. MAPPO：集中训练、分散执行

MAPPO 将 PPO 用于合作式多智能体任务。常见形式是每个智能体的 Actor 只使用执行时可获得的局部信息，而训练期 Critic 可使用全局状态或其他集中信息，即 centralized training with decentralized execution（CTDE）。

若 $o_t^i$ 是智能体 $i$ 的局部信息，$x_t$ 是只在训练期可用的集中信息，则执行与训练的边界可写为

\[a_t^i\sim\pi_{\theta_i}(\cdot\mid o_t^i),\qquad V_\phi=V_\phi(x_t,i).\]

集中 Critic 改变的是价值估计的信息集，不代表 Actor 在部署时可以读取 $x_t$。参数共享时还应给 Actor 可辨识的身份/角色信息，或使用满足任务对称性的结构。

核心挑战包括：

  • 其他智能体同时更新造成非平稳性；
  • 智能体数量、死亡/存活 mask 与可变实体；
  • 参数共享时身份信息与置换结构；
  • 全局 Critic 输入扩张和价值归一化；
  • Agent 有效 mask、终止语义与优势归一化的统计范围；
  • 多智能体 Batch 的时间、环境、Agent 维度不能误展平。

MAPPO 论文在其合作式基准上表明，经过仔细实现和调参的 PPO 系方法可以成为强基线；该结论不能直接外推到竞争、混合动机或新通信结构。它也不是“把单智能体观测拼起来”就完成的算法。

第一个消融应在相同 Actor、样本量和评估规则下比较 IPPO 的局部 Critic、MAPPO 的集中 Critic，以及是否参数共享；全局信息必须只进入训练期 Critic。

6. Recurrent PPO：给策略显式记忆

部分可观测任务中，当前观测不足以推断状态，可在 Actor/Critic 中加入 LSTM/GRU。PPO 的裁剪公式可以保持不变，但“同一个状态条件下重算 Log Probability”的对象已包含历史形成的隐藏状态，因此数据契约必须改变：

行为策略生成动作时的隐藏状态、Episode 起始标记与序列位置必须能在更新时重建；否则即使观测和动作相同，重算的 new_log_prob 也不是同一条件分布。

  • Rollout 保存每段初始隐藏状态；
  • Mini-batch 以连续序列块采样，而非完全随机时间步；
  • Episode 边界重置隐藏状态；
  • 序列截断点使用保存的精确隐藏状态，或用不计 Loss 的 burn-in 重建；
  • Padding 位置不进入 Loss；
  • 旧 Log Probability、优势、有效步 mask 与动作必须在同一时间索引；
  • Truncated Backpropagation Through Time 的长度成为新超参数。

先用 Frame Stack 或显式历史验证记忆需求，再引入 RNN。第一个消融要匹配参数量和环境步数，比较无历史、不同历史窗口与 RNN；同时测试跨 Episode 隐状态泄漏。RNN 增加的不是只有网络层，还包括状态管理、序列 Batch、推理导出和可复现性难度。

7. RND：为稀疏奖励增加内在动机

Random Network Distillation 使用固定随机目标网络 $f$ 和可训练预测网络 $\hat f$。令 $x_t$ 表示写入第 $t$ 个内在奖励的观测；若奖励记在执行 $a_t$ 之后，则应明确 $x_t=o_{t+1}$，避免观测与奖励错一位。对归一化观测 $\tilde x_t$ 的预测误差可写为

\[r_t^{int}=\frac{\eta}{2}\left\lVert \hat f(\tilde x_t)-f(\tilde x_t)\right\rVert_2^2.\]

再将内在奖励与外在奖励结合，用 PPO 训练策略。预测器持续学习会使奖励本身非平稳，因此需要明确内外奖励权重、各自折扣/价值头以及观测和 Return 的归一化更新时机。RND 误差是一个学习得到的访问新奇代理量，不等同于严格访问计数或可靠的认知不确定性。

需要分别记录内在/外在奖励、各自 Return、价值头误差和状态覆盖率。如果随机噪声观测永远难预测，策略可能追逐无意义的高误差状态，即常说的“噪声电视”问题。

第一个消融应比较外在奖励 only、同预算的随机探索基线与 RND，并同时报告任务成功率和状态覆盖，而不是只报告混合后的总奖励。

8. RPO：连续动作中的策略均值扰动

这里的 RPO 指 Robust Policy Optimization。对 Rollout 中旧动作 $a_t$ 重算 new_log_prob 时，它把当前高斯策略均值扰动为

\[\mu'_\theta(s_t)=\mu_\theta(s_t)+z_t,\qquad z_t\sim\mathcal U([-\alpha,\alpha]^{d_a}),\]

再用 $\mathcal N(\mu’\theta,\sigma\theta^2)$ 计算该旧动作的概率。rpo_alpha=0 时退化为对应的 PPO 实现。扰动发生在更新期的概率重评估，不等于给送入环境的动作加噪声，也不等于参数噪声或域随机化。

若只移动高斯均值而保持 $\sigma$ 不变，单个条件高斯的解析熵并不会因为均值平移而改变；RPO 的作用不应简写成“直接增加 entropy bonus”，更准确的理解是对均值附近的概率评估进行随机平滑。比较时必须记录扰动分布、每维尺度、应用阶段和评估时是否关闭扰动。

第一个消融应以相同 Seed 集合比较 $\alpha=0$ 与若干小尺度，并与熵系数、初始标准差和 squashed 分布设计对照；不能因为改动代码少就宣称对所有连续控制都更鲁棒。

9. Maskable PPO：把非法动作排除在分布外

在动作依状态变化、许多动作非法的离散任务中，仅靠环境惩罚会浪费探索。若 $\mathcal A(s)$ 是状态 $s$ 的合法动作集合，则掩码分布是

\[\pi_{mask}(a\mid s)= \begin{cases} \pi(a\mid s)\big/\sum_{b\in\mathcal A(s)}\pi(b\mid s),&a\in\mathcal A(s),\\ 0,&a\notin\mathcal A(s). \end{cases}\]

因此 PPO 的旧/新概率比必须在同一合法支撑集上计算。必须保证：

  • 采样时和更新时对同一状态使用一致 mask；
  • 至少一个动作合法；
  • 评估与部署也应用相同规则；
  • 向量环境能正确获取每个子环境的 mask；
  • mask 是环境约束，不泄漏未来信息。

若同一记录状态的 mask 在采样与更新间改变，旧动作可能突然落到零概率支撑之外，ratio 便失去预期语义。Mask 只能由该时刻可用的环境约束决定，不能偷偷使用未来信息；SB3-Contrib 当前支持 Discrete、MultiDiscrete 与 MultiBinary，不支持通用连续 Box 约束。

如果动作可通过环境接口设计为始终合法，先改善动作空间通常更稳健。第一个消融应比较“无 mask + 非法动作惩罚”“重构动作空间”“Maskable PPO”，并使用真正传入 mask 的评估器，报告非法动作率、成功率与样本效率。

10. APPO：异步 Actor-Learner 吞吐

APPO 使用异步采样与学习架构提高硬件利用率。Actor 持续从环境采样，Learner 独立更新参数；采样工作进程与 Learner 因而可能使用不同版本的策略。

若 Actor 的行为策略是 $\mu_b$，Learner 当前策略是 $\pi_\theta$，校正首先依赖可重建的密度比

\[\rho_t=\frac{\pi_\theta(a_t\mid s_t)}{\mu_b(a_t\mid s_t)}.\]

截至 2026-10-09，Ray RLlib 文档说明其 APPO 最初以 IMPACT 名称发表，采用 IMPALA 式异步架构，并提供 V-trace 配置来处理 EnvRunner 的策略滞后；其他框架的同名实现仍需按具体版本和源码核对。V-trace 的截断比率、PPO 的裁剪比率和样本丢弃规则是不同层面的机制，不能只记录一个 clip 超参数。

路线 数据一致性 主要优势 主要风险
标准同步 PPO Worker 用同一版本策略采样，聚合后更新 on-policy 语义清晰 等待慢 Worker，硬件可能空闲
APPO 类异步架构 Actor 与 Learner 并行，常配重要性校正/V-trace 吞吐和扩展性更高 Policy lag、样本陈旧、系统复杂

一旦 Actor 使用的策略版本落后于 Learner，数据就不再严格来自当前策略。此时必须记录行为/学习策略版本、Lag 分布、队列等待时间、样本复用次数、重要性比率和校正/截断机制，不能只保留 PPO Clip 就宣称 on-policy 语义未变。

机器人 GPU 并行环境在单进程内批量步进，未必需要异步 Actor-Learner。第一个实验应先 Profile 仿真、策略推理、传输和更新，再在相同硬件与样本预算下比较同步并行 PPO 和异步架构的吞吐、样本效率与墙钟收敛。

11. DPPO：用 PPO 微调 Diffusion Policy

这里的 DPPO 指 Diffusion Policy Policy Optimization。它研究如何用策略梯度对 Diffusion Policy 进行强化学习微调，使策略继续利用扩散模型表达多峰动作分布与动作序列的能力，同时从在线交互奖励中改进。

标准高斯 Actor 通常一步得到分布参数并采样动作；Diffusion Policy 则从噪声出发经过多步去噪生成动作或动作块。DPPO 把每个环境决策内的去噪链视为扩展的决策过程：外层索引环境步，内层索引去噪步；PPO 风格 ratio 对应去噪转移的条件概率，而环境 Advantage 需要分配到相关去噪步骤。

因此，环境动作 Horizon、实际执行/重规划长度、去噪步数、噪声调度和每个去噪转移的旧 Log Probability 都属于策略契约。把所有去噪步骤误当成独立环境样本，会混淆两层时间并错误放大样本量。

不要把这里的 DPPO 与图像生成领域常见的 DDPO（Denoising Diffusion Policy Optimization） 混为同一算法；二者都利用去噪过程，但任务、状态/动作语义和论文目标不同。

适合的问题

已有模仿学习得到的 Diffusion Policy，需要用在线奖励进一步优化复杂机器人操作，并希望保留多峰动作表达。

新增代价

多步去噪带来更高采样/反向传播成本；策略概率、动作块、环境步和 Advantage 的对应关系更复杂。

DPPO 不能被简化为“把普通 PPO 的 Actor 换成任意 VLA 网络”。扩散策略的条件输入和动作块语义必须可用于计算训练所需的概率；若 VLA 接口只返回动作而没有一致的随机策略密度，就不能直接套用 PPO ratio。

第一个消融应固定模仿预训练数据、在线交互量、模型容量和推理预算，比较仅模仿学习、标准策略参数化的 PPO 微调与 DPPO；同时报告任务成功率、探索分布、采样延迟和训练成本。

12. PPO-style RLHF：Token 级策略优化

在语言模型偏好优化流程中，PPO 可用于最大化奖励模型分数，同时用相对参考模型的 KL 惩罚控制策略漂移。以提示 $x$、生成序列 $y=(a_1,\ldots,a_T)$ 为例，一种常见的序列目标记法是

\[R(x,y)=r_{RM}(x,y)-\beta\sum_{t=1}^{T}\left[\log\pi_\theta(a_t\mid s_t)-\log\pi_{ref}(a_t\mid s_t)\right].\]

括号内是在采样 Token 上得到的 KL 代理项；具体实现可能使用不同估计或奖励整形。PPO 更新本身还使用 Rollout 旧策略 $\pi_{old}$ 构造 ratio，$\pi_{old}$ 与冻结参考模型 $\pi_{ref}$ 承担不同角色，不能共用一个“旧模型”概念。

它与控制任务 PPO 共享 ratio、优势、价值头和近端更新思想，但数据单位、奖励构造与 KL 位置不同：

  • 状态/动作是前缀与 Token；
  • 奖励可能主要在序列末给出，再与逐 Token KL shaping 组合；
  • Reference Model 与采样旧策略是两个不同参照角色；
  • Padding、EOS、Attention Mask 和序列长度影响优势与 Loss；
  • 奖励模型偏差、长度偏好和 Reward Hacking 成为主要风险。

因此，控制 PPO 的超参数不能直接迁移到 RLHF。现代偏好优化还有 DPO 等无需在线 PPO Rollout 的路线，应按是否需要在线采样、奖励模型、参考约束和算力预算比较；“更新方法更简单”不代表偏好数据或奖励偏差消失。

第一个审计应同时画出奖励模型分数、参考 KL、响应长度、截断/EOS 比例和人工/独立评估，防止只优化单一 RM 分数而产生长度偏好或 Reward Hacking。

14. 研究实验设计

  1. 声明基础 PPO 基线。 固定公式、实现、总环境步数、网络、Batch、评估和 Seed。
  2. 定义失败指标。 例如 KL 尖峰频率、成功率、样本效率、吞吐、动作违规率，而非笼统“更稳定”。
  3. 单机制消融。 新机制关闭时应尽量退化为同一基线。
  4. 匹配资源。 同时报告环境步、梯度步、墙钟时间、GPU 数与参数量。
  5. 报告分布。 多种子均值与离散程度，并公开失败运行。
  6. 验证副作用。 更高回报是否来自更多计算、奖励漏洞、特权信息或评估分布变化。
  7. 回归基础不变量。 新方法加入后仍要验证终止/截断、旧 Log Probability、动作变换、mask、隐藏状态和有限数；新缩写不能掩盖旧实现错误。
  8. 分层写结论。 分开记录“论文报告”“当前复现观察”和“本页推断”，并把外推条件、失败运行与尚未验证的假设一起保留。

研究地图的核心创新不是收集更多算法名，而是设置选择门： 先用可否证证据定位瓶颈，再写清新机制改变的层、必须保持的不变量、首个单机制消融和不能外推的边界。只有这四项同时成立，才进入组合实验。
