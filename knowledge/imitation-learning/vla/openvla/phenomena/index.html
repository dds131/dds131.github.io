一、本页的收录标准

本页不是「OpenVLA 疑难杂症大全」。它只收一类现象：

本页关注模型、服务与控制器共同形成的闭环系统。 重点讨论三类容易被误判为“模型变笨”的问题：服务与控制时序、推理接口契约、训练标签瑕疵。参数量、网络结构和数据配方的详细消融只保留索引。

之所以单独整理这些现象，是因为离线动作预测质量不能单独决定真机成功率。相同基础检查点在不同数值精度、推理时序和控制语义下可能得到不同的闭环结果。第四、五节的量化实验给出了本页证据最强的案例，但结论只适用于论文所测模型变体、任务和控制栈。

三、简化系统框架：质量、时序、控制与接口

真机成功率由完整闭环共同决定，而不只是单步动作预测质量。本页用下面的简化框架组织分析；它服务于排查，并不穷尽环境分布、传感器标定、安全控制和执行器等因素。

“更快”与“更准”是两种不同改进。 成功率会把它们与控制器、接口共同折叠成一个结果。量化实验的价值正在于：论文通过改变控制方式，检查 int8 的掉点是否主要来自服务时序。

四、现象 A：为什么非阻塞控制下 int8 更差

这是本页证据最强、方法论价值最高的案例：论文先提出速度解释，再用阻塞控制重测。它强力支持该解释，但不是对所有量化模型和部署条件的普遍证明。

第一步，观察到异常。 论文在 §5.4 用三种精度在 BridgeData V2 上评测，采用非阻塞控制（层一，Table 2 的成功率列）：

精度 非阻塞控制下的成功率
bfloat16 71.3 ± 4.8%
int8 58.1 ± 5.1%
int4 71.9 ± 4.7%
先限定模型口径。 论文第 10 页脚注 4 说明，§5.3 与 §5.4 使用的是预训练数据混合更小、只含 SigLIP 视觉编码器的 OpenVLA 变体，而非最终发布的双编码器模型。附录 D.4 重做的是这组量化评测，因此两表属于同一模型变体和同一组 8 个任务；三种精度来自同一基础检查点，但数值表示并不相同。

异常在于：int8 不仅低于 bfloat16，还低于位宽更低的 int4。如果只采用“位宽越高，近似越准确”的单因素解释，这个排序难以说明；但任务成功率还受量化算子、硬件吞吐和闭环时序影响，不能预设它必然随位宽单调变化。

第二步，提出假设。 在论文使用的 A5000 与当时软件栈上，int8 约为 1.2 Hz，而 int4 约为 3 Hz。论文还报告 int8、int4 与 bfloat16 在训练数据离线评测上的 token accuracy 相当，据此假设：非阻塞评测中的 int8 掉点主要来自 8 比特运算造成的低推理速度，而不是动作预测能力显著下降。训练集 token accuracy 既不是 held-out 指标，也不测物理单位误差或闭环能力，因此它只是支持该假设的旁证。这个速度排序依赖硬件和算子实现，不是 int8 与 int4 的普遍属性。

第三步，设计受控实验。 论文改用阻塞控制重做评测：一个动作完全执行后才预测下一个。按论文的实验设计，这会把高吞吐的 bfloat16 与 int4 强制放慢，显著降低不同推理速度造成的动作时序差异。它不能让三种策略经历完全相同的状态轨迹，也不是严格“独立于速度”的质量测量；阻塞控制本身改变了部署语义，因此结论应限定在这组对照中。

第四步，结果。 见下一节。

五、Table 2 与 Table 11 并排

把两组实验放在一起，是本页最有说服力的一张表（层一，两表的成功率列）：

精度 非阻塞控制（Table 2） 阻塞控制（Table 11） 均值变化
bfloat16 71.3 ± 4.8% 70.0 ± 5.1% −1.3 个百分点
int8 58.1 ± 5.1% 74.4 ± 4.9% +16.3 个百分点
int4 71.9 ± 4.7% 68.8 ± 5.2% −3.1 个百分点
三者极差 13.8 个百分点 5.6 个百分点 点估计更接近

这张表要读出三层信息：

其一，点估计排序反转非阻塞下 int8 最低，阻塞下 int8 的均值最高。但这只是均值排序，不代表统计上存在稳定排名。
其二，方向符合速度假设在阻塞控制下，int8 不再承受非阻塞部署中的速度劣势，其成功率点估计大幅回升。
其三，Table 11 未显示明确差异三组均值的标准误差条重叠；论文据此称三种方法表现相当，并认为结果确认了其速度假设。

表中的“±”是标准误差，不是等价性检验。误差条重叠只说明这组实验没有显示出清晰差异；若要证明三种精度等价，还需要预先规定可接受差异，并分析配对差值的置信区间。Table 2 与 Table 11 也不是同一批逐轨迹配对样本，因此“变化”列用于理解趋势，不是个体配对效应。

准确结论：在论文所测模型变体、8 个 BridgeData V2 任务、A5000 和控制栈中，阻塞控制结果强力支持“较低推理速度是 int8 非阻塞掉点的重要解释”，与作者的主要原因假设一致。两表是非配对 rollout，不能量化 16.3 个百分点中究竟多少由速度解释；结果也不证明 int8 完全无量化误差，不能外推到其他硬件、量化库和任务。

论文同时指出，使用最低的 4 比特精度时也没有观察到实质性的性能退化，这与 §5.4 的结论一致（层一）。

六、从现象 A 提炼的方法论

这段实验的价值超出 OpenVLA 本身。它给出的是一条可迁移的评测纪律：

对实时闭环策略，任何可能改变服务时序的改动，都应同时报告吞吐、端到端延迟、延迟抖动、控制频率和动作保持语义。 否则，成功率无法区分“动作变差”与“动作来得太晚”。

这条纪律适用于量化精度、模型规模、推理框架、编译优化、采样步数、动作分块和投机解码等改动。它们可能改变平均吞吐，也可能主要改变首 token 延迟、尾延迟或抖动，不能只记录一个 Hz。

若只看到 至少要区分 推荐对照
成功率下降 动作预测退化 / 延迟或抖动增大 / 控制语义改变 固定控制语义，分别比较离线动作指标与时序指标
成功率不变 两者均无变化 / 正负效应抵消 / 评测方差过大 报告置信区间，并做逐任务分析
成功率上升 动作更准 / 服务更快更稳 / 两者共同作用 做匹配时序或匹配动作质量的消融

对照阅读：扩散类与流匹配类策略的采样步数选择面临完全相同的权衡，可参考 π0 专题 与 SmolVLA 专题。

七、阻塞与非阻塞控制器

上面反复出现的概念需要与具体控制器实现绑定。论文对阻塞控制给出了明确定义；对非阻塞控制，只报告了频率，并没有在正文中规定“拿不到新动作时一定重复上一动作”。

模式 论文或工程定义 能够推出什么
非阻塞 工程抽象：控制循环不等待当前推理完成；可采用 hold-last、动作队列或安全回退 论文未公开具体保持/排队语义；必须查看控制器实现

若控制器明确采用 hold-last，设控制时刻为 \(t_k\)，动作到达时刻为 \(s_i\)，则执行的是最新可得动作：

\[\mathcal I_k=\{i:s_i\le t_k\}, \qquad u(t_k)= \begin{cases} \hat u_{\max \mathcal I_k}, & \mathcal I_k\neq\varnothing,\\ u_{\mathrm{safe}}, & \text{尚无预测到达}. \end{cases}\]

此时才可以用 \(f_c/f_p\) 粗略估计一个预测动作被保持多少个控制周期；网络抖动和推理抖动会使实际保持次数变化。

八、现象 B：官方接口为什么补 token 29871

论文发布的 OpenVLA-7B 实现在生成前检查输入序列末位：如果不是 token id 29871，就补上该 token。两套 predict_action 实现的注释都说明，这是为了匹配训练时的提示前缀。

项 内容 位置（层二）

源码事实不等于性能消融。 可以确定的是官方 OpenVLA-7B 接口把 29871 当作提示契约的一部分；绕过该接口可能得到偏离官方格式的前缀，而生成过程仍可能正常返回 token。论文没有报告“去掉 29871”的定量消融，因此这里只能说存在静默劣化风险，不能断言下降幅度。若更换 tokenizer，也必须重新确认对应 token，不能照搬硬编码 id。

九、推理接口契约的五项检查

token 29871 只是接口契约的一部分。下面五项都可能造成训练—推理错位，但是否报错取决于具体实现：不存在的统计键会被官方代码拒绝，有效但错误的键则可能静默通过。

契约面 可能的错位 自检手段
提示形态 模板文字、末尾 token、特殊符号不同 同时记录原始 prompt、token id 和解码文本；与训练样本核对

unnorm_key 的错误要分两种：键不存在，或多数据集模型没有提供键时，官方实现会触发断言；如果选中了一个存在但属于其他本体的键，程序可能正常运行，却按错误的动作维数和分位区间生成、反归一化动作。后者才是危险的静默错误。即使键名正确，也要验证统计来源：微调脚本把新统计另存为 dataset_statistics.json，而服务只有在加载本地目录时才用它覆盖配置。模型 revision、统计文件哈希、维数、mask、q01/q99 应联合校验，不能在旁路文件缺失时静默回退到基座统计。

生成端也有类似的静默错误：两版 predict_action() 只设置 max_new_tokens=D，随后无条件截取整段序列末尾的 D 个 id，既不验证早停，也不施加动作词表硬掩码。提前 EOS 会让 prompt token 混入切片；普通文本 token 又会在反量化时被裁到首尾分箱中心。do_sample=False 只关闭随机采样，不能替代长度和合法区间检查。

十、现象 C：全零动作让策略整个冻住

论文在附录 C 记录了开发过程中的一个发现（层一）：原始版本的 BridgeData V2 含有大量全零（no-op）动作的转移，且每一条演示的第一个时间步记录的真值动作都是全零。其后果是：

在未经任何数据预处理的原始数据集上训练一个高表达力的 VLA 模型，会得到一个频繁预测全零动作、并在评测中冻住的策略（层一，附录 C 原文）。

处置方式很简单：过滤掉每条演示的第一个转移，论文称这在多数情况下已足以缓解冻结行为（层一）。清洗动作本身与其源码位置属 子页 ④ OXE 数据与配方筛选 第十一节。

实现边界也要说清：固定源码的 bridge_oxe/bridge_orig transform 对整条轨迹的字段统一取 [1:] 后再重标动作，删除的是每条轨迹首个 transition，并不是像 LIBERO 那样逐动作识别并过滤所有 no-op。

论文建立了什么。 论文观察到高表达力 VLA 会模仿 no-op 并冻结，也观察到过滤首个转移能够在多数情况下缓解；它没有给出模型容量消融，因而不能据此断言“弱模型会把 no-op 当噪声平均掉”。

一种合理但尚未验证的闭环解释。 行为克隆会提高训练数据中 no-op 标签的条件概率。如果执行 no-op 后观测几乎不变，确定性解码可能再次选择 no-op，形成近似自保持状态：

\[o_{t+1}\approx o_t,\qquad \arg\max_a \pi(a\mid o_t,l)=0 \;\Longrightarrow\; a_{t+k}\approx 0.\]

模型容量可能使其更容易拟合这类条件关系，但“记住首帧”是否是主因仍需容量、no-op 比例和解码方式的受控消融。

这不是“整体学得太好”，而是忠实学习了错误监督。 LIBERO 数据处理中也需要过滤 no-op；论文说明不清洗会使 OpenVLA 这类高表达力单步策略在某些状态下持续冻结。两处结果共同说明 no-op 清洗具有跨设置的重要性，但不证明两个数据集的具体生成机制完全相同。

十一、RT-2-X 的两种规避方案

十二、现象 D：OpenVLA 在 LIBERO 上的相对优势更窄

论文在附录 E.2 观察到：OpenVLA 在 LIBERO 上取得所测方法中最高的平均成功率与平均排名，但相对其他方法的优势幅度比 §5.2 的真机实验更窄。这里比较的是“相对基线的优势”，不是同一模型微调前后的“微调增益”。

论文把这一现象归因于纯真机预训练数据与仿真环境、动力学之间的域差；原文使用 attribute to，这不是受控因果实验，而且真机与 LIBERO 的任务、基线和评测协议也不同，不能把两组 margin 当作严格的同口径量值。

论文还给出了一条旁证：Octo 同样是在大量真实机器人数据上预训练的策略，它相对于「从零训练的 Diffusion Policy」这一简单而强的基线，也只取得了很小的整体提升（层一）。作者预期，若把仿真数据加入预训练混合，预训练加微调类方法的增益会增加。

这条归因的证据结构值得注意。 它不是受控实验，而是「两个具有相同特征（纯真机预训练）的方法表现出相同的模式（仿真增益收窄）」这样的观察性证据。论文自己用的措辞是归因与提示，本页保留这个强度。可验证的下一步是论文自己提出的那一条：把仿真数据加入预训练混合后重测。

阻塞重测后差距缩小，说明服务时序是重要贡献因素，但不能据此证明它是唯一原因；同样，把 prompt 解码回文本只能检查文本前缀，不能覆盖图像预处理和动作接口。

为什么 token accuracy 不够

动作 token 准确率是有效动作位置上的 0/1 指标。令 \(m_{n,j}\in\{0,1\}\) 表示该位置是否进入动作 mask，则更贴近官方实现的写法是：

\[\operatorname{Acc}_{\mathrm{tok}}= \frac{\sum_{n,j}m_{n,j}\,\mathbf 1[\hat z_{n,j}=z_{n,j}]} {\sum_{n,j}m_{n,j}}.\]

只有每条样本恰有 \(d\) 个有效动作位置时，分母才可简写为 \(Nd\)；EOS、IGNORE_INDEX 和截断位置不应混入。

相邻分箱和相距很远的分箱只要不相等，都记为一次错误；它还可能被易预测维度、no-op 标签和训练集过拟合抬高。因此它能描述离散标签拟合程度，不能单独证明任务已经学会。

解码后的归一化动作误差可以写成：

\[\operatorname{MAE}_{\mathrm{norm}}= \frac{\sum_{n,j}m_{n,j} \left|\hat a^{\mathrm{norm}}_{n,j}-a^{\mathrm{norm}}_{n,j}\right|} {\sum_{n,j}m_{n,j}}.\]

官方训练循环记录的 L1 正是 argmax token 解码到归一化分箱中心后的误差；该处没有使用 q01/q99 恢复为机器人物理单位，也不是自由闭环 rollout。更隐蔽的是，argmax 在完整语言词表上进行：若预测出非法的普通文本 token，解码函数会把索引裁到首尾分箱中心，仍产生有限 L1。因而应额外报告“预测 token 落在合法动作区间的比例”，再同时报告逐维 token accuracy、归一化 MAE、held-out 指标和真机成功率。反归一化后的误差应按平移、旋转、夹爪等维度和单位分别报告；若要合成一个数，必须先声明无量纲化或加权方案。详见 子页 ③。

  1. Kim, M. J. et al. OpenVLA: An Open-Source Vision-Language-Action Model. CoRL 2024. arXiv:2406.09246 —— 核对内容：§3.5（RTX 4090 上约 6 Hz）；§5.2（Franka-Tabletop 5 Hz 与 Franka-DROID 15 Hz 两套非阻塞控制器）；§5.4 与 Table 2 的成功率列（三种精度在非阻塞控制下的表现）；附录 C 全文（BridgeData V2 全零动作、每条演示首帧为全零、高表达力模型频繁预测全零并冻住、过滤首个转移、RT-2-X 始终取次可能动作的规避方案、动态查询反而更差及其关于查询延迟改变机器人动力学的假设）；附录 D.4 全文与 Table 11（假设的提出、阻塞控制的定义与其统一系统动力学的作用、把高吞吐精度强制放慢以匹配 8 比特动力学的设计说明、三种精度在阻塞控制下相当、论文称此确认了该假设、4 比特无实质退化）；附录 E.1 第 2 步（LIBERO 同样必须滤除空操作，否则策略会模仿并无限期冻结）；附录 E.2（OpenVLA 在 LIBERO 上平均成功率与排名第一但优势幅度窄于真机、归因于纯真机预训练带来的域差、以 Octo 为旁证、预期加入仿真数据可提升增益）；Table 12 表注（三个随机种子、每个 500 次试验）。HTML 版 arxiv.org/html/2406.09246。

层二 · 源码与发布权重

  1. OpenVLA 固定 commit c8f03f48 —— 第八节的 token 29871 补位见 HF 与原生两版 predict_action；第九节的大小写、生成长度和 unnorm_key 行为来自两版实现对照；第十三节的 L1 监控见 prismatic/training/strategies/base_strategy.py，其输入是 action token 解码得到的归一化分箱中心。本地裁剪镜像记录为 2026-09-16 的 main 且没有可验证 SHA，因此固定链接是版本证据，本地文件只用于符号级交叉检查。
