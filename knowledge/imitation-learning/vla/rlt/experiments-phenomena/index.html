VLA/后训练与对齐/RLT/实验与诊断

RLT v2 支持的是固定任务、固定 regime 和固定公开配置下的结果。critical-phase ≠ full-task，interaction time ≠ wall-clock ≠ derived samples，result ≠ causal explanation。论文未报告 training seeds、跨 run variance 或 confidence intervals 时，正确状态是 unknown/not reported，不能用相邻图、项目短文或第三方视频补齐。

冻结协议审计消融进入诊断树返回 RLT 枢纽

问题、证据层级与协议快照

页面只回答四个可审计问题：Q1 在同 task/regime/protocol 下 Base→RLT 的 success/throughput 是否变化；Q2 在 Ethernet disclosed budget 下与 baselines 如何比较；Q3 full 与 declared treatment 的 curve/failure/endpoint 差异能支持多强的 component claim；Q4 teleop/Base/RLT trajectory 只支持何种 strategy-difference hypothesis。

每个 result snapshot 前冻结 source/version/date/locator、task/regime/critical boundary、initial-state distribution、evaluation policy artifact、Base VLA/RL Token/actor/critic/reference/action/reward/safety revisions、success authority、termination taxonomy、metric/window/denominator/censoring、train/eval/practice splits、hardware/environment class，以及 run/seed/episode IDs。未报告字段显式写 unknown。

证据强度由弱到强是 qualitative observation、one-snapshot descriptive result、same-protocol contrast、controlled single-variable ablation、repeated-run causal estimate with uncertainty；不得把前两级写成后两级。

样本预算、真实交互与人力成本

量 v2 披露范围 单位 不能混称为
teleoperation demonstrations 每任务约 1–10 h recorded demo time online RL interaction
Stage-1 optimization 约 2,000–10,000 gradient steps robot steps/hours
online training 约 400–1,000 episodes evaluation trials
unique robot interaction 每 experiment 约 15 min–5 h executed physical time derived windows
final report snapshot 约 gathering 5 h data snapshot-specific 每任务统一预算

第 43 页的 stride=2/50 Hz 可以派生约 25 windows/s，但不会增加 unique interaction。报告必须并列列出 unique_physical_steps、unique_interaction_seconds、derived_window_count、overlap_stride/group_count、learner_updates 和 UTD denominator。

total wall-clock 还包括 reset/setup、annotation latency、intervention/switch labor、learner latency、validation/publish waiting、safety/incident/quarantine downtime 与 other recorded overhead。论文未拆出的项是 not reported，不能把 wall-clock - robot time 自动命名为 reset。

human labor 还要区分 demonstration、terminal labeling、corrective intervention、critical-phase switching、safety supervision、reset/setup 和 incident adjudication；缺公开数字写 missing，不写 0。“sample-efficient”只能绑定 disclosed robot interaction；“低成本/自主/少量人工”还需要 labor、wall-clock、compute、wear 和 incident 证据。

四任务、两种 regime 与指标语义

task critical phase / disclosed difficulty scope
screw installation 工具与 M3 screw 对齐/旋入；亚毫米与长工具姿态误差 本硬件/设置
zip tie fastening 柔性尾端穿锁扣；双臂、柔性物体、紧容差 本任务
Ethernet insertion 对准并越过端口阻力；接触与 probing 本端口任务
charger insertion prong/socket 对准；可见性不完整 本设置

critical-phase controlled 从部分完成、接近关键阶段且轻微随机化的状态开始，四任务每 agent/task 公开 50 episodes；full-task 从 home position 开始，由 Base VLA 前段诱导入口，只报告 screw 与 zip tie，文本未给明确 evaluation count。两种 regime 不能合并 numerator/denominator。

success_rate=success/eligible evaluated episodes，需说明 failed/aborted/safety-stop/infra/unknown 如何计入；throughput=successful completions/10-minute interval，需说明 timing、reset、failed attempts 与 censoring；episode length 必须给 steps/frequency/population/regime；speedup 必须给 ratio 两端和 mean/median/ratio-of-means。成功率高不等于快，critical speedup 不等于 full-task speedup，success-only duration 有 survivorship bias，sparse return 也不等于安全或任务质量。

主结果、量纲与适用范围

学习曲线、checkpoint 与不确定性

learning curve 的横轴必须把 unique robot interaction minutes/steps 与 total experiment wall-clock 分开；wall-clock 未报告时显示 disabled / not reported，不能由采样率反推。每个点绑定 policy/checkpoint、interaction、wall-clock、task/regime、eval episode set、metric、failures/interventions/safety stops、run/seed、aggregation/smoothing 和 reported/digitized status。

Figure 7 的 5 min 是 Ethernet critical-part robot data consumed，~40 min 是对应 total experiment time；二者不是通用收敛时间，也不能由单点推导 sample-complexity law。“超过替代 policy”还必须写清替代项和 metric。

论文未报告 seeds/variance/CI 时，仍可展示 scoped central result，但必须同时显示 seeds: not reported、cross-run variance: not reported、confidence intervals: not reported。不得伪造 error bars、把 50 evaluation episodes 当 independent training runs，或把 episode-level binomial variation 当 training-seed uncertainty。checkpoint selection 只可写 final/last/best-validation/best-observed/unknown。

schema: rlt.learning-curve.v1

反直觉现象与证据强度

六类 phenomenon 必须拆成 observation、scope、evidence type、author interpretation、alternative hypotheses 与 needed evidence：Base success but slow；Ethernet final RLT 比数据集 teleop demonstrations 更快；Base probing；首次失败后 pressure/wiggle；no-pass-through endpoint catch-up 但 early cost 更高；critical-phase gain 与 full-task drop 并存。

“更快于 demos”不是超过所有人类专家能力；probing/wiggle 没有公开 frequency，不能写“经常/普遍”；“来自 online exploration”是 author interpretation，没有 counterfactual 不能升级为唯一原因。γ<1 只提供 earlier reward 的方向性解释，实际 speed 还受 reward timing、termination、Q error 和 constraints 影响。full-task drop 可能来自 entrance shift、handoff、前段 failure、sensor mismatch 或 safety stop。

局限、missing evidence 与路线出口

四个精密 manipulation tasks 不证明开放世界/长时任务普遍有效；reconstruction RL Token 不保证所有 contact/safety state；human reward/intervention/switch/safety labor 仍是系统组成；maximum critical speedup 不是 full-task average；BC anchor 不是 safety constraint；作者比较不是跨方法/硬件/compute 的统一排行榜；第三方 π0/π0.5/openpi 复现不能替代 π0.6 原实验。

固定 missing-evidence panel：seeds/independent runs，cross-run variance/CI，full-task evaluation count，raw episode ledger，metric timing/reset/censoring，40%/60% scale，human labor by role，incident/safety/wear counts，pure chunk/critic ablations，qualitative case frequency/selection。未知不是 0，也不是负面证据。
