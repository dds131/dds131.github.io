一、本页在专题中的位置

X-VLA 的结构在论文里被描述得很简洁：一个视觉语言编码器、一个共享的视觉主干和一个标准 Transformer encoder。但要真正读懂源码或迁移到自己的机器上，还需要回答：每段 token 从哪里来、形状怎样变化、域条件在哪些位置生效、哪些长度是默认配置而不是方法本身的常数。本页只回答这些结构问题。

262默认一次前向的总序列长度
50每路视角的视觉 token 数
1024全链路统一隐藏维
72控制流通道维
24主干 block 数
512prompt 前位置编码容量
本页刻意不讲：Soft Prompt 为什么需要、为什么必须提前注入（子页 ①）；损失与 Flow Matching（子页 ③）；训练超参与学习率调度（子页 ④）；源码调用链（子页 ⑤）；推理与部署（子页 ⑥）；反常现象排查（子页 ⑦）。本页只讲结构与形状。
证据口径：论文层以 arXiv:2510.10274 v1 为准；实现层固定到官方源码提交 6bc2513f5f1cbec715cc668b414392a6cae5c671与 checkpoint 固定配置，复核日期为 2026-10-04。论文负责说明设计意图；张量顺序、掩码与配置是否生效以固定源码为准，不能把本页描述外推为未来版本的永久接口。
先抓住创新层级：X-VLA 的核心创新是用数据源专属 Soft Prompt 在共享主干中注入域条件；与之配套的架构设计包括「主视角继续做图文融合、辅助视角复用同一条 Florence 图像编码路径但绕过语言 encoder」和域专属动作输入/输出投影。50 个视觉 token、262 的默认总长度以及 embedding 表式批量分派，都是当前实现选择，不应当作方法定义。

二、四条输入流与它们的分工

X-VLA 的输入不是「图像加语言」两路，而是四条性质不同的流，它们在不同的位置汇入同一个序列。

四条流的关键区别：

流 承担什么 进入序列的位置 X-VLA 外层位置编码 参数归属
视觉语言 任务级语义与物体定位 第 2 段 是 共享
辅助视觉 补充近距离或其他视角证据 第 3 段 是 共享（与主视角同一份权重）
控制 本体状态、待去噪动作、时刻 第 1 段 是 输入投影按数据源私有
数据源条件 数据源/域槽位的隐式条件 第 4 段 否 按数据源私有
这里的 domain_id 是数据源/域槽位索引；它选择 prompt 与动作边界投影，却不显式携带相机参数、机器人型号等结构化字段。prompt 最终学到什么由训练数据与动作监督决定，不能仅凭查表结构把它称为已验证的“硬件配置编码”。
一个反直觉的排列：动作段排在最前面，视觉语言段排在中间，提示段排在最后。由于动作主干使用双向全注意力且没有注意力掩码，各段之间相互可见；但段顺序仍会改变前三段获得的绝对位置编码，并决定输出端从哪里读取动作，因此不能随意重排。

三、Florence-2 Large 在 X-VLA 里被裁成了什么样

3.1 规模判定：证据在 checkpoint 的 config 里

论文 Appendix C 写的是采用 Florence-Large 作为视觉语言编码器（层一）。这一点可以从发布权重的配置直接验证（层二，2toINF/X-VLA-Pt 的 config.json 中 florence_config 一节）：

"text_config":   { "d_model": 1024, "encoder_layers": 12, "decoder_layers": 12,
                   "encoder_attention_heads": 16, "encoder_ffn_dim": 4096,
                   "vocab_size": 51289 }
"vision_config": { "model_type": "davit",
                   "dim_embed":    [256, 512, 1024, 2048],
                   "depths":       [1, 1, 9, 1],
                   "num_heads":    [8, 16, 32, 64],
                   "patch_size":   [7, 3, 3, 3],
                   "patch_stride": [4, 2, 2, 2],
                   "patch_padding":[3, 1, 1, 1],
                   "window_size":  12,
                   "image_feature_source": ["spatial_avg_pool", "temporal_avg_pool"] }
"projection_dim": 1024

d_model 为 1024、encoder_layers 为 12、DaViT 的 dim_embed 为 [256, 512, 1024, 2048] —— 这一组正是 Florence-2 large 的规格（base 对应的是 768 / 6 / [128, 256, 512, 1024]）。

3.2 decoder 与 lm_head 被直接删掉

X-VLA 只需要 Florence-2 的编码能力，不需要它生成文本。构造时直接把生成侧的模块删除（层二）：

# models/modeling_xvla.py，XVLA.__init__ 节选
self.vlm = Florence2ForConditionalGeneration(config.florence_config).to(torch.float32)
if hasattr(self.vlm, "language_model"):
    lm = self.vlm.language_model
    if hasattr(lm, "model") and hasattr(lm.model, "decoder"):
        del lm.model.decoder          # 解码器被删掉
    if hasattr(lm, "lm_head"):
        del lm.lm_head                # 词表输出头也删掉

两点后果值得注意：

  • config.json 里仍写着 decoder_layers: 12，但那 12 层在运行时并不存在。 照配置估算参数量会偏大。类的文档串也写明了它是 encoder-only 的视觉语言主干。
  • 训练阶段没有任何语言建模损失。 文本只作为条件进入，不承担生成任务；这与一部分 VLA 保留语言头做辅助监督的做法不同。

3.3 每路视角的 50 个 token 是怎么算出来的

这是本页最值得逐步复算的一处。固定提交的公开训练数据路径会执行 Resize((224, 224))；这是本页默认形状与公开训练实现，不是模型 _encode_image 内部硬编码的唯一分辨率。

第一步：DaViT 下采样。 不能只看 stride 连乘，还要同时看卷积核与 padding。每个 stage 的单边输出尺寸满足

\[n_{\mathrm{out}} = \left\lfloor\frac{n_{\mathrm{in}}+2p-k}{s}\right\rfloor+1.\]

当前配置的 patch_size=[7,3,3,3]、patch_stride=[4,2,2,2]、patch_padding=[3,1,1,1]，所以边长依次为

\[224 \longrightarrow 56 \longrightarrow 28 \longrightarrow 14 \longrightarrow 7.\]

这与总步长 \(4\times2\times2\times2=32\)、且输入可整除时的 \(224/32=7\) 一致；换成其他尺寸时应使用上面的卷积公式复算，不能只做整数除法。最终空间位置共 \(7\times7=49\) 个，forward_features_unpool 返回这 49 个位置，通道数取最后一个 stage 的 dim_embed，即 2048。

第二步：先注入 Florence 内部的位置表示。 这 49 个位置在池化前会加入可学习的二维图像位置编码；单帧输入还会加入 Florence 的 temporal cosine embedding。后者在 \(T=1\) 时不给不同帧制造相对次序，但仍会给视觉特征加入一个时间位置向量。

第三步：两种池化各出多少个 token。 源码把单帧输入记作 \(T = 1\)，特征张量视作 [B, T, 49, 2048]，然后做两种池化：

# models/modeling_florence2.py，_encode_image 节选
spatial_avg_pool_x = x.view(batch_size, T, -1, x.shape[-1]).mean(dim=2)   # 对 49 个空间位置取平均
x_feat_dict['spatial_avg_pool'] = spatial_avg_pool_x                       # -> [B, T, 2048]，T=1 即 1 个 token

temporal_avg_pool_x = x.view(batch_size, T, -1, x.shape[-1]).mean(dim=1) # 对 T 个时刻取平均
x_feat_dict['temporal_avg_pool'] = temporal_avg_pool_x # -> [B, 49, 2048]，即 49 个 token

new_x = []
for _image_feature_source in self.image_feature_source:
    new_x.append(x_feat_dict[_image_feature_source])
x = torch.cat(new_x, dim=1)  # ['spatial_avg_pool','temporal_avg_pool'] -> 1 + 49 = 50

x = x @ self.image_projection # 2048 -> projection_dim = 1024
x = self.image_proj_norm(x)
return x # [B, 50, 1024]

第四步：合计。

\[\underbrace{1}_{\text{spatial\_avg\_pool}} + \underbrace{49}_{\text{temporal\_avg\_pool}} = 50\]

再经 image_projection 把 2048 维投到 1024 维，与语言侧的 d_model 对齐。主视角的 50 个视觉 token 随后与 50 个文本 token 拼接；进入 Florence encoder 时，这 100 个位置还会再获得一套一维绝对位置编码。

单帧输入时，temporal_avg_pool 是对长度为 1 的时间轴取平均，因此不发生跨帧聚合；spatial_avg_pool 则把 49 个空间位置汇总为 1 个全局摘要。最终仍是1 个全局摘要 token 加 49 个保留空间位置的 token。需要注意，二者都来自已经加入 Florence 内部位置表示的视觉特征，并非对原始 DaViT 特征做无位置信息的纯平均。源码对非四维输入直接抛异常，当前实现只支持单帧。

3.4 文本的 padding 并没有被 mask 掉

语言侧定长 50 个 token（层二，processing_xvla.py 的 language_max_length = 50，且 padding="max_length"）。指令通常远短于 50 个词，其余位置全是 padding。

但拼接时构造的注意力掩码是全 1：

# models/modeling_florence2.py，_merge_input_ids_with_image_features 节选
image_attention_mask = torch.ones(batch_size, image_token_length, device=device)
task_prefix_attention_mask = torch.ones(batch_size, task_prefix_embeds.size(1), device=device)
# concat [image embeds, task prefix embeds]
inputs_embeds = torch.cat([image_features, task_prefix_embeds], dim=1)

而 XVLAProcessor.encode_language 只返回 input_ids，不返回 attention_mask。两者叠加的结果是：文本的 padding token 与真实词元一样参与 Florence encoder 的注意力。

这些 padding 位置没有被结构性地排除：每个位置由 pad token embedding 与各自的一维位置编码组成，经 Florence encoder 后又作为 vlm_features 进入动作主干。模型可能通过动作损失学会降低其影响，但源码并不保证一定忽略。迁移时增大 language_max_length 会增加 padding 位置的计算，并改变 Florence 内部的位置分配、后续辅助视觉段在动作主干中的起始位置，以及预训练时的整体序列布局。

四、两路视觉为什么共享同一个主干

论文 Appendix C 的表述是辅助视角（如腕部视角）用一个共享的视觉主干处理（层一）。固定源码进一步表明：所有有效视角先在批维展平，再由同一次 self.vlm._encode_image 调用处理。这条共享路径不只包含 DaViT，还包含 Florence 的二维图像位置表示、单帧时间位置表示、两种池化、image_projection 与 image_proj_norm。

4.1 源码：一次展平、一次前向

# models/modeling_xvla.py，forward_vlm 节选
B, V = pixel_values.shape[:2]                       # V = num_views = 3
flat_mask   = image_mask.view(-1).to(torch.bool)    # [B*V]
flat_images = pixel_values.flatten(0, 1)            # [B*V, C, H, W]  三路视角展平到同一批

valid_images = flat_images[flat_mask] # 只把有效视角送进去
valid_feats = self.vlm._encode_image(valid_images) # 同一套完整图像编码路径，单次调用
N, D = valid_feats.shape[1:] # N = 50, D = 1024

image_features = valid_feats.new_zeros((B * V, N, D))
image_features[flat_mask] = valid_feats # 无效视角回填为零
image_features = image_features.view(B, V, N, D) # [B, 3, 50, 1024]

也就是说，不存在「主视觉编码器」与「辅助视觉编码器」两个独立模块。三路视角在批维上并排走过同一条 Florence 图像编码路径；分流发生在这条路径输出 50 个图像 token 之后。

4.2 分流发生在哪一步

差异出现在 DaViT 之后：

# models/modeling_xvla.py，forward_vlm 续
inputs_embeds = self.vlm.get_input_embeddings()(input_ids)      # [B, 50, 1024]

merged_embeds, attention_mask = self.vlm._merge_input_ids_with_image_features(
    image_features[:, 0], # 只有第 0 路视角与文本拼接
    inputs_embeds,
)
enc_out = self.vlm.language_model.model.encoder(
    attention_mask=attention_mask, inputs_embeds=merged_embeds,
)[0] # [B, 100, 1024]

aux_visual_inputs = image_features[:, 1:].reshape(B, -1, D) # [B, 100, 1024]
return {"vlm_features": enc_out, "aux_visual_inputs": aux_visual_inputs}
第 0 路视角与文本 token 拼接后进入 Florence 的语言 encoder，因此它的表示经过了 12 层图文融合，携带语言条件。
第 1、2 路视角绕过语言 encoder，以 _encode_image 输出的视觉 token送进动作主干；它们已经经过 Florence 的位置表示、池化、图像投影与归一化，并非裸 DaViT 特征。

所以两路视觉的区别不在前端图像编码器，而在是否继续经过 12 层语言 encoder 做图文融合。 相机顺序因此具有语义：第 0 路是唯一与语言共同进入 Florence encoder 的视角。迁移时应沿用预训练数据的相机排序约定；通常把覆盖工作区的固定视角放在第 0 路更稳妥，但这是一条工程建议，不是架构定理，仍应根据任务和数据分布验证。

4.3 缺失视角被补零，且补零 token 仍参与注意力

视角数固定为 3（层二，processing_xvla.py 的 num_views = 3）。实际相机不足 3 路时，处理器补零并用 image_mask 标记：

# models/processing_xvla.py，encode_image 节选
if V_exist < self.num_views:
    processed = torch.cat(
        [
            processed,
            processed.new_zeros(self.num_views - V_exist, *processed.shape[1:]),
        ],
        dim=0,
    )
image_mask = torch.zeros(self.num_views, dtype=torch.bool, device=processed.device)
image_mask[:V_exist] = True

image_mask 的作用范围到此为止——它只用于决定哪些图像送进 DaViT（省算力），以及把无效位置回填为零。它没有传给动作主干：SoftPromptedTransformer.forward 的签名里没有任何 mask 参数，Attention.forward 里也不接受掩码。

因此缺失视角对应的 50 个占位 token 仍然完整参与 24 层的注意力计算。回填的视觉特征虽为零，但经过带偏置的 aux_visual_proj 和动作主干位置编码后通常不再为零；它们既可能形成可学习的“缺失视角”信号，也会占用注意力计算。

这条的工程含义是：相机路数不足时，补零位置不是“不存在”，而是以占位 token 的形式继续存在。如果训练数据包含足够多的缺失视角样本，模型可能通过动作损失学会降低其影响；源码本身没有掩码保证。只有 1 路相机时，仍有 100 个源自补零视角的占位 token 参与全部 24 层计算，因此应同时评估计算开销与改变预训练序列布局的代价。
另一个边界条件来自有效视角检查：当前 `forward_vlm` 主要检查整个 batch 是否至少存在一个有效视角，并未逐样本保证“每个样本至少一幅有效图像”。数据入口应增加逐样本断言，避免某个样本在同批其他样本有效时仍以全占位视觉特征继续前向。

五、控制流：状态、含噪动作与时间在通道维拼接

5.1 72 维的来历

# models/transformer.py，SoftPromptedTransformer.forward 节选
time_emb       = timestep_embedding(t, self.dim_time)                        # [B, 32]
time_tokens    = time_emb.unsqueeze(1).expand(B, num_actions, self.dim_time) # [B, 30, 32]
proprio_tokens = proprio.unsqueeze(1).expand(B, num_actions, proprio.shape[-1])  # [B, 30, 20]
action_tokens  = torch.cat([action_with_noise, proprio_tokens, time_tokens], dim=-1)  # [B, 30, 72]
x = self.action_encoder(action_tokens, domain_id)                            # [B, 30, 1024]
\[\underbrace{20}_{\text{含噪动作}} \;+\; \underbrace{20}_{\text{本体状态}} \;+\; \underbrace{32}_{\text{时间嵌入}} \;=\; 72\]

默认 EE6DActionSpace 下，源码取 dim_proprio = getattr(action_space, "dim_proprio", dim_action)；由于该动作空间没有单独声明 dim_proprio，状态维度回退为 dim_action = 20。官方预处理约定使默认状态与动作都使用 20 维表示，但“维度相等”本身不等于任意自定义状态都具有相同语义。尤其要注意，AutoActionSpace 会把动作补齐到统一维度，却不会自动把任意 proprioception 补齐为 20 维；接入新数据时必须单独核对状态布局。

5.2 为什么状态与时间不占独立 token 位

它们被 expand 广播到全部 30 个动作位置，与含噪动作在通道维拼接，而不是各自做成一个 token。三个后果：

序列不变长控制流只贡献 30 个 token。若把状态与时间各做成一个 token，序列会变成 32，且需要额外处理它们与动作 token 的关系。
每个动作位置都直接看到条件不依赖注意力去取。时刻 t 对去噪目标是逐位置同等重要的，广播比让模型自己去 attend 更直接。
与 π0 的做法不同π0 把机器人状态单独做成一个 token 放进 suffix。两种做法都可行，但形状与迁移改动点完全不同。

5.3 时间嵌入：正余弦频率尺度 100，没有额外 MLP

# models/transformer.py
def timestep_embedding(t: torch.Tensor, dim: int, max_period: int = 100) -> torch.Tensor:
    half  = dim // 2
    freqs = torch.exp(-math.log(max_period)
        * torch.arange(start=0, end=half, dtype=t.dtype, device=t.device) / half)
    args      = t[:, None] * freqs[None]
    embedding = torch.cat([torch.cos(args), torch.sin(args)], dim=-1)

对默认的 dim_time = 32，共有 16 个角频率：

\[\omega_i = 100^{-i/16}, \qquad i=0,\ldots,15\]

对应嵌入为：

\[e(t)= [\cos(t\omega_0),\ldots,\cos(t\omega_{15}), \sin(t\omega_0),\ldots,\sin(t\omega_{15})]\]

max_period=100 是控制频率指数衰减的尺度参数，不是所有通道共同的“周期 100”。第 \(i\) 个通道对应的周期是 \(T_i=2\pi/\omega_i\)；对训练使用的 \(t\in[0,1]\)，这些通道都不会走完一个完整周期。

三个实现细节需要分开理解：

  • 100 而不是常见的 10000。 较小的尺度使低频通道在 \([0,1]\) 内变化得更明显；论文没有给出两种取值的消融，因此不能据此断言 10000 必然浪费维度。
  • 先放全部 cos，再放全部 sin。 原始 Transformer 位置编码通常按维交错放置 sin/cos，这里采用分块拼接。后续线性层可以吸收固定维度置换，但逐通道对比其他实现时不能直接对齐。
  • 没有额外 MLP 或 SiLU 投影。 32 维向量直接与动作、状态在通道维拼接，再统一进入 action_encoder。这不同于用时间 MLP 产生 AdaLN 参数的 DiT 路线。

把标量映射成多频率向量的思想与 Transformer 的位置编码同源，但这里编码的是连续去噪时刻，而不是序列位置。

六、DomainAwareLinear：把整张权重矩阵存进 embedding 表

6.1 实现

# models/transformer.py
class DomainAwareLinear(nn.Module):
    def __init__(self, input_size, output_size, num_domains=20):
        super().__init__()
        self.input_size = input_size
        self.output_size = output_size
        self.fc   = nn.Embedding(num_domains, output_size * input_size)   # 整张权重矩阵存成一行
        self.bias = nn.Embedding(num_domains, output_size)
        nn.init.xavier_uniform_(self.fc.weight); nn.init.zeros_(self.bias.weight)

    def forward(self, x, domain_id):
        B = domain_id.shape[0]
        squeeze_T = False
        if x.dim() == 2:
            x = x.unsqueeze(1)
            squeeze_T = True
        W = self.fc(domain_id).view(B, self.input_size, self.output_size)   # 逐样本取权重
        b = self.bias(domain_id).view(B, self.output_size)
        y = torch.matmul(x, W) + b.view(B, 1, self.output_size)
        if squeeze_T:
            y = y.squeeze(1)
        return y

签名里的 num_domains=20 是源码缺省值，本页核验的 X-VLA-Pt checkpoint 实际配成 30（层二，config.json）。本页第十一节与下表按该 checkpoint 的 30 个槽位计算，两个数字对应不同口径。

还有一个容易忽略的初始化细节：xavier_uniform_ 一次作用于形状为 [num_domains, output_size * input_size] 的整张 embedding 表，而不是分别作用于每个重塑后的线性矩阵。按 30 槽位计算，动作输入表的 Xavier 均匀分布边界约为 ±0.0090；若把每个 [1024,72] 线性层独立初始化，标准边界约为 ±0.0740。动作输出表对应约 ±0.0171，而逐域独立线性层约为 ±0.0758。源码因此采用了明显更窄的初始权重范围；论文没有消融这一选择，不能把它解释成已经验证过的稳定性来源。

它被用在两处（层二）：

模块 形状变换 每槽参数量 30 个槽位合计
action_encoder 72 维到 1024 维 74,752 2,242,560
action_decoder 1024 维到 20 维 20,500 615,000

图文与辅助视觉两路的投影默认不用它：本页核验的 X-VLA-Pt checkpoint 中 use_hetero_proj=false，两路均走普通的 nn.Linear(1024, 1024)。不能在未逐个核验其他权重的情况下把这一配置推广为“全部已发布 checkpoint”都相同。

6.2 为什么不用 nn.ModuleList

直觉的写法是 nn.ModuleList([nn.Linear(...) for _ in range(num_domains)])，再按域选择模块。这并非做不到混合域训练，但实现路径不同：

nn.ModuleList 不能用一个 domain_id 张量直接完成逐样本模块索引；混合 batch 通常需要按域分组、分别调用相应模块，再把结果恢复到原顺序。这样可行，但代码和调度更复杂。

nn.Embedding 支持张量索引。self.fc(domain_id) 一次取回 [B, out * in]，重塑为 [B, in, out] 后用 torch.matmul 批量计算，于是每个样本可在一次向量化前向中使用自己的矩阵。

DomainAwareLinear 因此是支持混合域 batch 的一种高效向量化实现，不是均衡采样在数学上成立的前提。改用按域分组的 ModuleList 或其他 batched-weight 实现，仍可执行同一采样策略；区别主要在工程复杂度和计算效率。采样策略本身见子页 ④。

代价是显存：权重矩阵与偏置都按数据源复制。对 action_encoder 而言，权重有 \(30\times72\times1024=2{,}211{,}840\) 个参数，偏置另有 \(30\times1024=30{,}720\) 个，总计 2,242,560；即使预训练映射只使用 7 个槽位，发布 checkpoint 仍存储全部 30 行。

七、序列拼装与全链路张量形状

7.1 逐步形状追踪

以下按 batch size 为 \(B\)、三路视角全部有效、单帧输入推算。每一行都可以对着源码独立复算。

\[L_{\mathrm{pre}} = T_a + L_t + V N_v\] \[L_{\mathrm{total}} = L_{\mathrm{pre}} + L_p\]

\[L_{\mathrm{pre}} = 30 + 50 + 3\times50 = 230, \qquad L_{\mathrm{total}} = 230 + 32 = 262\]

# models/transformer.py，forward 节选
seq_len = x.shape[1]
if seq_len > self.pos_emb.shape[1]:
    raise ValueError(f"Sequence length {seq_len} exceeds max_len_seq={self.pos_emb.shape[1]}.")

7.2 X-VLA 动作主干的位置编码只覆盖前三段

# models/transformer.py，forward 节选
x = x + self.pos_emb[:, :seq_len, :]          # seq_len 此时是 230，提示段尚未拼上

# Append soft prompts

if self.len_soft_prompts > 0:
    soft_prompts = self.soft_prompt_hub(domain_id).view(B, self.len_soft_prompts, self.hidden_size)
    x = torch.cat([x, soft_prompts], dim=1) # 提示段拼在加完位置编码之后

这里需要区分代码事实与解释：

  • 代码事实：prompt 没有外层绝对位置编码。 在关闭 dropout 的确定性前向中，当前结构又没有注意力掩码和位置相关 bias，并且只解码普通 token，因此共同置换 32 行 prompt 不会改变普通 token 的输出；动作主干更接近把它们当作一个无序提示集合。训练态的逐元素 dropout 会破坏单次前向的严格等价，但随机分布仍保持这种置换对称性。
  • 不能推出“不加位置编码就是类型标记”。 Transformer 只看到最终向量，无法观察某次加法是否发生；在没有位置 bias 或掩码时，“位于序列末尾”也不是可直接读取的类型信号。模型能利用的是 prompt 自身可学习的内容分布，而“缺少位置编码”本身不是显式标签；这种集合式设计是否优于带位置编码的 prompt，仍需要消融验证。

还要注意，本节只讨论 X-VLA 动作主干的外层位置编码。视觉 token 在 Florence 内部已经获得二维图像位置、temporal embedding；主视角与文本进入 Florence encoder 时还会获得一维序列位置编码。

八、主干：24 层最朴素的 pre-LN block

8.1 源码与逐项参数

# models/transformer.py
class TransformerBlock(nn.Module):
    def __init__(self, hidden_size, num_heads, mlp_ratio=4.0):
        self.norm1 = nn.LayerNorm(hidden_size)
        self.norm2 = nn.LayerNorm(hidden_size)
        self.attn  = Attention(hidden_size, num_heads=num_heads, qkv_bias=True, attn_drop=0.1)
        self.mlp   = Mlp(in_features=hidden_size, hidden_features=int(hidden_size * mlp_ratio), drop=0.1)

    def forward(self, x):
        x = x + self.attn(self.norm1(x))
        x = x + self.mlp(self.norm2(x))
        return x

注意力头数 16 num_heads，每头 64 维

归一化位置 pre-LN 先归一化再进子层，残差走原始通路
注意力权重 dropout 0.1 attn_drop=0.1
注意力输出 dropout 0.0 proj_drop 未传值，沿用缺省 0.0

这是典型的 ViT 风格 pre-LN encoder block。 原始 BERT 更常被归为 post-LN，因此不宜把二者并列成完全相同的标准结构。该 block 没有 AdaLN 调制、交叉注意力、按 token 类型分路的专家权重或 RoPE。

8.2 刻意不用 AdaLN，论文给了数值

DiT 类结构处理条件信息的常见做法是 AdaLN：把条件向量经 MLP 变成每层归一化的缩放与偏移参数。X-VLA 没有走这条路：时刻 \(t\) 与本体状态进入动作 token 的通道内容；数据源信息一方面进入 Soft Prompt，另一方面选择域专属动作输入/输出投影。准确结论是“没有用 AdaLN 做逐层调制”，而不是所有条件都只以同一种内容 token 形式进入。

X-VLA（本文） 0.041

Appendix I 说明这组前期架构探索采用 Florence-Base 与 12 层、768 隐藏维的 DiT-Base 级设置；它不是发布版 24 层、1024 隐藏维模型上的逐项严格消融。

在论文所测试的同一设置中，X-VLA 标准 encoder 的验证误差最低；MM-DiT 的 0.140 则高于 DiT 的 0.077。该表支持“在这组架构探索设置下，简单共享 encoder 更有效”，但不是标准 encoder 普遍优于 AdaLN/MM-DiT 的定理，也不能仅凭四个数值确定唯一原因。论文把 MM-DiT 的较差表现与训练不稳定联系起来，应保留为作者的实验解释。

结构简单确实降低了扩展主干的复杂度，但“加数据、参数或本体完全不用改代码”仍然过强：新增视角、域槽位、动作空间或 prompt 长度都可能要求修改配置、迁移查表权重和重算序列容量。更稳妥的概括是：X-VLA 尽量把域差异放进输入条件与边界投影，保持 24 层共享主干同构。

8.3 双向全注意力，不加任何掩码

# models/transformer.py，Attention.forward 签名
def forward(self, x):          # 没有 attn_mask、没有 key_padding_mask
    ...

注意力函数不接受任何掩码参数。后果有三：

  • 动作 token 之间完全互见。动作块是一次性整体生成而非逐步自回归，块内因果掩码没有必要。
  • 条件 token 也能看到动作 token。信息是双向流动的，这与 π0 的 prefix 单向流向 suffix 不同。Florence/DaViT 特征在 generate_actions 中会先计算一次并跨去噪步复用；不能缓存的是 24 层动作 Transformer 内部的条件表示，因此每一步仍要重算完整 262-token 动作主干。较短序列可能缓解开销，但页面没有实测数据，不把它写成已经证明的抵消关系。
  • 缺失视角占位与文本 padding 都参与注意力。第 4.3 节与第 3.4 节分别说明了这一点。它们确实增加计算，但也可能被模型利用为固定占位模式；在没有消融前，不把其语义作用直接判定为“纯浪费”。

掩码如何改变可见性、以及缩放点积注意力本身的机制，见注意力机制。

九、输出端：只解码前 30 个 token

# models/transformer.py，forward 最后一行
return self.action_decoder(self.norm(x[:, :num_actions]), domain_id)

三个要点：

  • 只有动作段被输出头直接解码。 其余 232 个位置没有逐 token 的语言或视觉辅助损失，但会通过双向注意力影响动作位置，因此动作损失仍会反向传播到图文 token、辅助视觉 token、Soft Prompt 及其上游模块。
  • 末尾还有一次 LayerNorm。 每个 pre-LN block 只在进入注意力或 MLP 前归一化；最后一层的残差和不会自动再经过归一化。因此源码在动作读出前显式执行一次 LayerNorm，但论文没有单独消融它的必要性或收益。
  • 输出的是干净动作块，不是速度场。 形状 [B, 30, 20]，与真值动作同形。这与论文正文的 Flow Matching 表述不同，是本专题最需要注意的一处分歧，完整说明见子页 ③ 与枢纽页第七节。

十、与 π0 架构的逐项对照

两者同属「预训练视觉语言主干加连续动作生成」路线，但结构组织几乎每一项都不同。下表的 π0 数值来自站内 π0 架构页所固定的 OpenPI 实现与配置，而不是 π0 方法的永久常数；两列输入布局不同，也不能把 262 与约 867 当成同条件速度基准。

维度 π0（站内专页固定 OpenPI 实现） X-VLA（本页固定实现）
视觉语言主干 PaliGemma（SigLIP 加 Gemma） Florence-2 Large，decoder 与 lm_head 被删
视觉 token 数 每路 256 每路 50（1 个全局摘要加 49 个空间位置）
相机路数 3 路，不足时补零 3 路，不足时补零
辅助视角处理 与主视角同等，全部进主干 复用 Florence 图像编码路径，绕过语言 encoder
动作侧参数 独立的动作专家，一套完整权重 无专家分支，只有输入输出两个私有投影
状态注入 单独一个 token 广播到 30 个动作位置，通道维拼接
时间注入 与动作拼接后过 MLP 正余弦直接参与通道拼接，无 MLP
条件化方式 分块因果掩码控制信息流向 提示 token 加入序列，无掩码
注意力 prefix 与 suffix 分块因果 全序列双向
KV 缓存 prefix 可跨去噪步复用 Florence/DaViT 特征可复用；24 层动作主干每步重算
序列长度 约 867 262
输出 50 步原始动作 30 个锚点；对应物理时长由域处理器决定

公开预训练代码包含 AGIBOT、Droid、RoboMind 三个数据族处理器，它们都设 qdur=4.0 秒，并覆盖表 8 的 7 个预训练域；因此“4 秒”是这组数据处理配置，不是 num_actions=30 自动决定的架构常数。处理器在 episode 尾部还会把查询终点截到现有参考时间，实际覆盖时长可能短于 4 秒。接入新域时，30 个锚点可以映射到不同物理时长，必须与控制频率和插值规则一起定义。

一句话概括结构上的差异：π0 用「掩码与专家权重」在一个序列内部划分角色，X-VLA 用「内容、Soft Prompt 与域专属边界投影」区分角色，24 层动作主干保持同构共享。π0 的 prefix 设计提供动作主干内的缓存机会；X-VLA 则用更均质的结构换取实现简洁。262 与约 867 的长度只能帮助判断计算量级，不能单凭长度断言一种方案已完全抵消另一种方案的缓存优势。

十一、迁移到自己的配置时要检查什么

本节只列结构相关的改动点；训练配置与部署流程分别见子页 ④ 与 ⑥。

11.1 相机、动作与域槽位

  • 先确认第 0 路视角的语义。只有它会与语言一起进入 Florence encoder。应优先沿用预训练数据的相机排序；把覆盖工作区的固定视角放在第 0 路通常更稳妥，但不是对所有任务都成立的硬规则。
  • 超过 3 路不会被安全地静默截断。官方处理器只实现了“不足时补零”，没有实现“超出时截断”。直接传入多于 num_views 的图像，会使图像张量与固定长度 image_mask 不一致，通常在堆叠或布尔索引时报错。若要增加相机，必须同步修改处理器、输入收集逻辑，并重算序列长度。
  • 少于 3 路会保留占位 token。只有 1 路相机时，仍有 100 个源自缺失视角的占位 token 进入 24 层动作主干；它们经投影偏置和位置编码后通常不再为零。减小 num_views 可以省计算，但会改变预训练时的序列布局，需要重新适配。
  • 动作与状态维度要分别核对。默认控制输入为 20 维动作、20 维 proprioception 和 32 维时间嵌入，共 72 维。更换动作空间会改变域专属输入/输出投影；AutoActionSpace 对动作的补齐也不能替代对 proprioception 形状与语义的检查。
  • 扩充域槽位不等于重置旧域。把 num_domains 从 30 调大，会改变私有查表张量形状，旧 checkpoint 通常不能直接严格加载。稳妥做法是新建更大的表、复制已有行，只初始化新增行；同时保持既有 domain_id 到权重行的映射不变。默认配置涉及 Soft Prompt、action encoder 和 action decoder 三个逻辑模块，底层共有 5 张 embedding 表：prompt 一张，输入/输出投影各含权重与偏置两张。
  • 改图像尺寸要计算完整序列。若视觉塔接受 448 输入，并仍按总步长 32 下采样，则每路为 14×14+1=197 个视觉 token。三路时 L_pre=30+50+3×197=671，已经超过 512 的外层位置编码容量；再加 32 个 prompt 后，真实注意力长度为 703。不能只拿 591 个视觉 token 与 512 比较。

用默认的每路 50 个视觉 token，追加 prompt 前的长度是：

\[L_{\mathrm{pre}}=30+50+50V=80+50V\]

因此默认位置编码容量最多覆盖 8 路视角（\(L_{\mathrm{pre}}=480\)）；9 路时为 530，才会触发当前的 512 上限。这个算术上限不代表现有处理器已经支持 8 路，相机输入和 mask 仍需同步改造。

11.2 三个容易误用的配置项

配置项 当前源码中的真实作用 修改风险
use_proprio 构造函数会保存该字段，但当前前向路径仍要求并拼接 proprioception 设为 false 不会自动关闭状态输入；若要移除，需修改前向签名和输入投影维度
len_soft_prompts / soft_prompt_length 实际传给动作 Transformer 的是 len_soft_prompts；后者当前未接入这条建模路径 改错字段不会生效；改变有效长度会改变 prompt 权重形状和真实注意力长度
use_hetero_proj 本页核验的 checkpoint 为 false，图文与辅助视觉投影使用共享 nn.Linear 切到 true 会改成域专属查表，state dict 键与形状都变化，不能当作无损开关

len_soft_prompts=0 会在模型构造与前向中取消 prompt；但官方 train.py 的优化器分组仍会无条件访问 soft_prompt_hub，直接用该训练脚本会报属性错误，必须同步修改优化器分组。prompt 长度虽然不参加 max_len_seq 的前缀越界检查，仍会增加总序列长度和近似平方增长的注意力计算。若把共享视觉投影迁移为域专属投影，不能只切换布尔配置：nn.Linear.weight 的形状是 [out, in]，而 DomainAwareLinear 查表后按 [in, out] 使用，因此复制到各域前需要转置权重，并单独迁移偏置。
