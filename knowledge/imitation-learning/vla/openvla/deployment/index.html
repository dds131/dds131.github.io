DEPLOYMENT · BASE-7B · SINGLE-STEP ACTION

模型输出不等于可执行动作。OpenVLA 候选策略必须依次通过 artifact、input、output、timing、embodiment 与 safety 六道拒绝门，才可进入指定实验协议。

结论：部署是一串拒绝门

OpenVLA 部署不是“载入权重并调用 predict_action”，而是依次证明制品、输入、动作、时序、本体和安全合同都满足。任何门缺失时只能启动失败、请求拒绝、动作丢弃或进入已定义 fallback，不能猜测。

  1. Artifact · checkpoint/processor/config/stats/hash
  2. Input · camera/color/transform/prompt
  3. Output · token count/range/dim/finite
  4. Timing · deadline/action age/queue
  5. Embodiment · frame/unit/controller
  6. Safety · envelope/watchdog/operator
门 必须冻结 失败动作
Artifact checkpoint、processor、config、stats、hash、version 启动失败
Input camera、color、transform、prompt、instruction 请求拒绝
Output token count/range、dim、finite、unnorm 动作拒绝
Timing deadline、action age、queue、control schedule 丢弃并 fallback
Embodiment frame、unit、delta/absolute、gripper、controller 禁止下发
Safety workspace、speed、force、watchdog、operator 独立安全停止

Training 入站与制品完整性

Training 交付的是候选制品血缘，不授予 inference-ready、robot-ready、safe 或 production-ready。权重没有 SHA-256、processor/config/tokenizer/stats 不同包、依赖写 latest、停止依据缺失、远程代码 revision 未审计，任一情况都保持 handoff-incomplete。

闭环状态为空却标记 robot-ready 也是入站失败。完整模型权重不等于完整 bundle；adapter、统计量、prompt 或 processor 任一变更都必须产生新的 bundle identity 与 hash。

微调策略怎么选

论文策略 更新范围 固定 finetune.py 是否直接提供
Full FT 全部参数 非 LoRA 路径为全量更新
Last layer only 最后一层 + token embedding 否，需另行冻结实现
Frozen vision 冻结视觉，其余更新 否，不能虚构脚本开关
Sandwich 视觉 + token embedding + 最后一层 否，需另行实现
LoRA 所有线性层低秩适配 是；论文建议从 r=32 起

固定脚本还提供要求 LoRA 的 4-bit NF4、BF16-compute QLoRA 分支；它与 Table 1 的 LoRA 不是同一实验条件。选择顺序应先验证数据与动作合同，再在同一 split、trial、seed、controller 与安全协议下比较适配容量，不能只按 VRAM 选方法。

default_candidate: lora-r32
decision_order: [verify-data-and-action-contract, establish-full-or-published-baseline, test-lora-r32, compare-under-same-rollout-protocol, escalate-capacity-only-after-diagnosis]
quantized_lora:
  label: qlora-4bit-nf4-bf16
  separate_from_table1_lora: true
  target-task-reevaluation: required
forbidden: [select-by-vram-alone, compare-different-model-variants-as-equal, claim-r64-better-from-equal-point-estimates]

制品打包与统计量单一真源

权重、processor、tokenizer、config、statistics 与 manifest 必须属于同一 bundle_id，每个文件和 bundle 都有 SHA-256。运行时不得从另一个可变 Hub 路径补文件，也不得只替换 adapter 而不更新统计与 lineage。

schema: openvla.normalization-artifact.v1
artifact_id: required
sha256: required
source_dataset_key: required
unnorm_key: required
action_dim: required
dimension_order: required
q01: required
q99: required
mask: required
units: required-by-embodiment-binding
coordinate_frame: required-by-embodiment-binding
delta_or_absolute: required-by-embodiment-binding
config_norm_stats_sha256: required
sidecar_norm_stats_sha256: required
hashes_must_match: true

加载后必须从运行中模型读回 key 集、所选 key 的 action dimension、q01/q99/mask 与 config stats hash，再和 sidecar 及 binding 比对。存在但错误的 unnorm_key 比不存在更危险：它可能正常返回数组，却使用错误尺度与语义。hash、维数或 dimension order 不一致时启动失败，不允许选择“最近的 key”或首个 key。

固定 finetune.py 的部署相关事实还包括：LoRA 默认 r=32、dropout 0、all-linear；4-bit 路径为 NF4/BF16 compute；statistics 另存 dataset_statistics.json；adapter 保存后重新加载基座再合并；公开路径未显式固定 Hub revision，且保存包不含 optimizer、scheduler、RNG 与数据位置。

schema: openvla.finetune-to-deployment-risk.v1
fixed_commit: c8f03f48af692657d3060c19588038c7220e9af9
risks:
  - {id: mutable-base-revision, source: from-pretrained-without-revision, gate: resolved-model-sha-required}
  - {id: stats-sidecar-divergence, source: dataset-statistics-json-vs-config-norm-stats, gate: canonical-stats-hash-required}
  - {id: incomplete-resume-state, source: no-optimizer-scheduler-rng-data-position, gate: label-as-inference-snapshot}

固定 revision 的模型加载

processor、model、LoRA 合并基座与 trust_remote_code 必须绑定同一固定 revision 31f090d05236101ebfc381b61c674dd4746d4ce0，并记录实际解析 SHA；remote implementation files 进入 SBOM。不能依赖 tag、branch 或 mutable main。

schema: openvla.model-loading-contract.v1
model_id: openvla/openvla-7b
model_revision: 31f090d05236101ebfc381b61c674dd4746d4ce0
processor_revision_must_equal_model_revision: true
lora_merge_base_revision_must_equal_model_revision: true
trust_remote_code: audited-fixed-revision-only
resolved_revision_recorded: true
artifact_hashes_verified_before_load: true
required_runtime_manifest: [pytorch, cuda, transformers, tokenizers, timm, flash-attn, dtype, attention-implementation, device]

固定 HF port 的依赖口径包括 Transformers 4.40.1、tokenizers 0.19.1，timm 允许 0.9.10/0.9.11/0.9.12/0.9.16；版本提示不是兼容性测试。CUDA + bf16 + compatible attention 只能成为验证候选；CUDA int4 要独立闭环复验。代码存在 CPU device 分支不等于 CPU + 默认 FlashAttention 2/bf16 已验证。OOM 后也不能静默降精度，必须换 manifest 后显式重启。

图像、prompt 与动作 ABI

基线 Pure In/Out 模板精确为：

In: What action should the robot take to {instruction.lower()}?
Out:

它只属于 openvla/openvla-7b 基线；v01 使用不同 Vicuna 风格模板，生产 wrapper 不能靠路径字符串是否包含 v01 猜测。

schema: openvla.inference-input.v1
camera_order: [third_person_rgb]
history_length: 1
color_space: RGB
dtype_before_processor: uint8
shape: HxWx3
image_transform_id: required
processor_revision: required
crop_resize_policy: processor-bound
instruction: {encoding: utf-8, empty_allowed: false, normalization: lowercase, max_bytes: deployment-required}
prompt_template_id: pure-in-out-v1
request_timestamp: required
request_id: required

图像 shape/dtype/range/color、相机序号/时间戳、instruction 编码/长度、processor revision、template ID 或 freshness 任一不符，请求直接拒绝。

动作 token、反归一化与拒绝式 ABI。固定 predict_action() 先从统计量取得维数 D，调用 generate(max_new_tokens=D)，截取序列最后 D 个 ID，再反向映射、clip bin index 并用 q01/q99 反归一化。它没有证明“新生成恰好 D 个合法动作 token”；异常 ID 经 clip 可能静默落到端点，所以生产 wrapper 必须先验证、后解码。

schema: openvla.action-validation.v1
order:
  - generation-finished-before-deadline
  - exact-new-token-count
  - every-token-in-legal-action-range
  - selected-unnorm-key-exists
  - action-dimension-matches-binding
  - decode-without-prevalidation-clipping
  - every-value-finite
  - units-and-frame-bound
  - deterministic-envelope-check
  - action-age-within-budget

吞吐、延迟与控制时序

throughput 是稳态单位时间完成的动作数；request latency 是服务接收至响应；action age 是相机曝光至动作实际执行的年龄。三者不能互换。端到端预算至少覆盖：

T_e2e = T_capture + T_encode + T_upload + T_queue + T_preprocess + T_inference + T_download + T_validate + T_dispatch。

论文正文报告 RTX 4090、bf16 约 6 actions/s。这是特定实现/硬件的吞吐，不是 p50/p99；倒数约 167 ms 仅在 batch=1、稳态、串行、无队列且口径可近似时成立。5 Hz 周期 200 ms 的名义 33 ms 差额不是安全余量；15 Hz 周期约 66.7 ms，不能要求基线每周期产生新动作。

独立安全层与 fallback

VLA 只能提出 candidate action。workspace、joint/Cartesian、velocity/acceleration/jerk、force/torque/collision、emergency stop、watchdog、operator takeover、fallback 与 actuation interlock 均由模型外的独立层拥有，模型不可覆盖。

fallback 必须写明触发条件、命令语义、执行层、完成确认、更高等级停止、恢复条件与 owner。对 delta 控制，重复上一动作通常会累计位移，不能作为默认 fallback。输入漂移、invalid token 或 latency anomaly 可作 OOD 辅助信号，但不能替代确定性安全层；输出 clamp 也不是独立安全控制器。
