部署安全与验证证据

OpenPI RTC + DAgger RM75 的安全主张、故障响应、证据等级、真机门槛与 A/B 统计协议

项目概览 架构与接管 纠正数据 数据与训练 安全与验证 工程迭代 论文与路线
SAFETY CASEEVIDENCE LADDERNO AUTO START

安全机制、测试证据与残余风险必须分别陈述。

默认不动、单一命令通道、运动约束、故障监测与可回滚部署共同降低风险；它们不能替代整机风险评估、经验证的物理急停或受控真机试验。

一、先建立“主张—机制—证据—残余风险”

只列功能清单不足以构成安全论证。每个主张都要有可触发的机制、可复查的证据，以及明确未覆盖的风险。

安全主张 主要机制 真机前必须看到的证据 仍然存在的残余风险
未显式开始前不应产生运动命令 IDLE 默认态、启动门、保持参考 冷启动与异常重启测试；发送计数为零或仅有明确定义的保持命令 驱动器残留命令、外部写者或硬件故障
任一时刻只有一个软件路径写硬件 RTC/VR 只产候选参考，单一 send_tick 下发 并发注入测试、写入线程标识和命令序号连续 绕过主进程的外部工具或独立控制器
被接受命令满足配置的运动边界 关节限位、限速/限加速度、奇异区策略、夹爪单通道 边界值与故障注入测试；发送前后命令日志可对照 环境碰撞、模型误判、限制参数配置错误
陈旧或非法输入不能继续驱动新策略动作 时间戳/序号、watchdog、NaN/Inf 检查、超时状态 冻结相机、延迟推理、VR 断连和控制周期超限测试 停止方式自身的制动距离和硬件响应
数据与模型更换可追溯、可回滚 schema verify、manifest、临时落点、独立加载 artifact 摘要、配置与回滚演练 它是运维/学习质量保障，不是即时物理防护

最后一项很重要，但不应与物理安全功能混为一谈：坏数据会让后续策略退化，数据闸降低长期学习风险；它不能在本次运动中阻止碰撞。

二、五层防线分别解决什么

L1 · SESSION

会话授权

IDLE 默认不动；显式开始；非法相位操作拒绝；接管与交还都走完整协议。

L2 · OWNERSHIP

控制权与单写者

AUTO 与 TELEOP 只切换参考来源，不能各自拥有硬件发送线程。

L3 · MOTION

运动边界

插值、限位、限速/限加速度、奇异区策略和夹爪门控约束已选命令；仍需实机验证参数与制动距离。

L4 · WATCHDOG

故障监测

观测陈旧、推理超时、非有限值、VR 断连和周期超限必须进入预定义的保守状态。

L5 · DATA / OPS

数据与运维

录制门、schema verify、模型独立加载、版本化切换和成套回滚保证可审计性。

安全不是一个 speed_scale。降低速度通常能减小动能和给操作员更多反应时间，但不能消除双写者、错误坐标系、失效 watchdog、碰撞路径或错误 checkpoint 带来的风险。

本页也不声称符合任何安全标准或取得认证。工业机器人本体与集成应用分别有专门要求；项目级软件检查表只能作为风险评估输入，不能替代合格人员对整机、工作站与应用的评审。

三、停止、急停、Home 与退出是五种不同语义

操作 目的 正确边界
soft stop 从 RTC 运动过渡到可接管的稳定状态 拒绝新块、让旧块失效、切换到保持参考，再由状态化限制器减速；不是瞬时零速度
软件故障停止 发现超时、非有限值或内部异常后进入定义的故障状态 反应时间和最终状态必须通过故障注入测试；不能自动等同于物理急停
物理急停 在紧急情况下由独立、经验证的硬件安全功能降低风险 具体停止类别与复位流程以机器人/控制柜和现场风险评估为准；主程序不得冒充该功能
Home 在条件允许时执行到已知姿态的主动运动 只有清错、确认路径和人员退出危险区后才能发起；Home 不是安全状态，也不是急停
正常退出 有序停止线程、阻止新命令、处理临时记录并释放资源 Ctrl+C 只有在确定被可靠信号处理器捕获时才可能触发该流程；强杀进程可能绕过清理

物理急停的优先级高于数据保存。急停复位后也不能自动恢复运动；应重新确认状态、控制权和启动条件。

四、验证阶梯：历史记录不等于本轮复验

测试层 需求文档中的状态 本轮审计状态 能证明 不能证明
FSM / mock VR 已记录通过 未复跑 在记录所对应版本上，相位、门控与乱序处理曾通过用例 真 VR 键值、线程时序和动力学
导入与模块自测 已记录通过 未复跑 当时的依赖链与指定模块可加载 长时间稳定性与当前环境仍一致
自动化 dry-run 已记录通过 未复跑 当时的 RTC→接管→录制→保存→复位软件流连通 真实机械臂跟踪、制动和碰撞风险
转换与传输 已记录通过 未复跑 指定样例的 schema 与归档摘要曾一致 新一批数据语义正确或分布有效
聚合/训练冒烟 已记录通过 未复跑，且训练侧不在本机挂载 接口曾能更新并写出 checkpoint 收敛、泛化、旧技能保持或真机收益
真 VR / 低速真机 待执行 待执行 完成后可验证键值、离合方向、故障响应与保守运动边界 多轮训练收益与分布外安全
完整闭环评测 待执行 待执行 完成后可比较预注册条件内的任务指标 未测试场景的保证或安全认证

任何“通过”都应绑定：代码版本、配置摘要、环境/设备标识、测试输入、预期结果、实际日志、日期和执行者。没有这些 artifact 的状态更准确地说是“历史记录声称通过”，而不是可独立复核的证据包。

五、真机前门槛与故障注入

风险与工作区核查

确认机器人/控制柜手册、急停与复位流程、工作区隔离、载荷和环境碰撞风险；设备空闲且没有外部写者。

VR 键值核对

只读打印 A/B/X/Y、Grip、Trigger 和摇杆值，确认 SDK 映射、去抖和阈值；不能从文档名称猜测。

无执行器 dry-run

不使能机械臂和夹爪，验证离合方向、IK、Grip 门控、超时与误按提示。

故障注入

模拟相机冻结、推理超时、VR 断连、NaN/Inf、控制周期超限和日志/磁盘故障，核对预定义响应。

低速短窗口真机

由用户手动发起；限制工作区、速度和单次运动时长，确认物理急停有效并由专人监护。

数据与模型验收

保存后验证数据；新 checkpoint 先做固定输入与离线回放，再进入受控闭环。

故障响应必须按故障类型定义，不能全部写成“继续保持”：控制命令非有限值、关键观测陈旧或单写者不变量被破坏时，应禁止新的策略动作并进入经现场验证的保守停止流程；日志或数据落盘失败则不应阻塞实时发送线程，但必须停止录制、显著告警并按运维策略决定是否结束会话。

定向复现失败状态的额外门槛

把机器人和工件直接复现到已知失败附近可以提高采集效率，但“复现失败”本身也是一次有风险的初始化操作，不能在 RTC 仍运行或旧动作仍可能下发时摆放。

  • 先结束自主会话，使新推理、旧动作队列和在途结果全部失效；确认唯一发送链处于经验证的保持/停止状态。
  • 工件只在机器人稳定且不会意外运动时摆放；机械臂姿态应通过设备手册和现场风险评估允许的示教/拖动/点动方式到达，不能默认带电手推安全。
  • 为每个失败模板保存关节状态、夹爪、工件位姿、相机画面、接触状态和初始化方法；仅靠“看起来一样”无法复现速度、力、控制器内部状态或 RTC 观测历史。
  • 使能后的第一段运动采用受限速度、受限工作区和短时间窗，由监护人观察碰撞间隙并准备物理急停；先空载/无接触验证，再采正式恢复段。
  • 若真实失败依赖滑动、碰撞后回弹、夹持力或队列时序，静态摆放样本只能标为近似复现；仍需在线 DAgger 样本验证其分布代表性。

这套门槛不会把定向复现变成严格 DAgger；它只是让高吞吐恢复采集具有明确的安全边界和 provenance。

六、可观测性要回答“发生了什么”和“证据在哪里”

运行时

  • 相位、控制源、Grip/Arm、队列 epoch 与命令序号
  • 观测年龄、推理延迟、发送周期和超限计数
  • watchdog、限位、限速和故障状态的触发原因
  • 日志必须异步/有界，不能反向阻塞控制线程

数据与模型

  • episode 来源、fps、相机、帧数和有效窗口数
  • 转换/聚合 manifest 与 schema/统计摘要
  • 训练起点、配置、seed、trainable 参数数和 artifact 摘要
  • 部署版本、启动配置、回滚版本与加载结果

仪表板颜色或“RUNNING”文字不是安全证据；它们必须来自与实际仲裁/发送状态同源的数据，并能链接到时间戳一致的日志。

真机边界：页面不提供内部连接信息或可直接复制的一键真机命令。真机运动必须由用户手动发起，先完成风险核查、无执行器 dry-run 与故障注入，并始终以现场物理安全措施为最高优先级。

七、效果评测必须分成两种协议

“零接管 A/B”与“统计接管次数”若写在同一协议里会自相矛盾，应拆开：

  1. 安全辅助试验：允许监护人接管或急停。记录“需要接管”的 trial 数、首次接管时间、接管次数、急停/软件停止与失败类别。被接管后由人完成任务的 trial 不能计作策略独立成功。
  2. 固定无辅助 A/B：基线与新 checkpoint 使用同一任务清单、初始条件、物体布局、速度和 RTC 参数。任何人工接管、安全停止或超时均按预先规则记为失败/中止，不再由人完成后改记成功。

每个 trial 记录 checkpoint 摘要、场景/seed、成功、接管、停止原因、完成时间和关键安全触发。完成时间应分别报告成功样本，不能用失败 trial 的截断时间冒充更快。

若 $n$ 次独立 trial 中成功 $S$ 次，点估计为 $\hat p=S/n$。小样本不应只报百分比；例如可报告 Wilson 区间

\[p_{\pm} = \frac{ \hat p+\frac{z^2}{2n} \pm z\sqrt{ \frac{\hat p(1-\hat p)}{n} + \frac{z^2}{4n^2} } }{ 1+\frac{z^2}{n} },\]

其中 95% 区间取 $z\approx1.96$。配对 A/B 还应保留每个相同场景上的“基线/新模型”成败对，并对成功率差给出配对区间或适当的配对检验；一次成功视频不能替代这些结果。

八、知识点、重点与工程创新

知识点

  • 安全主张、控制机制、验证证据和残余风险
  • operational stop、软件故障停止与物理急停的区别
  • 故障注入、watchdog 与保守失败
  • 定向复现失败状态的初始化与首动安全
  • 二项成功率、置信区间与配对 A/B

本页重点

  • 历史测试记录不等于本轮复验
  • 软件安全链不等于安全认证功能
  • Home 是运动命令，不是急停
  • 人工完成的 trial 不能算策略独立成功

工程创新点是把会话交接、单写者、动作边界、watchdog、数据/模型血缘与证据等级放进同一安全案例，并主动列出每项测试不能证明什么。这是一种工程论证与审计结构，不是对真实机器人安全性的先验保证。

九、标准与证据边界

本页只用公开标准入口说明边界：ISO 10218-1:2025 面向工业机器人本体，ISO 10218-2:2025 面向机器人应用与单元集成，ISO 13850:2015 规定机械急停功能的设计原则。页面没有执行合规评估，也不据此宣称 RM75、控制柜或本项目满足这些标准；适用性和合规结论必须由掌握完整系统与现场条件的合格人员确定。
