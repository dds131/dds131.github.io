② PERCEPTION · BBOX→MASK · SAME-FRAME CONTRACT

本页把 Planner 交付的目标 bbox 转成 SAM 首帧二值 mask，再由 Cutie 在当前 attempt 内传播目标身份。核心输出不是“看起来正确”的叠加图，而是与头部 RGB 同帧、同尺寸、二值且属于当前 track generation 的 mask。

返回专题总览上一知识点：① 高层规划器与目标抽象下一知识点：③ 观测编码器与 DiT
accepted · batch 5SAM seedCutie memoryruntime not run

Planner 只决定“抓谁”和“目标在某张头部图中的 bbox”；本页负责验证该 handoff、生成首帧 mask、维护跟踪 memory，并把对齐的 head frame 与 mask 交给 Architecture。它不重新解释用户意图，不讲 mask encoder 内部张量，也不控制动作何时执行。

1 + 6 = 7每个动作块最多的静态 get_mask 调用数

先给证据边界。 论文中的 149/150 只评估 Planner bbox，不是分割 IoU 或跟踪 J&F；长程图是定性流程案例。固定代码可证明调用顺序、shape 与转换，但没有证明 SAM score 已校准、Cutie 在任意遮挡下稳定，或 frame 对齐风险已经实际发生。

二、Planner 入站与感知状态机

Page111 的目标合同要求 instruction、bbox_xyxy、head frame id、图像宽高、采集单调时间、Planner request id 与证据版本。固定公开调用点实际上只传 bbox 数组，并从共享 third_color_image 再读当前帧；因此 frame id/timestamp 是目标接口字段，不能写成当前已经实现。

入口 gate 必须先证明 bbox 有序、在范围内、frame 仍新鲜。有效时清空旧 Cutie memory，在 handoff 对应帧运行 SAM，选择 seed mask，首次 get_mask 播种 Cutie；之后只以图像推进跟踪。新目标或新 attempt 重新开始一代 memory。固定实现没有显式 Rejected、Degraded、LOST 状态，下图中的异常状态是工程目标。

这里的“同一 frame”应按数据身份理解，而不只是分辨率相同。两张 640×480 图可能来自不同采集时刻；即便 bbox 坐标都落在合法范围，移动的相机、机械臂、目标或遮挡仍可能使空间提示失效。理想 receipt 应把 Planner request、head frame、bbox、采集时间和当前 target generation 一起验证；固定调用点只带数组的事实必须保留，不能在文档中静默补成已有能力。

stateDiagram-v2
  [*] --> HandoffReceived
  HandoffReceived --> Rejected: invalid bbox / stale frame
  HandoffReceived --> MemoryCleared: valid

  SamCandidates --> Rejected: empty / invalid

  SeedMaskSelected --> CutieSeedPending

  Tracking --> MemoryCleared: new target or new attempt

文本回退： 接收入站 → 在任何感知调用前验证 bbox 与 frame；无效则拒绝，有效则清空旧 memory → SAM 产生候选 → 选择二值 seed mask → 第一次 Cutie step 携带 image、seed 与 objects → 后续 step 只携带 image；目标/attempt 改变时新建 generation，漂移、遮挡或陈旧帧进入“重新分割或停止”的目标状态。

三、SAM 输入：颜色、坐标与同 frame 合同

固定 initialize_sam_cutie(bbox) 对 self.third_color_image[..., ::-1] 调用 predictor.set_image，即将真机 BGR 末轴反转为 SAM 所用 RGB。逻辑图像形状为 H×W×3，部署口径为 640×480；bbox 使用同一原分辨率头部图的 [x1,y1,x2,y2]。Planner 工作区白填充不改变尺寸，但 Planner 返回后相机线程可能更新共享图像，所以“四个坐标相同”不足以证明“图像相同”。

颜色、shape、坐标和时序必须共同成立
字段 目标合同 当前边界
图像 head frame；H×W×3；640×480 部署口径 共享 third_color_image
颜色 真机 BGR 经末轴反转后传 SAM RGB 输入若已经是 RGB，不得盲目再翻转
bbox xyxy、有限、有序、在 W/H 范围内 固定调用点缺少完整 gate
关联 head frame id、采集单调时间、宽、高 固定调用只带 bbox 数组

目标不变量是：产生 bbox 的 frame = SAM set_image 的 frame。工作区外填白只改变像素，不改变坐标尺寸；它不能消除 bbox 与后续共享帧之间的时序竞争。

四、SAM 九步初始化与候选选择边界

固定调用顺序不能压缩成“bbox 直接变 mask”：

  1. clear_memory() 清空旧 Cutie memory；
  2. torch.cuda.empty_cache()；
  3. predictor.set_image(current_rgb_image)；
  4. predictor.predict(box=bbox, multimask_output=True)；
  5. np.argmax(scores) 选择 best_mask；
  6. 保存 mask overlay；
  7. 转为 uint8 CUDA seed tensor；
  8. 从非零 unique mask 值得到 objects；
  9. 设置 cutie_initialized=False，等待首次播种。

清 CUDA cache 只是实现副作用，不是分割正确性证明。multimask_output=True 返回候选集合，固定实现按 score argmax 选一项；候选数依赖实际安装版本/配置，本站不硬编码。固定片段没有 score threshold、空 mask、面积范围、连通域、bbox overlap 或校准检查。score 是 predictor 的排序信号，不是该目标的实测 IoU、校准概率或安全置信度。

选择最高分候选只解决“在返回集合里取哪一个”，没有回答“这组候选是否包含正确目标”。例如空区域、过大前景、多个断开区域或只覆盖遮挡物的 mask，都可能在缺少独立 gate 时继续进入 Cutie。稳健实现需要把候选 score 与几何/语义检查分开记录：score 用于排序，面积、连通性、bbox 交叠与人工标注集用于判断是否接受。具体阈值必须来自验证数据，本站不提供未经实测的常数。

“可见信号”不等于“质量 gate”
信号/检查 固定路径 允许结论
candidate scores 可见；用于 argmax 候选内排序，不是校准概率
empty/area/components 未见显式拒绝 不能默认 seed 有效
bbox overlap 未进入质量 gate 不能由“有 bbox”推出 mask 覆盖目标
saved overlay 可供人工查看 保存成功不等于自动验证通过

五、Seed mask ABI 与 Cutie memory 生命周期

论文写首帧 m₀∈{0,1}^{H×W×1}；固定 NumPy best_mask 在加通道前是 H×W，随后转为 CUDA 上的 uint8 seed。objects 来自排序后的非零 unique 值；二值 mask 通常只有标签 1，但多个断开区域仍共享同一标签，unique value 不会自动执行连通域拆分。空 mask 会得到空 objects，而固定片段没有显式拒绝。

固定 init_controller 用 get_default_model() 建立 Cutie，并由 InferenceCore(self.cutie, cfg=self.cutie.cfg) 包装；processor.max_internal_size=-1 是源码事实。由于依赖 revision 未固定，不能从该值继续外推内部缩放行为。

每个 Planner bbox 初始化都先清 memory，再把 cutie_initialized 置 False。因此 memory scope 是“一次目标/attempt generation”，不是整条长程提示共享。即使 Planner 再次选择同一语义目标，新轮次仍会清 memory、重跑 SAM、替换 seed 并重新播种；这与“同轮漂移后自动恢复”不同，后者在固定路径中缺失。

generation 边界同时是防止目标身份串线的边界。上一轮 memory 即使仍能输出非空 mask，也不能直接服务于新 instruction；语义名称相同也不代表场景实例、bbox 或 frame 没有变化。反过来，同一 generation 内输出突然变化也不应被解释为 Planner 改了目标，因为 Planner 并未参与每一帧传播。页面因此把“目标切换”“新 attempt 固定重建”“同轮跟踪退化”拆成三种事件，避免用一次通用 reset 掩盖不同故障。

六、Cutie 首次播种、后续传播与调用时钟

get_mask() 位于 torch.no_grad()：读取当前头部图，BGR→RGB、copy、转 tensor、CUDA、float。若 cutie_initialized=False，调用 processor.step(image_tensor, seed_mask, objects=objects) 并置 True；之后只调用 processor.step(image_tensor)。两条路径都将 output_prob 经 output_prob_to_mask 离散化，再转为 CPU NumPy uint8、形状 H×W 返回。

固定 execute_grasping 在每个动作块预测前调用 1 次 get_mask；execute_action 执行前 6 个动作时每步又调用 1 次，所以静态结构最多是 1+6=7 次/生成块。这个数字是函数调用计数，不是独立相机帧数：固定 get_mask 没有 frame id/new-frame gate。不能从标称 20 Hz 控制率或录像 fps 推导 Cutie 实测频率。

首次 stepimage + seed mask + objects；完成后 generation 进入 tracking。
后续 step只给 image；由 memory 传播目标身份并输出当前概率。
新轮次固定清 memory、重跑 SAM、替换 seed、重新播种。
同轮退化没有质量触发的 SAM rerun 或自动漂移恢复；不能写成已有能力。

七、两类 frame 对齐风险与 rgbm ABI

静态审计显示两个独立风险。其一，Planner 在某个共享 head frame 上得到 bbox，返回后 SAM 可能读取已更新的 third_color_image；固定调用点没有 bbox frame id。其二，get_mask 对共享图像做 copy 计算 mask，随后 get_obs 再读取共享 third_color_image 拼 rgbm，两次读取间相机线程可能更新。源码注释提示 mask/image 可能错位，但这只是静态风险，不是已复现故障。

固定 get_obs 将 third_color_image 与 mask[...,None] 沿最后一维拼接，目标形状为 H×W×4，mask channel index 为 3。process_obs 对前三通道采用 bilinear resize，对 mask 采用 nearest resize，再以 >0.5 二值化并拼成 T×4×518×518。本页只签发原分辨率同帧 mask；mask encoder 与 token 融合归 Architecture。

nearest resize 用于避免把离散标签当作连续颜色平滑，但它不能修复上游错位、空 mask 或错误身份；>0.5 也只是二值化边界，不是质量判定。诊断日志应能够把“生成 mask 的 frame”和“与 mask 拼接的 RGB frame”分别识别，再验证二者相等。若只保存最终四通道 tensor，后续很难判断问题发生在 Cutie 输出、共享帧读取、resize 还是 Architecture 编码阶段。

两个对齐 gate 与四通道 ABI
边界 目标不变量 固定实现缺口
bbox→SAM bbox frame = SAM image frame bbox frame id 未显式传递
mask→RGB mask frame = rgbm head frame 缺少 atomic pair capture
原始 ABI head H×W×3 + mask H×W → H×W×4 颜色语义仍需按管线核对
Architecture 预处理 RGB bilinear；mask nearest + >0.5；T×4×518×518 不在本页解释 mask ViT

八、训练 mask 与在线 mask：共享模态不等于同分布

论文说每个示教时刻记录 mₜ，且 mask 的标注方式与 controller 相同；README 样例 Zarr 把 mask 放在 rgbm 第四通道，容器形状 K×H×W×4。这些信息支持“示教和在线控制共享 mask 模态”，但没有提供逐帧 mask 质量 ground truth、SAM/Cutie revision、score 或漂移标注。

因此不能声称所有训练 mask 都由当前主仓 commit 在线重放生成，也不能假定训练与部署使用相同依赖版本或 mask 分布完全一致。若训练 mask 更稳定、遮挡更少或人工筛选更强，在线漂移就可能形成未量化的条件偏移；这是一项待验证假设，不是论文已经报告的结论。

方法叙事支持“mask 显式标出目标区域、把语言接口与控制器输入分离、时序 tracker 可以传播身份”，但二值化不等于统计域不变，Cutie 也不等于任意遮挡鲁棒。缺失的关键对照包括 no-mask、oracle-mask、SAM-only、alternate tracker、corrupted mask 与 delayed mask。

九、质量信号、18 类失败与传播故障树

固定路径可观察 bbox、SAM candidate scores、selected seed mask、Cutie output_prob、离散 current mask 与保存的 overlay；其中 score/prob 没有接入统一质量 gate。明确缺少的 monitor 包括 mask area range、connected component count、bbox-mask overlap、temporal IoU、centroid velocity、identity confidence 与 frame age。

检测信号、当前处理和建议处理必须分开
层 typed failure 当前/目标边界
Planner handoff BBOX_INVALID、BBOX_STALE、BBOX_FRAME_MISMATCH 目标 gate 在 SAM 前拒绝；固定 coverage 稀疏
SAM/设备 SAM_NO_CANDIDATE、SAM_EMPTY_MASK、SAM_DEGENERATE_MASK、SAM_LOW_SCORE、DEVICE_ERROR argmax 不覆盖这些质量判断
Cutie CUTIE_SEED_FAILED、TARGET_LOST、MASK_DRIFT、IDENTITY_SWITCH、OCCLUSION_NOT_RECOVERED、MEMORY_CONTAMINATED 固定实现无完整 typed 状态
输出/时序 MASK_NON_BINARY、MASK_SHAPE_MISMATCH、RGB_MASK_MISALIGNED、FRAME_STALE 无显式检测不等于 PASS

错误可沿 Planner bbox → SAM seed → Cutie current mask → rgbm packaging → mask encoder → head-mask token fusion → DiT condition → action chunk 传播。一次行为失败仍可能来自 Planner、SAM、Cutie、frame alignment、encoder、policy 或 controller；Grasp Outcome 最多发现“没有抓住”，不能局部归因 mask 漂移。没有隔离实验时，禁止把失败唯一归因于跟踪。

故障诊断至少要同时保存 generation、frame/request 关联、seed 来源、离散 mask 摘要和下游是否发出动作请求。面积突变可以提示退化，却不能区分目标离开视野与身份切换；bbox overlap 可以检查首帧几何一致性，却不能证明像素边界正确；时序 IoU 可以暴露快速变化，却会把真实形变也计入。任何单一信号都只能作为 gate 的一部分，不能直接充当“跟踪成功”标签。

十、Fail-closed 恢复目标与独立评测缺口

建议策略是：无效 handoff 在 SAM 前拒绝；无有效 seed 时在同 frame 重试或返回 Planner；tracking 退化时阻止新的动作请求，可恢复时在最新 frame 重分割，不可恢复时安全停止；目标改变启动新 generation；任何晚到的旧 generation mask 都丢弃。阈值与重试次数必须来自离线标注集和运行日志，不能由知识页给出拍脑袋数值。这是工程建议，不是当前实现事实。

论文报告 150 次独立 bbox 测试，但独立 SAM mask 测试为 0、独立 Cutie tracking sequence 为 0；长程 mask 图不是定量分割/跟踪评测。本页只登记以下 NOT_RUN 请求：

  1. seed mask IoU 与 Boundary F；
  2. empty/degenerate mask rate；
  3. temporal J&F 或 temporal IoU；
  4. time-to-drift；
  5. occlusion recovery rate；
  6. identity switch rate；
  7. bbox-frame 与 RGB-mask misalignment rate；
  8. perception latency distribution。

这些请求尚未执行；具体协议与未来结果归 Experiments。系统成功率、干扰实验或长程图都不能替代组件隔离，亦不能证明 mask 是全部泛化收益的唯一原因。

未来评测还应固定序列划分、遮挡类型、目标更换规则、依赖 revision、checkpoint 与随机性，分别报告首帧分割和跨帧传播。否则，较好的系统成功率可能来自 Planner 重选目标、低层闭环重抓或固定复位，而不是感知质量本身；较差的系统结果也可能由控制器或硬件造成。请求矩阵的作用是建立可证伪问题，不是预先假定 SAM/Cutie 一定是瓶颈。

十一、复现闭包、媒体与安全边界
