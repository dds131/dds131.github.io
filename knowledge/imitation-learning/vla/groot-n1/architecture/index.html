一、本页在专题中的位置

本页以初代 GR00T N1 的 n1-release（commit 755876a）和 nvidia/GR00T-N1-2B 发布配置为边界，拆解一次训练前向与一次动作块生成。数字分为四类来源：论文声明、发布配置、仓库内置 Eagle-2 配置、源码默认值；由数字推导出的维度会明确写出计算过程，不把推导结果伪装成配置字段。

第二节先用整体结构图、形状表和六阶段速查建立全局数据流；第三、四、五节再分别解释 System 2、System 1 与按本体接口，其中单个 DiT 块的结构图放在第四节。最后两节只保留参数量和设计取舍，避免重复罗列模块。这里的 “System 1 / System 2” 是论文对快速动作生成器和较慢视觉语言编码器的命名，并不表示两个独立决策主体。

本页不推导流匹配，只把它当成动作端的训练目标接口，完整推导见 ② Flow Matching、损失与时间方向。训练配置只在涉及冻结策略时提一句，完整配方见 ④ 训练配方、损失组合与优化配置。

2.2 一次前向的完整形状追踪

下表追踪一次训练前向。记批大小为 \(B\)，动作块长度为 \(H=16\)，每个样本的图像帧或视角数为 \(F\)。为便于写形状，先假设同一 batch 中 \(F\) 固定；视觉塔通常把图像展平到批维，因此前四步的有效批大小是 \(BF\)。

对第 \(b\) 个样本，送入 SmolLM2 的有效聊天序列长度近似为

\[N_b=N_{\text{non-image},b}+64F_b,\]

其中 \(N_{\text{non-image},b}\) 包含语言、模板和特殊 token。批处理张量按 \(N=\max_b N_b\) 补齐。表中的 64 维状态和 32 维动作都是接口上限，不代表每种机器人都使用全部维度。

步 张量 形状 产生它的模块
1 展平后的输入图像 \((BF)\times 3\times 224\times 224\) 数据管线把帧/视角并入视觉批维
2 SigLIP-2 patch 特征 \((BF)\times 256\times 1152\) 视觉塔（\(224/14=16\)，\(16^2=256\)）；SigLIP 分支不丢弃任何 token
3 pixel shuffle 后 \((BF)\times 64\times 4608\) 空间减半、通道升四倍（\(256\times0.5^2=64\)，\(1152\times4=4608\)）
4 每帧视觉 token \((BF)\times 64\times 2048\) mlp1：LayerNorm、Linear(4608,2048)、GELU、Linear(2048,2048)
5 模板化输入序列词嵌入 \(B\times N\times 2048\) 含语言、特殊 token 与 \(64F\) 个图像占位符
6 散射后的混合序列 \(B\times N\times 2048\) 视觉 token 覆盖 img_context_token 所在位置
7 LLM 隐状态 \(B\times N\times 2048\) SmolLM2 前 12 层，取最后一层输出
8 视觉语言 token \(\varphi\) \(B\times N\times \mathbf{1536}\) 主干投影层 nn.Linear(2048, 1536)
9 状态 \(q\) \(B\times 1\times 64\) 数据管线，按本体的有效状态维度补齐到上限 64
10 状态 token \(B\times 1\times 1536\) state_encoder（按本体）
11 加噪动作块 \(A^\tau\) \(B\times 16\times 32\) 对补齐后的动作加噪；32 是最大动作维度
12 动作 token \(B\times 16\times 1536\) action_encoder（按本体，含时刻）
13 拼接后序列 \(B\times 17\times 1536\) torch.cat，状态在前
14 DiT 输出 \(B\times 17\times 1024\) 16 个块 + 输出归一化与投影
15 解码后 \(B\times 17\times 32\) action_decoder（按本体）
16 速度场预测 \(B\times 16\times 32\) 取末 \(H\) 个 token；训练损失再用 action_mask 排除无效动作维

padding 与损失掩码。 动作监督只在有效动作维上计算。令 \(m_{bhj}\) 为 action_mask、\(v\) 为目标速度、\(\hat v\) 为预测速度，则源码对应

\[\mathcal L =\frac{\sum_{b,h,j}m_{bhj}(\hat v_{bhj}-v_{bhj})^2} {\sum_{b,h,j}m_{bhj}}.\]

因此 32 维输出是统一容器，不是所有机器人都执行 32 个控制量。action_mask 只屏蔽损失，并不会从动作编码器或注意力计算中删除补齐维。更具体地说，训练代码先在完整的 32 维张量上采样噪声，再构造 \(A^\tau=(1-\tau)\epsilon+\tau A\)；所以真值虽已补零，无效动作维仍会含 \((1-\tau)\epsilon\)，并经稠密的 W1 与有效维混合。action_mask 只消除这些输出维的直接损失，不消除它们作为输入的影响。状态无效维会保持上游补零值，但动作头虽接收到 state_mask，并未读取或应用它。

第 8 步是本表最容易被略过的一步。 语言模型的隐藏维是 2048，而 DiT 的内部宽度是 1536，两者并不相等；衔接靠的是主干末端一个独立的线性层 nn.Linear(2048, 1536)（源码 eagle_backbone.py，由配置项 projector_dim: 2048 触发；若该项为 -1 则退化为 Identity）。

这一层在论文里没有提及，但它是整条通路能接上的必要条件——少了它，视觉语言 token 的维度对不上 DiT 交叉注意力所要求的键值维度。

交叉注意力的形状关系可以写得更直接。令动作端表示为 \(X\in\mathbb{R}^{B\times17\times1536}\)，视觉语言表示为 \(\varphi\in\mathbb{R}^{B\times N\times1536}\)，则每一头计算

\[Q=XW_Q,\qquad K=\varphi W_K,\qquad V=\varphi W_V,\] \[\operatorname{Attn}(X,\varphi) =\operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{48}}\right)V.\]

因此动作端自注意力的打分矩阵规模是 \(17\times17\)，交叉注意力的规模是 \(17\times N\)。动作 query 的长度不随图像数增长，但 VLM 自注意力与 DiT 交叉注意力仍会随 \(N\) 增长。

三点值得先记住：

  • 动作端的查询序列固定为 17 个 token（1 个状态加 16 个动作）；图像数量和指令长度只改变键值序列长度 \(N\)，不会改变这 17 个查询槽位。
  • 进入 DiT 交叉注意力的视觉语言 token 必须已经是 1536 维——因为 attn1 构造时 cross_attention_dim 为 None，其键值投影按查询维度 1536 建立，不会再替不同维度的输入做适配。这个前提由第 8 步的主干投影层保证。
  • 解码器实际作用在全部 17 个 token 上，之后才切片取末 16 个。状态位对应的那一路输出被直接丢弃。

2.3 六阶段职责速查

第二节只需要记住六个阶段；各模块的实现细节在后续章节展开。

阶段 主要模块 数据变化 当前实现中解决的问题
1. 视觉编码与压缩 SigLIP-2、pixel shuffle、mlp1 单帧像素 → 256 个 patch → 64 个 2048 维视觉 token 利用预训练视觉表征，并控制送入 LLM 的序列长度
2. 图文条件形成 词嵌入、图像 token 散射、SmolLM2 前 12 层、2048→1536 投影 模板化混合序列 → \(\varphi\in\mathbb R^{B\times N\times1536}\) 形成包含图像和指令的条件序列，并与 DiT 宽度对齐
3. 本体输入接口 state_encoder、action_encoder、动作位置嵌入 补齐状态与插值动作 → 1+16 个 1536 维 token 把不同机器人的输入语义映射到共享动作空间，并标出流时间和动作槽位
4. 条件读取 偶数号交叉注意力块、adaLN 17 个动作侧查询读取 \(N\) 个 VL token；流时间逐层调制 注入“看到什么、要做什么、当前位于流的哪里”
5. 动作内部协调 奇数号自注意力块、前馈网络 17 个 token 之间交换信息 让状态与动作槽位显式通信，并做逐 token 非线性变换
6. 本体输出接口 输出归一化/proj_out、action_decoder、切片 1536 → 1024 → 32，再取末 16 个 token 输出统一上限宽度的速度场；训练时仅在有效动作维上计损失

这六阶段也给出阅读顺序：System 2 负责第 1–2 阶段，System 1 负责第 4–5 阶段，三个按本体模块位于第 3 和第 6 阶段。它们共同构成一次速度场求值；推理时会在不同流时间重复执行动作侧阶段。

三、System 2：Eagle-2 视觉语言模型

3.1 它由哪两部分组成

Eagle-2 不是一个从零训练的模型，而是把视觉编码器与语言模型对齐起来的组合。仓库内置配置 gr00t/model/backbone/eagle2_hg_model/config.json 给出：

部件 实际取值
模型类 Eagle2ChatModel（model_type: eagle_chat）
语言模型 SmolLM2-1.7B-Instruct，LlamaForCausalLM 结构，hidden 2048，24 层，32 头，中间层 8192，词表 49164
视觉编码器 siglip_vision_model，hidden 1152，27 层，16 头，输入 224，patch 14
下采样比 downsample_ratio: 0.5
对话模板 template: qwen2-chat

配置里的 template: qwen2-chat 只是对话格式模板，不表示语言模型是 Qwen2；实际路径是 ./pretrained/SmolLM2-1_7B-Instruct。同样地，顶层 hidden_size: 1536 是 GR00T 动作侧共享宽度，不是语言模型的 2048 维隐藏宽度。

还要注意，SmolLM2 是因果语言模型。这里的“图文联合编码”不是任意双向融合：可见信息受聊天模板中的 token 顺序和因果掩码约束；DiT 随后读取整条输出序列。

3.2 每帧 64 个 token 是怎么算出来的

论文只给结论「每帧 64 个 image token」。把配置代进去可以完整还原：

输入边长 224，patch 边长 14，因此每边的 patch 数为

\[224/14=16\]

一帧共

\[16\times16=256\]

个 patch。pixel shuffle 的下采样比为 0.5，在二维上意味着边长各减半、token 数变为四分之一：

\[256\times 0.5^2=64\]

与论文所述精确吻合。

这一步是空间到通道的重排：

\[B\times16\times16\times1152 \longrightarrow B\times8\times8\times(4\cdot1152) = B\times64\times4608.\]

重排前后的元素数相同：

\[256\times1152=64\times4608=294\,912.\]

因此 pixel shuffle 本身不丢元素；真正的通道压缩发生在随后的 Linear(4608,2048)。每帧视觉 token 数减少 75%，但不能据此声称“注意力开销固定减少 75%”：自注意力打分随整条序列长度近似二次增长，而线性投影和 MLP 近似线性增长，实际节省还取决于文本长度与图像帧数。

核心取舍不是“64 一定足够”，而是分辨率与计算量的平衡。 8×8 token 网格降低了 VLM 序列长度，也可能削弱细粒度空间线索。论文证明的是该配置在其训练分布和评测任务上有效，并没有证明所有桌面操作都以 64 个 token 达到饱和。

3.3 只保留前 12 层：论文说的和代码做的

论文的表述是：「我们发现使用中间层而非最后一层的语言模型嵌入，既能提高推理速度，又能提高下游策略成功率；对 GR00T-N1-2B 我们使用第 12 层的表示。」

实现上并不是「算完 24 层再取第 12 层的输出」。n1-release 的 eagle_backbone.py：

# 去掉语言模型头
self.model.language_model.lm_head = torch.nn.Identity()

# 只保留前 select_layer 个 Transformer block
while len(self.model.language_model.model.layers) > select_layer:
    self.model.language_model.model.layers.pop(-1)

# 视觉塔的池化头也换成恒等映射
self.model.vision_model.vision_model.head = torch.nn.Identity()

取特征时则是：

embeddings = self.language_model.forward(
    inputs_embeds=input_embeds, attention_mask=attention_mask,
    output_hidden_states=True)
embeddings = embeddings.hidden_states[-1]

注意最后一行取的是 hidden_states[-1]，即截断之后那个模型的最后一层——由于后 12 层已被物理删除，它就是原模型的第 12 层。

这解释了论文所称的推理提速。 如果先运行 24 层再读取中间层，主干计算并不会减少；当前实现直接删除后 12 个 Transformer 层，并把语言模型头替换为恒等映射，因此确实减少计算、激活和参数。被删除的是一半 Transformer 层，但词嵌入等参数仍保留，所以不应把整个语言模块精确说成“参数腰斩”。

至于为什么中间层的表示反而更适合机器人控制，这属于反常现象的范畴，机制分析放在 ⑥ 反常现象、证据边界与可能机制，本页只交代实现方式。

3.4 冻结策略

发布配置中 tune_llm: false、tune_visual: true。源码把 language_model.requires_grad 设为 false，而视觉模型与 mlp1 保持可训练；主干末端的 2048→1536 投影和动作头也不属于被冻结的语言模型。

论文 Table 6 写的是 “Backbone’s text tokenizer: frozen”。tokenizer 本身没有需要反向传播的网络权重，真正消除歧义的是发布配置和源码：冻结的是 SmolLM2 语言模型，视觉编码器则解冻。更完整的训练配方见子页 ④。

四、System 1：Flow Matching 的 DiT 动作头

论文和源码沿用 “Diffusion Transformer（DiT）” 这一结构名称，但 N1 的监督目标是条件 Flow Matching，而不是标准 DDPM 的噪声预测。下文把 \(\tau\) 称为流时间/插值时刻；它与样本中噪声和数据的混合比例相关，但不应在所有语境下直接等同于“扩散噪声等级”。

4.1 发布权重里的确切配置

发布 config.json 的 action_head_cfg.diffusion_model_cfg：

字段 取值 含义
num_layers 16 块的总数
num_attention_heads 32 注意力头数
attention_head_dim 48 每头维度
内部宽度（推得） \(32\times48=1536\) 与视觉语言 token 维度相同
output_dim 1024 输出投影后的维度
norm_type ada_norm 用时刻调制层归一化
interleave_self_attention true 开启交叉与自注意力交替
dropout / final_dropout 0.2 / true 注意力和 FF 使用 0.2；两条输出路径启用额外 dropout
positional_embeddings null DiT 内部不加位置编码

源码 cross_attention_dit.py 的构造默认值是每头 64 维、12 层、输出 26 维，与发布权重不同。默认值只是没有显式配置时的兜底；描述 GR00T-N1-2B 时应以发布 config.json 为准。

4.2 交替排布与单块结构

论文说 DiT「由交替的交叉注意力块与自注意力块构成」。源码与这个表述一致，但具体形式值得说清楚：每个 BasicTransformerBlock 只有一个注意力子层，16 个块各自拥有独立参数，并不是在单个块内先做自注意力再做交叉注意力。

flowchart TB
  IN["输入 hidden_states<br/>B×17×1536"] --> N1["norm1：adaLN<br/>由 temb 给出缩放与偏移"]
  TEMB["流时间嵌入 temb"] --> N1
  N1 --> ATT["该 block 自己的 attn1"]
  COND["视觉语言 token φ<br/>仅偶数号块传入"] -.-> ATT
  ATT --> DO["final dropout 0.2"]
  DO --> R1["残差相加"]
  IN --> R1
  R1 --> N3["norm3：普通 LayerNorm"]
  N3 --> FF["前馈网络<br/>gelu-approximate"]
  FF --> R2["残差相加"]
  R1 --> R2
  R2 --> OUTB["输出 hidden_states"]

DiT.forward 的块循环：

for idx, block in enumerate(self.transformer_blocks):
    if idx % 2 == 1 and self.config.interleave_self_attention:
        hidden_states = block(hidden_states, attention_mask=None,
                              encoder_hidden_states=None,          # ← 不给条件
                              encoder_attention_mask=None, temb=temb)
    else:
        hidden_states = block(hidden_states, attention_mask=None,
                              encoder_hidden_states=encoder_hidden_states,  # ← 给条件
                              encoder_attention_mask=None, temb=temb)

而 BasicTransformerBlock 里只构造了一个注意力模块：

self.attn1 = Attention(
    query_dim=dim,
    ...
    cross_attention_dim=None,
)
...
attn_output = self.attn1(
    norm_hidden_states,
    encoder_hidden_states=encoder_hidden_states,   # 给了就是交叉，不给就是自注意力
    attention_mask=attention_mask,
)

两处合起来得到确切结论：

块序号 idx 传入 encoder_hidden_states 该块实际是 数量
偶数（0,2,…,14） 是 交叉注意力块 8
奇数（1,3,…,15） 否 自注意力块 8

要点：复用的是 Attention 的实现形式，不是 16 个块之间的权重。 每个 block 都有自己的 attn1 参数；偶数块传入视觉语言键值，奇数块不传。16 层因此形成 8 组“交叉注意力—自注意力”，从交叉块开始、以自注意力块结束。

cross_attention_dim=None 使键值投影的输入宽度默认等于查询宽度 1536，所以视觉语言 token 必须先经过 2048→1536 的主干投影。

实现边界：VL padding mask 没有进入实际交叉注意力。 Backbone 会返回 backbone_attention_mask，训练路径也把它传给 DiT；但 DiT.forward 调用各 block 时把 encoder_attention_mask 设为 None，BasicTransformerBlock 内对应传参也被注释。推理路径同样没有传入该 mask。因此不能把当前实现描述为“只关注有效视觉语言 token”。这是 n1-release 的源码行为，其实际影响取决于 batching 与 padding 方式，不宜反推为论文有意设计。

4.3 两种块各自在做什么

交叉注意力块（偶数号）查询来自状态与动作 token，键值来自视觉语言 token。作用是把「看到了什么、要做什么」注入动作表示。这一步不改变序列长度，也不让视觉语言 token 之间发生任何新的交互。
自注意力块（奇数号）查询、键、值都来自那 17 个 token。它为动作块内部各时间步之间、以及状态与动作之间的信息交换提供通路，使模型能够联合建模整段轨迹；这不等于结构本身保证轨迹连续或动力学可行。

交替排布可以理解为八轮“读取视觉语言条件—协调状态与动作”：交叉注意力更新每个查询对视觉语言信息的读取，自注意力随后允许 17 个动作侧 token 相互通信。相比把两类块分组堆叠，它提供了多轮条件读取与内部协调；但论文没有给出两种排序的直接消融，因此这里是结构解释，不是已验证的最优性结论。

4.4 时刻如何调制每一层

norm_type 为 ada_norm，即自适应层归一化。流时间先经 timestep_encoder 变成向量 temb，再在每个块内调制归一化的缩放与偏移；最后的输出投影同样受它调制：

conditioning = temb
shift, scale = self.proj_out_1(F.silu(conditioning)).chunk(2, dim=1)
hidden_states = self.norm_out(hidden_states) * (1 + scale[:, None]) + shift[:, None]
return self.proj_out_2(hidden_states)

这使同一套 DiT 参数能够随流时间改变中间特征的缩放与偏移。直觉上，从随机初值向数据轨迹积分时可能先形成大尺度轨迹、再做局部修正；但 Flow Matching 损失并不强制“早期粗、后期细”的语义分工，是否出现这种现象需要用速度场或轨迹可视化验证。

流时间还会在动作编码器内部与每个加噪动作 token 拼接：动作编码器提供输入级条件，adaLN 提供逐层条件。完整时间方向和损失推导见子页 ②。

五、按本体分组的三个模块

这里的“本体（embodiment）”指机器人形态或平台类别。按本体分组的编码器/解码器是动作头中最显式的异构接口：它把各机器人的状态、动作语义隔离在边界层，同时让中间的 DiT 继续共享。padding、有效维度掩码和共享主干同样是跨本体训练的一部分。

5.1 机制：按 embodiment_id 查表取整张权重矩阵

n1-release 的 flow_matching_action_head.py：

class CategorySpecificLinear(nn.Module):
    def __init__(self, num_categories, input_dim, hidden_dim):
        self.W = nn.Parameter(0.02 * torch.randn(num_categories, input_dim, hidden_dim))
        self.b = nn.Parameter(torch.zeros(num_categories, hidden_dim))

    def forward(self, x, cat_ids):
        selected_W = self.W[cat_ids]
        selected_b = self.b[cat_ids]
        return torch.bmm(x, selected_W) + selected_b.unsqueeze(1)

这不是“共享权重加小适配器”，而是每个槽位各有完整的权重与偏置。若槽位数为 \(E\)，一个分组线性层的参数量为

\[P_{\text{grouped-linear}} =E(d_{\text{in}}d_{\text{out}}+d_{\text{out}}).\]

max_num_embodiments=32 来自 FlowmatchingActionHeadConfig 的源码默认值，不是发布 config.json 中的显式字段。32 表示可分配槽位数，也不等于预训练数据中恰好存在 32 种机器人。

5.2 三个模块的确切形状

模块 结构 输入 → 输出
state_encoder CategorySpecificMLP（两层，ReLU） 64 → 1024 → 1536
action_encoder MultiEmbodimentActionEncoder 见下
action_decoder CategorySpecificMLP（两层，ReLU） 1024 → 1024 → 32

动作编码器结构稍复杂，因为它要同时吃进动作与时刻：

a_emb   = self.W1(actions, cat_ids)       # 32 -> 1536（按本体）
tau_emb = self.pos_encoding(timesteps)    # 时刻 -> 1536 正弦编码
x = torch.cat([a_emb, tau_emb], dim=-1)   # -> 3072
x = swish(self.W2(x, cat_ids))            # 3072 -> 1536（按本体）
x = self.W3(x, cat_ids)                   # 1536 -> 1536（按本体）

三个线性层全部是按本体查表的。时刻编码本身不分本体（正弦编码无参数），但它与动作嵌入拼接后所过的两层是分本体的。

按 \(E=32\) 代入源码中的输入输出维度，可得到三个模块的确切分配参数量：

模块 参数量
state_encoder 52,510,720
action_encoder 228,212,736
action_decoder 34,636,800
合计 315,360,256（约 315M）

这个结果解释了为什么它不是“小适配器”：参数量随槽位数线性增长，而且即使某些槽位未用于当前 batch，相应参数仍已分配在 checkpoint 结构中。实际参与当前样本计算和获得梯度的是由 embodiment_id 选中的槽位。

5.3 位置嵌入只加在动作 token 上

if self.config.add_pos_embed:
    pos_ids = torch.arange(action_features.shape[1], ...)
    pos_embs = self.position_embedding(pos_ids).unsqueeze(0)
    action_features = action_features + pos_embs

position_embedding 是 nn.Embedding(max_seq_len=1024, 1536)，学习式而非正弦式，且只加在动作特征上，状态 token 不加。

动作块的 16 个槽位对应不同未来时刻。若没有位置嵌入，自注意力对动作 token 的排列保持置换等变，无法仅凭槽位索引判断“这是未来第几步”，但仍可能依据不同 token 的内容产生不同输出。因此准确说法是：位置嵌入提供稳定的时间槽位身份，而不是把原本“完全相同”的 token 强行区分开。状态只有一个 token，且在位置嵌入之后才与动作序列拼接，所以不会获得动作序列的第 0 号位置向量。

5.4 共享与隔离的边界

GR00T N1 只在状态编码器、动作编码器和动作解码器中按本体选择参数；VLM、2048→1536 投影、动作位置嵌入和 DiT 仍由所有本体共享。因此：

  • 被隔离的是输入输出边界处的维度与控制语义，某个本体不会直接更新另一个本体的三组 MLP 槽位；
  • 仍然耦合的是视觉语言表征和动作主干，某个本体对共享 DiT 的梯度仍可能改善或干扰其他本体；
  • 新增本体通常需要为对应槽位学习新的边界参数，同时决定共享主干是否参与微调；“有空槽位”不等于能够零样本接入。

不同 VLA 对跨本体问题的比较必须统一口径：soft prompt、统一补齐动作空间、离散动作 token 和按本体 MLP 分别作用在不同层面，不能简单排成“隔离强弱”的单一序列。X-VLA 的 soft prompt 机制另见 X-VLA · Soft Prompt 与跨本体机制。

六、参数量怎样分布

论文给出：GR00T-N1-2B 总参数量约 2.2B，其中 VLM 约 1.34B。两者相减得到动作侧及连接层约

\[2.20\text{B}-1.34\text{B}=0.86\text{B}.\]

1.34B 对应发布模型中已经截断的视觉语言模块，不应拿完整的 SmolLM2-1.7B 再与 SigLIP-2 相加。源码还能确定以下部分：

  • 三个按本体模块合计约 315.36M，计算见第 5.2 节；
  • 动作位置表有 \(1024\times1536=1{,}572{,}864\) 个参数；
  • 2048→1536 主干投影含 \(2048\times1536+1536=3{,}147{,}264\) 个参数；
  • 其余主要位于 16 个 DiT block、时间编码器与输出调制/投影中。

上述 315.36M 是按 32 个已分配槽位计算的结构参数量，不是“当前数据实际用了几个本体”乘出来的动态值。页面不再臆测 DiT 的逐子层占比；若要给出精确总和，应在固定 n1-release 依赖版本后直接运行 numel() 统计。

七、关键设计、创新边界与取舍

先区分“使用了什么组件”和“GR00T N1 把它们怎样组合”：

层次 内容
继承的基础组件 SigLIP-2、SmolLM2、pixel shuffle、动作分块、Flow Matching、DiT、交叉/自注意力、adaLN；这些不应写成 N1 单独首创
N1 的关键工程选择 物理截断到 SmolLM2 前 12 层；每帧 256→64 个视觉 token；2048→1536 主干投影；17 个动作侧查询；8 组交叉—自注意力；流时间的输入级与逐层双重注入；按本体边界 MLP
系统级贡献 把静态视觉语言条件、短动作序列、共享 Flow Matching DiT 和按本体输入输出接口组合成可跨机器人训练的策略，并与数据金字塔共同形成完整方法

这套组合有四项需要同时看到的取舍：

短动作查询，对长条件做按需读取动作端始终只有 17 个查询 token；VLM 输出在一个动作块的多次积分中只计算一次。动作 query 每步都会变化，所以交叉注意力可以重新加权不同 VL token。单次前向中动作流不会写回并重算 VLM token，但训练损失仍会沿交叉注意力回传到未冻结的视觉塔、mlp1 和主干投影。官方实现复用的是 VLM 输出张量，没有显式缓存交叉注意力的 K/V 投影。
边界隔离，共享主干按本体 MLP 减少异构状态和动作语义在接口处的直接冲突，但共享 DiT 仍产生跨本体迁移与干扰；约 315M 的槽位参数也是这项隔离的容量代价。
中间层换取速度，能力边界需实验证明删除后 12 层显著减少计算，论文同时报告更高策略成功率。这证明第 12 层在其评测上是更好的选择，但不能单凭层数断言复杂语言任务必然失败；更强主干是否改善特定能力仍需受控实验。
64 个视觉 token 换取较短序列pixel shuffle 只重排元素，把 2×2 邻域收进通道；真正有损的瓶颈是随后逐 token 的 4608→2048 投影及后续网络。收益是降低 LLM 序列计算，代价是独立空间槽位减为 8×8，细粒度线索能否保留取决于通道压缩与训练。

逐条核验过的来源

  1. GR00T N1 论文 v2（arXiv:2503.14734）
    支持双系统定义、\(H=16\)、Eagle-2/SmolLM2/SigLIP-2、每帧 64 个视觉 token、第 12 层表示、交替注意力与 adaLN，以及 2.2B/1.34B 参数量。
  2. eagle_backbone.py（固定 commit） 与 Eagle-2 内置配置
    支持图像 token 散射、24→12 层物理截断、2048→1536 主干投影、冻结边界，以及视觉/语言主干的确切配置。
  3. cross_attention_dit.py（固定 commit）
    支持单块内部顺序、16 个独立 block、偶数交叉/奇数自注意力、adaLN、输出调制，以及 VL mask 未进入实际 Attention 的实现事实。
  4. flow_matching_action_head.py（固定 commit）
    支持三个按本体模块、max_num_embodiments=32 的源码默认值、动作位置嵌入、action_mask 和推理积分循环。
  5. GR00T-N1-2B 发布 config.json
    支持 1536/1024/64/32/16/12 等发布维度及 tune_llm=false、tune_visual=true；该文件不包含 max_num_embodiments 和 max_seq_len。
