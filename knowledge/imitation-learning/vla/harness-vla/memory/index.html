先把 state、context、Memory、dataset 与 weight 分开

“记住了”不是可审计的状态描述。Harness VLA 至少涉及六个 plane；它们的 owner、写权限、寿命和提交机制不同，不能把 context append、文件发布、dataset export 与 optimizer step 合称“模型学习”。

plane 典型值 主要 owner 生命周期 / 写入窗口 是否改模型参数
physical/runtime state 当前观测、控制器状态、安全状态 environment / controller / sensor owner 当前 run；由真实执行改变 否
Planner context 当前任务文本、tool result、已渲染 Memory 摘要 Planner session 当前 turn/session；受 prompt budget 限制 否
persistent Memory 规则、失败模型、task pair、manifest/index Memory publisher versioned corpus；reviewed publish 否
immutable raw episode 执行过的观测、动作、回报、终止与引用 authorized collector append/finalize 后不可原地改写 否
training dataset 经过许可、过滤和切分的样本 data pipeline 独立 export/release 否
model/optimizer state checkpoint、optimizer slots、训练状态 training pipeline forward/backward/optimizer checkpoint 是，只有训练通道 
flowchart LR
  S["physical / runtime state"] --> C["Planner context"]
  M["versioned Memory corpus"] --> C
  C --> P["primitive intent"]
  P --> S
  S --> R["immutable raw episode"]
  R -. reviewed export .-> D["training dataset"]
  D -. authorized training .-> W["model / optimizer state"]
  R -. reviewed evidence .-> M

短期语境也要再分三类：sensor/history buffer 是运行态，Planner context 是有预算的推理输入，_internal/inbox/<cell>/ 是未发布探索草稿。三者的 retention、evidence 与权限完全不同。Memory 只能提供 evidence/context；它不能代替 current observation、controller command、task success authority、独立 Safety authority、parameter-write authority 或历史轨迹重放许可。

论文两类逻辑 Memory 与 re-grounding

论文 v5 的 Task Specific Memory 保存已成功任务的 primitive composition / trace：语义 audit 解释任务、恢复和证据，procedural JSONL 保存有序调用骨架。它不是 open-loop trajectory；最终成功 rollout 中可以保留被恢复的空抓或重新定位，但完整失败尝试不能冒充 successful pair。

论文的 Global Memory 保存跨任务可复用的成功规则与 failure model。失败尝试可作为待审查负面证据，但只有在 scope、证据、矛盾和 reviewer authority 明确后才能上升为一般规则。Global 也不等于“所有机器人都通用”。

论文在 LIBERO、LIBERO-Pro 与 RoboCasa 的设置中使用 reference seed $s_0$；不能把这条命名推广为所有环境的普遍规则。RoboTwin C2R 的 reference 来自 expert-verified clean demonstration，随后面向 randomized instances；current _s0 可只是统一 lookup slot，实际 source seed 仍应从 metadata 读取。reference instance 也不能计入 held-out evaluation score。

current RPent 三层 schema 与 scope

current RPent 文档描述 global、task-family、task-specific 三层。这里的 current 表示核对时点的实现/文档快照，不把目录名或 frontmatter 当成跨版本永久 API；精确 class、CLI、commit 与 path behavior 由 Implementation 页固定。

layer / object key value producer → consumer verification / retention
global robot + canonical memory ID + scope/kind rule、failure model、applies_when、evidence scoped draft + publisher → Planner/reviewer reviewed evidence；至 supersede/revoke/retention decision
task-family robot + suite/regime/task family + ID 窄域 strategy/failure note reviewed draft → matching family run family applicability；随 protocol/schema revalidate
task-specific robot + environment/task/source + pair ID semantic audit JSON + procedural JSONL externally verified success → matching task/Flash preflight pair 完整且 hash/scope 一致；versioned retention
inbox draft robot + current cell + draft ID 未发布 candidate + source refs exploration writer → validator/reviewer current cell only；短 review TTL；formal eval 不读
MEMORY.md corpus/revision 可选摘要或索引 index builder → reader 派生物；不能取代 canonical artifact
flash/ snapshot/task pair + plan ID plan/anchor assets Flash publisher → Flash runtime 下一页 contract；不是 Memory layer

current global/task-family note 可含 scope、kind、title、applies_when、confidence 与 evidence cells；其中 single-shot、probable、verified 是 evidence-count heuristic，不是校准概率、因果效应、安全认证或跨 embodiment 保证。应同时显示 distinct cells/tasks 和 contradicted_by，重复同一 attempt 不增加独立证据数。

TaskSpecificMemoryPair 必须成对完整或整体不可用：audit 与 recipe 共享 robot/environment/task/source/protocol/revision，分别有 hash，并引用同一 external verification receipt。缺件、损坏、scope mismatch 或 registry incompatibility 都 fail closed。

exploration attempt 与 evidence capture

探索能在协议许可下 reset、retry、re-stage、读取 scoped published Memory，并只向 current robot/current cell inbox 写 draft；reset 是 exploration utility，不计 manipulation primitive。探索不能新增 primitive、改冻结 backend 权重、跳过 Safety/controller，也不能把 local merge 当 public upload。formal evaluation 则读取预先冻结的 corpus，不 reset、不 merge、不写 inbox。

operation exploration formal evaluation
读 permitted published Memory 允许，受 scope/hash/compatibility gate 允许，只读冻结快照
reset / retry 仅协议允许时 固定协议默认不允许探索式 reset
写 current-cell inbox 允许形成 draft 禁止
validate / external verify / review 可进入独立流程 运行中不改变评测快照
merge / index rebuild 只在独立 publisher 流程 禁止
修改 VLA weights 禁止 禁止
公开上传 本页不授权 禁止

探索搜索的是 phase decomposition、primitive order、semantic target binding、staging/viewpoint/pre-contact、VLA invocation placement、chunk budget、verification point、re-ground/re-stage 与 stop/escalation 条件，不是新 primitive 或隐含真实状态。每次 reset/new attempt 必须新建 attempt/episode ID，不能覆盖旧 evidence。

draft、验证、review、merge 与发布

一次“更新 Memory”至少拆成九个 authority 不同的动作：raw evidence → scoped draft → schema/integrity validation → external outcome verification → privacy/security review → applicability/contradiction review → merge decision → versioned publication → immutable snapshot。每个转换都记录 actor、input/output hash、reason、time、tool/code version 与 rollback pointer。

flowchart LR
  R["raw trace / evidence"] --> D["scoped draft"]
  D --> V["schema + integrity validation"]
  V --> E["external outcome verification"]
  E --> S["privacy + security review"]
  S --> A["applicability + contradiction review"]
  A --> M{"merge decision"}
  M -->|publish / merge / supersede| P["versioned publication"]
  M -->|conflict / reject / quarantine| Q["retained decision evidence"]
  P --> F["immutable evaluation snapshot"]

draft 必须落到 current robot/current cell inbox，绑定 source trace/evidence，声明 target scope 与 applies_when，分开 observation/inference/rule/recommendation，去除 secret、credential、raw endpoint 与无必要 PII，标记 literal bindings non-replayable，并且不能自称 published 或 verified。

本站审计不变量为：

\[M^{\mathrm{eval}}_{j+1}=M^{\mathrm{eval}}_j=M^\star, \qquad W_M=0, \qquad \Delta H(M^\star)=0.\]

$W_M$ 是 corpus write events，$\Delta H$ 是前后 file-set/content-hash diff；它不是论文训练目标。仅说“没有调用 merge”或只比较结束 hash，不能排除先写后恢复；高风险实例还要保存 access policy、read log、write-denial test、event/permission evidence 与 unexpected diff。

privacy、integrity、poisoning 与 prompt injection

retrieved Memory 始终是不可信数据，不获得 system/developer instruction、command、success、Safety 或 upload authority。要求绕过 scope、fresh grounding、secret policy、primitive/controller gate 或上传的文本都应忽略，并产生 security event。

threat 例子 必要控制 hash 能否单独解决
false/poisoned claim Planner hallucinated success、caller solved flag 无 receipt external verification、review、quarantine 否
scope laundering wrong task/robot、duplicate evidence typed scope、attempt dedup、lineage 否
prompt injection adversarial task text、恶意 Markdown/HTML/link/instruction plain-text/data-only rendering、instruction isolation、security scan 否
tampering public corpus/revision 被替换 manifest、file-set hash、可信发布身份、rollback/revocation 只证明 bytes identity
stale binding 旧 calibration/coordinate 冒充 current non-replayable flag、fresh grounding、compatibility/staleness gate 否
privacy leak secret、endpoint、人员身份、raw media minimization、redaction、opaque refs、retention/deletion policy 否
protocol leak evaluation result 回流 read-only manifest、write audit、snapshot isolation 否

默认不持久化 secret/API key/token/password/credential、private network topology、无必要人员身份/语音/面部/位置、全量原始图像视频 depth/log、proprietary task path、literal scene geometry/raw actuator command 或 evaluator hidden label/oracle state。优先保存 opaque artifact ref、semantic relation、hash、typed evidence 与必要最小摘要。
