openpi-RLT ②：RL-Token 训练与冻结审计

解析 RM75 Stage-1 的 hidden-token 输入、全元素重建 MSE、配置派生、GuardedAdamW、batch 上限与逐比特 VLA 冻结证据

总览 三阶段 RL-Token 运行架构 E-2 / F / G L4 在线训练 工程修复 结果与归因
11999 stepsbatch 128π0.5 frozen

把 768 × 2048 的 VLA prefix hidden states 压成一个 2048 维 RL token，同时证明部署用 VLA 一个参数都没有改变。

输入不是原始图像 patch

训练入口以 image_only=True 提取三路图像位置：每路 256 个，共 768 个。它丢弃语言与离散 state token 的输出位置，但保留的是 PaliGemma prefix 主干处理后的最终层 hidden states，不是原始 ViT patch embedding。由于 prefix 内部采用双向 attention，图像位置可能已经混入语言与状态上下文；“可能携带”不等于这些信息被显式分离或完整保留。

\[H\in\mathbb R^{B\times768\times2048},\qquad \bar H=\operatorname{sg}(H),\qquad z_{\mathrm{rl}}=E_\phi(\bar H)\in\mathbb R^{B\times1\times2048}.\]

本项目实际损失

本项目 decoder 从 768 个可学习位置查询开始，每个查询只 cross-attend 到单个 $z_{\mathrm{rl}}$；它不接收真实 token 前缀，且 causal=False。训练入口又以 mask=None 调用模块，因此所有位置、所有维度都进入均值：

\[\widehat H=D_\phi(z_{\mathrm{rl}})\in\mathbb R^{B\times768\times2048}, \qquad \mathcal L_{\mathrm{RLT}} =\frac{\lVert\widehat H-\bar H\rVert_F^2}{B\cdot768\cdot2048}.\]

通用训练入口支持 $\mathcal L_{\mathrm{total}}=\mathcal L_{\mathrm{RLT}}+\alpha\mathcal L_{\mathrm{VLA}}$，本项目取 $\alpha=0$。同时，trainable filter 只把 rlt_module 交给优化器；stop-gradient 阻断重建损失、$\alpha=0$ 关闭 VLA 的 BC 损失、参数过滤器排除 VLA 的 AdamW 与权重衰减，三者共同定义冻结边界。

对比项 论文公式 本项目实现
Decoder 条件 RL token + 此前的真实 embeddings RL token + 768 个可学习位置查询
重建顺序 teacher-forcing 式自回归 非因果并行重建
Mask 因果顺序隐含在公式中 调用时 mask=None
可以声称 论文提出的信息瓶颈目标 本项目复现采用的工程近似

因此，本页只把当前网络称为“RL-Token 风格的全元素重建实现”，不把它写成论文式 (2) 的逐项等价实现。

配置不是重抄一份 TrainConfig，而是从已验证的三相机 BC 配置通过 dataclasses.replace 派生。这样 checkpoint 的 PyTree、数据变换和模型定义天然同构，只覆盖 RLT 必需字段。

这里的“约 2.4 亿可训练参数”只属于离线 Stage-1 的 encoder/decoder。进入在线 RL 后，它们与 VLA 一起冻结；在线更新的是另一组约 230 万参数的 actor/critic，不能把两个阶段的参数规模相加或混称为同一个训练负载。

实际训练、监控与冻结核验命令

以下命令按本项目完成运行时的脚本与参数记录整理。路径只保留仓库相对形式；尖括号内容是需要在本地替换的产物路径。GPU 编号必须在运行前重新核实，示例中的 0,1,2,3 只展示逗号分隔格式，不能据此认定这些卡当前空闲。

训练入口

nvidia-smi --query-gpu=index,memory.used,memory.total,utilization.gpu --format=csv,noheader
nvidia-smi --query-compute-apps=pid,used_memory --format=csv,noheader

export RM75_RLT_GPUS=0,1,2,3
RM75_RLT_BATCH=128 \
RM75_RLT_FSDP=4 \
RM75_RLT_STEPS=12000 \
RM75_RLT_SAVE_INTERVAL=2000 \
bash my_custom_code_files/ruierman75_openpi_rlt/rlt_stage1_rm75/train_rlt_rm75.sh

前两条 nvidia-smi 只读地回答“每张卡占了多少显存、是否存在计算进程”。启动脚本不会自动抢卡；RM75_RLT_GPUS 未设置时会直接退出，目标卡有计算进程时默认也拒绝启动。

参数 本次取值 作用与实际效果
RM75_RLT_GPUS 4 张经人工确认的空闲卡 赋给 CUDA_VISIBLE_DEVICES，同时决定脚本计算的卡数；必须是逗号分隔的物理索引。
RM75_RLT_BATCH 128 全局 batch；必须能被可见 GPU 数整除。本实现四卡 batch 256 实测显存余量不足，128 约为 61.6 GiB/卡。
RM75_RLT_FSDP 4 传给 --fsdp-devices，指定参与 FSDP 分片的设备数；应与本次四卡口径一致。
RM75_RLT_STEPS 12000 传给 --num-train-steps，同时写入 --lr-schedule.decay-steps；因此最终 checkpoint 步号是 11999。
RM75_RLT_SAVE_INTERVAL 2000 同时传给 --save-interval 与 --keep-period，每 2000 步保存并保留一个周期 checkpoint。
train_rlt_rm75.sh — 完成残留进程检查、目标卡占用检查、底模存在性、norm stats 一致性、batch 整除性、日志与产出目录准备，然后后台启动训练。

脚本最终调用的核心命令等价于：

.venv/bin/python -u scripts/train_rlt.py rlt_pi05_rm75_3cam \
  --exp-name rlt_rm75_3cam_frozen \
  --checkpoint-base-dir <STAGE1_CHECKPOINT_ROOT> \
  --num-train-steps 12000 \
  --batch-size 128 \
  --fsdp-devices 4 \
  --lr-schedule.warmup-steps 1000 \
  --lr-schedule.peak-lr 2.5e-5 \
  --lr-schedule.decay-steps 12000 \
  --lr-schedule.decay-lr 2.5e-6 \
  --save-interval 2000 \
  --keep-period 2000 \
  --num-workers 8 \
  --no-wandb-enabled \
  --overwrite
命令项 作用 容易误读的边界
rlt_pi05_rm75_3cam 位置参数，选择从 RM75 三相机 BC 配置派生的 RLT 配置。 它决定数据变换、模型树和底模加载器，不只是一个日志名称。
--exp-name 组成 checkpoint 的实验子目录。 改名会形成另一条实验，不会续接原产物。
--checkpoint-base-dir 指定 Stage-1 产物根目录。 网页不公开私有绝对路径；复现时必须指向有足够空间的本地产物盘。
--num-train-steps 训练更新总数。 本框架从 step 0 计数，所以 12000 次更新对应末步 11999。
--batch-size / --fsdp-devices 定义全局批量与参数分片设备数。 batch 必须被卡数整除；显存可用不等于这些卡没有其他任务。
--lr-schedule.warmup-steps 前 1000 步把学习率升到峰值。 warmup 属于 12000 步总预算，不是额外步数。
--lr-schedule.peak-lr / --lr-schedule.decay-lr 余弦退火的峰值与末值。 都只作用于 rlt_module；不能据此推断 VLA 被优化。
--lr-schedule.decay-steps 余弦退火长度。 必须与总步数同步，否则会提前到末值或训练结束时仍未走完整条调度。
--save-interval / --keep-period 控制保存频率与周期保留。 两者相同意味着每个 2000 步周期点都保留，不只保留最新一次。
--num-workers 数据加载 worker 数。 提高它主要改变输入吞吐和主机资源占用，不改变数学 batch。
--no-wandb-enabled 禁用外部实验上报。 本地日志与 checkpoint 仍然写入。
--overwrite 允许在目标实验目录按“新运行”语义启动。 不能用于续训；复用已有产物目录前必须先核对，避免覆盖有效 checkpoint。

tr 把进度条使用的回车转换成换行，grep '^Step ' 只保留训练步日志，tail -5 显示最近五条；它不会修改日志。verify_stage1_ckpt.py 只解析 checkpoint 的 _METADATA，核对顶层分支、参数 key 集合与 norm stats，不读取张量值，因此只能证明结构同构。真正的冻结实值审计由 compare_vla_weights.py 完成：它读取 RLT 的 vla 子树与 BC 权重，按 bf16 原始字节逐张量比较。本次记录为 51/51 个 VLA 张量逐比特一致；复查时必须阅读输出中的 [cmp] 逐比特相同的张量 与差异汇总，不能只凭进程退出码判定。

收敛曲线

0.1628 是训练批次上的重建 MSE；本次运行没有单独的 held-out 重建 MSE。它证明 encoder/decoder 能拟合当前训练分布上的 hidden states，但不等于 z_rl 已保留所有任务相关信息，更不等于成功率会提升。0.5 也是本项目的工程闸门，不是 RLT 的通用理论阈值。

四层冻结证据

GRADIENT

sg + alpha = 0

hidden target stop-gradient；VLA 行为克隆项关闭。

OPTIMIZER

只开放 rlt_module

VLA 不接收 AdamW 更新，也不进入 decoupled weight decay。

STRUCTURE

两支参数树

checkpoint 顶层恰为 vla 与 rlt_module。

BITWISE

51 / 51 相同

VLA 张量与 BC step 40000 逐比特一致，是决定性证据。

日志中的 param_norm 从 2242.0388 到 2242.0229，变化很小，但它是训练状态的聚合范数，不能解释成“VLA 参数范数”。即使单独记录了 VLA 总范数，聚合统计也不能排除张量内部发生抵消；51 个 VLA 张量逐比特一致才是冻结结论的决定性证据。

非有限数值防线

早期环境中出现过健康若干步后 loss 突变为 inf 的现象。标准 global-norm clip 可写为：

\[\lVert g\rVert_2=\infty, \qquad g'_i=g_i\min\!\left(1,\frac{c}{\lVert g\rVert_2}\right).\]

此时有限分量乘 0 会成为 0，但无限分量执行 $\infty\times0$ 会产生 nan；一旦写入 Adam moments，后续有限梯度也无法自动修复。本项目 GuardedAdamW 在 clip 之前检查的是全局梯度范数，若其非有限就把整棵梯度树置零，再进入 clip。因为 AdamW 仍可能执行 decoupled weight decay，这更准确地说是“近似跳过梯度更新”，而不是保证每个参数逐比特不动。

归因更正：正式完成的健康 run 中，守门器没有被触发。早期 Step 0 全 nan 的直接恢复来自清理后的干净进程状态。因此 GuardedAdamW 是预防性防线，不能被写成这次收敛的原因，也不能声称它同时检查了 loss。

开跑前的七类防线

锁定底模

误用公共 pi05_base 也可能正常降 MSE，却会得到与部署策略不匹配的 z_rl。

配置同构

从三相机 BC 配置派生，避免 shape、dtype 与 PyTree 漂移。

校验 norm stats

配置名变化后复制并逐字节核对资产。

检查计算资源

显式选择空闲卡并识别崩溃残留；不把别的训练进程当作可清理对象。

选择 batch 128

本项目实测 batch 256 在四卡重计算后仍需约 77.74 GiB/卡，超过稳定余量；这是当前硬件与实现的边界，不是算法上限。

轻量结构自检

只解析 Orbax 元数据，不加载完整 21 GB checkpoint。

逐比特权重审计

下游使用前再次对比部署基座与 stage-1 内 vla 子树。

输出给在线阶段什么

Stage-1 checkpoint 里包含 vla 与 rlt_module。在线特征服务加载冻结的 VLA 和 encoder，返回 z_rl[2048] 与冻结 VLA 生成的 ref_chunk[50,8]。decoder 虽保存在 checkpoint 中，但在线请求不会调用；优化器状态也不是部署输入。完整运行关系见 实机运行架构。
