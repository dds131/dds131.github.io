GR00T N1.6/④ 训练与优化
PRETRAINING · POST-TRAINING · OPTIMIZATION

理解 N1.6 训练最重要的是先拆开三个口径：基础模型预训练、NVIDIA 真实机器人任务后训练、公开仓库单节点微调默认。它们使用同一模型家族，但数据混合、训练规模、正则、损失公开程度和实际可训练参数并不相同。

Flow 入站合同与阻断门

schema: groot-n1-6-training.flow-input.v1
contract_id: groot-n1-6.flow-matching-to-training.v1
producer: groot-n1-6-flow-matching
status: static-specified
target_space: normalized-representation-space
container_shape: [B, 50, 128]
interpolation: x_t=(1-t)*epsilon+t*A
velocity_target: A-epsilon
time_rule: beta-1.5-1.0-then-one-minus-times-0.999
loss_reduction: global-valid-action-elements
required_bindings: [representation_id, statistics_id, action_mask, embodiment_mapping]

静态合同齐备只允许进入设计与页面转换，不代表数据或训练已经验证。任一 representation/statistics ID、50×128 shape、mask 语义或 embodiment mapping 缺失时必须 fail closed；本页不改写 Flow 的速度符号、时间方向或分母。

一、三类训练配置不能混成一张配方

口径 步数 / batch 数据 可确认的参数范围 证据边界
官方基础预训练 300K updates；global batch 16384 N1.5 混合 + YAM/Genie1/BEHAVIOR/G1 数千小时 Research 明确解冻 VLM 顶部四层；训练 32 层 DiT 等 未公开完整 mixture 数值、全部 loss 实现、学习率与优化器细节
官方任务后训练 通常 10K–30K；global batch 1K 或更小 小型任务专属数据；按需与预训练数据共训 官方说明使用更强状态正则、增强、共训，并按实验使用 DAgger/RTC 经验总结，不是一套统一命令；未公开每项任务的完整冻结表与超参
公共单节点微调默认 10K updates；声明 global batch 64；accumulation 1 CLI 接受一个 LeRobot 数据集 tune_llm/visual=false，tune_projector/DiT=true；官方 checkpoint 的 top-4 设置仍需单独核对 可运行的后训练入口，不等于基础预训练配方

max_steps 在 Trainer 中表示优化器更新次数。官方基础预训练的 300000×16384 对应约 49.15 亿个采样槽位，但绝不是 49.15 亿条独立轨迹：同一 episode 可被重复采样并切出不同时间窗，mixture 也会按权重重采样。

二、基础预训练：能确认什么，不能补猜什么

flowchart LR
  D[N1.5 数据混合] --> M[多本体预训练 mixture]
  Y[YAM / Genie1 / BEHAVIOR / G1] --> M
  M --> V[VLM retained top 4 trainable]
  M --> A[32-layer DiT + embodiment boundaries]
  V --> L[动作 Flow Matching<br/>+ 官方所述 world modeling]
  A --> L
  L --> C[GR00T-N1.6-3B checkpoint]

Research 公开了 300K updates、global batch 16384、顶部四层解冻等事实，但没有公开基础预训练的 AdamW 参数、学习率曲线、world-modeling loss 权重、全部冻结集合或逐来源精确采样权重。因此不能把公共 FinetuneConfig 的 1e-4、5% warmup 或单节点冻结设置倒推为基础预训练配方；模型卡中的联合目标也不能由常规公开 forward 完整复现。

flowchart LR
  C[checkpoint model/config] --> M[model config merge]
  F[FinetuneConfig / CLI] --> E[experiment config]
  T[TrainingConfig defaults] --> E
  E --> A[TrainingArguments actually passed]
  M --> R[resolved trainability]
  A --> R

文本回退：最终行为由 checkpoint/model config、FinetuneConfig/CLI、TrainingConfig、experiment 合并与实际传入 TrainingArguments 的字段共同决定；未传字段不能仅凭 dataclass 存在就认定生效。

3.1 global_batch_size 与累积步数的实现陷阱

当前 experiment.py 先计算

\[B_{\mathrm{device}}=\left\lfloor\frac{B_{\mathrm{declared}}}{N_{\mathrm{gpu}}}\right\rfloor,\]

再把 gradient_accumulation_steps=G 交给 Trainer。因此近似的实际有效 batch 是

\[B_{\mathrm{eff}}=B_{\mathrm{device}}\,N_{\mathrm{world}}\,G.\]

当 num_gpus 与实际 world size 一致、声明 batch 可整除且 \(G=1\) 时，\(B_{\mathrm{eff}}=B_{\mathrm{declared}}\)。但把 accumulation 从 1 改成 4、仍把 declared global batch 写 64，会得到约 256 的有效 batch，而不是继续保持 64；不可整除时还会因整数除法向下取整。复现日志应记录 per-device batch、world size、accumulation 和计算后的 \(B_{\mathrm{eff}}\)，不能只抄 global_batch_size 字段。

3.2 学习率时间线

当前入口只把 warmup ratio \(r=0.05\) 传给 Trainer。若总更新数为 \(T\)、峰值学习率为 \(\eta_0\)，忽略取整后可写成

\[\eta(s)= \begin{cases} \eta_0\dfrac{s}{rT}, & 0\le s<rT,\\[6pt] \dfrac{\eta_0}{2}\left[1+\cos\left(\pi\dfrac{s-rT}{(1-r)T}\right)\right], & rT\le s\le T. \end{cases}\]

warmup 与 cosine decay 可以缓和训练初期和末期的步长变化，但不会保证闭环指标随 training loss 单调改善。具体 warmup step 还受 Trainer 的整数取整规则影响。

四、哪些参数实际会更新

动作头由三个开关控制：

  • tune_projector：这个名字容易误解；它实际共同控制 state encoder、action encoder、action decoder、动作位置 embedding 与可选 state mask token；
  • tune_diffusion_model：控制 32 层 AlternateVLDiT；
  • tune_vlln：控制 VLM token 进入动作头前的 LayerNorm。该字段未暴露在 FinetuneConfig CLI 中，通常沿用 checkpoint/模型配置。

VLM 侧由 tune_llm、tune_visual、tune_top_llm_layers 控制。固定实现先在 tune_llm=false 时冻结整个语言模型，再按 tune_top_llm_layers 重新启用截断骨干的顶部若干层。官方 checkpoint 保存 top-4 设置，而单节点 CLI 没有单独暴露这个字段，所以在它未被其它配置覆盖时，tune_llm=false 仍可能有顶部四层 requires_grad=true。tune_visual=false 则冻结 vision model 与 mlp1。

requires_grad、train/eval mode 与 dtype 是三条独立轴
模块 requires_grad mode dtype/边界
DiT / state-action projector 由 tune_diffusion_model / tune_projector 控制 随训练流程 混合精度不改变所有权
VLM language model 全冻结后可按 tune_top_llm_layers 重开顶部层 固定实现可保持 eval eval 不等于冻结或 requires_grad=false
vision model + mlp1 tune_visual=false 时冻结 仍参与前向 冻结不等于从前向图中删除

必须打印而不是猜。 开训前应保存合并后的 model/processor/training 配置，列出全部 requires_grad=true 参数及数量，并记录各模块 train/eval 状态、源码 commit、checkpoint revision。只看 CLI 的两个布尔值无法还原最终冻结集合。

五、一次参数更新发生了什么

flowchart LR
  MB[micro-batch forward] --> L[masked Flow MSE]
  L --> B[backward / accumulate]
  B --> G{accumulation boundary}
  G --> C[gradient clipping]
  C --> O[AdamW step]
  O --> S[cosine scheduler step]
  S --> K[checkpoint / optional eval]

文本回退：每个 micro-batch 前向和反向先累积梯度；仅在 accumulation 边界执行裁剪、AdamW 更新与 scheduler 更新，再按保存间隔写 checkpoint，eval 只在显式启用时运行。

micro-batch → 图像/语言/状态/动作处理
            → VLM 条件 token
            → 噪声动作 + Beta 时间
            → 32 层 AlternateVLDiT 速度预测
            → masked flow-matching MSE
            → backward / 累积梯度
到达 accumulation 边界
            → gradient clipping
            → AdamW step
            → cosine scheduler step
            → 按 save_steps 保存 checkpoint
            → eval 仅在显式启用时运行

AdamW 对梯度的一阶矩、二阶矩做指数移动平均，并把 weight decay 与梯度更新解耦。仓库把 optimizer 创建交给 Transformers；若需要逐位复现，应记录所用 Transformers 版本以及最终 optimizer 的 \(\beta_1,\beta_2,\epsilon\)，不要把框架默认值伪装成 N1.6 Research 公布的专属超参。

六、更快收敛与过拟合：事实和机制解释要分开

NVIDIA Discussion 的直接观察是：N1.6 比 N1.5 收敛更快、动作更平滑，同时需要更谨慎的正则以防过拟合。把这一现象归因于更强 VLM、更深 DiT 或相对动作是合理假设，但官方没有给出逐因素消融，不能写成已证明的单一原因。对小任务数据，背景、物体初始位置、相机视角和固定语言模板都可能成为捷径，因此 training loss 下降不保证闭环成功率继续上升。

state dropout

固定实现按样本用可学习 mask token 替换整段 state features，迫使策略更多利用其它条件；过强会丢失本体反馈。

state additive noise

训练期在编码后的 state features 上加高斯噪声。模型配置支持它，但单节点 FinetuneConfig 未直接暴露该参数，需要更底层配置。

图像增强

CLI 可设置颜色抖动、随机旋转和额外 mask-guided 增强；强度必须通过真实任务验证，不能默认越强越好。

预训练数据共训

Research 报告它有助于正则化后训练。公共单节点 CLI 只构造一个数据集；多数据集 mixture 需使用底层 DataConfig 配置路径。

七、DAgger：官方建议与公开实现边界

离线示教数据来自专家状态分布 \(d_{\pi_E}\)，部署时学习策略访问的是 \(d_{\pi_\theta}\)。DAgger 的通用迭代是：

  1. 用当前策略运行真实或仿真闭环，并设置安全接管；
  2. 在策略实际访问的状态上由专家提供动作标签；
  3. 将新标注与已有数据聚合，并记录采样轮次；
  4. 重新训练或继续后训练，再进行独立闭环评估；
  5. 重复到性能、失败覆盖或安全指标趋于稳定。

NVIDIA Discussion 推荐真实机器人表现不足时使用 DAgger。它针对的是策略诱导的状态分布偏移，不是奖励/Advantage 更新；普通 N1.6 后训练仍是监督式动作学习。固定 n1.6-release 没有提供一条可直接运行的 DAgger 命令或自动专家标注管线，因此上述步骤是需要机器人系统、标注与训练流程共同实现的工作流，不应写成仓库内置功能。

八、RTC：官方实验使用，不等于固定版本已完整发布

Research 表示 train-time 与 test-time RTC 都能改善异步 rollout 的平滑性和鲁棒性，并用于 Unitree G1 与 Bimanual YAM 实验。公开部署文档把 RTC 描述为动作 inpainting/重叠融合：新块开头与旧块尚未执行的部分重叠，并用 overlap、frozen 等参数管理切换。

但同一固定版本文档也明确写明：官方 RTC 支持“coming soon”，当前伪代码可能需要手工适配。因此可以介绍其原理和官方实验结论，不能声称 n1.6-release 已提供与内部 train-time RTC 等价的完整训练实现，也不能把文档伪代码当成已验证 API。RTC 的推理时序与异常现象见 ⑤ 推理闭环与反常现象。

九、建议的训练监控

  • training loss、held-out open-loop loss 与闭环指标分开记录；默认 eval 关闭时需主动配置；
  • 闭环 success / average progress，使用多个随机种子与足够 episode，并报告不确定性；
  • per-device batch、world size、accumulation 与实际有效 batch；
  • action mask 有效比例、动作裁剪/饱和比例、逐 horizon 相对动作分布；
  • 视觉、语言、状态消融，检查是否依赖固定背景、相机或语言模板；
  • data processing、backbone、action head 与端到端延迟分别计时；
  • 块边界速度/加速度跳变、恢复行为与安全接管率；
  • 保存最终生效配置、requires_grad 清单、源码 commit、checkpoint revision 与 statistics hash。
