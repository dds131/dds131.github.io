一、本页在专题中的位置

论文告诉你「用了多少数据、跑了多少步」，源码告诉你「每个参数怎样执行」。两层数字不能直接互换：论文的 200K 次是 64 卡、全局 batch 1024 的预训练；公开循环每取一个 batch 就执行一次 optim.step()，没有梯度累积逻辑，因此 --batch_size 16 在 64 个进程下对应名义全局 batch 1024。由于各进程数据流没有显式互斥分片，单步独立样本数仍可能小于 1024。脚本默认 --iters 1000000 也不是论文的训练步数。比较训练规模时至少要报告优化器步数、进程数、每进程 batch，以及数据重叠和任何自行增加的梯度累积。

本页按这两层分开组织，每个数字都标注出自哪一层。

290K预训练 episode
64 / 1024A100 卡数 / 全局 batch
4学习率参数组
3高风险参数语义
9MLoRA 可训练参数
本页刻意不讲：网络结构与张量形状（子页 ②）、损失与动作表示（子页 ③）、源码调用链（子页 ⑤）、推理与部署（子页 ⑥）、反常现象排查（子页 ⑦）。两步适配的设计动机与证据边界在子页 ① 第 7.1 节，本页只讲它在代码里怎么实现。
创新点定位：X-VLA 的核心方法创新是域特定 Soft Prompt。动作对齐、时间降采样、加权采样、定制学习率和两步适配属于支撑效果的重要训练配方；Table 1 对前三项只给出组合消融，不能拆分各自贡献。AdamW、LoRA、余弦调度以及本页列出的代码陷阱都是已有方法或实现事实，不应包装成 X-VLA 的独立创新。
证据口径：本文以论文 v1、官方仓库 main@6bc2513 和已发布的 2toINF/X-VLA-Pt 配置为准，核验日期为 2026-10-04。论文数字表示作者报告的训练配方；README 命令只是公开示例；运行时权重、学习率、数据流和保存行为以该源码快照为准。三者不一致时不把示例命令反推成论文实验的完整启动配置。

二、预训练数据：290K episodes 的组成

2.1 数据源与采样权重

论文第 5.1 节写：在 290K episodes 的异构混合数据上预训练，数据来自 Droid、RoboMind、AGIBOT 三个来源，横跨七个平台、五类机械臂，从单臂到双臂都有（层一）。

Appendix G 的 Table 8 给出逐项配比（层一）。源码 datasets/domain_config.py 的 DATA_WEIGHTS 前七项与之完全一致（层二）；但这张表先表示声明的目标权重，运行时是否命中还取决于元数据生成的采样键，见表后说明：

数据源 轨迹数 采样权重 episode 自然比例 相对自然比例（直观）
AGIBOT 141K 0.40 约 0.49 被压低
Droid-Left 45K 0.15 约 0.16 基本持平
Droid-Right 45K 0.15 约 0.16 基本持平
RoboMind-UR 25K 0.10 约 0.09 略抬高
RoboMind-Franka 19K 0.10 约 0.07 明显抬高
RoboMind-Agilex 11K 0.07 约 0.04 明显抬高
RoboMind-Dual-Franka 2K 0.03 约 0.007 抬高约 4 倍

轨迹数合计 288K，与「约 290K」吻合；权重合计 1.00。

怎样读这组目标权重。它比 episode 数的自然比例更接近均匀：最大与最小数据源的 episode 数相差约 70 倍，声明权重只相差约 13 倍。顶层循环每次按归一化权重选择一个数据源生成器，再从它产出一个样本；只有当运行时名称命中相应键且各生成器能持续供样本时，输出样本的数据源期望占比才等于该表。它不是直接抽 episode：episode 长度与候选帧数会改变同一数据源内部各 episode 的贡献和重访频率。因此「权重 ÷ episode 自然比例」只能帮助理解源级倾向，不能当作每条 episode 的精确重复倍数。降低大源支配、提高小源曝光是合理解释，但「必然防止欠拟合或过拟合」没有单独实验支持。论文 Table 8 第 3 行重复写了 Droid-Left；结合总数、权重和 Table 10，应为 Droid-Right。
LeRobot v2.1 元数据存在采样键错位。通用元数据以 dataset_name 作为 self.metas 的键，能直接命中上表；LeRobot v2.1 分支却以 root_path 为键，而 __iter__ 正是用这个键执行 DATA_WEIGHTS.get(name, 1.0)。若 root_path 是普通文件路径，它不会命中 AGIBOT，该源会回退到 1.0 而不是 0.4；任何未登记名称也同样回退到 1.0。多源训练必须在启动时打印并核对“运行时键、原始权重、归一化权重”，或改为始终按 robot_type/dataset_name 查表。公开仓库未附预训练 meta，因此不能仅凭常量表证明作者运行时确实用了 0.4。

2.3 验证集怎么构造

论文用 AGIBOT-beta 中被排除出训练划分的轨迹作验证集，覆盖 189 个任务、每任务 3 条，报告预测轨迹与真值之间的 \(\ell_1\) 误差（层一）。

这个指标是第八节消融表的中列。论文据此把验证误差作为预训练性能代理，但证据只来自该组累积消融与 Simpler-WidowX 下游结果；它不是跨平台、跨动作表示都成立的定律，而且表中本身存在一次「误差下降、成功率反降」的反例。

三、数据管线：六处会影响结果的处理

从原始轨迹到一个训练样本，源码中有六类关键处理。论文只概括动作对齐、意图抽象和均衡采样；下面的具体顺序、阈值与回退行为来自公开源码（层二）。流程图描述使用固定时间窗口的主路径；AGIWorld handler 改用按片段长度归一化的重采样，不能套用其中的 qdur 结论。

flowchart LR
  M["meta 文件<br/>按数据源分组"] --> W["按 DATA_WEIGHTS 加权<br/>random.choices 选数据源"]
  W --> T["数据源内轨迹顺序<br/>random.shuffle"]
  T --> E["episode 内候选帧下标<br/>random.shuffle"]
  E --> Q["未来 qdur 秒窗口<br/>等时间间隔插值出 31 点"]
  Q --> F["近静止开头过滤<br/>首锚点间隔多通道变化低于阈值则丢弃"]
  F --> L["语言增强<br/>从同义句表随机取一条"]
  L --> A["切分为 1 个 proprio<br/>加 30 个动作锚点"]
  A --> B["组 batch"]

3.1 三层打散

# datasets/dataset.py，__iter__ 节选
gens = [iter(self._iter_one_dataset(n)) for n in names]
ws = [DATA_WEIGHTS.get(n, 1.0) for n in names]
s = sum(ws); ws = [w / s for w in ws]
while True:
    i = random.choices(range(len(names)), weights=ws, k=1)[0]
    yield next(gens[i])

三层依次是：数据源之间按权重随机选择生成器；数据源内部打乱 episode 顺序；episode 内部打乱候选帧下标。这实现的是概率意义上的混合，不是轮转，也不保证每个 batch 严格满足目标比例。源内生成器仍会把当前 episode 的候选样本产出完，再进入下一个 episode；因此它没有做全局的跨 episode 样本缓冲洗牌。

在开始采样前还存在元数据键覆盖。通用格式执行 self.metas[dataset_name] = meta，LeRobot v2.1 格式执行 self.metas[root_path] = meta；同一键出现两次时，后读文件会静默覆盖先读文件，而不是合并轨迹。目录中 JSON 的枚举顺序也不应被当成数据契约。若要把同一数据源拆成多个 meta 文件，应先显式合并 datalist，或为每份数据使用唯一键并同步配置采样权重。
_iter_one_dataset 用 yield from self._iter_one_dataset(...) 递归开启下一轮遍历；每完整跑完一轮，生成器委托链都会增加一层。风险取决于训练期间完成了多少轮，而不只取决于名义 episode 数：小数据集、短 episode 或长时间训练更容易累积较深的链。仓库没有给出长期运行边界，稳妥实现应改为显式 while True。

3.2 时间重采样：30 个锚点是怎么取的

# datasets/domain_handler/base.py，iter_episode 节选
L = interp1d(lt, left,  axis=0, bounds_error=False, fill_value=(left[0],  left[-1]))
R = interp1d(rt, right, axis=0, bounds_error=False, fill_value=(right[0], right[-1]))
ref = (lt + rt) / 2.0
for idx in idxs:
    cur = ref[idx]
    q = np.linspace(cur, min(cur + qdur, float(ref.max())), num_actions + 1, dtype=np.float32)
    lseq = torch.tensor(L(q)); rseq = torch.tensor(R(q))

在当前时刻之后的 qdur 秒窗口内等时间间隔插值出 num_actions + 1 = 31 个点，第 0 点作本体状态、后 30 点作动作块。下表覆盖公开仓库中采用这一固定时间窗口写法的 handler（层二）：

在未缩短窗口且 handler 使用均匀时间轴时，名义锚点间隔与窗口内原始帧数分别约为

\[\Delta t_{\mathrm{anchor}}=\frac{qdur}{30}, \qquad N_{\mathrm{source}}\approx f_{\mathrm{sample}}\,qdur.\]

预训练 handler 的 30 Hz 与 15 Hz 数据都投到 4 秒、30 个未来锚点上，因此在均匀时间轴下，它们的目标预测时域和锚点时间坐标一致；这正是论文所谓 intention abstraction（意图抽象）。若 handler 提供真实时间戳，插值会使用时间戳而非名义 freq；靠近片尾时窗口还会缩短。该处理不会自动消除坐标系、控制接口、动作尺度或原始采样信息量的差异，不能说动作本身已经完全可比。

三个预训练源统一取 4 秒；下游多数 30 Hz 仿真 handler 取 1 秒，而 RT1、Bridge、WidowX 分别取 10、5、5 秒。这个表呈现出低频源常用更长窗口的现象，但源码没有证明 qdur 由采集频率唯一决定。迁移时应先按任务速度、控制语义和闭环执行长度确定预测时域，再检查采样频率能否为 30 个锚点提供足够信息；不能只从 Hz 反推 qdur。

靠近 episode 尾部时，min(cur + qdur, ref.max()) 会缩短实际预测窗口，于是锚点间隔也随之变小。fill_value 是左右时间轴不完全一致时的越界保护，不是窗口收缩的原因。各 handler 通常还会在 index_candidates 中排除末尾若干帧，所以不能笼统断言 30 个锚点会全部退化到终点；实际最短窗口必须结合对应 handler 的候选索引边界计算。
AGIWorld 是另一条时间语义。AGIWolrdHandler 先按任务配置的 DOMAIN2CHUNKSIZE 截取帧片段，再把该片段的归一化坐标 [0,1] 插值为 31 点；代码没有把帧号换成秒，也没有统一的 freq/qdur。因此同为 30 个动作锚点，不代表与上表具有相同的物理预测时域。

3.3 首个间隔近静止的样本被丢弃

# datasets/domain_handler/base.py，iter_episode 节选
# Skip static segments
if (lseq[1] - lseq[0]).abs().max() < 1e-5 and (rseq[1] - rseq[0]).abs().max() < 1e-5: continue

若第 0、1 个锚点之间，左右两侧被检查向量的最大绝对变化都小于 \(10^{-5}\)，整个样本会被跳过。这里检查的是 handler 产出的原始动作向量，通常包含位置、Rotate6D 和夹爪等通道，不能简写成只检查「位姿」。

这个规则只看第一个锚点间隔：保留下来的动作块后段仍可静止；一侧运动时，另一侧的静止监督也仍会存在。因此它会减少「以近静止开头」的样本，但不能推出模型几乎看不到保持动作。更重要的是，同一个 \(10^{-5}\) 阈值作用于不同单位和不同 \(\Delta t_{\mathrm{anchor}}\)，过滤强度可能随域变化；复现时应统计各域被过滤比例，而不是只看阈值本身。

3.4 语言增强会在 episode 内继承状态

# datasets/domain_handler/base.py，iter_episode 循环体内
if training and lang_aug_map and ins in lang_aug_map:
    ins = random.choice(lang_aug_map[ins])

ins 在这里被就地重新赋值。iter_episode 对同一个 episode 的每个候选帧都走一遍这个循环体，因此：

  • 第 1 个样本：ins 是原始指令，命中 lang_aug_map，被替换成某条同义句。
  • 第 2 个样本开始：ins 已经是那条同义句。除非同义句本身也是 lang_aug_map 的键，否则 ins in lang_aug_map 为假，不再替换。

在常见的「只有原句是键」映射中，同一 episode 的已保留样本会共用第一次抽到的同义句，而不是每个样本独立重抽；若同义句也作为键，则会沿映射继续变化。因此准确结论是 ins 的就地改写会把语言状态带到后续样本，具体次数由映射结构决定。

这段代码来自 BaseHDF5Handler，并且受 training 条件保护；AGIBOT/LeRobot 等独立 handler 有相似的就地改写，但没有同样的 training 判断。若验证 meta 仍携带 lang_aug_map，这些路径也可能改写评测指令，不能把本节结论无条件推广到所有 handler。

3.5 handler 注册与 domain id 是两道独立检查

# datasets/dataset.py，_iter_one_dataset 节选
sample["domain_id"] = torch.tensor(DATA_DOMAIN_ID.get(robot_type, 0))

这行代码确实会让 DATA_DOMAIN_ID 查不到的 robot_type 默认取 0，而 0 号槽位对应 Bridge 的 prompt 与私有动作投影（层二，domain_config.py）。但它不是完整未知类型的第一道处理：此前的 get_handler_cls(robot_type) 使用严格注册表，完全没有注册 handler 的类型会先抛出 KeyError，不会走到这里。

真正会静默回退的是：已经在 handler registry 注册、却漏写 DATA_DOMAIN_ID 的新类型。此时它会使用 domain 0 的 Bridge soft prompt 与动作投影；若启用异构视觉投影，还会选中 0 号视觉参数。损失可能仍能下降，但这不是保证。新增数据源必须同时登记 handler、domain id 与采样键，并在启动时断言三者一致。

四、优化器与四个参数组

4.1 参数如何分组

# train.py
def build_optimizer(model, lr, weight_decay, betas=(0.9, 0.95), lr_coef_soft=1.0):
    vlm_params          = list(model.vlm.parameters())
    soft_prompt_params  = list(model.transformer.soft_prompt_hub.parameters())
    action_params       = list(model.transformer.action_decoder.parameters()) \
                        + list(model.transformer.action_encoder.parameters())
    exclude = set(map(id, vlm_params + soft_prompt_params + action_params))
    transformer_core_params = [p for p in model.parameters() if id(p) not in exclude]
    param_groups = [
        {"name": "vlm",              "params": vlm_params,              "lr": 0.0,             "weight_decay": weight_decay},
        {"name": "transformer_core", "params": transformer_core_params, "lr": 0.0,             "weight_decay": weight_decay},
        {"name": "soft_prompts",     "params": soft_prompt_params,      "lr": lr*lr_coef_soft, "weight_decay": weight_decay},
        {"name": "action_heads",     "params": action_params,           "lr": lr,              "weight_decay": weight_decay},
    ]
    return AdamW(param_groups, betas=betas)
参数组 包含什么 大致规模
vlm 整个 Florence-2 Large（DaViT 视觉塔 + 12 层语言 encoder） 最大
transformer_core 24 层 block、位置编码、末尾 LayerNorm、两路视觉投影（用排除法得到） 次之
soft_prompts 只有 soft_prompt_hub 约 0.98M
action_heads action_encoder 与 action_decoder 两个私有投影 约 2.86M
transformer_core 用排除法获得：新加但未显式归组的模块会静默进入该组，并按基准学习率训练。四组都直接接收同一个 weight_decay，代码没有常见的 bias、LayerNorm、embedding no-decay 列表；修改模型或复现论文 0.01 时，两件事都应显式检查。域私有参数又以稠密 nn.Embedding 表保存多行：当前域使整张参数获得非空梯度后，AdamW 的解耦衰减会作用于整张表，未被当前 batch 选中的域行也可能缩小。需要保留旧域能力时，应评估行级冻结、更新掩码或 no-decay，而不能把“本 batch 未索引该行”当作完全不更新。

4.2 每步的学习率调度

# train.py
def update_group_lrs(optim, step, args):
    base = {
        "vlm":              args.learning_rate * args.learning_coef,
        "transformer_core": args.learning_rate,
        "soft_prompts":     args.learning_rate * args.learning_coef,
        "action_heads":     args.learning_rate,
    }
    def schedule(step, base_lr):
        return linear_warmup_cosine(step, args.freeze_steps, args.warmup_steps,
                                    args.iters, base_lr, args.min_lr_ratio)
    if step < args.freeze_steps:
        set_group_lr(optim, "vlm", 0.0)
        set_group_lr(optim, "transformer_core", 0.0)
        set_group_lr(optim, "soft_prompts", base["soft_prompts"])
        set_group_lr(optim, "action_heads", base["action_heads"])
    else:
        for name, base_lr in base.items():
            new_lr = schedule(step, base_lr) if args.use_cosine_decay else base_lr
            set_group_lr(optim, name, new_lr)

调度函数本体：

def linear_warmup_cosine(step, start, warmup, total, base_lr, min_ratio):
    if step < start: return 0.0
    progress = step - start
    if progress < warmup:
        return base_lr * (progress / max(1, warmup))
    remain = max(1, total - (start + warmup))
    ratio = 0.5 * (1 + math.cos(math.pi * min(1.0, (progress - warmup) / remain)))
    return base_lr * (min_ratio + (1 - min_ratio) * ratio)

令 \(F\) 为 freeze_steps、\(W\) 为 warmup_steps、\(N\) 为 iters、\(b_g\) 为组 \(g\) 的基准学习率。开启 --use_cosine_decay 后，源码对应的分段函数是

\[\eta_g(s)= \begin{cases} 0, & s<F,\ g\in{\mathrm{vlm},\mathrm{core}},\\ b_g, & s<F,\ g\in{\mathrm{prompt},\mathrm{action}},\\ b_g\dfrac{s-F}{\max(1,W)}, & F\le s<F+W,\\ b_g\left[r_{\min}+(1-r_{\min})\dfrac{1+\cos\!\left(\pi\,\min\!\left(1,\dfrac{s-F-W}{\max(1,N-F-W)}\right)\right)}{2}\right], & s\ge F+W. \end{cases}\]

这个公式揭示了一个容易漏掉的边界：当 \(W>0\) 时，在 \(s=F\) 所有组的学习率都等于 0；soft prompt 与 action head 会从冻结阶段的基准学习率突然降到 0，再随其余两组一起 warmup。若 \(W=0\)，第三段为空，\(s=F\) 直接进入余弦段并取 \(b_g\)。不开 --use_cosine_decay 时，上述 warmup 与余弦段全部消失，四组在边界直接切到各自基准学习率并保持恒定。在常规的 \(N>F+W\) 配置下，训练实际更新步为 \(s=0,\ldots,N-1\)；理论最低值 \(r_{\min}b_g\) 在 \(s=N\) 才精确达到，所以最后一个实际更新步会略高。

脚本没有校验 \(N>F+W\)。若总步数不超过冻结步数与 warmup 步数之和，训练可能始终停留在局部阶段或尚未升到基准学习率，也不会进入预期的余弦衰减段；修改三个参数时应把这一关系作为启动前断言。

不要把适配默认值带回预训练。论文第 4.2.1 节明确写的是：预训练阶段从一开始就联合优化 backbone 与各域 soft prompt。公开脚本却默认 freeze_steps=1000；若把这份脚本用于论文式预训练而不覆盖该参数，前 1000 步会只更新 prompt 与动作投影，与论文配方不一致。仓库没有发布预训练启动命令，因此不能把脚本默认值当作论文预训练配置；要对齐“从第 0 步联合训练”，至少应显式设为 --freeze_steps 0，并另外核对步数、weight decay、进程数与数据元信息。

4.3 训练步的完整顺序

# train.py，训练循环节选
update_group_lrs(optim, global_step, args)          # 先按当前 step 更新四组 lr

loss_dict = model(**inputs)
loss = sum(loss_dict.values()) # 当前 action_space 返回的全部损失直接求和；默认 ee6d 为三项
accelerator.backward(loss)
if args.max_grad_norm:
    accelerator.clip_grad_norm_(model.parameters(), args.max_grad_norm) # 默认 1.0
optim.step()
optim.zero_grad()

顺序是 反向 → 裁剪 → 更新 → 清零，梯度裁剪排在优化器之前，符合常规。混合精度不在脚本里设置，而是由外部的 accelerate launch --mixed_precision bf16 决定。

论文目标与当前训练代码并不相同。论文把预训练写成速度场 Flow Matching；当前 model.forward 对位置/旋转通道直接监督干净动作，对夹爪通道使用 BCE logits，随后由这里把各分项相加。加载公开权重时应复现源码目标；若按论文公式改成速度回归，需要重新训练，不能沿用当前采样器并假定等价。完整代数与损失归约见子页 ③。
dataloader 没有经过 accelerator.prepare。模型与优化器仍经过 prepare，所以常规多进程训练会包装模型并同步梯度；这里缺失的是 Accelerate 对数据流的分片。普通 DistributedSampler 不适用于 IterableDataset，但 Accelerate 本身提供 IterableDatasetShard；因此「不 prepare 才正确」并不成立。当前实现只用不同的 rank/worker 随机种子产生独立随机流，而 InfiniteDataReader.__iter__ 没有按 get_worker_info() 或 rank 显式分片。随机流不同不等于样本互斥，多进程和四个 persistent worker 之间仍可能重复轨迹或帧。应记录样本标识实测重叠率，再决定采用显式分片、集中分发还是接受有放回采样。

4.4 保存不是完整断点续训

训练脚本在保存点写出模型、processor 和只含 global_step 的 state.json，但没有保存 AdamW 状态、随机数状态、dataloader/worker 状态，也没有读取 state.json 恢复步数的逻辑。直接从某个模型目录重新启动时，优化器和手工学习率调度都会从第 0 步开始，freeze_steps 也会再次执行；这与从原训练现场继续并不等价。peft_train.py 还没有保存 processor。

若目标是真正续训，应保存并恢复模型、优化器、全局步数与各随机数状态，并验证数据流恢复策略；仅把 save_interval 调小只能增加模型快照数量，不能获得完整 resume 能力。

五、三个容易被参数名或文档误读的行为

这三处是复现时最容易出错的地方（层二）：learning_coef 的 argparse 帮助文本不完整；freeze_steps 的名称容易被理解为真正关闭梯度；README 示例虽传了 warmup_steps，却没有开启使它生效的余弦调度开关。

5.1 learning_coef 不只作用于 soft prompt

README 与 argparse 的 help 都写成 “LR multiplier for soft prompts”。但 update_group_lrs 里它同时乘在 vlm 组上：

base = {
    "vlm":              args.learning_rate * args.learning_coef,   # ← 也乘了
    "transformer_core": args.learning_rate,
    "soft_prompts":     args.learning_rate * args.learning_coef,
    "action_heads":     args.learning_rate,
}

论文正文第 4.2.1 节的表述反而更准确——原文写的是 “a reduced learning rate for the soft prompts as well as for the vision–language modules“，即降低的是 soft prompt 以及视觉语言模块的学习率。按 README 示例传 --learning_coef 0.1，实际效果是 Florence-2 整个主干也只用十分之一的学习率——这是一个有实质影响的差别，而不是文档措辞问题。

5.2 freeze_steps 不是真的冻结

它只是把两个参数组的学习率置为 0，不修改 requires_grad：

学习率为 0 时，AdamW 的参数步和解耦 weight decay 都乘以 0，所以参数值暂时不变；但一、二阶矩仍按梯度更新：

\[m_s=\beta_1m_{s-1}+(1-\beta_1)g_s, \qquad v_s=\beta_2v_{s-1}+(1-\beta_2)g_s^2.\]

因此这只是在参数值层面「冻住」，并不等价于 requires_grad=False：对所有实际得到梯度（grad is not None）的参数，梯度仍会计算和同步，AdamW 的一、二阶矩仍会更新，解冻后的更新也会受冻结期状态影响；没有梯度的参数则不会进入该次 AdamW 更新。模型整体仍处于 train() 模式，冻结组中的 dropout 等训练态算子不会因此关闭。脚本还把 model.parameters() 全部交给全局梯度裁剪，所以零学习率组中实际存在的梯度也计入总范数，可能缩小 prompt/action head 的有效梯度。当前写法没有带来真正冻结应有的计算、通信和优化器状态节省。若要真冻结，应关闭相应参数的梯度，并明确处理解冻时的参数组、AdamW 状态和裁剪集合。PEFT 是另一种只训练少量参数的路径。

5.3 warmup_steps 默认不生效

linear_warmup_cosine 只在 args.use_cosine_decay 为真时才被调用，而该开关的 argparse 定义是：

parser.add_argument("--use_cosine_decay", action="store_true", default=False)

默认关闭，且 README 的示例启动命令里也没有这个开关：

accelerate launch --mixed_precision bf16 train.py \
    --models '2toINF/X-VLA-Pt' --train_metas_path /path/to/meta_files.json \
    --learning_rate 1e-4 --learning_coef 0.1 --iters 50000 \
    --freeze_steps 1000 --warmup_steps 2000

按这条命令跑，--warmup_steps 2000 完全不起作用：1000 步之后学习率直接跳到各组的基准值并保持恒定到结束，既没有 warmup 也没有衰减。

即使打开 --use_cosine_decay，warmup 也从 freeze_steps 开始。默认「1000 + 2000」要到第 3000 步才回到基准学习率，而且在第 1000 步提示与动作头也会从基准值重置到 0。它只在「先局部、后联合」的阶段顺序上接近论文；论文写的是 1000 步局部训练后接 1000 步 warmup，步数与边界行为都不完全一致。

六、两步适配：论文配方与代码的对应

论文 Appendix H 写（层一）：前 1000 次迭代只更新 soft prompt 与动作头、其余参数全部冻结；随后用 1000 次迭代的 warm-up 把学习率逐步恢复到默认值，进入联合训练。

论文的描述 代码里对应什么 结论
前 1000 步只训提示与动作头 freeze_steps=1000 时把 vlm 与 core 的学习率置零 参数值不变，但不是真冻结，见 5.2
随后 1000 步 warm-up 默认 warmup_steps=2000，且必须显式开启 --use_cosine_decay 不一致：步数不同，README 默认还不生效
恢复到默认学习率后联合训练 开启余弦且 warmup 大于 0 时四组从 0 一起升温；不开余弦时直接切到基准学习率 只有阶段意图对应，边界行为并非论文完整复现

论文采用「先只适配 soft prompt 与动作头，再联合优化」：其设计意图是先让新提示适配冻结的预训练表示，为联合训练提供较好的初始化。但论文没有给出“反序训练”消融，也没有直接测量所谓随机 prompt 梯度污染；因此不能把这套解释写成“顺序颠倒必然失败”的已证事实。更完整的机制讨论见子页 ① Soft Prompt 与跨本体机制 第 7.1 节。

论文里的“新 prompt”与公开脚本还差一步。论文把目标域适配描述为引入一组新的 soft prompt；固定公开实现则在模型构造时预先创建 30 行 prompt 和域私有动作投影，训练脚本只读取样本的 domain_id 选择其中一行，没有“新增一行”或“把目标行重新随机初始化”的代码。因此复现者必须显式决定目标域占用哪个槽位，并确认该槽位中 prompt、action encoder 与 action decoder 的初始化和既有训练状态；不能依赖缺省 domain_id=0，因为那会选择 Bridge 的私有参数，也不能仅凭 freeze_steps 就认为论文的两步适配已完整落地。

论文 Table 1 的最后一行显示：在其他一切都已就位的前提下，加入整套两步适配流程带来 6.2 个百分点的累计提升（89.6 到 95.8）。这支持“两步流程有效”，但不能单独证明其顺序因果或上述梯度机制。

七、PEFT：LoRA 配置

# peft_train.py
lora_config = LoraConfig(
    lora_alpha=16,
    r=8,
    bias="none",
    target_modules="all-linear",
    modules_to_save=["transformer.soft_prompt_hub",
                     "transformer.action_encoder",
                     "transformer.action_decoder"],
)
model = get_peft_model(model, lora_config)
秩 8、alpha 16在默认非 rsLoRA 语义下，LoRA 缩放系数为 alpha / r = 2。
覆盖 PEFT 识别的线性层target_modules="all-linear" 不等于覆盖所有数学上的仿射映射；自定义 DomainAwareLinear 由 embedding 查表实现，不是普通 nn.Linear。
三个私有模块全量训练并保存modules_to_save 保证 soft prompt、action encoder 与 action decoder 作为完整模块训练和写入 checkpoint，而不是给它们添加低秩支路。
这一配置的工程含义是：共享主干用 LoRA 降低可训练参数量，本体专属 prompt 与动作投影保持全秩可训练。三处私有参数约为 0.98M、2.24M、0.62M；论文报告的约 9M 是整个 PEFT 方案的可训练参数总量，不是模型总参数量，也不是仅由这三处相加得到。

peft_train.py 复用了与 train.py 相同的四组学习率和训练循环，因此前述调度边界仍然存在；它不是逐行完全相同，日志有所删减，保存时也没有写 processor。

论文 Table 3 报告：LoRA 版本以约 9M 可训练参数取得与 π0（3B）可比的结果——LIBERO 四个 suite 平均约 93%、Simpler-WidowX 约 54%，对应参数量相差约 300 倍（层一）。

十、按踩坑概率排序的复现要点

  • 先区分论文方法与固定公开实现。论文训练速度场；当前源码对连续通道回归干净动作、对夹爪使用 BCE。两套目标不能只换采样循环而共用同一权重。
  • 预训练与适配不能共用未检查的默认阶段。论文预训练从第 0 步联合优化；公开脚本默认前 1000 步把 VLM/core 学习率置零。论文适配还要求“新 prompt”，而脚本只会按 domain_id 选择预分配槽位。
  • 确认是否真的开启 warmup。README 未传 --use_cosine_decay，所以 warmup_steps 默认无效；开启后，prompt/action 在解冻边界会先从基准学习率降到 0 再升温。
  • 不要把零学习率当成真冻结。对实际有梯度的参数，反向、分布式同步、AdamW 状态更新和全局梯度裁剪仍会发生；需要真冻结时须显式管理 requires_grad、优化器状态与裁剪集合。
  • 同时核对名义 batch 与有效样本重叠。脚本没有梯度累积，名义全局 batch 约为每进程 batch × 进程数；IterableDataset 未显式按 rank/worker 分片，还应记录样本标识来测量重复。
  • 启动时打印采样键、归一化权重与 domain id。LeRobot v2.1 的 root_path 可能无法命中声明权重；meta 同键会覆盖；已注册 handler 若漏配 domain id 会回退到 0 号 Bridge 私有参数。
  • 按任务时域核对重采样与静止过滤。qdur 不能只由 Hz 反推；应同时统计各域实际窗口、片尾缩短和首锚点间隔被过滤的比例。
  • 修正并验证 HDF5 颜色通道。cv2.imdecode 输出 BGR，当前路径直接交给 PIL；应转成 RGB，并与 PyAV 的 rgb24 路径做同帧对照。
  • 对齐优化配置时检查作用范围。脚本 weight decay 默认 0.0；改为论文的 0.01 后会作用于全部四组，未排除 bias、LayerNorm 或 embedding。新模块还会因排除法默认进入 transformer_core。
  • 区分模型快照与完整续训。现有 checkpoint 不保存优化器、随机数和数据流状态，重启还会从第 0 步重新执行学习率阶段。
