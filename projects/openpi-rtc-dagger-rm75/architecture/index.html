RTC 自主与 VR 接管架构

OpenPI RTC + DAgger RM75 的状态分层、异步推理、五相位交接、单一下发链和记录门控

项目概览 架构与接管 纠正数据 数据与训练 安全与验证 工程迭代 论文与路线
CONTROLRTCVR → IK

只切换目标来源，不让两个控制线程争夺硬件。

RTC 动作块与 VR→IK 关节目标先在会话层完成仲裁，再进入同一个高频下发与安全约束路径。软停止和离合重锚负责把“自主运动中”变成“人可以安全接管”。

一、先分清四种“状态口径”

需求概览中的“六态机”、本页的“五相位”和 AUTONOMOUS / CORRECTING 并不互相矛盾，它们描述的是不同层。如果把它们混成一套枚举，读者会误以为页面少写了一个状态。

层次 本页采用的口径 负责什么 不应怎样理解
RTC 算法与队列层 异步产块、动作队列、pause / resume / reset 让新动作块与已承诺前缀连续，并管理在途推理与旧队列 不是 DAgger 接管状态机
DAgger 会话层 IDLE → AUTO → SOFT_STOP → HANDOFF → TELEOP 决定当前由 RTC、保持参考还是 VR 提供目标 五相位不是底层控制器全部状态
底层 RTC / 安全控制层 需求所称的既有六状态控制器；设计上保持原实现 处理运行、停止、故障、复位等硬件生命周期及安全约束 本页不重命名其内部状态
叙述层 AUTONOMOUS / CORRECTING 对“自主段 / 人工纠正段”的简写 不是新增的代码枚举
本页重点：按需求设计，DAgger 只在既有 RTC 与安全控制器之上增加“谁提供目标”的会话仲裁；底层六状态控制器和三道安全闸仍由原 RTC 路径负责。该结构仍需项目源码与运行证据确认。

二、四层职责与三个调度域

策略产块

RTC 在后台根据最新观测生成下一动作块，并利用尚未执行的前缀保持块间连续。推理耗时会变化，因此它是异步任务，不是固定频率“时钟”。

实时下发

约 110 Hz 的单一发送路径消费当前参考，执行插值、运动约束与夹爪门控。只有这一条路径拥有硬件写权限。

纠正采样

约 30 Hz 采样观测、实际下发命令和三路图像。控制热路径只复制或 append；编码与落盘延后到 episode 收尾。

会话编排

事件驱动的纯逻辑 FSM 把按键和运行状态转换为动作列表，再由 Runner 执行副作用。它不是第四个周期时钟。

三个调度域故意解耦：策略产块受推理延迟影响，下发必须保持稳定节拍，数据采样只需与训练集 fps 对齐。若把视频编码、磁盘写入或网络传输塞进 110 Hz 热路径，I/O 抖动会直接侵占约 $1/110\approx9.1\,\mathrm{ms}$ 的单周期预算。

三、五相位接管协议

会话相位 参考来源 RTC 生命周期 硬件侧行为 记录资格
IDLE 安全保持参考 暂停或未启动 默认不动，等待显式开始 无
AUTO RTC 动作块 产生并消费新块 自主执行 无
SOFT_STOP 关节保持参考 停止接受新块 发送链继续运行，由既有限速/限加速度状态平滑减速 无
HANDOFF 关节保持参考 暂停且旧块不得重新生效 停稳，等待有效 Grip 与离合重锚 无
TELEOP, Grip=1 VR 增量映射 → IK 暂停 人工关节目标进入同一安全链 满足其余录制门时有
TELEOP, Grip=0 关节保持参考 暂停 冻结/保持，不追随手柄 无

软停止不是“把目标瞬间设为零速度”。它先阻止新的 RTC 块进入，再把关节参考切到保持目标；真正的减速由仍在运行的状态化限速、限加速度和滤波链完成。停稳后进行离合重锚，是为了避免把手柄当时的绝对姿态直接解释为机械臂的新绝对目标。

页面中的 Grip 指需求文档所描述的有效接管门。现有文档按右 Grip 描述，但真机前仍需用按键检查工具核对 SDK 键值；需求概览中的“双 Grip 接管”只能视为高层描述，不能替代实际映射验证。

从人工控制交还 RTC 时必须满足什么

若一轮纠正后允许在同一会话回到 AUTO，至少要完成四件事：结束并保存或丢弃当前录制段；保持机械臂稳定；清空或失效化接管前的旧 RTC 队列/在途结果；用最新观测生成可用的新块后再显式恢复自主控制。否则旧块可能把机械臂拉回接管前轨迹。若当前版本没有实现这条原子化交还路径，应先回到 IDLE，不能仅把相位变量改回 AUTO。

四、单一下发不变量及正确的数学表达

先区分“观测状态”和“硬件命令”：

  • $x_t=[q_t,w_t]\in\mathbb R^8$：七个实测关节角 $q_t$ 与连续夹爪开口 $w_t$；
  • $u_t=[q_t^{cmd},c_t]\in\mathbb R^7\times\mathcal C$：七个最终关节命令与离散夹爪命令，$\mathcal C={\text{open},\text{hold},\text{close}}$；
  • $h_t$：插值器、限速/限加速度器和其他状态化安全模块的内部状态。

令 $r_t$ 为会话仲裁后的参考，$\mathcal S$ 为唯一安全下发链，则

\[(u_t,h_{t+1})=\mathcal S(r_t,x_t,h_t), \qquad r_t= \begin{cases} r_t^{RTC}, & z_t=\mathrm{AUTO},\\ r_t^{hold}, & z_t\in\{\mathrm{IDLE},\mathrm{SOFT\_STOP},\mathrm{HANDOFF}\},\\ r_t^{VR\rightarrow IK}, & z_t=\mathrm{TELEOP}\land g_t=1,\\ r_t^{hold}, & z_t=\mathrm{TELEOP}\land g_t=0. \end{cases}\] \[r_t^{hold}=[q_t,c_{t-1}^{safe}],\]

这里的保持参考使用当前实测关节角和上一条已接受的安全夹爪命令，不能直接写成 $r_t=x_t$：$x_t$ 的第八维是连续夹爪测量，而命令第八维是离散类别，二者语义不同。公式显式保留 $h_t$，因为软停止是否平滑取决于上一周期命令和滤波器状态；仅写 $\mathcal S(r_t,x_t)$ 会把安全链误画成无记忆函数。

单一下发不变量包含三层意思：

  1. RTC 与 VR 只能产生候选参考，不能各自写硬件；
  2. 参考来源的切换发生在安全链之前；
  3. 记录器保存的是安全链之后真正下发的 $u_t$，而不是未通过约束的 VR/RTC 候选值。

五、控制门与记录门不是同一个开关

令 $m_t$ 表示录制已武装，$e_t$ 表示当前存在活动 episode，$g_t$ 表示有效 Grip，则“本帧进入纠正缓冲”的条件是

\[y_t= \mathbf 1\!\left[ z_t=\mathrm{TELEOP} \land m_t=\mathrm{ARMED} \land g_t=1 \land e_t=\mathrm{ACTIVE} \right].\]

TELEOP ∧ Grip 只说明 VR 可以驱动；$y_t=1$ 才说明本帧应追加到缓冲。它仍不等于 episode 已持久化：用户完成恢复后还要显式保存，坏段则应丢弃。因此可以先进入 TELEOP 做离合校准，再武装录制；中途松开 Grip 时机械臂保持且不新增冻结帧，重新握住后继续同一恢复段。

六、知识点、重点与工程创新

KNOWLEDGE

异步产块不等于控制频率

RTC 解决动作块推理延迟与块间连续性；110 Hz 是硬件下发节拍，30 Hz 是数据采样节拍，三者不能混写。

FOCUS

交接是一段协议

暂停新块、状态化软停、离合重锚和旧队列失效共同构成接管边界；单独切换一个布尔变量不够。

ENGINEERING

单写者仲裁

工程创新在于把 RTC 与 VR 的仲裁放到既有安全链之前，并让记录器观察安全后的真实命令；它不是新的 RTC 或 DAgger 理论。

DATA SEMANTICS

控制与采集解耦

人工拥有控制权并不自动产生训练样本；明确的武装、Grip、活动 episode 和保存步骤共同保证数据来源可审计。

八、RTC 与既有动作平滑的关系

本任务的现场观察是：RTC 的实际运动观感与动作平滑工程页中的“异步推理 + 动作块间平滑过渡”接近，二者都能减少推理等待和动作块切换处的停顿或突跳。这个观察有工程价值，但它是操作者感受，不是锁定条件下的量化结论。

机制 作用位置 连续性从哪里来 不能单独解决什么
RTC 新动作块的生成/推理阶段 把已承诺执行的动作作为前缀条件，只补全尚未承诺的后缀，并按实际推理延迟确定重叠 执行器限速、通信抖动、异常队列、策略语义错误
执行侧动作平滑 动作块已生成后的调度/下发阶段 用当前实测状态锚定、跨块淡化、队列守卫等方式抑制边界跳变 从生成分布上修正新块，也不等价于策略理解了失败
二者组合 生成与执行两层 RTC 减少计划边界冲突，执行侧再处理残余抖动和安全约束 仍需截止期监控、失败检测与真机安全链

之所以“感觉差不多”，是因为最终可见信号都是关节命令和运动轨迹：只要块边界附近的位置、速度或加速度更连续，操作者就会感到更顺滑。但相似观感不能推出内部机制、延迟鲁棒性、峰值 jerk、任务成功率或故障恢复能力等价。尤其是强执行侧淡化可能掩盖 RTC 生成的不连续，也可能因过度平滑而造成相位滞后。

应在同一 checkpoint、观测序列、控制频率、网络延迟分布和安全参数下做四组配对试验：基线、仅 RTC、仅执行侧平滑、RTC + 执行侧平滑。同时报告 deadline miss、块边界位置/速度/jerk、任务成功率、人工接管率和安全限幅触发数；只有组合组在连续性与任务指标上稳定优于单独组，才能主张二者互补。RTC 数学原理另见 RTC 原理专题。

历史需求记录：原始项目文档把 DAgger FSM 正常/异常事件、mock VR、导入链和自动化 dry-run 标为通过；本轮未复跑，且当前网页工作区未定位到表中的同名实现文件。
这些记录不能证明：当前代码仍存在或仍通过，也不能证明真实 SDK 按键映射、软停真机动力学、离合方向、安全裕量和接管体验；这些都需要绑定 commit、配置、日志的复验。
