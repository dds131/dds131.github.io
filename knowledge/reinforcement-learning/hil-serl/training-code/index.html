总览架构接管与数据Loss奖励与控制训练与源码现象诊断研究路线
Preparation · Async Training · Reproduction

先让奖励与控制可信，再启动 Actor 和 Learner

HIL-SERL 不是“运行一个训练脚本”即可复现的算法。奖励、示范、动作语义、安全控制、两池恢复和参数同步有严格依赖顺序；在线训练只是最后一阶段。

1. 三阶段训练总览

flowchart LR
  A["A. 任务与控制校准"] --> B["B. 离线奖励与示范准备"]
  B --> C["C. 在线异步 RL"]
  A --> A1["相机 / 状态 / 动作 / 安全 / 复位"]
  B --> B1["奖励数据 → 分类器"]
  B --> B2["20–30 条示范 → Demo Buffer"]
  C --> C1["Actor: 执行、接管、发送转移"]
  C --> C2["Learner: 50/50 采样、更新、推参"]
A

任务、传感与控制校准

  1. 定义成功条件、失败边界、回合终止和复位；成功必须能由奖励视角可靠观察。
  2. 核对相机同步、ROI、颜色/归一化、本体单位与时间戳。
  3. 写清动作维数、坐标系、物理尺度、限幅和离散夹爪语义。
  4. 在无 RL 情况下完成遥操作压力测试：整个任务、边界状态、接触、急停与通信失联。
  5. 确认低层控制频率、参考限制和复位脚本不会把可恢复失败变成硬件事故。
B

离线奖励与示范准备

  1. 采集正/负图像，按轨迹而不是相邻帧随机切分训练/验证集。
  2. 训练 Reward Classifier，并建立半成功、错误位置、遮挡和光照变化的难负样本集。
  3. 采集约 20–30 条成功示范；逐条回放检查状态、实际动作、奖励、终止与 mask。
  4. 将示范载入 Demo Buffer；奖励分类图像集不是 transition replay，两者不要混放。
C

在线异步学习与无接管评估

  1. Learner 初始化 SAC/RLPD、RL Buffer、Demo Buffer iterator、日志与参数服务。
  2. Actor 接收 Learner 发布的完整参数快照，按固定控制节拍运行；异步系统中该快照允许短暂滞后。
  3. 人类必要时短暂覆盖；环境 wrapper 通过 intervene_action 返回实际接管动作，Actor 用它覆盖待保存动作并把该步双路由。
  4. Learner 等 RL Buffer 达到 training_starts 后，按 50/50 构造 batch；每个外层步先做 cta_ratio-1 次 Critic-only 更新，再做 1 次 Critic + Actor + Temperature 联合更新，混合动作任务同时更新 Grasp Critic。
  5. 按 steps_per_update 个 Learner 外层步发布参数；同时监控队列积压、参数年龄、环境 FPS 与 Learner UPS。
  6. 训练判断基于无接管评估，不能把人完成的回合算成自主成功。

2. 概念级伪代码

下面只描述数据合同，不是官方可直接执行命令：

# offline preparation
reward_model = train_success_classifier(positive_images, negative_images)
offline_demo_buffer = load_checked_demonstrations()
agent = build_sac_rlpd_agent()
assert B % 2 == 0

# actor process: two queued datastores send transitions to the learner
while collecting:
    s = env.observe()
    a_proposed = agent.sample_action(s)  # hybrid agent also supplies gripper action
    s_next, r, terminated, truncated, info = env.step(a_proposed)

    intervened = "intervene_action" in info
    a_stored = info.pop("intervene_action") if intervened else a_proposed
    transition = {
        "observations": s,
        "actions": a_stored,
        "next_observations": s_next,
        "rewards": r,
        "masks": 1.0 - terminated,
        "dones": terminated,
    }
    online_queue.insert(transition)           # every executed step
    if intervened:
        intervention_queue.insert(transition) # duplicate only this corrected step

    s = s_next
    if terminated or truncated:
        client.update()                       # flush queues/statistics, then reset
        s = env.reset()

# learner process: buffers live beside the learner
wait_until(len(online_buffer) >= training_starts)
publish_network(agent.params)                 # initial snapshot
online_it = iterator(online_buffer, B // 2)
demo_it = iterator(demo_buffer, B // 2)       # offline demos + received interventions

while training:
    for _ in range(cta_ratio - 1):
        batch = concat(next(online_it), next(demo_it))
        agent = update(batch, networks={"critic", optional_grasp_critic})

    batch = concat(next(online_it), next(demo_it))
    agent = update(
        batch,
        networks={"critic", optional_grasp_critic, "actor", "temperature"},
    )
    # target critic is Polyak-updated inside every update that includes critic
    if learner_step > 0 and learner_step % steps_per_update == 0:
        publish_network(agent.params)

真实实现还要处理图像内存压缩、队列断线、checkpoint、数据恢复、设备 sharding 和多进程统计。伪代码不能替代官方 walkthrough。上面的 masks=1-terminated 对齐当前 Berkeley 主循环：时间截断会触发 reset，但若 terminated=False 仍允许 bootstrap。若你的环境把 time-limit 合并进 done，必须重新核对语义。另需保证 $B$ 为偶数；否则两个 $B//2$ 拼接后只有 $B-1$ 个样本。

3. 环境步、Learner 步和参数版本是三条时间轴

时间轴 计数单位 决定什么 常见误读
环境时间 robot transition / episode 数据成本、控制频率、接管时机 当成等于梯度步
优化时间 learner update UTD、网络收敛与过拟合 只报 epoch 不报新增数据
参数时间 pushed policy version Actor 行为策略的新鲜度 认为 Actor 每步都用最新权重

按常用的 Critic 更新口径，更新数据比可写为

\[\mathrm{UTD}_Q= \frac{N_{\text{critic optimizer steps}}} {N_{\text{new online transitions}}}.\]

cta_ratio 不是这个比值本身：它表示每个 Learner 外层步中 Critic 更新次数与 Actor/Temperature 更新次数之比。若 Learner 每秒完成 $L$ 个外层步、Actor 每秒新增 $R$ 条在线转移，则观测窗口内近似有 $\mathrm{UTD}_Q\approx \texttt{cta_ratio}\,L/R$；异步吞吐变化会使它随时间波动。高 $\mathrm{UTD}_Q$ 能复用昂贵数据，也会更快放大奖励误报、错误 mask 和 Q 偏差。

参数发布节拍还要区分实现：Berkeley steps_per_update 按 Learner 外层步计数；LeRobot 当前指南的 policy_parameters_push_frequency 按秒计，默认 4 秒，并说明可降到 1–2 秒换取更新鲜权重，但网络流量更高。二者不能只按数值直接比较。

5. JAX 原版与 LeRobot 路线怎么选？

Berkeley HIL-SERL

JAX/Flax，最适合论文逐项对齐、研究原版实现和已有 Franka/官方基础设施的场景。

Hugging Face LeRobot

PyTorch 与更广的机器人/数据接口，教程覆盖遥操作、ROI、Actor/Learner、W&B 和接管策略，适合 LeRobot 生态。

LeRobot 页面是独立实现路线，不是 Berkeley JAX 代码逐行翻译。比较结果必须固定：仓库 commit、教程版本、硬件、观测、动作、奖励、控制频率、demo 数、接管协议和评估次数。只说“都叫 HIL-SERL”不足以证明复现等价。

官方 LeRobot 教程：https://huggingface.co/docs/lerobot/main/en/hilserl

6. 每次实验必须记录什么？

类别 必记字段 为什么
视觉 相机键、ROI、分辨率、增强、延迟 决定策略与奖励分布
本体 字段、单位、坐标系、归一化 避免训练/执行语义漂移
动作 维数、物理尺度、frame、限幅、频率 网络输出必须对应真实执行
Replay 两池大小、采样比、容量、恢复点 定义数据分布和重用
SAC/RLPD $\gamma,\tau,B$, UTD、学习率、ensemble、backup_entropy 定义优化目标与节拍
熵 初始温度、目标熵、更新频率 决定探索与纠正可保持性
奖励 分类器 commit、阈值、数据版本、难负样本 奖励变化等于任务变化
接管 设备、门控方式、平均段长、操作者 人类数据不是可忽略噪声
终止 success/failure/time-limit、mask 决定是否 bootstrap
系统 Actor/Learner 设备、推送周期、队列、staleness 异步偏差与吞吐

论文附录各任务的折扣、动作空间、随机化、总转移数和训练时长并不相同。例如 Object Handover 报告 $\gamma=0.97$、43,000 条转移；Object Flipping 报告 $\gamma=0.985$、25,000 条转移。不能提炼成一个“官方统一超参数表”。

7. 四层监控面板

任务层

无接管成功率、周期时间、恢复成功率、失败类型分布。

人类层

接管率、段数、持续步数、归还控制后的自主保持时间。

学习层

两池 TD、Q 分位数、Actor/Temperature loss、entropy、梯度/参数范数。

系统层

环境 FPS、Learner UPS、实际 UTD、队列积压、参数年龄、相机与动作延迟。

任务曲线必须与系统曲线对齐时间戳。成功率突然下降可能不是算法，而是参数推送中断、相机帧冻结、队列积压或奖励模型版本改变。

8. 上线前六道门禁

  1. Reward 门禁：独立盲测 + 线上高奖励帧人工复核，难负样本不过不启动 RL。
  2. Transition 门禁：接管时记录实际动作；terminal/truncation/mask 有单元测试。
  3. Loss 门禁：用玩具 batch 手算 TD target，与 backup_entropy 两种分支逐项对齐。
  4. 控制门禁：无 RL 遥操作覆盖动作范围、接触、急停、失联与复位。
  5. 并发门禁：短跑中参数版本递增、两池有数据、队列不持续增长、checkpoint 可恢复。
  6. 评估门禁：独立无接管评估进程，固定初始分布和试验次数。
复现失败时不要先调所有超参数。先确认奖励真、动作真、mask 真、参数真的送到 Actor；这四项任何一个为假，调学习率只会让错误系统更快收敛。

9. 知识点、重点与创新边界

知识点

Actor 环境步、Learner 外层步和参数版本是三条独立时间轴；cta_ratio 控制 Critic/Actor 更新节拍，实际 UTD 还由异步吞吐决定；transition 必须保存真实执行动作和正确终止 mask。

实现重点

先过奖励、动作、mask 与控制门禁，再调学习率；固定代码 commit、配置与数据版本；同时记录两池采样、队列积压和参数年龄，否则“同一算法”可能对应完全不同的训练分布。

创新边界

异步 Actor–Learner、经验回放和 SAC 都有既有来源。HIL-SERL 的关键系统贡献是把实际接管动作、双经验池 50/50 采样、在线离策略更新和真实机器人控制组成可工作的协议；源码复现不能缩减为抄一个 Loss 函数。
