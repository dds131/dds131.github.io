一句话回答

记录器以关节真实测量时刻为锚，在三路15帧缓冲中选择时间戳最近的图像，并同时保存实际下发动作、真机回读、帧号、时间差和陈旧度。恢复执行时，再把30Hz模型路点按墙钟插值到110Hz发送拍，并用C²平滑权重融合新旧动作块。

一、采集命令和参数

cd "$D/data_collection"
"$PY" record_collector.py \
  --dataset-name pick_cube --max-steps 3000 \
  --head-dev "$HEAD_DEV" --arm-dev "$ARM_DEV" --third-dev "$THIRD_DEV" \
  --preview-port 9001
参数 当前值 作用
--dataset-name pick_cube 决定会话目录和任务分组，不改变采样算法
--max-steps 3000 30Hz下最长约100秒，到点后停止并等待保存或丢弃
--head-dev / --arm-dev / --third-dev 三个稳定设备标识 固定全局、腕部、第三视角语义，避免 /dev/videoN 漂移
--preview-port 9001 只控制预览端口，不改变录制内容
--record-hz 默认30 从110Hz状态流抽样，卡顿时不追补，不参与机械臂控制
--state-port 默认5604 接收128B控制状态包
--gripper-state-port 默认5601 接收50Hz夹爪真实开口；缺失时不以期望值冒充

正式采集前用 view_cameras.py --probe 确认识别结果，再以 --web 检查三路画面；预览必须在录制前退出，避免两个进程争用同一V4L2设备。

二、110 Hz 状态怎样变成30 Hz训练样本

  1. 控制进程广播安全链之后真正发出的 action、关节回读和夹爪实测值。
  2. 三路640×480@30fps相机分别写入15帧环形缓冲。
  3. 每个记录时刻用关节真实测量时刻作为锚点，从每路缓冲选最近帧。
  4. 保存帧序号、相对时间差、补帧标记、qpos_age 和 gripper_age。
  5. 若循环已错过名义采样点，重新锚定下一时刻，不连续补写相似帧。
  6. 状态包超过1秒未更新时停止并丢弃当前episode。

已有记录中的图像—关节对齐误差p50约7ms、最大不超过16.7ms。这个结果来自记录器对齐字段，不甡视频肉眼观感推断。

五、30 Hz动作怎样插值为110 Hz指令

恢复动作块的前七维是绝对关节角，第八维是夹爪档位。速度比例 $s=0.35$ 时：

\[f_{step}=30s=10.5\ \text{step/s}.\]

对动作块开始时刻 $t_0$ 和任一110Hz发送时刻 $t_m$：

\[u=f_{step}(t_m-t_0),\qquad k=\lfloor u\rfloor,\qquad \lambda=u-k,\] \[\mathbf q(t_m)=(1-\lambda)\mathbf q_k+\lambda\mathbf q_{k+1}.\]

必须使用墙钟时间，因为 $110/10.5$ 不是整数；若在每两个路点之间固定插入相同帧数，模型时间轴会持续漂移。动作块已经执行完而新块尚未到达时保持末帧，避免CAN-FD断流。夹爪不做连续插值，而是取最近路点并吸附到 0 / 0.5 / 1 三档。

E=25覆盖约2.38s；在 E-V=15 步、约1.43s后请求下一块；V=10对应约0.95s重叠窗。推理p50 118.0ms约等于1.24个当前动作步，执行器向上取整跳过新块前2步，避免重放已经过时的块头。

六、新旧动作块怎样平滑衔接

新块到达后，旧块和新块先在同一个墙钟时刻分别插值，再使用五次 smootherstep：

\[w(z)=6z^5-15z^4+10z^3,\] \[\mathbf q_{blend}=(1-w)\mathbf q_{old}+w\mathbf q_{new},\quad z\in[0,1].\]

它满足窗口两端一阶、二阶导数为0，避免融合权重额外制造速度和加速度突变。--blend-max-jump-deg 2.0是融合安全闸：110Hz融合结果单帧跳变超过2°时，放弃本次混合并切到经安全链处理的新块。

融合后仍按“EMA 0.25 → 144°/s限速 → 15°软限位 → 目标制动 → 1000°/s²限加速度 → 硬限位”处理。线性插值负责时间升频，C²融合负责块接缝，安全链负责物理边界，三者不能互相替代。

七、软急停与人工接管

  • 左手握把达到80%并持续100ms，才从AUTO进入SOFT_STOP。
  • SOFT_STOP在0.25s内沿原规划时间轴减速，不中断110Hz发送。
  • HANDOFF继续以110Hz重发冻结点。
  • 完成VR离合重锚后进入TELEOP，只有此时允许录制人工纠正。

第一批恢复数据审计发现5条episode共5,659帧中，3,486帧（61.6%）属于模型推理期，其中两条没有人工操作。用 observations/trigger 是否为NaN筛选后保留2,173帧人工数据，并在入口增加TELEOP-only门控。

证据边界：旧页面的“733 + 580 = 1,313条、796,412帧、64%→92%”没有在本次允许查看的容器中找到对应清单或逐次评估表，因此不作为已验证成果展示。

八、面试回答模板

“常规VR示教没有把30Hz插值成110Hz，30Hz只是记录时间轴。真正的30→110动作插值发生在恢复运行的VLA动作块：我按单调墙钟确定两个30Hz路点和插值系数，再由110Hz外环发送；新旧块在同一时刻插值后用C² smootherstep融合，最后还要经过完整安全链。”
