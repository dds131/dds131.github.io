知识库首页 /模仿学习 /VLA 总览 /GR00T N1.5 总览 /⑥ 官方源码剖析

本页沿着真实入口解释公开代码，而不是逐行复述文件。源码基准固定为 n1.5-release 对应提交 4af2b622892f7dcb5aae5a3fb70bcb02dc217b96；发布检查点配置单独核对 GR00T-N1.5-3B/config.json。源码能证明公开微调与推理路径执行了什么，不能还原 NVIDIA 内部预训练的全部实现。

先区分三个层次： Gr00tPolicy 负责数据变换和反变换；GR00T_N1_5 负责串联主干与动作头；FlowmatchingActionHead 才负责流匹配损失与欧拉生成。只阅读动作头会漏掉归一化、真实动作维拆分、配置覆盖和服务封装。

一、版本边界与读码地图

仓库主线会继续演进，因此页面事实不以 main 为准，也不把可移动标签当作最终定位依据。以下是本页使用的最短读码路径：

问题 文件与入口
原始观测怎样进入模型 gr00t/model/policy.py::Gr00tPolicy.get_action
拼接、补齐、掩码和逆变换 gr00t/model/transforms.py::GR00TTransform、gr00t/data/transform/concat.py
主干与动作头怎样串联 gr00t/model/gr00t_n1.py::GR00T_N1_5
Eagle 输出怎样截层 gr00t/model/backbone/eagle_backbone.py::EagleBackbone
流匹配训练和采样 gr00t/model/action_head/flow_matching_action_head.py
交叉注意力与自注意力怎样交替 gr00t/model/action_head/cross_attention_dit.py::DiT
微调入口如何重建动作头 scripts/gr00t_finetune.py::main
LoRA 实际插到哪些层 gr00t/utils/peft.py::get_lora_model
ZMQ、HTTP 与 TensorRT 服务 scripts/inference_service.py、gr00t/eval/

页面不再用“某文件增加多少行”推断性能来源。代码行数只能描述文本变化，不能替代主干换代、数据规模和训练目标的消融实验。

二、数据契约：模型前后都还有变换

2.1 data_config 决定输入语义

具体变换由所选数据配置构造，并非模型类内部固定。例如 FourierGr1ArmsOnlyDataConfig 依次处理视频、状态和动作，再拼接为统一键，最后交给 GR00TTransform：

阶段 公开代码行为 容易误读之处
视频 转张量、裁剪、缩放、颜色增强，再转回 NumPy 增强只在训练态由对应 transform 控制，不是 Eagle 内部操作
状态 转张量，可执行正余弦表示，再按配置顺序拼接 不同本体的键顺序属于数据契约
动作 转张量、按元数据归一化，再按配置顺序拼接 归一化方式由 data config 指定，不是所有配置都相同
GR00TTransform 生成 VLM 输入；状态补齐到 max_state_dim，动作补齐到 max_action_dim 补齐维不是机器人真实自由度
逆变换 ComposedModalityTransform.unapply 逆序执行，ConcatTransform.unapply 按记录维度拆回各动作键 GR00TTransform.unapply 本身只是原样返回，真正拆分发生在外层管线

GR00TTransform 会同时产生 state_mask 与 action_mask。在固定提交中，全仓库只有变换代码写入 state_mask，模型没有读取它；action_mask 则只在训练损失中排除补齐维。推理时没有动作掩码替用户修正配置，输出真实维度依赖元数据和逆变换顺序。

Gr00tPolicy 从检查点的 experiment_cfg/metadata.json 读取指定本体的统计量，并通过 set_metadata 注入整条变换管线。缺失本体元数据会直接报错，而不是退回通用统计。

2.2 公共推理调用链

Gr00tPolicy.get_action(observation)
  ├─ 判断 batch 维并复制输入
  ├─ ComposedModalityTransform.apply
  ├─ GR00T_N1_5.get_action
  │    ├─ prepare_input：拆成 backbone/action 两组并搬到设备
  │    ├─ EagleBackbone.forward
  │    └─ FlowmatchingActionHead.get_action
  ├─ action_pred.float().cpu()
  └─ ComposedModalityTransform.unapply
       └─ 反归一化并拆回 action.<name> 键

训练入口走 GR00T_N1_5.forward，与推理共同复用 prepare_input 和主干，但动作头分别调用 forward 与 get_action。因此“训练和推理只差有没有梯度”不准确：一个构造带噪监督并返回损失，另一个从高斯噪声出发做多步数值积分。

三、主干到动作头：2048 维条件与 1536 维查询

发布配置给出的关键接口如下：

位置 发布配置 源码落点
Eagle 选层 select_layer=12 初始化时裁掉更深语言层，前向取 hidden_states[12]
主干额外投影 project_to_dim=null eagle_linear=Identity()，输出保持 2048 维
VL 归一化与自注意力 use_vlln=true，4 层、32 头 vlln 与 vl_self_attention 都工作在 2048 维
状态、future、动作 token 1536 维 三者拼成 DiT 的 query 序列
DiT 16 层、32 头、每头 48 维 内部宽度 $32\times48=1536$，交叉注意力条件宽度 2048
动作解码前输出 1024 维 DiT 的 output_dim=1024，再按本体进入动作解码器

EagleBackbone.forward_eagle 返回选定层特征和 Eagle 的 attention mask。动作头随后执行：

backbone_features
  → LayerNorm（vlln）
  → 4 层 SelfAttentionTransformer
  → 作为 16 层 DiT 的 cross-attention 条件

这段接口在冻结主干时仍提供可训练适配容量，但公开代码没有说明它是“为了补偿冻结”而设计，不能把机制解释写成作者动机。

3.1 一个必须暴露的掩码缺口

训练动作头把 backbone_attention_mask 作为 encoder_attention_mask 传给 DiT.forward，但固定提交中的 DiT.forward 在调用各 block 时又传入 encoder_attention_mask=None；BasicTransformerBlock 内对应参数也没有送入 Attention。四层 SelfAttentionTransformer 同样没有接收 VL mask。

因此准确结论是：公开代码保留并传递了 mask 字段，但动作头这两段注意力没有实际消费它。 这不等于一定产生错误——具体输入可能没有需要屏蔽的尾部位置——但不能宣称 DiT 已依据该 mask 排除 padding。若修改 token 化或批处理策略，应先补测试再决定是否接通掩码。

四、动作头训练路径：公式与代码逐项对应

4.1 token 构造

状态由按本体选择参数的 CategorySpecificMLP 编码；动作由 MultiEmbodimentActionEncoder 将当前带噪动作、离散时间和本体 ID 联合编码。只有动作 token 叠加可学习位置嵌入。序列顺序是

\[[\text{state tokens};\ \text{future tokens};\ \text{action tokens}].\]

其中 future token 来自一张可学习 embedding 表。它们没有直接动作输出，但会在 DiT 自注意力层中与动作 token 交互，所以不能称为“纯开销”。

4.2 时间、目标速度与损失

对真实动作 $a$ 和高斯噪声 $\epsilon$，公开训练路径构造

\[z_t=(1-t)\epsilon+ta,\qquad u^\star=a-\epsilon.\]

源码先采 $q\sim\mathrm{Beta}(1.5,1.0)$，再用 $s=0.999$ 计算

\[t=\frac{s-q}{s}.\]

代码没有把 $t$ 裁到 $[0,1]$：其严格范围为 $(-1/999,1)$，且约 $0.15\%$ 的样本小于 0。送入动作编码器前再计算 (t * 1000).long()；这里的 .long() 是向零截断，不是四舍五入，所以这些很小的负值落到 0 桶，但连续 $t$ 仍用于插值。连续时间与离散桶不能混为同一个量。

动作头只截取序列末尾与动作长度相同的预测，并计算

\[\mathcal L_{\mathrm{FM}} =\frac{\sum_{b,h,d}m_{bhd}\bigl(\hat u_{bhd}-u^\star_{bhd}\bigr)^2} {\sum_{b,h,d}m_{bhd}}.\]

这个损失能排除补齐动作维，但它是 batch 内所有有效标量的总体平均。有效动作维更多的样本会贡献更多项，因此它不保证“每个样本等权”或“每个本体等权”。代码也没有为分母为零提供保护，数据管线必须保证训练样本存在有效动作。

4.3 公开路径没有 FLARE 损失

DiT.forward 支持可选返回各层隐状态，但动作头调用时明确设置 return_all_hidden_states=False，并带有 not using flare now 注释。随后公开返回值只有流匹配损失，没有未来表征目标、投影损失或加权总损失。

这个接口与 FLARE 所需的中间层抽取兼容；仅凭接口和注释，不能进一步断言它最初就是“专为 FLARE 预留”。

五、推理路径：哪些只算一次，哪些每步重算

动作头先处理 VL 特征、编码状态并采样初始动作噪声，然后执行 $K$ 次前向欧拉更新：

\[A_{k+1}=A_k+\frac{1}{K}V_\theta\!\left(A_k,\frac{k}{K}\mid c\right), \qquad A_0\sim\mathcal N(0,I).\]
操作 每个动作块 每个欧拉步
Eagle 主干 1 次 0
vlln + 4 层 VL self-attention 1 次 0
状态编码器 1 次 0
初始高斯噪声 1 次 0
动作编码器与时间嵌入 0 1 次
future-token 展开与拼接 0 1 次
16 层 DiT 与动作解码器 0 1 次
欧拉更新 0 1 次

处理后的 VL 特征张量会跨步复用，但公开 PyTorch 路径没有显式缓存 cross-attention 的 K/V 投影。future token 也不是“没有输出就没有作用”：解码器虽然最终只返回动作位置，它们仍能通过 DiT 自注意力改变动作表示，同时增加序列长度和计算量。

发布配置为 $K=4$、动作长度 $H=16$、共享动作上限 32；num_inference_timesteps 的配置类默认却是 None。因此 4 是该检查点和服务脚本的默认选择，不是动作头类不可修改的常量。

setter 和动作头都不校验 $K$：它必须是正整数，否则会出现除零、range 类型错误，或在负数时跳过循环并返回初始噪声。可覆盖性只是接口能力，不代表任意覆盖值都有定义。

六、微调入口：配置会被多次覆盖

只读 config.json 无法判断一次实际训练最终更新什么。公开微调入口按以下顺序处理配置：

层级 行为 结果
类默认值 EagleBackbone 默认 tune_visual=false；动作步数默认 None 只对直接实例化有意义
检查点配置 保存结构、动作长度和部分 tune 字段 用于重建初始模型
GR00T_N1_5.from_pretrained 加载后再次执行主干和动作头的 setter 调用参数覆盖保存的 trainability 状态
gr00t_finetune.py 默认参数 tune_llm=false、tune_visual=false、两个动作头开关为真 发布配置中的 tune_visual=true 不等于公开微调默认会训练视觉塔
data config 计算动作长度与 max_action_dim 不匹配时重建整个动作头并复制可兼容权重
LoRA lora_rank>0 时再包装 PEFT 基础参数的 requires_grad 状态会被 PEFT 改写
Gr00tPolicy 可用 modality action horizon 重建动作头，并用 denoising_steps 覆盖步数 部署参数可能不同于检查点字段

动作维变化时，脚本意图复制所有同形张量，再复制动作编解码器的重叠维，并把新增维随机初始化；同形张量的直接复制路径是明确的。但固定提交中的两条特殊键名判断与当前模块注册名不一致：动作编码器参数键以 action_encoder.W1.W 一类形式出现，不含 W1.weight；动作解码器受维度影响的键以 .W、.b 结尾，不含 weight、bias。

因此，在当前实现里，维度不兼容的动作输入／输出张量不会进入“复制重叠维”分支，而是整体保留新动作头的随机初始化。辅助函数还以扩展维度为主要假设，日志中的“新增维”口径不适合直接套到缩小动作维的情形。

这仍是跨本体适配的重要工程入口，但不能把部分继承当作已兑现的保证。实际使用必须核对打印出的 copied/random 统计，并逐项比较新旧 state-dict；若修复键名，还应分别测试扩维和缩维。

七、冻结开关与 LoRA 的真实覆盖范围

7.1 普通非 LoRA 路径

两个 setter 都先把各自模块的参数设为可训练，再按开关选择性冻结：

模块 受哪个内置开关控制 两个相关开关均关闭时
语言模型 tune_llm 冻结
视觉模型与 Eagle mlp1 tune_visual 冻结
eagle_linear 无 若是线性层则仍可训练；发布配置中为无参数 Identity
状态编码器、动作编码器、动作解码器、位置 embedding tune_projector 冻结
16 层 DiT tune_diffusion_model 冻结
vlln、VL self-attention、future token 无 仍可训练

所以“关掉 projector 和 diffusion 就冻结整个动作头”是错误的。三个 N1.5 新增模块仍可从动作损失获得梯度，其中 future token 通过影响动作 token 接受间接监督。

7.2 LoRA 是另一套规则

公开脚本默认 lora_rank=0，即不开启 LoRA。开启后，get_lora_model 默认只扫描动作头，并仅选择名称包含 Q/K/V 投影模式的线性层；它不是给动作头每个线性层都加适配器。若 lora_full_model=true，扫描范围才扩到整个模型。

PEFT 包装通常冻结基础参数，只让选中的 LoRA 参数训练。因此 LoRA 模式下，future token、vlln 等基础参数不会因为上表“无内置开关控制”就继续更新。讨论可训练集合时必须先说明是全参数路径还是 LoRA 路径。

八、公开 FLARE 缺口：能确认什么，不能推断什么

固定提交中与 FLARE 相关的源码事实只有：

  1. 存在 32 个可学习 future token，并在训练和推理时都加入动作序列；
  2. DiT 能选择返回各层隐状态；
  3. 公开动作头把该选项关闭，并明确注释当前没有使用 FLARE；
  4. 公开数据路径没有未来观测目标，forward 也只返回流匹配损失。

所以公开微调脚本不能复现官方所述的 FLARE 后训练。发布权重可能包含内部训练获得的 FLARE 效果，但继续用公开脚本微调时不会再次施加该约束。

若按 FLARE 方法另行实现，需要额外的数据目标、目标编码器或教师表示、中间层抽取、投影头、对齐损失及其权重。切片不能写死为 [:, 1:1+M]，因为状态 token 数并非模型接口上的常量；稳健写法应按运行时长度处理：

S = state_features.shape[1]
M = future_tokens.shape[1]
future_hidden = hidden_states[:, S:S + M]

即使补齐这些部件，也只能得到一套依据公开方法设计的实现，不能声称还原 NVIDIA 内部训练配方。

九、推理服务不是模型本体

RobotInferenceServer 在 ZMQ 服务上注册 get_action 和 get_modality_config；RobotInferenceClient 通过同名端点调用。scripts/inference_service.py 还可以改用 HTTP /act，并把命令行的 denoising_steps 传给 Gr00tPolicy，默认值为 4。

可选 TensorRT 路径要求先构建对应引擎，再通过 setup_tensorrt_engines 接入 policy。它属于部署替换层，不改变上层 observation/action 协议。ZMQ、HTTP 或 TensorRT 都不会自动提供闭环控制、碰撞检查和安全停止；这些职责仍在机器人客户端。

十、重点、创新点与实现边界

  1. 三层封装缺一不可：Policy 处理真实数据契约，顶层模型串联双系统，动作头负责生成；仅看其中一层容易得出错误部署结论。
  2. 异宽双系统接口：2048 维 Eagle 条件通过交叉注意力驱动 1536 维动作序列，避免强制先投到相同宽度。
  3. 跨本体动作专家：状态和动作编解码器按本体 ID 选择参数，数据变换负责把不同键映射到共享上限。
  4. 少步流匹配：动作头从高斯噪声出发做 4 次欧拉更新；步数可以被服务或运行时覆盖。
  5. future token 兼具表示与计算角色：它们没有直接动作输出，却参与注意力并接收动作损失的间接梯度。
  6. 公开训练与官方训练必须分开：公开微调只有流匹配；FLARE 的内部后训练实现没有随该提交发布。
  7. 配置不是单一真相源：检查点、加载参数、data config、LoRA 和部署参数会依次改变最终行为。
  8. 源码仍有需验证的边界：state_mask 未消费、VL mask 在动作注意力中未接通、动作维部分复制的键名与注册名不匹配；迁移本体或修改 padding 策略时应单独测试。
