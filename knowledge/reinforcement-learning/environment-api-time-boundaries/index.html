Environment contract · time semantics · bootstrap

先定义“为什么结束”，再计算 target

一条轨迹停止，不等于任务进入终止状态。真正终止通常关闭 bootstrap；采样器的外部截断通常仍要从最后真实观测 bootstrap。把二者压成一个 done，会让正确的算法学到错误的目标。

5 返回值Gymnasium 风格 step 契约
4 类 maskreset / bootstrap / loss / valid
3 个时间层仿真、控制、策略推理
16 项测试覆盖最易错的边界

核心公式

\[m_t^{\mathrm{boot}}=1-\mathbb{1}[\texttt{terminated}_t], \qquad y_t=r_t+\gamma\,m_t^{\mathrm{boot}}V(o^{\mathrm{final}}_{t+1}).\]

这条式子成立的前提是：terminated 的含义与任务定义一致，\(o^{\mathrm{final}}_{t+1}\) 是该转移真正到达的最后观测，而不是 auto-reset 后下一回合的初始观测。

1. 本页先解决哪四个问题

读完后应能明确回答：

  1. 当前任务的时间上限属于 MDP，还是只属于采样器？
  2. rollout 停止时，环境、RNN 隐状态、return 递推和价值 bootstrap 分别该不该重置？
  3. auto-reset 返回的 obs 是本次转移的最后观测，还是下一回合的初始观测？
  4. 改变 action repeat 或控制频率以后，奖励与折扣是否仍代表同一个物理时间目标？

前置知识是马尔可夫决策过程；公式落地可继续看时序差分。本页不讲某个算法如何优化，只统一它们共同依赖的数据语义。

2. 环境交互契约：五个返回值不是五个随意字段

Gymnasium 风格单环境接口为：

obs, info = env.reset(seed=seed)
next_obs, reward, terminated, truncated, info = env.step(action)
字段 必须回答的语义 不应偷偷承担的职责
next_obs 动作执行后，环境向智能体暴露的下一观测 不保证是完整 Markov state；auto-reset 模式下也未必是最后观测
reward 这一步按任务奖励定义产生的标量或结构化信号 不是“是否成功”的通用替代品
terminated 任务定义内是否进入终止状态 不表示所有停止采样的原因
truncated 是否因 MDP 外条件提前切断这段交互 不应默认关闭价值 bootstrap
info 诊断量、分项奖励、最后观测、版本能力等辅助信息 不应依赖未经声明、随版本漂移的私有键

两个常用派生量是：

\[e_t=\mathbb{1}[\texttt{terminated}_t\lor\texttt{truncated}_t], \qquad m_t^{\mathrm{boot}}=1-\mathbb{1}[\texttt{terminated}_t].\]

\(e_t\) 表示“这段 episode/采样片段到此结束”；\(m_t^{\mathrm{boot}}\) 表示“价值目标是否允许从下一状态继续估计”。二者回答的是不同问题，不能共享一个 done。

terminated=False, truncated=False 并不保证样本有效；传感器丢帧、数值爆炸、padding 或人工剔除应由独立的 valid_mask / loss_mask 表达。反过来，truncated=True 也不等于无效样本。

3. terminated 与 truncated：先看任务定义，不看变量名字

3.1 真正终止

真正终止是任务动力学或目标定义的一部分，例如：

  • 到达吸收式成功状态；
  • 跌倒、碰撞后任务明确定义为失败终点；
  • 有限时域任务的倒计时归零，且“剩余时间”已经包含在状态或观测中；
  • 任务规定的不可恢复终点。

此时后续回报不属于当前 episode，通常令 \(m_t^{\mathrm{boot}}=0\)。

3.2 外部截断

外部截断来自 MDP 之外，例如：

  • 训练器只允许每段 rollout 收集 \(T\) 步；
  • 为提高数据多样性而设置的采样 time limit；
  • 机器维护、调度或日志分片切断了一段 continuing task；
  • 数据导出时人为把长轨迹切成固定窗口。

如果底层任务本来还会继续，截断处仍有后续价值，应保留 bootstrap，并使用截断前最后真实观测。

3.3 同一个“时间到”为什么可能属于两类

设任务目标是“在 30 秒内完成装配”。若 30 秒是任务本身的规则，并且策略能区分还剩 20 秒还是 1 秒，那么倒计时归零可建模为真正终止。若任务实际是持续运行，而训练器每 30 秒强制 reset 以便采样，那么它是外部截断。

有限时域却不向智能体提供剩余时间，会把“物理状态相同、剩余时长不同”的两个决策情形混在一起，破坏 Markov 性。可使用明确的剩余时间特征，例如归一化的 \(h_t/H\)；不能只在 info 中记录却不提供给策略。

flowchart TD
  A["一段交互为什么停止？"] --> B{"停止条件属于任务定义吗？"}
  B -- "是" --> C{"策略观测能区分剩余时域吗？"}
  C -- "是" --> D["terminated = True<br/>通常关闭 bootstrap"]
  C -- "否" --> E["先修正状态/观测定义<br/>否则存在时间混叠"]
  B -- "否" --> F["truncated = True<br/>通常保留 bootstrap"]
  F --> G{"最后真实观测可得吗？"}
  G -- "是" --> H["从 final next observation bootstrap"]
  G -- "否" --> I["样本语义不完整<br/>修数据或隔离处理"]

不要用“成功就是 terminated、超时就是 truncated”作死记规则。失败也可以是真终止；任务内的有限时域也可以是真终止。判据始终是：停止条件是否属于所定义的决策过程，以及时间信息是否进入状态。

3.4 两个信号同时为真

自定义环境或 wrapper 组合可能产生 terminated=True 且 truncated=True。实现不应假定互斥：

  • episode 确实结束：reset_mask=1；
  • 因为存在真终止：bootstrap_mask=0；
  • 两个原始标志都要保存，便于追查环境契约；
  • 若项目想采用别的优先级，必须在环境规范中显式写出并单测。

4. 四类 mask：不要让一个 done 控制所有事情

名称 典型定义 控制对象 截断时典型值
reset_mask terminated OR truncated episode 统计、环境重置、轨迹分段 1
bootstrap_mask NOT terminated TD、GAE、n-step 尾部的价值项 1
valid_mask 数据是否真实存在 padding、变长 batch、缺失步 1，除非数据本身缺失
loss_mask 当前样本是否参与某项损失 无标签、人工过滤、burn-in、质量门禁 由该损失定义

建议把原始字段与派生字段都写入 buffer：

transition = {
    "obs": obs,
    "action": action,
    "reward": reward,
    "next_obs": transition_next_obs,
    "terminated": terminated,
    "truncated": truncated,
    "episode_id": episode_id,
    "timestep": timestep,
    "valid_mask": valid_mask,
}
transition["reset_mask"] = logical_or(terminated, truncated)
transition["bootstrap_mask"] = logical_not(terminated)

loss_mask 通常在组 batch 时按任务生成，不宜永久覆盖原始真相。例如 RNN 的 burn-in 步可以 valid_mask=1 但 loss_mask=0：这些观测真实存在并用于恢复隐状态，只是不在其上计算训练损失。

4.1 一步 TD target

以状态价值为例：

\[y_t=r_t+\gamma(1-\mathbb{1}[\texttt{terminated}_t])V_{\bar\theta}(o^{\mathrm{final}}_{t+1}).\]

以离散动作 Q-learning 为例：

\[y_t=r_t+\gamma(1-\mathbb{1}[\texttt{terminated}_t]) \max_{a'}Q_{\bar\theta}(o^{\mathrm{final}}_{t+1},a').\]

valid_mask / loss_mask 应乘在损失上，而不是擅自改写 target：

\[L=\frac{\sum_t m_t^{\mathrm{loss}}m_t^{\mathrm{valid}} \left(Q_\theta(o_t,a_t)-y_t\right)^2} {\max\left(1,\sum_t m_t^{\mathrm{loss}}m_t^{\mathrm{valid}}\right)}.\]

分母必须与有效样本数一致。直接对包含 padding 的张量 .mean()，即使把 padding loss 乘成 0，也会让有效样本越少时梯度被稀释。

5. Auto-reset：返回的下一观测可能已经跨 episode

5.1 三种常见行为

向量环境常见三类 auto-reset 模式：

  1. 同一步重置（same-step）：结束步立即 reset；返回的 next_obs 是新 episode 初始观测，结束步的最后观测放在 info 的专用字段。
  2. 下一步重置（next-step）：结束步先返回最后观测，下一次调用再 reset。
  3. 禁用 auto-reset：调用方按 per-env mask 显式 reset。

不同 Gymnasium 版本和其他框架的字段名、默认模式并不完全相同。截至 Gymnasium 1.2.x，内置 SyncVectorEnv / AsyncVectorEnv 的默认模式是 next-step，模式应从 metadata["autoreset_mode"] 或显式构造参数读取；same-step 的最后观测字段也有版本差异。适配器必须读取锁定版本的能力或显式配置，不能靠“看见某个 key 就猜”。

5.2 必须区分三个观测

  • transition_next_obs：动作 \(a_t\) 真正到达的观测，写入 replay 并用于 target；
  • collector_next_obs：采样循环下一次选动作时使用的观测；
  • reset_obs：新 episode 的初始观测。

在 same-step auto-reset 下：

\[o^{\mathrm{transition}}_{t+1}=o^{\mathrm{final}}, \qquad o^{\mathrm{collector}}_{t+1}=o^{\mathrm{reset}}.\]

两者不能共用同一数组后就地覆盖。

5.3 概念适配器

下面第一个模板负责 same-step 模式下“reset observation 与 final observation 同次返回”的拆分，也适用于没有覆盖最后观测的普通输出；它不处理 next-step 模式特有的 reset-only 占位 step。项目应把具体字段名和模式差异封装在唯一适配层中：

def split_step_result(step_obs, terminated, truncated, info, adapter):
    episode_end = terminated | truncated
    learn_next_obs = copy_array(step_obs)

    if adapter.autoreset_mode == "same_step":
        has_final, final_obs = adapter.read_final_observation(info)
        required = episode_end
        assert all(has_final[required]), "结束步缺少 final observation"
        learn_next_obs[required] = final_obs[required]

    collector_obs = step_obs
    return collector_obs, learn_next_obs, episode_end

随后只用 learn_next_obs 算 target：

collector_obs, learn_next_obs, reset_mask = split_step_result(
    step_obs, terminated, truncated, info, adapter
)
bootstrap_mask = logical_not(terminated)

with no_grad():
    next_value = target_value_network(learn_next_obs)
target = reward + gamma * bootstrap_mask * next_value

错误 对截断样本直接用 same-step 返回的 reset observation 做 bootstrap，会把 episode A 的奖励接到 episode B 的初始价值上，形成跨回合污染。

next-step 模式需要额外保存“上一调用哪些子环境刚结束”。在 Gymnasium 的该模式下，这些槽位下一次 step 只执行 reset：调用方传入的动作被忽略，返回 reset observation、零奖励和 false/false 标志。这个返回值用于更新 collector observation，但不是环境转移，不得写入 replay、不得累计 episode return 或推进 episode 内步号：

previous_episode_end = zeros_bool(num_envs)

while collecting:
    actions = policy(collector_obs)
    step_obs, reward, terminated, truncated, info = env.step(actions)

    reset_only = previous_episode_end
    transition_valid = logical_not(reset_only)

    # 只把真实执行了动作的槽位写入 replay / rollout。
    buffer.add_masked(
        mask=transition_valid,
        obs=collector_obs,
        action=actions,
        reward=reward,
        next_obs=step_obs,
        terminated=terminated,
        truncated=truncated,
    )

    collector_obs = step_obs
    previous_episode_end = logical_or(terminated, truncated)

对 recurrent policy，还必须让 reset_only 槽位不把“为已结束 episode 的 final observation 计算但被环境忽略的动作”当成新 episode 历史。若项目不愿维护这类占位语义，应显式选择 same-step 或 disabled 模式，并使用与该模式匹配的适配器。

6. 向量环境：所有边界都必须是逐环境的

设并行环境数为 \(N\)。以下量都应保留 batch 维：

\[\mathbf e_t=\mathbf{terminated}_t\lor\mathbf{truncated}_t, \qquad \mathbf m_t^{\mathrm{boot}}=1-\mathbf{terminated}_t.\]

一个子环境结束时，不能：

  • 把整批 RNN hidden state 清零；
  • 把整批 GAE 递推截断；
  • 用单个 Python if done: 处理数组；
  • 假设 info 中每个索引都存在 final observation；
  • 因为某一环境 reset 就推进全部环境的 episode id。

推荐日志至少记录：

env_id, episode_id, timestep,
terminated, truncated, reset_mask, bootstrap_mask,
has_final_observation, autoreset_mode,
collector_observation_id, transition_next_observation_id

向量 info 常用并行 mask 标记某字段在哪些子环境有效。读取 final observation 或 episode statistics 时，必须同时检查该字段的存在 mask；不要把未定义槽位当成真实值。

7. n-step、GAE 与 replay：边界要沿整条递推传播

7.1 n-step target

对最多 \(n\) 步的 target：

\[G_t^{(n)} = \sum_{k=0}^{K-1}\gamma^k r_{t+k} + \gamma^K \left(\prod_{j=0}^{K-1}m_{t+j}^{\mathrm{boot}}\right) V(o_{t+K}),\]

其中 \(K\le n\)。遇到真正终止时，乘积归零；遇到外部截断时，可以在截断处用最后观测的价值收尾，但不能跨到 reset 后的新 episode 继续累加奖励。

这揭示两个不同的“停止”：

  • 停止收集同一条轨迹的奖励：看 reset_mask；
  • 是否保留尾部价值：看 bootstrap_mask。

7.2 GAE

GAE 的一步残差是：

\[\delta_t = r_t+\gamma m_t^{\mathrm{boot}}V(o_{t+1})-V(o_t).\]

但向后递推不能穿过 episode 分段：

\[A_t = \delta_t + \gamma\lambda(1-e_t)A_{t+1}.\]

因此在外部截断处，\(\delta_t\) 仍可从最后观测 bootstrap；而 \(A_{t+1}\) 属于新 episode，不应接回来。用一个 done 同时替代这两个 mask，恰好会丢掉这一差别。

7.3 Replay 必存的边界字段

至少保存 terminated、truncated、真正的 next_obs、episode_id 和 episode 内步号。若只保存 done：

  • 无法重建正确 bootstrap；
  • 无法安全构造 n-step 样本；
  • 无法验证 sequence batch 是否跨 episode；
  • 离线数据转换时无法区分任务终点和导出切片。

8. RNN 隐状态：需要重置，但不等于关闭 bootstrap

POMDP 或 recurrent policy 中，hidden state 代表当前 episode 的历史摘要。无论真终止还是外部截断，环境 reset 后都不能把旧 episode 的 hidden state 带入新 episode：

\[h_{t+1}^{\mathrm{collector}} = (1-e_t)\,f_\theta(h_t,o_{t+1}) + e_t\,h_{\mathrm{init}}.\]

然而截断处的价值 target 仍可能 bootstrap：

\[m_t^{\mathrm{hidden}}=1-e_t, \qquad m_t^{\mathrm{boot}}=1-\texttt{terminated}_t.\]

两者在 truncated=True 时分别为 0 和 1。实现中应保留 hidden_reset_mask 这个独立名字，即使它当前数值与 reset_mask 相同。

序列训练还要区分：

  • padding：valid_mask=0；
  • burn-in：valid_mask=1, loss_mask=0；
  • episode 边界：重置 hidden，sequence 不跨界；
  • 截断尾部：可以用最后真实观测及其正确历史 hidden 估值。

9. Action repeat、frame skip 与奖励聚合

9.1 三个时间层

定义：

  • 仿真物理步长 \(\Delta t_{\mathrm{sim}}\)；
  • 控制器更新周期 \(\Delta t_{\mathrm{ctrl}}\)；
  • 策略推理周期 \(\Delta t_{\mathrm{policy}}\)；
  • action repeat 为 \(k\) 时，常有 \(\Delta t_{\mathrm{ctrl}}=k\Delta t_{\mathrm{sim}}\)，但并非必然。

“环境一步”必须明确指哪一层。仅写“训练 1M steps”不足以比较两个系统。

9.2 精确的宏步 target

若一个策略动作覆盖 \(k\) 个物理步，且基础折扣为 \(\gamma_{\mathrm{sim}}\)，精确宏步关系是：

\[R_t^{(k)} = \sum_{j=0}^{k-1}\gamma_{\mathrm{sim}}^j r_{t,j}, \qquad y_t = R_t^{(k)} + \gamma_{\mathrm{sim}}^k m_t^{\mathrm{boot}}V(o_{t+1}).\]

许多 wrapper 返回未折扣的 reward sum，再由算法每个宏步乘一次固定 \(\gamma\)。这可以是一套重新定义后的控制步目标，但它不自动等价于原物理步目标。报告必须写清：

  • reward 是 sum、mean、last，还是对时间的数值积分；
  • 终止发生在 repeat 中途时实际执行了几步；
  • bootstrap 使用 \(\gamma^k\)、固定控制步折扣，还是连续时间折扣；
  • frame skip 是只跳渲染、跳观测，还是同时重复动作。

9.3 跨控制频率比较

若希望同一个物理时间长度对应同样折扣，可定义连续时间衰减率 \(\beta\)：

\[\gamma(\Delta t)=e^{-\beta\Delta t}.\]

等价地，已知参考周期 \(\Delta t_0\) 的 \(\gamma_0\)：

\[\gamma(\Delta t) = \gamma_0^{\Delta t/\Delta t_0}.\]

例如把控制频率从 20 Hz 改为 100 Hz 却继续每步使用同一 \(\gamma\)，会把有效物理 horizon 缩短约 5 倍；不能再声称目标时域未变。

奖励若代表“每秒成本率”，聚合时应考虑 \(\Delta t\)；若代表“一次事件的成本”，不能再乘持续时间。先明确单位，再决定 sum、mean 或积分。

10. 观测、动作与时间戳：机器人系统尤其不能省略

真实系统的一条 transition 至少可能涉及：

  • 传感器采集时刻 \(t_{\mathrm{obs}}\)；
  • 策略开始/结束推理时刻；
  • 动作命令发出时刻 \(t_{\mathrm{cmd}}\)；
  • 底层控制器实际生效时刻 \(t_{\mathrm{act}}\)；
  • 奖励或成功标志对应的物理时刻；
  • 下一观测采集时刻。

若观测延迟、推理延迟或执行延迟不可忽略，记录 (obs_t, action_t, next_obs_t) 并不保证它们在因果上对齐。至少应记录单调时钟时间戳、控制序号、丢帧/重复帧标志与动作确认状态。必要时把动作历史、延迟估计或时间差作为观测的一部分。

外部安全层还会产生三个动作：

  1. policy proposed action；
  2. shield / limiter 修改后的动作；
  3. 底层控制器实际执行的动作。

环境转移由第 3 个动作产生。若训练时却把第 1 个动作当行为动作，off-policy 校正与归因都可能错误。

11. Wrapper 顺序：组合本身就是环境定义

wrapper 可改变 observation、action、reward、episode 边界和 info。A(B(env)) 与 B(A(env)) 一般不等价。例如：

  • 先重复动作再施加 time limit，限制的是宏步数；
  • 先限制基础环境步数再重复动作，可能在一次 repeat 中途结束；
  • RecordEpisodeStatistics 放在 reward transform 内外，记录的 return 可能不同；
  • normalization wrapper 在评估时若继续更新统计量，会让评估分布漂移；
  • observation frame stack 应明确 reset 后如何填充历史帧；
  • auto-reset 与 final observation 适配器的相对位置决定谁看得到最后观测。

不要背诵一个适用于所有项目的固定顺序。应把 wrapper 栈序列化进运行配置，并对最终对外接口做契约测试：

assert env.observation_space.contains(obs)
assert is_bool(terminated) and is_bool(truncated)
assert not has_nan(reward)
assert wrapper_stack == expected_wrapper_stack
assert final_observation_contract_is_satisfied(...)

12. Seed 与可复现：同一个整数不等于同一次实验

建议至少分别控制：

  • 环境 PRNG：创建后第一次 reset(seed=...)；
  • action/observation space 采样器；
  • Python、NumPy、深度学习框架与设备端 RNG；
  • 各向量子环境的派生 seed；
  • replay 采样、数据加载 worker 与探索噪声；
  • 环境初态列表、评估任务列表和 wrapper 配置。

不要每个 episode 都用同一个 seed reset，否则会反复得到同一初态序列。向量环境可由一个主 seed 经确定性 SeedSequence 派生，不要仅靠 base_seed + env_id 后就省略记录。

即使所有 seed 相同，异步调度、GPU 非确定性算子、物理引擎接触求解和硬件传感器仍可能造成差异。复现报告应保存版本、配置、数据哈希和多 seed 分布，而不是只报告单条曲线。

13. Offline dataset：timeout 缺失时不能假装知道边界

离线数据应尽量保留：

observations, actions, rewards, next_observations,
terminated, truncated, episode_id, timestep,
task_horizon, discount, control_dt, action_repeat,
final_observation_valid, provenance

常见歧义：

  • 数据只有 done，不知道是真终止还是 timeout；
  • 数据在固定长度处切片，却没有 truncated；
  • 最后一个 next_observation 是全零、重复当前观测或下一 episode 初态；
  • 导出器把所有 episode 最后一步都标成 terminal；
  • timeouts 存在，但其含义是任务内时限还是采集器时限未说明。

处理顺序应是：

  1. 查数据生成代码、规范和原始日志；
  2. 用 episode 长度分布、任务成功标志和状态连续性做证据核对；
  3. 无法恢复时把语义标成 unknown，分别做“关闭/保留 bootstrap”的敏感性实验；
  4. 不要仅凭“步号等于常见 horizon”批量改标签。

进一步学习见离线强化学习；该页负责分布外动作与保守目标，本页只负责边界数据契约。

14. 多智能体：个体结束与全局结束必须分开

多智能体环境至少需要：

  • 每个 agent 的 terminated_i / truncated_i；
  • agent 是否仍活跃的 active_mask_i；
  • 环境级 global_terminated / global_truncated；
  • 动态 agent 集合的加入、退出与 padding 规则。

某个 agent 死亡后，其他 agent 可能继续。此时：

  • 该 agent 的 bootstrap 是否关闭取决于个体任务定义；
  • centralized critic 是否继续估值取决于全局状态与训练目标；
  • dead-agent padding 不应参与 policy loss；
  • episode 统计何时结束应由全局规则决定，不能简单 any(done_i) 或 all(done_i) 而不声明。

合作任务还要明确 team reward 在个体退出后如何分配。PettingZoo 等框架的具体字段可在适配层处理，但原始个体/全局边界不能被一个标量 done 覆盖。

15. 正确与错误实现对照

15.1 把所有结束都关掉 bootstrap

错误

done = terminated or truncated
target = reward + gamma * (1 - done) * value(next_obs)

这会把外部截断误当终止；若 next_obs 又是 auto-reset 初态，则还可能同时出现两个错误。

正确语义

transition_next_obs = final_observation_adapter(
    step_obs=next_obs,
    terminated=terminated,
    truncated=truncated,
    info=info,
)
bootstrap_mask = 1.0 - terminated.astype(float)
target = reward + gamma * bootstrap_mask * value(transition_next_obs)

15.2 GAE 递推穿过 reset

错误

delta[t] = r[t] + gamma * (1 - done[t]) * v_next[t] - v[t]
adv[t] = delta[t] + gamma * lam * (1 - done[t]) * adv[t + 1]

正确语义

bootstrap_mask = 1.0 - terminated[t]
continuation_mask = 1.0 - (terminated[t] or truncated[t])

delta[t] = r[t] + gamma * bootstrap_mask * v_final_next[t] - v[t]
adv[t] = delta[t] + gamma * lam * continuation_mask * adv[t + 1]

15.3 RNN hidden 与 value 共用 mask

错误

hidden = hidden * bootstrap_mask

正确语义

hidden = hidden * (1.0 - reset_mask)  # 新 episode 不继承历史
target = reward + gamma * bootstrap_mask * next_value

16. 固定 transition 夹具

先让与算法无关的适配器和 mask 纯函数通过下面 10 个夹具，再接入 DQN、PPO 或 SAC。表中 B 是 bootstrap mask，R 是 reset/trajectory-boundary mask。

编号 场景 terminated truncated final obs B R 预期
F1 普通转移 0 0 step obs 1 0 正常 bootstrap
F2 真正成功/失败终点 1 0 step obs 0 1 target 只有即时奖励
F3 外部 time limit 0 1 step obs 1 1 从最后观测 bootstrap
F4 两信号同时为真 1 1 step obs 0 1 终止优先关闭 bootstrap，并记录异常
F5 same-step auto-reset 截断 0 1 info 中 final obs 1 1 禁止使用 reset obs
F6 向量环境部分结束 [0,1,0] [1,0,0] 逐环境 [1,0,1] [1,1,0] 只改对应槽位
F7 padding 任意 任意 无 任意 任意 valid=0，不计损失
F8 离线 timeout 语义未知 未知 未知 可疑 未定 1 隔离并做敏感性分析
F9 continuing task 日志分片 0 1 最后真实观测 1 1 片段断开，价值不断开
F10 next-step reset-only 返回 0 0 新 episode 初始观测 不适用 0 valid=0，不写 replay，不推进步号

概念测试可写成：

def expected_masks(terminated, truncated):
    reset_mask = logical_or(terminated, truncated)
    bootstrap_mask = logical_not(terminated)
    return reset_mask, bootstrap_mask

def test_external_truncation_bootstraps_but_resets_episode():
    reset_mask, bootstrap_mask = expected_masks(False, True)
    assert reset_mask is True
    assert bootstrap_mask is True

def test_true_terminal_disables_bootstrap():
    reset_mask, bootstrap_mask = expected_masks(True, False)
    assert reset_mask is True
    assert bootstrap_mask is False

17. 必须覆盖的 16 项测试

基础边界

  1. true terminal
  2. time-limit truncation
  3. terminated 与 truncated 同时为真
  4. continuing task 分片
  5. 旧 Gym done 数据迁移

采样与序列

  1. auto-reset final observation
  2. next-step reset-only 不进入 replay/RNN 历史
  3. vector env 部分完成
  4. RNN hidden reset
  5. n-step 不跨 episode
  6. replay episode id 连续性

时间与数据

  1. action repeat 奖励聚合
  2. frame skip 最后观测
  3. 不同 control Hz 的折扣
  4. multi-agent 部分终止
  5. offline timeout 缺失

每项测试不只检查布尔值，还应检查最终数值 target。例如设 \(r=2,\gamma=0.9,V(o_{t+1})=10\)：

  • 真终止 target 应为 \(2\)；
  • 外部截断 target 应为 \(2+0.9\times10=11\)；
  • same-step auto-reset 若 reset observation 的 value 为 100，target 仍必须是 11，而不是 92。

18. 运行时断言与诊断面板

建议在小规模 debug run 中启用：

assert all(not isnan(reward))
needs_final_obs = logical_and(reset_mask, bootstrap_mask)
assert all(logical_or(valid_final_obs, logical_not(needs_final_obs)))
assert all(bootstrap_mask == logical_not(terminated))
assert no_sequence_crosses_episode_id()
assert no_rnn_state_leaks_across_reset()
指标 正常用途 异常信号
terminated / truncated rate 了解任务与采样边界占比 所有结束都落在同一类，可能是适配错误
final observation missing rate 验证 auto-reset 契约 same-step 结束样本中非零即高风险
value at truncation 监控 partial-episode bootstrap 被系统性压到 0，可能误关 bootstrap
value at true terminal 验证终点拟合 长期远离终点回报，可能 mask 错误
episode length histogram 查 time limit 与提前失败 尖峰整体偏移，可能 wrapper 顺序变化
cross-episode sample count 查 n-step/RNN batch 必须为 0，除非算法显式允许且有隔离
effective physical horizon 跨频率比较 control Hz 改变后无意漂移

优先排查顺序：任务定义 → wrapper 栈 → 原始五返回值 → auto-reset 模式 → final observation → buffer 字段 → batch mask → target 数值。不要一看到 loss 发散就先调学习率；边界语义错误时，调参只会掩盖问题。

19. 与其他页面的职责边界

  • MDP：定义状态、转移、回报和有限/无限时域；

  • 具体算法实现页：只说明框架字段如何映射到本页统一语义，不重复发明 done 规则。

20. 最小实施清单

在开始训练前逐项确认：

  • 任务规范写明自然终止、失败终止和外部截断；
  • 有限时域若属于任务，剩余时间进入状态/观测；
  • buffer 分开保存 terminated 与 truncated；
  • same-step auto-reset 使用最后真实观测计算 target；
  • reset_mask 与 bootstrap_mask 分离；
  • RNN hidden、GAE continuation、loss、padding 各用正确 mask；
  • n-step 与 sequence sample 不跨 episode id；
  • action repeat 的奖励聚合与折扣单位明确；
  • control Hz 改变时重新换算物理时间 horizon；
  • wrapper 顺序、版本、auto-reset 模式写入配置；
  • offline timeout 缺失被显式标记为未知；
  • 10 个固定夹具和 16 类边界测试通过；
  • 日志能同时定位环境原始信号、适配结果与最终 target。

  6. Pardo et al., Time Limits in Reinforcement Learning, ICML 2018——任务内有限时域的 time-awareness 与任务外时间限制的 partial-episode bootstrapping。
  7. Sutton & Barto, Reinforcement Learning: An Introduction, 2nd ed.——episodic/continuing task、return、TD 与函数逼近的基础定义。
