VLA 模型家族/上一专题：X‑VLA/SmolVLA 总览

COMPACT VLA · FLOW MATCHING · ASYNCHRONOUS EXECUTION

SmolVLA 以截断的 SmolVLM2、压缩视觉 token、约 100M 的动作专家和 Flow Matching 动作块构成约 450M 参数策略，并以 legacy async 把动作预测与执行并行；它证明了低预算完整路线的可行性，但没有证明任意 CPU 实时、跨本体零样本或安全关键部署。

≈450M论文主模型总参数标签；不是本页重新统计。
≈100M论文动作专家参数标签。
16 / 32固定发布实例使用前 16 个文本层。
1024 → 64每个有效画面的 patch 表示与后续视觉 token。
50 / 50 / 10预测块、同步执行窗口、Euler 迭代，三者不可互换。
0 runtime approval本页不签发部署许可，也没有运行模型或机器人。
paper · arXiv v1code · fixed commitcheckpoint · fixed revisionpoint estimates ≠ guarantees

轻量化设计：节省发生在哪里

“Smol”不是单个层，而是一组成本选择。每一项必须同时回答节省什么、没有节省什么以及引入何种信息或适配风险；不能把几个孤立比例相乘成端到端加速倍数。

四项轻量化选择的成本边界
选择 直接节省 仍保留的成本或信息损失 证据上限
文本塔前 16 / 32 层 稳态参数、后 16 层前向与后续 KV 固定路径会先构造或加载完整 VLM 再截断；不能声称初始化峰值从未包含后 16 层 Table 8：前 16 层 78.5、全 32 层 80.3，仅为该设置点估计
1024 → 64 视觉 token 文本塔序列计算和 prefix KV SigLIP 仍处理 1024 个 patch 表示；pixel shuffle 只重排，12288→960 线性投影才有损 没有独立成功率消融证明 64 为全局最优
动作专家 960 → 720 专家注意力与 FFN 成本 0.75 宽度不是 Table 9 的最高点，也未给出完整延迟—显存曲线 只能称工程折中，不能称最优宽度
冻结 VLM VLM 梯度与优化器状态 VLM 前向仍存在，也可能留下任务适配差距 “可单卡训练”不改写论文预训练使用 4 GPU 的记录

固定主干配置提供可复算边界：文本 hidden 960、FFN 2560、32 层、15 个注意力头、5 个 KV 头、head dim 64；视觉塔输入 512、patch 16、hidden 768、12 个头。每边 32 个 patch 得到 1024 个 patch 表示，shuffle factor 4 将空间序列变为 64 项，随后做通道投影。这里的“64 token”是每个有效画面进入文本塔的数量，不是相机总数固定为一。

硬件主张边界：论文和博客的“可在 CPU 运行”只能支持兼容性陈述；是否实时取决于目标 CPU、相机数、控制频率、推理延迟分布、通信与控制器预算。本页不提供任意 CPU 实时保证。

总架构：条件前缀与动作后缀

图像、语言、状态属于 prefix；含噪动作和 flow time 属于 suffix。固定发布实例中 num_vlm_layers=16，num_expert_layers=0；在固定提交里非正专家层数跟随截断后的 VLM 深度，因此得到 16 层专家。这个固定实现等价关系不能外推为所有未来版本的方法不变量。

固定提交中的 prefix 会在所有层先完成 prefill。去噪时，joint self-attention 的动作 query 可以读取 prefix cache 和因果可见的动作位置；cross-attention 的动作 query 从 prefix K/V 读取条件。每次去噪步后裁去临时 suffix K/V，保留 prefix 供下一步复用。交错由 attention_mode=cross_attn 与 self_attn_every_n_layers=2 共同决定，不是“一半层完全看不到观测”。

论文 Table 6 的 CA+SA 85.5、纯 CA 79.0、纯 SA 74.5，以及 Table 7 的 causal 74.5、bidirectional 67.5，只是论文标记配置下的点估计。现有证据不能证明这些分支与固定提交控制流逐行一致，也不能把“动作 token 利用局部相关性形成捷径”写成唯一原因。

动作生成采用固定实现约定：

\[x_t=t\epsilon+(1-t)A,\qquad u_t=\epsilon-A,\]

其中 t=1 是噪声端、t=0 是数据端。训练时刻为 0.999·Beta(1.5,1)+0.001；推理从噪声端以负步长做反向 Euler。论文印刷式 A_\tau=\tau A+(1-\tau)\epsilon 的导数应为 A-\epsilon，却同时写目标 \epsilon-A，因此本专题保留符号冲突，并以固定可执行实现作为运行时约定，不静默拼接两套时间方向。

三种时间尺度，不能互换

预测 horizon50chunk_size：一次策略调用生成多少个动作。
同步执行 horizon50n_action_steps：同步策略把多少个动作放入内部队列后再规划。
积分 horizon10num_steps：一次动作块生成中的反向 Euler 更新次数。

文本等价：50 个预测动作不表示必须连续执行 50 步；50 个同步队列动作也不等于 50 次 Euler；10 次数值积分更不定义控制频率。论文 LIBERO 主结果每执行 1 个动作就重新规划，因此复现该口径需要显式把执行窗口设为 1，或采用等价的数据处理与调用方式。

同步、legacy async 与 RTC

文本等价：同步路径由 SmolVLAPolicy.select_action 管理内部队列，空队列触发新推理；legacy async 的动作队列属于机器人客户端，余量低于阈值 g 时向策略服务器请求新块，固定默认阈值为 0.5，预算依据是平均端到端延迟；RTC 是独立扩展，块与重叠前缀由调用方管理，SmolVLA 固定入口默认没有 RTC 配置。

模式 队列 owner / 触发 可获得的收益 必须补验的风险

legacy async robot client；余量比例低于阈值 在队列未耗尽时重叠预测与执行 网络与推理尾延迟、队列耗尽、融合误差、超时与停止责任
RTC caller；调用方决定 新块重叠部分可施加一致性引导 额外梯度与配置成本；不能冒充论文原始 async

七条论文局限与系统边界

  1. 预训练只含 SO100 一种机器人类型，未验证多形态联合预训练和零样本跨形态。
  2. 约 23K 条轨迹仍小于部分大型 VLA 数据规模。
  3. 在保持可访问性的同时扩展模型仍是开放问题。
  4. 选用的 VLM 主干没有被证明对机器人交互全局最优。
  5. 多模态数据与机器人数据没有联合训练。
  6. 任务相对简单且时程较短，复杂长时程与层级规划仍未解决。
  7. 主要依赖模仿学习，RL 后训练能否改善复杂控制仍待验证。
适合优先考察低预算教学、原型验证、公开链路学习与单机微调；仍需在目标硬件和目标任务上验证。
CPU-only先做目标硬件延迟、吞吐与内存基准；“可运行”不是“满足控制周期”。
跨本体与开放世界没有零样本跨本体、开放世界或长时程统一证据；SO101 结果经过目标数据微调。
安全关键部署没有硬实时或安全认证；必须另设限位、速度/力矩约束、watchdog、人工接管、超时停机和 fallback owner。
