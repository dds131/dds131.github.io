openpi-RLT ④：E-2、F、G 离线数据流水线

从纯 VLA 加人工接管的 E-2 数据采集，到 Actor-Critic 离线预训练和原始动作安全闸，解释数据口径、过拟合判据与上机准入

总览 三阶段 RL-Token 运行架构 E-2 / F / G L4 在线训练 工程修复 结果与归因
E-2 collectF offline trainG safety gate

先采到有来源语义的真机 Replay，再离线把 Actor 训到可控范围，最后检查原始输出是否具备上机资格。

阶段漏斗

E-2 · 真机采集

冻结 VLA 为主，人类在跑偏时接管；保存逐步实际动作、BASE / HUMAN / MIXED 来源、奖励和完整 step trace。

数据质量闸

检查规模、成功 episode、BASE 比例、退化动作和夹爪档位。

F · 离线预训练

Actor 在 BASE chunk 贴住 reference，在 HUMAN / MIXED chunk 学习记录的实际动作；Twin Critic 同步训练。

G · 动作准入闸

在安全整形前检查 Actor 原始输出的三项硬条件；100% 通过才具备进入 L4 的必要资格。

E-2：数据不是“40 条成功演示”

2,443BASE transitions

246采集期 drop，未写入
33 / 40含人工接管的成功

82.5% 只说明这 40 条采集 episode 在允许人类接管的条件下有 33 条被判为成功。它不能回答纯 VLA 或 RLT actor 单独完成任务的概率。

这里还有三个不能相加的计数：246 条在采集期因 drop_transition 没有写入 journal；后验数据质量闸对已写入数据的结论是 40/40 episodes 通过、额外剔除 0 条；Replay 中有 32 条 episode 带正奖励。最后一个数字与 33 条 success 相差 1，说明“运行时成功标志”和“可用于训练的 +1 奖励”必须分别审计。

质量闸

判据 准入线 为什么
Transition 总数 ≥ 600 满足 warmup 最小 replay
成功 episode ≥ 1 需要至少一条正奖励链
BASE 占比 ≥ 50% 防止数据被人工动作完全主导

夹爪档位 必须合规 防止离散档位被连续噪声污染

F：真正部署的是 source=all

Actor 的 BC target 是条件目标：

bc_target = recorded action_chunk   if source_chunk ∈ {HUMAN, MIXED}
bc_target = VLA ref_chunk           otherwise

MIXED 的 action_chunk 是逐步实际执行动作组成的混合块，不应全部改称“纯人类动作”。因此部署模型必须看包含 HUMAN / MIXED 的 source=all 结果；只看 BASE 子集会丢掉学习纠正动作的目标。

此处 fit 也不是训练时的条件 BC loss，而是在原始物理单位上度量 Actor 均值与冻结 VLA reference 的平均绝对偏差：

\[\operatorname{fit}(D) =\frac{1}{|D|\cdot10\cdot8} \sum_{x\in D}\left\lVert a_{\mathrm{actor}}(x)-a_{\mathrm{ref}}(x)\right\rVert_1, \qquad \operatorname{gap}=\frac{\operatorname{val\_fit}-\operatorname{train\_fit}}{\operatorname{train\_fit}}.\]
口径 train / val n train_fit val_fit gap 正确用途
source=all 2,671 / 140 0.5003 0.4879 −2.5% 部署模型主要视角
source=base 2,321 / 122 0.3457 0.3395 −1.8% “是否贴住 VLA”子集诊断
项目早期汇总常引用 0.3395 / −1.8%，但它是 BASE 子集。完整呈现必须先报告 source=all 的 0.4879 / −2.5%，再用 BASE 解释 reference 拟合情况。负 gap 只表示本次切分中验证误差略低于训练误差，不表示“负过拟合”或策略优于 reference。

为什么旧阈值不适用

上游曾使用 val_fit 小于 0.02，但该值来自弧度动作口径。本项目关节使用度制，18 次历史训练均在约 0.55–0.94 量级，不可能靠同一阈值验收。

本项目采用：

val_fit < 0.5
gap = (val_fit - train_fit) / train_fit < 15%
val_max < 5.0
val_joint8 < 0.125
seeds >= 4

这些是本项目基于度制历史 run 制定的工程闸门，必须在相同 source、切分和推理模式下比较；它们不是跨机器人通用常数。

从 787 条到 2811 条

787 · BASE gap+38.5%–+43.9%
2811 · ALL gap−2.5%
2811 · BASE gap−1.8%

早期小数据 run 同时存在弱正则、seed 不稳和小验证集问题；图中的 +38.5%～+43.9% 是四个 source=base 历史 run。扩充到 2,811 条后，本次切分不再出现正的 train/validation gap；但验证集仍只有 source=all 140 条、source=base 122 条，且来自同一轮采集。因此它只能支持“这次切分未见原来的大 gap”，不能证明跨场景泛化，也不保证动作比 VLA 平滑。

G：检查整形前的原始 Actor

GATE 01

数值有限

任何 NaN 或 Inf 都直接阻止上机。

GATE 02

首步关节偏差闸

Actor 第一帧的七关节不能离当前关节状态超过 10°。

GATE 03

块内关节跳变闸

动作块内部七关节的相邻帧跳变不能超过 10°。

L4 种子 bundle 在 2,811 条 E-2 Replay 状态上的确定性均值输出通过率为 100%。在线训练后的对应评估曾下降到 99.75% 和 99.90%；这说明 G 闸不只是一次性准入，也能暴露在线策略漂移。不同评估集或采样模式之间不能只比较百分比而忽略分母。

安全整形器能让最终下发动作落在硬阈值内，但它可能掩盖 Actor 本身已经恶化。G 闸必须检查整形前的原始输出，且准入线是严格 100%。该 100% 只覆盖有限性、关节首步偏差和关节块内跳变；软限位、关节 4 奇异区和夹爪非三值只做诊断统计，更不证明任务会成功。

两种低质量人工数据处理

第七路 · 三态自动判据

chunk 内存在人工控制、整块没有握住 Grip 且七关节变化小于 0.3° 时命中。默认 log 只统计；显式切到 drop 后才丢弃“挂着接管模式但没有示范”的空块。

丢段键 · 人工语义

操作员发现刚才纠正做错时，可回溯标记该段。它处理的是算法无法仅凭位移判断的“动作有变化但质量差”。

第七路先以 log 模式观察误杀，再转 drop；项目验证轮中 drop 模式命中的 39/39 个 chunk 均未进入 Replay。它仍不能判断“动作有变化但语义上做错了”，所以需要丢段键补上人工判断。

接下来进入 L4 在线训练：通过 G 闸的 Actor 会先冻结上机，再允许真人介入与在线更新。
