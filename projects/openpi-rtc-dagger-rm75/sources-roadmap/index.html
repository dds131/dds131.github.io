先回答“证据证明了什么”，再讨论“下一步做什么”。

RTC、DAgger 与 HG-DAgger 的论文结论，上游 main 分支的当前能力，本项目需求文档中的设计，以及尚未执行的真机路线属于四种不同证据；本页不再把它们混成一条“已经实现”的叙事。

二、RTC：论文方法、推理模式与版本边界

A · PAPER · v2

Real-Time Execution of Action Chunking Flow Policies

论文提出推理时 RTC：异步生成下一动作块，冻结必然执行的前缀，并对其余部分做 inpainting；论文说明无需为该模式重新训练。

 A · AUTHOR PAGE

Physical Intelligence · RTC

作者项目页提供方法说明与实验视频；它展示论文系统，不证明本项目的 RM75 适配状态。

 B · DOCS · MAIN

LeRobot · RTC 文档

当前 main 文档同时描述 inference-time guided 与兼容 checkpoint 的 trained 模式；页面明确提示 main 可能要求源码安装。

 B · SOURCE · MAIN

LeRobot RTC 推理引擎

当前源码可核对后台推理、动作队列、延迟跟踪、暂停/恢复/重置与相对动作前缀重锚等实现。

 A · FOLLOW-UP · v2

Training-Time Action Conditioning

该后续工作在训练时模拟延迟并显式条件化动作前缀，以省去推理时 inpainting 开销；它需要相容的训练与 checkpoint，不能当作 guided 权重的无条件运行时开关。

若已提交前缀长度为 $k$，推理时 RTC 的核心约束可概括为“新块的前缀继续已承诺动作”：

\[\mathbf a^{\mathrm{new}}_{0:k} \approx \mathbf a^{\mathrm{committed}}_{0:k}.\]

这只是语义摘要，不是完整损失函数。实际对齐还依赖延迟估计、软掩码、执行时域与具体实现。RTC 的直接目标是降低动作块交界处的停顿和不连续；它不自动解决错误感知、错误任务理解、碰撞风险或人工接管协议。

三、DAgger、人工门控与 HG-DAgger 不能混称

A · DAGGER · AISTATS 2011

No-Regret Imitation Learning

DAgger 在学习策略诱导的状态分布上查询专家标签，并迭代聚合训练集，以处理行为克隆的分布偏移。

 A · HG-DAGGER · v2

Interactive Imitation Learning with Human Experts

HG-DAgger 不只包含“人来接管”：论文还学习基于模型不确定性的风险度量与安全阈值。

 B · SOURCE · MAIN

LeRobot DAgger rollout

当前 main 源码区分连续记录和 corrections-only；后者只记录人工纠正窗口，并把纠正帧标记为 intervention=True。

 B · GUIDE · MAIN

LeRobot HIL 数据采集

官方指南说明策略 rollout、teleoperator 前提、RTC 后端和数据记录流程；硬件兼容性仍需按项目设备单独验证。

经典 DAgger 第 $i$ 轮的逻辑可写成：

\[s \sim d_{\pi_i},\qquad a^\star=\pi^\star(s),\qquad \mathcal D_i=\mathcal D_{i-1}\uplus\{(s,a^\star)\},\qquad \pi_{i+1}\leftarrow\operatorname{Train}(\mathcal D_i).\]

这里的 $\uplus$ 表示保留样本身份的拼接，而不是去重集合。人工门控只在操作者判断需要时产生标签，因此更接近 human-gated / DAgger-inspired 数据聚合。除非项目还实现并验证了 HG-DAgger 的不确定性风险模型与阈值学习，否则不能把“VR 接管”直接称为“完整 HG-DAgger”。 场景驱动的定向恢复示教则从历史失败清单出发，由人安全复现已知失败附近的状态。它提高已知失败簇的采集效率，但样本并非本次策略 rollout 诱导，因此不能直接继承 DAgger 对策略访问分布的叙述。推荐把它作为独立数据源，与低频在线 DAgger 组合；记录 collection mode、失败类型、策略可达性和初始化方式，再用真实在线样本检查分布偏差。

六、知识点、重点与创新边界

知识点

  • 论文、上游实现、项目实现和路线计划是不同证据层。
  • RTC 解决动作块异步交接；DAgger 解决策略诱导分布下的数据聚合。
  • human-gated DAgger 与包含风险模型/阈值学习的完整 HG-DAgger 不同。
  • main 链接便于阅读，但 commit 才能支持复现。

本页重点

  • 每条工程主张都要落到版本、配置、测试与运行记录。
  • 未来路线必须有进入条件、退出条件和失败回退。
  • 效果结论必须来自锁定协议的 trial，而不是训练损失或精选视频。
  • 不把软件防护写成安全认证。
创新边界：RTC、DAgger、HG-DAgger 的算法贡献分别属于原论文。本项目可以主张的创新仅限于“面向 RM75 的 RTC、VR 人工接管、统一安全链、纠正数据契约与跨域训练闭环的工程设计/集成”；在补齐 C 级证据前，应写成“设计与适配目标”，而不是已验证的新算法或已完成系统。

七、从版本锁到真机 A/B 的门控路线

G0 · 版本冻结

记录 LeRobot、OpenPI 与项目仓库 commit；保存依赖锁、配置摘要、数据版本和 checkpoint SHA。退出条件：另一环境可重建同一软件与配置。

G1 · 静态与单元证据

补齐设计地图中的源码定位；验证状态机非法转移、schema、相机语义、尾部窗口和异常清理。退出条件：测试报告可追溯到 commit。

G2 · 无运动 dry-run

用录制观测或 mock robot 检查 RTC 暂停/恢复、队列失效、接管事件和保存/丢弃。退出条件：没有真实运动命令且事件日志闭合。

G3 · 低速受监管真机

限定空间、速度和单步时长，现场准备物理急停；先做 assisted safety trials。退出条件：故障注入和恢复流程达到预设门槛。

G4 · 数据闭环

纠正段通过契约检查后转换、聚合并重建索引/统计；训练输出记录起点、步数、参数更新范围和 SHA。退出条件：固定样本可复现同一输入张量与输出元数据。

G5 · 锁定评测

冻结基线/候选权重和 A/B 协议后，才开始零接管 rollout；评测中不得继续调参。退出条件：原始 trial、排除原因和统计结果齐全。

门控是单向证据链，不是时间表。任一阶段失败都回到最近一个通过的阶段；“下一阶段已经规划”不能替代当前阶段的通过证据。

G4 前必须完成的两个决策实验

  1. 采集路线实验：对相同失败簇分别使用在线 DAgger 接管和定向恢复示教，比较每小时通过质量闸的 episode、失败簇覆盖、策略真实可达率、恢复成功率和动态上下文缺失。目标不是选一个永久替代另一个，而是确定高吞吐定向库与低频在线审计的比例。
  2. 训练框架实验：固定数据 manifest、模型、可训练参数、dtype、有效 batch、GPU 和步数，分开统计首次编译、预热后 samples/s、峰值显存与端到端时间；随后验证损失/梯度短程一致性、checkpoint 转换和 PyTorch RTC 部署回归。只有净收益为正时，才把 JAX 设为大规模训练主路径。

两项实验都应在开始前写出通过阈值；“感觉更快”或“episode 更多”不能代替质量、分布和部署等价性证据。

八、A/B 统计对象与视频计划

正式 A/B 使用相同任务集合、初始条件分层和随机执行顺序。主要终点应在试验前固定，例如任务成功率、零接管完成率和安全触发率；完成时间等连续指标作为次要终点。若第 $m$ 个匹配条件下基线与候选结果为 $y_m^{(A)}$、$y_m^{(B)}$，配对差估计为

\[\widehat{\Delta} = \frac{1}{M}\sum_{m=1}^{M} \left(y_m^{(B)}-y_m^{(A)}\right).\]

一个“trial”才是统计单位，不能把同一 episode 的视频帧当作独立样本放大样本量。二元成功率报告分子/分母和 Wilson 区间；配对二元差异可报告四格配对计数，并按预注册方法检验。需要同时报告旧任务保持集、所有失败类型、排除规则与缺失 trial，不能只报告最佳子集。

评测前锁定

  1. 任务、场景、初始位姿和随机化范围。
  2. 速度、RTC 参数、软件 commit 与两份权重 SHA。
  3. trial 数、主要终点、停止条件和排除规则。
  4. 操作者接管触发规则；正式零接管 A/B 与安全试跑分开。

媒体补录

  1. 同一 episode 的自主、软停、接管和完成多视角同步视频。
  2. 相同初始条件下的基线/候选并排 A/B。
  3. 失败、坏段丢弃和回退案例，避免成功样本偏差。
  4. 画面叠加 trial ID、相位、录制态和匿名化版本摘要。
当前媒体边界：尚无可核对版本的 RTC+DAgger 专属真机效果视频，因此页面不使用演示视频证明系统效果。视频只有在 trial ID、版本与原始记录可对应后，才能作为结果的辅助证据；它仍不能替代统计报告。

九、复现记录最小清单

  • 上游与项目 commit、依赖锁文件摘要、运行配置摘要；
  • 数据集版本、episode 清单、collection mode、失败簇、初始化方法、转换日志与统计文件摘要；
  • 训练起点、框架、随机种子、优化步数、参数更新范围、吞吐/显存基准与 checkpoint SHA；
  • 机器人/相机逻辑标识、标定版本、控制频率与 RTC 延迟统计；
  • 每个 trial 的条件、顺序、结果、人工接管、安全触发、失败分类和排除原因；
  • 测试执行日期与负责人；“需求中记录为通过”与“本次重新执行通过”分开标注。

当前最重要且仍缺的非 DAgger 指标是：严格同条件的真机 RTC on/off 多 trial 配对、发送循环的计划 deadline/lateness、成功率分子/分母与置信区间，以及统一绑定 checkpoint hash、数据集 fingerprint、代码 commit、配置和 trial 的不可变 manifest。缺失项不在本页填入估计值。
