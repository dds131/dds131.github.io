一、阅读边界：以符号为主，以行号为辅

本页回答三个源码问题：一次训练如何进入主循环、一个 RLDS step 如何变成监督样本、发布版如何把生成 token 还原为机器人动作。 网络原理、量化误差、优化数学和数据配方分别由其他子页展开；这里保留理解调用关系所需的最小语义，不重复实验结论。

106固定 Git commit 中的文件数
97其中 Python 文件数
2原生版与 HF 版模型实现
5vla-scripts/ 下的脚本数

为什么必须固定版本

文件行号会随格式化和注释变化，main 分支也不是可复现版本。本页采用：

  • OpenVLA commit c8f03f48af692657d3060c19588038c7220e9af9；
  • Hugging Face openvla/openvla-7b code revision 31f090d05236101ebfc381b61c674dd4746d4ce0。

本页的行号只对这两个版本有效。真正稳定的索引是“文件路径 + 类/函数全限定名”，例如 prismatic.models.load.load_vla，而不是孤立的 L122。

本地 local_only_do_not_upload/dds_tools/openvla_src 是为核对关键路径保留的裁剪镜像，而且没有可验证的 Git 元数据；它不能仅凭目录内容证明自己与上述 commit 逐文件一致。因此，本页以固定链接为版本证据，用本地镜像做符号级交叉检查。下文的 106/97/5 等数量均指固定 commit 的递归文件树，不指本地裁剪镜像。

还要区分“本页引用固定版本”和“脚本运行时固定版本”：官方 deploy.py、finetune.py 的 from_pretrained(..., trust_remote_code=True) 没有传 revision=。若输入 Hub 模型名，远程代码仍可能随默认分支变化。可复现运行应使用已固定的本地模型目录，或在 processor 与 model 两处显式传同一 revision；仅在文档中记录 revision 不会自动约束脚本。

证据 能确认什么 不能单独确认什么
固定 commit 的源码 控制流、默认值、接口与代码注释 训练时实际使用的命令和阶段日志
发布 checkpoint 的配置与远程代码 发布模型结构、统计量和 HF 推理接口 原生训练版与 HF 版在所有环境下数值完全一致
转换脚本 参数名映射与结构装载是否完整 两套预处理和前向计算是否逐元素相等
验证脚本 HF 模型能否加载并完成推理 与原生实现的端到端对照误差

二、仓库分层与四个核心工程接口

路径 快照文件数 主要职责
prismatic/conf/ 4 模型、数据集与 VLA 训练配置注册表
prismatic/models/ 29 视觉/语言主干、projector、VLM/VLA 以及加载逻辑
prismatic/vla/ 19 动作 tokenizer、RLDS 数据管线与 OXE 数据适配
prismatic/training/ 7 训练循环、指标与 FSDP/DDP 策略
prismatic/util/ 5 collator、projector 模块和通用张量工具
prismatic/extern/hf/ 4 面向 Transformers AutoClass 的独立发布实现
vla-scripts/ 5 训练、微调、部署、转换和验证入口
experiments/robot/ 9 Bridge 与 LIBERO 等评测路径

从工程职责看，最关键的是四个接口：

  1. 模型加载接口：prismatic/models/load.py 决定载入基座 VLM 还是 VLA checkpoint。
  2. 数据装配接口：prismatic/vla/materialize.py 把数据集、动作 tokenizer、batch transform 与 collator 绑定起来。
  3. 训练策略接口：prismatic/training/materialize.py 根据策略名构造 FSDP 或 DDP 策略。
  4. 发布推理接口：prismatic/extern/hf/ 把模型、图像处理器和 tokenizer 包装成 Transformers 可加载对象。

OpenVLA 的源码级创新不在某个孤立类，而在这些接口的组合：RLDS/TensorFlow 数据可以流入 PyTorch 训练；动作被表示为语言模型 token；原生 FSDP 训练实现可以转换为自包含的 Hugging Face 发布实现。

三、训练主链路：必须区分两种模型加载分支

vla-scripts/train.py::train() 是原生大规模训练入口，但它不会无条件构造 OpenVLA。是否提供 pretrained_checkpoint 决定了模型类型。

场景 调用 返回对象 动作相关状态

这个分支揭示了一个重要设计点：动作监督主要通过输入序列和 labels 注入，初始训练不要求模型对象先变成 OpenVLA。 OpenVLA 是 PrismaticVLM 的轻量包装，额外承担动作解码、反归一化和便捷推理接口。

train() 随后的固定顺序是：设置设备与随机种子、保存配置、加载模型、冻结参数、装配数据、保存数据统计量、构造训练策略、初始化指标、进入 run_vla_training()。页面排查训练问题时应先判断故障发生在哪个阶段，而不是只搜索 OpenVLA 类。

这里的“继续训练”不是完整状态恢复。固定实现的 FSDP checkpoint 只保存 model state dict；resume_step 与 resume_epoch 用于校验 checkpoint 文件名和延续记账，但优化器、学习率调度器、随机数状态及数据迭代位置都会重新初始化。因此它适合“从模型权重续训”，不能保证与一次不中断的训练逐步等价。

四个层次不要混为一谈

层次 核心文件 负责的事情
数据集声明 rlds/oxe/configs.py、transforms.py 原始字段、相机角色、动作语义与数据集专属标准化

PyTorch 适配 datasets.py、util/data_utils.py NumPy 记录转训练样本，再组成右填充 batch

RLDSDataset 是 IterableDataset：__iter__() 遍历 tf.data.Dataset.as_numpy_iterator()，__getitem__() 明确抛出异常。训练循环因此设置 DataLoader(num_workers=0)，把并行读取交给 RLDS 管线。底层数据会 repeat，所以 VLA 主循环不再套一个普通的 epoch 外层循环。

RLDSBatchTransform.__call__() 每次完成：

  1. 读取当前 step 的主视角图像、动作和语言指令；
  2. 将指令小写化并构造问答提示词；
  3. 把动作编码为 token 字符串；
  4. tokenize 整个序列；
  5. 按动作维数保留末尾动作 token 与 EOS 的 labels，将此前位置写成 IGNORE_INDEX；若关闭 predict_stop_token，再屏蔽 EOS；
  6. 返回 pixel_values、input_ids、labels 和 dataset_name。

右填充、视觉 token 与指标切片是一组契约

collator 明确断言 padding_side == "right"，并分别用 pad_token_id 与 IGNORE_INDEX 填充输入和标签。模型随后在第一个文本 token 后插入 \(P\) 个视觉 patch token：

\[[\mathrm{BOS},T_1,\ldots,T_L] \longrightarrow [\mathrm{BOS},V_1,\ldots,V_P,T_1,\ldots,T_L].\]

训练指标据此使用：

action_preds = output.logits[:, P:-1].argmax(dim=2)
action_gt    = labels[:, 1:]

P 个视觉位置补偿了插入偏移，-1 与 labels[:, 1:] 则对应因果语言模型的一步移位。BOS 来自 tokenizer 与 prompt，而不是右填充本身；右填充的作用是让 BOS 保持在每个 batch 样本的索引 0。若直接改成左填充，BOS 会被移到填充区之后，而模型仍在索引 1 插入视觉 token，于是破坏“在 BOS 后插图”的契约。

collator 在填充后按 model_max_length 从右侧截断。动作 token 位于序列尾部，因此自定义长提示词时必须确认截断没有删除动作监督，而不能只检查 batch 是否成功生成。

指标代码还有一个边界：它先在完整语言词表上做 argmax，再只按 ground-truth 动作位置取预测。代码没有把 logits 硬限制到动作 token 区间；若预测出普通文本 token，decode_token_ids_to_actions() 会把其反量化索引裁到端点。因而训练监控除 token accuracy 和解码后 L1 外，还应记录“预测 token 落在合法动作区间的比例”，否则端点裁剪可能掩盖非法类别。

DummyDataset 的准确定位

DummyDataset 用随机图像、随机动作和固定指令跑通接口，不是真实训练数据源。它没有暴露 predict_stop_token 开关；默认配置下，Dummy 与 RLDS 路径都监督动作 token 和停止 token。只有真实路径关闭停止 token 监督时，两者的标签掩码才不同。

五、配置与工厂函数：同名模块，不是同名函数

仓库有多个 materialize.py，但它们导出的工厂函数不同。

模块 主要工厂函数 输出
prismatic/models/materialize.py get_vision_backbone_and_transform()、get_llm_backbone_and_tokenizer() 视觉与语言主干
prismatic/vla/materialize.py get_vla_dataset_and_collator() 数据集、动作 tokenizer、collator
prismatic/vla/datasets/rlds/oxe/materialize.py get_oxe_dataset_kwargs_and_weights() 逐数据集 kwargs 与倍率
prismatic/training/materialize.py get_train_strategy() FSDP 或 DDP 训练策略

prismatic/conf/vla.py 使用 VLAConfig 与 VLARegistry 注册命名实验。固定版本中，正式双视觉 OXE 配置类是 Exp_DinoSigLIP_224px_OXE_Magic_Soup_Plus；类名保留 Plus，但 oxe_magic_soup_plus 那一行已被注释，实际生效的 data_mix 是 oxe_magic_soup_plus_minus。这只描述该配置启动时使用的后段配方，不能据此复原发布模型此前的第一阶段训练。阅读配置时必须查看字段值，不能只根据类名推断完整训练历史。

同一文件 L144–L194 共定义 6 个微调配置：5 个 TDROID 变体和 1 个 DROID Wipe 配置。expected_world_size、global_batch_size 与 per_device_batch_size 是训练规模约束，不是模型结构参数。

新增训练配置时需要同时检查：

  • vla_id 是否唯一；
  • 基座 VLM、冻结策略与训练策略是否匹配；
  • 数据混合名是否已经注册；
  • world size 与启动命令是否一致；
  • batch、梯度累积能力和停止条件是否受对应训练循环支持。

六、模型装配与多模态前向

原生训练版的类关系

PrismaticVLM 位于 prismatic/models/vlms/prismatic.py，负责视觉主干、projector、语言主干以及多模态 forward()。它没有继承 Transformers 的 PreTrainedModel，但基类提供 GenerationMixin 所需能力，因此其 forward() 和 prepare_inputs_for_generation() 必须遵守因果语言模型接口。

OpenVLA 位于 prismatic/models/vlas/openvla.py，继承 PrismaticVLM，额外保存：

  • norm_stats；
  • ActionTokenizer；
  • predict_action()；
  • unnorm_key 检查和动作维数查询。

多模态前向的真实顺序

pixel_values
  → vision_backbone
  → patch_features
  → projector
  → projected_patch_embeddings

input_ids
  → LLM token embeddings
  → 在 BOS 后插入 projected_patch_embeddings
  → 同步扩展 attention_mask 与 labels
  → language model

视觉 patch 对应的 labels 被置为 IGNORE_INDEX，因此它们参与上下文建模，但不作为语言模型监督目标。训练阶段真正产生损失的是未屏蔽的动作 token，以及配置允许时的停止 token。

FSDP 包装策略的边界

PrismaticVLM.get_fsdp_wrapping_policy() 合并三类策略：视觉主干策略、语言主干策略、projector 模块策略。LinearProjector、MLPProjector 和 FusedMLPProjector 会被显式识别；未命中的模块并非“不参与 FSDP”，而是折叠进根 VLM 的 FSDP 实例。

FSDPStrategy.run_setup() 随后负责混合精度策略、FSDP 包装、非重入激活检查点、优化器和学习率调度器。模型定义与分布式策略分离，使同一个 PrismaticVLM.forward() 可以在不同训练策略下复用。

七、动作 token 与 predict_action 两条推理路径

ActionTokenizer 的源码边界

prismatic/vla/action_tokenizer.py 只有一个核心类，但有一个容易忽略的计数差异：默认 n_bins=256 时，np.linspace 产生 256 个边界值，而相邻边界的中心只有 255 个。编码使用 np.digitize，解码时减一并裁剪到有效中心索引。完整数学解释见动作 token 化与量化误差。

两版 predict_action 的共同主干

flowchart LR
  A["提示词、input_ids 与 pixel_values"]
  B["必要时补 token 29871"]
  C["generate()<br/>最多生成 action_dim 个新 token"]
  D["截取末尾动作 token id"]
  E["反量化为归一化动作"]
  F["按 unnorm_key 读取 q01/q99 与 mask"]
  G["反归一化为机器人动作"]
  A --> B --> C --> D --> E --> F --> G
对照项 原生训练版 OpenVLA.predict_action() HF 版 OpenVLAForActionPrediction.predict_action()
面向的调用者 直接持有 PIL 图像和指令字符串的代码 Transformers processor 的调用路径
显式输入 image、instruction、unnorm_key input_ids、unnorm_key
其他模型输入 函数内部生成 pixel_values、attention_mask 等通过 **kwargs 转发
提示词与小写化 函数内部构造并调用 .lower() 调用方负责，processor 本身不会替调用者决定提示文本
图像预处理 内部调用 image_transform 调用方通常先调用 AutoProcessor
精度管理 根据模型配置在函数内部进入 autocast 由模型加载 dtype、输入 dtype 和调用上下文决定
生成调用 绕过 PrismaticVLM.generate()，进入 GenerationMixin 调用 self.generate()
反量化 调 ActionTokenizer.decode_token_ids_to_actions() 使用类内的 bin_centers 就地计算
原始词表大小 tokenizer.vocab_size text_config.vocab_size - pad_to_multiple_of
反归一化 q01/q99 加 mask 同一公式与分支结构

HF 版的函数签名虽然只显式列出 input_ids，但正常调用必须把 processor 产生的完整输入传给它；只传 input_ids 不足以完成视觉条件推理。

两套实现的目标相同，但不能无条件宣称输出相同。只有权重、图像处理、提示词、小写化、tokenizer、dtype、注意力实现、生成参数和 norm_stats 全部匹配时，才应比较其数值结果。

更重要的是，两版代码把 max_new_tokens=D 当作上限，随后都直接截取序列末尾 D 个 id；它们没有断言实际新生成长度等于 D，也没有对每一步施加动作词表硬掩码。若 EOS 提前终止，末尾切片可能混入 prompt token；若生成普通文本 token，反量化又会把索引裁到首尾中心。稳健部署应同时验证：new_token_count == D、每个 id 属于合法动作 token 集合，并把早停或非法 id 视为失败，而不是继续下发动作。

八、HF 发布实现、权重转换与验证边界

组件 原生训练版 Hugging Face 发布版
主模型 models/vlms/prismatic.py extern/hf/modeling_prismatic.py
VLA 包装 models/vlas/openvla.py OpenVLAForActionPrediction
配置 conf/models.py、conf/vla.py configuration_prismatic.py
图像与文本处理 主干各自的 transform/tokenizer processing_prismatic.py
主要用途 原生 FSDP 训练与 checkpoint 恢复 AutoClass 加载、推理与 HF 风格微调

convert_openvla_weights_to_hf.py 的关键工作是：创建 HF 配置与 processor、重映射视觉/projector/语言模型参数名、用 strict=True, assign=True 装载 state dict、转换为 BF16 并保存。严格装载能发现缺键、多键和形状不匹配，但不能证明两套前向逻辑逐元素相同；BF16 转换本身也会引入相对于高精度权重的舍入。

转换入口还有一个容易漏掉的文件名契约：本地转换分支固定读取 checkpoints/latest-checkpoint.pt，而 FSDP 保存的实际文件名是带 step、epoch 与 loss 的 .pt；把最新文件复制为 latest-checkpoint.pt 的两行代码在固定版本中被注释。新训练目录不能直接假定转换脚本可用，必须先明确选择某个 step checkpoint，再手工复制/建立链接或修改转换参数，并记录所选文件的校验值。

verify_openvla.py 只加载 HF 模型，并对随机图像重复调用 predict_action()、打印耗时和动作。它是加载与推理烟雾测试，不是原生版和 HF 版的数值对照测试。

如果要验证实现等价性，至少应依次比较：

  1. processor 与原生 image transform 的输出；
  2. 提示词和 input_ids；
  3. 视觉特征与 projector 输出；
  4. 首个生成位置的 logits；
  5. 贪心生成的动作 token；
  6. 反量化后的归一化动作；
  7. 使用相同 unnorm_key 后的最终动作。

可以把证据强度写成：

state-dict 严格装载
    ≠ forward 数值相等
    ≠ 自回归 token 必然相同
    ≠ 反归一化后的动作必然相同

九、训练、微调、部署与扩展入口

两条训练路径

路径 入口 主要实现 适用场景
原生大规模训练/模型权重续训 vla-scripts/train.py Prismatic + FSDP 策略 OXE 预训练、从原生模型 state dict 继续训练
HF 风格微调 vla-scripts/finetune.py AutoClass、PEFT/LoRA 或全量微调 新任务、新本体和较轻量实验

两条路径使用不同模型包装、配置入口和保存格式，不能把 finetune.py 的参数直接套到 train.py。HF 微调把新数据的统计量另存为 dataset_statistics.json，但保存模型时不会自动把它写回 vla.config.norm_stats；模型初始化又默认从 config 读取 norm_stats。所以权重、processor 与该 JSON 必须成套保存，或者在保存前显式同步 model.norm_stats 和 model.config.norm_stats。加载后还要核对目标 unnorm_key，不能默认权重目录里的统计量一定匹配。具体 batch、step、FSDP 和指标口径见训练目标、优化与并行。

部署与评测

  • vla-scripts/deploy.py：提供远程推理服务，最终调用 HF 模型的 predict_action()；只有 openvla_path 是本地目录时，它才从旁路 dataset_statistics.json 覆盖 vla.norm_stats；
  • experiments/robot/openvla_utils.py：模型加载与推理封装；
  • experiments/robot/bridge/：WidowX/BridgeData V2 评测；
  • experiments/robot/libero/：LIBERO 仿真评测和数据再生成工具。

部署时必须把 processor、提示词模板、dtype、生成参数和 unnorm_key 看作一个整体接口。输出张量形状正确，不代表动作坐标、单位和尺度正确。具体接入要求见微调与部署。

复现前检查

  • 固定 Git commit、HF model revision 和依赖版本；
  • 注意固定实现会检查/警告 transformers==4.40.1、tokenizers==0.19.1，并只接受 timm 0.9.10/0.9.11/0.9.12/0.9.16；
  • 先判断使用的是 load() 还是 load_vla() 分支；
  • 若从 checkpoint 续训，记录优化器、调度器、RNG 与数据位置没有恢复这一事实；
  • 保存并核对数据集统计量，不能只保存模型权重；
  • 确认 prompt、大小写、空 token 29871 和 tokenizer 版本；
  • 确认图像 processor、resize 策略和视觉主干相匹配；
  • 确认模型参数 dtype、输入 dtype、autocast 与注意力实现；
  • 显式设置生成参数，不把库版本默认值当成实验配置；
  • 检查实际新生成长度和动作 token 合法率，拒绝早停或越界类别；
  • 推理时使用正确的 unnorm_key，并核对动作坐标与夹爪语义；
  • 若转换格式，至少执行一次逐层数值对照，不能只依赖 smoke test。
