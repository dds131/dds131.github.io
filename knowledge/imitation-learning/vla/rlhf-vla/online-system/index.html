在线 RLHF-VLA 的核心不是频繁更新，而是每次更新都有证据链

在线采集、在线反馈与 on-policy 更新是三件不同的事。系统应让每个 episode、训练 run、候选模型、评估结论和部署决策通过不可变 ID 相互关联，并把“可回滚的软件版本”与“不可逆的物理后果”严格区分。

一、先定义“在线”与模型角色

1.1 三种“在线”

  • 在线采集：策略在当前环境中产生新 trajectory。
  • 在线反馈：人类或 evaluator 在采集过程中或之后持续给标签。
  • on-policy 更新：优化器使用由指定行为策略刚产生、满足新鲜度要求的数据。

一个系统可以持续收集介入数据，却每天离线做一次 KTO；也可以在线标注，但仍用固定数据训练 RM。只有第三项决定 PPO 的 on-policy 条件，不能用“有数据飞轮”替代。

1.2 六个容易混淆的角色

角色 含义 生命周期要求
Champion 当前批准执行任务的 last-known-good 未经门禁不得覆盖
Candidate 待评估、尚未晋级的模型 与训练 run、数据 cutoff 一一关联
Behavior $\pi_b$ 实际生成某条日志 action 的策略 episode 内不可含糊；必须记录版本与 log-prob 条件
Current $\pi_\theta$ 正在更新的参数 每个 optimizer step 可变化
Old $\pi_{old}$ PPO rollout 的冻结快照 一批 PPO epoch 内固定
Reference $\pi_{ref}$ KL/DPO/KTO 的冻结行为锚点 刷新策略必须显式版本化

这些角色可以暂时指向同一 checkpoint，但语义不同。例如一次 PPO rollout 开始时 Behavior 与 Old 通常相同，Current 随更新分离；Reference 不应随 minibatch 同步更新。

二、闭环全景

flowchart LR
  C[Champion 受限采集] --> F[人类介入 · 偏好 · 结果]
  F --> D[不可变 episode store]
  D --> V[版本化训练 views]
  V --> T[BC · RM · DPO/KTO/APO · PPO]
  T --> P[Candidate]
  P --> E[独立回放 · 仿真 · Shadow]
  E --> G{统计 + 安全门禁}
  G -->|通过| R[灰度真机]
  G -->|拒绝| A[诊断与新数据]
  R -->|晋级| C
  R -->|越界| B[停止分配 + 软件回滚]
  A --> D

训练标签生成器与 release gate evaluator 应尽量独立。若同一个 VLM 既产生训练偏好又决定是否晋级，Candidate 可能只学会利用它的盲点，形成循环自证。

三、不可变事件与版本谱系

每个 episode 至少绑定：

  • episode_id、task_id、场景与机器人 ID。
  • requested、loaded、behavior、reference、reward model、label evaluator 和 gate evaluator 的不可变版本。
  • 数据预处理、动作归一化和安全配置版本。
  • 观测、sampled latent、policy/commanded action、safety-filtered/executed action 与时间戳。
  • behavior log-prob、有效 token/chunk mask，以及计算它们所需的 tokenizer/action head 版本。
  • 人工介入区间、原因、纠正动作和恢复结果。
  • 标注规则、标注者匿名 ID、置信度与审核状态。
  • 仿真 seed、终止/截断/安全中止语义，以及传感器缺失/丢帧标记。

版本号不能只写 latest。episode 是不可变事实记录；修正标签应追加新 annotation revision，而不是覆盖原事件。训练 run manifest 通过内容哈希关联 data view、split、代码、配置、依赖、模型和评估报告，不要求所有 artifact 共用一个 ID。

还要分开 event_time、ingest_time、label_time、train_cutoff 与 deploy_time。日志脱敏规则属于 schema：原始图像、自然语言批注和操作者标识在进入长期存储前就应经过访问控制与审计。

四、四种人类信号不能混成一个 label

4.1 成对偏好

人类比较同条件的两段轨迹，适合 RM、DPO 或 TPO。优点是能表达相对质量，缺点是无法实时阻止危险，且配对条件必须保存。

4.2 单样本 desirability

对一次行为给接受/拒绝标签，适合 KTO；APO 论文则从介入时序构造动作 desirability。它不等同于 chosen/rejected pair。

4.3 在线介入与纠正

操作者在策略即将失败或不安全时接管。介入事件可作为风险代理，接管后的动作可作为 corrective demonstration。DAgger 聚合专家标签；RLIF 把介入信号作为 reward 用于 off-policy RL。它们与 RLHF 有交集，但不是 pairwise preference 的同义词。

4.4 标量与自然语言反馈

评分、标签、原因码或文字批注能提供更丰富监督，但不同标注者尺度不同，需要规范、校准和结构化解析。

五、Human-in-the-loop 时延与归因窗口

机器人高速控制与人类反应速度不匹配。系统应分别记录

\[t_{observe},\;t_{decision},\;t_{input},\;t_{execute}\]

并按操作者、设备和任务估计延迟 $\hat d$ 与不确定半宽 $\Delta$。候选风险窗口可记为

\[W_{risk}= [t_{input}-\hat d-\Delta,\;t_{input}-\hat d+\Delta].\]

它只是待审核区间，不代表其中每一步都是确定负例。数据应保存窗口权重、人工复核状态和“介入是否因外部事件触发”，避免把反应延迟变成系统性错误标签。

六、不可变存储、数据视图与 split

同一 episode 可同时满足多种用途。更稳健的结构是“不可变 episode store + 可重算 materialized views”，而不是把副本搬入多个目录后分别修改：

视图 成员条件 主要用途
Golden 人工审核高质量演示 BC、回归门禁
Preference chosen/rejected 或 desirability RM、DPO/KTO/APO
Intervention 接管前后与 corrective action BC、RLIF、风险建模
Failure 碰撞、超时、不可恢复状态 诊断、负例、仿真复现
Frontier 高不确定、新任务、新场景 主动学习与覆盖扩张
Replay audit 固定历史基准 防遗忘和版本对比

先按 episode、场景、seed、时间和机器人分组切分，再生成 pair、介入窗口或 chunk。若先扩增再随机 split，同一轨迹的相邻帧很容易同时进入训练集与门禁集。

采样既要考虑失败信息量，也要维持正常行为分布。Frontier/主动学习 view 负责找高价值样本，但不能替代随机覆盖样本和固定 golden audit；只训练困难案例会制造新的分布偏移和遗忘。

七、数据新鲜度决定算法能否使用

更新方法 可否复用历史数据 必须保存 主要边界
BC/SFT 可以 target、mask、数据来源 覆盖偏差与遗忘
RM/DPO/KTO 可以 条件、标签、Reference/labeler 版本 离线分布与当前部署分布可能错位
APO 可跨轮累积，但每轮要记录部署策略 介入标签、窗口、Reference、balanced view desirability 噪声与版本混合
PPO 原则上使用本轮 Behavior/Old 数据 behavior log-prob、policy version、advantage target 无修正混入旧数据会破坏 on-policy ratio
Off-policy RL / RLIF 可以使用 replay behavior action、终止语义、reward/介入定义 extrapolation 与 reward 非平稳性

对行为策略 $\pi_b$ 采出的动作，重要性比为

\[\rho_t(\theta)= \frac{\pi_\theta(a_t\mid h_t)}{\pi_b(a_t\mid h_t)} =\exp(\log\pi_\theta-\log\pi_b).\]

它要求两者对同一 action 变量有共同支持。若保存的是 commanded-action log-prob，却把 safety-filtered executed action 代入，ratio 没有定义上的对应。PPO clipping 只限制 surrogate，不能把任意陈旧数据自动变成无偏 on-policy 数据；系统应设置最大 sample_age、版本白名单和 KL/ratio early stop。

八、训练作业编排

一套可复现作业应固定：

  1. 数据 manifest 与 split 规则。
  2. 基座、Behavior/Old、Reference、RM 和 teacher/evaluator checkpoint。
  3. 算法配置、随机种子、依赖与硬件摘要。
  4. 训练日志、梯度/奖励/动作统计。
  5. 输出 checkpoint、评估报告和模型卡。

每个 policy update 应绑定冻结的 RM、Reference、label schema 和 evaluator snapshot。新 RM 先在固定 holdout 上比较排序、校准和 slice error，再以冻结候选做策略级评估；若 RM 与策略同时快速变化，奖励非平稳且历史指标不可比较。

release gate 不应只复用训练 evaluator。至少保留隐藏 golden set、独立规则/传感器安全指标和人工抽检；测试集被用于调阈值后，应产生新版本而不能继续称为未见评估。

九、评估金字塔与 Shadow 边界

L0 · 静态检查
schema、单位、mask、哈希、依赖与敏感信息。
L1 · 离线回放
动作误差、偏好排序、OOD 与回归集。
L2 · 仿真闭环
成功、安全、扰动与长时程恢复。
L3 · Shadow
真实观测上推理但不执行；检查延迟、稳定性、OOD 与动作分歧。
L4 · 受限真机
低速度、小工作区、人工监督和即时回滚。
L5 · 灰度扩大
逐任务、逐场景、逐机器人提升覆盖。

Shadow 中 Candidate 的动作没有改变后续状态，因此它不能直接估计 Candidate 的闭环成功率、恢复能力或其诱导状态分布。任何层级失败都返回数据/诊断环节，而不是通过调低门槛强行晋级。

十、安全门禁需要暴露量和置信界

门禁至少包含硬阈值与相对回归：

  • 零容忍事件：严重碰撞、越界、急停失效。
  • 成本上限：接管率、力矩峰值、workspace violation。
  • 性能下限：成功率与 last-known-good 的置信区间比较。
  • 分布检查：新策略动作饱和、抖动、延迟与 OOD 比例。
  • 人工 sign-off：高风险任务必须有人审核。
不要只用平均成功率：平均值可能掩盖某个物体、相机或机器人上的严重退化。门禁应按关键分层分别计算。

10.1 “零事故”不等于风险为零

在 $n$ 次独立同分布 Bernoulli 暴露中观察到 0 次事故时，置信度 $1-\alpha$ 的单侧精确上界是

\[p_{upper}=1-\alpha^{1/n} \approx\frac{-\log\alpha}{n}.\]

例如 100 次零事故时，95% 上界仍约为 2.95%。真实 episode 常有关联和分布差异，所以还应按关键场景分层并保守处理；这个计算用于反驳“零事件＝零风险”，不是安全认证。

10.2 Candidate 相对 Champion 的非劣检验

预先指定可接受退化 $\delta$，成功率要求可写为

\[p_{candidate}-p_{champion}\ge-\delta,\]

并要求差值的单侧置信下界也高于 $-\delta$。安全成本通常反向要求上置信界不超过预算。尽量对相同任务、初态和 seed 做配对比较；预注册样本量、阈值和停止规则，避免反复查看结果后临时改门槛。

十一、部署、灰度与回滚

部署包应同时携带模型、归一化统计、tokenizer、动作解码器和安全配置。策略服务需记录 requested_version 与 loaded_version，避免控制器以为升级成功而实际仍运行旧模型。

回滚条件应预先定义并自动化：异常率、接管率或延迟越界时停止新任务分配，切回已验证软件版本，同时冻结相关 episode 供复盘。回滚不能撤销已经发生的碰撞、物体状态改变或敏感数据暴露；真机仍依赖 watchdog、急停、动作/工作空间限制和事故响应流程。

十二、可观测性面板

系统级指标包括：event→ingest→label→train→deploy 各段 freshness、标注 backlog、训练吞吐、评估覆盖、版本一致性和缺失率；模型级指标包括 success、preference、KL、reward、ratio 与 action statistics；安全级指标包括 intervention、collision、force/torque、near-miss。

每个 rate 必须同时报告 numerator、denominator、有效覆盖和置信区间，并能按 task、scene、robot、policy version 与时间切片；只有百分比而没有暴露量无法支持门禁决策。

十三、知识点、重点与创新点

13.1 知识点

  • 在线采集、在线反馈、on-policy 更新三种语义。
  • policy 角色、不可变 episode、artifact lineage、数据 views 与 split。
  • 介入延迟、样本新鲜度、importance ratio 和算法选数边界。
  • 独立评估、统计门禁、灰度、last-known-good 与回滚。

13.2 重点

  • policy/commanded/executed action 与生成它们的版本必须分开记录。
  • PPO 的 Behavior 新鲜度与 log-prob 是数学前提；历史数据可用不等于所有算法都可直接使用。
  • training evaluator、release gate 和 shadow 各有不同证据能力，不能循环自证。
  • 零事故、平均成功率和软件可回滚都不是安全证明。

13.3 创新点

  • 将 diverse human feedback、版本谱系、算法资格与部署证据连接成可审计数据飞轮。
  • 用 Frontier/active query 提高标注信息密度，同时保留正常分布和固定审计集。
  • 用多层独立门禁、暴露量和置信界管理真机风险；这是工程控制，不是未知风险归零的保证。
