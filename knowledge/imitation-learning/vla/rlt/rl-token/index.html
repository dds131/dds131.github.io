VLA/后训练与对齐/RLT/RL Token

本页只拆解 Stage 1 的表征接口：从指定 VLA 的 final-layer token sequence 学出一个 z_rl，再把冻结后的 VLA 与 encoder 打包交给 Stage 2。z_rl 不是 action token、reward token、语言 token 或完整状态保证；decoder 只提供训练压力，不进入 Stage 2 feature path。

flowchart LR
  O["o_k 与指令 ℓ"] --> V["指定 VLA revision"]
  V --> T["final-layer z_1:M"]
  E["learned e_rl"] --> G["encoder g_φ"]
  T --> G
  G --> Z["readout z_rl"]
  Z --> D["Stage 1 decoder + projection"]
  T -. "stopped targets" .-> D
  Z --> F["freeze-and-package gate"]
  F --> AC["Stage 2 actor / critic"]
核对 token 来源审计梯度边界检查 feature bundle返回 RLT 总览

VLA token 来源与输入合同

在 chunk 决策时刻 k，本站将 Foundations 的物理时间采样记为 o_k := o_{t_k}，并采用论文一般式：

\[z_{k,1:M}=f(o_k,\ell;\theta_{\mathrm{vla}}).\]

z_{k,1:M} 必须来自一个已固定 revision 的 VLA，并在论文口径下指 final-layer token sequence；若具体实现读取其他层，记录为 implementation-divergence，不能继续冒充论文原式。一般方法表述使用全部 VLA final-layer embeddings；论文实验因每个任务采用固定语言指令而可省略 language embeddings。这是实验简化，不表示表征天然与语言无关。image、action、state、prefix、special、padding 或 masked token 是否进入 encoder 和重建 denominator，都必须由实现 manifest 固定，不能从某个第三方 hook 反推论文实际子集。

VLATokenSourceManifest:
  vla_checkpoint_id: required
  vla_checkpoint_hash: required
  architecture_revision: required
  processor_revision: required
  token_source_layer: final-layer | implementation-divergence
  token_selection: required
  token_order: required
  token_count_M: fixed-or-dynamic
  embedding_dim: fixed-or-unknown
  attention_mask_semantics: required
  padding_semantics: required
  dtype: required
  train_eval_mode: required
  instruction_mode: fixed-per-task | variable
  observation_contract_revision: required

Stage 1/2 的 checkpoint 或 processor 不同、相机数量/顺序/crop 改变、instruction template 或 tokenization 漂移、token layer/order/mask 变化、dtype/precision/normalization 未生成新 revision，都会改变 feature space。若 M 可随输入变化，不能把一次观测值硬编码成全局常量。

<rl> embedding 与 encoder readout

这里有三个不同对象：learned input embedding e_rl=e_φ(<rl>) 是 Stage 1 可训练参数；encoder transformer g_φ 读取 VLA token sequence 和追加在末尾的 e_rl；特殊位置输出

\[z_{\mathrm{rl}}=g_\phi([z_{1:M},e_{\mathrm{rl}}])_{M+1}\]

才是每次 observation 重新计算的 RL Token。Stage 2 冻结 e_rl 与 encoder，但仍为每个新 observation 计算新 z_rl。

非等价关系 原因
e_rl ≠ z_rl 前者是共享参数，后者依赖当前 token sequence
z_rl ≠ mean-pooling(z) 论文使用 additional transformer readout
z_rl ≠ VLA vocabulary token <rl> 属于新增表征模块，不是 VLA 词表项
z_rl ≠ action token 它不直接解码为机器人动作
z_rl ≠ reward token reward 标量和定义不在此向量中
z_rl ≠ complete state guarantee 重建目标只建立紧凑接口，不证明 Markov sufficiency

embedding_dim、encoder depth、head count 和 parameter count 必须来自论文明确字段或固定实现 revision；没有证据时写 unknown。示意图宽度不表示维度比例。

schema: rlt.rl-token-architecture.v1
inputs: {vla_tokens: z_1_to_M, learned_embedding: e_rl}
encoder: {symbol: g_phi, readout_position: M_plus_1, output: z_rl}
decoder: {symbol: d_phi, conditioning: [z_rl, stopped_target_prefix]}
projection: {symbol: h_phi, output_space: vla_embedding_space}
stage2: {encoder_required: true, decoder_required: false, projection_required: false}

为什么用 embedding reconstruction

只追加特殊 embedding 并不会让它自动聚合信息。RLT 让 z_rl 支持重建 VLA internal embeddings，以 learned bottleneck 为 downstream actor/critic 提供比整段 token sequence 更紧凑的接口。目标空间已经过 VLA pretraining 或 task adaptation；相较 raw pixels，它不要求小模块重新学习所有低层视觉细节，并且无需用 online reward 直接更新大 VLA。

目标 target / 信号 能直接说明什么
pixel reconstruction raw image / perception detail 不属于 RLT 原式
embedding reconstruction stopped VLA tokens 只约束 VLA internal structure 的可预测性
value / TD loss return bootstrap Stage 2 的任务价值目标
action SFT demonstrated actions 可选 L_vla 的 imitation 路由

重建目标不证明所有被保存的信息都与控制相关，也不保证低方差但关键的控制信息被保留。未输入的接触力、遮挡对象和历史不会凭空出现；z_rl 不能据此推广到任意新任务、语言或机器人，最低 MSE checkpoint 也不必有最佳 downstream return。bottleneck 仍可能 shortcut 或 collapse，这些都要靠独立诊断和 Stage 2 证据回答。

自回归 decoder、teacher forcing 与 Loss

论文目标可写成：

\[\bar z_i=\operatorname{sg}(z_i),\qquad \mathcal L_{\mathrm{ro}}= \mathbb E_{\mathcal D}\left[ \sum_i\left\| h_\phi\!\left(d_\phi([z_{\mathrm{rl}},\bar z_{1:i-1}])\right)_i-\bar z_i \right\|_2^2\right].\]

其中 D 是 task-specific demonstrations，必须固定 dataset revision、split 与 sampling；bar(z_i) 是 stopped target；bar(z_1:i-1) 是 teacher-forced target prefix，必须核对 causal shift、mask 和 padding；d_φ(...)_i 是 decoder 的位置 i 输出；h_φ 将其投影回 VLA embedding space；squared norm 是逐 token embedding error。论文式对位置求和，若实现改为 mean，必须登记为 implementation-divergence/normalization。

decoder 在预测 i 时已看见真实 stopped prefix，所以 reconstruction 是 z_rl 与 prefix 的共同结果。L_ro 迫使 z_rl 提供有助于全序列重建的条件，但 prefix 可能承担大量局部可预测信息；低 loss 不能证明仅凭 z_rl 可无损重建整段 token sequence。

本站工程诊断至少包括：置零或随机置换 z_rl、截短或扰动 prefix、held-out demonstrations 的 per-position loss、按 token type/layer 分解、prefix-only baseline，以及 encoder output 的 norm/variance/covariance。这些是工程建议，不是论文公开实验结果。报告还必须固定 valid-token、padding 与 token-type mask，逐维/逐 token/逐 batch reduction 和 denominator。

schema: rlt.reconstruction-objective.v1
dataset_revision: required
split: train | validation | test
target: stopped_vla_embedding
teacher_forcing_prefix: true
metric: squared_l2
token_mask_revision: required
reduction:
  token: sum | mean | implementation-defined
  dimension: sum | mean | implementation-defined
  batch: mean | implementation-defined
parameter_routes: {representation_phi: update, vla_theta_from_l_ro: no-update}

Stop-gradient 与冻结是两条边界

第一条边界是 bar(z_i)=sg(z_i)：target branch 不接收 gradient，防止通过移动 target 降低误差。第二条是 VLA 对 L_ro considered frozen：即便 encoder input 来自 VLA tokens，reconstruction 也不能更新 θ_vla。只做 target sg 不能阻断 input path；只从 optimizer 排除 VLA 也不说明没有 gradient allocation、train-mode stochasticity 或 preprocessing 漂移。

对象 L_ro L_vla Stage 1 Stage 2
θ_vla 禁止 update；input detach 需登记 α>0 时允许 条件可变 冻结
e_rl、g_φ update 不更新 可变 冻结
d_φ、h_φ update 不更新 可变 不部署/不训练
processor/normalizer 无 gradient 无 gradient revision 必须固定 不可漂移
RNG/dropout/cache 非 parameter state 非 parameter state mode-dependent 固定 eval contract

冻结证明必须同时保留 requires_grad inventory、optimizer parameter IDs、backward 后 gradient presence、optimizer step 前后 parameter hash、train/eval mode、dropout/RNG/BatchNorm/cache 行为、checkpoint write set，以及 processor/normalizer revision。model.eval() 不等于参数被冻结；parameter hash 未变也不证明 preprocessing 未变。

schema: rlt.gradient-boundary.v1
objectives:
  l_ro:
    updates: [e_rl, encoder, decoder, projection]
    excludes: [vla_parameters]
    target_stop_gradient: true
  alpha_l_vla:
    enabled: declared
    updates: [declared_vla_parameter_groups]
    excludes: [representation_phi]
evidence:
  requires_grad_inventory: required
  optimizer_parameter_ids: required
  gradient_presence: required
  pre_post_hash: required

联合 SFT 与 α 的参数路由

Stage 1 的总目标是参数路由图，不是“两个 loss 更新所有参数”：

\[\mathcal L_{\mathrm{stage1}}(\phi,\theta_{\mathrm{vla}}) =\mathcal L_{\mathrm{ro}}(\phi)+\alpha\mathcal L_{\mathrm{vla}}(\theta_{\mathrm{vla}}).\]

当 α=0，既有 VLA 不由 Stage 1 objective 更新，L_ro 只训练 representation group；当 α>0，VLA 只由 αL_vla 的 declared parameter groups 更新，representation group 仍由 L_ro 更新。若实现让 L_vla 更新 encoder，或让 L_ro 更新 VLA，必须标作 implementation divergence。

α 是 VLA SFT objective 权重，不是 RL discount、BC coefficient 或 target-network update rate。复现记录应包含其值与 schedule、VLA parameter groups、各组 learning rate、gradient accumulation、checkpoint selection metric 和关闭条件；本页不给推荐数值。论文 protocol 报告每项任务约 1–10 小时 teleoperation demonstrations、2,000–10,000 gradient steps；它受任务、机器人、data quality、batch size、optimizer 和选模方式影响，不是最低数据或训练步保证。

flowchart TD
  LRO["L_ro"] --> R["e_rl + encoder + decoder + projection"]
  LRO -. "no VLA update" .-> V["θ_vla"]
  LV["α L_vla · optional"] --> V
  R --> P["freeze-and-package gate"]
  V --> P

四种训练/推理状态

状态 VLA Encoder Decoder / projection Actor / critic
S1_INTERFACE_ONLY frozen params train train absent
S1_JOINT_SFT train via L_vla train via L_ro train via L_ro absent
S2_ONLINE_RL frozen/eval contract frozen/eval contract not in forward train
EVAL_DEPLOY frozen/eval frozen/eval omitted actor forward；critic 仅可选诊断

合法生命周期是 raw VLA + Stage1 data → S1_INTERFACE_ONLY 或 S1_JOINT_SFT → freeze-and-package gate → S2_ONLINE_RL → evaluation/release gate → EVAL_DEPLOY。Stage 2 不得读取可训练 encoder 或另一个 VLA checkpoint；deployment 不得依赖 decoder 才能计算 z_rl；joint SFT 后不能继续用旧 VLA hash 标注 Replay；只恢复 encoder、却不恢复 decoder/optimizer 的 resume 也不能声称与连续训练等价。

训练 artifact 与部署 bundle

training/resume bundle 必须保留 VLA、encoder、decoder、projection、optimizer/scaler、step、RNG、config 和 data manifest；audit/reproduction bundle 保留 selected checkpoint、decoder/projection、metrics、source revision、hash、split 和 gradient inventory；Stage 2 deployment feature bundle 只加载冻结的 VLA、encoder、processor、normalizer、instruction template 和 token source manifest。

“decoder 可以丢弃”只表示 runtime forward 排除 decoder/projection，不表示可删除唯一可复核的 decoder checkpoint、training config 或 reconstruction metrics。部署路径要验证 missing/unexpected keys、dtype/device、encoder/VLA dimension handshake、token order/mask、eval mode、content hash，以及固定 test vector 在数值容差内的输出；decoder 缺席不得影响 feature path。

  processor_normalizer: required
  token_source_manifest: required

feature_bundle_id 至少绑定 (vla_checkpoint_hash, rl_token_encoder_hash, processor_revision, normalization_revision, instruction_template_hash, token_source_manifest_hash)。任一项变化都建立新 feature space；旧 Replay token 或 cache 只能在同一 feature bundle 内使用，除非有明确迁移证明，不能静默混采。

显式 proprio 与 Stage 2 state

论文定义 Stage 2 输入为

\[x_k=(z^{\mathrm{rl}}_k,s^p_k).\]

显式 proprio 为 actor/critic 提供精确、低维的机器人状态，绕过表征瓶颈；这不证明 VLA tokens 完全没有编码 proprio，也不允许忽略 z_rl_k 与 s^p_k 的时间对齐。论文不同任务使用 joint position 或 end-effector pose，并在 appendix 概述 position/velocity 输入，不能从单个任务或第三方 config 推出通用 9 维或 19 维状态标准。

常见错位包括：两个输入时间戳不同步；position frame/units 与 action contract 不一致；quaternion/rotation representation 未固定；velocity filtering 引入未记录延迟；missing field 以零填充而无法与真实零区分；Stage 1/2 normalization stats 不一致。所有字段、顺序、frame、unit、shape 与缺失处理都必须随 feature bundle 固定。
