专题总览 2 VLM 与空间 Grounding 3 动作表示与生成目标 4 数据与跨本体

视觉—语言—动作（Vision-Language-Action，VLA）策略输出的不是抽象“动作”，而是带坐标系、单位、参考状态、时间与 consumer 的接口对象。同一动作块可以离散为 token、压缩为 FAST 序列、直接回归，或由条件变分自编码器、Diffusion、Flow Matching 采样；选择生成方法前，必须先写清 Action ABI 与闭环 scheduler。

  • 动作 shape 不等于动作语义。 缺少字段顺序、单位、坐标系、absolute/delta、reference 与时基时，输出不可进入控制链。
  • Normalization 和 quantile clipping 是数据变换，不是机器人安全限制。 反归一化后仍需独立的有限值、速度、加速度、可达性、碰撞与 supervisor 门禁。
  • 训练 loss 的名字不能识别生成方法。 连续回归、Diffusion 与 Flow Matching 都可能使用 MSE，但输入状态、监督 target 与推理动力系统不同。
  • Smoothness 不是 safety，EOS 不是 success。 平滑、停止、成功、超时、人工停止、故障和急停必须由不同信号与状态机处理。

本页给出模型无关的比较语言。ACT、OpenVLA、π0、SmolVLA、GR00T 等模型的维度、时间方向、token ID、采样步数与结果，只能由对应版本页和一手资料支持。页面不运行模型，不下载 checkpoint，不连接控制器，也不生成可执行机器人命令。

动作空间不是 shape：先冻结 Action ABI

Action ABI 是 producer 与 consumer 对动作字段、物理语义、时间和有效性的版本化约定。它的任务不是让张量“能传过去”，而是保证双方对每个数的含义、参考对象和失败行为达成同一解释。

三层对象：任务动作、策略表示、控制器 reference

flowchart LR
  T["Task intention<br/>grasp · move-to · open"] -->|"label / condition"| A["Physical Action ABI<br/>joint / Cartesian · frame · unit · time"]
  A -->|"encode training target"| R["Representation<br/>continuous · bins/tokens · FAST · latent/noisy/path state"]
  R -->|"objective + generator"| M["Model output"]
  M -->|"decode / inverse"| D["Adapter<br/>reference reconstruction · mapping"]
  D -->|"deterministic checks"| S["Limits / supervisor"]
  S -->|"validated reference"| C["Controller"]
  S -.->|"reject / hold / fallback"| F["Defined failure owner"]

图 1｜动作生成与执行的四层栈。 任务意图先落到物理 Action ABI；训练数据把 ABI 对象编码为连续值、token、频域系数或生成路径状态；模型输出必须逆变换回同一 ABI；adapter 再恢复 reference 并通过确定性检查后交给 controller。condition 从上一页进入生成器，mask 在 loss 与 execution 中责任不同，deterministic check 不属于生成模型。

同一个“向右移动”可以表示为 Cartesian delta、目标 pose、joint delta 或供更低层轨迹器消费的 waypoint。策略输出不是 hardware command；adapter 也不能静默改 frame、单位或时间语义。每层至少记录 producer、schema、rate、timestamp、validity、consumer 与 failure behavior。

层 典型对象 必须冻结 不得偷换
任务/技能 grasp、move-to、open-gripper 目标、对象、成功条件 低层关节命令
策略动作 token、joint vector、pose、twist、chunk 字段、frame、unit、relative、horizon controller 已接受
adapter 输出 合法化后的 reference 映射、rate、limits、timestamp safety guarantee
controller 命令 position/velocity/effort 等 实际接口、周期、状态机 策略原始输出

Joint 与 Cartesian 的最小分类

空间 示例字段 强制元数据 主要风险
joint position q_target 或 Δq joint order、rad/deg、absolute/reference 关节重排、限位、不可达
joint velocity qdot joint order、rad/s、duration 频率变化导致位移变化
joint effort tau joint order、N·m、gravity compensation 高风险，不能由页面给默认值
Cartesian position xyz frame、m/mm、reference base/tool/camera 混淆
Cartesian orientation quat/axis-angle/Euler/rot6d convention、order、frame、projection 不合法旋转、奇异与符号
Cartesian twist linear + angular velocity expressed-in frame、unit、duration body/spatial twist 混淆
wrench force + torque frame、N/N·m、sensor/command 传感与命令混淆
gripper width/position/velocity/force/open-close sign、range、unit、semantics 方向、阈值与饱和
base/mobile planar velocity/pose map/odom/base frame、rate 与机械臂时间不同步

移动底盘、双臂、灵巧手与工具会改变字段数量，本页不给默认维度。padding 后 shape 固定也不表示 padding 维可执行；dimension mask、机器人配置与 consumer schema 必须同时匹配。

Absolute、Delta 与 Relative 必须写全 reference

以下三种 relative 语义互不等价：state-relative 把每个目标与重规划时的 measured state 比较；adjacent delta 表示相邻预测步的增量；chunk-origin 则把每步相对同一 chunk 起点表达。延迟、丢帧和重规划会让三者生成不同轨迹。

“delta pose”还要说明平移在哪个 frame 表达，旋转增量在左侧还是右侧复合，reference 是 observation timestamp、inference completion 还是预计 execution timestamp 的状态。固定检查如下：reference 对象和采样时间是什么；delta 在什么 frame；序列内是否累积；adapter 是否用 measured state 恢复 absolute target；重规划是否重置 reference；旧计划到达时如何处置。

Rotation 与 Gripper 不允许靠维度猜

rotation 6D 通常由两个三维向量构成，需正交化为合法 SO(3) 旋转矩阵，并不是六个 Euler 角。实现必须记录 quaternion、axis-angle、Euler、matrix 或 rot6d；标量顺序与 active/passive convention；frame；absolute 或 incremental composition；projection 与退化输入；controller 格式转换 owner；角度 wrap、quaternion 双覆盖和跨时间连续性。

gripper 的一维也可能表示 opening width、normalized position、velocity、force、binary command 或 event。必须冻结 sign、range、unit、夹紧判据、hold 行为、无效值、双夹爪映射与是否进入连续轨迹；最后一维不能靠经验猜。

Action ABI 最小字段

字段 必填内容
action_schema_id 可版本化稳定 ID
fields 每维名称、index、机器人/工具归属
semantic position、velocity、effort、pose、twist、wrench、gripper
unit 每字段 SI 或明确约定
frame base/tool/camera/map 等稳定 frame ID
representation absolute/delta/relative、rotation/gripper 编码
reference 相对对象、采样时间与重置条件
rate_and_dt 训练采样率、执行率与每步 duration
validity padding/mask、有限值与 OOD 条件
normalization stats ID、方法、clip、inverse 与版本
consumer adapter/controller 及期望 schema
limits_owner 确定性限制属于哪个下游模块

ABI 版本变更必须被当作接口迁移，而不是简单修改 tensor shape。新增字段、调整关节顺序、改变 rotation 格式、替换 frame、更新 gripper 方向或 stats，都要产生新的 schema version，并定义旧数据能否无损迁移。consumer 如果只检查长度，就可能在 shape 完全一致时执行另一套语义。发布前应使用固定 fixture 对每个字段做 encode → decode → adapter round-trip，比较名称、单位、frame、reference、时间与数值，而不只比较数组。

动作日志也要保存三个层次：policy 的原始表示、恢复到 physical ABI 后的候选 reference、以及 controller 实际接受和 measured 的结果。若只保存最终轨迹，就无法判断模型是否输出错误但被 clamp 修正；若只保存 prediction，又会把未执行尾部误当成真实行为。每条记录应通过 decision ID、chunk ID、sequence ID 和 timestamp 串联，并引用 checkpoint、stats、adapter 与 controller contract 的内容 hash。

对跨机器人或换工具场景，字段语义必须按组处理。某些 joint 或 gripper 只在特定 embodiment 有效，dimension mask 必须同时进入 loss、decode 与 execution；缺失维不能用零值冒充真实“保持”。adapter 只能执行已注册的显式映射，遇到未知关节、工具或 schema 应 fail closed。成功完成 schema 映射也不证明目标动作可达、无碰撞或安全，它只是后续验证的入口。

ABI 还要约束错误分类：长度不匹配、未知字段、非有限值、旧版本、缺少 reference、过期 timestamp 与 consumer 不兼容应产生不同 typed failure。把所有错误都降级为 clipping 会隐藏根因，也可能让不兼容输出进入控制链。只有经过独立验证的 hold、stop 或 fallback 可以成为处置；“尽量执行剩余维度”不是默认容错策略。

Action Chunk、时域与归一化

四个 horizon 与一个频率

H_o 是 observation horizon，H_p 是 prediction horizon，H_e 是 execution horizon，R 是 replan interval，f_exec 是 controller 或 action consumer 的实际执行频率。常见设置满足 1 ≤ R ≤ H_e ≤ H_p，但异步 pipeline、overlap、丢帧与拒绝会改变实际消费。

\[T_{\mathrm{pred}}=\frac{H_p}{f_{\mathrm{exec}}}, \qquad T_{\mathrm{replan}}=\frac{R}{f_{\mathrm{exec}}}.\]

这两个量是名义时长，仍需与 observation timestamp、inference latency、deadline 和 queue 状态一起解释。训练 target、模型 prediction、execution queue、每周期 controller reference 与 logged executed action 可能具有相似 shape，却代表不同时间对象；prediction 不能代替实际 submitted、accepted 或 measured action。

Receding horizon 不是一句“闭环”

flowchart LR
  O["t0 · observation history H_o<br/>cutoff + capture timestamps"] --> I["inference latency L<br/>旧 queue 继续或暂停"]
  I --> P["new prediction H_p<br/>reference + first-action rule"]
  P --> V{"deadline / stale / schema<br/>checks pass?"}
  V -- "否" --> F["reject · hold · stop · approved fallback"]
  V -- "是" --> M["align overlap / merge<br/>execution horizon H_e"]
  M --> Q["consume R steps<br/>submitted → accepted → measured"]
  Q -->|"new observation"| O

图 2｜Chunk 与闭环时间线。 t0 截止观测后开始推理；延迟期间旧计划是否继续由 scheduler 定义；新 chunk 到达后先检查 deadline、staleness、schema 与 reference，再对齐 overlap，最多消费 H_e 步，并在 R 步后用新观测重规划。predicted、queued、submitted、accepted 与 measured 各有独立时间戳；late result 必须被拒绝或按已验证规则合并。

至少区分 stop-and-wait、infer 时继续旧 queue、fixed R 重规划、overlap merge 与 event-triggered replan。后者的偏差或置信触发器也不是安全证明。scheduler 要记录 observation cutoff、first action timestamp、latency、jitter、queue depth、deadline、stale threshold、overlap index、合并规则、late result、underflow、reset 与 fault 清空规则。

Temporal ensemble 的适用边界

多个历史 chunk 可能对同一执行时刻给出候选。合并前要保证相同物理语义、frame 与 absolute reference；对 delta 直接平均未必有物理意义。每个候选要保留 replan ID、目标 timestamp、是否先恢复 absolute target，以及 rotation、gripper event、过期与分歧过大时的规则。权重可以依年龄、置信或固定核，但必须版本化并在闭环评测；ACT 的具体权重与 query 仍留在模型页。

Normalize、Clip 与 Unnormalize 的顺序

固定审计顺序是 physical label → optional data clip → normalize(stats_id) → model target/output → representation decode → unnormalize(same stats_id) → ABI conversion → deterministic limits → controller。

训练与部署要共享 stats 的数据范围、本体、字段顺序、公式与版本；明确 min/max、mean/std、quantile、常量维处理、clip 阶段、padding 是否参与统计、gripper 是否单独处理、inverse dtype 与有限值检查，以及 dataset key/unnorm_key 的缺失行为。分位数只是数据统计，不是硬件极限；大量饱和说明数据、stats 或部署分布不匹配，不能因归一化值落在某区间就继续执行。

Chunk mask 与 padding

必须分开 padding value、参与 loss 的 action-valid mask、跨本体 dimension mask、允许下发的 execution mask、termination label，以及 loss 按维、步还是 batch 的归一方式。augmentation 后 mask 也要同步变换。零向量不是无效动作，padding 也不是 stop；mask 丢失会让模型在 episode 尾部向零收缩，offline loss 仍可能表面改善。

scheduler 的核心制品不是一组 horizon 数字，而是“哪个计划在什么时刻拥有哪段执行权”的时间账本。每次 replan 要记录观测截止、推理请求、结果返回、验证完成、入队、出队和 controller ack；旧计划和新计划重叠时，必须能重建每个 submitted action 来自哪个 chunk。若日志只保存最新 chunk，就无法解释 late result、queue starvation 或接缝抖动。

同步实现还要区分 prediction index 与 wall-clock slot。推理延迟可能让 chunk 的第零步在结果到达时已经过期；直接把它当“当前动作”会错位，盲目丢掉固定前缀也可能在 jitter 下错位。first-action timestamp rule 应使用实际 observation cutoff、预测语义与 controller timebase 计算，并为超出 deadline 的结果产生明确 reject 记录，而不是靠平均 latency 猜测偏移。

overlap merge 需要先统一 representation。absolute pose 可以在合法旋转空间做插值，delta 则要先相对同一 reference 恢复为 absolute；discrete gripper event 不能与连续关节量使用同一平均规则。权重归一、候选年龄、最大分歧、无候选处置和 merge 后再次 limits check 都应冻结。任何 ensemble 带来的平滑只是一种输出性质，不能抵消错误 frame、旧目标或碰撞风险。

归一化验证至少包括 stats round-trip、常量维、极端值、错误 key 和跨 robot key。部署时若 stats 缺失、hash 不符或字段顺序改变，应拒绝运行；自动回退到“默认 stats”会把接口错误变成静默物理偏差。clip 前后值与饱和标志都要入日志，帮助区分模型本身输出 OOD、数据统计不匹配和确定性限制频繁介入。

离散 Bin、Action Token 与 FAST

逐维 Bin 的编码与解码

对动作维 j，可在统计区间 [l_j,u_j] 上建立 K 个区间，将连续值映射为 bin index，再从 index 解码为中心、边界或条件代表值。页面不固定 K，也不规定 uniform 或 quantile bins，但必须记录 stats scope、每维端点与来源、edge/center 数、endpoint convention、underflow/overflow 处置、token offset、reserved IDs、dequantize 规则、rotation/gripper 策略、mask/EOS/PAD 词表占用和 round-trip 误差。

等宽 bin 的名义分辨率约为 (u_j-l_j)/K，实际任务误差还依赖数据密度、控制敏感度、频率与坐标语义。逐维独立量化也不会自动建模维间与时间相关性。

自回归 Action Token

若每个时间步的 D_a 个维度被序列化，应冻结类似 [t0:d0, t0:d1, …, t1:d0, …] 的 token order；按维优先或组合 token 会改变条件依赖、序列长度和错误传播。词表必须区分 BOS、EOS、PAD、action range 与 invalid IDs，记录 teacher forcing 与 free-running inference 的差异、decoding strategy、生成长度上限、物理 uncertainty 映射、KV cache 与墙钟延迟。

分类交叉熵可以表达每个位置的类别分布，却不等于物理一致的多模态轨迹。某一 token 错误可能影响同一步其他维与后续动作，协调性仍由联合模型、序列化、数据和解码共同决定。

共享语言词表不是共享语义

复用 LLM vocabulary 槽位时，要区分 vocabulary storage、连续动作到 ID 的 tokenizer mapping、embedding/head 参数是否共享、ID 在动作上下文中的物理 semantics、与普通词是否 collision、哪些位置允许 action decode，以及遇到 EOS、普通词或越界 ID 的失败行为。

同一个 token ID 不会让动作自动获得自然语言语义，也不能证明语言生成能力迁移到精细控制。只有动作段、schema 与 decode gate 同时匹配时，ID 才能被解释为动作。

FAST 类频域 Tokenizer

FAST 类路线可拆为四步：沿时间轴做离散余弦变换（Discrete Cosine Transform，DCT）或其他时频 transform；按 scale round/quantize；按固定顺序 serialize 系数；再用字节对编码（Byte Pair Encoding，BPE）学习可变长 token 序列。逆路径是 tokens → BPE decode → coefficients → reshape/order restore → dequantize → inverse transform → normalized chunk → unnormalize。

必须冻结 D_a、H_p、coefficient shape、transform normalization、scale/round 与 overflow、flatten order、整数表示、BPE vocabulary、unknown/decode failure、token length 分布和 per-dim/per-time round-trip error。高频动作、短 chunk、gripper event 与 discontinuity 要单独测试。DCT 与 BPE 可逆不代表量化无损；FAST 或 FAST+ 的速度与压缩结论只能在其论文设置内引用。

离散路线的验证卡

离线同时报告 token accuracy 与 physical-space error；按维给出 confusion、boundary error、overflow/clip rate；解码后评估 position、orientation 与 gripper；区分 teacher-forced 和 free-running；报告 sequence length、tokens/action-step、EOS/PAD/invalid rate 与 wall-clock latency。不同 robot/stats key 交叉使用必须 fail closed，full-chunk exact match 不能成为唯一指标。

量化误差要回到物理语义中解释。同一 bin 宽度对平移、旋转、gripper 和高灵敏关节的影响并不相同；per-dim token accuracy 相同，也可能造成截然不同的闭环偏差。评估应按字段给出 round-trip error、相邻 bin 切换、饱和比例与对 controller reference 的影响，并检查量化中心是否在合法旋转或 gripper domain 内。仅报告平均 token loss 会掩盖少数关键维的灾难性错误。

自回归序列需要独立测试“首个错误传播”。可以在固定 condition 下替换某一 token，观察同一动作剩余维、后续时间步、EOS 与 decode 长度怎样变化；也要比较 teacher-forced 与 free-running 的差距。非法 ID、过早 EOS、达到最大长度和重复 token 循环应有不同失败码。decoder 不应在无法还原完整 chunk 时用缺省值拼出动作。

共享语言 vocabulary 时还要防止上下文边界错误：普通文本区出现 action ID、动作区出现文本 ID、special token 被错误解释，或 tokenizer version 改变保留区间。Action decode gate 应依赖明确 segment/type 信息，不依赖“某个数值大概在尾部”。checkpoint、tokenizer、action mapping 与 stats 必须作为同一 bundle 校验，任一版本撕裂都拒绝下发。

FAST 的压缩收益要同时报告序列长度分布和重建代价。短而突变的 chunk 可能没有足够频域冗余，高频接触修正和 gripper event 也可能对 scale/round 更敏感。BPE token 数减少不等于端到端延迟同比下降，因为还包含 transform、序列生成、decode、inverse transform 和 transfer。应使用同硬件、同 batch、同 ABI 进行墙钟比较，并把 decode failure 与长尾 token 长度纳入报告。

连续回归、CVAE 与条件分布

Deterministic Regression

连续策略可以一次输出动作或 chunk。常见 masked 目标包括：

\[L_2=\operatorname{mean}\!\left(m\lVert\hat a-a\rVert^2\right), \qquad L_1=\operatorname{mean}\!\left(m\lvert\hat a-a\rvert\right).\]

在理想 Bayes-risk 条件下，平方误差点估计对应条件均值，绝对误差对应条件中位数；有限数据、mask、regularization、优化与轨迹耦合会改变实际行为。本页只说点估计可能在多解数据中落入低密度折中，不把“平均动作”写成任何 L2 策略的必然结果。

实现要记录 loss 位于 normalized 还是 physical space、各字段 scale/weight、chunk step 权重、rotation 合法性、gripper/termination 的独立目标、padding/dimension mask、是否建模输出方差，以及 offline 指标与 closed-loop 的证据。优点通常是单次前向和延迟易控；点估计本身不能表达完整条件分布。

CVAE 的训练图

条件变分自编码器（Conditional Variational Autoencoder，CVAE）引入 latent z。训练时近似 posterior 可以读取目标动作与条件：

\[z\sim q_\phi(z\mid a,c), \qquad \hat a=\operatorname{decoder}_\theta(z,c),\] \[L=\operatorname{reconstruction}(\hat a,a;m) +\beta\,D_{\mathrm{KL}}\!\left(q_\phi(z\mid a,c)\Vert p(z\mid c)\right).\]

condition c 可以包含 observation、language、state 与 history。posterior 只在训练时能看到目标动作，部署不得泄漏未来标签；prior 可能是标准高斯或 conditional prior；reconstruction space、mask 与权重必须说明。beta、free bits、annealing 是实现选择，latent dimension、sampling temperature 与 inference latent policy 都要版本化。KL 小不等于 latent 有用，KL 大也不等于多样性好。

CVAE 的推理图

推理时没有目标动作，只能从 p(z|c) 采样或使用由 policy 明确规定的 deterministic latent，再由 decoder 生成动作。要记录采样数、是否排序或筛选、零/均值/fixed/random latent 的依据、random seed、posterior-prior gap、latent 对物理轨迹的敏感性，以及谁选择多个候选。

多样样本只有对应不同、有效且可行的任务模式才有价值；高频噪声、gripper 抖动或不合法旋转不应计作 diversity。候选选择器也会增加延迟与风险，必须进入 objective trace 与闭环评测。

Posterior Collapse 与“伪多模态”

若 decoder 依赖强 condition 就能重建，它可能忽略 z，posterior 接近 prior，latent intervention 几乎不改变输出。验证应固定 c 多次采样 z 并测物理 diversity，固定 z 改变 c 检查条件路径，比较 posterior/prior sample，结合 mode coverage 与 task success，并排除只是噪声或非法动作的伪多样性。latent traversal 只作诊断，不应被宣传为可解释语义控制。

连续回归的“单次前向”优势只有在完整 pipeline 下才成立。condition encoding、action head、unnormalize、rotation projection、adapter 和 transfer 都属于端到端延迟；如果 backbone 每次重新计算，head 本身一次调用并不代表满足 deadline。回归输出还要检查跨时间 continuity、不同字段尺度和 mask reduction，否则低 loss 可能主要由低风险或大数量字段主导。

评估多模态分布时，样本 diversity、mode coverage、feasibility 与 task outcome 应分开。大量样本落在不合法旋转、越界或碰撞区域，不能因彼此不同而算作更好覆盖；所有样本都集中在单一安全动作，也不能仅凭成功率断言 posterior collapse。应在同一 condition 上重复采样，用定义明确的轨迹距离和 mode label，再由独立约束筛除不可执行候选并报告筛除率。

CVAE 的 prior 与 posterior gap 需要在同一 metric 下比较。训练重建使用 posterior sample，部署使用 prior sample；如果只报告前者，可能严重高估可用质量。deterministic latent、prior mean 或 zero latent 都是具体 inference policy，而不是 CVAE 默认定义，必须写进 checkpoint/bundle 与评测协议。随机 seed 只能帮助复现样本，不能消除分布不确定性。

候选选择器也是系统组件。若从多个 latent sample 中按 value、collision score 或语言一致性选择，它会新增模型、阈值、延迟与 failure mode；选择器使用未来结果或评测标签还会造成泄漏。报告应给出生成样本数、筛选依据、全部候选被拒绝时的 fallback 和选择前后分布，而不是把最终一条轨迹都归因给 CVAE decoder。

Diffusion、Score 与 Flow Matching

先分清数据、噪声、时间和条件

设 clean action chunk 为 x_data，base noise 为 x_base，多模态 condition 为 c，连续或离散时间为 t。任何方法说明都要画清 forward/noising 或 probability path 如何构造 x_t，网络输入是否含 x_t,t,c,mask，训练 target 是 noise、score、clean sample 还是 velocity，推理从何处分布初始化、沿哪个方向积分、每步调用网络几次，以及何时 decode、unnormalize 并返回 Action ABI。

只写“使用 diffusion/flow loss”不足以识别算法。训练每个样本随机取一个 t，也不代表推理只需要一次网络调用。

Diffusion 的四类常见参数化

参数化 网络近似预测 必须配套
epsilon prediction 加入的 noise noise schedule 与 reverse update
score prediction ∇x log p_t(x|c) SDE/ODE 与尺度约定
x0 prediction clean action posterior/update 与 clipping
v prediction noise/data 的特定线性组合 明确 v 定义，不能只写字母

这些参数化可能在同一 schedule 下转换，但 checkpoint 的 prediction type 与 sampler 公式不能混用。训练需要记录 data 与 condition、采样的 t 和 noise、forward process、target construction、有效 step/dimension mask、schedule、parameterization 与 stats version。

Score、SDE 与 Probability Flow ODE 的边界

score 是 noisy marginal log density 对状态 x 的梯度。Score-based 模型可用随机微分方程（Stochastic Differential Equation，SDE）描述 forward/noising 与 reverse-time SDE，也可构造 probability flow 常微分方程（Ordinary Differential Equation，ODE）。reverse SDE 含随机项，probability flow ODE 是确定性动力系统；相同 score model 可以配不同 numerical solver。

solver step、每步网络调用和误差控制都会影响函数评估次数（Number of Function Evaluations，NFE）、延迟与样本。使用 SDE 或 ODE 不会自动满足 frame、限位、碰撞或控制 deadline。

Flow Matching 的条件向量场

Flow Matching 回归所选 conditional probability path 的 vector field。给定 path sample x_t 与 target velocity u_t：

\[L_{\mathrm{FM}}= \mathbb E\!\left[m\lVert v_\theta(x_t,t,c)-u_t\rVert^2\right], \qquad \frac{dx}{dt}=v_\theta(x,t,c).\]

推理从 base endpoint 沿 ODE 积分到 data endpoint。必须记录 base distribution、endpoint、path/interpolant、x_t sampling、u_t 公式、t distribution、time direction、solver、step schedule、steps、NFE、tolerance、condition、mask、guidance 与 output inverse pipeline。

直线 interpolant 只是常见选择，不是 Flow Matching 唯一路径；原始工作也覆盖与 diffusion path 兼容的构造。因此不能写成“flow 等于直线，diffusion 等于曲线”。

同样是 MSE，为何不是同一目标

路线 输入状态 target 推理
continuous regression condition c clean action x_data 一次前向
diffusion epsilon x_t,t,c sampled noise iterative reverse update
score model x_t,t,c score target reverse SDE 或 ODE
x0 prediction x_t,t,c clean x_data iterative sampler
flow matching path state x_t,t,c path velocity u_t ODE integration

代码审计必须沿 target construction、time convention 与 inference update 追踪，不能用 MSELoss 类名判断方法。目标张量 shape 相同，也不表示其物理或概率语义相同。

训练 step、采样 step 与 NFE

train timestep sample 是为一条训练样本抽取的 t；optimizer step 是一次参数更新；sampler/integration step 是推理轨迹中的数值步；NFE 是 denoiser/vector field 实际网络评估次数；wall-clock latency 还包含 condition encoding、solver、decode、transfer 与 queue；real-time factor 比较生成 chunk 耗时和可用时间预算。

高阶 solver 每个 step 可能调用网络多次，因此 steps 不等于 NFE。缓存 VLM condition 也会改变每次调用成本。速度比较必须对齐 hardware、batch、precision、warmup、compile 与 I/O boundary，并报告分位延迟，而不是只给均值。

Diffusion 与 Flow 的比较边界

flowchart TB
  B["Bins / Action Token<br/>label → quantize → autoregressive IDs → dequantize"] --> ABI["Same Physical Action ABI"]
  F["FAST<br/>chunk → DCT → quantize/serialize → BPE → inverse"] --> ABI
  R["Regression<br/>condition → one forward → continuous chunk"] --> ABI
  C["CVAE<br/>train posterior · infer prior/sample → decoder"] --> ABI
  D["Diffusion<br/>data/noise path → target → iterative reverse sampler"] --> ABI
  M["Flow Matching<br/>base/path sample → velocity → ODE solver"] --> ABI
  ABI --> E["decode · unnormalize · scheduler · limits · controller"]

图 3｜六条生成路径回到同一 Action ABI。 bins 与 FAST 含显式有损量化，自回归调用与 token 长度相关；regression 常为一次前向；CVAE 的 posterior 是 train-only、prior/sample 是 inference path；Diffusion 和 Flow 的成本依 sampler/solver steps 与 NFE。无论路线，最终都必须恢复相同字段、frame、unit、reference、mask 与 consumer 后才能比较闭环行为。

允许比较 target/path 可解释性、mode coverage、sample quality、NFE、latency、solver sensitivity、chunk smoothness、高频误差、guidance、offline distribution metrics 和 closed-loop failure。不能因 Flow 是 ODE 就推断必然更快，也不能因 Diffusion 多步就断定更慢；结果取决于 network、solver、NFE、cache、hardware、horizon 与质量要求。

生成路径验证要先做数值 fixture。使用已知 x_data、x_base、t 和 condition，逐项核对 x_t、target 与网络输出 shape；再用一个可解析 vector field 或 denoiser 检查 sampler/solver 的时间方向、端点和 step schedule。若正反方向、时间缩放或 prediction type 设错，模型仍可能输出有限值，却会沿错误动力系统积分。fixture 不运行真实控制，只验证离线数学与实现合同。

solver 对照至少报告 fixed/adaptive、步长序列、tolerance、steps、NFE、拒绝步、随机 seed 和终止条件。adaptive solver 的 step 数会随样本变化，固定 steps 的高阶方法也可能每步多次评估，因此 latency 要按分布报告。减少 NFE 后样本质量下降是精度—成本权衡，不足以宣布某种生成范式不适合机器人。

condition guidance 也会改变成本和目标。classifier-free guidance 或多条件组合可能让每个 integration step 需要额外网络调用，并可能放大动作幅度或使结果偏离训练分布。guidance scale、条件 dropout、unconditional branch、cache 共享与最终 limits event 都要记录；guidance 改善文本一致性不能自动推出物理可行性。

最终输出要在 physical space 检查，而不是停留在 normalized sample。比较 Diffusion 与 Flow 时，应使用同一 Action ABI、stats、scheduler、controller、任务划分和安全门禁；分别报告生成误差、轨迹频谱、staleness、deadline miss、limit rejection、closed-loop success 与 recovery。若不同方法配不同 backbone 或数据，结果只能描述完整系统，不能把差异单独归因于 objective。

闭环执行、方法选择与验证

从模型输出到 Controller 的门禁

固定流水线是 raw output → representation decode → length/schema → finite → unnormalize → frame/reference conversion → rotation projection → per-field deterministic limits → scheduler/merge → controller reference。任何步骤失败都不能静默继续。

hard reject 用于 schema、NaN/Inf、unknown stats、invalid token 与 unknown frame；hold/stop request 用于缺少 fresh plan 或 controller not ready；fallback policy 只有已定义且验证过才可启用；human escalation 明确交给人工；log-only warning 只能用于不改变执行语义的诊断。limit check 仍不是完整 safety system，碰撞、可达性、watchdog、急停与 hardware state 由后续安全/部署页负责。

Termination 是状态机，不是一个 Token

信号 含义 可能来源 直接等于 success?
EOS token sequence end decoder 否
model stop 策略建议停止或不再生成 policy head 否
environment success 任务判定满足 evaluator/environment 可能是证据，但需定义
timeout 达到时间或步数上限 scheduler 否
abort 系统主动中止 supervisor 否
human stop 人工停止 operator 否
controller fault 低层故障 controller/hardware 否
emergency stop 独立安全链触发 safety system 否

优先级由独立 supervisor 决定，不由生成模型自行仲裁。termination contract 要记录 source、timestamp、latched、priority、required evidence、queue behavior、gripper behavior、reset permission 和 audit log。

关键风险 边界、顺序、invalid ID 有损、词表与高频 多解折中 prior gap/collapse schedule/sampler/NFE path/solver/time convention
适配检查 decode + unnormalize 完整 inverse pipeline unnormalize latent policy + unnormalize sampler + unnormalize solver + unnormalize

选择前依次问：Action ABI 和 controller 要什么；数据是否真正多解；D_a、H_p、频率与高频成分；deadline、hardware 与最大 NFE；quantization error 与 sampling error 哪个更影响控制；scheduler 怎样重规划、合并与处理旧 chunk；offline improvement 是否在 closed-loop success、intervention 与 limit events 上成立。没有一种路线因名称本身成为默认答案。

五层验证梯

第一层验证 schema 与 round-trip：字段顺序、shape、dtype、mask、token range，normalize/inverse、token encode/decode、FAST transform/inverse、rotation conversion 与 serialization。第二层验证 objective：target construction、future label leakage、CVAE posterior train-only、Diffusion/Flow 的 t/path/noise/velocity、mask 与 train/inference parameterization。

第三层看 physical trajectory：per-dim/per-step error、quantization/saturation、mode coverage、position/orientation/gripper、velocity/acceleration/jerk、discontinuity 与 wrong stats fail-closed。第四层看 scheduler/real-time：H_o/H_p/H_e/R/f_exec、stale/late result、queue underflow/overflow、overlap、p50/p95/p99 latency、NFE、memory 与端到端 timestamp。第五层看 closed-loop/fault：task success、failure taxonomy、intervention、abort、timeout、limit/collision/near-miss、controller fault、observation perturbation、lost plan、invalid output 与 recovery。

页面内交互与完成演练

本地、无状态的表示选择器只能按 action space、absolute/delta、D_a/H_p/H_e/R/f_exec 与 token/FAST/regression/CVAE/Diffusion/Flow 选择显示必填字段和缺失项。输入不发送网络、不保存、不生成控制命令；“检查完成”只说明字段齐全，不表示模型正确、安全或可部署。

完成演练要求填完一份 Action ABI、normalize/inverse round-trip、objective trace、H_o/H_p/H_e/R 时间线、late result 与 invalid output 处置，以及 offline、latency 与 closed-loop 指标。缺少任一项，状态只能是“待补字段”。

可比实验必须先冻结共同输入，而不是只把不同方法的最终成功率排成一列。数据切分、condition、Action ABI、预测 horizon、有效 mask、归一化统计、backbone 规模、允许延迟、controller 与任务判定都应一致；无法一致的部分要作为混杂因素单独列出。token 方法应同时报告生成 token 数，连续生成方法应报告实际 NFE，所有路线都报告从 observation cutoff 到 validated reference 的端到端时延。这样才能区分表示方式、网络容量、计算预算与调度实现带来的差异。

ABI conformance suite 至少要准备正常、边界和拒绝三类 fixture。正常 fixture 覆盖每种字段、frame、reference 与 mask；边界 fixture 覆盖合法限值、旋转 wrap、空 gripper 事件、短 episode 和部分 dimension；拒绝 fixture 注入 NaN/Inf、错误 dtype、未知 schema、乱序关节、缺失 stats、过期 timestamp、非法 token、异常 EOS 和不可逆 transform。每个 fixture 都要写预期阶段、typed error、是否允许进入 queue，以及日志中必须出现的 decision ID。只验证“函数没有抛异常”不能证明接口合规。

离线 replay 应重放 observation、原始输出、decode 后动作、scheduler 决策和 controller 回执，而不是重新运行模型后比较两个最终轨迹。对随机方法，保存 base noise、latent、seed、time grid 与 solver 配置；对自回归方法，保存 token 序列和停止原因；对 temporal ensemble，保存每个候选及权重。重放结果若与原记录不同，应定位为输入、数值、版本或非确定性差异，不能直接用容差把整段轨迹判为“足够一致”。

故障注入只在隔离、不可执行的测试环境验证处置合同。可以构造 late result、queue underflow、重复 sequence、旧 bundle、错误 frame、全 mask、decoder 超长、solver 未收敛和 controller reject，检查系统是否在预定 owner 处停止传播。测试不得把生成的 reference 发送给真实控制器；通过条件是拒绝位置、状态转换、日志证据与恢复权限符合契约，而不是动作看起来平滑。

scheduler 验收应从时间线反推每个 action slot：它使用哪次观测、哪次推理、哪个 chunk、何时通过门禁、是否被替换，以及 controller 实际何时接受。对于 overlap，既要证明权重归一和 reference 一致，也要证明 merge 后的结果重新通过限制检查；对于丢失计划，要验证 hold、stop 或批准的 fallback 不会读取未初始化缓存。p50 延迟满足预算而 p99 经常越界时，系统仍未满足实时合同。

最终审阅包要能从页面模板生成一份只读证据索引：schema 与 bundle hash、fixture 结果、数据切分、方法配置、latency 分布、failure 明细、人工介入、未运行项和已知限制。任何摘要都必须链接回逐样本或逐事件记录，并区分 predicted、decoded、queued、submitted、accepted 与 measured。审核者若不能仅凭记录回答“某一时刻为何执行或拒绝这一步”，页面就只能标为内容完整，不能标为系统验证通过。

方法升级还要设置反例驱动的退出条件。若新 tokenizer 降低平均序列长度却提高关键维的物理误差，若新 sampler 降低平均 NFE 却增加 deadline miss，或若多模态生成提高样本覆盖却让有效候选全部被门禁拒绝，就不能用单项收益宣布升级成功。验收结论应同时陈列收益、退化、未知项和统计不确定性，并由预先登记的阈值决定继续、回滚或补充试验，避免看到结果后重新定义通过标准。

跨方法的 failure owner 也要保持一致。decoder 负责 representation 完整性，adapter 负责明确的语义转换，scheduler 负责时效和执行权，controller 负责低层接口状态，独立 supervisor 负责系统级禁止条件。不能让 Diffusion sampler 修补 frame 错误，也不能让 tokenizer 用特殊 token 代替急停链。错误被下游拦截只是防线工作，并不消除上游缺陷；报告需要同时记录首次产生点和最终拦截点。

当页面上的所有字段都填写完毕，允许给出的最高结论仍只是“动作表示合同具备离线审阅条件”。进入任何真实或仿真的闭环试验前，还需要独立批准对应环境、数据、软件版本、计算资源、控制接口和安全程序。本页的示例值、伪代码与图示都不构成运行许可，也不应该被脚本抽取成默认配置；任何自动化 consumer 都必须把占位符、示例标记与未知证据视为硬失败。

  5. Song 等，Score-Based Generative Modeling through SDEs，arXiv:2011.13456：score、reverse SDE 与 probability flow ODE。
  6. Chi 等，Diffusion Policy，arXiv:2303.04137：动作序列扩散与 receding-horizon 实例。
  7. Lipman 等，Flow Matching for Generative Modeling，arXiv:2210.02747：conditional path、vector field 与 ODE 生成。
  8. Pertsch 等，FAST，arXiv:2501.09747：DCT、量化、序列化与 BPE 动作 tokenizer。
  9. Brohan 等，RT-1，arXiv:2212.06817：离散机器人动作 token 实例。

  12. Lynch 与 Park，Modern Robotics, Chapter 3，教材页面：rotation、frame、twist 与坐标表达。

证据标签分为基础定义、模型论文、站内源码核验、工程推导和待系统验证。不能写“Diffusion 天然安全”“Flow 必然更快”“FAST 对所有机器人都无损加速”“CVAE 必然解决多模态”或“token 化一定提升跨本体泛化”。

验证报告必须把“没有运行”“不适用”“失败”“证据不足”和“通过”分开。某方法因依赖或硬件缺失未执行，不能计入通过率；invalid output 被安全层拒绝，也不能同时记为任务成功。每个 aggregate metric 要保留分母、样本数、置信区间、排除规则和按 failure taxonomy 的明细，防止用单一平均数掩盖偶发严重错误。

发布门禁以完整 bundle 为单位：checkpoint、processor、tokenizer、action mapping、stats、objective config、solver/sampler、scheduler、adapter、controller contract 和 limits policy 必须互相兼容。只替换 checkpoint 会导致 prediction type、词表、time convention 或 normalization 撕裂。rollback 也要恢复完整已验证 bundle，并保留失败版本、日志与触发原因供审计。

闭环评测不能把人类完成的后半段计为 autonomous success，也不能把 emergency stop 当普通 timeout。需要分别报告模型自主段、人工接管、supervisor reject、controller fault、环境失败和恢复结果；按 action representation、robot、task、scene 与 OOD 轴分层。离线 physical error 较低若没有转化为闭环改善，应优先检查 scheduler、reference、latency 与 limits，而不是继续优化同一 loss。

本页的完成标准只到接口与证据可审计：读者能从 raw label 追到 training target，从 model output 追到 accepted/measured action，并解释所有时间、mask、随机变量与 failure owner。它不授予训练、部署或真机权限，也不产生任何默认控制参数。后续数据页负责 stats 与跨本体来源，实时页负责 queue/latency，安全页负责独立风险论证。
