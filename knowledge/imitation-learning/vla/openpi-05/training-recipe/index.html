π0.5 相对 π0 最大的改动不在网络里，在训练流程里。π0 从第一步起就带着流匹配动作专家一起训；π0.5 把训练劈成两段——前 280k 步根本没有动作专家，动作被 FAST 分词器压成离散 token，整个模型就是一个做下一 token 预测的普通 VLM；后 80k 步才把随机初始化的动作专家挂上来，用交叉熵与流匹配的加权和联合训练。

论文用对照实验支持这套安排的计算效率：即使把 π0 基线延长到 300k 步，完整 π0.5 仍显著更好。但这个对比同时改变了训练配方以及 HL/WD 数据，不能单靠这一组结果把全部差距归因于“两阶段”一个变量；第八节会分开解释可证结论与因果边界。

本页数字分两层。A 层为 π0.5 论文 arXiv:2504.16054 的 Section IV-B/C/D、Section V-D 与 Appendix E；B 层为 openpi 源码。本页描述的是论文中的完整训练配方——它与当前公开 openpi 仓库实际实现的训练路径并不是同一套程序，这一点极其重要，差异逐条列在本专题子页 ⑦。凡论文未给可复现数字的量（混合比例、各图的具体百分比），本页只写方向性结论。

类别 条目 在本页哪一节
知识点 FAST 动作分词器的接口事实：动作 token 被映射进 PaliGemma 已有词表的尾部，未扩充词表 第二节
知识点 朴素分箱失效的根因：自回归的训练信号正比于 token 的边际信息量，而逐时间步分箱下该信息量随控制频率升高趋近于零，模型退化为复制上一个动作 第二节

创新点 展平顺序是列优先而非行优先：先预测刻画整体形状的低频分量能让 rollout 更稳定；可类比“先出边界框再出子任务”，但两篇论文没有建立二者的直接联系 第二节

知识点 阶段一四类监督信号的统一形态：文本、边界框、子任务、FAST 动作 token 第四节

知识点 论文时间约定与 openpi 时间约定的代换 \(\tau = 1 - t\) 第七节
知识点 动作数据的归一化口径：按 1% 与 99% 分位数压进 \([-1,1]\)，低维机器人零填充 第九节
创新点 把训练劈成「离散预训练 + 连续后训练」两段：前 280k 步根本没有动作专家，模型就是一个做下一 token 预测的 VLM 第三、四、五节
创新点 同一模型同时被训练成两种动作输出方式，训练吃离散表示的效率、推理走连续表示的速度 第二节
创新点 用单个标量 \(\alpha\) 在同一数学目标中连接两个阶段：\(\alpha=0\) 时式 (1) 退化成标准 VLM 训练；这不表示公开 openpi 用同一段训练代码实现了论文全配方 第六节

重点 阶段二里交叉熵没有被关掉，它的职能从「唯一目标」变成「防止语言能力在后训练中退化」 第五节
重点 论文把 π0 对照延长到 300k 步后结论仍成立，支持 FAST 训练更省算力；但完整 π0.5 共训练 360k 步且多用 HL/WD，不能把该结果读成严格的单变量消融 第八节
重点 后训练去掉了 CE 跨本体实验室数据、新增了 VI 口头指令数据；VI 仅占高层样本约 11% 却至关重要 第五节

一、本页在专题中的位置

本页只回答「训练流程怎么走、损失怎么写」。几个相邻问题归别处：

不重推流匹配条件流匹配的推导、Beta 时间步分布的完整论证与截断阈值的含义，都在 π0 专题子页 ②。论文 Appendix E 原话是「We follow π0 for sampling the flow-matching timestep τ」——这部分 π0.5 一字未改。

不讲梯度干扰为什么「先离散后连续」还能进一步演化成 stop-gradient 方案，以及 Knowledge Insulation 与本页所述配方的关系，在本专题子页 ④。

二、为什么需要两种动作表示

论文 Section IV-B 把动机写得很直接，可以概括成一个两难：

表示方式 训练时 推理时
FAST 离散 token 快。与文本共用一套交叉熵目标，可直接套用大规模语言模型的训练工具链 慢。必须逐 token 自回归解码，不适合实时控制
流匹配连续动作 在论文实验中收敛较慢；动作回归不能直接作为纯文本样本的监督目标，但可与文本交叉熵共同训练共享主干 快。整块动作并行输出，固定 10 步积分

论文的原话是：用离散 token 表示动作时 VLA 训练可以快得多，尤其是用 FAST 这类对动作块压缩效率高的分词方案；但离散表示不适合实时推理，因为需要昂贵的自回归解码。于是「理想的模型设计应当在离散动作上训练，同时仍能在推理时用流匹配产生连续动作」。

π0.5 的做法就是把这句话直接实现出来：同一个模型被训练成两种方式都会输出动作，训练时主要吃 FAST 那条路的效率红利，推理时只走流匹配那条路。

这个方案成立的前提是两条路径不能互相偷看目标。论文用注意力掩码保证动作专家的 embedding 不去看 FAST 动作 token；若允许这种连接，连续分支可能利用离散答案形成目标泄漏，训练目标就不再检验它能否仅根据观测与指令预测动作。完整的掩码规则见本专题子页 ②。

FAST 动作分词器

FAST 来自 Physical Intelligence 的另一项工作（论文 Section IV-B 引用条目 [64]，即 π0-FAST 所用的分词器，原文为 arXiv:2501.09747）。下面按「它要解决什么问题 → 问题的根因 → 算法 → 两个实现细节」的顺序展开，因为不理解根因就会把 FAST 误解成单纯的「压缩省 token」，而它真正改变的是训练信号本身。

根因：朴素分箱让每个 token 的边际信息量趋近于零

FAST 论文用一个很干净的玩具实验把问题暴露出来：给定四个随机点，让一个小的自回归 Transformer 预测穿过它们的三次样条曲线；保持底层数据分布不变，只改变采样率（每条序列 25 到 800 个时间步），目标序列按先前 VLA 通用的做法逐元素分箱成 256 档。

结果是：低采样率下预测误差很低；随采样率升高误差急剧上升，最终模型退化成直接复制第一个动作。

论文强调这不能归咎于数据——底层分布的复杂度没变，同样容量、同样训练步数的模型本应在各采样率下表现相当。真正的原因在学习目标本身：

自回归模型的训练信号，正比于 \(T_i\) 在给定 \(T_{1:i-1}\) 下的边际信息量。而采用逐时间步分箱时，随着控制频率升高，这个边际信息量趋近于零——对于平滑信号，时间步越短，每步的变化量就越小。

把这句话换成工程语言：高频动作序列里，”下一个 token”几乎完全由前一个 token 决定，交叉熵在它上面几乎学不到东西。模型用最省力的方式把损失降下去，就是照抄上一个值。这既拖慢收敛，也让复杂高频数据集难以拟合。

论文还给了一条真实世界的佐证：OpenVLA 在低频的 BridgeV2 与 RT-1 上表现良好，却难以拟合频率更高的 DROID。

这一条对理解 π0.5 的两阶段配方非常关键。阶段一之所以能靠离散目标跑得快，前提是每个动作 token 都携带足够的信息量；如果用朴素分箱，阶段一不但不会更快，反而会比流匹配更糟。“离散目标训练更快”这句话只在配上一个好的压缩分词器时才成立，FAST 正是为此存在。

算法：DCT + 量化 + 列优先展平 + BPE

FAST 的流水线只有四步，论文 Algorithm 1 给出伪代码。这里必须区分“可快速解码”与“无损”：DCT 与 BPE 可逆，缩放后取整会丢失系数精度，因此从原始连续动作到 token 的整体映射是有损的。论文后文也明确说明 FAST 并非完全无损，缩放系数 \(\gamma\) 控制压缩率与重建误差的权衡。

步骤 操作 为什么是这一步
① 归一化 用训练集中每个动作维度的 1% 与 99% 分位数映射到 \([-1,1]\) 统一取值范围；用分位数而非极值，是为了对大规模机器人数据中偶发的离群动作稳健；也使不同本体、不同动作尺度的数据更容易统一分词
② 离散余弦变换 对每个动作维度分别做 DCT 低频分量刻画信号整体形状、高频分量对应突变。机器人动作随时间平滑变化，因此少数几个系数就能承载绝大部分信息——这与 JPEG 压缩图像成立的理由相同
③ 量化 \(\bar{C}^{\,i}_{j}=\mathrm{round}\big(\gamma\cdot C^{\,i}_{j}\big)\) 用一次「缩放再取整」实现「丢弃不显著系数」。\(\gamma\) 是唯一在有损与压缩率之间做权衡的超参数。取整后系数矩阵通常高度稀疏
④ 展平 + BPE 把 \(\lvert A\rvert\times H\) 的系数矩阵展平成整数序列，再用字节对编码无损压缩 BPE 把大量零值「压扁」，并把跨维度频繁共现的系数组合并成单个 token。选 BPE 还有一个工程理由：它能产出固定大小的词表，便于并入视觉语言模型已有的词表
\[a_{1:H} \;\xrightarrow{\ \text{分位数归一化}\ }\; \tilde{a}_{1:H} \;\xrightarrow{\ \mathrm{DCT}\ }\; C^{\,i}_{j} \;\xrightarrow{\ \mathrm{round}(\gamma\,\cdot)\ }\; \bar{C}^{\,i}_{j} \;\xrightarrow{\ \text{列优先展平}\ }\; [T_k] \;\xrightarrow{\ \mathrm{BPE}\ }\; [\bar{T}_1,\dots,\bar{T}_{\bar{k}}]\]

两个容易被略过、但影响实际效果的细节

其一，展平顺序不是任意的。\(\lvert A\rvert\times H\) 的系数矩阵有两种展平方式：按列优先（先把所有维度的最低频分量拼在一起），或按行优先（先把单个维度的所有频率分量拼完）。论文明确选列优先，理由是：

在自回归预测中先预测刻画输出序列整体形状的低频分量，会让策略 rollout 更稳定。

可以把这个选择与分层推理里“先出边界框再出子任务”作一个帮助理解的类比：两者都让较早输出为后续输出提供条件。但这是本站的结构类比，不是 FAST 或 π0.5 论文声称的共同设计来源；频率系数的“由低到高”也不能简单等同于语义推理的“由粗到细”。

其二，超参数只有两个，且都不敏感。分词器只有「取整前的缩放系数」与「BPE 词表大小」两个超参数；论文称两者都不很敏感，其全部单数据集实验统一使用缩放系数 10、BPE 词表 1024。论文特意把这一点与基于向量量化的端到端学习式压缩作对比：后者训练繁琐，且需要针对数据集仔细选超参数才能得到好的重建。

FAST+：为什么 openpi 里那一行是从 HuggingFace 直接拉的

FAST 中唯一需要学习的部分是 BPE 词表，它需要为每个新数据集训练一次（论文称通常只要几分钟）。为免去这一步，作者在一个跨本体数据集上训练了一个通用分词器 FAST+，该数据集约含 100 万个 1 秒动作块，覆盖单臂、双臂与移动操作机器人，含关节空间与末端执行器两类动作空间以及各种控制频率。论文将 FAST+ 定位为可直接用于新机器人 1 秒动作序列的黑盒默认方案；这是一项目标与实验结论，不等于对任意本体、动作定义和分布都保证无须验证。

这正好解释了 openpi 源码里那一行的来历——它拉取的就是论文发布的 FAST+：

openpi 里能直接核对的是接口层事实，src/openpi/models/tokenizer.py 的 FASTTokenizer：

self._fast_tokenizer = AutoProcessor.from_pretrained("physical-intelligence/fast", trust_remote_code=True)
self._fast_skip_tokens = 128  # Skip last 128 tokens in PaliGemma vocab since they are special tokens

也就是说，FAST 动作 token 没有扩充输出词表，而是通过 vocab_size - 1 - 128 - token_id 反向映射到 PaliGemma 词表尾部的一段 ID，同时避开最后 128 个特殊 token。这种 ID 复用让动作、文本与位置 token 可以共享词嵌入/输出头和交叉熵目标；它是共训练的一个接口条件，而不是共训练成功的充分原因。

拼出来的序列形如：

Task: {指令}, State: {状态整数串};
Action: {FAST 动作 token}|

离散与连续两条路各自的确切代价

FAST 论文在同一硬件上量了两者的推理耗时，并说明了差距的来源——这组数字比任何定性描述都更能说明 π0.5 为什么要「训练用离散、推理用连续」：

模型 预测 1 秒动作块的耗时（NVIDIA 4090） 为什么是这个量级
π0（扩散 / 流匹配） 约 100 ms 固定 10 步去噪，且每步只重算 300M 的动作专家
π0-FAST（自回归） 约 750 ms 需要自回归解码通常 30–60 个动作 token，且每步都要走完整的 2B 语言模型主干

差距的两个来源要分开看：步数（30–60 对 10）与每步的算力（2B 对 300M），两者相乘才是那七倍多的差距。这也解释了 ② 页讲的那个取舍——把参数放在只算一遍的 prefix 一侧几乎不影响延迟，放在要算十遍的 suffix 一侧则要乘以步数。

而在训练这一侧，方向正好相反。FAST 论文报告：π0-FAST 与扩散版 π0 在跨本体通用策略上表现相当（含最难的叠衣物任务），但达到该表现所需的 GPU 小时数少约 5 倍；论文还给出了算力对齐的对照检查点，结论一致。

把这两组数字并排放，可以看出 π0.5 配方所利用的工程权衡；它们为“预训练用 FAST、部署用流匹配”提供量化动机，但不是在 π0.5 同一训练运行上的严格成本分解：

  • 训练侧：FAST 论文的 generalist π0-FAST 实验所需 GPU 小时约少 5 倍 → 支持阶段一用 FAST；
  • 推理侧：单个动作块约 750 ms 对 100 ms（比值约 7.5，由这两个数相除得到，FAST 论文本身没有写这个倍数）→ 所以部署只走流匹配。

π0.5 论文 Section V-D 明确把“FAST token 训练在计算效率上优于纯扩散训练”的结论关联到 FAST 工作；这里的 5 倍训练算力与 750/100 ms 延迟数字来自 FAST 论文的相应实验口径。

两个「7.5 倍」不要混为一谈。本页这个是推理延迟之比（750 ms ÷ 100 ms，FAST 论文 Section VI，NVIDIA 4090、1 秒动作块）；④ 知识隔离 里的 7.5 倍是 Knowledge Insulation 论文 Fig. 6 的原话——在 table bussing 的 generalist 实验中，π0 需要约 7.5 倍的训练步数才能达到相近表现。一个是推理速度、一个是训练步数，数值相近纯属巧合，互相之间不构成印证。

三、两阶段配方总览

论文 Fig. 3 把整条流程画在一张图里，左半是预训练、右半是后训练与推理：

把时间轴单独画出来，两阶段的差别集中在三件事：损失里 α 的取值、动作走哪种表示、动作专家在不在。

四、阶段一：280k 步离散预训练

论文 Section IV-C 的描述是：π0.5 「作为一个标准的自回归 transformer 训练，对文本、物体位置与 FAST 编码的动作 token做下一 token 预测」。

关键在于这一阶段四类监督信号形式完全相同，都是词表上的分类问题：

监督信号 来源 在序列里的形态
语言子任务 人工标注的 HL 数据 一句短语的 token
离散化动作 机器人数据经 FAST 分词 映射到 PaliGemma 词表尾部的 token
开放词汇描述 网络图文数据 描述文本的 token
边界框 物体定位数据与 HL 标注 位置坐标被编码成的 token

因此论文在这一阶段取 \(\alpha=0\)：连续动作的流匹配项被禁用，机器人动作改由 FAST token 的交叉熵监督，交叉熵也同时覆盖其他文本化目标。原始机器人数据当然仍含连续动作；“禁用”来自训练设计，而不是数据里没有动作。

这里要注意论文那句好评的归属对象。论文 Section IV-B 的原话是：这套方案「使我们得以先把模型当作标准 VLM transformer 来预训练，做法是把动作映射成文本 token（\(\alpha = 0\)），随后在后训练阶段再加入预测连续动作的动作专家权重」，接着才说「我们发现遵循这一流程（procedure）会带来稳定的预训练与优秀的语言跟随能力」。

也就是说，这句评价指向的是「α=0 预训练 + 后训练才引入动作专家」这一整套两阶段流程，而不是单独的「阶段一取 α=0」。把它读成后者，会得出「只要预训练时 α=0 就能获得好的语言跟随」这种论文并未支持的结论。

一个容易被忽略的细节：边界框不只是网络数据带来的副产品。论文 Section IV-C 在讲 HL 数据时明确写道，他们「标注当前观测中相关的边界框，并训练 π0.5 在预测子任务之前先预测它们」。也就是说高层输出本身是有内部顺序的：先定位，再决定做什么。这条的展开在本专题子页 ⑤。

五、阶段二：80k 步联合后训练

论文 Section IV-D 给出这一阶段的三个目的：把模型专门化到目标用例（家庭移动操作）、加入能产生连续动作块的动作专家、同时保住文本预测能力。

三件事情同时发生：

  • 动作专家被创建，且是随机权重。 原文：「the action expert … is initialized with random weights at the beginning of post-training」。源码中的零初始化 gate 会在第 0 步屏蔽 Transformer 注意力与前馈残差分支，但输入/输出投影和最终归一化仍参与计算；因此它降低随机块更新的直接扰动，却不能表述为“整个动作专家不参与”或“保证不会不稳定”。论文也没有把零 gate 明确写成随机初始化的原因。详见本专题子页 ② 第七节。
  • α 从 0 变成 10.0。 流匹配项被打开，其显式系数为 10；这个数不能跨损失量纲直接与交叉熵系数 1 比较重要性。
  • 交叉熵项没有被关掉。 论文明确说这一阶段「jointly trains with next-token prediction, to preserve text prediction capabilities」——它的作用从「唯一目标」变成了「防止语言能力在后训练中退化」。

数据构成也变了：

数据 阶段一 阶段二 阶段二的处理
MM 移动操作 有 有 过滤为成功且长度低于固定阈值的 episode
ME 多环境非移动 有 有 同上
CE 实验室跨本体 有 无 论文明确说后训练去掉 CE，以聚焦移动操作与多样环境
HL 高层子任务 有 部分 只保留多环境数据集对应的那一部分
WD 网络图文 有 有 保留，用于维持语义与视觉能力
VI 口头指令 无 有 后训练新增
VI 是这张表里最值得单独说的一项。论文的定义是：由专家用户提供「语言示范」——实时用语言遥操作机器人，一步步给出合适的子任务命令，让已经训好的低层策略去执行。所以 VI 采集到的不是动作，而是「对一个已有策略而言，什么样的高层子任务输出是好的」。它只占高层移动操作样本的约 11%，但论文 Section V-E 的消融显示去掉它会导致显著退化。

六、组合损失的完整定义

论文式 (1) 的完整形式是：

\[\mathcal{L}(\theta) \;=\; \mathbb{E}_{\mathcal{D},\,\tau,\,\omega} \Big[\; \underbrace{H\big(x_{1:M},\, f^{\ell}_{\theta}(o_t, \ell)\big)}_{\text{离散项：交叉熵，权重恒为 1}} \;+\; \alpha \cdot \underbrace{\big\lVert\, \omega - a_{t:t+H} \;-\; f^{a}_{\theta}\big(a^{\tau,\omega}_{t:t+H},\, o_t,\, \ell\big) \,\big\rVert^{2}}_{\text{连续项：流匹配，权重为 }\alpha} \;\Big]\]

其中含噪动作块按

\[a^{\tau,\omega}_{t:t+H} \;=\; \tau\, a_{t:t+H} \;+\; (1-\tau)\,\omega, \qquad \omega \sim \mathcal{N}(0, I),\qquad \tau \in [0, 1]\]

构造。符号逐项解释：

符号 含义
\(\mathcal{D}\) 训练数据分布。它是异构的：一条样本可能只有文本标签，也可能同时有动作标签
\(o_t\) 观测，论文定义为 \([I^1_t, \ldots, I^n_t,\ q_t]\)，即各路相机图像与本体状态
\(\ell\) 总任务指令，例如「put away the dishes」
\(x_{1:M}\) 目标文本 token 序列。论文明确说它包含 FAST 编码的动作 token，不只是自然语言
\(f^{\ell}_{\theta}\) 模型的文本 logits 输出头
\(H(\cdot,\cdot)\) 交叉熵
\(a_{t:t+H}\) 真实动作块。Appendix E 给出 action horizon 为 50，即 \(H = 49\)
\(\omega\) 与动作块同形的标准高斯噪声
\(\tau\) 流匹配时间。注意这里用的是论文约定，见下一节
\(a^{\tau,\omega}\) 噪声与真实动作之间的线性插值点
\(f^{a}_{\theta}\) 动作专家的输出，论文写明它是那个「较小的」专家
\(\omega - a_{t:t+H}\) 回归目标，即这条直线路径上的速度场，与 \(\tau\) 无关
\(\alpha\) 权衡系数。论文取 \(\alpha = 0\)（预训练）与 \(\alpha = 10.0\)（后训练）

三个容易读错的地方

  • 权重挂在流匹配项上，不是交叉熵项上。 式 (1) 里交叉熵项的系数恒为 1，\(\alpha\) 只乘在连续项前。因此「\(\alpha = 0\)」的含义非常干净：整个目标退化成一个标准 VLM 的下一 token 预测，动作专家的梯度为零——这正是它在阶段一可以根本不存在的原因。
  • 论文没有写指示函数。 一条纯图文样本没有动作标签，它的流匹配项自然无从计算；但论文式 (1) 是按「一个期望」写的，把这件事交给数据分布 \(\mathcal{D}\) 与批次构造去处理，而不是在损失里显式写一个开关。本页按论文原样书写。
  • \(\alpha = 10\) 并不意味着流匹配比语言重要十倍。 两项的单位、按 token/维度的归约方式和未经加权的数值尺度都不同；系数 10 只定义论文采用的优化权衡，不能当作语义重要性或梯度贡献的十倍。论文没有报告两项的实际损失/梯度尺度，也没有给出该取值的推导或消融，因此不应进一步断言它恰好把两项“拉到同一尺度”。

七、时间方向：论文约定与 openpi 约定的代换

π0.5 论文与 openpi 源码在流匹配时间的方向上是相反的，和 π0 的情况完全一样。本站全站统一按 openpi 约定书写，本页在上一节用论文符号写式 (1) 是为了与原文逐字对应，这里给出代换。

约定 记号 取 0 时是什么 取 1 时是什么 插值式
π0.5 论文 \(\tau\) 纯噪声 \(\omega\) 真实动作 \(a\) \(a^{\tau,\omega} = \tau a + (1-\tau)\omega\)
openpi 源码 \(t\) 真实动作 \(A\) 纯噪声 \(\epsilon\) \(x_t = t\,\epsilon + (1-t)A\)

代换关系就是一行：

\[\tau \;=\; 1 - t\]

代进去立刻可见两者逐字等同：

\[a^{\tau,\omega} \;=\; (1-t)\,a + t\,\omega \;=\; x_t\]

而回归目标在两套写法下是同一个表达式：论文写 \(\omega - a\)，源码写 u_t = noise - actions。

time = jax.random.beta(time_rng, 1.5, 1, batch_shape) * 0.999 + 0.001
x_t  = time * noise + (1 - time) * actions
u_t  = noise - actions
...
return jnp.mean(jnp.square(v_t - u_t), axis=-1)
这里只给代换，不重复讨论「论文的时间方向是否自洽」。那件事在 π0 上已经完整处理过：两套约定的换算、Beta 时间步在两种写法下的等价性证明、以及论文若干条陈述无法同时成立的精确指认，全部在 π0 专题子页 ③ 与 子页 ②。π0.5 论文 Appendix E 明确写「We follow π0 for sampling the flow-matching timestep τ」，采样分布与截断阈值均未改动，因此那两页的结论可直接套用。

八、论文用什么证据支撑「先离散后连续」

这是本页最值得记住的一组实验，因为它回答的是「两阶段配方到底是必要的，还是只是一种可行做法」。

论文 Section V-D 设了两个对照组：

模型 训练方式 数据 能否高层推理
π0 始终带着流匹配动作专家 同一份跨本体机器人训练集 否
π0-FAST+Flow 采用式 (1) 的混合配方（与 π0.5 相同） 只用含动作的数据，无 HL、无 WD 否
π0.5 混合配方：离散预训练加流匹配后训练 上述数据再加 HL 与 WD 是

论文强调这个对照尽量保持公平：三者拿到同一份跨本体机器人训练集、训练可比的步数。完整 π0.5 相对 π0 同时多了 HL/WD 共训练数据并采用混合训练流程；π0-FAST+Flow 则采用混合流程、但只使用含机器人动作的数据。因而 π0 与 π0-FAST+Flow 更接近“在 action-only 数据上比较训练流程”，而 π0-FAST+Flow 与 π0.5 主要显示加入 HL/WD 与高层能力后的完整系统差异。它仍不是所有条件完全相同的实验矩阵，页面不把任一模型差距归给单一因素。

结果是 π0.5 显著优于两者。作者还用下面这句支持「算力效率」结论：

论文原文：这个结果在把 π0 的训练延长到 300k 步时仍然成立，从而确认——正如 FAST 那篇工作所指出的——用 FAST token 训练在算力上比纯扩散式训练更有效。

准确的读法是：把 π0 延长到 300k 步后总体排序不变，说明结果不能简单解释为 π0 基线步数过少，并与 FAST 论文的 compute-matched 结论一致。它不能证明“所有差距都只来自离散目标”：完整 π0.5 的总训练是 280k + 80k = 360k 步，且加入了 HL/WD；论文也没有给出本页可换算成 FLOPs 的逐模型成本。因而“FAST token 训练在算力上更有效”应保留为作者结合 π0-FAST+Flow 与既有 FAST 证据得出的结论，而不是由“300k 大于 280k”单独推出来。

为什么离散目标在训练期更”划算”

π0.5 论文在本节没有展开机制，但 FAST 论文给出了更可靠的解释。重点不是“分类天然比回归信息更多”，而是动作分词是否移除了高频轨迹里的时间冗余：

  • 朴素逐时间步分箱时，相邻 token 高度可预测，条件边际信息量随控制频率升高而降低；模型容易靠复制前值降低损失。FAST 先用 DCT 集中轨迹信息、再量化和 BPE 压缩，使每个输出 token 覆盖更长时间结构，提升 next-token 目标的有效学习信号。
  • 离散动作、文本、边界框和子任务可以复用词嵌入/输出头与交叉熵训练接口；连续动作仍需要独立的流匹配头。这里的好处是目标和工具链统一，不表示每个 minibatch 必须同时含所有数据类型，也不表示所有样本更新完全相同的参数集合。

这两点解释“为什么 FAST 式离散目标可能收敛更快”，但具体 5 倍结果仍依赖 FAST 论文的模型、数据、硬件与停止标准，不能当作 π0.5 所有设置中的固定倍数。

九、动作数据的口径：归一化与维度补齐

这一节的内容不起眼，但它是复现时最容易出错的地方，而且与本专题子页 ② 讲的状态离散化共用同一个区间。

论文 Section IV-C 给出三条口径：

  • 预测目标同时包含关节位姿与末端位姿。 为了区分这两种控制模式，论文在文本 prompt 里加一段 <control mode> joint/end effector <control mode> 标记。也就是说控制模式不是一个网络分支，而是一段提示词。
  • 归一化用分位数而不是极值。 每个动作维度按该数据集自身的 1% 与 99% 分位数归一化到 \([-1, 1]\)。用分位数而非最大最小值，是为了让少数极端样本不把整个区间撑开、导致绝大多数动作被压在中间一小段里。
  • 维度取固定值加零填充。 动作维度设为能容纳所有数据集中最大动作空间的固定数；自由度较低的机器人，动作向量补零。

这里还要区分论文与公开实现的口径：论文此处明确说的是动作按分位数归一化；公开 openpi 的预处理也会把本体 state 归一化，再由 tokenizer 按固定阈值离散。tokenizer 本身不裁剪：低于 \(-1\) 的 state 会得到 -1，达到最后一个阈值（约 0.9922）及以上则得到 255。因此口径不一致可能导致边界饱和或范围外编号，但不是“所有越界值都进首尾两档”，也不能直接推成“完全没有本体反馈”。精确边界与排查见子页 ② 与 ⑦。
