VLA/RLHF-VLA/基础概念与方法坐标

Foundations · taxonomy · boundary

先定义反馈是什么，再决定谁能消费它

observed feedback ≠ latent target；producer ≠ semantics ≠ optimizer；intervention event can derive multiple supervised views；source-domain evidence ≠ target VLA evidence。

本页只建立术语、方法边界、风险和交接合同，不把标题中的 “human”“preference” 或 “RLHF” 当作方法证明，也不把代理分数当任务成功或安全许可。

目标、反馈、派生信号、奖励、回报与价值

潜在目标写作 $U_{p,t}(\tau,c)$：它依赖 producer/population、时间 $t$、轨迹 $\tau$ 与上下文 $c$，不可直接观测，也不假定跨人、跨任务或跨时稳定。一次比较、评分、接管或纠正只是特定 query、exposure、interface 与 producer state 下的观测事件 $f_e$；它不是目标本身。

1 · Latent target / utility$U_{p,t}(\tau,c)$；不可观测，必须保留 context、population、time 与 uncertainty。
2 · Feedback event$f_e$；原始事实，带 query、exposure、selection、producer、scope 与时间。
3 · Derived signal$d_e^v$；按 versioned rule 从 parent events 派生的 label、preference、reward 或 cost。
4 · Proxy model$R_\phi$ 或 preference model；有限 feedback/data 上训练的代理输出，不是 ground truth。
5 · Sample return$G_t$；给定 reward、discount、termination、bootstrap、mask 与 horizon revision 后的随机和。
6 · Value$V^\pi/Q^\pi$；给定 policy、condition/action 与 reward revision 的未来 return 条件期望估计。

站点采用以下观测 formalization，而不是“人类效用可被准确读取”的主张：

f_e ~ p(f | target_context, compared_items, producer_state,
        query_policy, exposure, interface, time, noise)

定义 $G_t$ 前要固定 reward revision、step/chunk、discount exponent、terminal/truncation/bootstrap、valid mask 与 horizon。若 $R_\phi$ 输出 segment/trajectory score，如何得到逐步 $\tilde r_t$ 必须另有 conversion record；Reward Model 与 Critic 的监督来源、更新阶段和语义也必须分开。

禁止替换： RM score ≠ derived reward ≠ return ≠ value ≠ success ≠ safety。它们即使都是标量，也不能共享含义、单位、证据或发布权限。

比较、评分、轨迹、干预与纠正

“反馈”不是一种数据类型。每条记录先定义语义，再定义被比较对象和作用范围：preference relation 是带条件的相对关系；pairwise comparison 可为 left/right/tie/abstain/unknown；listwise ranking 是两个以上对象的全序、偏序或分组；binary desirability 是单对象 desirable/undesirable/unknown，不要求同 query 内存在配对。

scalar/evaluative feedback 必须有量表、方向、范围与校准；trajectory feedback 还要说明 whole/segment/stage scope。intervention decision 是某 causal window 内接管、否决或切换 authority 的事件，而 correction/demonstration 是实际给出的目标动作或恢复轨迹，两者不能合并。language critique 需要 parser revision、PII/secret redaction 与不确定性；outcome/verifier signal 必须保留环境、规则或 verifier 的来源和 authority。

Relativepairwise · listwise · partial order；tie/abstain/unknown 是合法结果。
Single-itembinary desirability · scalar · attribute；量表与校准不能省略。
Temporalsegment · stage · trajectory · outcome；不自动解决逐步 credit assignment。
Interactiveintervention decision ≠ correction action；authority 与 action provenance 分开。

作用域固定为 action | chunk | segment | stage | trajectory | episode-result。四个主时钟是 sensor、policy-decision、execution、feedback；command timestamp 作为 decision→execution 链的一部分记录。缺 scope、clock 或 causal window 时，不得派生 action-level label。comparison、score 和 intervention 都受 query selection、interface、exposure、latency、experience/fatigue 与 missingness 影响；不能把 tie/abstain/unknown 强转 winner 或零值。

反馈来源 × 优化方式二维坐标

来源轴回答“谁产生观测”：human、AI/VLM、rule/verifier、environment、mixed；优化轴回答“哪张计算图消费派生信号”：BC/SFT、learned RM+RL、direct preference、trajectory preference、feedback-as-reward RL、evaluation-only。角色与 authority 要另列，来源不证明正确性，optimizer 也不能反推出真人标签。

Producer × optimizer 坐标；P=possible，D=paper-demonstrated，T=target-validated，I=incompatible，?=unknown。状态必须附 evidence、semantics 与 policy-interface，单字母不是结论。

表中 D 只表示某个固定来源已展示该组合，不表示本网站目标 VLA 已验证。human pair 可进入 RM+RL 或 direct objective；AI comparison 可进入 RLAIF-style RM+RL；rule/environment outcome 可进入 verifier-style reward；VLP 的视觉语言偏好与 GRAPE 的轨迹 cost/preference 是自动构造，不是逐条真人标签；RLIF 则是 human intervention 派生 reward 后由 off-policy RL 消费。

BC、DAgger/HG 与 preference learning

BC / SFT消费 target action/sequence。stochastic normalized policy 可用 NLL；deterministic、diffusion、flow 需各自监督目标，不能统一写成 $-\log\pi(a\mid c)$。
DAgger在 learner 访问到的状态上查询 expert action 并聚合；核心仍是 action supervision。
HG-DAggerintervention timing/control authority 是采集机制；corrective action 才是模仿监督，不会自动变成 reward。
Preference / RL消费 pair、desirability、trajectory preference 或派生 reward；需要独立的 semantics、derivation 与 optimizer 合同。

同一 episode 可以产生 correction view 与 preference/reward view，但必须使用不同 dataset/view IDs、inclusion/mask rules、split-group/parent lineage，并分别报告人力、安全成本和效果。若同一 parent event 的不同 view 被拆到 train 与 evaluation，应按 parent lineage 阻断泄漏，而不是只看文件名或 row ID。

组合不等于替代：HG-DAgger 可以采集动作和接管事实，APO-like view 可以从经过因果审查的窗口派生 binary desirability，RLIF-like view 可以派生 intervention reward；这三者的 counterfactual assumption、梯度和证据都不同。HG-DAgger 正确入口是 人工门控的数据聚合，不存在 /vla/hg-dagger/ 这一 canonical。

显式 Reward Model + RL

显式 learned-reward 路线的最小计算图是 feedback dataset → reward/preference model → reward conversion → rollout/replay → return/advantage/TD → policy update → candidate evaluation。Christiano-style 方法从 human pairwise trajectory segments 学 reward 再做 RL；InstructGPT 展示 demonstrations→SFT、rankings→RM、PPO fine-tuning。两者分别来自模拟控制/Atari与语言模型域，不是任意机器人 VLA 的验证结果。

RM 从 preference/scalar labels 学 proxy quality/reward；Critic 从指定 reward revision 下的 return/TD target 学 policy-dependent future return。RM 可以给 segment/trajectory 打分，Critic 则必须绑定 state/action/time semantics。两者可以同存，但不能因网络形状相似而共用“value”名称。

KL 或 log-ratio 必须固定 current/reference artifact、action random variable、support/measure、condition、mask、chunk/sequence normalization、transform/Jacobian 与 behavior data source。单个 sample log-ratio 可以为负，不代表作为期望定义的 KL divergence 为负。PPO 是 on-policy-ish policy-gradient family；SAC/off-policy actor-critic 使用 replay/TD 合同。它们是优化器，不是“人类反馈方法”，也不能默认适配所有 action head。

RM validation accuracy 只检查已采样 feedback distribution。policy 优化会改变分布，因此还要检查 calibration、held-out/OOD、reward hacking/overoptimization、independent task metric 与 safety/reliability metric；proxy 上升不能单独批准 Candidate。

DPO、KTO、APO 与可取性

DPO · pair同 condition 的 chosen/rejected；current/reference 必须在相同 random variable、support、measure、mask 与 normalization 上可比较。
KTO · single desirability消费 single desirable/undesirable signal（单项），不要求逐项 pair；ICML 2024 原始证据域是 LLM。
APO · intervention-derived desirabilityAction Preference Optimization；human intervention 派生 binary action desirability，绑定论文的自回归 action-token 接口。

DPO 的机器人记号使用 condition $c$ 与明确定义的 action、chunk 或 trajectory objects，而不是把语言变量 $x,y_w,y_l$ 原样当物理动作。记录必须包含 same-condition rule、chosen/rejected construction、current/reference identity、support compatibility、$\beta$/temperature scope、token/step/chunk mask、offline source 与 distribution shift。原论文的等价关系有 KL-regularized reward-modeling assumptions；它不证明任意 continuous policy 都有可用的 exact log-prob。

KTO 只需要 desirable/undesirable interface，但“较易采集”不是机器人性能或安全保证。APO 以 arXiv:2506.07127v3 和作者 Action-Preference-Optimization 为固定来源；human intervention、class balance、continuous-action-error reweighting 属于该具体方法。早期/项目语境出现 HAPO 时只作为 alias/source-version 记录，不能扩张为所有非自回归、diffusion、flow 或 deterministic head 的结论。

Direct 不等于 objective-free：即便没有独立 RM 或 Critic，仍有 reference dependence、proxy assumptions、dataset/query bias、OOD shift 与独立安全评估。DPO/KTO 的来源域是语言模型；APO 有机器人实验但 protocol/action-interface scope 受限，迁移状态应逐目标 artifact 重新登记。

同一接管事件的四种派生

原始 intervention event 是不可变父记录：至少含 detect/request/grant/execute/release times，pre/post proposed、commanded、safe、executed actions，behavior/candidate/safety revisions，operator pseudonymous role/authority、reason、uncertainty、incident relation 与四时钟 receipt。派生视图不能覆盖这些事实。

安全 authority、人力成本与证据层级

feedback producer、annotation aggregator、trainer、task evaluator、release approver、safety owner 与 operator 是不同 authority。同一人可以兼任，但 manifest 必须逐角色登记并触发 independence review。人工接管不是独立硬安全层；RM、preference model、verifier 或自动 evaluator 也不能替代 safety controller、site approval 或 rollback authority。

1 · Feedback qualityagreement、calibration、latency、coverage、tie/abstain/missing。
2 · Proxy qualityRM/preference prediction、held-out、OOD、optimization pressure。
3 · Task qualityindependent protocol 下的 success、efficiency、generalization。
4 · Safety / reliabilityincident、near miss、constraint、intervention、rollback。
5 · Human / data costquery、exposure、time、labor、supervision、consent 与 retention。

五层不互相继承。每个 claim 标 source-domain fact | target-domain evidence | transfer hypothesis | site formalization | unknown，并记录 falsifier 和 missing evidence。训练 labeler/自动 evaluator 同时决定 release 时，状态必须为 independence conflict，等待独立复核。

一手来源与迁移边界

  • Deep RL from Human Preferences v4：human pairwise trajectory segments→learned reward→RL；Atari/模拟 locomotion 来源域。
  • InstructGPT v1：demonstrations→SFT、rankings→RM、PPO；语言模型来源域。
  • DPO v3 与 KTO / ICML 2024：pair 或 single desirability 的 direct objectives；原始证据域是语言模型。
  • APO v3 与 官方项目：intervention-derived binary action desirability；机器人证据绑定具体自回归 action-token protocol。
  • RLIF v2：intervention signal 派生 reward 并用于 off-policy RL；不是 pairwise preference 或 corrective imitation。
  • Uni-RLHF v2：多反馈平台、数据与 modular offline baselines；不证明全部 VLA 分支。
  • VLP v1：构造无人工标注的 vision-language preference dataset；实验为模拟具身 manipulation。
  • GRAPE v2：VLM/keypoint/stage constraints 构造 trajectory cost/preference；不是逐条 human label。
  • Constitutional AI / RLAIF v1：模型比较 samples、训练 preference model 并以其作 RL reward；语言模型来源域。
  • Reward Model Overoptimization v1：提供 proxy/gold overoptimization 风险证据；公开定量不外推机器人。
