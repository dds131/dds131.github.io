知识库 · 机器人模仿学习与 VLA · RTC · Guided Inpainting
  • 必读前驱：先完成 RTC Foundations，并能区分绝对 tick、s_plan/s_run、d_hat/d_meas、proposal/committed/dispatched 与 authority epoch。
  • 范围：本页只拥有推理期 guidance 数学和 sampler contract；线程、queue、timeout、merge、dispatch 与 fallback 归 Runtime。
  • 安全：所有公式、伪代码和数值示例仅用于教育与静态核验，不是可直接部署的控制器，不运行模型、仿真或机器人，不上传，也不自动备份。

Guided RTC 在兼容 Flow/Diffusion policy 的每个生成步上，用旧块的对齐动作约束修正当前采样速度；它不更新模型参数，也不是在生成结束后把两个动作块做平均。

  • 从 branch contract 构造有绝对 tick、validity 与 ABI 证据的目标 Y 和权重 W。
  • 用统一列向量约定解释最终动作估计、加权误差与 vector–Jacobian product。
  • 验证 Hard/Soft Mask、guidance coefficient、finite 状态和 Runtime handoff，不把 proposal 直接当 executed action。

Guided 分支：在生成过程中做条件补全

四个角色，各有边界

Inpainting

用已知或可信时间位置约束未知后缀。目标必须带 frame、unit、anchor、tick 与 provenance，不能从相同 shape 推断语义。

VJP

把最终动作空间的误差拉回当前采样状态。它依赖 reverse-mode autodiff，只避免显式完整 Jacobian，不表示没有反向成本。

Soft Mask

让重叠区权重随未来距离衰减。它是 guidance 时间权重，不是 output blend、Transformer attention 或低层滤波器。

beta

限制 guidance coefficient 的最大值。具体值依赖 policy、solver、动作缩放与评测协议，不是跨模型默认参数。

“无需重训练”有七道兼容门槛

| 条件 | 必须满足 | 不满足时 | | — | — | — | | 生成器 | diffusion/flow 类迭代生成，能暴露采样状态和速度或去噪映射 | 不宣称可直接使用 Guided RTC | | 自动微分 | 能对 A^tau -> A_hat^1_tau 做 VJP | 比较 Training-Time 或其他方法，不伪造近似 | | 动作块 | horizon 可声明，局部 index 能映射绝对 tick | 返回 Foundations 修复 contract | | 动作语义 | old/new action_abi_hash 一致或有版本化 adapter | 拒绝构造误差 | | provenance | 能取得 actual committed/dispatched 旧动作，不只 proposal | 标记证据不足，阻止可部署状态 | | authority | source/epoch 未变化，或已重建 prefix | 丢弃旧目标并交给 Runtime | | 数值域 | policy sample 与 Y 在同一规范化空间 | 先转换、核验并保存 adapter hash |

绿色勾号不能概括任意 policy。兼容 iterative sampler 仍可能在 mixed precision、编译、显存、VJP 延迟或少步积分上失败；这些是要测量的实现事实，不应从方法名称推断。

Guided 发生在采样轨迹内，不是生成后修补

post-hoc smoothing 已经得到两个完整动作块，再对输出边界做插值、滤波或平均；Guided RTC 则在每个生成步计算当前样本的最终动作估计，用对齐旧目标形成误差，再通过 VJP 改写当前积分速度。两者的因果位置不同：前者看不到生成器内部 Jacobian，后者让约束参与后续全部积分步骤。即使最后曲线相似，也不能据此把两种方法写成等价。

Guided 也不是硬拷贝旧块。Hard prefix 与 soft overlap 只在 validity、ABI、authority 和绝对 tick 证据成立时产生直接误差；free suffix 仍由当前 observation 与基础 policy 决定。共享网络会让局部约束影响整个样本，因此“某位置权重为零”不保证该 token 与 prefix 完全统计独立，也不意味着远期动作无需检查。

这一分支的输出身份始终是 candidate proposal。它没有权力确认实际 d_meas、撤销已经 committed 的 queue、改变 controller authority 或越过 safety gate。若文章、代码或 UI 把 sampler 返回直接叫作 executed chunk，会掩盖 Runtime 的验证/合并与实际 dispatch 之间的关键边界。

Flow 时间方向与基础采样

本页固定 tau=0 噪声、tau=1 动作

对动作块 A in R^(H x M) 与同形状噪声 epsilon，采用线性条件路径：

\[\mathbf A^\tau=(1-\tau)\boldsymbol\epsilon+\tau\mathbf A, \qquad \tau\in[0,1].\]

端点和条件速度为：

\[\mathbf A^0=\boldsymbol\epsilon, \qquad \mathbf A^1=\mathbf A, \qquad \mathbf u_\tau=\frac{\mathrm d\mathbf A^\tau}{\mathrm d\tau}=\mathbf A-\boldsymbol\epsilon.\]

policy 学习条件速度场 v_theta(A^tau,o,tau)，shape 为 [H,M]。完整 Flow Matching 训练推导见 π0 · Flow Matching；本页只需知道普通 sampler 从噪声端沿速度场积分到动作端，Guided RTC 不改变基础 policy 参数。

flowchart LR
  N["tau=0<br/>noise epsilon"] -->|"integrate v_theta(A^tau,o,tau)"| S["intermediate sample A^tau"] --> A["tau=1<br/>action proposal"]
  T["model-native time t"] -. "explicit adapter: tau=1-t" .-> S

图 1｜Flow 时间方向。 tau 是 sampler 的生成时间，不是 wall clock 或 control tick。若 policy 原生采用 t=1 噪声、t=0 动作，adapter 必须同时处理端点、速度符号、步长方向与 scheduler 顺序；只改变量名不够。

最小 Euler 采样与端点

若离散步数为 n_flow：

\[\Delta\tau=\frac{1}{n_{\mathrm{flow}}}, \qquad \tau_k=\frac{k}{n_{\mathrm{flow}}}, \quad k=0,\ldots,n_{\mathrm{flow}}-1,\] \[\mathbf A^{\tau_{k+1}} = \mathbf A^{\tau_k} + \Delta\tau\, \mathbf v_\theta(\mathbf A^{\tau_k},\mathbf o,\tau_k).\]

最后一次速度在 tau=(n_flow-1)/n_flow 求值，更新后到 tau=1；这个 Euler 日程不在 tau=1 再求速度。使用其他 solver、不均匀 grid 或 adaptive step 时，要记录 solver、实际 tau_k 和 step size，不能沿用本段端点结论。

时间方向 property tests

  • tau=0 映射噪声输入，tau=1 映射动作输出；反向约定 adapter 在两端完全互换。
  • 转换后速度符号与积分方向正确；一个可解析常速度场应到达相同终点。
  • time tensor 的 dtype/device 与 policy 一致，n_flow>=1，每个 tau_k finite 且单调。
  • trace 同时写 rtc_time=tau 与适用的 model_time=t，禁止把两列都命名为 time。
  • 生成时间不与 d_meas、control tick 或 monotonic duration 相加。

Time adapter 要有可复算的审计

时间方向 adapter 至少冻结四件事：模型原生端点、本站 tau 端点、velocity/denoiser 的符号变换、solver 的迭代顺序。对于 velocity parameterization，简单令 tau=1-t 可能还需要相应翻转导数方向；对于直接预测 denoised action 或 noise 的模型，最终估计公式也未必与本文速度场形式相同。兼容性必须根据 policy contract 推导，不能只看 API 参数也叫 time。

审计用三个小型 oracle。第一，常速度场的解析终点应在原生和转换坐标中一致；第二，identity denoiser 的 pullback 应返回可预测结果；第三，正向 grid 与映射后的反向 grid 应逐步一一对应。每项记录输入 shape、dtype、device、tolerance 与 software revision。若端点只能近似相等，报告误差与原因，不用布尔 pass 隐藏精度问题。

自适应 solver 还会改变求值点数量与顺序。此时 n_flow 只能表示配置上限或接受步数之一，必须另存 actual evaluation count、accepted/rejected steps 与 time grid artifact。后文关于 tau=0.8 的结论只属于特定五步 Euler，不能迁移到自适应求解器。

flow_time_mapping:
  rtc_time_convention: noise_0_action_1
  model_time_convention: "<enum>"
  adapter_ref: "<artifact-ref|null>"
  solver: "<enum>"
  n_flow: "<positive-int>"
  time_grid_ref: "<artifact-ref>"
  endpoint_property_test: "<pass|fail>"

从旧块构造可核验的 Inpainting 目标

输入来自 branch contract，不从数组猜时间

Guided sampler 至少读取 request_id、observation_id、old_chunk_id、old/new anchor tick、old actual action reference、committed/dispatched range、H/M/s_plan/s_run/d_hat、Action ABI、authority source/epoch、normalization artifact 与 clock/control session。字段缺失时保持 null 并拒绝“可部署”状态，不能从长度或上一次进程内变量补造。

old_actual_action_ref 优先指向经 safety/controller 修改后实际进入队列或执行历史的动作。若只有模型 proposal，目标可以用于受限离线分析，但页面必须显示“不能证明 prefix 与机器人实际状态一致”。authority epoch 改变后，旧目标默认失效；Runtime 若能建立新 provenance，必须产生新 contract，而不是复用旧 hash。

用绝对 tick join 构造 Y 与 validity

对旧局部索引 j 和新局部索引 i：

\[k_{\mathrm{old}}+j=k_{\mathrm{new}}+i.\]

只有满足等式、ABI 一致且 source validity 为真的位置才写入 Y_i。构造结果包括：

| 字段 | shape / 类型 | 含义 | | — | — | — | | Y | [H,M] finite tensor | 已转换到 policy 比较空间的旧块目标 | | validity | [H] boolean | 该位置是否有可追溯、可比较目标 | | source_idx | [H] nullable int | 对应的旧块局部 index | | source_tick | [H] absolute tick | 两块共享的物理控制 tick | | source_kind | enum | proposal / committed / dispatched / feedback | | authority_epoch | opaque | 目标属于哪一次控制权代次 |

无旧块对应的位置可用任意有限占位值补齐 shape，但必须 validity=false 且最终 W=0。不能依赖 NaN * 0 得到零，因为 IEEE 浮点仍可能传播 NaN；占位值、validity 与 mask 合成顺序都要测试。

aligned_target_manifest:
  alignment: absolute_control_tick
  old_chunk_id: "<opaque>"
  old_actual_action_ref: "<artifact-ref>"
  new_chunk_anchor_tick: "<int>"
  action_abi_hash: "<sha256>"
  normalization_artifact_ref: "<artifact-ref>"
  authority_epoch: "<opaque>"
  target_ref: "<artifact-ref>"
  validity_ref: "<artifact-ref>"
  source_tick_range: "[start,end)"

A_cur[s:H] 只是论文理想化简写

原算法可写 A_prev=A_cur[s:H]，但它只在固定控制频率、无 skipped tick、旧 anchor 未变化、s=s_run、局部 index 连续、authority/epoch 相同且 safety 修改可追溯时，等价于绝对 tick join。本页保留该式用于定位论文，不把它当通用实现接口。

如果 s_plan 与 s_run 因 jitter 不同，或 Runtime 已多提交若干 tick，按配置切片会产生 off-by-one。若 relative action 以不同状态为 anchor，甚至相同 tick 也要先重锚定；若 controller 记录实际 dispatched action，则不能用原模型 proposal 覆盖它。

Target provenance 决定约束是否可信

同一 target tick 可能同时存在 model proposal、queue committed、controller dispatched 与 execution feedback 四种记录。它们不是可以任意替换的“旧动作”。proposal 表示模型当时想做什么；committed 表示 Runtime 已保证不会撤回；dispatched 表示控制器接口收到什么；feedback 表示平台能观测到的实际结果。Guidance 选用哪一种，必须写入 source_kind 并说明平台延迟和可用性。

通常优先使用最接近实际 authority 的可追溯记录，但并非总能等待 feedback：feedback 可能晚于下一次推理启动，或只包含状态而不是命令。此时可使用 committed/dispatched 动作，同时把未确认部分标成相应 evidence class。绝不能把暂缺 feedback 写成“已执行”，也不能用未来才到达的 feedback 回填在线决策记录而不改变版本。

如果 safety gate 对一部分维度限幅、替换或 veto，目标要么引用修改后动作，要么让对应 validity=false。若人类接管导致 authority epoch 变化，旧 policy prefix 整体失效，除非新 owner 明确签发转换 contract。若 clock session 重启、source tick 跨域不明或 adapter hash 变化，也应返回 typed rejection，不做最近邻 index 猜测。

目标构造后可做双向一致性检查：每个 valid 新索引都能反查唯一旧 source index/tick；每个 source tick 最多映射一个新位置；region 与 validity 交集没有越过 ABI/authority 边界；manifest hash 能复算。重复 tick、缺口或多对一映射均要显式报告。

三段强度不改变 Runtime 派发边界

  • [0,d)：新块 ready 时已经过期，但可在生成中作为 hard guidance；Runtime 不得重新 dispatch。
  • [d,H-s)：仍与旧块对应的 soft overlap；目标的 provenance 与 validity 继续生效。
  • [H-s,H)：旧块没有直接目标的 free suffix；其 W=0，由基础 policy 和新观测生成。

这里的 d/s 是论文理想化符号；实际 sampler 用冻结的 d_hat 构造 mask，结果 ready 后 Runtime 再用 d_meas、merge 时刻、queue 与 authority 求真正可派发起点。“hard”只表示 guidance 强度，不表示这些位置会在新块中再次执行。

最终动作估计、加权误差与 VJP

从当前状态外推到动作端

在当前 Flow 状态上，把速度在剩余生成区间近似保持不变：

\[\widehat{\mathbf A}^{1}_{\tau} = \mathbf A^{\tau} + (1-\tau)\, \mathbf v_\theta(\mathbf A^{\tau},\mathbf o,\tau).\]

A_hat^1_tau 是当前采样状态上的 denoising function，不是新网络头，也不是已完成的真实动作。它依赖冻结观测、当前随机样本、time convention 与 policy 速度场；非线性速度场、粗 grid、少步 solver 和数值精度都会使“一步外推到终点”存在误差。

统一列向量与广播约定

把 [H,M] 张量按固定 row-major 规则展平为 HM 维列向量。时间权重广播为：

\[\widetilde{\mathbf W}=\mathbf W\otimes\mathbf 1_M.\]

加权误差是：

\[\mathbf e_\tau = \widetilde{\mathbf W} \odot \left( \mathbf Y-\widehat{\mathbf A}^{1}_{\tau} \right).\]

误差的 shape 为 [H,M]。Y 与 A_hat 必须处于同一 action ABI 和规范化空间；W 先与 validity 合成，再只沿 action dimension 广播。禁止让 [H] 权重意外沿 batch 或错误的 feature 轴广播。

VJP 把误差拉回当前采样状态

概念 Jacobian 为：

\[\mathbf J_\tau = \frac{\partial\operatorname{vec}(\widehat{\mathbf A}^{1}_{\tau})} {\partial\operatorname{vec}(\mathbf A^{\tau})}.\]

修正方向采用列向量约定：

\[\operatorname{vec}(\mathbf g_\tau) = \mathbf J_\tau^{\mathsf T} \operatorname{vec}(\mathbf e_\tau).\]

实现用 reverse-mode vector–Jacobian product，不实例化 [HM,HM] Jacobian。vjp(denoiser,A_tau) 返回 A_hat 与 pullback，以 e_tau 为 cotangent 调用 pullback，结果必须与 A_tau 同 shape。这不是 J e 的 JVP，也不是对模型参数做 optimizer step。

policy 参数参与前向和求导图，但本页只对当前 sample state A^tau 求导；Y、W、observation 与 contract metadata 按常量处理，不更新权重。mixed precision、activation checkpointing、编译与 peak memory 要测量；“无显式 Jacobian”不能翻译成“无反向开销”。

用解析小模型区分 VJP、JVP 与参数梯度

令教学 denoiser 为 f(x)=Bx+c，其中 x、e 为列向量。正确 pullback 是 B^T e；JVP 则是 B e，只有在特定对称矩阵上才会偶然相同。测试矩阵应故意选非对称、非方阵分块或具有不同尺度的结构，避免错误实现因简单 identity case 通过。再用有限差分验证标量 e^T f(x) 对 x 的梯度，但有限差分只作为测试 oracle。

参数梯度是另一条轴。若 f_theta(x) 含模型参数，autodiff 系统可能默认追踪 theta；本页要求冻结参数叶节点，不建立 optimizer state，也不调用 update。测试应断言采样后 checkpoint hash 未变、参数 grad 未被持久化、随机数状态只按声明推进。不能仅凭“没有 optimizer”就认定没有意外参数梯度或显存占用。

Y/W 按常量处理也需要验证：把 target 或 mask 标成可导张量可能造成无意义梯度和额外内存。pullback 返回若是 tuple，要明确只取 A_tau 分量，并检查 aux 输出不改变求导接口。compile/checkpointing 可能重算前向，因此 observation adapter 若有副作用或非确定状态，会破坏 VJP；此类 adapter 必须纯函数化或在 contract 中拒绝。

数值报告至少比较 v_norm、e_norm、g_norm 与 lambda*g 范数，并标 dtype。极小 error 配合巨大 Jacobian 仍可产生大修正；反之，large error 也可能落在低敏感方向。只画 error 下降曲线不足以证明引导工作正确。

最小接口伪代码

function denoiser(a_tau, observation, tau):
    v_tau = policy_velocity(a_tau, observation, tau)
    a_hat = a_tau + (1 - tau) * v_tau
    return a_hat, v_tau

a_hat, pullback, v_tau = vjp(denoiser, a_tau, observation, tau,
                              differentiate_only = a_tau)
error = broadcast_time_weights(weights, action_dim=M) * (target - a_hat)
g_tau = pullback(error)
require shape(g_tau) == shape(a_tau) == [H,M]

differentiate_only 是语言无关的接口说明，不承诺具体框架存在同名参数；框架 API 映射须在 Source Code 页固定 commit 后再写。

Hard Mask 与 Soft Mask

Hard Mask 只直接约束确定前缀

\[W_i^{\mathrm{hard}} = \begin{cases} 1,&0\le i<d,\\ 0,&d\le i<H. \end{cases}\]

d=0 时 Hard Mask 全零。d>=H 表示新块返回时所有 nominal 位置均过期，不能静默变成全一后继续 merge。Hard Mask 语义清晰，但 d 很小时携带的策略模式信息可能不足；VJP 仍只是近似条件化。

原论文 Soft Mask 与适用域

仅在 0<=d<=s<=H-d 的论文理想化条件下：

\[W_i = \begin{cases} 1,&i<d,\\[3pt] c_i\dfrac{e^{c_i}-1}{e-1},&d\le i<H-s,\\[8pt] 0,&i\ge H-s, \end{cases}\]

其中：

\[c_i=\frac{H-s-i}{H-s-d+1}, \qquad i\in\{0,\ldots,H-1\}.\]

公式里的 s/d 是论文符号；站内 contract 保存 s_run/d_hat/d_meas，并以绝对 tick 计算有效 overlap。LeRobot 或其他实现中的同名 execution_horizon 不能未经版本核对直接代入。

权重语义与常见误读

| 区间 | Soft 权重 | 语义 | 禁止误读 | | — | — | — | — | | [0,d) | 1 | hard guidance；目标来自确定/实际旧前缀 | 不代表新块重放这些动作 | | [d,H-s) | (0,1) 衰减 | 保留旧模式信息，同时允许新观测修正 | 不是新旧 output 线性混合 | | [H-s,H) | 0 | 无直接旧目标误差的 free suffix | 不代表网络耦合影响为零 |

Soft Mask 中的“attention”只是通俗的 guidance 权重描述，不是 Transformer attention 权重或新注意力层。W_i=0 仅说明该位置没有直接误差项；共享网络和 VJP 可能让其他位置的约束间接影响它。

一个静态索引例子只验证区间

取明显虚构的 H=8,d=2,s=3，则 hard prefix 是 [0,2)，soft overlap 是 [2,5)，free suffix 是 [5,8)。Soft 公式只在索引 2、3、4 上求值，index 1 必须仍为 1，index 5 必须已经为 0。这个例子验证 half-open boundary 与 shape，不给出控制频率、机器人动作或推荐配置。

若 validity 在 index 3 为 false，最终权重必须在生成误差前置零，即便 Soft 公式原本给出正值。实现最好分开保存 W_formula 与 W_effective=where(validity,W_formula,0) 的 digest，便于区分公式错误和 provenance 缺口。若直接覆写唯一 mask，事后很难判断某个零来自 free suffix 还是无效 target。

H-s=d 时 soft 区为空，不应进入分母或索引循环；d=0 时 hard 区为空，但 soft 区可存在；s=H,d=0 时所有位置 free。若 d>H-s，不是把负长度改成零就能恢复论文可行域，因为旧块已无法覆盖到新块 ready。typed error 必须保留输入和失败规则，交给 Runtime 选择降级。

Mask 单调性只约束直接权重，不保证 e_norm、g_norm 或最终动作差随 index 单调。网络耦合、动作 scale 和 Jacobian 都会改变结果。因此可视化应把 weight curve 与 action/diagnostic curve 分开，避免把漂亮的衰减形状误读为动力学平滑证明。

Mask property tests

对合法整数网格 H=1..64 与所有合法 d/s，至少断言：shape 恰为 [H]、显式浮点 dtype、所有元素 finite、0<=W_i<=1、hard prefix 全一、free suffix 全零、soft 区随 index 非增、validity=false 的位置最终为零。i=d-1/d 与 i=H-s-1/H-s 单独检查 off-by-one。

d=0、H-s=d、s=H 分别覆盖 hard empty、soft empty 和 overlap empty。d>s、d>H-s、H-s-d<0、d>=H 必须返回 typed error 或有记录的降级，不能靠 clamp、负 slice 或广播偶然运行。广播后 shape 必须是 [H,M]，并验证无效位置的任意有限占位值不改变直接误差。

Guidance coefficient、裁剪与端点

论文系数与 Guided 速度

路径方差项：

\[r_\tau^2=\frac{(1-\tau)^2}{\tau^2+(1-\tau)^2}.\]

未裁剪系数：

\[\lambda_{\mathrm{raw}}(\tau) = \frac{1-\tau}{\tau r_\tau^2} = \frac{\tau^2+(1-\tau)^2}{\tau(1-\tau)} = \frac{\tau}{1-\tau}+\frac{1-\tau}{\tau}.\]

裁剪与最终速度：

\[\lambda_\tau=\min\left(\beta,\lambda_{\mathrm{raw}}(\tau)\right), \qquad \mathbf v_{\mathrm{guided}}=\mathbf v_\theta+\lambda_\tau\mathbf g_\tau.\]

U 形、对称性与裁剪含义

lambda_raw 在 tau -> 0+ 与 tau -> 1- 都发散，关于 tau=1/2 对称，并在中点取得最小值 2。beta 是最大 coefficient，不是最低引导强度；提高它不自动等于更连续、更准确或更安全。实际修正范数还取决于 e_tau、Jacobian、动作 scaling 与 dtype。

论文特定数值不转成默认值

在原论文等步长 Euler、n_flow=5 的设置里，速度求值点为 0,0.2,0.4,0.6,0.8，tau=1 不求值；tau=0.8 的 raw coefficient 是 4.25。论文附录在其模拟消融条件下采用 beta=5，并报告少步采样中过高系数可能导致 chunk 发散和更高 jerk。

原论文特定设置 上述数字只帮助复核公式与来源；不能据此推导其他 policy、solver、精度、horizon、动作空间或硬件的推荐值。任何迁移数值都要在 Experiments 记录协议和失败出口。

实现先分支，再计算

require finite(beta) and beta > 0
if tau == 0:
    lambda_used = beta
elif tau >= 1:
    reject evaluation for the stated Euler schedule
else:
    lambda_raw = ((tau*tau) + (1-tau)*(1-tau)) / (tau*(1-tau))
    lambda_used = min(beta, lambda_raw)
require finite(lambda_used) and 0 <= lambda_used <= beta

禁止先算出 inf/NaN 再假设下游乘零会修复。低精度下分别检查 tau、lambda_used、g_tau、lambda*g 与最终 update；日志可把端点 raw 值记为分类状态，不把 NaN 填进主数值字段。

Coefficient 审计不仅看 beta

每个 step 要同时记录 raw 分类、used value、g_norm、lambda*g 范数与 base v_norm，再计算有限的修正比率。lambda_used 被裁到同一值不代表实际修正相同：动作归一化、Jacobian 与误差大小会把同一 coefficient 转换成完全不同的更新。若只记录 beta，无法解释过冲究竟来自裁剪上限还是异常梯度。

tau 接近端点时，低精度的减法 1-tau 与分母乘积可能损失有效位。实现应根据 dtype 选择经过验证的计算形式，并用高精度 oracle 比较，而不是自行添加未记录 epsilon。若确需 epsilon、log-domain 或替代表达，它是实现迁移，必须进入 algorithm record、source mapping 与 property tests。

裁剪顺序也要固定：先验证 beta，按端点分支决定是否计算 raw，再计算有限 lambda_used，最后才与 g 相乘。对 tau<0、tau>1、非有限 tau、非正 beta 与非有限 g 直接拒绝。不能 clamp 非法 tau 到区间边界，因为那会隐藏 scheduler/time adapter 错误。

实验比较应把 coefficient schedule 与 solver/time grid 绑定。改变 n_flow 会同时改变求值点、单步跨度、总 VJP 次数和可能的 wall-clock delay；因此“更大 beta”与“更多步”不是独立旋钮。记录完整组合，才能让 Experiments 区分数值稳定性和系统延迟效应。

Guided sampler：伪代码与形状检查

Contract-driven 核心流程

function GuidedSample(policy, observation, handoff, rng):
    require handoff.contract_version/hash valid
    require handoff.authority source/epoch current
    require action_abi_hash matches policy and old actual actions
    require H > 0, M > 0, n_flow > 0
    require 0 <= d_hat <= s_run <= H - d_hat under selected paper mapping

    Y, validity, source_ticks = align_previous_actions_by_absolute_tick(handoff)
    W = build_soft_mask(H, d_hat, s_run)
    W = where(validity, W, 0)
    require shapes Y=[H,M], W=[H], validity=[H]
    require all_finite(Y, W) and 0 <= W <= 1

    A = normal(rng, shape=[H,M], dtype=policy.sample_dtype)
    delta_tau = 1 / n_flow
    for k in 0 .. n_flow-1:
        tau = k / n_flow
        A_hat, pullback, v = vjp_final_estimate(policy, A, observation, tau)
        error = W[:,None] * (Y - A_hat)
        g = pullback(error)
        lambda_used = finite_clipped_guidance(tau, beta)
        require shapes A_hat=v=error=g=[H,M]
        require all_finite(A_hat, v, error, g, lambda_used)
        A = A + delta_tau * (v + lambda_used * g)
        record metadata-only step trace

    require shape A=[H,M] and all_finite(A)
    return GuidedProposal(branch="guided", contract_hash=handoff.contract_hash,
                          action_abi_hash=handoff.action_abi_hash,
                          authority_epoch=handoff.authority_epoch,
                          mask_digest=digest(W), action_chunk_ref=artifact_ref)

这段流程不包含 queue merge、stale proposal 判定、controller dispatch/ack、execution feedback、安全 gate 或自动重试。任何失败只返回 typed error 与最小诊断；线程、锁、backpressure、timeout 和 fallback 都由 Runtime 定义。

每一步做 shape 与 finite 检查

| 对象 | 预期 shape | 必须检查 | | — | — | — | | A / A_hat / v / error / g | [H,M] | dtype/device 一致、finite | | Y | [H,M] | ABI、normalization、finite placeholder | | W / validity | [H] | 范围、bool/float dtype、广播轴 | | tau / lambda_used / beta | scalar | finite、合法范围、time convention | | source_ticks | [H] nullable | monotonic、control session、anchor join | | proposal metadata | scalar/opaque | contract hash、authority epoch、branch |

随机数生成器及 seed/provenance 要进入 sampler record，但页面不提供可执行命令。determinism 的含义也要写清：同一 seed、代码、checkpoint、device 和数值模式下尽力重现，不把跨硬件 bitwise equality 当默认保证。

Typed failure 是 sampler 的正常输出

失败结果至少区分 contract invalid、ABI mismatch、authority stale、alignment missing、mask infeasible、non-finite base output、non-finite VJP、coefficient invalid、resource limit 与 cancelled request。每类附首个失败 step、可公开的范数和 artifact reference，不复制敏感 observation/action。上层依据稳定枚举选择 retry、fallback 或 safe state，不能解析自由文本猜动作。

sampler 一旦失败，不应返回部分动作块作为 ready proposal。调试 artifact 可以受控保存中间 sample，但 status=rejected 的 action_chunk_ref 必须为空。自动 retry 若存在，属于 Runtime：它要重新判断 deadline、authority epoch、queue coverage 与 request supersession，不能由算法内部在未知时序下悄悄重复。

正常返回也必须满足 closure：最终 A shape/finite、contract hash 未变、source mask digest 可复算、branch 固定为 guided、authority epoch 与输入一致、trace step 数匹配实际 solver 记录。任何 closure 断言失败都把整个 proposal 标为 rejected，而不是只删掉异常维度。

资源限制同样是一等失败。VJP 造成的 peak memory、compile latency、warm-up、device queue wait 与每步耗时要进入测量，但算法页不设通用阈值。超预算时由 Runtime/部署 contract 决定停止或 fallback；不得通过跳过 VJP step 或降低精度而不改变 algorithm record。

每步状态机要保持输入不可变

一次 sampler request 中，observation reference、contract hash、Action ABI、aligned target、effective mask、authority epoch 与 time adapter 在 step 0 前冻结。循环内唯一按算法更新的主状态是 A；tau 来自冻结 time grid，trace 只追加不覆写。若外部系统需要更新 observation 或 prefix，应取消旧 request 并创建新 request，而不是在 VJP 图中途替换输入。

这种不可变性让同一 step 的 A_hat、error、g 和 update 能共享因果上下文。若 mask 在循环中随 queue 变化，前后 step 实际优化的是不同目标，algorithm record 却可能仍只有一个 digest；若 normalization adapter 热更新，数值空间也会静默变化。所有动态变化都应通过 request/version 边界表达。

取消信号可以在 step 边界检查，但取消后的中间 sample 不能伪装成完成 proposal。trace 记录 cancel_observed_at_step、原因与当时 finite 状态；Runtime 再判断是否启动替代 request。算法层不吞掉取消继续算，也不把取消统一归类为数值失败，因为两者的 owner 和后续动作不同。

编译或缓存复用也要绑定 shape、dtype、policy/checkpoint hash、time convention 与 branch mode。仅按 H/M 复用 executable 可能把旧 adapter、旧 beta schedule 或错误设备模式带入新请求。cache hit/miss 可记录为性能元数据，但不能改变数学输出 schema。

离线重放时，应从 frozen input artifacts 与 RNG provenance 重新生成 trace，并比较 step count、time grid、mask digest、finite classification 和允许容差内的范数。重放差异先标为 reproducibility gap，不立即归因于模型；硬件、编译器与非确定 kernel 都需进入解释。

动作空间决定误差含义

论文/实现中的欧氏型动作误差必须注明空间：normalized、model-native 或 physical。每维 scale、unit 和 clipping 会改变 VJP 强度；gripper 离散维未必应与连续 joint 维同权；Cartesian translation、rotation 与 joint action 也不能默认共用一个范数。relative action 必须确认 reference state 与旧 target 一致。

本站默认复现固定来源所用空间，不替用户设计物理安全度量。维度重加权、robust loss、rotation metric 或 gripper 特殊处理均属于方法迁移/工程建议，应产生新 algorithm record 并在 Experiments 单独验证，不能悄悄改公式仍称原论文复现。

连续性、reactivity 与 safety 分开评估

  • Soft overlap 更长或权重更强，可能更连续，也可能更依赖旧计划、降低 fresh-observation reactivity。
  • W_i=0 只消除直接旧目标误差；共享网络跨 token 耦合仍可能传播影响。
  • 一次 sampler 只消费该 request 冻结的 observation，不因此获得推理期间的新观测 streaming。
  • 生成轨迹连续不保证速度、加速度、jerk、力、碰撞、工作空间或任务约束成立。
  • 独立 safety gate、watchdog、actuator inhibit、safe state、re-arm 与人在回路 authority 仍由安全页管理。

测试 oracle 与发布边界

Mask 可以在合法整数网格穷举；coefficient 可验证化简式、tau=0.5 -> 2 与关于 0.5 的对称性；微型线性 denoiser 上可把 VJP 与显式 J^T e、有限差分 oracle 对照。有限差分只用于测试，不是 runtime 算法。float32 与选定 mixed precision 的容差、设备与编译模式写入报告。

测试通过只证明实现符合声明的数学与 shape contract，不证明真实任务稳定、安全或成功。真机路径还需 Runtime、Safety、评测协议与现场 risk acceptance；缺 contract hash、Action ABI 或 authority epoch 的实例不能标绿。

诊断指标必须成组解读

至少把 boundary action jump、velocity/acceleration/jerk proxy、weighted error、VJP correction ratio、deadline miss、valid suffix length、fresh observation age、task outcome 与 safety intervention 放在同一 trial/trace 语境。只报告平滑度，会遗漏任务反应变慢；只报告成功率，会遗漏危险但侥幸完成的轨迹；只报告 latency 平均值，会遗漏 tail delay 让整个新块过期。

指标的时间窗口与空间必须明确。动作 jump 在 normalized space 变小，不表示 physical joint、pose 或 force 差也变小；controller 插值后的平滑，不应归功于 policy guidance；feedback 轨迹与 commanded trajectory 的偏差也要单独记录。跨方法比较必须共享 adapter、controller 与 safety 设置。

异常诊断按因果层分组：time/contract 层检查 tick、epoch、ABI；sampler 层检查 mask、VJP、coefficient 与 finite；Runtime 层检查 stale、queue、merge 与 dispatch；controller/safety 层检查限幅、veto 与 feedback。先定位层，再选择 owner，避免一看到抖动就调 beta。

停止条件优先于优化。任何 non-finite、authority mismatch、无 valid suffix、contract/hash 不一致或 safety reject 都阻止 merge；性能下降或 continuity 不佳则进入离线实验。页面不提供绕过 gate 的 debug 开关，也不把“仅测试”作为忽略安全边界的理由。

Handoff 有三个不可混写的时刻

sampler started 时，d_hat、contract、observation 与 authority epoch 已冻结；proposal ready 时，只能证明候选和 trace 已生成；Runtime merge 时，才用最新 d_meas、queue、committed boundary 与 safety 状态决定是否接纳。三者分别记录 monotonic event，不用一个 generated_at 兼任全部语义。

ready 到 merge 之间可能发生新 request supersede、authority change、controller pause、adapter reload 或 deadline miss。Runtime 必须重新校验，而不是因为 Guided 内部 checks 已通过就跳过。若有效后缀缩短，Runtime 可按声明裁剪；若为空，则 reject/fallback。算法页不能预先决定重复末值、hold 或 stop。

merge 后仍不等于 executed。dispatch 与 controller ack 需要自己的 sequence，safety gate 的改写/否决也进入 provenance。若后续 Guided request 要使用这段动作作为旧目标，应引用最终 committed/dispatched 记录，而不是原始 proposal，形成闭环可追溯链。

横向切换到 Training-Time 时，要创建新的 branch algorithm record；不能把 Guided mask/beta 字段留在 trained 模式中造成假象，也不能假定同一 checkpoint 两种模式都兼容。共同字段沿用 Foundations contract，分支特有字段按 schema 分开。

发布前做四层独立复核

方法层复核公式、时间方向、Mask 适用域与 coefficient 化简；实现层复核 shape、dtype、VJP 自变量、finite 分支和固定版本代码映射；系统层复核 absolute tick、authority、Runtime handoff 与 Safety 边界；证据层复核来源版本、标签、访问日期和结论强度。四层可以由同一项目维护，但检查记录要分开，避免一个“公式正确”勾号覆盖系统缺口。

每个断言分成 verified、verified_with_scope、pending_version_lock、not_applicable 或 rejected。例如论文 Soft Mask 公式可 verified；Kinetix main 的某行实现只能 pending_version_lock；真机实时性在没有测量时是 pending，而不是 false 或 true。范围化状态让页面在不夸大证据的同时仍可继续完成静态内容。

复核者还要检查负面空间：页面没有把 VJP 写成零成本，没有把 beta=5 写成默认，没有把平滑写成安全，没有把 proposal 写成 dispatched，没有把 Training-Time 写成后继，也没有提供真实命令、地址、凭证或机器人参数。缺少这些否定约束时，正确公式仍可能被错误使用。

最终 handoff 报告列出源 hash、覆盖稿 hash、正式 patch hash、专页 checker、全量回归结果，以及尚未完成的构建/浏览器验收。失败时只回滚本页覆盖稿和关系补丁，不触碰只读源或范围外文件；任何发布、安装或上传仍需要单独授权。
