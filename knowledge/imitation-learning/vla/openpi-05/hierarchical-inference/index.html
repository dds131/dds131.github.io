本页的知识点、创新点与重点

两层高层子任务 + 低层动作
同一总体模型不是两个独立部署的模型
50 步 / 1 秒一个动作块（官方博客）
4 路 / 3 路高层用相机数 / 低层用相机数
7 个V-E 的高层方法对照组
未公开openpi 的高层文本解码路径
本页的重点有两个。其一是条件独立假设：给定当前观测与已生成子任务后，低层不再直接读取原始指令；但把子任务边缘化后，动作仍通过高层分布间接依赖原始指令。其二是论文 V-E 的两个反直觉结果：完整模型的实验均值超过了原本用作“oracle upper bound”的 human HL 基线，而运行时不显式生成子任务的 implicit HL 排第二。这些是有限实验上的排序，不是数学上界或普遍定律。

一、本页在专题中的位置

本页负责推理时的结构：一次调用中两层如何衔接、各自看什么，以及论文明确给出和没有给出的运行节奏。

本页沿用 π0 的部分，不重讲。低层仍用流匹配与 10 步数值积分生成动作块。论文没有说明每次实际执行动作块中的多少步后重新查询，因此本页不把“输出 50 步”自动等同于“50 步全部开环执行”。完整流匹配推导见 π0 · Flow Matching 动作生成 与 π0 · 时间方向约定与推理期现象。π0.5 新增的是：低层动作生成前先产生子任务文本，而且两步由同一总体模型承担；高层主要走 VLM 文本头，低层还会使用独立的动作专家参数，因此“同一模型”不等于每个参数都完全共享。

二、分布分解式：分层到底分的是什么

论文 IV-A 把 π0.5 要表示的分布写成

\[\pi_{\theta}\!\left(\mathbf{a}_{t:t+H},\,\hat{\ell} \;\middle|\; \mathbf{o}_{t},\,\ell\right)\]

其中 \(\mathbf{o}_{t}=[\mathbf{I}^{1}_{t},\dots,\mathbf{I}^{n}_{t},\mathbf{q}_{t}]\) 是全部相机图像与机器人本体构型（关节角、夹爪位姿、躯干升降位姿、底盘速度），\(\ell\) 是用户给的整体任务指令（如「把餐具收走」），\(\hat{\ell}\) 是模型输出的文本（可以是预测出的高层子任务，也可以是网络数据里视觉语言提示的答案），\(\mathbf{a}_{t:t+H}\) 是预测的动作块。

先看一般的概率链式法则：

\[\pi_{\theta}\!\left(\mathbf{a}_{t:t+H},\hat{\ell} \mid \mathbf{o}_{t},\ell\right) = \pi_{\theta}\!\left(\mathbf{a}_{t:t+H} \mid \mathbf{o}_{t},\ell,\hat{\ell}\right)\, \pi_{\theta}\!\left(\hat{\ell} \mid \mathbf{o}_{t},\ell\right)\]

上式对任意联合分布都成立。π0.5 进一步施加

\[\mathbf{a}_{t:t+H}\ \perp\!\!\!\perp\ \ell \ \mid\ (\mathbf{o}_{t},\hat{\ell}),\]

于是才得到论文写出的模型分解：

\[\pi_{\theta}\!\left(\mathbf{a}_{t:t+H},\hat{\ell} \mid \mathbf{o}_{t},\ell\right) = \pi_{\theta}\!\left(\mathbf{a}_{t:t+H} \mid \mathbf{o}_{t},\hat{\ell}\right)\, \pi_{\theta}\!\left(\hat{\ell} \mid \mathbf{o}_{t},\ell\right).\]

因此，高层表示 \(\pi_{\theta}(\hat{\ell}\mid\mathbf{o}_{t},\ell)\)，低层表示 \(\pi_{\theta}(\mathbf{a}_{t:t+H}\mid\mathbf{o}_{t},\hat{\ell})\)。这是模型结构假设，不是仅靠概率论就能推出的恒等式。

2.1 这条条件独立假设意味着什么

对一次已经采样出的 \(\hat{\ell}\)，低层不再直接看到 \(\ell\)；原始指令的影响经由高层分布传递。把子任务边缘化后仍有

\[\pi_{\theta}(\mathbf{a}\mid\mathbf{o},\ell) =\sum_{\hat{\ell}} \pi_{\theta}(\mathbf{a}\mid\mathbf{o},\hat{\ell})\, \pi_{\theta}(\hat{\ell}\mid\mathbf{o},\ell),\]

所以不能简写成“最终动作与原始指令无关”。准确的工程含义是：原始指令不能绕过子任务文本直接约束低层。

后果 具体表现
收益：职责分解 低层面对局部子任务，高层负责依据观测与整体指令选择下一步；这会减轻但不保证消除长期状态与部分可观测问题
收益：可替换 \(\hat{\ell}\) 是一段人可读的文本，可以被人工替换、被另一个高层模型产生、被日志完整记录
收益：可复用 多个整体任务可以调用同一低层技能分布，前提是子任务措辞与状态落在低层能力范围内
代价：信息瓶颈 原始指令中未被子任务文本表达出来的约束（如「轻拿轻放」「先做这个再做那个」）无法传到动作层
代价：错误会传播 低层没有原始指令，无法据此判断子任务是否违背用户意图；但它仍可因场景不一致而失败，后续高层也可能重规划，故并非逻辑上不可挽回
论文确实报告高层会被干扰，例如在收纳物品时反复开关同一抽屉，并提出更丰富标注、上下文与记忆作为未来方向；但它**没有**写“高层没有独立监督信号”这一句。相反，HL 与 VI 都提供了子任务文本监督，只是仍属于示范式监督，而非基于实际执行结果的奖励或在线纠错。

三、一次推理调用里发生了什么

论文 IV-B 对推理过程的原话是：先对文本 token \(\hat{\ell}\) 做标准的自回归解码，然后以这些文本 token 为条件，做 10 步去噪，产生动作 \(\mathbf{a}_{t:t+H}\)。

注意下标的差一问题。论文写 \(\mathbf{a}_{t:t+H}\)，区间两端都计入，因此附录明确说明 50 个动作对应 \(H=49\)；公开配置则直接把数组长度命名为 action_horizon=50。二者只是符号口径不同，不能把 \(H\) 与动作个数都写成 50。

3.1 子任务长什么样：论文给出的真机实例

上面一直在说「子任务文本」，但它具体是什么形态、粒度多粗，只有看到实例才有概念。论文 Fig. 7(a) 给出了三个真实家庭里的回放，每一帧下方的蓝色文字就是 π0.5 当时预测的高层子任务。

把三行逐条读出来，可以直接观察到三件事：

家庭 人给的指令 模型依次预测的子任务
1 put the items in the drawer pull out the drawer → pull out the top right drawer → pick up tong → put tong into drawer → push the top drawer
2 place the dishes in the sink pick up plate → put plate in the sink → put cup in the sink → pick up the spoon → pick up bowl
3 put the laundry in the laundry basket pick up shirt → pick up shirt → put clothes in the laundry basket → put the shirt in the laundry basket → put clothes in laundry basket
  • 粒度是「一次单物体操作」。 子任务既不是「收拾厨房」那种整体目标，也不是「向前 2 厘米」那种运动指令，而是「拿起夹子」「把盘子放进水槽」这一级——正好对应第四节说的那个取舍：粗到没有指导性、细到退化成动作本身，都不行。
  • 同一条指令下，子任务序列是「开容器 → 取物 → 放入 → 关容器」这样的结构（家庭 1 尤其明显）。这说明高层输出的不是一个固定脚本，而是随当前观测推进的下一步。
  • 家庭 3 的前两帧文字同为 pick up shirt。这只说明两个展示时刻的预测文本相同；模型可能每次都重新解码出同一句，也可能复用旧子任务。Fig. 7 的稀疏帧无法区分两者，因而不能据此推出高层解码频率。

家庭 3 的措辞在 pick up shirt、put clothes in the laundry basket、put the shirt in the laundry basket 之间变化，显示输出至少不是图中可见的单一规范措辞。若工程上要把子任务接入离散状态机，需要自行做语义归一化；论文没有说明它使用受控词表，也没有专门评估同义改写的稳定性。

四、为什么子任务用离散 token 而动作用连续生成

两个出口的取舍方向完全相反，这是分层设计里最需要论证的地方。

比较项 高层出口（子任务文本） 低层出口（动作块）
量的性质 语义目标，以文本 token 表示 物理控制量，连续、高频，可具有多峰分布
表示方式 词表 token，自回归解码 连续向量，流匹配并行生成整块
与其他数据共享 与网络图文数据共用同一套交叉熵目标，共训练因此成立 只有机器人动作数据能提供监督
序列长度 通常是短子任务描述，实际 token 数由措辞决定 50 个时间步 × 动作维；公开默认最大动作维为 32
延迟特性 只生成短文本，论文选择自回归解码 离散动作需自回归生成压缩 token；连续专家可并行输出整块
精度要求 需要语义明确且与低层能力匹配 需要细粒度连续控制；离散动作会引入量化/重建误差
错误的可发现性 语义错误通常可由文本直接审查 连续动作误差需结合轨迹、任务结果与控制日志，不能仅靠文本判断

这组设计体现了不同目标：语义层重视可读、可监督与可复用，动作层重视连续精度和快速生成。它解释了论文为什么让两个出口采用不同表示，但表格中的工程动机并非逐项消融结论。

这一取舍与训练侧的取舍方向并不相同，容易混淆：训练时 π0.5 也把动作表示成离散 FAST token（因为离散目标训练效率更高），只是不用它来做推理。也就是说，动作在训练期有离散与连续两种表示，在推理期只用连续那一种。完整论证见 ③ 两阶段训练与组合损失。

五、边界框为什么排在子任务之前

论文 IV-C 在介绍 HL 数据时写明：对 MM、ME、CE 中涉及多个子任务的机器人数据，人工标注子任务的语义描述；同时标注当前观测中相关物体的边界框，并训练 π0.5 在预测子任务之前先预测这些边界框。

论文明确规定了这个顺序，但没有单独证明它优于其他顺序。把它放在自回归解码框架里，可作如下结构性理解：

解码顺序 该步在做什么 它为后一步提供了什么
先：边界框 在图像中定位出与当前任务相关的物体 把「场上有哪些可操作对象、各在什么位置」显式写进了上下文
后：子任务 决定下一步对哪个对象做什么 文本解码可条件于前面输出的定位 token；这不保证定位一定正确，也不等于视觉特征不会被再次使用

三点解释：

  • 自回归解码中，先写出的 token 会成为后续 token 的条件。因此边界框可作为显式中间表示，再参与子任务生成。论文把“把整体任务拆成子任务”类比为思维链；它没有把“边界框先于子任务”单独证明为思维链。
  • 它把一个容易出错的环节显式化了。 第二节说过，低层无法用原始指令核对子任务是否正确。把定位步骤提前并显式输出，使得「模型看错了物体」与「模型看对了但选错了动作」在输出上可分。
  • 它与 WD 的物体定位输出形式兼容。网络数据包含室内/家居物体的边界框任务，机器人 HL 数据也输出定位 token，因此可共享下一 token 训练接口；“两类数据一定互相增强”是合理假说，但论文没有对这种共享格式单独消融。
需要严格说明：论文没有对「边界框是否必须排在子任务之前」做单独消融。上面三条是对论文所述设计的机制分析，不能声称这个顺序独立贡献了多少性能。论文用消融验证过的是 WD 整体的作用（见 ①）与 HL 数据整体的作用（见本页第七节）。

六、两层各自看什么，更新节奏知道多少

6.1 相机分配：两层用的输入并不相同

论文 IV-E 给出了一个容易被忽略但很有信息量的细节。机器人平台有四路相机：前向、后向、左右腕部各一。而：

推理层 论文明确使用的相机 可以得到的结构事实
高层 四路全用 高层输入包含前向、后向与两路腕部视角
低层 腕部两路 + 前向一路 低层相对高层只去掉后向视角；图像 token 更少会降低注意力计算，但论文未报告节省幅度

把两行相减，可以得到一个比「低层用得少」更精确的说法：四路减三路，低层唯一丢弃的是后向相机。

这一差集与“高层看更广、低层聚焦当前操作”的直觉相容，但不能断言后向视角对所有低层导航动作都无用。论文只给配置，没有给选择理由：

相机 高层 低层 它主要提供什么
左右腕部（两路） 用 用 近距离手—物视角；具体必要性未单独消融
前向（一路） 用 用 前方场景视角；具体作用未单独消融
后向（一路） 用 不用 补充身后场景；为何只供高层使用，论文未解释

因此能确定的是两层输入范围不同，且低层少处理一路图像。把它解释为“高层广域、低层局部”的功能分工是合理推断，不是论文验证过的因果结论。

需要说明边界：论文只写明了两层各用哪些相机，没有给出这样分配的理由，也没有做过「低层加上后向相机会怎样」的消融。上表末列是对相机朝向与两层职责的结构性解读，不是论文结论。

6.2 更新节奏

量 取值与依据
一个动作块 50 步；官方博客明确写为「50-step (1-second) action chunk」
控制频率 论文 IV-E：模型直接下发手臂、夹爪、躯干升降的目标位姿与底盘目标速度，频率 50 Hz，配合动作分块
底层跟踪 论文 IV-E：目标由简单的 PD 控制器跟踪，没有额外的轨迹规划与碰撞检测，导航与操作全部端到端
一次多阶段任务时长 论文 V-A：许多任务涉及多个阶段（如搬运多个物体），持续约 2 至 5 分钟
更完整清洁行为时长 论文 Fig. 1 与引言：清理整间厨房或卧室的展示可达约 10 至 15 分钟；与上行的单项评测口径不同
需要区分三种“频率”。50 Hz 是目标控制量的时间步频率；50 个动作构成约 1 秒的预测时域；但论文没有给出每次实际执行其中多少步后重新查询，也没有给出高层文本是每次查询都重新解码，还是跨若干查询复用。一个子任务的语义持续时间可以长于 1 秒，却不代表解码器一定没有再次运行。任何具体高层频率都属推测。

七、论文 V-E：高层推理到底有多重要

论文 V-E 用同一套 π0.5 低层推理，只替换高层策略，构造了七个对照。

编号 方法 高层策略是什么
1 π0.5 用 π0.5 自己做高层与低层推理（完整方法）
2 no WD 去掉网络数据训练出的 π0.5 变体做高层
3 no VI 去掉口头指令数据训练出的 π0.5 变体做高层
4 implicit HL 运行时不做高层推理，但训练里保留了高层数据
5 no HL 运行时不做高层推理，训练里也完全没有高层数据
6 GPT-4 用 GPT-4 做高层策略，提示中给出任务描述与最常用标签列表供其选择
7 human HL 由人类专家充当高层策略；论文把它设计为“oracle upper bound”基线

论文给出的排序结论是：完整 π0.5 最好，implicit HL 第二，no HL 显著更差，no VI 与 no WD 都显著更弱，GPT-4 最差。其中两条反直觉，需要单独解释。

7.1 反直觉之一：完整模型均值超过了预设的 human HL “上界”

论文原文写明，完整 π0.5 的实验表现超过了 human HL。这里的“upper bound”只是作者对基线角色的预期；既然实测被超过，它就不是数学上界。

这个实验固定 π0.5 低层、只替换高层，因此比较的是高层输出与特定低层策略组合后的端到端进度，不是脱离接口的纯规划智力。它也不支持“模型普遍比人类更会规划”。

一种合理解释是接口匹配：模型高层的措辞与粒度来自和低层相关的同一训练体系，human HL 的选择未必最符合低层能力分布。其他可能因素还包括人类操作协议、有限试验数与误差条。论文没有为“为何超过 human HL”做单独消融，因此不能把接口匹配写成已证实的唯一原因。

VI 的采集方式是让专家用语言实时“遥操作”已训练的低层策略（见 ①），确实会产生与低层可执行性相匹配的示范；no VI 显著变弱与上述解释相容，但仍不是对 human HL 反直觉结果的直接因果证明。

7.2 反直觉之二：运行时不做高层解码的变体排第二

implicit HL 在运行时不产生子任务文本，而是把整体任务提示直接交给低层；它排在完整模型之后、位居第二，并优于 no HL。按论文定义，两者的主要设计差异是训练混合中是否包含高层子任务预测数据。

论文对此的判断是：这有力地说明了共训练配方的重要性——显式推断高层子任务确实有收益，但其中相当一部分收益，只靠在训练混合里包含子任务预测数据就已经获得了。

一种机制假说是：训练中的子任务预测目标促使主干学习任务阶段与语义结构；即使运行时不显式生成文本，这些表示仍可能帮助动作分支。论文的实验支持“高层训练数据本身有价值”，但没有直接探测内部是否编码了某个“阶段变量”。

这条结果给出一个值得验证的工程方案：若显式文本解码的延迟不可接受，可比较 implicit HL，而不应默认连训练期的子任务数据也一起删除。论文聚合实验中 implicit HL 的损失小于 no HL，但具体差距依任务而变，不能直接保证迁移到新系统。

7.3 逐任务看：高层推理在哪些任务上才关键

论文附录 A-D（Fig. 17）把 V-E 拆到四个任务上：

任务 高层推理的重要性 图与正文支持的谨慎解读
Items in Drawer 完整模型最好；no HL 较低，no WD / no VI 更低 显式高层有帮助，且语义数据来源对该任务尤其重要
Dishes in Sink 完整模型显著高于 no HL 与 GPT-4 HL Fig. 17 与附录前一句均支持高层推理在此任务很重要
Laundry Basket 各高层方法均值接近 对高层选择相对不敏感
Make the Bed 完整模型均值最高，但误差条较宽；其他方法较接近 不宜仅凭图断言某种高层方法有稳定显著优势

论文附录这里有一处内部矛盾。前一句明确说 Items in Drawer 与 Dishes in Sink 的 high-level inference 很关键；紧接着却又写 Laundry Basket 与 Dishes in Sink 对高层选择较不敏感，同一任务不可能同时满足这两种概括。Fig. 17 中 Dishes in Sink 的完整模型明显高于 no HL，而 Laundry Basket 各方法更接近，因此本表采用前一句与图一致的读法；对 Make the Bed 只报告图中均值和误差条，不替论文猜测被误写的任务名。

总体趋势是：需要结构化步骤选择与物体语义的任务更可能受益于显式高层，但任务长度并非唯一变量，图中样本量和误差条也限制了泛化强度。评估分层是否值得，应在目标任务上同时比较完整模型、implicit HL 与 no HL。

八、分层带来的可调试性

可读子任务为诊断提供了额外观测，但不能仅凭一句文本唯一定位故障：

观测 优先排查方向 可能的改进
子任务文本本身就不合理 高层语义、定位或任务阶段判断 检查边界框输出，补 HL / VI 与相应场景
子任务合理，但动作没做到位 低层技能、状态估计、可达性或控制执行 补技能数据并检查观测、控制器与动作接口

分层后，每次高层推理产生的文本都可记录、离线复盘和统计，Fig. 7(a) 的蓝色文字就是这类输出。它提高了可观测性，但“文本合理”不保证视觉定位与内部条件正确，“动作失败”也可能源于高层给出不可达目标，因此仍需结合边界框、视频与控制日志判断。

九、开源实现上的缺口

这是当前公开实现的边界，不是论文方法本身。截至 2026-10-08，官方 README 仍说明 π0.5 训练与推理只支持流匹配头；当前 Pi0.compute_loss() 只返回流匹配均方误差，sample_actions() 则把图像、prompt 与状态编码为 prefix 后直接进入动作专家积分，没有自回归生成子任务文本。官方维护者也在 openpi issue #647 明确回复“currently only support action decoding”。

因此，公开仓库可运行的是低层动作路径，不是论文完整的“先文本、后动作”分层推理。判断这一点应直接检查损失函数、采样入口与维护者答复，而不能用关键词检索代替实现级证据。要复现论文流程，需要另行实现高层自回归解码、终止条件、低层 prompt 重建，以及高层/低层的调度策略。

这与官方 README 的说明是一致的：该仓库对 π0.5 的训练与推理目前只支持流匹配头。差异的完整清单见 ⑦ 论文与实现的差异及推理期现象。

自行实现时不应简单把子任务追加到原 prompt。按论文分解，低层条件是当前观测与 $$\hat{\ell}$$，更直接的做法是用预测子任务重建低层 prompt，再重新分词；若仍保留原始指令，就已经改变了论文的条件独立结构。公开 PaligemmaTokenizer 的 π0.5 输入格式为 Task: {prompt}, State: {状态整数串};\nAction: ，默认总长度上限为 200，超长会 warning 后截断。高层生成还需另设解码长度和 EOS 终止规则，不能把这 200 个 prefix 槽位误当成现成的高层输出缓存。相关格式见 ② 网络架构与结构差异。
