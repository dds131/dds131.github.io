RLHF-VLA/在线迭代训练系统

COMMON MERGE · orchestration · evaluation · deployment · safety

merge_policy: any 只表示任一分支可进入共同系统，不表示三路合同可以取交集、互相补字段或共享同一训练语义；灰度与回滚只改变后续软件分配，不能撤销已经发生的物理后果。

本页只定义可审计系统合同：不可变事件、分支专属作业、独立评估、人工授权、受限 exposure、监控、containment、撤销与回滚。没有运行采集、训练、评测或部署。

any ≠ all21 versioned contractsrollback ≠ undo physics

入口：三路 router 与 any 语义

设三路 handoff 为 $H_b$：

\[Eligible_{merge}=\bigvee_b[ schema_b\ valid \land state_b\in\{complete\text{-}with\text{-}evidence,ready\text{-}with\text{-}limits\} \land limits_b\ accepted].\]

router 先验 schema、branch/source/target 和 hash，再把字段原样绑定到 lane。ready-with-limits 交人工 review；incompatible、unsupported、forbidden、stale、revoked、unknown fail closed。缺失兄弟分支不阻塞，也不能从兄弟分支借 RM、Critic、Reference、likelihood 或 evaluator 补字段。

flowchart LR
  P[PPO handoff] --> R{merge policy any}
  D[Direct Preference handoff] --> R
  T[Trajectory Continuous handoff] --> R
  R --> L[independent branch lane]
  L --> S[immutable events · queue · views]
  S --> J[branch-specific run]
  J --> E[independent evaluation]
  E --> G[authority · staged exposure]
  G --> O[monitor · contain · rollback]

多个 handoff 默认生成独立 Candidate jobs，各有 snapshot、namespace、gate 和 exposure。共享 raw store 不等于共享 view/split/label/optimizer。组合必须新建 composition ID、参数/数据/objective/role/validation/rollback 合同，并作为新方法验收。

角色：逻辑身份、制品与权威边界

Champion 是获准基线；Candidate 是待评估产物；Behavior 证明谁生成数据；Current 接收梯度；Old 是 PPO denominator；Reference 是 KL/偏好锚点；RM 映射反馈；Critic 估值；training evaluator 只参与训练选择；release evaluator 产生 acceptance evidence；safety controller 和 release approver 位于 optimizer 外。

同一 hash 可同时绑定初始 Current 与 Reference，但 logical bindings 不合并。每个 binding 保存 artifact/package hash、code/config/processor/Action ABI/safety config、generation、effective interval、requested/loaded/served-active、owner/approver/signature、branch/run/eval/deploy IDs 与 revocation state。角色改变追加 event，不改历史。

trainer 可提交 Candidate，不能宣布 Champion；evaluator 不能修改产物；release gate 可拒绝但不能越过独立 safety controls；watchdog/interlock/E-stop/现场人工可随时停止。approval 只对固定 package/evidence/generation/exposure 有效。

分支泳道：freshness、eligibility 与 run snapshot

新鲜度分别记录 data age、label age/revision、Behavior→training generation lag，以及 Reference/RM/evaluator/processor/safety/runtime lag。BC/SFT、RM、DPO/KTO、APO、PPO、trajectory route、learned-reward diffusion 和 off-policy intervention 各有不同 eligibility，禁止单一全局阈值。

PPO 只消费 sealed Behavior/Old rollout；DPO/KTO 绑定 Current/Reference/processor/ABI；APO 绑定 iteration policy/operator/guideline；trajectory route 绑定 pair dependency/credit/solver；diffusion route 绑定 RM/reward/noise/solver。RM/Reference/evaluator/processor/ABI/Champion 更新分别传播 stale/incompatible/rebaseline，不能改写旧事实。

编排：idempotency、lease、generation、CAS 与状态机

统计：预注册、zero-event、non-inferiority 与 multiplicity

结果前冻结 metric definition/direction/unit、population/slices、experimental/cluster unit、numerator/denominator/exposure、Champion generation、gate class、threshold/margin、interval/alpha/power/sample size、multiplicity、sequential looks/stopping、missing/censoring/abort/takeover、zero-tolerance veto 和 authorities。

若 $n$ 个 iid Bernoulli units 中零事件，一侧 $1-\alpha$ 上界：

\[p_U=1-\alpha^{1/n}.\]

这不证明风险为零。$n$ 不能随意取 step；cluster、同 robot/scene、non-stationary policy、重复 action 与 adaptive stopping 破坏简单 iid。非零或依赖数据使用预注册方法；zero-tolerance event 可直接 fail。

对越大越好指标 $d=M_{candidate}-M_{champion}$，只有 $LCB(d)>-\delta$ 才通过预注册 non-inferiority；风险指标用 UCB。平均通过不能掩盖 core slice 或 safety veto。primary/exploratory 分开，multiplicity 与 sequential peeking 有明确 policy；post-result 改门槛禁止，missing/unknown 不通过。
