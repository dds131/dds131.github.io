← Actor-Critic 枢纽·⑥ A2C / A3C

A3C 的核心贡献不是发明 Actor-Critic，而是用多个异步 actor-learner 提供并行环境流，让多条时间轴上的梯度交错写入共享参数，并在单机多核 CPU 上稳定训练深度网络。A2C 保留“多环境并行 + 多步优势”，把无锁异步写回改为同步收集、聚合与更新。

先澄清两个名称。原始 2016 论文正式提出的是 A3C；“A2C”是后来广泛使用的同步版本名称。OpenAI 所称的 synchronous, deterministic 指同步屏障使更新顺序更确定，不表示策略必须选确定性动作。A2C/A3C 训练时通常仍从随机策略分布采样。

无 replay 不等于无 buffer。两者都需要保存当前短片段的 observation、action、reward、value、log-prob 与边界信息来构造多步目标；它们没有的是跨许多旧策略长期随机复用的 replay buffer。

一、A3C 为什么在 2016 年重要

当时深度 Q-learning 常依赖经验回放降低连续样本相关性。回放占用额外存储，也会让更新样本来自旧行为策略；对 RNN 还需维护序列切片与隐藏状态。A3C 改为让多个 worker 在各自环境中并行探索，依靠不同时间轴和异步更新降低单一连续轨迹对训练的支配，不使用长期 replay。“降低相关性”不等于样本独立：相同初始化、相似策略和同构环境仍可产生高度相关的数据。

原论文不是只研究 Actor-Critic，而是给出异步 one-step Q-learning、one-step Sarsa、n-step Q-learning 和 advantage actor-critic。论文在其 Atari、连续控制与 3D 迷宫实验中把 A3C 作为综合表现最好的方案；这是论文设定下的历史结果，不能外推成 A3C 在现代任务上普遍优于 PPO、SAC 或其他分布式架构。

二、A3C 的参数拓扑

实现中要区分三类状态：

  1. 全局共享状态：Actor/Critic 参数、全局环境步计数，以及所选异步优化器的状态；复现论文中较稳的 shared-RMSProp 变体时，平方梯度移动平均 \(g\) 也必须共享。
  2. worker 本地状态：参数快照、局部梯度、独立环境、随机数流；RNN 还包含本地 hidden state。
  3. 短片段数据：最多 \(t_{max}\) 步的 transition，仅用于本次多步回报和反传，用完即丢弃。

A3C 传回的是基于本地参数计算的梯度，并把它应用到全局参数；它不是先让每个 worker 独立训练很久再平均模型参数，也不是把所有 worker 轨迹拼成一个同步大批次。

三、n 步目标、损失与边界语义

设一个 worker 用固定本地参数从 \(t_0\) 收集到 \(t-1\)。在片段末端，先初始化：

\[R_t= \begin{cases} 0, & s_t\text{ 是任务真实终止状态},\\ V_{\phi'}(s_t), & \text{非真实终止的片段边界}. \end{cases}\]

然后对 \(i=t-1,\ldots,t_0\) 逆序计算：

\[\begin{aligned} R_i&=r_i+\gamma R_{i+1},\\ \hat A_i&=R_i-V_{\phi'}(s_i). \end{aligned}\] \[\begin{aligned} L_{\pi}^{\text{local}} &=-\sum_i \Bigl[\\[-0.2em] &\quad \log\pi_{\theta'}(a_i\mid s_i) \operatorname{sg}(\hat A_i)\\ &\quad+\beta\mathcal H\!\left( \pi_{\theta'}(\cdot\mid s_i) \right)\Bigr]. \end{aligned}\] \[\begin{aligned} L_V^{\text{local}} &=\frac12\sum_i \Bigl[ V_{\phi'}(s_i)\\ &\qquad-\operatorname{sg}(R_i) \Bigr]^2. \end{aligned}\]

片段内越接近末端，可用的实际奖励项越少；最早位置最多使用 \(t_{max}\) 步回报。这里统一写成“最小化 loss”：策略项和熵奖励带负号，价值项下降。若照原论文伪代码写成策略目标的梯度上升方向，符号会相反；实现不能把 Actor 上升式与 Critic 下降式机械地交给同一种加法更新。

现代环境 API 必须扩展原论文的 terminal 二分法。任务真实终止（terminated）不自举；固定 rollout 边界要自举；外部时间限制导致的 truncated 通常也应从该 transition 的真实 final observation 自举，然后在 reset 处切断轨迹递推。若时间上限本身属于任务定义，则剩余时间应进入状态，边界按任务终止处理。使用 autoreset 向量环境时，不能误用下一回合初始观测替代 final observation。

四、A3C 更新顺序与陈旧梯度

每个 worker 的一次循环应保持明确顺序：

  1. 从全局参数复制本地 \(\theta',\phi'\)，并清空本地梯度。
  2. 用这份本地快照运行至真实终止或最多 \(t_{max}\) 步，保存短片段。
  3. 按边界语义初始化 bootstrap value，逆序构造 return 与 advantage。
  4. 对局部网络反传并按既定口径裁剪梯度；随后把局部梯度异步应用到全局参数及其优化器状态。
  5. 丢弃片段并重新同步参数。RNN 在真实 episode 开始时重置 hidden state；在非终止片段边界可以携带数值，但必须 detach 计算图，形成截断 BPTT。

片段采样和梯度计算相对于 worker 的本地策略是 on-policy 的；但写回时全局参数可能已被其他 worker 更新，所以该梯度不是“当前全局策略”的精确 on-policy 梯度。原始 A3C 没有用重要性采样修正这种 local/global mismatch。线程数、\(t_{max}\)、环境速度差异和同步成本都会改变陈旧度。

可把一次更新的陈旧度记为 \(\Delta u=u_{\text{apply}}-u_{\text{sync}}\)：worker 同步本地参数后，全局已发生多少次更新才应用该梯度。仅记录平均值会掩盖慢 worker，至少应看中位数、P95、最大值及其与梯度范数/回报的关系。陈旧噪声可能换来吞吐，但不能先验称为有益正则。

原论文使用单机多线程的 Hogwild 风格更新，并比较 momentum SGD、独立 RMSProp 统计、共享 RMSProp 统计；在论文的 Atari 子集消融中，共享平方梯度统计的 RMSProp 更稳。现代多进程复现必须实际验证全局参数和优化器状态位于共享存储，且明确锁、原子性和更新顺序；仅仅启动多个 process 并不自动等价于论文并发语义。

五、A2C：同步屏障换来更规整的批

A2C 在一次 rollout 内冻结策略参数，让 \(N\) 个环境各收集 \(T\) 个 transition；对每个环境的片段末端分别处理终止与 bootstrap，再把 \(N\times T\) 个样本聚合为规则批次，通常计算一个联合梯度并同步更新一次。Stable-Baselines3 的 A2C 也把 batch 定义为 n_steps × n_envs，每个 rollout buffer 做一次整批更新。

同步并不要求环境必须在不同进程运行：向量环境可以串行，也可以并行。若环境并行执行，慢环境会在每次向量 step 或 rollout 屏障处拖住整体；换来的好处是参数版本统一、批处理规整、GPU/CPU 向量化更直接。

维度 A3C A2C
参数更新 worker 异步应用梯度 聚合后同步一步
rollout 内参数 各 worker 使用各自本地快照 所有环境使用同一参数快照
更新顺序 受调度影响，通常不确定 屏障后固定顺序，更易复现
批量形状 到终止时可短于 \(t_{max}\) 通常为规则 \(N\times T\)
主要硬件取向 原论文面向单机多核 CPU 向量环境，CPU/GPU 都方便
主要代价 写竞争与梯度陈旧 同步屏障、慢环境与大批尺度
短期 rollout 存储 有 有
长期 replay 无 无

OpenAI 2017 年的 Baselines 文章报告，其同步 A2C 实现在相应基准上达到或超过异步实现，并未观察到异步噪声的性能收益。这是特定代码、任务与预算的经验结果，不是“A2C 对所有任务都不差于 A3C”的定理。文中的 deterministic 仍是更新调度语义，不是把随机策略改为 argmax/均值动作。

六、原论文网络与实验口径

原论文覆盖 Atari、TORCS、MuJoCo 连续控制和 Labyrinth 3D 迷宫。Atari 网络用卷积共享主干，再分成策略 softmax 与标量 value 输出；Labyrinth 版本加入 LSTM 处理部分可观测性；连续动作实验使用高斯策略。论文把 Actor 与 Critic 参数分开记号，但实际网络通常共享非输出层。

阅读历史结果时要保留实验口径：

  • 论文的五游戏训练速度图把异步方法放在 16 个 CPU core 上，与单张 Nvidia K40 上的 DQN 比较；这说明当时的工程可行性，不能单独证明算法样本效率更高。
  • 该图的 DQN 曲线是固定超参数的 5 个 seed；异步方法曲线则从 50 次学习率采样实验中取最佳 5 个模型平均。两组平均曲线的选择口径不同，不能把它们简单当作同质的五次独立复现实验。
  • 57 个 Atari 游戏的评估先在 6 个游戏上调学习率和梯度范数裁剪，然后固定全部超参数并应用到 57 个游戏。所谓“统一超参数”应理解为调参后固定应用，而不是完全没有开发集选择。

因此，论文证实的是其并行 actor-learner 框架在这些历史基准上的稳定性和广泛适用性；它没有证明 A3C 在所有任务、现代硬件或相同样本预算下优于 PPO/SAC。

七、后继方法定位

GA3C / PAAC分别提高 GPU 批处理效率，或采用并行同步 Actor-Critic。
ACER加入 replay、截断重要性采样与偏差修正，并用 trust-region 风格约束更新。
ACKTR使用 K-FAC 近似自然梯度，同时处理策略与价值函数的曲率。
IMPALA将 actors 与 learner 解耦，以 V-trace 修正行为策略滞后。

IMPALA 的关键问题与原始单机 A3C 不同：高吞吐 actors 通过队列把轨迹送给集中 learner，数据可能来自显著滞后的行为策略；V-trace 用截断重要性权重修正。它不是简单地“把 A3C 线程扩到更多机器”。ACER 则明确允许 replay 数据，因此也不能再沿用 A2C/A3C 的无 replay 训练目标。

八、何时选 A2C/A3C

  • 教学、轻量 CPU、多环境基线：优先 A2C，数据时间轴和更新顺序更容易审计。
  • 环境步耗时差异很大、必须避免全局更新屏障：异步架构可能提高吞吐，但要显式测量陈旧度，不能只比较 wall-clock。
  • 希望有限复用最新 on-policy 批次：考虑 PPO。它保存旧 log-prob，对同一批做多 epoch，并用概率比与 clipping 约束更新；不能只把“多个 epoch”搬进 A2C 而保持原目标不变。
  • 希望长期、大量复用 replay：考虑 SAC、TD3、ACER 等明确的 off-policy 方法。
  • 大规模 actor/learner 解耦：研究 IMPALA/V-trace 或其他有行为策略修正的分布式设计，而不是直接增加 A3C worker。

选择时至少同时报告环境 transition、optimizer update、wall-clock、硬件与环境并发度。吞吐更高、样本效率更高和最终回报更高是三个不同命题。

九、实现验收清单

  1. A2C rollout 期间参数保持冻结；更新前用同一 observation/action 重算的 old/new log-prob 在容差内一致。
  2. A3C 每个片段开始先同步本地参数并清空局部梯度；片段结束只应用一次本片段梯度，避免跨片段意外累积。
  3. 真终止、外部截断和 \(t_{max}\) 边界分别测试；autoreset 时使用 final observation，自举只发生一次。
  4. RNN 在 episode 开始重置 hidden state，在非终止片段边界 carry value 但 detach graph；padding 不参与 loss 归约。
  5. A3C 全局参数与预期共享的 RMSProp 状态确实共享；用小测试确认多个 worker 看到彼此的更新。
  6. 每个 worker/environment 使用可追踪的不同随机数流，避免 fork 后复制相同 RNG 状态；仍需多个顶层 seed 报告结果。
  7. 监控每 worker 采样步数、应用更新数、梯度范数、\(\Delta u\) 分位数、queue/锁等待和 learner 吞吐。
  8. A2C 与 A3C 都记录短期 rollout 占用；文档不得把“无 replay”误写成“完全不存 transition”。
  9. 单 worker A3C 与单环境 n-step Actor-Critic 做语义对照；同步 worker 数、\(t_{max}\) 或 batch 增大后重新解释学习率和更新频率。
  10. 评估使用冻结归一化统计与独立环境，多 seed 报告均值和离散程度；不要只展示调参后最佳运行。
