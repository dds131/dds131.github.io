GR00T N1 总览/⑤ 推理部署与动作块消费

POLICY I/O · K-STEP SAMPLING · CHUNK CONSUMPTION · SAFETY

固定 n1-release 的公开入口是 Gr00tPolicy.get_action：它把原始观测经过变换、一次主干与 K 次动作侧 Euler 更新，再把归一化的 [16,32] 输出逆变换成有序物理字段；公开代码没有动作块消费者、实时保证或机器人安全控制器。

1 + K每个动作块一次 backbone，动作 encoder/DiT/decoder 各运行 K 次。
K=4 / 16论文和两个公开 CLI 默认4；固定 checkpoint config 默认16。
16×29 → 16×32GR-1 物理动作维度与模型 padding 后维度。
R0本轮仅完成静态规格与网页验收，未执行推理、服务或机器人。
公开已实现固定发布配置目标部署合同未知或未验证
返回：GR00T N1 总览下一页：⑥ 实验、基准与合成数据收益

页面边界与 Training 入站

本页只拥有初代 N1 的 Policy I/O、运行时调用、采样、服务边界、动作块消费目标合同和安全边界。Flow 数学留在 ③ Flow Matching，优化与制品生成留在 ④ Training，结果数字留给 Experiments。固定证据来自 n1-release commit 755876a9afdb41ca6eb6383b36f4a0adb085c73f、checkpoint nvidia/GR00T-N1-2B revision fc879581ca32f4f6d6e02cf0cc80452f6b0c3873 和论文 arXiv:2503.14734v2；不把主线 2026 API 或 N1.5/N1.6 行为移植到本页。

进入本页前，权重、model config、processor/data config、metadata、字段顺序、归一化规则和本体映射必须形成同一版本闭包。下列合同与上一页逐字一致；三个 validation 字段是发布门，不是本轮已通过的运行结果。

Policy 调用路径与 wrapper 边界

flowchart LR
  O[raw observation dict] --> B[batch detection]
  B --> F[forward transforms]
  F --> M[GR00T_N1.get_action]
  M --> V[one backbone pass]
  V --> K[K action-side Euler steps]
  K --> N[normalized 16x32]
  N --> R[reverse transforms]
  R --> A[physical action fields]

Gr00tPolicy 负责 checkpoint 路径、model/transform 的 eval()、metadata 注入、batch 处理、整链 torch.inference_mode()、CUDA bfloat16 autocast、输出 float32/CPU 化与逆变换。裸 GR00T_N1.get_action 只做 prepare→backbone→action head→validate；它不加载 metadata，也不反归一化。动作头自身的 @torch.no_grad() 不覆盖此前运行的 backbone，因此不能把裸模型调用当作等价入口。

Policy 虽接受 CPU device 值，固定 wrapper 的 autocast device type 仍写死为 CUDA，所以 CPU 整链没有被固定版本证明。prepare_input 只转换浮点叶子的 dtype；整数/布尔叶子保留索引和 mask 语义。归一化动作以 float32 搬到 CPU 后才开始 inverse transform。

默认 GR-1 I/O、batch 与字段形状

默认 data_config=gr1_arms_waist、embodiment_tag=gr1。视频键为 video.ego_view，单样本原始 shape [1,256,256,3]、dtype uint8。state/action 都按 left_arm 7、right_arm 7、left_hand 6、right_hand 6、waist 3 排列，总物理维度 29；动作 horizon 为16，单样本物理块是 [16,29]。

固定默认字段合同
模态 键/顺序 shape 或约束
video video.ego_view [1,256,256,3] uint8
state left_arm → right_arm → left_hand → right_hand → waist 7+7+6+6+3=29
language config annotation.human.coarse_action 配置声明
language example annotation.human.action.task_description 示例键；与配置不一致
action 与 state 同序 [16,29] physical

语言示例之所以可能通过，是 GR00TTransform 只寻找唯一 annotation 键；这不消除公开契约张力。batch 判定则扫描键名含 state 的数组：任一值 rank<3 即按单样本处理，无 state 键时默认已 batched，且没有跨模态 batch-size 一致性检查。单样本结果使用无 axis 的 squeeze，自定义 D=1 动作字段可能从 [16,1] 退化为 [16]，所以外层 batch 维和字段 feature 维必须分别校验。

Transform、metadata、pad 与反归一化

默认正向链是：video 转 Tensor→0.95 crop→224×224 linear resize→仅训练态 ColorJitter→回 NumPy；state 转 Tensor→sin/cos；训练 action 转 Tensor→min-max；各字段变换后按固定顺序 concat，最后由 GR00TTransform 做 VLM processing、pad 和本体 ID。Policy 把组合变换切到 eval，故 crop/resize 保留、ColorJitter 关闭。

Policy 读取 experiment_cfg/metadata.json，以 embodiment_tag.value 选唯一条目，经 DatasetMetadata.model_validate 后递归注入 transforms；缺条目是硬错误。固定 metadata 顶层只有 gr1，视频为 256×256、3通道、20 fps，统计字段为 min/max/mean/std/q01/q99。metadata 键集合不等于 runtime 有序选择。

state 的29维经 sin/cos 变58再 pad到64；action 的29维 pad到32。inverse 按 action 有序字段和原始维度切片，只取前29维并丢弃 padded tail。固定 selector 是 gr1→24、new_embodiment→31；调用者不能提交任意整数代替完整 metadata、mapping、字段与训练制品绑定。

forward: z = 2(x-min)/(max-min) - 1
inverse: x = (z+1)(max-min)/2 + min

逆变换前没有 clip；z 超出 [-1,1] 会外推到训练统计范围之外。训练 min/max 不是硬件限位。公开 Policy 没有 joint limit、速度/加速度/jerk、碰撞或 NaN gate；机器人适配层必须逐字段做 finite、shape、range、rate 和约束校验。

K 步采样、随机性与生效优先级

x_0 ~ Normal(0, I), shape [B,16,32]
for j in 0..K-1:
  bucket_j = int(1000*j/K)
  v_j = decoder(DiT(action_encoder(x_j, bucket_j), condition))
  x_{j+1} = x_j + v_j/K

视觉语言 backbone 和 state encoder 在循环外各运行一次；action encoder、DiT、decoder 运行 K 次，循环内不重采噪，固定源码也没有跨步 attention K/V cache。论文 v2 报告 K=4，checkpoint config 默认16，Gr00tPolicy(denoising_steps=...) 会覆写 config，两个公开 CLI 默认都显式传4。源码不验证正值：目标入口必须在构造前拒绝 K&lt;1，并记录最终生效 K。

K=4 的桶是 0/250/500/750；K=16 是 0/62/125/187/250/312/375/437/500/562/625/687/750/812/875/937。它们只是固定公式的静态展开，不构成速度或精度结论。

每次调用从 torch.randn 开始，接口不接收 noise、Generator 或 seed，因此相同观测不保证相同动作。调试 provenance 至少绑定 request ID、observation timestamp、artifact hashes、effective K、seed 或初始噪声 hash、device/dtype 与 output hash；原始图像和敏感指令默认不得落日志。

三层延迟账本与计量边界

T_model = T_forward_transform + T_backbone
        + K*(T_action_encoder + T_DiT + T_decoder + T_Euler)
        + T_inverse_transform
T_rpc = T_serialize + T_queue + T_transport + T_server + T_deserialize
T_loop = T_sensor_age + T_rpc + T_safety_gate + T_actuator_dispatch

模型、RPC 与闭环延迟不能混成一个毫秒数。CUDA 测量需同步，且要报告 warmup、设备、batch、K、网络和 p50/p95/p99/max。固定证据没有成套 benchmark，所以 latency SLA 为 not-established，也不能声称 realtime。

ZeroMQ 服务拓扑与暴露风险

公开 inference_service.py 由 server 构建 Policy，再启动 ZeroMQ REP 的 RobotInferenceServer；端点是 ping、kill、get_action、get_modality_config。REQ/REP 循环串行接收、处理、响应，没有 worker pool、batcher、优先级、取消或 backpressure。CLI 虽有 host 参数，server 分支只传 port；默认 bind host 是所有接口，因此示例拓扑不能冒充生产服务。

请求和响应使用 torch.save，接收端为 torch.load(weights_only=False)。固定服务没有认证、授权、传输加密、payload size limit、协议版本、request ID 或 replay 防护，kill 也没有鉴权。timeout_ms=15000 只存为属性，未设置 socket send/receive timeout；recv() 仍可能阻塞，异常响应也只有非结构化 ERROR。该示例只能放在受信隔离边界，禁止直接暴露到公开网络。

动作块消费、重规划与 deadline 目标合同

公开 Policy/服务返回每字段 [16,D_i] 的完整动作块；示例只打印 shape，eval_policy.py 只做离线轨迹 MSE。固定代码没有机器人 command adapter、action queue、execution prefix、tail 丢弃、replanning trigger、control frequency、observation freshness、watchdog 或 emergency-stop state machine。下面是目标部署合同，不是公开实现。

flowchart LR
  O[observation + capture time] --> P[Policy returns H_pred=16]
  P --> G[field, finite, range, rate, safety gates]
  G -->|pass| Q[enqueue H_exec prefix]
  G -->|reject| S[hold or stop]
  Q --> R[new observation or replan event]
  R --> N[new plan; discard old tail]

H_pred=16 是模型预测 horizon；H_exec 是一次实际消费的前缀，必须配置在1..16。每个动作携带 observation ID、capture time、plan ID、chunk index 与 deadline；新计划通过 gate 后替换旧计划，丢弃未执行 tail，禁止新旧块交错。允许 fixed-prefix、fixed-wall-time、event-triggered 三种模式，但实验必须登记实际选择。

设控制频率为 f_ctrl，名义执行窗口 T_exec=H_exec/f_ctrl。metadata 的20 fps 是数据视频采样率，不等于控制频率。只有 capture time、sensor age、RPC latency 与 gate latency 满足 deadline，块才能入队；迟到计划默认拒绝，不无限重放旧 tail，进入带原因码的 hold/stop。hold-last 是否允许必须绑定机器人、速度限制与已验证时长。
