数据划分、统计量与泄漏边界

当前官方实现先在 main() 设置固定种子 1，再用 np.random.permutation 以 episode 为单位按 train_ratio=0.8 划分。命令行 --seed 到 train_bc() 内才设置，因此改变训练 seed 不会改变这一路径下的 train/val episode 划分。这是实现事实，不是所有复现必须沿用的协议。

get_norm_stats(dataset_dir,num_episodes) 在划分前读取全部 episode 的动作和 qpos，计算逐维 mean/std；因此验证 episode 参与统计量。泄漏的是每维矩统计量，不是完整轨迹。没有 train-only 对照时，既不能声称影响可忽略，也不能声称一定造成显著偏差。

更严格的泛化协议可以只用训练 episode 计算统计量，并把同一统计量应用于验证；但这已改变预处理协议，旧结果不能直接横比。每次实验至少应记录 episode ID 清单、split seed、数据版本、stats scope 与 stats hash。当前页面只做静态审计，没有读取训练数据。

随机切片怎样构成一个样本

EpisodicDataset.__len__ 返回 episode 数；__getitem__(index) 先锁定该 episode，再在其时间步中均匀随机选择 start_ts。因此一 epoch 是“每条 episode 抽一个随机起点”，不是遍历所有时间窗口。episode 之间等权，但时间步并不等权：短 episode 中单个时间步被抽到的概率更高。

观测取 start_ts 的多相机图像和 qpos。动作标签先读取到 episode 末尾：仿真从 start_ts 开始，真机从 max(0,start_ts-1) 开始；后者是公开实现的对齐修补，不能写成严格同步保证。动作先写入 episode 长零缓冲并生成 is_pad，传入 policy 后动作和 mask 一起截断到 H。

padding 在动作归一化前是零，归一化后一般变成 -mean/std，所以必须依赖 mask 排除；不能靠值等于零识别 padding。

batch 字段、shape 与归一化

DataLoader 输出与 policy 内 H 截断必须分开
字段 DataLoader 一般 shape Policy 截断后 语义
image [B,C,3,H_img,W_img] 不变 当前时刻多相机 RGB。
qpos [B,d_q] 不变 当前关节状态。
actions [B,T_ep,d_a] [B,H,d_a] 绝对目标关节位置标签。
is_pad [B,T_ep] [B,H] True 表示补齐时间步。

三套归一化的作用域不同：图像先在 Dataset 中除以 255 到 [0,1]，再在 policy 中使用 ImageNet mean/std；qpos 与 action 各自使用本数据集逐维 mean/std，std 下限裁到 1e-2。动作与 qpos 统计量不能互换。

训练 checkpoint 必须与生成它时的 dataset_stats.pkl 成对管理；配套关系由数据版本、字段 shape 与 hash 证明，不能靠文件名猜测。页面不展示真实本地数据路径。

前向路径与 L1 + beta·KL

训练调用同时传入 actions 和 is_pad，因此启用 CVAE recognition 路径：真实动作块与 qpos 产生 mu,logvar，重参数化得到 32 维 z；图像、qpos 和 z 进入主 Transformer，输出 a_hat:[B,H,d_a]。推理不传动作并使用 z=0，完整差异见 CVAE。

当前公开目标可压缩为：

\[\begin{aligned} \mathrm{all\_l1} &= |a-\hat a| \in \mathbb R^{B\times H\times d_a},\\ \mathcal L_{L1} &= \operatorname{mean}\!\left(\mathrm{all\_l1}\odot \neg\mathrm{is\_pad}[:,:,\mathrm{None}]\right),\\ \mathcal L_{KL} &= \operatorname{mean}_{b}\sum_{j=1}^{32}D_{KL}\!\left(q(z_j\mid x,y)\Vert\mathcal N(0,1)\right),\\ \mathcal L &= \mathcal L_{L1}+\beta\mathcal L_{KL}. \end{aligned}\]

L1 在归一化动作空间逐元素计算；KL 先沿 32 个 latent 维求和，再对 batch 求均值。公开示例 beta=kl_weight=10，但 beta 的有效尺度依赖动作归一化、padding 比例、latent 维数和 KL reduction，不能跨平台直接照搬。

论文 Algorithm 1 写 MSE，而论文正文实现说明与公开 policy.py 使用 L1。复现当前公开实现时应使用 L1，不能把两者混写为等价。模型还返回 is_pad_hat，但当前公开 task loss 未使用它；这里不猜作者动机，也不把它加进目标。

padding mask 与固定分母

当前代码先把 padding 位置的逐元素 L1 乘零，再对完整 [B,H,d_a] 张量调用 mean()。所以分母仍是 B*H*d_a，不是有效元素数。若样本 b 只有 m_b 个有效时间步，它的 L1 相对完整块被乘以 m_b/H；越靠 episode 尾部的短片段权重越低，而 KL 仍按样本等权。

三种归约定义不同，也会改变有效 KL/L1 比
Reduction 分母 样本权重 协议状态
当前公开实现 B*H*d_a 与 m_b/H 成正比 当前复现目标。
Valid-element mean d_a*sum_b(m_b) 每个有效时间步等权 替代目标。
Equal-sample mean 每样本先除 d_a*m_b，再对 B 均值 每个随机起点样本等权 替代目标。

三者不等价。改为有效元素均值或逐样本归一化会改变 L1 的尺度和有效 KL/L1 比，需要重新标定 beta 并使用固定协议比较。当前固定分母口径可以讨论其权重后果，但不能仅凭这一点武断标成 bug。

反向传播、优化器与训练量

一次 batch 的顺序是 zero_grad → forward → loss → backward → optimizer.step → zero_grad，没有梯度累积。当前模型构造使用 AdamW，并按参数名是否包含 backbone 分成 non-backbone 与 backbone 两组；官方仿真示例两组 LR 均为 1e-5，参数组存在但示例数值相同，weight_decay=1e-4。

当前公开训练循环没有 learning-rate scheduler，也没有 gradient clipping。这只是实现事实，不能推出训练必然不稳定，或恒定 LR 是平台期后继续改善的原因。梯度范数、非有限值、参数更新量与两组实际 LR 都是未来监控请求，当前为 NOT_RUN。

因为 Dataset 长度等于训练 episode 数，一 epoch 的样本数是 N_train，更新数是 ceil(N_train/batch_size)。官方语境中的 50 条示范、80/20 划分、batch 8 对应 40 个训练样本与 5 次更新；2000 epochs 对应 80,000 次随机片段抽样与 10,000 次更新。这是配置代入算术，不是所有 ACT 任务的固定训练量。

官方 README 的仿真示例为 2000 epochs，并建议真机数据至少 5000 epochs 或 loss plateau 后继续其时长的 3–4 倍。这是配置/经验引用，不是自动停止规则。比较训练量必须同时换算 episode 数、batch、随机窗口抽样数和 optimizer updates；完整命令、环境和硬件归规划中的 Reproduction 页面。

验证、checkpoint 与训练诊断

验证传入真实动作，所以仍走 CVAE posterior 随机采样，而不是部署的 zero-latent 路径；验证 episode 每轮也重新随机起点。官方 10 条验证 episode、batch 8 形成 8+2 两个 batch，compute_dict_mean 对两个 batch 等权，于是尾 batch 中单个样本的报告权重是首 batch 单样本的 4 倍；shuffle=True 还会改变哪些样本落入高权重尾 batch。

policy_best.ckpt 由最低 validation total loss 选择，policy_last.ckpt 保存最终训练状态，另有当前每 100 epoch 的周期 checkpoint 和配套 dataset_stats.pkl。best 不等于最终状态，也不等于部署成功率。固定窗口、样本等权、posterior mean 或多 z 平均都属于新的验证协议，必须另行记录。

诊断字段与证据上限

至少应分开记录 l1、kl、beta*kl、总 loss、有效步比例、逐维 KL/active latent、梯度范数、两参数组 LR、验证随机源，以及 stats/checkpoint hash。总 KL 接近零只能提示 posterior collapse 风险；确诊还需要逐维 KL 和固定观测下输出对 z 的敏感性。loss 下降也不能证明闭环任务成功。

可先静态排查 shape/mask、stats 与 checkpoint 配对、split/stats scope、验证聚合和制品 hash；需要数据、权重、输出或 rollout 的验证全部保持 NOT_RUN。本页没有读取数据或执行训练。

证据、交接与下一页

本页只拥有数据到参数更新和验证选择合同。CVAE 概率推导归前页，Transformer token/memory/action queries 归 Transformer，固定函数映射归 Source Code，命令、环境与重复实验归规划中的 Reproduction，rollout 与任务成功率归 Experiments。

交给 Temporal Ensembling 的固定 payload

下游接收成对的 checkpoint 与 stats hash、H、绝对目标关节位置动作合同，以及训练 posterior sample/部署 zero latent 的差异。Temporal Ensembling 不参与训练 loss，不应重复数据 split、optimizer 或 checkpoint 选择。
