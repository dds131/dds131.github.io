先冻结 claim、treatment 与 result snapshot

一句“某方法达到 82.4%”还不是可审计 claim。最小发布单位必须同时回答谁、在哪里、测什么、与谁比、证据有多强、数字来自哪个冻结来源：

Claim = subject treatment
      + benchmark population
      + outcome / measure
      + comparison target
      + scope / uncertainty
      + source snapshot

因此可写：“paper_v5 下，Harness VLA (CC) 在 LIBERO-Pro 的 800 trials 报告 82.4%，direct π_RLinf 报告 50.0%；两者相差 +32.4 percentage points，这是 whole-treatment descriptive contrast。”不能缩成“Memory 提升 32.4%”。

  C["EvaluationClaimRecord"] --> T["TreatmentDefinition"]
  T --> P["EvaluationProtocolManifest"]
  P --> S["ResultSnapshotManifest"]
  S --> R["ResultTableRow"]
  R --> U["UncertaintyReport"]
  R --> B["BaselineComparabilityAssessment"]
  B --> X["allowed claim strength"]
  U --> X
class Planner / Memory sequence / grounding 发布标签
direct frozen VLA 无 Harness Planner / Memory policy direct / policy 内部 direct_frozen_vla
online Harness few-shot online / published reference Memory dynamic / live online_harness_fewshot
online Harness zero-shot online / target-setting Memory denied dynamic / live online_harness_zero_shot
Flash pure 无 online Planner / published plan-anchor compiled / live flash_pure
hybrid fallback compiled 后切换 owner treatment 已改变 / live hybrid_fallback
external baseline method-specific method-specific external_reported

Treatment identity 还要冻结 planner family/model/reasoning/config、frozen VLA backend/checkpoint、primitive registry、Memory mode/snapshot、online planning、Flash selection、fallback relabel、observation/controller/environment、timeout/reset/budget、code/data/protocol revision 与 success authority。任一字段 unknown 时不能默认 same。

paper_v5、leaderboard_latest_2026-10-14 与 reproduction_<revision> 是三个独立 ResultSnapshotManifest。同名方法也不能跨 snapshot 拼接 suite、timing、token 或 Memory 字段。claim strength 从 reported → descriptive → associational → ablation-supported → causal under protocol 逐级增加；diagnostic hypothesis 永远不能冒充已证实根因。

四类 benchmark 与 experimental unit

下表只描述论文 v5 protocol。current reproduction 若任务数、seed、Memory snapshot 或 success authority 不同，必须另建 manifest，不能继承这一行。

benchmark paper v5 population experimental unit Memory / source regime direct backend success authority
LIBERO 4 suites × 10 tasks × 10 seeds = 400 task×seed trial reference seed bootstraps；held-out eval π_RLinf native benchmark predicate
LIBERO-Pro 8 cells × 10 tasks × 10 seeds = 800 suite×task×seed trial few-shot；Goal 另有 zero-shot π_RLinf top-level terminated / native predicate
RoboCasa365 50 tasks × 5 held-out seeds = 250 task×seed rollout reference seed；三个 split 均 held-out RLDX-1 environment native success
RoboTwin C2R 50 tasks × 5 randomized seeds = 250 task×randomized-seed rollout expert-verified clean trace → randomized LingBot-VLA native eval_success 
flowchart TD
  S["suite / split / perturbation cell"] --> T["task"]
  T --> E["seed / case"]
  E --> O["episode outcome"]
  M["shared Memory / card"] -.cluster.-> E
  B["service / infrastructure batch"] -.cluster.-> E
  P["paired treatment on same task×seed"] -.pair.-> E

Episode 是最小 outcome observation，却不自动是独立统计单位：seed 嵌套于 task，task 嵌套于 suite/split；相同 seed 可能做 paired treatments；shared Memory/card/model service 和 infra batch 会产生 cluster correlation。reference seed 不计 reported evaluation；Memory source、selection cases 与 evaluation cases 分开。RoboTwin clean source 也不是 randomized evaluation case。

Planner finish、tool ok、primitive completion、视觉接近、夹爪闭合、视频结束或文件存在都不是 benchmark success。结果只能引用 environment/official evaluator/authorized operator 的 typed verdict。

每个 assigned unit 必须属于 success / failure / timeout / cancelled / safe_stop / infra_invalid / missing_asset / fallback_relabel / excluded_predeclared 之一。后验删除 timeout、missing 或某方法的失败会改变 denominator；只能按预声明规则处理并给 sensitivity。

baseline comparability 与公平对照

“同一 frozen backend”是重要条件，但不表示除 Harness 外所有变量都相同。逐对比较还要检查 population、coverage、seed/pairing、observations/action/controller、success predicate、Memory/reference、Planner/registry、budget/reset/timeout、missing/fallback、revision；比较效率时还要检查 hardware/load/cache 和计时边界。

verdict 证据条件 页面允许行为
DIRECTLY_COMPARABLE primary fields same/paired，差异明确 descriptive 或 paired contrast
PARTIALLY_COMPARABLE 只有部分字段相同 共同子集或带 caveat 的对照
CONTEXT_ONLY external protocol/coverage 不同 只作背景，不排序
NOT_COMPARABLE outcome/population/identity 不同 不计算 effect
UNKNOWN source 信息不足 保留 unknown，不猜测 
flowchart TD
  A["same outcome + population?"] -->|no| N["NOT_COMPARABLE"]
  A -->|unknown| U["UNKNOWN"]
  A -->|yes| B["same coverage + success authority?"]
  B -->|no| C["CONTEXT_ONLY / common subset"]
  B -->|yes| D["backend, Memory, budget, revision checked?"]
  D -->|all primary same| E["DIRECTLY_COMPARABLE"]
  D -->|declared differences| F["PARTIALLY_COMPARABLE"]
  D -->|unknown| U

论文内 direct contrasts 是 whole-system descriptive comparisons：LIBERO、LIBERO-Pro、RoboCasa365、RoboTwin C2R 均不能从总表拆出 Memory、Planner、retry 或 primitive 的独立贡献。RATS 与 Cap-X 在论文 Table 3 缺 LIBERO-10 T/S，overall 只覆盖六个 cells；82.4 − 43.8 = +38.6 pp 是 headline cross-coverage context，不是八 cells 上的 paired effect。

Codex、CC、Astra、Qwen 与 no-reasoning rows 也不是只替换一个 planner 字符串。reasoning、token budget、tool behavior、Memory snapshot、run batch 和 timing scope 可能同时变化；equality manifest 不完整时至多 PARTIALLY_COMPARABLE。

schema: baseline-comparability-assessment/v1
BaselineComparabilityAssessment:
  assessment_id: <opaque-id>
  row_a: <row-id>
  row_b: <row-id>
  field_checks:
    population: same | different | unknown
    coverage: same | different | unknown
    seed_pairing: same | different | unknown
    vla_backend: same | different | unknown
    success_authority: same | different | unknown
    memory_policy: same | different | unknown
    budget_reset_timeout: same | different | unknown
    revisions: same | different | unknown
  verdict: DIRECTLY_COMPARABLE | PARTIALLY_COMPARABLE | CONTEXT_ONLY | NOT_COMPARABLE | UNKNOWN
  allowed_claims: [<claim-class>]
  reasons: [<reason-code>]

LIBERO-Pro · 800 π_RLinf 50.0% Codex 72.1%；CC 82.4% +22.1 / +32.4 pp whole Harness vs direct
RoboCasa365 · 250 RLDX-1 30.0% prose 57.1/48.6；Table 4 57.2/48.8 +27.1 或 +27.2；+18.6 或 +18.8 pp 保留 prose/table source boundary

RoboCasa paper prose/abstract 与 Table 4 不完全相同。本页不从 rounded split 反推唯一 raw counts，也不选择一个值冒充“修正版”：引用 headline 时保留 57.1/48.6，引用 Table 4 时保留 57.2/48.8。其 Overall 以 18 Atomic + 16 Composite-Seen + 16 Composite-Unseen 共 50 tasks 等权；每 task 五个 held-out seeds。future reproduction 若 per-task seed 数不同，task-weighted 和 rollout-weighted 可能分离。

每个 row 最少报告 assigned/eligible/attempted/scored、success/failure/timeout/missing/invalid/fallback、numerator/denominator、task/suite/split coverage、aggregation、missing/invalid policy、rounding precision 与 raw-data availability。

flowchart TD
  A["paired task×seed outcomes"] --> B["paired difference + cluster-aware CI/test"]
  C["per-task counts"] --> D["task bootstrap / hierarchical"]
  E["aggregate counts only"] --> F["naive binomial · descriptive only"]
  G["no numerator/denominator"] --> H["not computable"]
  I["source reports no test"] --> J["do not invent p-value"]

粗略教学公式可以写为：

\[\widehat p=\frac{\text{successes}}{\text{scored trials}},\qquad \operatorname{naive\_SE}=\sqrt{\frac{\widehat p(1-\widehat p)}{N}}.\]

但 seeds/tasks/suites 的 clustering、paired treatments、Memory/card reuse 与 selection 破坏简单 IID 假设；这不是 paper-reported CI。只有 aggregate counts 时，naive binomial interval 也只能作粗略 descriptive interval。

measure 定义 使用边界
percentage-point difference p_A - p_B 最直观的成功率描述差
relative risk/change p_A/p_B 或 (p_A-p_B)/p_B baseline 非零且同口径
paired risk difference same units 的 Y_A-Y_B paired outcomes 可用
odds ratio odds contrast 需解释，不替代 pp
task-level average effect per-task difference 平均 避免大 task 过度加权

八 cells、多 planners、多 baselines 和多个 failure modes 会增加偶然发现。primary contrast 应预声明；其余标 exploratory，并说明 correction/FDR policy。sensitivity 至少覆盖 missing/timeout counted failure vs predeclared exclusion、task-macro vs rollout-micro、paper text vs table、six vs eight cells、Flash same-seed vs held-out、pure vs fallback-relabelled。

failure taxonomy 与多因一果

Failure event 是 observation，不是 root cause。“object did not move”可能来自 wrong target、bad binding、rejected primitive、empty grasp、controller fault 或 stale verifier；“success=false”也只是 terminal observation。

code layer / owner observable event 不能直接推出
PROT protocol / evaluation owner wrong snapshot、leakage、denominator drift robot skill failure
MEM Memory / curator missing、stale、wrong-scope trace Planner inability
PLAN planner / task owner wrong target/order/subgoal VLA contact failure
GRND perception/binding owner absent、ambiguous、stale coordinate/frame semantic plan wrong
PRIM registry/admission owner invalid primitive/args/unit/frame physical failure
VLA contact policy owner empty grasp、miss、short insertion high-level plan wrong
ANL controller/adapter owner unreachable、collision reject、transport/drop VLA weakness
SAFE safety owner inhibit、safe stop、watchdog benchmark root cause alone
VER verifier/evaluator owner false positive/negative/unknown execution state itself
INFRA service/session owner timeout、crash、stale callback method-level weakness
BUDG scheduler/protocol owner turn/time/retry exhausted unrecoverable task

Attribution 必须多标签：primary 只有在 intervention evidence 足够时才填写；同时列 contributing、ruled-out evidence、unresolved alternatives、confidence、reviewer/timestamp。证据不够就写 unknown。

wrong target 可是 PLAN/GRND；empty grasp 可是 VLA/GRND/PLAN；lift 后掉落可涉及 VLA/ANL；placement 后 predicate false 可是 VLA/VER/PLAN；base move 后 offset 可是 GRND/ANL；timeout 的 INFRA/BUDG 也只是候选。method failure、safe stop、budget exhaustion、service timeout 是否计失败由预声明协议决定，并同时给 all-assigned 与 valid-only sensitivity。
