架构、视觉 Token 与动作接口摘要

N1.5 仍是 VLM 条件主干 + DiT 动作主干。官方称 VLM 在预训练和微调中冻结、适配器被简化；公开微调默认 tune_llm=false, tune_visual=false，而保存 config 的 tune_visual=true 是第三种口径，三者不能合成单一训练事实。官方架构图标 Eagle-2，正文称从 Eagle 2.5 出发，公开语言模型是 Qwen3-1.7B；命名张力保留。

224/14=16，因此关闭 pixel shuffle 时每 tile 有 16²=256 个视觉 token；N1 的 ratio0.5 对应 64 个。动态 tiling 两代都有，实际每帧视觉 token 是 tile数×256，不是恒定256。N1.5 连接器为 1152→2048 单层 Linear，Qwen3 由原28层物理保留前12层。

image/text -> frozen truncated VLM -> tokens width 2048
  -> vlln LayerNorm(2048)
  -> 4-layer VL self-attention, 32 heads x 64 = 2048
state tokens + 32 learned future tokens + 16 noisy action tokens
  -> 16 alternating DiT blocks, query width 1536, cross KV width 2048
  -> decode final 16 action positions

project_to_dim=null 令主干输出保持2048；DiT query宽1536，cross KV宽2048，动作投影 hidden_size/output_dim=1024。序列总长是 S+32+16，只有运行时 S=1 才是49；公开 post-VLM vlln 不等于官方所说“进入LLM前的输入LayerNorm”。

FLARE 目标轴与 DreamGen 数据轴

FLARE · 目标轴官方在 Flow Matching 外加入系数0.2的FLARE，用于预训练与后训练。方法把DiT中间特征经future tokens与未来观测潜在表示对齐；无动作人类第一视角视频可只通过对齐项参与。固定公开动作头含future tokens，但没有target encoder、projection heads、cosine alignment或EMA teacher，loss字典仍只有Flow MSE。状态是：official-used / method-defined / public-structure-present / public-loss-absent。
DreamGen · 数据轴DreamGen v2以四阶段视频世界模型管线生成neural-trajectory video，再用latent action model或inverse dynamics model恢复伪动作。官方列出内部GR‑1、OpenXE、模拟GR‑1/DexMG、DreamGen neural trajectories、AgiBot-Beta五类预训练来源；未公开完整快照、比例、过滤规则或全部生成代码。

FLARE 解决“加什么目标、如何利用无动作视频”，DreamGen 解决“生成什么训练数据”。二者可共同参与系统，但没有 DreamGen→FLARE 或 FLARE→DreamGen 的依赖证据。

官方训练、公共微调与推理边界

两个不能拼成一套配方的车道
车道 已知 不可推出
官方内部训练 250,000 steps；原文“1K H100”；global batch16,384；AdamW；cosine；warmup0.05；FLARE coefficient0.2 不能把1K精确解释为1000设备，不能反推per-device batch或GPU-hours
公开微调 视觉默认冻结；公开Flow路径可执行；固定源码与checkpoint可审计 不等价完整官方预训练；公开FLARE loss路径缺失

N1.5 checkpoint 保存 num_inference_timesteps=4，N1 checkpoint 保存16；N1论文已经报告4步可用，所以N1.5不是“四步首次证明”。公开 get_action 从标准高斯开始，主干每 chunk 一次、动作侧K次正 Euler；没有显式 generator/seed 参数，同观测同动作不保证。32 future tokens 在公开推理的每个DiT block参与计算，即使公开loss没有FLARE项也不会自动消失；K改值原因仍unknown。

Policy继续输出归一化 [16,32] 动作容器，再由inverse transform按有序字段拆分、反归一化和绑定本体；16×32不等于任意机器人32自由度。部署另需字段顺序、统计、单位、控制周期、动作消费、freshness/watchdog、急停和人工监督；公开模型仓库没有完整chunk consumer，模型也不是安全监督器。
