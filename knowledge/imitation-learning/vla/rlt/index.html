RLT 是 VLA 上的在线 RL 方法层

RLT 是挂接在预训练 VLA 上的在线强化学习方法层：VLA 提供内部任务表征与参考动作，RL Token 把高维 token 压缩成可供小型 Actor-Critic 使用的状态接口，在线阶段只更新轻量控制与价值网络。它不是新的 VLA、π0.6 的后继模型、reward token 或 action tokenizer。

基座 VLA 负责从观测、指令和本体状态产生任务相关 hidden tokens 与 reference action chunk；Stage 1 学习紧凑的 RL Token 接口；Stage 2 冻结 VLA 与 RL-token 表征模块，更新 actor、online twin critics 及其 target 参数。真正送往执行侧的是 actor 提议经独立 safety/control gate 接受、裁剪或拒绝后的动作块。critic、Replay、target network 和本网页都不直接控制机器人。

身份online_rl 方法层，不进入 VLA family/version 血统。
训练范围Stage 2 只更新轻量 learner；“冻结 VLA”不等于系统无可训练参数。
决策粒度actor 在 VLA action chunk 接口附近做价值引导的改进。
证据状态论文 v2 定义方法；实现仓库必须独立绑定身份与版本。
检查先修并开始 RLT直接查看七页地图返回 VLA 后训练与对齐

四个概念不能互换：language token 表示多模态序列；action token/action representation 表示或可解码为动作；RL Token 是紧凑 RL 状态接口；reward 才是环境或人工给出的标量学习信号。RL Token 本身既不是标量 reward，也不是直接动作。

从 VLA 建议到在线更新的完整闭环

flowchart LR
  O["观测 + 指令"] --> V["预训练/适配后的 VLA"]
  V --> H["hidden tokens"]
  H --> E["冻结的 RL-token encoder"]
  E --> X["RL state: z_rl + proprio"]
  V --> R["reference action chunk"]
  X --> A["online actor"]
  R --> A
  A ==>|"control proposal"| G["safety / control gate"]
  G ==>|"accepted executed action"| ENV["机器人与环境"]
  ENV --> N["next obs / reward / done"]
  N --> B[("Replay")]
  X --> B
  R --> B
  G --> B
  B -.->|"parameter update"| Q["twin critic / actor learner"]
  Q -.->|"delayed target update"| T["target actor / critics"]
  T --> Q

这是依据论文 v2 绘制的教学抽象；边表示数据、更新或控制关系，不表示所有模块位于一个进程，也不表示论文已经完整实现独立 safety gate。文本版关系是：VLA 产生 hidden tokens 与 reference；encoder 形成 RL state；actor 提议动作；gate 决定实际执行动作；环境反馈进入 Replay；learner 从 Replay 更新 online 参数，再滞后同步 target 参数。

RLT 论文的在线 Stage 2 冻结 VLA 与 RL-token 表征模块；Stage 1 是否联合进行任务 VLA 适配由目标中的 VLA 项与设置决定。因此“冻结 VLA”不能无条件外推到整个两阶段流程。冻结权重也不表示运行状态、缓存、输入规范、归一化、动作反归一化或 Replay 分布不会变化，更不表示 actor/critic 不会提出不安全动作。

继承的 RL 组件与 RLT 新接口

层级 组件 在 RLT 中的作用 是否是 RLT 新理论
通用 RL MDP、TD bootstrap、Replay、Target Network、Twin-Q、Actor-Critic 提供 off-policy 连续控制骨架 否
RLT 方法接口 RL Token、VLA reference conditioning、chunk-level RL、BC-like anchor、reference dropout 把 VLA 表征与动作先验接入轻量在线 learner 按论文限定表述
在线系统工程 warmup、actor/learner 并发、人工奖励与接管、版本化、发布/回滚、safety gate 使真实机器人数据闭环可管理 论文部分描述 + 工程实现

五个非等价关系是本专题的读图护栏：RL Token ≠ reward token；reference-conditioned actor ≠ 必须显式 residual actor；BC-like anchor ≠ 硬动作约束或安全证书；Twin-Q ≠ 两个 target network；online system ≠ 一项 loss 或单个神经网络。reference dropout 是论文接口设计的一部分，但不是任意任务上的稳定性保证。

RLT = frozen VLA representation/reference
    + compact RL state interface
    + lightweight off-policy actor-critic
    + versioned online interaction loop

这是总览唯一保留的概念式。encoder/decoder、stop-gradient 与表征目标进入 RL Token 页；TD target、critic/actor loss 与 target update 进入 Actor-Critic 页；action horizon、reference、BC anchor 和 dropout 进入 Action Refinement 页。

适用条件、安全交接与完成标准

RLT 只有在基座 VLA 已能进入局部精密阶段、policy I/O 合同稳定、奖励与终止可审计、在线交互有界且受监控时，才是研究候选。Replay 必须保留实际执行动作、policy version、终止原因与干预来源；系统还需要离线门禁、灰度发布、回滚与回放审计。若 VLA 无法识别任务、动作 frame/unit/归一化错误、done 与 truncated 混淆、奖励和安全目标冲突，先修复这些问题，不应期待 Q 值补救错误语义。

权限 责任 不得替代
reward authority 给 transition 奖励/标签并记录来源 emergency stop
intervention authority 临时接管动作并留下 provenance 长期发布批准
stop authority 硬件/软件急停、限位与 watchdog critic 低分提示
release authority 审批 policy version 进入评测/部署 单次成功或训练 loss
rollback authority 恢复已知安全版本和数据快照 继续在线更新“自愈”

BC-like anchor、Twin-Q、target network、warmup 或人工奖励都不是安全证书。只能接受零失败的生产环境不适合直接在线探索；无独立急停、工作空间限制、操作员授权与发布批准时，本页不给出继续执行路径。本文没有安装、训练、推理、评测、仿真、SIL/HIL 或机器人操作，也不含权重下载、连接设备或启动服务的控件。
