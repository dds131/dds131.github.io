DDPG 常被概括为“一个 Actor 加一个 Critic”，但标准算法在逻辑上维护四套参数化函数： 在线 Actor、在线 Critic 及其两个滞后目标副本。代码可以把它们实现为四个模块、函数式参数快照， 或带共享编码器的受控变体；关键不是 Python 对象数量，而是在线与目标参数的职责边界。 两个在线参数集合被优化器更新；两个目标参数集合只通过显式复制缓慢跟随。四者的功能、输入和 梯度边界如果混淆，代码可能正常运行、loss 也会下降，却已经不是正确的 DDPG。

本页重点。第三节的动作仿射映射、第五节的三条计算路径和第六节的梯度开关。 分工：确定性策略梯度为何成立见 子页 ①； 公式、optimizer 和更新顺序见 子页 ③。 本页不把“网络宽度 400/300”写成算法定义，因为现代实现常用不同宽度与融合位置。

一、四个网络不是四个独立任务

记在线 Actor、Critic 参数为 \(\theta,\phi\)，目标参数为 \(\bar\theta,\bar\phi\)。

逻辑实例 参数集合 optimizer 直接更新 反向传播用途 主要输入
在线 Actor \(\mu_\theta\) \(\theta\) 是，Actor optimizer 接受经 Critic 动作端传回的梯度 当前状态 \(s\)
在线 Critic \(Q_\phi\) \(\phi\) 是，Critic optimizer Bellman 回归；Actor 前向中的可微评分器 当前状态和动作 \((s,a)\)
目标 Actor \(\mu_{\bar\theta}\) \(\bar\theta\) 否 target 前向，无梯度 下一状态 \(s'\)
目标 Critic \(Q_{\bar\phi}\) \(\bar\phi\) 否 target 前向，无梯度 \((s',\mu_{\bar\theta}(s'))\)

目标网络不是第二组独立学习器。初始化时必须从在线网络精确复制参数；若模块含持久 buffer， 初始状态也应一并复制。之后目标参数不接收 optimizer step，只按规定执行 Polyak 插值。 若在线与目标网络分别随机初始化，训练最早期的 Bellman target 已与在线估计 毫无对应，目标网络“稳定副本”的含义被破坏。

  subgraph ONLINE["在线参数：optimizer 更新"]
    A["Actor mu_theta"]
    C["Critic Q_phi"]
  end
  subgraph TARGET["目标参数：只做软复制"]
    AT["Target Actor mu_bar"]
    CT["Target Critic Q_bar"]
  end
  A -. "Polyak: theta → theta_bar" .-> AT
  C -. "Polyak: phi → phi_bar" .-> CT
  AT -->|next action| CT
  C -->|dQ / da| A

二、在线 Actor：把反复动作搜索近似摊销成前向传播

2.1 输入与输出

Actor 接收批状态

\[S\in\mathbb R^{B\times d_s}\]

并输出批动作

\[\mu_\theta(S)\in\mathbb R^{B\times d_a}.\]

对于低维状态，常见实现是多层感知机；视觉状态则可在前面接卷积或视觉编码器。 DDPG 只规定“状态映射到可微连续动作”，没有规定必须两层 MLP，也没有规定所有任务共用 同一种编码器。

连续动作 Q-learning 若直接采用贪心改进，需要在每个状态求解 \(\arg\max_a Q(s,a)\)。Actor 用跨状态共享的参数函数近似承担这项搜索：训练时沿 \(\nabla_aQ\) 做局部改进，使用时一次前向传播给出动作。这可以理解为摊销式近似优化， 但并不表示 Actor 在每个状态都求得了 Q 的全局最大动作。

2.2 为什么最终常用 tanh

连续控制环境通常给出每维上下界有限的有界 Box 动作空间。若网络最后一层不限制范围，早期随机权重就可能 输出极大动作；环境内部的 clip 通常位于 Actor 训练图之外，Actor loss 不会自动得到 “动作已被环境截断”的正确导数。tanh 提供规范化动作

\[u_\theta(s)=\tanh z_\theta(s)\in[-1,1]^{d_a}.\]

再把它映射到物理动作区间。

2.3 非对称、逐维动作边界的正确映射

设每维下界、上界向量为 \(\ell,u\)：

\[\mathrm{scale}=\frac{u-\ell}{2}, \qquad \mathrm{bias}=\frac{u+\ell}{2},\] \[a = \mathrm{bias} + \mathrm{scale}\odot\tanh z. \tag{1}\]

逐维乘法记为 \(\odot\)。式 (1) 同时处理：

  • 对称区间，如 \([-2,2]\)；
  • 非对称区间，如 \([-1,2]\)；
  • 每个关节不同边界。

该映射还要求每一维的 \(\ell_i,u_i\) 都是有限数且 \(u_i>\ell_i\)。若动作空间含无界维度， 不能直接从无穷边界构造 scale / bias；应为这些维度选择与环境和控制约束一致的参数化， 而不是让 tanh 公式产生无穷数或假装存在有限安全边界。

只写

\[a=a_{\max}\tanh z\]

隐含了所有维度都以 0 对称、且上界可代表幅值。对非对称区间，这种写法会让一侧动作永远 不可达。

动作归一化不是装饰。Actor 输出、探索噪声、动作 clip 和 Critic 输入必须使用一致尺度。 若一个关节范围是 \([-1,1]\)、另一个是 \([-100,100]\)，直接在物理空间给两维加相同标准差， 意味着完全不同的相对探索强度。

2.4 tanh 饱和的梯度代价

\[\frac{\mathrm d}{\mathrm dz}\tanh z = 1-\tanh^2 z.\]

当 \(|z|\) 很大，导数接近 0。动作长期贴边可能来自最优控制确实需要边界，也可能来自 Actor logit 饱和、映射错误或 Critic 梯度持续推向边界。仅看最终动作无法区分， 诊断时要同时记录 pre-tanh logit 和 clip 前动作。

三、在线 Critic：既是回归器，也是 Actor 的可微评分器

3.1 输入、输出与形状

Critic 输入

\[S\in\mathbb R^{B\times d_s}, \qquad A\in\mathbb R^{B\times d_a},\]

输出每个样本的标量

\[Q_\phi(S,A)\in\mathbb R^{B\times1}.\]

最后一层通常不加 tanh 或 sigmoid，因为折扣回报的范围由奖励与折扣决定， 并不天然落在固定区间。

3.2 状态与动作在哪里融合

早融合

先连接状态与动作，再送入第一层。代码短、形状清晰，CleanRL 等现代教学实现常见。

后融合

先编码状态，再在后续隐层加入动作。接近 DDPG 原论文低维网络的描述。

两者都实现 \(Q(s,a)\)。融合位置影响归纳偏置和参数量，却不是“是否属于 DDPG”的判据。 对机器人多模态观测，也可先分别编码图像、本体状态，再与动作特征融合；必须报告结构， 但不应把某一结构说成算法唯一形式。

3.3 Critic 的双重角色

  1. Bellman 回归器：对 replay 动作 \(a\) 输出 Q，与 target \(y\) 做回归。
  2. Actor 的回报评分器：对当前 Actor 动作 \(\mu_\theta(s)\) 输出 Q， 并提供 \(\nabla_aQ_\phi(s,a)\)。

第一种路径更新 Critic 参数；第二种路径使用 Critic 的导数，但目标是更新 Actor。 这两个前向调用可能使用同一批状态，却不能混用动作。 Critic 近似的是目标策略下的折扣回报，不是状态转移函数，因此不能把它解释成环境动力学模型。

四、目标 Actor 与目标 Critic

4.1 为什么目标端也需要 Actor

Bellman target 需要下一状态的目标动作：

\[a'=\mu_{\bar\theta}(s').\]

若改用在线 Actor \(\mu_\theta(s')\)，即使目标 Critic 很慢，下一动作仍会在每次 Actor step 后改变。target 的动作端成为快速移动源，双目标网络只剩一半。

4.2 为什么目标 Critic 不能被 optimizer 更新

目标 Critic 的职责是提供滞后参考。若它同时拟合本轮 target，它会和在线 Critic 一样快速 变化；软更新不再定义唯一生命周期。正确做法是：

  • 从在线 Critic 初始化；
  • 不加入 Critic optimizer；
  • target 前向放在 no-grad 区域；
  • 可将目标参数设置为 requires_grad_(False) 作为防御性约束；
  • 每次规定的 target update 时刻，用在线参数插值。

4.3 参数与状态缓冲区

网络可能含两类状态：

  • 可训练参数，如权重、偏置；
  • 非参数缓冲区，如 BatchNorm 的 running mean / variance。

只对 parameters() 做 Polyak 不会自动更新所有 buffer。若使用 BatchNorm， 必须明确目标网络模式与统计量同步策略；否则权重在缓慢跟随，归一化统计却来自另一套分布， 目标输出仍会漂移。还要注意：torch.no_grad() 只关闭自动微分，不会阻止 train 模式的 BatchNorm 更新 running statistics，也不会关闭 Dropout。目标前向通常应使用 确定且明确的模式，并按选定策略复制或维护 buffer。低维 MLP 的现代实现常省略 BatchNorm， 从而减少这类状态管理。

原论文使用 Batch Normalization 应对不同观测量纲；现代实现也常在环境或 replay 输入端 做显式标准化。二者不能不加说明地叠加，也不能从“原论文用了 BatchNorm”推出 “DDPG 算法定义要求 BatchNorm”。

五、同一批数据的三条计算路径

从 ReplayBuffer 采样

\[\left(S,A,R,S',M_{\mathrm{term}}\right).\]

5.1 路径 A：Critic 更新

flowchart LR
  B["Replay batch"] --> Q["Q_phi(S,A)"]
  B --> TA["mu_bar(S')"]
  TA --> TQ["Q_bar(S',mu_bar(S'))"]
  TQ --> Y["y = R + gamma(1-M)Q_bar"]
  Y --> L["MSE(Q_phi,y)"]
  Q --> L
  L -->|"backward: update phi"| Q
  • 当前动作使用 replay 中实际执行的 \(A\)。
  • target Actor 和 target Critic 都不求梯度。
  • 只更新在线 Critic 参数 \(\phi\)。

5.2 路径 B：Actor 更新

flowchart LR
  S["Replay states S"] --> A["mu_theta(S)"]
  A --> Q["Q_phi(S,mu_theta(S))"]
  Q --> L["-mean Q"]
  L -->|"gradient through action"| A
  Q -. "Critic weights not stepped" .-> Q
  • ReplayBuffer 只提供状态 \(S\)。
  • 动作由当前在线 Actor 重新计算。
  • 梯度从 Q 输出流向动作，再流向 Actor 参数。
  • Critic 参数不应在这一阶段被 optimizer 更新。

5.3 路径 C：目标参数软复制

flowchart LR
  A["online Actor theta"] -. "interpolate" .-> AT["target Actor theta_bar"]
  C["online Critic phi"] -. "interpolate" .-> CT["target Critic phi_bar"]

这不是反向传播。没有 loss、没有 optimizer、没有梯度；只是对参数状态做显式插值。

六、冻结 Critic 参数为什么不阻断动作梯度

Actor step 常见做法是临时执行：

for parameter in critic.parameters():
    parameter.requires_grad_(False)

actor_optimizer.zero_grad(set_to_none=True)
actor_loss = -critic(obs, actor(obs)).mean()
actor_loss.backward()
actor_optimizer.step()

for parameter in critic.parameters():
    parameter.requires_grad_(True)

这里关闭的是“对 Critic 参数求梯度”，不是“把 Critic 前向从计算图摘掉”。 Critic 的运算仍由可微张量操作组成，自动微分仍可计算输出对输入动作的梯度 \(\partial Q/\partial a\)，再传给 Actor。

requires_grad_(False) 也不会清空 Critic 在上一阶段留下的 .grad，不会切换 train()/eval()，更不会冻结 BatchNorm buffer。 因此，检查“Actor step 有没有误改 Critic”时，要分别检查 optimizer、参数梯度、模块模式和 buffer； 不能只看其中一个信号。若 Critic 含 BatchNorm 或 Dropout，Actor 前向采用何种模式必须显式规定并在之后恢复。

错误的做法包括：

  • 对 critic(obs, actor(obs)) 整体使用 no_grad： 动作梯度也被切断。
  • 对 Actor 输出 detach： Critic 得到动作，但 Actor 收不到梯度。
  • 忘记清空 Critic 的旧梯度后用“有没有 grad”判断本轮是否更新： 看到的可能是上一阶段残留。
参数梯度开关与输入梯度是两件事。Actor 更新需要 Critic 对动作可导， 不需要也不应为 Critic 权重积累新梯度。

七、张量形状：最容易静默出错的一层

以下表格针对低维向量观测，以 batch size \(B\) 为例：

张量 推荐形状 备注
obs \([B,d_s]\) 浮点
action \([B,d_a]\) 已缩放到环境动作单位
reward \([B,1]\) 与 Q 统一
next_obs \([B,d_s]\) 截断时应保存真实 final observation
terminated \([B,1]\) bootstrap mask
q、target_q \([B,1]\) 避免与 \([B]\) 混算

若 q 是 \([B,1]\)、target 是 \([B]\)，PyTorch 广播可能生成 \([B,B]\) 误差矩阵。程序不会报错，loss 也会变化，却在比较每个预测与整批所有 target。 实现页会给出 shape 断言；本页的结论是：每个标量字段从 buffer 到 loss 全程保持同一秩。 图像观测通常是 \([B,C,H,W]\)，字典或多模态观测则保留各字段自己的 batch-first 结构； 不应为了套用 \([B,d_s]\) 而把所有观测无条件压平。无论观测结构如何，reward、终止掩码与 每样本 Q 仍应明确对齐为 \([B,1]\) 或另一套全程一致的标量形状。

八、原论文结构与现代实现的差异

方面 DDPG 原论文低维任务 常见现代教学实现 算法不变量
隐层宽度 400、300 常见 256、256 Actor 输出连续动作，Critic 输出标量 Q
Critic 动作注入 第二隐层加入动作 首层连接状态与动作 Q 必须对动作可微
隐层激活 ReLU ReLU 为主，也可选择其他激活 未固定
归一化 使用 BatchNorm 常省略或外部标准化 量纲需被妥善处理
Actor 输出 tanh 后按动作范围缩放 action scale + bias 输出必须匹配逐维边界
探索 OU 过程 常见 Gaussian 随机性属于行为动作

网络层数、宽度和融合点是实现选择；四套逻辑参数的职责、Actor 动作梯度、目标端 no-grad 与软复制 才是 DDPG 结构的核心不变量。

九、知识重点、结构创新与边界

9.1 必须掌握的结构重点

  1. 在线 Critic 在 Critic step 中拟合 replay action，在 Actor step 中评价当前 Actor action； 两条路径共享网络，但动作来源和更新对象不同。
  2. 目标 Actor 稳定 target 的动作选择端，目标 Critic 稳定估值端；只保留一个目标副本会让另一端快速移动。
  3. 参数是否求梯度、参数是否被 optimizer step、输入是否保留梯度、buffer 是否更新，是四个不同问题。
  4. Actor、探索噪声、环境 clip、ReplayBuffer 和 Critic 必须对动作单位达成一致。

9.2 机制来源与 DDPG 的结构组合创新

  • DPG 提供的机制：用确定性 Actor 把连续动作搜索近似摊销为可微前向映射，并由 Critic 的动作梯度训练；这不是 DDPG 首次提出。
  • DQN 提供的稳定化思路：经验回放与目标网络；DDPG 将其带入深度连续动作 Actor-Critic，而不是重新发明这两个机制。
  • DDPG 的关键组合：同时维护目标 Actor 与目标 Critic，并用软复制让 target 的动作选择端和 价值估计端共同滞后；在线 Critic 又同时连接 Bellman 回归与可微策略改进。

因此，这里的“创新”应理解为面向深度连续控制的结构组合与工程稳定化，而不是把每个组成模块 都归为 DDPG 的原创发明。

9.3 不能越界的结论

  • 目标网络只减缓 target 漂移，不消除自举偏差、过估计、分布外动作或函数逼近误差，也不提供收敛保证。
  • 四套逻辑参数不等于四个独立优化目标；目标副本没有自己的 loss。
  • 400/300 隐层、BatchNorm 与 OU 噪声是原论文实现选择，不是 DDPG 定义的必要条件。

十、结构审计清单

  1. 目标网络是否从在线网络完整复制，而非独立随机初始化？
  2. 目标参数是否完全不属于 optimizer？
  3. Actor 是否对每个动作维使用正确的 scale 和 bias？
  4. ReplayBuffer 是否存环境实际执行的动作？
  5. Critic 输出是否为每个样本一个无界标量？
  6. Critic step 是否用 replay action，Actor step 是否用当前 Actor action？
  7. Target 路径是否 no-grad？
  8. Actor step 是否先清空 Actor 梯度，并保留动作梯度、同时避免更新 Critic 参数？
  9. reward、mask 与 Q 的 shape 是否完全一致？
  10. 若用了 BatchNorm，在线/目标网络的统计量、Actor step 模式和 train/eval 切换是否有明确策略？
