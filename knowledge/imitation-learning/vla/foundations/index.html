知识库 · 机器人模仿学习与 VLA · VLA · 公共基础

具体视觉—语言—动作（Vision-Language-Action，VLA）策略可以使用不同的视觉语言主干、动作 token、连续生成头和训练数据，但它们进入机器人闭环时都必须回答同一组接口问题：看到了什么、在什么时刻和坐标系、输出什么动作、怎样变成控制命令、如何评测、出错时由谁拒绝或接管。

  • 原论文事实：不同来源只支持其明确任务、数据、模型和评测条件下的结论。
  • 方法迁移：把论文机制映射到另一机器人、动作空间或系统时，必须重新验证。
  • 工程建议：接口契约、版本清单、安全层与回滚是本站面向可复现性的治理要求。

只有能定位到官方仓库的明确版本或提交时，代码行为才标为官方实现事实；仍需目标任务实验支持的判断标为待验证假设。

必需先修：Behavior Cloning 建议复习：DAgger 开始公共基础：机器人学、坐标系与控制接口 →

为什么 VLA 需要公共基础

VLA 不是“图像加一句话再输出动作”这么简单；任何可复现的闭环都同时依赖观测契约、空间与时间语义、动作表示、数据血缘、训练版本、评测协议、实时系统和独立安全责任。本站把 VLA policy 定义为：消费视觉观测与任务或语言条件，并产生可由机器人控制链消费的动作表示。它也可能使用本体状态、历史、深度或力觉，但它不是 planner、控制器或安全系统的同义词。

三层责任不能互相代替

语义与规划层

主要产物：任务目标、语言条件、子目标、技能选择或上下文。

不能替代：可执行动作、时限保证和物理安全。

VLA policy 层

主要产物：动作、动作分布或按时间排列的动作块。

不能替代：低层控制器、执行确认和硬件约束。

控制与安全层

主要产物：坐标变换、限幅、控制、监控、停止与回退。

不能替代：模型学习、任务语义和数据覆盖。

为什么先学 BC

VLA 训练常包含示范数据上的监督目标，但部署时策略访问的是自己行为诱导的轨迹。一次动作误差会改变后续观测，因此逐样本 loss 不包含完整的闭环后果。Behavior Cloning 给出这个起点；DAgger 进一步说明为什么要关注策略诱导分布上的数据。公共基础树不提供一个“最佳模型”，而是把任何候选系统都必须回答的问题分给十个责任页。

从观测到安全执行的闭环

flowchart LR
  ENV["环境与机器人"] --> SENS["传感器与机器人状态"]
  SENS --> PRE["时间同步、标定与预处理"]
  TASK["任务、语言与历史条件"] --> POLICY["VLA policy"]
  PRE --> POLICY
  POLICY --> AREP["动作表示或动作块"]
  AREP --> POST["反归一化、frame 变换与限幅"]
  POST --> SAFE["独立安全约束与运行监控"]
  SAFE --> CTRL["低层控制器与执行器"]
  CTRL --> ENV
  SAFE -->|"拒绝、停止或人工接管"| FALLBACK["安全状态 / fallback 所有者"]
  ENV --> LOG["结果、事件与系统日志"]
  LOG --> DATA["版本化数据与划分"]
  DATA --> TRAIN["训练或适配候选"]
  TRAIN --> EVAL["离线 + 闭环 + 安全评测"]
  EVAL -->|"门禁通过"| POLICY
  EVAL -->|"失败或证据不足"| DATA

图 1｜VLA 的正常路径、反馈路径与失败出口。 环境产生带时间和坐标语义的观测，任务条件与预处理结果进入策略；候选动作经反归一化、坐标变换、限幅和独立安全约束后，才交给低层控制器。结果与事件进入版本化数据，新的候选只在离线、闭环和安全评测门禁通过后进入发布路径。训练反馈箭头表示受控、可回滚的版本迭代，不表示运行中的模型可以未经审批自动更新。

每条边都需要契约

边 必须回答 责任页
传感器 → 预处理 frame、标定、时间戳、缺失语义和观测年龄是什么 机器人/控制；实时部署
任务条件 → policy prompt 来源、历史窗口、冲突处理和消费方是什么 VLM/grounding；长时序
policy → 动作表示 输出是 token、连续值、分布还是 chunk 动作表示
动作 → 控制器 反归一化、frame 变换、clamp、模式和频率是什么 实时部署
安全层 → 执行器 哪些确定性约束可拒绝动作，谁拥有 fallback 安全/可靠性
环境 → 数据 success、failure、intervention 和 termination 怎样记录 数据/跨本体
候选 → 评测 数据隔离、闭环协议、trial/seed 和 I/O hash 是什么 统一评测

观测缺失、过期或标定不匹配时，不得用静默填充值冒充有效输入；动作 schema、归一化或 frame 不匹配时，应拒绝下发而不是猜测转换。推理、网络或队列超时必须进入已定义的保持、停止或人工接管路径。ID（分布内）/ OOD（分布外）条件、矛盾指令或安全监控触发时，模型的置信或拒答语句不能覆盖独立约束；评测失败或证据不足时，候选保持未发布状态并返回数据与训练分析。

共享术语与接口契约

最小术语表

术语 本站工作定义 详细责任页
VLM 视觉语言模型（Vision-Language Model）：消费视觉和语言并产生语义表示或文本输出；不自动等于控制策略 VLM 与空间 Grounding
embodied VLM 用于具身观测或任务的 VLM；可能只规划或描述，不一定输出动作 VLM 与空间 Grounding
planner 产生任务、技能、子目标或原语选择的组件 长时序
VLA policy 把观测和任务条件映射为机器人动作表示的策略 动作表示；训练/适配
action decoder / expert 把共享表示变成离散或连续动作的专用组件 动作表示
embodiment 机器人形态、运动学、传感器、动作和控制接口的组合 数据/跨本体
adapter 在数据、观测或动作接口间执行显式转换的版本化组件 数据/跨本体；实时部署
action chunk 按时间排列的一段候选动作；预测长度不等于实际执行长度 动作表示；实时部署
rollout 策略与环境闭环交互产生的轨迹 统一评测
safety layer 可独立拒绝、限幅、停止或升级处理的约束与监控责任 安全/可靠性

policy_io_contract 只在此预览

契约块 最小字段 禁止的默认假设
观测 模态、shape、dtype、frame、unit、timestamp、rate、calibration、mask “RGB 就足够”“相机顺序无关”
任务条件 prompt 模板、processor、历史、允许命令、冲突处理 “自然语言天然无歧义”
动作 维度、语义、absolute/delta、frame、unit、mode、normalization、gripper mapping “相同维度在所有机器人上语义相同”
时序 observation age、inference/control rate、chunk、prediction/execution horizon、deadline “推理频率等于控制频率”
版本 model/checkpoint、code、processor、adapter、stats、robot config、contract version/hash “只记录 checkpoint 即可复现”
约束与回退 clamp、workspace、collision/watchdog、timeout、human owner、safe state “模型拒答等于物理安全”

这个 overview 的 policy_io_contract_id 为空，因为它只展示字段类别，不冒充真实系统合同。具体单位、枚举、校验规则和值由机器人/控制、评测、实时部署和安全页冻结。checkpoint 只是 release bundle 的一个成员；processor、adapter、统计文件、代码、机器人配置与契约 hash 缺一不可。

数据采样频率描述记录写入数据集的速率；模型推理频率描述产生新动作或动作块的速率；底层控制/执行频率描述控制器更新与执行器接收命令的速率。动作块覆盖时间同时取决于执行步数和控制周期，不能把任意一种频率当作另外两种。

十页公共知识树

十页按同一条核心路线累积制品。每张卡只给一个主链接、一个中心问题、一个交付物和一个边界；页面序号不是模型优劣排名。

1 · 机器人学、坐标系与控制接口
中心问题
观测和动作处在哪个 frame、单位、控制模式与时间基准中？
交付物
机器人观测—动作接口表及限制清单。
边界
不替具体平台填写数值或安全阈值。
2 · VLM 与空间 Grounding
中心问题
视觉、语言、状态与空间信息怎样编码、融合并由谁消费？
交付物
模态流、token/mask 与 grounding 责任图。
边界
语言理解不自动等于空间精度或可执行性。
3 · 动作表示与生成目标
中心问题
joint/Cartesian、absolute/delta、token、CVAE、Diffusion、Flow 与 chunk 怎样选择？
交付物
动作表示与目标函数决策表。
边界
不同表示不能脱离控制接口直接排序。
4 · 数据与跨本体
中心问题
异构机器人数据怎样采集、同步、转换、混合、划分与追踪？
交付物
数据 schema、转换和血缘 manifest。
边界
共享字段不代表动作语义已经一致。
5 · 奠基模型与创新谱系
中心问题
各奠基模型继承了什么、改变了什么，代价与证据是什么？
交付物
带证据日期的创新谱系卡。
边界
时间更晚、规模更大都不等于更适合目标任务。
6 · 训练与适配
中心问题
预训练、co-training、SFT、冻结、全量与 PEFT 怎样选择并验证？
交付物
数据—参数更新—checkpoint—回滚方案。
边界
训练 loss 不能单独证明闭环收益。
7 · 长时序任务
中心问题
task、skill、subgoal、action、记忆、终止与重规划怎样组合？
交付物
分层决策、记忆生命周期与恢复图。
边界
更长上下文不自动带来可靠长期规划。
8 · 统一评测与 Benchmark
中心问题

完成标准、失败边界与下一步

完成十页后应交付什么

  • 观测与动作带 frame、unit、timestamp、rate、calibration/version 和缺失语义。
  • policy 输入输出、processor、adapter、统计文件、checkpoint、代码与机器人配置可追踪。
  • prediction/execution horizon、采样/推理/控制频率和 deadline 不混用。
  • 数据来源、许可、划分、去重、泄漏检查、混合权重和血缘可追踪。
  • 离线、闭环、ID/OOD、trial/seed、置信区间和失败分类口径齐全。
  • 独立安全约束、fallback、人工接管、发布与回滚所有者明确。

评测与部署必须引用同一份 version/hash 一致的 policy_io_contract。可复制的盘点字段包括：任务及成功/终止定义；观测的模态、frame、单位、时间戳、采样率、标定与缺失语义；语言条件来源、允许范围与冲突处理；动作语义、坐标系、归一化、chunk 与控制模式；policy bundle 各组件版本；端到端延迟预算；评测划分与统计口径；独立安全控制器、人工接管和回滚条件。这里提供的是空字段清单，不是任何平台的有效合同。

这些结论不能由公共基础推出

  • 完成专题不能证明某个 VLA 适合目标任务。
  • 更大的预训练模型不能自动证明空间精度、低延迟或安全性更好。
  • 语言泛化或 benchmark 成功不能自动证明真实机器人控制稳定。
  • 较低的离线动作误差不能自动证明闭环成功率更高。
  • uncertainty、拒答或“安全”文本不能替代物理限制与独立安全层。
  • 仿真结果不能脱离 sim-real 条件直接成为真机发布证据。
  • 论文或官方仓库的默认预处理、动作统计与控制频率不能跨机器人直接复用。

来源与证据边界

一手来源只支撑其明确声明，具体实现细节下沉到责任页。RT-2 提出的 VLA 命名与动作 token 路线、OpenVLA 的开源离散动作实例、π0 的连续 Flow Matching 实例共同说明 VLA 不只有一种动作接口；它们不能证明所有 VLA 都必须采用相同 VLM、数据配方或安全架构。

  1. Ross、Gordon 与 Bagnell，A Reduction of Imitation Learning and Structured Prediction to No-Regret Online Learning，AISTATS 2011，PMLR 论文页（离站）：策略诱导分布与闭环数据聚合背景。
  2. Brohan 等，RT-1: Robotics Transformer for Real-World Control at Scale，2022，arXiv:2212.06817（离站）：大规模多任务真实机器人策略背景，不用于定义全部 VLA。
  3. Brohan 等，RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control，2023，arXiv:2307.15818（离站）：VLA 类别命名与动作 token 联合训练实例。
  4. Open X-Embodiment Collaboration，Open X-Embodiment: Robotic Learning Datasets and RT-X Models，2023 / ICRA 2024，arXiv:2310.08864（离站）：跨本体数据标准化与适配背景。
  5. Octo Model Team，Octo: An Open-Source Generalist Robot Policy，RSS 2024，arXiv:2405.12213（离站）：可适配观测/动作空间的通用策略实例。
  6. Kim 等，OpenVLA: An Open-Source Vision-Language-Action Model，CoRL 2024，arXiv:2406.09246（离站）：开源离散动作 token 与参数高效适配实例。
  7. Black 等，π0: A Vision-Language-Action Flow Model for General Robot Control，2024，arXiv:2410.24164（离站）：预训练 VLM 上的连续 Flow Matching 动作专家实例。
  8. Chi 等，Diffusion Policy: Visuomotor Policy Learning via Action Diffusion，RSS 2023 / IJRR，arXiv:2303.04137（离站）：条件动作扩散与 receding-horizon 背景，不用于定义全部 VLA。

证据规则：论文结果保留任务、数据、机器人和评测条件；项目页只能支持其自报内容；代码行为只有绑定版本或提交才标为官方实现事实；迁移到新机器人时必须列出接口差异并重新实验。选择模型之前，先冻结问题和接口。只有当观测、动作、时间、版本、评测与安全责任都能写入同一套契约时，模型成绩才有可比较和可部署的上下文。
