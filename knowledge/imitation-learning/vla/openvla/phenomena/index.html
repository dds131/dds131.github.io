OVL-OBS-01 RT-2-X 查询

论文 Appendix C 报告：BridgeData V2 原始数据含许多全零 transition；RT-2-X 未采用相同预处理，部署时会冻结。作者不能重训该专有模型，固定选择 second-most-likely action 后改善，而“先取 top-1、遇全零再查询 second”的 dynamic 方案更差。作者假设额外查询延迟改变了轨迹；论文未公开候选的联合概率、粒度、API 语义或完整延迟分布，因此不能解释成“每个动作维度取第二大 token”。

竞争解释、测试与证伪条件
  • H1：fallback 额外延迟或抖动中断运动；应在触发点看到 latency/action-age 尖峰。
  • H2：fixed second 的候选动作质量系统性更好；即使延迟匹配，质量差仍存在。
  • H3：controller 对 pause、hold 或 queue 的语义造成 first divergence。
  • H4：服务缓存或 query state 改变了返回行为。
  • H0：trial 分配或 success 判定差异；配对初态与盲评后差异应消失。

安全顺序是先做离线 request trace，再在录制回放或另行批准的仿真中给 fixed-second 注入与 dynamic 匹配的延迟分布；只在独立安全与授权门完整后才可考虑真机。若延迟分布相同仍稳定更差、注入等量延迟不复现，或失败发生在 fallback 之前，H1 被削弱。

schema: openvla.observation-diagnostic.v1
observation_id: OVL-OBS-01
evidence: appendix-c
claim_state: {freeze: observed, fixed-second-better-than-dynamic: observed, latency-explanation: hypothesized-by-authors}
primary_hypothesis: extra-query-latency-perturbs-trajectory
alternatives: [candidate-action-quality, controller-pause-semantics, service-cache-or-state, evaluator-or-trial-allocation]
diagnostic_test: latency-matched-first-divergence
falsifier: failure-precedes-fallback-or-equal-latency-gap-persists
execution_status: not-run

OVL-OBS-02 int8 与时序

同一论文设置里，int8 在非阻塞摘要为 58.1，阻塞摘要为 74.4；固定硬件/软件栈下论文还报告 int8 约 1.2 Hz、int4 约 3 Hz。Table 2 与 Table 11 改变了控制模式且不是逐轨迹配对，所以 16.3 pp 不能当纯时延因果效应。blocking 结果支持速度/时序解释，但仍限定于论文模型变体、任务、硬件与控制栈。

竞争解释、测试与证伪条件
  • H1：低 completion frequency 与更老的 action 是主因。
  • H2：int8 数值误差改变候选动作质量。
  • H3：量化 kernel、device path 或序列化链路带来额外差异。
  • H4：blocking 同时改变 controller 动力学，不只是去除延迟。
  • H0：rollout 方差或非配对初态造成点估计差异。

区分性测试需要匹配 capture-to-execution 的延迟分布、controller 语义、初态与评估分母，同时记录 normalized error、分维物理单位误差、stale action 与 p50/p95/p99。若匹配时序后仍有稳定数值误差和闭环差异，或时序改善而动作误差/成功率不随之变化，则“主要由速度解释”被削弱。

claim_state: supported-within-paper-protocol
primary_hypothesis: runtime-timing-and-action-age
alternatives: [quantization-numeric-error, kernel-or-device-path, controller-dynamics, rollout-variance]
diagnostic_test: matched-timing-controller-and-initial-state
required_metrics: [physical-unit-error-by-dimension, stale-action-rate, latency-p50, latency-p95, latency-p99]

execution_status: not-run

OVL-OBS-03 no-op 冻结

Bridge 的处理是删除每条演示的第一个 transition，不等于检测并删除所有 no-op。LIBERO 则逐动作过滤：translation、rotation 均接近零且 gripper 不变时移除。两套阈值与语义不能混用。论文把高表达策略模仿 no-op 后冻结记录为观察；“闭环 self-loop”是本站分析，不是论文已经证明的唯一机制。

\[o_t \rightarrow a_t\approx 0 \rightarrow o_{t+1}\approx o_t \rightarrow a_{t+1}\approx 0.\]
竞争解释、测试与证伪条件
  • H1：训练 no-op 标签提高了静止动作概率，并在相似观测下形成自保持。
  • H2：safety/controller 将非零 proposed action 归零。
  • H3：统计、frame、unit 或 gripper convention 错配，使动作执行后近似为零。
  • H4：任务包含合法等待，freeze detector 把它误判为故障。
  • H5：capacity、decoding 或观测退化导致重复动作，与标签无关。

必须同时追踪 proposed、safety-modified、commanded、executed、最长 no-op run 与观测变化。若冻结之前 proposed action 持续非零，而归零首次发生在安全层或控制器，标签自保持不是 first divergence；若合法等待标签和观测变化解释了 run，则 detector 需要修订。

evidence: [appendix-c, appendix-e1]
claim_state: observed-in-paper-settings
primary_hypothesis: no-op-label-induced-self-loop
alternatives: [safety-or-controller-zeroing, interface-or-unnorm-mismatch, legitimate-wait, capacity-or-decoding, detector-error]
diagnostic_test: proposed-to-executed-noop-trace
falsifier: nonzero-proposed-actions-before-freeze
execution_status: not-run

OVL-OBS-04 LIBERO margin

实验与基准页记录了 LIBERO 四套件结果；相对于真机新本体适配，OpenVLA 在 LIBERO 的相对优势更窄。作者把它归因于 base OpenVLA 只在真机机器人数据上预训练，而不是仿真数据。这里保留 author-attribution：Figure 5 与 Table 12 的平台、基线、任务、分母和协议不同，不能直接相减成 sim-real 因果量，Octo 的表现也只能作为旁证。

竞争解释、测试与证伪条件
  • H1：缺少仿真预训练导致 domain gap。
  • H2：不同 baseline 与 ceiling 压缩了可见 margin。
  • H3：suite aggregation 隐藏了分任务异质性。
  • H4：预处理、action/control interface 或训练预算不同。
  • H0：seed、sample 与 rollout variance 足以解释窄 margin。

最强的区分性设计只改变“加入仿真预训练”这一变量，冻结模型规模、真实数据、微调预算、processor、控制协议、seed 与评估器，并按四套件逐套报告。若加入仿真预训练仍无一致改善，或改善只随其他改动出现，H1 被削弱。OFT 同时改变多项设计，不能充当该单变量证据。

first-divergence 排障树

先排 measurement 与 lineage，再排接口和 action ABI，然后从模型输出向执行链逐层找第一个不一致；时序、controller、数据与模型机制只在前置层清楚后继续。这个顺序是站内诊断框架，不声称穷尽所有机制。

  1. raw observation
  2. preprocessing
  3. prompt/tokens
  4. logits/tokens
  5. normalized action
  6. physical proposed
  7. safety modified
  8. commanded
  9. executed
  10. evaluator
raw observation → preprocessing → prompt/tokens → logits/generated tokens
→ normalized action → physical proposed → safety modified → commanded
→ executed → evaluator
每站记录 expected、observed、timestamp、artifact/config ref 与 evidence status；
第一处差异只定位层级，不自动等于 root cause。

指标与 instrumentation

token accuracy 与 normalized action L1 都必须公开 split、mask、EOS、dataset slice、sample count、checkpoint 与 aggregation：

\[\operatorname{Acc}_{tok}=\frac{\sum_{n,j}m_{n,j}\mathbf 1[\hat z_{n,j}=z_{n,j}]}{\sum_{n,j}m_{n,j}},\qquad \operatorname{MAE}_{norm}=\frac{\sum_{n,j}m_{n,j}|\hat a^{norm}_{n,j}-a^{norm}_{n,j}|}{\sum_{n,j}m_{n,j}}.\]
