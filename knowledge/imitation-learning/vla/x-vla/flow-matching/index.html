一、本页在专题中的位置

这是整个 X-VLA 专题里论文描述与公开实现差异最集中的一页。论文第 2 节描述的是条件流匹配：回归速度并沿常微分方程积分；当前官方 ee6d 实现则让位置与旋转通道回归干净动作、让夹爪通道输出分类 logit，并在推理时用固定初始噪声与上一步连续动作估计反复重混合。若只按论文公式编写推理循环，不能直接复现公开权重的行为。

本页把三类内容分开：论文声称的方法、源码可以直接确认的事实、以及由代码推得但作者未验证的分析。干净动作与速度输出在连续通道、\(t>0\) 且允许外部仿射换算时可以互推；这不代表两种训练目标、网络参数化或采样算法整体等价。

创新点定位：X-VLA 的主要论文创新是用域特定 Soft Prompt 吸收跨本体异质性；本页涉及的 Flow Matching 与 Rotate6D 都来自已有方法。EEF 对齐和 30 个未来锚点属于论文训练配方的重要设计；连续通道的 x0-prediction、固定噪声重混合与 500 / 10 / 1 则是公开实现事实，论文没有把它们作为经过消融验证的创新提出。
本页刻意不讲：网络结构与张量形状（子页 ②）；训练超参与学习率调度（子页 ④）；源码调用链（子页 ⑤）；采样循环的逐行解释与各评测客户端的执行节奏（子页 ⑥）；反常现象排查（子页 ⑦）。条件流匹配的完整理论推导已在 π0 · Flow Matching 动作生成展开；本页只补上理解论文—实现差异所必需的条件期望。
证据口径：论文层以 arXiv:2510.10274 v1 为准；实现层固定到官方源码提交 6bc2513f5f1cbec715cc668b414392a6cae5c671与 checkpoint 固定配置，复核日期为 2026-10-04。论文说明方法主张；张量混合、损失归约、夹爪标签和采样循环均以固定源码为准。LeRobot 移植版只用于明确集成差异，不反推官方仓库的设计。

二、动作表示：统一到 EE6D 的 20 维

2.1 统一到哪一层

论文第 4.2.2 节的表述是（层一）：把动作空间标准化为末端位姿表示，包含三部分——笛卡尔末端 xyz 位置、用 Rotate6D 编码的绝对末端旋转、以及离散的二值夹爪状态；位置与旋转用均方误差优化，夹爪状态用二元交叉熵优化。

这个选择的关键在于「统一到哪一层」。不是统一到关节指令（各本体自由度与关节顺序不同），也不是只学习无法直接执行的抽象动作嵌入，而是统一到笛卡尔末端控制接口。平台侧仍需把末端目标交给自己的控制器或逆运动学模块，并处理坐标系、可达性、冗余解、动作频率与执行延迟等差异。

换句话说：统一的是较容易跨本体共享的低层笛卡尔目标，不是完整的机器人动力学。同一末端轨迹可能对应不同关节构型、碰撞风险与控制代价；这些差异不会因为采用 EEF 表示而自动消失。

2.2 20 维的逐通道定义

源码 models/action_hub.py 的 EE6DActionSpace 给出确切布局（层二）。字段名里的 _1 / _2 表示第一、第二机械臂；官方已提供的双臂数据处理器通常按左臂、右臂映射，但动作空间类本身并没有把这两个槽位永久绑定到某种硬件命名：

@register_action("ee6d")
class EE6DActionSpace(BaseActionSpace):
    """End-effector layout with xyz, 6D rotation, and gripper channels."""
    dim_action = 20
    gripper_idx = (9, 19)
    GRIPPER_SCALE = 1.0
    XYZ_SCALE     = 500.0
    ROT_SCALE     = 10.0
    POS_IDX_1 = (0, 1, 2);                 POS_IDX_2 = (10, 11, 12)
    ROT_IDX_1 = (3, 4, 5, 6, 7, 8);        ROT_IDX_2 = (13, 14, 15, 16, 17, 18)
这里要纠正一个常见说法。官方 README 把布局写成「3（位置）加 6（旋转）加 1（夹爪）加 10（padding）」，那是单臂视角的描述。源码里 POS_IDX_2 为 (10, 11, 12)、ROT_IDX_2 为 (13, ..., 18)、gripper_idx 为 (9, 19)——后十维是第二机械臂槽；在使用该槽的双臂域中，它不是 padding。若不核对域处理器便把它整段丢弃，会丢失第二机械臂指令。

2.3 这 20 维是怎么从原始轨迹产生的

数据侧的切分在 datasets/utils.py 的 action_slice（层二）：

def action_slice(abs_traj, idx_for_delta=(), idx_for_mask_proprio=()):
    proprio = abs_traj[0]          # [D]      第 0 个点作本体状态
    action  = abs_traj[1:].clone() # [H, D]   后 H 个点作动作块

    if idx_for_delta:              # 指定通道转成相对于 proprio 的增量
        idx = torch.as_tensor(idx_for_delta, dtype=torch.long, device=abs_traj.device)
        action[:, idx] -= proprio[idx]
    if idx_for_mask_proprio:       # 指定通道的本体状态清零
        idx = torch.as_tensor(idx_for_mask_proprio, dtype=torch.long, device=abs_traj.device)
        proprio[idx] = 0.0
    return {"proprio": proprio, "action": action}

action_slice 本身只要求输入为 \(H+1\) 个点，并没有把 \(H\) 写死为 30；论文的默认配方和页面核验的 X-VLA-Pt 配置使用 30 个未来锚点，因此标准配置对应 1 个当前 proprio 加 30 个动作目标。迁移到其他配置时应以数据处理器与 num_actions 为准。这一切分解释了两件事：

状态与动作共享槽位布局在执行可选的 delta 与 mask 处理前，它们来自同一条插值轨迹的相邻切片，因此共用 20 维 EE6D 槽位；处理后部分通道的数值语义可能不同。子页 ② 第 5.1 节说明了 dim_proprio 的维度回退。
绝对与相对两种控制接口idx_for_delta 提供了把指定通道转成增量的开关。论文 Appendix H 的正文说 Simpler-Google 使用 Rel XYZ 加 Abs Rotation，并把原因归于相机改动下绝对参数化更敏感；但同页 Table 9 把该接口列在 FactalData 行，且没有 Simpler-Google 行。论文内部口径并不一致，复现某个基准时应以对应数据处理与评测代码为准，不能只引用其中一句。
30 个锚点不等于每个样本都恰好覆盖 4 秒。num_actions=30 只规定锚点数量；各处理器的 qdur 给出期望的最长未来窗口。官方预训练用的 RoboMind、DROID、AGIBOT 处理器均设为 4 秒，与论文的默认配方一致；下游处理器则出现 1、2、3、5、10 秒等取值。通用处理器实际用 min(cur + qdur, ref.max()) 截止终点，因此轨迹末尾样本会把 30 个锚点压缩到更短的剩余时长，锚点间隔也随之变小。迁移时必须同时检查锚点数、qdur、末端采样策略与执行频率，不能只对齐张量形状。
锚点是表示空间中的线性插值，不是位姿空间中的几何插值。通用 BaseHDF5Handler 用 interp1d 对两个机械臂槽的整条向量逐通道插值：xyz、Rotate6D 六个分量和夹爪都一起处理。因此旋转锚点不是在 SO(3) 上做 SLERP，插值后的六维数也不保证对应正交列；它要到执行端转换旋转时才经 Gram–Schmidt 投影回合法旋转。夹爪跨越开合跳变时则可能得到软标签。这个实现选择会影响监督目标的几何含义。

三、为何选择 Rotate6D：连续性动机与实现约定

3.1 连续性问题的实质

论文给的理由是避免欧拉角与四元数固有的不连续性（层一）。这句话需要展开才有用。

问题不在于「这些表示能不能表示旋转」，而在于是否存在适合欧氏空间回归的连续表示与连续解码。

  • 欧拉角：以常见的 \([-\pi, \pi)\) 取值为例，跨过周期边界时数值会跳变，虽然真实姿态只变化一点；万向锁附近还会出现坐标奇异。
  • 四元数：\(q\) 与 \(-q\) 表示同一个旋转。若直接使用分量 MSE 且训练标签的符号不一致，同一姿态会有两个相反标签，中间值又不是合法单位四元数。统一符号或使用双覆盖不变损失可以缓解这一训练问题，但不能改变其全局拓扑限制。
  • 更一般的结论：Zhou 等人使用适用于神经网络的连续表示定义，证明 \(\mathrm{SO}(3)\) 在四维及以下欧氏空间中不存在这类连续表示，并给出 5D 与 6D 构造。6D 不是理论最低维，而是实现简单、使用广泛的选择。

6D 编码器从旋转矩阵取前两列，把 \(\mathrm{SO}(3)\) 连续地嵌入 \(\mathbb{R}^6\)。解码器再用 Gram-Schmidt 补出第三列；它只在第一向量非零且两向量不共线的区域有定义并连续。不能把解码器描述成定义在整个 \(\mathbb{R}^6\) 上的连续映射。

3.2 源码里的正变换与反变换

# datasets/utils.py
def quat_to_rotate6d(q, scalar_first=False):
    return R.from_quat(q, scalar_first=scalar_first).as_matrix()[..., :, :2].reshape(q.shape[:-1] + (6,))

def rotate6d_to_quat(v6, scalar_first=False):
    a1 = v6[..., 0:5:2] # 下标 0 2 4
    a2 = v6[..., 1:6:2] # 下标 1 3 5
    b1 = a1 / np.linalg.norm(a1, axis=-1, keepdims=True)
    proj = np.sum(b1 * a2, axis=-1, keepdims=True) * b1
    b2 = a2 - proj
    b2 = b2 / np.linalg.norm(b2, axis=-1, keepdims=True)
    b3 = np.cross(b1, b2)
    rot_mats = np.stack((b1, b2, b3), axis=-1)
    return R.from_matrix(rot_mats).as_quat(scalar_first=scalar_first)

反变换就是标准的 Gram-Schmidt：把第一列归一化得 \(b_1\)，把第二列减去它在 \(b_1\) 上的投影再归一化得 \(b_2\)，叉乘补出 \(b_3\)。

3.3 一个会静默出错的细节：内存布局是交错的

as_matrix() 返回 \(3 \times 3\) 矩阵，[..., :, :2] 取前两列，得到 \(3 \times 2\) 的块。reshape 按行优先展平，于是这 6 个数的顺序是

\[\bigl[\, m_{00},\; m_{01},\; m_{10},\; m_{11},\; m_{20},\; m_{21} \,\bigr]\]

即第一列与第二列的分量交错排列，而不是常见的「第一列三个数接第二列三个数」。反变换用 v6[..., 0:5:2] 与 v6[..., 1:6:2] 两个跨步切片取回两列，与正变换自洽。

“Rotate6D”不是唯一的序列化协议。例如 PyTorch3D 固定版本实现把六维向量按前三维与后三维拆成两个 Gram–Schmidt 向量，并在反向转换时展平旋转矩阵的前两行；X-VLA 则取前两列后按行优先展平，因此六个分量交错。两者同时存在布局与行列约定差异，不能直接互换。错误解析通常仍会输出一个合法旋转矩阵，因而很难从表面现象定位。应始终配套使用 X-VLA 的编码与解码函数。

3.4 网络输出不保证是合法旋转

模型回归的是 6 个自由的实数，没有任何约束保证这两列正交或单位长。合法性是在解码时由 Gram-Schmidt 强制的：归一化、去投影、再归一化。

两个推论：

  • 训练时的 MSE 是在这 6 个自由数上算的，不是在 \(\mathrm{SO}(3)\) 上算的。 因此损失值与真实的姿态角误差之间不是线性关系，两者不可直接换算。
  • 模型可以输出零向量或接近共线的两列。 源码归一化时没有显式 epsilon：接近退化会放大数值误差，严格退化还可能除以零并产生 NaN。训练数据来自合法旋转并不保证分布外预测永不退化，因此部署前应监控两列范数与夹角，必要时增加数值保护。

四、论文层：条件流匹配的定义

论文第 2 节按标准条件流匹配写（层一）。记 \(A^0 \sim \mathcal{N}(0, I)\) 为纯噪声、\(A\) 为真实动作块、\(o\) 为观测条件，虚拟时刻 \(t \in [0,1]\) 从噪声端走向数据端：

\[A^t = (1-t)\, A^0 + t\, A\]

对一对固定端点 \((A^0,A)\) 求导，得到样本条件速度目标：

\[u_t(A^t\mid A^0,A) = \frac{\mathrm{d} A^t}{\mathrm{d} t} = A - A^0\]

右侧不显含 \(t\)，但这不表示网络最终学到的边际速度场与时间无关。网络只看到 \((A^t,o,t)\)；在平方损失下，点态最优解是

\[v^*(x,o,t)=\mathbb{E}\!\left[A-A^0\mid A^t=x,\,o,\,t\right],\]

它一般仍随 \(x\)、\(o\) 和 \(t\) 变化。训练目标是让网络逼近这个条件目标：

\[\mathcal{L}^{\mathrm{FM}}_{\mathrm{BC}}(\theta) = \mathbb{E}_{t \sim \mathcal{U}(0,1),\ (o, A) \sim \mathcal{D},\ A^0 \sim \mathcal{N}(0, I)} \left\lVert\, v_\theta(A^t,\, o,\, t) - \left(A - A^0\right) \,\right\rVert^2\]

推理侧论文称其使用 ODE 求解器，并提到 Euler-Maruyama；但论文展示的更新式是

\[A^{t + \Delta t} = A^t + v_\theta(A^t,\, o,\, t)\,\Delta t,\]

其中没有随机扩散项，数学形式实际是显式 Euler 的 ODE 更新。Euler-Maruyama 通常用于 SDE，还应包含与 \(\sqrt{\Delta t}\) 成比例的随机增量。这里保留论文原意，但不沿用其术语混淆。

「为什么回归一个条件量得到的最优解恰好是边际速度场」这条推导是条件流匹配的核心，已在 π0 · Flow Matching 动作生成完整给出，本页不重复。本节只是把 X-VLA 论文写的那一版列出来，作为下一节对照的基准。论文正文没有给推理步数的数值。

五、源码层：连续通道实际做的是 x0-prediction

先区分两个“0”：论文符号 A^0 表示噪声端；本页所说的 x0-prediction 沿用扩散模型术语，指源码时间 t=0 的干净动作端。二者不是同一个端点。

5.2 三处与论文不同

项 论文（层一） 源码（层二）
网络输出 速度场 \(v_\theta\) 位置/旋转输出干净动作值；夹爪输出 logit，监督目标仍取自 action
时间方向 \(t = 0\) 噪声，\(t = 1\) 数据 \(t = 1\) 噪声，\(t = 0\) 数据
时刻采样 \(\mathcal{U}(0,1)\) 近似随机平移网格：整批共享随机相位，理想间隔为 \(1/B\)

时间方向的换算。 记论文的时刻为 \(t_{\text{p}}\)、源码的为 \(t_{\text{c}}\)。论文写 \(A^{t_\text{p}} = (1 - t_\text{p}) A^0 + t_\text{p} A\)，源码写 \(x_{t_\text{c}} = t_\text{c}\, \epsilon + (1 - t_\text{c})\, A\)。两式在

\[t_{\text{c}} = 1 - t_{\text{p}}\]

下重合。因此源码的时间方向反而与 π0 一致（都是 1 为噪声端），枢纽页第 11.2 节的三列对照表给出了完整比较。

批内时间采样的含义。 把取模常数理想化为 1 时，它是同一个随机相位加上 \(i/B\) 后绕单位圆取模，因而每个样本的边缘分布均匀，批内各点等距但彼此相关。当前代码实际对 \(1-10^{-5}\) 取模，而相位来自 [0,1)：圆周长度与步长不再严格匹配，网格只近似等距，边缘分布也在长度约 \(10^{-5}\) 的小区间内出现轻微畸变。这样的分层覆盖可能改善批内时间覆盖，并降低对时间期望作 Monte Carlo 估计的方差；但这是机制推测，源码和论文没有证明它对任意数据顺序或损失都优于独立采样。

为了下面的推导统一，本页此后一律采用源码的时间约定：\(t = 1\) 是噪声端，\(t = 0\) 是数据端，

\[x_t = t\,\epsilon + (1-t)\,A, \qquad \epsilon \sim \mathcal{N}(0, I)\]

六、两种参数化的关系：哪里等价，哪里不等价

这是本页的核心一节。结论先给：在连续通道与 \(t>0\) 上，两种输出坐标可以点态互换；实际训练目标、网络参数化和采样器并不因此等价。 X-VLA 的夹爪通道使用 BCE 且在含噪输入中被清零，不属于下面的线性 MSE 换算。

6.1 代数上可以互推

设网络输出干净动作的估计 \(\hat A = f_\theta(x_t, t)\)。在源码的约定下，路径的真实速度是

\[v = \frac{\mathrm{d} x_t}{\mathrm{d} t} = \epsilon - A\]

给定 \((x_t, t)\) 与 \(\hat A\)，可以解出对应的噪声估计（\(t > 0\)）：

\[x_t = t\,\hat\epsilon + (1-t)\,\hat A \;\Longrightarrow\; \hat\epsilon = \frac{x_t - (1-t)\,\hat A}{t}\]

于是隐含的速度估计是

\[\hat v = \hat\epsilon - \hat A = \frac{x_t - (1-t)\hat A}{t} - \hat A = \frac{x_t - (1-t)\hat A - t\hat A}{t} = \frac{x_t - \hat A}{t}\]

反过来

\[\hat A = x_t - t\,\hat v\]

对固定的 \((x_t,t)\)，两种输出可通过外部仿射变换互换；但必须同时看到两个限定：\(t=0\) 时反推速度是奇异的，而且从干净动作输出得到速度需要显式使用输入 \(x_t\) 的跳连。因而这里证明的是输出坐标的点态对应，不是两个未经改造的网络类、优化过程或采样过程完全相同。

6.2 不等价之一：损失在 \(t\) 上的隐含加权不同

把真实速度同样写成 \(v = (x_t - A)/t\)。如果先由同一个干净动作预测 \(\hat A\) 构造 \(\hat v=(x_t-\hat A)/t\)，则

\[\hat v-v =\frac{x_t-\hat A}{t}-\frac{x_t-A}{t} =\frac{A-\hat A}{t},\]

所以连续通道上的点态误差满足

\[\bigl\lVert\hat v-v\bigr\rVert^2 =\frac{1}{t^2}\,\bigl\lVert\hat A-A\bigr\rVert^2.\]

反向写同一个关系可得

\[\bigl\lVert\hat A-A\bigr\rVert^2 =t^2\,\bigl\lVert\hat v-v\bigr\rVert^2.\]

因此，换算方向不能省略：

  • 从同一个干净动作误差构造速度误差时，要除以 \(t^2\)；
  • 从同一个速度误差写回干净动作误差时，要乘以 \(t^2\)。

若把源码的干净动作 MSE 写成其隐含速度误差的函数，则

\[\mathcal L_{x_0} =\mathbb E\!\left[t^2\lVert\hat v-v\rVert^2\right], \qquad \mathcal L_v =\mathbb E\!\left[\lVert\hat v-v\rVert^2\right].\]

相反，若固定同一个 \(\hat A\) 输出、把它换算到速度坐标后再用速度 MSE 评价，才得到

\[\mathcal L_{v\leftarrow x_0} =\mathbb E\!\left[\frac{1}{t^2}\lVert\hat A-A\rVert^2\right].\]

这说明两种目标对共享参数的有限容量网络施加了不同的时间权重；它不表示直接预测速度时目标或梯度必然发散。直接速度回归的监督目标是 \(\epsilon-A\)，其数值不会仅因 \(t\to0\) 自动发散。奇异的是从 \(\hat A\) 反推 \(\hat v\) 的坐标变换。若模型能在每个 \(t\) 上独立达到条件期望，正的时间权重不会改变各时刻的点态 MSE 最优解；实际网络跨时间共享参数，所以优化轨迹和有限容量解仍可能不同。

上面的 \(1/t^2\) 关系只适用于使用 MSE 的连续位置与 Rotate6D 通道。ee6d 的夹爪输入会被清零，监督使用 BCE，不能套用这条换算。源码确实允许采到非常接近 0 的 t，但仅凭这一点不能推出直接速度训练必须截断或重加权。

必须说明证据边界：论文与仓库都没有做过「x0-prediction 对照速度场」的实验。本页只说明点态坐标换算与目标加权的差异，不判断哪一种更好，也不猜测作者为何选择当前实现。

6.3 不等价之二：采样器不是同一个算法

# models/modeling_xvla.py，generate_actions 节选（推理）
x1 = torch.randn(B, self.num_actions, D, ...)   # 只采样一次，循环中永不更新
action = torch.zeros_like(x1)                   # 干净动作估计初始化为全零

for i in range(steps, 0, -1): # steps 默认 10
    t = torch.full((B,), i / steps, ...) # 1.0 递减到 1/steps
    x_t = x1 * t.view(-1, 1, 1) + action * (1 - t).view(-1, 1, 1)
    proprio_m, x_t_m = self.action_space.preprocess(proprio, x_t)
    action = self.transformer(..., action_with_noise=x_t_m, t=t, ...)
return self.action_space.postprocess(action)

循环里没有任何累加，不存在 x = x + v * dt。对位置与旋转通道，实际发生的是：用固定不变的初始噪声与当前的干净动作估计按当前 \(t\) 重新线性混合，再预测一次。对 ee6d 的夹爪通道，混合结果随后会被 preprocess 清零，因此既不保留固定夹爪噪声，也不把上一步夹爪 logit 反馈到下一步。

把第 \(k\) 步写成递推式更清楚。令 \(P_a\) 表示动作空间对含噪动作的预处理、\(P_p\) 表示对 proprioception 的预处理，则真实调用是

\[\hat A_k =f_\theta\!\left(P_a\!\left[t_kx_1+(1-t_k)\hat A_{k-1}\right],\,P_p(p),\,o,\,t_k\right).\]

对 ee6d 的 18 个位置/旋转通道，\(P_a\) 是恒等映射；对两个夹爪通道，\(P_a\) 恒为零。

可以怎样理解。 对连续通道，随着 \(t_k\) 下降，固定噪声 \(x_1\) 的系数减小，上一步动作估计的系数增大，因此它像一种使用自身预测构造下一次输入的迭代去噪。第一步 \(t_1=1\) 时输入是纯噪声，零初始化的 action 不起作用。夹爪则不是迭代去噪：每一步都从相同的零夹爪输入重新产生 logit；它仍可能因时刻、视觉语言条件、其他动作通道和注意力交互而随步改变。

不能由代码推出什么。 每一步的 \(t_k\) 不同，迭代映射也随步数变化，所以这不是对同一个函数反复求固定点。并且 \(\hat A_{k-1}\) 是模型预测而不是真实动作；混合后的输入只在代数形式上像训练加噪样本，不保证仍服从训练联合分布。因而源码本身没有提供收敛证明，也不能保证 \(t\) 越小输入就必然更准确或信息更多。

它与欧拉积分的差别。 欧拉法累加速度增量来推进当前状态；这里每一步重新预测完整的干净动作，前一步只通过下一次混合输入间接影响结果。即使两种方法使用相关的输出坐标，它们的离散算法与误差传播方式仍然不同。

两个由代码直接导出的事实：其一，给定观测、模型参数和 x1 后，循环不再显式采样随机数，而且 self.eval() 会关闭 dropout；算法层面因此是确定的，位级复现仍取决于 PyTorch/CUDA 的确定性设置。对 ee6d 的夹爪输出，x1 的夹爪分量还会被清零而不起作用。其二，t 从 1.0 递减到 1/steps，不会取到 0。最后一次调用直接给出连续动作估计与夹爪 logits，所以“不调用 \(t=0\)”本身不是错误；但步数会改变最小时刻、离散网格和自生成输入分布，性能需要通过闭环消融确认。

还存在一个训练—推理端点差异：训练公式经取模后满足 0 ≤ t < 1-1e-5，不会精确取到 1；推理第一步却固定使用 t=1.0，此时连续通道输入是纯噪声。训练样本可以任意接近这个端点，因此这不是超出区间的外推；更准确地说，它是训练不会精确取到的端点求值。源码与论文没有对此做消融，因此应把它记录为复现边界，而不能直接断言它有害或无害。

七、损失的完整定义

7.1 三项分权

连续位置与旋转通道监督干净动作而非速度；夹爪通道输出 logit，并以目标夹爪状态计算 BCE。因此总损失不是统一的速度场均方误差，而是三个按物理量定义的分项之和（层二，EE6DActionSpace.compute_loss）：

\[\mathcal{L} =\mathcal L_{\mathrm{pos}} +\mathcal L_{\mathrm{rot}} +\mathcal L_{\mathrm{grip}}.\]

其中每个 nn.MSELoss() 默认对所选张量的 batch、时间与通道全部取平均；每个 BCEWithLogitsLoss() 对 batch 与时间取平均。令 \(\operatorname{MSE}_{P_1}\) 表示第一机械臂三个位置通道上的全局均值，其余记号同理，则源码的精确 reduction 是

\[\mathcal L_{\mathrm{pos}} =500\left(\operatorname{MSE}_{P_1}+\operatorname{MSE}_{P_2}\right), \qquad \mathcal L_{\mathrm{rot}} =10\left(\operatorname{MSE}_{R_1}+\operatorname{MSE}_{R_2}\right),\] \[\mathcal L_{\mathrm{grip}} =\frac{1}{2}\left(\operatorname{BCE}_{g_1}+\operatorname{BCE}_{g_2}\right).\]

三项在 train.py 里直接执行 sum(loss_dict.values())，没有按有效机械臂数再次归一化。因位置每臂平均 3 个通道、旋转每臂平均 6 个通道，500 与 10 也不能直接解释成单通道梯度的 50 倍关系。

  A --> S2["旋转通道<br/>3 到 8 与 13 到 18"]
  A --> S3["夹爪通道<br/>9 与 19"]

7.2 500 / 10 / 1 是实现中的固定损失权重

源码可以确认三个系数的取值和归约方式，但论文与仓库没有公开它们的选择依据。因此不能把 500 / 10 / 1 称为已经验证的经验最优值，不能唯一归因于“量纲配平”，也不能直接读成“位置在语义上比旋转重要 50 倍”。

决定三项相对贡献的是预测残差而不是动作坐标本身：

  • 位置 MSE 受长度单位、数据工作空间和预测误差影响；
  • Rotate6D 分量虽是 \(O(1)\) 的无量纲坐标，但训练后残差通常远小于坐标幅值，且六维欧氏误差不等于旋转角误差；
  • 夹爪使用 BCEWithLogits，与两个 MSE 的数值尺度和梯度形式都不同；
  • 位置与旋转是两个机械臂槽的损失相加，夹爪是两通道平均，归约方式也不相同。

所以最稳妥的说法是：它们是当前实现在特定单位、表示和 reduction 下使用的固定损失权重。从结构上看，它们可能同时承担尺度补偿与任务折中，但这不是代码本身能够证明的设计动机。是否真正平衡，应查看训练日志中的各项损失及梯度范数，而不能用原始动作幅值代替误差统计。

单位变化仍然有明确影响：若位置数值整体乘以 c，位置 MSE 会乘以 c²；若希望保持相同物理误差对应的目标值，位置权重应相应除以 c²。迁移时应重新统计各项误差，而不是机械复制 500 / 10 / 1。

7.3 夹爪：BCE、输入端清零、推理端 sigmoid

夹爪通道有三处特殊处理，缺一不可（层二）：

def preprocess(self, proprio, action, mode="train"):
    """Zero-out gripper channels in proprio/action."""
    proprio_m = proprio.clone(); action_m = action.clone()
    proprio_m[..., self.gripper_idx] = 0.0
    action_m[..., self.gripper_idx]  = 0.0
    return proprio_m, action_m

def postprocess(self, action):
    """Apply sigmoid to gripper logits."""
    if action.size(-1) > max(self.gripper_idx):
        action[..., self.gripper_idx] = torch.sigmoid(action[..., self.gripper_idx])
    return action
  • 输入端清零。preprocess 把含噪动作以及本体状态的夹爪通道都置零。模型不能从这两个显式通道读取当前开合状态或带噪目标，只能利用视觉、语言、其余状态/动作通道、域提示与时刻等条件间接推断。推理循环中，上一步夹爪 logit 也不会经夹爪输入通道反馈。
  • 训练用 logits。损失是 BCEWithLogitsLoss，网络输出的是未经 sigmoid 的 logit，可以是任意实数。
  • 推理端才过 sigmoid。postprocess 把 logit 映回 [0, 1]，但模型层不负责把它变成硬开合指令。官方评测示例中有客户端以 0.5 二值化，也有客户端使用 0.7；具体集成还可能映射为连续夹爪位置。因此阈值、方向与硬件值域必须由执行端明确，不能假设存在统一协议——详见子页 ⑥。
论文说“二值夹爪”，源码却没有在最终边界强制二值。compute_loss 不检查或裁剪标签；通用 BaseHDF5Handler 又用线性插值同时重采样位置、旋转与夹爪，所以查询时刻跨过开合跳变时可能生成 (0,1) 内的软标签。部分处理器（如 DROID、RT1、VLABench）还会直接传递原始夹爪值，而不是统一阈值化。BCEWithLogitsLoss 可以用 [0,1] 内的软目标，但这已经不同于论文所说的离散二值监督；若原始值越界，源码也没有保护。接入新数据时必须显式决定“先二值化再插值”“插值后再二值化”还是保留软标签，并验证范围。

7.4 没有 padding mask

单臂平台上后十维补零，compute_loss 没有 padding mask，但“补零会统一稀释全部损失”并不准确：

  • 位置与旋转分别对两个机械臂槽求 MSE 后相加。有效的第一槽项不会被除以 2；补零的第二槽目标形成一个额外的“输出零”约束。
  • 夹爪先分别计算两个 BCE，再取平均。因此单臂真实夹爪项的有效系数会减半，同时还有一个虚拟右夹爪的零目标 BCE。

所以补零的影响取决于具体 reduction，不能用一句“稀释损失”概括。单双臂、不同 action_mode 的总损失含义不同，跨配置比较时应先把各分项、有效通道与归约方式对齐。

还要区分“训练占位”与“可执行姿态”：当前单臂处理约定中，第二机械臂槽的 Rotate6D 六维目标为全零，而全零并不是可经 Gram–Schmidt 解码的合法旋转表示。它只能作为被损失约束的占位值，执行端必须按有效槽位丢弃；若把整段 20 维都无条件解码，虚拟第二槽可能在归一化时产生 NaN。

八、四种动作空间的差异

官方仓库 models/action_hub.py 注册了 4 个动作空间。它们在损失形式上的差别比想象中大（层二）：

空间 维度 夹爪损失 夹爪权重 其余权重 preprocess postprocess
ee6d 20 BCEWithLogits 1.0 位置 500 / 旋转 10 清零夹爪通道 夹爪过 sigmoid
joint 14 BCEWithLogits 0.1 关节 1.0 清零夹爪通道 夹爪过 sigmoid
agibot_ee6d 20 MSE 10.0 位置 500 / 旋转 10 不做任何处理 不做任何处理
auto 真实维补零到 20 无夹爪项 — 全维 MSE 乘 100.0 仅动作补零；proprio 原样返回 裁回真实维，无 sigmoid

三点值得强调：

  • agibot_ee6d 按连续量处理夹爪通道。 代码能确认它使用 MSE、保留夹爪输入且不做 sigmoid；具体物理范围仍应以 AGIBOT 数据处理器和执行端协议为准，不能仅凭损失函数断言其硬件语义。页面核验的 X-VLA-Pt checkpoint 使用 ee6d，不是这个变体。
  • auto 放弃了 ee6d 的分项目标。 它只在真实维度上计算全维 MSE 并乘 100.0，没有独立夹爪 BCE、不清零夹爪输入、不过 sigmoid；仅动作会被补到 20 维，proprioception 原样返回。它实际还要求 real_dim <= max_dim，源码没有为负 padding 长度提供友好检查。该模式便于接入较低维动作，但目标与状态适配都已改变，效果不能由 ee6d 直接推断。
  • LeRobot 移植版另注册了两个（franka_joint7 与 so101_bimanual），官方 X-VLA 仓库里没有；该固定版本的 auto 权重和构造参数也与本页核验的官方版本不同，不能只按名字认定行为一致。集成侧差异见子页 ⑥。

九、复现与迁移时最容易错的几点

  • 先明确复现目标。若要加载官方权重并复现公开推理行为，应遵循连续通道的 x0-prediction、夹爪 BCE logits 与固定噪声重混合；若要实现论文文字描述的速度场加 ODE 积分，则需要按该目标重新训练，并明确它不是官方权重对应的采样器。
  • Rotate6D 的六个通道是交错存放的。不能照搬按前三维/后三维拆成两个向量的其他实现；应使用 v6[0:5:2] 与 v6[1:6:2] 取回 X-VLA 的两列。
  • 后十维不应一概称为 padding。在使用第二机械臂槽的双臂域中，它承载真实控制量；只有相应单臂处理约定才把它补零。应以域处理器的槽位映射为准。
  • 换动作单位或表示就要重新标定损失。500 / 10 / 1 是当前代码的固定权重，选择依据未公开；应依据各分项误差、梯度与 reduction 重新检查，不能把它当成普适比例。
  • 模型看不到显式的当前夹爪状态。preprocess 把本体状态与含噪动作的夹爪通道都清零；推理时上一步夹爪 logit 也不会从该通道反馈，只能由其他条件间接推断。
  • 不要默认 BCE 标签必为 0/1。官方通用处理器可能线性插值夹爪，部分域还直接传原始值；应检查范围并明确软标签或二值化策略。
  • 损失数值不可直接跨配置比较。位置、旋转与夹爪对两个机械臂槽采用不同归约；单双臂及不同 action_mode 的总损失含义不同。
  • 用 auto 时要知道自己放弃了什么。没有夹爪 BCE、没有分项加权、没有 sigmoid；它也不补 proprioception，并隐含要求 real_dim <= max_dim。
  • 代码允许直接修改推理步数。无需重载或重训权重即可改变 steps，但这会改变最小 t、离散时间网格和自生成输入分布；性能与稳定性不保证随步数单调提升，仍须闭环消融。
  • 30 个锚点只说明数量。物理时间范围由域处理器的 qdur 决定；只有对齐锚点数、时间跨度与执行频率，动作块才具有相同语义。
