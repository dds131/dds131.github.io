VLA/RLHF-VLA/整体网络与模块数据流

Architecture · branch point · lifecycle · capability

逻辑角色不等于一张物理网络；三条分支不共享必需模块

先验证数据与策略能力，再选择计算图。logical role ≠ artifact ≠ runtime instance；old/behavior ≠ reference；RM ≠ Critic；sampling capability ≠ log-prob capability；three branches are optional and independent。

3 explicit peer branches15 architecture contractsunknown capability → no route
核对角色绑定检查概率能力选择同级分支上一页：反馈数据

逻辑角色、物理 artifact 与运行实例

架构身份分五层：logical role 是数学/流程职责；artifact 是 checkpoint、adapter、config、stats 与 code revision；parameter set 是真实可变参数及共享关系；runtime instance 是某 device/precision/process 中的加载实例；service endpoint 是训练、评分、推理或监控接口。同一 artifact 可加载多个 runtime，一个 runtime 可提供多个 heads；只要 purpose、update/freeze 或输入语义不同，就要有独立 binding。

Current actor当前被优化或候选部署策略；不是本批数据的必然 behavior。
Behavior / OldBehavior 生成 rollout/replay；Old 是 PPO fixed denominator，可由 snapshot 或 old-log-prob receipt 承担。
Reference policy偏好/KL 的阶段或长期锚点；refresh policy 独立于 Old。
Reward model / converterRM 从 feedback 学 proxy score；converter 把 score/rule/outcome 变为具体 reward/cost revision。
Critic V/Q在指定 policy、reward、termination/bootstrapping 下估计 future return。
Producer / evaluator / safety / approverlabel、task evaluation、runtime monitor 与 release authority 分开登记。

Old/behavior 与 rollout revision 绑定，通常按 update iteration 刷新；Reference 与 regularization baseline 绑定，可以长期冻结或按显式 cycle 更新。即使某一时刻指向同一 hash，也必须保留不同 role ID、purpose、refresh event 与 expiry。RM 的监督来自 pair/rank/scalar/attribute，Critic 的 target 来自 reward revision 下的 return/TD；共享 backbone 或 scalar head 外形不构成语义等价。

token、density、diffusion、flow 与 log-ratio 能力

能力状态固定为 exact-tractable | tractable-by-decomposition | estimated-with-receipt | surrogate-objective-only | unavailable | unknown，且必须绑定具体 (artifact, action view, context, transform, mask, measure, reduction, gradient mode)，不能只凭模型家族命名。

interface 可声明能力 不可默认
autoregressive token 固定 tokenizer/vocabulary/order/BOS-EOS/mask/decode 后的 token conditional log-prob token score 就是 executed continuous action probability
explicit density Gaussian/mixture 在 base measure、squash/Jacobian、bounds/covariance 下的 density 不同 normalization/support 可直接相减
diffusion denoising process、path ratio/ELBO/score surrogate 或 reward-weighted denoising 的 method-specific receipt denoising MSE 是 final action log-prob
flow/CNF vector-field objective；满足 CNF/ODE/divergence/solver 条件时的 density estimate Flow Matching regression 自带廉价 token-like likelihood
deterministic/residual regression、critic 或 residual objective 凭采样能力生成 exact log-prob

current/reference/behavior 的 ratio compatibility 必须一致：observation/history/prompt context、action view/transform、support/base measure、tokenizer/noise/path parameterization、valid/padding/executed masks、step/chunk/trajectory reduction、artifact timing/fixed snapshot 与 gradient path。任一 unknown 就是 review-required。

log π_current(a|c)-log π_ref(a|c) 的单 sample 可正可负；KL 是指定 distribution/measure 下的非负期望。UI 必须区分 sample log-ratio、KL estimate 与 exact KL。FDPP v1 是 learned reward + diffusion-policy RL 的具体实例；Flow Matching v2 是 conditional path 上的 vector-field regression；π₀ flow head不自动提供可替代 token log-prob 的低成本接口。

显式 Reward Model + PPO 分支

该分支需要 current actor、behavior/Old、RM、reward converter、critic、rollout environment/worker、safety controller 与 independent task evaluator；Reference 只在 objective 要求时加入，cost model/constraint critic/monitor 为可选。

flowchart LR
  P["eligible preference view"] --> RM["RM update + calibration"]
  B["frozen behavior / Old"] --> ENV["environment + safety rollout"]
  RM --> RC["versioned reward converter"]
  ENV --> FIX["fixed batch receipt"]
  RC --> FIX --> PPO["Current + Critic update"]
  REF["Reference if configured"] --> PPO
  PPO --> EVAL["independent task + safety evaluation"]

RM stage 中 actor 不接收 RM gradient。rollout stage 用 frozen behavior/current snapshot 记录 generated/commanded/executed、old-log-prob receipt、RM/reference inputs 与 abort。PPO update 在固定 batch 上由 Current 重算 compatible log-prob；reward converter 生成 reward revision，Critic 生成 value；Current/Critic 分 owner 更新，Old/Reference/RM 冻结。

reward chain 是 feedback view → RM score → calibrated score → reward conversion → per-step/terminal shaped reward/cost → return/advantage/TD target。每条 arrow 有 revision，并登记 direction/scale、aggregation、normalization/clipping、terminal allocation、KL/cost composition、discount、termination/truncation/bootstrap。Critic 绑定完整 reward-definition hash；上游变化会使旧 value semantics stale。

PPO batch receipt 固定 behavior artifact、trajectory/action IDs、old denominator/log-probs、contexts/masks、reward revision、advantages/targets、collection time、policy lag、safety overrides 与 validity；multi-epoch update 中不替换 actions、Old 或 targets。Old 是 importance-ratio denominator，Reference 是 regularization anchor；即使同 hash 也不合并角色。RM score 或 PPO clipping 不授予 rollout 权限，robot risk budget、supervision、reset/abort、incident、offline evaluation 与 rollback 仍需独立通过。

DPO、KTO、APO 直接偏好分支

共同图仅为 eligible preference/desirability view → current/reference compatible scores/log-ratios → method-specific objective → update Current。显式 RM、Critic 与 Old rollout 不是共同必需。

DPOmatched chosen/rejected pair；condition、support、mask 与 reference assumptions 齐全。
KTO-likesingle desirable/undesirable；normalizer/reference/class balance assumptions；不伪造 pair。
APO profileintervention-derived c/view、autoregressive token log-ratio、decoded continuous-action error 与 causal-window revision。

三者使用不同 input_port_id/objective_capability_id，不能由 preference_dataset 文件名自动选择。policy/reference log-ratio 在各自推导中可承担 relative reward parameterization，但不等于得到可独立部署、校准或跨策略外推的 RM，也不等于 environment absolute reward。

Reference manifest 保存 base origin、refresh policy、frozen scope、base/adapter composition、tokenizer/action transform 与 precision。Current 若更新 shared base 而 Reference 只保留旧 adapter，必须证明完整 Reference function 仍可重建。只有 diffusion/flow surrogate 且无该方法要求的 compatible log-ratio 时，状态为 incompatible/review-required；不能把 token objective 贴到 continuous head。

轨迹偏好与连续生成分支

该分支从 Architecture 直接进入，不以 RM、PPO 或 direct preference 为顺序前置。它可以选择三类子图：chosen/rejected trajectories + current/reference compatible trajectory likelihood；trajectory feedback → learned reward → continuous-policy RL（FDPP 属于具体实例）；或 preference/reward-weighted vector field、score/path/residual 等 likelihood-free method-specific objective。三类是 alternatives，不是升级链。

GRAPE v2 的 TPO profile 绑定 same initial state、task/context、length/termination/mask、support、Reference 与 trajectory reduction，并在其 MDP/step-policy setting 下将 trajectory ratio 分解为 step log-ratios。GCPG 的 VLM/stage/keypoint/cost/self-reward/success pipeline 是 replaceable preference producer，不是任何 TPO 的必需网络，也不参与 TPO loss 的反向传播。

continuous capability 还要记录 action chunk、prediction/execution horizon、denoising/flow time 与 environment time、path sampler、executed mask、credit assignment、compute/latency。环境 $t$、denoising $k/\tau$、flow path $s$ 不可混用。FDPP、GRAPE、Flow Matching 与 π₀ 分别证明不同 component/domain；把它们组合为目标 VLA pipeline 属于 transfer hypothesis，除非已有目标实现和证据。

共享、冻结、梯度与 optimizer 所有权

参数分区至少列 vision encoder、language/VLM backbone、proprio encoder、fusion、action head、value head/trunk、reward head/trunk、LoRA/adapters、normalization/tokenizer/non-trainable stats。每区固定 artifact/parameter IDs 与 owner、trainable/frozen/detached、loss IDs、optimizer、LR/decay、precision、accumulation/clip、update order、checkpoint/export behavior。

“共享”必须区分 same mutable parameter object、independent snapshots from same initialization、shared frozen feature cache、shared base + separate adapters/heads。它们的 gradient、staleness、memory/recompute 与 deployment merge 后果不同。freeze state 则区分 head-frozen | trunk-frozen | full-function-frozen-snapshot | cached-feature-frozen | eval-mode-only | no-gradient-but-buffer-updates | unknown；只冻 RM head 但 actor 仍更新 shared trunk，不是冻结完整 RM function。

每条 loss→parameter edge 标 update | stop-gradient | read-only | not-connected | unknown。同一 parameter 被多个 optimizers 更新时必须声明 order/sync/accumulation 和 conflict handling；unknown 阻断 branch readiness。BatchNorm/EMA/buffer、dropout mode、tokenizer/stats 也进入 binding。feature cache 绑定 producer hash、preprocessing、precision、layer、dataset/split 与 expiry；producer 改变后 cache stale。

动作链为 policy-generated → decoded → denormalized → frame-transformed → clamped → safety-filtered/blended → commanded → executed；每条 edge 有 transform revision 与 receipt。Preference/RL loss 必须声明其 action view，generated token 的 log-prob 不能解释为 executed action 的概率。

一手来源与接口边界

  • Deep RL from Human Preferences v4、InstructGPT v1 与 PPO v2：定义经典 learned-reward/RL 与 optimizer 来源；不构成任意 VLA 架构验证。
  • DPO v3、KTO / ICML 2024 与 APO v3：pair、single desirability 与 intervention-derived action preference 的不同接口；前两者来源域为 LLM，APO 绑定 autoregressive VLA。
  • GRAPE v2：trajectory-level preference alignment 与自动时空约束；其 producer/TPO assumptions 不泛化为所有 trajectory 方法。
  • FDPP v1：preference-learned reward + RL fine-tuning diffusion policy；归入 RM+RL 子图，不是 direct preference。
  • Flow Matching v2：OpenVLA v3 与 π₀ v4 分别提供 vector-field、autoregressive action-token 与 flow-matching VLA 来源；接口不能互换。

本页 prev 仅 反馈与数据构造；三个 next 是同级显式选择，不形成 RM→Direct→Trajectory 顺序。
