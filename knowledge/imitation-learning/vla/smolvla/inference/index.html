SmolVLA · 推理、动作块与异步执行

解释 SmolVLA 从完整 checkpoint bundle 到 policy I/O、10 次 Flow 求解与 50 步动作块，并区分同步队列、legacy async、RTC 和独立安全授权。

知识库 / VLA / SmolVLA / 推理、动作块与异步执行

Runtime contract · candidate action only

SmolVLA 一次默认用 10 次速度场求值生成 50 步动作块，但生成长度不等于实际开环长度：系统默认由同步队列消费动作，legacy async 与 RTC 是两条不同的显式调度路径；无论选择哪条路径，完整 processor/schema 绑定和独立安全监督器都必须先于执行授权。

10 evaluations 50 predicted actions sync / legacy / RTC policy output ≠ authorization
检查 policy I/O 比较运行模式 下一页：Ablations
10每个动作块的速度场求值次数，不是控制周期数。
50默认预测块长；同步执行量由 `n_action_steps` 决定。
g = 0.5legacy 剩余比例阈值；不是 RTC 整数阈值。
30 actionsrollout RTC 默认 queue threshold；RTC 仍需显式选择。
fail closed任一 artifact/schema/unit/time/safety 门失败即拒绝候选动作。

同步队列：默认路径

rollout 默认使用同步 backend。控制线程每个 tick 都做 observation 准备和完整 processor 链，再调用 select_action；但 policy 内部队列非空时只弹出一个动作，只有队列空时才做一次新 chunk 前向。因此“每 tick 调 API”不等于“每 tick 模型前向”。

control_thread_owns_policy: true

  - preprocessor
  - select-action
  - postprocessor
  - squeeze-batch
  - cpu-candidate
policy_queue:
  refill_when: empty
  refill_count: n_action_steps
  reference_n_action_steps: 50
task_change:
  behavior: drop-precomputed-actions-without-full-policy-reset
reset:
  behavior: reset-policy-preprocessor-postprocessor
runtime_default: true

同步并不天然更安全。是否适用取决于控制频率、任务动态、端到端延迟、允许的 observation age、queue exhaustion 处理与 supervisor margin。仿真主协议每执行一个动作就重采观测并预测；SO100/SO101 主真机协议同步执行完整块。二者只能在同任务、同域、同控制频率、同成功定义和同模式内比较，禁止直接做跨域成功率相减。

legacy async：队列、阈值与融合

legacy async 是 SmolVLA 论文系统对应的研究/历史路径：robot client 的控制线程持续执行动作，receiver thread 阻塞等待 action response；RPC 连接 policy server，server 只有容量 1 的等待 observation queue。队列满时丢掉最旧的等待 observation、保留最新一条，但不会抢占正在进行的推理。

schema: smolvla.inference-legacy-topology.v1
robot_client:
  control_loop: execute-action-and-maybe-send-observation
  receiver_thread: blocking-get-actions
  action_queue_owner: client
transport: insecure-grpc
serialization: pickle
policy_server:
  observation_queue_maxsize: 1
  when_full: drop-oldest-keep-latest-waiting
  inference_entry: predict_action_chunk-observation-only
  return_slice: first-actions-per-chunk
concurrency_goal: overlap-action-execution-and-policy-inference
hard_real_time_guarantee: false
production_security_ready: false

client 的补块条件为 remaining_queue / action_chunk_size <= chunk_size_threshold。默认比例阈值 g=0.5；分母是历次实际收到非空 chunk 长度的 running max，而非请求配置。若实际收到 50 步、控制频率 30 Hz，则余量 25 步时触发，覆盖约 25/30=0.8333333333 秒。这只是 queue coverage，不包括观测采集、序列化、网络、server 排队、预/后处理和推理的 tail，也不是 GPU deadline 保证。

新 response 到达后，固定实现从 incoming timed actions 重建 future queue：过期 incoming 被丢弃；与当前 queue 同 timestep 的 old/new 聚合；新 timestep 加入；旧 queue 中没有 incoming 对应项的尾部不会保留。因此它不是 old/new 时间戳集合的 union。

schema: smolvla.inference-legacy-fusion.v1
input:
  - current-client-queue
  - incoming-timed-actions
stale_rule: discard-incoming-timestep-less-than-or-equal-latest-executed
overlap_rule: aggregate-old-and-new-at-same-timestep
new_rule: append-incoming-future-timestep
old_only_tail_rule: omitted-from-rebuilt-queue
default_registered_weighted_average:
  old_weight: 0.3
  new_weight: 0.7
other_registered_choices:
  - latest
  - average
  - conservative
implementation_warning:
  queue_deque_reference_captured_under_lock_but_iterated_after_unlock: true

取得底层 deque 引用后在 lock 外迭代是并发风险，不等于已经证明发生确定性损坏。0.3/0.7、latest、average 或 conservative 只定义重叠动作的数值组合，均不验证单位、范围、碰撞、速率和时效，不能替代 supervisor。

延迟预算、观测去重与异常活性

设端到端延迟 L=L_c2s+L_server+L_s2c、控制周期 Δt、实际 chunk 长度 n。期望的线性分解不要求三项独立，但模式选择应优先使用实测端到端分布，而不是只拿 server 均值。

目标分位数消耗步数为 m_p=ceil(q_p(L)/Δt)。固定实现比较 <=，覆盖该 tail 的必要门槛是 g>=m_p/n；论文伪代码用严格 <，恰在离散边界时需 g>m_p/n。若 m_p>n，任何闭区间 [0,1] 内比例都无法靠一个 chunk 覆盖该 tail。

schema: smolvla.inference-latency-budget.v1
latency_components:
  - client-to-server
  - server-queue-and-inference-and-postprocess
  - server-to-client
mean:
  equation: "E[L]=E[L_c2s]+E[L_server]+E[L_s2c]"
  independence_required: false
tail:
  consumed_steps: "m_p=ceil(q_p(L)/delta_t)"
  fixed-implementation-condition: "g>=m_p/n"
  paper-strict-pseudocode-condition: "g>m_p/n at equality boundary"
uncoverable:
  condition: m_p>n
  implication: no-ratio-in-closed-unit-interval-covers-tail-with-one-chunk
required_measurement: end-to-end-monotonic-timestamps
guarantee: budget-not-hard-deadline

legacy server 默认只比较 state 的 L2 距离，容差 1，图像不参与相似性。普通 observation 受“timestep 未预测”和“state 不太相似”过滤；must_go 可绕过两者。该事件初始化为 set，只有 action queue 为空时附到待发 observation；发出后 clear，收到非空 actions 后再 set，而空 response 不会 re-arm。

server 又在推理前把 timestep 放进 predicted set，异常时不回滚。若 first inference 在记账后失败，client 已 clear must_go、空 response 不 re-arm、相同 timestep 又被过滤，存在无动作且不再强制重试的失活路径。这是代码路径风险，不是所有异常必然死锁。predicted set 仅在新 client Ready/reset 清理，长运行还需监控其增长。

RTC：显式选择、前缀与延迟合并

RTC 来自独立后续方法，不是 SmolVLA 论文原始贡献。三个“默认”必须分开：构造出的 RTCConfig 对象内部 enabled=true；SmolVLA policy 默认 rtc_config=null；rollout 工厂默认 backend 是 sync。因此 RTC 仍需显式选择。

固定提交中 SmolVLA 支持 guided RTC，不支持 trained RTC；trained RTC 的 policy type 门只允许 PI05，并要求正的 training max delay、execution_horizon>=training_max_delay、queue_threshold>=training_max_delay 以及 horizon 不越过 chunk 可用范围。

schema: smolvla.inference-rtc-defaults.v1
rtc_config_object:
  enabled: true
  mode: guided
  execution_horizon: 10
  max_guidance_weight: 10.0
  prefix_attention_schedule: linear
smolvla_policy_config:
  rtc_config: null
rollout:
  default_inference_backend: sync
  rtc_queue_threshold: 30
support:
  smolvla_guided_rtc: true
  smolvla_trained_rtc: false
  trained_rtc_allowed_policy_type_at_fixed_commit: pi05
provenance:
  rtc_method: arXiv:2506.07339
  smolvla_paper_original_contribution: false

execution_horizon=10 是上一块剩余前缀参与 guidance 的目标长度：太长截断，太短重复最后动作，完全为空则传 null/no-prefix；不能用零填充，因为逆归一化后的零可能代表数据均值。它不是“先固定执行 10 步才重规划”。

RTC background thread 在剩余队列 <=30 时尝试补块；用控制周期 1/fps 把 latency 换成 ceil(latency/period) 个动作步，并用 warmup 后的最大观测延迟做下一次条件。relative-action processor 存在时，前缀还需由缓存 raw state 与 processed leftover 重新锚定。

新 chunk 返回后，合并同时比较壁钟 delay 与推理期间实际消费的 action-index difference；不一致时取较小值，避免跳过尚未物理消费的动作，再把 delay clamp 到 original/processed chunk 长度并替换剩余 queue。

schema: smolvla.inference-rtc-merge.v1
refill_trigger:
  condition: remaining-actions-less-than-or-equal-queue-threshold
  default_queue_threshold: 30
delay:
  period: one-over-fps
  conversion: ceil-latency-over-period
  predictor: maximum-observed-after-warmup-policy
prefix:
  source: unconsumed-original-actions
  target_length: execution_horizon
  too_long: truncate
  too_short: repeat-last-action
  empty: null-no-prefix
relative_action: reanchor-when-processor-requires
merge:
  measured_delay_vs_consumed_index: take-minimum-when-different
  final_delay: clamp-to-both-chunk-lengths
  queue_operation: replace-with-new-chunk-after-delay
reason: never-skip-ahead-of-physical-consumption

legacy 按 timestep 用聚合函数重建 client queue；RTC 则在生成时用旧队列剩余动作做 prefix guidance，并按 delay 在 caller queue 上替换。两者虽然都处理重叠，但 owner、阈值、计算位置与语义不同，固定实现也不支持与 legacy 开箱叠加。

reset 会清空队列并增加 reset_epoch；in-flight 推理合并前在同一临界区核对 epoch，旧 chunk 因此被丢弃。普通 RTC 推理连续 10 次错误升级为 fatal failure；trained RTC 连续 5 个 chunk 因 delay 超出 overlap 被丢弃时升级；thread stop join timeout 为 3 秒。这些是固定源码默认，不是部署推荐值。
