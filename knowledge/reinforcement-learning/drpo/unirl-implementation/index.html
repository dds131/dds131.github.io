知识库/DRPO/UniRL 工程与诊断
Formula → data contract → distributed runtime

Loss 只有十几行，正确训练取决于整条数据链

本页把 $r_t$、$\mu_t$、$\hat A_t$ 与二次 penalty 映射到 UniRL 字段，并优先排查 rollout/replay 一致性、anchor、mask 和聚合。

old_logp冻结的行为策略 anchor
new_logp相同 token 的训练重放
loss_mask定义真正参与优化的位置
7 组诊断量区分现有指标与建议新增项

诊断优先级： 先证明“相同权重、相同输入、相同采样语义”下 ratio 约等于 1，再讨论学习率、$\delta$ 和更新次数。数据契约错误不能靠更保守的正则修复。

版本事实要以可执行源码为准。 截至本次审校，当前 drpo.py 设置 supports_multi_update=True，并在 prepare_segment 中冻结 anchor；Qwen3 DRPO recipe 使用 num_updates_per_batch: 4。官方 DRPO 教程仍有一段旧文字声称“不冻结且只支持单更新”，与当前代码冲突。复现实验必须记录仓库 commit，并按该 commit 的源码、recipe 与测试解释行为。

1. UniRL 的完整运行时地图

flowchart TB
  C[Hydra recipe] --> T[Domain Trainer]
  T --> O["Rollout engine<br/>SGLang / train-side"]
  O --> P["Sample / Part / TextSegment"]
  P --> W[RewardService]
  W --> A[Group advantage]
  A --> TS[TrainStack + FSDP]
  TS --> ALG[DRPO algorithm]
  ALG --> RP["ARStage.replay 重算 new_logp"]
  RP --> B[backward + optimizer]
  B --> SYNC[权重同步]
  SYNC --> O

Trainer 负责编排，Rollout 生成回答，RewardService 添加标量奖励，Part 形成组内优势，TrainStack 切 mini/micro-batch；DRPO 类只负责新旧 log-prob、逐 token Loss、聚合、反传与指标。任何层的 token、温度、权重或 mask 语义不一致，都会直接污染正则项。

2. 六行核心代码对应什么数学？

官方 unirl/algorithms/drpo.py 的核心可概括为：

log_diff = torch.clamp(new_logp - old_logp, min=-20.0, max=20.0)
ratio = torch.exp(log_diff)
adv = advantages.detach()
old_prob = torch.exp(old_logp).detach()
quadratic_penalty = (
    adv.abs() * old_prob * (ratio - 1.0).square()
    / (2.0 * epsilon)
)
loss_per_token = -adv * ratio + quadratic_penalty
字段 数学量 正确性契约 典型故障
old_logp $\log\mu_t$ 对应实际生成 token；固定，不回传梯度 rollout/replay 引擎不一致
new_logp $\log\pi_\theta(y_t\mid s_t)$ 相同 token、前缀、温度与 mask 下重放 token 或 batch 对齐错误
ratio $r_t$ 在有效回答 token 上统计 极端值被均值掩盖
old_prob $\mu_t$ detach()；决定绝对概率几何 被误删或用错策略
advantages $\hat A$ 组级信号扩展到 token；detach() 同组同奖励导致全零
loss_mask 有效 token 集 排除 prompt/padding/不训练位置 分母与 mask 不一致
epsilon 论文 $\delta$ 绝对概率位移尺度 被当成 PPO clip 值
penalty_mu_weighted 是否乘 $\mu_t$ true 为 DRPO；false 为 SPO 型固定 ratio 几何 被误当成普通强度开关

理论页已推导完整目标；这里最重要的是两个 detach() 与“新旧 log-prob 必须描述同一个条件分布事件”。此外，penalty_mu_weighted 会切换正则的几何类别：它不是调整惩罚大小的普通系数。

clamp(-20, 20) 不只是防溢出

令 $z=\operatorname{clamp}(\log\pi_t-\log\mu_t,-20,20)$、$r_t=e^z$。在区间内，它等于论文 ratio；一旦原始 log-diff 越界，PyTorch clamp 对输入的导数为 0，策略项与 penalty 通过 ratio 的梯度也随之饱和。因此代码在极端区间不再与未截断论文目标完全等价。除检查 NaN/Inf 外，还应记录 log_diff 命中上下界的比例。

3. Anchor：来自 rollout 还是 replay？

old_logp_source 的选择决定 DRPO 在约束什么：

rollout

  • 使用推理引擎真实输出的 log-prob，并在同一 rollout 的全部更新中固定。
  • ratio 同时包含“训练参数相对行为策略的漂移”和“推理引擎相对训练前向的数值差异”。
  • 因而即使权重相同，第一个优化步前 ratio 也可能偏离 1；这不是自动证明策略已经更新。

replay

  • 在更新前用训练侧 stage.replay 做一次无梯度前向，把结果写入固定的 segment.log_probs；原 rollout log-prob 另存用于差异诊断。
  • 第一更新的训练侧 ratio 在确定性与输入契约一致时应接近 1，后续更新只反映相对该冻结训练侧 anchor 的参数漂移。
  • 代价是额外一次前向；它隔离了引擎差异，并不证明线上推理引擎与训练侧一致。

prepare_segment 必须在 num_updates_per_batch 循环前只运行一次并冻结 anchor。若每步都重算分母，目标就从“相对固定行为策略受控更新”变成“追逐正在移动的参照”。当前 Qwen3 recipe 选择 rollout anchor，并对同一批 rollout 做 4 个互斥 mini-batch 更新：第 2—4 步会逐渐 off-policy，正是正则需要工作的阶段。

bf16 前向可能受 batch 形状、kernel、log-prob 保存精度与算子选择影响。对照实验要匹配训练的 mini/micro slice、chat template、temperature、top-k/top-p 与 thinking 开关，不能用大批 rollout 和小批 replay 的微小差异直接判定权重同步失败。

4. Token Loss 还要怎样聚合？

逐 token loss_per_elem 不是最终标量。聚合模式会改变长短回答的相对贡献：

  • token-mean：对所有有效 token 取平均；每个 token 同权，长回答包含更多项。
  • seq-mean-token-mean：先对每个回答的有效 token 求均值，再跨回答平均；每个非空回答同权。
  • seq-mean-token-sum-norm：每个回答先求 token 和、除以固定 horizon，再跨回答平均。当前 Qwen3 recipe 使用此模式，且 horizon=max_new_tokens=8192。
  • loss_mask 应同时作用于分子与分母；只乘 mask 却仍除以总长度，会系统性压低短回答或稀疏 mask 样本的权重。

seq-mean-token-sum-norm 并不等于“每条回答完全同权”：回答越长，仍可能累积更多 token 项，只是所有回答除以同一个固定尺度。比较实验时，loss_agg_mode、horizon、最大响应长度和有效 token 分布必须一并记录。

5. 最小训练仪表盘

指标 来源 回答的问题 不应怎样解释
ratio_mean 当前源码 新旧策略对有效采样 token 的平均相对变化 均值接近 1 不代表尾部稳定
ratio_max 当前源码 是否出现极端 ratio 大值不必然意味着绝对概率变化大
approx_kl 当前源码 $[(r-1)-\log r]$ 的有效 token 均值 不是完整词表精确 KL，也不是默认的正向 $D_{KL}(\pi|\mu)$
drpo_penalty_mean 当前源码 二次 penalty 在有效 token 上的均值 不能脱离优势尺度、$\mu_t$ 与聚合解释
clipfrac_upper/lower 当前源码 超出自适应边界的诊断比例 DRPO 没有执行 PPO 式 clip；默认阈值下它应退化为 0
rollout_replay_logp_absdiff_* 当前源码 推理 log-prob 与当前 replay 的差异 多更新时还混入参数漂移；小均值不能排除少数错位
ratio 分位数、clamp 饱和率、reward std / zero-std group 建议新增 尾部、数值饱和与优势可辨识性 这些不是 _drpo_loss 当前默认全部提供的字段

代码中的 approx_kl=(r-1)-\log r 是 K3 型非负量；若动作确由 $\mu$ 采样且不考虑 clamp，其期望对应 $D_{KL}(\mu|\pi)$。当前值只是有限 rollout 上的蒙特卡洛均值，还会受到 engine gap、mask 和截断影响。

当 drpo_epsilon=12.5>1 且新旧 log-prob 都代表有效概率时，$\lvert\pi_t-\mu_t\rvert\le1$，自适应上下界在理论上不可越过，因此两个 clipfrac 应为 0。若默认设置下它们非零，应先怀疑 log-prob 契约或数值实现，而不是解释成“训练经常触发 DRPO 边界”。

建议再按 old_prob 区间、token 位置、回答长度、token 类型和更新步数分桶。只存单个全局均值会失去 DRPO 想修复的长尾信息。

6. 可否证诊断树

flowchart TD
  S["回报不升 / ratio 异常 / penalty 暴涨"] --> A{"冻结权重重放：ratio≈1？"}
  A -->|否| B["查温度、token、mask、batch 几何、权重同步"]
  A -->|是| C{"组内优势有方差？"}
  C -->|否| D["查同组同奖励、verifier 饱和、采样多样性"]
  C -->|是| E{"绝对概率位移集中在高概率 token？"}
  E -->|是| F["检查学习率、更新次数与 delta"]
  E -->|否| G{"只有 ratio 尾部异常？"}
  G -->|是| H["按 old_prob 分桶，识别低概率相对放大"]
  G -->|否| I["检查聚合、数据错位与分布式切批"]

四个短实验

  1. 冻结一致性。 相同 token、权重、温度、前向模式下，预测 ratio≈1；否则优先修数据管线。
  2. 切换 anchor。 若 replay 源恢复 ratio≈1 而 rollout 源没有，偏差位于推理—训练边界。
  3. 单步更新。 首步即暴涨通常指向优势尺度、错误对齐或学习率；多步后才涨更像 stale anchor 与复用强度。
  4. 概率分桶。 若极端 ratio 只出现在低 old_prob 且 $\lvert\pi-\mu\rvert$ 小，不应用 PPO 的 ratio 阈值直接告警。

7. 典型失效模式

Sampling temperature 不一致

训练 replay 常计算 log_softmax(logits / T)。若 rollout 的实际温度不同，每个 token 的 log-prob 都会系统偏移。必须统一采样配方，不能在 ratio 后做经验校准。

adv.detach() 或 old_prob.detach() 被删除

优势估计或行为策略概率会成为错误梯度通道，目标不再对应论文。单元测试应断言二者无梯度，并用手算检查 new_logp 的更新方向。

Packed sequence 与 loss_mask 错位

症状包括 prompt/padding 被训练、短回答权重异常、reward 正常却某些回答无梯度。构造不同长度、带 prompt/pad 的最小 batch，逐位置核对索引。

指标名沿用 clipfrac

代码里的 clipfrac_upper/lower 是“超出 $1\pm\delta/\mu_t$ 的比例”，不是发生了裁剪。文档、告警和看板应改用“adaptive-bound exceedance”解释。

8. 最小单元测试

  1. new_logp == old_logp：ratio=1、penalty=0，单 token loss 应为 $-A$，不是 0。
  2. $A=0$：策略项与 penalty 都为 0。
  3. 相同 $\lvert r-1\rvert$：正负优势的 penalty 相同。
  4. 固定 ratio 位移：高旧概率产生更大 penalty。
  5. penalty_mu_weighted 开关：true 与手算 DRPO 一致，false 与 SPO 型目标一致。
  6. 无效 token：不贡献 Loss 和指标。
  7. 极端 log-diff：clamp 后无 NaN/Inf，并显式验证区间外 ratio 路径梯度为 0。
  8. 已知 ratio：approx_kl=(r-1)-log(r) 且逐点非负。
  9. 有效概率对、$\epsilon>1$：上下 clipfrac 都应为 0。
  10. 不同长度序列：聚合结果与手算一致。
  11. 多更新：4 个更新中 anchor 保持冻结，replay 源只在循环前额外前向一次。
