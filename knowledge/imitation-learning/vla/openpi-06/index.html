前面几代的机器人控制监督主要来自演示；π0.5 虽然还加入网络多模态共训练，但仍不利用机器人执行后的成败反馈。π*0.6 要突破的正是这一点：让策略也从自主 rollout、失败轨迹和人工纠正中学习。整套工作分成两层：π0.6 是监督训练的基座模型，通过更大的主干、动作专家、数据规模和条件输入提升开箱能力；π*0.6 是以 π0.6 为起点、再用 RECAP 做强化学习式后训练的版本。它不是直接对 VLA 做策略梯度，而是训练价值模型、构造优势条件，再以监督目标更新策略。

必须先建立的区分。本专题涉及两个名字相近但含义不同的对象。π0.6 是基座视觉-语言-动作模型，训练方式仍然是监督学习（模仿学习加共训练），它延续 π0.5 的分层设计——高层预测语言子任务，低层动作专家生成连续动作；模型卡把它放在不做任务特定微调的开箱设置中评测，这是一种评测口径，不是“所有新任务都不再需要微调”的保证。π*0.6 是以 π0.6 为基座、再用 RECAP 后训练得到的模型，它新增了价值判断、优势条件和经验数据闭环。凡本专题写「π0.6」处指基座，写「π*0.6」处指后训练版本，两者的实验也分属两组、不可混引。
本页的事实口径。基座部分取自官方 π0.6 Model Card（Physical Intelligence，2025 年 11 月 17 日）与 arXiv 2511.14759 第五节；RECAP 部分取自同一篇论文的第四节与附录。需要说明两点：RECAP 的实现不在开源 openpi 仓库中，因此本专题涉及 RECAP 的结构描述无法用源码复核，只能对照论文；论文与模型卡都未给出的量（失败代价取值、预训练数据各来源的规模与配比）一律写定性描述，不做转述；预训练数据的总体量级，论文只给出「数万小时演示」一句。
本专题的架构底座在形态上延续 π0 与 π0.5，那两个专题的数字已依据 openpi 源码逐项核对。但具体规模已经换代——本代的主干是 Gemma 3 4B、动作专家 860M，与前两个专题记录的 PaliGemma 3B 加 300M 不是同一组权重。凡与 π0 / π0.5 机制相同的部分，本专题只指出差异并给出链接，不重复讲解。

一、π0.6 在 π 系列中的位置

π0.6 不是另起炉灶，而是沿着同一条线演化而来。把四代的关系写成两个式子，后面整个专题的结构就清楚了：

\[\pi_{0.6} \approx \pi_{0.5}\text{ 的核心框架} + \text{Gemma 3 4B} + \text{860M 动作专家} + \text{扩展的多平台数据} + \text{metadata 与文本因果掩码}\] \[\pi^{*}_{0.6} = \pi_{0.6} + \text{价值函数} + \text{优势条件} + \text{RECAP 迭代后训练}\]

这里的加号表示概念差异，不是可以直接相加的参数或检查点。第一式仍属于监督学习，没有引入任务回报；第二式才加入由执行结果训练的价值函数、优势条件与迭代闭环。模型卡主要描述基座，论文则给出 RECAP，并在第五节补充基座改动。

二、π0.6 基座：官方架构图与关键改动

论文第五节用三句话概括了 π0.6 相对 π0.5 的改动，原文是：预训练数据集增补了来自多个机器人平台的额外数据；基座 VLM 换成 Gemma 3 4B；动作专家的规模增加到 860M 参数。模型卡补充了这三点之外的结构细节。

两个容易被一句话带过、但实际决定了这一代形态的点：

  • 知识隔离不是「冻结主干」。 模型卡的原话是：视觉-语言主干预测 FAST 动作 token 与共训练样本（例如多模态网络数据），动作专家预测连续动作，而动作专家的梯度不回流到主 VLM 主干。主干依然在更新，只是不被流匹配那一路的梯度更新。这两件事的区别，以及为什么必须这样切，见子页 ②。
  • 离散动作与连续动作是独立预测的。 论文第五节明确写道，动作专家不接收 FAST 动作 token 作为输入，因此离散与连续两路动作是各自独立预测出来的。这不是造了两个控制器，而是让主干也获得动作层面的监督信号。

三、π*0.6 与 RECAP：从经验中学习

RECAP 的核心工程主张是：演示、自主 rollout、人工接管纠错，这三类数据不该走三套流程，应该在同一个后训练目标下被消化掉。统一它们的钥匙是「这段轨迹后来怎么样了」这一条共同可得的标注。

整个方法可以压缩成一条链，然后不断重复：

\[\mathcal{D} \longrightarrow R_t \longrightarrow V_{\phi}(o_t, \ell) \longrightarrow \mathrm{Adv}_t \longrightarrow I_t \longrightarrow \pi_{\theta}(a \mid o, \ell, I)\]

其中 \(R_t\) 是从该轨迹得到的经验回报，\(V_{\phi}\) 学习的是给定观测与任务后的条件期望，\(\mathrm{Adv}_t\) 是 \(N\) 步优势，\(I_t\) 是按任务阈值二值化后的指示。每轮把新数据并入累计数据集后，价值函数和策略都按 Algorithm 1 从各自的预训练检查点重新训练，而不是沿用上一轮权重续训。

flowchart TB
  D1["专家演示 人遥操作全程采集"] --> POOL["统一数据池"]
  D2["自主 rollout 策略上机跑 成功与失败都保留"] --> POOL
  D3["人工接管纠错 纠正段强制记为正 整条 episode 可选并入"] --> POOL
  POOL --> LAB["任务结果标注 成功或失败"]
  LAB --> VTRAIN["训练价值函数 回报离散成 201 档做分类"]
  VTRAIN --> ADV["逐动作块计算 N 等于 50 步的优势"]
  ADV --> BIN["与任务阈值比较 得到二值优势指示 I"]
  BIN --> POLTRAIN["训练优势条件策略 条件取该样本的真实 I 并以 30% 概率丢弃"]
  POLTRAIN --> CKPT["新一版策略权重"]
  CKPT --> INFER["推理时条件固定取 I 为真"]
  INFER --> ROLL["上机执行 产生新的 rollout"]
  ROLL --> D2
  ROLL --> D3
  ROLL --> LAB

这张图里唯一不显然的是回流的三条边：一次上机同时产出自主 rollout 数据、人接管时的纠错片段、以及该次任务的结果标注。三者来自同一批物理执行，采集成本被摊薄——本站认为这是闭环能持续运转的一个现实条件。

三类数据各自补的信息

数据来源 怎么产生 它提供的信息 缺了它会怎样
专家演示 人遥操作全程采集 任务该怎么做的基本示范 策略没有可用的起点，价值函数也没有正样本可参照
自主 rollout 模型自己上机跑，成功与失败都留 当前策略实际访问的状态分布与失败模式 缺少部署分布覆盖，价值模型与策略只能依赖对专家分布之外状态的外推，误差更难控制
人工接管纠错 人在模型跑偏时接管；纠正段强制置为正，整条 episode（含自主部分）可选并入 从坏状态回到好状态的恢复动作 坏状态下缺少直接的正确示范，只能靠自主尝试中出现的较好动作经优势筛选出来

三类数据都能附带 episode 结果，因此可以进入同一个价值学习流程；但它们的作用不只由结果标签决定，还取决于覆盖的状态与动作分布：演示偏向专家访问的状态，rollout 覆盖当前策略真正会遇到的状态，纠正数据集中在“模型跑偏后怎样恢复”的过渡区。纠正数据通常更费人力，因为采集时需要人持续监看并在必要时接管。

上表「缺了它会怎样」一栏是本站的分析，不是论文的结论。尤其第三行需要注意：纠错数据有用，但不是必需的——论文的衣物折叠迭代实验刻意不用任何人工纠正，定向失败移除实验也完全靠强化学习、不含介入数据或额外演示，两者都取得了显著改进（结果见子页 ⑥ 第六、八节）。
