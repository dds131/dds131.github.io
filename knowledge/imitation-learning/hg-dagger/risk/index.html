专题总览 1 Foundations 2 Intervention 3 Risk 4 VLA Pipeline

HG-DAgger 用策略 ensemble 的动作分歧构造 doubt，并从后期人工接管时刻提取经验阈值。这个分数可以帮助识别模型不熟悉的区域，但它不是碰撞概率；低于阈值也不能证明状态安全。

原论文事实边界：训练时仍由人决定接管，阈值主要用于理解和评估最终策略。自动把控制权切给保守控制器是论文提出的未来方向，不是原实验已经验证的部署流程。
必需先修：Intervention——authority、事件窗口与日志 schema

风险信号定义：doubt 测量的究竟是什么

从 ensemble action 到 covariance

对同一观测 o_t，第 k 个 novice 成员输出：

\[a_t^{(k)}=\pi_{\theta_k}(o_t),\qquad k=1,\ldots,K.\]

动作均值为：

\[\bar a_t=\frac{1}{K}\sum_{k=1}^{K}a_t^{(k)}.\]

协方差写成带显式实现约定的形式：

\[C_t=\frac{1}{\nu}\sum_{k=1}^{K} \bigl(a_t^{(k)}-\bar a_t\bigr) \bigl(a_t^{(k)}-\bar a_t\bigr)^\top.\]

ν 必须由实现声明：population convention 可用 K，unbiased sample convention 可用 K-1。原论文只规定使用 ensemble 输出的 covariance，没有强制唯一分母。K<2 时无法从成员间分歧构造有意义的 covariance。

原始 doubt

原论文定义：

\[d_N(o_t)=\left\lVert\operatorname{diag}(C_t)\right\rVert_2.\]
  • diag(C_t) 保留每个动作维的边际方差，忽略维度间协方差结构。
  • 二范数把多维方差压成一个标量。
  • 若动作没有标准化，数值受单位与尺度支配，量纲与动作单位平方相关。
  • 它表示 ensemble 输出分歧代理，不是碰撞概率、失败概率或精确贝叶斯后验方差。
flowchart LR
  O[同一观测 o_t] --> A[成员输出聚集<br/>低分歧]
  O --> B[成员输出分散<br/>高分歧]
  A --> C[成员较一致]
  B --> D[成员较不一致]
  C -. 不能直接推出 .-> S[任务安全]
  D -. 不自动等于 .-> R[任务危险]

图 1｜合成的 ensemble 直觉。 分散只表示成员不一致，不自动等于任务危险；聚集也可能来自共模错误。

四种概念不可互换

概念 例子 能回答 不能回答
模型分歧 ensemble action variance 成员对动作是否一致 动作是否安全或任务是否成功
数据陌生度 embedding / OOD distance 输入是否偏离训练覆盖 偏离是否一定危险
任务风险 碰撞裕度、掉落、不可恢复性 后果严重度或失败倾向 模型是否见过该状态
人类干预 takeover request / confirmed event 人在当时选择接管 完整、无延迟的真实风险标签

页面中心结论：doubt 可以与风险相关，但“相关代理”不等于“风险本身”。

风险信号登记表

任何信号进入阈值或融合前必须登记：

字段 含义
signal_id / signal_version 稳定名称与版本
producer 产生信号的模型、规则或设备
input_contract 使用的观测、历史、动作和时间戳
output_semantics 分歧、距离、概率、物理余量或故障状态
unit_and_range 单位、范围与数值方向
update_rate / max_age 更新频率和最大有效年龄
normalization_hash 动作或特征归一化版本
policy_scope 适用 checkpoint、成员和任务范围
known_failures 共模错误、传感器缺失、饱和或 OOD
consumer 评估、提示、请求接管或独立安全层

没有单位、时效和版本登记的分数不得与阈值比较。

阈值与校准：从干预日志到可验证 operating point

原论文阈值

每次人类开始接管时记录当前 novice doubt，按训练时序形成：

\[\mathcal I=[d_1,d_2,\ldots,d_N].\]

原论文使用干预日志最后 25% 的均值作为 τ。下面是本站为“最后 25%”给出的确定化取整示例，不是论文唯一索引约定：

N = len(I)
if N == 0: threshold is undefined
m = max(1, ceil(N / 4))
tail = I[N-m : N]
tau = mean(tail)

实现必须记录 N、m、排序键、取整方式、缺失事件处理和重复干预去重规则。后期 novice 通常更接近最终策略，因此后期干预 doubt 更相关；但 25% 是经验选择，不是最优性定理，样本少、策略突变或分数不可比时会不稳定。

估计允许集

原论文写作：

\[\hat{\mathcal P} =\{x_t\mid d_N(\mathcal O(x_t))\le\tau\}.\]

P 是人判断的 permitted set；P̂ 是 doubt 阈值产生的估计集合。x∈P̂ 只说明当前有效信号未超过阈值，不证明 x∈P，更不证明未来轨迹安全。阈值方向由信号语义决定；输入过期、无效或版本错配时归属为 unknown，不能默认放入 P̂。

阈值构造不等于概率校准

  1. score：如 d_N，用于排序或区分样本。
  2. thresholded decision：如 d_N>τ，产生告警或不告警。
  3. calibrated probability：如 P(event within Δ | score)=p，需要单独拟合并在未见数据验证。

原始 τ 只完成第二层。若输出概率，还需要可靠性图、分箱统计或恰当评分规则；本页所称校准主要是阈值评估、漂移检查和 operating point 验证。

阈值选择流程

flowchart TD
  A[冻结 signal spec 与 policy scope] --> B[定义事件标签和预警窗口]
  B --> C[按 episode 场景版本划分]
  C --> D[calibration split 计算论文基线和候选阈值]
  D --> E[validation split 扫描 precision recall lead time burden]
  E --> F{满足预声明约束?}
  F -- 否 --> G[信号不可用或重新设计]
  F -- 是 --> H[冻结 threshold spec 与 hash]
  H --> I[独立 closed-loop test 只评估一次]
  I --> J[Pipeline 决定是否允许发布]

图 2｜阈值选择与冻结。 calibration、validation、test 按 episode / 场景隔离；不能用测试集反复调阈值。同一版本数据在调参后不能再次充当独立测试证据。

threshold spec 必须绑定 signal version、policy / ensemble hashes、动作归一化、任务、本体、数据范围与日期。论文 τ 是复现基线；quantile、成本敏感或多目标阈值属于工程扩展。N=0 或数据不足时返回 undefined / not validated，不得以 0、无穷或历史阈值静默代替。

误报、漏报与失效模式：评价告警，而不是只看分数

先定义评估目标

  • human_takeover：人类请求或确认接管，是行为代理标签。
  • independent_safety_event：限位、碰撞监控、急停或硬件故障事件。
  • task_failure：掉落、碰撞、越界、语义错误、超时或不可恢复终止。
  • recovery_outcome：成功恢复、再次接管、停止或重置。

同一信号对每类目标分别评估。人的偏好、疲劳和反应延迟影响接管标签；及时干预可能阻止物理失败，所以 task failure 也不能单独充当全部正例。

事件窗口级混淆矩阵

先冻结预警窗口 Δ_pre、事件合并间隔、告警去抖和冷却，再以独立事件为单位：

事件在窗口内发生 事件未发生
信号提前告警 TP：有效提前量内预警 FP：告警但没有目标事件
未提前告警 FN：事件发生但无有效预警 TN：无告警且无事件

事件后才出现的告警不能算 TP；持续告警不能逐帧重复计数；TN 单位固定为时间窗或 episode，避免帧频让 accuracy 虚高。takeover request、confirmed 与 first human action 是不同锚点，必须预先声明。告警促成人工接管后没有碰撞属于被干预的反事实，不能简单标成 FP。

最小指标集

指标 回答的问题 必须同时报告
event recall / sensitivity 多少事件被提前捕获 事件数、严重度、置信区间
precision 告警中多少对应目标事件 标签类型与干预策略
false alarms / hour 或 episode 操作负担多大 暴露时长或回合数
miss rate by severity 严重事件漏报多少 严重度定义
lead-time distribution 告警比事件早多久 中位数、分位数、负提前量
time under alert 处于告警状态多久 去抖、迟滞和冷却配置
intervention burden 增加多少人工接管 人员、任务和会话分层
PR curve / threshold sweep 稀有正例下的权衡 数据版本与 operating point
cross-version drift 更新后分布是否改变 policy / signal 版本

单一 accuracy、AUROC 或均值不能独立作为通过证据。风险稀有时优先展示 PR 曲线、每回合误报和严重漏报。

四象限与典型原因

象限 解释 典型原因 处理
高 doubt / 高任务风险 理想告警 数据稀疏且接近失败 补数据并核验提前量
高 doubt / 低任务风险 可能误报 多模态安全动作、冗余自由度、尺度失衡 分组信号并重校准
低 doubt / 高任务风险 危险漏报 共模偏差、传感器故障、系统性缺口 独立安全信号、失败挖掘、停止发布
低 doubt / 低任务风险 期望区域 数据覆盖且成员一致 仍不能推出形式安全

失效模式—检测—响应矩阵

失效模式 可观察证据 风险 响应
ensemble 成员高度相关 输出长期近同，seed / data 几乎一致 伪低 doubt 审计训练多样性，补共模测试
人类反应延迟 score 上升早于 takeover request 阈值锚点偏晚 报告 lead time，使用窗口标签
后期干预样本太少 m 小且 bootstrap 区间宽 τ 不稳定 标记未验证或继续受控采集
单位 / 归一化变化 normalization hash 改变 分数尺度漂移 旧阈值失效并重估
策略版本变化 score 分布与错误类型改变 阈值错配 绑定 checkpoint / ensemble 并重验
输入缺失或过期 validity=false 或 age 超限 低分数无意义 输出 unknown，不视为低风险
传感器共模错误 成员收到同一错误输入 一致错误 独立健康监控与跨模态检查
多模态安全动作 成员提出不同但可行动作 高 doubt 误报 任务后果评估，不压制动作多样性
分布漂移 OOD 或分任务指标恶化 旧校准失效 限定 scope 并触发再验证

安全降级：风险信号只能请求动作，不能证明安全

与 Intervention 状态机的唯一接口

风险监控器只输出结构化事件：

risk_event_id
signal_id / signal_version
policy_id / threshold_spec_id
score / threshold / comparison_result
risk_level = normal | caution | request_takeover | invalid
reason_codes[]
observed_at / produced_at / valid_until
input_validity

它可以生成 model_risk_signal 或 safety_monitor_trip 请求，却不能直接把状态写成 HUMAN_RECOVERY。控制权仍由 Intervention 的 authority arbiter 和底层确认决定。

信号状态与系统响应模板

信号状态 监控器输出 状态机建议处理 不允许的解释
有效且低于阈值 normal 继续受独立安全层约束的当前状态 已证明安全
接近阈值或短时异常 caution 提示人、加强监控、记录上下文 自动降低安全约束
有效且超过阈值 request_takeover 请求接管或平台保守路径 直接伪造 human authority
输入无效 / 过期 invalid 按平台故障策略保持或停止 用上次低分数无限续期
多信号冲突 带 reason 的 caution / request / invalid 预先验证的优先级或停止 在线临时选择更乐观信号
独立硬安全触发 safety_monitor_trip 直接走平台安全降级 等待模型阈值确认

hold、限速、制动、回退、人工接管或终止必须由平台安全分析和验证确定；本页只定义语义，不给真实硬件命令。

降级原则

  1. invalid 不等于 normal：缺失、过期、NaN、版本不匹配和输入异常都进入未知或故障处理。
  2. 硬安全信号优先：物理限位、急停与经验证的监控不等待模型 uncertainty。
  3. 人工确认真实存在：无人可接管或确认超时时走平台安全降级，不伪造人工接管。
  4. 失败保持可审计：记录信号、版本、状态迁移、实际 authority 与 outcome。
  5. 重复告警升级：反复接管或持续 invalid 触发停止或重置，不无限抖动。
  6. 默认不自动恢复：从 SAFE_STOP 返回需显式复位与新回合授权。

独立安全层的边界

独立安全层可以使用碰撞检测、工作空间/速度/力矩限制、硬件 watchdog、急停和平台特定保护。模型 doubt、OOD、融合分数和人工接管事件不能替代这些职责。Risk 只验证信号对目标事件是否有预测价值；Pipeline 再检查整个系统能否进入受控发布阶段。

本页不做发布决定

本页输出 threshold artifact、验证指标、known failures 和降级接口。进入仿真、台架、受限真机或扩大范围属于 Pipeline release gate。证据不足时只能输出 not validated，不能通过改文案变成可发布。

VLA 与多信号扩展：高维、多模态与共模失败

连续混合单位动作

VLA 动作可能混合米、弧度、关节量和夹爪量，直接在原单位求 covariance 会让高尺度维主导。可以在训练动作契约的标准化空间计算并记录 normalization hash；按位置、姿态、关节和夹爪分组；或使用具有物理解释的显式权重。必须同时显示各组分数，避免单一标量掩盖局部异常。

动作表示、单位、归一化或维数改变后，旧 doubt 与阈值全部失效。

动作块

对 H×d_a 动作块至少区分：

  • 逐时间步 covariance 再取 max、quantile 或 weighted sum。
  • 展平整块后计算，但维数和时间尺度会改变分数。
  • 近期动作比远期动作权重更高的折扣聚合。
  • 只评估即将执行的 H_exec，而不是全部预测步。

每种选择都改变 signal semantics，必须注册独立 signal_version。lead time 相对实际执行时刻计算，而不是含糊地相对 chunk 生成时刻。

离散 token 与生成式策略

  • token ID 是类别编号，不能直接求数值方差。
  • 可以比较类别分布的 entropy、mutual information、KL / JS divergence 或 top-k disagreement，但要分别定义和验证。
  • 同一随机策略多次采样的多样性可能是任务多模态，不等于 ensemble 的 epistemic disagreement。
  • Diffusion / Flow / CVAE 的 sampling spread、模型成员分歧和条件敏感性必须分开。
  • 多个安全可行动作会造成高分歧，不能惩罚全部多模态行为。

多模态输入与共享骨干

共享视觉/语言骨干而只更换小头部的 ensemble 可能高度相关并共享感知错误。相机冻结、遮挡、顺序错位、语言歧义和本体状态失真，都可能让成员一致地产生错误动作。风险评估必须并列输入健康、freshness、任务进度、物理约束和模型分歧；缺失模态使用显式 validity，不能用占位零值换取低 doubt。跨本体 adapter 改变尺度和语义，threshold scope 必须绑定 robot / config。

多信号融合

信号 代表 典型盲点 失效处理
ensemble doubt 模型成员分歧 共模错误、多模态动作 与输入健康和物理信号并列
OOD / embedding distance 数据陌生度 语义距离不等于后果 限定数据与 backbone 版本
constraint margin 物理边界余量 模型或标定误差 独立安全层优先
task progress / verifier 任务是否偏离 verifier 可能错误 保留人工与结果评估
system health 传感器、时钟和通信 不判断任务语义 invalid 走故障降级
human request 人的综合判断 延迟、疲劳与偏好 最高优先正常接管请求

融合规则必须固定 AND / OR / priority 或学习模型的确切语义；保存全部原始信号与 reason code；缺失值不能填成低风险；在未见 episode 与闭环场景验证。学习式融合还要独立划分训练、校准和测试集，避免与 policy 数据泄漏。

收束与下一页接口

  • 原论文事实：HG-DAgger 用 ensemble action covariance 对角线的二范数构造 doubt，并用后期人工干预日志形成经验阈值。
  • 评估要求：阈值绑定信号、策略、动作契约、任务和事件窗口；误报、漏报、提前量和失效模式在独立数据报告。
  • 工程边界：风险信号只能请求状态迁移并支持评估，不能替代控制权确认、独立安全层或发布审批。
