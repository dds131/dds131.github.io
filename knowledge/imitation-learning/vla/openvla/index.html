一、一句话定位：把动作当语言说出来

OpenVLA 是一个 7B 视觉-语言-动作模型（Vision-Language-Action model，VLA）。论文与项目公开了 OpenVLA 的训练数据配方、训练代码和模型权重；不过完整系统仍继承 DINOv2、SigLIP、Llama 2 等上游组件各自的许可证与获取条件，因此这里不把“开放发布”简化成所有组成部分都使用同一种开放许可。

它的核心方法是把连续机器人动作量化成语言模型词表中的 token，再用 VLM 的自回归接口预测这些 token。网络主体和损失形式高度复用现有 VLM：没有另加独立的动作专家或扩散头，训练使用因果语言建模交叉熵。但机器人任务仍需要专门的动作 tokenizer、RLDS 数据管线、提示模板与 label mask、反归一化和 predict_action() 部署接口；因此“复用 VLM 栈”不等于“无需机器人专用工程”或“训练与文本生成完全相同”。

7B参数量
970k预训练演示轨迹数
256论文中的动作标签数；源码解码为 255 个不同中心
7论文标准动作维度（3 位移 + 3 旋转 + 1 夹爪）
64×A100预训练集群规模
14 天预训练时长
2048全局 batch size
约 6 HzRTX 4090 上的推理频率

一个必须先立住的定位：原始 OpenVLA 本质上是大规模模仿学习（behavior cloning，行为克隆），只不过把连续机器人动作转成了 token，从而把模仿学习改写成语言模型的 next-token prediction。它不是 PPO、SAC 这一类强化学习，模型里没有 Critic、没有 Q 网络、没有 reward model。论文把目标抽象为动作 token 上的交叉熵；发布实现默认还监督动作序列后的 EOS。凡是把 OpenVLA 说成「强化学习方法」的材料，第一句就错了。

本专题的事实来源分三层，正文每处标明出自哪一层：层一 论文 arXiv 2406.09246（CoRL 2024）；层二 官方源码固定提交 c8f03f48 与 HuggingFace 权重固定修订 31f090d0 的 config.json、modeling_prismatic.py；层三 官方 Project Page。三层之间存在若干实质分歧（例如 projector 的层数），凡有分歧处本专题以层二为准并注明层一的说法。仓库主分支仍作为最新入口，但可复核结论不依赖会继续变化的 main。

论文摘要给出的对比口径是：OpenVLA 在 WidowX 与 Google Robot 两个本体、29 个评测任务上，绝对成功率比此前的 55B 参数 RT-2-X 高 16.5 个百分点，而参数量约为其七分之一（层一）。更准确的历史定位是：作者将其称为首个开放发布的通用 VLA；“通用”指在多数据集、多任务和多本体上训练与评测，并不等于无需适配即可覆盖任意新机器人。

读这一页之前建议先看 VLA 总览，那里交代了两条动作表示路线的分野与 RT-1 到 RT-2 的脉络。

三、官方演示与整体架构图

先看模型实际在做什么，再看它是怎么搭的。下面四段视频取自官方 Project Page 的定性结果展示，官方按能力维度分了目录，这里各取一段。视频从官方站点直接播放，本站不留存副本。

杂乱场景中选对目标

官方归类为 correct target。桌面上有多个物体，模型必须把指令里的名词落到正确的那一个上。这一类任务考察的是语言落地（language grounding），而不只是抓取动作本身——抓错物体的失败与抓不稳的失败，成因完全不同。

按物体朝向调整夹爪姿态

官方归类为 good orientation。抓取细长电池时，夹爪需要结合物体朝向调整姿态；这段 rollout 说明策略对空间信息敏感。它不能单独证明能力来自 DINOv2 分支，具体贡献需要双视觉编码器消融才能判断。

抓取失败后自主重试

官方归类为 reattempt。第一次未抓稳后，策略根据后续观测再次尝试；发布模型没有显式的重试状态机。该视频展示了闭环策略能够出现恢复行为，但论文与视频没有隔离其来源，不能据此断言一定由含失败重试的演示片段所致。

Google Robot 本体上的抓取

取自官方与基线方法的对照展示，对应论文中的 Google Robot 评测。论文使用通用预训练检查点在 WidowX 与 Google Robot 任务上评估跨本体能力；这一结果支持共享表示的可迁移性，但不意味着模型可零配置部署到任意新本体。

四、完整前向路径

从单帧第三人称 RGB 图像和语言指令到 7 维末端动作，发布模型的标准路径如下。这里的“7 维”是论文与官方检查点采用的接口；换本体时必须重新核对动作维度、坐标系、控制周期与归一化键，不能只替换机械臂驱动。

flowchart TB
  IMG["第三人称 RGB 图像"] --> PP["DINOv2 与 SigLIP 各自的预处理：缩放至 224×224 并按各自统计量归一化"]
  PP --> DIN["DINOv2 ViT-L/14：倒数第二层 patch 特征"]
  PP --> SIG["SigLIP ViT-SO400M/14：倒数第二层 patch 特征"]
  DIN --> CAT["按通道维拼接同一 patch 位置的两路特征"]
  SIG --> CAT
  CAT --> MLP["FusedMLPProjector：3 个 Linear + 2 个 GELU，映射到语言隐藏维"]
  TXT["自然语言指令"] --> TKZ["Llama 2 tokenizer 与词嵌入"]
  MLP --> SEQ["序列拼装：BOS → 视觉 token → 指令 token"]
  TKZ --> SEQ
  SEQ --> LLM["Llama 2 7B：因果注意力"]
  LLM --> AR["自回归生成 7 个动作 token（标准配置）"]
  AR --> DEQ["token id → 分箱索引 → 分箱中心"]
  DEQ --> UNNORM["按数据集与动作维度的统计量反归一化"]
  UNNORM --> ACT["3 位移 + 3 旋转 + 1 夹爪"]
  ACT --> CTRL["底层控制器"]

理解这条链路时要区分三层事实：

  • 输入序列与监督序列不是一回事。 视觉 token 和指令 token 构成条件，label mask 会忽略这些位置。论文把目标概括为 7 个动作 token；发布训练实现默认还监督动作后的 EOS，因此标准 7 维样本通常有 8 个受监督位置。
  • 主体网络复用 VLM，机器人接口仍是专用工程。 双视觉编码器、projector、Llama 2 与语言模型输出头来自 Prismatic/VLM 范式；动作量化、数据混合、提示格式、损失掩码、反归一化与控制循环则是 OpenVLA 的机器人任务接口。
  • 视觉嵌入插在 BOS 之后。 这是发布实现的序列约定。位置顺序改变会同时改变因果可见性和 Llama 2 的 RoPE 位置；复现时应直接核对序列拼装代码，而不是按自然语言描述猜测。

五、模块速览表

下表只给出能够由架构与训练目标直接支持的作用。DINOv2 与 SigLIP 的预训练目标带来不同表征偏置，但不能凭单段 rollout 把某项成功完全归因于某一路；确切边际贡献需要消融实验。

模块 输入 → 输出 可确认的作用 需要避免的误解
图像预处理 相机帧 → 两份 224×224 张量 分别匹配 DINOv2 与 SigLIP 的输入统计 两路预处理不可随意共用；224 是发布配置，不是所有分辨率都无效
DINOv2 图像 → patch 特征 B 提供自监督视觉表征，偏向保留局部与空间结构 “负责位置和姿态”是功能概括，不是独占的因果分工
SigLIP 图像 → patch 特征 A 提供图文对齐表征，便于语言条件关联视觉内容 它也包含空间信息，不能简化为只识别物体类别
通道拼接 A、B → 融合特征 在拼接点完整保留两路数值，交给后续层选择与混合 “无损”只适用于该操作本身；projector 与后续网络仍可能压缩信息
projector 融合特征 → Llama 隐藏维 完成维度转换并学习视觉—语言接口 线性映射也能跨通道混合；GELU 增加表达能力，但不能据此断言非线性“必需”
序列拼装 视觉嵌入 + 文本嵌入 → 单序列 让后续指令位置和动作位置在因果注意力下访问视觉上下文 BOS、视觉、文本的顺序属于实现协议
Llama 2 7B 条件序列 → 下一 token 分布 复用预训练语言模型的表示与自回归生成能力 预训练“常识直接产生正确动作”是机制假设，不是单独被证明的因果结论
语言模型输出头 隐状态 → 全词表 logits 用既有词表末段的 token 表示动作标签 未扩展词表不等于没有动作 tokenizer 或专用解码逻辑

七、动作 token 化：一页纸

动作是连续向量，而语言模型输出词表 id。OpenVLA 用“数据侧归一化 + 模型侧均匀分箱 + 词表映射”连接两者；把这三步混成一个“分位数分箱”会得到错误结论。

步骤 运算 位置与职责
逐维归一化 仅对归一化掩码 \(m_i=\mathrm{true}\) 的维度，以第 1/99 百分位 \(L_i,H_i\) 映射到 \([-1,1]\) 并截断；\(m_i=\mathrm{false}\) 时保持数据变换后的尺度 RLDS 数据管线；标准 OXE 配置通常归一化前 6 个末端维度，不归一化绝对夹爪维
均匀分箱 np.linspace(-1, 1, 256) 生成 256 个边界，np.digitize 得到索引 ActionTokenizer；区间内是等宽而非等频
词表映射 反向使用词表末段 id 表示动作标签 不扩展输出头，但需要固定映射协议
解码 token id → 索引 → 分箱中心；仅对 \(m_i=\mathrm{true}\) 的维度按 \(L_i,H_i\) 反归一化 predict_action()；必须选对数据集统计键与掩码

这里有三个容易混淆的数字：

  • 论文把每维动作描述为 256 个离散类别/标签。
  • 发布源码用 256 个边界，因此相邻边界间距为 \(2/255\)，得到 255 个区间中心。
  • 编码路径可产生 256 个动作 token id，但解码会把索引裁到 \(0\ldots254\)，所以最高两个标签落到同一个中心；实际只有 255 个不同解码值。

以下推导只适用于 \(m_i=\mathrm{true}\)、确实使用该统计量归一化和反归一化的维度。设原始动作分位区间为 \([L_i,H_i]\)，量程 \(R_i=H_i-L_i\)，并令截断后的动作

\[\tilde a_i=\operatorname{clip}(a_i,L_i,H_i).\]

对区间内的等距中心解码，网格间距在原始量纲中为 \(R_i/255\)，因此除浮点舍入与边界实现细节 \(\varepsilon\) 外，

\[\left|\hat a_i-\tilde a_i\right| \le \frac{R_i}{510}+\varepsilon.\]

若关心未截断的原始动作，还必须把截断误差计入：

\[\left|\hat a_i-a_i\right| \le \operatorname{dist}\!\left(a_i,[L_i,H_i]\right) +\frac{R_i}{510}+\varepsilon.\]

对 \(m_i=\mathrm{false}\) 的维度，上述 \(R_i/510\) 不能直接套用；它保留数据变换后的尺度，量化误差应在该尺度下按实际输入区间单独分析。无论哪种维度，这都不是模型最终控制误差的上界，只是 tokenizer 的单维网格误差。策略预测错误、传感器噪声、控制延迟、坐标变换和执行器误差都不在式中。它也不支持“精细任务必然失败”的结论；完整推导见子页 ②。

八、训练目标：因果语言建模交叉熵

论文把一个动作向量写成 \(N\) 个动作 token。给定图像 \(o\)、语言指令 \(\ell\) 与动作 token 序列 \(w_{1:N}\)，论文层面的目标是

\[\mathcal{L}_{\text{action}}(\theta) = -\mathbb{E}_{(o,\ell,w_{1:N})\sim\mathcal D} \left[ \sum_{i=1}^{N} \log p_\theta\!\left(w_i\mid o,\ell,w_{<i}\right) \right].\]

发布的标准检查点采用 \(N=7\)，对应 3 维位移、3 维旋转和 1 维夹爪；这个数不是所有 OpenVLA 衍生配置的固定定律。训练采用 teacher forcing：预测第 \(i\) 个 token 时可以看到真实的 \(w_{<i}\)，部署时则看到模型自己先前生成的 token，因此仍存在自回归误差传播。

实现口径比上式多一个细节：默认配置 predict_stop_token=True，数据 collator 除 7 个动作位置外还保留 EOS 标签。因此标准样本通常在 8 个位置计算交叉熵。视觉、提示和 padding 位置被设为忽略值；“只监督动作部分”应理解为不重建图像或指令，而不是字面上永远只有 7 个监督位置。

项 固定配置或论文作业结果 含义
优化器 AdamW 全参数微调；不是 PPO 或 Q-learning
学习率 \(2\times10^{-5}\) 固定学习率
warmup / weight decay 无 / 0.0 以发布配置为准
梯度裁剪 全局范数 1.0 限制单步梯度幅度
全局 batch size 2048 正式 FSDP 作业每卡 32、64 卡，梯度累积为 1
训练长度 论文作业最终约 27 epochs；配置字段 epochs=1000 27 是论文训练历史，不是代码按 epoch 自动停止的上限
并行与精度 FSDP HYBRID_SHARD、BF16、FP32 梯度规约 通常节点内分片、节点间复制同步；确切分组依赖运行拓扑
梯度检查点 语言主干开启 用额外计算换激活显存
输入分辨率 224×224 论文的 384×384 实验约需 3 倍训练时间且未显示收益

这项设计的创新点不在于提出新损失，而在于把机器人动作监督转换成已有语言模型训练基础设施可处理的类别序列。它带来两类边界：

  • 自回归分解能表示条件相关的离散联合分布，但每个动作维度需要串行生成，延迟随 token 数增加。
  • softmax 在理论上可给多个离散序列分配概率质量，但官方 predict_action() 默认贪心解码，只返回一条序列；交叉熵本身也不保证多种合理动作会形成时间一致的轨迹。因而不能简单说“softmax 已经解决多峰动作问题”。

最后，token 准确率只是代理指标。它可以反映离散标签拟合程度，却不能单独反映相邻分箱错误的物理大小、控制时延、闭环稳定性或任务成功率。详细的 label mask、EOS 监督、优化配置与 FSDP 分工见子页 ③。

九、训练数据与配方：先统一接口，再讨论规模

OpenVLA 在 Open X-Embodiment（OXE）混合上训练，论文报告 27 个数据集、约 97 万条真实机器人演示。发布检查点则只有 25 组 norm_stats；已发布缓存统计覆盖 434,633 条轨迹、23,343,169 个 transition，不能把这些数字互相替代，也不能把缓存条目数直接当作最终有效训练样本数。这里的关键不只是“数据多”，而是把来源不同的数据转换成同一监督接口，并用采样权重控制各数据集对梯度的贡献。

  • 限定可兼容的观测。 发布配置主要使用第三人称 RGB 图像和语言指令，没有把所有数据集可用的深度、腕部相机、历史帧或本体状态统一塞入模型。
  • 统一动作张量槽位，而非完成全部物理标定。 标准接口为 3 维相对末端位移、3 维相对旋转和 1 维绝对夹爪动作；数据集专属 transform 处理已知差异。但各数据集的坐标系、单位、Euler 约定、频率和控制器仍可能不同，剩余尺度由每数据集统计量和部署契约共同约束。
  • 按数据集、按维度保存统计量。 第 1/99 百分位决定归一化与反归一化。它描述动作尺度，不描述数据集采样概率；部署选错统计键会直接造成动作幅度错误。
  • 显式重加权数据混合。 采样权重决定训练时看到各来源的频率，用于避免体量大的数据集完全支配训练。权重是配方选择，不等于数据质量排名，也不能只由原始轨迹数推出。

DROID 是理解证据边界的好例子。论文报告先让它占约 10% 的训练混合，观察到其动作 token 准确率学习较慢，并在训练最后三分之一将其移出，以降低影响最终模型质量的风险；代码配置中的原始倍率 0.06 不是可直接等同的展示百分比。论文也没有公开两阶段切换的精确命令与恢复步数。作者提出的可能解释是：DROID 也许需要更大混合权重或更大模型容量。这个过程说明当前容量与配方未能充分吸收 DROID，不证明 DROID 数据质量差，也没有受控实验证明保留它一定会降低最终成功率。

还要区分论文配方与发布代码中的相近名称：代码的某些 “plus/minus” 混合不仅处理 DROID，也可能调整 Language Table、Fractal 等数据集权重。复现时应记录具体配置名、提交版本和展开后的权重表，不能只写“使用 OXE”。完整数据集清单、RLDS 转换与配方差异见子页 ④。

十、反常现象：区分观测、证据与解释

这些现象提醒我们：离线拟合、单次推理和闭环控制是三个不同层级。下表把“直接观测到什么”与“能够下多强的结论”分开。

现象 证据支持的结论 不应过度推出
27 epochs 远多于常见 LLM 微调轮数 论文观察到训练动作 token 准确率超过约 95% 前，真机性能仍在提升 95% 不是跨数据集通用阈值，token 准确率也不能替代真机评测
非阻塞控制下 int8 比 int4/bfloat16 差 在论文测试硬件与控制设置中，int8 约 1.2 Hz；阻塞控制后各方案误差条重叠、未显示清晰差异，与速度/时序解释一致 这不是等价性检验；不能证明所有 int8 内核都慢，也不能量化速度解释了多少差异
冻结视觉编码器的变体掉点 该实验设置下，端到端更新视觉表示更有效 论文相关消融使用的变体不等同于最终双塔模型；“projector 必然无法补偿”只是可能机制
384×384 训练约慢 3 倍但未见收益 在论文任务和配置中，提高分辨率不划算 不能推广为 VLA 永远不需要高分辨率；论文没有确定根因
DROID token 准确率学习较慢 当前模型容量、权重与训练配方未充分吸收该数据 不等于数据质量差，也未证明移除后成功率一定提高
推理提示在特定条件下补 token id 29871 发布的 predict_action() 在缺失该前缀 token 时补齐，以匹配训练提示的 token 化形式 29871 不应被泛称为“特殊空 token”；官方没有给出去掉它的受控性能消融

int8 的阻塞控制对照尤其重要，因为它改变了检验方式：非阻塞控制同时改变数值精度和控制频率，阻塞控制则削弱频率差异对轨迹时序的影响。阻塞表中的点估计仍有约 5.6 个百分点极差，只是误差条重叠而未显示清晰差异；结果与“主要掉点来自速度”的解释一致，但不能证明方案等价，也不能量化速度的解释比例。

因此部署评测至少要同时记录：模型与量化配置、设备和内核、端到端推理延迟、实际控制频率、阻塞/非阻塞语义、动作归一化键和任务成功率。只报离线 token 准确率或单次前向耗时，都不足以解释闭环策略。六类现象的实验条件、替代解释与排障顺序见子页 ⑦。

十一、与 π0 连续动作路线的对比

OpenVLA 与 π0 都把视觉、语言和动作放进统一策略，但动作头的建模假设不同。下表比较的是原始论文方案，不代表所有后续变体。

维度 OpenVLA（离散 token） π0（连续 Flow Matching）
动作表示 论文为每维 256 个标签；发布解码器对应 255 个不同中心 连续动作向量
条件联合分布 按动作维度自回归分解 用条件流生成整段连续动作
训练目标 因果语言建模交叉熵 Flow Matching 向量场回归
输出模块 复用语言模型输出头，但需要动作 tokenizer、提示/掩码和反量化 增加动作专家、动作投影与相应注意力结构
推理过程 每个动作 token 串行生成 每个数值积分/去噪步骤并行更新动作块全部位置，但需要多次迭代

选择路线时应从任务约束出发，而不是给模型贴“更先进”的单一标签。若目标是复用成熟语言建模基础设施、研究离散动作表示或对齐公开 OpenVLA 基线，OpenVLA 是自然起点；若任务依赖连续精度、长动作块或并行输出，连续生成方案更匹配，但会增加动作专家与采样器的实现和调参成本。两者都需要真实闭环评测，不能由离线损失直接判定优劣。

OpenVLA-OFT 在同一主干上实验了并行解码、动作分块、连续动作 L1 目标以及额外输入/FiLM 等改动，并在其测试设置中报告了较高的成功率点估计和动作吞吐。这表明原始离散自回归接口不是唯一选择，也揭示了速度和动作分块的重要性；但论文没有在主表中给出统一多随机种子方差或显著性检验，因此这里不把点估计差写成“统计显著”。它不等于证明所有离散策略都无效，也不能把不同改动的收益在缺少对应消融时全部归因于“连续动作”。动作吞吐也不等于视觉闭环重规划频率：OFT 的整块开环执行协议与部署边界见子页 ⑧。

  4. 读子页 ③ 与 ④，把 行为克隆 → 动作离散化 → 自回归建模 → 交叉熵 这条数学主线和它依赖的数据配方连起来。
  5. 读子页 ⑤，对着源码把上面所有结论落到具体文件与函数上。
  6. 读子页 ⑥ 与 ⑦，进入实际使用与调试阶段：怎么微调、怎么部署、出问题时怎么定位。
  7. 最后读子页 ⑧，回头反思这套设计的边界，并接上扩散与流匹配等连续动作路线。

想接着看连续动作这条线，走 π0；想看小模型怎么在同样的思路下压到消费级硬件，走 SmolVLA；想看跨本体适配的另一种解法，走 X-VLA。

  2. Karamcheti, S. et al. Prismatic VLMs: Investigating the Design Space of Visually-Conditioned Language Models. ICML 2024. arXiv:2402.07865 —— OpenVLA 的 VLM 主干来源，双视觉编码器设计出自这里。

  4. Brohan, A. et al. RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control. CoRL 2023. arXiv:2307.15818 —— 离散动作 token 路线的直接前身，256 档离散化与覆写词表的做法出自这里。

  7. Hu, E. J. et al. LoRA: Low-Rank Adaptation of Large Language Models. ICLR 2022. arXiv:2106.09685 —— 参数高效微调的方法来源。
  8. Kim, M. J. et al. Fine-Tuning Vision-Language-Action Models: Optimizing Speed and Success (OpenVLA-OFT). arXiv:2502.19645 —— 子页 ⑧ 的主要依据。
  9. Vaswani, A. et al. Attention Is All You Need. NeurIPS 2017. arXiv:1706.03762 —— 因果注意力、缩放点积与位置编码的底座。
