一、先给结论：不是“把动作四舍五入成 256 档”

OpenVLA 的动作 token 化包含三层变换：

  1. 数据管线按数据集、动作维度用第 1/99 百分位数归一化；
  2. ActionTokenizer 用共享边界把每个标量映射为词表 id；
  3. 推理时模型自回归生成 id，再按指定数据集的统计量反归一化。

实现中有 256 个可用动作 token id，却只有 255 个不同的解码中心。同一个 id 在不同数据集上表示相同的归一化档位，但通常不表示相同的物理位移、转角或夹爪语义。

256动作 token id 数
255不同解码中心数
2/255相邻边界间距
31744–31999OpenVLA-7B 动作 id
32000映射使用的基础词表大小

本文以 OpenVLA 官方仓库提交 c8f03f4 和 Hugging Face 权重修订版 47a0ec7 为实现依据。论文、源码与本文推导分别说明，避免把解释性判断写成官方结论。

二、真实数据流：训练侧还有一次字符串往返

训练时，连续动作不是直接变成最终 input_ids。官方数据变换先让 ActionTokenizer 返回动作 token 解码出的字符串，把它放入 assistant 回答，再对完整对话重新分词：

flowchart LR
  A["原始动作 a"] --> B["按数据集统计量归一化 y"]
  B --> C["np.digitize 得到 d"]
  C --> D["动作 id：V-d"]
  D --> E["tokenizer.decode 得到字符串"]
  E --> F["拼入对话模板"]
  F --> G["基础 tokenizer 重新编码"]
  G --> H["监督动作 token 与 EOS"]

这条链路有两个隐藏契约：

  • 应验证动作序列满足 encode(decode(ids)) == ids，否则字符串往返可能改变 token 边界。
  • 标签掩码按 len(action) + 1 保留各动作维和 EOS，隐含“每维恰好一个 token”的前提。

推理侧不走字符串往返。predict_action 把动作维数设为 max_new_tokens，再截取生成序列末尾的相同数量 token，映射到分箱中心并反归一化：

flowchart LR
  P["图像 + 指令"] --> Q["generate"]
  Q --> R["最多 D 个新 id；默认期望实际生成 D 个"]
  R --> S["id 转索引并裁剪"]
  S --> T["255 个中心之一"]
  T --> U["按 unnorm_key 反归一化"]
  U --> V["D 维连续动作"]

所以只检查 ActionTokenizer.__call__ 不够；字符串往返、生成长度、动作维顺序和 unnorm_key 都属于同一个接口契约。尤其要注意：max_new_tokens=D 只是上限，不是长度断言；若生成因 EOS 提前结束，generated_ids[0, -D:] 可能把提示词尾部也切进来，官方包装器不会主动报错。

三、归一化：分位数、掩码与数据集语义

3.1 精确公式

对掩码为真的第 \(j\) 维，记

\[L_j=q_{01,j},\quad H_j=q_{99,j},\quad R_j=H_j-L_j,\quad \varepsilon=10^{-8}.\]

数据管线执行

\[y_j=\operatorname{clip}\!\left( 2\frac{a_j-L_j}{R_j+\varepsilon}-1,\,-1,\,1 \right).\]

分位数端点可避免少量离群值把多数样本压缩到很窄的区间。分位数只决定端点，端点之间仍是等宽分箱，不是等频分箱。

mask[j] == false 只表示该维跳过归一化，并在推理时跳过反归一化；它仍会进入 clip + digitize。官方 OXE 物化代码对支持的 EEF_POS 与 EEF_R6 动作统一把末维夹爪掩码设为假，但这不等于“末维一定是二值量”：标准化变换仍可能提供连续夹爪开度。

另有独立规则：若元数据中某维 min == max，数据管线把该未使用维设为 0。它与 mask=false 含义不同。

3.2 百分位数不保证固定 token 频率

连续分布、无大量并列值且统计样本与训练样本一致时，区间外两端各约有 1% 样本。实际频率还受经验分位数插值、重复值、有限样本和 mask=false 影响。因此“最外侧 token 各严格占 1%”不是数学保证。

3.3 反归一化依赖 unnorm_key

推理时，掩码为真的维度执行

\[\hat a_j=L_j+\frac{R_j}{2}(\hat y_j+1),\]

掩码为假的维度直接取 \(\hat a_j=\hat y_j\)。模型含多套统计量时，unnorm_key 决定使用哪一套；统计量不唯一又未指定时，官方实现会报错。

所以相同 token 只共享“归一化位置”，不共享物理单位。跨本体学习还依赖数据转换、维度顺序、坐标系和视觉—语言表征；动作 token 化不是跨本体泛化的充分条件。

四、等宽量化的精确定义

官方默认构造 256 个边界：

\[b_k=-1+\frac{2k}{255},\qquad k=0,\ldots,255.\]

相邻边界间距为

\[\Delta=\frac{2}{255}.\]

np.linspace(-1, 1, 256) 返回 256 个点、255 个区间，所以档宽不是 \(2/256\)。解码中心为

\[c_k=\frac{b_k+b_{k+1}}2=-1+\frac{2k+1}{255}, \qquad k=0,\ldots,254.\]

4.1 np.digitize 的边界归属

默认 right=False。输入裁到 \([-1,1]\) 后：

\[d= \begin{cases} 1,\ldots,255, & b_{d-1}\le y<b_d,\\ 256, & y=1. \end{cases}\]

因此 \(d=1\) 覆盖整个 \([b_0,b_1)\)，并不只对应精确的 \(-1\)；\(d=256\) 才是上端点的特殊索引。

归一化输入 digitize 结果 动作 id 解码中心
\(-1\le y<b_1\) 1 31999 \(c_0\)
\(b_k\le y<b_{k+1}\) \(k+1\) \(31999-k\) \(c_k\)
\(y=1\) 256 31744 \(c_{254}\)

五、动作 id：所有维共享 256 个

设基础 tokenizer 的词表大小为 \(V=32000\)。编码为

\[t=V-d.\]

由于 \(d\in\{1,\ldots,256\}\)，合法动作 id 是 31744–31999。所有动作维度共享这 256 个 id，并不是每维各有 256 个专用 token。维度语义由固定生成位置和上下文决定。

对应的条件分布为

\[p(d_{1:D}\mid o,\ell)= \prod_{j=1}^{D}p(d_j\mid o,\ell,d_{<j}),\]

其中 \(o\) 是视觉观测，\(\ell\) 是语言指令。后面的维度可以依赖前面的维度，但这是单步动作各维的自回归分解，不是时间上的动作历史建模。

5.1 32000、32064 与 31743

OpenVLA-7B 有三个容易混淆的数字：

  • 基础 tokenizer 的 vocab_size 是 32000，动作 id 映射使用它；
  • 语言模型嵌入/输出层扩充到 32064 行，以满足 pad_to_multiple_of=64；
  • pad_token_id=32000，32001–32063 是补齐行，不属于动作 token。

action_token_begin_idx 等于 31743。训练代码在计算动作准确率与连续 L1 指标时，用 labels > action_token_begin_idx 筛出动作 token，因此它是开区间阈值；第一个合法动作 id 是 31744，31743 本身不是动作 token。它不负责构造训练损失的标签掩码：损失标签是在数据变换中按末尾 len(action)+1 个位置保留的。

六、复用词表尾部是兼容性取舍

论文选择复用 Llama 词表中最少使用的 256 个 token；实现直接假定 BPE tokenizer 的词表尾部满足这一条件。复用动作 id 本身不需要为动作再新增 256 行，因此能沿用原有词嵌入与输出行；不过 OpenVLA-7B 实际仍为新增 PAD 并满足 pad_to_multiple_of=64，把语言模型矩阵从 32000 行扩到 32064 行。

但不能据此断言“扩词表一定更差”。扩词表会新增需要初始化和训练的参数行，并改变检查点及工具链的张量形状；它不会让已有预训练行丢失。反过来，复用方案也依赖“尾部 token 在自然语言中足够少见”的假设，替换 tokenizer 时必须重新核验。

七、为什么 256 个标签只有 255 个输出

解码先计算

\[d=V-t,\qquad k=\operatorname{clip}(d-1,0,254),\qquad \hat y=c_k.\]

\(d=255\) 与 \(d=256\) 都被映射到 \(k=254\)。因此 id 31745 和 31744 解码为同一个最高中心 \(1-1/255\)。

准确表述是：

  • 训练标签空间最多有 256 个动作 id；
  • 连续解码空间只有 255 个不同中心；
  • 最高两个标签发生多对一别名；
  • 两标签的交叉熵仍不同，但执行器接收的连续值相同。

解码裁剪不是唯一信息损失；分位数裁剪和区间量化本身也都是多对一映射。

7.1 端点输出范围

对需要反归一化的维度，

\[\hat a_{\min}=L+\frac{R}{510},\qquad \hat a_{\max}=H-\frac{R}{510}.\]

这表示单步命令相对统计端点内缩了 \(R/510\)，不能直接推出“机器人永远到不了关节限位或工作空间边界”。官方 OXE 接口中运动维通常是增量量，而夹爪末维是绝对量；闭环累积、控制器缩放和物理限位都会改变系统级可达性。

八、误差要拆成三类

8.1 区间内量化误差

未触发分位数裁剪时，

\[a=L+\frac{R+\varepsilon}{2}(y+1),\qquad \hat a=L+\frac{R}{2}(c+1).\]

所以二者不是严格互逆：

\[\hat a-a= \frac{R}{2}(c-y)-\frac{\varepsilon}{2}(y+1).\]

中心到区间内任一点的最大归一化距离不超过 \(1/255\)，故

\[|\hat a-a|\le\frac{R}{510}+\varepsilon.\]

工程上常忽略 \(10^{-8}\)，写成约 \(R/510\)。这个精度随数据集和动作维的 \(R\) 变化，不是固定物理精度。

若额外假设区间内均匀分布且忽略 \(\varepsilon\)，理想化均方误差为

\[\operatorname{MSE}\approx\frac{\delta_a^2}{12}, \qquad \delta_a=\frac{R}{255}.\]

真实动作分布通常不均匀，因此它只是基线，不是实测结论。

8.2 触发端点裁剪后的误差

当归一化结果被裁到 \(y=-1\) 时，也就是 \(a\le L\)，

\[|\hat a-a|=L-a+\frac{R}{510}.\]

当归一化结果被裁到 \(y=1\) 时，按源码中含 \(\varepsilon\) 的分母，精确条件是 \(a\ge H+\varepsilon\)，此时

\[|\hat a-a|=a-H+\frac{R}{510}.\]

工程上因 \(\varepsilon=10^{-8}\) 很小，常把高端条件近似写成 \(a>H\)，但严格推导不应省略这一区别。仅凭 \(q_{01}\) 和 \(q_{99}\) 无法给出全局上界；若知道物理范围或数据极值，则可得到有限上界。把它笼统称作“无界误差”会忽略真实控制系统通常存在的限幅。

8.3 最高标签别名

\(d=255\) 与 \(d=256\) 的执行结果相同。它不会让连续输出超过上述 255 中心的量化半径，却会形成标签冗余。分析模型置信度或混淆矩阵时，应先按执行等价类合并这一对标签。

九、夹爪维不是专用二值编码

若某数据集对夹爪维设置 mask=false：

  1. 原值跳过分位数归一化；
  2. 仍被裁到 \([-1,1]\) 并分箱；
  3. 解码后跳过反归一化，直接返回中心值。

输入 0 会解码为 0；输入 1 会解码为 \(1-1/255\approx0.996078\)。对于二态夹爪，中间 token 通常没有目标标签，但不能说模型“为夹爪单独浪费 255 个参数”，因为所有维共享同一组 token 行。

也不要预设开/关的符号。不同数据转换可能使用 \(\{-1,1\}\)、\(\{0,1\}\) 或连续开度，应以目标数据集转换与统计配置为准。

十、论文与实现的边界

层次 可确定事实 不应过度解读为
论文 每维 256 个 bin；第 1/99 百分位之间均匀划分；复用低频词表 token 论文规定了 NumPy 边界和全部部署细节
ActionTokenizer 256 个边界、digitize 返回 1–256、id 为 \(V-d\) 有 256 个不同连续中心
数据管线 BOUNDS_Q99、逐数据集统计量、mask、动作字符串回填 所有维都经过同一物理尺度归一化
HF predict_action max_new_tokens 设为 \(D\)、截取末尾 \(D\) 个 id、索引裁到 0–254、按 unnorm_key 反归一化 一定生成了恰好 \(D\) 个新动作 token，或非法 id 会主动报错
部署脚本 示例设置 do_sample=False 贪心是全序列 MAP 或保证时间一致性

论文的概念描述与发布实现的边界语义并不完全一致：论文写每维 256 个 bin，发布源码却用 256 个边界形成 255 个中心，并把两个最高端标签解码到同一中心。现有材料不足以断定这是术语计数口径还是有意设计的端点特例；复现现有检查点时，应以源码的“256 个可编码 id、255 个解码中心”为准。

十一、生成策略与安全边界

官方部署示例设置 do_sample=False，通常表现为每个位置选当前条件下分数最高的 token。它确定、易复现，但不表达多峰动作中的多种合理选择。

\[\text{逐位置贪心} \neq \arg\max_{d_{1:D}}p(d_{1:D}\mid o,\ell).\]

逐位置选择一般不保证得到联合概率最大的完整动作序列，也不自动保证跨时间步平滑。

当前 HF 解码会裁剪中心下标，却不先断言生成 id 合法：

  • \(t\ge32000\) 会被压到最低中心；
  • \(t\le31743\) 会被压到最高中心。

所以非动作 token 可能静默变成极端动作。生产推理应先验证

\[31744\le t_j\le31999\quad\forall j,\]

并同时验证实际新增 token 数恰好为 \(D\)，再对非法 id 或提前停止拒绝执行、重试或安全停机。此处是根据源码行为给出的安全建议，不是官方实现已提供的保证。

十二、实现与复现检查清单

检查项 应满足 失败后果
统计量 unnorm_key 与当前机器人/数据转换一致 尺度、符号或坐标系错误
维度顺序 训练、推理、控制器一致 平移、旋转、夹爪错位
tokenizer 往返 encode(decode(ids)) == ids id 或标签数量改变
id 范围 每个生成 id 在 31744–31999 非动作 token 静默映射为极值
生成长度 实际新增 token 数恰好等于 action_dim，不能只检查 max_new_tokens 提前 EOS 时可能把提示词尾部误当动作
分箱口径 256 边界、255 中心、档宽 \(2/255\) 索引偏移或误差上界错误
mask 来自目标数据集元数据 夹爪等维被错误缩放
未使用维 min == max 时按训练逻辑置零 无效维产生随机命令
版本 固定源码提交和模型修订版 主分支变化使文档失真

最小测试应覆盖 \(y=-1,0,1\)、各边界左右邻域、全部 256 个合法 id、若干非法 id，以及每套 norm_stats 的往返误差。随机测试很容易漏掉端点别名和边界归属。

十三、常见误解速查

常见说法 正确结论
256 个 bin 就有 256 个连续输出 当前实现只有 255 个不同解码中心
档宽是 \(2/256\) 256 个边界形成 255 个区间，档宽 \(2/255\)
\(d=1\) 只在 \(y=-1\) 出现 它覆盖完整首区间 \([b_0,b_1)\)
两端各严格占 1% 样本 只能在特定连续分布假设下近似理解
编码与解码严格互逆 编码含 \(\varepsilon\) 和裁剪，解码不用 \(\varepsilon\)
解码裁剪是唯一信息损失 还有分位数裁剪、量化和最高标签别名
每维有自己的 256 个 token 所有维共享一组 id，位置区分语义
夹爪维不参与分箱 mask=false 只跳过归一化与反归一化
扩词表会破坏已有预训练行 它保留已有行，但新增行并改变模型形状
贪心得到全动作序列最大概率解 它只是逐位置局部选择
max_new_tokens=D 保证得到 \(D\) 个动作 token 它只给上限；应校验新增长度、每个 id 的范围及停止原因
非法 token 会被拒绝 当前实现会把非法 id 静默裁到极端中心，应额外校验
