这条主线为什么要单列

本板块原来的三条主线里，模仿学习与 VLA 那一支的页面几乎全部建立在 Transformer 之上：

  • ACT 用的是标准的 Transformer encoder-decoder，动作块由 decoder 的一组 query token 一次性输出。
  • VLA 总览 里从 RT-1 到 RT-2 再到 OpenVLA 的整条脉络，都建立在「把视觉与语言编码成 token 序列，再用自注意力融合」这个前提上。
  • π0 的核心工程设计是一个分块注意力掩码，让 prefix 与 suffix 之间只有单向信息流动，从而复用 KV cache。这个设计要讲清楚，必须先讲清楚掩码在注意力里究竟改的是哪一步。
  • π0.5、π0.6、OpenVLA、X-VLA、SmolVLA 各自的差异，也大量落在注意力的用法上：谁做 cross-attention、哪些 token 共享权重、序列长度上限是多少。

问题在于：这些页面每一篇都要用到 QKV、多头、掩码、位置编码，如果每一篇各讲一遍，会出现两个后果。一是重复，同样的公式在七个页面里写七遍；二是深度不够，模型页的主线是模型本身，不可能停下来做半页的方差分析，于是每次都只能讲到「是什么」，讲不到「为什么」。

把共同底座抽出来单独讲一次，模型页就可以直接链过来，把版面留给模型自己的设计。这是本主线存在的全部理由。

为什么不并进论文索引页

论文索引页只做一件事：按主题给出论文的元信息与链接，方便回查出处。它不承载推导，也不解释机制。而本主线要讲的恰恰是推导——缩放因子的方差分析、多头为什么不增加计算量、注意力矩阵为什么是显存瓶颈，这些都需要成段的展开，放进索引页会把那一页的定位破坏掉。

两者的分工是：论文索引页回答「这个结论出自哪篇」，本主线回答「这个结论是怎么来的」。

本主线不讲什么

为了不和其他主线重叠，下面这些内容明确不在本主线范围内：

  • 具体模型的超参数与源码细节，归各模型页。
  • 训练工程（分布式、混合精度、显存优化的具体命令），归 Docker 工程环境。
  • 强化学习的价值函数与策略梯度，归强化学习总览；那一支里 Transformer 用得少，主要是 MLP。

从 RNN 到 Attention 再到 Transformer

理解注意力最省力的路径，不是从公式进去，而是从它被发明出来要修什么进去。可以沿三个维度看这条脉络。

起点：seq2seq 的上下文向量瓶颈

注意力最早不是作为 RNN 的替代品提出的，而是作为它的补丁。早期的编码器-解码器（seq2seq）翻译模型把整个源句压成一个固定长度的向量，再由解码器展开成目标句。句子越长，这个向量要承载的信息越多，而它的容量是固定的，于是长句翻译质量随长度明显下降。

注意力的原始动机就是取消这个瓶颈：解码每一个目标词时，不再只看那一个压缩向量，而是回头对源句的全部隐状态做一次加权求和，权重由当前解码状态与各源位置的相关性决定。信息不再被迫压缩，需要什么就取什么。

后来的关键一步是发现：既然这个「按相关性取值」的操作这么有用，为什么还要保留外面那层 RNN。去掉 RNN、只保留注意力，就是 Transformer。

维度一：长程依赖

循环网络（RNN）把序列信息压进一个不断更新的隐状态里。序列中第 1 个位置的信息要影响第 n 个位置，必须经过 n 次矩阵乘法与非线性变换。反向传播时梯度也要沿同一条链传回去，于是出现梯度消失或爆炸。LSTM 与 GRU 用门控机制把这条链修得更通畅，但没有改变路径长度随距离线性增长这个事实。

注意力的做法是：任意两个位置之间直接建立一条边。第 1 个位置和第 n 个位置的交互路径长度恒为 1，与 n 无关。梯度也就不必再沿长链传播。

维度二：并行化

RNN 的第 t 步计算依赖第 t-1 步的隐状态，这是结构性的顺序约束，无法通过增加算力消除。训练一条长度为 n 的序列，至少要串行 n 步。

自注意力（self-attention）对每个位置的计算只依赖整个输入序列，彼此之间没有先后关系，可以写成一次矩阵乘法，在 GPU 上完全并行。这是 Transformer 能把模型规模推上去的直接前提——不能并行的架构，堆再多卡也没用。

维度三：归纳偏置

这一维度最容易被忽略，但对理解 VLA 为什么需要大规模预训练很关键。

架构 内置的归纳偏置 代价
RNN / LSTM 递归结构，天然假设「时间上邻近」 长程依赖弱，无法并行
CNN 局部性 + 平移等变 + 权重共享 感受野随层数线性扩大，远距离交互需要堆深度
Self-Attention 几乎没有 需要更多数据；必须额外注入位置信息

自注意力对输入的唯一假设是「这是一个集合」。它对置换是等变的：把输入序列打乱，输出也只是跟着打乱，模型察觉不到顺序变了。好处是不预设任何结构，模型可以从数据里自己学关系；代价是两条：

  1. 偏置少意味着样本效率低，所以 ViT 在中小数据集上打不过 CNN，要靠大规模预训练才翻盘。
  2. 顺序信息必须显式补回来，这就是位置编码存在的原因。

理解了第 2 点，就能理解为什么位置编码不是可有可无的小配件，而是自注意力架构的必要补丁。

论文里的复杂度对照

原论文 Table 1 给出了三种层的对照（n 是序列长度，d 是表示维度，k 是卷积核宽度）：

层类型 每层复杂度 最少顺序操作数 最大路径长度
Self-Attention O(n² · d) O(1) O(1)
Recurrent O(n · d²) O(n) O(n)
Convolutional O(k · n · d²) O(1) O(log_k n)

这张表把权衡说得很清楚：自注意力用序列长度上的平方复杂度换来了常数级的路径长度与顺序操作数。当 n 小于 d 时（自然语言的常见情形），自注意力反而比 RNN 更便宜；当 n 很大时（长文档、高分辨率图像、长动作序列），平方项就成了瓶颈。这个权衡是后续一大批工作的出发点。

继承链：从点积注意力到 VLA

下面这张图是本主线的骨架。左边是机制，中间是结构，右边是本站其他页面讲的模型。

flowchart TB
  A["Scaled Dot-Product Attention<br/>QKV 加权求和 + 缩放"] --> B["Multi-Head Attention<br/>h 个低维子空间并行"]
  PE["Positional Encoding<br/>补回顺序信息"] --> C
  B --> C["Transformer Block<br/>MHA + FFN + 残差 + LayerNorm"]
  C --> D["Transformer Encoder-Decoder<br/>自注意力 + 交叉注意力 + 因果掩码"]
  D --> E["ViT<br/>图像切 patch 当 token"]
  D --> F["LLM<br/>纯 decoder + 因果掩码"]
  E --> G["VLM<br/>视觉 token 与语言 token 拼一条序列"]
  F --> G
  G --> H["VLA<br/>再接动作 token / 动作专家"]
  C --> I["ACT<br/>encoder-decoder + 动作块 query"]

这条链上每一级都只做一件事：

  • Scaled Dot-Product Attention：定义「按相关性加权求和」这个基本运算。
  • Multi-Head：让同一层能同时表达多种关系，而不是只有一种对齐模式。
  • Transformer Block：把注意力和逐位置前馈网络（FFN）用残差连接与层归一化串成一个可以无限堆叠的单元。
  • ViT / LLM：把同一个块分别用在图像 patch 序列和文本 token 序列上，证明这套结构与模态无关。
  • VLM / VLA：既然与模态无关，就把视觉 token 和语言 token 拼进同一条序列；再拼上动作 token，就成了 VLA。
值得留意的是：从 Transformer Block 到 VLA，核心算子一次都没变过。变的只是 token 从哪来、掩码怎么画、输出头接什么。这也是把底座抽出来单独讲一次的价值——把这一层吃透，后面每个模型只需要关心它自己改了哪一处。

本主线是被引用方，下面按「谁用了什么」列出对应关系。

模仿学习与 VLA 一支

  • ACT：标准 Transformer encoder-decoder。decoder 侧用一组固定数量的 query token 通过 cross-attention 读取 encoder 输出，一次性产出整个动作块。要理解「为什么 query 的数量就等于动作块长度」，需要先理解 cross-attention 里 Q 与 K/V 的来源不同这件事。
  • VLA 总览：RT-2 与 OpenVLA 这条路线把动作离散成 token，接在语言模型的词表里，靠的是 decoder 的因果掩码逐个自回归生成。掩码的具体实现写在注意力页。
  • π0：分块注意力掩码是这一页工程价值最高的设计——prefix（图像与语言 token）内部双向可见，suffix（状态与含噪动作 token）能看到 prefix，但 prefix 看不到 suffix。这样 prefix 的 KV cache 在 10 步欧拉积分中只需计算一次。注意力页专门用一节把这个掩码和标准的三种注意力放在一起对照。
  • π0.5 / π0.6 / OpenVLA / X-VLA / SmolVLA：差异大量体现在序列长度上限、共享哪几组权重、以及在哪一层做视觉与语言的融合。这些都是同一套算子的不同接法。

强化学习一支

强化学习总览下的 DDPG、TD3、SAC、PPO 四页，网络主体是 MLP，对本主线的依赖较弱。交叉点主要在两处：一是把 Transformer 当作序列建模的策略骨干（Decision Transformer 那条路线）；二是 π0.6 的 RECAP 流程把价值函数接在 VLA 主干上，那里的价值头读的正是注意力层的输出。

Docker 工程环境一支

Docker一支与本主线的关系是间接的：注意力的显存瓶颈在注意力矩阵而不是参数量，这一点直接决定了容器要挂多大显存、batch 与序列长度怎么配。注意力页的复杂度一节会给出这个结论的推导。

建议的阅读顺序

目标 顺序
只想补齐读 π0 的前置知识 注意力机制 → 位置编码 → VLA 总览 → π0
想搞懂 ACT 的动作块设计 注意力机制（重点看 cross-attention 一节）→ ACT
想自己实现一个 Transformer 注意力机制全文 → 位置编码全文 → 原论文 Section 3
只想弄清楚显存为什么爆 注意力机制的「计算与显存复杂度」一节

如果时间只够读一节，读注意力页的缩放点积那一节。除以维度平方根这一步看起来只是个数值技巧，实际上是理解「为什么 softmax 会饱和、为什么梯度会消失」的入口，后面多头的维度切分、pre-norm 与 post-norm 的取舍，都能顺着这条线索理解。
