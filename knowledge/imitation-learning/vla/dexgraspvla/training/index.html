⑤ TRAINING · 2094 DEMOS · 8 × 48 LOCAL BATCH

Training 从 Diffusion 的归一化动作与 epsilon 配方开始，负责把两阶段示教整理为 Zarr、64 步窗口、本地 batch、优化更新和可移交 checkpoint。关键边界是 75→75 个窗口、42% 尾部重复、3272/409 双步数，以及论文 84 轮与 YAML 125 轮的官方分歧。

证据分层。 论文负责 2094 条演示、84 轮、8 卡、BF16 与 FusedAdamW；固定仓库负责 51 条样例、125 轮配置、循环与保存；Accelerate/diffusers 固定版本负责分片和 scheduler 包装；本站只做静态算术。冲突必须并列，不能用一个来源覆盖另一个。

一、职责、证据与 Diffusion 入站

固定证据为 DexGraspVLA arXiv:2502.20900v5、官方 commit 0144c7928817c5149ae836da2682291360828a21、Accelerate 1.2.1 和 diffusers 0.32.1。Training 独占 dataset、sampler、normalizer、distributed loop、optimizer 与 checkpoint；Architecture 的网络层、Diffusion 的数学目标、Inference 的执行线程、Experiments 的结果表和 Source Code 的逐文件调用图不在本页重讲。

入站是 limits 归一化的 B×64×13 动作、范围 [-1,1]、每样本一个 0–49 整数 timestep、50 档噪声网格、epsilon target 和全元素 mean MSE。Immiscible 只在本地 batch 内做一一噪声排列；50 不是每批 50 次前向。receipt 固定配方，不证明数据统计或 scheduler 制品已匹配。

这张 receipt 解决的是“上游交来什么”，不是把 Diffusion 页搬到 Training 页。训练循环消费已经归一化的干净动作、分配后的噪声和 epsilon 目标；本页只追踪这些张量如何随 dataset、batch、optimizer 与 checkpoint 流动。Architecture 的 encoder trainability 仍由其页面解释，Inference 的 replanning、动作执行和 runtime threads 仍由后继页解释；Experiments 拥有成功率、消融和泛化表，Source Code 拥有逐文件调用图与硬件接口缺口。由此，任何数值都可回到论文、固定源码、依赖源码或本站静态复算四类证据之一。

验收时还要区分“配方存在”与“制品相容”：即使 shape 都是 B×64×13，若 action normalizer、diffusers 配置或本地 batch 语义不同，receipt 也不能通过。页面用 STATIC_SPECIFIED 表示字段已静态写明，用 NOT_RUN 表示没有运行态证据；二者不能改写成训练已成功。

二、两阶段示教与训练数据范围

第一阶段以 kinesthetic teaching 记录目标关节轨迹；第二阶段复位场景，用 PD 控制重放目标，同步记录图像、实际关节角和目标关节角。论文记录频率为 20 Hz，目标 mask 在记录后离线生成。right_state 是 13 维实际臂手关节角，action 是 13 维 PD 目标关节角。减少操作者入镜只能标为推断，不能写成作者验证的因果收益。

flowchart LR
  A[two-stage successful demonstrations] --> B[Zarr replay buffer]
  B --> C[64-step SequenceSampler]
  C --> D[action limits normalization + image processing]
  D --> E[8 local batches]
  E --> F[epsilon all-element mean MSE]
  F --> G[AdamW + cosine + gradient clip]
  G --> H[top-1 and periodic checkpoints]

文本回退： 两阶段示教进入 Zarr；SequenceSampler 生成 64 步窗口；动作按训练 limits 归一化，RGB 与 mask 分别预处理；Accelerate 把完整 batch 分发给 8 个进程；epsilon MSE 驱动 AdamW、cosine scheduler 与梯度裁剪；最终保存 top-1 和定期 checkpoint。VLM、SAM、Cutie 与机器人 runtime 均排除在反向图外。

两阶段采集必须按时间语义理解：第一阶段保存“想让机器人到达的目标轨迹”，第二阶段才在复位后的场景中由 PD 重放并形成图像—当前状态—目标动作的对齐样本。这样能解释为何 right_state 与 action 都是 13 维却不是同一个量：前者是时刻内实际测得的臂手关节角，后者是控制器收到的目标关节角。20 Hz 是记录频率，不是推理线程或机器人闭环频率；离线 mask 生成也不进入策略反向图。

三个数据口径不能混用。2094/36/75/64/84 描述论文一般抓取设置；1029/32/100/200 描述非抓取扩展；仓库中的 51 条样例只足以核对格式与流程。页面不会从样例推导论文性能，也不会把“减少操作者入镜”写成作者已经验证的因果收益。

三、Zarr ABI、窗口索引与 42% 尾部重复

Zarr 五字段为 data/action: K×13、data/right_state: K×13、data/rgbm: K×H×W×4、data/right_cam_img: K×H×W×3、meta/episode_ends: J。rgbm 是头部 BGR 加二值 mask，right_cam_img 是腕部 BGR；窗口边界来自 episode_ends，禁止跨 episode 拼接。

sequence_length=64、pad_before=0、pad_after=63。L=75 时 max_start=L-sequence_length+pad_after=74，起点 0–74，共 75 个；无 padding 时只有 75-64+1=12 个，数量比 75/12=6.25。高度重叠窗口不等于独立演示扩大 6.25 倍。

越过末尾就重复最后元素：起点 12 补 1 步，起点 74 补 63 步。动作位置共 75×64=4800，填充位置 1+…+63=2016，比例 2016/4800=42%。控制器没有 valid_mask，重复位置等权进入 MSE，会强化末态保持。

单个 75 步 episode
项目 值 解释
窗口 75 起点 0–74
无 padding 12 75−64+1
动作位置 4800 75×64
重复位置 2016 1+…+63
比例 42% 默认进入 loss

索引账本的关键不是“多切了多少窗口”，而是每个窗口内哪些位置是真实未来、哪些位置是末元素复制。起点 0–11 都能取满 64 个真实动作；从起点 12 开始，所需未来超出 episode 末尾，补齐量按 1 到 63 递增。因此 2016 是补齐位置总数，不是新增 episode 数，也不是 2016 条独立监督。因为控制器拒绝 valid_mask，这些复制动作与真实位置具有相同损失权重；改变 padding 或引入 mask 会改变训练目标，不能作为无影响的数据整理细节跳过复验。

Zarr ABI 同样是硬边界：episode_ends 决定切片终点，窗口不能越过相邻 episode；头部 rgbm 的第四通道是二值目标 mask，腕部 right_cam_img 没有该通道。只核对数组总长度而不核对 episode 边界，仍可能产生形状合法但语义错误的训练样本。

四、图像 processor、动作 normalizer 与状态

RGB 除以 255 后 bilinear resize 到 518×518；mask 用 nearest resize 并以 0.5 重新二值化。编码器随后执行 BGR→RGB、训练期颜色扰动和 ImageNet 标准化。两种插值不能互换。

LinearNormalizer 以 limits 模式拟合 raw action 与 raw right_state；训练前向只对 action 调用 normalize，映射到 [-1,1]。right_state 统计会保存，但当前状态仍以原始关节角进入线性层。normalizer 在原始数组上拟合，不把窗口尾部人工重复再次计入；主进程计算，其他进程等待后读取同一文件。

因此制品身份不只是权重。动作 min/max、观测 ABI、processor 尺寸与 scheduler 必须绑定；shape 正确但统计错配会同时改变 matching 距离、加噪尺度、裁剪和反归一化。

预处理顺序不可随意交换。原始图像数值先除以 255；RGB 用 bilinear 到 518×518，mask 用 nearest 后再按 0.5 二值化，以免插值制造软标签。后续编码器路径才执行 BGR→RGB、训练期颜色扰动与 ImageNet 标准化。mask 若误用 bilinear，即使输出仍是四通道，也已改变目标区域边界。

normalizer 的拟合对象是原始训练 split 中的 action 与 right_state 数组，不是 SequenceSampler 产生的 64 步重叠窗口。这样 42% 的人工尾部重复不会再次进入统计量。当前前向只归一化 action；right_state 的统计虽随制品保存，状态仍以原始关节角进入线性层。主进程先计算并保存统计，其他进程等待并读取同一文件，避免各 rank 分片后各自得到不同范围。

五、8 卡 batch、Accelerate 与 3272/409

总窗口 N=2094×75=157050；本地 batch 48，进程数 8。prepare 前 DataLoader 长度 ceil(157050/48)=3272；prepare 后每进程每轮 409 个本地 batch，每批仍有 48 样本；全局 batch 48×8=384，drop_last=false。

Accelerate 1.2.1 默认 split_batches=false、even_batches=true，完整 batch 是分发单位。3272 可被 8 整除，主数据无需复制 batch；换数据规模必须重算 even_batches。

scheduler 在 accelerator.prepare 前创建，底层总步数用 prepare 前长度×epochs。每轮真实更新 409 次；每次真实更新推进底层 scheduler 8 次，所以内部步 409×8=3272，轮末对齐。禁止再手工乘一次进程数。

全局 batch 384 48×8
内部步 3272 409×8

白话说，3272 是 prepare 前看到的完整 batch 数，409 是一个进程实际迭代和更新的次数，384 是一次 DDP 更新共同覆盖的样本数；它们不是同一单位。Accelerate 的 scheduler wrapper 为每次真实更新推进八个底层内部步，恰好使每轮末回到 3272。若在配置阶段又把总步数手工乘以 world size，就会发生二次缩放；若更换数据量后 prepare 前 batch 数不能被 8 整除，even_batches=true 是否复制数据也必须重新核算。

这里的 157050 来自固定完整集假设 2094×75。它不是 Zarr 总行数，也不包含 51 条样例的替代计算。drop_last=false 保留末尾不满的原始 batch，而主数据的 3272 个 batch 恰好可被 8 个进程整除，所以本口径不需要为进程对齐复制 batch。

六、warmup、AdamW、BF16 与循环

warmup_steps=2000 是内部调度步，8 卡等价 250 次真实更新。完整集 warmup 为 250/409≈0.6112469438 epoch；125 轮总内部步 3272×125=409000，warmup 占 0.0048899756。51 条样例有 51×75=3825 窗口，prepare 前每轮 80 批；125 轮内部步 10000，warmup 占 20%并持续 25 epoch，不能与完整集等同。

AdamW 使用 lr=1e-4、betas=(0.95,0.999)。仅 requires_grad 参数进入；tensor.dim≥2 的 weight decay 为 1e-4，一维为 0。三维 cond_pos_emb decay；bias 与 Norm scale no-decay；冻结 DINO 不分配 Adam 状态。只有签名支持时才传 fused=true。

mixed_precision=bf16 写死在 workspace；不支持 BF16 的硬件需改代码并重验。backward 后 clip_grad_norm_ 的 max_norm=0.5 是源码事实，论文表未列，也没有阈值消融。默认 gradient_accumulate_every=1；非默认累积可能在 micro-batch 后裁剪部分梯度，并有 global_step=0 提前更新风险。

每批顺序为 raw loss/累积因子 → backward → clip → optimizer.step → zero_grad → scheduler.step；EMA 若启用则最后 step。最后一个 batch 暂不递增 global_step，epoch 末日志后补一次，默认每轮仍增加 409。

参数分组按张量维数而非模块名称：dim≥2 进入 weight_decay=1e-4，所以三维 cond_pos_emb 也衰减；bias 与 Norm 的一维 scale 进入 no-decay。冻结 DINOv2 因 requires_grad=false 被排除，既不更新也不分配 Adam 状态。fused=true 只在当前 AdamW 签名支持时传入，页面不把论文的 FusedAdamW 陈述扩展成所有环境都能无条件启用。

BF16 是 workspace 写死的执行选择，不是可由 YAML 自动降级的建议；不支持它的硬件需要改代码并重新验证。max_norm=0.5 只说明源码在 backward 后裁剪，公开材料没有阈值消融。默认累积为 1 时顺序明确；改为非默认值会让部分累积梯度在 micro-batch 后被裁剪，并触发 global_step=0 提前更新风险，所以不能只改一个配置数字便沿用原账本。

七、EMA、runner、validation 与 sample 边界

YAML 定义 EMA 参数但 use_ema=false，默认不创建、更新或切换 EMA。每 10 轮的 RealGraspImageRunner.run 只返回空字典，不连接机器人也不产生成功率。val_ratio=0 使验证 sampler 长度为 0，默认 validation loss 不运行，作者原因未知。

sample_every=10 只在主进程使用该 epoch 最后一个训练 batch，从随机噪声做 16 步 DDIM，输出 train_action_mse_error；它不是验证指标或机器人成功率。注意力导出只保留 batch 前两个样本和第一个动作 token 对全部条件 token 的权重，不能严格复现论文 Figure 4 的全动作 token 聚合。

EMA 关闭不证明 EMA 有害，val_ratio=0 不证明验证无用，空 runner 不是硬件失败。页面只记录默认分支，不虚构运行结果。

这些分支的共同边界是“代码路径存在”不等于“产生了评测证据”。env_runner.run 虽按每 10 轮触发，但公开实现返回空字典；validation loader 因 sampler 长度为 0 不进入循环；训练集采样只对最后一个 batch 做重建误差。三者都不能补出真实成功率，也不能解释作者为何选择 val_ratio=0。

注意力导出还有两个显式截断：只取 batch 前两个样本，并且只保留第一个动作 token 对全部条件 token 的权重。因此默认导出链与论文 Figure 4 的全动作 token 聚合不是同一个统计对象；若要复现图示，必须另行定义聚合、样本范围和可视化流程，而不是把已有文件直接命名为 Figure 4 复现。

八、checkpoint 与 84/125 轮冲突

top-k 监控 train_loss、mode=min、k=1；判据是主进程本地 shard 的 batch 平均，不是八卡 gather，也不是最佳真机策略。save_last_ckpt=false、save_last_snapshot=false。epoch 40、60、80、100、120 另存定期点；84 轮保存前三个，125 轮保存五个，末轮不额外保存 latest。

论文正文与 Table 2 写 84 epochs，公开 YAML 写 125，材料未解释差异或发布 checkpoint 来源。

口径 内部步 真实更新 边界

top-1 也有严格的 metric scope：train_loss 来自主进程本地 shard 的 batch 平均，没有八卡 gather。它能驱动 mode=min, k=1 的文件保留，却不能代表全局验证最优或真机成功率最优。定期 checkpoint 独立于 top-1 删除逻辑；epoch 索引 40、60、80、100、120 分别保存，84 轮口径只能覆盖前三个，125 轮口径覆盖五个。因为两个 save_last 都为 false，最后一轮不会额外出现 latest 制品。

轮数差异还会改变 cosine 曲线，而不只是多训练 41 轮。84 轮原生配置把 274848 个内部步铺满整个衰减区间；125 轮配置总计 409000 内部步，其第 84 轮对应 warmup 后进度约 0.6703882064、cosine 因子约 0.245。公开材料没有说明发布 checkpoint 属于哪一种，因此 epoch provenance 必须随制品保存。

九、超参数来源与 warm start

论文与实现一致：lr 1e-4、cosine、warmup 2000、weight decay 1e-4；betas [0.95,0.999]、batch/GPU 48、horizon 64；DiT 12 层 8 头、attention dropout 0.1、BF16。epochs 84/125 是冲突。clip 0.5、accumulation 1、EMA false、val_ratio 0、observation_steps 1、attention_mask false 是代码项，论文表未列。

policy.start_ckpt_path 只加载模型权重；默认 training.resume=false，保存排除 optimizer。加载后 global_step 与 epoch 重置为 0，normalizer 按当前数据重设，optimizer 与 scheduler 重建。因此默认是 warm start/微调，不是严格续训；严格续训需恢复 optimizer、scheduler、计数器和 normalizer 身份。

超参数必须按来源登记。lr=1e-4、cosine、warmup 2000、weight decay 1e-4、betas [0.95,0.999]、每 GPU batch 48、horizon 64、DiT 12 层 8 头、attention dropout 0.1 和 BF16 在论文与实现间一致；84/125 是明确冲突。clip 0.5、accumulation 1、EMA false、val_ratio 0、observation_steps 1 与 attention_mask false 只属于代码项，不能反向标成论文设置。

严格续训比权重热启动多出状态连续性：optimizer 的动量、scheduler 所处步、epoch/global_step 计数和原 normalizer 都要恢复并核验。默认入口缺少这些保证，因此页面统一使用 warm start。若新数据重算了 normalizer，即使加载同一 model state，也已形成不同的输入输出标度，必须作为新训练谱系记录。

51 条样例不得冒充论文性能复现；0.5 裁剪不得附会为已验证治疗机制；top-1 不得写成最佳机器人策略。本页运行状态为 NOT_RUN。

十、最小制品 bundle

最小 bundle 必须含 model state、action normalizer 逐维 min/max、rgbm/right_cam_img ABI、518×518 图像/mask processor、action_dim=13、horizon=64、50 档 epsilon/16 步 DDIM、仓库 commit 与依赖版本。仅权重不足；还要记录 top-1 或明确 epoch 身份和 metric scope。

交接前应验证 normalizer 来自相同训练 split，processor 保持 RGB bilinear 与 mask nearest/threshold，checkpoint 身份明确，scheduler/prediction type 一致，观测 ABI 和动作维序相同。任一身份缺失就 fail closed。

bundle 的目的不是扩大文件清单，而是让 Inference 能回答每个数值的来源。model state 要与 top-1 或具体 epoch 绑定；13 维 action 的逐维 min/max 要能被同一反归一化路径读取；rgbm 与 right_cam_img 的通道、颜色顺序和尺寸要固定；50 档训练 scheduler、epsilon prediction 和 16 步 DDIM 要成套记录。仓库 commit、Accelerate 和 diffusers 版本用于锁定解释这些字段的实现语义。

静态验收只确认合同字段齐全、算术一致和补丁可重放，不读取 checkpoint，也不加载 normalizer 文件。故 artifact bundle 在本页是交付规范，不是声称真实制品已经生成；任何缺失都必须阻断下游可复现性声明。

G0 选择 84 或 125 轮；G1 标识完整集或 51 条样例；G2 重算窗口/padding/valid mask；G3 重算 batch 与 scheduler；G4 保持 accumulation=1 或重验；G5 记录 checkpoint/metric scope；G6 绑定 normalizer/processor；G7 验证制品后交给 Inference；G8 另行获取运行授权。全部故障 fail closed，taxonomy 不表示已经发生。

故障传播按依赖关系处理：数据范围、episode crossing 或 padding 漂移先阻断 loss 解释；normalizer/processor 错配阻断张量语义和下游反归一化；batch、scheduler、warmup 或 accumulation 错配阻断步数与学习率曲线；local metric、warm start、epoch provenance 和空 runner 被误读时阻断 checkpoint 质量声明；注意力聚合或 BF16 环境不匹配则阻断对应导出或执行声明。故障名是一组预先定义的验收结果，不表示仓库已经出现这些事故。

G0–G8 是从证据选择到运行授权的顺序门：先选轮数与数据集，再复算窗口、batch 和 scheduler，随后固定累积、metric scope 与预处理制品，最后才允许交给 Inference。G8 明确把真实运行留在另行授权范围内，因此通过 G0–G7 也只代表静态交接就绪。
