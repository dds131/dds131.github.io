π0.7 总览/网络架构与输入输出

LOW-LEVEL VLA · INPUT/OUTPUT · ATTENTION · GRADIENT

低层 π0.7 是约 5B 参数的 VLA：它把 MEM 历史、当前观测和多模态 context 编成激活，再由独立的 860M Action Expert 生成 50 步连续速度场。

高层语言策略与 BAGEL 衍生世界模型是外部 context 生产者，不属于这约 5B，也不应被画成同一实例、缓存或服务。本页中的 π0.7 读作 pi zero point seven。

一、模型边界与全链

论文把低层策略描述为约 5B 参数 VLA：Gemma 3 4B 初始化的 VLM 主干（其中视觉编码器约 400M）加 860M Flow Matching Action Expert。4B + 860M ≈ 5B 只是作者尺度口径，不能当作精确、互不重叠的参数账。π0.7 的直接前身是 π0.6-MEM；Gemma 3、FAST、Flow Matching、Knowledge Insulation（KI）和 MEM 都有继承关系，不能写成 π0.7 首创。PAPER_ARCHITECTUREINHERITED_PI06INHERITED_MEM

“低层模型”是本页最重要的边界。独立高层策略负责在较长时间尺度上产生语言子任务，BAGEL 衍生世界模型负责生成多视角视觉子目标；它们可以改变低层收到的 context，却没有被论文并入同一 5B 参数实体。页面因此既不汇总三者参数，也不假定三者共享权重、KV cache、进程、设备或服务生命周期。没有外部视觉目标时，低层仍可在训练所支持的条件子集上工作；这也不等于任意缺失组合均已得到同等验证。

条件策略可辨识地写作 (\mathbf A_t\sim\pi_\theta(\mathbf A\mid\mathbf o_{t-T:t},\ell_t,\hat\ell_t,\mathbf g_t,m_t,c_t))，但这不补造正式字段、序列化顺序或部署协议。基础先修是 π0.6 架构 与 π0 Flow Matching。

式中的 (\mathbf o_{t-T:t}) 代表图像和本体状态历史，(\ell_t) 是总体任务，(\hat\ell_t) 是当前子任务，(\mathbf g_t) 是可选视觉目标，(m_t) 与 (c_t) 分别概括 episode metadata 和控制模式。它只说明“动作块以这些信息为条件”，不声明变量总是同时存在，也不把概率模型记号等价为已经公开的调用签名。

三个输入组承担不同职责。观察与历史给出“当前处境”；任务、子任务、目标图、metadata 和 control mode 给出“希望哪一种行为”；带噪动作与 flow time 给出“当前去噪状态”。输出 velocity field 与带噪动作同形状，仍需积分、动作解码、坐标转换、限幅和控制器才能进入真实执行链。由于论文没有给出完整 (D_q)、(D_a)、关节/末端字段、夹爪语义、单位及归一化，本站的 policy_io_contract_id 保持 null。

三、VLM、MEM 视觉编码与连续状态

MEM 对历史图像同时做时间与空间压缩，使一段历史输出固定数量、且与单帧相同数量的视觉 token。它避免 token 数随帧数线性增长，但不表示无损、零计算或零显存，也不能从“至多 4 路 × 6 帧”推出所谓固定 24 倍消除。视觉目标经过同一个 encoder；这不自动证明所有 embedding、缓存和预处理都完全共享。INHERITED_MEM

π0.7 按 MEM 设计把当前与历史 proprio state 线性投影到主干维度，每个历史时刻一个独立 token；若历史图像被 dropout，对应 state token 也必须 mask，避免视觉与状态错时配对。本站用 StateHistory[D_q] 表示这一接口，但 (D_q)、字段顺序、单位、归一化与投影完整 shape 均未报告。线性投影是结构事实，不是“已被消融证明优于离散状态”的结论。

这里的对齐是语义约束，不是已公开的数据结构：第 (k) 个历史视觉时刻和第 (k) 个状态 token 应描述同一采样位置；丢弃一个历史视觉时刻时，相应状态不能继续泄露该时刻信息。论文确认的是这种遮蔽关系，但没有公开每个平台如何对时间戳、掉帧、插值或不同频率传感器做工程对齐。那些问题应由数据管线和部署合同回答，不能从网络图中反推。

四、状态、context 与 token 块

阅读序列时应先区分三类信息：observation/history 描述机器人已经看见和经历的内容；Prompt/context 描述总体任务、当前子任务、视觉目标、episode metadata 与控制模式；Flow 块则承载带噪动作和 flow time。把它们统称为“更多 token”会抹掉训练缺失、可见性和梯度边界。

训练态还可出现 FAST token 与 RTC conditioning；推理态不提供 FAST token，而是从带噪动作迭代得到连续速度场。FAST token 属于离散监督，50 个 Flow action token 是动作位置的隐藏表示，两者不是同一词表。Prompt 的字段含义、缺失组合与 CFG 进入下一页；历史对齐进入 Memory 页。

块的“位置”与“可见性”也要分开理解：一个块在论文图中的相邻摆放不自动决定全部 attention edge，块内双向也不意味着它能读取其他任意块。本站因此把每个 query 块能读取什么单独登记，并把未明确的排列保持为张力，而不是从图示布局推导唯一序列。

五、Block-causal 可见性

论文 Section VI-B 的文字表述与 Appendix A-B 对 goal block “位于 text prompt 之后”的说明存在书写顺序张力。因此本站登记为 ORDERING_TENSION，不宣布唯一的 [obs→goal→text] 或 [obs→text→goal]，也不反向创造官方 mask tensor 代码。注意力隔离只说明信息可达性，不等于梯度隔离或统计独立。PAPER_ATTENTIONORDERING_TENSION

CFG attention tree 是推理时同时组织正、负条件分支的特殊结构：两条分支可共享此前允许的前缀，但互相不能读取对方的条件后缀。它说明论文如何避免分支串扰，不足以推出一个可复用于任意 batch packing 的通用技巧。CFG 的具体条件选择、公式和指导强度由 Prompt 与 Inference 页承担，本页只保留 reachability 边界。

六、Action Expert 与梯度路由

Action Expert 是 860M 参数 Transformer，不是第二个完整 VLM。它通过 adaptive RMSNorm 注入 Flow time，并以 (v_\theta(A_\tau,\tau,C)) 表示在 context (C) 下对连续 velocity field 的预测。本页只保留机制接口；插值方向、时间采样、积分器、Loss 权重和训练阶段属于 Training。PAPER_TRAINING

“FAST 与 Flow 不互相注意”是 attention boundary；“Flow loss 不回流 VLM”是 gradient boundary。二者解决的问题不同，不能合并成一句“两个头完全独立”。

同理，Flow loss ↛ VLM 不能翻译成“VLM 冻结”。VLM 仍通过训练期 FAST 交叉熵以及论文允许的其他 VLM 目标获得更新；Action Expert 则读取 VLM 的前向激活并接受连续 Flow 目标。页面不推断两个目标的数值权重、同 batch 更新顺序、optimizer 分组或阶段性冻结，因为这些实现细节没有由正式 π0.7 配置公开。

七、训练态、推理态与跨页合同

训练态观察历史、context、FAST tokens、带噪动作、Flow time，并可接收 training-time RTC 条件；FAST CE 与 Flow loss 遵循不同梯度路由。
推理态没有 FAST tokens；Action Expert 对带噪动作迭代去噪，可选接收 subgoal、CFG 与 RTC context。
运行时边界低层消费 latest available context，但不承诺同步、新鲜度、deadline、安全回退或外部生产者缺失策略。

training-time RTC 在论文中模拟 0–12 个 timestep 延迟；只在 50Hz 口径下可换算为最大 240ms。它在本页只是 RTC conditioning receipt，不是 Transformer 层或新增参数块。prefix、队列、执行 15/25 步、异步重规划和延迟语义归 Inference 与 RTC Foundations。Prompt 缺失策略归下一页，历史机制归 Memory。

运行实验总是提供 metadata 与 control mode，但训练 dropout 会让模型见到部分 context 子集。这个事实只支持“结构可接收可选条件”，不支持“任意子集在任意机器人上等价可靠”。异步高层或世界模型可在不同周期更新条件，低层只消费 latest available 值；条件是否过期、生产者失败时如何降级、deadline 是否满足以及安全状态如何恢复，均属于运行时和控制系统责任。
