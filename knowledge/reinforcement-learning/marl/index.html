本章要解决什么问题

现实任务里很少只有一个决策者

单智能体的建模方式对很多任务是够用的：一台机械臂抓取桌面上的物体，环境里除了它没有别的决策者，物体的运动完全由物理规律决定。但下面这些任务无法这样建模：

  • 多机器人协作搬运。两台机械臂共同抬起一根长杆，任一台的动作都会通过刚体约束立刻改变另一台感受到的力与位姿。
  • 仓储机器人调度。几十台移动机器人在同一片场地内避让、抢占通道，一台改变路径规划，其余所有机器人的可行路径随之改变。
  • 对抗任务。追捕与逃跑、博弈类游戏，一方策略改变会改变另一方所面对的对手分布；在零和任务中，一方收益增加对应另一方收益减少。
  • 交通信号联合控制。每个路口是一个智能体，上游放行策略直接决定下游的到达流量。

这些任务的共同点是：联合结果由多个决策者的动作共同决定。它们可以在特定条件下建模成联合控制器，但会改变信息、目标与部署约束；下文会说明何时这种集中化可行。

三类设定

按奖励关系可做以下粗分；零和只是竞争问题的一个重要特例，不应把所有竞争任务都等同于零和。

设定 奖励关系 典型任务 主要困难
完全合作 共享团队回报或同一联合目标 多机械臂协同搬运、协同覆盖 个体信用分配、协调探索与局部信息
零和竞争 常见两方情形满足收益互为相反数 棋类、严格零和追逃 学习 minimax／均衡策略，对手也在适应
一般和／混合 既有共同利益也有冲突，收益不能化为单一团队目标 多队对抗、有资源竞争的调度 队内协作、队间对抗与均衡选择同时存在

本页与下一页的实验环境属于混合设定：simple_adversary 里有一组合作的 good agents 与一个 adversary，存在合作和冲突，但官方文档不把所有 MPE 对抗任务都定义为严格零和。它适合演示联合动作与不同观测，不应被当成对所有 MARL 难点的充分检验。

天真的做法与它为什么失败

面对多智能体问题，最直接的想法是：每个智能体各自跑一份单智能体算法，把其他智能体当成环境的一部分。这种做法叫独立学习（Independent Learning），把 Q-learning 装进去就是 IQL，把 DDPG 装进去就是本页要实现的 IDDPG。

它实现简单，只需运行 \(N\) 份单智能体学习器。它不是“原理错误”：在固定对手、弱耦合、充分扩展状态或某些受限博弈中可以有效；但当其他智能体同时更新时，直接套用固定环境的理论需要额外条件。

准确边界。经典表格型 Q-learning 的收敛定理要求固定 MDP、充分探索和规定步长等条件；深度函数逼近算法本来就没有同等级的普遍保证。并发学习会使单个智能体边缘化他方动作后得到的有效转移与奖励随他方策略变化，因此不能直接援引固定 MDP 定理。

这就是环境非平稳性（non-stationarity），本章的核心问题，下文用一整节展开。

本章在主线中的位置

本主线的前十八章按「单智能体、环境固定」这条线索推进：从表格法到函数近似，从基于价值到基于策略，从在线到离线。本章是第一次改变问题设定本身，而不是改进算法。因此本章的重点不是某个具体算法，而是说清楚多智能体设定带来了哪些新问题；下一章的 MADDPG 才是针对这些问题的具体解法。

形式化定义：随机博弈与 Dec-POMDP

从 MDP 到随机博弈

单智能体的 MDP 是五元组 \((\mathcal{S}, \mathcal{A}, P, r, \gamma)\)。多智能体的对应物叫随机博弈（stochastic game，又称马尔可夫博弈），把动作与奖励都改成按智能体分列：

\[\big(\mathcal{N},\ \mathcal{S},\ \{\mathcal{A}^i\}_{i \in \mathcal{N}},\ P,\ \{r^i\}_{i \in \mathcal{N}},\ \gamma \big)\]

逐项解释：

  • \(\mathcal{N} = \{1, \dots, N\}\) 是智能体集合。
  • \(\mathcal{S}\) 是环境的全局状态空间，与单智能体一致。
  • \(\mathcal{A}^i\) 是第 \(i\) 个智能体的动作空间。联合动作空间是各智能体动作空间的笛卡尔积 \(\mathcal{A} = \mathcal{A}^1 \times \dots \times \mathcal{A}^N\)，一个联合动作记作 \(\boldsymbol{a} = (a^1, \dots, a^N)\)。
  • \(P(s' \mid s, \boldsymbol{a})\) 是状态转移概率。注意它依赖的是联合动作，而不是任何单个智能体的动作——这一条是后面所有分析的源头。
  • \(r^i(s, \boldsymbol{a})\) 是第 \(i\) 个智能体的奖励函数，同样可依赖联合动作。完全合作可共享奖励；零和设定满足各方收益相抵，但一般竞争或混合任务不要求奖励和为零。
  • \(\gamma\) 是折扣因子，各智能体通常取同一个值。

每个智能体有自己的策略 \(\pi_{\theta^i}^i\)，要最大化自己的折扣回报期望：

\[J^i(\theta^1, \dots, \theta^N) = \mathbb{E}\left[ \sum_{t=0}^{\infty} \gamma^t\, r^i_t \right]\]

这里必须看清：\(J^i\) 是全部 \(N\) 组参数的函数，而第 \(i\) 个智能体只能直接改动 \(\theta^i\)。因此一般不能脱离他方策略谈某个智能体的绝对最优策略，而要说明解概念：完全合作可优化联合团队目标，双人零和常讨论 minimax，固定他方时可谈 best response，一般和博弈常讨论 Nash 或相关均衡。不存在一种解概念覆盖所有 MARL 任务。

部分可观测：Dec-POMDP 与 POSG

随机博弈常以全局状态描述环境，但执行者通常只收到局部观测。共享团队回报的合作模型称为分布式部分可观测马尔可夫决策过程（Dec-POMDP）；若各智能体有不同回报并允许一般和或对抗关系，更准确的名称是部分可观测随机博弈（POSG，也常写 Dec-POSG）。

\[\big(\mathcal{N},\ \mathcal{S},\ \{\mathcal{A}^i\},\ P,\ R,\ \{\mathcal{O}^i\},\ O,\ \gamma \big)\]

上式用共享团队奖励 \(R\) 表示 Dec-POMDP；把它替换成 \(\{r^i\}\) 就得到一般收益的部分可观测博弈。不同文献的元组记号略有差别，关键不是元素个数，而是奖励关系、观测条件和执行信息。

新增的观测对象是：

  • \(\mathcal{O}^i\) 是第 \(i\) 个智能体的观测空间。
  • 联合观测模型可写为 \(O(\boldsymbol{o}\mid s',\boldsymbol{a})\)；在条件独立或确定性简化下，也可分别写成 \(O^i(o^i\mid s')\) 或 \(o^i=O^i(s')\)。

一般的去中心化策略以本地动作—观测历史 \(h_t^i\) 为条件：

\[a_t^i \sim \pi_{\theta^i}^i(\cdot \mid h_t^i)\]

只输入当前 \(o_t^i\) 是一种 reactive 近似；循环网络可把历史压缩为隐状态，但不自动得到精确充分统计量。

三条边界必须保留：

  • 当前局部观测通常不是全局状态的充分统计量，因此部分可观测问题与“其他学习者导致的非平稳性”是两个不同难点。
  • 训练器可能访问全局状态、联合观测或 simulator state；“执行者看不到”不等于环境以外的训练系统永远拿不到。
  • Bernstein 等人的 NEXP-complete 结论针对一般的有限时域 Dec-POMDP 决策问题（两名及以上智能体即可达到该复杂度）。它是最坏情况复杂度结论，不表示每个实例都没有可行的精确或结构化算法。

  RW -.->|"回报信号"| P2

读图要点在 JA 这个节点：转移与奖励都挂在联合动作上。第 \(i\) 个智能体只贡献这个联合动作的一个分量，却要为整个联合动作导致的后果负责。信用分配的困难与非平稳性的困难都从这里长出来。

环境非平稳性：本章的核心问题

这一节区分两层事实：环境的联合核 \(P(s'\mid s,\boldsymbol a)\) 可以始终固定；但若智能体只用自己的动作并把他方动作边缘化，并发更新的他方策略会使其有效转移与奖励随训练变化。若他方策略冻结，这一时间非平稳来源就消失，但局部观测仍可能带来部分可观测性。

单个智能体眼中的有效转移概率

固定考察第 \(i\) 个智能体。为清楚展示机制，先假设他方采用条件独立的 reactive 策略，且全局状态确定各自观测；有共享随机变量或历史策略时还要对这些变量边缘化。记其余智能体参数为 \(\boldsymbol{\theta}^{-i}\)、联合动作为 \(\boldsymbol{a}^{-i}\)，则：

\[\tilde{P}^{i}\big(s' \mid s,\, a^{i};\, \boldsymbol{\theta}^{-i}\big) \;=\; \sum_{\boldsymbol{a}^{-i}} P\big(s' \mid s,\, a^{i},\, \boldsymbol{a}^{-i}\big) \prod_{j \neq i} \pi_{\theta^{j}}^{j}\big(a^{j} \mid o^{j}\big)\]

同理，它感受到的期望奖励是：

\[\tilde{r}^{i}\big(s,\, a^{i};\, \boldsymbol{\theta}^{-i}\big) \;=\; \sum_{\boldsymbol{a}^{-i}} r^{i}\big(s,\, a^{i},\, \boldsymbol{a}^{-i}\big) \prod_{j \neq i} \pi_{\theta^{j}}^{j}\big(a^{j} \mid o^{j}\big)\]

逐项看这两条式子：

  • 左边的记号里带了分号后的 \(\boldsymbol{\theta}^{-i}\)，这是关键。\(\tilde{P}^i\) 与 \(\tilde{r}^i\) 都是他方策略参数的函数，而不是只与 \((s, a^i, s')\) 有关的固定量。
  • 真实的 \(P\) 与 \(r^i\) 由环境物理规律决定，训练全程不变；变的是求和里的权重 \(\prod_{j \neq i} \pi^j_{\theta^j}\)。
  • 其余智能体更新参数时，相关动作概率可能改变，从而使 \(\tilde{P}^i\) 与 \(\tilde{r}^i\) 随训练阶段变化；无关参数变化或等价策略不一定改变有效核。

写成随时间变化的形式，训练进行到第 \(k\) 轮与第 \(m\) 轮时：

\[\tilde{P}^{i}\big(\cdot \mid s, a^{i};\, \boldsymbol{\theta}^{-i}_{k}\big) \;\not\equiv\; \tilde{P}^{i}\big(\cdot \mid s, a^{i};\, \boldsymbol{\theta}^{-i}_{m}\big)\quad\text{（一般情形）}\]

这表示两个有效核一般不是同一个函数；某次参数变化也可能不改变相关动作概率，所以不能把每次更新都写成必然严格不等。

非平稳性与部分可观测不要混为一谈

这里有两个可独立出现的问题：当前局部观测可能不是充分状态，以及他方策略随训练时间改变。需要分别诊断：

  • 联合过程 \((s,\boldsymbol a)\to s'\) 仍由固定环境核描述；记录联合动作后，历史转移没有被物理上“改写”。
  • 即使所有策略冻结，单个 \(o_t^i\) 也可能不满足 Markov 性，需要历史或记忆。这是部分可观测问题。
  • 即使给智能体全局状态，只要隐藏他方动作且他方策略在更新，边缘核仍会随训练变化。这是学习者引起的时间非平稳性。

例如，第 1 台机械臂在相同全局状态下执行“向上抬”，结果还取决于第 2 台的动作。训练早期与后期，观测到的 \((s,a^1)\) 可以相同，但被省略的 \(a^2\) 及其分布不同，所以奖励分布不同；不能称两条完整联合数据“完全一致”。

为什么经验回放尤其成问题

并发学习会让经验回放更难使用，尤其是独立学习器只保存自身 \((o^i,a^i,r^i,o^{i\prime})\) 时。问题不是旧转移在物理上变成假的，而是数据由旧联合策略生成，且局部 Critic 没有记录足以区分这些策略条件的信息。

在固定单智能体 MDP 中，旧转移仍来自同一个环境核，但 off-policy 分布偏移、函数逼近和自举仍可能带来误差；不能写成“容量越大必然越稳”。多智能体还增加了策略版本这一隐藏条件。

对独立 replay，可作如下解释：

  • 池中一条 \((s, a^i, r^i, s')\) 是在当时的他方策略 \(\boldsymbol{\theta}^{-i}_{k}\) 下产生的，它是 \(\tilde{P}^i(\cdot \mid s, a^i; \boldsymbol{\theta}^{-i}_{k})\) 的样本。
  • 训练进行到第 \(m\) 轮时把它采出来用，Critic 却是在拟合 \(\tilde{P}^i(\cdot \mid s, a^i; \boldsymbol{\theta}^{-i}_{m})\)。
  • 若没有联合动作、策略版本或可用于重加权的信息，这些样本混合了不同的行为条件，局部 Critic 难以判断差异来自哪里。

因此更准确的说法是“当前目标与旧数据分布错配且条件信息不足”，不是“标签失效、任何加权都救不回来”。Foerster 等工作正是用重要性采样和策略 fingerprint 缓解 multi-agent replay 的陈旧性。

更大的 buffer 可能增加策略年龄跨度，也可能增加覆盖与样本复用；净效应取决于更新速度、对手漂移、采样与校正方法，不能预设随容量单调恶化。常见手段包括近期窗口、on-policy 更新、importance weighting、fingerprint／policy ID、对手建模和中心化训练信息。

实验上应同时记录样本年龄、策略更新幅度、TD 误差与评估表现，不能仅凭训练曲线震荡把原因唯一归到 replay 非平稳性。

三种基本范式的对比

下面三种范式同时涉及训练信息、执行信息、目标是否可标量化以及联合动作如何表示。它们是设计坐标，不是严格互斥且覆盖所有算法的三分法。

完全去中心化（独立学习）

每个智能体各自持有一份完整的单智能体算法，只用自己的观测与自己的奖励训练，彼此不交换任何信息。装 Q-learning 得到 IQL，装 DDPG 得到 IDDPG。

  • 优点：模块简单；若每个体网络规模固定，学习器计算与存储大致随智能体数线性增加；训练和执行使用相同的本地信息。
  • 限制：普通 IQL／IDDPG 不显式条件化他方动作或策略版本，因此并发更新时容易遭遇上述有效非平稳性与协调问题。
  • 适用边界：固定对手、弱耦合、共享参数或合适的稳定化机制都可能让独立学习成为强基线，不能预设耦合一强必然学不出。
  • 本页角色：IDDPG 用于暴露数据接口与局部 Critic 的信息缺口，不代表所有去中心化学习方法。

完全中心化

在完全合作且共享一个标量目标时，可以把团队视为联合控制器：状态是全局状态，动作是 \(\boldsymbol a=(a^1,\ldots,a^N)\)。一般和博弈若直接把奖励求和，会改变原博弈的激励结构，不能因此声称等价变成单智能体 MDP。

代价出在动作空间的规模上。设每个智能体有 \(\lvert \mathcal{A} \rvert\) 个离散动作，则联合动作空间的大小是：

\[\big\lvert \mathcal{A}^1 \times \dots \times \mathcal{A}^N \big\rvert = \lvert \mathcal{A} \rvert^{N}\]

显式枚举离散联合动作时，基数随 \(N\) 指数增长；但因子化策略、结构化搜索或问题分解可以避免完整枚举，因此不能直接说所有价值法和策略法都不可行。连续联合动作的维度通常相加增长，但协调、探索和函数表示仍可能随交互结构迅速变难。

若部署时仍由单个联合控制器根据全局信息输出联合动作，就需要相应的观测汇聚、通信与集中算力；在具备可靠基础设施的系统里这可能可行，在带宽、时延、故障隔离或隐私受限的系统里则可能不合适。

中心化训练、去中心化执行（CTDE）

第三条路把「训练」与「执行」两个阶段分开处理：

  • 训练时允许使用执行时不可用的额外信息，例如全局状态、联合观测、联合动作或其他智能体轨迹；信息来源可以是仿真器或集中日志，并非必须同一进程。
  • 执行时每个策略只使用协议允许的本地历史。若任务把显式通信作为观测或动作的一部分，CTDE 并不意味着“绝对不通信”。

CTDE 的定义性特征是训练可用信息多于执行信息。MADDPG 中中心化 Critic 可在部署时丢弃；MAPPO 的集中价值基线、VDN/QMIX 的混合网络也体现 CTDE，但结构并不等同于“每个 Critic 都吃全部动作”。

它通常缓解而非消除问题：

  • 联合动作条件可消除因遗漏同一步他方动作造成的一类歧义，但目标策略、部分可观测、函数逼近和 replay 分布仍会变化。
  • 朴素拼接的输入维数在每体维度固定时线性增加；表示所有高阶交互所需的模型容量、数据和通信并不保证线性扩展。
  • 去中心化部署符合信息约束，但策略性能仍取决于本地观测是否足够、训练与部署信息是否正确隔离。

算法流程：独立 DDPG

本页实现的基线是 IDDPG：\(N\) 份互相独立的 DDPG，各自持有 Actor、Critic 与两个目标网络，各自持有一个只装自己数据的回放池。单智能体 DDPG 的细节（软更新、探索噪声、目标值构造）见 DDPG 页，此处不重复，只写出多智能体循环的骨架。

输入: 智能体数 N, 折扣 gamma, 软更新系数 tau, 批量大小 B,
      每个智能体的 buffer 容量 M, 探索噪声强度 sigma

1  for i = 1 .. N do
2      随机初始化第 i 个智能体的 Actor 参数 theta^i 与 Critic 参数 phi^i
3      目标网络硬拷贝: theta^i' <- theta^i, phi^i' <- phi^i
4      初始化空 buffer D^i, 容量 M
5  end for
6  for episode = 1, 2, ... do
7      重置环境, 得到所有智能体的初始观测 o^1, ..., o^N
8      for t = 1 .. T do
9          for i = 1 .. N do
10             a^i <- clip( mu_{theta^i}(o^i) + noise, a_min, a_max )
11         end for
12         把联合动作 (a^1, ..., a^N) 一次性交给环境执行
13         得到奖励、下一观测、terminated^i 与 truncated^i
14         for i = 1 .. N do
15             把 (o^i, a^i, r^i, o^i', terminated^i) 存入 D^i
16             # 注意: 存进去的只有自己的观测与自己的动作
17             #       该局部 buffer 没有保存他方动作或策略版本
18         end for
19         for i = 1 .. N do
20             若 D^i 中样本不足则跳过
21             从 D^i 采样 B 条转移
22             a_next^i <- mu_{theta^i'}(o^i')                     # 自己的目标 Actor
23             y^i <- r^i + gamma * (1 - terminated^i) * Q_{phi^i'}(o^i', a_next^i)
24             L_critic^i <- mean( ( Q_{phi^i}(o^i, a^i) - y^i )^2 )
25             对 phi^i 做一步梯度下降
26             L_actor^i  <- - mean( Q_{phi^i}(o^i, mu_{theta^i}(o^i)) )
27             对 theta^i 做一步梯度下降
28             phi^i'   <- tau * phi^i   + (1 - tau) * phi^i'
29             theta^i' <- tau * theta^i + (1 - tau) * theta^i'
30         end for
31         若环境回合因 termination 或 truncation 结束则 break
32     end for
33 end for

与单智能体 DDPG 相比，表面代码主要多了多智能体数据编排，但任务语义、联合动作、回放条件和评估对手都要重新核对：

  • 第 12 行：动作必须一次性作为联合动作交给环境。环境的转移依赖联合动作，逐个智能体分别调用 step 在语义上是错的（除非环境本身就是按顺序决策的回合制博弈）。
  • 第 15 至 17 行：局部 buffer 不保存他方动作或策略版本，因而无法在更新时按这些条件区分样本；若采集系统另存了联合日志，则不是物理上不可恢复。下一章 MADDPG 会直接保存联合信息。
  • 第 22 至 23 行：目标值只用自己的目标网络，Critic 的输入只有 \((o^i, a^i)\)。它拟合的是那个会随他方策略漂移的 \(\tilde{Q}^i\)。

伪代码中的各个 IDDPG 更新没有跨智能体参数依赖，可以概念上并行；下面 Python 的 for 循环实际仍是顺序执行。若共享随机数生成器，遍历顺序还会改变各 buffer 抽到的样本，因此不能声称逐位结果与顺序无关。

  • 观测与动作空间的维度不要写死。不同版本、不同 N 参数下维度会变，一律从 env.observation_space(agent) 与 env.action_space(agent) 读取。

任务选 simple_adversary：场地上有若干个地标，一方（合作方）要靠近目标地标同时不暴露目标位置，另一方（对抗方）要靠近目标地标。合作与对抗同时存在，属于混合设定。

代码分六段：一、四、六段是样板，第二段讲环境接口，第三段的 IDDPG 类与第五段的训练循环是要讲透的地方。

第二段：环境接口（需要留意的地方）

def make_env(num_good_agents=2):
    """创建并行接口的 MPE 环境。

    parallel_env 表示所有智能体在同一时间步同时决策、同时执行，
    与本页伪代码第 12 行的「联合动作一次性交给环境」一致。
    PettingZoo 还提供 AEC 接口；它能表示顺序交互，也能按 agent cycle
    包装同步环境。本例选择 Parallel API 是为了直接提交联合动作字典。
    """
    env = simple_adversary_v3.parallel_env(
        N=num_good_agents,        # 合作方的智能体数量
        max_cycles=MAX_CYCLES,
        continuous_actions=True,  # 用连续动作，才能直接套用 DDPG
    )
    return env


env = make_env()
observations, infos = env.reset(seed=SEED)

# env.agents 是当前存活智能体列表；possible_agents 是该环境的稳定全集。
# 本例在 reset 后记录名字，依赖 MPE 智能体只在回合末同时退出。
agent_names = list(env.agents)

# 各智能体的观测维度与动作维度可以不同，逐个读取。
obs_dims = {a: env.observation_space(a).shape[0] for a in agent_names}
act_dims = {a: env.action_space(a).shape[0] for a in agent_names}

这一段有三处必须留意。

其一：并行接口与逐智能体循环的对应关系。 parallel_env 的 step 接收的是一个字典，键是智能体名字，值是该智能体的动作；返回的同样是五个字典。这正是伪代码第 12 至 13 行的直接对应：先把每个智能体的动作收集成字典，再一次调用 step。写成对每个智能体分别调用 step 是错的——环境的转移依赖联合动作，分开调用等于让环境在别人还没动作时就先推进了物理仿真。

其二：观测与动作维度按智能体不同。 simple_adversary 里对抗方与合作方看到的信息量不同，观测维度不相等。因此上面用字典而不是单个整数来存维度。这一点在下一章会成为关键：中心化 Critic 要把所有观测拼起来，输入维度是各智能体观测维度之和，而不是某一个维度乘以 \(N\)。

其三：智能体可能中途退出。 PettingZoo 允许智能体在回合中途终止，此时它会从 env.agents 中移除，后续步骤的字典里也不再有它的键。MPE 的这些任务里所有智能体同时到达 max_cycles 而结束，不会出现中途退出，因此本页代码按「智能体集合固定」处理。若换到会中途死亡的环境，所有按 agent_names 遍历的地方都要改成按当前 env.agents 遍历，否则会因为缺键而报错。

第三段：网络与回放池（样板）

class MLPActor(nn.Module):
    """两层 MLP。输出经 sigmoid 压到 [0, 1]，
    与 MPE 连续动作空间的取值范围对齐（各版本以 action_space 为准）。"""

    def __init__(self, obs_dim, hidden_dim, act_dim):
        super().__init__()
        self.fc1 = nn.Linear(obs_dim, hidden_dim)
        self.fc2 = nn.Linear(hidden_dim, hidden_dim)
        self.fc3 = nn.Linear(hidden_dim, act_dim)

    def forward(self, obs):
        x = F.relu(self.fc1(obs))
        x = F.relu(self.fc2(x))
        return torch.sigmoid(self.fc3(x))


class MLPCritic(nn.Module):
    """输入拼接后的向量，输出标量 Q 值。输出层不接激活。"""

    def __init__(self, in_dim, hidden_dim):
        super().__init__()
        self.fc1 = nn.Linear(in_dim, hidden_dim)
        self.fc2 = nn.Linear(hidden_dim, hidden_dim)
        self.fc3 = nn.Linear(hidden_dim, 1)

    def forward(self, x):
        x = F.relu(self.fc1(x))
        x = F.relu(self.fc2(x))
        return self.fc3(x)


class ReplayBuffer:
    """普通的单智能体回放池，每个智能体各持有一个。"""

    def __init__(self, capacity):
        self.buffer = deque(maxlen=capacity)

    def add(self, obs, act, rew, next_obs, terminal):
        self.buffer.append((obs, act, rew, next_obs, terminal))

    def sample(self, batch_size):
        batch = random.sample(self.buffer, batch_size)
        obs, act, rew, next_obs, terminal = zip(*batch)
        to_t = lambda x, dt: torch.tensor(np.array(x), dtype=dt, device=DEVICE)
        return (to_t(obs, torch.float), to_t(act, torch.float),
                to_t(rew, torch.float).view(-1, 1),
                to_t(next_obs, torch.float),
                to_t(terminal, torch.float).view(-1, 1))

    def __len__(self):
        return len(self.buffer)

样板，与 DDPG 页的实现一致，不展开。只说两点：Actor 输出层用 sigmoid 而不是 DDPG 常用的 tanh，是因为 MPE 的连续动作空间取值为非负；MLPCritic 的 in_dim 写成参数而不是写死成「观测维加动作维」，是为了让同一个类在下一章的中心化 Critic 里能直接复用。

第四段：单个独立智能体（本节核心）

class IndependentDDPGAgent:
    """一个完全独立的 DDPG 智能体。

    关键在于它看不到任何他方信息：
    Critic 的输入只有 (o^i, a^i)，buffer 里也只有自己的数据。
    """

    def __init__(self, obs_dim, act_dim, hidden_dim):
        self.actor = MLPActor(obs_dim, hidden_dim, act_dim).to(DEVICE)
        self.target_actor = MLPActor(obs_dim, hidden_dim, act_dim).to(DEVICE)
        # Critic 输入维度 = 自己的观测维 + 自己的动作维。
        # 下一章 MADDPG 改的就是这一行。
        self.critic = MLPCritic(obs_dim + act_dim, hidden_dim).to(DEVICE)
        self.target_critic = MLPCritic(obs_dim + act_dim, hidden_dim).to(DEVICE)

        # 目标网络硬拷贝初始化，对应伪代码第 3 行
        self.target_actor.load_state_dict(self.actor.state_dict())
        self.target_critic.load_state_dict(self.critic.state_dict())

        self.actor_opt = torch.optim.Adam(self.actor.parameters(), lr=ACTOR_LR)
        self.critic_opt = torch.optim.Adam(self.critic.parameters(), lr=CRITIC_LR)
        self.buffer = ReplayBuffer(BUFFER_SIZE)
        self.act_dim = act_dim

    def take_action(self, obs, sigma=0.1, explore=True):
        obs = torch.tensor(np.array([obs]), dtype=torch.float, device=DEVICE)
        with torch.no_grad():
            action = self.actor(obs).cpu().numpy()[0]
        if explore:
            action = action + sigma * np.random.randn(self.act_dim)
        # 裁剪到动作空间的合法范围
        return np.clip(action, 0.0, 1.0)

    def soft_update(self, net, target_net):
        for p, tp in zip(net.parameters(), target_net.parameters()):
            tp.data.copy_(TAU * p.data + (1.0 - TAU) * tp.data)

    def update(self):
        if len(self.buffer) < BATCH_SIZE:
            return
        obs, act, rew, next_obs, terminal = self.buffer.sample(BATCH_SIZE)

        # ---- Critic 更新，对应伪代码第 22 至 25 行 ----
        with torch.no_grad():                       # 目标必须切断梯度
            next_act = self.target_actor(next_obs)  # 只用自己的目标 Actor
            q_next = self.target_critic(torch.cat([next_obs, next_act], dim=1))
            y = rew + GAMMA * (1.0 - terminal) * q_next
        q = self.critic(torch.cat([obs, act], dim=1))
        critic_loss = F.mse_loss(q, y)
        self.critic_opt.zero_grad()
        critic_loss.backward()
        self.critic_opt.step()

        # ---- Actor 更新，对应伪代码第 26 至 27 行 ----
        # 送进 Critic 的是 actor(obs)，不是 buffer 里的 act
        cur_act = self.actor(obs)
        actor_loss = -self.critic(torch.cat([obs, cur_act], dim=1)).mean()
        self.actor_opt.zero_grad()
        actor_loss.backward()
        self.actor_opt.step()

        # ---- 软更新两个目标网络 ----
        self.soft_update(self.actor, self.target_actor)
        self.soft_update(self.critic, self.target_critic)

这个类沿用单智能体 DDPG 的更新形式，并刻意不读取其他智能体信息。它展示的是局部函数近似的条件缺口，而不是证明这种结构在所有任务上必然失败。

  • self.critic = MLPCritic(obs_dim + act_dim, ...) 表示 Critic 只拟合 \(Q^i(o^i,a^i)\)。他方动作、隐藏状态和策略版本都进入条件外的不确定性；它们是否可忽略取决于任务。
  • update 的后继动作只显式计算自己的目标 Actor。其他智能体的影响被折叠进局部经验分布，而不是数学上“不存在”。
  • replay 混合多个策略时期时，相同局部输入可能对应不同条件分布；MSE 会拟合该训练分布下的折中值，不能预先断言它对每个时期都错误。

下一章 MADDPG 将 Critic 改为联合条件、buffer 保存联合信息，并用各目标 Actor 构造联合后继动作；同时还要检查 actor 梯度中他方动作的 detach、终止掩码、信息边界和评估协议，不能概括为只改三行。

第五段：训练循环（核心在字典与列表的转换）

def train():
    env = make_env()
    observations, _ = env.reset(seed=SEED)
    agent_names = list(env.agents)

    agents = {
        name: IndependentDDPGAgent(
            env.observation_space(name).shape[0],
            env.action_space(name).shape[0],
            HIDDEN_DIM,
        )
        for name in agent_names
    }

    return_history = {name: [] for name in agent_names}
    total_steps = 0

    for episode in range(NUM_EPISODES):
        observations, _ = env.reset()
        ep_return = {name: 0.0 for name in agent_names}

        while env.agents:                     # 直到本回合所有智能体结束
            # --- 收集联合动作：先逐个智能体算，再打包成字典 ---
            if total_steps < WARMUP_STEPS:
                actions = {name: env.action_space(name).sample()
                           for name in env.agents}
            else:
                actions = {name: agents[name].take_action(observations[name])
                           for name in env.agents}

            # --- 一次性执行联合动作，对应伪代码第 12 行 ---
            next_observations, rewards, terminations, truncations, _ = env.step(actions)

            # --- 各自存各自的那一份，他方动作在此丢弃 ---
            for name in agent_names:
                terminal = float(terminations[name])
                agents[name].buffer.add(
                    observations[name], actions[name], rewards[name],
                    next_observations[name], terminal,
                )
                ep_return[name] += rewards[name]

            observations = next_observations
            total_steps += 1

            # --- 各自更新：无跨智能体参数依赖，但 Python 循环顺序执行 ---
            if total_steps >= WARMUP_STEPS and total_steps % UPDATE_INTERVAL == 0:
                for name in agent_names:
                    agents[name].update()

        for name in agent_names:
            return_history[name].append(ep_return[name])

    env.close()
    return return_history

四处要点。

其一：while env.agents 而不是固定步数。 PettingZoo 用 env.agents 是否为空表示回合是否结束。到达 max_cycles 时所有智能体的 truncations 置真，下一次 step 后 env.agents 变空，循环退出。写成 for t in range(MAX_CYCLES) 在这个环境上碰巧等价，但换到智能体会中途退出的环境就会出错。

其二：terminations 与 truncations 分开保存语义。 本例只把 terminations[name] 写入 Bellman mask；truncations 负责结束采集。若任务目标是真正有限时域，应把剩余时间纳入状态或按有限时域价值定义处理，而不是无说明地合并两个标志。

其三：UPDATE_INTERVAL 不是每步更新。 本页每 100 个环境步做一次更新、batch 为 1024，这只是未验证的教学预算。应同时报告环境步数、梯度步数和样本复用率，不能把它称为 MPE 的通用配置。

其四：各更新在模型依赖上独立，但代码顺序执行。 IDDPG 不读取他方参数，所以没有同一步参数覆盖问题；共享随机数生成器仍会让遍历顺序影响各 buffer 抽样。需要严格复现时，应给每个智能体独立 RNG 并固定 agent ordering。

实验与结果分析

哪些现象只能算诊断线索

本页没有训练日志，代码也只绘制带探索的训练回报，因此不能声称已经“稳定复现”非平稳性。下列量都需要联合分析，单独一项不能证明因果：

  • 回报震荡也可能来自探索噪声、学习率、奖励尺度、有限样本或对手变化。
  • 跨种子方差大说明流程不稳定或多模态，但不能唯一归因于 multi-agent non-stationarity。
  • TD loss 回升可能来自目标网络、自举、分布偏移或函数逼近，不是他方策略更新的专属指纹。

应检验的假设与对照

把结论写成可证伪假设，并设置能隔离变量的对照：

假设 必要对照或记录
并发更新增加局部目标漂移 固定其他智能体策略，与共同训练组比较
replay 策略年龄影响 IDDPG 扫描窗口／容量，并记录样本年龄而非只看容量
联合动作条件改善估值 在同一数据和预算下比较局部 Critic 与中心化 Critic
增加智能体数提高协调难度 同时控制任务几何、奖励和网络容量，不能只改 N

评估协议

  • 预先规定多个独立训练种子、汇总统计和不确定性区间；不要把“三到五个”写成普遍充分样本数。
  • 关闭探索噪声，冻结所有被评估策略；共同训练中的训练回报不能替代冻结快照评估。
  • 明确对手与队友分布：固定 checkpoint、checkpoint pool、交叉对局矩阵或外部基准会回答不同问题。
  • simple_adversary 不是严格零和，不能用“一方涨则另一方必跌”作为硬约束；应分别报告每个角色和团队指标。
  • 同时记录策略变化量、样本年龄、TD 误差、回报和任务成功指标；通过冻结对手、移除 replay 等干预做因果诊断。
  • “固定一方后另一方还能改进”只表明存在可利用的响应，不足以证明原联合策略不是 Nash 均衡；近似 exploitability 需要定义策略空间和 best-response 训练质量。

关键参数配置与原因

下表记录代码中的教学配置，不把它们包装成 MARL 通用默认值。正式报告还应给出环境步数、每个智能体的样本数、梯度步数、batch、策略更新频率和评估预算。

参数 本页代码值 必须说明的性质
折扣因子 gamma 0.95 改变时间偏好，不由回合长度唯一决定
max cycles 25 PettingZoo 环境时限，不等于真终止
batch size 1024 未经本页实验验证
更新间隔 100 步 每 100 个联合环境步做一次梯度更新
buffer 容量 100000／体 决定覆盖、复用与策略年龄跨度

折扣因子 gamma

  • 本页取值：0.95，未在本页做消融。
  • 解释边界：\(1/(1-\gamma)=20\) 只是持续任务中理解折扣尺度的直觉，不是精确有效视野。有限时域还受 terminal、truncation 和是否把剩余时间纳入状态影响。
  • 选择方法：较小 \(\gamma\) 更强调近期收益，较大值延长信用传播并可能放大自举误差；0.99 在短回合中仍可能有意义，不能仅因尺度超过 25 就判为无效。

batch size 与更新间隔

  • 本页取值：batch 1024、每 100 个联合环境步更新一次，只是演示配置。
  • 需要联报：该代码约为 0.01 次梯度更新／环境步；batch 大小不等于更新比。还要报告 warmup、总样本数和同一样本期望复用次数。
  • 取舍：大 batch 可能降低梯度方差，也会混合更宽的策略年龄；低更新频率减少参数变化，也可能严重欠优化。效果必须通过预算对齐的消融确定。

每个智能体的回放池容量

  • 本页取值：每个体 100000 条局部转移。
  • 真正变量：容量与更新速度共同决定策略年龄跨度；旧样本仍是真实历史联合交互，但局部记录缺少行为条件。
  • 选择方法：同时扫描容量或近期窗口，记录样本年龄、覆盖、TD 误差与评估表现。中心化 Critic 也使用 off-policy replay，CTDE 不会自动免除陈旧数据问题。

软更新系数 tau

  • 本页取值：0.01，未证明优于其他值。
  • 解释边界：\(1/\tau\) 只是 EMA 记忆尺度的近似，并且单位是目标网络更新次数，不是环境步。
  • 取舍：较大值跟随主网络更快但平滑更弱，较小值更平滑但滞后更长；应与更新间隔、学习率和 target update 次数联合消融。

探索噪声

  • 本页取值：sigma=0.1 且代码没有衰减；动作再裁剪到 [0,1]，因此边界附近的噪声分布会被截断。
  • 多智能体含义：一个智能体的探索会改变其他智能体收到的数据分布，可能促进联合探索，也可能增加对手／队友行为的不确定性。
  • 选择方法：报告噪声日程和裁剪比例，比较独立噪声、相关探索或参数噪声；不能预先断言某一强度必然学不到协同或必然避免次优协调。

小结与下一章衔接

五句话回顾

  1. 奖励关系可粗分为完全合作、零和竞争与一般和／混合；simple_adversary 是含合作与冲突的混合任务，但不应假定严格零和。
  2. 随机博弈描述联合状态与动作；共享回报的部分可观测合作模型是 Dec-POMDP，一般独立回报则更准确地写成 POSG。NEXP-complete 是一般有限时域 Dec-POMDP 决策问题的最坏情况结论。
  3. 联合环境核可以固定；普通独立学习把他方动作边缘化后，有效核依赖他方策略。并发更新会破坏直接套用固定 MDP 定理的条件，但部分可观测与时间非平稳必须分开。
  4. replay 中旧样本仍是真实历史交互，风险在于策略年龄、当前目标分布与缺失条件信息；影响不随容量必然单调，fingerprint、重加权、近期窗口和集中信息都可能缓解。
  5. CTDE 是常用信息范式而非万能解：MADDPG、MAPPO、COMA、VDN 和 QMIX 使用集中信息的方式不同，规模、信用分配、协调探索与均衡问题仍需单独处理。

这一章留下的问题

IDDPG 的局部 Critic 看不到他方动作，是可明确修正的一项信息缺口，但不是所有困难的唯一来源：

  • 他方策略更新会改变局部有效分布，replay 还混合不同策略年龄。
  • 局部观测、团队信用分配、协调探索和一般和均衡仍未解决。
  • 增加集中信息可能降低歧义，也会带来规模、可用性与训练—部署信息泄漏风险。

下一章

MADDPG 具体展示一种 CTDE actor–critic：训练时让每个体 Critic 条件化联合观测与动作，执行 Actor 只使用协议允许的本地信息。它减少遗漏他方动作造成的歧义，但不自动保证平稳、无偏或收敛。下一章还需核对联合 replay、各目标 Actor 构造的后继动作、actor 梯度中的他方动作处理、终止掩码和评估对手。
