知识库 · 机器人模仿学习与 VLA · VLA · 公共基础 · VLM 骨干、具身与空间 Grounding
专题总览 1 机器人与控制接口 2 VLM 与空间 Grounding 3 动作表示与生成目标

把图像、指令和机器人状态都称为 token，并不能说明它们怎样进入模型、彼此能否看见、是否带有正确的时间与空间语义，更不能证明输出可直接控制机器人。本页沿每类输入追踪 encoding、position、time、mask 和 consumer，并把语义、二维、三维、动作与低层控制逐层分开。

  • 必须追踪：encoding、position、time、mask、consumer、loss/update path。
  • 必须区分：视觉语言模型（Vision-Language Model，VLM）、具身 VLM、视觉—语言—动作策略（Vision-Language-Action，VLA）、planner、action expert 与 controller。
  • 不能推出：patch 不等于 object；同 hidden size 不等于已经对齐；空间语言不等于度量三维；attention 不等于因果解释。

本页只提供结构审计模板，不包含模型 shape、机器人参数或能力保证，不下载权重、不调用模型服务、不执行推理或机器人动作。

先问表示

输入是离散 ID、连续 embedding 还是序列槽位？它从哪个原始字段和预处理版本产生？

再问可见性

槽位处于什么位置，带什么相机与时间身份，哪些 query 能读到它，缺失时如何 mask？

最后问消费方

输出交给文本 planner、空间模块、action expert、adapter 还是 controller？失败由谁处理？

三份页面产物分别是逐模态 trace sheet、融合与更新矩阵、grounding 责任表。它们必须绑定目标 checkpoint、代码和数据契约；任一字段未知时应显式记为待核验，不能靠模型名字或论文示意图补齐。建议选择一个输入，从原始 source 一路追到 action condition，再从 loss 反向检查实际更新路径。

从 ViT、VLM 到 VLA：先分清角色

Vision Transformer（ViT）把图像 patch 组织成 Transformer 序列；大型语言模型（Large Language Model，LLM）处理文本表示；VLM 连接视觉与语言；VLA 则进一步输出能被机器人动作链消费的表示。分类依据始终是输入、输出、consumer 与责任，不是模型名字。

角色不是模型名字

角色 最小输入 典型输出 谁消费 不能自动推出
ViT / vision encoder 图像或视频帧 patch/global visual features VLM、perception head、policy 语言理解、度量三维、动作
LLM 文本 token/embedding 文本 hidden states 或 token 分布 用户、planner、工具层、VLM/VLA 视觉观测、可行控制
VLM 图像/视频 + 文本 描述、回答、跨模态 hidden states 人、planner、action module 本体状态、实时闭环或机器人动作
embodied VLM 视觉/文本 + 连续传感或状态 具身任务表征、回答或计划 planner、policy 或人 必然直接输出低层动作
VLA 视觉/语言/状态等条件 action token、连续动作或动作分布 adapter / safety / controller 动作可达、安全或控制稳定
planner 目标、状态、技能/世界信息 子目标、技能序列或计划 policy、skill executor 每周期低层 reference
action expert/head 多模态条件 + 状态/噪声/历史 动作或动作块 adapter / safety 机器人接口语义已正确
low-level controller reference + measured state hardware command actuator 高层语义理解

一个模型可以承担多个角色，一个系统也可以把多个模型串联。embodied VLM 与 VLA 有交集但不等价；关键是它是否学习并输出动作表示，以及输出交给谁。VLM 能生成合理文本，只直接支持相应语言任务，不能自动证明空间精度、可达性或闭环控制能力。

感知、计划、动作与控制的四道边界

flowchart LR
  S["sensors<br/>RGB · language · state · history · depth/point cloud"] --> E["encoders<br/>preprocess · position · time · mask"]
  E --> G["multimodal fusion / grounding"]
  G -.->|"可选：目标 / 子任务"| P["planner"]
  G -->|"VLM hidden / action condition"| A["action expert / head"]
  P -.->|"plan / skill condition"| A
  A -->|"action output"| L["adapter + deterministic limits"]
  L -->|"controller reference"| C["low-level controller"]
  C -->|"hardware command"| H["actuator"]

图 1｜从传感器到控制器的职责数据流。 sensors 产生带来源、时间、标定与有效性的观测；encoder 形成表示；fusion/grounding 提供跨模态表示或空间输出；planner 是可选条件路径；action expert 产生动作表示；adapter 和确定性限制把它转换为 controller reference；低层 controller 才生成 hardware command。VLM 输出、action output 与 controller reference 是三条不同边，不能合并为一个“robot command”。

核验时依次问：“它看见了什么？”对应感知或 grounding；“下一步做什么？”对应目标、子任务或计划；“用什么动作表示实现？”对应 VLA/action head；“怎样在当前机器人上稳定执行？”对应 adapter、限制与 controller。若文档只写“模型理解并执行”，必须补齐输出 schema、consumer 和分层证据。

同一个系统中的模块边界也可能随部署方式变化：离线训练时，语言目标可能直接监督共享 backbone；在线运行时，planner 可能成为独立服务；某些策略则完全没有显式 planner。页面不能用进程边界代替功能边界，也不能因两个模块共享参数就把它们的责任合并。每条边至少记录输入 schema、输出 schema、调用时刻、版本、失败码和下游拒绝规则；如果中间产物无法被日志重建，就不能在故障后可靠判断是感知、规划、动作生成还是控制层出错。

角色表还用于约束能力语气：视觉 encoder 的分类准确率不能证明语言条件有效，planner 的文本可读性不能证明 action expert 使用了该计划，action expert 的离线 loss 不能证明 adapter 接收的物理动作正确，controller 的跟踪误差较小也不能证明高层目标合理。只有把相应输出与 consumer 的输入合同、干预测试和闭环结果同时对齐，才可以提出受范围限制的能力结论。

ViT patch 的最小直觉

输入图像先被分成 patch，每个 patch 经线性映射与位置编码形成序列，Transformer 再在槽位间计算表示。patch 不是天然语义对象：一个物体可能跨多个 patch，一个 patch 也可能同时包含背景与多个物体；resize、crop、pad 会改变像素与 token 的几何对应。

最小图像路径是 raw image → decode/color → resize/crop/pad → normalize → patchify → vision encoder → select layer/tokens → projector/resampler → fusion。每一步都要有版本、输入输出 shape、几何映射与失败规则。只要颜色顺序、裁剪或取层改变，后续 tensor 即使 shape 仍合法，语义分布也可能已经改变。

Token、Projector 与融合路径

三种“token”必须分开

术语 本页定义 例子 常见误读
token ID 词表中的离散索引 tokenizer 输出的整数 所有模态都必须有词表
embedding 一个连续向量 词 embedding、patch feature、state projection 连续向量必然已经语义对齐
sequence slot 注意力序列中的位置 第 k 个视觉槽位或状态槽位 槽位数量等于信息量

语言通常从离散 ID 查表得到 embedding，视觉往往直接生成连续 patch feature，状态可由多层感知机（Multi-Layer Perceptron，MLP）或线性层生成一个或多个 embedding。动作既可能离散为 token ID，也可能保持连续向量。页面必须同时说明 representation、shape、position 和 mask，不能用“最终都是 token”结束解释。

encoder、projector 与 resampler

模块 主要责任 必须核验 不能默认
vision encoder 从像素产生视觉特征 预处理、patch 网格、取层、输出 token 已与语言空间对齐
state encoder 把本体/传感状态映射为特征 字段顺序、单位、归一化、缺失 mask 已经学会机器人运动学
projector 调整特征维度与表示接口 输入/输出 dim、非线性、初始化、训练边界 单独完成语义 grounding
resampler / pooling 压缩或重组视觉序列 query 数、位置保留、mask、压缩率 token 更少且信息无损
tokenizer/embedding 文本 ID 与向量接口 词表、特殊 token、截断、padding 自然语言总能无损编码任务
modality/type embedding 标注相机、模态或段 ID 映射、加入位置、是否训练 concat 后模型自动识别来源

“投到同一 hidden size”只说明张量接口兼容，不证明统计分布、语义、空间位置或尺度已经对齐。对齐来自训练数据、目标函数、参数更新路径与后续网络共同作用；projector 也可能成为信息瓶颈，必须用目标任务指标和消融检查。

三类融合结构

flowchart TB
  subgraph M1["模式一 · 共享序列 self-attention"]
    I1["projected visual · language · state slots<br/>position + modality + time"] --> K1["mask 决定 query-key 可见性"]
    K1 --> O1["shared / grouped self-attention"]
    O1 --> H1["selected output slots / head"]
  end
  subgraph M2["模式二 · context + cross-attention"]
    C2["context K/V<br/>visual · language · state"] --> X2["cross-attention layers"]
    Q2["consumer queries<br/>action / language / latent"] --> X2
    X2 --> H2["consumer stream output"]
  end
  subgraph M3["模式三 · VLM + action expert"]
    V3["VLM condition<br/>frozen or trainable"] --> X3["明确接口<br/>shared self-attention / cross-attention / modulation"]
    S3["state · noisy action · time"] --> A3["action expert"]
    X3 --> A3
    A3 --> H3["action representation"]
  end

图 2｜三种常见融合模式。 共享序列模式需要冻结拼接顺序、position、模态标识与 mask；cross-attention 要画清 consumer query 与 context key/value 的方向；VLM + action expert 要核验两侧通过何种接口交互，以及条件端是 frozen 还是 trainable。early/late 只是相对标签，实际数据路径、可见性和梯度路径才是可核验描述。

比较融合结构时，应对同一输入逐层记录槽位数量、隐藏维度、position 来源、mask 形状、query/key/value 的产生模块、输出被哪些 head 读取，以及梯度能否返回各编码器。只画一个“fusion”方框会隐藏最关键的接口差异。即使两个模型都写 cross-attention，一个也可能让 action query 读取冻结视觉条件，另一个可能让语言 query 读取可训练动作 latent；二者不能共享同一个未经说明的架构标签。

融合后的表示也不一定只有一个消费方。文本 head、value head、action head 与辅助重建 loss 可能从不同层或不同槽位读取，因此“共享 backbone”不等于所有任务看到相同信息。审计时为每个 consumer 建立读取位置、mask、梯度与版本记录；如果辅助目标在训练时存在、部署时被移除，还要确认它影响的是参数学习而不是运行时必需输入。

共享 self-attention 中，视觉、语言与状态形成一个逻辑序列，但不表示所有槽位互相可见。独立 context + cross-attention 中，query 可以来自动作、语言或 latent stream，context 可以按图像与非图像分流。双系统或 action expert 也可能复用 self-attention、cross-attention 或调制，不能从名字推断实现。OpenVLA、π0 与 GR00T 只作为具体模式入口，其层数、shape、mask 和训练结论留在各自页面。

self-attention 与 cross-attention 的核验句法

self-attention 的 Q,K,V 来自同一逻辑序列，但参数可以按 expert 或模态分组；cross-attention 的 query 来自 consumer stream，K,V 来自 context stream，方向不能画成无箭头连线。mask 对每个 query-key 对定义可见性，padding、causal、block 与 modality mask 不能折叠成一个含糊布尔量。sequence index、二维 patch position、camera/view ID 与 time index 也不是同一种坐标。

\[\operatorname{Attention}(Q,K,V;M) = \operatorname{softmax}\!\left(\frac{QK^{\mathsf T}}{\sqrt d}+M\right)V.\]

不可见位置应在 softmax 前被 mask 抑制，具体实现仍要验证广播方向、dtype、padding 与数值稳定。attention 权重只是计算中间量，不足以单独证明模型因果上“看了”某个物体；需要输入干预、输出变化和任务指标共同支持。

压缩与缓存的边界

视觉 token 压缩可以减少后续序列长度与计算，却可能丢失小物体、边界或多实例信息；能否接受必须由任务级消融支持。键值缓存（Key-Value cache，KV cache）只在图像、语言、状态、mask、position 和模型参数确实未变时才可复用 prefix 中间状态。

cache key 必须覆盖所有影响 prefix 的输入与版本；历史或本体状态变化不能错误命中；缺失相机或 padding 改变后要重新核验 position；train mode、dropout 或可训练参数下不得不当复用；延迟收益也必须实测，不能只从 token 数推断。

多相机、状态与历史上下文

多相机不是无序集合

字段 必填内容 核验问题
camera_id / semantic_role 固定 ID；base、wrist-left 等角色 角色是否与训练 schema 一致
tensor_order batch/sequence 中的确定顺序 换序是否被显式支持
frame_id / calibration_version optical frame、内外参与版本 是否引用采集时有效标定

简单 concat 一般不会自动具有相机置换不变性。训练顺序若是 [base, wrist_left, wrist_right]，推理时换序即使 shape 不变也会改变语义。复制一张图填补缺失相机、用全零图占位、或把 valid_mask=false 都不是天然等价操作；必须以代码路径、训练分布和消融验证为准。

proprioception 的位置是架构选择

proprioception 可以作为视觉/语言 prefix 的一个或多个槽位，放在语言之后与动作之前的 suffix，只进入 action expert/DiT，也可以经 cross-attention、特征线性调制（Feature-wise Linear Modulation，FiLM）或独立残差路径进入，甚至在多个位置重复注入。

每种选择都要记录 state_fields、字段顺序、单位、frame、归一化统计、采样时间、mask、position、重复注入点和 consumer。“离动作槽位更近”不自动等于效果更好；其作用与可见性、训练目标、数据覆盖和架构共同决定。一个 state encoder 输出正常，也不能证明模型学会了机器人运动学。

历史窗口、时间编码与 reset

历史输入合同可以写成 history = {source, length, stride, time_order, timestamp, padding, reset_boundary, temporal_encoding, visibility, consumer}。必须区分当前 observation 中堆叠多帧、多帧分别形成 token、recurrent/latent memory、上一动作或 chunk 回馈，以及 KV cache 对 prefix 计算的复用。

固定窗口不等于长期记忆，KV cache 也不等于任务状态。episode reset、人工接管、相机断流、控制模式切换或机器人配置变化后，是否清空或截断历史必须显式。训练与推理的 history length、stride、padding 方向、时间编码或 timestamp 对齐不一致时，应优先当作接口错误，而不是泛化能力不足。

缺失、过期与异步输入

每个模态都要记录 valid、相对决策时刻的 freshness、槽位可见性的 attention_mask、目标是否参与损失的 loss_mask、缺失时的 fallback，以及原始、插值、复制或占位值的 provenance。

attention_mask=false 不会自动阻止错误值进入归一化统计、日志、cache key、residual 或其他旁路。检查必须从 input adapter 贯穿 encoder、placement、fusion、consumer 和 loss；过期输入即使数值有限，也要按 freshness 与 deadline 规则拒绝或降级。

每次决策最好形成一份只读 observation receipt：列出实际收到的模态、原始时间戳、预处理与标定版本、是否插值或占位、最终槽位范围、position/view/time ID、可见性和消费模块。receipt 不保存敏感原始图像也可以保留 hash 与派生关系，使离线回放能区分“传感器没有提供”“adapter 丢弃”“mask 屏蔽”和“模型读取但未使用”等不同情况。

异步输入还需要明确一致性边界：如果 base 相机是新帧而 wrist 相机、状态或历史仍来自旧时刻，这组输入是允许的近似快照、需要插值的组合，还是必须拒绝的撕裂状态。允许异步不等于忽略时间差；每种模态都要有最大年龄、容忍误差、更新触发和 fallback owner。训练数据若只包含同步样本，部署时的异步组合应被视为新的分布条件并单独评测。

层级 核心问题 可验收输出 下一 consumer 不能推出
语义识别 画面中有什么 类别/属性/文本答案 planner、selector 指向哪个实例
指代表达 grounding “左边红杯”是哪一个 instance ID、mask 或区域 perception/action module 度量位置
2D grounding 在图像哪里 bbox、mask、keypoint + image frame 2D servo、3D lifting 深度与可达
3D grounding 在哪个 3D frame、何种不确定性 point/pose/volume + frame + covariance planner、IK、policy 抓取可行与安全

action/control 机器人怎样运动 action/chunk/reference adapter/controller 已满足限制与稳定性

VLM 的文本回答正确，只能直接支持对应语言任务；不能据此证明实例级 mask、度量三维 pose、可达性、碰撞约束或闭环控制。分布外（Out-of-Distribution，OOD）状态也要作为 grounding 输出的有效性字段，而不能仅依赖语言置信描述。

2D grounding 的完整输出

二维输出至少包含 {image_id, camera_id, timestamp, pixel_coordinate_convention, original_size, processed_size, transform_back, geometry, confidence, uncertainty, valid}。bbox 要说明 xyxy 或 xywh、是否归一化、端点是否包含；mask 要说明分辨率和插值；keypoint 要说明顺序、可见性与置信度。

若输出位于 resize/crop 后的图像，必须能按预处理几何可逆映射回原图，并用已知点做坐标测试。定性叠图可以帮助检查，却不能用“看起来对”替代像素约定、误差统计和失效样本。

从 2D 到 3D 需要额外证据

从像素 (u,v) 到三维至少需要深度或多视角几何、相机内参、畸变状态、depth-to-RGB 对齐、外参、时间同步、有效值规则和目标 frame。数据流应显式写成 2D region/keypoint + depth/stereo/point cloud + calibration + timestamps → 3D estimator → pose/volume in named frame + uncertainty。

视觉 token 即使带二维 position，也不自动包含度量关系。单目模型可能学习统计深度或空间语言，但尺度、frame、一致性与任务域性能要单独评测；上一页定义的几何与标定合同仍是必需输入。

深度与点云怎样进入模型

路径 输入形式 需要冻结 常见失败
深度作为额外图像通道 红绿蓝与深度（RGB-D）tensor scale、invalid、normalize、channel order 把 0 当近距离；预训练通道不兼容
深度独立 encoder depth token encoder、position、对齐、fusion RGB/depth crop 不一致
点云 encoder XYZ/feature points frame、unit、sampling、ordering/invariance 混 frame、密度偏差、丢小物体

SpatialVLA 是显式空间表示的论文实例，SpatialVLM 则说明定量三维能力需要专门数据和评测。两者都不构成所有 VLA 的标准组件，也不能替代目标 checkpoint 的空间精度与闭环验证。

grounding 输出必须写 consumer

每个 grounding 结果必须绑定 output schema 与坐标/图像 frame，记录 confidence、uncertainty、validity 与 OOD 状态，说明 consumer 是文本 planner、二维 servo、三维 planner、IK、action expert 还是 policy condition，并冻结 consumer 期待的单位、时间与更新频率。

不可达、歧义、多实例、遮挡或超时要有 fallback；训练标签与在线输出也要使用同一定义。没有 consumer 的 grounding 指标可能只是孤立 benchmark；有 consumer 却没有 frame 和时间的输出，可能在系统中被静默误解。

“冻结”至少拆成六个字段

字段 核验问题 常见误判

从 loss 反向追踪更新路径

选择一个 action loss，反向回答：哪些 action 位置参与、哪些被 loss mask 排除；action head/expert 怎样形成输出；条件通过 self-attention、cross-attention 或调制怎样进入；梯度能否回到 projector、state encoder、vision encoder 与 language backbone；参数是否属于 optimizer；gradient clipping、mixed precision 与冻结逻辑是否改变更新；一步之后 parameter delta 是否非零；checkpoint 是否保存并恢复这些参数与 optimizer state。

“存在梯度路径”只证明理论上可更新，不证明实际 optimizer step、有效学习或能力提升。反过来，模块参数不更新也不表示它对 loss 或输出没有因果影响；还要通过输入干预与前向对照核验。

能力验证、失效诊断与边界

分层验证，不用单一成功率替代

至少设置五层检查：静态验证输入 shape、dtype、字段、顺序与 mask；用已知像素、相机和时间扰动验证 position、frame 与 history 映射；通过交换相机、遮挡目标、打乱语言、清零状态与移动历史顺序做模态干预；为语义、二维、三维与 affordance 使用匹配输出类型的指标；最后在独立限制下评测闭环成功、恢复、延迟和失败类型。

闭环任务成功不能反向证明某个 projector、attention 模式或 grounding 模块单独正确。模型比较必须报告输入模态、相机、预处理、checkpoint、动作表示、数据、评测协议和随机性，否则不能把结果归因于架构差异。

分层结果应使用同一份样本或明确的样本映射表串联：语义判断引用哪个 image ID，二维输出引用哪个预处理变换，三维估计使用哪份深度与标定，动作条件对应哪个 decision ID，闭环结果对应哪个 episode 与失败类型。若各层在不同数据子集上报告最优数字，就不能把它们拼接成一条已经验证的端到端能力链。

验证报告还要区分未运行、不可用、失败与证据不足。输入缺失导致的 skip 不能计为通过，无法获得三维真值不能被写成“误差为零”，闭环被安全层拒绝也不能同时计作策略成功。每个指标都要保留分母、样本数、置信区间、排除规则和失败分布；这样才能判断改动影响的是感知覆盖、grounding 精度、动作条件还是最终执行。

eval 漂移或不稳定 train/eval、随机增强、dropout、精度 固定种子重复前向
cache 开启后结果陈旧 cache key、失效规则、状态/图像变化 命中日志与对照运行
attention 看似正确但输出错误 value 路径、head、因果验证缺失 输入干预，而不是 attention 图
planner 语言合理但动作不可行 grounding frame、可达性、action/adapter 分层日志与可行性检查
闭环振荡或越界 上一页的时序、单位、controller、limit 不先归咎于 VLM 一项

页面完成演练

对一个不含模型尺寸的桌面抓取系统，读者应能逐项说明：base 与 wrist RGB 各怎样预处理并进入哪个 vision encoder；patch 怎样携带相机身份、二维 position 与 capture time；语言在哪里截断和 padding；proprioception 何时采样、如何归一化、位于 prefix、suffix 还是 action expert；历史长度、顺序与 reset；projector/resampler 改变了什么、没有证明什么；action query 通过 self-attention 还是 cross-attention 读取条件；“红杯”怎样从文本指代到二维实例，再到 base frame 下三维目标；grounding 输出的 confidence、frame、time 与 consumer；vision/projector/LLM/action expert 哪些 frozen、哪些属于 optimizer、各处 train/eval；最终动作怎样进入 adapter、确定性限制与 controller。

任何一项只能回答“模型会自己学”“都是 token”“在 Transformer 里融合”或“VLM 已经理解空间”，演练不通过。完成演练仍不代表模型能力、安全性或部署可用性已经获得验证。

来源与证据边界

  • 基础架构事实：Transformer、ViT、VLM 常见接口与论文明确结构。
  • 模型论文事实：PaLM-E、RT-2、OpenVLA、π0、GR00T、SpatialVLM 与 SpatialVLA 在各自版本和实验中的结论。
  • 站内源码核验：具体模型页对固定代码/配置的 shape、mask、层和冻结行为审计。
  • 工程推导：逐模态 trace、camera contract、grounding ladder、更新矩阵与失败流程。
  • 待系统验证：目标机器人上的准确率、时延、三维精度、可行性、闭环性能与安全结论。

论文标题中的 “spatial”“embodied”“generalist” 不是能力证明，一种模型的实现也不能定义整个 VLM/VLA 类别。一手入口如下，均为离站链接：
