π0 是 Physical Intelligence 提出的通用机器人策略框架。它把预训练视觉—语言模型、按模态固定分流的动作专家、连续动作上的条件 Flow Matching、动作分块，以及跨本体的预训练—后训练配方组合到一个系统中。输入是多路图像、语言指令和本体状态；输出是一段连续动作，而不是离散动作 token。

先固定证据边界。本文的“论文”专指 arXiv:2410.24164v4；“openpi 实现”专指官方仓库 commit 215abfb。论文实验使用 18 维统一状态/动作空间；该源码版本的 Pi0Config.action_dim 类默认值是 32，具体配置仍可覆盖。两套数字属于不同层级，不能混写成一个“π0 固定参数”。

一、60 秒认识 π0

理解 π0，可以先抓住四条相互配合的主线。

从 VLM 继承视觉—语言先验PaliGemma 为图像和指令提供初始化，使机器人策略能够利用互联网图文预训练得到的语义表征。它改善的是起点和数据利用方式，不保证对所有未见物体或说法都能成功。
用动作专家处理机器人 token图像和语言 token 走较大的 VLM 专家；状态和含噪动作 token 走较小的动作专家。路由由模态固定决定，没有可学习门控；两组权重在每层的联合自注意力中交换信息。
在连续空间生成动作块π0 不把动作量化成词表，而是用 Conditional Flow Matching 学习速度场，从高斯噪声生成长度 50 的连续动作块。生成模型可以表达多峰动作分布，但 Flow Matching 并不是唯一可行方案。
用数据配方形成通用策略平台变换、统一宽度、归一化和数据混合让多种机器人进入同一模型；广覆盖预训练提供基础能力，高质量任务数据再用于后训练。补零只解决张量形状，不等于已经解决跨本体语义对齐。

这四条并不是四项彼此独立的发明。PaliGemma、Flow Matching、动作分块、跨本体训练和专家模型都已有前序工作；π0 的主要贡献是把它们整合成可训练、可实时运行并经过大规模真实机器人评测的 VLA 框架。论文也将自身贡献明确描述为以系统集成为主。

论文在 7 种自有机器人配置、68 类任务及开源机器人数据上预训练，并展示了衣物折叠、餐桌清理、纸盒组装和鸡蛋装盒等任务。能力结论必须结合实验设置理解：有些任务直接提示基础模型，有些需要任务后训练，部分长时程任务还使用高层 VLM 产生子任务指令。演示视频和任务列表可查看 官方发布页；定量结果、评分口径与局限见子页 ⑥。

三、从观测到动作：一条完整数据流

下图按固定源码的默认最大形状示例绘制：三个图像槽位、语言最多 48 个 token、action_dim=32、action_horizon=50。这不是论文所有机器人的固定输入；论文中的机器人使用 2 或 3 路图像，缺失图像槽位由 mask 处理，论文统一状态/动作宽度是 18。

flowchart TB
  IMG["最多三路图像槽位<br/>各 224 x 224 x 3"] --> SIG["SigLIP So400m/14"]
  SIG --> IT["每路 256 个图像 token<br/>宽度 2048"]
  TXT["语言指令<br/>最多 48 个 token"] --> LT["Gemma 词嵌入<br/>宽度 2048"]
  IT --> PRE["图像—语言 prefix<br/>走 VLM 专家"]
  LT --> PRE
  ST["本体状态<br/>源码默认补齐到 32 维"] --> SP["state_proj"]
  SP --> STT["1 个 state token<br/>宽度 1024"]
  NOI["含噪动作块<br/>50 x 32"] --> AP["action_in_proj"]
  TIME["流时间"] --> PE["正弦余弦编码"]
  AP --> MIX["动作—时间融合 MLP"]
  PE --> MIX
  MIX --> AT["50 个动作 token<br/>宽度 1024"]
  STT --> SUF["state—动作 suffix<br/>走动作专家"]
  AT --> SUF
  PRE --> TR["18 层双专家 Transformer<br/>在联合自注意力中交互"]

默认最大形状下，图像 token 为 \(3\times256=768\)，语言槽位最多 48，因此图像—语言 prefix 最长 816；suffix 包含 1 个 state token 与 50 个动作 token，共 51 个槽位，逻辑序列最长 867。

这里的“867”只是逻辑槽位数，不是一个统一的 \(867\times width\) 隐状态张量。VLM 专家宽度是 2048，动作专家宽度是 1024；两侧分别计算投影，并在兼容的注意力头空间中联合计算自注意力。

当前 openpi 推理会先计算并缓存图像—语言 prefix，然后在每个积分步重新构造整个 suffix。因此 state 虽然在十个积分步中不变，固定提交仍会重复计算它。论文的三块掩码使 state 在算法上具备缓存条件，但“设计允许缓存”不等于“当前源码已经缓存”。

为什么动作专家较小。多步生成会重复运行动作侧前向。论文明确把动作专家缩小到宽度 1024、MLP 维度 4096，动机是降低重复推理成本；它没有证明“动作天然比语言简单”，也没有证明约 300M 是唯一合理规模。

四、Flow Matching 的最小数学闭环

记观测为 \(o\)，真实动作块为 \(A\)，同形状高斯噪声为 \(\epsilon\sim\mathcal N(0,I)\)。论文 v4 采用“\(\tau=0\) 是噪声、\(\tau=1\) 是数据”的约定：

\[A^{\tau}=\tau A+(1-\tau)\epsilon, \qquad u^{\tau}=\frac{\partial A^{\tau}}{\partial\tau}=A-\epsilon.\]

训练网络拟合这个条件速度目标：

\[\mathcal L(\theta)= \mathbb E_{o,A,\epsilon,\tau} \left[ \left\lVert v_{\theta}(A^{\tau},o,\tau)-(A-\epsilon)\right\rVert_2^2 \right].\]

固定 openpi 源码使用相反坐标 \(t=1-\tau\)，因此 \(t=1\) 是噪声、\(t=0\) 是数据：

\[A^t=t\epsilon+(1-t)A, \qquad u^t=\epsilon-A.\]

推理从 \(A^1\sim\mathcal N(0,I)\) 开始，默认用 \(K=10\) 个负步长 Euler 更新：

\[A_{k+1}=A_k+\Delta t\,v_{\theta}(A_k,o,t_k), \qquad \Delta t=-\frac{1}{K}, \qquad t:1\rightarrow0.\]

两套公式描述同一个生成方向；符号和积分方向必须成对转换，不能只改速度目标的正负号。

“速度恒定”只对逐样本条件目标成立。固定一对 $$(A,\epsilon)$$ 后，线性条件路径的导数确实不依赖流时间；网络学习的边际速度场是给定当前含噪动作和观测后的条件期望，通常随位置、观测和时间变化，生成 ODE 的实际轨迹也不保证是直线。Flow Matching 还可以选择其他概率路径，直线是 π0 的具体选择，不是该方法的定义。

论文版本还需单独标记：历史 v3 的目标符号与其积分方向不一致，v4 已修正；v4 仍把高斯路径的协方差写成 \((1-\tau)I\)，而随后给出的采样式使用噪声系数 \((1-\tau)\)，后者对应协方差 \((1-\tau)^2I\)。复现时应以明确的采样式和目标场为准。完整推导见子页 ② Flow Matching，版本与时间换算见子页 ③ 时间方向。

五、动作块与跨本体接口

π0 建模的是整个未来动作块的条件分布：

\[A_r=[a_r,a_{r+1},\ldots,a_{r+H-1}], \qquad H=50, \qquad p(A_r\mid o_r).\]

这里用下标 \(r\) 表示机器人控制时间，避免与流时间 \(t\) 或 \(\tau\) 混淆。一次生成整块可以显式建模动作间的时间相关性，并减少块内逐动作自回归生成造成的误差传播；但执行期间仍可能因观测陈旧、扰动或动力学误差偏离轨迹。

论文采用块内开环、块间重规划：20 Hz 的 UR5e 和 Franka 执行 16 步、约 0.8 秒后重新推理；其他 50 Hz 机器人执行 25 步、约 0.5 秒后重新推理。因此模型虽然预测 50 步，实际并不会默认把整块全部执行。论文报告早期尝试 temporal ensembling 会降低性能，因而没有融合相邻推理调用的动作；论文没有给出经过验证的原因机制。

跨本体时，论文将状态和动作补零到数据集中最大宽度 18；固定源码先进行平台相关映射和归一化，再补齐到模型配置的 action_dim，其类默认值为 32。补零只统一张量形状，还必须保证关节顺序、动作坐标系、绝对/增量控制、夹爪定义、控制频率和归一化统计一致。

固定提交的 π0 损失对动作维度取均值，没有用逐动作维度 mask 排除补零项，因此补零位置也受到零目标约束。不要把它与“缺失图像槽位使用 image mask”混为一谈。

六、训练与推理不要混为一条路径

环节 训练 推理
动作输入 真实动作与随机噪声的插值 高斯噪声初始化，随后反复更新整块动作
流时间 每个样本采一个时间点 默认从 1 到 0 积分 10 步
Transformer 调用 一次完整训练前向 一次 prefix 前向加十次 suffix 前向
当前源码缓存 不需要跨积分步缓存 缓存图像—语言 prefix；state 与动作 suffix 每步重算
网络输出 与目标速度做均方误差 乘负步长并累加到当前动作状态
推理权重 不适用 取决于后端和训练配置；不能一概写成 EMA 权重

“十一次前向”不等于完整网络重复运行十一次：图像编码和图像—语言 prefix 只运行一次，十次重复的是较短的 suffix。训练时也不是执行十次去噪，而是为每个训练样本随机采一个流时间并进行一次前向。

数值 所属层级 应怎样理解
动作宽度 18 论文实验 对应论文跨本体数据中的最大状态/动作宽度
action_dim=32 固定源码的类默认值 可被具体模型配置覆盖，不是 π0 理论常数
action_horizon=50 论文与固定源码默认值 预测长度；实际执行通常提前重规划
num_steps=10 论文实验与源码默认值 推理期可改，但速度、离散化误差和任务表现需重新评估
max_token_len=48 固定源码 π0 默认分支 π0.5 分支为 200；不是论文给出的模型定律
num_train_steps=30000 TrainConfig 类默认值 具体命名配置可覆盖，不能据此判断预训练或后训练阶段
ema_decay=0.99 TrainConfig 类默认值 EMA 可关闭或覆盖；固定提交的 PyTorch 训练不支持 EMA

七、创新点、证据与能力边界

7.1 应当怎样概括创新

动作专家接口在预训练 VLM 中加入机器人状态和连续动作 token，并给这些 token 配置独立、较小的专家权重；两侧通过联合自注意力交换信息。
连续高频动作生成把 Conditional Flow Matching 用于长度 50 的连续动作块，并用缓存和较小动作专家组织多步推理。作者将其称为据其所知首个此类高频 Flow Matching VLA。
基础模型训练框架把跨本体数据混合、基础预训练、任务后训练、语言条件和真实机器人部署组织成一套完整配方，而不是只提出一个动作头。
大规模真实机器人验证论文覆盖直接提示、语言跟随、新技能适配和复杂多阶段任务，展示了系统级可行性；实验结论应按评分 rubric、任务后训练和高层策略条件分别阅读。

7.2 哪些不能被写成已证实因果

  • π0-small 不只是“去掉 VLM 初始化”：它还改变模型规模、语言编码器、视觉编码器、编码器—动作专家交互方式、视觉权重共享和时间注入结构。因此该对比支持整套 VLM 路线，但不能定量隔离“纯 VLM 预训练收益”。
  • 论文没有分别消融证明 shifted-Beta、10 步 Euler、300M 动作专家或每一项掩码设计各自贡献了多少最终性能。
  • temporal ensembling 在 π0 上降低性能是实验观察，不能在没有证据时补写原因。
  • 73 ms 是 RTX 4090、三路图像和 10 个积分步下的论文测量；板外推理另有 13 ms 网络延迟，总计 86 ms。它不是所有硬件和配置的通用延迟。
  • 论文评测多数使用任务进度 rubric 的归一化得分，不能统一改称“成功率”。

7.3 最容易混淆的六件事

容易误解的说法 更准确的表述
π0 是在 VLM 后面接一个独立动作解码器 主模型更接近一个带两套模态专家权重的逻辑 Transformer；两侧逐层联合注意，而不是串联的编码器—解码器
π0 就是标准稀疏 MoE 它与 MoE 类似，但按模态固定路由，没有可学习 router 和负载均衡损失
使用 MSE 就一定会平均掉多峰动作 单输出 MSE 在条件分布多峰且观测不能消除歧义时趋向条件均值；并非所有任务都会出现该问题
Flow Matching 的速度场是常量 线性条件路径的逐样本目标是常量；网络学习的边际速度场不是
10 个积分步就是机器人执行 10 步 每个积分步都更新完整的 50 步动作块；积分时间与机器人控制时间是不同维度
论文与源码只是符号方向不同，所以两边所有公式都正确 v4 与源码可通过变量换元对应；历史 v3 有目标符号问题，v4 仍有协方差记号与采样式不一致

八、与后续版本的关系

  • π0.5 把重点扩展到开放世界泛化、异构数据共训练和高层—低层协作。固定 openpi 代码中，pi05=True 还会把状态放入离散 prefix、把语言长度上限改为 200，并改用 adaRMSNorm 注入流时间；这些实现差异不能反向当作 π0 论文定义。
  • π0.6 进一步研究从自主 rollout、人工纠错和价值信号中迭代改进策略。其训练系统和证据应在 π0.6 专题中独立核对，本页不把后续版本简单概括成“只修复 π0 的一个短板”。
