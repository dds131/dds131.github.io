注意力（attention）是一个很小的算子：对一组值做加权求和，权重由查询与键的相关性决定。它能撑起从 BERT 到 π0 的整条路线，不在于复杂，而在于它同时解决了长程依赖、并行化与跨模态融合三件原本互相牵制的事。本页把这个算子逐项拆开，重点放在「为什么这么设计」而不是「它是什么」。

64每头维度 d_k
2048base 配置 d_ff
6编码器 / 解码器层数

本页所有具体数值均出自 Attention Is All You Need 正文与 Table 3，文中会标出处。凡未能在论文里核实的数字一律写成定性描述。

问题起点：顺序依赖与上下文瓶颈

循环网络（RNN, recurrent neural network）及其门控变体 LSTM、GRU 维护一个随时间更新的隐状态：第 t 步的隐状态由第 t-1 步的隐状态与第 t 个输入共同决定。这个定义带来两个无法通过调参绕开的限制。

第一，长程依赖弱。 第 1 个位置的信息要影响第 n 个位置，必须逐步穿过 n 次矩阵乘法与非线性变换；反向传播时梯度沿同一条链回传，每步乘上一个雅可比矩阵，连乘结果要么指数衰减（梯度消失）要么指数放大（梯度爆炸）。LSTM 的门控让梯度在记忆单元这条支路上更接近恒等映射，缓解了衰减速度，但交互路径长度随距离线性增长这一点没有改变。

第二，无法并行。 第 t 步的计算需要第 t-1 步的输出，这是结构性的顺序约束，加再多显卡也消除不掉。训练一条长度为 n 的序列至少要串行 n 步，序列越长，GPU 利用率越低。

固定长度上下文向量的瓶颈

早期的编码器-解码器（seq2seq）翻译模型在此之上还叠了一层问题：编码器把整个源句压成一个固定长度的向量，解码器再从这个向量展开出目标句。这隐含了一个不成立的假设——任意长度的句子都能被无损压进同一个固定维度。实际后果是句子越长、需要塞进去的信息越多而容量不变，翻译质量随源句长度明显下降。

注意力的原始动机就是取消这个瓶颈：解码第 i 个目标词时不再只读那个压缩向量，而是回头对源句的全部隐状态做一次加权求和，权重由当前解码状态与各源位置的相关性给出，需要哪个位置的信息就把权重压到哪里。

再往后的关键一步是：既然「按相关性取值」已经承担了绝大部分跨位置的信息流动，外面那层 RNN 就成了纯粹的负担——它带来顺序约束却不再提供不可替代的功能。去掉 RNN、只保留注意力，再用位置编码把丢掉的顺序信息补回来，就得到了 Transformer。

维度 RNN / LSTM 自注意力
最大路径长度 O(n) O(1)
顺序操作数 O(n) O(1)
每层复杂度 O(n · d²) O(n² · d)
顺序信息 由递归结构自带 必须显式注入

这是原论文 Table 1 的节选，说明这次替换本质是一次权衡：用序列长度上的平方复杂度，换取常数级的路径长度与顺序操作数。n 小于 d 时这笔交易划算；n 很大时平方项就成了新瓶颈，这是后面复杂度一节的主题。

注意力的一般形式：Query / Key / Value

抛开具体形式，注意力做的事可以写成一行：给定一个查询和 n 个候选，先算出 n 个权重，再用这些权重对 n 个内容加权求和。

\[\text{output} = \sum_{i=1}^{n} \alpha_i \, v_i, \qquad \sum_{i=1}^{n} \alpha_i = 1\]

所有设计上的选择都集中在一处：\(\alpha_i\) 怎么算。QKV 这套记法给出的答案是——把「用来算权重的东西」和「被加权的东西」分开表示。

记号 名称 语义 形状（单头）
Q (query) 查询 当前位置「我要找什么」 n_q × d_k
K (key) 键 各候选位置「我有什么特征可以被检索到」 n_kv × d_k
V (value) 值 各候选位置「被选中后我实际提供什么」 n_kv × d_v

这套分工相当于一次软性的字典查找：查询与所有键逐一比对相似度，但不像哈希表那样只命中一项，而是把所有项按相似度加权取回。「软」体现在权重连续可导，因此整个过程能端到端训练。三者都由输入经各自的线性变换得到：

\[Q = X_q W^Q, \qquad K = X_{kv} W^K, \qquad V = X_{kv} W^V\]

Q 的输入 \(X_q\) 与 K、V 的输入 \(X_{kv}\) 可以相同也可以不同，这一点决定了它是自注意力还是交叉注意力。

为什么 K 和 V 必须分开

如果令 K = V，即用同一份表示既承担「被检索」又承担「被取用」，会有两个问题。

第一，两个角色的最优表示不一致。 键需要的是判别性，只要能让正确的查询与它对齐、错误的查询远离它就够了，方向比幅值更重要；值需要的是信息量，要携带下游真正需要的内容，幅值和各个分量都有意义。绑成一份表示等于强迫一个向量同时在两个目标下最优，必然互相妥协。

第二，维度无法解耦。 键的维度受制于点积，必须与查询一致；值的维度决定输出宽度，本可独立选择。共用一份表示就把这两个自由度绑死了。原论文 base 配置恰好取 \(d_k = d_v = 64\)，但这是选择而非约束。

分开之后还有一个直接的工程收益：推理时可以缓存 K 和 V。自回归生成时前面位置的 K、V 不再改变，缓存起来（KV cache）就能避免每生成一个 token 重算整条序列。π0 的分块掩码能省下大量推理开销，靠的正是这个性质。

为什么用点积算相关性

原论文比较了两类打分方式：加性注意力把查询与键拼接后过一个带隐层的前馈网络，表达能力略强但需要额外参数，且无法写成一次矩阵乘法；点积注意力直接做内积，没有额外参数，整批查询与整批键的分数用一次 \(QK^{\top}\) 就能算完。论文指出两者理论复杂度相近，但点积形式在实践中更快也更省显存，因为它能直接调用高度优化的矩阵乘法内核。这个纯工程理由决定了后来所有主流实现的形式。

Scaled Dot-Product Attention

\[\text{Attention}(Q,K,V)=\text{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V\]

逐项拆开：

  • \(QK^{\top}\)：形状 n_q × n_kv 的注意力分数矩阵，第 (i, j) 项是第 i 个查询与第 j 个键的内积，即两者未归一化的相关性。
  • \(1/\sqrt{d_k}\)：缩放因子，把分数的方差拉回到与维度无关的量级，下一小节展开。
  • \(\text{softmax}(\cdot)\)：按行归一化，使每行权重非负且和为 1。是按行不是按列——每个查询独立地在所有键上分配自己的注意力预算。
  • 右乘 \(V\)：用权重矩阵对值加权求和，输出形状 n_q × d_v。
flowchart LR
  X["输入 X<br/>n x d_model"] --> WQ["线性 W_Q"]
  X --> WK["线性 W_K"]
  X --> WV["线性 W_V"]
  WQ --> Q["Q<br/>n x d_k"]
  WK --> K["K<br/>n x d_k"]
  WV --> V["V<br/>n x d_v"]
  Q --> MM1["矩阵乘 Q x K 转置"]
  K --> MM1
  MM1 --> S["分数矩阵<br/>n x n"]
  S --> SC["除以 d_k 的平方根"]
  SC --> MK["加掩码<br/>被屏蔽处置为负无穷"]
  MK --> SM["按行 softmax"]
  SM --> W["权重矩阵<br/>n x n 每行和为 1"]
  W --> MM2["矩阵乘 权重 x V"]
  V --> MM2
  MM2 --> O["输出<br/>n x d_v"]

图里有两处值得留意。一是中间那个 n × n 方阵，规模只与序列长度有关、与特征维度无关，这是显存瓶颈的来源。二是掩码加在 softmax 之前，做法是把要屏蔽位置的分数置为负无穷，softmax 之后对应权重恰为 0；若放在 softmax 之后再置零，剩余权重之和就不再是 1，还需重新归一化。

为什么要除以 d_k 的平方根

缩放因子看上去只是个数值技巧，实际上决定了模型在高维下能不能训得动。

方差分析。 设查询向量 q 与键向量 k 的各分量相互独立、均值为 0、方差为 1，它们的内积是

\[q \cdot k = \sum_{i=1}^{d_k} q_i k_i\]

对单项而言，由独立性有 \(\mathbb{E}[q_i k_i] = \mathbb{E}[q_i]\mathbb{E}[k_i] = 0\)，而 \(\mathrm{Var}(q_i k_i) = \mathbb{E}[q_i^2 k_i^2] = \mathbb{E}[q_i^2]\mathbb{E}[k_i^2] = 1\)。各项之间同样独立，方差可加，于是

\[\mathbb{E}[q \cdot k] = 0, \qquad \mathrm{Var}(q \cdot k) = d_k\]

也就是说，点积的标准差随维度按平方根增长。base 配置下 \(d_k = 64\)，标准差为 8；若不切多头、直接用 \(d_k = 512\)，标准差约为 22.6。维度越高，分数的动态范围越大。

为什么大方差有害。 softmax 对输入的差值敏感。当一行分数中最大值远大于其余值时，softmax 输出趋近独热向量，此时它的雅可比 \(\partial p_i / \partial z_j = p_i(\delta_{ij} - p_j)\) 中每一项都趋于 0：被选中的位置 \(p_i \to 1\) 使 \(p_i(1-p_i) \to 0\)，其余位置 \(p_i \to 0\) 同样使乘积趋于 0。梯度几乎无法回传，这一层进入了饱和区。后果不只是训练慢：饱和意味着注意力权重在训练早期就被随机初始化的分数锁死成近乎硬性的选择，模型失去了在候选之间重新分配权重的能力，等于把一个本应可学习的软性检索退化成固定路由。

缩放做了什么。 除以 \(\sqrt{d_k}\) 之后，\(\mathrm{Var}(q \cdot k / \sqrt{d_k}) = d_k / d_k = 1\)，分数方差被拉回 1 且与维度无关。这样无论 \(d_k\) 取多少，softmax 的输入都在同一量级上，既不会一开始就饱和，又保留了后续通过学习把权重推向尖锐分布的空间。原论文脚注给出的正是这个理由。

这里的假设（各分量独立、零均值单位方差）在初始化时近似成立，训练之后未必严格成立。缩放因子解决的主要是初始化阶段的尺度问题，让训练能够启动；训练稳定后真正维持尺度的是层归一化。二者互补，不是替代关系。

Multi-Head Attention

一次 softmax 只产生一组归一化权重。由于权重非负且和为 1，注意力预算是稀缺的：给某个位置的多了，别处必然少。这意味着单头注意力在一层里只能表达一种对齐模式。但序列中的关系通常是多种的——同一层可能既要关注句法上的支配关系，又要关注语义上的指代关系，还要关注局部的相邻关系。强迫它们共享同一组权重，模型只能学出一个折中。

多头的做法是做 h 次相互独立的注意力，各自有各自的投影矩阵，最后拼接：

\[\text{MultiHead}(Q,K,V) = \text{Concat}(\text{head}_1, \dots, \text{head}_h)\,W^O, \qquad \text{head}_i = \text{Attention}\left(QW_i^Q,\; KW_i^K,\; VW_i^V\right)\]

关键约定是总维度不变、按头平分：\(d_k = d_v = d_{\text{model}} / h\)。base 配置下 \(d_{\text{model}} = 512\)、\(h = 8\)，于是每头 \(d_k = d_v = 64\)。

flowchart TB
  IN["输入 X<br/>n x 512"] --> P["三组线性投影<br/>W_Q W_K W_V"]
  P --> SP["按头切分<br/>512 拆成 8 份 每份 64"]
  SP --> H1["head 1<br/>n x 64"]
  SP --> H2["head 2<br/>n x 64"]
  SP --> HD["其余各头"]
  SP --> H8["head 8<br/>n x 64"]
  H1 --> A1["缩放点积注意力<br/>除以 64 的平方根"]
  H2 --> A2["缩放点积注意力"]
  H8 --> A8["缩放点积注意力"]
  A1 --> CC["沿特征维拼接<br/>8 x 64 = 512"]
  A2 --> CC
  HD --> CC
  A8 --> CC
  CC --> WO["输出投影 W_O<br/>512 x 512"]
  WO --> OUT["输出<br/>n x 512"]

拼接之后必须再过输出投影 \(W^O\)，这一步不能省：拼接只是把 h 个子空间的结果并排放好，各头之间还没有发生任何交互，\(W^O\) 负责把它们线性混合成下一层可用的统一表示。

为什么多头几乎不增加计算量

这一点常被误解为「多头是用算力换效果」，实际不是。考虑投影部分：单头且 \(d_k = d_{\text{model}}\) 时，\(W^Q\) 规模是 \(d_{\text{model}} \times d_{\text{model}}\)；多头时每个 \(W_i^Q\) 规模是 \(d_{\text{model}} \times (d_{\text{model}}/h)\)，共 h 个，合计 \(h \times d_{\text{model}} \times (d_{\text{model}}/h) = d_{\text{model}}^2\)，与单头完全相同。实现上根本不需要 h 个独立矩阵，只用一个 \(d_{\text{model}} \times d_{\text{model}}\) 的大矩阵做投影，再把结果 reshape 成 (h, n, d_k)，切分是一次视图变换，不产生额外计算。注意力部分同理：单头是一个 n × n、内层维度 \(d_{\text{model}}\)；多头是 h 个 n × n、内层维度 \(d_{\text{model}}/h\)，乘法次数合计相同。

所以多头的准确说法是：在总计算预算不变的前提下，把一个高维空间换成 h 个低维子空间。代价是每个子空间的表达能力下降（d_k 从 512 降到 64），收益是能同时表达 h 种对齐模式。原论文的结论是这笔交易划算，但也指出头数过多、每头维度过小时效果会回落。

三种注意力的区别

同一个算子，因 Q 与 K、V 的来源不同、掩码不同，用在了三个完全不同的位置。

    SX --> SV["V"]
  end
  subgraph CA["交叉注意力 cross-attention"]
    CY["目标序列 Y"] --> CQ["Q"]
    CX["源序列 X"] --> CK["K"]
    CX --> CV["V"]
  end

    MQ --> MOUT
  end
类型 Q 来自 K / V 来自 掩码 典型位置
自注意力 同一序列 同一序列 无（或填充掩码） 编码器每一层；ViT 全部层
交叉注意力 目标序列 源序列 通常只有填充掩码 解码器中间子层；ACT 的动作解码
因果自注意力 同一序列 同一序列 上三角掩码 解码器首个子层；自回归 LLM

自注意力的 Q、K、V 全部由同一条序列投影得到，每个位置都能看到序列中所有位置（含自身），作用是在一层内完成全局上下文融合。需要注意它对输入是置换等变的：打乱输入顺序，输出只是跟着一起打乱，模型无法察觉顺序变了，因此顺序信息必须由位置编码显式补入。

交叉注意力的 Q 来自一条序列、K 与 V 来自另一条，是跨序列与跨模态融合的标准手段：Q 那一侧决定输出有多少个位置，K/V 那一侧提供被检索的内容，两条序列的长度和维度都可以不同。ACT 的解码器就是这样工作的——一组固定数量的 query token 通过交叉注意力去读编码器输出的视觉与状态特征，query 的数量直接等于动作块的长度。理解了「Q 那一侧决定输出长度」，就理解了为什么改动作块长度只需要改 query 的个数。

因果自注意力结构上是自注意力，但加了上三角掩码，禁止位置 i 看到任何 j > i 的位置。实现上构造一个布尔矩阵，把需要屏蔽的分数置为负无穷再过 softmax：

mask = torch.triu(torch.ones(n, n, dtype=torch.bool), diagonal=1)
scores = scores.masked_fill(mask, float("-inf"))
weights = torch.softmax(scores, dim=-1)

用负无穷而不是一个很小的有限值，是为了让 softmax 之后的权重精确为 0；有限值会残留极小但非零的泄漏，深层堆叠后可能累积。因果掩码存在的理由是训练与推理的一致性：推理时第 i 个 token 生成时后面的 token 还不存在，若训练时允许看到，模型就学会了依赖推理时拿不到的信息。有了掩码，一条长度为 n 的序列可以在一次前向里同时得到 n 个位置的训练信号，而每个位置的可见范围都与推理时一致。

联系：π0 的分块注意力掩码

π0 用的既不是纯双向也不是纯因果，而是一个分块掩码：序列切成 prefix（图像与语言 token）和 suffix（状态与含噪动作 token），prefix 内部双向可见，suffix 能看到 prefix 与自身，但 prefix 看不到 suffix。

这说明掩码并不局限于「全可见」与「上三角」两种，它本质上是一个可以自由指定的布尔矩阵，按任意的信息流拓扑来画即可。π0 这样画的收益非常具体：prefix 的表示不依赖 suffix，而推理时要做多步去噪、每步 suffix 都在变，于是 prefix 的 KV cache 只需算一次就能复用，2B 参数的主干不必每步重跑。掩码设计在这里不是理论上的讲究，而是决定模型能否上真机的工程选择。

计算与显存复杂度

设序列长度为 n、模型维度为 d，整个注意力分五步：

步骤 运算 复杂度
QKV 投影 n × d 乘 d × d，三次 O(n · d²)
计算分数 n × d 乘 d × n O(n² · d)
softmax 对 n × n 逐元素 O(n²)
加权求和 n × n 乘 n × d O(n² · d)
输出投影 n × d 乘 d × d O(n · d²)

平方项只来自两处：分数矩阵的计算和用权重矩阵去乘 V。两者都必须遍历所有查询-键配对，配对数就是 n²。这不是实现不好，而是「任意两个位置直接连边」这个定义的必然代价——路径长度降到 O(1) 的另一面，就是边数升到 n²。投影部分是 O(n · d²)，与序列长度只是线性关系；因此 n 远小于 d 时投影是主要开销，n 接近或超过 d 时注意力部分开始主导。

显存瓶颈在注意力矩阵而非参数

一层注意力的参数量是四个 d × d 的投影矩阵，约 4d²，与序列长度无关；而中间激活里那个分数矩阵是 b × h × n × n（b 是批大小，h 是头数），与序列长度成平方关系：

\[\text{注意力矩阵显存} \;\propto\; b \cdot h \cdot n^2\]

反向传播需要保留前向中间结果，这个矩阵通常要存两份以上（softmax 前的分数与 softmax 后的权重）。于是出现一个常见现象：模型参数只有几百 MB，权重加优化器状态都装得下，但把序列长度翻一倍就立刻显存溢出——溢出的是激活，不是参数。相应的应对手段也就清楚了：减小批大小、减小序列长度、用梯度检查点以时间换显存，或换一个不显式构造这个矩阵的实现。

FlashAttention 这类工作在优化什么

标准实现会把完整的 n × n 分数矩阵写进显存（HBM），再读回做 softmax，再写回，再读回乘 V。计算本身并不慢，慢的是这几趟显存读写——现代 GPU 的算力增长远快于显存带宽增长，这类算子是访存受限而非算力受限的。

FlashAttention 的核心思路是分块计算加在线归一化：把 Q、K、V 切成能放进片上 SRAM 的小块，在片上完成一个块的分数计算、softmax 累积与加权求和，只把最终输出写回显存，完整的 n × n 矩阵从不落地。softmax 需要全局的归一化分母，它通过维护运行中的最大值与累加和在线修正已算出的部分结果，因此结果与标准实现在数值上等价，不是近似。反向传播时不保存注意力矩阵而是重算，用少量额外算力换掉大量访存与显存占用。

需要区分两类工作：FlashAttention 这类做的是精确注意力的 IO 优化，复杂度仍是 O(n²)，省的是常数与显存；稀疏注意力、线性注意力那类改的是算法本身，把复杂度降到次平方，代价是不再精确。二者可以叠加使用。

关键参数配置与原因

原论文 Table 3 给出的两套配置如下，本节逐项说明取值理由与配错的后果。

参数 base big 含义
N 6 6 编码器 / 解码器层数
d_model 512 1024 模型主干维度
d_ff 2048 4096 前馈网络隐层维度
h 8 16 注意力头数
d_k = d_v 64 64 每头维度
P_drop 0.1 0.3 dropout 比例
warmup 4000 4000 学习率预热步数

d_model

典型取值 base 512、big 1024，后来的大模型普遍在数千量级。为什么这么配：它是贯穿网络的残差流宽度，每层的输入输出都是这个维度，决定了模型能携带的信息带宽；同时是参数量的主导因子——注意力投影是 O(d_model²)，前馈是 O(d_model · d_ff)，都随它平方增长。配错了会怎样：太小则表示能力不足，模型在训练集上就欠拟合，加数据也不涨；太大则参数量与显存平方增长，数据不足时过拟合且训练成本迅速失控。它还必须能被 h 整除，否则维度切分对不齐。

h（头数）与 d_k

典型取值 h 取 8 或 16，d_k 取 64，两者通过 \(d_k = d_{\text{model}} / h\) 关联。为什么这么配：头数决定同一层能并行表达多少种对齐模式，d_k 决定每种模式的分辨率，总预算固定时二者此消彼长。64 是原论文的经验选择，在多数后续工作里被沿用。配错了会怎样：h 过小则一层只能表达少数几种关系，需要靠堆层数补偿；h 过大则 d_k 被压得很小，每个头能容纳的判别信息不足，注意力分布趋于噪声化，原论文的消融实验中头数过多时效果确实回落。此外 d_model 不能被 h 整除会直接导致实现报错。

d_ff

典型取值 \(d_{\text{ff}} = 4 \times d_{\text{model}}\)，base 下即 2048。为什么这么配：前馈网络是逐位置独立作用的两层 MLP，先升维再降维。注意力负责位置之间的信息交换，前馈负责每个位置内部的非线性变换，分工明确；中间放大是为了给非线性提供足够宽的空间，四倍是原论文取值，后续工作大多沿用这个比例。配错了会怎样：太小会成为容量瓶颈，注意力混合来的信息没有足够的非线性去加工；太大则前馈会主导参数量与计算量（四倍时它已占每层参数的多数），性价比下降。

dropout 的位置

典型取值 base 0.1，big 0.3。为什么这么配：原论文把 dropout 加在三处——每个子层的输出（在残差相加与归一化之前）、词嵌入与位置编码之和，常见实现还会在 softmax 之后的注意力权重上再加一次。加在子层输出上是为了让残差支路不至于完全依赖单一路径；加在注意力权重上是为了防止模型把注意力固定在少数几个位置。big 把比例提到 0.3，是因为参数量翻倍后过拟合风险上升，需要更强的正则。配错了会怎样：比例过高会让训练信号噪声过大，收敛慢且欠拟合；过低在中小数据集上过拟合明显。位置放错的后果更隐蔽——例如加在残差相加之后，会破坏恒等映射路径，深层堆叠时训练稳定性下降。

pre-norm 与 post-norm

这是对训练稳定性影响最大的一个结构选择。post-norm 是原论文的做法，pre-norm 是后续大模型的普遍做法：

\[\text{post-norm:}\quad x_{l+1} = \text{LayerNorm}\left(x_l + \text{Sublayer}(x_l)\right)\] \[\text{pre-norm:}\quad x_{l+1} = x_l + \text{Sublayer}\left(\text{LayerNorm}(x_l)\right)\]

差别只在归一化放在残差之内还是之外，后果却很不一样。post-norm 里归一化在残差相加之后，残差路径不是恒等的——每经过一层信号都要被重新归一化，梯度回传时逐层被缩放，层数一深初始阶段的梯度尺度就不受控，因此必须配学习率预热（原论文用 4000 步）把前期更新幅度压住，否则容易发散。pre-norm 把归一化挪到子层内部，从输入到输出存在一条完全恒等的残差通路，梯度可以不经缩放地直达浅层，代价是残差流幅值随层数累积增长，通常需要在最后再补一次归一化。

对比项 post-norm pre-norm
残差路径 非恒等，逐层被归一化 恒等
学习率预热 基本必需 可省去或大幅缩短
深层稳定性 较差 较好
最终效果 调好后通常略优 稍逊，但更容易调出来

配错了会怎样：用 post-norm 且忘记加 warmup，深层模型很可能在最初几百步就发散，表现为损失变成非数值；用 pre-norm 而不在最后补一次归一化，输出幅值会随深度漂移，影响输出头的数值稳定性。当前多数大模型选 pre-norm，取的是训练可靠性而非极限效果。
