VLA 总览/DexGraspVLA/扩散建模与 Immiscible Diffusion

④ DIFFUSION · 50 TRAIN LEVELS · 16 DDIM CALLS

Architecture 交付条件 token 与当前带噪动作表示；Diffusion 定义归一化 64×13 动作块怎样加噪、匹配噪声、学习 epsilon 并经 16 次 DDIM 调用还原。50、16、64、6 分别属于四种不同计数，不能互换成控制周期。

返回专题总览上一知识点：③ 观测编码器与 DiT 架构下一知识点：⑤ 训练流程与超参数
epsilon predictionsquaredcos_cap_v2local-batch assignmentruntime not measured
50训练 scheduler 的离散噪声档位
16一次采样中的 DiT 前向次数
64 × 13生成动作块的 horizon 与维度
6Inference 每轮执行的动作前缀

首屏时间边界。 训练时，每个样本只抽一个 k∈[0,49] 并调用一次 DiT；推理时，一次动作块采样在 16 个 scheduler 索引上各调用一次 DiT；输出含 64 个动作位置；机器人执行前 6 个后重新观测与采样。前两项属于扩散计算，后两项属于动作与系统时间，不能写成“50/16/64/6 个控制周期”。

一、页面责任、固定证据与 Architecture 入站

本页固定 DexGraspVLA 论文 arXiv:2502.20900v5、官方 commit 0144c7928817c5149ae836da2682291360828a21、Immiscible Diffusion arXiv:2406.12303v2 与 diffusers 0.32.1。DexGraspVLA 论文与源码负责动作块、目标、配置和调用顺序；Immiscible 原论文只支撑方法动机及其自身实验范围；固定依赖负责 beta 构造、时间步 spacing、裁剪、eta 与最后一步边界。原方法的图像实验或加速结果不能迁移成 DexGraspVLA 机器人收益。

Architecture 拥有条件编码器、动作 token 和 epsilon 网络结构；本页从归一化干净动作、条件 token 与网络输出接口开始，拥有 x₀↔x_k、epsilon 目标、批内 matching 和 DDIM。数据窗口、优化器、DDP 循环、EMA 与 checkpoint 归 Training；何时重采样、执行前 6 步和线程归 Inference；结果表与消融归 Experiments；全仓调用图归 Source Code。

二、完整路径与四种计数

flowchart LR
  A[normalized clean action x0: 64×13] --> N[draw Gaussian noise]
  N --> M[training-only local-batch assignment]
  M --> K[draw one k per sample: 0..49]
  K --> X[construct x_k]
  C[condition tokens: 2740×1024] --> D[DiT predicts epsilon]
  X --> D
  D --> L[training: one all-element MSE]
  G[inference: fresh Gaussian 64×13] --> S[16 DDIM model calls: 45..0]
  C --> S
  S --> B[normalized generated block: 64×13]
  B --> U[Inference owner: unnormalize and execute first 6]
  U --> R[new observation and resample]

文本回退： 训练路径先取得归一化 64×13 动作，采样同形高斯噪声，仅在训练期做本地 batch 一一配对，然后每样本独立抽一个 0–49 档位，闭式构造 x_k，DiT 一次预测 epsilon 并计算全元素均方误差。推理路径从新采样的 64×13 高斯开始，在 45、42 直到 0 的 16 个档位调用 DiT，得到归一化动作块；反归一化和只执行前 6 步由 Inference 页面负责。

50、16、64、6 的类型不能互换
数值 单位 准确语义 不是
50 scheduler indices 训练噪声网格大小 一次 batch 的模型调用数
16 DiT forward calls 一次动作块逆采样调用数 动作步或控制周期
64 action steps 预测 horizon 本轮都要执行的步数
6 action steps 每轮执行前缀 由 16 次去噪单独决定

相机帧率、机器人控制 Hz 和 Planner 事件频率都不能从这四个数字直接推导。16 次网络计算可能影响闭环延迟，但当前证据没有隔离证明“执行 6 步”唯一由 16 次去噪造成。

这套类型划分也是排错入口：训练 loss 异常先检查 50 档配置、归一化和 timestep；采样轨迹异常再检查 16 项 timetable、epsilon 预测和裁剪；动作块 shape 由 64×13 合同约束；执行节奏、前缀消费和重规划则交给 Inference。把四类数字混在一处，会让 scheduler 问题被误诊为控制频率问题，或把系统调度问题错误归因于扩散公式。

三、条件动作分布、归一化与前向加噪

目标分布写作 p(A_t|c_t)，其中条件语义包括 head RGB、wrist RGB、target mask 和 joint state，随机变量是 64×13 动作块。同一观测允许多个轨迹模态是可能性，不是逐观测已证明事实。平方误差点估计的总体风险最优解是条件均值，但不能据此声称直接回归必然失败；充分观测、混合密度、离散化或其他多模态头也可能有效。论文未提供扩散头相对单点回归的隔离消融。

扩散作用在按训练集逐维范围映射到 [-1,1] 的动作，而非原始关节单位。定义 x₀=A_t∈R^{64×13}、k∈{0,…,49}、高斯噪声 ε 与条件 c_t。状态和图像使用各自预处理，不使用动作 normalizer；Immiscible 距离也在归一化且展平的动作空间计算。

\[\alpha_k=1-\beta_k,\qquad \bar\alpha_k=\prod_{i=0}^{k}\alpha_i,\] \[x_k=\sqrt{\bar\alpha_k}x_0+\sqrt{1-\bar\alpha_k}\epsilon.\]

scheduler.add_noise 可从 x₀ 一次跳到抽样档位 x_k。前向加噪本身不调用 DiT；一次训练样本随后只进行一次 DiT 预测，并不会从 0 顺序走到 k，也不会执行 50 次网络前向。标准过程在 assignment 前令基础噪声独立于数据；Immiscible 通过数据决定的置换改变 assignment 后的条件独立性。

接口验收不能只看 B×64×13 一致：还要确认 13 维顺序、每维训练范围、padding 是否参与 loss，以及 normalizer 统计来自训练 split。形状正确但统计错配，会同时改变动作尺度、matching 距离、加噪相对强度和反归一化结果。图像与状态的预处理属于条件通路，不应误套动作统计；动作 normalizer 也不负责修正条件 token。

四、50 档 scheduler 与余弦数值账本

主配置是 diffusers.DDIMScheduler：num_train_timesteps=50、beta_schedule=squaredcos_cap_v2、clip_sample=True、set_alpha_to_one=True、steps_offset=0、prediction_type=epsilon、num_inference_steps=16，默认 timestep_spacing=leading。

配置同时保留 beta_start=0.0001 和 beta_end=0.02，但固定依赖的余弦分支调用 betas_for_alpha_bar(50)：

\[g(u)=\cos^2\left(\frac{u+0.008}{1.008}\frac{\pi}{2}\right),\qquad \beta_k=\min\left(1-\frac{g((k+1)/K)}{g(k/K)},0.999\right).\]

该分支不读取 beta_start/end；这两个字段的作用是严格为零，而不是“参数太小所以近似无效”。只有切换到 linear、scaled-linear 等读取它们的分支时才会重新生效。

五、每样本 timestep、epsilon MSE 与裁剪边界

公开 compute_loss 以 torch.randint(0,50,(B,)) 为 batch 中每个样本独立、均匀抽一个整数 k；batch 内可以重复，不要求一次覆盖全部 50 档。噪声 matching 先于 timestep 抽样，其距离代价不依赖 k；之后一次 add_noise、一次模型前向和一次 MSE。

主配置输出与匹配后噪声同为 B×64×13，目标是 assigned noise。默认 torch.nn.functional.mse_loss(pred,target) 对 batch、64 个动作位置和 13 个动作维度做全元素 mean；固定 loss 没有有效动作 mask，也没有语言、分割、重建或成功分类辅助项。单一 loss 仍向所有非冻结控制模块传梯度，不等于只训练输出头；冻结 DINO 与外部 Planner、SAM、Cutie 不接收该梯度。

由前向式可反解：

\[\hat x_0=\frac{x_k-\sqrt{1-\bar\alpha_k}\hat\epsilon}{\sqrt{\bar\alpha_k}}.\]

标准独立高斯扰动下，MSE 最优预测器与 score 存在经典关系；Immiscible 后 q(ε|x₀,batch) 依赖数据与 batch，因此不能把独立高斯前提下的恒等式直接当成完整方法证明。实际优化 epsilon MSE 仍是源码事实，这一理论适用边界不是实现失败。

clip_sample=True 在每个 DDIM step 裁剪反解的 pred_original_sample 到 [-1,1]，不是先整体裁剪当前 x_k。这与动作 normalizer 区间一致，超出训练范围会在边界饱和，不是外推。公开 loss 还有 prediction_type=sample 备用分支，但主配置未启用；固定 loss 中没有 v_prediction 主路径。

全元素 mean 还意味着不同样本、动作位置和维度在固定 loss 中按元素等权；它没有显式按关节组、末端动作或有效长度重新加权。这个实现事实不等于每个维度物理重要性相同，也不证明尾部重复窗口没有影响。若未来加入 mask 或权重，loss 分母和日志尺度都会改变，Training 页面必须记录新的 reduction，而不能继续沿用这里的全元素均值结论。

六、Immiscible 的 832 维一一匹配

对本地 batch 的 B 个归一化动作块与 B 份同形高斯噪声，代码分别展平为 832 维，构造 D_ij=||A_i-ε_j||₂ 的 B×B 欧氏距离矩阵，再用 SciPy linear_sum_assignment 求最小总距离的一一置换。每个动作和每份噪声各使用一次；它只重排原始噪声，不加权、不插值、不删除，也不产生新噪声。

训练 batch 内的十一阶段静态顺序
序号 操作 关键边界
1–2 归一化动作就绪；采样同形高斯 两者均为 B×64×13
3–4 展平；`torch.cdist` 832 维；B×B L2
5–6 `dist.cpu()`；SciPy 分配 设备同步；CPU solver
7 重排原始 noise 数值集合不变
8–9 抽 k；`add_noise` solver 先于 timestep
10–11 预测 epsilon；对重排噪声 MSE 目标不是重排前索引

固定片段对 nonfinite、empty batch、shape mismatch 和 solver error 缺少完整 typed gate；assignment 索引还必须能用于原 device 上的 noise tensor。把这条 SciPy CPU 路径写成 GPU assignment 会改变事实。

一一约束保证每份已采样噪声在当前 batch 恰用一次，但不保证每个配对距离都逐项最小，也不保证不同 batch 得到相同置换。求解目标是全局总距离，因此单个样本可能接受并非其最近邻的噪声。batch 构成、动作尺度和 RNG 都会改变 cost matrix；复现 matching 时必须保存这些上下文，而不是只保存最终 assignment 索引。

七、保持噪声集合，但改变条件耦合

assignment 前，B 份噪声是 iid standard normal 且独立于动作。assignment 后，一个 batch 内的噪声 multiset 没有变化，从集合或无条件 batch 边缘看仍保留原高斯样本；但置换由动作—噪声距离和 batch 组成决定，给定动作与 batch 的噪声不再是独立标准高斯。

因此，“噪声边缘被替换成非高斯”是错误的，“训练分布完全没有变化”同样错误；方法本体是改变数据—噪声 coupling。这个区别也解释了为什么标准 score 恒等式需要单独标注前提。

Immiscible 原论文报告限制混合范围、batch linear assignment、图像域训练加速与约 2% 距离缩短，这些属于原方法证据。DexGraspVLA 的直接证据只表明采用它改善动作—噪声映射；公开材料没有 on/off、训练加速比例、机器人成功率贡献或替代距离 cost 消融，不能把原论文最高约 3× 加速迁移成该系统收益。当前因果贡献状态是 unisolated。

若要验证该模块在本系统中的作用，至少要固定数据划分、初始化、总更新数、scheduler 和评测协议，对比启用与关闭 matching，并同时报告训练曲线、墙钟开销和机器人指标。不同 cost 或跨 rank matching 属于另一项实验轴，不能混进单一 on/off 对照。本页只登记所需证据，所有这类运行态实验均保持 NOT_RUN。

八、计算复杂度、CPU 同步与 DDP 范围

主配置每 GPU 本地 batch 为 48。距离计算约 O(B²×832)，距离矩阵内存 O(B²)，线性分配通常记为 O(B³)。dist.cpu() 形成设备同步点，SciPy 在 CPU 求解；当前未做运行时测量，不能把复杂度式换成实际毫秒数。

公开实现让每个训练进程在自己看到的 local mini-batch 内独立匹配，没有跨 rank 汇总。world size 改变会改变全局 batch，却不会自动把 matching 扩展为全局 assignment。Immiscible 原论文提出的量化或多 GPU 加速不在固定实现中，不能当成已启用优化。

工程验收应记录 local batch、world size、SciPy 与 diffusers 版本，以及 CPU/GPU 同步和索引 device；若增大 batch，需要单独测量 cdist、传输和 solver，而不是只依据大 O 记号预测吞吐。本页仅登记这些复现条件，没有运行训练或 profiler。

九、DDIM 16 步时间表与更新顺序

固定 diffusers 0.32.1、50 个训练档位、timestep_spacing=leading 与 16 个推理步时，step_ratio=floor(50/16)=3，模型调用档位为：

[45,42,39,36,33,30,27,24,21,18,15,12,9,6,3,0]。

最高访问 45，46–49 不进入模型循环。它是在同一 50 档 scheduler 上选择 16 个索引，不是重新训练一条 16 档 schedule，也不是把 50 个结果平均成 16 个。

每轮动作块采样的固定档位
调用 timestep 前一 scheduler 索引
1–4 45, 42, 39, 36 每次减 3
5–8 33, 30, 27, 24 每次减 3
9–12 21, 18, 15, 12 每次减 3
13–16 9, 6, 3, 0 最后落到终端边界

每个档位先由 epsilon 预测反解 pred_original_sample，再裁剪，然后更新到前一 scheduler 索引。控制器没有传 eta，依赖默认 eta=0，因此不额外采样方差噪声。set_alpha_to_one=True 只把 k=0 之前的最终累计 alpha 边界设为 1，不会把所有 alpha 设为 1；steps_offset=0 不额外平移时间表。

“16 步”必须和“16 次模型调用”绑定，而不是理解成 16 个动作位置。条件 token 在这轮采样中可复用，但每个 scheduler 索引都需要新的 epsilon 预测；DDIM step 再根据当前样本与该预测更新。页面不据此给出实际延迟，因为网络设备、精度、batch 和实现开销都未测量；闭环是否满足目标控制频率需要 Inference 的独立时序证据。

十、条件确定性、初始随机性与 k45 起点

当 eta=0、条件、模型参数、初始噪声与数值执行都相同时，DDIM 更新是确定性的。公开 conditional_sample 每次用 torch.randn 创建新的 B×64×13 初噪声，固定调用点不传 generator；因此普通重复策略调用不保证相同结果。复现还需锁定 global seed、具体初噪声、设备算法、dtype 和依赖版本，“DDIM deterministic”不等于整条策略无随机性。

采样从标准高斯开始，但首个模型调用为 k=45，而不是 k=49。固定账本在 k45 给出 alpha_bar=0.015463760093、数据幅度系数 0.124353367839、噪声幅度系数 0.992237995597。仅在把 clean action 近似看作单位方差时，数据方差占比才约 1.546%；0.1244 是幅度系数，不能称为“含 12.44% 数据”。

纯高斯起点与前向 x_45 的精确分布匹配没有建立。论文未比较 leading 与 linspace、trailing，也没有量化这项起点差异对成功率的影响；应将其保留为 spacing ablation 未运行的边界，而不是已观察失败。

可复现性应把“条件确定”与“调用可重放”分开：即便 eta 为零，只要初噪声、条件快照、模型权重、dtype 或设备算法任一变化，输出就不必相同。反过来，保存 generator seed 也不充分，因为条件帧和 normalizer 版本仍可能漂移。合格记录应关联输入 provenance、checkpoint、scheduler 全配置与初始噪声摘要，但固定公开调用点当前没有自动提供完整记录。
