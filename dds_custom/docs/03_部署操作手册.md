## 五、提交并推送到 GitHub

```bash
# 5.1 设置提交身份
git config user.name dds131
git config user.email dds131@users.noreply.github.com

# 5.2 查看将要提交的内容
git add -A
git status --short

# 5.3 提交
git commit -m "配置 al-folio 部署到 dds131.github.io"

# 5.4 备份当前里程碑
bash dds_custom/scripts/01_backup.sh \
  al-folio.v1.1.0.config-patched-for-dds131-pages.2026.07.30 \
  "已修改配置，推送 GitHub 前的状态"
```

推送（**在宿主机执行**，以便用 `-e` 安全传入 token）：

```bash
docker exec -e GH_TOKEN='<你的PAT>' xitu_dds_linshi_project_1 bash -lc '
source /workspace/project_files/dds_web_projection_1/al-folio/dds_custom/scripts/00_env_proxy.sh
cd /workspace/project_files/dds_web_projection_1/al-folio
git -c credential.helper="!f(){ echo username=dds131; echo password=$GH_TOKEN; };f" \
    push --force https://github.com/dds131/dds131.github.io.git main:main'
```

要点：

| 要点 | 说明 |
| --- | --- |
| `credential.helper` 内联函数 | token 从环境变量读取，不进 `.git/config`、不进 argv |
| 显式 refspec `main:main` | **只推 main 分支，本地备份 tag 不会被推上去** |
| `--force` | 仅首次需要（远端原有内容与本地历史无共同祖先）。后续增量推送**不需要** |
| 不加 remote | 用完整 URL 一次性推送，仓库里不留任何指向个人账号的持久配置 |

推送后确认无残留：

```bash
docker exec xitu_dds_linshi_project_1 bash -lc '
cd /workspace/project_files/dds_web_projection_1/al-folio
git remote -v
grep -cE 'gh[p]_' .git/config 2>/dev/null || echo "无 token 残留 ✓"'
```

## 六、配置 GitHub Actions 与 Pages

以下全部可通过 API 完成，无需在网页端点击。把 `<你的PAT>` 替换为实际 token。

```bash
export HTTPS_PROXY=http://192.168.2.144:7897 HTTP_PROXY=http://192.168.2.144:7897
export GH_TOKEN='<你的PAT>'
A="Authorization: Bearer $GH_TOKEN"
R=dds131/dds131.github.io
```

### 6.1 把 Actions 的 workflow 权限设为可写

`deploy.yml` 需要写权限才能把构建产物推到 `gh-pages` 分支。

```bash
curl -s -X PUT -H "$A" -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/$R/actions/permissions/workflow \
  -d '{"default_workflow_permissions":"write","can_approve_pull_request_reviews":false}'

# 确认
curl -s -H "$A" https://api.github.com/repos/$R/actions/permissions/workflow
# 期望: {"default_workflow_permissions":"write", ...}
```

对应网页端操作：`Settings → Actions → General → Workflow permissions → Read and write permissions`

### 6.2 触发构建

> **注意**：首次强制推送（历史无共同祖先）时，`deploy.yml` 的 `paths:` 过滤器无法正常比对变更文件，
> 因此**不会自动触发**，必须手动触发一次。后续正常增量推送会自动触发。

```bash
curl -s -X POST -H "$A" -H "Accept: application/vnd.github+json" \
  "https://api.github.com/repos/$R/actions/workflows/deploy.yml/dispatches" \
  -d '{"ref":"main"}'

# 查看运行状态
curl -s -H "$A" "https://api.github.com/repos/$R/actions/runs?per_page=5" \
 | python3 -c "
import json,sys
for r in json.load(sys.stdin)['workflow_runs']:
    print(f\"{r['name'][:30]:32s} {r['status']:12s} {str(r['conclusion']):10s} #{r['run_number']}\")"
```

等待 `Deploy site` 变为 `completed success`（约 1~2 分钟），此时 `gh-pages` 分支已生成。

对应网页端操作：`Actions → Deploy site → Run workflow`

### 6.3 把 Pages 发布源设为 `gh-pages`

```bash
curl -s -X PUT -H "$A" -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/$R/pages \
  -d '{"source":{"branch":"gh-pages","path":"/"}}'

# 确认
curl -s -H "$A" https://api.github.com/repos/$R/pages
# 期望 source 为 {"branch":"gh-pages","path":"/"}
```

对应网页端操作：`Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: gh-pages / (root)`

> ⚠️ 必须选 `gh-pages`，**不能选 `main`**。
> `main` 是 al-folio 源码，GitHub 内置 Jekyll 不支持 al-folio 的插件，选 `main` 必然构建失败。

### 6.4 触发 Pages 部署（首次切换发布源后需要）

```bash
curl -s -X POST -H "$A" -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/$R/pages/builds

# 轮询直到 built
curl -s -H "$A" https://api.github.com/repos/$R/pages/builds/latest \
 | python3 -c "import json,sys; print(json.load(sys.stdin)['status'])"
```

## 七、验收

```bash
export HTTPS_PROXY=http://192.168.2.144:7897 HTTP_PROXY=http://192.168.2.144:7897

# 7.1 页面可访问性
for p in "/" "/blog/" "/cv/" "/projects/" "/publications/" "/repositories/" \
         "/teaching/" "/news/" "/people/" "/books/" "/plugins/" \
         "/sitemap.xml" "/feed.xml" "/robots.txt" "/404.html" \
         "/_pages/dropdown/" "/.nojekyll"; do
  printf "%-22s -> %s\n" "$p" "$(curl -s -o /dev/null -w '%{http_code}' -m 25 https://dds131.github.io$p)"
done

# 7.2 资源路径（验证 baseurl 配置正确，这是最容易出错的地方）
curl -s https://dds131.github.io/ \
 | grep -oE '(href|src)="/assets/[^"]*"' | sed -E 's/^(href|src)="//; s/"$//' | sort -u \
 | while read -r a; do
     printf "%-3s %s\n" "$(curl -s -o /dev/null -w '%{http_code}' -m 25 "https://dds131.github.io$a")" "$a"
   done

# 7.3 确认站点身份
curl -s https://dds131.github.io/ | grep -oE '<title>[^<]*</title>'
```

本项目的实测验收结果：**全部 200，零 404**。

## 八、日常更新流程

改完内容后：

```bash
docker exec -it xitu_dds_linshi_project_1 /bin/bash
cd /workspace/project_files/dds_web_projection_1/al-folio

# 改内容，例如编辑 _pages/about.md ...

git add -A
git commit -m "更新内容说明"

# 打个备份里程碑（可选但推荐）
bash dds_custom/scripts/01_backup.sh \
  al-folio.v1.3.0.<内容简述>.$(date +%Y.%m.%d) "<说明>"
exit
```

推送（宿主机执行，**不需要 `--force`**）：

```bash
docker exec -e GH_TOKEN='<你的PAT>' xitu_dds_linshi_project_1 bash -lc '
source /workspace/project_files/dds_web_projection_1/al-folio/dds_custom/scripts/00_env_proxy.sh
cd /workspace/project_files/dds_web_projection_1/al-folio
git -c credential.helper="!f(){ echo username=dds131; echo password=$GH_TOKEN; };f" \
    push https://github.com/dds131/dds131.github.io.git main:main'
```

推送后 `Deploy site` 会自动触发，约 2~4 分钟后站点更新。

> 若发现站点没更新：GitHub 官方文档指出「使用 `GITHUB_TOKEN` 的 workflow 产生的提交不会触发 Pages 构建」。
> 本项目已通过 `.nojekyll` 规避该问题。万一仍未刷新，手动触发一次即可（见 6.4）。
