前四个子页分别回答了「学什么」「怎么表达多样性」「用什么结构算」「怎么执行」。本页回答剩下的一个问题：这套模型究竟是怎么被训出来的。

内容分两半。前半是损失：两项各自在管什么、为什么这样写、哪些细节写错了会静默出问题。后半是数据与超参：数据怎么喂进来、三套归一化各管什么、实际生效的超参是哪些值。

L1 + 10·KL总损失的构成
40训练集 episode 数（50 条的 80%）
40一个 epoch 的样本数，与上一格相同
2000官方仿真命令的 epoch 数
5000+官方对真机数据的建议 epoch 数
3 套归一化，作用域各不相同
本页最需要记住的三条：一个 epoch 只有「训练集 episode 数」个随机片段（官方配置下是 40 个），比较训练量时必须换算更新次数；L1 掩码后取全元素均值而非有效元素均值，因此尾部短片段权重更低、有效 KL/L1 比更高；验证并不是固定的部署口径评估，它同时受到随机起点、随机后验样本和不等 batch 聚合影响。

一、这一层在 ACT 中的位置

前面四个子页讲的都是「模型是什么样的」，本页讲「模型怎么变成那个样子」。两者的关系可以这样摆：

子页 决定了什么 对训练侧提出的要求
② 动作分块 监督标签是一段 \(H\) 步动作 损失要能处理「标签是序列」，且 episode 尾部凑不满 \(H\) 步时不能污染目标
③ CVAE 目标函数含一个 KL 正则项 两项量纲不同，需要一个权重把它们摆平
④ Transformer 主干是预训练 ResNet，其余随机初始化 优化器将两部分拆成参数组，允许分别设置学习率
⑤ 时间集成 完全不参与训练 对训练侧无要求

因此本页的内容基本由前面四层决定，没有多少「独立的设计选择」。真正值得细看的是那些写错了不会报错、只会让结果变差的地方——padding 掩码的口径、归一化统计量的来源、epoch 与样本数的关系。本页把重点放在这些上。

另需说明本页与子页 ③ 的分工：L1 与 KL 两项为什么存在、KL 的闭式解怎么推、后验坍塌是怎么回事，都在子页 ③ 讲过，本页不重复。本页只讲它们的工程形态：代码怎么写的、掩码怎么算的、权重怎么定的。

二、总损失的构成

全部训练逻辑集中在 policy.py 的一个分支里，代码很短：

def __call__(self, qpos, image, actions=None, is_pad=None):
    env_state = None
    normalize = transforms.Normalize(mean=[0.485, 0.456, 0.406],
                                     std=[0.229, 0.224, 0.225])
    image = normalize(image)
    if actions is not None:                                   # 训练分支
        actions = actions[:, :self.model.num_queries]         # 截断到 H
        is_pad  = is_pad[:, :self.model.num_queries]
 
        a_hat, is_pad_hat, (mu, logvar) = self.model(qpos, image, env_state, actions, is_pad)
        total_kld, dim_wise_kld, mean_kld = kl_divergence(mu, logvar)
 
        loss_dict = dict()
        all_l1 = F.l1_loss(actions, a_hat, reduction='none')  # 逐元素，不聚合
        l1 = (all_l1 * ~is_pad.unsqueeze(-1)).mean()          # 掩码后取均值
        loss_dict['l1']   = l1
        loss_dict['kl']   = total_kld[0]
        loss_dict['loss'] = loss_dict['l1'] + loss_dict['kl'] * self.kl_weight
        return loss_dict
    else:                                                     # 推理分支
        a_hat, _, (_, _) = self.model(qpos, image, env_state)
        return a_hat

写成公式：

\[\mathcal{L} \;=\; \mathcal{L}_{\text{L1}} \;+\; \beta \cdot \mathcal{L}_{\text{KL}}, \qquad \beta = \texttt{kl\_weight} = 10\]

三个值得注意的点：

三项分别记录loss_dict 同时存了 l1、kl、loss，训练日志里三项分开打印。第十一节会说明为什么必须分开看。
KL 只取 total_kld[0]kl_divergence 返回三个量：潜变量维求和后对 batch 求均值的标量、对 batch 求均值后保留 latent 维的向量、对 batch 与 latent 全部元素求均值的标量。实际进入损失的只有第一个，另外两个当前没有接入日志。
截断发生在这里数据加载器给出的 actions 与 is_pad 长度是整条 episode，在这里才被截断到 num_queries。这一点在第七节还会用到。
注意 is_pad_hat 被接收后直接丢弃，没有参与任何损失。它对应模型里的 is_pad_head；当前公开代码没有说明保留该头的原因（详见子页 ④）。也就是说，这个独立输出头在训练中收不到任务损失梯度，其输出也不参与控制。不能据此推断作者意图，但在统计有效参数和分析梯度时应把它与实际训练路径区分开。

三、为什么用 L1 而不是 L2

官方代码用的是 F.l1_loss，不是均方误差。CVAE 的重构项本质上是负对数似然 \(-\log p_{\theta}(a \mid o,z)\)：固定方差的逐元素高斯似然对应 L2，固定尺度的逐元素 Laplace 似然则对应 L1。因此，L1 既是官方根据实验作出的工程选择，也可以解释为 Laplace 观测模型下的负对数似然，不能说它没有概率解释。

\[p(a \mid o,z)=\operatorname{Laplace}(a;\hat a,b) \quad\Longrightarrow\quad -\log p(a \mid o,z)=\frac{|a-\hat a|}{b}+\log(2b).\]

当 \(b\) 固定时，最小化右式等价于最小化 L1。官方实现没有显式预测 Laplace 尺度，这个概率解释用于说明损失的统计含义，而不是声称源码实现了完整的概率输出头。

论文第 IV-C 节（Implementing ACT，也是第四节的最后一个小节）末对此给了一句说明：

We use L1 loss for reconstruction instead of the more common L2 loss: we noted that L1 loss leads to more precise modeling of the action sequence.

理由很简短——L1 能更精确地建模动作序列——属于实验观察，论文没有展开机制。同一段还有一条相关表述：

We also noted degraded performance when using delta joint positions as actions instead of target joint positions.

这为子页 ② 第 9.1 节「为什么用绝对位置而非增量」提供了实验依据。需要同时指出，论文 Algorithm 1 第 9 行把重构项写成了 MSE；正文第 IV-C 节与官方 policy.py 则一致使用 L1。对复现而言应以正文的实现说明和公开代码为准，并把算法框中的 MSE 记为论文内部不一致，而不是把两者混写成同一个目标。

下面三小节补充的是机制层面的解释，用来理解论文那句「more precise modeling」可能来自哪里。这部分是本页的分析，不是论文的论证。

3.1 梯度性质的差别

两者的逐元素梯度形式完全不同：

\[\frac{\partial}{\partial \hat{a}} \big\lvert \hat{a} - a \big\rvert \;\in\; \partial\lvert \hat a-a\rvert, \qquad \frac{\partial}{\partial \hat{a}} \big( \hat{a} - a \big)^{2} \;=\; 2(\hat{a} - a)\]

当 \(\hat a\ne a\) 时，L1 对预测值的导数是 \(\operatorname{sign}(\hat a-a)\)；在零残差处不可微，PyTorch 采用 0 作为子梯度。忽略损失的均值因子后，L1 对预测输出的梯度幅值不随残差增大，L2 则正比于残差。因此，一个残差绝对值为 10 的元素，其 L2 输出梯度幅值是残差为 1 的元素的 10 倍；L1 的两者相同。这里比较的是损失对预测输出的局部梯度，最终参数梯度还取决于网络 Jacobian、不同样本的方向与 batch 内抵消。

3.2 遥操作数据里的离群帧从哪来

这个差别之所以重要，是因为人类遥操作数据中确实存在不少「标签本身不理想」的帧：

操作者的停顿与犹豫人在判断下一步怎么做时会短暂停住，此时记录下的动作与前后不连贯，但它不代表任务需要这样做。
手部抖动主从遥操作会把操作者的高频抖动一并记录进动作标签。
时间同步误差图像与关节读数的时间戳未必严格对齐。源码里对真机数据有一处 action = root['/action'][max(0, start_ts - 1):]，注释写着「hack, to make timesteps more aligned」，正是在处理这类偏移。
纠错动作操作者发现偏了之后的快速修正，动作幅度异常大，但它是对当时那个偏差状态的响应，未必适用于策略遇到的状态。

在 L2 下，大残差元素更容易支配输出侧梯度，模型为了压低少数大误差点，可能牺牲大量正常帧的拟合精度。L1 限制了残差幅值带来的线性放大，因此对离群值更稳健；这是一种合理机制解释，但论文没有证明上述每一种噪声都是选择 L1 的具体原因。

3.3 一个更深的差别：中位数与均值

对标量随机变量，最小化期望 L1 的解是中位数集合，最小化期望 L2 的唯一解（方差有限时）是条件均值。

\[\arg\min_{c} \ \mathbb{E}\big[\lvert Y - c \rvert\big] = \operatorname{Med}(Y), \qquad \arg\min_{c} \ \mathbb{E}\big[(Y - c)^{2}\big] = \mathbb{E}[Y]\]

这里的 \(\operatorname{Med}(Y)\) 是所有中位数构成的集合，可能不止一个。设 \(Y\) 以相同概率取 \(-1\) 和 \(+1\)，则

\[\arg\min_c\mathbb E|Y-c|=[-1,+1].\]

两个峰之间的每一点都是 L1 最优解，L1 本身并不保证选择某一个峰。若一个分离模式拥有超过一半的概率质量，标量中位数可能落入该模式；但对宽峰、重叠峰或等权模式，不能给出统一的「选择主峰」结论。

准则 标量总体最优解 对双峰分布能保证什么
L2 条件均值 均值可能位于两峰之间；当峰间区域低密度时，可能形成无效折中
L1 条件中位数集合 对离群值更稳健，但一般不保证落入某个峰；等权离散双峰可有整段最优解

ACT 对 14 维动作使用逐元素 L1，因此对应的是逐坐标条件中位数。不同坐标可能分别落在不同模式的代表值上，组合后仍可能形成不属于任何真实轨迹的混合动作。多模态行为主要由 CVAE 的隐变量建模；L1 的稳健性与 CVAE 可以互补，但 L1 不能独立解决模式平均，也不能保证模式分离。

需要标明引用边界：中位数、离群值鲁棒性和 Laplace 似然是统计学解释，论文并未用它们论证 ACT。 论文只报告 L1 带来更精确的动作序列建模；不能把本页的机制分析反写成作者动机或实验已经验证的因果结论。

四、padding 掩码：必要性与分母口径

4.1 补齐从哪来

数据加载时，样本的起点 start_ts 在整条 episode 上随机采样。若起点靠近末尾，剩余的真实动作不足 \(H\) 步，需要补齐：

padded_action = np.zeros(original_action_shape, dtype=np.float32)
padded_action[:action_len] = action
is_pad = np.zeros(episode_len)
is_pad[action_len:] = 1

补齐值是零。注意此时动作还没有归一化（归一化在 __getitem__ 末尾进行），所以补齐位置在归一化后会变成 \(-\mu / \sigma\)，是一个与真实动作分布无关的人造值。若让它参与损失，模型会被迫去拟合这个人造值。

is_pad 的长度是整条 episode_len，不是 \(H\)；截断到 \(H\) 发生在 policy.py 里（见第二节）。

4.2 掩码怎么写的

all_l1 = F.l1_loss(actions, a_hat, reduction='none')   # (B, H, 14)，逐元素
l1 = (all_l1 * ~is_pad.unsqueeze(-1)).mean()           # 掩码后取全元素均值

~is_pad 把有效位置置 1、补齐位置置 0，相乘后补齐位置的贡献变为零。这一步是必须的，写漏了模型就会去拟合人造零值。

4.3 分母口径：一个容易忽略的细节

关键在最后那个 .mean()。它的分母是张量的全部元素数 \(B \times H \times 14\)，而不是有效元素数。

\[\mathcal{L}_{\text{L1}} \;=\; \frac{1}{B \cdot H \cdot 14} \sum_{b,\, h,\, d} \big\lvert \hat{a} - a \big\rvert_{b,h,d} \cdot \mathbb{1}[\text{非补齐}]\]

也就是说，一个只有 \(m\) 个有效步的样本，其等效权重是 \(m / H\)，而不是 1。越靠近 episode 尾部的样本，对损失的贡献越小。

这不仅改变整体数值尺度，也改变样本权重：同一 batch 内，尾部短片段的 L1 权重更低，而每个样本的 KL 仍按 batch 等权平均。因此，padding 越多，那个样本相对于 L1 所承受的 KL 约束越强。

若希望改变口径，需要先明确目标。下面两种常见写法并不等价：

\[\mathcal L_{\text{valid-step}} = \frac{\sum_{b,h,d}M_{b,h}e_{b,h,d}} {D\sum_{b,h}M_{b,h}}, \qquad \mathcal L_{\text{equal-sample}} = \frac1B\sum_b \frac{\sum_{h,d}M_{b,h}e_{b,h,d}} {D\sum_hM_{b,h}}.\]

前者让所有有效时间步等权，后者让每个随机起点样本等权；官方实现使用的都不是，而是固定分母 \(BHD\)。

影响大小可以直接算。仿真分支中有效长度为 \(m=\min(H,T-t)\)，其平均等效权重为

\[\mathbb E[m/H]=1-\frac{H-1}{2T}.\]

真机分支采用 max(0, start_ts - 1) 的一步对齐，有效长度多一帧（起点 0 与 1 都从动作 0 开始），对应

\[\mathbb E[m/H]=1-\frac{(H-1)(H-2)}{2TH}.\]
分支与配置 完整 chunk 占比 发生 padding 的占比 平均等效权重 相对等权样本口径的平均缩小幅度
真机：\(T = 1000\)，\(H = 90\) 91.2% 8.8% 0.956 约 4.4%
真机：\(T = 600\)，\(H = 90\) 85.3% 14.7% 0.927 约 7.3%
仿真通用式：\(T = 400\)，\(H = 100\) 75.2% 24.8% 0.876 约 12.4%

前两行按真机的一步对齐逻辑计算，第三行用于展示不含该偏移的通用仿真口径。平均缩小约 4% 到 7% 不代表每个样本只缩小这么多：最靠近尾部的片段可能被大幅降权。当 \(H/T\) 上升时，padding 样本比例、样本间权重差异以及有效 KL/L1 比都会增大。

这是官方代码实际定义的训练目标，不能简单归类为实现错误；但也不能说它「只改变尺度」。它隐式降低尾部短片段的权重，并使有效 KL/L1 比随 padding 比例变化。若改用有效元素或逐样本归一化，应重新标定 kl_weight，并通过 rollout 验证哪一种样本加权更适合任务。

五、kl_weight 的量纲问题

官方训练命令给的是 --kl_weight 10。这个数字不能孤立理解，因为它乘的那一项与 L1 项的量纲完全不同。

5.1 两项的量纲差在哪

项 单位 聚合方式 典型量级
L1 归一化后的关节位置误差 对 \(B \times H \times 14\) 全部元素取均值 与归一化尺度同阶，训练后期通常远小于 1
KL 自然对数（nat） 对 32 个 latent 维求和，再对 batch 取均值 在同一组逐维 KL 上，求和结果是逐维均值的 32 倍

KL 的聚合方式是关键。回看子页 ③ 核对过的实现：

klds = -0.5 * (1 + logvar - mu.pow(2) - logvar.exp())
total_kld = klds.sum(1).mean(0, True)      # 先沿 latent 维求和，再对 batch 求均值

sum(1) 沿 latent_dim = 32 求和。假如换成 mean(1)，同样的 kl_weight 就相当于被除以了 32——两种写法下 10 这个数字的含义完全不同。

5.2 所以该怎么调

第一步应当看加权后两项的相对大小，而不是只看 kl_weight 的数值；但损失标量相近不等于对参数的梯度影响相近。两项通过不同计算路径作用于共享参数，严谨诊断还需要结合逐维 KL、latent 扰动敏感性、梯度范数和部署口径的 rollout 指标。

训练日志里 l1、kl、loss 三项是分开打印的，可以直接读出 \(\beta \cdot \mathcal{L}_{\text{KL}}\) 与 \(\mathcal{L}_{\text{L1}}\) 的比值。两端的失效模式在子页 ③ 已详细讲过（后验坍塌与推理分布偏移），这里只给对照：

加权 KL 长期过强会提高后验被压向先验、latent 信息量下降的风险；是否已经后验坍塌，还要检查逐维 KL 和输出对 z 的敏感性。
加权 KL 长期过弱会提高后验远离先验的风险，训练时后验采样与部署时 z = 0 之间可能产生更大的分布偏移。
换了 latent 维度或 KL 聚合方式应重新标定 kl_weight。若每一维 KL 的分布近似不变，latent_dim 从 32 增至 64 会使 sum 聚合值接近翻倍；重新训练后每维 KL 会自适应变化，因此不能机械按二倍换算。
一个实用提醒：L1 已对动作维求均值；若新增动作维与原维度具有相近的标准化误差分布，维度数量本身不会代数性地放大 L1。实际量级仍会随动作表示、归一化质量、padding 比例和误差分布变化；KL 则同时取决于 latent 维数、数据、编码器、解码器与训练状态。因此 kl_weight = 10 不能跨平台直接照搬，但也不能只按动作维数或 latent 维数机械换算。

六、三套归一化各管什么

ACT 实际有三套归一化，分别在不同位置、用不同来源的统计量。混淆它们是复现时的常见问题。

编号 对象 在哪做 统计量来源 形式
① 图像 EpisodicDataset.__getitem__ 无 image_data / 255.0，缩放到 \([0, 1]\)
② 图像 ACTPolicy.__call__ ImageNet 预训练统计量 均值 \([0.485, 0.456, 0.406]\)，标准差 \([0.229, 0.224, 0.225]\)
③ 动作与 qpos EpisodicDataset.__getitem__ 本数据集统计量 减均值除标准差

6.1 图像为什么分两步

第 ① 步只是把 uint8 的 0 到 255 变成 float 的 0 到 1；第 ② 步才是真正的标准化，用的是 ImageNet 的统计量——因为视觉主干是 ImageNet 预训练的 ResNet-18（见子页 ④），输入分布必须与预训练时一致，否则预训练特征的效果会打折扣。

两步分处两个文件，容易只看到其中一步。若自己实现推理管线时漏掉第 ② 步，模型不会报错，但视觉特征会系统性偏移。

6.2 动作与状态的统计量怎么算的

action_mean = all_action_data.mean(dim=[0, 1], keepdim=True)
action_std  = all_action_data.std(dim=[0, 1], keepdim=True)
action_std  = torch.clip(action_std, 1e-2, np.inf)     # 标准差下限截断
# qpos 同理

三个细节：

沿 episode 维与时间维聚合dim=[0, 1] 表示对「哪条 episode」和「第几步」都求均值，只保留动作维度。得到的是每个关节一组统计量。
标准差有下限 0.01torch.clip(std, 1e-2, inf)。若某个关节在全部示范中几乎不动，其标准差接近零，除法会放大噪声甚至溢出。这个下限是必要的保护。
统计量用全部 episode 计算get_norm_stats(dataset_dir, num_episodes) 传入的是全部 episode 数，而不是训练集索引——验证集的数据也参与了统计量计算。

最后一条值得单独说明。这属于验证信息通过预处理统计量进入训练的泄漏：泄漏的是各关节的整体均值与标准差，不是完整轨迹，但影响大小取决于数据量以及训练集、验证集的分布差异，不能在没有对照实验时断言「很小」。若验证集只用于工程上的 checkpoint 选择，应如实记录这一口径；若要严格估计对未见 episode 的泛化，应只用训练集计算统计量，再原样应用到验证集。

6.3 统计量随 checkpoint 一起保存

stats_path = os.path.join(ckpt_dir, f'dataset_stats.pkl')   # 源码此处确为 f-string，但串内无占位符
with open(stats_path, 'wb') as f:
    pickle.dump(stats, f)

推理时从这个文件读回，构造正反变换：

pre_process  = lambda s_qpos: (s_qpos - stats['qpos_mean']) / stats['qpos_std']
post_process = lambda a: a * stats['action_std'] + stats['action_mean']
这是一类典型的「不报错但结果全错」的故障源：换了数据集重新训练，却复用了旧的 dataset_stats.pkl，或者反过来。模型结构完全正确、推理正常运行，但输出的目标关节位置幅值异常、夹爪开合不对。排查真机异常动作时，核对这个文件与 checkpoint 是否配套应当排在很前面。

七、一个 epoch 究竟有多少样本

这一节是本页最值得记住的内容。它说明了为什么 2000 或 5000 个 epoch 不能按常见的大型时间步数据集来理解：每个 epoch 的更新次数很少。这个实现事实可以解释大 epoch 数为何不等于巨量更新，但官方 README 没有把它明确写成选择 2000/5000 的唯一原因。

7.1 数据集的长度是 episode 数，不是时间步数

class EpisodicDataset(torch.utils.data.Dataset):
    def __len__(self):
        return len(self.episode_ids)          # ← 训练集的 episode 条数
 
    def __getitem__(self, index):
        sample_full_episode = False           # hardcode
        episode_id = self.episode_ids[index]
        ...
        start_ts = np.random.choice(episode_len)   # ← 每次取样随机选起点
        qpos = root['/observations/qpos'][start_ts]
        ...

两行合起来决定了整个数据管线的行为：

索引的是 episode，不是时间步__len__ 返回 episode 条数。DataLoader 遍历一遍，就是每条 episode 各取一次。
起点每次随机同一条 episode 在不同 epoch 被取到时，start_ts 不同，因此得到的是不同的训练样本。随机性来自 __getitem__ 内部，不是来自索引。

也就是说，一个 epoch 遍历的是「每条 episode 抽一个随机片段」，而不是「所有可能的片段」。

7.2 代入官方配置算一遍

量 计算 结果
示范总数 官方每任务 50 条
训练集 train_ratio = 0.8 40 条
验证集 其余 10 条
数据集 __len__ 等于训练集条数 40
每 epoch 的 batch 数 \(\lceil 40 / 8 \rceil\) 5
每 epoch 的参数更新次数 同上 5 次
2000 epochs 的总更新次数 \(5 \times 2000\) 10000 次
2000 epochs 的抽样次数 \(40 \times 2000\) 80000 次随机片段抽样

一个 epoch 只有 5 次参数更新。 它仍然是对 Dataset 索引的一次完整遍历，只是这个 Dataset 的一个索引表示「从一条 episode 随机生成一个片段」，而不是一个固定时间步样本。因此 num_epochs 同时也是每条训练 episode 被随机抽样的轮数；比较不同实现的训练量时，应换算为更新次数和抽样次数。

作为对照：若按时间步建索引（即每条 episode 的每个起点都是一个独立样本），1000 步的 episode 下训练集将有 \(40 \times 1000 = 40000\) 个样本，一个 epoch 就是 5000 个 batch。两种设计下「epoch」这个词的含义完全不同。

7.3 这个设计的取舍

好处：实现简单且不重复读盘每个样本只需从 hdf5 里读一帧图像与一段动作。若按时间步建索引，同一条 episode 会被反复打开，或者需要把整条 episode 常驻内存。
好处：episode 内起点均匀给定一条 episode，其每个起点被抽到的概率相同。整体采样是「先让 episode 等权，再在该 episode 内均匀选起点」；若 episode 长度不同，全数据集的每个时间步并非等概率，短 episode 的单个时间步概率更高。
代价：名义 epoch 不便横向比较「训练了 2000 个 epoch」实际只有 1 万次更新。与其他方法对比训练量时，应换算成参数更新次数或随机片段抽样次数，而不是直接比较 epoch 数。
代价：每个 epoch 的验证损失噪声较大验证集只有 10 条 episode、每条抽一个随机片段，一次验证只有 10 个样本。这直接影响第十节的 checkpoint 选择。
本节的所有数字按官方配置（50 条示范、train_ratio = 0.8、batch_size 8、num_epochs 2000）计算得出。复现时若示范条数或 batch size 不同，需按同样方式重算。增加示范条数会同时增大每个 epoch 的更新次数；只有在希望维持近似固定的总更新预算时，才应相应下调 epoch 数，不能把它当成普遍规则。

9.1 验证在训练之前

每个 epoch 先跑验证、再训练。这意味着：

epoch 0 的验证损失是未训练模型的此时权重还是初始化状态，这个点应当被当作基线而非训练结果。
第 n 个 epoch 打印的验证损失，反映的是第 n−1 个 epoch 结束时的权重对齐训练曲线与验证曲线时需要注意这个一步的偏移。
最后一个 epoch 训练完之后没有再验证因此最终权重的验证损失从未被计算过，也就不可能被选为 best。

最后一条的实际后果：best_ckpt_info 最多只能是倒数第二个 epoch 结束时的权重。如果模型在最后一个 epoch 仍在改善，这个改善不会被 best 机制捕捉到——但 policy_last.ckpt 保存了最终权重，可以手动对比。

9.2 CVAE encoder 在验证时仍然参与

forward_pass 在验证时同样传入了真实动作，因此走的是训练分支：CVAE encoder 被使用，z 由后验采样而来。调用 policy.eval() 只会关闭 dropout 等训练态行为，不会关闭 reparametrize 中的随机正态采样。验证损失衡量的是「给定真实动作后，从近似后验随机采样一次 z 的重建与 KL」，不是「推理时固定 \(z = 0\) 的表现」。

这会引入一层额外的 Monte Carlo 噪声：即使固定验证片段和模型权重，两次验证也可能因采到不同 \(z\) 而得到不同重建损失。验证损失低不等于部署表现好，因为部署路径固定 \(z=0\)，还会经历闭环状态分布和控制执行。

9.3 验证损失的 batch 聚合并非样本等权

官方配置有 10 条验证 episode、batch_size = 8，因此验证产生一个 8 样本 batch 和一个 2 样本 batch。每个 batch 的 L1 与 KL 已经各自取均值，但 compute_dict_mean 随后又对两个 batch 等权平均：

\[\mathcal L_{\mathrm{reported}} =\frac12\left( \frac18\sum_{i=1}^{8}\ell_i +\frac12\sum_{i=9}^{10}\ell_i \right).\]

于是前 8 个样本各占 \(1/16\)，最后 2 个样本各占 \(1/4\)；后者单样本权重是前者的 4 倍。验证 DataLoader 还设置了 shuffle=True，每轮落入最后一个小 batch 的 episode 会变化。再叠加随机起点与随机后验样本，单轮验证损失共有三层波动来源：

片段变化每条验证 episode 重新随机选择 start_ts。
后验采样reparametrize 每次重新采样 latent 噪声。
聚合权重变化shuffle 后进入 2 样本尾 batch 的 episode 获得更高报告权重。

若要得到样本等权的验证指标，应按每个 batch 的实际样本数加权汇总，或累计逐样本损失后除以验证样本总数。若还希望曲线可复现，应固定验证起点，并明确使用后验均值、固定采样种子或多次采样平均；这些都是改进方案，不是原始实现行为。

9.4 两处训练循环细节

梯度清零的位置循环外先 zero_grad() 一次，循环内每步 step() 后再 zero_grad()。等价于标准的「每个 batch 更新一次」，没有梯度累积。
epoch 汇总的切片假设compute_dict_mean(train_history[(batch_idx+1)*epoch : (batch_idx+1)*(epoch+1)]) 用「本 epoch 的 batch 数」乘以 epoch 号来切片，隐含假设每个 epoch 的 batch 数完全相同。在当前设计下成立（数据集长度固定），但若改用会变长的数据集，这里的汇总会错位。

十、checkpoint 与随机种子

10.1 一共产生哪些 checkpoint

文件名 何时保存 内容
policy_epoch_{n}_seed_{s}.ckpt 每 100 个 epoch 完成编号 n 的训练循环后保存的权重
policy_last.ckpt 训练结束 最终权重
policy_epoch_{best}_seed_{s}.ckpt 训练结束 验证损失最优的权重
policy_best.ckpt 训练结束，在 main() 中 同上，评估时加载的就是这个
dataset_stats.pkl 训练开始前 归一化统计量，见第 6.3 节

评估分支加载的是 policy_best.ckpt：

if is_eval:
    ckpt_names = [f'policy_best.ckpt']
    ...
# 训练结束后，在 main() 里：
best_epoch, min_val_loss, best_state_dict = best_ckpt_info
ckpt_path = os.path.join(ckpt_dir, f'policy_best.ckpt')
torch.save(best_state_dict, ckpt_path)

保存与加载的文件名一致，训练完直接加 --eval 即可评估。

需要注意编号口径：编号为 \(n\) 的验证发生在该轮训练之前，而周期 checkpoint 在该轮训练之后保存，因此二者虽共享编号，代表的权重状态相差一次训练遍历。若 best_epoch 恰好是 100 的倍数，训练结束时再次保存同名 policy_epoch_{best}_seed_{s}.ckpt，还会用该轮开始时选中的 best 权重覆盖原有周期 checkpoint；policy_best.ckpt 则始终保存同一份 best 权重。

10.2 best 的选择依据有多可靠

结合第 7.3、9.2 与 9.3 节，best 选择有三类限制：

样本少且输入随机10 条 episode 每条只抽一个随机片段，不能覆盖整条验证轨迹。
后验样本随机验证使用随机 z，而部署固定 z = 0；最低验证损失未必对应最高 rollout 成功率。
batch 聚合不等权2 样本尾 batch 与 8 样本 batch 等权，使尾 batch 的单样本权重放大 4 倍。

因此实践中不宜完全依赖 policy_best.ckpt。每 100 个 epoch 保存的中间 checkpoint 可以用于仿真或真机 rollout 对比，但源码没有说明保存它们的唯一目的，不能把这种用法写成作者意图。

10.3 随机种子的两处作用域

set_seed 在代码中被调用了三次，位置不同、作用域不同：

调用处 种子 影响什么
main() 开头 固定为 1 其后 load_data 中的 np.random.permutation —— 即训练与验证集的划分
train_bc() 开头 命令行 --seed 模型初始化、dropout、数据加载的起点采样等训练过程随机性
eval_bc() 中 固定为 1000 评估时的环境初始化与物体位姿采样

这导致一个容易误判的行为：改 --seed 不会改变训练与验证集的划分。

def main(args):
    set_seed(1)                    # ← 固定值，与 --seed 无关
    ...
    train_dataloader, val_dataloader, stats, _ = load_data(...)   # 划分在此发生
    ...
    best_ckpt_info = train_bc(...)  # train_bc 内部才 set_seed(args['seed'])
这个设计有其合理性——固定划分使不同种子的实验可比，差异只来自训练过程而非数据划分。但它也意味着用多个 --seed 跑实验并不能评估「换一批数据划分会怎样」。若要做后者，需要自己修改 main() 里那个固定的 1，或者改成从命令行读取。

set_seed 本身只设了两处随机源：

def set_seed(seed):
    torch.manual_seed(seed)
    np.random.seed(seed)

torch.manual_seed 会设置 CPU 与 CUDA 默认生成器，因此不能因为源码没有显式调用 torch.cuda.manual_seed_all 就断言 CUDA 未设种子。严格逐位复现仍没有保证：源码未要求确定性算法，也没有锁定完整的 PyTorch、CUDA、cuDNN、驱动与硬件组合；DataLoader 也没有显式传入 generator 或 worker 初始化函数。Python random 没有设置，但只有训练路径实际使用它时才会产生影响。若追求严格复现，应依据所用 PyTorch 版本配置确定性算法与 DataLoader 随机源，并记录完整运行环境；某些确定性设置会降低性能或对不支持的算子报错。

十一、训练监控：该看什么

11.1 三项必须分开看

训练日志把 l1、kl、loss 三项分别打印，这不是冗余：

指标 下降说明什么 异常形态与含义
l1 动作块重建越来越准 长期不降：模型容量、学习率或数据本身有问题
kl 后验与先验的距离 长期接近 0：疑似 latent 未被利用；很大且不降：后验远离先验，部署固定 \(z = 0\) 时有分布偏移风险
loss 两项加权之和 单看它无法区分上面两类问题

只看总损失可能掩盖 kl 下降而 l1 基本不动的情形。较小的 KL 是后验接近先验的证据，但“后验坍塌”还要求 latent 不再提供有效信息，不能仅靠一个总 KL 阈值确诊。应同时查看逐维 KL、有效 latent 数，并测试改变 \(z\) 是否会系统性改变预测动作。

源码每 100 个 epoch 调用一次 plot_history，会把训练与验证曲线存成图，可以直接用。

11.2 验证损失怎么读

结合第 9.2 与 10.2 节，读验证曲线时要记住两件事：

它是噪声较大的一次验证只有 10 个样本（10 条 episode 各抽一个随机起点）。逐 epoch 的抖动不必过度解读，应看趋势。
它与真机口径不同验证走训练分支，z 来自后验采样；真机固定 z = 0。验证损失低只说明「有真实动作参考时重建得好」。

11.3 训练多久：官方给的经验

官方 README 明确写道：

For real-world data where things can be harder to model, train for at least 5000 epochs or 3-4 times the length after the loss has plateaued.

两条信息：真机数据至少 5000 个 epoch（仿真命令给的是 2000）；损失进入平台期之后还要再训练 3 到 4 倍的时长。

后一条是 ACT 官方针对真机数据给出的经验建议：离线损失进入平台期后，策略平滑度或成功率仍可能改善。它说明不能只凭一次 loss 平台期机械早停，但不是对所有任务、数据规模和早停准则的普遍否定。源码确实使用恒定学习率；现有资料没有证明这就是平台期后继续改善的原因，因此两者应分别陈述。

官方 README 另有一份 tuning tips 文档链接，本页未打开核验，不转述其内容。

11.4 还应该看什么

损失之外，真正决定 ACT 好坏的指标在损失曲线里看不到：

rollout 成功率官方评估脚本一次跑 50 个 rollout（num_rollouts = 50），统计成功率与平均回报。这是最终判据。
动作曲线的平滑度把下发的目标关节位置画出来，看是否有阶跃或高频抖动。这是子页 ⑤ 关心的问题，损失完全反映不出来。
失败发生在哪个阶段接近、对准、接触、插入——不同阶段失败对应完全不同的原因。评估脚本会保存每个 rollout 的视频，应当实际看。
开启与关闭时间集成的对比同一 checkpoint 两种模式各评估一次，可判断重叠预测聚合是否改善当前表现；它提供诊断证据，但不能单独把故障唯一归因到模型层或执行层。方法见子页 ⑤ 第 9.3 节。
一条更稳健的排查顺序是：先联合检查总 KL、逐维 KL 与 latent 敏感性 → 再看 L1 和两项梯度是否稳定 → 用固定协议比较多个 checkpoint 的 rollout → 最后把时间集成开关作为一项受控变量。 每一步都在缩小原因范围，但单个指标或单次 A/B 都不能唯一定位故障层。
