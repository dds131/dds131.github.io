X-VLA 面向一个具体问题：VLA 训练数据来自机器人、相机、控制接口和采集风格各不相同的数据域。若共享模型没有获得足够的域信息，不同监督可能发生冲突。论文的一条累积消融路径中，加入尚未充分对齐的异构预训练后，Simpler-WidowX 成功率由 39.6 降至 25.0，即下降 14.6 个百分点；这说明“直接混合这批数据”在该设置下产生了负迁移，并不等于异构预训练普遍无效。X-VLA 的核心方案是：域专属动作输入投影、域专属 Soft Prompt、共享 Transformer 动作主干和域专属动作输出投影。Soft Prompt 让域条件从主干第一层起参与融合，而不是独自“吸收全部异构性”。

一、X-VLA 要解决什么：跨本体异构性的四个层面

跨本体训练常先把不同平台的动作转换成统一表示，例如 OpenVLA 使用统一的连续动作接口再离散化成 token。统一张量格式是必要步骤，但不会自动消除坐标约定、观测配置、时间尺度和数据风格的差异。为便于分析，可把异构性拆成四个相互耦合的层面：

  • 自由度与动作空间不同。单臂 7 维、双臂 14 维、加移动底盘再多几维；即使维度凑巧相同，关节顺序、单位、正方向定义也未必一致。直接拼进同一个 batch，第 \(k\) 个通道在不同样本里含义不同。
  • 相机配置不同。相机数量、安装位置、内参、有没有腕部相机各不相同。同一条指令在固定视角机位和手眼机位下对应的像素证据完全不同。
  • 控制语义与频率不同。同样是「向前移动 1 厘米」，末端坐标系原点与朝向的定义在不同平台上不一样；采集频率从十几赫兹到上百赫兹都有，同样一段轨迹在不同频率下的相邻帧差值差一个数量级。
  • 数据风格不同。遥操作手感、任务分布、抓取习惯、失败重试的比例都带有强烈的数据源指纹。

在平方误差、无限数据与容量并达到总体最优的理想条件下，如果输入 \(x\) 没有显式域标识，最优共享预测器是

\[f^*(x)=\mathbb{E}[A\mid x]=\sum_d p(d\mid x)\,\mathbb{E}[A\mid x,d].\]

只有当不同域的条件均值确实冲突、且域不能从其他输入中可靠识别时，这个混合均值才会偏离每个域各自的最优策略；若各域目标一致，或图像等输入足以确定域，平均并非必然有害。X-VLA 的 Soft Prompt 与域专属动作投影所做的事情，是把域 \(d\) 直接提供给模型，减少这种不必要的歧义。数据量不平衡仍需通过采样策略单独处理。

X-VLA 自己也保留了随域数线性增长的私有参数：prompt 与动作输入、输出投影都按域存储。它解决的不是“新增域零成本”，而是让 24 层动作主干保持共享，把线性增长限制在主干两端和提示向量；标准配置的具体预算见 3.2 节。

统一定长动作空间只解决了张量形状问题，没解决语义问题——这是理解 X-VLA 动机的关键一句。补零让 batch 能拼起来，但第 3 个通道在 A 机器上是肘关节角、在 B 机器上是末端 z 轴速度，模型仍然要在同一组权重里同时拟合这两种含义。

论文把这条动机做成了可量化的实验：在 Simpler-WidowX 上，不做任何预训练但用了定制学习率的基线达到 39.6，而直接在异构数据上朴素预训练之后反而掉到 25.0。这个负收益是全篇的出发点，完整消融路径见第十节。（层一，论文 Table 1）

三、Soft Prompt：一页纸版本

3.1 思想来源与正式定义

Soft Prompt 来自 NLP 的 prompt tuning。经典 Prompt Tuning 的适配设定是冻结预训练语言模型，只在输入序列里拼接一段连续的、可学习的向量，用梯度下降寻找能让主干完成目标任务的“提示”；它与手写离散提示词的区别是搜索空间从词表变成整个嵌入空间。X-VLA 借用了这种连续提示形式，却没有照搬“全程冻结主干”的训练方式：跨域预训练时主干与各域 prompt 联合优化；迁移到新域时，论文 Appendix H 才先冻结主干、更新新 prompt 与动作头，再解冻做联合微调。

X-VLA 把这个机制平移到机器人上。论文（层一）的表述是为每个数据源分配一组可学习 embedding：

\[\mathcal{P}^{H} = \{\, p_i \,\}_{i=1}^{H}, \qquad p_i \approx \Phi(h_i)\]

其中 \(H\) 是异构数据源的个数，\(h_i\) 是第 \(i\) 个数据源的硬件配置，\(\Phi\) 是作者用于解释 prompt 的隐式映射。固定代码并不接收结构化硬件字段，只按数据源/域槽位查表；论文也没有证明 prompt 只编码本体形态。论文特别强调 \(\Phi\) 不由人工模板预先定义，而是随机初始化后由端到端训练隐式优化——没有额外的辅助损失，也不注入任何人工设定的本体先验。

3.2 源码里它到底是什么

# models/transformer.py，SoftPromptedTransformer.__init__ 节选
if len_soft_prompts > 0:

每个域槽位对应 128,020 个私有参数。按发布配置的名义 0.9B 参数口径，以同一粗略分母估算，单个槽位约占 0.014%，预训练实际使用的 7 行约占 0.10%，全部 30 行共 3,840,600 个参数、约占 0.43%。这些都是依据源码张量形状得到的量级估算，并非论文报告的精确“新增参数占比”；0.9B 本身也是论文采用的规模标签。论文 Fig. 10 caption 另写非共享参数占 0.04%，但没有说明按单域、7 个已用域还是全部 30 个槽位统计，也未给精确总参数分母，因此该比例无法由公开口径唯一复算。域私有参数仍按域数 \(H\) 线性增长，X-VLA 的扩展性来自把 24 层大主干共享，而不是把每个新域的参数成本降为零。

论文只说“minimally added parameters”，长度 32 与上述完整预算论文均未给出，只能从固定源码与 checkpoint config 推导。

3.3 为什么少量域参数可能有效

  • 它承担的是域条件，不是全部运动知识。 机器人自由度、相机、坐标系等配置在一个数据域内通常固定，但 prompt 也可能吸收任务分布、操作者习惯等数据源特征；论文并未证明其各维对应哪些物理属性。32 个 token 在论文实验中有效，只能说明该容量对这些设置足够，不能推出任意新本体都“绰绰有余”。
  • 主干本身已经具备条件化能力。自注意力天然支持「一部分 token 调制另一部分 token 的表示」：prompt 作为 Key 与 Value 参与每一次缩放点积，其他 token 的 Query 都能取到它。Soft Prompt 因此不需要自己完成任何计算，它只需要进入序列，让 24 层里每一层的注意力都能读到它，从而把同一份共享权重按本体分化成不同的有效计算路径。
  • 显式域条件减少了识别歧义。 domain_id 是一个已知的类别条件，不是“一位免费信息”；查表后的连续 prompt 仍需从数据中学习。它让模型不必只靠图像推断数据域，但不保证共享主干一定把域差异与共性运动知识完全解耦。
一个源码层的细节值得先记住：soft prompt 在 x = x + pos_emb 之后才拼入序列，因此不带动作主干的绝对位置编码。在关闭 dropout 的确定性前向中，若只重排这 32 个 prompt token，动作位置的输出保持不变；训练时逐元素 dropout 会破坏单次前向的严格相等，但不改变这种分布层面的置换对称性。主干能依据向量内容区分 prompt，却看不到独立的序号位置标签。它们位于序列末尾也不妨碍普通 token 读取，因为这里使用无掩码双向注意力。严格条件见子页 ①。

3.4 新增一个本体时怎么做

论文给出的是两阶段适配（层一，Appendix H）：

  1. prompt 热身。为新域引入一组 prompt，前 1000 次迭代固定其余预训练权重，只更新 prompt 与动作头。
  2. 联合适配。随后联合优化主干与域私有参数，并用 1000 步逐步恢复学习率。

“先局部、后联合”可减少小数据早期对共享表示的扰动，但论文没有做反序消融，不能把这一解释写成已验证因果。更重要的是，固定官方 train.py 只会按 domain_id 选择已预分配的 prompt 与动作投影行；它不会创建、扩容或重置新槽位。--freeze_steps 只是用零学习率近似第一阶段，也不会自动完成新域初始化。接入新域时必须显式选择未占用槽位，必要时初始化或复制三处域私有参数，并确保配置、数据映射和 checkpoint 一致；若索引超出 num_domains，还需扩表并迁移旧权重。详见子页 ①、④、⑤。

这个设计让共享主干的激活按域条件化，同时把动作接口留在域专属输入/输出投影中。推理时必须提供与 checkpoint 映射一致的 domain_id；接入新域也不只是新增 prompt，还要为两个动作投影准备对应行并用目标域数据适配。官方方法没有提供或验证“无槽位、无适配数据”的全新平台 zero-shot 部署；论文只把它列为待探索方向。

四个要点：

  • DomainAwareLinear 把整张权重矩阵存进 embedding 表。它不是 nn.ModuleList，而是 nn.Embedding(num_domains, out * in)，按 domain_id 查表后 view 回矩阵做批量矩阵乘。这个实现能高效支持同一 batch 逐样本选择域权重，但不是混域训练或均衡采样在数学上成立的前提；按域分组的其他实现也可以完成同样的采样策略。

  • 主干是 encoder 而不是 decoder。所有 token 在同一层里双向可见，动作 token 之间也没有因果掩码，注意力矩阵上不加任何掩码（掩码如何改变可见性见注意力机制）。块本身是最朴素的 pre-LN 结构，没有 DiT 式的 AdaLN 调制。

七、Flow Matching 与损失：论文定义与官方实现

X-VLA 被论文定义为 flow-matching-based 架构。但论文正文的速度场参数化与本页复核的官方实现并不是同一训练目标或同一采样器，这是读 X-VLA 时最容易出错的一处。本节把两层分开陈述。二者可以在 \(t>0\) 时作代数换算，却不能因此称为实现等价；完整推导放在子页 ③。

7.1 论文层的定义

论文第 2 节按标准条件流匹配写：记 \(A^0 \sim \mathcal{N}(0, I)\) 为纯噪声、\(A\) 为真实动作块，虚拟时刻 \(t \in [0,1]\) 从噪声端走向数据端，插值路径与训练目标是

\[A^t = (1-t) A^0 + t A, \qquad \mathcal{L}^{\mathrm{FM}}_{\mathrm{BC}}(\theta) = \mathbb{E}\left\lVert\, v_\theta(A^t, o, t) - (A - A^0) \,\right\rVert^2\]

推理侧论文写的是用 ODE 求解器沿 \(t\) 正向积分，\(A^{t+\Delta t} = A^t + v_\theta(A^t, o, t)\,\Delta t\)。按这套表述，\(t = 0\) 是噪声端、\(t = 1\) 是数据端，与 π0 的约定相反。

7.2 源码层实际做的事

# models/modeling_xvla.py，forward 节选（训练）
# docstring: "Diffusion-style noisy mixture of actions: x_t = t*noise + (1-t)*gt."
t = (torch.rand(1, device=input_ids.device)
     + torch.arange(B, device=input_ids.device) / B) % (1 - 1e-5)

action_noisy = torch.randn_like(action) * t.view(-1, 1, 1) + action * (1 - t).view(-1, 1, 1)
proprio_m, action_noisy_m = self.action_space.preprocess(proprio, action_noisy)

pred_action = self.transformer(domain_id=domain_id, action_with_noise=action_noisy_m,
t=t, proprio=proprio_m, **enc)
return self.action_space.compute_loss(pred_action, action)

三处与论文不同，每一处都能从上面这段代码直接读出：

  • 网络输出的是干净动作，不是速度场。 最后一行的监督目标是 action，即 dataloader 给的真值动作块本身。代码里没有任何 A - A0 形式的目标构造。这是 x0-prediction。
  • 时间方向相反。 代码写的是 \(x_t = t\,\epsilon + (1-t)\,A\)，即 \(t=1\) 为噪声、\(t=0\) 为数据。与论文的 \(t\) 满足 \(t_{\text{code}} = 1 - t_{\text{paper}}\)，因此源码方向反而与 π0 一致。
  • 时刻不是独立均匀采样。 令 \(L=1-10^{-5}\)、\(U\sim\mathcal U[0,1)\)，代码对第 \(k\) 个 batch 元素取 \(t_k=(U+k/B)\bmod L\)。共享的 \(U\) 让一个 batch 形成近等距的循环网格，样本之间因此相关而非独立。单个 \(t_k\) 的边缘分布也只近似均匀：长度 \(\delta=10^{-5}\) 的一段区间会被映射两次，其起点为 \((k/B)\bmod L\)，其余区间一次；这段重复区间随 \(k\) 平移，并非总在 0 附近。更准确的说法是“近似均匀的随机平移等距采样”，不能仅凭覆盖更均匀就断言训练梯度方差必然更低。

若沿源码路径定义速度 \(v=\mathrm{d}x_t/\mathrm{d}t=\epsilon-A\)，则对 \(t>0\) 有

\[v = \frac{x_t-A}{t}, \qquad \hat v_\theta(x_t,t,c)=\frac{x_t-\hat A_\theta(x_t,t,c)}{t}.\]

因此 \(\lVert \hat v-v\rVert^2=\lVert \hat A-A\rVert^2/t^2\)。这说明从 x0 预测换算出的速度误差带有 \(1/t^2\) 权重；源码训练的未加权动作回归并不等于论文的未加权速度回归。它只是另一种可定义的监督目标，是否更好需要消融，而不能仅凭代数可换算得出。

7.3 推理：不是欧拉积分

# models/modeling_xvla.py，generate_actions 节选（推理）
# docstring: "Iterative denoising (linear schedule)."
x1 = torch.randn(B, self.num_actions, D, device=proprio.device, dtype=proprio.dtype)
action = torch.zeros_like(x1)

steps = max(1, int(steps))
for i in range(steps, 0, -1):
t = torch.full((B,), i / steps, device=proprio.device, dtype=proprio.dtype)
x_t = x1 * t.view(-1, 1, 1) + action * (1 - t).view(-1, 1, 1)
proprio_m, x_t_m = self.action_space.preprocess(proprio, x_t)
action = self.transformer(domain_id=domain_id, action_with_noise=x_t_m,
proprio=proprio_m, t=t, **enc)
return self.action_space.postprocess(action)

循环里没有任何累加，不存在 x = x + v * dt 这一步。实际发生的是：

  1. 采一次初始噪声 x1，整个循环中固定不变，永不重采样；
  2. 当前的干净动作估计 action 初始化为全零；
  3. 每一步用 x1 和当前估计按当前 t 重新线性混合出一个含噪输入，再让网络重新预测一次干净动作。

这可以描述为 x0-parameterization 下的固定噪声重混合递推，但代码没有给出收敛证明。平方损失在总体风险下的最优输出是 \(f^*(x_t,t,c)=\mathbb{E}[A\mid x_t,t,c]\)，而不是每条样本的真实动作；精确到 \(t=1\) 时，若 \(\epsilon\) 与动作在条件 \(c\) 下独立，则 \(x_t=\epsilon\)，最优连续输出退化为 \(\mathbb{E}[A\mid c]\)。后续混合中的 action 是上一步模型估计，不是真实动作，因此不能由 \(t\) 下降推出“真实成分增加、预测必然更准”，也不能由默认 10 步推出单调收敛。

两个边界必须同时看到：其一，x1 是循环唯一显式的随机采样源；固定观测、权重与 x1 并启用确定性算子时，递推可复现，但 GPU 非确定性仍可能造成数值差异。其二，训练采样位于 [0, 1-1e-5)，推理却从精确的 t=1 开始，再止于 1/steps。因此首步依赖未被精确训练的边界泛化；而 t<1/steps 的近数据端区域虽在训练中出现，却不会被推理直接查询。默认步数是否足够只能用闭环消融验证。

7.4 损失的完整定义

监督目标是干净动作。对本页核验的默认 ee6d 动作空间，损失不是速度场均方误差，而是以下分项组合（层二，EE6DActionSpace.compute_loss）。joint、agibot_ee6d 与 auto 的通道、权重及夹爪目标不同，不能直接套用此式：

\[\mathcal{L} = 500 \cdot \mathcal{L}^{\mathrm{MSE}}_{\text{pos}} + 10 \cdot \mathcal{L}^{\mathrm{MSE}}_{\text{rot6d}} + 1 \cdot \mathcal{L}^{\mathrm{BCE}}_{\text{grip}}\]
分项 通道 损失形式 权重 为什么是这个量级
位置 0–2 与 10–12 MSE 500.0 末端位置以米为单位，一次抓取的位移常在 0.01 量级，平方后到 \(10^{-4}\)，不放大则梯度被其他项淹没
旋转 3–8 与 13–18 MSE 10.0 Rotate6D 的分量是单位向量的坐标，量级接近 1，平方后本身就比位置项大若干数量级
夹爪 9 与 19 BCEWithLogits 1.0 二值开合是分类而非回归问题，交叉熵的数值量级与两个 MSE 项本就不同

源码只证明三个系数的取值与求和方式，没有给出选择它们的单项消融。按量纲分析，500 / 10 / 1 可理解为对米制位置、Rotate6D 分量和 BCE 数值尺度的工程配平；它不等于“位置在任务语义上比旋转重要 50 倍”。位置与旋转分别对左右臂两段 MSE 求和，夹爪对两通道 BCE 取平均，三项最后直接相加。

两个容易漏掉的实现细节：

  • 默认 ee6d 的数值夹爪通道在输入端被置零。 preprocess 会清零含噪动作与本体状态中的夹爪维，因此模型无法直接读取这两个数值通道；它仍可利用图像、语言、其余 proprio/action 通道和域条件间接推断开合状态。这个结论不能推广到不执行该预处理的其他动作空间。
  • 推理时夹爪要过 sigmoid。训练用的是 logits，postprocess 负责把它变回 \([0,1]\)；各评测客户端再按各自的阈值二值化，而这些阈值并不统一，详见子页 ⑥。

九、训练与适配：一页纸版本

9.1 预训练

论文的预训练数据是 290K 条 episode，来自 Droid、RoboMind、AgiBot 三个来源，覆盖 7 个平台／硬件配置与 5 类机械臂（层一）。训练效果同时依赖表示对齐、采样、架构与优化。Table 1 把动作对齐、意图抽象和均衡采样作为一个组合加入，因此只能读出组合边际变化，不能拆出三者各自的独立贡献。

三件事：

  1. 动作对齐。把各数据源原生控制量转换到统一的末端位姿表示，减少同一通道跨域语义冲突；各平台的坐标约定和控制接口仍需 handler 正确实现。
  2. 意图抽象。在各域配置的未来时间窗内等间隔插值 30 个锚点，把不同采集频率映射到统一的时间坐标与张量长度。它不会自动消除坐标系、动作尺度或插值信息损失。源码没有独立的 anchor 模块；重采样发生在数据侧 domain_handler。
  3. 目标混合采样。论文称其为 balanced sampling，但并非七个域等概率：源码按预设数据源权重抽取，并在轨迹级与帧级再打散。它改变的是期望训练分布，目的在于避免直接按轨迹数量采样时大数据源压倒其他域；权重本身仍是需要选择的超参数。源码中的前七项权重与论文 Table 8 一致，例如 AGIBOT 为 0.4、Droid 左右各 0.15、RoboMind-Franka 为 0.1。

主干与所有数据源的 Soft Prompt 在预训练阶段联合优化。每个 batch 里的样本各自按 domain_id 取对应的私有权重，因此一个 batch 可以同时包含多个本体。

论文给出的预训练规模是 64 张 A100、全局 batch 1024、200K 迭代、bf16，耗时约 4 天（层一，Table 7）。

9.3 优化配置里的三个坑

官方 train.py 把参数分成 vlm、transformer_core、soft_prompts、action_heads 四组分别调度。先注意一个阶段边界：论文预训练从第一步起联合优化主干与 prompts；论文的“前 1000 步局部更新 + 1000 步恢复”属于下游适配。固定脚本没有预训练/适配模式开关，默认 freeze_steps=1000 会作用于所有运行，因此复现论文预训练时应显式重新设定调度，不能把脚本默认值当作论文配方。另有三处实现边界（层二）：

  • learning_coef 不只作用于 soft prompt。README 与命令行帮助都写成 "LR multiplier for soft prompts"，但代码里它同时乘在 vlm 组上。论文正文第 4.2.1 节的表述反而更准确：降低的是 soft prompt 以及视觉语言模块的学习率。
  • freeze_steps 不等价于真正冻结。它只把 vlm 与 transformer_core 的学习率置为 0：参数值暂时不变，但梯度仍计算和同步；对本步 grad is not None 的参数，AdamW 一、二阶矩仍更新，而且这些梯度参与全局范数裁剪，可能影响 prompt 与动作头的有效更新。它也没有获得真冻结通常带来的前后向、通信和优化器状态节省。
  • warmup_steps 默认不生效。它只在显式传入 --use_cosine_decay 时才被读取，而该开关默认关闭、README 的示例命令里也没有它。照抄示例命令跑，--warmup_steps 2000 是个摆设，1000 步之后学习率就是恒定值。

10.3 扩展性

论文沿模型容量、数据多样性和数据总量三个轴做了扩展性实验，并在所测试范围内观察到性能继续改善、尚未明显饱和。这支持“继续扩大可能仍有收益”，但不证明曲线会在更大规模保持同一趋势，也不能据此断定 0.9B 是最优性价比点。

10.4 证据边界与论文自陈局限

  • 不是免适配的通用控制器。 论文中的新平台仍需目标域示范、域专属 prompt 与动作投影，并经过适配；任意新本体即插即用仍是未来方向。
  • 监督信息仍然偏低维。 30 个动作锚点能压缩短期意图，却没有显式提供 3D 推理、物理动力学或中间子目标；论文把更丰富监督与自监督目标列为后续方向。
  • 扩展趋势只覆盖已测试区间。 0.9B、当前数据规模与当前基准上的未饱和曲线不构成更大规模的保证，也没有给出算力—收益最优点。
  • 开放实现与论文算法存在落差。 第七节记录的 x0 回归与固定噪声重混合递推来自公开代码，不应被论文的 Flow Matching 名称自动背书；部署前应以目标 checkpoint 对应的代码快照做闭环验证。

更准确的概括是：所核验的 π0 实现没有显式 domain_id，而通过固定宽度接口、mask 与观测条件处理平台差异；X-VLA 在统一动作表示之外，额外用 domain_id 选择 Soft Prompt 与动作边界投影。两者都做条件建模，差别在于当前实现是否设置专门的域条件通路，而不是“一个处理异构性、另一个完全不处理”。

11.2 时间方向约定：必须分层比较

上一版本页把 X-VLA 与 π0 的时间方向写成「相反」。这在论文层成立，在源码层不成立，因此拆成三列。

十二、最容易误解的几点

  • 「X-VLA 回归速度场」是错的。论文第 2 节确实给了速度场的流匹配公式，但当前官方实现直接回归干净动作。凡是基于论文公式写的复现代码，与官方权重的行为不一致。见第七节。
  • 「推理是欧拉积分」是错的。去噪循环里没有累加，是用固定初始噪声与当前估计重新混合后再预测。把它当成 ODE 积分去改写采样器，会得到完全不同的轨迹。
  • 「只有 Soft Prompt 是私有参数」不完整。动作的输入投影与输出投影同样按数据源查表。忽略这一点，迁移到新本体时只处理 prompt 而不处理两个动作投影，模型拿不到正确的量纲映射；固定训练脚本也不会自动创建或重置任何新域行。
  • 「30 个 anchor 是网络里的一组 query」是错的。源码中不存在 anchor 模块，它就是动作块长度 30；「锚点」这个说法描述的是数据侧在固定时长窗口内的等间隔重采样。
  • 「20 维里后 10 维是 padding」只在单臂时成立。双臂平台上 10–19 是右臂的位置、旋转与夹爪。
  • 「位置损失权重 500 说明位置在语义上重要 50 倍」是误读。从数值尺度看，它可解释为米制位置、Rotate6D 与 BCE 的工程配平；论文和源码没有提供权重消融，不能把这一解释当作作者证明。
  • 「默认 EE6D 模型能直接读取数值夹爪状态」是错的。preprocess 会清零 proprio 与含噪动作中的夹爪维，但图像、其余状态与动作通道仍可能提供间接线索；其他动作空间还需分别检查。
  • 「X-VLA 能对全新本体零样本迁移」论文没有证明。论文只做了 t-SNE 聚类与「冻结近亲 prompt」两个观察性实验，并把零样本列为待探索方向。prompt 插值实验论文完全没有做。
  • 「序列恒定为 262 个 token」不准确。262 来自公开配置的三视角槽、50 个文本槽、30 个动作槽和 32 个 prompt；缺失视角仍保留零槽，但修改视角槽数、文本长度或动作块会改变总长。
  • 「默认 10 步已经足够或最优」没有证据。源码只给出默认值，论文没有步数消融；改变步数会改变整条反馈递推，质量与延迟应闭环测量。
  • 「论文表中的每一项都排名第一」不成立。CALVIN ABC→D 的 4.43 低于表内 FLOWER-1B 的 4.53；“领先”还只针对论文 Table 2 当时列出的对照方法，不是动态排行榜结论。
  • README 的数字与论文的数字不是同一套。两者在多个基准上不一致，引用时必须说明口径。
