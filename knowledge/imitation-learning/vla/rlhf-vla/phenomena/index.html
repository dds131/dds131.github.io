RLHF-VLA/异常现象与诊断

RLHF-VLA · DIAGNOSTICS · CONTAIN BEFORE EXPLAIN

异常不是根因，相关性不是机制，修复后曲线变好也不是独立复验；P0/P1 先进入安全态并保全证据，任何诊断试验都不得绕过硬安全层或扩大未经授权的真实暴露。

本页接收 Online System 的运行/事故证据或 Implementation 的源码/复现证据，按六个故障域建立可证伪诊断。当前所有 test 均为 not-run，没有根因确认、真实暴露、系统安全或复现成功声明。

contain before explainmerge policy: any24 versioned contractstests executed: 0

双入口、严重度与 containment

Online handoff 提供 role bindings、event/view/run/evaluation/deployment lineage、clocks、freshness、gate、canary、rollback、SLO、incident 和四段 action evidence；它不能证明 implementation file、commit 或 test status。Implementation handoff 提供 repository pins、capability claims、concept map、gaps、patch/SBOM/license、test plan 与 reproduction level；静态审计不能生成真实 success、failure、安全事件或运行曝光。

merge_policy: any 表示任一合法入口足以建立受限 case。双入口同时存在时只按 artifact hash、commit、config digest、schema revision、role 和 time window 显式 join；同名字段不合并。冲突建立 EvidenceConflictRecord 并阻止因果结论。无 handoff 时只能教材阅读，case creation 与 topic completion 禁用。

flowchart LR
  O[Online runtime and incident evidence] --> R{explicit join}
  I[Implementation source and reproduction evidence] --> R
  R --> C[diagnostic case]
  C --> S{P0 or P1}
  S -->|yes| K[contain · safe state · preserve]
  S -->|no| W[freeze observation window]
  K --> H[competing hypotheses]
  W --> H
  H --> T[discriminating test plan]
  T --> A[independent acceptance]

P0 为人员/设备即时风险或硬安全失效：现场安全 authority 进入安全态、隔离能量/区域、停止 Candidate 暴露并走事故流程。P1 为安全退化、版本错配或 LKG 不确定：release 与 safety 双 authority 停流、冻结证据、验证 LKG。P2 保持 Champion、Candidate 仅离线/授权 shadow；P3 冻结窗口和配置、补观测而不扩大范围。

数据、测量与 Reward Model

先检查 metric/evaluator definition/version/direction/unit；再查 numerator/denominator/exposure、dedup、missing/late data；再查 task/scene/seed/operator mixture 与 allocation；再查 split/group lineage、same-parent leakage 与 label revision；再查 policy/RM/evaluator artifact 和 event time；全部通过后才比较 model mechanism。

reward 上升而真实指标下降至少有七个竞争解释：policy 利用 proxy shortcut；RM 在 Candidate-induced distribution 上失准；component/weight/config/version 漂移；success evaluator 或 label 错；test population/allocation 改变；logging/join/clock/aggregation 错；策略能力退化但与 RM 无直接机制。ensemble disagreement 只是 heuristic，不是 OOD 证明、ground truth 或 safety veto。

区分性证据包括：同一 immutable trajectory 用旧/新 RM、calibrator、config 重算；hidden human/golden evaluator 对高 RM failure 盲审；保持 task fact 的遮挡/反事实扰动；按 policy/task/scene/background/duration/stopping 分层；检查 evaluator independence。降低 weight、补 hard negative、再校准或补数据都只是候选修复。

PPO 数学不变量

对 $a_t\sim\pi_b(\cdot\mid h_t)$，逐样本 log-ratio

\[k_t=\log\pi_b(a_t\mid h_t)-\log\pi_{ref}(a_t\mid h_t)\]

可以为负。只有共同支持、正确 measure 且对 $\pi_b$ 取期望时，$D_{KL}(\pi_b|\pi_{ref})=\mathbb E_{a\sim\pi_b}[\log(\pi_b/\pi_{ref})]\ge0$。面板必须记录 policy role/hash、sampling policy、random variable、support/measure、processor/transform、exact/sampled/approx estimator 与 token/step/chunk/episode aggregation，字段名 kl 不足以定义指标。

Current=Reference 且 processor/codec/mask/action 相同时，每个有效位置 log-ratio 应在预注册容差内为 0；不能只看会正负抵消的 batch mean。

applicability_preconditions: {same_artifact: true, same_processor_codec: true, same_condition_action_mask: true}
random_variable_measure: pending

tolerance: pending
expected: zero

PPO ratio 为 $r_t(\theta)=\exp[\log\pi_\theta(a_t\mid h_t)-\log\pi_{old}(a_t\mid h_t)]$。optimizer 第一步前，Current 与 Old 的 artifact、condition/action、processor/mask 相同则有效位置应为 1；否则先查 role binding、freshness、serialized Old log-prob、动作变量、precision 与 worker version，不先扩大 clip range。clipping 不是 hard KL bound 或安全保证。

常见非负近似 $\widehat D=N^{-1}\sum_t[(r_t-1)-\log r_t]$ 依赖 $x-1-\log x\ge0$；不同 estimator 不能只按同名 kl 比较。对非负 importance weights，$ESS=(\sum_iw_i)^2/\sum_iw_i^2$；signed/negative weights 或强依赖 step 不能解释为独立样本数，低 ESS 只是权重集中信号。

$EV=1-\operatorname{Var}(y-\hat y)/\operatorname{Var}(y)$；当 target variance 小于阈值时状态是 undefined-low-target-variance。EV<0 不自动等于数值发散。GAE 必须把 task terminal、valid time-limit truncation、safety abort、operator intervention、environment error 和 missing next state 分开定义 bootstrap；不能压成一个 done。

来源与外推边界

固定版本来源

  • PPO v2（2017-08-28）：支持 surrogate、policy ratio 与多 epoch minibatch 背景；不定义 VLA chunk、RM、安全或事故流程。
  • GAE v6（2018-10-20）：支持 bias/variance 折衷；不决定 terminal/truncation/intervention/safety-abort 的 bootstrap 合同。
  • Deep RL from Human Preferences v4（2023-02-17）：支持 trajectory segment pair 与 reward predictor 分离；不证明 VLA 真机安全。
  • Reward Model Overoptimization v1（2022-10-19）：proxy overoptimization 是合理候选；synthetic gold setup 不允许本站仅凭曲线宣布 reward hacking。
  • DPO v3（2024-07-29）：语言模型 pair objective 来源；不能无验证迁移到连续动作 density 或闭环控制。
  • APO v3（2025-10-30）：human-assisted VLA refinement、binary desirability 与 adaptive reweighting；不能用普通 DPO 诊断替代。
  • RLIF v2（2024-03-18）：intervention signal 的 off-policy RL；不把任意接管自动解释为 reward 或 native VLA 接口。
  • GRAPE v2（2025-02-04）：trajectory-level VLA preference 与时空 constraint；不外推本站任务、硬件或其他 objective。

公式与合同分别属于论文事实、常见 estimator、源页工程建议或本站诊断 formalization；没有把本站 schema 归因给上游。当前未运行训练、模型、测试、评测、仿真、SIL、HIL、服务、部署或机器人，未修改只读源站，未上传、发布或备份，也未产生任何 root-cause-confirmed 或 safety-approved 结论。
