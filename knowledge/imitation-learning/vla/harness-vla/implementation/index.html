复现 claim ladder

“仓库能安装”“进程退出 0”“Planner finish”“一条 seed 成功”和“论文数值复现”是五种不同主张。证据等级不能跳跃。

Level 名称 最小证据 可以写 不能写
0 Source snapshot audit commit、dirty state、文件/SHA、符号/docs 固定提交存在该实现 代码已运行
1 Offline framework validation resolved env、CPU unit tests、command/log 指定 tests 在该环境通过 模型链或任务成功
2 Component/policy-chain validation model/assets、component/GPU lifecycle 指定 chain 可启动/调用/清理 native task success 或 benchmark score
3 Benchmark protocol reproduction protocol/treatment/snapshot、all cells、native success、raw results 该 manifest 下复现 aggregate 论文机制已复现
4 Paper number/mechanism audit paper-matched scope、lineage、recomputed table、trace/ablation 特定 paper row/机制得到核验 跨平台普遍成立 
flowchart LR
  L0["L0 source snapshot"] --> L1["L1 offline unit"]
  L1 --> L2["L2 component / GPU"]
  L2 --> L3["L3 benchmark protocol"]
  L3 --> L4["L4 paper row / mechanism audit"]
  N["negative evidence + not-run layers"] -.required at every level.-> L0
  N -.-> L1
  N -.-> L2
  N -.-> L3
  N -.-> L4

每条 claim 同时保存未运行层级、缺失 artifacts、dirty/dependency drift、non-comparable protocol fields、failed/skipped/timeout cells、native result availability、unresolved discrepancy、reviewer 与日期。import 成功不等于 unit suite；service health 不等于 tool semantics；finish_result、zero exit code、video 与 no exception 都不等于 environment success 或 safety approval。

本轮只完成 L0-source-audit-only：没有创建 Python env、安装 dependency、下载 model/Memory/asset、启动 service、运行 test/benchmark/simulator/SIL/HIL 或机器人。

ReproductionClaimRecord:
  claim_id: <opaque-id>
  text: <exact-claim>
  level: 0 | 1 | 2 | 3 | 4
  protocol_id: <id-or-null>
  treatment_id: <id-or-null>
  result_snapshot_id: <id-or-null>
  source_revision_id: <id>
  positive_evidence_refs: [<ref>]
  negative_evidence_refs: [<ref>]
  not_run: [<layer>]
  noncomparable_fields: [<field>]
  status: supported | contradicted | partial | not_computable | unknown
  reviewed_at: <timestamp>

entrypoint 与调用链

flowchart TD
  A["rpent console script"] --> B["cli.main.main · two-phase argparse"]
  B --> C["enumerate / get RobotSpec"]
  C --> D["validate_args + parse_config"]
  D --> E["prepare_run_memory"]
  E --> F["build_planner + render prompts"]
  F --> G["robot_spec.init_runtime"]
  G --> H["get_toolkit"]
  H --> I["planner.solve"]
  I --> J["Toolkit.list_tools / execute_tool"]
  J --> K["strict validation + scheduler + handler"]
  K --> L["get_env_state + StepRecord"]
  L --> M["toolkit close + daemons stop"]
  M --> N["transcript + optional finalize/merge"]
  N --> O["process exit"]

CLI 先解析 robot/dashboard 等 early fields，加载对应 RobotSpec 后再添加 adapter flags：--robot 决定合法 options；fixed commit 的 --env 是 deprecated alias；global help 与 robot-specific help 不同；dashboard/terminal interactive 有互斥规则；real-robot adapter 可能要求 TTY/operator confirmation。

prepare_run_memory 在 init_runtime 前执行。evaluation 默认 HF profile，exploration 默认 local profile；adapter prepare_memory hook 可负责 sync/select 和 memory_dir。这必须遵守 Memory 页的 snapshot、read-only 和 leakage contract。

Planner 获得 prompts、Toolkit 与 turn budget；tool schemas 来自 Toolkit.list_tools()，调用进入 Toolkit.execute_tool()。current dispatch guards 包含 unknown tool、Pydantic strict validation、readonly/state-advancing scheduling、cancellation admission、handler exception capture、elapsed time、get_env_state、StepRecord publication、JSON serialization guard 与 scheduler release in finally。它们不是 independent robot safety proof。

Cleanup 要记录 Toolkit close、operator input close、owned daemons stop；请求 stop 不证明所有 external process 或 physical motion 已安全停止。CLI return code 只受 agent_error 控制，不等于 native task success。

config、dependency 与 asset identity

每个 resolved field 同时保存 provided value、default source、resolved value、owner symbol；只保存最后一条 CLI 会丢失 adapter default、environment-derived value 与 precedence。

category examples required identity

固定 repo 根目录没有完整 uv.lock、poetry.lock、Pipfile.lock 或 full requirements lock。pyproject.toml 同时有 exact pins、range specs 与指向 main、rpent、release branch 的 VCS refs；extras 有 explicit conflicts。editable install 的最终 graph 依赖 resolver time、index、platform 与 VCS head；package 0.0.0 不能替代 commit。

Future dependency runbook 只能在 disposable checkout、隔离环境和明确授权下运行，并选择一个 robot extra。它需保存 resolver、Python/platform、resolved distributions、VCS full commits、wheel hashes、index class 与 install log；本轮没有运行安装或访问网络获取依赖。

模型、Memory、simulator assets、task definitions 分别建 manifest。路径存在不是 hash verified；代码 Apache-2.0 也不延伸到 third-party assets。container 保存 immutable digest 而非 tag，并保存 OS/arch/Python/CUDA/driver/GPU/CPU/memory/topology。

Stage A 只读固定 repository/commit/files/symbols/docs/test map/declarations；本轮仅完成这一层。Stage B 需网络/安装授权，选择一个 extra，解析 distributions/VCS/wheels；不默认下载 model/Memory/simulator asset。Stage C 只跑 offline CPU framework，不连 external service。

license、security 与 safety gate

Fixed repository LICENSE 是 Apache License 2.0；它不自动覆盖 third-party models、datasets、simulators、assets、SDKs、services、firmware 或 recordings。

公开 manifest 只保存 credential variable name、source class、present/absent、provider/model identity、redaction policy 与 approved opaque ref；不保存 raw key/token/password/cookie、account identity、private endpoint/address、proxy credential、signed URL、full environment dump 或 sensitive request payload。

Transcript、prompt、image/video、Memory、stack trace 与 CLI may contain sensitive data。先分类，再生成 provenance-linked redacted derivative；不能修改 original 后仍宣称 hash unchanged。

Safety gate：source/unit 默认不启动 model/environment；GPU/simulator 需显式 resource/run authorization；real robot 需 operator、workspace、calibration、E-stop、watchdog、reset 与 incident procedure。Planner/tool success 不授予 actuator permit；诊断文字不授权 recovery；页面没有执行按钮、真实 endpoint、pose/coordinate/device path。

Supply-chain manifest 记录 repository/index class/VCS commits/artifact hashes/signatures or attestations/build log/SBOM。hash mismatch、untrusted source、unexpected binary 或 unresolved license 直接停止，不能以“能 import”覆盖风险。
