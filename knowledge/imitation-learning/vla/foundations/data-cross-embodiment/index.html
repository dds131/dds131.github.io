专题总览 3 动作表示与生成目标 4 数据与跨本体 5 模型谱系

视觉—语言—动作（Vision-Language-Action，VLA）数据不只是图像、指令和动作 tensor。每个训练样本都应能追溯到采集方式、机器人与传感器版本、坐标/时间/控制语义、清洗与跨本体转换、split、sampling、许可和隐私决定。统一容器让数据可读，版本化契约才让混合训练可解释。

  • 同一个 shape 或字段名不代表同一个物理语义。 跨本体混合前必须冻结 frame、unit、rate、controller、reference、mask、normalization 和 adapter。
  • 统一格式不等于统一数据分布。 原始规模、过滤后规模、期望 sampling probability、经验 batch 占比和 gradient contribution 是五个不同口径。
  • Split 必须先按实体分组，再产生 window。 随机打散同一 episode、scene、session、operator、robot 或 lineage 的重叠窗口会制造高隐蔽泄漏。
  • 公开可访问不等于可任意训练、再分发或展示。 License、consent、privacy、retention 与 takedown 必须跟随 lineage。
  • 来源必须分层。 Synthetic、simulation、scripted、policy rollout 与 human demonstration 可以共同训练，但不能在 manifest 中被压成同一个“机器人数据”来源。

RLDS、Open X-Embodiment（OXE）、LeRobot 与 DROID 位于不同层级；本页只提供跨格式审计语言。具体数据版本、字段与许可必须回到官方 release、数据卡和目标模型代码核验。本页不下载数据、不运行 ETL、去重、统计或训练作业，不连接相机、机器人、controller 或对象存储，也不收集任何真实人员和站点信息。

采集方式、数据单位与 Provenance

Provenance 不是一个来源字符串，而是一份可验证说明：谁或什么系统在何时、何地、以哪套机器人、工具、传感器、控制器、标定、软件和采集策略产生了行为；之后又经过哪些转换。缺少这些信息的数据即使能被 loader 读取，也不能判断其动作语义、行为分布和使用边界。

先区分谁在产生行为

采集方式 行为来源 优势 偏差与必填 provenance
teleoperation 人通过 VR、SpaceMouse 或主从臂控制 意图直接，可覆盖精细操作 operator、device、mapping、latency、experience、prompt、reset
play data 人在弱约束环境自由探索 覆盖广，含自然过渡 意图与成功不明确，需后续分段和语言标注
scripted 规则、轨迹模板或 planner 可重复、标签清楚、成本可控 script/version、randomization、failure condition、行为单一
simulation 仿真器、脚本或策略 状态和几何真值丰富 simulator、assets、physics、randomization、sim-real gap
autonomous rollout 特定 policy/checkpoint 接近策略诱导分布，可见失败和恢复 behavior policy hash、exploration、safety filter、accept/reject
correction/intervention 人在策略执行中接管或纠正 聚焦偏离和高风险区域 trigger、control state、handoff latency、pre/post context
synthetic/pseudo-action 生成模型、重放、重定向或逆动力学 扩展场景和任务 generator、seed、prompt、filter、pseudo-label model、confidence

同一个 episode 可由人启动、策略自主运行、人在中途 intervention、再由安全系统终止。仅保存 episode 级 collection_method=mixed 会抹掉策略何时拥有控制权。step 或 segment 必须记录 control_source、intervention_state、切换时间和触发原因，并将操作者动作、模型候选、supervisor 拒绝与 controller 接受分开。

五种计数单位不能混写

单位 定义 常见用途 不能直接比较
episode/trajectory 一次 reset 到结束 任务覆盖、成功率、采集成本 长度差异大的训练贡献
segment 同一 subtask/control source 的连续区间 纠正、技能和来源切分 完整任务成功
step/frame 一个逻辑时间索引的记录 存储量和传感频率 真实时长与有效 transition
transition 对齐后的 observation-action-next observation BC 与 offline RL 视频帧和原始 sensor packet
window/chunk 从序列抽取的上下文或未来片段 policy batch 原始 episode 和独立样本数

报告“百万样本”必须同时给出 unit、过滤前后数量、平均和长尾长度、有效 mask、window stride 与 overlap。一个长 episode 可以产生许多高度相关窗口；一小时视频也不等于一小时有效动作标签。计数口径应进入 release manifest 和图表标签，不能只藏在脚注。

Collection manifest 最小字段

episode 级 identity 至少含 dataset_id、release_id、episode_id 与 session_id。采集侧保存 method、control-source segments、site/environment/scene/task 的受控 ID；人的信息只用匿名稳定 ID、experience bucket 和受限 consent reference。硬件侧引用 embodiment、tool/gripper、controller config、sensor schema、camera role、calibration bundle 与 clock map。

软件和过程还要记录 acquisition software、firmware、teleop mapping、behavior policy/checkpoint hash、instruction source、annotation stage、reset protocol、start precondition、stop reason、timezone policy、raw artifact hash 与 ingest transform。公开 manifest 不得含姓名、账号、邮件、网络地址、对象存储路径或访问令牌。标识符需要稳定以便撤回和去重，但不应使外部读者反推出个人或现场身份。

真实、仿真、自动与合成必须分层

固定 source_tier 至少区分 real-human、real-scripted、real-policy、simulation、rendered-or-generated-video、pseudo-action 与 derived。真实机器人并不等于人工示范；生成视频也没有真实控制动作。IDM、LAPA 或其他模型产生的伪动作必须指向 generator、checkpoint、输入父项、置信度和筛选规则。

派生数据要同时引用原始父项和 transform。裁剪、重采样、重新标注、retarget、窗口化、去标识、补伪动作都产生新的 lineage 节点；它们不能以新文件名伪装为独立采集。训练混合可以选择多个 tier，但每个 tier 的数量、采样与结果必须分层报告，不能把合成数据的规模当成真实机器人覆盖。

flowchart LR

采集协议本身应建模为状态机：preflight、reset、ready、recording、paused、intervention、fault、terminating 与 reviewed 不能只靠视频推断。每次转换记录触发者、timestamp、证据与可恢复条件，尤其要区分 operator 暂停、controller 故障和任务自然结束。若 recorder 在 fault 后仍写入帧，后续门禁必须知道这些记录是否可作为观测、恢复样本或仅作诊断，不能一律裁掉或并入成功片段。

行为分布还受采集界面和安全过滤器影响。teleoperator 看见哪些相机、控制映射是否有 deadband、策略 rollout 的候选动作被 supervisor 拒绝多少、script 是否只覆盖理想轨迹，都会改变可观测的数据。manifest 应保存界面版本、过滤前候选的可用性、拒绝原因统计和人工接管条件，使“失败少”不会被误解为策略更好，也不会把安全层的作用归给模型。

provenance 字段必须在 ingest 时生成并随 artifact 固定，不能等训练失败后凭文件名补写。后补字段要形成带 author/reviewer role、时间和依据的新 annotation revision；无法核实的值保持 unknown，不允许用同批次最常见配置批量填充。对跨站点集合，局部 ID 先映射为全局 opaque ID，同时保留映射表的受限访问边界和撤回 owner。

采集覆盖评估要同时看任务、动作、场景与故障分布。大量静止帧会放大 step 数，短成功 episode 会放大 episode 数，密集窗口会放大训练样本数；任何一种都不能单独证明覆盖。发布报告至少按 source tier 和 control source 给出持续时间、有效 transition、独立 session、intervention、failure/recovery 与被拒绝片段，使后续 mixture 能基于真实可用池而不是宣传数字。

Episode/Step Schema 与标签语义

Episode 是一次 reset 到结束的序列边界，不自动等于任务成功；step 是逻辑时间索引下的结构记录，可能包含多路不同源时间；transition 则由明确对齐规则形成。容器、物理含义和任务标签是三套责任，不能由一个 done 布尔值代替。

RLDS 只定义最小序列容器

机器人学习数据集（Reinforcement Learning Datasets，RLDS）按 episode 组织，每个 episode 含 steps 与可选 metadata。is_first 和 is_last 描述边界；is_terminal 区分终止性质，但 observation、action、reward、discount 及 metadata 的存在、shape 和物理含义仍由具体数据集决定。

is_last=true 只表示最后一步，不等于 success。truncated ending、timeout、abort、operator stop、controller fault 和正常 terminal 需要独立 reason；final observation 后的 action/reward 可能没有普通 transition 语义。两个数据集都采用 RLDS 也不能直接 concat，仍要核对相机、动作、坐标、单位、频率、语言和许可。本页把 RLDS 当容器实例，不把 TensorFlow、TFDS 或某个 loader 变成 VLA 唯一实现。

episode ID 必须全局稳定，或与 dataset/release 组合唯一。重切分、重标注、脱敏和格式转换不能悄悄复用相同 ID 表示不同内容；派生 episode 获得新 ID 并保留 parent_episode_ids 和 raw offsets。header 引用的 schema、calibration、clock、license 和 parent 都要能解析，悬空引用直接阻断 release。

Step record

每个 step 至少有单调 step_index 和 canonical timestamp；每路 modality 另存 source timestamp、clock ID、arrival timestamp、valid、freshness 与 missing reason。observation 按 camera、depth、proprioception、force、tactile 分字段；action 引用 Action ABI、reference timestamp，并明确 commanded、submitted、accepted 与 measured。

step 还记录 persistent instruction、event annotation 或当前 subtask，以及 is_first、is_last、is_terminal、success/failure、correction/intervention、control source、quality flags 和 step/dimension/modality/action-valid masks。raw record/hash offset 让每个训练窗口能返回原始 artifact。只保留对齐后的单一 timestamp 会让因果关系、延迟和修复过程无法审计。

标签 作用域 例子

done=true 不能替代这些字段。success 必须指向 evaluator、证据、判定时间与 revision；失败可以有多个根因、责任 owner 和可恢复性。unknown 不是失败，也不能在清洗时默认为 success。人工停止、急停和 controller fault 都要与任务结果分开，防止把安全触发统计成普通 timeout。

Language 与 annotation provenance

operator prompt、持续指令、event/subtask annotation、post-hoc caption、generated/rephrased language 和 evaluator note 具有不同时间可用性。每条语言标注要记录 language/locale、source、human 或 model、timestamp coverage、confidence、revision，以及是否允许作为 policy input、training target 或仅作审核证据。

事后观看完整轨迹写出的 caption 可能包含结果，不能无说明地送入早期 step 的输入。paraphrase 扩充了语言表达，却没有产生新的行为 episode；统计时要保留 parent annotation。模型生成文本还需 generator/checkpoint、prompt、筛选和人工复核状态，不能与原始 operator 指令混为同一证据等级。

schema evolution 要区分 storage change 与 semantic change。增加可选 metadata、重排文件分片或更换 codec 可能不改变样本含义；调整 action 字段顺序、frame、unit、terminal rule 或 language coverage 则必须升级语义版本。migration 需要 old/new schema、逐字段映射、不可逆损失、fixture 与回滚边界；loader 能读取新文件并不代表旧 checkpoint 仍能正确消费。

transition、window 和 action chunk 都是从 episode 派生的 view。其 manifest 要冻结 anchor index、history length、future horizon、stride、边界 padding、drop rule、mask、label cutoff 和 parent offsets。训练端若临时改变 stride 或过滤空窗口，实际样本池已经变化；必须产生新的 view ID 和 counts，不能只修改 dataloader 参数却继续引用原 release。

标签冲突应保留 disagreement，而不是强制多数票覆盖。两位 annotator 对 success、subtask 边界或 intervention 原因意见不同，可以记录各自 label、confidence、guideline revision 和 adjudication；未知项也可以保留。若后续重新裁决，要新增 revision 并说明哪些 split、stats、mixture 和历史结果受影响，避免无声改变 benchmark ground truth。

episode 边界验证需要从 reset 和 controller 状态交叉取证。is_first 前应有可解释 reset/start precondition，is_last 后不能继续出现同一 episode 的 accepted action；recorder restart、clock epoch 变化和人工暂停不一定等于新 episode。拼接或切分时要保存父 offsets 与边界原因，并检查语言、calibration、control source 和 task state 是否跨边界错误继承。

同步、标定、清洗与质量门禁

多模态 tensor 能拼接不代表它们描述同一时刻。相机曝光、状态读取、力传感、动作提交和 controller 响应可能来自不同 clock，并经过不同驱动缓存和滤波延迟。数据工程必须保留原始时间，再由版本化 clock map 构造可审计的 canonical timeline。

Causal alignment

以 anchor time t 构造样本时，先冻结 observation cutoff，再定义每个 modality 取 previous、nearest、interpolation 还是 window aggregate；记录 frame age、允许的 stale threshold 和对齐误差。future action chunk 的起点必须晚于可用 observation，并区分 command 发出、生效和 measured response。

离线平滑和人工结果标签可以使用未来信息来产生 train-only target，但不能伪装成部署时可用 input。任何 t 之后才观察到的图像、状态、接触或任务结果进入 t 时刻 condition 都构成 future leakage。公式骨架是 t_canonical = clock_map(t_source) - latency_estimate；clock map、latency estimate、unit、误差和版本缺一不可。

Calibration bundle

清洗、去重与修复

清洗可以移除启动/复位异常段，隔离损坏帧或时间逆序，统一已知 gripper sign 和 rotation convention，检查语言覆盖区间，并给 failure、recovery、correction 添加显式标签。未知许可、标定或动作语义不能靠“看起来合理”修补，只能 quarantine 并等待 owner 决策。

去重结合 raw hash、perceptual/video similarity、metadata/entity key 和 trajectory similarity。近重复判断要保存算法、阈值、候选组、人工裁决与 split 处置；同一场景的两次真实执行不能因视觉相似就自动删除。去重和修复后重新计算 eligible counts、normalization stats、window yield 与 mixture base counts，否则 sampler 配置和实际 pool 会分裂。

时间对齐要有可重复 fixture，而不只看曲线是否平滑。可选择带已知同步事件、快速接触或离散 gripper 切换的短片段，核对 clock map 前后顺序、最大 residual、frame age 与 action response。每个 modality 的误差预算应由采集和控制 owner 定义；超预算样本标记 reject 或 quarantine，不能用更强插值把不确定性隐藏在连续信号中。

标定验证除单次 residual 外，还应检查跨样本分布和 closure。相机重投影、frame graph 回环、已知工具点、depth 平面、force 零偏和 joint/TCP 对照可以揭示矩阵方向、单位或过期 bundle。若只替换某一路标定，所有依赖它的 aligned episode、3D label、adapter fixture 与统计都要列入影响集；验证通过前不能继续沿旧 lineage 发布。

质量阈值必须有 owner、单位、适用 source 和变更历史。同一 frame-age 阈值不一定适合低频相机与高频 tactile，同一动作速率界限也不能跨 robot 复制。reason code 要稳定且允许层级聚合，例如 temporal.clock-reset 与 temporal.stale-frame 分开；否则统计只能显示“时间失败”，无法判断是采集、同步、adapter 还是数据损坏导致。

repair pipeline 要能从 raw 和 manifest 重放，并输出逐记录变更清单。插值了哪些 timestamp、替换了哪些 frame、翻转了哪个 gripper sign、删掉了哪些 segment，都应与代码 revision、参数和 reviewer 相连。去重也保存 cluster membership 和保留代表项，确保撤回一个 parent 时能发现所有近重复和派生副本，而不是只删除文件名相同的对象。

跨本体 Adapter、Mask 与物理语义

跨本体不是把不同维度补零到同一个 tensor。每个 embodiment 是机器人、工具、传感器、controller、接口、软件与有效时间的版本化组合；adapter 则明确说明源 schema 如何转换为公共训练 schema或目标机器人的消费接口，以及转换丢失了什么。

Embodiment manifest

manifest 保存 robot model/configuration、arm count、joint names/order/limits、tool、gripper、mobile base、end-effector geometry、sensor set、camera role/order/frame、controller modes、command schema 与执行频率。state/proprio 和 Action ABI 都要有 unit、frame、timestamp、normalization stats family 与 consumer。

还要列出 task/workspace capabilities、not-applicable fields、calibration bundle、firmware/software、effective date、opaque embodiment_id 和 compatible/supersedes relation。同一型号更换 gripper、TCP、相机或 controller 后可能形成新版本；平台名称相同不能作为 schema 兼容证明。

Fixed width 与 mask

固定宽度合同区分 physical_dim、model_dim 和 field_map；dimension_valid_mask 表示当前样本哪些 slot 有物理含义，loss_mask 表示哪些位置参与目标，execution_mask 表示哪些位置可进入 adapter。padding_value 只是占位数，missing_reason 区分 not-applicable、not-recorded、sensor-fault、redacted，domain_id 指向确切 embodiment/source 版本。

零可以是合法状态或动作，因此 zero value 不能承载 missing 语义。loss mask 和 execution mask 也不能默认相同：某些观测维可作为 condition 但没有目标，某些标签可用于训练却不应下发。任何 mask 都要随窗口化、augmentation、batch padding 和 adapter 转换同步变化并经过 fixture。

Camera 与 missing modality

多相机使用 semantic role，例如 primary、wrist、left/right、overhead，而不是只依赖数组位置。manifest 冻结 identity/order、intrinsics/extrinsics、resolution、crop/resize、frame timestamp、freshness、valid mask、missing reason 和 fallback。augmentation 要在多视角间保持规定的几何与时间一致性。

absent camera 可能选择 drop slot、zero feature、learned missing token 或拒绝样本，但必须与训练方式和 consumer 匹配。零图、复制其他相机、复用上一帧、mask=false 与删除 slot 都不是等价操作。depth、force、tactile、proprio 的缺失也要独立策略，不能用统一的空 tensor 抹平 sensor fault 和 not-applicable。

Adapter round-trip 与目标机器人接入

每个连续字段都要测试 source physical → common normalized → source physical，报告 round-trip error、saturation、mask 和字段单位。还要验证 frame transform closure、time resample/integral consistency、gripper event/sign、rotation legal projection，以及 unknown domain、stats、calibration 的 fail-closed 行为。

误差骨架为 e = metric(a_physical, inverse(adapter(a_physical)))；metric、unit、mask 和适用范围必须写明。目标机器人接入顺序是 freeze embodiment manifest → collect calibration/reset samples → define adapters → small labeled dataset → round-trip/offline replay → split/mixture → train → closed-loop evaluation。公共 tensor 可生成并不允许绕过目标 controller、独立安全门禁或环境批准。

adapter registry 应以 source schema、target schema、embodiment、calibration、stats 和有效时间作为查找键，而不是只按机器人名字选择。启动加载时验证所有依赖 hash，遇到多个候选、未知版本或 superseded contract 要拒绝，并把选择结果写入每个派生 episode。隐式“选最新 adapter”会让同一 release 随时间得到不同 tensor，破坏可复现性。

跨本体测试要包含错误域反例：交换 A/B 的 field map、给不存在的 camera role、使用另一 robot 的 stats、隐藏 gripper dimension、注入旧 calibration 或未知 domain ID。预期结果不是“仍能输出有限向量”，而是在指定层产生 typed reject，且不会进入 execution mask。只有正向 round-trip 而没有反例，无法证明 mask 和注册表真正防止语义串线。

missing modality 策略要在训练和推理保持同一合同。若训练随机 drop camera 但部署用 stale-frame reuse，两者表示的缺失分布不同；learned missing token 也需要明确 position、mask 和初始化。报告按 modality、embodiment 和 missing reason 给出出现率与任务覆盖，避免模型只在某个 robot 上学会把“缺相机”当成任务或站点捷径。

跨本体比较最终仍要回到 physical space。normalized loss、token accuracy 或公共 slot error 相同，不代表不同 robot 的末端位移、速度和 gripper 行为相同。离线报告应按字段换回 unit，分开 adapter error 与 model error，并在 held-out embodiment 上核对 schema rejection、目标域校准和真实 consumer 可接受性；不可达或不安全仍由后续系统门禁判断。

Co-training 混合、权重与无泄漏划分

数据“占比”只有在明确分母、unit、stage 和采样层级后才有意义。Co-training 的数据侧责任是保留 source、objective、schema、label availability 与 batch route；optimizer、loss coefficient、gradient routing 和 freeze/unfreeze 属于下一页。

五种“占比”

口径 定义 必需说明
raw composition 采集/下载制品的 episode、step、hour 或 byte artifact 与原始 unit
eligible pool 通过许可、schema、去重与门禁的候选 filter revision 与拒绝原因
expected sampling probability sampler 配置的理论 source/group 概率 层级、replacement、stage
empirical draw ratio 指定区间实际抽到的 sample/step/token 窗口、seed、worker/rank
gradient contribution mask、weight、length、accumulation 后的更新贡献 训练侧测量，不由 mixture 名义值代替

“某数据集占 10%”必须标明属于哪一行、按 episode、transition、window 还是 token，以及在哪个训练 stage。sampler 先选 source 再选 episode 与直接在所有 transitions 上抽样会产生不同分布；序列长度和 mask 又会改变有效目标数量。

两类常见采样公式

自然规模加倍率可写为 p_i = w_i N_i / sum_j(w_j N_j)。N_i 必须声明是 episode、transition、window 或 token，w_i 是相对倍率，不是最终概率、质量分数或梯度贡献。filter、去重和 window yield 改变后要重新计算 N_i。

group power/temperature balancing 可写为 p_g = N_g^alpha / sum_j(N_j^alpha)。当 0 < alpha < 1 时，大组仍有更高总概率但增长被压平；alpha=0 接近组均匀，alpha=1 接近按规模。本页不给通用 alpha。manifest 还需记录 replacement、repeat/epoch 定义、多级 source→task→episode→window 顺序、batch 是否混域、worker/rank shard、seed、curriculum 和 empirical log 的统计窗口。

Co-training 的数据侧定义

Co-training 指一个训练过程从两个或更多不同 source/objective/schema 的数据流取样，并保留每个样本的 source_id、objective_id、eligible labels/masks 和 routing。实例可以是 robot trajectory + image-text/VQA、continuous action + discrete token、real + simulation、true action + pseudo-action，或 success demonstration + failure/recovery/correction。

manifest 记录 sampling unit、expected weight、active stage、mixed/alternating/separate batch route、tokenizer/processor/schema version、loss availability、允许更新模块的声明入口，以及 empirical draw 和 rejected counts。该入口只是下一页的输入，不代表 optimizer 实际让两种数据产生相等梯度，也不能从“同一 run 出现”推导正迁移。

混合审计

混合前后按 source/group 报告 raw、eligible、rejected、deduplicated 数和 reason 分布，并列 episode length、step rate、window yield、task、robot、site、operator、object、scene、success/failure、modality、mask 与 calibration coverage。expected probability 与实际 draws 必须同时报告。

审计还要寻找 rare group starvation、head dominance、重复曝光和 long-tail sequence 对 token 计数的影响。synthetic 与 pseudo-action 作为独立 tier；license/privacy/access 不兼容的来源不能因采样权重为零而混入 release。per-source loss 可作诊断，但不能直接当数据质量排序，因为 loss 同时受 objective、规模、噪声、mask 和模型容量影响。

Split 先按实体，再抽样本

默认禁止先把 overlapping windows 随机分到 train/validation/test。应先建立 group key，候选包括 raw episode、session/day/run、site/environment/scene、robot/embodiment/calibration、operator、task/instruction template、object instance/category、camera placement，以及 source video 与 synthetic/pseudo-label descendants。

一个 lineage connected component 默认进入同一 split，然后才产生窗口。若某个 OOD 实验刻意按 robot 或 scene 留出，其他相关实体仍要报告，避免 held-out robot 仍与 train 共用同一操作员、物体实例或派生视频。split manifest 固定 grouping algorithm、entity list/hash、seed、filter 和 intended question。

ID/OOD 划分矩阵

轴 ID OOD 示例
embodiment 已见 robot/config held-out robot/tool/gripper
task 已见 task family held-out skill/composition
scene/site 已见环境分布 held-out building/layout
object 已见实例/类别 held-out instance/category
language 已见模板/词汇 paraphrase/compositional
sensor 已见 camera/calibration held-out pose/modality degradation
operator/style 已见控制风格 held-out operator/device
time 同采集期 later hardware/software drift

“validation”不是单一集合名。每个 split 都要声明要回答的泛化问题，并报告与其他轴的交叉。模型比较使用同一 split revision、filter 与 stats；若更换 calibration、去重或 lineage 规则，就形成新 release，不能沿用旧结果标签。

Leakage 清单

发布前检查同一 raw episode 的窗口、同一视频的 caption/paraphrase/pseudo-action、near-duplicate scene/task sequence 和派生 parent 是否跨 split；也检查 normalization stats、bin edges、BPE tokenizer、calibration fitting、dedup index 是否读取 test。统计量虽不经 optimizer，仍可能泄露 test 分布。

还要追踪 model-generated data 的 teacher 是否见过 test、annotation 是否看到未来结果、cache 是否引用错误 release、evaluation rollout 是否未换版本就自动回流、benchmark public demo 是否混入训练，以及 task template 是否让 split 可被字符串记忆。leakage 不只指字节相同，而是任何与 intended question 冲突的信息共享。

sampler 必须输出可重建的 draw event：run/stage、worker/rank、seed stream、source/group、parent episode、window、objective、mask count、接受或拒绝原因。只有 epoch 末汇总无法发现某些 shard 饥饿、worker 重复 seed 或数据耗尽后悄悄 repeat。理论 p_i 与 event log 的经验置信区间应并列，并在差异超出预期时阻断训练报告，而不是事后把配置概率当成实际分布。

gradient contribution 只能由训练侧度量，数据页至多提供可计算所需的 objective、token/step 数和 mask。某来源被抽到很多次，却可能因标签缺失、loss mask、较短序列或冻结模块而几乎不更新参数；另一来源权重很小，却因大 loss scale 主导。数据 release 不伪造这个结论，但要求 run manifest 把 empirical draws、有效目标数和后续梯度诊断关联回同一 source revision。

split 一旦用于公开比较就应冻结 entity list/hash；新增数据首先进入新的候选 release，而不是自动补进旧 train。validation/test 的修复、撤回或重新标注同样会产生新 split revision，并要求结果注明可比性。若 OOD 轴改变，例如从 held-out object 改为 held-out site，不能沿用同一个“test”名称掩盖评测问题变化。

发现 leakage 后不能只删除当前窗口。应定位共享实体、派生 component、stats/tokenizer/calibration 和所有消费 checkpoint，建立影响范围；然后生成修复后的 split 与派生制品，重新运行必要训练或明确废弃结果。报告同时保留发现方式、首次受影响 release、处置决定和无法撤回的限制，避免“修复数据集”被误解为历史模型也已自动净化。

许可、隐私、版本、血缘与发布验证

数据 release 是带 schema、version、hash、lineage、quality 和治理快照的不可变制品，不是一个可变目录。能下载、能解析和能训练是三件不同的事；是否允许训练、再分发、公开展示或商业使用，必须由授权负责人对目标 release 作出判断。

License 与使用权是逐层交集

逐项核对 raw dataset license 和 data card，图像、视频、语言、标注、代码、模型生成物的权利，上游 attribution/share-alike/non-commercial 要求，以及训练、微调、再分发、展示和商业使用范围。synthetic 数据可能同时受 source、生成模型和服务条款约束，多来源混合还需兼容性审阅。

“代码仓库是 MIT/Apache”不能推出数据或权重使用同一许可；公开网页可访问也不是使用授权。地域、机构、伦理审批与研究用途限制要有 owner。权利不明的数据进入 quarantine，不进入 eligible pool；撤回或删除要沿 parent/child lineage 传播到 stats、tokenizer、mixture、checkpoint 和发布说明。

Privacy 与 Consent

机器人数据可能记录人脸、声音、屏幕、家庭布局、地址标签、操作员、儿童、旁观者和可识别物品。manifest 保存 consent scope（采集、训练、分享、展示、期限），subject/operator/bystander 的处理，face/screen/audio/location redaction 方法和版本，以及 raw/derived/public access tier。

还要记录 retention、encryption、audit、最小权限 owner、privacy scan、误检/漏检 review、delete/takedown request ID 和 lineage propagation。页面模板只接受 opaque ID，不要求姓名、邮件、账号、地址、设备 IP 或真实站点。脱敏本身也是 transform，必须产生新 artifact，并保留受限 raw 的访问边界。

不可变 Release 与 Lineage DAG

推荐链为 raw immutable artifacts → standardized episodes → aligned/cleaned episodes → split views → training windows → mixture snapshot → model run。每个节点有 artifact/release ID、semantic version、content/manifest/schema hash、parent IDs 与 transform DAG。

transform 记录 code commit、container/dependency、parameters、random seed、deterministic 状态、calibration/stats/tokenizer/adapter versions、quality report、rejected/quarantined set、governance snapshot、created/approved/deprecated/superseded dates 与 owner/reviewer role。latest 只能是人类友好别名；训练、评测和论文引用不可变 release/hash。改标签、删除 episode、更新 calibration 或修 privacy 都生成新 release，不原地覆盖。

Stats、Tokenizer 与 Split 都是数据制品

normalization stats 记录来自哪个 train split、哪些 mask/字段和算法；tokenizer、BPE vocabulary 与 bin edges 记录训练数据、版本和 hash；split manifest 记录 grouping key、seed、实体列表和 filter；calibration、language/task vocabulary、dedup index、mixture config、empirical draw log、adapter code/config 同样独立版本化。

checkpoint manifest 必须引用这些制品，不能只写 dataset name。错误 stats 或 action vocabulary 可在 shape 合法时改变物理语义；错误 split 使结果无法比较；删除源 episode 后还要判断派生 statistics 和 tokenizer 是否需要重新生成。数据依赖锁定和代码依赖锁定同等重要。

六层发布验证

第一层 schema 检查 JSON/YAML/Parquet/TFDS 可解析、required IDs、dtype、shape、enum、mask、episode/step boundary 和 parent reference。第二层时间与几何检查 timestamp、clock residual、causal alignment、camera/frame/calibration、depth/force/rotation/unit。

第三层行为与标签检查 reset、control source、success/failure/termination、intervention/correction 和 action/state consistency，保留 unknown/disagreement。第四层跨本体检查 field map、dimension mask、domain ID、normalization/inverse、time resample、round-trip 和 information loss。

第五层 split 与 mixture 检查 group/lineage leakage、train-only stats/tokenizer、expected/empirical sampling、source/objective/mask coverage 和 synthetic/real 分层。第六层治理与发布检查 license/consent/privacy/access、content/manifest hash、dataset card、quality report、known limitations、takedown/delete 演练和可复现 loader smoke test。每层结果区分未运行、不适用、失败、证据不足和通过。

目标机器人方案演练

完成演练依次列出 collection methods/provenance，冻结 embodiment、observation 与 Action ABI，定义 calibration/clock/reset，写 episode/step schema 与标签，执行七层质量门禁，定义跨本体 adapter/masks，按 entity/lineage split，选择 sampling unit/weights/objective tags，并生成 stats/tokenizer/split/mixture 制品。

随后由授权负责人核对 license/privacy/consent，发布不可变 release/hash 与 dataset card，再把 release 交给训练页制定参数更新、checkpoint 和 rollback。缺少任何一项，学习状态只能显示“数据制品未具备训练准入条件”。页面字段填写完整也不证明数据高质量、合法、安全或适合某个机器人。

takedown 演练要从一个受控 parent ID 开始，查询所有标准化 episode、窗口、split、stats、tokenizer、mixture、cache 和 checkpoint 引用，再按政策区分删除、阻断访问、重新生成、废弃或保留受限证据。仅从当前训练目录删文件无法处理复制、派生与已发布版本。演练应记录传播覆盖、未解析节点、完成时间和批准者角色，但不暴露请求人的身份。

reproducible loader smoke test 使用最小只读 fixture，验证 manifest hash、schema、媒体引用、episode boundary、mask、action unit、timestamp 和 deterministic sample IDs。它不需要下载完整数据，也不证明训练质量；目的在于确认另一环境能够根据锁定 dependency 读取相同逻辑样本。网络依赖、随机顺序或可变 latest 若影响结果，应作为发布失败而不是忽略。

每个新 release 需要 machine-readable diff：新增、删除、替换了哪些 parent，哪些 schema、transform、calibration、stats、split、license 或 privacy 决策变化，哪些历史结果仍可比较。semantic version 只能辅助沟通，不能替代内容 hash。审核者应能从任意 training window 逆向走到 raw 证据，也能从任意撤回 parent 正向找齐全部后代。

release candidate 应先进入不可变 staging 状态，接受结构、时间、几何、行为、跨本体、split、mixture 与治理的联合审核。审核过程中任何修复都生成新的 candidate ID，原候选保留失败报告；不能在同一目录就地改文件后沿用已签名 hash。只有全部必需门禁获得明确结论、例外有 owner 和到期时间时，才允许生成 approved release alias。

dataset card 不只是来源简介，还应说明预期用途、禁止用途、数据组成、采集人群与环境范围、标注过程、已知偏差、质量门禁、split 问题、许可隐私、维护联系人角色和撤回流程。规模表必须带 unit 和 eligible 口径，示例媒体必须来自允许展示的 access tier。card 的内容也有 revision/hash，并与 release 一起废弃或 supersede。

privacy scan 的“未发现”不是无风险证明。自动检测要报告模型和阈值、抽样范围、误检漏检复核及未覆盖 modality；人工 review 记录角色而非个人身份。音频转写、OCR、屏幕和背景反射可能暴露信息，派生 caption 也可能重新写入已脱敏内容，因此每个 transform 后都要重新评估新增泄露面，而不是只扫描 raw 视频一次。

access tier 必须由存储和 loader 实际强制，而不是 manifest 上的一列文字。raw-restricted、derived-internal、training-approved 与 public-example 等层级应对应明确主体、用途、期限、审计和导出限制；缓存、临时文件与训练日志也继承最严格父项。若某个 batch 混入不兼容 tier，loader 应产生拒绝证据，不允许依赖研究者手工记忆。

发布验收要用证据查询反向测试合同：随机选择一个 window，回答它来自哪个采集 session、哪些 raw packet、哪个 clock/calibration/adapter、为何进入该 split、抽样概率如何计算、许可和 consent 是否覆盖；再选择一个 raw parent，枚举所有派生、release 与模型引用。任一查询出现 unknown link、循环或无法解析的 alias，都说明 lineage 尚未达到可审计状态。

最终批准应保存各责任域的角色签署、例外清单、known limitations、监控与重新审阅触发器。新撤回请求、发现 leakage、标定错误、许可变化或 loader 不可复现都可使 release 进入 deprecated/quarantined，而不是静默继续使用。rollback 指向上一个完整且治理仍有效的 release bundle；回滚数据版本不会自动回滚已经训练的模型，二者的处置必须分别记录。

本页最高可给出的结论是“数据制品具备离线训练准入审阅条件”。它不执行数据下载、清洗、训练或机器人控制，也不给法律许可结论和通用质量阈值。只有目标项目的授权 owner 完成治理、系统和环境验证后，某个不可变 release 才能进入后续训练流程；未运行、不适用、失败、证据不足和通过必须保持为五种不同状态。

训练准入前还应冻结一份 consumer contract：允许的 release/hash、view、schema、split、stats、tokenizer、adapter 和 access tier，以及遇到 deprecated、quarantined 或 takedown 节点时的失败行为。训练脚本不能自动选择同名新版本，也不能把缺少字段降级为默认值；否则数据侧已建立的不可变边界会在入口处失效。

发布指标必须同时保留分母和拒绝集合。只汇报通过门禁后的成功比例会隐藏多少 episode 因许可、同步、标定、标签或 adapter 问题被排除；把 reject 当作普通缺失又会夸大可用覆盖。报告按 source tier、embodiment、task 和 site 给出 pass/warn/reject/quarantine，明确哪些差异来自真实分布，哪些来自门禁规则。

完成审阅后仍要安排漂移触发器：采集软件、硬件、工具、标定、controller、隐私政策、上游 license 或数据格式变化时，相关 manifest 和验证自动过期。旧 release 可以为复现保留受控访问，但不得因曾经通过就默认适用于新项目。每次重新准入都引用当时的证据快照，而不是复制上一版结论。

当多个团队消费同一 release 时，还要统一问题反馈入口和严重度规则。发现一条错标、一次隐私暴露或一个 adapter 缺陷后，应能确定影响的是单个样本、一个 source、一个 split 还是全部派生制品，并通知对应 consumer。修复状态、临时阻断和恢复条件都进入公开给授权使用者的变更记录，避免各团队私下复制一份“已修版本”而再次分叉 lineage。
