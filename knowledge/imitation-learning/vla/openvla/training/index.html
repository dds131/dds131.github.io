OpenVLA 总览/OXE 数据/④ 训练目标、优化与并行

TRAINING · FULL VLA FINE-TUNING · BASE-7B

OpenVLA 用标准 causal-LM 交叉熵全量微调 VLA；难点不在发明新损失，而在监督位置、分布式更新、停止条件和制品血缘。训练动作 token 准确率不是闭环成功率。

2e-5 · constant固定正式配置的学习率；warmup ratio 与 weight decay 均为 0。
64 × 32 = 2048论文/正式入口的 world size、每 rank batch 与 global batch；累积为 1。
27 epochs论文报告的运行结果，不是配置自动停止条件。
14 days · ≈21,500 h论文口径；项目页另写 15 天，冲突未消解。
paper v3 · repo commit · framework pinstoken accuracy ≠ closed-loop successfinal job stopping lineage: incompletetraining: not-run

先给结论与证据分层

本页把“论文描述”“固定实现”“站点推导”分开。论文将目标概括为动作 token 上的交叉熵；固定实现默认还监督 EOS。论文报告 27 个 epoch、64 张 A100、14 天与约 21,500 A100-hours；固定配置里的 epochs=1000 不会在无限 RLDS 流上自动结束。站点只核对公开文本与固定源码，不把静态审计冒充复现。

层级 本页可确认 本页不能推出
论文事实 action-token CE、全量微调、27 epochs、64 A100、14 天、约 21,500 A100-hours 完整的最终作业调度与恢复点
固定实现 action+EOS、AdamW、step 顺序、HYBRID_SHARD、rank-0 local metrics 论文最终作业逐步日志
站点复算 64×14×24=21,504、持久状态 16P 下界 FLOPs、利用率、峰值显存、成功率
阅读边界：CE、action accuracy 与 bin-center L1 都是训练代理量；只有引用了明确 protocol 的闭环评测才能讨论任务成功。本页没有运行数据、tokenizer、模型、训练、评测、服务、仿真或机器人。

监督位置与交叉熵

令 x=(o,ℓ) 为视觉观测与语言指令，量化动作序列为 W=(w₁,…,wN)。论文的动作目标可写为 −Σj log pθ(wj | x,w<j)。固定实现默认 predict_stop_token=True，所以标准七维样本的非忽略目标通常是 7 个 action token 加 1 个 EOS，共 8 个位置。

  1. prompt · `-100`
  2. action 1
  3. action 2
  4. action 3
  5. action 4
  6. action 5
  7. action 6
  8. action 7
  9. EOS · fixed implementation
  10. padding · `-100`

Transformers 4.40.1 的 Llama 在 forward(labels=...) 内部执行 logits/labels 的一位 shift；Data 管线不手工 shift。默认 CrossEntropyLoss 对全 batch 所有非 -100 token 求 mean，不是先按每个样本求 7 项和再平均。

teacher forcing 与推理解码边界

训练时完整真值动作序列作为输入，causal mask 让每个位置只看到真值前缀；一次 forward 并行产生全部位置 logits，不是执行七次完整视觉—语言 forward。推理时模型只能读取已生成前缀，因而按 token 顺序解码；KV cache 是否复用、如何缓存属于 Deployment 的 runtime 实现。

阶段 前缀来源 计算 边界
training ground-truth action prefix 一次 causal forward 产生全部 logits 不泄漏未来 token，但存在 teacher-forcing 暴露偏差
inference model-generated prefix 顺序生成 前序错误可影响后序；不能保证恰好生成 7 项 
schema: openvla.teacher-forcing-boundary.v1
training: {prefix: ground-truth, forward_passes_per_batch: one, logits: parallel-by-position, causal_future_visibility: false}
inference: {prefix: model-generated, decoding: sequential, kv-cache: deployment-implementation-dependent}
exposure_bias: present
not_guaranteed: [exactly-seven-generated-tokens, learned-all-action-dependencies, impossible-invalid-action-combinations]
runtime_owner: openvla-deployment

loss、accuracy、L1 与闭环评测

层 口径 参与反向 正确用途
CE loss action token + 默认 EOS，所有非 ignore token mean 是 唯一训练目标
action token accuracy action mask 内 argmax；不含 EOS 否 当前 batch token 分类诊断
bin-center L1 argmax id 经索引裁剪后映射到 normalized bin center 否 归一化离散误差启发式
closed-loop success 指定环境、任务与 trial protocol 否 独立下游评测，不能由前三项换算

固定代码的 action mask 只检查 action_gt > action_tokenizer.action_token_begin_idx，没有同时检查合法动作词表上界。新 tokenizer 应增加上界和非空断言；若 mask 为空，不应显示 0%，而应进入 supervision-mask-empty。L1 在 backward 后用 detached NumPy 数据计算，不读取 unnorm_key，不是米、弧度或夹爪物理误差；非动作 argmax 会被裁剪到端点。

VLAMetrics 默认 window_size=1，且只由 rank 0 push()；发布循环没有对 accuracy/L1 做 all_reduce。逐数据集指标只在 rank-0 当前 batch 出现多个数据集时更新。因此页面的 scope 标记必须是 rank-0 local batch，不能写成 global batch 2048 或完整训练集。

schema: openvla.training-metrics-contract.v1
loss: {scope: all-non-ignore-action-plus-eos-tokens, gradient: true}
action_accuracy: {scope: action-mask-only-no-eos, gradient: false, mask_code: lower-bound-only}
bin_center_l1: {scope: normalized-bin-centers, argmax: full-vocabulary-then-clip, uses-unnorm-key: false, gradient: false, physical-units: false}
logging: {writer: rank-0, scope: local-batch, all-reduce: false, window-size: 1}
per_dataset: {source: rank-0-local-batch, update-condition: more-than-one-dataset-in-current-batch}
empty_mask_state: supervision-mask-empty
recommended_new_tokenizer_checks: [legal-upper-bound, nonempty-action-mask]
paper_95_percent: observation-not-early-stop-and-metric-scope-not-proven-identical
closed_loop_success: separate-protocol-required
失败态：loss、grad norm 或 L1 首次出现 NaN/Inf 时，应记录 step、rank 与 dataset keys，把 checkpoint 标为 `training-invalid-pending-diagnosis`；不能自动归因于某个数据集，也不能交接 Deployment。

  2. commit loss

ordered_operations:

  - commit-current-loss
  - backward
  - compute-detached-accuracy-and-bin-center-l1

  - optimizer-step
  - scheduler-step
  - zero-grad
  - update-runtime-epoch-estimate

checkpoint trigger 发生在 metrics push 之后；文件名里的 loss 是保存时 rank-0 当前本地 loss，不是 validation score。改变 accumulation 会同时改变上述顺序的频率与语义，不能只改一个除法结果。

batch、world size 与梯度累积

正式入口断言实际 world size 等于 64；VLA loop 也断言梯度累积为 1：

2048 / (32 × 64) = 1。

仓库中的 vla-scripts/finetune.py 是另一条 HF/DDP 微调路径，不应冒充论文正式 OXE/FSDP 路径。实际 world size 不为 64 时，正式配置应失败，并新建实验配置；不应静默缩放每卡或全局 batch。

FSDP 分片范围

配置名 fsdp-full-shard 经解析为 full-shard，固定策略代码实际映射到 PyTorch 2.2 的 HYBRID_SHARD，不是跨全部 64 rank 的单一 FULL_SHARD。

名称 shard group replicate group 参数驻留差异
FULL_SHARD 由显式/默认 process group 决定 无混合复制要求 forward 后重新分片，backward 前再 all-gather
HYBRID_SHARD 节点内 full shard 节点间复制 昂贵 all-gather/reduce-scatter 限于节点内
_HYBRID_SHARD_ZERO2 节点内 shard-grad-op 节点间复制 forward 后保留完整参数到 backward 结束

固定代码没有显式 process group；PyTorch 2.2 按其默认语义建立节点内 shard group 与节点间 replicate group。8 cards per node × 8 nodes 只能作为可能拓扑假设，论文没有报告实际节点布局。

激活检查点与显存估算

固定策略启用 PyTorch checkpoint_wrapper 的 NO_REENTRANT 变体，只匹配 LLM transformer layers；视觉塔没有套用同一 wrapper。这能减少需保存的语言层激活，但不提供峰值显存数值。

设固定实现可训练参数 P=7,541,237,184。在 FP32 参数、FP32 梯度与两份 FP32 Adam moments 假设下，持久训练状态的未分片分析下界为：

4P + 4P + 8P = 16P = 120,659,794,944 bytes ≈ 120.66 GB ≈ 112.37 GiB。

若仅作 S=8 shard group 假设，理想均分为 16P/8 = 15,082,474,368 bytes ≈ 15.08 GB/card。这不是论文拓扑事实，也不是单卡峰值或“能装下 batch 32”的证明。

checkpoint、resume 与指标血缘

默认每 2,500 step 触发保存。FSDP 用 FULL_STATE_DICT 在 CPU gather，只有 rank 0 写入；默认保存完整模型，而不是 only_trainable 子集。公开保存路径展示的 payload 不含 optimizer、scheduler 或 RNG state，latest-checkpoint copy 也处于注释状态。

文件名携带 step、在线估算 epoch 与当前 rank-0 local loss；它不是 validation score。resume 时文件名 step/epoch 必须与显式 counters 一致，否则进入 resume-metadata-mismatch。仅加载模型权重和 counters 不等于无缝恢复 Adam moments、scheduler 与 RNG。
