专题总览 1 机器人与控制接口 2 VLM 与空间 Grounding

同样是 7 个浮点数，它可能表示 7 个关节目标，也可能表示 3 维平移、3 维旋转和夹爪命令；即使 shape 相同，frame、单位、顺序、delta 约定或控制模式错一个，动作就会在物理世界中变成另一件事。本页不教一整本机器人学，而是冻结视觉—语言—动作（Vision-Language-Action，VLA）策略从观测到控制必须说清的接口语义。

  • 必须先写：frame / unit / timestamp / mode / rate / controller / calibration / limit。
  • 必须区分：模型动作、controller reference、hardware command、measured state。
  • 不能推出：shape 正确不等于物理语义正确；离线预测正确不等于闭环稳定；限幅存在不等于系统安全。

这里的公式、字段和模板只用于离线学习与接口审计，不包含任何平台安全值，也不会执行机器人、控制器、相机或传感器操作。

变换必须有方向

必须说明从哪个 frame 表达到哪个 frame；一个没有 source、target、timestamp 和版本的 4×4 数组不是完整变换。

五种频率不能混写

推理频率不等于控制频率；动作块步数只有结合实际执行周期才有物理时间意义。

模型外仍有责任

模型输出不得绕过确定性限制与独立安全责任；字段完整也不构成部署批准。

本页最终应留下三份可复制但不可直接部署的制品：坐标与标定登记表、观测/动作接口表、频率与限制预算表。每份表都要写明字段来源、版本、所有者、有效条件与失败出口；任何空值都必须被标成待确认，而不能被默认值静默补齐。它们用于在模型、数据、运行时和控制团队之间建立共同语言，不替代机器人手册、控制器验证、风险评估或安全审核。

建议按“先识别语义，再核对变换，随后检查时间，最后确认限制与反馈”的顺序阅读。一个数组即使通过 shape、dtype 与有限值检查，只要关节顺序、旋转顺序、参考 frame、单位、时钟域或控制模式中有一项不一致，就应被视为契约不匹配。排查时先保留原始输入、变换前后值、限制事件与实测反馈，避免通过反复调模型掩盖系统接口错误。

先补数学/机器人基础（离站） 直接按八字段检查

坐标系、SE(3) 与旋转表示

三维特殊欧氏群（Special Euclidean Group，SE(3)）用于表达刚体位姿，三维特殊正交群（Special Orthogonal Group，SO(3)）用于表达旋转。这里最重要的不是背符号，而是让同一个符号在数据、模型、适配器与控制器之间保持同一方向。

先冻结变换方向

本站约定 {}^{A}T_B 表示“把在坐标系 B 中表达的点，变换为在坐标系 A 中表达”。因此：

\[p^A = {}^{A}T_B p^B, \qquad {}^{A}T_C = {}^{A}T_B {}^{B}T_C, \qquad {}^{B}T_A = ({}^{A}T_B)^{-1}.\]

齐次变换的最低必要结构是：

\[{}^{A}T_B = \begin{bmatrix} {}^{A}R_B & {}^{A}t_B \\ 0 & 1 \end{bmatrix} \in SE(3).\]

其中 {}^{A}t_B 是 B 原点在 A 中的坐标，{}^{A}R_B 把 B 中表达的向量改写为 A 中表达。若把“B frame 在 A 中的位姿”与“把 A 中的点转到 B”混写，就会产生常见的转置或求逆错误。接口应同时记录 source、target、矩阵方向、行/列向量约定和乘法次序，不能只靠变量名猜测。

  W -->|"static · optical 轴约定"| O["optical_frame"]

frame 名称不是语义本身

字段 必填问题 缺失后果
frame_id 名称是否唯一，谁发布和维护 同名 frame 被不同组件解释
parent_frame_id 父 frame 是谁，关系是否无歧义 变换链无法闭合或出现环
transform_direction 记录的是 parent-to-child 还是反向映射 求逆错误仍可能维度合法
static_or_dynamic 刚性安装、在线估计还是随关节变化 把旧动态位姿当常量
timestamp / clock_domain 对应哪个事件时刻与时钟域 空间正确但时间错位
unit / handedness / axis 平移单位、左右手系与轴方向 尺度、符号或轴互换
source / version / hash 来自模型、标定、URDF、估计还是配置 结果无法复现或回滚
validity / covariance 有效期、残差、不确定性与失效条件 过期或低质量变换静默进入控制

ROS REP 103 给出一套官方约定实例：使用国际单位制、右手系，机体 frame 常用 x 前、y 左、z 上，相机 optical frame 常用 z 前、x 右、y 下。它不是宇宙唯一标准；系统采用其他约定时，必须在边界显式转换并记录版本。

五类旋转表示

表示 优点 必须冻结 主要陷阱
旋转矩阵 R∈SO(3) 复合直接，没有参数化奇异点 行/列向量约定与映射方向 9 个数表达 3 自由度；网络输出需投影回 SO(3)
四元数 紧凑，适合插值 xyzw 或 wxyz、单位化与连续化 q 与 -q 表示同一旋转，欧氏损失可能跳变
轴角/旋转向量 连接指数映射，局部增量自然 轴归一化、角单位和主值范围 接近 π 的分支与数值连续性
Euler / RPY 人类较易阅读 内禀/外禀、轴顺序与角单位 多套合法约定与万向节奇异
6D 网络表示 可为学习提供连续嵌入 两列/两向量顺序与正交化算法 不是可直接发送给控制器的通用姿态格式

Zhou 等的工作支持某些连续表示对神经网络学习有价值，但不能推出 6D 表示对所有任务必然更优。任何旋转输出进入控制链前，都应转换成平台接受的合法姿态，并检查有限值、单位化、正交性、行列式和跨时间连续性。

delta 位姿的左乘与右乘

以 {}^{W}T_E 表示当前末端位姿，space/world frame 增量与 body/tool frame 增量分别可写为：

\[{}^{W}T_E' = \exp([\xi_s]\Delta t)\,{}^{W}T_E, \qquad {}^{W}T_E' = {}^{W}T_E\,\exp([\xi_b]\Delta t).\]

两者维数相同，物理运动却不同。接口必须记录 reference_frame、composition_side、rotation_parameterization、delta_or_absolute、dt 与裁剪顺序。平移与旋转也不能逐元素混加；rot6d、四元数或旋转矩阵要先按各自规则恢复合法旋转，再做群上的复合。

力、力矩与 wrench

twist（空间速度）和 wrench（力—力矩组合）都依赖表达 frame。跨 frame 变换涉及 SE(3) 的 adjoint 与 dual-adjoint；只旋转三维力而忽略参考点变化，会漏掉力矩耦合。接口验收关心的是：力在哪个 frame 表达、力矩绕哪个原点、单位是 N 与 N·m 还是其他、是否完成零偏和重力/工具补偿、传感器何时采样以及饱和与无效值如何标记。本页不把这些字段替代为完整的动力学或接触稳定性证明。

正逆运动学、Jacobian 与奇异位形

从关节空间到任务空间

正运动学（Forward Kinematics，FK）、空间/本体 Jacobian 与关节速度之间的最低关系是：

\[{}^{B}T_E=f(q), \qquad V_s=J_s(q)\dot q, \qquad V_b=J_b(q)\dot q.\]

q 不是无名数组，而是带关节名、固定顺序、单位、零位、正方向、连续/有限类型和有效范围的向量；f 的机器人模型与工具配置也要有版本。V_s 和 V_b 分别是在 space frame 与 body frame 表达的末端 twist，不能因为维数相同而互换。只写“若干自由度 state”无法复现任何变换或控制行为。

FK、IK 与冗余

问题 输入 → 输出 VLA 接口含义
正运动学 FK q → T 把本体状态映射为末端、相机与工具位姿
逆运动学 IK T_target → q_candidate 笛卡尔目标不能假定有唯一关节解
速度运动学 q̇ ↔ V 决定 joint/cartesian velocity 的映射与放大
静力关系 wrench ↔ joint effort 接触与力控必须包含 frame 和参考点
冗余解析 同一任务目标 → 多个 q 需要零空间目标、限位与连续性策略

逆运动学（Inverse Kinematics，IK）可能无解、多解或对初值敏感。冗余机械臂的末端目标不会唯一决定肘部与腕部构型；同一目标在不同分支上可能有完全不同的自碰撞、关节余量和连续性。若策略输出笛卡尔目标，IK solver、路径连续性、自碰撞、限位与无解处置必须归属于明确的 adapter、controller 或 safety owner，不能隐含成“机器人会自己到达”。

Jacobian 与奇异位形

Jacobian 把关节速度映射为末端速度，也连接末端 wrench 与关节 effort。接近秩亏区域时，某些任务空间方向变得不可达，或需要过大的关节速度；简单伪逆可能放大观测噪声、目标抖动和数值误差。

  • 记录 Jacobian 的 frame、关节变量顺序、机器人与工具模型版本。
  • 秩、最小奇异值、条件数或 manipulability 只能作为代理量；阈值必须由目标系统验证。
  • 阻尼最小二乘、速度缩放、任务降级或停止属于 controller/safety 策略，不是 VLA 自带能力。
  • IK 失败、奇异触发、被限幅命令和替代目标都要进入日志，避免把执行器没有实现的动作当成成功监督。

本页不提供通用阻尼、阈值或控制器配方。一个候选命令通过数值 IK，也不能证明路径无碰撞、可稳定跟踪或满足目标系统的风险约束。

workspace 不等于安全工作区

理论运动学 workspace 只说明几何上可能到达；当前机器人配置的可达集还受关节范围、工具与载荷影响；经验证操作区进一步受自碰撞、环境碰撞、线缆、速度、力和禁入区约束。可以把关系理解为“理论 workspace 包含当前配置可达集，后者再包含经验证操作区”，但这些集合不一定都能被静态、精确求出。页面或模型不能把“目标点落在机械臂可达范围内”写成安全或可执行保证。

相机、标定、深度与空间观测

针孔模型、内参与外参

采用 OpenCV 文档同向表达时，三维世界点到像素的最小关系是：

\[s \begin{bmatrix}u\\v\\1\end{bmatrix} = K \begin{bmatrix}R&t\end{bmatrix} \begin{bmatrix}X_w\\Y_w\\Z_w\\1\end{bmatrix}.\]

K 是内参，[R|t] 把 world 中的点变换到 camera frame，s 是投影尺度。内参依赖成像模型和分辨率；图像 resize 或 crop 后要同步更新 K，或显式记录新的投影关系。外参表达 frame 关系，并不等于内参。畸变模型、系数顺序、图像尺寸、是否已去畸变、颜色顺序与时间戳都是接口的一部分。重投影误差只是标定质量指标之一，不能单独证明所有工作距离、温度与姿态下都准确。

眼在手、眼在外与标定血缘

配置 冻结的安装关系 运行时变换链 关键证据
眼在手 eye-in-hand {}^{E}T_C，相机相对末端/夹爪的刚性变换 {}^{B}T_C(t)={}^{B}T_E(t){}^{E}T_C 手眼标定数据、残差、版本与工具配置
眼在外 eye-to-hand 固定安装时的 {}^{B}T_C 目标/工具通过 base-camera 链转换 外参、安装有效期与复验条件
多相机 每台相机独立内参、畸变与 frame 在观测时刻转换到选定 reference frame 各自 timestamp、同步误差与标定 hash

OpenCV calibrateHandEye 只是一个带版本的官方接口实例，调用函数不等于完成高质量标定。采集姿态的空间覆盖、运动轴多样性、靶标质量、同步误差、安装刚性、工具更换、温漂和复验条件都会影响结果。标定制品应包含方法、数据集 hash、软件版本、参数与残差分布、适用范围、审核人和失效条件；数据样本还要引用当时有效的标定版本。

深度、点云与目标位姿

已对齐深度 Z 反投影到相机 frame 的最小关系是：

\[X_c=(u-c_x)Z/f_x, \qquad Y_c=(v-c_y)Z/f_y, \qquad Z_c=Z.\]

这个公式只有在五个条件明确后才有接口意义：深度原始值是否已按 scale 换成 SI 单位；无效值、饱和、近远裁剪与遮挡如何标记；深度对齐到哪台 RGB 相机、使用什么插值规则；depth、RGB optical 与目标 reference frame 如何连接；两路 timestamp 或同步误差是否可追踪。

点云还要记录 organized/unorganized、点顺序、坐标单位、frame、timestamp、invalid mask、颜色对齐和下采样方法。object_pose 或 target_pose 这种名称不能说明“谁相对谁”；source frame、target frame、旋转格式、估计方法、covariance、有效期和 consumer 都不能省略。

从感知到视觉伺服

基于图像的视觉伺服（Image-Based Visual Servoing，IBVS）直接从图像特征误差闭环生成相机或机器人运动；基于位置的视觉伺服（Position-Based Visual Servoing，PBVS）先估计目标或相机的三维位姿，再在位姿空间控制。VLA 可能输出动作、目标位姿、关键点、可供性或子目标，但必须声明哪个下游模块消费、输出在哪个 frame、以何种频率重算以及失败时走哪条路径。

本页不推导 interaction matrix，也不宣称 IBVS 或 PBVS 普遍更优。空间 grounding 的输出如果没有 frame、尺度、时间、有效性和控制 consumer，就仍然只是一个感知制品，不是可执行机器人接口。

动作空间、控制模式与执行链

三层接口必须分开

模型动作不是控制器设定值，控制器设定值也不是执行器命令。每一层都可能发生反归一化、坐标变换、IK、插值、限幅、滤波、拒绝或降级，因此必须逐层记录输入、输出、版本、时间与所有者。

flowchart LR
  P["policy output"] --> D["decode / denormalize"]
  D --> A["action adapter<br/>旋转解码 · frame 变换 · 关节/夹爪映射"]
  A --> S["deterministic safety / limits"]
  S -->|"允许"| R["controller reference"]
  S -.->|"拒绝 / fallback"| F["safe state / owner"]
  R --> H["hardware command"]
  H --> X["actuator loop"]
  X --> M["measured state"]
  M -.->|"反馈"| O["next observation"]

适配次序与可审计性

推荐的审计次序是：先验证 shape、dtype、finite 与 mask；按冻结统计量反归一化；解码旋转或离散 token 并检查合法性；按 absolute/delta 与左右复合恢复物理目标；转换到 controller 所需 frame；映射关节与夹爪顺序，必要时运行明确归属的 IK/adapter；应用目标平台已验证的 deterministic limits；提交 reference 并记录接受/拒绝、deadline 和 sequence ID；最后记录实际反馈与命令差异。

这不是所有平台的唯一管线，但每个有状态或可改变语义的步骤都应有版本与日志。pre_clamp_action、post_clamp_reference 和 measured_state 必须分开；否则离线分析无法判断偏差来自模型、解码、适配、限制、控制器还是硬件。

五个时间点和动作年龄

每个闭环样本至少区分 t_capture（物理采样/曝光）、t_receive（到达策略进程）、t_policy_start / t_policy_end（推理起止）、t_command_deadline（允许提交的最晚时刻）与 t_apply（控制器或硬件实际应用/确认）。动作应用时，观测年龄是：

\[a_{\mathrm{obs}}(t_{\mathrm{apply}}) = t_{\mathrm{apply}}-t_{\mathrm{capture}}.\]

若组件处于不同 clock domain，必须先记录同步方法、offset/drift 估计和不确定性，禁止直接相减。tf2 Jazzy 的官方实现说明 frame 关系按时间缓存、查询，并可能面对插值或外推边界；空间对齐应使用观测对应时刻，不能默认拿“最新 transform”替代。

  R --> P["policy inference<br/>t_policy_start → t_policy_end"]
  P --> U["reference publish<br/>deadline + sequence"]

图 3｜五频率时间线。 sensor capture、policy inference、reference publish、controller tick 与 actuator/feedback 不必同频，也可能存在抖动、丢帧、保持、插值和队列。t_capture 到 t_apply 决定动作使用的观测年龄；每个含 H 步、按实际执行周期排列的动作块，其名义覆盖时间是 T_chunk = H / f_execute，不是 H / f_policy。页面不为任一频率预填默认值。

同步策略必须显式

可用策略包括硬件触发或共享时钟、带最大时间差的近似同步、以 reference timestamp 插值 joint state 或 transform，以及对不能插值的触觉/事件数据使用 nearest、hold 或 drop。超过 freshness 或 deadline 时，系统还要明确丢弃、保持、降级还是进入安全状态。

任何同步策略都要报告丢帧率、跨模态时间差分布、插值比例、观测年龄、过期动作数和 clock 校准版本，而不是只写“已经同步”。算法上允许插值，也不等于在物理快速变化或接触事件附近一定有效；这类假设要在目标系统独立验证。

八字段接口验收

对每个 observation 和 action，以下八项都必须有“值、来源、版本、所有者或失效条件”，不能只是空标签：

  1. frame：在哪个坐标系表达，变换方向和版本是什么。
  2. unit：物理单位、scale、角度约定与 dtype 是什么。
  3. timestamp：代表哪个事件时刻，时钟域和不确定性是什么。
  4. mode：absolute/delta、joint/cartesian、position/velocity/effort/impedance 的具体语义。
  5. rate：采样、预测、发布、控制或执行中的哪一种频率，实测分布是什么。
  6. controller：谁消费，接口、版本、插值、保持、超时和反馈是什么。
  7. calibration：内外参、零偏、scale、mapping 的 version/hash 与有效条件是什么。
  8. limit：在哪层检查，来源、单位、阈值版本、触发动作和 fallback owner 是谁。

所有字段填写后，只能报告“接口字段完整”。这不等于安全、稳定或任务成功，也不是发布门禁通过；它只说明文档结构可以进入下一阶段的离线、闭环、故障与风险验证。页面不会生成“安全通过”徽章。

最小验收演练

以不含数值的桌面抓取为例，依次回答：wrist RGB 的 optical frame、内参版本与采样时刻是什么；深度是否对齐、单位和 invalid mask 是什么；{}^{B}T_E(t_capture) 与 {}^{E}T_C 如何组成相机位姿；目标位姿相对 base、camera 还是 tool；模型输出是 world-frame 还是 tool-frame delta、左乘还是右乘；adapter 怎样恢复绝对目标并映射夹爪；H 步 chunk 覆盖多少实际时间；controller 在两次 policy 输出之间如何更新；IK、奇异、碰撞、workspace、速度、effort 与超时分别由谁处理；失败后进入哪种安全状态，谁允许 reset。
