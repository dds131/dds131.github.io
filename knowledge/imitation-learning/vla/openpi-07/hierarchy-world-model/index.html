π0.7 总览/数据与训练目标/高层策略与世界模型

OPTIONAL CONTEXT PRODUCERS · VISUAL SUBGOALS · ASYNCHRONOUS HANDOFF

两个可选 context producer，不是固定三段流水线：人类或学习高层可以给出 subtask；世界模型可再生成多视角 subgoal；低层 π0.7 仍独立负责连续动作。

三者拥有不同训练数据、目标与运行边界。可组合不等于共享权重、联合反传或所有组合性能等价。本页中的 π0.7 读作 pi zero point seven。

一、可组合三对象与运行模式

低层、学习高层和世界模型是三个模型及三个训练过程。低层约 5B，读取 observation/history 与合法 Prompt/context，输出 50-step continuous action chunk；学习高层基于同类 Gemma3 4B 架构生成 subtask text；世界模型从 14B BAGEL mixture-of-transformers 初始化，生成多视角视觉子目标。这里的“同类架构”或“initialized from”都不推出共享实例、权重、optimizer、KV cache、设备或服务。

对象可组合，但不组成所有场景必经的三段流水线
对象 / 模式 输入与输出 可选性 不能推出
低层 VLA observation/history + Prompt/context → 连续动作块 执行链必选 包含高层或 BAGEL 参数
学习高层 观测、总任务、过去 subtask → 新 subtask 文本 可由人类替代，也可省略 输出动作、共享低层权重
世界模型 当前多视角观测、subtask、metadata → 多视角 subgoal 有 subtask 时也仍可省略 完整状态 rollout 或物理仿真
A · 仅低层 无 subtask、无 subgoal；论文实验规则仍提供 metadata/control mode 论文支持的条件分支 无任何 context
B / C 人类或学习高层给 subtask；世界模型按需给 subgoal 两个 producer 都是可选 所有组合效果等价

视觉目标不是低层执行的必需输入：低层训练只在部分 examples 中加入 visual goal，论文也比较无目标模式。反过来，世界模型也不是高层的必然后继，subtask 可以直接进入低层。MODULE_OPTIONALITY

二、人类 Coaching 与学习高层

低层使用可随时间变化的 subtask instruction \hat{\ell}_t；推理时它可由 learned high-level policy、人类提供或省略。人类 coaching 是执行中逐步给语言指令，不是提供动作轨迹，也不改变低层权重。论文使用 verbal coaching data finetune π0.7 as a high-level policy：公开映射是 robot observations、task specification 和 history of past subtask instructions 到 new subtask instruction。高层输出文本，低层仍负责连续动作。HIGH_LEVEL_POLICY

公开语义合同与未公开训练 / 服务接口必须分开
项 可确认 未知或不可推出
人类 coaching 执行中逐步给 subtask 语言 动作轨迹、在线改权重、任意语言必成功
学习高层输入 robot observations + task specification + past subtask instructions observation window、历史截断、token 序列化 / mask
学习高层输出 new subtask instruction 文本 正式 schema、终止、重试、unknown token
训练与运行 由 verbal coaching data 微调；五个任务上可 roughly match 对应 coaching episodes 精确 objective、样本量、optimizer/LR/batch/steps、query cadence、普遍优于人类

“past subtask instructions”是高层文本上下文，不等于 MEM 论文的显式长期语言摘要。五任务的具体协议、指标和数字归 Phenomena；本页不扩成所有任务或零人工成本结论。

三、视觉子目标语义与世界模型边界

视觉子目标 (\mathbf g_t=[G_t^1,\ldots,G_t^n]) 是当前 subtask 成功推进后的 desired near-future image。base/front 视角强调场景与对象关系，wrist 视角可呈现 arm/gripper 附近结果；低层最多接收三路目标且不含 rear 目标。它表达“结果应看起来怎样”，不编码唯一到达路径。

公开条件可写为 (g_\psi(\mathbf o_t,\hat\ell_t,m))：current observation、与低层相同的 subtask、episode metadata。公式没有列 candidate action sequence、reward、control mode、history window 或总体任务作为直接条件；页面不自行添加，也不因公式省略就断言模型内部永远无法间接获得相关信息。

输出不是 joint/EE trajectory、action chunk、reward/value、termination、碰撞图、深度/力预测或完整 state transition rollout。模型不以候选动作滚动状态，因此本页称其为 subgoal image generator，而不泛化成 action-conditioned dynamics 或物理仿真器。图像本身也不能证明目标几何可达、动力学可行或碰撞安全；这些责任仍落在当前观测、低层闭环和外部安全系统。

四、训练数据、CFM 与双视觉通路

世界模型从 BAGEL 初始化；BAGEL 是 14B mixture-of-transformers 理解、编辑与生成模型，但通用 BAGEL 不是 π0.7 机器人世界模型成品。π0.7 使用 robot data 与 egocentric human video 中具有高质量分段语言标签的子集，并混入 open-source image-editing 和 video datasets 以保留语义知识。BAGEL_BACKGROUNDWORLD_MODEL_PAPER

世界模型监督固定为 segment-end；不要套用低层真实目标采样规则
项目 论文可确认 证据边界
数据来源 robot data、egocentric human video、开放图像编辑和视频数据 精确规模、比例与 sampler 未报告
机器人 example 一个 subtask、3 camera inputs \(\mathbf o_t\)、3 target images \(\mathbf o_{t_{end}}\) metadata 在公开目标条件中出现，但 Appendix 字段表未重复列出
目标时刻 包含 t 的高质量语义 segment 最后时刻；\(\mathbf g_t^*=\mathbf o_{t_{end}}\) 不是低层 0.25 / 0.75 采样
CFM 论文给抽象条件 Flow Matching loss 符号、velocity MSE、noise/time path、weighting、optimizer 未展开

[ \max_{\psi}\;\mathbb E_{\mathcal D_g}!\left[\mathcal L_{\mathrm{CFM}}!\left(\mathbf g_t^*,g_\psi(\mathbf o_t,\hat\ell_t,m)\right)\right] ]

论文称 (\mathcal L_{\mathrm{CFM}}) 为 loss 却写 max；这里标为 FORMULA_SIGN_TENSION，不擅自改成 min，也不复制 Action Expert 在动作空间的 Flow 公式。时间分段标签质量影响 subgoal quality 是论文观察，但没有公开筛选阈值、标注误差曲线或因果百分点。

五、多视角注意力与分辨率合同

世界模型双视觉通路与低层视觉输入属于不同预处理合同
通路 / 对象 分辨率与 patch 进入位置 不能推出
ViT current 448×336；patch size 14 7B LLM backbone，semantic understanding 与 VAE 共用同一 tokenization
VAE current 512×384；patch size 16 7B generation backbone，生成细节条件 等同低层 448×448 输入
VAE noisy goal 512×384；patch size 16 7B generation backbone，目标生成 生成结果可原样送入低层
低层 VLA camera observations 与 subgoal images 为 448×448 低层视觉编码器 公开了裁剪、缩放、归一化或 camera-slot binding

每个世界模型 group 内对多视角使用 block-bidirectional attention；推理 CFG 有三个 CFG groups。这里的三组不是三相机。BAGEL 的 14B MoT 口径与两个 7B backbone 不能被本站简单相加成精确、完全独立的参数账，也不能据此声明没有共享或路由重叠。论文 Fig.19 支持注意力组与 CFG 拓扑，但不足以恢复完整实现。NOT_REPORTED

世界模型输出怎样裁剪、缩放、归一化并绑定到低层的 camera slot，公开材料没有给出完整合同。因此，512×384 只能作为世界模型 VAE 路径的公开输入尺度，不能直接当成低层收到的目标图 shape；本站也不补 letterbox、中心裁剪或插值算法。类似地，block-bidirectional 只说明同一 group 内多视角可互相读取，不定义 group 间完整 mask、position IDs、缓存布局或生成次序。

六、真实 / 生成目标向低层交接

低层训练同时接收 real future images 与 world-model-generated images。真实目标的低层数据构造以 0.25 概率取当前 segment end，以 0.75 概率从未来 0–4 秒均匀采样；此外构造含大量生成 subgoal 的 additional examples，用于缓解 train-test mismatch。具体 real/generated 比例、生成次数、缓存与混合日程没有公开。PAPER_TRAINING_RULE

三个数字必须分域阅读：世界模型自身始终以 segment-end image 为 ground truth；0.25 / 0.75 是低层真实目标的取时规则；另一个独立 25% 是低层 batch 中带 visual goal 的 examples 比例。它们不能相乘、互换或拼成联合概率。

训练期 real future image 是监督条件，运行时低层不读取真实未来，只读取 latest generated goal 或走无 goal 分支。生成目标是期望结果的提议，不是事实观测，不能写进 Memory history，也不能单独证明任务完成。论文只声称生成样本用于缓解分布差异；“风格差异、几何误差、细节缺失”是 SITE_INTERFACE_RISK 分类，不是论文逐项保证或已测频率。

七、4 秒刷新、异步与计算预算

运行时在 semantic intent 改变、出现 new subtask，或距上次 subgoal 生成达到 (\Delta=4) seconds 时刷新，whichever happens first。4 秒是 world-model regeneration interval，不是目标预测 horizon、history stride、控制周期或高层固定 query cadence。subtask 与 subgoal generation 在 separate threads；VLA inference always uses latest ones available。论文称这是 naive asynchronous strategy：世界模型生成时，低层继续执行。PAPER_RUNTIME_SETTING

“latest available”只表示选择最近已经完成的产物，不证明该目标与当前 observation 同步、足够新鲜或来自同一 subtask 版本。官方未报告旧请求取消、乱序完成处理、deadline、timeout、失败重试、无 goal fallback、旧 goal 最大年龄、subtask/goal 一致性校验或机器人安全停机策略；这些缺口必须显式留在接口验收中，不能由页面指定一组看似合理的生产默认值。

世界模型 1.25 seconds 必须连同完整条件读取：14B model、total sequence length nearly 10,000 tokens、4-way tensor parallelism on 4×H100、large matrix multiplications 量化到 8-bit、modified SageAttention、25 denoising steps，且每步含 text and image CFG。它不是单 GPU、任意硬件、未量化或任意视角 / step 数的通用延迟，也不是训练耗时。

低层 minimal π0.7 在 3 cameras、5 denoising steps、training-time RTC、single H100 下为 38ms；MEM + subgoal images 共同启用的 worst case 为 127ms。两者不含 world model 1.25 秒，127ms 也不能拆出 MEM 或 subgoal 单项开销。异步重叠意味着墙钟链路不应简单相加 1.25s+127ms，却不表示世界模型“免费”。端到端 goal age、触发到消费、排队、资源隔离、高层延迟、吞吐、显存、能耗及 P50/P95/P99 都未报告。进入运行闭环前先阅读 RTC Foundations。NOT_RUN
