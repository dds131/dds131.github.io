GR00T N1.6/⑥ 固定源码剖析
SOURCE MAP · CALL GRAPH · PUBLIC BOUNDARY

研究 N1.6 必须同时固定源码 tag、发布 checkpoint、processor 配置和任务 modality config。本页把代码事实锚定在 n1.6-release 的 release commit ead5283；仓库主线后来进入 N1.7，不能用当前 main 静默替代。

先区分研究架构与公共运行时。 Research/README 把基础 VLM 描述为内部 Cosmos-Reason-2B 变体；固定公共实现实际只构造 nvidia/Eagle-Block2A-2B-v2。两者可以解释同一发布模型的研究口径与开源运行口径，但不能把 eagle_backbone.py 写成“公开 Cosmos 实现”。

一、十一处必须联读的源码

gr00t/configs/model/gr00t_n1d6.py

模型类默认值：16/29 容器、32 层 DiT、四步推理、冻结开关、state dropout/noise 与时间桶。

gr00t/model/gr00t_n1d6/setup.py

模型与 processor 的实际创建入口；决定从 checkpoint 加载哪些字段、哪些运行时字段覆盖 processor，并保存最终配置与 statistics。

gr00t/model/gr00t_n1d6/gr00t_n1d6.py

模型总装、输入搬运、state/action encoder、Flow Matching loss、四步 Euler 和顶层 forward/get_action。

gr00t/model/modules/dit.py

BasicTransformerBlock、AdaLayerNorm、DiT、AlternateVLDiT，以及 self/image/non-image block 交替与 mask 选择。

gr00t/model/modules/eagle_backbone.py

公共 Eagle 骨干构造、层截断、冻结/顶部层重新解冻，以及 VL hidden state、有效 token mask、image token mask。

gr00t/model/modules/embodiment_conditioned_mlp.py

CategorySpecificLinear/MLP、多本体 state/action 编解码与动作时间正余弦编码。

gr00t/model/gr00t_n1d6/processing_gr00t_n1d6.py

VLM content、collator、统一 padded 容器，以及按本体 horizon/动作组切片和 decode。

gr00t/data/state_action/state_action_processor.py

归一化、absolute↔relative、statistics 选择、action type/format 与 EEF 刚体变换。

gr00t/policy/gr00t_policy.py

公共推理 API：输入校验、processor/collator、torch.inference_mode()、模型调用和物理量解码。

gr00t/experiment/launch_finetune.py

单节点微调 CLI；只覆盖一部分 model/training/data 字段，并强制相对动作与 Eagle 路径。

gr00t/experiment/experiment.py

TrainingArguments、Trainer、DDP/DeepSpeed、batch 计算、日志、保存与可选 open-loop 回调。

二、权重与配置如何真正加载

flowchart TD
  CLI[FinetuneConfig / CLI] --> DEF[get_default_config<br/>类默认值]
  DEF --> OV[launch_finetune<br/>白名单覆盖]
  OV --> PIPE[Gr00tN1d6Pipeline]
  PIPE --> M[AutoModel.from_pretrained<br/>发布 checkpoint + 少数字段覆盖]
  M --> E[EagleBackbone<br/>AutoModel.from_config 本地结构]
  M --> W[外层 from_pretrained<br/>加载完整 GR00T state_dict]
  PIPE --> P[AutoProcessor.from_pretrained<br/>checkpoint processor + modality/runtime 覆盖]
  P --> D[dataset 建立并设置 statistics]
  D --> SAVE[final model / processor / statistics 记录]

2.1 from_config 不等于最终随机权重

EagleBackbone 先从仓库内的 Eagle 配置用 AutoModel.from_config 构造网络结构；随后外层 AutoModel.from_pretrained(base_model_path) 把 GR00T checkpoint 的 state dict 加载进整个模型。只截取“内部用了 from_config”就断言 backbone 随机初始化，是错误的。

2.2 不是一份配置做简单三层合并

模型与 processor 有两条不同覆盖链：

  • model loader 只显式传入 tune_llm、tune_visual、tune_projector、tune_diffusion_model、tune_vlln、state_dropout_prob 等少数字段；其余多数结构字段来自 checkpoint；
  • processor loader 则显式覆盖 modality config、图像增强、apply_sincos_state_encoding、max_action_horizon 和 use_relative_action 等字段。

因此“类默认 + checkpoint + CLI = 一份最终配置”仍过于粗糙。应分别保存并比较 model.config、processor 配置、modality config 和 statistics；固定 setup 已写出 final_model_config.json、final_processor_config.json 与 dataset_statistics.json。

三、训练调用链与张量边界

flowchart TD
  DATA[dataset sample] --> PROC[processor / collator]
  PROC --> PREP[Gr00tN1d6.prepare_input]
  PREP --> BB[EagleBackbone.forward]
  BB --> OUT[VL hidden + valid mask + image mask]
  OUT --> AH[ActionHead.forward]
  AH --> ENC[state/action encoders]
  ENC --> DIT[AlternateVLDiT × 32 blocks]
  DIT --> DEC[action decoder]
  DEC --> LOSS[masked elementwise MSE]
  LOSS --> TR[Trainer backward / AdamW]

3.1 prepare_input 的实际行为

若输入含 vlm_content，模型先调用 collator，再用 inputs.pop("vlm_content") 和 inputs.update(prep) 修改传入字典。之后 backbone/action head 从同一字典各取所需字段；所有浮点张量被移动到模型 device/dtype，整数 token 与 id 只移动 device。直接复用同一个输入字典的调用者应注意这个原地修改副作用。

3.2 backbone 的三个输出

EagleBackbone.forward 仅保留 input_ids、attention_mask 与 pixel_values，并返回：

  • backbone_features: [B,S,2048]；
  • backbone_attention_mask: [B,S]，表示有效 token；
  • image_mask: [B,S]，由 input_ids == image_token_index 得到。

这两个 mask 的交集才决定 cross-attention 可见内容：

\[M_{\mathrm{img}}=M_{\mathrm{image}}\land M_{\mathrm{valid}}, \qquad M_{\mathrm{nonimg}}=\neg M_{\mathrm{image}}\land M_{\mathrm{valid}}.\]

3.3 32 个 block 的精确节奏

发布配置令 interleave_self_attention=true、attend_text_every_n_blocks=2。按从 0 开始的 block 索引：

  • 奇数层 1、3、…、31：state/action token 内部 self-attention；
  • 偶数层：cross-attention；
  • 偶数层中 \(i\bmod4=0\) 的 0、4、…、28 读 non-image token；
  • \(i\bmod4=2\) 的 2、6、…、30 读 image token。

所以 32 层恰好是 16 个 self、8 个 non-image cross、8 个 image cross。ActionHead.forward 虽然还传入 encoder_attention_mask，但 AlternateVLDiT.forward 不使用该形参，而是只用 image/backbone 两个 mask 重新构造分流 mask。修改 token 序列时，三个张量必须同步。

四、动作头的公开训练目标

vl = vlln(backbone_features)
state_h = state_encoder(state, embodiment_id)

eps ~ N(0, I)
b ~ Beta(1.5, 1.0)
t = (1 - b) * 0.999
x_t = (1 - t) * eps + t * action
target = action - eps
tau = floor(1000 * t)

action_h = action_encoder(x_t, tau, embodiment_id) + position_embedding
sa = concat(state_h, action_h)
h, all_hidden = AlternateVLDiT(sa, vl, image_mask, valid_mask, tau)
pred = action_decoder(h, embodiment_id)[last action_length tokens]
loss = sum(action_mask * (pred - target)^2) / (sum(action_mask) + 1e-6)

公开 forward 返回标量 loss，并额外返回逐元素 action_loss、action_mask、backbone/state features；优化目标仍只有 masked flow-matching MSE。padding 只从 loss 中排除，不会从动作 encoder 与 DiT 前向中删除。

4.1 hidden-state 列表的真实行为

训练调用显式设置 return_all_hidden_states=True，得到初始输入加 32 个 block 输出，共 33 个张量；调用方写成 model_output, _，随即丢弃列表，没有据此计算未来表征对齐 loss。

更容易漏掉的是：DiT 与 AlternateVLDiT 无论 flag 是 true 还是 false，都会先创建 all_hidden_states=[hidden_states] 并逐层 append；flag 只控制最终是否返回。推理在 no_grad 下不会保留反向图，但这些引用仍活到函数返回。它是固定代码的内存/实现行为，不是 world-modeling 目标已经接通的证据。

五、公共推理调用链

Gr00tPolicy 在初始化时执行 model.eval() 和 processor.eval()；每次推理按以下顺序运行：

  1. 严格模式检查 video/state/language 的 key、dtype、shape 与 temporal horizon；
  2. 按样本创建 VLAStepData，processor 处理后再 collate；
  3. 在 torch.inference_mode() 内调用顶层 model.get_action；
  4. backbone 与 state encoder 各执行一次，4 次 Euler 循环重复 action encoder、DiT 与 decoder；
  5. processor 按本体 horizon/动作组切片、去归一化并把 relative 组恢复为绝对物理目标；
  6. 输出每个动作组的 float32 数组。

顶层 Gr00tN1d6.get_action 自身没有 no_grad 装饰器；只有 action-head 的内层方法带该装饰器，backbone 在它之前运行。标准 Gr00tPolicy 已用 inference_mode 包住整条链，因此没有问题；绕过 Policy 直接调用模型时，应由调用者包住整次调用，而不是只相信内层装饰器。

六、类默认、checkpoint 与微调运行时

字段 配置类默认 发布 checkpoint 公共微调入口 / processor 的关键行为
action_horizon 16 50 processor 的 max_action_horizon 显式取运行时 model config，任务实际返回长度还由 delta_indices 决定
max_action_dim 29 128 模型内部宽度来自 checkpoint；processor 再按动作组真实维数切片
max_state_dim 29 128 模型内部 padded state 宽度来自 checkpoint
use_relative_action false true launch_finetune 强制 true，并显式覆盖 processor
apply_sincos_state_encoding false true setup 把运行时 model config 显式传给 processor；不能只看 checkpoint
eagle_collator false true launch 强制 true；Config.validate 还把 backbone type 归一到 Eagle
tune_top_llm_layers 4 4 先截断语言层，再重新启用当前列表顶部四层
state_dropout_prob 0 0 CLI 可覆盖并传入 model loader
num_inference_timesteps 4 4 四步只控制推理积分，不是训练时间点数量

最稳妥的复现记录不是抄这张表，而是保存最终 model/processor/modality/statistics 四份对象、requires_grad 清单、源码 commit 与 checkpoint revision。

七、六个高风险实现边界

7.1 world-modeling 没接入常规 loss

模型卡与 Research 说明基础预训练含 world-modeling objective；固定普通 forward 只计算动作 flow-matching MSE。hidden states 被收集并不等于存在 FLARE/教师/对齐损失。公共代码足以做标准动作微调，不足以一比一复刻全部基础预训练目标。

7.2 state dropout 对 forward 没有 train/eval 门控

只要 state_dropout_prob>0，训练/验证共用的 ActionHead.forward 都会按样本采一个布尔值，并用同一个可学习 mask token 替换该样本整段 state feature；代码没有检查 self.training。因此普通 eval loss 也可能随机受 dropout 影响。标准推理 get_action 走 _encode_features，完全不执行这段 dropout。训练、open-loop eval 与部署的 state 路径并不完全同构，必须在评估设计中说明。

7.3 state additive noise 与 dropout 不同

additive noise 有 self.training 门控，只在训练态加到编码后的 state feature；dropout 则由上述代码路径决定。不能把两者统一描述成“eval 自动关闭的常规 Dropout 层”。

7.4 顶部四层的冻结状态不能只看 tune_llm

backbone 先把语言层截断到 select_layer，tune_llm=false 冻结整个 language model，随后 tune_top_llm_layers=4 又重新启用当前列表最后四层。与此同时，set_frozen_modules_to_eval_mode 在 tune_llm=false 时仍把整个 language model 设为 eval。最终会出现“顶部四层可求梯度，但所属语言模型处于 eval 模式”的组合；requires_grad 与 train/eval 是两条独立状态轴。

7.5 Alternate mask 分流不会减少 token 张量本身

每个 cross block 仍接收完整 encoder_hidden_states，mask 决定哪些 key/value 可见；它不是先把图像或文本 token 物理删除后再构造短序列。因此不能仅凭分流 mask 宣称 FLOPs 按可见 token 比例等比下降。
