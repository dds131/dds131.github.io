本页把 GR00T N1.5 在感知侧与感知—动作接口侧的公开实现逐层拆开。枢纽页回答“改了什么”，本页进一步回答“张量怎样流动、计算代价怎样变化、哪些解释只是机制假设”。官方没有给出逐模块消融，因此“为什么有效”必须与可直接验证的结构事实分开。

本页的事实来源分四层，正文每处都标明出自哪一层，不混用。 层一NVIDIA 官方 Research 页；层二FLARE 与 DreamGen 论文；层三源码 n1.5-release 固定 commit 4af2b622…；层四发布权重固定 commit 869830fc… 的 config.json。本页以层三和层四为主；官方页描述的是训练系统，公开仓库描述的是发布实现，二者不一致时分别记录。N1 对照取自固定 n1-release 源码与 GR00T-N1-2B 配置。

一、本页在专题中的位置

本页只讲改动的部分。以下内容属于两代共有的结构，已在 GR00T N1 专题讲透，本页不重复，只在需要时引用其结论：

  • 扩散 Transformer 的块内结构、adaLN 如何注入去噪步、自注意力与交叉注意力如何交替排布，见 GR00T N1 · 网络架构与双系统。
  • 按本体分组的状态编码器、动作编码器与动作解码器，同上。
  • 流匹配的加噪式、速度场目标与时间方向约定，见 GR00T N1 · Flow Matching、损失与时间方向。

本页也不讲 FLARE 的损失构造——future token 在本页只作为「一段进入 DiT 序列的张量」处理，它承担的监督目标见 ② FLARE 未来潜在表征对齐。冻结策略在训练过程中的具体配置见 ④ 训练配方、损失组合与优化配置，而「为什么冻结反而更好」这一反常现象的机制分析见 ⑤ 推理流程与反常现象。

二、Eagle 2.5 主干的实际构成

2.1 eagle_path 能提供线索，但不是公开代码的运行时加载地址

发布配置的 backbone_cfg.eagle_path 保存了一个内部训练产物名称：

NVEagle/eagle_er-qwen3_1_7B-Siglip2_400M_stage1_5_128gpu_er_v7_1mlp_nops
片段 可作出的判断 证据边界
qwen3_1_7B 指向 Qwen3-1.7B 随仓库打包的 text_config 同时写明 Qwen/Qwen3-1.7B 与 qwen3，可交叉确认
Siglip2_400M 名称声称使用 SigLIP2 400M 系列 vision_config 只明确核心形状；“SigLIP2/400M”代际主要来自路径名，不能仅靠形状证明权重来源
1mlp 单层视觉连接器 mlp_connector_layers: 1 与单层 Linear 分支可直接确认
nops 不做 pixel shuffle use_pixel_shuffle: false 可直接确认
stage1_5、128gpu、er、v7 内部训练阶段、规模或版本标识 公开材料没有定义，不作展开解释

更关键的源码事实是：EagleBackbone.__init__ 虽接收 eagle_path 参数，却没有使用它。 公开实现固定执行 AutoConfig.from_pretrained(DEFAULT_EAGLE_PATH, trust_remote_code=True)，实际读取仓库随包提供的 gr00t/model/backbone/eagle2_hg_model 配置；发布 checkpoint 再为这个结构加载权重。因此长字符串只能作为训练产物的来源线索，不能理解为推理时会自动访问的模型地址。本页的结构结论均以打包配置和实际分支为准，而不是靠字符串猜测。

官方页正文称 N1.5 的 VLM “starting from Eagle 2.5”，但同页架构图仍标成 “Eagle-2 VLM”。这是官方材料自身的命名不一致；公开模块名 modeling_eagle2_5_vl.py 支持 Eagle 2.5 口径，但不能据此改写架构图原文。

2.2 语言模型：从 SmolLM2-1.7B 换成 Qwen3-1.7B

字段 N1 N1.5
_name_or_path ./pretrained/SmolLM2-1_7B-Instruct Qwen/Qwen3-1.7B
model_type llama qwen3
hidden_size 2048 2048
num_hidden_layers 24 28
查询头 / KV 头 32 / 32 16 / 8
intermediate_size 8192 6144
vocab_size 49,164 151,680

四点最值得注意。

  1. 接口宽度没变。 两代语言模型隐藏维都是 2048，因此后文 1536/2048 的变化不是由 Qwen3 的隐藏维被迫触发。
  2. 注意力结构换成分组查询注意力。 N1 的查询头与 KV 头都是 32；N1.5 为 16 个查询头、8 个 KV 头。KV 头少于查询头会减少 K/V 投影参数与中间激活；在标准自回归生成中还会缩小 KV cache。GR00T 在这里把语言模型当作截断的特征提取器，并不执行逐 token 生成，所以不应把“KV cache 更小”写成本路径的主要收益，也不能只用“注意力头从 32 降到 16”概括。
  3. 词表约为原来的 3.09 倍。 这会扩大输入词嵌入表，但不能只凭 vocab_size 推断多语言能力或整模型参数增量；后者还受权重共享、未使用的 LM head 和其余结构影响。
  4. 深度增加、前馈宽度下降。 28/6144 与 24/8192 是两种不同的容量分配，公开材料没有提供这两个因素的单独消融。

层截断的实现两代一致：

# needed since we don't use these layers. Also saves compute
while len(self.eagle_model.language_model.model.layers) > select_layer:
    self.eagle_model.language_model.model.layers.pop(-1)

self.select_layer = select_layer
# ...
eagle_features = eagle_output.hidden_states[self.select_layer]

select_layer=12 时，模型保留并执行前 12 个 decoder block；Hugging Face 的 hidden_states[0] 是嵌入输出，hidden_states[12] 是第 12 个 block 之后的表示。N1 从 24 层删掉 12 层，N1.5 从 28 层删掉 16 层，但两代实际执行深度都是 12 层。原文用“保留比例 50% 对 43%”推导 N1.5 使用“更浅部分”没有实际依据：不同架构的同序号中间层不能按总层数比例直接比较语义深浅。

取中间层的速度—性能权衡已在 GR00T N1 · 反常现象、证据边界与可能机制 讨论。本页只确认 N1.5 仍执行前 12 层；没有官方消融能够证明 Qwen3 的第 12 层优于其他截断位置。

2.3 视觉塔：核心张量形状相同，权重是否单独换代无法由公开字段证明

两份打包配置的核心结构字段相同：

字段 N1 N1.5
model_type siglip_vision_model siglip_vision_model
hidden_size 1152 1152
num_hidden_layers 27 27
查询头数 / 前馈宽度 16 / 4304 16 / 4304
patch_size / image_size 14 / 224 14 / 224

这只能证明视觉塔的主要网络形状一致，不能写成两份原始 JSON “完全相同”：N1 显式含 drop_path_rate: 0.1 等字段，N1.5 的精简配置未显式写出这些字段，并另含 bfloat16 元数据。更重要的是，N1 顶层 _name_or_path 本身已经带有 siglip2 字样，因此仅凭 N1.5 路径中的 Siglip2_400M，不能证明视觉塔从 SigLIP 1 换成 SigLIP 2，也不能隔离出视觉塔权重是否单独换代。

准确结论是：官方声称 N1.5 的整个 VLM 从 Eagle 2.5 出发并针对接地与物理理解调校；公开配置证明语言模型、视觉后处理和接口发生变化，但没有提供“只更换视觉塔权重”的对照。视觉侧可直接验证的显著行为变化发生在塔之后：关闭 pixel shuffle，并选择单层连接器。

三、视觉 token：每个图块由 64 增至 256

官方页只说连接器被简化，没有说明 pixel shuffle 的变化。发布配置与源码表明，N1.5 关闭了该操作；这会把每个 224×224 图块送入语言模型的视觉 token 数从 64 恢复为 256。两代都支持先把原图动态切成多个图块，因此这里比较的是“每图块 token 数”，不能写成“每帧固定 256 个”。

3.1 pixel shuffle 与动态切图是两个不同层级

pixel shuffle 在视觉塔之后进行：它把相邻的 $2\times2$ 个 patch 特征沿通道拼接，以通道宽度换序列长度。对单个 224×224 图块，patch 边长为 14，因此每边有 16 个 patch：

\[N_{\text{patch}}=(224/14)^2=16^2=256.\]

N1 使用 downsample_ratio=0.5，故每个图块输出

\[N_{\text{N1}}=256\times0.5^2=64, \qquad D_{\text{N1}}=1152/0.5^2=4608.\]

N1.5 的 use_pixel_shuffle=false，故每个图块保持

\[N_{\text{N1.5}}=256, \qquad D_{\text{N1.5}}=1152.\]

源码中的两个分支直接对应上述计算：

if config.use_pixel_shuffle:
    self.num_image_token = int(
        (image_size // patch_size) ** 2 * (config.downsample_ratio**2)
    )
else:
    self.num_image_token = int((image_size // patch_size) ** 2)

downsample_ratio 在 N1.5 配置里仍为 0.5，但关闭 pixel shuffle 后不参与 token 数计算。只看这个遗留字段会得出错误结论。

N1.5 的图像预处理器还有另一层行为：min_dynamic_tiles=1、max_dynamic_tiles=12、use_thumbnail=true。原图会按长宽比被切成若干个 224×224 图块；若切出多块，还会追加一张缩略图。设实际送入视觉塔的图块数为 $M$，则一张原图贡献的视觉 token 数是 $256M$，而不是恒定 256。max_dynamic_tiles=12 约束的是主切图方案；启用缩略图时，最终图块数还可能多 1。

3.2 单层连接器是发布配置中的配套选择，不是数学必然

代际 发布配置实际选择 每个图块的连接器输入
N1 LayerNorm(4608) → Linear(4608,2048) → GELU → Linear(2048,2048) 64 个、每个 4608 维
N1.5 Linear(1152,2048) 256 个、每个 1152 维

关闭 pixel shuffle 后，连接器不再需要把 4608 维压回 2048 维，而是把每个 patch token 从 1152 维升到 2048 维；这让单层映射成为自然的轻量选择。不过源码为 mlp_connector_layers 与 use_pixel_shuffle 保留了多种组合，因此二者是发布配置中共同采用的设置，不能写成“关闭 pixel shuffle 必然导致连接器只能简化”。官方也没有提供两项改动的独立消融。

3.3 代价不能用一个固定倍数概括

设文本 token 数为 $T$，所有图像经动态切图后的图块总数为 $M_{\Sigma}$，则 N1.5 送入语言模型的总序列长度近似为 $T+256M_{\Sigma}$。语言模型前 12 层和后置四层 VL 自注意力的注意力矩阵规模随各自序列长度近似二次增长；DiT 的查询长度固定时，交叉注意力对键值长度近似线性增长。

因此，“每个图块的视觉 token 数变为 4 倍”是准确的，但“整段计算量变为 16 倍”并不成立：文本长度、相机数量、动态切图数量、前馈网络开销和实现细节都会改变总成本。官方没有公布 N1 与 N1.5 的 FLOPs 或延迟对照，本页不虚构倍数。

官方报告的接地成绩也不能用于隔离这一改动：N1.5 主干在 GR-1 接地基准和 RefCOCOg 验证集上的 IoU 为 40.4 与 89.6，对照是 Qwen2.5-VL-3B 的 35.5 与 85.2，不是 N1 主干；官方将提升归于整个 VLM 的接地与物理理解调校，而非 token 数单项。完整实验见 ⑦ 实验结果与横向对比。

四、接口侧：保留 2048 维条件，由交叉注意力按层投影

4.1 可验证的接口变化

N1 在主干后用共享线性层把 2048 维压到 1536 维；N1.5 把该层换成恒等映射，并把 DiT 的 cross_attention_dim 显式设为 2048。

环节 N1 N1.5
backbone_cfg.project_to_dim 1536 null
主干末端 Linear(2048,1536) Identity()
进入动作头的 VL 条件宽度 1536 2048
DiT 查询侧内部宽度 1536 1536
交叉注意力 K/V 输入宽度 1536 2048 
if project_to_dim is not None:
    self.eagle_linear = torch.nn.Linear(2048, project_to_dim)
else:
    self.eagle_linear = torch.nn.Identity()

这里最容易混淆的是“条件宽度”和“DiT 内部宽度”：N1.5 保留 2048 维 VL 条件，但动作序列及每个注意力头组成的内部宽度仍为 $32\times48=1536$。交叉注意力自己的 K/V 投影负责把 2048 维条件映射到 1536 维内部空间。

4.2 16 层 DiT 中只有 8 层是交叉注意力

cross_attention_dit.py 以层索引奇偶交替构造注意力：奇数索引为动作序列自注意力，偶数索引为对 VL 条件的交叉注意力。因此 16 个 block 中是 8 个自注意力 block + 8 个交叉注意力 block，不是 16 个 block 都读取 VL 键值。

这也使参数增量可以精确计算。每个交叉注意力 block 的 K/V 输入宽度由 1536 增至 2048，内部宽度为 1536，所以新增权重为

\[2(2048-1536)\times1536=1{,}572{,}864\]

个参数；8 个交叉注意力 block 合计

\[8\times1{,}572{,}864=12{,}582{,}912.\]

N1 同时拥有一个共享的 Linear(2048,1536)，含

\[2048\times1536+1536=3{,}147{,}264\]

个参数。K/V 线性层在两代中都带同样大小的 1536 维偏置，输入宽度改变不会改变偏置参数量，因此增量公式只出现权重差；被移除的 N1 共享投影则要连同自身 1536 维偏置一起扣除。只比较这两处接口投影，N1.5 净增加 $12{,}582{,}912-3{,}147{,}264=9{,}435{,}648$ 个参数；这个数不含新增的 vlln、四层 VL 自注意力或 future token。

4.3 可以解释为“按层读取”，但不能宣称已证明更优

结构上，N1 的 8 个交叉注意力层共享一份预先压缩到 1536 维的条件；N1.5 则让每个交叉注意力层用自己的 K/V 投影从 2048 维条件读取信息。后者确实提供了按层选择语义分量的自由度，也移除了共享瓶颈。

但“因此保留了更多有用语义并提升性能”仍是机制解释，不是已证实因果：官方没有对 project_to_dim 或 cross_attention_dim 做单项消融。准确表述应是“接口容量和按层投影自由度增加，同时参数和计算量上升”。

五、动作头前的视觉语言适配，以及掩码边界

N1.5 在主干输出之后、DiT 之前新增 vlln 与四层 SelfAttentionTransformer；N1 对应动作头没有这两个模块。

5.1 实际调用顺序

backbone_features = self.vlln(backbone_features)
backbone_features = self.vl_self_attention(backbone_features)

发布配置中 use_vlln=true，因此 vlln=LayerNorm(2048)，随后启用四层 VL 自注意力。两个模块共用同一开关是实现事实；不能由此断言 LayerNorm 与四层适配器在方法上不可分。

5.2 官方“LLM 输入前归一化”与公开发布路径不是同一位置

官方 Research 页说：连接器被简化，并对进入 LLM 的视觉与文本 token 嵌入增加 LayerNorm。公开 n1.5-release 路径中，实际启用的一层连接器只有 Linear(1152,2048)，文本嵌入也直接进入语言模型；动作头的 vlln 则位于截断语言模型之后。与此同时，四层适配器内部本来就有各自的 LayerNorm，所以也不能写成“公开实现里唯一新增的 LayerNorm 就是 vlln”。

最稳妥的结论是：官方描述的是训练系统的输入归一化设计，而公开发布路径可直接看到的是输出侧 vlln；现有公开代码不足以证明两者就是同一个层，也不足以解释差异来自导出、重构还是未发布训练代码。页面必须并列记录，不能把其中一方强行改写成另一方。

把 vlln 解释为“为冻结主干输出提供可训练尺度与偏移”在机制上合理：LayerNorm 的仿射参数可让动作头适配固定特征分布。但官方没有这项单独消融，因此这只是机制假设，不是被实验确认的设计动机。

5.3 四层 VL 自注意力的确定事实

字段 取值 含义
num_layers 4 四个 Transformer block
num_attention_heads 32 32 个查询头
attention_head_dim 64 内部宽度 $32\times64=2048$
dropout 0.2 训练期 dropout
positional_embeddings null 该模块不额外添加位置嵌入

它是纯自注意力，不接收流匹配时间步，也不额外添加位置嵌入。VL token 已经过语言模型并携带其上下文位置表示，但这不等于“后置模块具有独立、可解释的二维视觉位置编码”。公开实现没有提供这种保证。

该模块为固定主干之后增加可训练的 token 间重组能力。它可能帮助动作任务重新组织视觉与语言条件，但没有官方消融能将收益单独归因于这四层。

5.4 padding mask 没有继续传入新增适配器和 DiT

批处理器使用左填充并生成 attention mask；Eagle 主干会使用该 mask。可是公开动作头调用 vl_self_attention(backbone_features) 时没有传 mask，SelfAttentionTransformer.forward 也没有 mask 参数。随后 DiT 虽然在接口上接收 encoder_attention_mask，公开前向却把它以 None 传给各 block；block 的交叉注意力路径同样没有实际应用主干 padding mask。

因此可验证的实现边界是：主干内部屏蔽了 padding，主干之后的四层 VL 自注意力和 DiT 交叉注意力没有继续使用这份 mask。 这意味着填充位置可能被后续模块当作普通条件位置参与计算。其实际影响取决于批次内长度差异、填充值经过主干后的表示以及训练数据分布；没有实验时不能直接断言一定造成性能下降。

5.5 冻结主干与下游可训练容量：事实与解释要分开

官方确认 VLM 在预训练与微调中冻结；公开 set_trainable_parameters 仍让 vlln、VL 自注意力与 future token 保持可训练，除非外部把整个动作头冻结。由此可以确认“可训练容量位于冻结主干下游”。

进一步说它们“专门用来补偿冻结主干”则是合理解释，而非官方逐模块因果结论。与 π0.5 的知识隔离可以作思路对照，但两者训练目标、梯度路由和证据并不等价，不能写成解决方案完全相同。详见 π0.5 · 知识隔离。

六、future token 没有专用 FLARE 损失，但仍有间接动作监督

N1.5 新增 32 个可学习 future token，并按“状态—future—动作”的顺序拼接：

future_tokens = self.future_tokens.weight.unsqueeze(0).expand(batch_size, -1, -1)
sa_embs = torch.cat((state_features, future_tokens, action_features), dim=1)

设状态历史 token 数为 $S$、动作块长度为 $H$，则 N1 的 DiT 查询序列长度是 $S+H$，N1.5 是 $S+32+H$。公开架构支持一般的 $S$；仓库内置数据配置均使用 observation_indices=[0]，故常用设置 $S=1$、$H=16$ 时，长度由 17 增至 49，约为 2.88 倍。

这个长度变化对两类注意力的影响不同。若只比较 DiT 查询序列并保持宽度不变，8 个自注意力 block 的注意力矩阵项数近似放大

\[\left(\frac{49}{17}\right)^2\approx 8.31,\]

而 8 个交叉注意力 block 对查询长度的主要缩放约为 $49/17\approx2.88$；其键值长度还取决于 VL token 数。这里算的是注意力矩阵的序列项，不是整模型 FLOPs 或实测延迟，因为线性投影、前馈层、VLM 与硬件实现还会贡献大量成本。

16 个 DiT block 交替执行 8 次交叉注意力与 8 次自注意力。future token 在交叉注意力 block 中作为查询读取 VL 条件，在自注意力 block 中与状态和动作 token 交互。最终只截取末 $H$ 个动作位置：

pred_velocity = pred[:, -self.action_horizon :]

公开前向没有单独计算 FLARE 对齐损失，也没有从输出中直接解码这 32 个位置；但这不等于它们没有监督。在 8 个自注意力 block 中，future token 会影响动作 token，动作位置的流匹配 MSE 因而可以沿注意力路径间接更新 future token。准确说法是“没有公开的专用 FLARE 对齐分支，但存在来自动作损失的间接梯度”。

还有一处位置编码差异：动作 token 在进入 DiT 前加了学习式 position_embedding，状态 token 与 future token 没有对应的专用位置嵌入；DiT block 自身的额外位置嵌入配置也为 null。这限制了“第几个 future token 代表哪个明确未来时刻”的可解释性，不能仅凭 token 顺序宣称公开模型实现了逐时刻未来对齐。

七、完整维度流水

下表按 n1.5-release 前向顺序列出张量。$B$ 为批量，$M_{\Sigma}$ 为一个样本中所有相机原图经动态切图后的图块总数，$N$ 为图像占位符与文本共同形成的 VL 序列长度，$S$ 为状态 token 数，$H$ 为动作块长度。常用发布设置为 $S=1$、$H=16$，但架构本身不要求 $S$ 恒为 1。

步 环节 输出形状或宽度 依据与边界
1 动态切图与视觉塔 每图块 256 个 token、宽 1152 单图块 224×224；总视觉 token 为 $256M_{\Sigma}$
2 单层连接器 每图块 256 个 token、宽 2048 Linear(1152,2048)
3 视觉 token 写入多模态序列 $B\times N\times2048$ $N$ 同时受文本、相机和切图数影响
4 Qwen3 前 12 个 block $B\times N\times2048$ 取 hidden_states[12]
5 主干末端与 vlln $B\times N\times2048$ Identity() 后接 LayerNorm(2048)
6 四层 VL 自注意力 $B\times N\times2048$ 不额外加位置嵌入，也未传 padding mask
7 状态编码器 $B\times S\times1536$ 内置配置通常 $S=1$
8 future token $B\times32\times1536$ 可学习 embedding
9 动作编码器 $B\times H\times1536$ 含时间步条件，并给动作位置加学习式位置嵌入
10 DiT 输入拼接 $B\times(S+32+H)\times1536$ 常用设置为 $B\times49\times1536$
11 16 个交替 block 同上 8 个交叉注意力 + 8 个自注意力；VL K/V 输入宽 2048
12 DiT 输出投影 $B\times(S+32+H)\times1024$ output_dim=1024，不是继续保持 1536
13 分组动作解码器 $B\times(S+32+H)\times32$ 1024 → action_dim=32
14 截取末 $H$ 个动作位置 $B\times H\times32$ 发布设置为 $B\times16\times32$

最关键的接口边界有三处：VL 条件保持 2048 维，而 DiT 查询侧保持 1536 维；16 个 block 只有 8 个读取 VL K/V；DiT 在交给动作解码器前先把 1536 维投影到 1024 维。把任一处写错，都会导致参数量或张量形状推导错误。

八、知识点、重点与创新点：按证据强度归纳

8.1 可直接确认的关键增量

  1. VLM 换代且冻结。 官方确认从 Eagle 2.5 出发并在预训练、微调中冻结；公开配置进一步显示语言侧为 Qwen3-1.7B，并仅执行前 12 个 decoder block。
  2. 提高每图块的视觉 token 保留率。 关闭 pixel shuffle 后，每个 224×224 图块从 64 个 token 增至 256 个；总数仍取决于动态切图，不能简写为每帧固定 256。
  3. 重建 VL—动作接口。 单层连接器输出 2048 维，主干末端不再共享降到 1536 维，而由 8 个交叉注意力 block 分别投影 K/V。
  4. 在冻结主干后增加可训练适配。 vlln 加四层 VL 自注意力，为动作头提供新的可训练条件处理容量。
  5. 把 32 个 future token 插入 DiT 查询序列。 它们没有公开的专用 FLARE 对齐分支，但能通过动作损失获得间接梯度；不能误写成完全无监督。

8.2 不能从现有证据推出的结论

容易出现的过度结论 为什么不成立 建议表述
视觉塔已被单独证明从 SigLIP 换到 SigLIP2 两代核心形状相同，N1 路径名也已含 siglip2，缺少权重级对照 整个 VLM 从 Eagle 2.5 出发；无法隔离视觉塔单项换代
4 倍视觉 token 让整体注意力成本变成 16 倍 总序列还含文本与多个动态图块，且 DiT 交叉注意力近似线性依赖 K/V 长度 只说明每图块 token 为 4 倍，并给出各模块复杂度关系
2048 维接口已被证明保留更多有效语义 没有 project_to_dim 单项消融 它移除共享瓶颈并增加按层投影自由度，是可能机制
vlln 就是官方所说的 LLM 输入归一化 一个在截断 LLM 后，一个被描述在 LLM 输入前 并列记录官方训练描述与公开发布路径
future token 在公开代码中完全没有监督 没有专用损失，但动作 MSE 可经自注意力间接反传 称“无公开专用 FLARE 对齐分支”
全部 16 个 DiT block 都是交叉注意力 源码按奇偶层交替 明确写成 8 个交叉注意力 + 8 个自注意力

8.3 与性能结果的正确连接方式

官方报告新物体零样本成功率从 N1 的 0% 提升到 N1.5 的 15.0%，加入基于人类视频、包含新物体的 FLARE 后训练后达到 55.0%。这些数字支持“整套 N1.5 训练系统改善新物体泛化”，但不能把 15 个或 40 个百分点拆给本页某个结构改动。架构、FLARE 目标、DreamGen 数据与训练配方共同变化，只有受控消融才能建立单项因果。
