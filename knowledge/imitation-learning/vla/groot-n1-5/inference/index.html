知识库首页 /模仿学习 /VLA 总览 /GR00T N1.5 总览 /⑤ 推理流程与反常现象

本页回答四个问题：一次 get_action 如何从观测变成真实机器人动作；4 步欧拉积分究竟意味着什么；future token 与 FLARE 在公开实现中处于什么状态；哪些“反常现象”是事实，哪些只是尚未验证的机制解释。

先分清三个对象。官方 Research 页描述 NVIDIA 声称采用的 N1.5 训练方法；发布权重的 config.json 给出该检查点的结构与默认推理参数；n1.5-release 源码说明公开使用路径实际执行什么。三者相关，但不能互相代替。本页源码结论固定到 n1.5-release 对应提交 4af2b622892f7dcb5aae5a3fb70bcb02dc217b96。

一、本页边界

本页只分析推理链路、数值积分和容易误读的现象：

  • 训练损失与冻结开关见 ④ 训练配方、损失组合与优化配置；
  • FLARE 方法本身见 ② FLARE 未来潜在表征对齐；
  • 网络层级与 token 组织见 ① 架构增量与 VL 接口重建；
  • 本页不会把发布配置、推理服务默认值或运行时覆盖值统称为“模型固定值”。

二、端到端推理链路

2.1 公共入口不只是模型前向

Gr00tPolicy.get_action 才是公开 Python 路径的完整入口。一次调用依次经过：

阶段 公开代码行为 频率
1 复制输入；判断是否已带 batch 维，必要时补 batch 维 每次请求一次
2 apply_transforms 处理图像、语言、状态，按配置拼接并用检查点元数据归一化 每次请求一次
3 Eagle 视觉语言主干产生中间层 token 每个动作块一次
4 vlln 与四层 VL self-attention 处理主干 token；状态编码器编码状态 每个动作块一次
5 采样高斯噪声，初始化形状为 $[B,H,D_{\max}]$ 的动作块 每个动作块一次
6 动作编码器、DiT、动作解码器和欧拉更新 重复 $K$ 次
7 将归一化动作转为 FP32/CPU，unapply_transforms 反归一化并按本体动作键拆分 每次请求一次

发布配置为 $H=16$、$D_{\max}=32$、$K=4$。这里的 32 是共享动作上限，不等于每台机器人都有 32 个物理自由度。推理动作头不会读取训练用的 action_mask；它先生成统一宽度的动作张量，随后 ConcatTransform.unapply 按元数据记录的各动作键维度切出真实部分，再执行反归一化和逆变换。

输出是动作块，不是完整控制器。一次调用返回未来 $H$ 个动作。执行全部动作、只执行前若干个动作，还是每个控制周期重规划，由机器人客户端和控制循环决定；模型本身没有闭环执行、碰撞检查或安全停止逻辑。

2.2 哪些结果复用，哪些仍重复计算

动作头在欧拉循环之前只计算一次：

  • process_backbone_output，即 vlln 与 VL self-attention；
  • 状态编码器；
  • 初始高斯噪声。

每个欧拉步仍会重新执行：

  • 当前动作块的动作编码器与时间嵌入；
  • future token 的 expand 与序列拼接；
  • 16 层 DiT；
  • 整个序列上的动作解码器；
  • 欧拉更新。

处理后的 VL token 张量会复用，但公开 PyTorch 路径没有跨欧拉步的显式 cross-attention K/V cache；DiT 每次调用仍会重新计算相应投影。因此“主干只跑一次”不能理解成视觉语言侧的全部计算都已缓存。

2.3 推理参数有三层来源

层级 num_inference_timesteps
动作头配置类的字段默认 None，单独实例化时必须提供
GR00T-N1.5-3B 发布配置 4
scripts/inference_service.py 命令行默认 4，并传给 Gr00tPolicy 覆盖动作头
运行时 Gr00tPolicy(..., denoising_steps=K) 或属性 setter 可再次覆盖

官方服务脚本同时提供 ZMQ 与 HTTP 服务；可选 TensorRT 路径要求预先构建引擎。通信协议只是封装，最终都调用同一个 Gr00tPolicy.get_action 语义。

三、欧拉积分、时间方向与随机性

3.1 训练路径与推理网格必须分开

训练时，公开动作头构造

\[z_t=(1-t)\epsilon+t\,a, \qquad u^*=a-\epsilon,\]

其中 $\epsilon$ 是高斯噪声，$a$ 是真实动作。训练时间不是均匀采样：源码先采 $u\sim\mathrm{Beta}(1.5,1.0)$，再计算 $t=(0.999-u)/0.999$。

这里还有一个容易漏掉的数值边界：由于 $u\in(0,1)$，严格范围是 $t\in(-1/999,1)$，并非完全落在 $[0,1]$。对该 Beta 分布，$\Pr(t<0)=1-0.999^{1.5}\approx0.15\%$。公开代码不做截断：极少数样本会在噪声端发生约千分之一幅度的外推；随后转成整数时间桶时，这些很小的负数又会因向零截断落到 0 桶。它对结果是否有可测影响没有公开消融，不能把“训练时间严格位于 $[0,1]$”当成源码事实。

推理时不再采 Beta 时间，而使用确定网格

\[t_k=\frac{k}{K},\qquad \Delta t=\frac{1}{K}, \qquad k=0,\ldots,K-1,\]

并执行前向欧拉更新

\[A_{k+1} = A_k+\Delta t\, V_\theta(A_k,t_k\mid c), \qquad A_0\sim\mathcal N(0,I).\]

发布配置 $K=4$ 时，连续时间依次为 $0,0.25,0.5,0.75$，离散时间桶为 $0,250,500,750$；最后一次更新把数值状态推进到 $t=1$。

这个推导要求 $K$ 是正整数。公开 setter 没有做范围校验：$K=0$ 会在计算 $1/K$ 时除零，负数会让循环不执行并直接返回初始高斯噪声，非整数则不能交给 range。因此“运行时可覆盖”不等于任意值都合法，部署层应显式验证 $K\in\mathbb N_{>0}$。

3.2 同一观测不保证每次输出完全相同

get_action 每次都用 torch.randn 重新采样 $A_0$。因此即使观测、权重和 $K$ 不变，重复调用也可能得到不同动作块。model.eval() 与 torch.inference_mode() 关闭训练态随机层和梯度记录，却不会取消这次显式高斯采样。

若部署需要可重复性，应在受控环境中固定并管理随机数生成器，同时记录精度、设备和运行库；仅调用 eval() 不足以保证逐位一致。固定随机种子也不等于真实机器人执行会确定，因为传感器输入和控制时序仍会变化。

四、4 步与 16 步：事实和不能推出的结论

4.1 可核对的事实

来源 步数
GR00T N1 论文正文 称 $K=4$ 已足够
GR00T-N1-2B 发布配置 16
FLARE v1 实验 按 GR00T N1 取 $K=4$
GR00T-N1.5-3B 发布配置 4

因此，“N1.5 发布配置相对 N1 发布配置由 16 改为 4”是事实；“N1.5 首次发现 4 步可行”不是事实。N1 论文已经采用 4 步，而 N1 的论文与发布配置本来就不一致。

发布材料没有说明把 N1.5 配置改成 4 的因果理由，也没有给出 N1.5 的 1/2/4/8/16 步成功率—延迟消融。页面只能说它与 N1 论文和 FLARE 的设置一致，不能把“对齐论文”“性能不下降”或“因为网络更强”写成已证结论。

从数值分析看，若学习到的速度场足够光滑，显式欧拉法的单步局部截断误差是 $O(\Delta t^2)$，区间上的全局离散误差是一阶的 $O(\Delta t)=O(1/K)$。这只约束“沿同一个已学习速度场求解 ODE”的离散误差，不包含速度场本身的学习误差；把 4 步增至 16 步也只有在渐近误差区间内才可能把该项约缩小到四分之一，不能由此推出任务成功率提高四倍或必然提高。

4.2 “线性插值”不等于生成轨迹必然是直线

对固定训练配对 $(\epsilon,a)$，条件插值 $(1-t)\epsilon+t a$ 的确是一条直线，目标速度 $a-\epsilon$ 也与 $t$ 无关。这是少步积分可能有效的重要结构动机。

但平方损失学到的速度场，在给定中间状态和条件后相当于对配对速度的条件平均。不同配对会在同一位置附近叠加，模型也存在逼近误差。因此对学习后速度场积分得到的单条 ODE 轨迹不保证是直线。

准确结论是：直线条件路径有利于构造较平滑的传输问题，但不能单靠这条公式证明 4 步与 16 步性能等价。“传统扩散路径一定曲率更大、因此必须更多步”也过于绝对；步数还取决于参数化、求解器、噪声日程和模型误差。

五、future token：没有直接动作输出，但不是“纯开销”

5.1 序列长度与计算位置

每个欧拉步都会拼接

\[[\text{state tokens};\ \text{32 future tokens};\ \text{H action tokens}].\]

所以 N1.5 的 DiT 序列长度是 $L=S+32+H$，其中 $S$ 是状态 token 数，而不是结构上恒定为 1。若某个数据配置使用 $S=1$ 且发布动作长度 $H=16$，则 $L=49$；对应的 N1 结构没有 32 个 future token，长度为 17。

仅比较 self-attention 的注意力矩阵元素数，单步比例约为

\[\frac{49^2}{17^2}\approx8.31.\]

再考虑 N1.5 为 4 步、N1 发布配置为 16 步，这一局部量的整块比例约为

\[\frac{4\cdot49^2}{16\cdot17^2}\approx2.08.\]

这只是特定 $S,H$ 假设下的结构性比较，不是端到端 FLOPs 或延迟结论；两代模型的层宽、主干、内核效率和服务路径也会影响实际速度。

5.2 为什么不能直接删除

动作解码器会先处理完整序列，随后只保留最后 $H$ 个动作位置。future token 对应位置没有直接返回给机器人，但它们在 DiT 自注意力中与动作 token 交互，因此能够间接改变最终动作预测。

  • 按官方训练描述，发布权重应接受过 FLARE 监督；公开权重和代码本身不能独立证明各 token 学到了什么。
  • 在公开的普通非 LoRA 微调路径中，future token 默认可训练，可通过动作损失的间接路径更新。
  • 启用 LoRA 后，PEFT 通常冻结这些基础参数，只训练被选中的注意力 Q/K/V 适配器。

所以“没有直接输出”正确，“不影响输出”或“纯开销”错误。删掉它们会改变序列结构与已训练注意力分布，必须重新训练并做消融，不能当作无损部署优化。

六、FLARE 的官方目标与公开实现缺口

6.1 两条证据链

证据 可以确认什么
NVIDIA Research 页 N1.5 在流匹配之外加入 FLARE；系数 0.2，并称预训练与后训练都使用
FLARE v1 给出未来表征对齐方法与独立实验设置
n1.5-release 有 32 个 future token 和返回中间层的接口，但公开动作头明确设置 return_all_hidden_states=False，旁注 not using flare now
公开微调脚本 返回并优化的只有掩码归一流匹配损失

因此，公开脚本可以微调发布权重，但不能复现官方所描述的含 FLARE 后训练目标。发布权重可能已经承载官方训练带来的 FLARE 效果；这不意味着后续仅流匹配微调会继续施加 FLARE 约束，也不保证其效果不会随微调改变。

6.2 为什么公开代码省略 FLARE：原因未知

仓库面向下游微调和部署、FLARE 需要额外未来观测与教师表示，这些都是合理背景，但官方没有说明为何发布代码省略该目标。尤其官方明确写了后训练也使用 0.2 系数，所以不能用“FLARE 主要只用于预训练”来调和两者。

可确认的是实现缺口，不可确认的是缺口原因。若要在自己的训练中加入 FLARE，需要实现未来观测数据路径、目标编码器／教师表示、层级抽取与对齐损失，并验证它们与公开动作头的切片和归一方式；仅把 return_all_hidden_states 改为 True 并不够。

七、冻结 VLM 与接口调整后能力提升：不能归因于单一因素

官方把以下两项修改合并描述为语言跟随与泛化显著改善：

  • 预训练与微调都冻结 VLM；
  • 简化视觉—语言连接接口并加入归一化相关修改。

此外，官方说明 N1.5 更新到以 Eagle 2.5 为起点、针对 grounding 与物理理解调优的 VLM。官方没有给出“只冻结 VLM、其余保持不变”的单因素消融。因此准确标题应是“冻结 VLM 与接口修改后，语言跟随和泛化提升”，而不是“冻结视觉塔反而带来提升”。

冻结可能降低窄机器人数据对通用语义表示的漂移，这是合理机制假设：动作损失可通过场景捷径取得低误差，却没有义务保存指代消解和物体常识。但公开证据没有直接测量表示漂移，也没有证明它是改善的唯一原因。

公开默认微调仍把适配能力留在 vlln、VL self-attention、future token、状态／动作编解码器和 DiT；具体可训练集合还会随 tune_projector、tune_diffusion_model 与 LoRA 模式变化。发布配置的 project_to_dim 为 null，所以 eagle_linear 在该检查点中是无参数的 Identity。

官方对“进入 LLM 前的归一化”的文字与 n1.5-release 公开结构并不完全对应；这是架构证据问题，不应在推理页强行调和。逐层核对见 ① 架构增量与 VL 接口重建。

八、部署时最容易忽略的四个边界

边界 实际含义
动作是随机生成的 每次调用重新采高斯噪声；eval() 不会消除它
推理不使用 action_mask 真实动作维依赖元数据、拼接顺序与 unapply；配置错位会直接产生错误控制量
4 步不是不可变常量 checkpoint、服务 CLI 和 setter 可以覆盖，但源码不校验正整数；修改后应重测正确性、成功率与延迟
动作块不等于闭环控制 $H=16$ 只是预测长度；执行多少步、何时重规划由外部控制器决定

此外，官方能力结果也应保持边界感：N1.5 在新物体任务的公开零样本成功率为 15.0%，加入包含新物体的人类视频后训练后为 55.0%；新行为实验仍使用 DreamGen 轨迹显式训练，官方把完整的零样本动词与环境泛化留作未来工作。推理链路能生成动作，不等于模型对任意新指令都具备可靠能力。

九、重点与创新点

  1. 计算分层：视觉语言主干和 VL 适配只运行一次，动作专家按欧拉步重复；这是双系统设计在推理侧的实际落点。
  2. 少步生成：发布配置用 4 次前向欧拉更新，但公开材料没有证明 4 步对所有任务都与 16 步等价。
  3. 跨本体输出：统一动作上限由输入变换和输出逆变换映射回本体真实维度；推理期不存在训练掩码替用户兜底。
  4. future token 的双重身份：它们源于未来表征监督，又在推理时作为参与注意力的隐状态；没有直接动作输出不等于没有功能。
  5. 论文—权重—代码分离：官方训练含 FLARE，公开微调只含流匹配。理解模型必须同时核对三层证据。
  6. 部署边界：随机初值、动作块执行策略、元数据和服务端覆盖参数都会改变实际行为，不能只看模型结构图。
