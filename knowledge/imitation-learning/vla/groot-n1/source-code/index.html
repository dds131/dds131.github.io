一、本页在专题中的位置

本页给出函数级、可复核的实现事实，源码基准固定为 n1-release 标签、commit 755876a9afdb41ca6eb6383b36f4a0adb085c73f。为避免把代码、配置和推断混为一谈，正文采用四类表述：

源码事实指定版本的代码直接执行了什么。
配置事实发布配置或 dataclass 明确给出的值。
一致性判定把代码、公式或多个文件合起来后得到的结论。
实践提示复现、微调或扩展时需要额外注意的边界。

公式层面的含义不在本页，见 ② Flow Matching、损失与时间方向；超参语义不在本页，见 ④ 训练配方、损失组合与优化配置；模块结构与维度不在本页，见 ① 网络架构与双系统。

二、先读这一节：版本边界

同一个仓库承载了多个 GR00T 版本。主线已经演进到后续版本，文件结构、配置和模型实现都可能与初代 N1 不同。

截至 2026-10-04，远端仍可见 n1-release、n1.5-release、n1.6-release、n1.6.1-release、n1.7-release；main 分支 README 标题为 NVIDIA Isaac GR00T N1.7，模型指向 nvidia/gr00t-n17 集合。

而 n1-release 的 README 标题是 NVIDIA Isaac GR00T N1，模型指向 nvidia/GR00T-N1-2B——这才是论文 arXiv:2503.14734 对应的版本。

取得本页所述代码的方式：

# 方式一：按标签克隆
git clone --depth 1 --branch n1-release https://github.com/NVIDIA/Isaac-GR00T

# 方式二：直接取该标签的归档（不需要 git 历史时更快）

curl -L -o n1.tar.gz \
https://codeload.github.com/NVIDIA/Isaac-GR00T/tar.gz/refs/tags/n1-release

截至上述检查日期，主线 README 仍把 arXiv:2503.14734 列为 Paper 链接。该论文描述的是初代 N1；主线继续链接论文，不等于主线实现与论文版本相同。

三、仓库结构与读码地图

3.1 顶层职责

目录 主要职责
gr00t/ 模型、数据变换、实验配置和评测库代码
getting_started/ notebook、数据格式规范与深入说明
scripts/ 微调、推理服务、策略评测和数据加载入口

3.2 理解顶层调用链的四个入口文件

按依赖顺序：

顺序 文件 看什么
1 gr00t/model/gr00t_n1.py 顶层装配：主干与动作头如何拼起来
2 gr00t/model/backbone/eagle_backbone.py System 2：层截断与特征提取
3 gr00t/model/action_head/flow_matching_action_head.py 训练与采样两条路径的全部逻辑
4 gr00t/model/action_head/cross_attention_dit.py System 1：块的交替排布与 adaLN

这四个入口足以追踪顶层调用链，但不覆盖视觉 token 压缩等全部细节。scripts/gr00t_finetune.py 与 gr00t/experiment/data_config.py 是使用侧的两个入口，见第八节。

四、顶层装配

gr00t/model/gr00t_n1.py 的结构非常薄，主要工作是把两个子模块接起来：

self.backbone = EagleBackbone(**config.backbone_cfg)
action_head_cfg = FlowmatchingActionHeadConfig(**config.action_head_cfg)
self.action_head = FlowmatchingActionHead(action_head_cfg)

顶层训练与推理的分叉发生在动作头：

def forward(self, inputs: dict) -> BatchFeature:
    backbone_inputs, action_inputs = self.prepare_input(inputs)
    backbone_outputs = self.backbone(backbone_inputs)
    action_head_outputs = self.action_head(backbone_outputs, action_inputs)
    self.validate_data(action_head_outputs, backbone_outputs, is_training=True)
    return action_head_outputs

def get_action(self, inputs: dict) -> BatchFeature:
    backbone_inputs, action_inputs = self.prepare_input(inputs)
    # Backbone 的训练与推理共用 forward 接口。
    backbone_outputs = self.backbone(backbone_inputs)
    action_head_outputs = self.action_head.get_action(
        backbone_outputs, action_inputs
    )
    self.validate_data(action_head_outputs, backbone_outputs, is_training=False)
    return action_head_outputs

源码事实： 两条顶层路径都调用 backbone 的 forward 接口；动作头分别进入 forward 和 get_action。这不等于 backbone 在 train() 与 eval() 状态下的数值行为完全相同——例如 dropout 仍可受模块模式影响。

实现含义： 一次动作块生成只计算一次视觉语言特征，随后在多步动作积分中复用该输出张量。源码没有实现交叉注意力 K/V 投影缓存，因此“复用主干输出”不应写成“缓存所有 K/V”。

prepare_input 还做了一件容易忽略的事：它把浮点叶子转换到 action_head.dtype，而整数和布尔叶子只移动到设备、保留 dtype。embodiment_id 必须保持整数才能用作索引，mask 也无需被错误转换成浮点语义。

实践提示：优先通过 Gr00tPolicy 推理。 动作头的 get_action 带有 @torch.no_grad()，但裸模型 GR00T_N1.get_action 中的 backbone 调用发生在进入动作头之前。官方 policy 封装会先执行 model.eval()，并用 torch.inference_mode() 与 autocast 包裹整条模型调用；它还负责输入变换、按 checkpoint 元数据反归一化动作以及单样本 batch 维处理。直接调用裸模型时，不要误以为动作头装饰器自动覆盖了主干，也不要漏掉这些数据变换。

设备边界： Gr00tPolicy 的 device 参数允许传入 "cpu"，但 _get_action_from_normalized_input 在该版本中把 torch.autocast(device_type="cuda", ...) 写死为 CUDA。因而源码接口“接受 CPU”不等于这条官方封装已完整验证 CPU 推理；非 CUDA 部署应先修改或显式测试这一上下文。

五、三条关键路径

5.1 训练路径 FlowmatchingActionHead.forward

源码事实。 下面是保留控制流的删节片段；训练路径按此顺序构造噪声—数据插值、速度目标和条件 token：

state_features = self.state_encoder(action_input.state, embodiment_id)

actions = action_input.action
noise = torch.randn(actions.shape, ...)
t = self.sample_time(actions.shape[0], ...)
t = t[:, None, None]

noisy_trajectory = (1 - t) * noise + t * actions
velocity = actions - noise

t_discretized = (t[:, 0, 0] * self.num_timestep_buckets).long()
action_features = self.action_encoder(noisy_trajectory, t_discretized, embodiment_id)

if self.config.add_pos_embed:
    pos_ids = torch.arange(action_features.shape[1], ...)
    action_features = action_features + self.position_embedding(pos_ids).unsqueeze(0)

sa_embs = torch.cat((state_features, action_features), dim=1)

model_output = self.model(
    hidden_states=sa_embs,
    encoder_hidden_states=vl_embs,
    encoder_attention_mask=vl_attn_mask,
    timestep=t_discretized,
)
pred = self.action_decoder(model_output, embodiment_id)
pred_actions = pred[:, -actions.shape[1]:]

action_mask = action_input.action_mask
loss = F.mse_loss(pred_actions, velocity, reduction="none") * action_mask
loss = loss.sum() / action_mask.sum()

八个容易看漏的点：

  • 源码事实：插值为 (1-t) * noise + t * actions，回归目标为 actions - noise；后者正是这条路径对时间的导数。
  • 一致性判定：该方向与下节从噪声向动作积分的正步长一致，但与论文式 (1) 写出的速度符号相反。完整判定见子页 ②；本页不把“源码与自身一致”扩写成对论文公式的替代证明。
  • 时间采样并非论文变换的等价改写：源码先取 U ~ Beta(1.5, 1)，再计算 t = (0.999 - U) / 0.999。这与论文给出的自然 Beta 变换不是同一随机变量；复现源码应照代码，讨论论文方法则应保留这条差异。
  • 源码没有裁剪连续时间：当 U > 0.999 时，t 会略小于 0。其概率为 1 - 0.999^1.5 ≈ 0.15%，下界约为 -0.001001；因此少量样本是在噪声端之外做很小的线性外推，而不是严格落在 [0, 1]。
  • 位置嵌入只加在动作特征上，且是在与状态拼接之前加的，因此状态位不会吃到第 0 号位置嵌入。
  • 拼接顺序是状态在前、动作在后，所以末 H 个 token 才是动作。
  • 解码器作用在全部 token 上，之后才切片，状态位对应的输出被直接丢弃。
  • 损失按 action_mask 加权并除以有效元素数，不是对全部元素求平均。

num_timestep_buckets=1000 在这里是把连续时间乘以 1000 后转成整数，随后送进正弦时间投影和 MLP；它不是“包含 1000 个可学习向量的查表嵌入”。由于转换使用 PyTorch 的 .long()（向零截断），负连续时间通常会变成 0，只有极靠近理论下界的尾部可能得到 -1；连续 t 仍会原样参与 noisy_trajectory。

action_mask 只屏蔽最终逐元素 MSE，不阻止填充动作值进入编码器与 DiT。实现还假定一个 batch 至少含一个有效动作标量；若 action_mask.sum() == 0，该除法没有保护，会产生非有限损失。

5.2 推理路径 FlowmatchingActionHead.get_action 

actions = torch.randn(
    size=(batch_size, self.config.action_horizon, self.config.action_dim), ...)

num_steps = self.num_inference_timesteps
dt = 1.0 / num_steps

for t in range(num_steps):
    t_cont = t / float(num_steps)
    t_discretized = int(t_cont * self.num_timestep_buckets)
    timesteps_tensor = torch.full(
        size=(batch_size,), fill_value=t_discretized, ...
    )

    action_features = self.action_encoder(actions, timesteps_tensor, embodiment_id)
    if self.config.add_pos_embed:
        action_features = action_features + pos_embs

    sa_embs = torch.cat((state_features, action_features), dim=1)
    model_output = self.model(
        hidden_states=sa_embs,
        encoder_hidden_states=vl_embs,
        timestep=timesteps_tensor,
    )
    pred = self.action_decoder(model_output, embodiment_id)
    pred_velocity = pred[:, -self.action_horizon:]

    actions = actions + dt * pred_velocity

return BatchFeature(data={"action_pred": actions})

三处与训练路径的差别：

其一，主干特征在积分循环外只算一次，循环内反复复用 vl_embs。

其二，推理调用没有传 encoder_attention_mask；训练虽然传入该参数，但 DiT 内部没有继续转发，见第 5.3 节。

其三，当前动作按 actions = actions + dt * pred_velocity 反复更新，是朴素的前向欧拉积分；循环中没有重新采样或重加噪。多次速度修正本身就是积分过程，不应写成“没有自校正”。

5.3 DiT 内部 cross_attention_dit.py

块循环的分支条件：

for idx, block in enumerate(self.transformer_blocks):
    if idx % 2 == 1 and self.config.interleave_self_attention:
        hidden_states = block(hidden_states, attention_mask=None,
                              encoder_hidden_states=None,           # 不给条件 → 自注意力
                              encoder_attention_mask=None, temb=temb)
    else:
        hidden_states = block(hidden_states, attention_mask=None,
                              encoder_hidden_states=encoder_hidden_states,  # 给条件 → 交叉注意力
                              encoder_attention_mask=None, temb=temb)

每个 BasicTransformerBlock 各自实例化一个 attn1：

self.attn1 = Attention(query_dim=dim, ..., cross_attention_dim=None)
...
attn_output = self.attn1(
    norm_hidden_states,
    encoder_hidden_states=encoder_hidden_states,
    attention_mask=attention_mask,
    # encoder_attention_mask=encoder_attention_mask,     ← 这一行是注释掉的
)

两处合起来给出两个边界清楚的结论：

块间交替，不是块内两级已固定版本的发布配置明确给出 num_layers=16、interleave_self_attention=true：索引 0、2、…、14 的 8 个块读取 VLM 条件，索引 1、3、…、15 的 8 个块做状态—动作 token 自注意力。每个块有独立的 attn1 参数；共享的是调用接口，不是权重。
encoder_attention_mask 当前未进入注意力DiT 两个分支传入 None，块内相应转发又被注释。若视觉语言序列含 padding，该参数不会显式屏蔽相应位置；源码本身不能证明实际影响大小。

attn1 构造时的 cross_attention_dim=None 容易造成误读：它使 K/V 投影输入维度默认等于 query 维度；运行时仍可通过 encoder_hidden_states 传入同为 1536 维的 VLM 特征，从而执行交叉注意力。奇数块传 None 时，K/V 才改用自身 token，执行自注意力。

输出端的处理：

conditioning  = temb
shift, scale  = self.proj_out_1(F.silu(conditioning)).chunk(2, dim=1)
hidden_states = self.norm_out(hidden_states) * (1 + scale[:, None]) + shift[:, None]
return self.proj_out_2(hidden_states)

在发布配置采用 norm_type="ada_norm" 的前提下，流时间在每个块的 adaLN 中参与调制，并在最终输出归一化后再次生成 shift/scale；这不是“同一块内调制两次”。

六、按本体分组是怎么实现的

flow_matching_action_head.py 的删节关键行如下（保留了模块初始化所需的 super().__init__()）：

class CategorySpecificLinear(nn.Module):
    def __init__(self, num_categories, input_dim, hidden_dim):
        super().__init__()
        self.W = nn.Parameter(0.02 * torch.randn(num_categories, input_dim, hidden_dim))
        self.b = nn.Parameter(torch.zeros(num_categories, hidden_dim))

    def forward(self, x, cat_ids):
        selected_W = self.W[cat_ids]
        selected_b = self.b[cat_ids]
        return torch.bmm(x, selected_W) + selected_b.unsqueeze(1)

关键在 self.W[cat_ids]：在这些 grouped encoder/decoder 线性层中，模型按本体 id 选出完整矩阵，再做批量矩阵乘；这不是共享矩阵外接轻量适配器。该隔离只发生在状态编码、动作编码与动作解码边界层，VLM、投影和 DiT 主体仍然共享。

FlowmatchingActionHeadConfig.max_num_embodiments 的源码默认值是 32；当前发布 config.json 没有显式写出这个字段，因此不能称为“发布配置明确给出 32”。按默认构造时，W 的第一维会分配 32 个槽位：未被当前批次索引的槽位没有来自任务损失的非零数据梯度，但参数、梯度和优化器状态仍按整个张量分配；使用 AdamW 时，解耦权重衰减还可能改变未被索引的切片。

三个模块的接法：state_encoder 与 action_decoder 是两层的 CategorySpecificMLP（ReLU 激活），action_encoder 是 MultiEmbodimentActionEncoder，内部三个线性层全部按本体查表，并把动作嵌入与正弦时刻编码拼接后再投影。

七、数据格式：扩展后的 LeRobot

7.1 基础格式

论文附录 E 说明训练语料建立在 LeRobot 数据集格式之上：表格数据（状态、动作、元数据）存 parquet，视觉观测存 MP4（或 PNG 序列）并在 parquet 中引用，统计量与索引存 JSON。

7.2 GR00T N1 的四处扩展

扩展 内容
modality.json 必须在 meta 目录下提供该配置文件
细粒度模态规范 相对论文所对应的 LeRobot 基础格式，此处需逐字段划分区间
多标注支持 支持多种标注类型（例如粗细两级任务描述）
旋转表示声明 显式声明旋转数据用的是哪种表示

demo_data 里的 modality.json 示例展示了细粒度划分的实际样子：

{
  "state": {
    "left_arm":   {"start": 0,  "end": 7},
    "left_hand":  {"start": 7,  "end": 13},
    "left_leg":   {"start": 13, "end": 19},
    "neck":       {"start": 19, "end": 22},
    "right_arm":  {"start": 22, "end": 29},
    "right_hand": {"start": 29, "end": 35},
    "right_leg":  {"start": 35, "end": 41},
    "waist":      {"start": 41, "end": 44}
  },
  "action": { ... }
}

为什么需要这种划分。 上面的 44 维示例主要展示如何把 GR-1 状态分成左右臂、手、腿、颈部和腰部等语义区间，它本身没有展示末端位姿旋转声明。更一般地，状态或动作向量还可以包含末端位置、旋转和夹爪量；不声明字段语义时，数据管线无法可靠判断哪些区间需要旋转表示转换、位置归一化或关节级处理。逐维归一化本身并非必然错误，问题在于不能据此恢复字段语义。

modality.json 提供字段边界、原始键和旋转表示等元数据；具体选择哪些字段、执行哪种转换以及最终拼接顺序，由所选 DataConfig 和 transform 管线显式决定。论文附录 E.2 的 best-effort 规范包括：状态中的末端旋转转成 6D 表示，动作中的末端旋转采用轴角；关节状态、关节动作、末端位置以及末端动作旋转做最小—最大归一化；状态与动作字段按约定顺序排列。 公开微调配置不会机械强制每个数据集同时具备所有字段或采用完全相同的顺序。

7.3 这样做的代价与收益

论文附录 E.1 自己列了收益：语义明确、支持逐字段变换、天然容纳多模态、便于数据校验、保持与上游格式的兼容。代价也很直白——增加了约束，使用者必须为自己的数据集写出这份 modality.json。

8.1 微调 scripts/gr00t_finetune.py

下表是公共微调脚本的运行默认值，不是论文完整预训练配置：

字段 默认值 说明
batch_size 16 每设备批量
max_steps 10000 公共脚本默认训练步数
learning_rate 1e-4 与论文 Table 6 一致
weight_decay 1e-5 与论文一致
warmup_ratio 0.05 与论文一致

这里的全局批量还取决于设备数与梯度累积：

\[B_{\text{global}} = B_{\text{per-device}}\,N_{\text{device}}\,N_{\text{grad-accum}}.\]

tune_projector 这个名字容易误导。沿实际调用链，它控制的是动作头的 state_encoder、action_encoder、action_decoder 和可学习位置嵌入，而不是单凭名称就能推断的“VLM 投影器”。tune_diffusion_model 控制 DiT；tune_visual 控制视觉塔与 mlp1；tune_llm 控制语言模型。发布配置的 projector_dim=2048，与动作头期望的 1536 维不同，因此 EagleBackbone.linear 实际是 2048 → 1536 的线性投影；它没有对应开关，默认保持可训练。只有当配置令输入维度无需重投影、该成员退化为 Identity 时，才不存在这组参数。

还有一个实现不对称：backbone 的 setter 只有“开关为 false 时冻结”的分支，不能保证把已经冻结的语言模型由 false 切回 true 后重新解冻；动作头 setter 则会先重设参数状态，再分别应用两个动作头开关。因此需要解冻 LLM 时，应直接检查 requires_grad，不能只相信配置标志。

文档与入口脚本存在默认值差异。 getting_started/4_deeper_understanding.md 对视觉塔和 diffusion 微调默认值的描述，与 scripts/gr00t_finetune.py 的实际参数默认值不一致。调用该脚本时，应以解析后的 CLI/脚本值为准，并显式写出关键开关，避免因上游文档差异改变训练范围。

8.2 本体标签与数据配置

gr00t/data/embodiment_tags.py 在该标签下只暴露两个枚举值：

class EmbodimentTag(Enum):
    GR1 = "gr1"                          # GR1 数据集
    NEW_EMBODIMENT = "new_embodiment"    # 微调用的任意新本体

公共 EmbodimentTag API 只暴露 gr1 和 new_embodiment 两个入口；这不等于预训练只使用两个本体，也不能推出其他槽位没有权重。数据变换中的公开映射为 gr1 → 24、new_embodiment → 31，但公开代码没有给出论文所有预训练本体与槽位索引的完整映射。

仅凭 enum 名称和映射，无法判断 checkpoint 的槽位 31 是否训练过，也不能断言加载 checkpoint 后会被重新初始化。官方教程将 new_embodiment 作为新机器人微调入口；要证明“从头学习”，还需看到显式重初始化或核对 checkpoint 权重，当前源码没有提供前者。

九、本页结论速查

N1 的关键工程组合静态 VLM 条件在多步动作积分中复用；短状态—动作序列通过交叉注意力读取长视觉语言序列；按本体边界层包围共享 DiT；字段级模态声明统一异构机器人数据。
不应归为 N1 原创Flow Matching、前向 Euler、adaLN、交叉/自注意力、LeRobot 数据组织、旋转表示转换和字段归一化都已有独立来源。创新判断应落在组合与系统取舍，而不是基础算子本身。
实现审计发现论文与源码的速度符号、Beta 时间变换、论文 4 步与发布配置 16 步、未进入注意力的 VL mask，以及公开标签与槽位映射不完整，都是版本或证据边界，不是模型创新。
问题 结论
本专题的源码基准 n1-release，commit 755876a；当前主线已是后续版本
主干在推理时算几次 一次，K 步去噪循环复用其输出
顶层训练/推理分叉 位于动作头；backbone 调用接口相同，但模式行为可不同
回归目标 actions - noise；与源码插值和正向积分一致
推理积分 前向欧拉，循环中不重新采样或重加噪
DiT 块排布 偶数交叉、奇数自注意力；各块参数独立
encoder_attention_mask 当前调用链未传入注意力；含 padding 时不会显式屏蔽
按本体分组 边界层按 id 选完整矩阵；主体共享；源码默认 32 个槽位
数据格式 LeRobot 加四处扩展，核心是 modality.json 的逐字段区间
公共 API 的本体标签 enum 仅暴露 gr1 与 new_embodiment；非预训练全集
