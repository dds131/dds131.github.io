← Actor-Critic 枢纽·④ 网络结构

Actor-Critic 不是“两个任意 MLP”的同义词。Actor 输出头决定动作分布的 support、log-prob 与可用梯度路径；Critic 的输入签名决定它提供 \(V\)、\(Q\) 还是动作梯度；共享方式又决定两种损失如何共同更新表征。网络形状只能提供这些能力，不能单独证明算法是 on-policy、off-policy 或训练正确——采样分布、目标、重要性校正和停止梯度同样必须匹配。

一、统一数据流与信息边界

flowchart LR
  O["观测 o_t"] --> P["预处理 / 特征提取"]
  P --> A["Actor 表征"]
  P --> C["Critic 表征"]
  A --> H["分布参数或确定性动作"]
  H --> E["环境"]
  H -->|"仅 Q-Critic：动作也作为输入"| C
  C --> V["V(s) 或 Q(s,a)"]
  E --> R["r_t, o_{t+1}, terminated, truncated"]
  R --> P

观测不等于马尔可夫状态。图像、历史堆叠、RNN 隐状态或机器人特权状态都可能参与 Critic，而部署端 Actor 只能使用实际可观测量。图中的动作到 Critic 连线只适用于 \(Q(s,a)\)；V-Critic 不接本步动作。预处理也属于模型契约：训练、评估与部署必须使用相同的特征顺序、dtype、归一化统计和动作尺度。

二、Actor 输出头先匹配动作 support

动作空间 常用分布/输出 log-prob 约定 必须检查
Discrete Categorical logits 每个样本一个标量 直接把 logits 交给分布；动作掩码必须在采样前进入 logits
MultiDiscrete 每个分量一组 Categorical logits 各分量相加 独立乘积分布是假设，不能表示分量间依赖
MultiBinary 每位一个 Bernoulli logit 各位相加 只在各位条件独立时成立；受约束组合需结构化策略
复合/混合动作 按子空间设置多个输出头 仅在声明因子化时可相加 Dict/Tuple 与离散—连续混合动作需检查算法和库是否原生支持
有限上下界 Box 对角高斯 \(\mu,\log\sigma\) 经可逆 tanh 与仿射变换 基高斯密度减去完整变换的 log-Jacobian 不能用 clamp 后仍沿用未裁剪高斯密度
单边/无界 Box 与实际区间匹配的变换或未变换分布 按所用变换逐维计算 Gymnasium Box 不保证每一维都有有限双边界
确定性连续动作 \(\mu_\theta(s)\) 没有策略密度 DDPG/TD3 通过 \(\nabla_aQ\) 更新；探索噪声不属于 Actor 密度
最大熵连续策略 可重参数化的 squashed Gaussian 变换后密度 SAC 需要 rsample 式路径与正确的 \(\log\pi\)

MultiDiscrete、MultiBinary 与对角高斯的“逐维独立”只是常用参数化，不是环境事实。若动作分量有互斥、预算或时序约束，应使用动作掩码、自回归/联合分布或重新设计动作空间。离散动作掩码要在构造 Categorical 前把非法动作 logits 设为不可选，并在采样、evaluate、entropy 与旧/新 log-prob 中使用同一张 mask；“全部非法”必须有显式回退或直接报错。

对有限边界连续动作，令

\[\begin{aligned} u&=\mu_\theta(s)+\sigma_\theta(s)\odot\epsilon,\\ y&=\tanh u,\\ a&=b+c\odot y. \end{aligned}\]

其中 \(b=(h+l)/2\)、\(c=(h-l)/2\) 且每个 \(c_i>0\)。环境动作密度是

\[\begin{aligned} \log\pi_A(a\mid s) &=\log\mathcal N(u;\mu,\sigma)\\ &\quad-\sum_i\bigl[\log c_i\\ &\qquad+\log\!\left(1-\tanh^2u_i\right)\bigr]. \end{aligned}\]

因此动作缩放项的符号也是“减去 log-Jacobian”，不是含糊地再“加一个常数”。数值实现宜直接保留预变换样本 \(u\)，并用稳定恒等式

\[\begin{aligned} \log(1-\tanh^2u) &=2\,[\log 2-u\\ &\quad-\operatorname{softplus}(-2u)]. \end{aligned}\]

避免在 \(\lvert u\rvert\) 很大时先算 1 - tanh(u)**2 得到零。若用逆变换重算 log-prob，还要处理边界附近 atanh 的数值稳定性。直接 clamp 高斯样本会把区间外概率质量压到边界点；这不是普通连续密度，不能继续使用原高斯 log-prob。部分 PPO/A2C 实现确实选择“采样后裁剪”，但这是一种实现折中，不应误写成严格匹配环境动作分布。

三、三条 Actor 梯度路径不能混用

方法族 Actor 梯度从哪里来 动作采样是否反传 常见停止梯度边界
A2C/A3C/PPO \(\nabla_\theta\log\pi_\theta(a_t\mid s_t)\,\hat A_t\) 否；环境与已采样动作不可导 优势、return、旧 log-prob、旧策略参数冻结
DDPG/TD3 \(\nabla_aQ_\phi(s,a)\nabla_\theta\mu_\theta(s)\) Actor 是确定性的 Critic 参数本轮不应被 optimizer 更新；target 全部无梯度
SAC 重参数化动作上的 \(Q-\alpha\log\pi\) 是，需 rsample/路径导数 replay 数据与 target 冻结；Actor 更新时不更新 Q 参数

“Critic 接动作”并不自动等于确定性策略梯度；PPO 的 V-Critic 和 SAC 的 Q-Critic 使用的是不同估计器与采样分布。DDPG/TD3 的交互探索噪声加在环境动作上；TD3 计算靶值时对 target actor 动作加入的裁剪噪声是另一件事，叫 target policy smoothing，不能共用同一个开关或统计。

四、Critic 签名与双 Q

  1. \(V_\phi(s)\to\mathbb R\)：不接本步动作，评价当前策略下的状态；适合 on-policy 得分函数梯度。
  2. \(Q_\phi(s,a)\to\mathbb R\)：显式接动作；Actor 可查询任意动作的价值或对动作求导，是 DDPG、TD3、SAC 等连续控制方法的核心组件，但“能查询任意动作”本身不构成 off-policy 正确性证明。
  3. \(Q_{\phi_1},Q_{\phi_2}\)：TD3、SAC 的 clipped double-Q 靶值常取两者较小值，以抑制 target/Actor 选择带来的过估计。取最小值会引入悲观倾向，它是偏差权衡，不是“真值保证”。

双 Critic 必须是不同的可训练估计器，至少使用独立参数的 Q 头。若两路连全部表征与初始化都共享，误差相关性会增强，取较小者的收益可能减弱；把同一标量复制两次则完全没有双 Q 效果。离散动作 Q-Critic 可一次输出 \(\lvert\mathcal A\rvert\) 个值，再按动作索引 gather；有显式策略时也可对动作分布求 Q 的期望。算法是否仍称 Actor-Critic，取决于是否存在独立优化的策略，而不是 Q 输出向量还是标量。

Q 网络拼接动作前应先把观测与动作缩放到可比较的数值范围。低维控制常在中间层拼接动作；图像任务通常先编码观测，再与动作融合。拼接位置是表征选择，不改变 \(Q(s,a)\) 的数学定义。

五、目标网络属于训练图，不是部署 Actor

DDPG、TD3、SAC 等 off-policy 方法通常维护在线 Critic 与 target Critic；有确定性 target actor 时也要单独维护。软更新写作

\[\bar\phi\leftarrow\tau\phi+(1-\tau)\bar\phi,\qquad 0<\tau\ll1.\]

target 参数不接梯度、不归 optimizer 所有，且不能与在线网络意外别名共享；更新发生在约定的优化步之后。含 BatchNorm 等 buffer 时，还要明确 running statistics 是硬拷贝、软更新还是单独维护，否则“参数已 Polyak 更新”并不等于整个模块状态一致。若 target actor 与 target Critic 有意共享编码器，只能更新一次并记录语义，避免同一参数一轮被软更新两遍。普通 on-policy V-Critic 通常不需要 target 网络，不能因为类名里有 ActorCritic 就机械添加。

六、共享主干还是分离网络

完全共享样本与计算效率高；策略梯度和值梯度可能冲突，value loss 系数会直接改变公共表征。
共享特征、分离 MLP图像任务常见折中；视觉层共享，策略与价值的任务特定层分开。
完全分离优化归属最清晰；参数和计算增加，Actor 与 Critic 不再自动共享有用特征。

A3C 的 Atari 网络共享卷积表征，再接策略与 value 输出；现代库是否共享则取决于算法与 policy 配置，不能从 ActorCriticPolicy 类名推断。共享参数还要回答“谁拥有 optimizer 状态”：同一参数若被两个 Adam optimizer 依次 step，会收到两次更新并维护两套动量；除非这是明确设计，否则应由一个 optimizer 统一拥有，或把两项损失合并后只更新一次。若只允许某一损失更新共享编码器，应在另一分支显式 detach，并用参数梯度断言验证，而不是仅凭模块命名猜测。

七、非对称 Actor-Critic

仿真机器人常令 Actor 只看部署可得观测 \(o_t\)，Critic 训练时看完整状态或特权信息 \(x_t\)：

\[a_t\sim\pi_\theta(\cdot\mid o_t),\qquad V_\phi(x_t).\]

这不会让部署端偷看特权状态，因为 Critic 在推理时被丢弃。策略梯度中作为基线的量可以依赖动作采样前已知的 \(x_t\)，但必须对本步动作条件独立，并在 Actor loss 中停止梯度；给定 \((o_t,x_t)\) 后，动作仍只由 \(\pi(\cdot\mid o_t)\) 产生。若 Critic 输入混入本步动作之后才产生的未来奖励、接触结果或成功标签，它不再只是合法基线。还要保证特权状态与观测时间同步；若 Actor 前向依赖 Critic 隐特征，部署时就不再真正非对称。部分可观测任务若 Actor 需要历史，应把记忆放进 Actor 本身，不能指望训练期特权 Critic 在部署时补回缺失信息。

八、初始化、归一化与数值尺度

  • 正交初始化常见于 on-policy 实现；策略输出层用较小增益可让初始 logits/均值较小，但具体增益是实现选择，不是理论常数。
  • value/Q 输出层通常保持线性，因为一般回报可正可负。即使当前样本回报都非负，也只有在目标按定义必为非负且已评估优化后果时，才适合把非负性作为输出约束。
  • 连续动作均值在 tanh 前不宜一开始就饱和；log_std 需限制到数值安全范围。全局 log_std 与状态依赖标准差表达能力不同，不能在加载权重时互换。
  • 观测标准化统计在训练采样阶段按约定更新，在评估/部署时冻结；恢复 checkpoint 时必须一并恢复。非对称 Critic 的特权输入通常需要独立统计，不能与 Actor 观测按位置混用。
  • 进入 Q-Critic 的动作应采用一致尺度。若环境动作区间差异很大，通常先用规范化动作训练 Actor/Q，再仅在环境边界做仿射映射。
  • 在纯粹“最大化期望折扣回报”、没有未缩放正则项或约束的前提下，把全部奖励乘同一正常数会保持策略排序，精确 \(V/Q/A\) 也同比缩放。但固定熵系数、代价惩罚、奖励裁剪、随时间变化的归一化或按回合长度加常数都会改变有效目标或权衡；不能把“正比例缩放不改最优策略”无条件外推到整个训练程序。

九、接口、形状与重算契约

class ActorCritic(nn.Module):
    def distribution(self, obs, action_mask=None): ...
    def value(self, obs, privileged=None): ...

    def act(self, obs, recurrent_state=None,
            action_mask=None, deterministic=False): ...

    def evaluate(self, obs, action, privileged=None,
                 recurrent_state=None, action_mask=None):
        dist = self.distribution(obs, action_mask)
        log_prob = reduce_event_dims(dist.log_prob(action))
        entropy = analytic_entropy_or_none(dist)
        value = self.value(obs, privileged)
        return log_prob, entropy, value

reduce_event_dims 与 analytic_entropy_or_none 是接口职责的伪代码，不是 PyTorch 内置方法。建议固定形状契约：action 为 [B, *A]，而 log_prob、entropy、V 与每个 Q 均为 [B]；不要依赖 [B,1] 与 [B] 的隐式广播。独立多维动作先对事件维求和，再对 batch 求均值。

act 面向环境交互，evaluate 对同一批已采样动作重算新策略 log-prob。PPO 还必须使用 rollout 保存的旧 log-prob 形成比率，不能用当前策略重算“旧值”。若使用 squashed distribution，旧/新两边必须采用同一变换与雅可比；最好保存足够的信息以避免在边界动作上不稳定地逆 tanh。tanh-squashed 分布的熵一般不等于基高斯熵，SAC 通常直接用样本的 \(-\log\pi(a\mid s)\) 处理熵项。

off-policy 实现即使把全部组件封装进一个 policy 对象，也应能明确枚举 actor、critic、target 与各自 optimizer 的参数归属，不能只靠名称推断。保存 checkpoint 时还应包括 target、optimizer、标准化统计和温度参数等完整训练状态；纯部署包才只保留 Actor 与必要预处理。

十、RNN 与批训练的额外不变量

RNN Actor-Critic 不能把普通的随机 transition minibatch 直接喂给循环网络。rollout 至少要保存每段序列的初始隐藏状态和 episode_start/reset mask；跨真终止或截断后的环境 reset 必须清零相应隐状态。采用截断反向传播时，要按连续时间片组 batch，padding 位置的 policy、value、entropy 损失全部乘有效位 mask。[T,B,...] 与 [B,T,...] 只要统一都可以，但展平前后必须用单元测试确认动作、旧 log-prob、优势与 hidden state 没有错位。

训练时常用 model.train()，评估时用 model.eval()；含 Dropout/BatchNorm 的网络若忽略模式切换，会让采样策略与重算 log-prob 的分布不一致。RL 中数据非独立同分布，BatchNorm running statistics 还可能随 replay/rollout 分布漂移，使用前需明确更新和冻结规则。

十一、设计检查表

  1. 分布 support 是否与每个动作维的真实边界一致，单边/无界维是否被错误 tanh？
  2. MultiDiscrete、MultiBinary 或对角高斯的独立性假设是否符合任务？
  3. 动作 mask 是否在采样、重算 log-prob 与 entropy 时完全一致，是否处理全非法情况？
  4. 多维动作的 log-prob 是否对事件维求和，最终张量是否严格为 [B]？
  5. tanh 与动作缩放的 log-Jacobian 是否都包含，符号和数值稳定式是否正确？
  6. Actor 更新时，优势/旧策略/target/Q 参数分别应该冻结还是反传？
  7. 共享参数是否被两个 optimizer 意外更新，target 参数是否与 online 参数别名共享？
  8. 双 Critic 是否为不同估计器，最小值的悲观偏差是否被正确理解？
  9. 训练、评估、部署是否使用同一观测归一化与动作变换？
  10. 非对称 Critic 的特权输入是否为动作前信息，Actor 是否完全不依赖它？
  11. RNN hidden state、episode-start mask、序列 padding 与 loss mask 是否同步？
  12. checkpoint 是否区分“可继续训练的完整状态”和“只用于推理的 Actor 包”？
