一、本页在专题中的位置

OpenVLA 的结构可以概括为：融合 DINOv2 与 SigLIP patch 特征的视觉编码器、把视觉特征映射到语言隐藏维的 projector，以及生成动作 token 的 Llama 2 7B。要复现发布模型，还必须明确每一路的 token 数与维度、取特征的层号、序列顺序，以及训练和推理时不同的张量路径。本页只讨论这些架构问题；动作量化、训练配方与部署分别在后续子页展开。

证据标记：「层一」表示论文明确陈述或实验；「层二」表示官方源码与发布 checkpoint；「层三」表示发布实现所支持的依赖库行为；标为「解释」的文字用于帮助理解，不等同于论文结论。本文涉及的框架行为均按发布实现明确接受的 timm 0.9.10 / 0.9.11 / 0.9.12 / 0.9.16 解读。
7.54B实测总参数量
256视觉 token 数（两路一致）
2176拼接后视觉特征维
4096语言主干隐藏维
倒数第二层两塔取特征的位置
3projector 的线性层数
本页的参数量与张量形状不是转述论文，也不是按规模名称估算，而是读取 Hugging Face 发布权重 openvla/openvla-7b 三个 safetensors 分片的张量头，按 shape 逐个累乘求和得到（层二）。它表示 checkpoint 中的张量元素数；实际前向是否使用、训练时是否更新，需要另行区分。

二、完整网络结构图、参数归属与各模块作用

OpenVLA 并不是从零设计的。它的准确表述是：

\[\text{Prismatic-7B VLM} \;\xrightarrow[\text{在 97 万条真实机器人轨迹上}]{\text{微调}}\; \text{OpenVLA}\]

Prismatic 系统比较了 CLIP、SigLIP、DINOv2 以及融合视觉表示等设计（层一）；OpenVLA 采用其中的 DINOv2 + SigLIP 方案。因此应先分清哪些结构继承自 Prismatic，哪些选择由 OpenVLA 的机器人训练验证。

设计 在 OpenVLA 中的性质
patch-as-token、多模态序列模板 继承自 Prismatic 及同类 VLM 路线，不是 OpenVLA 首创
DINOv2 + SigLIP 通道拼接 Prismatic 的视觉表示融合方案
融合分支的三层 projector 发布实现中的 Prismatic 结构
Llama 2 7B 因果语言主干 复用预训练语言模型
视觉塔在 VLA 训练中参与微调、选择 224 分辨率 OpenVLA 论文验证的训练选择
动作占用词表 token 并自回归生成 OpenVLA 的关键动作输出方案，详见子页 ②

三个部分的参数归属如下（层二实测）：

部分 模块 参数量 占比
视觉编码器 DINOv2 ViT-L/14（含 4 个 register） 303,230,976 4.0%
视觉编码器 SigLIP ViT-SO400M/14 @224 427,680,704 5.7%
视觉编码器 小计 730,911,680 9.7%
projector 三个线性层加两次 GELU 71,385,600 0.9%
语言主干 Llama 2 7B（32 层，含嵌入层与输出层） 6,738,939,904 89.4%
— 合计 7,541,237,184 100%
论文正文把 Prismatic 的视觉编码器概称为「600M 参数」（层一）；发布 checkpoint 中两座视觉塔的张量元素合计为 730.9M（层二）。两者统计口径和精度不同，不应混成一个精确数字。「7B」是沿用 Llama 2 7B 的名义规模类别；发布 checkpoint 的总张量元素数约为 7.54B。

语言主干约占 checkpoint 参数的 89.4%，因此它是权重存储、全量优化器状态和梯度内存的主要来源。不过，参数占比不能直接等同于推理耗时或功能占比：实际计算还取决于视觉 token 数、各层 FLOPs、KV cache、批量大小和硬件实现。LoRA 的可训练比例则由 rank 与目标层集合决定，不能由 89.4% 这一数字直接推出。

2.2 各模块的作用

下表是流程图的图例，集中列出模块规格、作用及改动时的约束。参数量与形状取自发布 checkpoint（层二）；“改动影响”一栏只写源码约束或已有证据，缺少消融时明确保留不确定性。后续各节分别解释输入融合、双视觉塔、层选择、projector、序列与位置机制。

模块 规格 参数量 在系统中的作用 去掉或替换的后果
图像预处理 两套独立变换，均为 resize-naive 直接拉伸到 224 0 按当前 OpenVLA/Prismatic checkpoint 的输入管线生成两路 224×224 张量，并分别使用各塔配置的插值与归一化 改用保持长宽比的缩放会偏离该 checkpoint 的微调与推理输入分布；两塔共用一套归一化参数同样错误
DINOv2 patch_embed Conv2d(3→1024, k=14, s=14) 603,136 把图像切成 16×16 共 256 个不重叠 patch，每个映射为 1024 维向量；这是 patch-as-token 的入口 增大 patch 会减少 token、牺牲空间粒度；减小 patch 会增加 token，并提高视觉塔和 LLM 的注意力计算量

三、OpenVLA 为什么采用 patch-as-token

patch-as-token 的做法是：把视觉 Transformer 的 patch 特征投影到 Llama 的隐藏维，然后与文本 embedding 拼成一条因果序列。对语言主干而言，视觉输入因此也表现为一组 4096 维 token。

\[X_{\mathrm{vision}}\in\mathbb{R}^{B\times N\times 2176} \;\xrightarrow{\text{projector}}\; Z_{\mathrm{vision}}\in\mathbb{R}^{B\times N\times 4096}.\]

这个选择的核心收益是尽量保留解码器式 LLM 的原始计算接口：训练仍可使用因果语言模型现有的数据并行、参数分片、混合精度、FlashAttention、梯度检查点和 KV cache。它不是所有 VLM 的唯一方案，也不能笼统说成“取代了”交叉注意力。

主序列拼接视觉 token 与文本共享 Llama 自注意力。实现简单，但视觉 token 会增加每一层 LLM 的上下文长度。
交叉注意力视觉 token 可保留在独立序列中，语言层通过新增 cross-attention 读取它们。原 LLM 权重仍可加载，但要增加模块、参数和训练逻辑。
两项独立选择patch-as-token 决定视觉输入如何接入；动作离散化与自回归逐维生成决定输出方式。前者并不必然要求后者。

若主序列长度为 \(S\)、隐藏维为 \(D\)，单层 Llama 的注意力项近似为 \(O(S^2D)\)，投影与前馈网络还包含 \(O(SD^2)\) 项。因此加入 256 个视觉 token 会增加计算，但不能只用“序列长度平方”精确预测端到端耗时。OpenVLA 的自回归延迟还来自动作被表示为多个输出 token；这部分属于动作建模选择，而不是 patch-as-token 的必然结果。

准确结论：patch-as-token 是 OpenVLA 复用预训练 LLM 与训练基础设施的重要前提之一；模型的能力与局限还同时受视觉表示、动作 token 化、训练数据、分辨率和解码方式影响。

四、双视觉编码器：训练目标、表征倾向与实验证据

Prismatic 将 DINOv2 与 SigLIP 的 patch 特征并列使用。两者的训练目标不同，因此表征具有互补倾向；这里讨论的是统计上的偏好，不是“语义塔只能识别、空间塔只能定位”的硬边界。

4.1 SigLIP：显式图文监督

SigLIP 对一个 batch 内的图文对分别做二元 sigmoid 判别。用 \(x_i\) 与 \(y_j\) 表示归一化后的图像和文本全局特征，\(z_{ij}=1\) 表示匹配、否则为 \(-1\)，其目标可概括为：

\[\mathcal{L}_{\mathrm{SigLIP}} = \frac{1}{B}\sum_{i=1}^{B}\sum_{j=1}^{B} \log\left(1+\exp\left[-z_{ij}\left(\tau x_i^\top y_j+b\right)\right]\right).\]

该目标显式奖励图文语义一致性，因此 SigLIP 表征通常更利于物体类别和语言相关属性的区分。不过，OpenVLA 读取的是中间 patch 特征，而不是 SigLIP 最终的图文匹配分数；这些 patch 特征也没有天然等同于 Llama 的词 embedding，仍需 projector 与后续 VLA 训练完成接口适配。

这里分母写 \(B\) 而不是 \(B^2\)，沿用 SigLIP 论文对一个 batch 总损失的归一化口径；它不表示只计算 \(B\) 个正样本，双重求和仍覆盖 batch 内的 \(B^2\) 个图文对。

4.2 DINOv2：纯视觉自监督

DINOv2 不使用文本，其训练包含图像级自蒸馏、iBOT 式 masked-image modeling 与 KoLeo 正则。其组成关系可概括为：

\[\mathcal{L}_{\mathrm{DINOv2}} = \lambda_{\mathrm{DINO}}\mathcal{L}_{\mathrm{DINO}} +\lambda_{\mathrm{iBOT}}\mathcal{L}_{\mathrm{iBOT}} +\lambda_{\mathrm{KoLeo}}\mathcal{L}_{\mathrm{KoLeo}}.\]

其中 DINO 项负责图像级自蒸馏，iBOT 项负责 masked patch 级目标，KoLeo 正则鼓励 batch 内特征分散；各项还包含教师—学生、温度与中心化等实现细节，上式只表示组成关系，不等价于逐项展开的完整训练公式。这些目标鼓励模型在不同视图和遮挡下学习稳定的图像级与 patch 级表征。实践中，DINOv2 常表现出较好的密集特征、边界和局部对应能力；但它没有显式的文本对齐，也不能据此声称它能直接给出度量深度、精确位姿或夹爪到物体的距离。

4.3 机器人任务为何可能受益

机器人策略既需要区分指令涉及的对象，也需要利用局部结构、遮挡和相对位置线索。SigLIP 与 DINOv2 的互补性为这两类需求提供了不同的预训练起点；真正的语言落地和动作条件关系仍由 projector、Llama 与机器人数据上的端到端训练共同学习。

论文附录的同口径消融比较了仅在 BridgeData V2 上训练的两个变体：

模型 视觉编码器 8 项任务平均成功率
OpenVLA-Bridge DINOv2 + SigLIP 45.6% ± 5.6%
OpenVLA-Bridge-SigLIP 仅 SigLIP 40.6% ± 5.5%

这个实验支持“加入 DINOv2 后均值提高约 5 个百分点”，但不支持“双编码器缺一不可”。它只覆盖 Bridge 单数据集、8 项任务，且差异明显小于移除 OpenX 数据带来的约 30 个百分点下降。另一方面，论文部分高效微调与量化实验使用 SigLIP 单编码器变体仍取得较强结果，也说明单塔方案可以工作。

应当区分三层结论：训练目标不同是事实；语义与局部结构的互补是有论文和既有表征研究支持的解释；每一路在具体动作决策中贡献多少，只能由同口径消融回答。

五、关键实现细节：读取倒数第二个 block

发布实现把两个视觉塔的 forward 替换为 get_intermediate_layers 调用（层二）：

self.featurizer.forward = unpack_tuple(
    partial(self.featurizer.get_intermediate_layers, n={len(self.featurizer.blocks) - 2})
)

源码注释里写得很清楚：默认让 get_intermediate_layers 返回倒数第二层的 patch 特征。也就是说：

事实 具体表现 来源
取的不是最后一层 DINOv2 有 24 个 block，取的是索引 22（即第 23 个）的输出；SigLIP 有 27 个 block，取的是索引 25 的输出 层二 + 层三
最终的 norm 层不参与 timm 的 get_intermediate_layers 默认 norm=False，两塔末尾的 LayerNorm 在这条前向路径上不被调用 层三
前缀 token 被剥掉 该接口默认 return_prefix_tokens=False，DINOv2 的 1 个 cls token 与 4 个 register token 都不会进入输出 层三
SigLIP 的池化头不参与 SigLIP 塔带一个约 1520 万参数的 attention pooling 头（attn_pool），它是为图文对比任务服务的，在这条前向路径上同样不被调用 层二

源码能证明“取了哪一层”，不能证明“为什么这一层最好”。 注释说明替换 forward 是为了 FSDP 兼容，并明确硬编码倒数第二个 block；官方材料没有给出最后一层与倒数第二层的同口径消融。一种常见解释是中间层可能保留更通用的局部特征，而最后若干组件更接近原预训练任务，但这只是解释，不应写成 OpenVLA 已验证的结论。尤其对 SigLIP，索引 25 的 block 输出还不是图文匹配分数，后面原本仍有最终 norm、attention pooling 和投影头。

这条对复现的实际影响：如果按论文正文的描述自己搭一遍，很自然会取最后一层输出、并且会保留 LayerNorm。这样做出来的模型加载官方权重时不会报错（形状完全对得上），但特征分布与官方实现不同，表现为「权重加载成功、推理结果不对」。凡是遇到这类症状，先核对取特征的层号与是否做了最终 norm。

视觉塔是否更新是另一项独立选择。OpenVLA 配置为 freeze_vision_backbone = False（层二），论文实验也认为在 VLA 训练中微调视觉编码器对良好性能很重要（层一）。这说明在论文评测设置下，允许视觉塔参数随 VLA 数据更新比保持冻结取得了更好性能；论文推测预训练特征可能缺少精细控制所需的空间信息，但相机域差异、优化耦合等可能机制并未被单独消融。完整训练策略对照见子页 ⑥。

六、通道维拼接：成立条件与替代方案

两塔各输出 256 个 patch 特征，融合方式是沿通道维拼接（层一、层二一致）：

return torch.cat([patches, patches_fused], dim=2)   # [B, 256, 1024] 与 [B, 256, 1152] 拼成 [B, 256, 2176]

之所以能这样做，前提是两塔的 patch 网格完全一致：两者都是 patch 14、输入 224，因此都恰好是 16×16 = 256 个 patch，同一个空间位置可以逐一对应。源码里对此有一行断言，直接要求两塔 num_patches 相等（层二）。

三种融合方式的前提与代价如下。后两种不是“失效”，而是需要不同的结构和训练假设：

方案 做法 前提与代价
通道维拼接（采用） 同一 patch 位置的两份特征在最后一维连接 两路 patch 网格必须一一对应；输入维从 1024/1152 增至 2176，计算交给 projector
逐元素相加 先把两路映射到相同维度，再逐元素相加 必须处理维度、尺度与基底不一致；求和会压缩两路信息，但不代表必然“互相抵消”
交叉注意力 保留独立视觉序列，由语言或融合模块查询 可以保留 patch 与位置；原 LLM 权重仍可加载，但需新增 cross-attention、参数和训练逻辑
拼接操作本身没有先对两路特征求和或降维；它把 2176 维输入交给 projector。第一层权重形状为 8704×2176，前 1024 列连接 DINOv2、后 1152 列连接 SigLIP，因此模型可以学习不同的组合方式。这里的“保留”只描述拼接这一操作，不保证经过后续网络后信息完全无损。

七、projector：发布实现包含三个 Linear

论文写的是“2 层 MLP projector”；发布 checkpoint 对应的融合分支实际执行三个 Linear 和两个 GELU，源码中的非融合 MLP 分支则是两个 Linear。二者存在表述与实现不一致；现有材料无法判定原因是论文简化、版本差异还是其他因素。复现发布 checkpoint 时应以融合分支的三个 Linear 为准。

层 形状 参数量 作用
fc1 2176 → 8704 18,948,608 映射到四倍视觉维的隐藏层
GELU — 0 非线性
fc2 8704 → 4096 35,655,680 映射到 Llama 隐藏维
GELU — 0 非线性
fc3 4096 → 4096 16,781,312 在目标维内继续变换
合计 — 71,385,600 与发布 checkpoint 一致

对每个 patch，projector 可写成：

\[Z = W_3\,\phi\!\left( W_2\,\phi(W_1X+b_1)+b_2 \right)+b_3,\]

其中 \(X\in\mathbb{R}^{2176}\)、\(Z\in\mathbb{R}^{4096}\)，\(\phi\) 为 GELU。几个需要分清的结论：

  • 形状对齐是必要的。 当前序列拼接要求视觉 token 与 Llama token 都是 4096 维；也可以设计其他接口，但不能把 2176 维张量直接拼到现有 4096 维 embedding 上。
  • 单层线性投影能够混合两路特征。 多层 MLP 的优势是增加非线性和中间容量，而不是“线性层无法对齐异构空间”。
  • 2176 → 4096 本身是升维。 先到 8704 再回到 4096 是更宽的隐藏层设计，不能解释为避免“直接降维丢失信息”。
  • 两个 GELU 不能忽略。 若全部移除，三个带 bias 的 Linear 可合并为一个仿射映射；加入激活后才具有更强的非线性表达能力。发布材料没有提供 projector 深度消融，因此不能声称三层一定最优。
初始化阶段必须分开说：从基础视觉塔和 Llama 构建 Prismatic VLM 时，projector 最初需要初始化并通过多模态数据学习接口；OpenVLA 的机器人训练则从已经预训练的 Prismatic-7B checkpoint 开始，此时 projector 不是随机权重。no-align+fused-gelu-mlp 表示 Prismatic 配方跳过单独的 projector-only 对齐阶段，采用融合 MLP 并端到端训练，不表示 OpenVLA 机器人微调重新随机初始化 projector。

八、序列拼装、因果可见性与标签

发布实现先查表得到文本 embedding，再把 256 个视觉 token 插入第一个输入 token 之后：

multimodal_embeddings = torch.cat(
    [input_embeddings[:, :1, :], projected_patch_embeddings, input_embeddings[:, 1:, :]],
    dim=1,
)

在标准提示模板中，第一个 token 是 <BOS>，因此训练序列可概括为：

flowchart LR
  A["&lt;BOS&gt;"] --> B["视觉 token<br/>256 个"]
  B --> C["提示文本 token"]
  C --> D["动作 token<br/>7 个"]
  D --> E["终止 token"]

Llama 使用因果掩码。对序列位置 \(i,j\)，可以写成：

\[M_{ij}= \begin{cases} 0,&j\le i,\\ -\infty,&j>i. \end{cases}\]

因此，排在视觉 token 之后的文本位置可以读取视觉上下文；末尾动作位置可以读取视觉、提示和已经出现的动作 token。若把视觉 token 放到文本之后，较早的文本隐状态确实不能读取图像，但末尾动作位置仍可能同时读取二者，所以不能说“顺序一改就绝对无法语言落地”。真正确定的是：改变顺序会改变训练模板、位置编号和中间表征，现有 checkpoint 不再对应原训练分布。

BOS 留在首位不是因为它能汇聚后文。在因果掩码下，首位 BOS 不能看到后续 token。保留它的理由是遵循 Llama 与 Prismatic 使用的序列起始约定，避免改变预训练和多模态训练时的模板。

标签构造也分两步：

  1. modeling_prismatic.py 为新增的 256 个视觉位置创建 IGNORE_INDEX=-100，这些位置不产生交叉熵损失。
  2. 提示文本是否计入损失由上游数据管线提供的 labels 决定；OpenVLA 训练会屏蔽非动作监督位置。仅看到视觉位置被设为 -100，还不足以单独推出“只在动作 token 上计算损失”。

九、两类位置机制：ViT 绝对位置与 Llama RoPE

OpenVLA 同时使用视觉塔内部的二维 patch 位置嵌入，以及 Llama 注意力中的一维 RoPE。它们作用在不同位置，不能理解为给视觉 token 连续“相加两次位置向量”。

层级 位置 形式 作用范围
patch 位置 两个视觉塔内部，各自一份 可学习绝对位置嵌入；DINOv2 为 [1,256,1024]，SigLIP 为 [1,256,1152] 各自的 16×16 patch 网格
序列位置 Llama 每层自注意力 RoPE：按一维 token 位置旋转 Q、K BOS、视觉、文本和动作组成的整条序列

对位置 \(i,j\) 的 query 和 key，RoPE 可写成：

\[q_i'=R(i)q_i,\qquad k_j'=R(j)k_j,\] \[{q_i'}^\top k_j' = q_i^\top R(i)^\top R(j)k_j = q_i^\top R(j-i)k_j.\]

所以 RoPE 不是把位置向量加到 embedding 上，而是让注意力分数感知 Q、K 的相对位置。进入 Llama 后，256 个视觉 token 按固定 raster 顺序占据连续的一维位置；其二维网格关系已经由视觉塔位置嵌入和视觉特征编码。Llama 没有额外的显式二维 RoPE，但可以利用固定的一维排列及特征内容学习空间关系。

DINOv2 的 pos_embed 为 [1,256,1024] 而不是 [1,261,1024]，与 no_embed_class=True 一致（层三）：位置嵌入只加到 256 个 patch；cls 与 4 个 register 随后作为前缀 token 加入。它们虽在输出端被移除，但在视觉 Transformer 内部会与 patch 发生注意力交互。

十、完整张量形状：公共视觉路径、训练与推理

先定义：\(B\) 为 batch size，\(L_p\) 为包含 BOS 的提示 token 数，\(L_a\) 为监督输出长度。官方默认训练管线令 \(L_a=8\)：7 个动作 token 加 1 个停止 token（EOS）；只有关闭 predict_stop_token 时，EOS 标签才会被置为 -100。发布 HF 推理接口只支持 batch size 1，并把新 token 数上限设为动作维数（通常是 7），不以 EOS 作为必需的动作解码步骤。

10.2 训练前向

训练时，7 个动作 token 与 EOS 已经位于 teacher-forcing 输入/标签序列中，而不是在同一次前向后再逐步解码：

操作 形状
文本侧输入（提示、动作与终止 token）查表 [B,L_p+L_a,4096]
在 BOS 后插入视觉 token [B,L_p+L_a+256,4096]
Llama 隐状态 [B,L_p+L_a+256,4096]
lm_head logits [B,L_p+L_a+256,32064]

视觉和非监督提示位置以 -100 屏蔽；交叉熵只在保留标签的位置计算。

10.3 自回归推理

推理先进行一次 prefill：

\[S_0=L_p+256,\]

对发布 HF 实现，这里 \(B=1\)：prefill 输入为 [1,S_0,4096]，logits 为 [1,S_0,32064]。随后生成动作 token 时使用 KV cache，每一步通常只输入新 token 的 [1,1] id/embedding，缓存上下文长度从 \(S_0\) 逐步增长。官方部署关闭采样，并把 max_new_tokens 设为动作维数；这是生成上限，若生成框架遇到已配置的终止条件也可能提前结束。它与训练时一次完成动作 token 与 EOS 监督的 teacher-forcing 前向是两条不同路径。

还要区分“训练使用的动作 token 集合”和“生成时的硬约束”：训练把 256 个动作值编码到 id 31744–31999，但 lm_head 仍对 32064 个输出行给出 logits，generate 没有动作词表 mask。正常预测应落在动作 token 区间；若模型生成了其他 id，predict_action 仍会执行 32000-id、减一和裁剪，再索引分箱中心。因此“越界 id 被映射”为容错行为，不应误解为生成阶段保证只会产生合法动作 token。

需要额外注意：

  • 权重矩阵宽度为 32064，而 tokenizer 的基础词表边界与动作反量化使用 32000；完整 id 变换见子页 ②。
  • embed_tokens.weight 与 lm_head.weight 均为 [32064,4096]，是两份独立权重。
  • 256 是当前 224×224、patch 14 配置下的视觉 token 数；换分辨率还需要相应的视觉模型/位置嵌入与处理器配置，不能只把 384 图像直接传给现有 224 发布接口。

十一、图像预处理：同一图像，两套独立变换

DINOv2 与 SigLIP 接收同一张 RGB 图像，但各自使用与预训练相匹配的归一化统计。发布配置采用 image_resize_strategy="resize-naive"，把输入直接调整为 224×224，不保持长宽比。

需要区分两个官方接口：

接口 预处理输出 视觉主干读取方式
OpenVLA/Prismatic 训练仓库 {"dino": [B,3,224,224], "siglip": [B,3,224,224]} 两座塔分别读取字典中的张量
Hugging Face 发布模型 [B,6,224,224] 沿通道切成两个 [B,3,224,224]

两种接口的数学含义相同：同一图像经过两套变换，再分别进入两座视觉塔。复现时应注意：

  • 归一化不能共用。 DINOv2 使用其 ImageNet 风格统计，SigLIP 使用自身的 0.5 均值与标准差；混用会改变输入分布。
  • resize-naive 是直接拉伸。 它保留完整视野，但会改变长宽比例。源码还支持 resize-crop 和 letterbox，不能把某一种策略说成普遍最优。
  • 修正 SigLIP 默认裁剪是实现事实。 代码替换默认 transform 的首个 Resize，避免默认的放大后裁剪路径；“边缘目标对机器人很重要”是合理动机，但论文没有单独消融裁剪内容与几何失真的贡献。
复现原则：训练和推理必须使用与 checkpoint 相同的尺寸、插值、归一化和通道/字典组织。保持长宽比在一般视觉任务中可能更合理，但直接替换会造成输入分布变化，应重新验证或微调。

十二、分辨率消融：实际 patch 数与计算量

论文比较分别按 224×224 与 384×384 构建的模型配置，并报告 384 在其评测中没有带来性能提升、训练时间约为 3 倍，因此最终采用 224（层一）。下文的 729 个 patch 指 384 配置的视觉塔输出，不是让现有 224 processor 接收一张 384 图像后的结果。

项 224×224 384×384
评测表现 基准 论文报告无明显差异
训练时间 基准 约 3 倍（端到端实测）
最终模型 采用 不采用

对 Conv2d(kernel=P,stride=P,padding=0)，每个方向的输出 patch 数为：

\[N(H,W,P) = \left\lfloor\frac{H-P}{P}+1\right\rfloor \left\lfloor\frac{W-P}{P}+1\right\rfloor = \left\lfloor\frac{H}{P}\right\rfloor \left\lfloor\frac{W}{P}\right\rfloor .\]

当 \(P=14\) 时：

\[N_{224}=16^2=256,\qquad N_{384}=27^2=729,\]

所以实际 token 数比例是 \(729/256\approx2.85\)，不是 \((384/224)^2\approx2.94\)。后者只是连续像素面积比，忽略了卷积网格取整。

计算量也不能由 2.85 直接等同为 3 倍。对序列长度 \(N\)、宽度 \(d\) 的 Transformer block，粗略包含：

\[O(N^2d)+O(Nd^2),\]

前者是注意力，后者来自 QKV/输出投影和 MLP。视觉塔与 Llama 主序列都会受更多 patch 影响，而数据处理、通信和硬件 kernel 又带来额外常数。因此：

  • “384 约慢 3 倍”是论文在特定设置下的端到端实测；
  • “注意力含二次项”解释增长方向；
  • 不能从单一 \(N^2\) 项精确推导整体训练时间，否则会错误得到接近 8 倍的直觉。
论文同时指出：更高分辨率常能改善 VLM 基准，但在当时的 VLA 评测中未观察到该趋势。论文没有验证唯一原因。可能的任务敏感度差异只能作为后续假设，不能写成已经证实的机制。可落实的工程结论是：不要把 VLM 上的分辨率收益直接外推到 VLA；应在目标相机、任务和延迟预算上重新评测。

十三、与 π0、X-VLA 的架构对照

下面只比较高层结构。不同论文对“主干参数”“总参数”和“激活参数”的统计口径不同，数字不能直接用于判断能力或速度；更可靠的是比较视觉接口与动作输出方式。

项 OpenVLA π0 X-VLA
视觉语言基座 Prismatic：DINOv2 + SigLIP + Llama 2 PaliGemma 系列基座 裁剪后的 Florence-2 Large
视觉表示 两座视觉塔，同位置 patch 通道拼接 单一视觉编码器，token 数随图像与相机数变化 DaViT 视觉编码器，多视角共享
动作模块 基线没有新增可学习动作头；复用词表 lm_head 独立动作专家 动作 Transformer 与本体 Soft Prompt
动作输出 离散 token，按维自回归生成 连续动作块，flow matching 连续/结构化动作表示，详见 X-VLA 子页
关键代价 7B 级 LLM 与串行动作 token 带来较高延迟 新增专家与连续生成计算 更小基座，但需要跨本体接口设计

真正值得对照的是三种设计哲学：

  1. OpenVLA：最大化复用。 视觉 token 接入原 LLM 序列，动作也复用词表和语言输出头；实现统一，但动作生成串行。
  2. π0：分离语义与动作生成。 视觉语言基座提供条件，动作专家负责连续动作块。
  3. X-VLA：强调跨本体接口。 更小的视觉语言基座配合动作模块与 soft prompt，显式处理不同机器人本体。

这些差异说明“是否新增动作模块”与“主干多大”是两条独立设计轴，不能仅按参数量排序能力。对照阅读：π0 网络架构、X-VLA 网络架构与 token 组织。

十四、易误解点与准确表述

易误解说法 准确表述 依据
“OpenVLA 精确等于 7B 参数” 7B 是名义规模类别；发布 checkpoint 含约 7.541B 个张量元素 层二
“视觉编码器就是精确的 600M” 论文作 600M 级概述；发布 checkpoint 两塔合计约 730.9M，且含当前路径不用的尾部参数 层一 / 层二
“projector 是 2 层” 论文高层描述为 2 层 MLP；发布融合分支实际执行 3 个 Linear + 2 个 GELU 层一 / 层二
“线性层无法对齐异构特征” 线性投影可以对齐和混合；多层 MLP 增加的是非线性与容量 数学性质
“取视觉塔最后一层” 取索引 22/25，即各自倒数第二个 block，且不调用最终 norm 层二 / 层三
“cls/register 被丢弃所以没作用” 它们参与 DINOv2 block 内部注意力，只在输出端被移除 层二 / 层三
“视觉 token 在 BOS 前面” 发布实现把视觉 token 插在 BOS 后、其余输入 token 前 层二
“BOS 汇聚整条序列” 因果掩码下 BOS 看不到后文；保留首位是为了匹配既有模板 因果掩码
“RoPE 再给 embedding 加一个位置向量” RoPE 在每层注意力中按位置旋转 Q/K，不直接加到输入 embedding Llama / RoPE
“patch-as-token 导致动作必须离散化” 输入融合与动作输出是独立选择；可以保留 patch-as-token 并改用连续动作头 架构逻辑
“HF 与训练仓库都输入 6 通道张量” HF 发布模型使用 6 通道；训练仓库使用 dino/siglip 两路字典 层二
“384 会产生约 750 个 patch” patch 14、无 padding 时为 27×27=729 卷积形状公式
“双视觉塔缺一不可” Bridge 消融均值提高约 5 点，但单 SigLIP 变体仍可工作 层一
“提高分辨率总会更好” 论文在其 VLA 评测中未见收益，并实测训练约慢 3 倍 层一
