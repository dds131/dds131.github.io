二、训练期的三个反常现象

2.1 更多数据反而更差：−14.6 个百分点

现象（层一，论文 Table 1）：在 Simpler-WidowX 上，不做预训练但用了定制学习率的基线是 39.6；加上在 290K 个异构 episodes 上的预训练之后，反而掉到 25.0。

子页 ① 第 2.1 节给出了混合分布的数学形式：当不同域的条件均值发生冲突时，共享预测一般不能同时对每个域最优。本节列出四类可能造成冲突的异构性，以及 X-VLA 对应采用的处理手段；这些对应关系是机制解释，不是逐项因果消融。

这条现象不能简单解释成「预训练无效」。同一张 Table 1 中，分组动作对齐、意图抽象与均衡采样是成组加入的，之后成功率回到 50.0；再加入编码流水线与 Soft Prompt 后达到 73.8，最终配置达到 95.8。它说明异构预训练需要显式处理数据口径与条件差异，但这是一条累积消融路径：无法据此分离四种因素各自的贡献，也不能证明每一项都不可替代。上面的四层对应关系应理解为机制解释，而不是论文完成了逐项因果验证。

2.2 验证误差是粗粒度代理，不是下游模型选择器

现象（层一，Table 1）：论文作者把预训练验证误差称为与下游成功率呈强相关的代理指标。整体路径确有这种趋势：误差从 0.11 降到 0.032，同时成功率从 25.0 升到 95.8；但表内至少有两处说明它既不单调，也不能替代下游闭环评测。

对照 验证误差 下游成功率 能说明什么
分组对齐等组合 → 标准 encoder 0.077 → 0.071 50.0 → 47.9 误差改善时成功率反而下降
规模扩展 → 两阶段适配 0.032 → 0.032 89.6 → 95.8 同一预训练结果因下游适配方案而异

原因边界。 该验证集由留出的 AGIBOT-beta 数据构成，共 189 个任务、每个任务 3 条轨迹，指标是预测轨迹与真值轨迹之间的平均 \(\ell_1\) 距离；下游结果则是在 Simpler-WidowX 适配后的闭环任务成功率。两者之间有两道差异：

  1. 不同的数据分布。验证集来自 AGIBOT，评测环境是 WidowX——前者降误差不必然转化为后者提升。
  2. 不同的度量语义。\(\ell_1\) 是连续的平均偏差，成功率是离散的任务级结果。一条轨迹平均误差更小，仍可能在关键时刻偏离并导致任务失败。

因而准确说法是：论文作者观察到总体相关趋势，但没有报告相关系数；Table 1 本身已经给出非单调反例。

对使用者的含义：可用该误差排除明显失败的预训练配置或监控预训练是否异常，但不能把它当作目标机器人的最终检查点选择器，更不能脱离下游验证直接制定早停规则。

2.3 更「先进」的结构反而更差

现象（层一，Table 4，预训练验证误差，越低越好）：这组对照属于 Appendix I 的预备实验设置，使用 Florence-Base、12 层且隐藏维 768 的主干；不能把数值直接外推为最终 0.9B、24 层模型的严格架构消融。

MM-DiT 是专门为多模态设计的、比朴素 DiT 更「讲究」的结构，结果却比它差近一倍。论文给的解释是：这类设计虽然试图缩小模态之间的语义鸿沟，但常常让训练不稳定。

这些结果只支持一个有范围的结论：在论文的数据混合、训练规模与超参数下，共享的标准 Transformer 配合条件输入取得了最低验证误差。它不能证明所有动态路由、专家结构或样本相关分支普遍无效；π0 风格结构的 0.056 实际也优于基础 DiT 的 0.077。Soft Prompt 不改变共享主干的参数布局，但会改变注意力激活，模型还包含域相关动作编码器与解码器。因此「把条件作为序列输入」适合作为本论文的经验性设计启示，而不是架构定律。

三、推理期的七个反直觉现象

以下七条以源码行为为起点，并明确区分可直接核对的实现事实、数学解释与尚待实验验证的假说。

3.1 干净动作估计从全零起步、第一步输入是纯噪声，为什么输出不是乱动

源码事实：generate_actions 先令 action = torch.zeros_like(x1)；第一次迭代 \(t=1\) 时，\(x_t=x_1\) 是纯高斯噪声。这里的“无信息”只针对动作输入，不代表整次前向没有条件信息。

同一次前向还包含：

  • 主视角与语言融合后的条件 token；
  • 辅助视角槽产生的视觉 token 与 Soft Prompt；无效槽内容会被置零，但槽位仍保留；
  • 广播到每个动作位置的本体状态与时间嵌入

总 token 数取决于文本长度、配置中的视角槽数、视觉 token 数和提示长度，不能固定写成“30/262”。训练构造为 \(x_t=t\epsilon+(1-t)a\)。若噪声 \(\epsilon\) 与干净动作 \(a\) 在给定条件 \(c\) 后独立，则在精确边界 \(t=1\) 有 \(x_1=\epsilon\)，动作输入本身不再携带 \(a\) 的信息。

若把同一生成过程扩展到 \(t=1\)，再对使用平方误差的连续动作分量求 Bayes 回归解，则在无限数据、充分容量并达到总体风险最优的理想条件下，

\[f^*(x_1,1,c)=\mathbb E[a\mid \epsilon,c]=\mathbb E[a\mid c].\]

这解释了“纯噪声输入”不等于“随机乱动”：条件观测、指令与状态仍能决定一个条件均值。但训练只覆盖 \(t<1\) 且可任意接近 1，并未在精确 \(t=1\) 施加该约束；有限网络还可能利用噪声产生不同输出。若条件动作分布多峰，均值甚至可能是不可执行的“折中动作”，后续递推只能被理解为模型迭代修正，不能据此保证收敛到某个真实模态。

夹爪等 BCE 分量不适用“动作均值”结论。若二值标签为 \(g\in{0,1}\)，并沿用前述条件独立假设 \(g\perp\epsilon\mid c\)，则

\[p=\Pr(g=1\mid x_1,c)=\Pr(g=1\mid c).\]

当 \(0<p<1\) 时，BCEWithLogitsLoss 的总体最优输出是 logit：

\[f_g^*(x_1,1,c)=\log\frac{p}{1-p},\qquad \sigma\!\left(f_g^*(x_1,1,c)\right)=p.\]

它不是连续夹爪控制量的条件均值；只有标签语义确为伯努利事件且模型校准良好时，后处理后的 sigmoid 分数才可解释为概率。

含义：第一步可理解为以观测、指令和状态为主的初始动作估计。特别地，steps=1 时 \(t_1=1\)，于是

\[x^{(1)}=\epsilon,\qquad a^{(1)}=f_\theta(\epsilon,1,c),\]

初值 \(a^{(0)}=0\) 被系数 \(1-t_1=0\) 完全消去；这不是从零动作逐步修正一次，而是在纯噪声上只预测一次。代码能够运行不代表精度只会“略差”，论文没有报告一步推理结果。

3.2 同一个观测两次推理，结果一样吗

源码事实：每次调用都会执行 x1 = torch.randn(...)，因此默认情况下两次输出可能不同。

边界：初始噪声是实现中主要的显式随机源；固定输入、权重与 x1，并启用确定性算子时，递推应复现相同结果。但 GPU 非确定算子仍可能带来微小差异，所以不能把全部差异无条件归因于 x1。

想要可复现在调用前固定随机种子，或直接改代码把 x1 做成可传入的参数。
想要比较固定同一个 x1 再比较步数或模型，避免把随机输入差异混入结论。
证据边界不同噪声得到不同动作，只说明模型定义了噪声驱动的随机映射；尚未证明这些输出是对真实条件动作分布的校准采样，也不能仅凭差异断言存在多峰。

3.3 训练覆盖的时刻与推理求值的时刻不重合

这一差异来自训练与推理源码的时间点定义。

训练侧：令 \(P=1-10^{-5}\)、\(u\sim\mathcal U[0,1)\)，批内第 \(b\) 个样本使用

\[t_b=\left(u+\frac{b}{B}\right)\bmod P,\qquad b=0,\ldots,B-1.\]

所以取值落在 \([0,P)\)，能够靠近 0；但同一批的 \(B\) 个时刻共享同一个 \(u\)，彼此强相关，不能称为“每个样本独立抖动”。更准确的说法是随机循环平移的近等距栅格。另外，随机偏移在长度为 1 的区间采样，而模数是略小于 1 的 \(P\)，故边缘存在 \(10^{-5}\) 量级的非均匀性；它通常可忽略，但实现并非严格的独立均匀采样。

推理侧：for i in range(steps, 0, -1) 里 t = i / steps，取值是

\[\left\{\, 1,\ \frac{steps-1}{steps},\ \dots,\ \frac{1}{steps} \,\right\}\]

最小值是 \(1/steps\)，永远取不到 0。 以 steps=10 为例，最小是 0.1。

含义有三点：

  • 推理首步查询精确的 \(t=1\)，训练却只采样到 \(1-10^{-5}\) 以下。 两者非常接近，但不完全相同；首步行为依赖边界泛化。
  • 推理不会直接查询 \(t<1/K\)。 这不等于这些训练样本“完全无用”：它们仍可能改善时间条件化的插值、正则化和接近数据端的预测。
  • 增大 steps 会令最小时间点更接近 0，同时改变整条递推。 steps=100 时最小是 0.01，但论文没有给出步数消融，不能由时间点覆盖直接推出收益必然递减或单调收敛。

3.4 改 steps 需要重训吗，10 步是否已被证明足够

改步数不要求重训，但它不是在同一条路径上加密采样。 令步数为 \(K\)、固定初始噪声为 \(\epsilon\)、上一步干净动作估计为 \(a^{(j-1)}\)。为突出时间网格，下面暂时省略每轮的 action_mode 预处理 \(P_m\) 与末端后处理 \(Q_m\)；包含二者的完整公式见子页 ⑥。递推主体可写成：

\[\epsilon\sim\mathcal N(0,I),\qquad a^{(0)}=0,\] \[t_j=\frac{K-j+1}{K},\qquad x^{(j)}=t_j\epsilon+(1-t_j)a^{(j-1)},\qquad a^{(j)}=f_\theta(x^{(j)},t_j,c).\]

这里的 \((1-t_j)a^{(j-1)}\) 是上一轮模型估计，不是“真实动作成分”；网络末轮输出还需经过 \(Q_m\) 才是服务返回值。改变 \(K\) 会同时改变全部时间点、每步输入和预测反馈链，所以会得到一条新的递推状态序列；论文也没有证明它对应某个固定 ODE 轨迹或随步数单调收敛。

  • 在固定 commit 的 17 个官方评测客户端入口中，16 个请求体显式发送 "steps": 10；RoboTwin 客户端省略该字段并继承服务端默认值 10。因此“10 步”是发布代码的一致工程默认值，不等于论文通过步数消融证明了“10 步最优”或“10 步已经足够”。
  • 比较不同步数时，应固定观测与同一份 \(\epsilon\)，同时记录任务成功率、动作误差、延迟和输出变化；仅比较单个动作块是否接近不能替代闭环评测。
建议做固定噪声的 steps ∈ {1, 2, 5, 10, 20, 50} 扫描，并允许结果非单调。这个实验方案是本页建议，不是论文已经完成的实验。

3.5 哪部分只算一次，哪部分会随步数重复

源码事实：forward_vlm 位于循环外，视觉—语言条件通常只编码一次；动作 Transformer 位于循环内，会执行 \(K\) 次。因此增加步数不会把整个模型等比例重复，但一定会增加动作主干计算。

公开论文与仓库没有提供两部分的 FLOPs、峰值显存或端到端延迟，不能断言“10 次动作主干比一次观测编码便宜”。参数量、层数和 token 数也不足以替代实测。

部分 单次请求执行次数 可以确认的结论
VLM 条件编码 1 次 其输出供各次动作迭代复用
动作 Transformer \(K\) 次 成本随步数增加；序列长度依赖文本长度、配置的视角槽数、提示长度和动作块长度；无效辅助视角是零特征槽，不会从序列中删除
普通自回归模型的 KV cache 不能直接套用到这里：动作主干进行联合的双向自注意力，条件 token 的中间状态可能随动作 token 改变。只有在重新设计注意力依赖、并验证数值等价或可接受误差后，才可讨论跨步缓存。正确的性能结论应来自同一硬件上的预热后延迟、显存和吞吐量测量。

3.6 domain_id 合法不等于语义正确

源码事实：当 domain_id 的整数类型、批形状、设备以及其他输入都兼容时，\(0\leq\text{domain\_id}<\text{num\_domains}\) 只保证查表不越界，不保证它与当前数据或平台语义匹配。若配置启用 use_hetero_proj，该 ID 还会选择域专属视觉投影；公开 X-VLA-Pt 配置中该开关为 false。

domain_id 用于选择 soft_prompt_hub、action_encoder 和 action_decoder。公开检查点配置的 num_domains=30，所以该检查点的合法索引是 0–29；这不是所有 X-VLA 配置永久固定的范围。

训练数据路径先执行严格的 get_handler_cls(robot_type)：若 robot_type 未注册，会在这里抛出 KeyError；只有名称已注册为数据处理器、但遗漏于 DATA_DOMAIN_ID 时，后续 DATA_DOMAIN_ID.get(robot_type, 0) 才会静默回退到 0。两套查表不是任选其一，执行顺序也不同；因此“未报错”仍不能证明域 ID 配置正确。

语义边界：域 ID 更接近数据来源或动作域条件，不保证与机器人一一对应；多个名称可以共享 ID，配置存在的槽位也不代表都经过充分训练。错误的合法 ID 可能选择另一个已训练域，也可能落入缺乏训练的槽位，不能一概描述为“换了一台机器”。

排查方法：同时记录 robot_type、解析后的 domain_id、检查点 num_domains 与动作空间，并与训练数据映射表核对。

3.7 部分动作模式为什么返回连续夹爪分数

适用范围：在 ee6d 和 joint 等使用夹爪 BCE 的动作空间中，网络输出 logit，训练用 BCEWithLogitsLoss 以数值稳定的方式合并 sigmoid 与 BCE；推理 postprocess 将 logit 映射到 \([0,1]\)，但不负责二值化。agibot_ee6d、auto 等模式不能直接套用这一结论，必须分别查看对应 action space。

该值更准确地称为 sigmoid 分数。只有当训练目标符合伯努利编码、模型达到相应风险最优且经过概率校准时，才适合把它解释为校准概率。控制器最终使用 0/1 还是 \(\{-1,+1\}\)，属于标签编码和部署映射问题，不能与网络输出混为一谈。

二值化阈值、极性和控制量映射由客户端决定。官方客户端存在多种阈值和极性约定，因此迁移到新平台时应使用本平台数据重新校验，不能照搬另一个任务的阈值。

输入屏蔽同样要按动作模式限定。 ee6d、joint 的预处理会清零相应的夹爪动作与本体夹爪通道；因此这些模式不能直接从该数值通道读取当前开合状态，但仍可能从当前图像及其他未屏蔽条件间接获得线索。官方模型前向本身没有观测历史输入。

四、实验数据里的反常：RoboTwin 的逐任务分布

论文 Table 16 给出 RoboTwin-2.0 全部 50 个任务在 Easy 与 Hard 两档下的成功率（层一）。汇总平均是 70.0 与 39.0；逐任务表同时显示明显的任务间差异，其中 4 项 Hard 严格高于 Easy，另有 1 项持平。

4.1 五个任务的 Hard 不低于 Easy

「Hard」档的设定应当比「Easy」更难，但有五个任务不是：

任务 Easy Hard 差值
Put Object Cabinet 78.0 82.0 +4.0
Handover Block 27.0 30.0 +3.0
Shake Horizontally 99.0 100.0 +1.0
Put Bottles Dustbin 0.00 1.00 +1.0
Shake Bottle 99.0 99.0 0.0

RoboTwin 公共评测协议规定每个任务、每种条件 100 次 rollout；X-VLA 的 Table 16 附近没有再次说明次数与是否配对。以下计算以该实验遵循公共协议、两组近似独立为条件，差值的标准误为

\[\operatorname{SE}(\hat p_H-\hat p_E)=\sqrt{\frac{\hat p_E(1-\hat p_E)}{n_E}+\frac{\hat p_H(1-\hat p_H)}{n_H}}.\]

代入 78% 对 82%，描述性的 Wald \(z\) 值约为 \(0.71\)，相应未合并 Wald 95% 区间约为 \([-7.1,15.1]\) 个百分点；代入 27% 对 30%，约为 \(0.47\)，区间约为 \([-9.5,15.5]\) 个百分点。这只是采用样本比例代入、假设两组独立的数量级判断，不是预先设定的正式假设检验；两项差异都与有限采样波动相容。对 0%/1% 和 99%/100% 这类边界比例，Wald 正态近似不稳；差值区间宜使用 Newcombe/Wilson score 方法，若要检验则应先明确原假设并选用 Fisher 精确检验等方法。若 Easy/Hard 复用了配对种子，还需要逐 rollout 的联合结果，并改用 McNemar 检验或相应的配对区间。

因此，表中只有 4 项是严格的描述性反转，另 1 项是持平；它们都不能据此断言 Hard 更容易。若要做机制解释，应确认评测协议，报告区间、种子和预先定义的统计标准；论文没有讨论这些非下降项。

这个数字值得单独指出，是因为它对「平均 70%」这个汇总量提供了必要的语境：70% 的平均之下，既有 Click Bell、Handover Mic、Place Cans Plasticbox 这样 100% 的任务，也有一个 0% 的任务。引用「RoboTwin-2.0 上 70%」时，如果读者据此推断「任意一个 RoboTwin 任务大概有七成把握」，就会被这个分布误导。论文没有讨论这个任务为何完全失败，本页也不推测。

五、论文自陈的局限（Appendix N）

论文在 Appendix N 用三段讨论了自身局限。这一节是理解 X-VLA 边界最直接的材料，逐条转述（层一）：

一、规模仍然有限0.9B 相对视觉语言与语言领域的基础模型仍属小规模，论文归因于算力约束与高质量机器人数据的稀缺。并指出即使已尽力整理开源数据集，当前机器人语料的多样性与规模仍远不及语言与视觉语言领域。
二、监督信号信息量不足低维动作标签本质上信息量有限——它们对直接控制是必要的，但只能刻画任务结构的很窄一面，往往无法传达更高层的推理、意图或多步依赖。论文明确说：简单的时间降采样只是部分缓解了这个问题，并没有从根本上丰富监督。
三、仍然依赖本体专属适配要真正做到「对任意下游任务免工程免重训即插即用」仍是开放挑战。当前部署仍需为每个本体采集少量演示做后训练；这在演示数据稀缺、昂贵或采集有风险的平台上会成为问题。
第三条尤其要注意：论文自己明确说明部署仍依赖本体专属适配，不是即插即用。这与子页 ① 第 6.3 节的结论一致——论文没有做过 zero-shot 新本体实验。因此不能把“zero-shot 新本体”宣传成论文已经验证的现有能力；论文只把 zero/few-shot 视为未来可能。若进一步声称当前模型无需工程与重训即可即插即用，则与 Appendix N 的自陈局限直接冲突。

论文给出的三个未来方向：扩大模型与数据规模并研究 VLA 的扩展律；引入更丰富的监督信号（三维空间推理线索、物理动力学、中间子目标标注，或从原始输入流做自监督）；探索统一的本体表示（通用运动学描述符、物理先验等 embodiment-agnostic 抽象）以降低对专属适配的依赖。原文末句使用 task-specific adaptation，但整段上下文主要讨论的是 embodiment/domain-specific adaptation；三者不应在其他语境中无条件视为同义。

另有一类局限论文放在 Appendix E，即两次失败尝试（异构 LoRA 与专家混合的路由坍缩），已在子页 ① 第八节展开，本页不重复。

  • Soft Prompt 之间的插值。论文完全没有做过在两个数据源的 prompt 之间插值、检验插值点是否对应某种「中间本体」的实验。
  • 四种异构处理方案的精确数值表。论文 Fig. 4 给出曲线而非表格；若从图中数字化估读，必须标注数字化方法和读图误差，不能伪装成论文直接报告的精确数值。
  • x0-prediction 与速度场参数化的对照实验。两者的数学差别可推导（子页 ③ 第六节），但哪个更好论文与仓库都没测过。
  • 验证误差与成功率的相关系数。论文只用了定性的 strong correlation，没有报告任何 r 值。
  • 真机 WidowX 五个任务的表格化逐任务成功率。Fig. 7 可能在图形中编码数值，但正文没有提供可直接复制的逐任务数据表；若读图使用，需注明估读方式。
  • 各模块的参数量拆分。论文只给 0.9B 总量与非共享参数占 0.04%。
  • 推理延迟的实测数字。论文与仓库都没有给。
引用任何具体数字前，应先问：它来自论文表格、图形估读、某个 commit 的源码、某个 checkpoint revision，还是第三方集成？只有来源、版本和适用范围同时明确，数字才可复核。
