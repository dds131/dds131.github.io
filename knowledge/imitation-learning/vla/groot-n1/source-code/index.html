仓库拓扑与推荐读码图

六个责任域是 gr00t/model、gr00t/data、gr00t/experiment、gr00t/eval、scripts 与动态说明 getting_started。目录顺序不是调用顺序；动态说明也不作为固定实现证据。推荐先确认发布 config/metadata 和 DataConfig/transform，再依次读 Policy、顶层模型、backbone、动作头/DiT、runner/trainer、service/eval。

flowchart LR
  C[release config + metadata] --> D[DataConfig + transforms]
  D --> P[Gr00tPolicy]
  P --> M[GR00T_N1]
  M --> B[EagleBackbone]
  B --> A[Flow head + DiT]
  A --> T[runner + trainer]
  A --> S[service + offline eval]

文本回退：release config/metadata → DataConfig/transforms → Gr00tPolicy → GR00T_N1 → EagleBackbone → Flow head/DiT → runner/trainer 或 service/offline eval。

GR00T_N1 装配 EagleBackbone 与 FlowmatchingActionHead。训练 forward 和推理 get_action 共用 prepare_input → backbone 前缀与 validate_data 尾部，但动作头入口不同。prepare_input 将浮点叶子转为动作头 dtype，整数和布尔只搬设备，保留索引/mask 语义。裸模型与 Policy 的职责不能混写，train/eval 的数值也不保证相同。

训练主调用链

dataset sample
  -> DataConfig transform pipeline
  -> model-ready BatchFeature
  -> GR00T_N1.forward
  -> EagleBackbone.forward once
  -> FlowmatchingActionHead.forward
  -> noise / tau / interpolation / target
  -> state + action tokens -> DiT -> decoder
  -> last H action positions
  -> masked elementwise MSE / valid-scalar count
  -> Trainer optimizer groups
  -> checkpoint callback -> runner final save

入口、编排器和优化器职责分别属于 scripts/gr00t_finetune.py、gr00t/experiment/runner.py 与 gr00t/experiment/trainer.py。每个训练 batch 的主干调用一次；动作头采样噪声与时间、构造目标，并以全 batch 有效动作标量为分母归约 masked MSE。checkpoint callback 位于 gr00t/utils/experiment.py，final save 归 runner。公共微调链并不代表论文完整预训练管线已经公开。

Flow 训练目标与归约

固定实现使用 noise ~ N(0,I)、U ~ Beta(1.5,1)、tau=(0.999-U)/0.999，并构造 x_tau=(1-tau)noise+tau*actions，目标为 actions-noise。state token 在前、16 个 action token 在后；位置嵌入只加到 action token，decoder 先处理全部 17 个 token，再取末 16 个动作输出。

action_mask 只乘最终逐元素 MSE，分母是全 batch 有效标量总数；零有效分母没有防护。该静态事实与正向 Euler 的符号自洽，但不能解释论文打印式差异的成因或经验影响。

推理主调用链

raw flat observation dict
  -> Gr00tPolicy batch detection
  -> forward transforms + metadata binding
  -> GR00T_N1.get_action
  -> EagleBackbone.forward once
  -> FlowmatchingActionHead.get_action: K Euler steps
  -> normalized action_pred [B,16,32]
  -> reverse transforms / unnormalize / ordered-field split
  -> physical action dict

公开入口是 Gr00tPolicy.get_action。包装层负责 batch 检测、metadata 注入、正向和逆向 transform；主干每个 action chunk 只算一次，动作编码/DiT/decoder 运行 K 次。归一化的 action_pred [B,16,32] 不是可直接执行的机器人命令，公开代码也没有动作块队列或重规划 consumer。

K 步 Euler 路径

动作头从 [B,16,32] 标准高斯开始，dt=1/K；第 j 步使用 tau=j/K 和 bucket int(1000j/K)，更新 actions += dt*pred_velocity。VL embeddings、state features 与 position IDs 在循环外；action encoder、DiT 与 action decoder 在循环内。循环不重新采样，没有 corrector/guidance，源码也不验证 K>0。

发布配置记录 num_inference_timesteps=16，论文实验叙述包含 K=4；静态页面只登记差异，不给质量或延迟排序。

Eagle、Flow 与交替 DiT 的静态裁决

Eagle 截断与 VL 接口

发布配置 select_layer=12。固定 EagleBackbone 将 lm_head 换为 Identity，持续 pop(-1) 直到从 24 个语言块物理保留 12 个，再读取截断模型的 hidden_states[-1]；不是运行全部24层后旁路读取中间层。视觉侧由 224/14 得 256 patch token，经 ratio 0.5 pixel shuffle 得 64 token、4倍通道即 4608，再经 mlp1 到 2048；混合 chat 隐状态通过 2048→1536 投影送入 DiT。

十六块 DiT 与 mask 调用链

发布 config 为 16 层且 interleave_self_attention=true：偶数索引 0–14 的 8 个块读取 1536 维 VL 条件，奇数索引 1–15 的 8 个块在 17 个 state/action token 上自注意力。它是块间交替，各块有独立 Attention 参数；时间同时进入 action encoder、每块 adaLN 与最终输出调制。

训练入口虽接收 encoder_attention_mask，但 DiT 调 block 时显式传 None，block 内对应转发也被注释；推理不传。可静态确认“固定调用链未使用该 mask”，但影响量保持 unknown，不能把它直接定性为已证实的性能缺陷。

本体边界、数据 schema 与 transform 合同

CategorySpecificLinear 通过 W[cat_ids] 与 b[cat_ids] 为每个样本选择完整矩阵和偏置，不是共享矩阵外接轻量 adapter。专属边界只包围 state encoder、action encoder 与 action decoder；VLM、backbone projection 与 DiT 共享。max_num_embodiments=32 来自 dataclass 默认，发布 config 未显式给出；公开映射 gr1→24、new_embodiment→31 不是论文预训练本体全集，也不能证明槽31加载时重置或支持零样本新本体。

基础数据以 parquet 承载状态/动作/元数据，以 MP4 或 PNG 序列承载视觉，以 JSON 承载统计与索引。N1 增加 meta/modality.json、逐字段区间、多标注类型和旋转表示声明。44维 GR‑1 例子只展示语义分段，不是默认策略29维状态合同；DataConfig 决定字段选择、转换和最终顺序。

正向链为 video → state/action field transform → concat → model transform，得到 state64、action32、horizon16 容器及 mask/embodiment selector；逆向链负责拆字段和反归一化。metadata 用 embodiment tag 选择 statistics，但不保存完整 DataConfig 名、完整 transform pipeline 或 ordered fields，因此外部绑定不可省略。

固定 DATA_CONFIG_MAP 的七个公共入口为：gr1_arms_waist、gr1_arms_only、gr1_full_upper_body、bimanual_panda_gripper、bimanual_panda_hand、single_panda_gripper、so100。registry 不是预训练本体全集，各配置也不保证字段顺序相同。

微调入口、Policy、服务与发布制品

公共微调与保存链

scripts/gr00t_finetune.py 的公共默认值是每设备 batch16、10,000 steps、LR 1e-4、weight decay 1e-5、warmup ratio 0.05、cosine 与 bf16。默认 tune_llm=false、tune_visual=true、tune_projector=true、tune_diffusion_model=true。tune_projector 实际控制动作头边界层与位置嵌入，不控制 Eagle 的 2048→1536 projection；后者没有独立开关。

optimizer 分 non-backbone/backbone 两组；LoRA 发布必须成对绑定 base model 与 adapter。runner 保存 model/config/metadata，但 metadata 不是完整发布合同，公共微调入口也不能冒充论文完整预训练配方。

Policy 与研究服务边界

Gr00tPolicy 负责 checkpoint resolution、model/transform eval、metadata injection、batch normalization、整链 inference_mode、autocast、inverse transform 与单 batch 移除。裸模型不加载 metadata、不反归一化；动作头的 no_grad 也不覆盖进入动作头之前的 backbone。包装器接受 cpu 参数，但 autocast 写死 CUDA，因此固定包装路径不能宣称无需修改即可 CPU 端到端运行。

研究服务是串行 ZeroMQ REQ/REP，端点只有 ping、kill、get_action、get_modality_config；没有认证、授权、传输加密、worker pool、batcher、backpressure 或结构化错误。torch.load(weights_only=False) 不适合不可信 payload，timeout 参数未施加到 socket。scripts/eval_policy.py 只计算离线 trajectory MSE，不执行机器人闭环。

发布/部署合同至少绑定：model或adapter权重、model config与base revision、processor cfg、source commit、DataConfig、transform version、metadata hash、有序state/action schema、normalization与embodiment binding、load parity结果。缺字段表示复现合同不完整，不等于权重已损坏。

静态风险、Claim ledger 与 R0–R7

十项固定风险只描述实现缺口与待验证事项，不虚构事故、不估计概率，也不建立严重度排名：

  1. VL mask 未进入固定 DiT 调用链；
  2. state mask 未被动作头消费；
  3. action mask 只屏蔽 loss，不能阻止无效输入参与前向耦合；
  4. temporal padding mask 缺失；
  5. 零有效 loss 分母无防护；
  6. 语言输入键合同不一致；
  7. K 未验证为正数；
  8. CPU 参数与 CUDA autocast 不一致；
  9. ZeroMQ 研究服务无认证且有不可信反序列化风险；
  10. release metadata 不构成完整复现合同。
