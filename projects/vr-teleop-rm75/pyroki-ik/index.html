PyRoki 逆解器：从目标位姿到七轴关节解

RM75 VR 遥操作中 PyRoki 逆运动学的目标函数、约束、求解流程、异步接入、使用方法与故障诊断

← 项目主页 ·系统架构 ·PyRoki 逆解器 ·数据采集与保存 ·工程问题记录

PyRoki 在本项目里承担一个边界清楚的任务：把经过坐标映射、离合重定位和输入低通后的末端目标位姿，转换成 RM75-B 的一组七轴关节角候选解。它不是厂商控制器的替代品，也不直接向电机发命令。

输入：1 个 SE(3) 位姿目标位置 + 目标姿态
变量：7 个关节角RM75-B 七自由度配置
输出：单帧关节目标不是带时间戳的完整轨迹
7.8–8.3 ms三次预热后的单次热解，非稳定分布
先分清两层：PyRoki 负责“这一帧末端目标对应哪组关节角”；其后的 EMA、144 °/s 限速、软限位刹车、目标刹车和 1000 °/s² 限加速度负责“怎样把这组关节角安全地送到真机”。两层不能混写成一个算法。

一、为什么七自由度机械臂需要优化式逆解

正运动学是已知关节角 $\mathbf q\in\mathbb R^7$，计算末端位姿：

\[\mathbf T(\mathbf q)=FK(\mathbf q)\in SE(3).\]

逆运动学则反过来：给定目标位姿 $\mathbf T^{\ast}$，寻找满足 $FK(\mathbf q)\approx\mathbf T^{\ast}$ 的 $\mathbf q$。末端位姿有 6 个自由度，而 RM75-B 有 7 个关节，所以同一个末端位姿通常可能对应多组肘部姿态；目标不可达、接近奇异位形或靠近自碰撞区域时，也可能没有满足全部条件的精确解。

因此本项目不是只解等式 $FK(\mathbf q)=\mathbf T^*$，而是把“末端要准、关节要连续、姿态不要偏离 home、不能越关节限位、不要自碰撞”组合成一个带约束的非线性最小二乘问题。可用下面的结构式理解：

\[\mathbf q_k^*=\arg\min_{\mathbf q} w_p\lVert\mathbf e_p(\mathbf q)\rVert^2+ w_R\lVert\mathbf e_R(\mathbf q)\rVert^2+ w_c\lVert\mathbf q-\mathbf q_{k-1}\rVert^2+ w_h\lVert\mathbf q-\mathbf q_{home}\rVert^2+ w_s\,\Phi_{self}(\mathbf q),\] \[\text{s.t.}\quad \mathbf q_{min}\le\mathbf q\le\mathbf q_{max}, \qquad d_{self}(\mathbf q)\ge m_{hard}.\]

这里的 $w_p,w_R,w_c,w_h,w_s$ 只表示各项相对权重，不是本页杜撰的一组配置值；项目运行时应以实际版本中的 config_pyroki.py 和求解器构造代码为准。

位姿误差不是“欧拉角直接相减”

PyRoki 用刚体变换群 $SE(3)$ 表示末端位姿。先由当前关节角做正运动学，再求当前位姿与目标位姿之间的相对变换，最后通过对数映射得到 6 维残差：

\[\mathbf e(\mathbf q)= \operatorname{Log}\!\left(\mathbf T(\mathbf q)^{-1}\mathbf T^*\right) =\begin{bmatrix}\mathbf e_p\\\mathbf e_R\end{bmatrix}.\]

$\mathbf e_p$ 表示平移误差，$\mathbf e_R$ 表示最短旋转误差。这样处理能尊重三维旋转的几何结构，避免欧拉角在 $\pm\pi$ 附近跳变，也允许位置与姿态使用不同权重。

二、目标函数和约束分别在做什么

项目 类型 逻辑 在本项目中的作用
末端位置误差 软代价 缩小 $\lVert\mathbf e_p\rVert$ 让夹爪尖端到达手柄给出的目标位置
末端姿态误差 软代价 缩小 $\lVert\mathbf e_R\rVert$ 让夹爪方向跟随手柄，而不是只跟位置
贴近上一帧 软代价 缩小 $\lVert\mathbf q-\mathbf q_{k-1}\rVert$ 在多解中优先选连续解，抑制肘部换支
偏向 home 软代价 缩小 $\lVert\mathbf q-\mathbf q_{home}\rVert$ 为七自由度冗余提供稳定偏好，减少怪异折叠姿态
自碰撞软代价 软代价，裕量 0.03 m 连杆距离进入 3 cm 缓冲区后逐渐增大惩罚 提前把优化方向推离危险区域
关节上下限 硬可行条件 $q_i^{min}\le q_i\le q_i^{max}$ 防止求解器给出超出机械结构范围的关节角
自碰撞硬约束 硬可行条件，裕量 0.01 m 候选解必须保留至少 1 cm 的模型间距 不接受“末端很准但机械臂过于贴近自身”的解
求解后安全门 独立复核，阈值 0.002 m 对求解结果重新计算最小距离，不通过就不下发 捕获数值误差或接口异常结果

软代价和硬约束不是重复设置。3 cm 软区负责提前引导，允许求解器在末端精度、连续性和避碰之间平滑权衡；1 cm 硬约束负责定义不可跨越的可行边界；2 mm 安全门是求解器外的最后复核，阈值更小是为了减少误拦，不能反过来替代前两层。

PyRoki 官方工具也支持环境碰撞、可操作度、轨迹平滑等通用代价，但本页只把已有项目证据能确认的配置写成“本项目实际启用”。不能因为库里存在某项能力，就默认本项目已经使用。

三、一次求解内部怎样运行

1 · 建模从 URDF 建立关节树、正运动学、关节限位和项目碰撞模型。
2 · 组装目标把滤波后的目标位置、四元数和 0.195 m TCP 偏置统一到基座坐标系。
3 · 计算残差由候选关节角做 FK，得到位姿、连续性、home 与碰撞残差。
4 · LM 迭代利用 JAX 得到雅可比，求阻尼最小二乘增量并更新七轴关节角。
5 · 约束收紧关节限位和硬碰撞条件参与迭代，直到满足容差或停止条件。
6 · 外部复核检查数值、关节边界和最小碰撞距离，再写入最新结果缓存。

Levenberg–Marquardt 为什么适合这个问题

把所有软项拼成残差向量 $\mathbf r(\mathbf q)$，在当前迭代点线性化：

\[\mathbf r(\mathbf q+\Delta\mathbf q) \approx\mathbf r(\mathbf q)+\mathbf J\Delta\mathbf q.\]

LM 的典型更新可写为：

\[(\mathbf J^\mathsf T\mathbf J+\lambda\mathbf I)\Delta\mathbf q =-\mathbf J^\mathsf T\mathbf r.\]

$\lambda$ 大时更接近保守的梯度下降，变小时更接近 Gauss–Newton。它比直接求解析闭式解更容易加入连续性、home 和碰撞项；JAX 则负责把同一套正运动学和残差编译、求导并在支持的 CPU/GPU/TPU 后端上执行。

JIT 预热与“热解”

JAX 首次看到一组固定形状的输入时会编译计算图，所以必须在进入控制回路前预热。当前能从恢复运行控制台逐条复核到三次启动记录：

历史运行 JIT 编译 随后一次热解
20260820_041841_recovery_pick_cube 4.74 s 7.8 ms
20260820_044507_recovery_pick_cube_grip 4.80 s 8.3 ms
20260820_050415_recovery_pick_cube 4.69 s 7.8 ms

这三条记录只能说明该三次启动的预热范围为 4.69–4.80 s、紧随预热的一次热解为 7.8–8.3 ms；它们不是稳定控制期的耗时分布。旧项目文档还记录过 16.4 s 编译、20.3 ms 热解和约 25 ms 单次求解，说明版本、硬件或编译缓存状态会显著改变结果。运行时仍要保持目标数量、碰撞对象数量和数组形状固定，避免再次编译。

PyRoki 的单帧 IK 是局部非线性优化，不是全局采样规划器。它不能保证找到所有可能解，也不能仅凭“两个端点都无碰撞”证明两帧之间的连续扫掠路径无碰撞。调参和真机安全不能只看末端误差。

四、它怎样接进 110 Hz 遥操作循环

110 Hz 主循环的理论周期只有 9.09 ms。即使只采用上表较新的 7.8–8.3 ms 单次热解记录，IK 本身也已经占去约 86%–91% 的周期预算，还没有计算 VR 读取、安全滤波与通信；旧文档记录的 20–90 ms 更会直接超期。因此项目采用“主循环 + 单独 IK worker + 最新结果缓存”：

VR 最新位姿 → 坐标映射/离合/输入低通 → 提交目标给 PyRoki worker
PyRoki worker → 求解并写入最新关节目标缓存
110 Hz 主循环 → 读取最新且有效的关节目标 → 后级安全滤波 → CAN-FD 下发
时序问题 实际策略 结果
新目标来得比求解快 worker 独立求解，主循环不等待且只消费最新完成结果 避免 IK 阻塞 110 Hz 时钟
新解尚未完成 继续保持最近一组有效关节目标 对异步 IK 输出做零阶保持，不虚构未来解
松握把或回位后恢复 若相邻两次 solve() 调用间隔超过 0.1 s，使残留异步结果失效 旧解不能在重新接管时抢先下发
新解突然变化 交给 IK 后级 EMA、限速、两类刹车与限加速度 把几何可行目标整形成真机可执行指令

这也解释了为什么页面不能写成“PyRoki 以 110 Hz 求解”：110 Hz 是控制与下发时钟，不是 IK worker 的完成频率。 主循环以 110 Hz 消费缓存，求解器按自己的耗时异步更新缓存。

五、项目中怎样启用

正式链路只使用 teleop_pub.py + record_collector.py。项目使用说明明确标注：其他旧入口缺少后续上层修复，不能因为它们名字里也有 pyroki 就当成等价启动方式。

D="/path/to/ruierman_robot"
PY="/path/to/rm75_vr_pyroki/bin/python"

cd "$D/data_collection"
"$PY" teleop_pub.py --tcp-len 0.195 \
  --source vr --backend canfd --rate 110 --follow \
  --safety pyroki --scale 1.5 --traj-mode 2 --radio 500 \
  --ema 0.25 --input-lp 0.3 \
  --max-accel 1000 --homing-accel 400 --homing-speed 25 \
  --no-viz --no-log
参数 处在链路哪里 作用
--tcp-len 0.195 IK 建模前 把法兰到夹爪尖端的 0.195 m 偏置纳入目标
--source vr 目标来源 使用真实 VR 位姿；离线验证才改用不占 VR SDK 的 mock 输入
--backend canfd 输出后端 把安全链批准的目标送入 CAN-FD；验证时可改成 dryrun，只计算不驱动真机
--rate 110 主循环与下发时钟 周期约 9.09 ms；它是消费最新 IK 结果的频率，不是 PyRoki 完成频率
--follow 控制器模式 启用 RM75 高跟随位置透传，因此发送连续性和上层平滑成为硬约束
--safety pyroki IK 与安全路径选择 启用 PyRoki 约束逆解及对应的关节安全链
--scale 1.5 IK 目标生成前 放大 VR 平移增量；越大越易触发不可达、限速或拒解
--traj-mode 2 控制器端 选择滤波模式；0 为透传、1 为曲线拟合、2 为滤波
--radio 500 控制器端 模式 2 的滤波强度，允许 0–999；增大更平滑，也会增加跟随滞后
--input-lp 0.3 IK 之前 当前输入权重为 0.3，压掉手柄位姿高频抖动，防止噪声经非线性 IK 放大
--ema 0.25 IK 之后 当前目标权重为 0.25；平滑关节目标，但不改变 PyRoki 内部代价函数
--max-accel 1000 IK 之后 限制关节指令帧间速度变化，单位 °/s²
--homing-speed 25 独立回位规划 回位速度上限 25 °/s，不改变正常遥操作限速
--homing-accel 400 独立回位规划 回位加速度上限 400 °/s²，不复用遥操作的 1000 °/s²
--no-viz 运行时 关闭逐帧可视化，把实时预算留给控制；不是关闭 IK
--no-log 运行时 关闭高列数逐帧 CSV；需要诊断发送断流时再单独启用发送间隔记录

项目已有不连机械臂、不占用 VR 的综合干跑脚本：

cd "$D/data_collection"
"$PY" tests/smoke_dryrun_all.py --verbose

它适合验证入口链能否启动和退出，但不能单独证明 URDF、TCP、自碰撞几何和真机方向全部正确；真机前仍需做下一节的分层验证。

六、从零接入时的正确顺序

  1. 固定模型契约。 核对 URDF 版本、七个关节名称与顺序、弧度/角度单位、末端 link、机械限位和 TCP 长度。
  2. 只验证 FK。 用真机多组关节角做正运动学对拍，先证明“同一组 $\mathbf q$ 得到同一个末端位姿”。本项目记录的基座系位置差均值与标准差均小于 $10^{-6}$ m，旋转角差 0.0011°。
  3. 做静态 IK 对拍。 从当前实测关节角附近求解一批可达目标，再用 FK 回代，分别统计位置误差、旋转误差、关节限位和最小自碰撞距离。
  4. 验证冗余连续性。 让目标沿小圆或直线缓慢移动，观察肘部是否突然换支；有跳变先检查上一帧连续性项和 home 偏置，不要先靠加大后级 EMA 掩盖。
  5. 验证不可达与拒解。 主动给出工作空间外、接近关节限位和接近自碰撞的目标，确认系统保持上一有效解，而不是输出 NaN 或任意大关节角。
  6. 完成 JIT 预热。 在不连真机或 dryrun 下触发一次完整求解，确认正式接管时不会再经历首次编译停顿。
  7. 最后接异步和真机。 检查结果有效性、solve() 间隔门控、滤波器重置和发送间隔，再从低速、小比例开始。

项目现有交叉验证还包括：PyRoki 与厂商逆解的关节角最大差 5.04°、均值 1.45°，但末端一致；七自由度冗余臂出现不同肘部解是允许的，不能把“关节角不完全相同”直接判成逆解错误。真机首解与实测关节角差为 0.012°。

七、怎样调权重才不互相打架

顺序 先观察什么 调整方向 常见误区
1 FK、坐标系、TCP 是否正确 修模型和单位，不调优化权重 用权重补偿坐标轴或 TCP 错误
2 位置/姿态回代误差 平衡位置与姿态权重 姿态权重过大时牺牲位置，或反之
3 肘部是否连续、是否远离怪异折叠 调上一帧连续性与 home 偏置 只加 EMA，让几何解仍在内部换支
4 最小自碰撞距离与误拦率 在离线覆盖测试后调软/硬裕量 为了少拒解直接把硬裕量降到危险值
5 单解耗时和是否重编译 固定输入形状、预热、关闭实时可视化 把 JIT 首次编译时间当成稳定求解耗时
6 真机速度、加速度和发送间隔 调 IK 后级滤波与动力学约束 把抖动或抱闸全部归因给 IK 权重

调参必须同时保存末端误差、关节变化量、最小碰撞距离、求解耗时、拒解率和发送间隔。只看“手感更顺”会把连续性、延迟和安全裕量之间的交换隐藏掉。

八、常见故障怎样定位

现象 优先检查 为什么
目标不动或频繁拒解 目标是否可达、TCP、坐标系、硬碰撞/关节约束 约束问题不能靠后级滤波修复
肘部突然翻转 上一帧参考、home 偏置、是否误取陈旧解 这是七自由度多解选择问题
第一次接管卡很久 JIT 是否预热、运行时形状是否变化 首次编译与重复重编译都会制造长停顿
末端总差固定距离 TCP 长度、末端 link、单位 固定偏差通常是模型契约错误，不是 LM 没收敛
方向或姿态反了 基座映射、四元数 xyzw/wxyz 顺序、最短弧处理 分量顺序错仍可能得到看似合法的旋转
求解正确但真机抖 VR 输入噪声、IK 后 EMA、CAN-FD 控制器参数 几何目标正确不代表时间序列可直接执行
靠近身体时频繁停住 记录软/硬/安全门三层最小距离 先定位是哪一层拒绝，不能盲目一起降低阈值
松手或回位后重新接管跳变 solve() 间隔门控、结果有效性、滤波器零速度重置 陈旧解和滤波器状态都可能造成首帧跳变

最有效的排查方式是沿接口切开：若 FK(q_solution) 已经不匹配目标，问题在 IK 或模型；若它匹配目标但 q_command 与 q_solution 差异异常，问题在后级安全滤波；若下发命令正常但真机回读异常，再检查通信、控制器模式和机械臂状态。

九、能力边界与延伸阅读

本项目使用的是 PyRoki 的单目标、单配置 IK能力。PyRoki 工具库本身还能表达轨迹优化、多目标、世界碰撞和可操作度等问题，但这些能力不会因为安装了库就自动出现在当前遥操作链路里。

  • PyRoki 论文：模块化变量与代价、LM 求解骨架、碰撞残差和实验边界。
  • 本项目 · 系统架构与控制链路：坐标映射、异步 worker、陈旧解门控和 IK 后安全链。
  • 本项目 · 工程问题记录：旧解、限加速度逃逸、自碰撞阈值和真机抱闸的完整取证过程。

一句话收束：PyRoki 给出“几何上更合适的一组七轴关节角”；异步门控和后级安全链决定“这组角能不能在此刻、以什么速度交给真机”。
