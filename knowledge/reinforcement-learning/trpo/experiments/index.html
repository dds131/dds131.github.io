这一页不把不同年代、不同环境版本和不同实现的分数拼成排行榜，而是回答三个更可靠的问题：原论文的实验实际证明了什么；现代复现为什么会得到不同结果；当训练曲线出现反常现象时，应检查哪一层因果链。

证据层次：2015 原论文任务与图表 → 2016 独立基准 → 官方现代实现基准 → 2020 实现细节与梯度质量研究 → 现象—原因—指标—处置诊断矩阵
2015 年论文的模拟器、状态定义、奖励函数和终止条件不同于今天的 Gymnasium MuJoCo v3、v4 或 v5；现代实现还加入 GAE、神经 Critic、归一化和不同网络。除非实验协议完全一致，本页只在同一表格或同一来源内部比较，不把跨来源绝对分数当作算法排名。

一、原论文实验要回答的三个问题

论文第 8 节围绕三组问题设计实验：

  1. single path 与 vine 两种采样方案各有什么效果与代价；
  2. 每步固定 KL 预算是否比自然梯度使用固定惩罚系数，以及 CEM、CMA 等黑盒搜索更稳健；
  3. 矩阵自由的二阶方法能否扩展到更大策略和复杂控制任务。

三、Figure 4 应怎样解读

论文比较了 Vine TRPO、Single Path TRPO、Natural Gradient、Max KL（仅 cart-pole）、Empirical FIM、CEM 与 CMA；曲线是五次随机初始化的平均。

论文在该实验范围内支持以下结论：

  • single path 与 vine TRPO 在四个问题上都找到了最好的一组解；
  • 自然策略梯度在两个较简单问题上表现良好，但没学出向前推进的 Hopper 与 Walker 步态；
  • 固定 KL 约束比固定 penalty 或固定步长更稳健；
  • max KL 在 cart-pole 上学得稍慢，平均 KL 的经验效果相近；
  • CEM 与 CMA 在较大问题上表现较差；
  • empirical FIM 与解析 Fisher 的策略改进速率相近；论文采用解析 Fisher 的主要理由是动作积分后的计算与存储更方便。

但不能由图中推出：

  • vine 在所有任务、所有阶段都严格优于 single path；
  • TRPO 每次策略更新都单调提高真实回报；
  • 平均 KL 与最大 KL 在数学上等价；
  • 2015 年任务上的领先会无条件迁移到现代环境版本。

3.1 “站稳但不前进”不是曲线读错

Figure 4 图注明确指出，Hopper 与 Walker 的某个平台分数可以通过平衡站立、没有前进速度来达到。这揭示了总回报的组合结构：

  • 存活或姿态稳定项往往先被优化；
  • “不摔倒”是局部容易策略；
  • 向前行走需要多关节周期协调；
  • 总回报平台可能对应一个有能力但非目标行为的局部解。

诊断时应同时记录前进速度、位移、存活奖励、控制代价、episode length，并观看轨迹。仅凭总回报无法区分“什么都没学会”和“学会站立但没学会走”。

四、single path 与 vine：方差、能力边界与现代选择

采样方式 核心做法 优势 限制
Single path 从旧策略采整条轨迹，用沿轨迹未来折扣奖励估计 (Q) 不要求恢复历史状态，可用于真实系统；流程简单 同一状态只观察到一个动作结果，局部比较方差较高
Vine 先采轨迹并选状态；每个状态从 proposal 分布采多个动作，各自 rollout 在同一状态比较动作，能降低局部 (Q) 差异的方差；可用公共随机数 需要把仿真器恢复到任意历史状态，仿真调用多，真实系统通常不可用

连续任务的 vine proposal 取当前策略效果好；Atari 中论文使用均匀动作 proposal，有时能带来更多探索。本站核对的主流现代实现均采用 single-path / rollout-buffer 路线，没有实现论文 vine。

Vine 不是“更高级的 TRPO”，而是一种需要仿真器状态恢复能力的估计方案。现代实现选择 single path，主要是通用性与系统成本取舍，不表示理论部分发生改变。

六、现代独立基准：不能与 2015 分数直接拼接

6.1 Duan et al. 2016

《Benchmarking Deep Reinforcement Learning for Continuous Control》指出当时连续控制缺少统一任务和评估协议，系统比较多种实现并公开 rllab 参考代码。它的重要性在于推动共同基准和可复现性；仅凭摘要不足以给 TRPO 编造精确名次，本页不补写未经核验的排名。

6.2 Spinning Up benchmark

官方 benchmark 使用 MuJoCo v3 的 HalfCheetah、Hopper、Walker2d、Swimmer 与 Ant：

  • 每个实验训练 3M steps；
  • 每项 10 个随机种子；
  • on-policy 网络为两层 64、32 单元 Tanh；
  • 每批 4,000 环境步；
  • TensorFlow 曲线包含 TRPO，PyTorch 曲线不含 TRPO。

这里的 on-policy 指标是每个 epoch 采样批中轨迹回报的平均，不是另开无噪声评估 episode；曲线还做了 11 个 epoch 的滑动平均。基准网络 64、32 是该 benchmark 的配置覆盖，不是前页所列 Spinning Up TRPO 函数的 64、64 默认值。

官方同时提醒：其 VPG、TRPO、PPO 整体弱于文献中最佳实现，缺少 observation normalization、normalized value regression targets 等常见技巧；研究对比更建议使用 Baselines。这个说明本身就是实验结论的一部分：算法名相同，数据预处理与代码路径不同，结果可以显著变化。

七、实现细节为什么会改变“算法结论”

Engstrom 等的案例研究显示，看似次要的 code-level optimizations 会显著改变深度策略梯度行为；在其 PPO/TRPO 研究范围内，这些优化解释了 PPO 相对 TRPO 的大部分累计回报差异。

可能改变结果的因素包括：

  • observation normalization；
  • reward scaling 或 clipping；
  • value target normalization；
  • 网络初始化与激活；
  • advantage normalization；
  • action clipping 或 squash；
  • 时间限制的 bootstrap；
  • Critic 训练轮数与小批量方式；
  • Actor/Critic 参数共享；
  • KL 方向、阻尼和线搜索接受谓词。
这是一项案例研究的范围内结论，不等于“PPO 的全部优势都来自代码技巧”。正确表述是：若代码级优化没有受控，算法对比会把实现差异误归因给目标函数。

八、样本替代目标为什么可能骗过我们

Ilyas 等对深度策略梯度做更细致测量，发现实践行为常偏离理论动机：

  • 样本 surrogate objective 可能与真实回报地形不一致；
  • 学到的 value estimator 可能不能很好代表真实价值；
  • 估计梯度与更精确参考梯度的相关性可能很低。

这解释了三个容易误读的现象：

  1. 线搜索在本批样本上通过，下一轮真实回报仍可能下降；
  2. KL 合格只能限制步长，不能修正错误的 advantage 或梯度方向；
  3. 把 CG 解得更精确，不一定改善一个本来就偏差很大的 (g)。
TRPO 控制的是“沿估计方向走多远”，不是“保证估计方向一定正确”。求解器、优势估计与环境评估必须分别诊断。

九、七类反常现象的因果诊断

9.1 实际 KL 经常远小于 (\delta)

可能原因：

  • KL 二次模型在该方向高估真实曲率；
  • 若满步按阻尼二次型定标，低曲率方向可能相对原始 KL 更保守；
  • CG 提前停止；
  • 线搜索发生回退；
  • 在把 FVP 子批与验收全批分开的实现中，两者状态分布不同。

应同时记录 full-step predicted KL、full-step actual KL、accepted KL 和 accepted fraction。这样才能区分“满步本来就保守”与“回退后才变小”。

9.2 线搜索几乎从不回退

这不一定异常。Spinning Up 说明线搜索通常无需回退，发生时也常只退一步；小 (\delta)、局部二次近似、阻尼与 CG 截断都可能让满步保守。

但若训练全程一次都不回退，应做三项反证检查：

  • 把 candidate 写入前后比较参数向量；
  • 用非对称新旧分布验证 KL 不恒为零；
  • 人为放大 full step，确认 KL 与拒绝逻辑会响应。

9.3 频繁线搜索失败

失败类别 常见原因 优先动作
KL 超限 曲率低估、FVP 子采样噪声、阻尼太小、target KL 太大 核对 KL 与分母；增加阻尼或减少子采样
目标不改善 advantage 噪声、符号反转、ratio 方向错、局部模型失真 在 toy objective 核对符号；增大策略批
非有限 standard deviation 崩溃、ratio overflow、HVP 数值问题 恢复旧策略；检查 log std、梯度和曲率
predicted improvement 接近零 advantage 或梯度退化、CG 输出接近零 检查 advantage std、grad norm、CG residual

若所有候选都失败，正确行为是跳过本轮 Actor 更新，而不是接受“最不坏”的失败候选。

9.4 训练后期明显变慢

对角高斯均值方向满足

\[\lvert\Delta\mu\rvert \le \sigma\sqrt{2\delta}\]

这条不等式只适用于单个状态、单个动作维度、其他分布参数不动且全部 KL 预算都用于该均值的情形；它不是共享网络在平均 KL 约束下的逐状态硬上限。它仍揭示正确的局部尺度：standard deviation 下降时，同样 KL 对应的绝对均值变化会变小；同时探索变弱，Critic 看到的数据更集中，策略可能停在局部行为。

记录每维 action std、policy entropy、均值改动除以 (\sigma) 的比例、return 与 accepted fraction，才能区分“信任域自然收紧”“探索耗尽”和“求解器失败”。

9.5 参数步很大，但 KL 很小

softmax 的共同 logit 平移完全不改变分布；接近确定性时也会出现很小的 Fisher 特征值。因此大参数范数不等于大策略变化。

应看真实 KL、动作概率、entropy 和行为轨迹。阻尼主要用于限制近零曲率方向上的巨大数值步，不能用普通参数范数代替策略距离。

9.6 平均 KL 合格，但稀有状态行为突变

平均 KL 按旧策略状态访问频率加权。稀有但安全关键的状态权重很小，可以消耗远高于平均值的 KL。

需要记录：

  • state KL 的中位数、90/95/99 分位；
  • 批内 max state KL（不是整个状态空间的最大值）；
  • 关键状态集上的条件 KL；
  • 行为约束或代价指标。

这些统计也只覆盖采到的状态；若稀有关键状态未进入批次，批内最大值仍可能看不见风险。这是 TRPO 与 CPO、安全强化学习之间的重要边界：平均策略接近不等于所有关键状态都安全。

9.7 Critic loss 下降，策略却变差

值函数 MSE 与策略梯度误差不是同一目标。Critic 可能更好地拟合频繁状态，却在决策敏感状态变差；也可能通过共享参数直接改变 Actor，或在更新后重算优势破坏旧快照。

应检查 explained variance、按状态分层的价值误差、Critic step 前后固定状态上的策略 KL、以及冻结 advantage 的哈希或统计量。

十一、TRPO 的结构性局限

11.1 计算成本高

一次 Actor 更新要做多次高阶自动微分 FVP、有限轮 CG 和多次候选前向评估。即使不形成 Hessian，墙钟时间和内存仍显著高于普通一阶更新。

11.2 实现复杂且错误常常静默

参数展平、旧分布快照、二阶图、阻尼口径、线搜索回滚与共享参数边界都可能出错；许多错误只表现为训练不稳，而不是异常栈。

11.3 on-policy 样本效率有限

策略批围绕 (\theta_{\mathrm{old}}) 构造，通常只做一次 Actor 更新。旧轨迹不能像 replay buffer 那样长期复用，在真实机器人或高成本仿真中代价明显。

11.4 平均 KL 不是真实回报保证

平均 KL 不控制每个状态，更不修复 advantage 与梯度估计偏差。它仍是有明确几何意义、可在样本上验收的风险控制量，但不再继承理论最大 KL 算法的单调改进保证。

11.5 与噪声层和参数共享的兼容性较差

PPO 论文指出，TRPO 相对复杂，并且不易兼容 dropout 等噪声架构或策略和值函数参数共享。候选比较需要同一批数据上的稳定局部几何，而随机层与共享参数更新会破坏这一前提。

11.6 仍然需要多组超参数

(\delta)、阻尼、CG 轮数、FVP 子采样、回溯系数、接受谓词、GAE、Critic 和标准差初始化都影响结果。信任域减少了“单一学习率”的脆弱性，但没有消除工程选择。

十二、后继方法继承了什么、放弃了什么

方法 继承的思想 放弃或改变的部分 主要目的
PPO 用旧策略概率比构造近端替代目标 去掉 HVP、CG 与显式线搜索；用 clip 或 KL penalty 近似控制更新 一阶优化、同批多轮、易并行
ACKTR 自然梯度与 trust-region 尺度 用 K-FAC 近似曲率；同时处理 Actor/Critic 降低曲率计算成本
CPO 信任域下的局部约束优化 增加期望代价约束与相应的局部约束求解 约束强化学习

TRPO 的历史价值不只在于今天是否仍是默认选择，而在于它把“策略更新步长应由分布变化而非参数距离定义”变成了可运行范式。PPO、ACKTR 与 CPO 分别沿近端一阶目标、可扩展曲率近似和显式约束方向发展；并非所有现代 on-policy 或 off-policy 方法都是 TRPO 的直接后继。

十三、复现实验的最低记录清单

  1. 环境全名与版本、奖励与时间限制包装器；
  2. 总环境步数、每轮步数、并行环境数与 seed 列表；
  3. Actor/Critic 网络、激活、初始化与共享方式；
  4. 动作分布、log standard deviation 参数化与动作边界处理；
  5. observation、reward、advantage 与 value target 的归一化；
  6. (\gamma)、(\lambda)、target KL、阻尼、CG 轮数和容差；
  7. FVP 子采样方式、线搜索收缩、最大次数与接受谓词；
  8. Critic optimizer、学习率、batch size 与更新次数；
  9. terminated/truncated 的 bootstrap 规则；
  10. 报告 mean、standard deviation、seed 数、评估协议和失败 seed；
  11. 保存 mean KL 之外的 state KL 分布与线搜索诊断；
  12. 固定代码提交、依赖锁文件和硬件信息。

没有这些信息，即使两个实验都写“TRPO”，也可能不是可解释的算法对比。
