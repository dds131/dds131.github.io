本专题要解决什么问题

六类缺陷里，最大化操作带来的过估计被研究得最早也最透，本节就以它作为整条改进链的入口；其余五类各自的病因在对应子页展开。

DQN 训练时会记录一个诊断量：每一步在当前状态上取到的最大 Q 值。把它随训练步数画出来，与「按当前策略实际跑一遍、算出真实折扣回报」的曲线放在一起对比，就会看到一个稳定复现的现象——估计曲线明显高于真实曲线，且随训练进行差距不收敛。

这件事的危害不在于数字难看，而在于它会改变策略本身：

  • Q 值高估如果在所有动作上均匀发生，贪心策略不受影响，因为 argmax 与常数偏移无关。
  • 但高估从来不是均匀的。被访问次数少的状态-动作对，逼近误差更大，被高估的幅度也更大。于是策略被系统性地推向数据稀少的区域，而那里的估值恰恰最不可信。
  • 更糟的是自举：这一轮高估的目标值写进了这一轮的回归目标，下一轮网络把它学进参数，再传给下下轮。偏差不是一次性的，它会随训练轮数累积。

过估计偏差与 Double DQN：要点

本节只保留结论、关键式子与对照表。完整推导——最大期望值与期望最大值这两个量的区分、Jensen 不等式与赢家诅咒、Thrun 上界与 van Hasselt 下界定理、双估计量为什么反而低估、原版 Double Q-learning 的双表算法与轮盘赌实验、Atari 上的实证数字——见子页过估计偏差与 Double DQN。

病因

DQN 的 TD 目标是

\[y = r + \gamma \max_{a'} Q_{\bar\theta}(s', a')\]

问题出在 \(\max_{a'}\) 这一步。最大值函数是凸函数，由 Jensen 不等式，即使每个动作上的估计都无偏，取最大之后的估计也是有偏的，且偏向高估：

\[\mathbb{E}\left[ \max_{a} Q_\theta(s, a) \right] \;\geq\; \max_{a} \mathbb{E}\left[ Q_\theta(s, a) \right] \;=\; \max_{a} Q^{*}(s, a)\]

一句话概括这个机制：最大化操作是一个筛选器，它专门挑出正误差、丢弃负误差，于是零均值噪声被筛成了系统性正偏差。 它在网络对每个动作都学得无偏的情况下依然存在，因此靠加大网络、多训几步、调小学习率都消不掉。

更要命的是自举会把单步偏差 \(b\) 沿时间累积成 \(b/(1-\gamma)\)。\(\gamma = 0.99\) 时放大倍数是 100 量级，这解释了为什么 DQN 的最大 Q 值曲线常常爬过 \(r_{\max}/(1-\gamma)\) 这个理论上限——突破上限本身就是过估计的直接证据。

对策

把目标里那一个 max 拆成「选」与「评」两步，交给不同的网络承担：

\[\max_{a'} Q_{\bar\theta}(s', a') \;=\; Q_{\bar\theta}\Big(s',\ \arg\max_{a'} Q_{\bar\theta}(s', a')\Big)\]

右端暴露出 DQN 的问题：选择与评估用的是同一份带噪估值，等于用同一批数据既选出了赢家、又宣布了赢家的成绩。Double DQN 把评估换给另一个网络：

\[y^{\text{Double}} \;=\; r + \gamma\, Q_{\bar\theta}\Big(s',\ \arg\max_{a'} Q_{\theta}(s', a')\Big)\]

唯一的改动是 argmax 里的下标从 \(\bar\theta\) 换成了 \(\theta\)：选动作用在线网络，评估该动作用目标网络。 落到代码上就是一行。

算法 选择用 评估用 偏差
Q-learning / DQN \(\bar\theta\) \(\bar\theta\) 显著为正
Double Q-learning \(\theta\) 独立训练的第二组 转为负偏
Double DQN \(\theta\) \(\bar\theta\) 被压低，但不为零
两处最容易被记错的地方。其一，Double DQN 的核心不是「从一个网络变成两个网络」——DQN 本来就有在线与目标两个网络，改的是它们在目标构造中的职责分工。其二，它并没有完全消除偏差：目标网络是在线网络的历史副本，两份误差高度相关，论文原文的措辞是「虽然并未完全解耦」。目标网络更新得越频繁，两者越接近，解耦效果越弱；极端情况下每步同步，Double DQN 退化回 DQN。

Dueling 价值与优势分解：要点

本节只保留结论与两条式子。完整展开——不可辨识性的确切含义与它对应的实测后果、最大值式与均值式的取舍理由、减均值带来的两条实用性质、梯度缩放与梯度裁剪两处工程措施、corridor 与 Atari 的定量证据——见子页Dueling 价值与优势分解。

动机

在很多状态上，「当前状态好不好」很重要，而「各个动作之间差多少」并不重要。但单流 Q 网络的一次更新只改动被执行动作对应的那一项，于是状态价值这份信息必须在每个动作上分别重学一遍。Dueling 把两者拆成两条流：共享卷积之后不接一串全连接层，而是分叉成两串，一条输出标量 \(V(s)\)，一条输出每个动作的 \(A(s,a)\)，最后再合并回单个 Q 输出。

为什么不能直接写 Q = V + A

因为这个分解不唯一。给 \(V\) 加上常数 \(c\)、同时从 \(A\) 减去同一个 \(c\)，两者抵消，得到完全相同的 \(Q\)：

\[\tilde{V}(s) = V(s) + c, \qquad \tilde{A}(s, a) = A(s, a) - c \qquad \Longrightarrow \qquad \tilde{V} + \tilde{A} = V + A\]

监督信号只约束了两条流输出的和，对各自的绝对水平没有任何约束。同一个 \(Q = 10\) 可以由 \(V=7, A=3\) 给出，也可以由 \(V=100, A=-90\) 给出。论文指出，这种不可辨识性对应着直接使用该式时可观测的性能下降。

聚合式

消掉那个自由常数的办法是给优势流加约束。论文给了两个方案，最终采用减均值这一个：

\[Q(s, a; \theta, \alpha, \beta) \;=\; V(s; \theta, \beta) + \left( A(s, a; \theta, \alpha) - \frac{1}{|\mathcal{A}|} \sum_{a'} A(s, a'; \theta, \alpha) \right)\]

另一个方案是把均值换成 \(\max_{a'} A(s,a')\)。它的语义更正确（此时 \(V\) 确实等于状态价值），但优化更不稳定：减均值时优势只需跟上均值的平滑变化，而减最大值时，一旦 \(\arg\max\) 切换，被减掉的那一项就会跳变。

减均值虽然让 \(V\) 与 \(A\) 都偏离真值一个常数，但它保住了两件要紧的事：不改变各动作之间的相对排序（因此贪心与 ε-贪心策略不受影响），以及行动时只需评估优势流即可决策。另外，聚合式是网络前向的一部分，不是独立的算法步骤——训练 Dueling 与训练标准 Q 网络一样只需反向传播，因此它能直接套用 DQN、Double DQN、SARSA 等现成算法。

与 Double DQN 的关系

两者正交：Double DQN 改的是 TD 目标的构造，Dueling 改的是网络结构，可以同时使用。需要澄清一个常见混淆——Dueling 并不直接消除过估计，它改善的是状态价值的估计效率，从而间接改善整体估计质量。

算法流程

本节压缩处理。整个流程与 DQN 完全一致，只有第 12 行不同，因此只需盯住那一行。

输入: 折扣 gamma, 学习率 alpha, 批量 B, buffer 容量 N,
      目标网络同步间隔 C, 探索系数 epsilon, 变体 variant

1  初始化 Q 网络参数 theta
     variant 含 dueling 时用双分支结构，否则用单分支结构
2  目标网络硬拷贝 theta_bar <- theta
3  初始化空 replay buffer D，容量 N
4  for episode = 1, 2, ... do
5      重置环境得到 s
6      for t = 1 .. T do
7          以概率 epsilon 均匀随机取 a，否则 a <- argmax_a Q_theta(s, a)
8          执行 a，得到 r, s_next, done
9          把 (s, a, r, s_next, done) 存入 D；D 满则覆盖最旧一条
10         s <- s_next
11         若 |D| < 起始学习阈值 则 continue
12         # ======== 全章唯一的分叉点：目标值怎么构造 ========
              variant 含 double:
                a_star <- argmax_a' Q_theta(s_next, a')        # 在线网络选
                q_next <- Q_theta_bar(s_next, a_star)          # 目标网络评
              否则:
                q_next <- max_a' Q_theta_bar(s_next, a')       # 同一网络既选又评
13         td_target <- r + gamma * (1 - done) * q_next        # 切断梯度
14         loss <- mean( ( Q_theta(s, a) - td_target )^2 )
15         对 theta 做一步梯度下降，最小化 loss
16         每 C 步执行一次 theta_bar <- theta
17         if done then break
18     end for
19 end for

几处实现约定，都与 DQN 页一致，不展开：第 13 行的 td_target 必须切断梯度；第 13 行的 done 要区分真终止与时间截断；第 16 行的硬同步也可以换成软更新，本页沿用 DQN 的硬同步以便与原论文对齐。

值得单独强调的只有一点：第 12 行的两个分支里，Q_theta 与 Q_theta_bar 的位置不能互换。 上一节的 callout 已经说明写反的后果。

代码实现

下面这份实现把三个变体放在同一份骨架上，靠两个布尔开关切换，这样对比实验才有意义——网络宽度、优化器、buffer、探索策略、随机种子全部相同，唯一的差别就是前面推导出的那两处。环境用 Gymnasium 的 Pendulum-v1，把一维连续力矩离散成若干档；这是展示过估计最合适的环境，因为它的动作在多数状态下价值相近，正是 Jensen 偏差最容易显现的情形。

代码按依赖顺序分成六段，复制到同一个文件里即可运行。前三段是样板，讲解从简；第四段的目标值构造与第三段的 Dueling 前向是本节要讲透的地方。

这一段没有需要讲的内容，只提三处与后文推导直接相关的取值。ACTION_DIM = 11 把力矩离散成 11 档——动作数越多，Jensen 偏差越大，这个值选得偏大正是为了让过估计现象显现出来。TARGET_UPDATE = 50 决定两个网络的参数相隔多远，也就决定了 Double DQN 里那份「独立性」有多接近成立。EPSILON 固定不衰减，是为了让三个变体面对的探索强度在整个训练过程中完全一致。

第二段：replay buffer（样板）

class ReplayBuffer:
    """先进先出的经验回放池，与 DQN 页的实现完全相同。"""

    def __init__(self, capacity):
        self.buffer = deque(maxlen=capacity)

    def add(self, state, action, reward, next_state, done):
        self.buffer.append((state, action, reward, next_state, done))

    def sample(self, batch_size):
        transitions = random.sample(self.buffer, batch_size)
        state, action, reward, next_state, done = zip(*transitions)
        return (
            np.array(state, dtype=np.float32),
            np.array(action, dtype=np.int64),
            np.array(reward, dtype=np.float32),
            np.array(next_state, dtype=np.float32),
            np.array(done, dtype=np.float32),
        )

    def __len__(self):
        return len(self.buffer)

标准样板，不展开。只提一点：action 必须存成整型（int64），因为后面要用它做 gather 的索引；存成浮点会在 gather 那一行直接报类型错误，这是最常见的一处低级错误。

第三段：两种网络结构（Dueling 分支是重点）

class QNet(nn.Module):
    """普通 DQN 用的单分支网络：状态进，每个动作一个 Q 值出。"""

    def __init__(self, state_dim, hidden_dim, action_dim):
        super().__init__()
        self.fc1 = nn.Linear(state_dim, hidden_dim)
        self.fc2 = nn.Linear(hidden_dim, action_dim)

    def forward(self, x):
        return self.fc2(F.relu(self.fc1(x)))


class VANet(nn.Module):
    """Dueling DQN 用的双分支网络：共享主干，分出 V 支与 A 支。"""

    def __init__(self, state_dim, hidden_dim, action_dim):
        super().__init__()
        self.fc_shared = nn.Linear(state_dim, hidden_dim)   # 共享特征主干
        self.fc_A = nn.Linear(hidden_dim, action_dim)       # 优势支，输出 |A| 维
        self.fc_V = nn.Linear(hidden_dim, 1)                # 价值支，输出标量

    def forward(self, x):
        feature = F.relu(self.fc_shared(x))
        advantage = self.fc_A(feature)                      # 形状 (B, action_dim)
        value = self.fc_V(feature)                          # 形状 (B, 1)
        # 关键一行：减去优势在动作维上的均值，把 V 与 A 的平移自由度钉死
        return value + advantage - advantage.mean(dim=1, keepdim=True)

QNet 是样板，跳过。要讲的是 VANet 的 forward，它把上一节的公式一比一落到代码上。

  • advantage 与 value 分别对应 \(A_{\theta}(s, \cdot)\) 与 \(V_{\theta}(s)\)，形状分别是 (B, action_dim) 与 (B, 1)。返回时 value 靠广播加到每个动作上，这正是「\(V\) 与动作无关」在张量层面的体现。
  • advantage.mean(dim=1, keepdim=True) 是沿动作维求均值，得到形状 (B, 1)。维度不能写错：写成 dim=0 会变成沿批量维求均值，把同一批里不同状态的优势混在一起，语义完全错误，而且不会报错——张量形状恰好也能广播，这是本段最隐蔽的一个坑。
  • keepdim=True 是为了保留那一维以便广播。写成 keepdim=False 时形状变成 (B,)，与 (B, action_dim) 相加会按 PyTorch 的广播规则从尾部对齐，在 B 恰好等于 action_dim 时不报错但结果错乱。
  • 减去均值这一步没有可学习参数，它是一个约束而不是一层网络。去掉这一行代码仍然能跑、损失也会下降，但得到的就是上一节分析过的不可辨识分解，Dueling 的收益归零。这正是「必须减去均值」在工程上的意义：它是一处删掉也不报错的关键行。
  • 若要改用最大值形式，把 advantage.mean(dim=1, keepdim=True) 换成 advantage.max(dim=1, keepdim=True)[0] 即可。max 返回的是 (values, indices) 二元组，取 [0] 才是数值——漏掉这个下标会让整支代码在类型上出错。
两种网络的输出形状完全一致，都是 (B, action_dim)。这是 Dueling 能作为「插件」使用的原因：算法类里除了实例化哪个网络，其余代码一行都不用改。下一段的 DQN 类会看到这一点。

第四段：算法类与目标值构造（本节核心）

class DQNAgent:
    """三个变体共用的算法类。variant 取 'vanilla' / 'double' / 'dueling' /
    'dueling_double'，两个特性互相正交，可以同时打开。"""

    def __init__(self, state_dim, hidden_dim, action_dim, variant="vanilla"):
        self.action_dim = action_dim
        self.gamma = GAMMA
        self.epsilon = EPSILON
        self.target_update = TARGET_UPDATE
        self.device = DEVICE
        self.count = 0                                   # 已完成的更新次数

        # 两个开关：一个决定网络结构，一个决定目标值构造，互不影响
        self.use_dueling = "dueling" in variant
        self.use_double = "double" in variant

        net_cls = VANet if self.use_dueling else QNet
        self.q_net = net_cls(state_dim, hidden_dim, action_dim).to(self.device)
        self.target_q_net = net_cls(state_dim, hidden_dim, action_dim).to(self.device)
        self.target_q_net.load_state_dict(self.q_net.state_dict())   # 硬拷贝初始化
        self.optimizer = torch.optim.Adam(self.q_net.parameters(), lr=LR)

    def take_action(self, state):
        """epsilon 贪心。"""
        if np.random.random() < self.epsilon:
            return np.random.randint(self.action_dim)
        state_t = torch.tensor(np.array([state]), dtype=torch.float, device=self.device)
        with torch.no_grad():
            return int(self.q_net(state_t).argmax(dim=1).item())

    def max_q_value(self, state):
        """诊断量：当前状态上的最大 Q 值，用来观察过估计。"""
        state_t = torch.tensor(np.array([state]), dtype=torch.float, device=self.device)
        with torch.no_grad():
            return float(self.q_net(state_t).max().item())

    def update(self, batch):
        states, actions, rewards, next_states, dones = batch
        states = torch.tensor(states, dtype=torch.float, device=self.device)
        actions = torch.tensor(actions, device=self.device).view(-1, 1)
        rewards = torch.tensor(rewards, dtype=torch.float, device=self.device).view(-1, 1)
        next_states = torch.tensor(next_states, dtype=torch.float, device=self.device)
        dones = torch.tensor(dones, dtype=torch.float, device=self.device).view(-1, 1)

        # 当前估值：取出实际执行过的那个动作对应的 Q
        q_values = self.q_net(states).gather(1, actions)

        # ======== 全章唯一的分叉点 ========
        with torch.no_grad():
            if self.use_double:
                # 选动作：在线网络。评估该动作：目标网络。两步用不同的网络
                best_action = self.q_net(next_states).argmax(dim=1, keepdim=True)
                max_next_q = self.target_q_net(next_states).gather(1, best_action)
            else:
                # 同一份估值既选又评，Jensen 偏差由此产生
                max_next_q = self.target_q_net(next_states).max(dim=1, keepdim=True)[0]
            td_target = rewards + self.gamma * max_next_q * (1 - dones)

        loss = F.mse_loss(q_values, td_target)
        self.optimizer.zero_grad()
        loss.backward()
        self.optimizer.step()

        self.count += 1
        if self.count % self.target_update == 0:
            self.target_q_net.load_state_dict(self.q_net.state_dict())
        return float(loss.item())

这一段要逐行讲。先看两个开关的设计：use_dueling 只决定 net_cls 选哪个类，use_double 只决定 update 里走哪个分支，两者在代码上没有任何交叉——这正是前面说的「两项改进正交」在实现层面的证据。

q_values = self.q_net(states).gather(1, actions) 这一行是所有 DQN 实现的公共写法：网络输出的是全部动作的 Q，而损失只应该作用在实际执行过的那个动作上。gather(1, actions) 沿动作维按索引取值，actions 必须是形状 (B, 1) 的整型张量，这就是第二段里强调存成 int64 的原因。

接下来是本节的重点，两种目标值构造的逐行对比：

写法 选动作用哪个网络 评估用哪个网络 对应公式
max(dim=1)[0] 目标网络 目标网络 \(r + \gamma \max_{a'} Q_{\bar\theta}(s', a')\)
argmax + gather 在线网络 目标网络 \(r + \gamma Q_{\bar\theta}(s', \arg\max_{a'} Q_{\theta}(s', a'))\)
  • 普通分支：self.target_q_net(next_states).max(dim=1, keepdim=True)[0]。一次前向就把选与评都做完了，因为 max 同时完成了「找出最大值在哪」和「返回那个最大值」。这份紧凑正是偏差的来源——两件事共用了同一次带噪输出。
  • Double 分支：拆成两次前向。self.q_net(next_states).argmax(dim=1, keepdim=True) 只取索引，不取数值，所以在线网络的噪声不会进入目标；self.target_q_net(next_states).gather(1, best_action) 只按这个索引取数值，评估用的是另一份参数。把这两行与上一节的解耦推导对照，best_action 就是 \(a^{*}\)，gather 出来的就是 \(Q_{\bar\theta}(s', a^{*})\)。
  • argmax 与 gather 的网络绝不能互换。 写成「目标网络 argmax、在线网络 gather」时，评估路径落在正在被优化的网络上；即便这里有 no_grad 挡着梯度，目标值也会随每一步更新而抖动，目标网络就失去了意义。
  • keepdim=True 在两个分支里都必须有。 max_next_q 要与形状 (B, 1) 的 rewards 和 dones 做逐元素运算，少了这一维会触发广播成 (B, B)，损失照样能算出来，但结果毫无意义且不报错。
  • 整块目标值计算包在 torch.no_grad() 里。 这等价于伪代码第 13 行的「切断梯度」。不切断时优化器会同时压低预测与目标，损失可以靠把两端一起拉平而下降，网络什么都学不到。
  • (1 - dones) 处理终止。 回合真正终止时后续回报置零。要注意 Gymnasium 区分 terminated 与 truncated，只有前者才是真终止，下一段会处理这一点。

第五段：动作离散化与训练循环（外壳部分从简）

def dis_to_con(discrete_action, env, action_dim):
    """把离散档位映射回 Pendulum 的连续力矩。"""
    low = float(env.action_space.low[0])
    high = float(env.action_space.high[0])
    return low + (high - low) * discrete_action / (action_dim - 1)


def train(variant, env_name="Pendulum-v1", num_episodes=NUM_EPISODES):
    env = gym.make(env_name)
    env.reset(seed=SEED)
    env.action_space.seed(SEED)

    discrete = isinstance(env.action_space, gym.spaces.Discrete)
    action_dim = env.action_space.n if discrete else ACTION_DIM
    state_dim = env.observation_space.shape[0]

    agent = DQNAgent(state_dim, HIDDEN_DIM, action_dim, variant=variant)
    buffer = ReplayBuffer(BUFFER_SIZE)
    return_list, max_q_list = [], []
    smoothed_q = 0.0

    for episode in range(num_episodes):
        state, _ = env.reset()
        episode_return, done = 0.0, False
        while not done:
            action = agent.take_action(state)
            # 诊断量做滑动平均，否则单步噪声会淹没趋势
            smoothed_q = agent.max_q_value(state) * 0.005 + smoothed_q * 0.995
            max_q_list.append(smoothed_q)

            if discrete:
                env_action = action
            else:
                env_action = [dis_to_con(action, env, action_dim)]
            next_state, reward, terminated, truncated, _ = env.step(env_action)
            done = terminated or truncated
            # 只有 terminated 才是真终止；truncated 是时间截断，不能置 1
            buffer.add(state, action, reward, next_state, float(terminated))
            state = next_state
            episode_return += reward

            if len(buffer) >= MINIMAL_SIZE:
                agent.update(buffer.sample(BATCH_SIZE))

        return_list.append(episode_return)

    env.close()
    return return_list, max_q_list

训练循环是标准外壳，只讲三处与本页结论直接相关的地方，其余（回合循环、返回值收集）不展开。

  • dis_to_con 的离散化。 Pendulum-v1 的动作是区间上的一维连续力矩，DQN 无法直接用，所以把它均匀切成 action_dim 档。档位数是本页实验里一个有意义的旋钮：档数越多，前面推导的 Jensen 偏差越大，因为取最大是在更多个带噪估值里取。想把过估计现象放大，把 ACTION_DIM 从 11 调到更大即可复现。
  • smoothed_q 的滑动平均。 单步的最大 Q 值抖动很大，直接画出来看不出趋势。这里用一个衰减系数很接近 1 的指数滑动平均把高频噪声滤掉，保留系统性的漂移——我们要观察的正是「有没有系统性地往上漂」，不是单步取值。
  • terminated 与 truncated 必须分开。 存进 buffer 的终止标志只用 terminated。Pendulum-v1 没有真正的失败状态，回合全部由时间上限截断结束，如果把 truncated 也当成终止，等于告诉网络「到点之后没有任何回报」，Q 值会被系统性压低——那会与本页要观察的过估计现象混在一起，实验结论就作废了。这是本段最容易毁掉整个实验的一处。

实验与结果分析

本节只给定性结论。具体数值依赖随机种子、离散档数与机器，逐次运行都会不同，写成精确数字没有意义；真正稳定复现的是曲线的形状与曲线之间的相对高低。

该看哪两条曲线

  • 最大 Q 值曲线（诊断量）。这条曲线是本页的主角。判断有没有过估计，最硬的依据是把它与理论上限比较：Pendulum-v1 的奖励非正且有下界，因此真实的 \(Q^{*}\) 处处不大于零。普通 DQN 的曲线会明显爬到零以上，这在真实值域里是不可能的，只能是估计偏差。
  • 回合回报曲线（性能量）。它衡量策略实际有多好，与 Q 值曲线相互独立——Q 值涨得高不等于策略好，这正是过估计的危害所在。

三条稳定复现的现象，与一条只是推导预期的

前三条是运行上面这份代码可以稳定看到的；第四条要单独标出来，因为它的地位不同。

  • 普通 DQN 的最大 Q 值突破理论上限。 曲线单调上爬并越过零，且训练越久越离谱。这是 Jensen 偏差经自举放大 \(1/(1-\gamma)\) 倍的直接可视化。
  • Double DQN 的最大 Q 值曲线明显低于普通 DQN，且贴着理论上限以下。 这与推导一致：解耦把正偏差压掉了大部分，剩下的选择误差是向下的。注意它并不是「更准」的绝对保证——曲线偶尔会压到略低于真实值，也就是前面说的轻微低估。
  • 两者叠加时兼有两方面表现： Q 曲线像 Double DQN 一样被压住，回报曲线像 Dueling 一样上升更快。这是「正交」最直观的证据。

第四条是推导给出的预期，不是本页的实测结论，请按这个分量看待。按前面的分析，Dueling DQN 的 Q 值曲线应当仍然偏高——它没有动目标值的构造，Jensen 偏差原封不动，因此其 Q 曲线预期与普通 DQN 同量级；它改善的应当是回报曲线，因为 \(V\) 支能从所有动作的样本里获得更新。

但要说清两件事：其一，Dueling 原论文报告的是分数与胜率，没有给出「Dueling 是否改变值估计量级」这条对照；其二，本页也没有给出该对照的实测数据。所以这一条目前只有推导支撑。跑上面的代码时值得专门把四条 Q 值曲线放在一起确认一次——如果实测与推导不符，那说明 Dueling 通过改善 \(V\) 的估计质量间接影响了偏差量级，这本身就是一个值得追的问题。

换到 CartPole-v1 之后为什么差别变小

把同一份代码换到 CartPole-v1 上，四个变体的差距会明显收窄。这不是实现出了问题，恰恰是本页推导的一个验证：

  • 动作只有两个。 取两个带噪估值的最大值，其正偏差远小于取十一个的情形。Jensen 偏差随动作数增长，动作少时它本来就小。
  • 任务本身容易。 状态维度低、奖励密集，普通 DQN 在偏差被放大到有害之前就已经解决了任务，改进没有发挥空间。
  • Dueling 的收益也随之变小。 价值流的好处来自「一次更新能为多少个动作共享同一份状态价值」，动作越少，可共享的面越窄。这一点在 Dueling 原论文的 corridor 实验里被单独验证过——该实验靠往环境里加 no-op 动作把动作数从 5 提到 10 再提到 20，动力学与最优策略完全不变，只有动作数在变：5 个动作时两种架构收敛速度相当，动作数增大后 Dueling 才明显占优（见子页②）。CartPole-v1 只有两个动作，正落在「看不出差别」的那一端。

这条对照说明了一件重要的事：改进算法的收益依赖于任务是否真的触发了它所针对的问题。 在动作数少、任务简单的环境上拿不到提升，不是改进无效，而是选错了验证环境。这也是原论文选择 Atari 那类动作数较多的环境做评测的原因。

实验设计上的几处注意

  • 单种子的结果不足以下结论。 强化学习的种子间方差很大，正式对比至少要跑若干个种子并画出区间。本节的四条现象是在多种子下稳定的那部分。
  • 不要用训练时的回报当评估指标。 训练时带 epsilon 探索，回报被噪声动作污染。严格做法是每隔若干回合关掉探索单独评估一次。
  • Q 值曲线与回报曲线必须一起看。 只看 Q 值会得出「DQN 学得最好」的荒谬结论，只看回报则看不到偏差的存在。本页的全部论点都建立在这两条曲线的背离上。

关键参数配置与原因

与 DQN 页重复的项（折扣因子 gamma、replay buffer 容量、batch size、起始学习阈值）本节不重复，见 DQN 与总览页的对应小节。这里只写与本页正文展开的两项改进（Double 与 Dueling）直接相关的四项。

目标网络同步间隔 C

  • 典型取值：本页代码取 50 次更新同步一次；原始 DQN 在 Atari 上取 10000 次参数更新同步一次。Double DQN 论文调参版进一步把它从 10000 拉到 30000，理由正是下面这条——间隔越大解耦越充分。
  • 为什么这么配：这是本页最需要重新审视的一个参数，因为 Double DQN 的效果直接取决于它。前面的推导要求「选」与「评」用的两份误差近似独立，而目标网络是在线网络的历史副本——两者相隔的更新步数就是这份独立性的来源。\(C\) 越大，参数相隔越远，误差相关性越低，解耦越充分。
  • 配错了会怎样：\(C\) 取得过小（极端情况每步同步）时，目标网络与在线网络几乎相同，argmax 与 gather 落在同一份估值上，Double DQN 退化回 DQN，改动完全失效且不会有任何报错——这是本页最隐蔽的失败模式。\(C\) 取得过大时，目标值长期陈旧，回归目标与当前网络脱节，学习变慢；在非平稳的早期训练阶段尤其明显。

离散化档数（动作数）

  • 典型取值：本页把 Pendulum-v1 的力矩切成 11 档。实际任务按控制精度需求定，通常在个位数到几十档之间。
  • 为什么这么配：档数同时影响两件事，方向相反。控制精度要求档数大；而前面推导过，取最大值的正偏差随动作数单调增长，档数大则过估计更严重。11 档是这两者的一个折中，同时也足够大到让过估计现象在实验里清楚显现。
  • 配错了会怎样：档数太少时动作粒度粗，摆锤这类需要精细力矩的任务无法稳定在目标位置，表现为回报曲线到某个水平就不再上升。档数太多时除了过估计加剧，还有一个实际问题——每个档位分到的样本变少，逼近误差变大，与偏差放大形成叠加。多维动作时更要注意：把 \(d\) 维动作各切 \(n\) 档，动作数是 \(n^{d}\)，这个组合爆炸正是基于价值的方法在连续控制上走不通的根本原因，也是下一章要处理的问题。

是否用均值形式还是最大值形式

  • 典型取值：均值形式，即减去 advantage.mean(dim=1, keepdim=True)。
  • 为什么这么配：两种形式都能消除平移自由度，区别在梯度行为。均值把梯度均匀分给所有动作分支，是所有动作的平滑函数；最大值只把梯度给当前取最大的那一支，最大值在动作之间跳变时梯度也跟着跳变，优化过程更不稳。代价是 \(V_{\theta}\) 学到的是各动作 Q 的均值而非最大值，与 \(V^{*}\) 相差一个只依赖状态的偏移——这个偏移不改变 argmax，因此不影响策略。
  • 配错了会怎样：完全不减是最严重的错误：分解不可辨识，\(V\) 与 \(A\) 可以同时漂移，Dueling 的样本效率收益归零，网络退化成一个参数更多的普通 DQN，且训练时两支的输出量级可能一起发散。这个错误不会报错、损失照样下降，只能靠打印 \(V\) 支的输出来发现。dim 写错（沿批量维求均值）同样不报错，但语义完全错误。

学习率 alpha 与隐层宽度

  • 典型取值：本页取 LR = 1e-2 与隐层 128，适合低维状态的小任务；视觉输入任务通常小两到三个数量级并配更宽的网络。
  • 为什么这么配：这两项本身与本页改进无关，但有一处必须注意——做变体对比时它们必须完全相同。三个变体的差异只有目标构造与网络分支两处，任何其他差异都会污染结论。Dueling 网络多出一支，参数量略高于普通网络，严格的对照实验会把普通网络的隐层调宽一点使参数量对齐，以排除「收益只是来自参数变多」的可能。
  • 配错了会怎样：学习率过大时 TD 回归本身震荡，目标网络也压不住，Q 值可能发散到数量级异常——这时看到的 Q 值飙升是发散而不是过估计，两者会被混淆。学习率过小则训练极慢，偏差还没积累到可见就已经跑完了预定回合数，实验会得出「三个变体没有差别」的错误结论。

小结与下一章衔接

三句话回顾（本页正文展开的部分）

  • 过估计不是 bug，是最大化操作的数学性质。 Jensen 不等式保证 \(\mathbb{E}[\max_a \hat{Q}] \ge \max_a \mathbb{E}[\hat{Q}]\)，零均值噪声被 max 筛成系统性正偏差，再经自举放大 \(1/(1-\gamma)\) 倍。
  • Double DQN 切断选择与评估之间的相关性。 用在线网络选动作、目标网络评估，让「被选中」这件事不再携带评估用误差的信息。它只能部分消除偏差，因为两个网络并非真正独立。
  • Dueling DQN 把 Q 拆成 V 与 A，并且必须减去优势的均值。 不减则分解不唯一、收益归零。它的收益来自 \(V\) 支能从所有动作的样本里获得更新，在动作多且价值相近的状态上尤其明显。

与 TD3 的双 Critic 是同一个思想

本页第一节已经点过这条线索，这里收拢。TD3 面对的是连续动作空间，那里没有显式的 \(\max_{a'}\)，取而代之的是 Actor 沿 \(\nabla_a Q\) 上升找出的动作——但 Actor 找的正是估值最高的动作，与 max 的筛选机制完全相同，因此同样产生系统性正偏差。

两者的解法思路一致、手段不同：

维度 Double DQN TD3 的 Clipped Double Q
动作空间 离散 连续
max 的形式 显式枚举 argmax Actor 网络近似
用几份估值 两份（在线网络与目标网络） 两份独立初始化并独立训练的 Critic
组合方式 一份选、另一份评 两份都评，取较小者
独立性来源 参数相隔若干次更新，较弱 独立初始化与独立优化器，较强
偏差方向 接近零，有时轻微偏负 明确偏负（取 min 是保守估计）

TD3 的独立性比 Double DQN 强得多——两个 Critic 从不同的初始化开始、由各自的优化器独立训练，而 Double DQN 的两个网络本就是同一条训练轨迹上的两个时刻。这也解释了为什么 TD3 敢用更激进的取最小值：估值来源足够独立，取 min 才不至于过度保守。完整推导见 TD3。

下一章：为什么要换一条路线

本专题的六项改进，全都在「先学 Q、再由 Q 导出策略」这条路线内部打补丁。但这条路线有一处根本限制，补丁修不了：动作一旦连续，\(\arg\max_a Q(s,a)\) 就无法计算。 本页的做法是把连续动作离散化，代价上面已经算过——\(d\) 维动作各切 \(n\) 档就是 \(n^{d}\) 个动作，维度稍高就完全不可行，而且档数增加还会同时加剧过估计。

下一章换一条完全不同的路线：不再学价值函数再导出策略，而是直接把策略参数化，对目标函数求梯度。这条路线天然支持连续动作，代价是要处理另一个问题——梯度估计的方差。之后的 Actor-Critic 把两条路线合起来，本页的价值函数以 Critic 的身份重新出场。
