PPO 的更新公式只占实现的一小部分。真正决定信号是否可信的，是此前的数据管线：哪个策略产生了动作、终止和截断如何编码、片段末端从哪里 Bootstrap、优势是否跨过了自动重置边界，以及多 Epoch 时哪些量保持冻结。

N × T并行环境数 × 每环境步数
old 值冻结log-prob、value、advantage
两种 maskBootstrap 与 trace 语义不同
K Epoch迭代内复用，迭代后丢弃

最重要的工程原则： “能否 Bootstrap”与“GAE 递推能否跨到下一条记录”不是同一个问题。时间上限截断通常允许从真实末状态 Bootstrap，但绝不能把 reset 后的新 Episode 当作前一条轨迹的下一状态。

1. 一批 PPO 数据是怎样产生的

设并行环境数为 $N$，每个环境采集 $T$ 步，总样本数 $B=N T$。

sequenceDiagram
  participant P as 固定采样策略 π_old
  participant E as N 个并行环境
  participant S as Rollout Storage
  participant G as GAE/Return
  participant U as PPO Update
  loop t = 0...T-1
    P->>E: 根据 obs 采样 action
    E-->>S: reward, next_obs, terminated, truncated
    P-->>S: old_log_prob, old_value
  end
  S->>G: T 步序列 + 末状态 value
  G->>U: 固定 advantage 与 return
  loop K 个 Epoch
    U->>U: Shuffle → Mini-batch → 重算新策略量
  end
  U-->>E: 丢弃旧批次，用更新后的策略重新采样

标准同步 PPO 在整段 Rollout 中冻结行为策略，采满一批后再统一更新。为每条记录保存匹配的 old_log_prob 是必要条件，但不是“边采边更新”的充分修正：若策略在采样途中变化，Storage 的状态访问分布会成为多个行为策略的混合，已不再对应单一的 $\pi_{old}$。

为什么常用固定长度 $T$

等待每个 Episode 自然结束会产生变长批次，并让长 Episode 或慢环境拖住同步更新。固定 $T$ 能给 GPU 提供规则张量和可预测的更新频率；未结束的 Episode 则在片段末用 $V_{old}$ Bootstrap。代价是 $T$ 太短时，更多优势依赖 Critic 的末端估计。

固定 $B=N T$ 时 主要收益 主要代价
增大 $N$、减小 $T$ 初始条件和并行状态通常更多样，吞吐可能更高 单环境连续上下文更短，更多样本受片段末 Bootstrap 影响
减小 $N$、增大 $T$ 每个环境提供更长的真实奖励链 时序相关性更强，并行度下降，慢环境等待可能更明显
同时增大 $N,T$ 总 Batch 和吞吐上限提高 更新间隔、显存占用与数据陈旧度一起增加

因此 $N T$ 相同只表示样本数相同，不表示时序信息、相关性或系统效率相同；不存在脱离环境与硬件的统一最佳比例。

2. Storage 最小字段与张量契约

以时间优先布局为例：

字段 典型形状 何时产生 多 Epoch 是否重算
obs [T, N, obs_dim] 环境交互前 否
actions [T, N, act_dim] 或 [T, N] 旧策略采样 否
rewards [T, N] 环境步进 否
terminated [T, N] 环境步进 否
truncated [T, N] 环境步进 否
old_log_prob [T, N] 旧策略评估实际动作 否
old_value [T, N] 旧 Critic 否
next_value_for_bootstrap [T, N] 或片段末 [N] 对正确末状态求值 否
advantage [T, N] Rollout 后逆序计算 否
return [T, N] advantage + old_value 否

若 Critic 使用特权观测，应额外存 critic_obs。若策略是循环网络，还需存初始隐藏状态和 Episode 起始 mask，不能简单把所有时间步完全打散。

不要只保存含糊的 done。在现代环境接口中，terminated 通常表示 MDP 内真正终止；truncated 表示时间上限或外部截断。两者都可能触发 reset，但对价值 Bootstrap 的含义不同。

3. 四种“末端”必须分清

情况 示例 对末状态 Bootstrap GAE 是否跨到下一条 Storage 记录
真终止 terminated 失败、成功、吸收态 通常否，末状态价值按 0 否
外部截断 truncated MDP 之外的时间上限、外部中止 通常是，用截断前真实末状态 否，因为随后会 reset 或显式开启新段
Rollout 片段末端 Episode 尚未结束但 $t=T-1$ 是，用片段后当前观测 不跨批次；以 Bootstrap 收尾
自动 reset 后观测 向量环境立即给出新 Episode 初态 不能拿它替代前一 Episode 的末状态 新 Episode 从新 trace 开始

时间上限不必然等于截断。 若有限时域本身属于任务定义，剩余时间应进入观测以保持 Markov 性，到达时域末端可属于 terminated；若时间上限在 MDP 定义之外，才是典型 truncated。训练代码应服从环境的任务语义和 API，而不是仅凭“达到最大步数”猜测。

自动重置的隐蔽错误

“next_obs 是末状态还是 reset 初态”取决于向量环境的自动重置模式，不能只按字段名推断。Gymnasium 1.1+ 定义了三种模式，并通过 metadata["autoreset_mode"] 暴露语义：

模式 结束步返回的观测 训练端责任
Next-Step（make_vec 默认） 结束步仍返回真实末观测，下一次调用才 reset 标记下一记录为 Episode 起点，避免把 reset 步当成普通转移
Same-Step 同一次 step 已返回 reset 初态；真实末观测通常在 info["final_obs"] 或等价字段 Bootstrap 必须显式取真实末观测
Disabled 不自动 reset 调用者根据结束 mask 显式 reset 对应子环境

第三方向量环境、旧版 Gym 和 wrapper 的字段名与模式可能不同，必须核对实际版本。若把 reset 初态当作前一 Episode 的后继状态，代码通常不会报 Shape 错误，却会造成 Return 串线、Value Loss 异常、优势偏置和训练方差增大。

4. 从 TD 残差到 GAE

对一步转移定义 Bootstrap mask $m_t$：真终止时为 0，其余可 Bootstrap 的情况为 1。TD 残差为

\[\delta_t=r_t+\gamma m_tV_{old}(s_{t+1})-V_{old}(s_t).\]

再定义 trace continuation mask $c_t$：只要下一条 Storage 记录属于不同 Episode，或当前已到 Rollout 末端，就令递推停止。GAE 逆序递推：

\[\hat A_t=\delta_t+\gamma\lambda c_t\hat A_{t+1}.\]

最后构造价值目标：

\[\hat R_t=\hat A_t+V_{old}(s_t).\]

如果环境没有发生 Episode 边界，通常 $m_t=c_t=1$；真终止时二者都为 0；时间截断时可出现 $m_t=1$、$c_t=0$。这正是两个 mask 不能混为一谈的原因。

逆序伪代码

gae = torch.zeros(num_envs, device=device)
for t in reversed(range(num_steps)):
    delta = reward[t] + gamma * bootstrap_mask[t] * next_value[t] - old_value[t]
    gae = delta + gamma * gae_lambda * trace_mask[t] * gae
    advantage[t] = gae
returns = advantage + old_value

这里的 next_value[t] 必须已经对应正确的真实后继状态。若实现只在片段末求一次 last_value，也要对中途发生的时间截断做专门校正。

一个可手算的截断例子

取 $\gamma=0.9$、$\lambda=0.8$，三步奖励为 $[1,0,2]$，旧价值为 $[0.5,0.4,0.3]$。第 2 步后发生外部时间截断，真实末状态价值为 $0.7$，因此该步允许 Bootstrap，但 trace 在此结束。

$t$ $r_t$ $V_{old}(s_t)$ $V_{old}(s_{t+1})$ $m_t$ $c_t$ $\delta_t$
0 1 0.5 0.4 1 1 0.86
1 0 0.4 0.3 1 1 -0.13
2 2 0.3 0.7 1 0 2.33
\[\hat A_2=2.33,\qquad \hat A_1=-0.13+0.72\times2.33=1.5476,\qquad \hat A_0=0.86+0.72\times1.5476=1.974272.\]

相应的未标准化 Return 为 $[2.474272,1.9476,2.63]$。最后一个值满足 $2+0.9\times0.7=2.63$：这正好验证“截断仍 Bootstrap，但不把 reset 后的新 Episode 接入 GAE”。

5. $\gamma$ 与 $\lambda$ 的作用与偏差—方差关系

在有限 Rollout 与 Episode 边界下，GAE 更准确地写成带 continuation mask 的有限和：

\[\hat A_t =\sum_{l=0}^{L_t-1}(\gamma\lambda)^l \left(\prod_{j=0}^{l-1}c_{t+j}\right)\delta_{t+l}.\]

其中空积定义为 1，$L_t$ 到当前可用片段末端为止。只有在无边界、无限视野的理想记号下，才可简写为 $\sum_{l=0}^{\infty}(\gamma\lambda)^l\delta_{t+l}$；实际代码的递推不会穿过 $c_t=0$ 的位置。

折扣因子 $\gamma$

决定任务目标对远期回报的权重，也进入优势估计。它不是纯粹的“平滑旋钮”，改变它会改变优化问题本身。

GAE 参数 $\lambda$

控制优势估计的偏差—方差折中。较小值更接近短期 TD、方差低但依赖 Critic；接近 1 更依赖长程回报、方差通常更高。

原论文实验常见 $\gamma=0.99$、$\lambda=0.95$，但这不是跨任务定律。控制周期、Episode 长度、奖励密度与物理时间尺度变化时，应重新解释有效视野，而不是机械复制。

6. 优势标准化与 Return

常见实现按整个 Batch 或每个 Mini-batch 做

\[\tilde A_t=\frac{\hat A_t-\mu_A}{\sigma_A+\varepsilon_{num}}.\]

它通常改善数值尺度并减轻学习率对奖励幅值的敏感性，但也改变有限样本中各样本的相对权重。需要记录范围：

顺序不能颠倒： 先用未标准化的 $\hat A_t$ 构造 $\hat R_t=\hat A_t+V_{old}(s_t)$，再单独标准化送给 Actor 的优势。若把 $\tilde A_t$ 加到旧价值上作为 Critic 目标，价值尺度就会随 Batch 均值和方差漂移。

操作 对象 主要作用 不能混同之处
Advantage normalization 当批原始优势 调整 Actor 梯度尺度；全批与 Mini-batch 口径不同 不应用标准化优势重建 Critic Return
Reward scaling/normalization 环境奖励或回报统计 控制价值目标量级 会改变 Value、Entropy 等项的相对尺度
Observation normalization 网络输入 改善特征尺度与优化条件 评估时应冻结并复用训练统计
Return normalization Critic 目标 稳定价值学习 需要相应的反标定语义，如 PopArt；不是优势标准化

returns 通常不随新 Critic 在多个 Epoch 中重算。否则价值目标会随优化过程漂移，并且 Actor 优势也失去固定参照。

7. 展平、打乱与 Mini-batch

前馈策略通常将 [T, N, ...] 展平成 [B, ...]，每个 Epoch 重新随机排列索引，再切成 Mini-batch。需要保证所有字段应用同一组索引。

batch_size = num_steps * num_envs
for _ in range(update_epochs):
    permutation = torch.randperm(batch_size, device=device)
    for start in range(0, batch_size, minibatch_size):
        mb_idx = permutation[start:start + minibatch_size]
        # obs/actions/old_log_prob/advantage/return 必须用同一个 mb_idx

若最后一个 Mini-batch 尺寸不一致，要明确是保留还是丢弃。并行机器人训练中，B 很大但样本相关性仍可能高：同一时刻不同环境若初始化和随机化过于同步，不等同于独立同分布的大样本。

循环策略不能随意展平

RNN/LSTM 策略需要按连续序列切块，并携带每段初始隐藏状态。Episode 边界处的隐藏状态应重置或 mask；把时间步完全随机打散会破坏记忆语义。Recurrent PPO 见 改进算法与研究地图。

8. on-policy 的准确含义

PPO 并非“每个样本只能做一次梯度更新”。它允许：

  1. 用当前冻结策略采一批数据；
  2. 在这批数据上做多个 Epoch；
  3. 依靠新旧概率比和近端机制控制批内复用造成的偏移；
  4. 更新结束后丢弃这批数据，再用新策略采样。

它不等同于将旧批次放入 Replay Buffer，在策略已改变许多轮之后继续训练。跨迭代复用若没有额外校正，会使重要性权重、优势估计和状态分布都严重过时。

9. 可否证的数据管线测试

手工轨迹测试

构造 2 个环境、4 个时间步的固定奖励和值函数：

  • 环境 A 在第 2 步真终止，验证末值被置零且 trace 不越界；
  • 环境 B 在第 3 步时间截断，验证使用截断前末状态价值，但 trace 不接到 reset 初态；
  • 令 $\lambda=0$，结果应等于一步 TD 残差；
  • 在无边界且 $\lambda=1$ 时，与相同折扣定义的 Monte Carlo 形式对照。

Storage 不变量

  • 每次更新前 obs/actions/old_log_prob/old_value/advantage/return 的首维样本数一致；
  • 所有用于 ratio 分母的 old_log_prob 不含梯度；
  • returns - old_value 与保存的未标准化 advantage 一致，标准化优势只进入 Actor；
  • Episode 边界后第一步的 GAE 不受上一 Episode 奖励影响；
  • 用测试覆盖所选 autoreset 模式；Same-Step 必须从真实末观测 Bootstrap，Next-Step 必须屏蔽 reset 步的伪转移；
  • 若环境同时报告 terminated=True 与 truncated=True，按真终止优先令 Bootstrap mask 和 trace mask 都为 0，并在适配层写明规则；
  • 多 Epoch 前后 Storage 内容哈希或数值保持不变；
  • 每个 Epoch 的索引覆盖预期样本数，且字段索引完全对齐。
