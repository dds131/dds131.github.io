机器人反馈数据首先是一个时序与来源追踪问题，然后才是 Loss 问题

只保存“人接管了”远远不够。必须知道策略生成了什么、机器人实际执行了什么、人何时看到风险、接管何时生效，以及标签对应动作、片段还是整条轨迹。

一、三种标签结构，加一种原始事件来源

pairwise、binary、scalar 描述的是标签结构；intervention 描述的是反馈怎样产生。它们不是互斥的四个算法类别：一次接管事件可以派生出动作示范、二元可取性标签或标量代价。数据契约至少同时记录三个轴：来源（人/AI/规则）、粒度（动作/chunk/片段/轨迹）和标签结构。

1.1 成对偏好

\[(c,\tau_A,\tau_B,\ell),\qquad \ell\in\{A\succ B,\ B\succ A,\ \mathrm{tie},\ \mathrm{invalid}\}.\]

适合视频或轨迹回放比较。上下文 $c$ 应包含任务语言、初始状态、评价维度和必要的环境条件。若两个轨迹任务条件不同，偏好可能反映难度而不是策略质量。标准二元 Bradley–Terry 或 DPO 目标可直接消费前两类严格偏好；tie 与 invalid 必须按预先声明的规则丢弃、转成软标签或交给显式支持平局的模型，不能静默当作普通负例。

1.2 二元好坏

\[(c,u,y),\qquad y\in\{\mathrm{desirable},\mathrm{undesirable},\mathrm{unknown}\},\]

其中 $u$ 可以是动作、chunk、片段或轨迹。它适合点赞/点踩、人工确认的纠正动作和接管前候选失败动作；unknown 用于保存证据不足而不是强迫二分类。KTO/APO 可使用不严格配对的二元数据，但训练前仍要明确怎样处理 unknown。

1.3 标量评分

\[(c,\tau,s),\qquad s\in\mathbb R\]

要明确评分量表：成功、安全、效率是一个总分还是三个维度。若 $s$ 来自 1–5 级 Likert 量表，它默认只有顺序意义；除非给出锚点样例、评价者校准或统计模型，否则不同评价者的 4 分未必可直接比较，也不能默认“5 与 4 的差”等于“3 与 2 的差”。

1.4 干预事件

接管日志至少记录观察到风险、发出请求、接管生效、释放控制、触发来源、策略生成动作、下发动作、人工动作和最终执行动作。它可以进一步转成示范、二元标签或 reward/cost，但原始事件不可被派生标签覆盖。

反馈 最小字段 适用方法 主要风险
Pairwise 标签 context、A、B、label、rubric 严格偏好子集可用于 BT RM、DPO、TPO 条件不匹配；tie 处理不一致
Binary 标签 sample、粒度、label、来源 KTO、APO 类别不平衡、误标、unknown 被强制二分
Scalar 标签 sample、score、rubric、scale RM、reward shaping 把序数标尺误当等距标尺
Intervention 事件 多时钟时间、动作来源、切换状态、派生规则版本 可派生 APO、RLIF、BC 数据 反应延迟和因果错位

二、机器人 episode 的最小记录结构

类别 字段示例 为什么必须保存
标识 episode、task、robot、scene、object、session 支持分组切分与复现
版本 policy/reference/RM checkpoint、代码与环境版本 判断数据由哪个系统产生
时钟 timestamp、clock domain、同步偏差 避免把不同设备的时间值直接相减

动作 generated、commanded、executed、单位、坐标系 区分模型输出、下发命令与真实执行
动作变换 反归一化参数、限幅、安全层、低层控制频率 复现从模型输出到执行器命令的映射

最重要的动作链：`generated → commanded → executed`。模型输出可能被反归一化、限幅、插值、低层控制器或安全层改写；只记录模型输出，会把没有真正发生的动作当成环境证据。三个动作还必须共享可核对的单位、坐标系和时间基准。

三、接管怎样变成 APO 式偏好

HAPO/APO 论文的标签构造是：

  • 专家示范与未被重标的交互动作使用 $c=1$。
  • 人工接管后的纠正动作使用 $c=2$。
  • 每次接管前 $K$ 步策略动作被重标为 $c=0$，作为 undesirable。
  • 优化时把 $c\ne0$ 作为 desirable 分支，把 $c=0$ 作为 undesirable 分支。

论文实验设置 $K=10$，并采用 50% expert、25% intervention、25% failure action 的 batch 比例。这些是论文在其控制频率、延迟和任务上的设置，不是可以跨平台照抄的常数。

接管数据的价值是同时暴露策略错误和人工修正。但在通用数据契约中仍应保留原始控制来源与派生标签：论文的 $c=1/2/0$ 是训练规则，不等于所有未触发接管的自主动作都被人逐一验证为正确；“接管前 $K$ 步”也只是因果位置的近似，不意味着其中每个动作都错误。

四、反应延迟：负样本窗口的根本噪声

令 $t_{observe}$ 是操作者观察到风险的时刻，$t_{request}$ 是发出接管请求的时刻，$t_{effective}$ 是人工命令真正开始生效的时刻，则

\[d_h=t_{request}-t_{observe},\qquad d_c=t_{effective}-t_{request}.\]

若只有延迟统计量，可以用

\[\hat t_{cause}=t_{effective}-(\hat d_h+\hat d_c)\]

作为候选因果窗口的中心，而不是致因动作的真值。真实 $d_h$ 会随任务、操作者与风险明显程度变化，环境接触后果本身也可能延迟显现，因此固定窗口存在双向错误：

  • 窗口太短：漏掉真正导致接管的动作。
  • 窗口太长：把正常靠近、观察或准备动作误标为失败。

可用三类改进：风险事件检测、随时间距离衰减的软权重、操作者回放修订。无论采用哪一种，都要保留估计区间、原始事件与派生标签的版本关系；不同设备时间戳还必须先完成时钟同步。

五、动作块必须记录已执行前缀

VLA 常一次预测 $C$ 个动作：

\[\mathbf a_{t:t+C-1}=(a_t,a_{t+1},\ldots,a_{t+C-1})\]

接管可能发生在 chunk 中间。此时应分为：

  1. 已执行前缀：产生了真实环境后果。
  2. 被取消后缀：模型生成但未执行。
  3. 人工纠正动作：新控制来源。

被取消后缀可用于分析策略意图或构造明确标注的反事实候选，却不能当作具有真实环境后果的失败轨迹。凡是声称从已执行行为学习环境回报或策略 log-prob 的损失，都应使用 executed_mask 排除未执行后缀；若某个目标专门学习“未执行但危险的意图”，必须另设标签并避免与 executed data 混写。

六、偏好界面怎样减少人为偏差

  • 左右视频随机交换，避免位置偏差。
  • 同步播放、相同速度、相同裁剪和视角。
  • 明确评价维度：成功、安全、效率或综合偏好。
  • 提供“相同”“都失败”“无法判断”，避免强迫二选一。
  • 插入重复 pair 估计评价一致性。
  • 记录观看次数与响应时间，识别过快或异常标注。
  • 多评价者样本保留每个原始标签，不只保存多数票。

七、数据质量的六个检查面

标注者差异

安全偏好、速度偏好和熟练度不同，需要重复样本和匿名评价者标识。

选择偏差

只标最明显失败会缺少决策边界附近样本，可用不确定性或分歧主动查询。

长度偏差

长轨迹包含更多事件和概率项，比较前要统一终止和有效 mask。

类别不平衡

纠正动作通常远少于正常动作，采样后分布必须与原始分布同时记录。

轨迹泄漏

同一 episode 的重叠片段不能跨集合；近重复场景、对象、初态与评价会话也要按评测目标分组。

版本漂移

新策略产生新失败模式，旧偏好数据不能永久代表当前策略分布。

八、Balanced Sampling 的正确理解

接管纠正数据稀少，若按原始频率随机采样，梯度会被大量普通动作淹没。Balanced sampling 让 expert、corrected 与 undesirable 样本获得可控比例，但它不会让标签本身更准确，并且会把训练分布从原始 $p(x,y)$ 改成采样分布 $q(x,y)$。

若目标仍是原始数据风险，在 $q(x,y)>0$ 覆盖所有 $p(x,y)>0$ 样本的条件下，可使用重要性修正：

\[\mathbb E_{p}[\ell(x,y)] =\mathbb E_{q}\!\left[\frac{p(x,y)}{q(x,y)}\ell(x,y)\right].\]

如果不乘 $p/q$，优化的就是有意重加权后的目标。这可以是合理设计，但报告中应明确“提高少数类权重”和“无偏估计原始风险”是两件事。

训练记录至少包含：

  • 原始样本数和比例。
  • 采样后的 batch 比例。
  • 是否使用重要性权重，以及权重裁剪规则。
  • 每类 loss、准确率和动作误差。
  • 重复采样次数，避免极少数样本被过拟合。

九、从采集到训练的数据流水线

flowchart LR
  A[原始 episode + 时间戳] --> B[同步与完整性检查]
  B --> C[片段 / chunk 切分]
  C --> D[人类比较或接管派生标签]
  D --> E[冲突与低质量过滤]
  E --> F[按 episode / scene / object / session 分组切分]
  F --> G[训练数据 manifest]
  G --> H[RM / DPO / KTO / APO]

每一步都生成新 manifest，而不是覆盖前一步。切分键要与评测主张一致：IID 评测可保留任务分布但隔离 episode；声称跨对象、跨场景或跨操作者泛化时，必须在相应维度留出。这样出现标签策略错误时可以回到原始日志重新派生，也不会因为重切片而污染测试集。

十、知识点、重点与创新点

10.1 知识点

  • 来源、粒度、标签结构三个数据轴。
  • generated、commanded、executed 与 human action 的区别。
  • 时间对齐、动作块 executed mask、分组切分和标签血缘。

10.2 重点

  • 接管不是准确的失败时间戳。
  • 正负动作通常不处于完全相同物理状态。
  • 数据来源和派生规则是模型可复现性的组成部分。
  • tie/invalid 与未执行动作不能被静默塞进标准二元损失。

10.3 创新点

  • HAPO/APO：从人工接管轨迹派生 action-level binary desirability，并结合平衡采样与连续动作误差自适应重加权。
  • Uni-RLHF：提供多反馈标注平台、众包数据集与模块化离线 RLHF baseline。
  • B-Pref：以参数化的模拟 teacher 构造误标、短视、跳过和平局等条件，用于压力测试偏好 RL；它不是对真人行为的直接测量。
