π0.5 的核心问题是：把机器人放进训练时未出现的家庭环境，它能否理解陌生场景、物体和长指令，并持续完成「收拾厨房」「整理卧室」一类多阶段任务？研究重点由同分布技能执行扩展到开放世界泛化。这里的“开放世界”仍受论文评测范围限制，并不等于已经覆盖任意机器人、任意家庭与任意任务。

六类共训练数据来源

本专题的事实口径。凡带具体数值的说法，来源只有两类：一是 π0.5 论文（arXiv:2504.16054）正文与附录，二是 openpi 官方仓库的源码与 README，文中逐条标出章节或文件。第三方解析只用作线索，与前两类冲突时以官方为准。论文没有单独消融过的改动，本专题只陈述结构事实与设计动机，不声称它独立贡献了多少性能。
必须先建立的一个区分。当前 openpi 仓库中的 pi05=True 模型分支不等同于论文完整训练与分层推理配方（FAST 离散预训练 + 流匹配后训练 + 高层子任务预测 + 异构共训练）。官方 README 明确写着：仓库目前只支持 π0.5 的流匹配头训练与推理。逐条差异见 ⑦ 论文与实现的差异。
本站有一个 π0.5 的真机落地案例。在睿尔曼 RM75-B 七自由度机械臂上做全参后训练与单卡部署， 含数据转换、三轮训练配置对比、四终端实时控制与动作块间轨迹平滑；最终配置在该项目定义的 100 次随机取放验收中成功 92 次。这个数字是特定平台与验收口径的工程结果，不是 π0.5 论文的开放世界指标。 见 VLA 视觉-语言-动作模型训练与真机部署。 本页只讲方法本身，工程落地的参数与踩坑在那边。

十个核心问题：按问题找页面

把 π0.5 学成「一篇论文的摘要」意义不大。更有用的是能回答下面十个问题，并按问题性质区分论文证据、数学关系、网络结构与当前源码；并非每一问都同时存在这四类证据。下表给出各问题的主要落点，可用作读完后的自检清单。

# 问题 落在哪一页哪一节
1 为什么传统行为克隆在开放世界下会失败 ① 第二节：失败的三种形态，以及它们为何不是运动控制问题
2 为什么跨本体数据能提高泛化 ① 第六节：去掉 ME 或 CE 的消融，以及「贡献显著的数据其本体与评测平台并不相同」这一点
3 为什么网络图文数据能改善陌生物体上的语言接地 ① 第七、八节：端到端不显著而语言跟随显著变差的成因，以及逐任务拆解
4 为什么 FAST 更适合大规模训练，却不适合高频实时控制 ③ 第二节：朴素逐时间步分箱的信息问题、FAST 的压缩方式，以及 FAST 论文特定硬件与模型口径下约 750 ms 对 100 ms 的对照
5 为什么流匹配更适合连续动作块 π0 专题（本专题不重讲）：π0 · Flow Matching 动作生成；π0.5 侧只在 ③ 第二节给出与离散路线的代价对照
6 为什么 π0.5 同时需要离散动作与连续动作 ③ 第二节提出取舍，第八节给出论文的证据
7 两个专家到底怎样通过注意力交换信息 ② 第二节：Q/K/V 沿序列轴拼接后联合注意力、三条 assert 的由来；第五节：掩码的六段结构与信息单向流动
8 state 从连续 suffix 移到离散 prefix 后，结构与代价怎样变化 ② 第四节：论文明确给出的改动、可由掩码推出的结构含义、量化与长度代价；论文没有单项消融或完整动机说明
9 adaRMSNorm 怎样把时间条件注入动作专家每一层 ② 第六、七节：两种注入形式、逐层调制与零初始化边界；缓存收益只作工程推断，不冒充论文动机
10 动作损失为何可能干扰 VLM，知识隔离怎样改变梯度路径 ④ 第三节给论文假说，第五节给停梯度矩阵、离散目标的前置条件，以及 KI 论文令 \(\alpha=1\) 的适用口径

第 5 问的落点值得单独说明，因为它体现了本专题的一条编写原则：π0.5 沿用而未改动的机制，一律不在本专题重讲。流匹配为什么适合连续动作块，是 π0 已经解决的问题，完整推导在 π0 专题；本专题只讲 π0.5 在此之上新增的取舍——即「训练期为什么还要再来一套离散表示」。

其余九问都落在本专题内，说明这十问所覆盖的知识点没有缺口。

README 在介绍 π0.5 的那一句里同时给出了两条关键信息：当前公开的 π0.5 是以知识隔离方法训练的升级版，以及本仓库对 π0.5 的训练与推理目前只支持流匹配头。前者对应 ④，后者对应 ⑦。

一、它要解决什么问题

π0 建立了「预训练 VLM 主干 + Flow Matching（流匹配）动作专家 + 动作块」这套架构。π0.5 论文把重点放到未参与训练的真实家庭，并把失败分析从低层控制扩展到语义理解、任务分解与陌生中间状态。下列三类是分析维度；一次失败可能同时涉及多类，不能据此排除低层控制误差。

  • 语义接地失败。模型可能无法把陌生外观的物体与指令中的类别、用途或目标位置对应起来。
  • 任务分解失败。整体指令没有显式拆成当前可执行步骤时，策略容易依赖训练轨迹中的常见顺序，难以适应不同初始状态。
  • 陌生中间态恢复失败。长任务产生的状态组合很难被演示穷尽；策略偏离示范轨迹后，可能重复、停滞或选择不合时宜的下一步。

增加同分布遥操作数据仍可能改善动作稳定性，但不能保证覆盖陌生物体语义与长任务的组合状态。π0.5 的方法选择是：用网络图文和跨本体机器人数据拓宽监督，再用显式子任务提供可读的中间决策；论文实验支持这些方向，却不证明它们是唯一可行方案。

于是有了两条主线：训练侧引入异构数据共训练（co-training），推理侧引入分层推理（hierarchical inference）。这两条主线的展开分别见 ① 开放世界泛化与数据配方 与 ⑤ 分层推理与长时程执行。

二、开放世界泛化的定义与评测口径

「泛化」如果不定义清楚，很容易退化成「测试分数更高」。下面把论文评测关注点拆成几个可区分但并不统计独立的维度，便于判断变化究竟来自环境、物体、指令还是任务时长。

泛化维度 变的是什么 失败时的典型表现
环境泛化 整套家具布局、光照、地面与台面材质 空间关系判断错，伸向不存在的位置
物体实例泛化 同类别但外观不同的杯子、衣物、餐具 抓取姿态套用了训练集里同类物体的模板
任务组合泛化 同一环境里换一句指令、换一个目标顺序 执行环境里最常见的那条轨迹，不跟随指令
长时程完成度 任务步数变长、中途出现未见过的中间态 在某一步卡死或反复重试同一个动作

评测方式上有两点与常规做法不同，值得单独记录。

  • 不用二值成功率作为唯一指标。 论文用的是任务推进度（task progress）：按附录 A-B 的逐步骤细则打分，报告为「该次试验拿到的分数占该任务满分的百分比」。理由是一个能做完八成步骤的策略与一个第一步就卡住的策略，在二值指标下都算失败，工程价值却完全不同。举个按细则算出来的例子——碗碟入水槽的细则是「每拿起一件 +1、每放入水槽一件 +1，4 件碗碟满分 8 分」，那么把其中两件拿起并放进水槽就得 4 分，即 50%（此例为本站按论文细则推算，论文未直接给出这个说法）。四套细则的完整分值见 ① 开放世界泛化与数据配方。
  • 评测环境与训练环境在物理上分离。 论文 V-A 在三个未进入训练集的真实家庭中评测，每个家庭包含卧室和厨房任务；另设便于反复对照的仿制家庭场景。后者用于受控实验，不能替代真实家庭结果，也不能据此推断任意家庭的表现。

泛化维度的完整定义、语言跟随评测的具体设置，以及泛化随训练场所数量增长的 scaling 趋势，见 ① 开放世界泛化与数据配方。

训练部分来自论文 IV-C 与 IV-D：预训练使用五类数据和交叉熵，后训练加入随机初始化的动作专家并令 α = 10.0。推理部分只表达一次两层调用及后续会再次观测；论文没有说明每个 50 步候选动作块实际执行多少步，也没有说明高层文本每次低层查询都重解还是跨调用复用。

三条需要记住的结论：

  1. 两阶段不是「预训练加微调」的常规说法，而是动作表示换了一次。 阶段一把动作也当成离散 token 来预测（用 FAST 分词器），阶段二才引入连续动作专家。论文给的理由是：离散 token 训练效率更高，但自回归解码不适合实时控制，所以训练时用前者、执行时用后者。完整论证见 ③ 两阶段训练与组合损失。
  2. 动作专家在后训练阶段才随机初始化加入。 这与 π0 全程使用动作专家不同，是 V-D 所概括的整体配方差异之一；该实验没有把这一项单独消融。证据边界见 ⑧ 从 π0 到 π0.5 的演进对比。
  3. 分层不等于刷新节奏已知。 系统后续会基于新观测继续调用，但论文未披露候选动作块实际执行多少步，也未披露子任务文本的重解频率；不能把“输出 50 步”自动写成“完整开环执行 50 步后重解高层”。见 ⑤ 分层推理与长时程执行。

四、六类共训练数据

论文 IV-C 给出预训练用的五类数据，IV-D 的后训练再加一类并去掉其中一类，合计六类。下表只给定位与一句话说明，每类的监督信号形式、补的是哪种能力、缺了会怎样，以及对应的消融结果，都在 ① 开放世界泛化与数据配方。

缩写 全称 一句话说明 预训练 后训练
MM Diverse Mobile Manipulator data 约 400 小时移动操作数据，覆盖约 100 个不同家庭环境，与评测任务最直接相关 有 有
ME Diverse Multi-Environment data 固定在台面或支架上的单臂、双臂机器人数据，本体与移动平台不同，但能覆盖更多种家庭 有 有
CE Cross-Embodiment laboratory data 实验室条件下多种机器人、多种任务的数据，含开源 OXE 数据集，是 π0 所用数据集的扩展版 有 无

一条结论：这六类数据的作用并不等价，而且各自的失效方式不同。 论文 V-C 的消融显示，去掉 ME 或 CE 会让端到端任务表现明显下降；去掉 WD 在端到端任务上的差异不具统计显著性，但在陌生物体的语言跟随上明显变差。这一现象的成因分析见 ①。

五、分层推理

π0.5 在推理时明确分成两层：先用离散 token 自回归地写出下一个应该执行的子任务文本，再把这段文本作为条件，由动作专家用 Flow Matching 生成连续动作块。同一个模型承担两层，不是两个独立模型。

论文 IV-A 把这件事写成一个分布分解：

\[\pi_{\theta}\!\left(\mathbf{a}_{t:t+H},\hat{\ell} \mid \mathbf{o}_{t},\ell\right) = \pi_{\theta}\!\left(\mathbf{a}_{t:t+H} \mid \mathbf{o}_{t},\hat{\ell}\right)\, \pi_{\theta}\!\left(\hat{\ell} \mid \mathbf{o}_{t},\ell\right)\]

其中 \(\ell\) 是用户给的高层指令，\(\hat{\ell}\) 是模型生成的子任务文本。右边第一项不再显式以 \(\ell\) 为条件，表示论文采用了条件独立假设 \(\mathbf{a}_{t:t+H}\perp\!\!\!\perp\ell\mid(\mathbf{o}_t,\hat\ell)\)。这不是一般概率链式法则自动保证的性质；把 \(\hat\ell\) 边缘化后，动作仍会通过高层分布间接依赖原始指令。展开见 ⑤。

三条结论：

  • 两个出口采用不同表示。 子任务是语义量，适合用词表 token 和交叉熵，并保留人可读性；动作是连续高频物理量，离散自回归既有量化误差又有逐 token 延迟，因此由流匹配在每个积分步并行处理整个动作块，默认做 10 次速度场评估。
  • 可读中间量改善诊断，但不能唯一定位根因。 不合理的子任务提示高层问题；子任务合理而执行失败提示低层问题。不过图像表征、数据分布与控制误差可能共同影响两层，两类修复路径并非互不干扰。
  • 训练期的高层数据本身有价值。 论文 V-E 的聚合结果中，保留高层训练数据但运行时不显式生成子任务的 implicit HL 位居第二；这说明显式解码有额外收益，同时相当一部分收益可在训练混合中获得。该排序来自有限任务，不是普遍规律。

六、相对 π0 的两处结构差异

抛开训练、数据变换和高层推理，Pi0Config 把 π0.5 模型分支相对 π0 的结构差异概括为两处。这对应 src/openpi/models/pi0_config.py 的注释 Pi05 has two differences from Pi0；“两处”不是整个系统改动的总数。

差异 π0 π0.5 详见

想看完整的网络结构图（从多路图像与本体状态一直画到动作块，含 18 层双专家主干的层内展开），以及覆盖全部十七个模块的逐模块拆解表（每个模块的作用、设计理由、源码符号，并标明它是继承自 π0 还是 π0.5 改动），见 ② 网络架构与结构差异 第九节。本页只给上表这两处最核心的差异。

π0.5 沿用的主线包括：PaliGemma 与 SigLIP、动作专家和 VLM 在同层联合注意力中交换信息的双专家结构、Flow Matching 目标与直线路径，以及默认 10 步欧拉积分。论文基础配置的动作时域为 50，但公开微调配置可以覆盖为 15 或 10，因此“沿用动作块机制”不等于所有 checkpoint 的长度都固定为 50。继承机制的推导见 π0 · 网络架构与双专家、π0 · Flow Matching 动作生成。

七、训练目标

论文 Eq. (1) 给出的联合目标是交叉熵与流匹配的加权和：

\[\mathbb{E}_{\mathcal{D},\tau,\omega}\Big[\, \underbrace{H\big(x_{1:M},\,f^{\ell}_{\theta}(\mathbf{o}_{t},\ell)\big)}_{\text{离散项：文本、边界框、子任务、FAST 动作 token}} \;+\;\alpha\, \underbrace{\left\lVert \omega-\mathbf{a}_{t:t+H}-f^{a}_{\theta}\!\left(\mathbf{a}^{\tau,\omega}_{t:t+H},\mathbf{o}_{t},\ell\right)\right\rVert^{2}}_{\text{连续项：流匹配速度场回归}} \Big]\]

\(\alpha\) 是两阶段目标函数的一个关键差别：

阶段 \(\alpha\) 步数 实际在优化什么
阶段一 · 离散预训练 0 280k 只有交叉熵；动作也以 FAST token 的形式进入交叉熵项
阶段二 · 联合后训练 10.0 80k 交叉熵与流匹配联合；动作专家此时才随机初始化加入

两阶段并非只差 \(\alpha\)：阶段一没有动作专家，使用 MM / ME / CE / HL / WD；阶段二才加入动作专家，数据换为 MM / ME / HL / WD / VI。所以上表只解释损失权重，不能被读成其余训练条件完全相同。

三点必须注意，否则很容易读错：连续项里写的是 \(\omega-\mathbf{a}\) 而不是 \(\mathbf{a}-\omega\)；论文的流匹配时间方向与 openpi 源码相反；离散项里的 \(x_{1:M}\) 同时包含语言、边界框、子任务与 FAST 动作四种 token。这三点的完整说明与代换关系见 ③ 两阶段训练与组合损失。

十、工程要点与局限

按实际踩坑概率排序，详细成因见括号内的子页。

  • 状态未按训练统计量归一化。 当前离散化使用 \([-1,1]\) 上的等距边界，但 np.digitize 前没有在该处显式 clip；超界值会落到异常或端部代码，破坏状态语义。应先核对归一化统计量与分量顺序，不能只做粗暴截断（②、⑥）。
  • prompt 超过默认 200 token。 tokenizer 会发出 warning 后截断，并非静默处理；状态整数串、指令和控制标记都要计入预算。若自行实现高层回灌，应按论文条件重建低层 prompt，并检查 Action: 等末尾标记是否被截掉（②、⑤、⑥）。
  • 用 π0 检查点初始化 π0.5。 suffix 结构不同、adaRMS 参数在 π0 权重里不存在，应从 pi05_base 加载（⑥）。
  • 把论文配方当成当前 π0.5 路径。 仓库里能找到服务于 π0-FAST 的 FASTTokenizer，但当前 pi05 数据路径没有把它接入论文两阶段配方；高层文本解码也未公开，现有 π0.5 训练与推理只支持流匹配头（⑥、⑦）。

局限

  • 高层子任务在训练时有 HL 等标注监督，但部署时没有独立的在线验证器；子任务选错后，论文没有给出显式的自检与纠错机制。
  • 状态离散化会引入归一化坐标误差；物理误差大小取决于各分量的反归一化尺度、传感器与控制器，不能仅凭“256”直接断言力控或亚毫米定位上限。
  • 开源实现只覆盖流匹配这条路径，复现完整的分层推理需要自行搭建高层解码与回灌逻辑。

下一步可看 π0.6：关注点从 π0.5 的开放世界共训练与分层推理，进一步扩展到如何把执行经验回收为训练信号。两者研究问题相接，但不能把后者简单等同于已经彻底解决高层子任务纠错。
