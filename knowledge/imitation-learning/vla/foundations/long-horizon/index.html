专题总览 6 训练与适配 7 长时序任务 8 统一评测

长时序能力不是“模型一次想得更远”，而是不同时间尺度的模块通过可验证接口反复观察、选择、执行、核验、恢复并终止。任务、技能/子目标、动作块和底层控制具有不同的时钟、证据与责任边界；只有把这些边界写成契约，系统才有可能在失败后作出有依据的改变。

  • 至少拆开四个时间尺度。 Task、skill/subgoal、action chunk 与 control 不能共用一个“动作完成”状态。
  • Planner 输出只是候选。 文本或目标图像必须通过 grounding、affordance、schema、资源和安全校验。
  • 记忆与世界模型都不是环境真值。 最新观测、权威成功谓词与独立安全控制器仍有更高优先级。
  • 恢复必须有限且有变化。 重试前要获得新证据或改变条件，并保留预算、升级与安全终点。
  • Planner 自报成功的权威任务结果为零。 Task success 只能来自冻结的环境谓词或授权人工核验。

本页只设计架构、研究和受控评测证据，不调用模型，不运行规划、仿真或真机动作，不上传文件，也不生成可直接部署的机器人参数。

时间抽象：Task、Skill、Action 与控制不是同一尺度

七类对象

| 对象 | 回答的问题 | 典型输出 | 时间/触发 | 完成证据 | | — | — | — | — | — | | Task / user goal | 最终要改变什么 | 任务谓词、约束、优先级 | trial/session | 环境或人类权威成功 | | Plan | 先后做哪些步骤 | 有序/分支 skill calls | 事件或阶段 | 所有必要子目标满足 | | Subgoal | 下一阶段应达到什么状态 | 文本、图像、对象、位姿、谓词、latent | 高层刷新 | subgoal predicate | | Skill / option | 用哪段闭环行为改变状态 | 参数化策略/原语调用 | 秒级或事件 | termination + postcondition | | Action chunk | 策略接下来建议哪些动作 | H 个动作/分布 | policy inference | 只表示生成完成 | | Command | controller 接收什么目标 | position/velocity/torque 等 | command rate | controller acknowledgement | | Servo update | 执行器怎样闭合误差 | 控制量 | control rate | 底层状态/故障 |

所有时间都是项目/模型特定值。页面只用相对层级，不给“skill 必须 1 秒、task 必须 10 分钟”的通用数值。

Skill/Option 的最小形式

借用 Options 框架的通用语义，将 skill 表示为：

Skill = (InitiationSet, Policy, Termination)

工程上扩展为：

SkillContract = (name, typed_args, precondition, controller/policy, postcondition, termination, failure, timeout, resources, owner)

这只是接口抽象，不要求系统必须用 HRL 或 Option-Critic 训练。固定解析原语、行为树节点、冻结 VLA 调用和学习策略都可实现同一契约。

五类时间

  1. 数据时间：示范中 observation/action 的时间戳与采样率。
  2. 模型时间：历史窗口、prediction horizon 和推理时延。
  3. 执行时间：执行前缀、command rate、servo rate。
  4. 任务时间：skill/subgoal 生命周期和整体 deadline。
  5. 系统时间：网络、队列、异步 world model/memory 的陈旧度。

页面用一条共同时间线展示 t_observe ≤ t_plan ≤ t_dispatch ≤ t_execute ≤ t_verify。每次决策记录观测年龄；时间戳来自不同时钟时必须先同步或标未知。

周期、事件与混合刷新

| 刷新方式 | 触发 | 优点 | 风险 | | — | — | — | — | | periodic | 固定 wall-clock / steps | 易预算 | 无事件也重复，事件间反应慢 | | event-driven | success/failure/contact/new object 等 | 语义清楚 | 漏事件会卡死 | | horizon-based | 执行动作块前缀后 | 与 policy 对齐 | 不代表 subgoal 完成 | | progress-based | 停滞/偏离达到阈值 | 能发现隐性失败 | 指标/窗口不稳会抖动 | | hybrid | 周期上限 + 事件提前 | 更完整 | 状态机更复杂 |

必须定义 debounce、cooldown、minimum dwell 和 maximum staleness，避免连续重规划和目标抖动。

prediction、execution 与 task horizon

  • prediction horizon：模型一次预测多少未来动作。
  • execution horizon：实际下发其中多少动作后重新观察。
  • skill horizon：当前技能允许持续多久/多少次 chunk。
  • planning horizon：Planner 考虑多少阶段或候选。
  • task horizon：trial 从 reset 到成功/终止的整体跨度。

prediction horizon ≥ execution horizon 常见但不是定律；任何不等式都要由具体 runtime 说明。动作块长只能降低模型调用频率或提供局部一致性，不能自动解决阶段记忆、任务分解和恢复。

资源与并发

每个 skill 声明：

  • arm/base/gripper/camera 等 resource locks；
  • 能否与 world model、感知或 memory 异步并发；
  • 谁可取消；
  • 取消后 controller 状态；
  • timeout owner；
  • 跨线程共享的 observation/version；
  • 双臂/移动底盘的互斥与同步。

Planner 不得在旧 skill 未完成或未安全取消时向同一资源并发下发不兼容命令。

时间契约先于模型调用。 每层对象都需要稳定 ID、输入版本、输出版本、时钟源、最大年龄、预算与 owner。Planner 读取的 observation、skill router 接收的 subgoal、controller 消费的 command 必须能沿同一决策轮次关联；若时钟未同步或 observation age 超过上限，系统进入刷新或停止分支，不能把缺失时间戳当作零延迟。

资源锁应采用可审计 lease，而不是进程内布尔值。lease 记录资源、持有者、plan/skill call ID、开始与到期时间、取消协议和释放证据；双臂、移动底盘与相机云台的共享约束必须在 validator 阶段解决。冲突默认拒绝，不能依赖“通常不会同时发生”。取消后还要等待 controller acknowledgement，确认队列和硬件状态已进入允许下一 skill 的边界。

五类时间要在 trace 中分别记录。数据时间解释 observation/action 对齐；模型时间解释历史与推理；执行时间解释 prefix、command 与 servo；任务时间解释 deadline 和阶段；系统时间解释队列与异步结果。只报告平均模型延迟会漏掉排队、陈旧结果、取消和验证耗时。任何异步输出都携带它计算时使用的 observation version，消费者拒绝已被更新状态超越的结果。

H、E、skill budget 与 task deadline 的单位必须显式。改变 policy rate 后，按 step 表示的 horizon 对应 wall-clock 会变化；改变 chunk overlap 后，有效执行长度也会变化。审计应把动作表示页的值原样接入，而不是在这里重新猜测。用三组反例验收：H 大但 E 小、H 与 E 相等、事件在 E 完成前触发取消，确认每种路径都能回到最新观察。

本节验收门禁。

  • Task 与 Plan 分开。
  • Plan 与 Subgoal 分开。
  • Subgoal 与 Skill/Option 分开。
  • Skill 与 Action chunk 分开。
  • Action chunk 与 Command/Servo 分开。
  • 每层输入明确。
  • 每层输出明确。
  • 每层 trigger/clock 明确。
  • 每层 owner 明确。
  • 每层 budget 明确。
  • 每层 completion evidence 明确。
  • Skill 有 typed arguments。
  • Skill 有 initiation/precondition。
  • Skill 有 policy/controller owner。
  • Skill 有 postcondition。
  • Skill 有 termination。
  • Skill 有 failure/timeout。
  • Skill 有 resource locks/cancellation。
  • Options 只作通用接口抽象，不强制 HRL。
  • 数据、模型、执行、任务、系统时间分开。
  • observation age 可计算。
  • periodic/event/horizon/progress trigger 分开。
  • debounce/cooldown/staleness 可配置。
  • prediction horizon 与 execution horizon 分开。
  • skill/planning/task horizon 分开。
  • action chunk 未被写成长时序规划。
  • 并发资源冲突默认拒绝。

时钟验收至少覆盖正常同步、固定偏移、漂移、乱序和缺失五种情况。固定偏移可以通过已验证转换修正，持续漂移需要重新同步，乱序事件应进入缓冲或拒绝，缺失时间戳只能标 unknown。比较 observation age 时使用同一单调时钟域；wall-clock 只用于跨系统审计，不能直接参与实时 deadline。若 planner 与 controller 使用不同机器，转换参数也作为版本化制品进入 trace。

任务层预算向下分配但不被低层自行扩张。Planner 可为 skill 分配 duration、attempt 与资源额度，skill 再为 chunk 和 command 留出余量；任何层超时都返回明确 failure，而不是把 deadline 更新为“从现在重新开始”。暂停、人工接管和安全 stop 是否消耗预算必须预注册。通过故意让下层接近 timeout、上层同时 replan 的竞态测试，验证只有一个 owner 能提交最终状态。

并发取消需验证三件事：旧请求不再产生新 command，已排队 command 被撤销或明确耗尽，资源 lease 只在 controller 确认后释放。若取消不可抢占，系统必须等待安全边界或触发独立 stop，不能假装即时完成。相机和感知任务虽不直接驱动执行，也可能改变 observation version；因此异步结果写回时要做 compare-and-set，避免旧检测覆盖较新的场景状态。

Planner–Policy 分层：从语言意图到可执行技能

六种子目标表示

| 表示 | 例子 | 优点 | 缺点/校验 | | — | — | — | — | | language subtask | “打开上层抽屉” | 可读、可记录 | 语义歧义、不可达 | | symbolic predicate | drawer=open | 可验证、适合状态机 | 需 grounding | | object/region | object ID、bbox、mask | 连接语言与视觉 | 漂移、遮挡、身份交换 | | pose/waypoint | frame + SE(3) + tolerance | 几何明确 | 需标定、IK/碰撞 | | goal image/video | 期望未来外观 | 表达丰富 | 不保证动作/物理可达 | | latent goal | learned embedding | 紧凑、可微 | 难解释、需解码/探针 |

页面必须显示“表示”与“完成判定”分开。例如 bbox 指定目标区域，不等于抓取已成功；goal image 指定外观，不等于接触满足。

Planner 输出 schema

自由文本只能作为解释，执行必须通过 schema：

  • skill_name；
  • typed arguments；
  • target entity/version；
  • coordinate frame/units（若适用）；
  • precondition references；
  • expected postcondition；
  • maximum duration/steps/retries；
  • observation version；
  • planner/model/version；
  • confidence/uncertainty（若有）；
  • fallback/escalation；
  • unique call ID。

unknown skill、缺字段、越界参数、未知对象或过期 observation 默认拒绝，不猜测修复后直接执行。

Grounding、Affordance 与验证

三道门分别回答：

  1. Grounding：语言中的对象/关系是否映射到当前观测实体？
  2. Affordance/feasibility：目标机器人在当前状态能否执行该 skill？
  3. Validator：schema、资源、坐标、约束和预算是否允许下发？

可用概念分数：

candidate_score = semantic_relevance × feasibility

该形式来自 SayCan 一类系统的教学抽象，不要求乘法，也不把 score 当安全概率。任一强约束失败都应 veto，而不是被另一项高分抵消。

Planner 与低层 Policy 的信息边界

Planner 可见：

  • 原始 task；
  • 当前 belief/scene/task state；
  • skill catalog；
  • verified memory；
  • recent outcomes；
  • constraints。

低层 Policy 可见范围依架构而定：

  • 原始 task；
  • 当前 subgoal；
  • goal image；
  • target mask/pose；
  • recent observations/state；
  • action history。

若低层只看 subgoal，不看原 task，则需明确条件独立假设和错误传播：低层无法仅凭原指令否决错误子目标。若两者都看，要说明冲突优先级，不能让低层悄悄忽略 Planner。

Skill catalog

每个技能条目至少记录：

  • canonical name 与 version；
  • natural-language aliases；
  • implementation owner；
  • Action ABI；
  • initiation/precondition；
  • supported robots/tasks；
  • termination/postcondition；
  • known failures；
  • expected latency；
  • safety constraints；
  • required observations；
  • evaluation evidence；
  • deprecation/replacement。

Planner 不得动态发明一个没有实现的技能名并视为“规划成功”。

Open-loop 与 closed-loop 计划

Open-loop：

  • 一次生成完整步骤；
  • 中间不读取新观测/回执；
  • 只适用于状态变化可忽略或有严格外部执行器保证的短段。

Closed-loop：

  1. 从最新 belief 提议下一 skill/subgoal；
  2. 校验并执行有限片段；
  3. 读取 outcome、新观测和 authoritative signal；
  4. 更新 belief/memory；
  5. 验证 postcondition/progress；
  6. 继续、重规划、恢复或停止。

“每一步再次调用 LLM”不是充分条件；如果输入仍是旧图像/旧坐标，系统仍是语义上的 open-loop。

模型特定实例框

所有实例带“不是通用默认”：

  • π0.5：同一模型可先生成高层语义子任务，再以该子任务条件低层动作；公开实现支持范围与论文完整分层流程要分开。
  • π0.7：高层策略产生 subtask，世界模型生成视觉目标，低层 VLA执行；视觉目标是期望结果，不是通用动力学仿真。
  • Harness VLA：Planner 在固定原语库中组合解析技能与冻结 vla_act，每次等待回执和新证据；Memory 是外部版本化制品。
  • DexGraspVLA：VLM 负责目标/框和执行核验，低层 diffusion policy 执行抓取；论文频率与公开代码可证事实分开。
  • SayCan：语言相关性与 skill value/affordance 共同筛选技能，是 grounding 思路实例，不是 VLA 唯一 planner。
  • Inner Monologue：环境反馈进入语言规划循环，是 closed-loop high-level feedback 实例，不保证低层安全。

Planner schema 应由版本化 registry 管理，并在生成后、执行前做确定性解析。解析器先验证结构与枚举，再解析 entity/version、frame/unit、资源与预算，最后运行 precondition、affordance 与 safety veto；每一道门保留独立结果。修补自由文本、自动补默认坐标或把未知 skill 映射到相似名称都会改变语义，默认应拒绝并请求重新提议。

Grounding 输出不是一个裸 bbox，而是 entity ID、观测版本、mask/pose、置信与失效条件的组合。相机、对象或底盘移动后，旧实体引用必须重新验证。Affordance 也不是对象类别属性：同一抽屉对不同机器人、当前姿态、占用资源和技能版本可能可行或不可行。硬几何、资源或安全约束失败时，不允许语言相关性或模型 confidence 用高分抵消。

Plan 的每次改变都产生新 plan version，并记录父版本、触发、新证据、保留步骤、删除步骤和新预算。Planner 可以提出分支或候选，但只有当前 active plan 的下一个 typed call 能进入 validator；旧计划返回、并发响应或超时重试不能覆盖新版本。调用的幂等键应由 trial、plan、skill call 和 attempt 组成，防止网络重试导致同一物理动作重复下发。

Closed-loop 的证明来自新证据，而不是调用次数。每段执行后必须读取 controller/outcome、更新 observation 与 belief、验证 postcondition，再决定继续。若 LLM 再次被调用但输入仍是旧截图、旧 memory summary 或未确认的 self-report，trace 应标为 stale-input loop。对低层不看原 task 的架构，还要故意提供错误 subgoal，验证它会被上游门禁发现，而不是期待低层自行理解全局意图。

本节验收门禁。

  • language subtask 被定义并有边界。
  • symbolic predicate 被定义并有边界。
  • object/bbox/mask 被定义并有边界。
  • pose/waypoint 被定义并有边界。
  • goal image/video 被定义并有边界。
  • latent goal 被定义并有边界。
  • 表示与完成判定分开。
  • Planner 输出经过 typed schema。
  • schema 含 skill、args、observation version 和 budget。
  • unknown skill 默认拒绝。
  • 缺字段/越界参数默认拒绝。
  • Grounding、affordance、validator 三道门分开。
  • language relevance 未被当作 feasibility。
  • feasibility score 未被当作安全概率。
  • hard veto 不被高总分抵消。
  • Planner 不直连 actuator。
  • Skill catalog 带 version、ABI、证据和 deprecation。
  • Planner 不得发明未实现技能。
  • 原 task 与 subgoal 的低层可见性明确。
  • 条件独立导致的错误传播明确。
  • low-level 冲突优先级明确。
  • open-loop 与 closed-loop 计划分开。
  • 新调用但旧观测不被称为闭环。
  • 每次执行后读取新证据。

Schema 演进必须向前兼容或显式迁移。新增可选字段、收紧枚举、改变单位、重命名 skill 或调整 postcondition 都创建新版本；Planner、validator 与 router 在同一 call 上记录各自解析的 schema hash。旧 Planner 产生新 router 无法解释的调用应 fail closed。迁移器只转换语法，不应凭空推断语义；无法确定 frame、entity 或单位时返回人工处理。

计划竞争测试可同时注入慢 Planner 响应、人工修改与 monitor 触发。每个提议携带它读取的 belief 和 observation version，提交时用 expected active version 做比较；版本落后则作废并记录，不得覆盖。对于 speculative planning，可提前计算候选但不能越过当前 postcondition 和资源边界。这样既保留并行计算收益，又避免迟到的高层回复让机器人执行已经过时的步骤。

Skill catalog 的证据要绑定 implementation version，而不只绑定名字。一次实现更新若改变 Action ABI、控制器、termination 或支持对象，旧评测不能自动继承。deprecation 指向替代技能并给出截止版本；Planner 查询时只得到与当前 robot、任务、资源和证据等级相容的条目。目录为空或候选全被 veto 是正常可处理状态，应进入请求人或安全停止，而不是让语言模型发明“近似技能”。

记忆与信念状态：记什么、谁写、何时清空

POMDP 视角

单帧观测 o_t 通常不能唯一确定环境/任务状态 s_t。系统维护 belief：

b_t = Update(b_{t-1}, o_t, a_{t-1}, feedback_t)

这里的 b_t 可以是概率分布、RNN/Transformer latent、显式 task state、外部 world map 或它们组合。它是估计，不是真值；必须保留 observation version、更新来源和不确定性。

七类“记忆”

| 类型 | 内容 | 时间尺度 | 读者/消费者 | Reset | | — | — | — | — | — | | observation history | 最近图像/状态/动作 | 短 | 低层 policy | episode/窗口 | | recurrent/latent state | 压缩历史的 hidden/belief | 短至中 | policy/estimator | 明确 reset | | working memory | 当前对象、阶段、候选、预算 | task 内 | planner/monitor | task | | task state | 已完成/待做/失败的谓词 | task 内 | planner/validator | task | | episodic memory | 带来源的过去 trace/summary | 跨 task 可选 | planner/retriever | policy-defined | | semantic/procedural memory | 经审查的规则、技能说明 | 长 | planner | versioned | | spatial/world memory | map、object identity、pose history | 场景/session | grounder/planner | scene reset |

模型参数是长期知识载体，但本页不把它和运行时 memory store 混为一个可写对象。

Memory 生命周期

每个 memory namespace 必须定义：

  1. Capture：从 observation/log/human/模型输出捕获什么。
  2. Verify：由 environment predicate、sensor consistency、人或规则验证。
  3. Summarize：允许怎样压缩，保留哪些反例/不确定性。
  4. Commit：谁批准从草稿写入可读层。
  5. Index：按 task/robot/scene/version 检索。
  6. Read：哪些模块、何时、最多取多少。
  7. Use：检索结果是建议、constraint 还是 executable data。
  8. Update：冲突、过时和新证据怎样合并。
  9. Evict/expire：TTL、容量、撤回与许可证。
  10. Reset：episode/task/session/user/robot 边界。
  11. Audit：来源、作者/模型、时间、hash、适用范围。
  12. Rollback：坏记忆如何隔离并回到已知快照。

写权限与证据等级

| 写入源 | 默认状态 | 升级条件 | | — | — | — | | raw sensor/log | immutable evidence | schema/完整性通过 | | Planner 输出 | draft hypothesis | 外部结果验证 | | policy/VLM self-report | unverified | predicate/人/独立 detector 证实 | | environment predicate | authoritative within benchmark | 环境版本和定义固定 | | human operator | reviewed evidence | 角色、时间和标准记录 | | summarized trace | derived | 可回指原始 trace | | imported global rule | external | 版本、适用机器人和复测 |

模型生成的“这次成功了”不能直接写为事实，也不能成为下一次成功判断的唯一证据。

Reset 与污染

必须防止：

  • 前一 episode hidden state 泄漏；
  • evaluation trial 之间 external memory 学习；
  • test 任务结果写入检索库；
  • 一个机器人坐标/技能规则迁移到另一机器人；
  • 用户/场地私有数据跨 namespace；
  • Planner summary 覆盖原始失败证据；
  • 旧 object ID/pose 在相机/底盘移动后继续使用；
  • 失败 trace 被无标记地当成功范例。

评测期 memory 若固定，记录 snapshot hash；若允许 online memory，作为单独方法并报告写入预算和顺序效应。

压缩与遗忘

记忆压缩要报告：

  • 原始时长/条目；
  • 采样或摘要方法；
  • 保留的事件/反例；
  • 丢失的信息；
  • 可回溯 source IDs；
  • summary model/version；
  • consistency check。

“上下文更长”不自动等于记忆更好。错误摘要、顺序偏差、检索噪声和陈旧规则都可能比无记忆更差。

短时与长期实例

  • π0.7/MEM：视频历史帮助识别近期阶段，长期文本记忆保存较抽象事件；具体六帧/十五分钟等结果绑定原论文。
  • Harness VLA：task-specific/global 规则文件是部署时外部上下文，不通过梯度更新；评测 snapshot 必须固定。
  • GR00T 公开 stateless policy 或有限 history 不应被写成自动拥有跨调用任务记忆。
  • π0.5 对更丰富上下文/记忆的讨论是限制与方向，不等于公开实现已有完整 memory manager。

Memory manager 应把记录视为带状态的证据对象。最小记录包含 namespace、content hash、source IDs、source authority、capture time、observation/plan version、uncertainty、适用范围、TTL、状态与父快照。内容相同但来源或范围不同仍是不同记录；摘要必须能回指原始 trace，不能用新摘要覆盖失败和反例。

写入流程采用 draft—verify—commit 三段。Planner、VLM、policy 产生的总结只能写 draft；environment predicate、独立 detector 或授权人工验证后才可 commit。冲突证据不能简单“最新覆盖”，而要保留并触发重新感知或人工裁决。负证据同样重要：某技能在特定机器人、姿态或对象上失败的范围必须进入检索条件，防止成功摘要把适用边界抹掉。

TTL 在读取时检查，reset 在边界事件执行，二者不能只靠后台清理。episode reset 清除 hidden state 与工作记忆；task reset 还清除阶段与预算；scene/robot/user 变化切换 namespace；跨任务 episodic/semantic memory 只有经过明确许可才保留。评测使用固定 snapshot hash 时，任何 online write 都进入隔离分支并使 trial 不再属于同一协议。

检索也需要预算和证据日志：query、过滤条件、候选数、返回 IDs、排序版本、被拒原因及最终消费方式。检索结果若只作建议，不得被下游当硬约束；若作为约束，必须有更高 authority。可以注入 stale pose、错误成功摘要、跨 robot rule 和相互矛盾记录，验收系统是否拒绝、降级或请求新证据，而不是安静地把错误记忆放进 prompt。

本节验收门禁。

  • observation 不被等同 true state。
  • belief 是估计并记录不确定性。
  • observation history 独立。
  • recurrent/latent state 独立。
  • working memory 独立。
  • task state 独立。
  • episodic memory 独立。
  • semantic/procedural memory 独立。
  • spatial/world memory 独立。
  • model weights 与 runtime memory 分开。
  • Capture 来源明确。
  • Verify 权威明确。
  • Summarize 损失明确。
  • Commit 权限明确。
  • Index/Read/Use 权限明确。
  • Update 冲突规则明确。
  • Evict/TTL/撤回明确。
  • Reset 边界明确。
  • Audit/provenance/hash 明确。
  • Rollback 快照明确。
  • Planner/VLM 输出默认 draft。
  • self-report 不直接升级事实。
  • episode hidden state 不泄漏。
  • evaluation trial 不在线污染。
  • robot/user/scene namespace 隔离。
  • 旧 pose/object ID 有失效规则。
  • 失败 trace 不被无标记当成功。
  • 在线 memory 与固定 memory 分开评测。
  • 摘要可回指原始 trace。
  • 长上下文未被写成必然更好。

Memory 冲突采用追加式事实图处理：新记录引用它支持、修正或否定的旧记录，查询时根据 authority、时间、适用范围和最新观测构造视图。高 authority 不代表永久有效，例如环境 predicate 只在固定 benchmark/version 内权威；人工规则也可能只适用于某机器人。若无法解析冲突，返回多候选与不确定性，而不是把排序第一项伪装成唯一事实。

Rollback 不只是切换一个向量库快照。还要恢复 index 版本、embedding/retriever、过滤策略、namespace 权限、摘要模型和 reader compatibility，并隔离坏快照期间派生的二级总结。演练从 snapshot hash 启动，执行固定检索查询并比较返回 IDs 与适用范围；若内容可读但检索顺序或过滤改变，仍视为不同 memory release，需要重新评测。

访问控制与最小化原则同时进入检索路径。查询者只看到其角色、robot、scene、task 和 user scope 允许的字段，日志保存访问理由而不复制无关敏感内容。撤回请求必须沿 source IDs 找到 derived summary、index entry 和受影响 trial。评测报告只保留必要摘要与哈希；若公开证据无法脱敏，应保留存在性和审阅结论，而不是把原始私有轨迹嵌入页面或 prompt。

世界模型：预测后果、生成目标还是制造数据

先按输入输出分类

| 角色 | 必需输入 | 输出 | 支持的决策 | 不能直接证明 | | — | — | — | — | — | | state estimator | history、actions、observations | belief/latent state | 当前状态估计 | 未来可达 | | action-conditioned forward model | state + candidate action | next state/observation/reward | 比较动作后果 | 长时准确、安全 | | latent dynamics / imagination | latent + action sequence | latent rollout/value features | policy learning/MPC | 像素/物理全真 | | goal/outcome generator | current obs + task/subgoal | desired future image/video | 为低层提供目标 | 候选动作导致该结果 | | evaluator | state/trajectory/goal | success/value/cost/risk | 排序、门禁 | 因果机制正确 | | offline data generator | initial frame/task/conditions | synthetic video/trajectory | 扩充训练数据 | 部署时实时规划 |

同一个系统可组合多个角色，但每项 claim 必须指明是哪一个。

世界模型契约

至少记录：

  • role；
  • input state/observation；
  • whether action-conditioned；
  • action representation；
  • output space；
  • prediction horizon；
  • stochastic samples；
  • objective/training data；
  • calibration/uncertainty；
  • latency/hardware；
  • refresh/caching；
  • downstream consumer；
  • guardrails；
  • OOD behavior；
  • validation protocol；
  • fallback。

只写“使用 world model”不通过验收。

Action-conditioned 反事实

要比较候选动作 a 和 a'，模型需在相同 belief 下估计不同条件后果：

p(o_{t+1:t+H} | b_t, a_{t:t+H-1})

没有动作输入的 instruction-conditioned 生成器只能回答“任务希望看到什么”或“训练分布中什么未来看起来合理”，不能回答“执行这个动作将发生什么”。

MPC/滚动规划模式

概念流程：

  1. 从最新 belief 生成候选 action/skill sequences。
  2. 用 action-conditioned model rollout。
  3. 由 cost/value/constraint 评估。
  4. 选通过 hard constraints 的候选。
  5. 只执行安全前缀。
  6. 重新观察和更新 belief。
  7. 若 model error/OOD/事件触发则重新规划或 fallback。

本页不提供优化器、采样器或真实控制参数。world model 预测仍需外部约束，不能让 learned cost 抵消安全 veto。

误差与不确定性

必须区分：

  • one-step predictive error；
  • multi-step compounding error；
  • visual realism；
  • task-relevant state error；
  • action consequence error；
  • calibration；
  • epistemic/OOD；
  • stochastic multimodality；
  • latency-induced staleness；
  • downstream sensitivity。

像素指标或“视频看起来合理”不能替代接触、几何、对象持有和环境 predicate。

Goal image 与实际后果

视觉子目标路径：

task + current observation → desired outcome image → low-level goal-conditioned policy

需要验证：

  • 目标图是否保留当前场景/对象身份；
  • 是否生成不可能/不安全状态；
  • 低层是否在训练中见过生成瑕疵；
  • 目标何时刷新；
  • 异步生成期间是否陈旧；
  • low-level 如何判断到达或拒绝。

π0.7 的公开描述属于此类；不能写成通用物理 dynamics 或碰撞预测器。

离线生成器

DreamGen 类路径：

initial frame + task → synthetic robot video → IDM/LAPA pseudo action → policy training

它改变训练数据，不是部署时每步 rollout 的实时 planner。需单独审计：

  • 视频生成质量；
  • 伪动作可执行性；
  • 时序/本体一致性；
  • synthetic/real mixture；
  • OOD 运动；
  • 数据标记与 lineage；
  • 下游闭环收益。

模型特定来源的边界

  • World Models / Dreamer 展示 latent dynamics 和 imagined behavior 的模型式学习语境，但不能直接当 VLA 真机配方。
  • π0.7 展示高层 subtask→视觉目标→低层 VLA 的结果生成路线。
  • DreamGen 展示离线视频 world model→伪动作→训练数据路线。
  • MEM 是 memory architecture，不因名字或视频编码自动成为 world model。
  • Harness Memory 是外部经验制品，不预测物理转移。
  • DexGraspVLA 的 VLM monitor 判断执行结果，不是 action-conditioned dynamics。

世界模型的第一项验收不是生成质量，而是角色一致性。测试卡先冻结输入 schema、是否含候选动作、输出语义与 consumer；然后用 counterfactual pair 检查改变动作是否改变预测。若模型完全不接收动作或对动作置换不敏感，它只能作为 goal/outcome generator 或弱条件模型，不能被报告为可比较动作后果的 forward model。

预测误差要按使用方式分层。one-step 误差可低而 multi-step rollout 迅速漂移；像素指标可好而对象持有、接触和任务 predicate 错；平均校准可好而 OOD 场景过度自信。因此同时记录 task-relevant state、动作后果、约束违规、随机样本覆盖、校准、OOD 拒绝、延迟与陈旧度。downstream 评测还要比较没有世界模型的基线，防止额外模块只增加延迟和故障面。

用于 MPC 或候选排序时，每个 rollout 绑定 belief、action sequence、模型版本、随机 seed、cost/value 版本和 hard-constraint 结果。learned score 只能在通过硬约束的集合内排序；执行安全前缀后必须重新观察。模型 OOD、rollout 分歧过大、延迟超标或 consumer 版本不匹配时，走经过评测的 fallback，不得沿用缓存预测继续多步执行。

Goal image 路线另做身份与可达性测试：是否保留当前对象、是否引入不存在物体、是否与场景几何冲突、低层能否识别生成伪影、目标何时失效。离线生成器则审计 synthetic lineage、伪动作质量和 real/synthetic mixture；它不参加运行时 planning latency。用这两组卡可以防止“都输出视频”掩盖一个是期望结果、另一个是训练数据来源。

终止、重规划与失败恢复：谁决定继续或停止

五种完成语义

  1. Action chunk generated/done：模型或队列完成一段动作。
  2. Skill termination：技能内部停止条件触发。
  3. Subgoal/postcondition achieved：外部条件证明阶段目标成立。
  4. Planner finish：高层决定不再提议技能。
  5. Task success：环境原生 predicate 或授权人证明最终任务完成。

另有 safety stop/abort：为避免风险终止，不属于 success。

页面用反例说明：夹爪闭合可能触发 skill termination，但物体未随动，subgoal 和 task 均失败。

七级恢复梯度

  1. Re-observe：刷新视觉/状态/目标身份。
  2. Retry changed：同一 skill 但改变可解释参数/seed/视角，而非原样重复。
  3. Re-ground/Re-stage：重新定位、预置或回到 initiation set。
  4. Alternate skill：使用已验证的替代实现。
  5. High-level replan：改变 subgoal/顺序。
  6. Retreat/Reset/Human：撤退到安全状态、环境 reset 或请求人。
  7. Safe stop/Takedown：无法保证时停止并记录 incident。

每级定义最大次数、累计时间、风险、升级条件和禁止条件。

恢复前必须改变什么

一次有效 recovery 至少改变：

  • observation/evidence；
  • state estimate；
  • target/grounding；
  • skill parameters；
  • implementation；
  • plan；
  • environment state；
  • human instruction。

如果什么都没变，只是重复随机采样，应明确标为 stochastic retry，并用独立预算限制。

终止优先级

建议优先级：

  1. independent safety stop；
  2. hardware/controller fault；
  3. human emergency intervention；
  4. task deadline/resource budget；
  5. unrecoverable failure；
  6. verified task success；
  7. planner finish。

Planner finish 不得覆盖更高优先级，也不能在 task predicate false 时自动标 success。

Monitor 的 authority 必须进入状态转换。advisory signal 可以请求更多观测，veto 可以阻止下发，authoritative predicate 才能结束相应阶段；一个 VLM confidence 不能同时承担三种角色。每个触发保存原始窗口、处理版本、阈值、hysteresis、数据年龄和裁决，便于重放假阳性与假阴性。多个信号冲突时使用预先定义的优先级，而不是由 Planner 临时解释。

失败分类要指向首个可证伪层级。错对象先重新 grounding；schema 错误退回 Planner；不可达由 affordance/IK 证明；策略接触失败查看 action 与 controller trace；硬件故障由设备状态确认；monitor 分歧进入独立复核。分类为 unknown 是允许的，但 unknown 不得直接触发原样重试，更不能被统计成某个已知模块的成功恢复。

每次恢复记录“与上次相比改变了什么”：新 observation、不同视角、更新 entity/pose、修改 skill args、替代 skill、新 plan、reset 或 human input。完全相同条件下的再次采样只标 stochastic retry，并受独立小预算约束。恢复预算同时限制次数、wall-clock、资源和风险暴露；局部预算耗尽升级到更高层，整体预算耗尽到 SafeStop，不允许计数器在 replan 后静默清零。

振荡检测不能只数相同字符串。将 canonical skill、规范化 arguments、target version、plan hash 和 progress state 组合成循环键，检测 A↔B、多节点环和“参数微变但无进度”的近似循环。触发后先冻结自动下发并保留证据，再选择重新感知、替代技能、高层重规划、撤退或人工接管。verified success 与安全停止分别记录 termination reason，任何中止都不能被 success 聚合器吞并。

状态机验收应枚举每个状态的允许事件、目标状态、证据、动作和副作用，并验证所有未列事件默认拒绝。Executing 期间收到 verified task、safety stop 与 Planner update 时，安全事件先处理，成功事件仍需完成权威核验，计划更新只能排队或取消。Verifying 超时不得自动 success；Recovering 不能直接跳过 Observe 回到 Executing；SafeStop 只有经过独立授权与 reset 才能离开。

恢复率必须和失败分母及风险一起报告。按 failure type 统计触发次数、进入的恢复级别、恢复后是否真正完成 task、是否引入新失败、额外时间和人工介入；把一次 retry 后动作继续当作 recovered 会夸大能力。对不可恢复或安全类失败，快速停止可能是正确结果，应单独报告 safe handling，而不是算作任务恢复失败。

可验证组合闭环：从观察到恢复和安全终止

十个模块

  1. Observer/adapter：时间同步和 observation version。
  2. State estimator/belief：融合历史与不确定性。
  3. Memory manager：按权限读取/写入。
  4. Planner：提出 typed skill/subgoal。
  5. Grounder/affordance checker：实体映射与可行性。
  6. Validator/resource manager：schema、资源、约束和预算。
  7. Skill router/policy：解析原语或 learned VLA。
  8. Controller：Action ABI→设备命令。
  9. Monitor/verifier：progress、postcondition、failure、success。
  10. Recovery/termination manager：有限恢复、人工升级和安全停止。

Event logger 横跨全部模块，独立 safety controller 位于策略外。

标准闭环

Observe → Estimate → Retrieve → Propose → Ground → Validate → Dispatch → Execute prefix → Monitor → Verify

Verify 后分支：

  • postcondition true 且 task 未完成 → 更新 task state，规划下一阶段；
  • task predicate true → 记录 verified success 并终止；
  • recoverable failure → 分类、选择恢复级别、重新观察；
  • uncertainty/staleness → 不执行，刷新或请求人；
  • safety/fatal/budget exhausted → safe stop。

最小故障注入

仅作为评测设计，不在当前阶段执行：

  • 移动物体使旧 bbox/pose 失效；
  • 遮挡造成短时部分可观测；
  • 返回 skill failure；
  • 延迟 world-model goal；
  • 注入 stale memory；
  • 让 success detector 与 environment predicate 冲突；
  • 模拟 Planner timeout；
  • 耗尽 retry budget。

每项预先定义期望状态转换；不以机器人实际碰撞测试验证软件错误处理。

端到端组合首先要有责任矩阵：每个模块列输入、输出、owner、authority、timeout、fallback 与日志键，检查是否存在无人负责的空隙或两个模块都认为对方已验证。Event logger 只能记录，不应改变控制决策；独立 safety controller 位于策略外，即使 Planner、Memory、world model 和 monitor 全部同意，也不能绕过其 veto。

Trace 要能确定性重放“为什么发生状态转换”，而不要求重放真实物理世界。回放器按 observation/version、belief、retrieved IDs、plan、validator、skill call、monitor 和 predicate 逐事件重建状态；缺事件、顺序倒置、父版本不存在或摘要不匹配都标证据不完整。对随机模型保存 seed 或输出制品，对外部人工裁决保存角色和时间，但不记录无关个人信息。

故障注入验收应先写 expected transition：旧 bbox 必须触发重新 grounding，遮挡进入更多观察或不确定，world-model goal 超时被拒绝，stale memory 不得被应用，success detector 与环境谓词冲突时不能成功，Planner timeout 走 fallback，retry 耗尽进入升级或 SafeStop。当前页面只固定这些预期，不实际运行仿真或机器人碰撞测试。

进入统一评测前，hierarchy、skill catalog、memory snapshot、world-model role card、monitor authority、recovery budget、reset semantics、trace schema 与版本摘要必须作为同一 evidence bundle 交付。统一评测按 whole-task、stage、conditional skill、failure propagation、recovery、loop、latency、staleness 和 ID/OOD 分轴；实时部署页再测真实线程、队列、取消与 action-to-command 时延，安全页负责物理限制、watchdog 和 incident。

页面完成不等于系统验证完成。没有目标机器人、运行日志与授权阈值时，所有值保持占位或 unknown；模型演示只证明案例存在，论文频率不替代目标硬件测量。实施者补入真实证据后还需重新执行完整性、闭环、失效退化和安全审查，才能把状态从“架构设计就绪”提升为“目标系统已验证”。

集成审查分三层。静态层核对 schema、版本、依赖图与状态转换完整性；离线回放层用冻结 trace 重建 decision 和 failure path；受控闭环层才检查真实时序、物理结果和恢复。低层失败时不进入更高层，较高层成功也不能补齐缺失的 lineage。每层的 pass、fail、not-run 和 evidence-missing 分开，避免把“尚未执行”统计为零失败。

端到端最小样例应同时包含成功路径和至少四条失败路径：未知 skill 在 Validate 被拒，stale grounding 回到 Observe，policy timeout 进入 Recovering，safety veto 进入 SafeStop；另加 Planner 自报 finish 但 task predicate false 的反例。每条路径都检查旧命令不会继续执行、预算正确递减、memory 只写允许状态、trace 父版本闭合且最终 termination reason 唯一。

Evidence bundle 使用不可变清单引用而不是复制所有制品。清单列 hierarchy、catalog、schema、model/runtime、memory snapshot、world-model card、monitor、state machine、fault-injection protocol、trace 与审批摘要；每项有 hash、owner、状态和缺口。缺少 world model 并不阻止一个明确的无 world-model 路径，但若架构声称使用它却没有角色卡或 fallback，则该能力进入 quarantine。

最终审阅可从任意 termination event 反向追到最新 observation、belief、plan、validator、skill、command、monitor 与恢复决定，也可从任一 memory 或 world-model 制品查出影响的 trial。两条查询闭合才说明系统具有可解释的长时序证据链。仍依赖目录名、聊天记录或操作者记忆才能回答的字段，保留为结构性缺口，不以演示视频补写。

还要做一次“无高级模块”退化审查：关闭 Planner、Memory 或 world model 后，系统只能进入已经单独验证的短任务、固定技能或安全停止路径，不能把上一轮缓存当成替代。每条 fallback 都有自己的适用任务、最大时域、观测要求和终止条件；若目标超出范围，明确拒绝。这个审查能区分高级模块带来的增量能力与底层本来就具备的控制能力，也能防止故障时范围反而扩大。

证据状态采用稳定枚举：designed 表示契约已写，statically_checked 表示结构通过，replayed 表示冻结 trace 可重建，closed_loop_evaluated 表示在指定环境完成受控闭环，approved 表示负责人接受相应范围。状态不能按演示质量自动升级，且始终绑定 protocol、版本和日期。论文或项目页只能支持实例存在与已报告设置，不能替目标系统填写后两级状态。

最后用两个方向检查责任闭合。正向从 user task 逐层走到 command，任何边都能指出 schema、owner 与 veto；反向从 success、failure 或 SafeStop 回到触发它的观测和权威证据，任何结论都不依赖 Planner 自述。若正向缺边，系统可能无法安全执行；若反向缺边，结果无法审计。只有两条路径都闭合、所有 unknown 有责任人和解除条件，页面蓝图才算完成。

审阅者还应逐项标记哪些结论来自静态契约、离线回放、仿真、HIL、受控真机或人工判断，不能用更高风险层的一次成功覆盖较低层缺失的结构证据。对未执行层保留 not_run，对不适用层写明理由，对失败层保存原始 trace 和停止决定。这样下一页计算成功、阶段完成、恢复与超时指标时，分母不会混入缺证据或被提前排除的 trial，也不会把安全停止误报为模型能力不足或任务成功。

任何新增模块、状态、memory namespace、skill 或 world-model role 都要重新运行责任矩阵与失效退化审查。若新增边使 Planner 能绕开 validator、让旧观测继续有效、让 draft memory 进入执行条件，或让 learned score 覆盖安全 veto，集成应直接失败。扩展长时序能力的原则不是增加更多自治循环，而是在每个新循环上增加明确证据、有限预算和可达停止点。

完成记录必须列出尚待目标系统提供的时钟、阈值、权限、设备和安全事实；在这些外部条件被真实证据关闭前，页面保持“设计就绪”，不得改写为已经部署、已经安全或已经具备通用长时序能力。

缺口清单本身也要有版本、负责人、截止条件和复核记录，不能用“待后续确认”长期悬置。

必须明确拒绝的错误表述。

  • “输出 50 步动作，所以能规划 50 步”错误；动作生成时域不等于任务级推理和结果验证。
  • “语言模型生成了正确步骤，所以计划可执行”错误；需技能库、前置条件、affordance 和当前状态核验。
  • “子目标是一个自然语言句子”过窄；子目标可为文本、目标图像、对象/区域、位姿、谓词或潜变量。
  • “Skill 就是一个 prompt”错误；可执行技能至少还要有 typed arguments、前置/后置条件、termination 和 budget。
  • “Affordance 就是物体类别”错误；本页使用的是状态、机器人和技能共同决定的可行性/可用性。
  • “Planner 输出低层关节动作”不是分层系统的必然定义；多数架构应由高层输出受 schema 约束的目标或技能调用。
  • “有视觉历史就有长期记忆”错误；有限历史主要缓解短时遮挡和阶段混淆。
  • “外部 Memory 更新就是持续学习”错误；文件/数据库更新与参数梯度更新必须分开。
  • “RNN hidden state 是真实环境状态”错误；它是模型内部估计，受观测、训练和重置影响。
  • “世界模型就是视频生成模型”错误；需按输入、输出和使用角色分类。
  • “生成目标图像能预测动作后果”错误；未接收候选动作的生成器不能比较动作条件反事实。
  • “像真实的未来图像就是物理正确”错误；外观一致不保证接触、遮挡、力、碰撞或任务谓词正确。
  • “Planner 说 done 就完成”错误；任务成功需权威外部 predicate 或受控人工核验。
  • “夹爪闭合就是抓取成功”错误；还需目标随动、持有稳定或任务专属条件。
  • “固定三次重试具有恢复能力”错误；恢复需新证据、策略变化、预算和退出路径。
  • “每一步都重规划更安全”错误；高延迟、噪声和不稳定目标可能导致抖动与振荡。
  • “世界模型越大越适合实时闭环”无依据；预测质量、时域、延迟、陈旧度和接口更关键。
  • “成功轨迹摘要可以直接加入全局记忆”错误；需外部验证、适用范围、去重、版本和污染审查。
  • “模型页展示了恢复案例，所以系统能从所有失败恢复”错误；恢复结论必须绑定失败类型和协议。
  • “高层规划器可绕过 controller”错误；所有执行仍受 Action ABI、底层控制和独立安全层约束。

读者完成后的自检。

读者必须能：

  1. 区分 task、plan、skill/option、subgoal、affordance、action chunk 和 command。
  2. 为每层写输入、输出、时钟、触发、预算和 owner。
  3. 判断一个计划是 open-loop 还是 closed-loop。
  4. 区分 periodic、event-driven 与 hybrid replanning。
  5. 说明为什么 prediction horizon 不等于 execution horizon。
  6. 将自由文本 Planner 输出改成 typed schema。
  7. 为技能定义 precondition、postcondition、termination、failure 和 timeout。
  8. 区分语言子任务、视觉目标、对象框、位姿和技能调用。
  9. 用当前状态/affordance 拒绝语言上合理但物理不可行的步骤。
  10. 区分短时历史、belief、working/task/episodic/semantic memory。
  11. 说明记忆的 write source、verify source、commit 和 reset。
  12. 防止跨 trial、机器人、用户和 benchmark 的状态泄漏。
  13. 区分模型参数更新与外部记忆更新。
  14. 区分六类 world-model role。
  15. 判断某世界模型是否 action-conditioned。
  16. 判断其预测的是实际后果、期望目标还是离线合成样本。
  17. 识别 rollout error、hallucination、OOD 和目标陈旧。
  18. 区分 chunk done、skill termination、subgoal success、planner finish 和 task success。
  19. 设计 monitor 的信号、窗口、阈值、debounce 和 authority。
  20. 设计有预算、有变化、有退出条件的恢复梯级。
  21. 检测重复动作、A↔B 振荡和无进度循环。
  22. 给每次 replanning 记录触发、旧计划、最新证据和新计划。
  23. 画出 observation→belief→plan→validate→execute→monitor→verify→recover/terminate 闭环。
  24. 为统一评测页输出阶段进度、失败、恢复和终止 trace。
  25. 对 π0.5、π0.7、Harness、DexGraspVLA 只提炼实例，不外推默认。
  26. 判断何时必须安全停止或请求人，而不是继续“自主恢复”。

一手来源与证据边界

所有来源在网页正文就近引用，参考区再集中列出。访问日期统一记录为 2026-10-13；上线前重新复核近期预印本版本、开源状态和许可证。

时间抽象、部分可观测与世界模型基础

  1. Richard Sutton、Doina Precup、Satinder Singh，Between MDPs and Semi-MDPs: A Framework for Temporal Abstraction in Reinforcement Learning，Artificial Intelligence 1999。 出版社页；DOI 10.1016/S0004-3702(99)00052-1。 支持 option 的 initiation/policy/termination 和多时间尺度概念；不要求 VLA 必须使用 HRL 训练。

  2. Leslie Kaelbling、Michael Littman、Anthony Cassandra，Planning and Acting in Partially Observable Stochastic Domains，Artificial Intelligence 1998。 出版社页。 支持部分可观测、belief 和有限记忆控制器语境；本页不展开精确 POMDP 求解。

  3. David Ha、Jürgen Schmidhuber，World Models，2018。 项目页；arXiv:1803.10122。 支持视觉编码、动态记忆和 controller 的经典 world-model 组合；不直接成为机器人 VLA 配方。

  4. Danijar Hafner 等，Mastering diverse control tasks through world models，Nature 2025。 Nature 正式页；arXiv:2301.04104。 支持 latent world model、imagined futures、actor/critic 的现代实例；真实机器人安全和 VLA 接口仍需另验。

语言规划、可行性与闭环反馈

  1. Michael Ahn 等，Do As I Can, Not As I Say: Grounding Language in Robotic Affordances。 OpenReview 论文；项目页；arXiv:2204.01691。 支持语言相关性与 skill value/affordance 共同筛选；不把 learned value 当安全证明。

  2. Wenlong Huang 等，Inner Monologue: Embodied Reasoning through Planning with Language Models，CoRL 2022/ PMLR 2023。 PMLR 正式页；arXiv:2207.05608。 支持 success detection、scene feedback 和 human feedback 进入高层语言规划闭环；不证明所有 LLM planner 都可靠。

  3. Jacky Liang 等，Code as Policies: Language Model Programs for Embodied Control，ICRA 2023。 项目页；arXiv:2209.07753。 支持由语言模型生成受 API/函数库约束的策略程序实例；生成代码仍需 schema、权限和安全审计。

  4. Michele Colledanchise、Petter Ögren，Behavior Trees in Robotics and AI。 arXiv:1709.00084。 用作状态/组合/回退结构的补充来源；本页不规定必须采用行为树。

VLA、记忆、世界模型与系统实例

  1. Kevin Black 等，π0.5: a Vision-Language-Action Model with Open-World Generalization，CoRL 2025。 PMLR 正式页；arXiv:2504.16054。 支持高层 semantic subtask、低层 action 和长任务实验；公开 openpi 完整高层解码支持范围需分开记录。

  2. Physical Intelligence，π0.7: a Steerable Generalist Robotic Foundation Model with Emergent Capabilities，2026 预印本。 arXiv:2604.15483；官方项目页。 支持 prompt conditioning、subgoal image、分层系统和多阶段实验；当前为近期作者来源，独立复现与完整世界模型制品另列。

  3. Marcel Torne 等，MEM: Multi-Scale Embodied Memory for Vision Language Action Models，2026 预印本。 arXiv:2603.03596。 支持视频短时记忆与文本长期记忆的多尺度组合；π0.7 中使用的具体子模块不能反向等同完整 MEM。

  4. Yixian Zhang 等，Harness VLA: Steering Frozen VLAs into Reliable Manipulation Primitives via Memory-Guided Agents，2026 预印本。 arXiv:2607.08448；RPent 文档。 支持固定原语、冻结 VLA、外部 Memory、结果回执和 retry/re-stage 系统实例；论文自报结果与独立复现分层。

  5. Yifan Zhong 等，DexGraspVLA: A Vision-Language-Action Framework Towards General Dexterous Grasping，AAAI 2026。 AAAI 论文；项目页；官方代码。 支持 VLM planner、目标框、低层 diffusion controller、核验与重抓实例；论文运行时与公开代码事实分开。

  6. Yecheng Jason Ma 等，Hi Robot: Open-Ended Instruction Following with Hierarchical Vision-Language-Action Models。 arXiv:2502.19417。 用于 π0.5 官方所述分层路线背景；不将其接口细节直接归给 π0.5。

  7. NVIDIA 等，DreamGen: Unlocking Generalization in Robot Learning through Video World Models。 arXiv:2505.12705；官方项目页。 支持 video world model 作为离线数据生成器、再由 IDM/LAPA 接动作监督的角色；不写成部署时实时 dynamics。

  8. Moo Jin Kim 等，OpenVLA: An Open-Source Vision-Language-Action Model，CoRL 2024。 PMLR 正式页；项目页。 用于端到端 VLA 与分层系统对照；不将单/多任务结果外推为长时序规划证明。

证据冲突处理

  • 正式论文、预印本版本、项目页、当前代码和站内固定 commit 分开。
  • π0.5 论文的高层推理不因 openpi 低层路径可运行而自动称“完整开源”。
  • π0.7/MEM/Harness 为 2026 近期来源，页面上线前必须复核版本、权重、代码和独立复现。
  • 模型演示视频只证明展示案例存在，不给出总体恢复率。
  • 作者自报“emergent/long-horizon/reliable”按论文定义和协议转述，不作为无条件事实。
  • 环境 predicate、人工判断、VLM monitor 和 planner self-report 使用不同 evidence badge。
  • World-model 图像质量、one-step prediction 和 downstream success 分开报告。
  • 论文硬件、频率和刷新周期只留在模型页；公共页使用符号和契约。
  • 代码缺少 timing/queue/termination 时标 unknown，不用论文设置补成代码事实。
  • 搜索摘要只用于发现来源；最终正文引用论文、proceedings、项目页或官方文档。
  • 未公开的世界模型权重、训练配方、memory update 或 planner prompt 写 unknown。
  • 第三方复现若更换技能库、robot、monitor 或 memory，标 modified protocol。
