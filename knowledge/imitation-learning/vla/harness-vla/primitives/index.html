先分清 primitive、tool 与 control channel

“tool”只是 agent-facing 接口集合，不自动等于动作原语。先按是否改变机器人/环境状态和由谁授权分成四类，再把 manipulation action 分为 analytic composite、analytic atomic 与 learned VLA 三族。

类别 是否改变环境/机器人状态 示例 authority 边界
manipulation action 是 analytic / VLA-backed primitive safety permit + exclusive admission
perception/state read 否 image、state、localization read readonly；不获得 motion authority
terminal/control 控制 Planner/session finish、cancel、status finish 不等于 task success
exploration utility 依协议 reset 仅指定 mode；不计 manipulation primitive 
flowchart LR
  P["Planner intent / PrimitiveCall"] --> X["primitive executor / policy adapter"]
  X --> C["controller command stream"]
  C --> A["actuator-facing controller"]
  R["perception/state read"] -. evidence only .-> P
  T["terminal/control"] -. planner/session .-> P
  U["exploration utility"] -. mode-gated .-> X

图 1｜意图到控制通道。 Planner 只能使用 registry 暴露的 intent-level schema；它不直接发 torque、joint target、raw action chunk 或 bus packet。analytic_composite 接受目标状态并由内部 solver/controller 协调多自由度，analytic_atomic 发有限 set-point/短 command，learned_vla 用冻结模型产生 action chunks。

current RPent 官方文档把 action tools 与 perception/state readonly tools 分开；finish 只结束 Planner loop，success 仍由 environment/operator 判定。type annotation/docstring 可生成 tool schema，Toolkit 负责 dispatch、捕获 state 并返回 ToolResult；这些 current 接口事实不改写论文 vocabulary。

论文把 grasp、constrained placement、fixture/button/drawer/insertion 等 contact-rich 局部阶段更多交给 VLA，把 grounding、staging、transport、release 与 recovery 更多交给 analytic primitive。这是工程启发，不是硬分类：一个 VLA chunk 可同时包含 approach 与 contact，analytic controller 也可能发生受约束接触。分类不替代 contact detection，也不授予 SafetyDecision。

从选择、参数化到执行准入

PrimitiveCall 不是任意 JSON。它把 run/session/episode/turn/call 与 parent/retry group 关联到固定 registry，引用 fresh observation、frame/unit、backend/adapter/controller contract、pre/postcondition、budget、deadline、Memory receipt 与 replay policy。

flowchart LR
  C["PrimitiveCall"] --> R["1 registry/name/version"]
  R --> J["2 JSON/type/schema"]
  J --> M["3 mode/permission/capability"]
  M --> O["4 observation freshness"]
  O --> F["5 frame/unit/arm/gripper"]
  F --> B["6 bounds/workspace/reachability"]
  B --> P["7 precondition evidence"]
  P --> S["8 independent safety permit"]
  S --> Q["9 exclusive admission/queue"]
  Q --> E["10 executor/controller acceptance"]

任一 gate 失败都返回 typed rejection，不进入下游 execution。JSON/type/schema valid 不能替代 workspace、collision、force、velocity、command-age 或 safety validation。示例参数只允许 <typed-target-ref>、<declared-frame> 等 placeholder，不展示真实坐标、速度、力、容差或步数，因此不能复制运行。

CallAdmissionDecision(permit) 只表示可进入执行队列；ExecutionAccepted 才表示 executor/controller 接管。二者都不等于 primitive completed、postcondition true 或 task success。

analytic composite 与 atomic execution

Composite primitive 如 move_to、move_pose、navigate_to 接受 goal-level target，内部可能依次使用 transform/calibration、IK/Jacobian/operational-space solver、path/waypoint、controller ticks、collision/workspace check、progress/stall detector 与 postcondition。Planner 不拥有 solver intermediate state，也不能把目标 pose 当作 actuator command。

Atomic primitive 如 rotate_wrist、rotate_pitch、set_gripper、release、move_base 只缩小接口粒度，仍需 current-state snapshot、mode/arm/channel ownership、unit/sign/range validation、controller acceptance、tick/step budget、fault/cancel boundary 与 post-action fresh state；atomic 不代表单 tick、瞬时或天然安全。

vla_act 的内部 chunk 闭环

vla_act 必须引用冻结的 backend bundle/checkpoint hash、processor/normalizer/calibration、observation/action/state schema、camera order/history、prompt schema、frame/unit/dimension/mask、prediction/execution horizon、inference steps/precision/compile、controller/safety handoff 与 session/reset semantics。

以外层 call ID (c) 与内部 chunk index (k) 表示教学时序：

\[A_{c,k}=f_{\theta_0}\left(O_{c,k},\ell_{\mathrm{local}};\mathcal C_{\mathrm{backend}}\right), \qquad k=0,\ldots,K_c-1,\] \[O_{c,k+1}=\operatorname{Observe}\left(\operatorname{ExecuteChunk}(A_{c,k})\right).\] 
sequenceDiagram
  participant H as Harness/Executor
  participant F as Frozen VLA
  participant A as Adapter + Safety
  participant C as Controller
  participant O as Observation
  loop each chunk under budget
    H->>F: fresh observation + local prompt + frozen contract
    F-->>H: typed action chunk
    H->>A: denormalize + frame/unit/embodiment map
    A->>C: permitted normalized command
    C-->>O: sequence + fresh state
    O-->>H: stop/progress/fault/cancel evidence
  end

图 5｜VLA chunk 内环。 (\theta_0) 固定，(\mathcal C_{\mathrm{backend}}) 是冻结 contract；公式只是一种本站时序抽象，不保证所有 backend 使用相同采样或每 chunk 刷新方式。每个 chunk 都重新检查 call/session、observation freshness、schema、adapter mapping、server/controller bounds 与 Safety Plane。

stop reason 必须区分 stop_predicate_true、postcondition_true、chunk_budget_exhausted_progressing、chunk_budget_exhausted_no_progress、controller_rejected、safety_inhibited、cancelled_at_safe_boundary、backend_fault、observation_stale 与 session_invalid。

若 backend 保持 history/RTC/cache state，state key 绑定 run/session/episode；不跨不相关 client/task 共享；task boundary 显式 reset/close；late request 不得写入新 session；state revision 写进 result evidence。

并发、timeout、cancel 与 late result

同一 actuator/controller domain 同时只允许一个 active state-changing operation；第二个进入 bounded queue 或 typed rejection。readonly call 可并发，但共享 cache/state 写必须同步；waiting exclusive call 的优先级要固定。cross-arm 并发只在 domain 独立且 collision/safety coordination 明确时允许。

current RPent 的状态变更工具采用 exclusive admission，readonly 工具可并发，等待中的 exclusive call 优先于新 readonly call；cancel_active_and_wait() 请求取消并等待 cleanup，long-running handler 通过 raise_if_cancelled() 在声明的安全边界响应。具体实现仍需在 Implementation 页固定 commit 后核对。

sequenceDiagram
  participant H as Harness
  participant X as Executor
  participant C as Controller
  participant S as Safety
  H->>X: call under deadline
  H-->>X: timeout / stop requested
  X->>C: cancel at declared safe boundary
  C-->>X: stop acknowledged + controller state
  X->>S: fresh physical state + cleanup evidence
  S-->>H: safe state / re-arm decision
  C--xH: late result isolated by call/epoch/session

timeout 只代表等待预算耗尽，不证明 physical stop。系统必须标 stop requested、等待 handler/controller 在 safe boundary 响应、取得 stop/cleanup ack 与 fresh state，再由 Safety 判断 safe state/re-arm 后才准入新动作。不能在任意 controller tick 生硬中断，留下悬空力、速度或抓持状态。

所有 request/result 绑定 call ID、operation epoch 与 session ID。late response 不更新新 call state、不覆盖新 observation、不触发 retry success，只记为 late/ignored evidence；若 physical side effect 可能持续，升级 safety/incident。Toolkit/service close()、process exit 或 RPC disconnect 也不等于 actuator safe stop。
