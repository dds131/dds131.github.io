π0 → π0.5 不是简单地「换动作头」或「把网络加深加宽」。论文称两个 Transformer 的维度沿用 π0，连续动作仍由 Flow Matching 生成；主要方法变化分布在训练流程、数据体系、分层推理，以及状态与时间条件的输入方式。实验能证明的是完整 π0.5 配方优于两个基线，不能把总差距精确分摊给某一个改动。

二、先行结论：改了什么、没改什么

2.1 没改的部分

论文附录 A-E 的原话是：两个 Transformer 的维度与 π0 相同。下面列的是论文口径，不是对当前源码参数的重新推断：

项目 取值（论文附录 A-E） 与 π0 的关系
VLM 专家 width 2048、depth 18、mlp_dim 16384、num_heads 18、num_kv_heads 1、head_dim 256，约 2B 论文称相同
动作专家 同上，但 width 1024、mlp_dim 4096，约 300M 相同
动作块长度 动作视界 50（论文写作 \(H=49\)） 相同
动作生成方式 Flow Matching，推理 10 步去噪 相同
时间步采样分布 论文明写「We follow \(\pi_0\) for sampling the flow-matching timestep \(\tau\)」 相同
两个专家的交互 通过联合自注意力交互；掩码使 prefix 不能读取 suffix，而 suffix 可以读取 prefix 相同

论文与当前源码的参数表并不完全一致。论文附录写 num_heads=18，当前官方 gemma.py 中 gemma_2b 与 gemma_300m 都配置为 num_heads=8、num_kv_heads=1、head_dim=256。这只能说明发布版本与论文表格存在数值差异，不能仅凭 \(8\times256\neq1024\) 或 \(2048\) 判定哪一方“写错”，因为查询投影的总维度不必等于隐藏宽度。详见 ⑦ 论文与实现的差异。

2.2 改了的五处

编号 改动 属于哪一层 有无单独消融
一 训练范式：全程流匹配 → 离散预训练加流匹配后训练 训练 有整体对照，非单变量消融（V-D）
二 状态位置：连续 suffix → 离散 prefix 模型代码 无
三 时间步注入：拼接 → adaRMSNorm 逐层调制 模型代码 无
四 数据体系：扩展为六类共训练数据 数据 有（V-C、V-E，按数据源与任务分析）
五 任务层级：单层策略 → 显式高层子任务加低层动作 推理与数据 有对照（V-E；并非所有条件都只差一个变量）

其中第二、三两处是 Pi0Config 所概括的模型结构差异，这也是 pi0_config.py 注释所说的「Pi05 相对 Pi0 有两点差异」。其余三处主要落在训练配方、数据变换或两阶段推理流程中，并非“完全在代码之外”。

下图把 π0 与 π0.5 并排画开，五处改动按它们主要落在哪一层归位。这里的“模型代码层”专指 Pi0Config 概括的两项结构分支，不表示其他改动无需代码实现。

三、关键优化一：训练范式

四栏 内容
π0 怎么做 从训练一开始就带动作专家，动作始终用流匹配连续表示。详见 π0 · Flow Matching 动作生成，本页不重讲
π0.5 怎么改 拆成两阶段：阶段一 280k 步，全部任务（含动作）用离散 token 表示，只有交叉熵；阶段二 80k 步，才把随机初始化的动作专家加进来，按 \(\mathcal{L}_{\mathrm{CE}}+\alpha\mathcal{L}_{\mathrm{FM}}\)、\(\alpha=10.0\) 联合训练
为什么改 论文 IV-B 的动机是兼取两种表示的长处：FAST token 能高效学习动作序列，连续 Flow Matching 能并行生成动作块，避免部署时逐 token 自回归解码
有无单独消融 有整体证据：V-D 把 π0.5 与 π0、π0-FAST+Flow 三方对照（见第七节）。但论文没有单独做「同样数据、只换两阶段与否」的单变量消融

这处改动最容易被误读成「π0.5 放弃了流匹配」。实际相反：低层动作在部署时仍由 Flow Matching 生成，不做自回归动作 token 解码。自回归只用于可选的高层子任务文本；变的是训练期额外引入了离散动作表示。

三页分工：本页只给「改了什么、为什么」；两阶段的完整配方、FAST 分词器做了什么、组合损失的定义与三处易读错的地方，全部在 ③ 两阶段训练与组合损失；而「动作损失的梯度会不会伤害 VLM」这一层，是 ④ 知识隔离 的主题。

四、关键优化二：状态从连续 suffix 迁到离散 prefix

四栏 内容
π0 怎么做 本体状态经 state_proj 线性投影成 suffix 的一个 token，与含噪动作一同由动作专家处理
π0.5 怎么改 状态在数据侧离散化后拼进 prompt 文本，随语言 token 进入 prefix；模型侧不再构造 state_proj，suffix 里只有动作 token
为什么改 论文 IV-A 只陈述了事实（本体状态被离散化并作为文本 token 输入模型），未展开论证。可以确定的结构性收益见下
有无单独消融 无。论文没有做「只改状态位置、其余不变」的单变量实验，因此不能声称它独立提升了多少成功率

可以确定的结构性含义（不是已经验证的性能收益）：

  • 输入接口更统一。 状态被编码进 prompt token 序列；没有本体状态的样本可以省略这段文本，而不必经过连续状态投影。这是接口层面的简化，不等于所有样本内容相同。
  • 状态进入 prefix 的语义上下文。 prefix token 之间可相互注意，因此状态可与图像、指令共同形成供动作 suffix 读取的上下文；π0 的连续状态 token 位于 suffix，prefix 受因果掩码约束，不能反向读取它。
  • 与离散预训练兼容。 阶段一的监督目标是 token 交叉熵；把状态也表示为 token，能把机器人条件纳入同一离散输入接口。论文没有单独验证这一选择是否优于连续状态输入。

代价同样明确：

  • 量化会损失精度。 当前分箱在归一化坐标上使用 256 个边界，名义步宽约为 \(2/256\)；换算成物理误差还取决于每个状态分量的反归一化尺度、传感器与控制器，不能直接推导成“力控或亚毫米定位上限”。源码使用 np.digitize 且未在该处显式裁剪，超出 \([-1,1]\) 的输入还需特别检查。
  • 占用更多 token。 当前配置把 max_token_len 的默认值从 π0 的 48 提到 π0.5 的 200，以容纳离散状态及更长 prompt；这是默认容量选择，不是“必须恰好为 200”的理论结论。
实现细节（分箱写法、prompt 拼接格式，以及当前 pi05_libero 配置使策略前向不以本体状态为条件）见 ⑥ OpenPI 源码剖析；掩码含义见 ② 网络架构与结构差异。

五、关键优化三：时间步注入方式

四栏 内容
π0 怎么做 论文附录 A-E 的表述是：π0 把流匹配时间步 \(\tau\) 与含噪动作融合之后再送进 Transformer。对应源码里的 action_time_mlp_in / _out
π0.5 怎么改 用一个单独的 MLP 只投影 \(\tau\)，再用自适应 RMSNorm 把时间步信息注入动作专家的每一层。时间步 MLP 的形式是 \(\mathrm{swish}(W_2\cdot\mathrm{swish}(W_1\cdot\phi(\tau)))\)，其中 \(\phi\) 是正余弦位置编码
为什么改 论文只陈述了这一结构差异，未展开论证。可确定的结构性差别见下
有无单独消融 无。论文没有做「adaRMSNorm 对比拼接」的单变量实验，不能声称它独立贡献了性能提升

可以确定的结构性差别，以及一个需要明确标注的工程推断：

  • 注入次数不同。 拼接方案只在输入端注入一次，深层要靠残差把这个信息带下去；条件调制在动作专家的每一层重新注入。
  • 条件的作用位置不同。 π0 在输入嵌入处融合时间；π0.5 先得到一个样本级时间条件，再在动作专家每层的归一化处调制。论文没有证明逐层调制一定更容易学习。
  • 只作用于动作专家。 源码中 use_adarms=[False, True]，VLM 专家不接受时间调制。由此可以推断：prefix 表示不随积分步变化，具备复用 KV cache 的结构条件；但论文没有把“缓存”写成采用 adaRMSNorm 的原因，当前 JAX sample_actions 也没有显式实现跨 ODE 步的 KV cache，因此不能把它说成已兑现的加速。
adaRMSNorm 的具体形式（零初始化的调制头、split 成 scale / shift / gate、恒等映射起点）以及它作用在哪两个归一化位置，见 ② 网络架构与结构差异，本页不重复。

六、关键优化四与五：数据体系与任务层级

这两处虽然分列，但在论文里是同一套共训练配方的两个面，因此合并对照。

四栏 优化四：数据体系 优化五：任务层级
π0 怎么做 已使用多机器人数据（含 Open X-Embodiment），跨本体共训练不是 π0.5 首创 单层策略：指令加观测直接出动作块
π0.5 怎么改 在此之上加入网络图文数据（WD）、高层子任务与边界框标注（HL）、口头指令示范（VI），并把移动操作（MM）与多环境非移动数据（ME）作为主力 推理分两层：先自回归写出子任务文本，再以它为条件生成动作块，两层由同一个模型承担
为什么改 目标从动作技能迁移扩展到陌生场景、物体和指令的语义泛化；论文用 WD、HL、VI 等数据补充仅靠机器人动作数据难以覆盖的监督 显式子任务把长指令拆成可随观测更新的短程目标，降低低层策略同时承担任务分解与连续控制的负担；这是设计动机，不是数学必然
有无单独消融 部分有。V-C 对 WD / ME / CE 做去除实验，V-E 还分析 WD、HL、VI 对高层策略的影响；不同图的任务与指标并不相同 有方法对照，但并非全是单变量。V-E 比较 no HL、implicit HL、GPT-4 HL、human HL 等，部分基线同时改变高层模型或训练方式
这两处的详细内容都已在别处深讲，本页不重复：六类数据逐项、消融结果与那条「去掉 WD 后端到端不显著、陌生物体语言跟随显著变差」的现象在 ① 开放世界泛化与数据配方；分布分解式、两个出口的取舍、V-E 的两个反直觉结果在 ⑤ 分层推理与长时程执行。

七、论文 V-D：三方对照实验

这是论文中直接比较 π0 与 π0.5 的核心实验。它支持整套方法的比较，但不能回答每个结构改动各贡献多少。

7.1 三个对照模型

模型 它是什么
π0 原始 π0 VLA
π0-FAST+Flow 论文构造的增强基线：按 Eq. (1) 的 Flow Matching 与 FAST 动作 token 联合目标训练，并沿用混合训练流程；但只使用含机器人动作的数据，不含 HL 与 WD，因此不具备论文定义的高层推理出口
π0.5 完整模型

论文对实验设置的说明是：三者接受相同的跨本体机器人训练集，并训练可比的步数。作者把主要差异概括为两条：

  1. π0.5 额外使用了 HL 与 WD 数据；
  2. π0.5 采用混合训练流程——预训练阶段用离散 token 训练，后训练阶段才加入 Flow Matching 动作专家；π0 则全程使用动作专家。π0-FAST+Flow 沿用混合流程，但训练数据都带机器人动作。

7.2 结论与其边界

论文给出的结论有两层：

  • π0.5 显著优于 π0 与增强版 π0-FAST+Flow。
  • 即便把 π0 的训练延长到 300k 步，π0.5 优于 π0 的结论仍成立。作者据此并结合 FAST 工作，把结果解释为：FAST token 训练比纯连续动作的扩散式训练更具计算效率。

这条结论的边界必须说清楚。

π0-FAST+Flow 的作用是缩小基线与 π0.5 在训练流程上的差异：它采用混合配方，却不加入 HL、WD，也不能执行高层子任务推理。因此 π0.5 相对该基线的优势说明额外共训练任务与由此获得的高层能力是完整方法不可忽略的组成部分。但它仍不是“只开关 WD”或“只开关 HL”的单变量实验；两类数据、高层能力与完整推理流程同时相关，具体作用应回到 V-C、V-E 的专项实验判断。

同理，论文正文只说 π0.5 显著优于另外两个模型，并没有把“π0-FAST+Flow 与 π0 的柱高差”报告为一个独立、显著的训练流程效应。因此本页不再把两段柱高机械地分摊给“数据”和“训练”。“π0 延长到 300k 步仍不及 π0.5”主要支持作者关于训练计算效率的解释，不能证明状态位置或 adaRMSNorm 的独立贡献。

7.3 一个补充证据：语言跟随

论文附录 C（Fig. 15）另给出跨模型的语言跟随比较：π0.5 的语言跟随率略高于 π0-FAST+Flow，而远高于 π0。论文将这一现象解释为离散 token 训练对语言跟随能力很重要。

这里应保留“论文解释”这一限定。Fig. 15 是跨模型比较，不是“数据完全相同、只切换离散 token”的单变量实验；π0-FAST+Flow 代表的是整套混合训练基线。因此它为离散 token 的重要性提供支持，却不能推出“语言能力主要来自离散 token、而不是网页数据”的贡献比例。WD 对陌生物体语言跟随的作用，应由 Fig. 11 的 no-WD 消融单独判断。更严格的梯度与知识保持问题见 ④ 知识隔离。

九、一句话总结

π0 的重点是让 VLM 通过动作专家与 Flow Matching 生成连续动作；π0.5 进一步把问题推向开放世界泛化：如何利用异构数据理解陌生场景与物体，并把长指令分解为可执行子任务。它保留连续动作生成主线，同时加入离散动作预训练、六类数据共训练、显式高层子任务，以及状态和时间条件接口的调整。

这次演进的研究重心从“如何表示并生成连续动作”扩展到“如何通过数据共训练和分层推理实现开放世界泛化”。不过，完整模型的优势来自一组同时变化的设计；除论文明确给出的去除实验外，不能把性能提升归给某个单独结构件。
