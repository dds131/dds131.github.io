π0.7 总览/多样化提示/短时视觉与状态记忆

OBSERVATION HISTORY · MEM ENCODER · STATE ALIGNMENT

π0.7 用过去观测解释当前动作阶段：稀疏多视角图像与本体状态历史进入低层 VLA，MEM 视频编码器把时间信息压入当前视觉表示。

论文写的是每路 up to six history frames、stride 为 1 秒；它没有明确 current 是否计入六帧，因此不能直接改写成“five past + current”或精确 5 秒回看。本页中的 π0.7 读作 pi zero point seven。

PI07_PAPERMEM_METHODHISTORY_INDEXING_AMBIGUITYruntime NOT_RUN

一、历史为何是 Observation 而非 Prompt

Observation/history 记录机器人实际看见和经历的事实；Prompt/context 指定希望执行的任务、步骤、结果和动作语义。历史图像与状态因此不属于 metadata，视觉子目标虽也是图像，却表达期望未来，不能写进事实历史。单帧中相似的夹爪姿态可能对应“准备抓取”“失败后重试”或“完成后撤离”，历史的作用是提供变化方向与近期上下文，而不是增加一种新指令。PI07_PAPER

当前事实、过去事实、未来目标与语言摘要不能混为一种 memory
对象 时间语义 位置 π0.7 可确认 不能推出
当前 observation 当前事实 低层 VLA 多视角图像 + proprio state 单帧足以判断动作阶段
历史视觉 / 状态 过去事实 低层 VLA 秒级稀疏历史；精确 span 未确认 无损保存全部事件
Visual subgoal 期望未来 外部 context 可选近未来条件 事实 observation 或 action rollout
Language memory 过去语义摘要 完整 MEM 高层系统 π0.6-MEM 的显式机制 π0.7 低层已实现同一摘要状态机

“历史可帮助区分遮挡或近期失败”是 MEM 的机制动机，不是 π0.7 在所有任务上的实测保证。信息可能在压缩中丢失，稀疏采样可能漏过快速事件，错误或陈旧观测可能形成偏置，视觉与状态也可能时间错配；这些限制必须与动机同时保留。

四类对象即使共享视觉或文本编码通道，也不能按张量外观合并语义。事实 observation 可用于判断刚才真正发生了什么；visual subgoal 只表达希望未来呈现什么；subtask history 记录高层发过哪些语义步骤；显式 language memory 则是完整 MEM 系统的压缩摘要。把未来条件当历史会造成因果误读，把高层摘要算进低层六帧窗口又会夸大 π0.7 已公开的记忆范围。

二、π0.7 公开的历史输入合同

数字均带对象和作用域，不组合成未公开的固定 ABI
项目 π0.7 论文可确认 作用域 不可推出
相机 front、two wrist、optional rear；最多四路 空间视角 固定四路或所有平台相同
历史 每路 up to six history frames 时间样本上限 five past + current、six past + current
采样 history stride = 1 秒 历史抽样间隔 20Hz / 50Hz 控制频率或 4 秒 subgoal 刷新
图像 camera observation 与 subgoal image 缩放到 448×448 模型视觉输入 原始传感器分辨率
状态 当前与历史 proprioceptive state 逐时刻线性投影 字段、单位、维度与 normalizer

最多四路 camera 是空间视角数，最多六个 history frames 是每路时间样本上限，最多三路 subgoal images 是不含 rear 的未来条件；三者不能相乘成官方固定输入数。HISTORY_INDEXING_AMBIGUITYMEM_PI06_CONFIG_ONLY

即使 K 恰好取 6，π0.7 的原文也不足以确定最早帧和当前帧之间有五个还是六个 1 秒间隔。启动阶段是否允许 K<6、缺少历史时如何 padding、各相机是否严格共享采样时间点也未报告。因此页面保留上限和 stride 两个独立事实，不把它们组合成唯一 lookback span，更不把这一稀疏采样节奏当作相机采集速率。

三、MEM 视频编码器的时空分离注意力

π0.7 明确采用 MEM history vision encoder；编码机制由 MEM 论文说明。单帧含 (n) 个 spatial patches、共有 (K) 个 observation timesteps 时，编码器先逐帧 patchify；常规 ViT 层在单帧内做双向空间注意力；每第 4 层再让同一 spatial patch 跨时间执行 causal temporal attention。MEM_METHOD

朴素时空联合注意力对应主项为 (\mathcal O(n^2K^2))，分离后为 (\mathcal O(Kn^2+nK^2))。这里 (n) 是单帧 spatial patch 数，(K) 是 observation timestep 数；渐近式只描述相应注意力操作，不是全模型端到端延迟，也不证明随 K 完全常数、显存固定或吞吐不变。

MEM 组件相对标准单图 ViT 不新增 learnable parameters：它复用原 ViT 投影，使用固定 sinusoidal temporal position encoding，且 (e(0)=0) 使 K=1 初始化与原 VLM 匹配。π0.7 未公开完整实现，不能进一步补造层号列表、patch 数、head 数、KV cache 或缓存布局。

“不新增 learnable parameters”只限定 MEM 论文所述时间注意力改造相对标准单图 ViT 的参数化方式，不表示整个 π0.7 没有新增模块，也不表示多帧前向免费。K 个时刻仍要 patchify 并参与多层空间与时间计算；只在上层把输出收敛回单时刻 token 数。因此参数量、输入 token 峰值、算力、显存与最终接口宽度是四个不同量，不能互相替换。

四、状态历史与成组缺失

π0.7 将当前与历史 proprioceptive state 线性投影到 backbone dimension，每个 history state 形成一个 individual token。状态不经过视觉压缩，但必须与对应视觉时刻对齐；当 entire history frames 被 dropout 时，对应 state token 也被 mask，避免状态泄露已删除时刻的信息。PI07_PAPER

训练缺失规则不能替代部署同步和缺帧合同
对象 论文规则 阶段 / 概率 未报告或不可推出
Entire history 整组 history frames dropout 训练期 0.3 逐帧或逐相机独立 Bernoulli
History state 随对应历史视觉一同 mask 训练期成组缺失 部署传感器故障策略
Optional rear 另有 rear-view dropout 训练期 0.3 与 history dropout 独立或互斥
Deployment alignment 没有公开正式实现合同 NOT_REPORTED timestamp、同步容差、插值、复制末帧、零填充

论文没有说明两种 0.3 dropout 的独立性、应用顺序，或单位是 example 还是 camera stream；不得计算 0.7×0.7 或联合 presence。部署确实需要 timestamp、相机/状态同步和缺帧政策，但这些是工程门禁，不是可从论文补出的默认值。

成组 mask 的目的，是避免已删除的视觉时刻仍通过状态 token 泄露给模型；它没有定义真实传感器部分掉线时应怎么处理。部署若遇到单相机缺帧、状态晚到或时间戳乱序，需要先由独立输入合同判定拒绝、等待、重采样还是降级。页面不能把训练增强直接升级为故障恢复策略，也不能推荐复制末帧或零填充，因为这些选择会改变模型看到的时间语义。

五、因果性、压缩与信息边界

MEM temporal attention 的 causal mask 只允许当前表示读取当前与过去位置；帧内空间注意力仍为双向。它阻止 history encoder 从未来历史帧取信息，但不自动证明数据切片、标签、subgoal 或评测协议不存在其他泄漏。π0.7 主干的 block-causal 规则由 Architecture 页负责；本页不裁决其 ORDERING_TENSION。

“与单帧相同数量的 token”只说明输出接口宽度：过去表示在上层被丢弃，历史信息要压进 current-timestep representation。它不表示过去信息无损、过去帧零计算、原始帧可重建、所有 K 延迟相同，也不保证 K 增加时表现单调改善。训练中的真实 future image 是 visual subgoal，不是 history；运行时生成 subgoal 也不能写回事实时间轴。

四类限制必须显式保留：压缩可能丢失事件；1 秒稀疏采样可能遗漏快速变化；错误或陈旧 observation 可能偏置当前动作；图像与状态对齐错误可能制造不存在的场景。其中“稀疏采样遗漏快速事件”是工程风险，不冒充论文已测失败。

六、短时视频记忆与长期语言记忆

完整 MEM 系统包含低层 video-based observation memory 与高层 text-based language memory (m_t)。后者根据前一摘要、当前观测与任务更新语义摘要并产生下一 subtask；15 分钟记忆与语言摘要结果属于完整 π0.6-MEM 系统。π0.7 明确继承的是 history vision encoder from MEM，只另外说明高层 language policy 读取 robot observations、task specification 和 past subtask instruction history；论文没有确认复用显式 (m_t\rightarrow m_{t+1}) 摘要机制。

因此，π0.7 历史视觉/状态是低层事实过去；π0.7 subtask history 是高层文本上下文，窗口未报告；MEM 显式 language memory 是 π0.6-MEM 完整系统的语义摘要；visual subgoal 是期望未来而不是 memory。π0.6-MEM post-training 曾扩展到最多 18 帧和 54 秒 observation-based memory，这只说明 MEM 方法在该实验中可扩展，不证明 π0.7 支持 18 帧、54 秒、任意长度或 15 分钟 dense visual history。MEM_PI06_CONFIG_ONLY

π0.7 高层读取 past subtask instruction history，说明历史语言可作为高层输入，却没有公开摘要何时更新、窗口多长、是否持久化或怎样与低层视觉历史同步。故而不能把 MEM 的 (m_t) 摘要递推公式直接贴到 π0.7，也不能用完整 MEM 的长任务结果填补 π0.7 低层能力。这里的界线是“论文明确继承哪个组件”，而不是两个系统是否在概念上相似。

七、动作块闭环、延迟与实验边界

历史、动作块与再规划构成闭环，但不是同一长度：① 收集新的真实图像与状态历史；② 低层用 5 个 denoising steps 预测 50-step action chunk；③ 运行时从每块执行 (\hat H\in{15,25}) 步；④ 新 observation 进入下一轮推理。它不表示先生成 50 步再同步等待固定时长，也不表示 history 每 15/25 步才更新。

training-time RTC 模拟 0–12 timesteps 延迟；只有在 50Hz 机器人上才对应最多 240ms。UR5e 为 20Hz、其余论文机器人为 50Hz，因此 50-step chunk 的名义时长分别是 2.5 秒或 1 秒，执行 15/25 步的墙钟时间也不同；history stride 仍独立保持 1 秒。服务队列、prefix 承诺和平滑见 Inference。PAPER_RUNTIME_SETTING

Appendix A-D 只报告最小 variant 在 3 cameras、5 denoising steps、training-time RTC、单张 H100 条件下为 38ms；同时启用 MEM vision encoder 与 subgoal images 的联合最坏情况为 127ms。后者必须标为 JOINT_LATENCY_ONLY，不能分离成 MEM 自身开销，也不能与 world model 约 1.25 秒生成时延混合。

Section IX-A 比较同一个 out-of-the-box π0.7 与 MEM 论文中为部分任务专门微调的 π0.6 memory specialists；Fig.8 的文字结论只支持在需要明确追踪先前上下文的任务上表现相近或更好。页面不目测柱高，不外推所有任务、本体或 history 长度，也不把系统间差异单因果归于 history encoder；没有 π0.7 memory/no-memory 消融数字。PAPER_RESULT

38ms 与 127ms 也不能作简单相减来宣称“MEM 开销为 89ms”：两项配置同时改变了 MEM 与 subgoal 等因素，且论文只给联合端点。相同理由下，Fig.8 的系统级差异包含模型版本、数据、Prompt、metadata 与训练配置。没有单因素对照时，运行时间和任务表现都只能按原协议报告，不能拆成某个组件的独立贡献。
