一、本页在专题中的位置

Soft Prompt 和域专属动作头都不是 X-VLA 首次提出的组件。X-VLA 的关键贡献是把它们组织成一条简洁的跨本体条件化路径：域专属控制流输入投影（动作、状态与时间）+ 域专属 Soft Prompt + 共享 Transformer + 域专属动作输出投影。域信息因此能从动作生成主干的第一层起参与融合，而无需为每个域复制整套主干。本页只讲这条机制及其证据边界。

二、异构性为什么会造成负迁移

2.1 先把问题写成一个混合分布

设数据源索引为 \(d \in \{1,\dots,H\}\)，训练采样器抽到第 \(d\) 个数据源的概率为 \(\rho_d\)。这里 \(o\) 统称除域标签外的模型可见条件，例如图像、语言与本体状态；为突出域混叠，本小节先采用直接动作回归的抽象。该域的条件分布记为 \(p_d(o)\)，专家动作条件分布记为 \(\pi_d(A\mid o)\)。合并数据后的联合分布是

\[p(d,o,A)=\rho_d\,p_d(o)\,\pi_d(A\mid o).\]

如果模型只接收 \(o\)、不显式接收 \(d\)，它面对的动作条件分布为

\[p(A\mid o) =\sum_{d=1}^{H}p(d\mid o)\,\pi_d(A\mid o), \qquad p(d\mid o)=\frac{\rho_d p_d(o)}{\sum_j \rho_jp_j(o)}.\]

这里的混合权重一般依赖观测 \(o\)，不能直接用全局轨迹占比代替。若机器人外观、相机视角或 proprioception 已经足以识别来源，\(p(d\mid o)\) 可能接近 one-hot，模型便能隐式区分域；真正困难的是观测或内部表示发生混叠，但不同域要求不同策略的区域。

先用直接动作回归的均方误差作一个说明性例子。对固定观测 \(o\)，不带域条件的 Bayes 最优预测是

\[A^{*}(o) =\mathbb{E}[A\mid o] =\sum_{d=1}^{H}p(d\mid o)\,\mathbb{E}_{\pi_d}[A\mid o].\]

当多个域在同一可观测条件下具有不同的条件最优动作时，这个解通常不能同时成为各域的最优解。域条件的作用，就是把一个有歧义的 \(p(A\mid o)\) 还原为更明确的 \(p(A\mid o,d)\)。

上式是解释“缺少域条件时为何会发生监督折中”的玩具模型，不是 X-VLA 论文的 Flow Matching 原式。按论文参数化，平方损失下的 Bayes 最优速度预测为 E[A − A⁰ | Aᵗ, o, t]；Flow Matching 能表示多模态动作分布，但仍需要足够条件信息来区分不同域的速度场。当前官方实现实际回归干净动作而非速度场，这一论文—源码差异及其数学后果见子页 ③，本页不混用两套目标。

2.2 四个层面各自在哪一步造成伤害

枢纽页列出了异构性的四个层面，本节说明每一层具体怎么污染训练信号。

层面 表现 对训练的具体伤害
动作空间与自由度 维度、通道顺序、单位、正方向或坐标系不同 未对齐时，同一输出通道在不同样本上可能具有不同物理语义，监督目标与梯度发生冲突
相机配置 路数、安装位、内外参不同；有无腕部相机不同 产生观测分布偏移并改变像素到三维空间的对应关系。模型有时能从图像隐式识别机位，但这增加了学习负担，遮挡或对称场景下还可能产生歧义
控制语义与频率 绝对/增量控制、末端坐标系和采样频率不同 对增量动作而言，频率会改变数值尺度；对绝对位姿目标则不一定。若不统一控制接口与时间尺度，相同数值可能代表不同运动，或相同运动对应不同目标
数据与任务风格 任务分布、遥操作习惯、失败重试比例与数据质量不同 改变条件分布与经验先验；任务指令不充分时还可能改变“什么是正确动作”，大数据源会进一步主导共享表示

这些问题不是互斥分类：动作接口主要是语义对齐问题，相机更接近协变量偏移，任务与采集风格则同时影响先验和监督。X-VLA 组合使用了三类手段：统一动作表示减少接口冲突，Soft Prompt 与域专属动作投影提供条件化，加权采样缓解大域支配。任何单一手段都不能自动消除全部异构性。

2.3 数据不平衡把上面所有问题放大一遍

X-VLA 预训练混合中，最大的数据源 AGIBOT 有 141K 条轨迹，最小的 RoboMind-Dual-Franka 只有 2K（层一，Table 8）。若每条轨迹被等概率使用，两者的自然轨迹占比相差约 70.5 倍；实际训练中的样本占比还会受到轨迹长度和采样器实现影响。

论文给出的采样权重与轨迹数并不成比例，这一点值得注意（层一 Table 8，与层二 datasets/domain_config.py 的 DATA_WEIGHTS 完全一致）：

数据源 轨迹数 采样权重 权重与自然比例的关系
AGIBOT 141K 0.40 被压低（自然比例约 0.49）
Droid-Left 45K 0.15 略低于自然比例 0.156
Droid-Right 45K 0.15 略低于自然比例 0.156
RoboMind-UR 25K 0.10 由约 0.087 抬高
RoboMind-Franka 19K 0.10 由约 0.066 抬高
RoboMind-Agilex 11K 0.07 由约 0.038 抬高
RoboMind-Dual-Franka 2K 0.03 约为自然轨迹占比的 4.32 倍

即：权重被向均匀方向拉，但没有拉到完全均匀。这样既降低 AGIBOT 的支配程度，又没有把 2K 轨迹的小域提高到每域约 14.3% 的完全均匀权重。它体现了数据覆盖与重复采样风险之间的折中；论文没有单独消融证明当前权重是最优值。

2.4 论文给出的实测：负迁移是真实存在的

上述分析在论文里有对应的实验证据（层一，Table 1）：

设置 预训练验证误差 Simpler-WidowX 下游成功率
基线，不预训练 – 4.1
只加定制学习率，仍不预训练 – 39.6
加上朴素异构预训练 0.11 25.0

也就是说，在异构数据上做了预训练之后，下游成功率反而比不预训练低了 14.6 个百分点。论文该表的 caption 原话是「朴素地在异构数据上训练会导致退化」。

这条结果的解读要谨慎。它不是说「预训练没用」，而是说：在这条累积消融路径中，加入尚未充分对齐的异构预训练后，成功率从 39.6 降到 25.0。同一张表随后把动作对齐、意图抽象和均衡采样作为一组加入，成功率到 50.0；再逐步加入编码流水线、Soft Prompt、模型扩展和两步适配，最终到 95.8。因为这是累积消融而非全因子实验，它能说明每一步的边际变化，不能把组合收益唯一归因于其中某个机制。

三、四种处理方案与各自的失效点

论文第 3 节把已有做法归纳成三类，加上自己的方案共四种，用 Fig. 2 并列示意、用 Fig. 4 对比训练曲线。

3.1 方案 a：每个数据源一个动作投影

最直觉的做法：主干完全共享，只在最后一层按数据源换一个线性投影。

论文的批评是：它的作用范围仅限于动作生成的最后一步，因此无法促使流水线更早的阶段做出「意识到本体」的推理，也没有在共享主干内部显式提供处理相机配置、任务分布等异构性的域条件。模型仍可能从图像、状态和指令中隐式识别这些差异，但识别负担完全落在共享表示上。

设共享主干产生表示 \(h=g_\theta(o)\)，域专属动作头给出

\[A_{d_1}=W_{d_1}h+b_{d_1},\qquad A_{d_2}=W_{d_2}h+b_{d_2}.\]

不同的 \(W_d\) 可以把同一个 \(h\) 映射成不同动作，因此末端动作头并非不能表达域差异。它的限制是：显式域条件只能改变最后的线性读出，不能参与此前动作主干对视觉 token 的选择性读取、可达性判断和跨模态融合；它也不能反向改变已经完成的 VLM 编码。所有域必须共用同一套非线性特征提取；若任务需要域条件参与早期推理，共享表示就必须同时保存各域可能需要的特征，容量与优化负担更大。

Soft Prompt 的优势是扩大域条件能够影响的计算范围，而不是证明末端头在数学上无法产生不同策略。

3.2 方案 b：HPT 式的中间投影

HPT-style 方法在多模态观测进入共享 DiT 主干之前，使用每个域独立的 cross-attention resampler 将输入映射到共享表示空间，并保留域专属动作头。它比末端分叉更早处理观测差异。

论文的解释是：不同域经过各自的中间投影后，送入共享主干的特征分布会随域变化，可能损害预训练 VLM 表示并带来不稳定训练。需要区分事实与归因：Appendix I 明确给出了 cross-attention resampler 的实现形态，但论文没有通过受控实验验证这种分布改变是否是失败的唯一原因，因此本页不把它简化成“随机线性层破坏表征”。

3.3 方案 c：硬件语言提示

把硬件配置写成一段自然语言，拼进语言指令里。论文 Appendix I 给出了它实际用过的模板（层一，Table 10），例如：

RoboMind-Franka      | Embodiment: Single Franka, Camera Setup: Top View, Freq: 30Hz
Droid-Left           | Embodiment: Single Franka, Camera Setup: Left View / Wrist View, Freq: 15Hz
AGIBOT               | Embodiment: AGIBOT, Camera Setup: Head View / Wrist View, Freq: 30Hz
RoboMind-Dual-Franka | Embodiment: Dual Franka, Camera Setup: Front View / Wrist View, Freq: 30Hz

这个方案的优点是注入得足够早（直接进语言 encoder），而且人类可读。论文的批评集中在可扩展性：它依赖精心编写的文本描述，实践中严重妨碍适应性与可扩展性。

下面三点中，第二点直接对应论文的可扩展性批评；第一、三点是对其具体模板的机制分析，论文没有单独消融：

  • 这组模板的信息分辨率有限。论文只写了 Top View、30Hz 等粗粒度描述，没有提供相机外参、视场角或控制标定。自然语言原则上可以写入数值参数，因此问题不在“词表必然无法表达连续量”，而在于当前模板省略了哪些变量、数值如何规范化，以及模型能否稳定利用这些描述。
  • 需要人来决定写什么。哪些硬件属性重要、粒度多细、用什么措辞，都要人工判断；换一个数据集就要重写一遍。
  • 硬件描述与任务指令共用语言通道。这会增加序列长度，并可能引入措辞敏感性；是否会明显争夺注意力，需要专门实验验证，不能仅凭结构断言。

3.4 方案 d：Soft Prompt

Soft Prompt 像 HPT-style 方法一样使用可学习的域专属表示吸收差异，也像语言提示一样显式提供域条件；区别在于它以 token 形式接入共享动作主干，避免为每个域插入独立的中间投影，同时免去逐域编写硬件文本。这里的“无需手工标注”不能理解为完全不需要域元数据：训练仍要由人定义数据源划分，并为每个样本提供正确的 domain_id。

“保留预训练表示”是论文相对于域专属中间投影的结构性主张，并不表示预训练阶段把 VLM 或动作主干冻结。论文明确写明主干与 soft prompt 联合优化，并对 VLM 与 prompt 使用较小学习率；真正先冻结共享参数的是下游两步适配的前 1000 次迭代。

四、Soft Prompt 的定义与实现

4.1 论文层的定义

论文（层一，第 3 节 d）写：引入数据源专属的可学习参数

\[\mathcal{P}^{H} = \{\, p_i \,\}_{i=1}^{H}\]

来吸收跨数据源的异构性，其中 \(p_i\) 被期望编码底层硬件配置：

\[p_i \approx \Phi(h_i), \qquad \Phi : \mathcal{H} \to \mathbb{R}^{k}\]

\(\Phi\) 是从硬件配置空间 \(\mathcal{H}\) 到提示空间的一个隐式映射。论文强调两点：\(\Phi\) 不像语言提示那样由硬模板预先定义，而是随机初始化后由端到端训练隐式优化；这些提示在动作生成的早期阶段被注入模型，自动引导主干走向「意识到本体」的学习。

论文没有给出 \(k\) 的数值，也没有给出每个 \(p_i\) 包含多少个 token。

4.2 源码层的实现

4.3 三个容易忽略的实现选择

其一，整组 prompt 被展平成 embedding 表的一行。 self.soft_prompt_hub(domain_id) 可以按样本一次取回一个混域 batch 所需的多组 prompt，避免按域拆分前向。它是高效的向量化查表方式，不是均衡采样在数学上成立的前提；三维参数张量配合索引同样可以实现。

其二，prompt 拼在序列末尾，不是前缀。 X-VLA 使用无 mask 的双向全注意力，因此前缀与后缀在可见性上相同。在关闭 dropout 的确定性前向中，若原 token 的位置编码不变、prompt 仍无位置编码、没有位置相关 attention bias 且读出索引保持正确，移动或重排 prompt 不会改变动作 token 的输出。训练时逐元素 dropout 的随机掩码会破坏单次前向的严格相等，但不改变模型结构与随机掩码分布层面的置换对称性。这个结论不能推广到因果注意力或带位置偏置的任意 Transformer。

其三，prompt 不带显式位置或类型编码。 pos_emb 在 torch.cat 之前只加到原序列。网络能依据 prompt 向量的内容区分不同槽，却看不到独立的 prompt 序号或“未加位置编码”的生成历史。因此 prompt 内容可以成为域条件信号，但不能把“缺少位置编码”本身称为有保证的类型标记；32 个槽也不是具有固定语义顺序的 32 个硬件字段。

五、为什么论文强调「提前注入」

本节用注意力计算说明“提前注入”的精确含义：Soft Prompt 扩大了显式域条件能够影响的计算范围，但不构成“其他条件化方案在理论上不可替代”的证明。

论文方案 a 只在输出端使用域专属投影；完整 X-VLA 还包含主干之前的域专属 action_encoder。因此 Soft Prompt 不是实现中唯一的早期域条件：输入投影先改变控制 token，Prompt 则作为独立 token 被所有序列位置读取。Table 1 只能说明在已有组件之上加入 Soft Prompt 的边际变化。

5.1 两种注入方式的信息流对比

5.2 一层注意力里，prompt 到底做了什么

记序列为 \(X=[\,x_1,\dots,x_n,P_1,\dots,P_L\,]\)，并令 \(Z=\operatorname{LN}(X)\)。对注意力头 \(h\)，令 \(Q^{(h)}=ZW_Q^{(h)}\)、\(K^{(h)}=ZW_K^{(h)}\)、\(V^{(h)}=ZW_V^{(h)}\)。对任意普通 token \(i\)：

\[a_{ir}^{(h)} = \frac{\exp({q_i^{(h)}}^\top k_r^{(h)}/\sqrt{d_k})} {\sum_{u=1}^{n+L}\exp({q_i^{(h)}}^\top k_u^{(h)}/\sqrt{d_k})},\] \[u_i^{(h)} = \sum_{j=1}^{n}a_{ij}^{(h)}v_j^{(h)} + \sum_{l=1}^{L}a_{i,n+l}^{(h)}v_{P_l}^{(h)}, \qquad y_i=W_O\operatorname{Concat}_{h}u_i^{(h)}.\]

其中 \(d_k\) 是单个 head 的维度；在每个 head 内，普通 token 与 prompt token 的权重属于同一个 softmax，总和为 1。上式描述关闭 dropout 时的多头注意力，并省略残差连接与 MLP。对当前层普通 token 的直接输出，Prompt 通过两条通路起作用：

  • Value 通路：提示的 Value 可以直接贡献到普通 token 的更新中。不同 token 的 Query 不同，因此可以以不同权重读取同一组域条件；这说明机制具备选择性读取能力，并不证明某个 prompt 维度已获得“动作尺度”或“腕部相机”等可解释语义。
  • Key 通路：提示的 Key 参与 softmax 分母，改变分配给原 token 与提示 token 的总注意力质量。若在某一层假设 prompt Value 全为零，原 token 之间的相对权重在该层保持不变，只会被共同缩放；进入后续层后，由于表示及 Query/Key 已改变，注意力图才可能进一步重新组织。

Prompt 的 Query 还会读取普通 token，从而更新 prompt token 自身；这条影响不会直接出现在当前层普通 token 的输出中，而会从下一层起经 Prompt 的 Key/Value 回流。

5.3 24 层都能读到意味着什么

单层调制之后，更新后的普通 token 与 prompt token 会一起进入下一层；因此第 2 层及以后计算 Query、Key、Value 时，域条件可以继续传播。这里应说通过层间函数复合反复传播，而不是“乘性累积”：残差网络中影响可能增强、衰减，也可能被某些注意力头忽略。准确说法是 24 层都具备读取 prompt 的结构通路，并不保证每层实际都赋予显著注意力。

把这件事和方案 a 对照一下就很清楚。方案 a 中条件只出现在最后一步：

\[A_d = W_d \, g_\theta(o)+b_d\]

条件能改变的函数族是 \(\{\, W\, g_\theta(o)+b : W \in \mathbb{R}^{m \times h},\ b\in\mathbb{R}^{m} \,\}\)，即在固定表示上的一族仿射映射。

方案 d 中条件从输入进入：

\[A_d = W^{\text{out}}_d \, g_\theta(o,\, P_d)+b^{\text{out}}_d\]

此时改变 \(P\) 会改变共享主干内部的非线性计算，因此域条件不再局限于最后的线性读出。可表达能力仍同时受 prompt 长度、主干深宽、注意力模式、动作头和优化过程约束，不能只归因于主干深度。

这就是论文所说“末端投影无法促成更早的本体感知推理”的精确含义。Table 1 的累积路径中，在已有编码流水线之上加入 Soft Prompt 后，成功率从 64.6 提升到 73.8、验证误差从 0.053 降到 0.041；这是该实验路径上的 9.2 个百分点边际变化，并非 Soft Prompt 脱离其余组件时的独立效果。

六、Soft Prompt 到底学到了什么

6.1 论文的 t-SNE 观察

论文把 7 个数据源学到的 prompt 做了降维可视化（层一，Fig. 8）。

论文给出的观察是：提示形成了结构良好的簇；更值得注意的是，来自 Droid 的两个 Franka 配置（左视角与右视角）是混杂在一起而非彼此分离的，因为它们只在指定的主视角上有差别。论文据此认为，soft prompt 并不是以暴力方式划分数据源，而是在利用跨本体的相似性。

这幅图只能作为定性线索：Droid 的两个 Franka 视角在二维图中混杂，与论文“提示利用了配置相似性”的解释相容。但 t-SNE 不保持全局距离，任意可学习的 domain ID 嵌入也可能形成不等距结构；因此这张图既不能排除“主要编码数据源编号”，也不能证明高维 prompt 空间已经形成连续、可度量的机器人形态空间。要验证后一结论，还需要跨随机种子、线性探针、距离相关性或 prompt 插值等实验。

6.2 严谨的表述：它是 domain latent，不是 morphology embedding

论文把 \(p_i\) 写成 \(\Phi(h_i)\)，\(h_i\) 是硬件配置。但必须注意：

  • 没有显式监督把 p_i 绑定到硬件量上。prompt 通过策略的动作相关目标获得梯度；自由度、连杆长度、相机外参等属性没有作为独立监督标签出现。
  • 一个「数据源」不等于一台机器。划分依据是数据集条目：Droid 的左视角与右视角是同一种机器人的两个条目，却占两个槽位；反过来，同一台机器上采的两批风格迥异的数据也可以被划进一个槽位。
  • 它可能吸收硬件之外的东西。任务分布、遥操作习惯、失败重试比例、标注口径等因素若与数据源高度相关，动作损失就可能把它们与硬件差异一起编码进 prompt；仅凭现有实验无法把这些因素解耦。

因此，更谨慎的称呼是：\(p_d\) 是由动作相关训练目标隐式学习的数据源级条件 token 集合，而不是已经得到验证的“机器人形态嵌入”。论文自己的措辞也留了余地——用的是「被期望编码」（is expected to encode）而不是断言。

6.3 论文没有做的两件事

这两条在二手材料里常被当成 X-VLA 的能力来介绍，但论文里并不存在对应实验：

Prompt 插值论文完全没有做过在两个数据源的 prompt 之间插值、并检验插值点是否对应某种「中间本体」的实验。这是一个自然的后续问题，但目前没有证据。
Zero-shot 新本体论文没有对完全没见过的本体做零样本评测。第 5.3 节的原话是这为跨本体迁移指出了一条有前景的路径，并说随着在更多平台上预训练，soft prompt 或许能够通过检索最接近的硬件配置来实现零样本或少样本泛化。这是展望，不是结果。

从机制上也能看出为什么零样本困难：一个从未出现过的数据源没有经过训练并与它绑定的 prompt。可以复用一个「最像」的已训练 prompt（论文做过冻结迁移实验，见第 7.2 节），也可以为目标域分配新的参数行并用数据适配；固定公开实现预分配了 30 行，但“表里有空余行”不等于该行已经携带目标域信息。

七、新本体接入：两步适配

7.1 两步的顺序与理由

论文 Appendix H 给出的流程是（层一）：前 1000 次迭代只更新 soft prompt 与动作头，其余参数冻结；随后解冻全部参数，在联合训练的前 1000 次迭代中把学习率逐步恢复到默认值。论文的“动作头”在固定训练脚本中对应 action_heads 参数组，即 action_encoder 与 action_decoder。

论文在抽象上把目标域参数记为新 prompt；固定公开实现则在预分配的 30 行域参数表中为目标域指定一个 domain_id。train.py 从 checkpoint 加载后没有新增参数行或显式重新初始化目标行，因此不能断言适配起点仍服从模型构造时使用的正态分布。

flowchart LR
  A["新平台数据就绪"] --> B["为目标域分配 domain_id<br/>选择对应的域私有参数行"]
  B --> C["阶段一 1000 步<br/>只更新 prompt 与控制流输入/动作输出投影"]
  C --> D["阶段二 解冻全部参数并联合训练<br/>前 1000 步执行学习率 warm-up"]
  D --> E["继续按正常学习率计划联合训练"]

为什么先局部适配、再联合训练：

第一阶段固定已经预训练好的共享主干，只让目标域对应的 prompt 与动作投影适配目标域。这样做把早期优化限制在少量域私有参数内，既保护已有表示免受目标域小数据造成的剧烈漂移，也让这些参数先对齐固定的特征空间。

第二阶段解冻全部参数并开始联合训练，同时以 warm-up 逐步恢复学习率，使模型能修正“只调域私有参数”无法弥合的剩余域差距，并降低突然全量更新带来的优化冲击。

这是对该流程的机制性解释。论文报告了两步适配的效果，但没有给出“颠倒顺序”的对照实验，也没有展示早期梯度范数或“随机梯度占主导”的证据，因此不能把该顺序写成数学上不可颠倒的结论。

Table 1 的累积消融中，最后加入两步适配后，成功率从 89.6 提升到 95.8，即在该完整配置上的 6.2 个百分点边际变化；这个数字不能单独证明上述机制，更不能视为跨任务恒定收益。

7.2 论文的冻结 prompt 迁移实验

论文第 5.3 节比较了三种设置：随机初始化后冻结、取自 UR5 的预训练 prompt 后冻结、以及两步适配。

关于第二种，论文的结论是：由于 UR5 与 WidowX 之间存在部分相似性，冻结的预训练 prompt 在早期阶段带来了很强的迁移收益；但不可避免的域间差距限制了最终性能。

这个结果同时说明了两件事：

  • 在论文测试的 UR5 → WidowX 迁移对上，复用预训练 prompt 比随机冻结初始化包含更多可迁移信息；这支持“prompt 不只是无意义随机向量”，但不足以证明整个 prompt 空间的几何距离都对应本体相似度。
  • 相似不等于相同。冻结旧 prompt 无法适配剩余域差距，因此最终表现受限；两步适配允许新 prompt 与动作头先学习目标域，再联合调整。

7.3 源码里 freeze_steps 的实现方式

官方 train.py 的 --freeze_steps 1000 实现了第一阶段的“参数值暂不更新”（层二），但它只是把 vlm 与 transformer_core 两个参数组的学习率置为 0，并不修改 requires_grad。因此这两组仍会计算和同步梯度，且梯度仍进入全局范数裁剪；只要对应参数的 grad 不是 None，AdamW 的一、二阶矩与步数状态也会随 optimizer.step() 演化。它既没有真正冻结带来的反向计算、通信与激活显存节省，也不与“前 1000 步完全不参与优化过程”严格等价。

还要区分论文流程与默认命令：调度器只有在显式传入 --use_cosine_decay 时才使用 warmup_steps；该开关默认关闭，README 示例也未开启。论文 Appendix H 写的是解冻后约 1000 步 warm-up，而源码参数默认值是 2000；复现实验时应显式设置两项参数，不能只依赖默认值。

这两点的完整代码、四个参数组的划分与学习率调度函数，见子页 ④。

八、论文自陈的两次失败尝试

论文 Appendix E 记录了两条走不通的路。这类内容在二手材料里几乎看不到，但对判断「还有哪些方向值得试」很有价值。

异构 LoRA思路是给每个数据源配一组 LoRA 适配器来吸收异构性。论文的结论是：额外的适配器常常与主干的优化动力学相冲突，导致训练不稳定，并使跨数据源的泛化能力下降。
异构性引导的专家混合思路是用 MoE，让路由器按异构性把样本分给不同专家。论文发现路由器倾向于坍缩，把绝大多数输入始终送给少数几个专家。加入负载均衡正则之后，专家之间的快速切换又让优化变得不稳定。

论文分别报告了 LoRA 的训练不稳定与泛化下降，以及 MoE 的路由坍缩和负载均衡后的优化不稳定。它们共同提示：按域增加专属参数或动态路径，可能加大混合域优化难度；但论文没有做受控实验来证明二者存在唯一、相同的失败原因。

Soft Prompt 的区别是：各域仍使用同一组主干权重和同一种计算路径，变化的是输入序列中的条件 token。它确实会改变各层激活与注意力分布，所以不能说“主干内部完全不受干预”；更准确的说法是结构与参数共享，激活按域条件化。

MM-DiT 对照及其因果边界见第 3.4 节。两类失败尝试与该对照共同提示了优化风险，但没有证明“更复杂的条件化结构必然更差”。

九、边界与开放问题

  • 推理时必须提供正确的 domain_id。部署时通常知道机器人与数据配置，但多相机配置、控制接口版本或错误映射仍可能造成歧义。模型也不能仅凭现有机制对一个没有已训练域参数、没有适配数据的新平台直接工作；选错 domain_id 的后果见子页 ⑦。
  • num_domains=30 是当前 checkpoint 的容量，不是方法的永久上限。当前映射把 7 个预训练域放在编号 11–17，其他下游任务使用 0–10 与 18 等编号；这不是“前 7 行就是预训练域”。需要更多槽位时应扩大配置及三张域参数表，并显式迁移旧行、初始化新增行后再训练；原 checkpoint 不能在不处理形状差异的情况下直接加载到扩容后的表。
  • “数据源”的划分粒度由人决定。合并差异明显的数据会让同一 prompt 承担互相冲突的条件；分得过细则每个槽位样本更少，估计方差和过拟合风险上升。论文没有给出自动划分或选择粒度的方法。
  • prompt 长度与数据量的关系没有被研究。约 2K 与 141K 条轨迹的数据源使用同样的 32 个 token。更长 prompt 同时增加容量和过拟合风险，因此不能简单推出“数据越多就应越长”；需要按数据量与域复杂度做消融。
  • 能否从硬件参数直接生成 prompt 仍是开放问题。若用小网络从自由度、相机外参等量生成初始化值，可能减少目标域适配数据或热身步数；但硬件参数不能覆盖任务分布、控制标定等域差异，现有论文也没有验证零热身。
