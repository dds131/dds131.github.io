RLT 的探索不是丢弃 VLA，而是在 VLA 建议附近做受约束的价值优化

Reference 同时进入 actor 的输入与 Loss，但两条路径承担不同职责；dropout 又刻意打断输入依赖。三者共同决定策略能否既从一个好起点出发，又真正学到超越复制的行为。

一、两个时间尺度：VLA horizon $H$ 与 RL chunk $C$

VLA 先产生较长动作序列

\[\tilde{\mathbf a}_{t:t+H-1}\in\mathbb R^{H\times d},\]

而 RLT Actor 只处理并执行较短前缀

\[\mathbf a_{t:t+C-1}\in\mathbb R^{C\times d}, \qquad C<H.\]

以下示意中，VLA 计划十步，RL 当前只决定并执行前三步；到下一个 chunk 边界重新观察、再生成 reference 与 $z_{rl}$。

1 执行2 执行3 执行4 计划5 计划6 计划7 计划8 计划9 计划10 计划

这里的数字只用于说明 $C<H$，不代表论文实际 $H/C$。原论文 π0.6 生成 $H=50$ 的 1 秒动作，RL 使用 $C=10$；具体系统仍需按控制频率、延迟与接触动力学选择。

$C$ 过大

  • 开环执行时间变长；
  • 接触后仍可能继续执行旧计划；
  • 状态更新和人介入响应变慢；
  • chunk 内 reward 与具体动作的归因变粗。

$C$ 过小

  • 决策时域重新变长；
  • 稀疏终局奖励更难向前传播；
  • VLA/encoder 查询更频繁；
  • 推理延迟相对执行窗口的占比增大。

因此，动作块不是只为“平滑”。它同时改变信用分配、推理吞吐、闭环反应性和 replay transition 的时间尺度。

消融证据边界：论文的 “w/o Chunk” 不只是把 $C$ 从 10 改成 1。因为单步策略要在 50 Hz 查询，而此时实时查询 VLA 不可行，作者同时用 ImageNet 预训练的 ResNet-10 替换了 RL token。因此该结果是组合消融，不能把全部差距都归因于 action chunk。

二、Reference pass-through：把 VLA 建议作为条件

Actor 不是只读 $x=(z_{rl},s^p)$，还直接读取 VLA 的参考动作：

\[\pi_\theta(a_{1:C}\mid x,\tilde a_{1:C}).\]

Pass-through 的意义是样本级条件化。即使两个状态的 $z_{rl}$ 相近，VLA 也可能因图像细节或生成随机性给出不同 reference；actor 看见 reference 后可以学习“什么时候保持、什么时候改哪个维度”。

去掉 pass-through 后，actor 仍可能仅凭 $z_{rl}+proprio$ 学出好策略，但早期必须自己重建一个合理动作分布。原论文在较容易的 Ethernet 任务上观察到该版本最终可接近完整 RLT；这不应泛化成所有任务都会追平。其早期学习更慢、失败更多，也更容易漂移。

三、BC anchor：把 reference 变成优化约束

Reference 还进入 actor Loss：

\[\beta\|a_{1:C}-\tilde a_{1:C}\|_2^2.\]

Pass-through 与 BC 不能互相替代：

输入路径：告诉 Actor “建议是什么”

Reference 被拼入网络输入；Actor 可以根据状态解释这条建议并输出条件化分布。

目标路径：软惩罚“走得太远”

即使网络看见 reference，也可能输出任意动作；BC 项对偏离施加连续代价，缩小但不硬性截断 critic 引导的搜索区域。

flowchart LR
  R["reference chunk"] -->|"pass-through"| A["Actor"]
  X["z_rl + proprio"] --> A
  A --> O["actor action chunk"]
  O --> Q["Critic: -Q"]
  O --> M["BC distance"]
  R -->|"target"| M
  Q --> L["Actor Loss"]
  M --> L

BC 项尤其重要，因为 actor 会主动寻找 critic 的高值区域。小数据 critic 在未覆盖动作上可能产生虚高估计；没有锚定时，策略可能利用这种误差，而不是真正提高环境回报。

归一化决定 $\beta$ 的含义。若各动作维度的量纲和尺度不同，原始 L2 会让大尺度关节/位置维度主导。应先核对训练与部署的动作归一化，不能脱离尺度比较不同仓库的 BC 权重。

四、为何“局部编辑”不等于固定 residual policy

从行为上看，RLT 在 VLA 附近改进；但论文定义的 actor 是以 reference 为条件的高斯分布：

\[\pi_\theta(a\mid x,\tilde a) =\mathcal N(\mu_\theta(x,\tilde a),\sigma^2I).\]

它并未要求输出必须写成

\[a=\tilde a+\Delta a.\]

显式 residual 是一种可行实现；例如第三方代码可把最后一层零初始化，使初始行为接近复制 VLA。但这是参数化与初始化选择，不是定义 RLT 的必要条件。论文层面的核心是：reference conditioning、向 reference 的正则，以及 chunk-level 价值优化。

五、Reference-action dropout：为什么故意不给建议

训练早期，critic 还不能可靠区分微小动作修改。此时两股力量都鼓励复制：

  • Actor 输入里有完整 reference，可以用最短路径直接输出它；
  • BC Loss 又惩罚任何偏离。

若一直如此，Actor 可能成为昂贵的恒等映射。RLT 对 batch 中随机子集把条件输入 reference 替换为零：

\[\tilde a^{\mathrm{cond}}= \begin{cases} 0,&m=0,\\ \tilde a,&m=1. \end{cases}\] 
flowchart TD
  B["Replay 中原始 reference"] --> M{"50% 条件输入 mask"}
  X["z_rl + proprio"] --> R
  X --> Z
  M -->|"keep"| R["actor(x, reference)"]
  M -->|"drop"| Z["actor(x, 0)"]
  R --> O["共享 Actor 输出"]
  Z --> O
  O --> Q["-Q"]
  O --> BC["BC distance"]
  B -->|"保留原始 target"| BC
  Q --> L["Actor Loss"]
  BC --> L

这项训练设计促使共享网络同时学习两种能力，但并不保证无 reference 分支一定达到同等性能：

  1. 有 reference 时利用其动作模式；
  2. 没有 reference 时仍能从 $z_{rl}+proprio$ 生成合理动作。

论文附录给出 50% mask，并在推理时始终提供 reference。50% 是论文配置，不是理论最优常数。若训练 dropout 后评估也误把 reference 清零，就改变了论文的推理分布。

实现审计点：dropout 应作用于 actor 的条件输入。Replay 中原始 reference 必须保留，BC target 也必须按算法语义核对；不能为了“方便”在写 replay 时永久置零。

六、探索来自哪里

RLT 的探索是多种机制叠加，不是单一噪声：

机制 作用范围 主要效果 风险
高斯策略固定小方差 Actor 输出 在当前均值附近局部随机探索 方差过大破坏接触，过小缺少新行为
Q 梯度 Actor 均值 朝 critic 预测更高回报方向移动 Critic OOD 误差会被利用
BC anchor Actor Loss 限制偏离 reference 的幅度 过强则复制示范
Reference dropout Actor 输入 避免条件通路退化 过强会增加无参考训练难度
Human intervention 实际 rollout/replay 在危险状态提供纠正分布 需要严格控制权和时间对齐

这些机制降低了无约束搜索风险，却不构成形式化安全保证。真实机器人仍需动作限幅、速度/力矩约束、工作空间边界、急停和可靠的人工接管。

七、为何 RLT 可能超过示范速度

行为克隆优化“像示范”，在线 RL 优化“得到回报”。若奖励只在成功时给 1，策略并没有显式的速度奖励；只有在 $\gamma<1$ 且成功前的时间步持续计入折扣时，更早成功才获得更大的折扣回报。论文另用吞吐量评估速度，但评估指标本身不会自动进入训练目标。

原论文 Ethernet 任务中：

  • 基座 VLA 常靠近端口、稍后退、重新调整，多次 probing；
  • RLT 更常以连续动作插入；
  • 首次失败时会保持压力并轻微 wiggle，利用机械顺应性。

这种行为没有出现在示范数据中，体现了价值学习超越模仿的可能性。但它是特定任务动力学下的涌现策略，不能写成所有插接任务都应硬编码的规则。

八、四种异常行为怎样定位

1. Actor 始终等于 reference

检查：BC 权重是否过大；dropout mask 是否真的进入 actor；critic 对 actor action 的梯度是否被 detach；replay 是否几乎全是成功 reference，缺少可排序差异。

2. Actor 在有 reference 时好，无 reference 时完全崩溃

说明独立生成通路没有训练好；检查 dropout 率、mask 广播维度和条件归一化。不要据此在推理时移除 reference——论文推理本就使用它。

3. Actor 很快远离 VLA 并产生饱和动作

检查动作归一化、BC 目标与输出单位、Q 过估计、$\beta$ 和动作裁剪。Critic 可能正在奖励 replay 覆盖之外的动作。

4. Chunk 内动作平滑，边界却跳变

这是时序问题而不一定是 Loss 问题。检查新旧 chunk 的执行缓存、观测时间戳、VLA/actor 推理延迟，以及是否在 chunk 边界错误重复或跳过动作。
