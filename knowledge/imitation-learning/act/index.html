ACT：动作分块 Transformer

ACTION CHUNKING · CONDITIONAL LATENT · PARALLEL QUERIES · OPTIONAL TEMPORAL ENSEMBLING

ACT 是基于示范学习的动作块策略：一次并行预测连续动作序列；训练使用条件潜变量路径；部署可选融合重叠预测。

它适合可获得示范轨迹、动作局部连贯、需要精细操作且部署动作接口明确的任务。它不自动解决分布外状态、感知失败、动作 ABI 错配、固定预测跨度、失败恢复或独立安全执行层。ACT 读作 Action Chunking with Transformers。

最小先修：理解行为克隆的训练/部署分布差异、序列监督、条件概率模型和 Transformer encoder/decoder；不要求先读完整源码。

Action Chunking把单步监督改为未来动作块；不等于整块开环执行。 CVAE训练 encoder 推断条件潜变量；部署不再读取真实未来动作。 DETR-style Transformeraction queries 并行解码动作块，不是逐动作自回归生成。 Temporal Ensembling可选融合对同一执行时刻的重叠预测，不改变训练输出表示。

ACT 解决什么问题

标准单步行为克隆在专家状态分布上学习 (o_tmapsto a_t)，部署偏差却会把策略带到训练数据稀少的状态。精细双臂操作还叠加接触敏感、硬件回差、高频控制和示范多样性；某一步的小误差可能改变后续接触模式。ACT 没有通过在线 DAgger 重新收集纠正数据，而是把监督输出改成未来动作块，为短期协调提供联合预测目标。

ACT 学习的是 (pi_ heta(o_t,z)mapsto(a_t,ldots,a_{t+H-1}))。这里 (H) 只表示预测 chunk 长度，不等于执行窗口或重规划周期；机器人仍逐步执行动作。只有关闭时间集成并完整顺序消费动作块时，查询次数才可能接近 (T/H)。开启时间集成的固定实现会每个控制步重新查询。

适用结构示范轨迹可获得；局部动作连贯；精细操作需要跨时刻协调；观测与动作接口稳定。
方法边界动作块不能消除 covariate shift，也不自带任务规划、价值函数、成功判别或重试状态机。
系统边界感知、量纲、延迟、控制器、碰撞限制、急停和回滚必须独立核对；策略不是最终安全授权。

官方项目页的真机语境使用 50 Hz、(H=90)、600–1000 步 episode；论文 v1 还报告六项真机任务通常各有 50 条示范，Thread Velcro 为 100 条，数据时长约 10–20 分钟、轨迹 400–700 步。固定仓库的仿真训练命令使用 (H=100)。这些来自不同任务与公开配置，只用于建立量纲，不能拼成一套统一实验。

四个机制组成一条策略路径

每个机制回答不同问题，详细推导下沉到唯一owner页
机制 问题 输出 / 作用阶段 不能写成

核心学习路线

核心路线恰好8页，解决“方法是什么、为什么这样做、证据到哪里”为止。Overview 只是专题入口，不伪造普通上一页/下一页；起点由 start_page_id: act-background 指定。

CORE 1问题背景与路线选择问题：单步BC为何在精细长时序操作中失效？产出：数据覆盖与ACT设计假设。 CORE 2动作分块问题：预测块如何改变监督与时序？产出：H / E / R、padding与执行边界。 CORE 3CVAE与隐变量z问题：训练后验和部署latent为何不同？产出：ELBO、重参数化与z=0边界。 CORE 4DETR-style Transformer问题：多相机条件如何进入并行动作queries？产出：架构级token与信息流。 CORE 5训练流程问题：batch、mask、L1、KL和checkpoint怎样闭合？产出：一次训练step与验证口径。 CORE 6Temporal Ensembling问题：如何对齐同一执行时刻的候选？产出：可选融合、平滑/响应权衡。 CORE 7实验与消融问题：哪些变量在哪些协议被测？产出：结果、负例、缺失统计和不可外推项。 CORE 8 · TERMINAL局限与后续选型问题：证据边界和下一方法怎样选择？产出：Generative Action Models、VLA或工程路线。

路线顺序固定为 Background → Action Chunking → CVAE → Transformer → Training → Temporal Ensembling → Experiments → Limits。Training 必须早于推理融合，Experiments 必须早于 Limits；Source Code 不阻断这条核心链。
