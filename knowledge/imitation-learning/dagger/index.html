知识库 · 机器人模仿学习与 VLA · DAgger
必需先修：先完成 Behavior Cloning 与分布漂移，理解专家诱导分布 dπ*、学习器诱导分布 dπθ 和闭环误差复合。

DAgger（Dataset Aggregation）是一种交互式模仿学习算法：让当前行为策略访问环境，在这些真实访问状态上查询专家动作，把新标注持续聚合进数据集并重新训练候选策略。它把监督目标逐步移向学习器会访问的状态，但不自动提供安全保证，也不规定网络结构和动作表示。

  • 区分专家策略、候选学习器、行为策略、实际执行动作与专家标签。
  • 逐轮写出随机混合、rollout、查询、聚合、训练和候选选择。
  • 识别 no-regret 与任务代价保证的完整条件链，并判断何时转入 HG-DAgger。

一句话定义与问题坐标

DAgger 改变的是训练状态分布和专家查询协议。第 i 轮由行为策略访问状态，专家对访问到的状态给出目标动作，聚合数据训练下一候选策略；数据中的监督标签不必等于环境当时真正执行的动作。

专家策略 π*

为访问状态提供目标动作。专家可以是规划器、控制器或人类，但必须定义它看见什么、何时查询以及标签何时有效。

候选学习器 π̂_i

在第 i 轮开始前由当前聚合数据训练得到。它是候选策略，不等同于本轮行为策略，也不保证最后一轮最好。

行为策略 π_i

本轮真正与环境交互并决定执行动作的策略。原始算法可随机混合专家与当前学习器。

聚合数据集 D

保存访问状态与专家标签，同时保留轮次、行为来源、实际动作和查询日志以供审计。

边界：DAgger 不规定 Transformer、Diffusion 或动作块，不等于共享控制，也不允许把理论性能界当作底层安全控制器。

从 BC 的分布错配到 DAgger 的目标

BC 主要在专家诱导分布上拟合动作：

\[\text{BC:}\qquad \min_{\pi}\;\mathbb{E}_{s\sim d_{\pi^*}}\!\left[\ell(s,\pi)\right].\]

部署真正关心的是学习器自身诱导分布上的误差：

\[\mathbb{E}_{s\sim d_{\pi}}\!\left[\ell(s,\pi)\right].\]

DAgger 把第 i 轮的代理损失定义在行为策略访问的状态上：

\[\ell_i(\pi) = \mathbb{E}_{s\sim d_{\pi_i}} \left[\ell\!\left(s,\pi,\pi^*\right)\right].\]

其中状态来自行为策略诱导分布 dπ_i，训练标签来自专家 π*。这不是直接最大化任务回报，而是把“模仿专家”的代理损失放到逐轮访问分布上。

维度 BC DAgger
访问状态 专家示范状态 当前行为策略访问状态
监督标签 示范中的专家动作 专家对本轮访问状态给出的动作
环境交互 训练可完全离线 逐轮 rollout 与查询
数据集 固定 持续聚合并保留来源
核心风险 训练/部署分布错配 查询成本、交互风险、标签可实现性

原始 DAgger 算法逐轮展开

先定义轮数 N、每轮轨迹数 m、时域 T 和非增混合日程 β_i。可以从已有专家数据初始化 D，也可以先用纯专家 rollout 建立首批数据，再训练第一个候选学习器。

第 i 轮的行为策略写作：

\[\pi_i=\beta_i\pi^*+(1-\beta_i)\hat{\pi}_i.\]

标准含义是在决策时以概率 β_i选择专家策略，以概率 1-β_i选择学习器。它不是两个连续动作向量的数值线性插值，不默认整条轨迹固定交给某一方，也不自动等于平滑共享控制。

flowchart LR
  A[1 训练候选 π̂_i] --> B[2 构造随机混合行为策略 π_i]
  B --> C[3 rollout 访问状态]
  C --> D[4 对访问状态查询专家]
  D --> E[5 聚合 D ← D ∪ D_i]
  E --> F[6 独立闭环验证候选]
  F --> A

图 1｜六步数据聚合环。 训练、采样、查询、聚合和候选验证是不同责任；闭环验证集不能直接回流成无标记的训练数据。

每轮执行：

  1. 用 π_i 采样 m 条、每条最多 T 步的轨迹。
  2. 对每个访问状态 s 查询专家动作 π*(s)。
  3. 构造 D_i = {(s, π*(s))}。
  4. 聚合 D ← D ∪ D_i，保留来源、执行动作和查询日志。
  5. 在聚合数据上训练 π̂_{i+1}。
  6. 在独立闭环验证中评估所有可部署候选。
D ← initial expert data
for i = 1 ... N:
    train π_hat[i] on D
    π_behavior ← stochastic_mix(π_expert, π_hat[i], beta[i])
    trajectories ← rollout(π_behavior)
    D_i ← {(visited_state, expert_action(visited_state))}
    D ← D ∪ D_i
return select_by_independent_closed_loop_validation({π_hat[i]})
最终策略选择：不能默认返回最后一轮。原始算法允许依据独立验证从候选序列中选择表现最佳的策略；训练数据上的监督 loss 与闭环候选选择必须分开。

行为动作、专家标签与数据记录不能混为一列

flowchart LR
  subgraph EXEC[环境执行泳道]
    S[state s_t] --> BP[behavior policy π_i]
    BP --> AE[executed action a_exec]
    AE --> NS[next state s_t+1]
  end
  subgraph LABEL[监督标签泳道]
    S2[same state s_t] --> Q[expert query π*]
    Q --> AL[label a*]
    AL --> AG[aggregate dataset]
  end

图 2｜执行/标签双泳道。 executed_action 解释环境为何转移到下一状态；expert_label 才是默认监督目标。两者可能不同，但必须引用同一访问状态和时间语义。

字段 含义 为什么必须单独记录
round_id / episode_id / step_id 聚合轮次与轨迹位置 追踪来源，避免历史窗口跨 episode。
state_or_observation 查询与执行时的输入 检查专家与学习器是否看到同样信息。
behavior_source 本步由 expert 或 learner 决策 统计实际混合比例与访问分布。
executed_action 环境真正执行的动作 复现状态转移；默认不把它当专家监督。
expert_label 专家对访问状态给出的目标动作 这是 DAgger 的监督标签。
query_latency / label_valid 查询延迟与标签有效性 判断反事实标签是否仍对应当前状态。
safety_event / termination 越界、碰撞、接管、超时与终止 风险审计和停止规则。
policy_version / dataset_version 策略与聚合数据版本 防止轮次、checkpoint 与数据错配。

例如学习器执行“向左”后进入偏左状态，专家对该状态的标签可能是“向右恢复”。聚合样本应是“偏左状态 → 向右恢复”；已执行的“向左”只用于解释转移，不能误写成专家标签。若查询延迟使“向右恢复”对应的已经是旧状态，应将标签标为过期或无效。

β 日程、访问分布与停止条件

β_i 只决定原始随机混合中专家策略被选择执行的概率。早期保留专家参与可减少极弱策略立即进入无意义或不可恢复状态；后期衰减则让访问分布接近纯学习器部署分布。若专家比例长期过高，聚合数据仍会偏向专家分布。

flowchart LR
  R1[早期轮次<br/>β 较高<br/>更多专家动作] --> R2[中期轮次<br/>β 下降<br/>扩大恢复状态覆盖]
  R2 --> R3[后期轮次<br/>β 接近 0<br/>更接近纯学习器分布]
  R3 --> R4[独立纯策略 rollout<br/>验证部署门禁]

图 3｜概念性 β 日程。 可使用指数衰减 β_i=(1-α)^(i-1) 或带安全门槛的分段衰减；图中没有通用最佳 α、轮数或阈值。β_i=0 最接近纯学习器分布，也可能风险最高。

每轮至少记录：

  • 专家动作实际执行比例、查询覆盖率与有效标签率。
  • 新增状态相对已有数据的密度或距离分布。
  • 正常、恢复、失败前与终止状态占比。
  • 新数据加入后的旧任务回归和新状态改进。
  • 候选策略的闭环成功、安全成功、干预与首次失败时刻。

停止不能只看“轮数到了”。应同时满足：连续多轮覆盖增量趋稳；独立闭环验证不再显著改善或开始回归；查询预算、安全事件与标签有效率仍在门槛内；纯学习器策略在目标初始状态和扰动集上通过最低门禁。

安全边界：未训练策略不能因为“DAgger 需要学习器分布”就无约束进入真机。应先使用低风险环境、独立约束控制器、停止区域与人工接管；算法的访问分布目标不授权危险探索。

no-regret 视角与理论保证的条件链

若在线学习算法产生候选序列 π̂_1,…,π̂_N，第 i 轮损失仍为：

\[\ell_i(\pi)=\mathbb{E}_{s\sim d_{\pi_i}}[\ell(s,\pi)].\]

平均 regret 条件写作：

\[\frac{1}{N}\sum_{i=1}^{N}\ell_i(\hat{\pi}_i) - \min_{\pi\in\Pi}\frac{1}{N}\sum_{i=1}^{N}\ell_i(\pi) \le \gamma_N, \qquad \gamma_N\to 0.\]

把历史数据全部聚合后做经验风险最小化可理解为 follow-the-leader 风格更新，但“神经网络 + SGD”并不会自动证明满足 no-regret。定义函数类中的平均最佳可达损失：

\[\epsilon_N= \min_{\pi\in\Pi} \frac{1}{N}\sum_{i=1}^{N} \mathbb{E}_{s\sim d_{\pi_i}}[\ell(s,\pi)].\]

在代理损失有界、β_i 非增并满足在线 regret 等条件时，Ross 等（2011）给出候选序列中某个策略 π̂ 的自身分布代理损失界：

\[\mathbb{E}_{s\sim d_{\hat{\pi}}}[\ell(s,\hat{\pi})] \le \epsilon_N+\gamma_N+ \frac{2\ell_{\max}}{N} \left[ n_\beta+T\sum_{i=n_\beta+1}^{N}\beta_i \right],\]

其中 n_β 是 β_i > 1/T 的最后轮次。右侧三部分分别对应函数类中最佳可达损失、在线学习 regret，以及混合行为策略与纯学习器分布之间的差异。

从代理损失继续到任务代价还要增加条件：代理 loss 能上界策略与专家动作分歧，而且一次动作偏离专家造成的剩余 cost-to-go 增量由 u 上界。若学习器在自身状态分布上的期望损失为 ε，才能写：

\[J(\pi)\le J(\pi^*)+uT\epsilon.\] 
flowchart TB
  A[逐轮访问分布上的代理损失] --> B[有界 loss 与函数类最佳可达 ε_N]
  B --> C[在线算法 regret γ_N → 0]
  C --> D[β 非增且混合分布误差受控]
  D --> E[代理 loss 上界动作分歧]
  E --> F[cost-to-go 增量由 u 上界]
  F --> G[任务代价界 Jπ ≤ Jπ* + uTε]

图 4｜理论条件阶梯。 任一台阶缺失，都不能直接宣称“DAgger 把平方保证变成线性保证”。若最坏情况下 u=O(T)，uTε 仍可能退化为二次量级。

定理不保证最后一轮最好，不保证非凸网络训练满足 no-regret，不保证连续动作 L1/L2 自动对应任务代价，也未消除有限轨迹、相关样本和专家噪声的统计误差。它是相对专家与函数类的性能条件，不代表必然超过专家，更不是碰撞概率或控制屏障意义上的安全证明。

从经典 DAgger 到 HG-DAgger

HG-DAgger 保留“多轮 rollout → 访问学习器相关状态 → 专家纠正 → 聚合 → 重训练 → 候选验证”的骨架，但改变人类如何参与：人不是持续为所有访问状态提供反事实动作，而是在风险升高时接管，并在真实闭环反馈下产生一段恢复控制。

责任 经典 DAgger HG-DAgger 方向
专家参与 对所有访问状态查询标签，动作未必执行 人基于风险接管并实际闭环控制
纠正数据 单状态反事实专家动作 接管期间的恢复控制片段
新增系统责任 混合日程、查询与聚合 触发、退出、迟滞、交权、反应延迟与遥操作对齐
仍不保证 真机安全、标签可实现性 独立安全层、恢复集完整性与零风险

SafeDAgger、EnsembleDAgger、ThriftyDAgger 等后续方法会改变查询和风险门控；它们不能倒写成原始 DAgger 的组成部分。下一专题只解释 HG-DAgger 的人工门控、接管状态机、风险信号和恢复数据。

证据分层：DAgger 算法、随机混合和定理属于“原论文事实”；中文条件拆解属于“理论解释”；日志、门禁与停止条件属于“工程建议”；HG 等改造属于“后续方法事实”；具体机器人上的时延与覆盖原因在实验前属于“待验证假设”。
