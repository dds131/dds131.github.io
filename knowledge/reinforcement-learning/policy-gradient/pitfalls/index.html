策略梯度在训练中会出现一批反直觉的现象：损失在降、回报却不涨；理论上无偏、实际抖得没法看；曲线爬到一半突然崩掉再也回不来。这些都不是玄学，每一条都有明确的数学原因。

本页是一本诊断手册。每条失效模式统一按五段写：现象 → 底层原因 → 如何验证 → 如何缓解 → 出口指向。

① 损失在降，回报不涨

现象

训练日志里替代损失稳步下降，看起来一切正常，但回合回报原地踏步甚至下滑。或者反过来：损失在涨，回报却在涨。

底层原因

有两层，两层都必须讲。

第一层：替代损失不是性能度量。 子页 ④ 讲过，

\[L_{\text{PG}}(\theta) \;=\; -\frac{1}{N} \sum_{i} \sum_{t} \Psi_t^{(i)}\, \log \pi_\theta\big( a_t^{(i)} \mid s_t^{(i)} \big)\]

是为了让自动微分吐出正确梯度而构造出来的量。OpenAI Spinning Up 把这一点说得很直接：这个「损失」在监督学习的通常意义上不是损失函数，它的值不度量任何性能。 它与 \(J(\theta)\) 之间不存在「损失越小性能越好」这种关系。（这不等于替代损失的值在任何意义上都无用：Schulman 等 2015 的随机计算图工作证明，在一定条件下它是真目标的上界，那是 TRPO 单调改进那条线的出发点。）

一个直观的说明：在当前这批数据上，只要把已经采到的高权重动作的概率推得足够高，\(L_{\text{PG}}\) 就能一直降下去——但这不代表策略在新的状态分布上表现更好。

第二层：跨迭代不可比。 这一层更根本。每一轮的数据都来自不同的策略：

\[\tau \sim \pi_{\theta_k} \quad \text{而更新之后} \quad \pi_{\theta_{k+1}} \neq \pi_{\theta_k}\]

于是第 \(k\) 轮的 \(L_{\text{PG}}\) 与第 \(k+1\) 轮的 \(L_{\text{PG}}\) 是在两个不同的分布上算出来的，它们的数值没有可比性。这与监督学习完全不同——监督学习的训练集固定，损失曲线才有意义。

Berkeley CS285 特别强调过这一点：策略梯度不是普通的监督学习，不能套用监督学习看损失曲线的那套习惯。

如何验证

把三样东西一起画出来，只看第一样：

  • 回合回报（必须画滑动平均）——这是唯一的性能指标。
  • 替代损失——只用来确认它没有变成 NaN 或爆炸，不用来判断好坏。
  • 策略熵——用来判断探索是否还在。

如果你发现自己在根据损失曲线调参，那就是走错了方向。

如何缓解

这不是一个需要「缓解」的 bug，而是一个需要改变判读习惯的事实。要做的只有两件：

  • 监控指标里把回报放在第一位，损失降级为健康检查。
  • 如果确实需要一个可跨迭代比较的量，看新旧策略的 KL 散度——它度量的是「这一步走了多远」，而不是「好不好」，但至少是可比的。

出口指向

替代损失的完整构造与「权重必须当常数」的含义见子页 ④；把 KL 从监控量升级为约束条件是 TRPO 的做法。

② 旧数据一用就训崩：on-policy 约束的数学根源

这是本页最值得深挖的一条。PPO 页已经讲清楚了这个约束在工程上怎么绕（重要性采样比、裁剪、K 轮更新后丢弃），本节讲的是它在数学上为什么绕不干净。

现象

把采过的轨迹存进 replay buffer 反复使用，或者在同一批数据上多做几轮梯度更新，训练迅速变差甚至发散。

底层原因：要修的有两层，只有一层修得动

策略梯度定理写成状态分布形式是

\[\nabla_\theta J(\theta) \;\propto\; \mathbb{E}_{\,s \sim \bar{d}^{\pi_\theta},\; a \sim \pi_\theta(\cdot \mid s)}\left[ \nabla_\theta \log \pi_\theta(a \mid s)\, A^{\pi_\theta}(s, a) \right]\]

期望下标里有两个分布，旧数据在这两个上都不匹配。

动作层：修得动。 给定同一个状态 \(s\)，旧策略采动作的分布是 \(\pi_{\text{old}}(\cdot \mid s)\) 而不是 \(\pi_\theta(\cdot \mid s)\)。这一层可以用重要性采样比修正：

\[\mathbb{E}_{a \sim \pi_{\text{old}}}\left[ \frac{\pi_\theta(a \mid s)}{\pi_{\text{old}}(a \mid s)} \cdot f(s,a) \right] \;=\; \mathbb{E}_{a \sim \pi_\theta}\left[ f(s,a) \right]\]

两个概率都是我们自己的网络算出来的，比值可以精确计算。TRPO 与 PPO 做的就是这件事，代价是比值偏离 1 太远时方差爆炸，所以需要约束或裁剪。

状态层：修不动。 数据里的状态服从 \(d^{\pi_{\text{old}}}\)，而梯度要求它们服从 \(d^{\pi_\theta}\)。要修正就需要

\[\frac{d^{\pi_\theta}(s)}{d^{\pi_{\text{old}}}(s)}\]

而这个比值算不出来。原因是 \(d^{\pi}\) 由策略与环境转移共同决定：

\[d^{\pi}(s) \;=\; \sum_{t \ge 0} \gamma^{t} \Pr(s_t = s \mid \pi,\, P)\]

它是策略沿着环境动力学一路传播出来的结果，没有闭式表达；要从样本估计它需要专门的密度比估计方法（DICE 一族），代价是引入新的估计误差与方差，工程上很少用。子页 ① 讲过，环境转移 \(P\) 在梯度里的贡献恰好为零——那是策略梯度最漂亮的性质；但在这里，\(P\) 通过状态分布回来了，而这一次躲不掉。

这里要避开一个容易想当然的说法。离策略修正本身并不需要环境模型：整条轨迹的重要性采样比是 \(\prod_t \pi_\theta(a_t \mid s_t) / \pi_{\text{old}}(a_t \mid s_t)\)，环境转移在分子分母里逐项抵消了。真正的障碍是这个连乘的方差随时域指数增长，实用算法因此把它截断，只保留单步的动作层修正——由此得到的才是上面说的半梯度。

实践中大家怎么做的：直接丢掉它

实用的离策略策略梯度算法根本不去构造那个状态分布之比。以 Degris、White 与 Sutton 在 2012 年的 Off-Policy Actor-Critic 为例，它的做法是把目标函数直接定义在行为策略的状态分布上：\(J_\gamma(u) = \sum_s d^{b}(s)\, V^{\pi_u,\gamma}(s)\)——既然目标本身就按 \(d^b\) 加权，就不存在「先该乘一个比值、再把它丢掉」这一步。它真正丢掉的是另一项：梯度展开式里的 \(\nabla_u Q^{\pi,\gamma}(s,a)\)，论文原文是「The first approximation involved in the theory of Off-PAC is to omit this term」。

后果是：得到的更新量是一个半梯度，不是任何函数的真梯度（论文的勘误里也是这么说的）。但这不等于「没有理论保证」——该文为这个近似给出了表格情形下的依据：策略改进定理、以及 \(\lambda = 0\) 时的收敛性证明。需要注意的是，论文的勘误把结论的适用范围收窄到了表格表示，不延伸到函数逼近。

想把状态分布这一项精确处理，有两条路线：emphatic weighting（Imani 等 2018），以及直接估计平稳分布密度比的 DICE 一族方法。两者都要引入新的估计误差与方差，工程上很少用。

这解释了 PPO 为什么是那个样子

把上面的逻辑串起来，PPO 的设计动机就完全清楚了：

  • 动作层可以修，但比值远离 1 时方差爆炸 → 需要限制比值。
  • 状态层修不动，只能指望新旧策略别差太远 → 需要限制策略变化幅度。

两个需求指向同一件事：把新策略约束在旧策略附近。TRPO 用 KL 信任域，PPO 用概率比裁剪，本质是同一个目的。

所以 PPO 不是凭空出现的技巧，它是在回答：能不能更充分地利用同一批数据，同时又不让新旧策略差得太远。

如何验证

  • 打印新旧策略的 KL 散度。若在多轮更新中它迅速增大，说明已经走出了近似成立的范围。
  • 打印重要性采样比的分布（如果用了的话）。比值的方差大、或出现极端值，是失真的直接信号。

如何缓解

  • 纯 REINFORCE：不要复用数据，一批只更新一次。这不是保守，是原理要求。
  • 需要复用：用 PPO 那一套（比值裁剪加多轮更新），并把 KL 作为早停条件。

出口指向

重要性采样比的完整推导见 TRPO；裁剪目标、K 轮更新与数据流的工程细节见 PPO，那里有完整的 on-policy 数据流图。本页不重复这两部分。

③ 回报断崖下跌后长时间不恢复

现象

训练曲线一路爬升，某个时刻突然断崖式下跌到很低的水平，之后长时间不恢复。

底层原因：一个正反馈回路

关键在于策略梯度的数据是策略自己产生的。这在监督学习里没有对应物。

flowchart TB
  BAD["一次过大的更新：策略被推到一个差的位置"]
  BAD --> DIST["采样分布随之退化：只能采到差的状态与动作"]
  DIST --> EST["在退化的分布上，优势估计变得更不准<br/>好动作根本没被采到，无从比较"]
  EST --> WORSE["下一次更新的方向更差"]
  WORSE --> BAD
  ENT["探索储备：策略熵"] -.->|"熵还足时有机会跳出去"| DIST
  BRK1["打断点一：限制单步更新幅度<br/>信任域或比值裁剪"] -.->|"见 TRPO 与 PPO"| BAD
  BRK2["打断点二：维持探索<br/>熵正则或最大熵目标"] -.->|"见 SAC"| ENT

回路的每一环都是确定的因果：策略差 → 采到的数据差 → 基于差数据的估计差 → 更新更差。

与价值方法的对比很能说明问题。 Q 网络学歪了，只要 replay buffer 里还有好的转移，它就有机会被纠正回来——buffer 里的数据不随当前策略退化。策略梯度没有这个缓冲：数据完全由当前策略决定，策略垮了，数据也就垮了。

需要准确的表述

「不可恢复」是经验现象，不是定理。能不能恢复取决于两个条件：

  • 奖励密度。 密集奖励下，退化后的策略仍然能收到有区分度的信号，有机会爬回来。稀疏奖励下，退化之后可能连一次成功都采不到，回路彻底闭合。
  • 熵是否还有储备。 熵还足够时，随机性本身提供了跳出去的机会；熵已经坍缩时（见下一条），策略被锁死。

所以准确的说法是：稀疏奖励、长时域、熵已坍缩这三个条件叠加时，往往不可逆；密集奖励且熵充足时，通常能自行恢复。

这正是 Kakade 与 Langford 在 2002 年提出保守策略迭代、以及后来 TRPO 引入单调改进保证的动机——与其事后恢复，不如从一开始就不让单步走太远。

如何验证

  • 回看崩塌前若干次迭代的策略熵。若熵在崩塌前已经很低，那就是熵坍缩叠加大步长。
  • 回看崩塌那一步的梯度范数。若远大于平常，说明是某条极端轨迹带来的大更新。
  • 打印新旧策略的 KL。崩塌点往往伴随一次异常大的 KL。

如何缓解

  • 限制单步幅度：梯度裁剪是最低成本的兜底；正式的解法是信任域或比值裁剪。
  • 维持探索：熵正则，见下一条。
  • 保留检查点：定期存档，崩塌后可以回退到崩塌前重新开始，而不是从头训。

出口指向

单调改进保证与信任域见 TRPO，裁剪的工程实现见 PPO。

④ 训练停滞：熵坍缩与标准差坍缩

现象

回报曲线走平，但停在一个明显不够好的水平上。看起来像收敛了，实际上是策略把自己锁死了。

连续控制里的对应表现是标准差坍缩：打印 \(\sigma\) 会看到它已经很小，动作几乎是确定的。

底层原因

机制在子页 ③里给了完整的数学分析，这里只复述结论：

  • 连续情形：\(\log \sigma\) 方向的期望更新量是 \(\mathbb{E}[(z^2-1)\Psi]\)，优势在均值附近更高时它为负，\(\sigma\) 收缩。收缩之后采样范围变窄，更难发现远处的好动作，于是继续收缩——单向自我强化。
  • 离散情形：得分函数是 \(e_a - \pi\)，被采样动作的推力大小是 \(1 - \pi_a\)。\(\pi_a \to 1\) 时熵趋于 0，同时梯度也趋于 0。

第二点是离散情形下最容易误判的地方：熵坍缩的表现不是训练崩掉，而是训练停滞——曲线平了，梯度范数也很小，一切看起来都像收敛了。

需要先分清的一件事

熵下降本身是正确行为。 标准强化学习目标（不含熵项）的最优解通常是确定性策略，所以训练过程中熵下降说明算法在正确地收敛。

病态只在两处：下降得太早（还没充分探索就确定了），以及下降之后无法恢复。

如何验证

把策略熵画出来，与回报曲线并排看。 判据很清晰：

熵的表现 回报的表现 判断
缓慢下降，后期低 已经到达高位 正常收敛
早期就快速跌到接近零 还很低 过早坍缩，是病态
几乎不下降 上不去 熵系数过大，策略被强行保持随机
下降到零且梯度范数同时很小 停在中等水平 已锁死，继续训也不会动

如何缓解

  • 加熵正则项。 子页 ③ 给出了它的机制：对角高斯的熵对 \(\log \sigma\) 的偏导恒为 1，所以它提供一个大小恒定的向上推力，系数通常可以在整个训练过程中固定不变，不需要像 \(\varepsilon\)-greedy 那样衰减。
  • 给 \(\log \sigma\) 设下界。 连续控制里常见的做法，直接把它裁剪到某个区间内，防止 \(\sigma\) 无限趋零（顺带也压住了子页 ③ 提到的 \(\sigma \to 0\) 时得分函数发散的问题）。
  • 检查输出层初始化。 初始增益过大会让初始策略就很尖锐，等于从一开始就少了探索储备。
  • 回退到熵坍缩之前的检查点，调大熵系数重训。已经锁死的策略继续训是没有用的。

出口指向

机制的完整推导见子页 ③；把熵从正则项提升为目标的一部分并自动调节系数，是 SAC 的做法。

⑤ 时间截断被当成真终止

这一条在教程里几乎不提，但它是 CartPole 这类带时间上限的任务上最实际的一个坑。

现象

训练前期正常，策略变好之后反而学不动了，回报卡在时间上限附近上不去，甚至略有回落。

底层原因

CartPole-v1 在 500 步处截断（truncate），而不是因为任务真的结束了。这两者的区别是本质的：

  • 真终止（terminated）：杆倒了，后续没有任何价值，\(V(s_T) = 0\) 是对的。
  • 时间截断（truncated）：杆还立着，后续本来还能拿很多奖励，\(V(s_T) \ne 0\)。

REINFORCE 把整条轨迹的奖励累加起来当作 \(G_t\)，等于默认截断处的后续价值为零。于是每个时间步的 \(G_t\) 都被系统性低估，低估的量是

\[\gamma^{\,T - t}\, V^{\pi}(s_T)\]

注意这个误差的分布：它在 \(t\) 接近截断点 \(T\) 时最大（指数项接近 1），在回合开始处最小（指数项接近 0）。也就是说，越靠近截断点的那些动作，权重被压得越狠。

更麻烦的是它出现的时机。训练早期杆很快就倒，绝大多数回合以真终止结束，这个偏差几乎不存在；策略变好之后，越来越多的回合以截断结束，偏差才开始显著——恰好在你以为快成功的时候。

如何验证

统计回合结束时 truncated 为真的比例。 Gymnasium 之所以把 terminated 与 truncated 分成两个返回值，正是为了让这件事可区分——旧版 Gym 只有一个 done，这个坑更难发现。

# 在训练循环里加一行统计
truncated_ratio = num_truncated / num_episodes

若这个比例随训练上升到较高水平，同时回报增长变慢，基本可以确认。

如何缓解

三种做法，代价递减但实现复杂度递增：

做法 偏差 代价
接受它 有，且随策略变好而增大 零成本，短回合任务上可接受
在截断处自举一个学出来的 V 基本消除 需要价值网络，此时已经是 Actor-Critic
把剩余时间加进观测 消除（问题被重新定义为有限时域 MDP） 改变了状态空间，需要重新设计观测

第三种做法值得单独说一句：把「还剩多少步」作为观测的一部分喂给策略，问题就从「被截断的无限时域 MDP」变成了一个定义良好的有限时域 MDP，价值函数依赖剩余时间，截断处的价值确实为零。Pardo 等人在 2018 年的工作分析了这一点。代价是策略必须学会依赖时间，泛化性变差。

最常用的是第二种。 这也是为什么几乎所有现代 on-policy 实现（PPO 等）都带一个价值网络——它不只是基线，也是处理截断的必要组件。

出口指向

价值网络的引入见 Actor-Critic；截断处自举的具体实现口径见 PPO。

⑥ 折扣因子的双重身份

现象

改动 \(\gamma\) 带来的效果远超「改变有效视野」所能解释的范围，而且不同实现之间对 \(\gamma\) 的敏感程度差别很大。

底层原因

子页 ① 给出了完整的数学，这里只讲诊断层面。核心事实是：

严格的策略梯度定理里，权重带一个 \(\gamma^{t}\) 因子，而绝大多数实现省略了它。

\[\text{严格形式：} \quad \sum_{t} \boldsymbol{\gamma^{t}}\, \nabla_\theta \log \pi_\theta(a_t \mid s_t)\, G_t \qquad \text{通行实现：} \quad \sum_{t} \nabla_\theta \log \pi_\theta(a_t \mid s_t)\, G_t\]

于是 \(\gamma\) 有了两重身份：

  • 带 \(\gamma^{t}\) 时：\(\gamma\) 是问题定义的一部分，规定了未来奖励值多少钱。
  • 省略 \(\gamma^{t}\) 时：\(\gamma\) 退化成一个偏差-方差旋钮——它通过压低 \(G_t\) 里远期奖励的贡献来降方差，同时引入对远期回报的系统性低估。而 Nota 与 Thomas 证明，此时的更新量不是任何函数的梯度。

这解释了为什么调 \(\gamma\) 的经验规律很难跨实现迁移：两种口径下它根本不是同一个参数。

如何验证

直接去代码里看更新式有没有 \(\gamma^{t}\)。 这是一个二元判断，不需要实验。看 Sutton 与 Barto 第 13.3 节的伪代码（带 \(\gamma^{t}\)）与手上的实现对照即可。

另外可以做一个简单的敏感性测试：固定其它一切，只扫 \(\gamma\)（例如 0.9、0.95、0.99），看回报曲线。如果差异远大于有效视野 \(1/(1-\gamma)\) 的变化所能解释的，那多半是方差在起作用。

如何缓解

这不是一个 bug，是一个需要知情的取舍：

  • 知道自己用的是哪个口径，不要混用两种口径下的调参经验。
  • 长时域任务上要特别小心：省略 \(\gamma^{t}\) 时，\(\gamma\) 越接近 1，\(G_t\) 累加进来的随机项越多，方差越大。这与「\(\gamma\) 大就看得远、所以更好」的直觉相反。
  • 把 \(\gamma\) 当作超参数来调，而不是当作问题设定里给定的常数——在通行实现下这才是它的实际角色。

出口指向

完整的数学分析、Nota 与 Thomas 的结论、以及为什么大家仍然选择省略，见子页 ①。

⑦ 随机种子与「看起来收敛了」

现象

换一个随机种子，两个方法的优劣排序就反过来了；或者同一份代码跑两次，一次收敛一次不收敛。

底层原因

策略梯度的方差大到单次运行的结果本身就是一个高方差的随机变量。用单次运行去比较两个方法，相当于用一个样本去估计两个分布的均值并比较大小。

这个问题在深度强化学习里普遍存在，Henderson 等人在 2018 年的《Deep Reinforcement Learning That Matters》里做了系统性的实证，论文自己的表述是：复现当前最好方法的结果很少是直截了当的，而且很难判断相对于既有最好结果的「改进」是否真实。

策略梯度尤其严重，因为它的方差来源比价值方法多一层（策略自身的随机性直接进入数据采集）。

如何验证

  • 至少跑若干个种子，画出回报曲线的分布区间（中位数加分位带），而不是单条曲线。
  • 若两个方法的区间大面积重叠，就不能下「A 比 B 好」的结论。

如何缓解

  • 固定并记录所有随机源：numpy、torch、环境的 reset(seed=...) 与 action_space.seed(...)。子页 ④ 里这四处都设了：第一段在模块级设了 numpy 与 torch，第四段的 train() 里设了环境的两处。
  • 报告分布而非单值。 这是实验设计问题，不是算法问题。
  • 区分训练回报与评估回报：训练时动作是采样的，评估时若改成取概率最大的动作分数通常更高，两者要分开报告。

出口指向

方差的直接度量方式（梯度余弦相似度等）见子页 ②的「方差怎么量化」一节。

六个可直接打印的诊断量

训练策略梯度时，只看回报曲线是不够的。下面六个量都可以在训练循环里直接打印，覆盖上面七条失效模式里的五条（①②③④⑦）。失效模式 ⑤ 与 ⑥ 不靠这六个量判断：前者统计回合结束时 truncated 为真的比例，后者直接去代码里查更新式有没有 gamma 的 t 次幂，两者的判据都在开头的失效模式总表里。

诊断量 怎么算 健康时的表现 异常指向
回合回报的滑动平均与分位带 多种子，取中位数与分位数 趋势向上，带宽随训练略收窄 见失效模式 ①③⑦

两点使用建议。

第一，KL 即使不用 PPO 也值得打印。 它是唯一一个可以跨迭代比较的过程量（回合回报当然也可跨迭代比较，但它是性能指标而不是过程量；替代损失则两者都不是），用来回答「这一步走了多远」这个问题非常直接。崩塌点几乎总伴随一次异常大的 KL。

第二，余弦相似度往往比人们预期的低得多。 第一次打印时看到接近零不要惊讶——这正是策略梯度方差大这件事的直接体现，也说明了为什么批量大小这么重要。

这一节列的是不会抛异常、但会让训练静默失败的一类问题。策略梯度的多数「训练不 work」属于这一类，所以排查时应当先过一遍这个清单，再去调超参数。

每步都更新一次参数，训练发散 step 写进了时间步循环里，破坏了 on-policy 前提 确认整条轨迹只调一次 step
用 tanh 压缩动作后熵与梯度都不对 漏了雅可比修正项 对照 SAC 页的对数概率表达式
屏蔽非法动作后出现 NaN 或熵算不出来 先 softmax、再乘掩码、再归一化取对数，丢掉了 logsumexp 的数值稳定性（极小概率下溢、熵里出现 0 乘 log 0）。注意不是「梯度回流到被屏蔽的 logits」——那一项恰好为零，见子页 ③ 改在 logits 上屏蔽，并置一个很大的负数而不是真的负无穷
前三行占了实践中绝大多数情况，而且三者都不会报错。养成一个习惯：新写一份策略梯度实现后，先打印第 0 步的权重与损失的符号，确认这两件事之后再开始调参。这比任何超参数搜索都省时间。

与子页 ④的关系：那里按代码行讲这些约定各自对应公式的哪一步（为什么必须这样写），本页按症状反向索引（出了这个现象该查哪里）。两个角度互补，不重复。

小结

  • 多数「训练不 work」是实现错误而不是调参问题。 写错的几处都不抛异常，所以先过实现清单，再调超参数。
  • 替代损失的值没有意义，且跨迭代不可比；唯一的性能指标是回合回报，唯一可跨迭代比较的过程量是新旧策略的 KL。
  • on-policy 约束的根源在状态层而不是动作层。 动作分布可以用重要性采样比精确修正，状态占用度量之比却依赖环境转移、没有闭式表达，要从样本估计必须另上密度比估计方法（DICE 一族），代价是新的估计误差与方差；所有实用的离策略策略梯度都直接丢掉这一项，得到的是半梯度。这既是 PPO 存在的理由，也是它必须把新旧策略约束在附近的理由。
  • 性能崩塌是一个正反馈回路：策略退化导致数据退化，数据退化导致估计更差。能否恢复取决于奖励密度与熵储备，「不可恢复」是经验现象而非定理。
