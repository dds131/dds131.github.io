DexGraspVLA 展示了失败后再次伸手、目标被移动后重新逼近、在人手干扰下继续跟随等行为。把这些现象统称为“涌现”很方便，却容易把观察到的效果、论文提出的解释、源码具备的条件混成同一件事。

本页采用更严格的三层证据：

  1. 论文事实：论文明确报告或定义的内容；
  2. 源码事实：公开实现能够逐行确认的控制流；
  3. 机制假设：由前两者推导出的合理解释，但尚无专门消融证明。
H = 64控制器预测的动作块长度
K = 6论文宣称执行后再预测的前缀
nobs = 1控制器使用的观测窗口
20 Hz论文实验设置，不是公开循环的实测频率
先给结论：论文描述的是一个 20 Hz、每执行 6 个动作便重新预测的闭环控制器；公开 inference.py 虽然遍历动作块前 6 项，却没有在该循环中设置 20 Hz 节拍、动作队列或完成确认。因此，0.3 s 重规划、3.3 Hz 策略与 23 Hz Cutie 都不能作为公开实现的确定运行频率。

一、先分清“评测尝试”与“内部重抓”

论文在大规模泛化实验中报告 \(\text{Ours@}k,\ k\in\{1,2,3\}\)：每个测试最多允许 \(k\) 次尝试，Ours@1 等同于 Ours。论文同时明确说明：

单次尝试内，策略在初次失败后进行的重抓被允许，且不单独计为新尝试。

所以 Ours@1 的 90.8% 表示“最多一个评测尝试”的聚合成功率，不等于一次伸手成功率。同一评测尝试内部可以包含多次接近、接触和再次合拢。论文还规定，成功要求物体被举到桌面上方 10 cm，并保持 20 s。

公开源码中的 consecutive_failed_attempts >= 3 与 Ours@3 没有对应关系。前者统计同一次控制执行中连续三个 VLM False 响应；后者是实验协议允许的最多三次外部评测尝试。

二、滚动时域：理论结构与公开实现

2.1 理想的 receding-horizon 形式

第 \(j\) 次重规划时，控制器读取当前观测

\[o_j=(I^{h}_j,m_j,I^{w}_j,s_j),\]

从高斯初始噪声 \(\epsilon_j\) 生成动作块

\[A_j=g_\theta(o_j,\epsilon_j) =[a_{j,0},a_{j,1},\ldots,a_{j,H-1}],\qquad H=64.\]

系统只执行前 \(K=6\) 个动作，再读取新观测并重新生成整个动作块：

\[o_j \rightarrow A_j \rightarrow \{a_{j,0},\ldots,a_{j,K-1}\} \rightarrow o_{j+1}.\]

这就是闭环与一次性生成 64 步后全部开环执行的根本区别：后 58 步不是承诺，而是本轮预测中未采用的尾部。

2.2 0.3 秒只属于理想节拍

论文给出的控制频率是 \(f_c=20\ \text{Hz}\)。若六个动作严格按该频率执行，纯执行时间为

\[T_{\text{exec}}=\frac{K}{f_c} =\frac{6}{20}=0.3\ \text{s}.\]

但完整重规划周期还受策略延迟、目标发布、低层消费和线程调度共同影响：

\[T_{\text{cycle}} =F(T_{\text{policy}},T_{\text{publish}},T_{\text{low-level}},T_{\text{schedule}}).\]

若策略推理和动作执行严格串行，周期近似为策略时间与执行时间之和；若二者充分流水重叠，则更接近两者中的较大者。公开代码的低层线程会与主线程并发，但没有时间戳记录，无法从静态代码判定真实重叠程度。因而策略更新频率只能写成

\[f_{\text{replan}}=\frac{1}{T_{\text{cycle}}},\]

必须通过运行时测量得到，不能直接断言为 \(1/0.3\approx3.3\ \text{Hz}\)。

2.3 公开代码真正保证了什么

execute_action 中的六次循环没有 sleep、时间戳、队列或低层确认。每次迭代会刷新一次观测缓存、覆盖臂目标并覆盖手部目标。低层机械臂线程则在另一个 Python 线程中运行。

因此应区分：

结论 是否可由公开代码直接保证
策略输出 \(64\times13\) 动作块 是
主线程依次处理动作块前 6 项 是
后 58 项不送入该六次循环 是
六个目标各保持 50 ms 否
六个目标都被低层线程完整消费 否
每 0.3 s 完成一次重新预测 否
真实部署遵循论文的 20 Hz 论文实验设置支持，但公开代码不足以独立验证

若主线程比低层线程快，中间目标可能在被消费前被覆盖。因而“执行前六个动作”是论文层面的算法语义；对公开 Python 实现，更精确的说法是“依次写入前六个目标”。

三、不是两条等价闭环，而是控制回路加异步终止器

flowchart TB
  O["当前图像、Cutie mask、关节状态"] --> P["predict_action<br/>ObsEncoder × 1，DDIM/DiT × 16"]
  P --> A["execute_action<br/>依次处理前 6 项"]
  A --> O
  V["check_grasp_success 后台线程<br/>同步请求 VLM"] --> F["写 in_post_run = True"]
  T["超时线程或键盘线程"] --> F
  F --> X["execute_grasping 退出"]
  X --> R["主线程统一执行 right_finish_reset"]
  R --> C["planner 模式再做 check_complete"]

策略循环负责连续生成动作；VLM 线程并不输出新的抓取动作，它只在满足条件后决定何时把 in_post_run 置真。超时线程和键盘线程写的是同一个标志。

3.1 VLM 核验不是固定 10 Hz

check_grasp_success 的一次循环包含同步阻塞式 VLM 请求，然后才 sleep(0.1)。实际核验间隔至少为：

\[T_{\text{verify}} =T_{\text{VLM}}+0.1\ \text{s}+T_{\text{local}}.\]

所以源码中的 0.1 s 是请求完成后的休眠，不代表每秒核验十次。

3.2 高度门控在公开代码中没有有效标定

核验条件写成 current_height > self.height_threshold，但公开实现把 height_threshold 初始化为 0，且未从配置读取。只有知道机器人坐标系与实际 z 值范围，才能判断该条件是否真的对应“物体已抬起”。不能直接把它解释为经过校准的离桌高度阈值。

3.3 三个 False 不是三次抓取

每次 reset_flags() 都把失败计数清零。在同一次 execute_grasping 运行期间，VLM 每返回一次 False，计数加一；连续三个 False 才设置结束标志。它统计的是同一抓取执行中的连续负面核验，不是三次独立动作尝试。

成功、三个 False、超时或用户回车最终都被压缩成同一个布尔标志。主线程不知道退出原因，随后统一调用 right_finish_reset()。这也是公开实现需要枚举化结束原因的原因。

四、为什么可能出现失败后重抓

官方重抓示例一

第一次接触后未稳定持握，后续动作再次接近并合拢。视频直接引用官方项目页。

官方重抓示例二

目标在接触中发生位移，控制器随后根据新观测继续动作。视频直接引用官方项目页。

4.1 论文明确提出的三个因素

论文把鲁棒性归因于：

  1. 基础模型感知在外观变化下提供较一致的语义表示；
  2. 模仿学习避免显式构造物体模型；
  3. 扩散动作头能够建模多模态动作分布。

这些是作者给出的总体解释，但论文没有针对“重抓”分别消融三项贡献，也没有证明某个失败状态一定落在训练分布内。因此，更严谨的表述是：三项因素使闭环重抓更可能可行，不是重抓行为的充分因果证明。

4.2 源码提供的三个必要条件

持续反馈外层 while 会在未收到终止信号时反复生成动作块，使接触后的新视觉状态有机会影响后续动作。
随机动作采样每次 conditional_sample 都从新的高斯噪声开始；同一观测也可能得到不同动作样本。
目标身份保持Cutie 在抓取尝试内维护目标 mask，使目标移动后仍可能作为同一控制对象进入下一次策略调用。

这三项能解释系统为什么具有重抓的结构条件，但不能证明“策略理解了失败”。

4.3 控制器没有时间窗口，但整个系统并非无记忆

配置为 n_obs_steps: 1，因此控制器每次只接收当前一帧图像和当前本体状态，没有显式的历史观测序列或循环隐状态。它无法直接比较“失败前”和“失败后”两帧。

但不能把整个系统称为无记忆：

  • Cutie 内部维护视频目标分割记忆；
  • planner 保存初始图像、用户提示和当前抓取指令；
  • 后台线程维护计数器、开始时间与结束标志；
  • 机器人当前关节与手部状态本身包含过去动作造成的物理结果。

准确结论是：低层策略是单帧条件策略，完整系统是有状态的。

4.4 成功演示不等于覆盖失败状态

训练数据包含 2,094 条通过质量检查的成功演示，通用抓取 episode 固定为 75 步。pad_after=63 允许 75 个时刻都作为 64 步动作窗口起点，越过末尾的部分用边界值填充。因此训练确实覆盖接近、接触、合拢与提起等不同成功阶段。

但这不能证明失败后的状态“属于训练分布”。失败可能造成目标翻转、滑落、遮挡、手指卡住或关节姿态异常，这些都可能远离成功轨迹。更稳妥的机制假设是：

当失败后的观测与某些成功轨迹中间状态足够相似时，单帧闭环策略可能继续输出合理抓取动作；相似性不足时则可能重复失败或产生异常动作。

这解释了为何成功演示也可能产生恢复行为，同时保留了必要的不确定性。

五、一次外层循环的精确调用次数

在不假设任何运行频率的前提下，公开代码仍能给出以下调用计数：

模块 / 操作 每次 execute_grasping 外层迭代
策略 predict_action 1 次
观测编码器 1 次
DiT 前向 16 次（默认 DDIM 16 步）
外层的 get_state/get_mask/get_obs 各 1 次
六步循环内的 get_state/get_mask/get_obs 各 6 次
臂目标写入 6 次
手部 execute_action 调用 6 次

所以 get_mask 的确被调用 7 次，观测编码器调用 1 次，DiT 调用 16 次。但“7:1”是调用次数比，不是频率比：

  • 六次内层调用之间没有固定等待；
  • 相机线程可能尚未产生新帧；
  • 对相同图像连续调用 Cutie 不等于获得七个独立时间点的目标位置；
  • 中间臂目标也可能被覆盖。

因此不能从该计数推导“Cutie 约 23 Hz、策略约 3.3 Hz、DiT 约 53 Hz”，也不能据此断言跟随主要由 23 Hz Cutie 驱动。

可以保留的一条重要优化是：每次策略调用只运行一次观测编码器，得到的条件 token 被 16 个 DDIM 去噪步骤复用。若在每个去噪步骤重复运行视觉编码器，推理开销会显著增加。

六、人为干扰下的跟随：谁贡献了什么

官方人为干扰示例一

目标在执行期间被移动，系统仍继续接近。视频直接引用官方项目页。

官方人为干扰示例二

目标多次改变位置，控制器根据后续观测调整动作。视频直接引用官方项目页。

跟随能力需要一条完整链路，而不是单个模块：

  1. 相机产生足够新的图像；
  2. Cutie 没有丢失或串换目标身份；
  3. RGBM 观测在下一次策略调用前完成更新；
  4. 控制器对新位置输出可行动作；
  5. 低层执行及时消费新目标。

Cutie 负责“目标还是不是同一个”，低层策略负责“当前观测下做什么”，动作执行层决定“新目标是否及时作用于机器人”。把抗干扰能力全部归给扩散策略或全部归给 Cutie 都过于简单。

公开代码还留下了 mask 与图像可能错位的 TODO。图像由独立线程持续覆盖，共享状态没有帧 ID 或时间戳；目标快速移动时，RGB、mask 与关节状态可能并非同一时刻的快照。

七、扩散随机性与多模态动作

默认 DDIM 步骤在给定初始样本、观测和确定性算子的条件下是确定的。随机性主要来自每次采样开头新建的高斯噪声：

\[A=g_\theta(o,\epsilon),\qquad \epsilon\sim\mathcal N(0,I).\]

因此：

  • 同一观测与同一初始噪声，理论上应得到同一动作块；
  • 同一观测与不同噪声，可能得到不同动作，但不保证一定落入不同语义模态；
  • 真机观测也在变化，所以实际差异同时来自 \(o\) 与 \(\epsilon\)；
  • Ours@2、Ours@3 的提升说明额外机会能够恢复部分失败，但不能仅凭结果把所有恢复都归因于扩散多模态性。

“预测 64 步”也不等于执行一个 3.2 s 的长期计划。以训练采样频率计算，动作块名义跨度为 \(64/20=3.2\) s，但部署只采用前缀，其主要价值是联合建模动作的时间结构，而非承诺执行完整尾部。

八、其他现象不要混入同一种“涌现”

现象 更准确的归属
失败后再次接近 低层闭环可能产生的行为；没有专门失败恢复监督
目标被移动后继续跟随 Cutie、观测更新、策略重规划与低层执行共同作用
透明、反光、可形变、背景近色物体 论文归因于基础模型表示、目标 mask 与闭环控制的组合
不同方向或姿态的接近 与观测条件和扩散动作分布都有关
长程任务自动换目标 高层 planner 的指令提出与完成检查，不是低层策略涌现
先推到桌沿再抓 使用 1,029 条专门演示重新训练的非抓取式控制器

非抓取式实验保持 planner 与整体架构不变，但控制器训练数据、视觉编码器配置和动作长度都发生变化：头部与腕部都使用 ViT-B/14，动作长度改为 100，并训练 200 epochs。它证明的是框架可迁移到新技能，不是原抓取权重零样本获得了新技能。

九、这些行为何时会失效

失效条件 原因
Cutie 漂移或串换目标 本次抓取尝试内不会重新调用 SAM 播种；要等尝试结束、planner 重新出框
RGB、mask、状态时间错位 共享数据没有锁、帧 ID 与同步快照
六个动作目标被快速覆盖 主循环没有 20 Hz 节拍、队列与消费确认
失败状态明显超出成功轨迹 仅成功演示不能保证该状态上的合理恢复
VLM 反复误判 布尔解析脆弱，三个 False 只是结束当前抓取；planner 仍可能继续下一轮
completion check 持续 False 内层规划循环没有全局 deadline 或最大抓取次数
需要触觉判断是否稳定持握 当前系统没有触觉；论文明确列为局限
功能性抓取与后续操作 当前工作没有覆盖，论文将其列为未来方向

此外，scale 没有对臂动作先限幅；生成值若越过 \([-1,1]\)，映射后的关节目标可能越过配置限位。真实硬件驱动是否二次限幅不在公开代码中，不能假定存在。

十、怎样验证这些机制，而不是只看演示视频

要区分各模块的因果贡献，可设计以下对照：

  1. 闭环消融：固定同一初始噪声，比较 \(K=6\) 与执行完整动作块；
  2. 跟踪消融：Cutie、逐帧 SAM、固定初始 mask 三组比较目标移动场景；
  3. 随机性消融：固定噪声与重采样噪声比较同一失败状态的恢复率；
  4. 历史消融：单帧策略与短时观测窗口比较重复失败和遮挡；
  5. 时序记录：为图像、mask、策略输出与低层目标打单调时钟时间戳，测真实延迟和丢目标率；
  6. 执行确认：记录六个目标中实际被低层控制器消费的数量，而不是只数 Python 循环；
  7. 失败状态数据集：按滑落、推移、遮挡、手型错误等类别保存中间状态，单独报告恢复率。

只有这些实验才能把“系统展示了重抓”推进到“哪种机制在多大程度上导致重抓”。

十一、结论：可以说什么，不能说什么

可以由证据支持 不应直接下结论
论文展示并报告闭环重抓与抗干扰行为 模型具有人类式失败理解
控制器每次只使用一帧观测 整个系统完全无记忆
动作块长度 64，公开代码遍历前 6 项 公开代码严格以 20 Hz 完成六个动作
每次外层迭代调用 Cutie 7 次 Cutie 的真实更新频率是 23 Hz
成功演示覆盖成功轨迹的多个阶段 失败后的状态必然处于训练分布内
扩散采样会使用新的初始噪声 每次重采样一定产生不同抓取模态
planner 用 VLM 判断抓取与任务完成 低层控制器知道自己是否抓取成功

DexGraspVLA 的重要贡献不是一个无法解释的“恢复智能”，而是把基础视觉表示、目标跟踪、动作扩散与层级规划组织成持续接收反馈的系统。该结构确实为重抓与抗干扰提供了条件；同时，公开实现的线程同步、动作节拍、输出校验和安全终止仍有明显工程缺口。把两面都写清楚，才能准确理解论文展示的能力。
