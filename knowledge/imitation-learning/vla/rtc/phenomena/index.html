知识库·机器人模仿学习与 VLA·RTC·Phenomena
  • 汇合语义：可从 Experiments 或 Source Code 任一路线进入，merge_policy:any；不要求两页同时完成，也不伪造默认上一页。
  • 诊断边界：先冻结版本与 trace，再提出至少两个候选原因；缓解项是诊断建议，不是现场安全指令。
  • 执行边界：本页只给静态诊断契约，所有实验模板均为 NOT_RUN；不运行模型、评测、仿真、服务或机器人。

先分清目标：连续性、反应性、吞吐、正确性与安全

“更平滑”不等于“更及时”；单次模型更慢可与任务更快同时成立；没有保护停机不等于安全；代码未报错也不等于 trained 条件仍在训练分布内。先明确目标，才知道该看什么 trace。

Continuity

boundary delta、二阶差分；需与 applied action 和 task success 同报。

Reactivity

capture-to-effective-action、observation age；不能只看新块 ready。

Throughput

逐 episode progress/duration；与 model latency 分开。

Correctness

任务阶段、接触和目标；平滑错误动作仍是错误。

Safety

reject、override、protective stop；与 exclusion 联合报告。

任何单指标优化都可能转移代价：强 overlap 改善连续性却降低远端反应；大 queue 减少 underflow 却消费更旧观测；controller filter 掩盖 proposal 跳变却增加延迟。诊断报告必须注明 primary objective 与 guardrail。

诊断契约：信号、假设、证伪与证据等级

Freeze→Capture→Classify→Hypothesize→Discriminate→Decide→Mitigate→Regress

Freeze 保存 code/config/checkpoint/task/seed；Capture 保存完整时间线与 raw/processed/dispatched/applied provenance；Classify 到公共、Guided、Training-Time 或 Runtime；Hypothesize 至少两个原因；Discriminate 做单变量或负对照；Decide 只用 supported/refuted/inconclusive；Mitigate 只改确认层；Regress 用固定 fixture 与真实 protocol 复核。

证据徽标：D1 现场 trace、D2 契约/几何推理、D3 固定实现、D4 论文证据；D5 本站复现 当前明确为 NOT_RUN。禁止 shortcut：只调 beta/queue threshold、只看平均 latency/proposal、只用一个 episode、见 NaN 就归因 GPU、见保护停机就删除 trial。

公共现象：多模态、观测时效、动作语义与指标错觉

C-COMMON-01 · 多模态平均失败

Signal：两个可行块分别绕行，逐元素平均却碰撞、停中间或失去抓取。假设：多模态；旋转/接触的欧氏平均无物理意义；ABI/anchor 不一致。证伪：固定观测多次采样并聚类，比较代表样本与均值；负对照为近单峰任务。缓解/Owner：选择一致模态或 RTC 约束，先修 ABI；policy + action representation。不能据此宣布所有 TE 失败。

C-COMMON-02 · 平滑但反应迟缓

测 observation age 与 capture-to-effective-action；候选原因是旧观测、s/H 太长、guidance 过强、后缀太短或 controller filtering。固定其他变量扫描 age/s，静态环境作负对照。先降低观测年龄，再讨论 horizon；不靠平滑分数判断。

C-COMMON-03 · 相对动作连续但物理跳变

若 action-space MSE 小但绝对轨迹跳变，检查 anchor、反归一化顺序、rotation composition 与 postprocessor。把动作重锚到同一 state/timestamp，分别比较 position/orientation/gripper；记录 raw/processed/applied。

C-COMMON-04 · 更平滑但成功率不升

联合报告 task、reaction、continuity、constraint 并按失败阶段回放。策略目标错误、必要纠正被压制、proxy 无构念效度或 controller 改写都可能成立；只需稳态跟踪的任务作负对照。

C-COMMON-05 · 模型调用更慢但任务更快

Guided model latency 上升可与 idle/retry 降低、throughput 上升并存。分测 model/request/idle/overlap/task duration/progress；同步执行或无 latency 小模型作负对照。不要宣称网络前向变快。

Guided 特有：短前缀、强引导与时间方向

C-GUIDED-01 · 小 delay 仍切换模式

d=1/2 且硬前缀满足后仍转向：可能是硬信号太短、多模态后缀、VJP/step 不足或 tick 错位。固定 observation/noise 扫 hard/soft/d/schedule；单峰任务为负对照。证据确认后才加 Soft overlap。

C-GUIDED-02 · beta 增大后发散/NaN

逐 flow step 记录 time、uncapped/capped weight、base velocity、VJP norm 与 finite；比较 beta=0。先核 time direction、correction sign、Euler step、normalization，再选 cap。任何 nonfinite command 在 postprocessor 前立即 fail closed。

C-GUIDED-03 · Soft Mask 过强导致迟钝

固定 observation pair，按时间位置测新观测对输出的差异；旧/新观测相同作负对照。只有证据支持时缩短 endpoint 或加快衰减，保留 hard prefix，并复查 task outcome。

C-GUIDED-04 · 跨框架符号看似相反

JAX 加、PyTorch 减可能来自 time/error 反向，也可能是 port bug。对齐 noise/data endpoint、final estimate、error、correction 和单步 update，用同 fixture 比最终状态；zero guidance 为负对照。

Training-Time 特有：support、checkpoint 与后缀自由度

C-TRAINED-01 · 超训练 support 仍能调用

API 返回 action 不代表可靠。保存 sampled support histogram，按 in/out-support 分桶并禁止 silent fallback；support 内同后缀长度作负对照。超界 typed discard/replan，Owner 为 trained distribution + Runtime。

C-TRAINED-02 · 高 delay 退化混合了多个原因

分别检验 condition OOD、有效后缀 H-d、observation age 与 queue discard；同 d 更大 H 或受控 age 作负对照。不能用一条成功率曲线锁定根因。

C-TRAINED-03 · checkpoint 名称兼容但能力缺失

核 `rtc_training_max_delay`、policy type、per-token time、prefix trace；已知 compatible fixed checkpoint 作负对照。缺失时 fail closed 为 `UNSUPPORTED_CHECKPOINT`。

C-TRAINED-04 · prefix 漂移或 loss 比例异常

逐步在 model eval 前后记录 prefix；手算 numerator/token denominator/action_dim。delay=0 常数比例可能来自 reduction，不等于 bug；empty mask/all-valid suffix 作负对照。

Runtime 竞态：延迟错位、队列、reset 与 authority

C-RUNTIME-01 · delay 接近却错位一到数步

统一 monotonic clock，记录 capture/start/ready/commit/dispatch 和 rounding，以 absolute tick join；fake clock 无 jitter 作负对照。裁剪用 measured consumption，predicted delay 只作条件。

C-RUNTIME-02 · 异步仍 queue underflow

把 queue depth 与阶段 latency、lock wait、exception 同轴，报告 P50/P95/P99/max；fake policy 固定 latency 作负对照。可能是 P99 超 runway、cold compile、争用、异常、锁或 backpressure。

C-RUNTIME-03 · reset 后旧动作写回

barrier 控制 in-flight job，reset 后释放并核 generation/epoch/authority；无 reset 时序作负对照。snapshot epoch + compare-and-commit，stale typed discard；authority mismatch 立即拒绝 dispatch。

C-RUNTIME-04 · applied 与 proposal 诊断相反

join model-space、processed、dispatched、acked、applied 五层，identity postprocessor/mock controller 作负对照；按首次产生差异层归属，不调模型掩盖 controller 问题。

C-RUNTIME-05 · 双 job 覆盖新结果

控制两个 fake job 反序返回并核 snapshot generation；单 job 为负对照。使用 single in-flight 或 generation-aware commit，不能把 completion order 当 creation order。

从可见症状进入的决策树

跳变 / 碰撞

先比较 raw → processed → applied 找首次差异层；核 absolute tick 与 relative anchor；最后才查 mask/mode。

周期停顿

查 queue depth 是否归零，再查 background exception、lock、P99 与 controller watchdog。

平滑但追不上

查 observation age、s/H/后缀长度、guidance/condition window，不先调 beta。

发散 / NaN

找 first nonfinite stage，再核 time direction/sign/cap、dtype/normalization/Euler step。

trained 丢块

比较 support/conditioned/measured delay、checkpoint capability 与 suffix length。

reset / authority 泄漏

核 epoch/generation/task/authority、compare-and-commit 及 ack/applied join。

每个叶节点回到具体 case，不直接给调参答案。trace 不足统一进入 INSUFFICIENT_TRACE，不能以邻近日志或一次复现猜测。

RTC 的能力边界与停止条件

Guided 依赖可迭代 action-chunk generator，每 flow step 增加 VJP 成本与 autodiff 约束；Training-Time 需要 compatible checkpoint、per-token time 与训练 support。有限 horizon 需满足 d<=s<=H-d，d>=H 时全块过期。连续性与反应性是条件化折中；RTC 不预测未来视觉，不是动力学安全层，也不替代 limit/collision/watchdog/e-stop。Kinetix 与 LeRobot 都不是公开的 PI 完整真机栈。

停止并升级：出现 nonfinite action/correction、ABI/contract hash mismatch、authority/reset epoch mismatch、controller/safety NACK、反复 underflow、support 反复超界、protective stop、无法还原 applied action，或需要改变现场安全阈值时，不继续在线调参。只转交公共安全页和组织处置流程；不提供现场恢复命令，也不自动 resume。

未证明：所有 VLA 都受益；某 beta/schedule/H 通用最优；平滑度带来安全；训练外 delay 固定速率退化；后续方法全面优于 RTC；公开仓库能复现 PI 真机系统。
