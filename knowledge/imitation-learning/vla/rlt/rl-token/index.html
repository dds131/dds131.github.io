RLT 枢纽· ← ① 方法定位· ② RL Token· ③ Actor-Critic →

RL token 是学习出来的状态读出接口，不是动作、语言或随意池化的 embedding

第一阶段让一个紧凑向量承担重建整段 VLA 内部表示的压力。第二阶段只保留 encoder 输出，把 decoder 丢弃并冻结 VLA，从而给小型在线 RL 提供稳定、低维、任务相关的状态。

一、从 VLA hidden states 到一个 RL 状态

设 VLA 接收环境状态 $s$ 与语言指令 $\ell$，最后一层产生 $M$ 个 token embeddings：

\[\mathbf z=f(s,\ell;\theta_{\mathrm{vla}}), \qquad \mathbf z_{1:M}=\{\mathbf z_1,\ldots,\mathbf z_M\}.\]

论文给出的是可包含语言条件的一般形式；但在四项实验里，每个任务只有一条固定语言指令，因此作者在重建步骤中省略了语言 embedding。这个实验简化不能外推成“RL token 与语言无关”。

这些 token 已经混合了视觉、任务语义和生成动作所需的信息，但序列长、维度高。RLT 添加一个轻量 encoder transformer $g_\phi$，在序列尾部附加可学习 embedding $e_{\texttt{rl}}$，只取特殊位置的输出：

\[\boxed{ \mathbf z_{\mathrm{rl}} =g_\phi([\mathbf z_{1:M},\mathbf e_{\texttt{rl}}])_{M+1} }\] 
flowchart LR
  I["VLA observation s · 语言 ℓ"] --> V["任务适配后的 VLA"]
  V --> T["z₁ z₂ … z_M"]
  E["learned e_rl"] --> G["轻量 Encoder Transformer"]
  T --> G
  G --> Z["z_rl<br/>单个紧凑向量"]
  Z --> D["Autoregressive Decoder"]
  T -. "stop-gradient targets" .-> D
  D --> R["重建 z₁ … z_M"]

这张图中，$z_{rl}$ 是 encoder 的读出位置；它不是把 <rl> 直接当成固定向量，也不是把所有 token 取平均。

二、为何训练目标是重建 VLA embedding

如果只加入一个特殊 token 却不给它任务，它没有理由汇总信息。RLT 训练 decoder 以 $z_{rl}$ 为条件，按顺序重建原始 VLA embeddings；单个向量因而形成结构上的信息瓶颈。重建目标鼓励它保留 VLA 信息，但“对 RL 有用”最终仍要由 Stage 2 的价值学习检验。

与像素重建相比，embedding 重建有两个重要含义：

  1. 目标空间已经经过 VLA 的任务训练，不要求小模块重新学习所有低层视觉细节。
  2. 重建保持的是“VLA 认为重要的内部信息”，而不是直接优化环境回报；Stage 2 的 critic 仍需从在线数据学习价值相关方向。
不能过度声称：低重建误差说明压缩向量能恢复 VLA 表示，不等价于证明它包含完整环境状态。接触力、遮挡物体或历史依赖若未进入 VLA 输入，RL token 也不会凭空补足。

三、自回归重建损失逐项拆解

定义 stop-gradient 目标

\[\bar{\mathbf z}_i=\operatorname{sg}(\mathbf z_i).\]

decoder transformer $d_\phi$ 与输出投影 $h_\phi$ 的目标为

\[\mathcal L_{\mathrm{ro}}= \mathbb E_{\mathcal D} \left[ \sum_{i=1}^{M} \left\| h_\phi\!\left( d_\phi([\mathbf z_{\mathrm{rl}},\bar{\mathbf z}_{1:i-1}]) \right)_i -\bar{\mathbf z}_i \right\|_2^2 \right].\]
压缩条件

每个预测位置都能读取 $z_{rl}$；它必须携带整段序列的全局信息。

已知前缀

预测第 $i$ 个 embedding 时，decoder 读取目标前缀 $\bar z_{1:i-1}$，形成 teacher-forcing 式自回归训练。

位置输出

$d_\phi(\cdot)_i$ 表示第 $i$ 个预测位置的 decoder hidden state。

维度投影

$h_\phi$ 把 decoder hidden state 映射回 VLA embedding 维度。

Embedding MSE

每个位置都与原始 VLA embedding 比较，并在示范数据 $\mathcal D$ 上求期望。

自回归 decoder 还能读取真实目标前缀，因此 $z_{rl}$ 不必独自记住每个 token 的全部细节；训练目标只是鼓励它补充有助于预测后续序列的全局上下文。若目标前缀本身已足够可预测，decoder 理论上仍可能弱化对 $z_{rl}$ 的依赖，所以不能把低重建误差等同于“单向量无损编码整段序列”。

四、Stop-gradient 究竟阻断什么

这里必须区分两个不同的梯度边界：

  1. $\bar z_i=\operatorname{sg}(z_i)$ 只把重建目标分支视为常量，防止模型通过移动目标 embedding 来降低误差；
  2. $z_{rl}$ 的输入仍来自 $z_{1:M}$，所以仅靠目标上的 sg 并不能阻断这条输入路径。论文另外规定 VLA 参数 $\theta_{vla}$ 不由 $\mathcal L_{ro}$ 更新，即把重建损失写成 $\mathcal L_{ro}(\phi)$。

实现时应通过冻结参数、detach VLA 输出或明确的 optimizer 参数组落实第二条；不能把“目标 stop-gradient”和“VLA 对重建损失冻结”混为一件事。

若第一阶段还做任务 SFT，总目标是

\[\mathcal L_{\mathrm{stage1}} =\mathcal L_{\mathrm{ro}}(\phi) +\alpha\mathcal L_{\mathrm{vla}}(\theta_{\mathrm{vla}}).\] 
flowchart TD
  LRO["L_ro"] --> PHI["更新 encoder / decoder / projection φ"]
  LRO -. "θ_vla 不在 L_ro 更新集合" .-> VLA["VLA θ_vla"]
  LVLA["α L_vla"] --> VLA
  VLA -->|"updated only if α > 0"| CKPT["Stage 1 checkpoint"]
  PHI --> CKPT
常见误读：“VLA 不受 $\mathcal L_{ro}$ 更新”不等于“Stage 1 的 VLA 永远冻结”。若 $\alpha>0$，VLA 仍由自己的监督动作目标 $\mathcal L_{vla}$ 更新；重建目标则只训练 $\phi$。

五、三种训练状态必须分清

阶段/设置 VLA Encoder Decoder Actor/Critic 主要产物
Stage 1，$\alpha=0$ 冻结 更新 更新 不存在 适配已有 VLA 的 RL 接口
Stage 1，$\alpha>0$ 由 $L_{vla}$ 更新 更新 更新 不存在 任务 VLA + RL 接口联合 checkpoint
Stage 2 在线 RL 冻结 冻结 不用 更新 actor、twin critic 与 target network
推理/评估 冻结 冻结 不用 actor 前向 $z_{rl}$、reference 与改进动作

原论文在每个目标任务上先用任务示范适配 VLA 并训练 RL token，附录报告 2,000–10,000 个梯度步；这是其实验设置，不是跨数据规模的固定规则。

六、decoder 为什么训练后可以丢弃

Decoder 的职责是给 $z_{rl}$ 提供学习压力，而不是在线验证压缩质量。Stage 2 只需要：

\[(s,\ell)\xrightarrow{\text{VLA}}z_{1:M} \xrightarrow{g_\phi}z_{rl}.\]

随后 actor/critic 直接消费 $z_{rl}$。保留 decoder 既不会给控制提供新信息，还会增加推理计算。因此部署模型可以丢弃 decoder 与输出投影，但不能丢弃 VLA 或 encoder：前者仍产生 hidden states 与 reference，后者仍产生 $z_{rl}$。

七、为何还要显式拼接 proprio

论文定义在线状态为

\[x=(z_{rl},s^p).\]

无论 VLA hidden states 是否已间接编码机器人构型，actor/critic 都显式拼接 proprio：这让精确、低维的本体状态绕过压缩瓶颈，不必要求 critic 再从 $z_{rl}$ 中反解。论文实验设置段区分了拧螺丝使用关节位置、其他三项任务使用末端执行器位姿；附录进一步说明 actor/critic 接收 proprioceptive position 与 velocity。复现时应以具体任务配置确认坐标系、维数与速度字段，不能只从概括句推断统一 schema。

不过，proprio 选择依任务而不同：论文拧螺丝使用关节位置，其他任务可使用末端位姿等。不能从单个复现配置推导出统一 19 维或 9 维状态标准。

八、Stage 1 与 Stage 2 一致性是最常见的工程风险

以下任一错位都会让“重建 loss 正常、在线 RL 失败”：

  1. 相机数量或顺序改变；
  2. 语言 prompt 改写导致 token 与任务条件不同；
  3. proprio 字段、单位或索引改变；
  4. action normalization stats 与数据集不匹配；
  5. Stage 2 用了错误 VLA config 或错误 Stage 1 checkpoint；
  6. 训练用任务示范，部署却进入明显不同的入口状态分布。

RLinf 文档因此要求 Stage 1/2 的 repo_id、OpenPI dataconfig、normalization statistics 与状态语义一致。具体字段属于 RLinf 实现，但这条一致性原则来自模型数据流本身。

九、异常现象与底层原因

1. 重建 loss 很低，critic 仍学不好

重建目标可能优先保存高方差但控制无关的信息；在线数据又可能只覆盖狭窄成功轨迹。应检查 $z_{rl}$ 对任务阶段、接触前后和失败模式的可分性，而不是只看 MSE。

2. 增大 $z_{rl}$ 维度后反而更慢

一种可能原因是维度增大后瓶颈变弱，同时 actor/critic 参数量与拟合难度上升；也可能只是优化超参数没有随维度重调。论文没有给出 $z_{rl}$ 维度的系统消融，因此这应作为待验证诊断假设，而非确定因果。

3. 不同 checkpoint 的 $z_{rl}$ 不能直接混用

$z_{rl}$ 的坐标系由 VLA hidden space 与 encoder 共同决定。更换任一方后，已有 replay 中旧 token 与新模型输出不再同分布；若未做版本隔离，critic 会把不同表征空间当成同一状态。

4. 只在图像上训练 RL token 不代表 proprio 无用

某些实现允许 image_only 或掩码选择，但论文的在线 state 仍显式加入 proprio。实现开关必须依据任务与代码语义核对，不能只凭名称推断。
