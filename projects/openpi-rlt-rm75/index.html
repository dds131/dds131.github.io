openpi-RLT：RM75 实机在线强化学习

π0.5、RL Token 与轻量 Actor-Critic 的三阶段实机闭环；完整记录数据闸、在线训练、工程修复，以及成功率未提升的证据化复盘

π0.5 RL Token Online Actor-Critic Human in the Loop

冻结大 VLA，让小型在线策略在参考动作附近学习；三阶段完整跑通，但精密插装成功率没有提升。

这套项目把公开 RLT 方法迁移到三相机、七关节加夹爪的 RM75-B 真机系统。页面既记录成功的工程闭环，也保留无效基线、失败判据和停止续训的依据。

项目做了什么

第一阶段继承既有 VR 示教数据采集 与 π0.5 训练、部署和动作平滑。本项目没有重新定义这套基座训练，而是从已经具备任务能力的 step 40000 检查点开始，不重复讲相机同步、数据格式、Flow Matching 主干和 C² 块间平滑。

第二阶段把三路图像位置的 768 个、每个 2048 维的 prefix hidden tokens 压成一个 2048 维 RL token。π0.5 完全冻结，最终训练重建 MSE 为 0.1628，VLA 子树 51/51 张量与基座逐比特一致。

第三阶段冻结 π0.5 和 RL-Token，只训练约 230 万参数的 Actor 与 Twin Critic。Actor 读取 RL token、机器人状态和 VLA reference chunk，输出十步修正动作块；人类可用 VR 接管，纠正动作进入 replay。

最重要的研究结论：训练数值稳定、Replay 合法、Actor 过安全闸，都只说明实现和优化过程处于可运行状态；它们不能代替任务分解、奖励可达性、人工纠正落点和严格对照基线。

L4.2 最终效果：负结果也需要直接证据

视频中的直接观察：
  • 自主推理与动作执行质量较差，未形成稳定、连续的任务推进；
  • 机器人在关键步骤出现执行失败，并在录像所示的失败状态下无法依靠当前策略继续完成任务；
  • 为避免错误继续累积并恢复操作流程，操作者进行了多次、反复的主动接管；
  • 经过多轮采集、训练与接管纠正后，现场仍未观察到可归因于本轮 RLT 的实际效果提升。

该阶段经过多轮采集与训练，相关数据累计超过 300 条，但最终现场表现仍不稳定，部分表现反而不及原始 π0.5。反复接管说明当前策略尚不能在所示失败状态下自主恢复或继续推进任务，也说明“训练过程可运行”和“任务效果得到改善”必须严格分开。视频支持上述项目现场的定性观察，但不能补足缺失的纯 VLA 零接管基线，不能单独证明退化由 RLT 引起，也不能据此精确计算相对下降幅度。

恢复数据与 DAgger 影像边界：本段录像已包含恢复数据集的采集过程，因此没有再用相似的数据采集画面冒充独立 DAgger 效果视频。多次主动接管能够证明操作者实际参与了失败恢复和纠正数据采集，但不能自动证明这些数据已经转化为策略能力。若要评价策略收益，仍需锁定 checkpoint、任务条件、trial ID 与统一成功判据后重新进行正式对照。

这次迁移真正留下了什么

混合动作契约

七维关节使用 delta，夹爪保留绝对量；训练、Replay、Actor 输出和控制端用同一语义，并在上机前核验单位、有限性与跳变。

人在回路语义拆分

动作接管、人工奖励、自动低质量过滤和人工事后丢段分别记录，避免把“人介入过”误写成单一监督信号。

真机分级准入

从离线单测、全假链路、真特征服务、dry-run、离线预训练和动作闸逐层放行，再进入在线更新。

负结果证据分级

把直接记录、量化瓶颈与待验证风险分开；“未观察到提升”与“能精确算出下降多少”保持不同结论强度。
