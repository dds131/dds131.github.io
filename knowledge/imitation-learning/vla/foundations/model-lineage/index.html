视觉—语言—动作（Vision-Language-Action，VLA）谱系至少包含控制规模、语义预训练、跨本体数据、动作生成、开放制品和系统部署六条并行问题线。发布先后只能回答“何时公开”，不能单独证明谁继承谁、谁更强；本页也不提供跨协议排行榜。

  • 时间相邻不等于实现继承。 每条谱系箭头必须标记 inherits、uses_data、addresses 或 conceptual_bridge。
  • 节点必须先分类。 OXE 是数据生态，FAST 是动作 tokenizer，OFT 是适配配方；它们不能与完整策略按同一层级排队。
  • 创新必须有边界。 同时写前代问题、继承机制、新增变量、成本、适用条件、失败边界和一手证据。
  • 开放不是布尔值。 论文、代码、权重、训练数据、评测脚本、许可证和硬件依赖分别记录。
  • 没有登记独立复现不是反证。 它只表示外部同协议证据尚不足。

本页维护 10 个核心模型/方法组、4 个前沿观察点、5 类节点与 0 个跨协议总冠军。所有数字绑定具体论文、版本和协议；页面不下载或运行模型，不连接机器人，不生成训练、部署或安全批准。

怎样读谱系：三条轴、五类节点、五级证据

谱系阅读先回答“哪个问题线发生了什么改变”，再看公开时间和证据成熟度。一个模型可以同时继承旧组件、使用新数据、针对公开瓶颈提出解法；教学上相关的工作也可能没有 checkpoint 或代码级父子关系。

三条轴必须分开

轴 A 记录 first_public_date 和 peer_reviewed_venue。预印本公开日、正式发表日与后续代码更新时间分别显示，时间轴只表示公开顺序，不用箭头暗示继承。轴 B 才描述问题和实现关系，且每条边都带语义。轴 C 记录协议可比性与证据状态，不把多维状态压成总分。

箭头 含义 使用条件
inherits 明确复用模型、权重、结构或配方 论文或代码可定位
uses_data 使用数据生态或特定 release 数据清单与配方可定位
addresses 针对前代公开瓶颈提出解法 引言、消融或实验可定位
conceptual_bridge 教学上帮助理解，无直接实现继承 必须显式标“教学关系”

PaLM-E 到 RT-2 主要是具身语义 grounding 的概念/方法桥梁，不能把整个 PaLM-E 系统写成 RT-2 唯一父节点。OXE 到多个模型通常是 uses_data，不是 inherits。OpenVLA 到 OFT 才有明确基座—配方关系。任何箭头若找不到来源定位或其方向只来自叙事方便，应删除或降级为教学连接。

五类节点

节点类型 定义 实例 禁止误写
完整模型/策略 从观测和条件产生动作接口 RT-1、RT-2、Octo、OpenVLA、π0、π0.5、SmolVLA、GR00T 有模型名不代表开放或通用
具身语义模型 输出文本推理/计划，可接低层策略 PaLM-E 不能直接写成低层动作 VLA
数据生态/协作 汇集、标准化和发布多来源数据 OXE/RT-X 不能压成单一网络
表示/Tokenizer 把动作序列编码为可学习符号 FAST/FAST+ 不能单独当闭环策略
适配配方/实例 在基座上改变解码、输入或目标 OpenVLA-OFT 不能与基座割裂比较

RDT-1B、SpatialVLA、Gemini Robotics 与 Helix 使用额外 observation_only 标记。这不是重要性评分，而是维护边界：本页只记录稳定问题线和可观察主张，不为快速变化的产品版本建立深层继承树。

五级证据显示

同行评审正文支持正式论文中的方法与实验范围；预印本/技术报告支持作者公开描述，但可能变化；官方制品让读者核对代码、权重、配置或评测入口，却不自动证明全部能力；厂商自报只写“厂商报告/演示”；独立复现必须给第三方制品、协议和差异。

同一节点可同时拥有多个标签，例如论文已同行评审但权重关闭，或代码开放但训练数据不完整。作者代码重跑不算独立复现；第三方在不同机器人上成功应登记为 modified protocol。没有找到独立复现时写“本页未登记”，不能写“证明不存在”。证据更新时间必须跟随 source URL、版本和访问日期。

统一模型卡规则

每张核心卡固定九字段：输入/历史、动作表示、架构、数据/混合、目标函数、推理/控制频率、评测协议、创新、局限/开放性。标题旁另列节点类型、首次公开日、同行评审状态和证据更新时间。未知值写 unknown，不能从演示视频、模型名称或同家族其他版本推断。

“推理/控制频率”必须分开模型生成、replan、命令发送和底层伺服；“创新”只写相对前代问题的可区分增量；“开放性”拆成制品而非一个 yes/no。卡片用于候选审计，不是把描述性字段换算为分数。

日期字段也要锁定 source type。论文首次上传、项目页上线、代码 release、权重发布和正式录用常常不同；如果只保留一个年份，就会把公开时间、可用时间与同行评审混为一谈。证据快照应保存日期所对应的 URL、版本、时区和查询时间，后续页面更新不能倒填一个更早但当时不可用的制品。

节点类型可能随版本变化，但不能追溯改写早期节点。一个技术报告后来开放权重，或产品系统后来发布论文，应在同一 identity 下新增 evidence marker；若动作接口、训练目标或模型边界实质改变，则建立新 version 节点和 supersedes 关系。把整个 family 合成一张“当前最佳状态”会掩盖历史证据和用户实际可获得的版本。

继承关系必须指向可核查对象。复用相同 backbone 名称不证明继承 checkpoint，采用相同 Flow Matching 目标也不构成模型父子关系；只有论文、配置、权重初始化或代码路径明确时才用 inherits。其余可以写“共享机制”或 addresses，并保留两项工作可能独立发展的可能性。

证据冲突不能用来源等级自动覆盖。正式论文与官方代码若字段不同，可能来自实验版、发布版或配置变体；应并列 paper value、code value、commit 和解释，而不是默认论文永远正确或 main 永远最新。冲突未解时相关卡片显示 unknown/conflicted，不得选择对论点最有利的数字。

统一模型卡还要接受负证据：失败案例、未复现消融、运行依赖缺失和作者公开更正。正面结果与负面证据使用同一协议标签，避免页面只收集成功主张。若第三方改进了实现，也应区分“复现原 claim”“修复工程缺陷”和“在新协议取得结果”，三者不能合并成一个复现勾选框。

证据也有失效条件。项目页改版、权重撤回、许可证变化、代码依赖不可安装、评测链接失效或后续勘误都可能降低实际可核验性。snapshot 除 reviewed_at 外还要写下次复核日期和触发器；过期证据不自动变假，但不能继续用“当前可用”描述。关键来源不可访问时，保留历史引用并把可复核状态降级。

页面的公开时间轴和继承图必须从不同数据结构生成，避免一条排序字段同时承担两个含义。时间轴允许并列和正式发表 marker，继承图允许循环检测与 typed edge，证据泳道允许多标签。构建检查应拒绝无类型箭头、指向不存在节点的边、未来日期和没有版本的数字主张，而不是依赖编辑者目测。

RT-1、PaLM-E 与 RT-2：控制规模化和语义 Grounding 的汇合

这组三节点不是单线祖谱。RT-1 回答如何用大规模真实机器人多任务数据维持在线控制；PaLM-E 回答连续传感怎样进入大型语言模型并参与具身语义任务；RT-2 则尝试让预训练 VLM 的语义直接进入低层动作生成。

分支图叙事

控制规模线从单任务、小数据策略难吸收异质真机数据，走向 RT-1 的紧凑 Transformer 与离散动作接口。语义 grounding 线从语言模型缺少连续传感入口，走向 PaLM-E 的多模态 token 注入和文本任务统一。汇合问题不是“把两个模型拼起来”，而是 robot/web co-fine-tuning 如何让 Internet 语义通过动作 token 参与直接控制。

比较时应保留系统边界：RT-1 是直接策略，PaLM-E 机器人案例主要输出文本计划并调用外部低层策略，RT-2 是端到端 VLA 实例。三者的输入、动作、频率和成功定义不同，不能把各论文数字排成一条增长曲线。

架构 FiLM EfficientNet、TokenLearner、Transformer；含预训练组件但非联合 VLM
数据/混合 单机器人家族约 13 万 episode、700+ 任务，绑定 RSS 2023
目标函数 监督行为克隆式离散动作分类/序列预测
推理/控制频率 论文系统约 3 Hz；不是底层伺服频率
评测协议 同机器人生态的已见、新任务、新环境和新物体
创新 规模化真机数据、紧凑视觉 token、语言条件与在线控制的系统组合
局限/开放性 本体/场景集中；Internet 语义、跨本体和长记忆未解决

它继承 Transformer、FiLM、EfficientNet、TokenLearner 和动作离散化，新增的是面向规模化真实机器人多任务控制的系统组合、数据规模实验与实时部署验证。代价包括持续真机采集、封闭基础设施、量化误差和较低模型环。把它写成“第一个 Transformer 机器人策略”或“从零训练且没有预训练”都越过证据。

PaLM-E 紧凑模型卡

PaLM-E 将文本 token 与图像、状态估计或神经 3D 表征的连续编码交错输入预训练 decoder-only PaLM。其目标仍是文本自回归 next-token，机器人案例主要输出答案、规划步骤或高层决策，低层动作由外部策略或控制器执行；因此不报告统一低层控制频率。

数据混合包含机器人规划、VQA、caption 和 Internet 语言/视觉语言任务。创新是连续传感可进入大型语言模型，并在多模态具身多任务训练中出现迁移；边界是最大模型、数据和完整训练栈不完全开放，文本计划正确不保证执行成功。562B 只描述论文实例，不是所有 PaLM-E 结论的默认规模。

RT-2 紧凑模型卡

RT-2 的输入是图像与自然语言条件，具体实例沿用预训练 VLM 接口；动作被离散后表示成文本 token，并在机器人提示下约束有效动作词表。论文将 PaLI-X/PaLM-E 类实例扩展为端到端 VLA，用机器人轨迹与 web-scale vision-language 任务 co-fine-tuning，自回归预测语言答案或动作 token。

其核心增量不是单独发明动作离散化、Transformer、VLM 或 co-training，而是把动作写进 VLM 输出空间，并系统展示 web 语义向直接控制迁移。论文约 6000 次机器人 trial 的证据限于指定机器人、技能、未见物体/背景、符号和推理指令；权重、完整训练栈、动作量化和自回归延迟仍是边界。“emergent”只能按论文测试定义使用。

三者对照结论

RT-1 的证据是规模化真实机器人多任务策略仍可在线控制，不等于完整 Internet VLM。PaLM-E 的证据是连续传感可被大型语言模型 grounding 并参与具身语义任务，不等于低层 VLA。RT-2 把预训练 VLM 语义和动作生成合到 token/co-fine-tuning 接口，但其结论仍受封闭模型和特定协议约束。

chain-of-thought 实例与普通直接动作实例也要分开；不能暗示所有 RT-2 控制都显式生成推理链。PaLM-E 到 RT-2 是教学桥梁而非唯一 checkpoint 继承。页面因此不画“RT-1 < PaLM-E < RT-2”的升级箭头。

RT-1 的 3 Hz 只能描述论文部署栈的模型节拍。相机采样、动作 token 解码、命令发送和底层 controller 可能运行在不同频率；没有这些接口就不能与后来的 action chunk 系统做延迟排名。论文中的长时运行证明系统在该环境能够持续工作，也不等于解决任意长时任务、记忆或故障恢复。

PaLM-E 的连续传感 token 说明非文本观测可以被语言模型条件化，但输出接口决定它在机器人系统中的责任。若文本计划由另一个 policy 执行，任务成败同时依赖 planner、技能库、grounding 和低层 controller；页面不能把最终 success 全部归给 PaLM-E，也不能把外部技能已有的能力算作端到端动作学习。

RT-2 的动作文本化需要同时看 token mapping、有效词表约束、量化范围和控制 consumer。语言 token 与动作 token 共用输出形式并不表示语义相同；无效 token、EOS、延迟和 error propagation 都是动作接口成本。web/robot co-fine-tuning 证明某些语义迁移，但无法单独识别收益来自数据、基座规模、预训练任务还是动作统一方式。

三者的“泛化”也不使用同一分母。RT-1 区分已见技能、新任务、新环境和新物体，PaLM-E 覆盖规划、VQA 与语言能力，RT-2 又加入符号、推理和未见背景。任何汇总表必须保留 task taxonomy、trial 数、成功定义和 baseline；不能把不同标签都简化成一个 OOD 百分比。

若目标项目在三条线之间选择，先问瓶颈：缺大规模一致动作数据、缺语义 grounding，还是需要语义直接影响低层动作。回答不同会导向不同验证。模型名称不能替代目标 Action ABI、相机历史、控制 deadline、可用数据与开放制品检查；谱系只生成候选假设，不生成部署决定。

三篇工作的数据规模也不能直接比较。episode、任务、web 样本和多任务 mixture 使用不同单位；RT-1 的真机 episode 数不能与 PaLM-E 的语言/视觉任务数量相加，RT-2 的 co-fine-tuning 又包含不同监督形式。页面只在各自卡片保留原分母，并要求读者回到数据 release、采样和 robot trial 定义。

success 的系统归因同样不同。RT-1 的动作由其策略进入控制栈，PaLM-E 的文本规划通过外部技能执行，RT-2 的 token decode 再进入机器人 adapter。若只看任务最终完成，会把低层技能、提示、人工 reset 和 safety filter 的贡献混入模型。对照表因此同时列 output contract、external component 和 failure owner，而不只列最终百分比。

OXE/RT-X、Octo 与 OpenVLA/OFT：跨本体和开放基座

跨本体数据生态、通用机器人初始化、开放 VLA 基座和下游适配 recipe 是四种不同责任。把它们统称为“开放大模型”会混淆数据、模型、动作目标和部署代价。

OXE/RT-X 节点卡

Open X-Embodiment（OXE）汇集多机构、多机器人、多任务数据与标准化管线；它没有单一输入、全局唯一动作空间、模型 loss 或控制频率。RT-1-X 与 RT-2-X 是基于该生态的实验模型，研究跨机器人 positive transfer、少量目标域数据和模型规模效应，不能把 RT-X 写成一种固定架构。

数据贡献与模型实验应分框：前者是 RLDS 表示、数据转换、清单与 mixture，后者才是具体策略。创新是使跨机构数据协作和 transfer 成为可研究变量；局限是格式统一不等于 frame、unit、rate、controller、许可和数据质量统一。任何数据集/本体数量都绑定论文和 release，不能当永久统计。

Octo 紧凑模型卡

Octo 面向“社区缺少可下载、可微调、能接不同传感器和动作空间的通用策略初始化”。它接收语言或目标图像、观测历史和可扩展传感输入，以模态 tokenizer、block-wise attention Transformer 与 readout token/head 组织架构，连续多模态 action chunk 由 diffusion readout 生成。

论文使用约 80 万 OXE trajectories，在 9 个机器人平台进行预训练、微调和消融。语言使用预训练 T5 编码，但 Octo 不以 Internet VLM 生成头为核心，也没有发明 Diffusion Policy。贡献应写为开放通用初始化、灵活 token/readout 接口与 OXE 规模验证；iterative diffusion 成本、数据覆盖和目标域微调仍决定实际表现，“generalist”不表示任意机器人零样本可用。

OpenVLA 紧凑模型卡

OpenVLA 针对 RT-2 类系统制品不可充分访问的问题，公开 7B Prismatic VLM 基座、代码、权重和训练/微调入口。主要输入为当前第三人称 RGB 与语言；DINOv2 和 SigLIP 视觉特征连接 Llama 2，连续动作逐维分位归一、分箱并映射语言词表 token，自回归 cross-entropy 训练，本质仍是监督行为克隆。

论文报告筛选 OXE mixture 中约 97 万真实机器人 demonstrations，并在多机器人、29 个任务与微调设定中比较。开放性必须拆成论文、代码、权重、脚本、数据引用、评测与许可证；开放制品不等于上游数据可任意再分发。原版 OpenVLA 没有 OFT 的并行连续 action chunk 头，动作量化、自回归吞吐、单帧输入和目标机器人适配是主要边界。

OpenVLA-OFT 配方卡

OpenVLA-OFT 针对原基座在下游机器人上的微调、输入扩展与逐 token 解码速度。它复用 OpenVLA 基座，可加入 wrist camera 和 proprioception，以连续 action chunk、parallel decoding、continuous head 与 L1 regression 形成适配 recipe；OFT 是配方，OpenVLA-OFT 是实例，OFT+ 的额外语言 grounding 增强不能混入基础 OFT。

论文在 LIBERO 与 ALOHA 协议内报告相对 base OpenVLA 的 26× action-generation throughput、3× lower latency 和成功率改善。这些数字依赖基座、硬件、解码与适配设置，不可外推任意 VLA。action chunk、连续回归、parallel decoding 和 L1 都非单项首创；准确归属是“经系统消融形成并验证的组合 recipe”。

四节点小结

OXE/RT-X 让跨本体数据协作和 transfer 可实证；Octo 提供不依赖大语言生成头的开放通用策略初始化；OpenVLA 提供 RT-2 式开放基座和研究入口；OFT 重做下游动作解码与训练配方以改善速度和成功。四者不能按发布日期、参数量或单一成功率排序。

开放性比较还需固定 revision：论文正式版、仓库 main、权重、数据 mixture 和评测脚本可能不同。代码可运行只说明实现入口存在，不证明论文数据、硬件和所有数字可复现。

OXE 的 standardization function 是每个来源的语义转换入口，不是一个神奇的全局 Action ABI。RT-X 实验可能筛选数据、设定公共输出或使用 dataset-specific adapter；这些选择属于模型配方。比较 Octo 与 OpenVLA 时必须固定它们各自使用的 OXE 子集、过滤、采样、相机和 action transform，不能用“OXE 训练”假设输入完全相同。

Octo 的开放价值包括可下载初始化、可扩展 modality/tokenizer 和目标动作 readout，但适配成本必须进入卡片。新增传感器或动作空间仍要定义 schema、mask、normalization、readout 与微调数据；diffusion sampler 的步骤、replan 和硬件也影响闭环吞吐。成功微调一个新平台不证明无需目标域数据，只说明公开入口使该实验可执行。

OpenVLA 的“开放 7B”需要一张制品矩阵：论文与项目页支持方法，代码/配置支持实现，权重支持初始化，训练脚本支持重建流程，数据引用支持来源追踪，评测脚本支持协议复查，license 决定可用范围。任一项缺失或受限都要显式列出，不能因 GitHub 可访问就把所有格子标 open。

OFT 的速度主张还要分解 measurement boundary。action-generation throughput、端到端 latency、replan frequency 和 controller command rate不是同一个指标；base 与 OFT 是否使用同硬件、precision、batch、缓存、输入数量和输出 horizon 决定数字含义。若目标机器人需要不同相机、chunk 或 safety gate，就必须重新测量，不能套用 26×。

版本边界应由依赖图维护：OpenVLA base revision、OFT recipe、OFT+ 变体、下游 dataset、processor、action head 和 checkpoint 共同组成实例。只写“OpenVLA-OFT”无法复现。若仓库未来改变默认 head 或输入，旧论文卡仍指向原制品，新版本另建 snapshot，防止 main 分支漂移改写历史结论。

跨模型适配成本应单列，而不是把“支持新机器人”写成零成本能力。Octo 可能更换 readout 和 tokenizer，OpenVLA 需要动作分箱、stats 与下游微调，OFT 还改变输入、head 和 chunk。数据采集量、可训练参数、显存、训练时长、calibration、controller adapter 与评测 trial 都要进入同一候选表；缺失值写 unknown。

baseline 公平性要检查每个模型是否得到其作者推荐的输入、优化和数据预算。用原始 OpenVLA 解码与经过 OFT 配方的另一个模型比较，或给 Octo 充分目标域微调却让 RT-X 零样本，都会把适配策略差异伪装成架构优劣。无法重做时可以引用论文内部结果，但必须明确 baseline setup 和不可对照项。

π0、FAST 与 π0.5：连续动作、离散序列和异构 Co-training

这组三节点最容易被压缩成“π0.5 是 π0 换了 FAST”。实际需要分开完整连续动作 VLA、动作序列 tokenizer，以及扩展架构、数据和目标的开放世界训练体系。

π0 紧凑模型卡

π0 接收多路图像、语言和本体状态，以预训练 PaliGemma VLM prefix 与较小 action expert suffix 逐层协作，使用条件 Flow Matching 速度场生成连续 action chunk。多机器人、单/双臂和移动操作数据与 Internet-scale VLM 预训练共同提供语义和控制基础。

贡献是把预训练 VLM、独立连续动作 expert、动作分块和 Flow Matching 组合成跨本体通用 VLA，并在复杂操作协议验证；并非首次发明 Flow Matching、PaliGemma、action chunk 或双流 attention。模型需多步积分，数据不完全公开，VLM prefix、replan、命令与底层伺服频率必须分开。2024-10 首次公开与 RSS 2025 同行评审日期同时显示，openpi 代码不等于论文全部数据和模型细节。

FAST/FAST+ 方法卡

FAST 的输入是一段连续动作序列，不直接消费图像或语言形成闭环策略。它沿时间轴做离散余弦变换（Discrete Cosine Transform，DCT）、量化、字节序列化与字节对编码（Byte Pair Encoding，BPE），得到更短的离散动作 token；FAST+ 是在大规模动作轨迹上构建的通用 tokenizer 制品。

创新是用频域压缩+BPE 缓解逐维逐时刻分箱在高频灵巧动作上的长序列问题。它单独不产生控制，吞吐取决于 token 数、decode 与 VLA serving；有损重建、词表数据依赖和跨本体接口仍需验证。论文报告与 π0 组合后训练时间最多约 5× 改善只属于其设置，不能写成任何模型必然加速。页面明确标记：不是完整 VLA。

π0.5 紧凑模型卡

π0.5 继承 π0 双专家，状态进入 VLM prefix，Flow 时间经 adaptive RMSNorm 注入，并用 attention mask 组织不同动作目标。训练配方容纳 FAST 离散 token 与连续 Flow Matching action expert，还混合 web、高层 semantic subtask prediction、多机器人数据和目标域阶段。

其系统级增量是把异构多模态 co-training、高层语义子任务预测和低层连续动作生成组织成开放世界 generalization 配方；不是只更换动作头。证据来自全新家庭的长时整理与消融，但数据/家庭覆盖和系统恢复仍有限。论文方法、公开 openpi 路径与 checkpoint 能力必须分栏；某些 pi05 实现路径可能只覆盖连续 Flow 分支，不能把论文双目标自动归入所有当前 checkpoint。

三节点关系

π0 是完整连续动作 VLA；FAST 是可接入自回归 VLA 的离散动作序列表示；π0.5 是在 π0 基础上扩展架构、数据、目标与训练路由的体系，FAST 只是其中一条信号。三者比较必须回到同一 Action ABI、tokenizer/solver、数据 release 和 closed-loop 协议。

π0 的 Flow Matching 证据要分训练目标和推理数值系统。论文可以规定 path、velocity target 与 action expert，实际 checkpoint 还依赖 solver、步数、precision、condition cache、unnormalization 和 scheduler。减少积分步可能降低延迟也可能改变轨迹质量；因此“连续动作”不是免费获得高频控制，仍需在目标硬件测 NFE、长尾延迟和闭环 deadline。

FAST 的评估不能只数 token。需要在相同动作、频率和本体上报告压缩率、重建误差、高频成分、gripper event、非法 decode、序列长尾与端到端训练/推理开销。BPE vocabulary 若使用 test 或目标域动作构建，还可能引入数据泄漏。FAST+ 的通用性是论文协议内主张，不代表任何新 robot 无需重建 stats 或验证 decoder。

π0.5 的 dual-objective 需要样本路由证据：哪些样本提供 FAST token、哪些提供 Flow target、attention mask 如何隔离、哪些模块收到梯度、高层 semantic subtask 怎样与低层 chunk 对齐。只看到 checkpoint 名称或 config 字段不足以证明所有目标已训练；论文、公开实现和具体权重必须分别标注支持范围。

三者的对照还要区分 representation capacity 与 system generalization。FAST 缩短离散序列不自动增加任务语义，Flow 生成连续轨迹也不自动产生长时规划；π0.5 的家庭任务表现来自数据、语义目标、模型、replan 和系统恢复共同作用。把结果只归给 tokenizer 或 objective 都会遗漏混杂因素。

反证条件应预先写入卡片：若 FAST 在目标高频动作上重建误差过大，若低 NFE 的 π0 未满足闭环质量，若 π0.5 公开 checkpoint 不含论文宣称的双目标，候选主张就要降级。负结果不是证明整条方法路线错误，而是限定版本、接口和协议的适用范围。

训练目标的名称也不能识别完整算法。π0 与 π0.5 都可能包含 Flow loss，但 condition、mask、数据路由、网络共享和 sampler 不同；FAST cross-entropy 也依赖 tokenizer、序列顺序和词表。审计应从 raw action 到 target construction，再到 checkpoint 输出和 inverse pipeline，不能靠配置里出现 flow 或 fast 字符串归类。

checkpoint identity 至少包含 architecture/config、processor、action schema、stats、tokenizer、solver/sampler、训练数据 snapshot 和代码 revision。论文 family 名称相同而这些依赖不同，就不是可互换制品。公开权重能被某个 loader 读取，只证明序列化兼容；是否实现论文方法、支持特定本体和达到报告结果仍需证据。

SmolVLA、GR00T 与四个前沿观察点

资源可达性、人形高维控制、显式空间表示和闭源大模型产品面向不同目标函数。页面不把“小”“人形”“200 Hz”或“厂商最新”换算成单一先进度。

SmolVLA 紧凑模型卡

SmolVLA 以多相机、sensorimotor state 和语言为输入，以约 450M SmolVLM2-based VLM 与较小 action expert 生成 Flow Matching action chunk。它把社区共享数据、LeRobot 工作流、小型开放基座、前缀缓存与可同步/异步队列组合，降低训练、微调和部署门槛。

450M 是发布模型规模，不是最佳规模证明；小型也不自动等于边缘实时。官方约 30% 任务时间缩短和约 2× 吞吐属于指定 Pick-Place 异步系统摘要，不是单次模型前向提速；同一论文的分段成功得分也未全面随异步提高。LIBERO、Meta-World 与 SO100/SO101 真机结果都受数据、适配和队列协议限制，RTC 是独立后续方法，不归作原始创新。

GR00T N1 紧凑模型卡

GR00T N1 面向人形和跨本体数据稀缺，输入多图像、语言与本体状态，状态/动作经本体专属边界模块映射。系统以 Eagle-2 视觉语言 System 2 提供条件，以 Flow Matching Diffusion Transformer System 1 生成连续 action chunk，并混合 web/human video、synthetic/simulation 和 real robot 数据金字塔。

贡献是面向人形跨本体的双系统、本体边界、数据组合与公开 2B 级制品；Diffusion Transformer、Flow Matching、VLM 和 synthetic data 是继承机制。多本体仿真、Fourier GR-1 和少样本适配结果不能外推其他人形平台；padding 接口、sim-real gap、硬件成本、数据开放度和独立复现仍待审计。N1.5/N1.6 等后续版本不得回填初代卡。

四个前沿观察点的共同模板

观察卡只显示公开日期/版本、瓶颈、可观察结构或数据增量、公开制品、作者/厂商协议内结果，以及尚不能下的结论与复核日期。它们不进入主矩阵总排序，也不会因为公司公告或项目视频自动成为核心继承节点。

“作者报告”与“厂商演示”要保留主语；开放状态拆成论文、代码、权重、数据和脚本。若正式论文、仓库或独立复现后来出现，更新 evidence snapshot，不重写早期公开日和当时证据状态。

RDT-1B 观察卡

RDT-1B 关注双臂协调、多峰连续动作和跨机器人动作语义，公开材料描述 1.2B diffusion Transformer、Physically Interpretable Unified Action Space 与多机器人预训练。证据包括 arXiv:2410.07864 和官方项目/代码，同行评审、固定 release 和许可证需在发布时复核。

作者报告真实双臂、未见物体/场景和少示范适配；这些结果不能从特定 6K+ 双臂数据与机器人外推所有本体，也不能据此宣布优于 π0/OpenVLA。它在本页只是连续生成与统一动作空间的前沿对照。

SpatialVLA 观察卡

SpatialVLA 针对 2D 图像 VLA 缺少显式 3D 空间关系，提出 Ego3D Position Encoding 与 Adaptive Action Grids。RSS 2025 论文与 arXiv:2501.15830 支持方法和约 110 万真实机器人 episode 的论文口径，代码承诺和实际仓库状态分开核对。

论文报告 zero-shot in-domain control 与新 setup adaptation，但“spatial-aware”不自动解决标定误差、遮挡、动力学、OOD 安全或所有 3D grounding。其数据规模不能与 OpenVLA/OXE 直接相加，也不能脱离动作网格和评测协议比较成功率。

Gemini Robotics 观察卡

Gemini Robotics 关注把 Gemini 多模态推理带入直接动作，官方材料把基于 Gemini 2.0 的 VLA 与 Robotics-ER 具身推理模型分开。2025-03 官方公告/技术报告支持产品定义和厂商演示，权重、训练数据、代码、评测脚本和访问方式分别记录。

厂商报告新物体、指令、环境、动态重规划、多本体与 dexterous demo；“超过两倍”必须保留 benchmark、baseline 和报告来源，不能写成对所有开放 VLA 的独立结论。受限测试、API 或 SDK 也不等于完整开源模型。

Helix 观察卡

Helix 针对大型 VLM 语义速度与人形高频全上身控制的时标冲突。Figure 2025-02 官方页面报告 S2 VLM 约 7–9 Hz、S1 visuomotor policy 200 Hz 的双速率结构和 35-DoF 上身控制，并展示未见物体、双机器人协作、单权重等主张。

当前核心证据属于厂商自报；缺少同协议公开代码、权重、数据和独立复现时，不能用 200 Hz 与 GR00T 成功率或开放性合并排名。200 Hz 也必须明确是哪个子系统输出，不等于整个 VLM 每秒前向 200 次。Helix 02/2.5 等后续产品不得回填初代卡。

小模型与人形系统不做一维排序

SmolVLA 优化开放、资源门槛和社区工作流；GR00T N1 优化人形/跨本体系统与异构数据；Gemini Robotics 强调闭源大模型语义与互动；Helix 强调人形高频双系统。目标硬件、数据、动作、开放程度和评测协议均不同。

定性比较可列语义预训练强度、动作生成复杂度、本体覆盖、开放制品、硬件门槛、评测可复核性、实时系统明确度和独立证据成熟度，但不画面积、不求和、不生成总分。每一格都链接具体证据或 unknown。

SmolVLA 的资源主张应同时给参数规模、显存/内存、precision、输入分辨率、chunk、solver、缓存和硬件。参数更少可能降低存储和算力，却不保证端到端延迟、数据效率或成功率更好；异步队列还会引入 staleness、overlap 和 fault handling。资源可达性是多维工程目标，不是一条“越小越优”的坐标轴。

GR00T 的人形覆盖也要按 embodiment 拆分。统一模型可使用本体专属输入/输出边界、padding 和 mask，因此“同一权重”不等于所有关节共享相同物理语义。数据金字塔中的 web video、simulation、synthetic 和 real robot 对目标与证据的作用不同，不能把总规模直接解释为真实动作数量或安全验证覆盖。

厂商观察卡采用可撤销语言：“官方页面报告”“演示显示”“技术报告描述”，并紧邻协议缺口。视频可支持某行为曾被展示，但没有失败样本、trial、seed、baseline、硬件和版本时不能估计成功率。营销词如 first、most advanced、virtually any 不进入 normalized claim，除非其定义和比较全集可公开核查。

前沿状态需要复核日而不是永久标签。代码、权重、论文、API、许可证或产品版本一旦更新，先判断是否仍是同一节点，再更新证据快照；不能把后续 Helix、Gemini 或 GR00T 版本能力回填到初代。过期但可复现的材料继续保留，404 或不可访问来源会让相应 claim 降级，而不是由搜索摘要补位。

所谓“目标函数雷达”只能是筛选提示：每个轴使用来源和定性状态，不以视觉面积暗示总价值。目标项目应选择与瓶颈相关的轴，例如边缘硬件看资源/延迟，人形看本体/控制接口，研究复现看开放制品；无关轴不应参与决策。筛选结果始终显示未知项，防止过滤器把证据缺失隐藏成不适用。

安全与交互主张需要独立证据。动态重规划、双速率控制、平滑 action chunk 或大规模仿真都不等于碰撞避免、力限制、急停和故障恢复已经验证。厂商页面展示人与机器人共处时，页面只能描述公开场景和系统声明，不能从视频推断安全认证、near-miss rate 或部署 envelope。

闭源或受限系统并非不能成为候选，但比较问题会改变。可测试 API、现场访问或合作评测可能支持 black-box 协议；无法固定模型版本、观察内部动作接口或导出日志时，创新归属和复现结论就更弱。卡片应区分“能力可测试”“实现可检查”“权重可持有”“训练可重建”，避免把访问权限当成开放性。

比较前置门禁

比较前披露是否匹配：机器人/Action ABI、任务难度、训练与微调数据预算、相机/状态/语言、action/execution horizon、replan/command rate、controller、成功定义、trial/seed、checkpoint selection、baseline 调优、预训练数据、硬件/precision/wall-clock，以及数据泄漏。

任一关键字段不同，就改写为“在作者协议 A 中，模型 X 相对 baseline Y 的指标 M 改善；由于机器人/数据/输入/控制/调优至少一项不同，本页不将其外推为跨模型总体排名”。不能直接相减来自不同 robot、任务或成功定义的百分比。

创新归属的七步检查

依次命名前代问题、列出继承机制、隔离新增变量、检查单变量/组合消融、记录训练/推理/集成成本、限定机器人/任务/频率/数据/安全条件，并写失败或反证条件。没有可定位问题不叫创新；没有隔离消融时写系统级贡献，不能把每个组成模块都归作首创。

成本不只指 FLOPs。更长 token、solver NFE、数据采集、专用硬件、闭源服务、adapter、校准和运维复杂度都影响可迁移性。一个方法在论文内提高成功率但增加无法满足的延迟或数据要求，对目标项目仍可能不适用。

Claim normalization

所有可检验主张转为 subject + change + baseline + scope + protocol + evidence/date。不合格的“OpenVLA 比 RT-2 强”应改为：OpenVLA 论文在其 29 项多机器人任务协议中，报告相对所采用 RT-2-X baseline 的平均成功率改善；两者权重、规模和数据不能完全对照，不构成通用排名。

“SmolVLA 异步快 30%”要改成指定 Pick-Place 系统的端到端任务完成时间点估计变化，而非模型前向速度。“Helix 200 Hz 所以比 GR00T 实时”要改成 Figure 页面报告的 S1/S2 频率，并注明缺少同机器人、硬件和协议对照。

读者验证练习

先写目标机器人的 observation、Action ABI、频率和外部安全边界；选择对应问题轴；填统一模型卡、创新归属卡、证据快照与可比性协议。所有未知用 unknown，至少给一条一手来源，并列出无法直接比较的字段。输出只能是“可验证候选假设”，不能生成“最佳模型”结论。

合格句式是：候选 A 可能适合目标本体，因为动作接口与连续 action chunk 相容且有公开权重/微调入口；仍需在相同观测、数据预算、控制频率和安全栈下与候选 B 做小规模验证，当前证据不支持通用优劣。训练、冻结、适配与 checkpoint 未知项交给下一页。

论文、项目页、代码和模型卡数字冲突时分别记录版本，不求平均；仓库 main 只用于发现，复现结论固定 commit；作者代码不算独立复现；厂商演示没有 trial、失败样本或统计时只支持存在性展示。无法访问来源时降级或移除 claim，不以搜索摘要替代正文。

候选对比应先建立目标 contract，再读取模型卡，而不是先选热门模型后寻找匹配理由。contract 包含 robot/tool、observation、Action ABI、controller、deadline、安全外部件、可用数据和治理限制。任何必要 adapter、tokenizer、solver 或服务依赖都成为比较成本；目标接口无法表达的模型输出不能靠“后续再适配”暂时忽略。

pilot 设计要把论文 claim 转成目标系统可证伪假设。先做离线 schema/round-trip、固定样本推理、latency/memory 和数据许可检查，再进入经过批准的仿真或闭环环境；每层预先定义通过、失败、停止和回滚。不能因开放权重能加载就跳到真机，也不能把单次 demo 成功当模型选择完成。

比较报告同时保留未运行、不可用、失败、证据不足和通过。依赖缺失或权重不可得不是零分，而是不可验证；协议不同不是失败，而是不直接可比。每个指标给分母、trial/seed、置信区间、排除规则、失败分布和版本，使后续读者能判断差异来自模型还是测量条件。

决策记录要写 chosen、rejected、deferred 的原因和触发重新评估的条件。选择一个候选不意味着其它节点普遍较差，可能只是制品、动作接口、数据、硬件或许可更匹配。若新 evidence、checkpoint、目标本体或预算出现，复用相同 comparison protocol 更新，而不是重写历史结论。

本页完成标准是每个核心节点有一致字段、每项创新可追溯、每个数字带协议、每个厂商主张有证据边界，并能产出安全的候选试验计划。它不下载模型、不执行训练/推理/机器人控制，也不授予部署权限。四份模板即使填满，最高也只表示“候选证据可进入下一阶段审阅”。

来源审阅应保存 claim-to-source 映射，而不是只列参考文献。每条模型卡字段和数字至少指向一个具体页、表、附录、配置或 commit；同一来源不能被用来支持其未讨论的开放性、安全或跨协议泛化。若引用只是背景机制，应标 context_only，避免读者误以为它验证了当前模型的实现。

最终候选清单要包含 no-go 条件。例如缺 Action ABI、数据权利不清、控制 deadline 无法满足、权重不可固定、评测日志不可取得或安全 envelope 未批准时，候选保持 deferred。no-go 不是模型质量判断，而是当前项目证据与接口不足；解决对应缺口后可按同一协议重新进入审阅。

主比较矩阵中的空白不能被排序器当作零。unknown、not_applicable、not_public、not_tested 与 not_registered 分别表达知识状态、责任边界、访问状态、实验状态和复现登记；它们对候选决策的影响不同。筛选时必须显示被排除节点及原因，避免证据最少的系统因为空字段不参与惩罚而显得更优。

所有论文数字还要保留原始单位和统计口径。平均成功率、分段得分、任务完成时间点估计、action-generation throughput、latency 与 token compression 不能放在同一“性能”列；即使单位相同，也要核对 trial aggregation、置信区间和 checkpoint selection。图表不归一化这些异质指标为百分制。

页面更新采用审阅日志：新增或移除 claim、改变节点类型、更新证据状态、修正日期或替换 URL 都写 reason、source 和 reviewer role。仅修复链接不应无声改变结论；正式论文出现也不自动让先前厂商主张升级为同行评审。历史 snapshot 保留，使读者能知道某次候选决定当时实际可见的证据。

与下一页的边界是：本页把模型 family 和证据缩小到可验证候选，不决定 full/frozen/LoRA、optimizer、loss weight、stage schedule、checkpoint selection 或 continual learning。下一页必须重新固定具体版本和训练制品；不能拿这里的 family 描述直接生成训练命令。若候选仍有开放性或接口未知，训练方案保持 blocked 而不是猜默认值。

读者离开本页时应能解释“为什么保留这个候选、哪些主张已被什么来源支持、哪些字段仍未知、什么观察会推翻当前判断”。若答案只有参数量、发布日期或一张成功率表，说明谱系审计尚未完成。候选记录必须携带 evidence snapshot 与 comparison ID，确保后续训练和评测不会把受限结论再次写成通用事实。

任何新增节点也必须先证明它补充了既有问题线或引入新的可审计问题；仅因发布更新、名称流行或参数更大，不足以进入核心谱系。无法稳定分类的系统先进入前沿观察区，待接口、制品和协议清晰后再评估是否升级。
