VLA/后训练与对齐/RLT/在线系统

本站系统合同采用 fail-closed 控制权：SAFETY_STOP > HUMAN_OVERRIDE > explicit BASE/RL authority > no-command。Replay 只把实际执行动作视作 Bellman truth；learner 只能看见原子 committed transition，不能读取 pending 半条记录。性能门不能覆盖安全门，本页也不启动 rollout、训练、发布或机器人。

flowchart LR
  O["observation service"] --> F["frozen VLA / feature"]
  F --> A["policy arbiter"]
  H["human / safety authority"] --> A
  A --> E["executor + independent safety"]
  E --> C["chunk receipt · executed truth"]
  C --> R["Replay pending → committed"]
  R --> L["learner candidate"]
  L --> P["publisher gates"]
  P -->|"chunk-boundary swap + ack"| A
  P -->|"rollback"| A
核对权限检查 Replay审计双门与回滚返回 RLT 总览

九主体、四时钟与写权限

主体 允许写入 不得写入
observation service immutable observation / sensor receipt policy、reward
frozen VLA/feature feature/reference receipt Stage 2 parameters
policy arbiter selected command owner / authority receipt learner parameters
executor/safety executed action、ack、safety event reward label
reward/termination service reward revision / termination action authority
Replay service transition lifecycle policy publish
learner actor/critic candidates active robot pointer
policy publisher active manifest / rollback receipt training data
human/safety authorities role-scoped events unrelated roles

四个时钟分别是 observation/sensor time、low-level control/executor time、chunk decision index k 和 learner logical step/update time。wall-clock 只用于 latency/audit，不能替代 logical ordering；跨主体消息必须带 monotonic sequence、timestamp domain 与 clock-sync status。

schema: rlt.online-actor-registry.v1
actors:
  - observation_service
  - frozen_vla_feature
  - policy_arbiter
  - executor_safety
  - reward_termination
  - replay_service
  - learner
  - policy_publisher
  - human_safety_authorities
clocks: [sensor, control, chunk_decision, learner_logical]
authority_precedence: [safety_stop, human_override, explicit_policy, no_command]

warmup 只是 Base authority 的阶段条件，不能绕过 safety。没有有效 lease/ack 或状态不确定时默认 no-command，而不是沿用旧动作。

Warmup admission、coverage 与退出

RLT 先用 Base VLA rollout 预填 Replay，让 critic 从可达状态和合理动作开始。论文只给抽象 N_warm，没有通用最优步数。任何 rollout 前的 admission 必须具备 feature/action/reward/termination revisions、sensor/action timestamp alignment、executor ack、safety readiness、operator roles、storage capacity、incident path 与静态合同检查；这里不执行这些运行流程。

WarmupGateReceipt:
  run_id: required
  base_policy_id: required
  feature_bundle_id: required
  action_contract_revision: required
  reward_revision: required
  safety_revision: required
  admission_checks: required
  coverage_summary: required
  success_failure_unknown_counts: required
  intervention_counts: required
  transition_validity_rate: required
  exit_reason: threshold | budget | operator | abort
  rl_authority_enabled: true | false

退出依据可包含有效 transition 数、状态覆盖、success/failure/unknown、action/reward 链路、intervention 和 safety incidents，但具体阈值由实现与风险评审提供。仅达到 N_warm 不证明 Replay 可学，也不证明 actor 可以获得控制权；enable RL authority 必须有单独 receipt。

一个 chunk collection transaction

chunk k 开始时 pin observation、feature bundle、VLA/reference sample、active actor manifest、action ABI、authority lease、safety revision、reward revision 与 timebase。仲裁只使用以下顺序：

if safety_stop: no motion / safe stop
elif valid human override: human command
elif explicit base authority or warmup: VLA reference
elif valid RL authority: active actor command
else: no command; abort collection

每次选择都生成 AuthorityReceipt，包含 request/ack IDs、owner、priority、lease start/end、reason、policy version 和 superseded request。executor 逐 low-level step 保存 raw/commanded/safety-modified/executed action、ack/deadline、observation、reward 与 termination；实际执行 1≤L_k≤C，terminal、safety stop、human intervention 或 infrastructure failure 都可提前结束。

schema: rlt.chunk-collection.v1
chunk_id: required
pinned_snapshot_ids: required
authority_receipt: required
reference_action_receipt: required
per_step_command_ack_execution: required
executed_length_L: required
reward_termination_receipt: required
next_observation_id: required
commit_status: committed | quarantined | aborted
content_hash: required

只有 next decision observation、reward-valid span、termination cause、executed prefix、reference/action provenance 与 hashes 齐全时才能原子 commit；否则从 pending timeout 进入 quarantined/aborted，learner 不可见。若 human/safety mid-chunk 接管，就在接管点结束 actor segment 并以真实 L_k 收口，再新建 authority segment；若只标 mixed authority，则默认 quarantine，直到算法明确支持，绝不能把整段归给单一 actor version。

Appendix 的 stride=2、C=10、50 Hz 因而约 25 windows/s 是 paper experiment；它既不改变真实 policy decision frequency，也不表示每秒产生 25 个独立样本。同一 episode、trajectory 或 overlap group 的窗口不能跨 train/validation/test。interaction time 按 unique physical steps 报告，training sample count 可以另列 windows，但要披露 overlap ratio 和 effective-sample caveat。

异步 rollout/learner 与策略发布

必须分开 learner update、checkpoint save/register 和 rollout publish：前者改变 training process 中的 candidate 参数，第二步生成 immutable artifact，第三步才原子切换 active actor manifest。一个笼统的“update”事件不能代表三者。

AsyncConsistencyContract:
  rollout_actor_version: required
  learner_actor_version: required
  target_q_version: required
  active_manifest_revision: required
  policy_lag_metric: required
  staleness_budget: required
  replay_visibility_watermark: required
  queue_backpressure_policy: required
  boundary_swap_only: true
  mid_chunk_hot_swap: forbidden

candidate 流程是 training → candidate registered → artifact checks → offline/static validation → shadow/no-authority validation → performance AND safety gates → chunk-boundary active swap → health observation → keep/rollback。具体环境不能做 shadow/canary 时必须记 not-run，不能伪称通过。

publish receipt 需要 model/config/action/feature hashes、signature/integrity、load result、device/dtype、test-vector result、activation boundary、old/new IDs 和 rollback pointer；actor worker load ack 前不得获得 authority。UTD numerator/denominator 继承第 41 页，系统另报 learner updates、Replay inserts、unique physical steps、publication cadence 和 on-robot policy lag，不能用高 updates/s 掩盖陈旧策略或旧 Replay 过拟合。

四类人工角色与控制权仲裁

角色 事件/权限 不自动拥有
reward annotator success/failure/unknown label、reward revision motion control
intervention operator corrective command、temporary action authority release approval
phase-switch operator Base↔RL request、phase authority safety bypass
safety operator/system stop/inhibit/recovery approval、highest veto reward rewrite

同一人可以兼任，但 event type、credential scope、UI action 和 audit record 必须分开；只保存 pseudonymous operator ID，避免无必要个人信息。

schema: rlt.human-authority-event.v1
event_id: required
role: reward | intervention | phase_switch | safety
operator_pseudonymous_id: required
reason_code: required
request_ack_times: required
authority_interval: required-or-none
affected_chunk_steps: required
command_source: required
reference_replacement: declared
safety_status: required
outcome: required

介入时 executed action 记录 human/safety 最终执行值，original VLA reference 保留；BC reference 是否替换为 human action按 Algorithm/implementation contract 登记。actor planned action 可保留 hash 供诊断，但不是 Bellman action。selection bias、intervention rate 与 human labor 进入实验成本。

奖励记录把 success/failure/unknown、label timestamp、annotator role、evidence、revision 与 adjudication 分开。unknown 不默认 0；progress reward 或 shaping 是 implementation extension，必须新建 reward revision。

Critical-phase handoff 与自动切换

BASE_ACTIVE → HANDOFF_PENDING → RL_ACTIVE ↔ HUMAN_OVERRIDE
RL_ACTIVE / HUMAN_OVERRIDE → TERMINAL or RECOVERY
ANY_STATE → SAFETY_STOP
SAFETY_STOP → RECOVERY_AUTHORIZED → BASE_ACTIVE or END

  transition_id: required

  trigger_source: predictor | operator | rule | safety
  trigger_version: required
  confidence: required-if-produced
  request_ack: required
  entry_observation_id: required

critical-only initialization distribution 与 Base VLA 前段诱导的 full-task entrance distribution 要分开版本化。升级前核对 pose/velocity/object configuration、failure modes、reference statistics 和 intervention rate；固定夹具上的成功不能代替 full-task entrance evidence。

训练末期可选的 handoff predictor 是独立 supervised VLA fine-tuning：dataset/label revision、VLA checkpoint、objective、selection、release 和 rollback 都单独登记。它不属于 frozen Stage 2 actor/critic optimizer，也没有 safety bypass。

性能门、安全门、incident 与 rollback

performance gate 使用 fixed protocol 的 return/success/throughput、variance 与 baseline；失败就不发布。safety gate 使用 independent constraints、incident-free evidence 和 operator readiness；失败必须 fail-closed/inhibit。两个 gate 都 pass 才可 active，critic Q、training loss 或单次成功不能替代任何 gate。

safety veto 始终优先；action bounds、velocity/acceleration/torque/force、workspace/collision、watchdog 与 emergency stop 由独立系统负责，具体阈值不进入公开页面。所有 safety modification/stop 都生成 event，并让 Replay 保存 executed truth 与 termination cause。

rollback target 必须是 validated immutable manifest，只在 chunk boundary 激活并获得 worker ack；回滚后的新数据带新 active revision，incident data 先 quarantine，不会因 rollback 自动删除。错误 reward label、sensor drift、action ABI mismatch 或 authority bug 都触发 affected-transition query、quarantine/invalidation、新 manifest 与新的 training/evaluation lineage，不能静默修改历史后复用旧报告。
