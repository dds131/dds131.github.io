π0 不直接用一次确定性回归输出最终动作块。它把连续动作建模为一个条件分布，再通过回归速度场，学习一条从高斯噪声到动作分布的生成流。这里需要区分两个事实：训练目标仍然是均方回归，但回归对象是条件速度，不是最终动作；推理时则需要多步积分，才能从噪声得到动作样本。

本页围绕三个问题展开：为什么直接动作回归在多模态数据上可能失效；Conditional Flow Matching 为什么能用可采样的监督目标学习条件动作分布；π0 的线性路径、时间采样和 Euler 积分在论文与源码中究竟如何对应。

条件分布目标是 p(A | o)，不是单一动作
线性条件路径固定动作—噪声对之间为直线
ε − Aπ0 的条件速度监督
Beta(1.5, 1)偏向高噪声端的时间采样
10 步默认 Euler 推理配置
无动作掩码固定提交的全部动作维度进损失
时间约定：本页统一采用 openpi 源码的方向，t = 1 是纯噪声，t = 0 是真实动作。π0 论文主要使用相反方向的 τ。两者满足 τ = 1 − t；更完整的符号核对见子页 ③。

一、π0 到底在建模什么

令 \(o\) 表示当前观测，包括图像、语言指令和机器人状态；令 \(A\) 表示未来一段连续动作组成的动作块。π0 的目标是条件分布

\[p_{\mathrm{data}}(A \mid o),\]

而不是只学习一个确定性映射。两种目标的差别如下。

建模方式 给定同一观测时的输出 能否直接表达多个动作模式
\(A=f_\theta(o)\) 一个固定动作块 不能
\(A\sim p_\theta(\cdot\mid o)\) 从条件分布采样一个合理动作块 可以

这里的“多个模式”不是指任意随机抖动，而是多个彼此不同、各自完整且可执行的策略，例如从障碍物左侧或右侧绕行。每次采样只需产生其中一个连贯模式，不应把不同模式逐元素平均。

二、直接动作回归的条件均值风险

2.1 结论成立需要哪些条件

若用平方误差训练单输出策略

\[\mathcal L_{\mathrm{act}}(\theta) = \mathbb E_{(o,A)\sim p_{\mathrm{data}}} \left[\lVert f_\theta(o)-A\rVert_2^2\right],\]

那么在讨论总体风险、模型容量足够且能达到最优解时，有

\[f^*(o)=\mathbb E[A\mid o].\]

因此，问题不是“使用 MSE 就必然失败”，而是：当 \(p(A\mid o)\) 明显多峰，且观测 \(o\) 不能消除模式歧义时，单输出 MSE 的总体最优解是条件均值；这个均值可能不属于任何真实动作模式。

2.2 条件均值为什么可能不可执行

从障碍物两侧绕行的轨迹都可行，但逐点平均后可能正好穿过障碍物。类似地，两种不同抓取姿态的关节角平均值，可能既不是第一种抓法，也不是第二种抓法。

训练 MSE 仍有诊断价值：多模态歧义可能表现为不可约误差，但较低的平均 MSE 不能证明闭环动作安全，也不能保证输出位于示范分布的高密度区域。最终仍需结合动作分布、闭环成功率和安全指标评估。

生成模型不是唯一可行路线。混合密度网络、离散动作策略和潜变量模型也能表达多模态分布。ACT 使用 CVAE 表达轨迹风格或模式，但推理时是否实际呈现多模态，还取决于隐变量的采样方式。π0 选择的是连续动作上的条件 Flow Matching。

三、为什么 π0 选择连续生成，而不是动作 token

离散动作策略可以把每个动作量化为词表 token，并用分类分布表达多个候选值；这条路线并非不能建模多模态。但它引入了两个额外设计问题：量化分辨率会影响连续控制精度，生成延迟则取决于 token 的组织与解码方式。

若把一个 \(H\times d\) 动作块的每个标量都单独离散化并自回归输出，最朴素的方案需要生成 \(Hd\) 个 token；这只是说明该具体编码方案的代价，并不代表 RT-2、OpenVLA 等模型都固定使用同样的动作块长度或 token 组织。

π0 选择直接在连续动作空间生成完整动作块，从而避免逐标量量化误差。不过，灵巧控制能力还同时受到数据、归一化、网络容量和闭环执行等因素影响，不能只归因于 Flow Matching。

四、Flow Matching 的生成过程

Flow Matching 学习一个随状态、时间和观测变化的速度场：

\[v_\theta(x,t,o).\]

推理从高斯噪声 \(x_1\sim\mathcal N(0,I)\) 出发，求解常微分方程

\[\frac{\mathrm d x_t}{\mathrm d t}=v_\theta(x_t,t,o),\]

并从 \(t=1\) 积分到 \(t=0\)，最终得到动作样本 \(x_0\)。改变初始噪声可以得到不同样本，但不同噪声是否对应清晰可分的行为模式，是训练结果而不是公式自动保证的性质。

高斯噪声 x₁（t = 1）
        │
        ▼
条件速度场 vθ(x,t,o)  ◀── 图像、语言、机器人状态 o
        │
        ▼
ODE 数值积分（t: 1 → 0）
        │
        ▼
动作样本 x₀

Flow Matching 是一个训练框架，并不规定所有概率路径都必须是直线。π0 具体选用了线性条件路径；其他 Flow Matching 模型也可以使用扩散路径等不同设计。

五、Conditional Flow Matching 的核心推导

5.1 真正想学的是观测条件下的边缘速度场

对固定观测 \(o\)，中间时刻的分布为

\[p_t(x\mid o) = \int p_t(x\mid A)\,p_{\mathrm{data}}(A\mid o)\,\mathrm dA.\]

其中 \(p_t(x\mid A)\) 表示围绕某个真实动作 \(A\) 构造的条件概率路径。能够推动 \(p_t(x\mid o)\) 演化的边缘速度场记为

\[u_t(x\mid o).\]

直接计算它需要对所有可能动作及其后验权重积分，训练时通常不可行。

5.2 可采样的条件监督

训练数据提供了 \((o,A)\)，我们还能采样噪声和时间，因此可以构造条件路径上的样本 \(x_t\)，并计算对应的条件速度 \(u_t(x_t\mid A)\)。Conditional Flow Matching 使用

\[\mathcal L_{\mathrm{CFM}}(\theta) = \mathbb E_{\substack{ (o,A)\sim p_{\mathrm{data}}\\ t\sim p(t),\;x_t\sim p_t(\cdot\mid A) }} \left[ \left\lVert v_\theta(x_t,t,o)-u_t(x_t\mid A) \right\rVert_2^2 \right].\]

平方误差的总体最优解是条件期望：

\[v^*(x,t,o) = \mathbb E\!\left[ u_t(x_t\mid A) \mid x_t=x,\,t,\,o \right] =u_t(x\mid o).\]

这一步解释了为什么“对速度目标做 MSE”与“直接对动作做 MSE”不是同一件事：前者在每个中间状态、时间和观测下恢复推动整个条件分布的边缘速度；后者只输出一个动作条件均值。

Flow Matching 理论表明，相应的总体 CFM 目标与边缘 Flow Matching 目标相差一个与参数无关的常数，因此二者对参数具有相同的总体梯度。这个结论不意味着有限批次的随机梯度逐样本相同，也不保证两种估计器的 SGD 轨迹逐步一致。

六、π0 的线性条件路径与完整训练目标

6.1 从动作到噪声的线性插值

按 openpi 源码的时间方向，采样

\[\epsilon\sim\mathcal N(0,I),\]

并定义

\[x_t=t\epsilon+(1-t)A.\]

端点满足

\[x_0=A,\qquad x_1=\epsilon.\]

对固定的动作—噪声对 \((A,\epsilon)\)，这是一条直线，其条件速度为

\[u_t(x_t\mid A,\epsilon) = \frac{\mathrm d x_t}{\mathrm d t} = \epsilon-A.\]

该监督目标沿这一个固定样本对的路径不随 \(t\) 变化，所以可以直接计算。

6.2 “直线、常速度”不能扩展到边缘流

训练时，许多不同的 \((A,\epsilon)\) 可能经过相同或相近的 \(x_t\)。网络的最优输出是这些条件速度在给定 \(x_t,t,o\) 后的条件期望，因此一般仍随 \(x_t\)、\(t\) 和 \(o\) 变化。

必须区分三层对象：

对象 是否必为直线或常量
固定 \((A,\epsilon)\) 的条件插值 路径是直线，监督速度为常量 \(\epsilon-A\)
学到的边缘条件速度 通常随 \(x,t,o\) 变化
推理时数值积分得到的 ODE 轨迹 不保证是直线

π0 论文将该线性条件路径称为 conditional optimal-transport path。这里的“conditional”很重要：条件路径具有 OT 形式，不代表混合所有条件路径后得到的边缘速度场一定是全局最优传输解。

6.3 完整损失

令 \(s=0.999\)，时间采样写成

\[U\sim\operatorname{Beta}(1.5,1), \qquad t=(1-s)+sU.\]

π0 的动作损失可写为

\[\boxed{ \mathcal L(\theta) = \mathbb E_{\substack{ (o,A)\sim p_{\mathrm{data}}\\ \epsilon\sim\mathcal N(0,I),\;U\sim\operatorname{Beta}(1.5,1) }} \left[ \left\lVert v_\theta(x_t,t,o)-(\epsilon-A) \right\rVert_2^2 \right], \quad x_t=t\epsilon+(1-t)A }\]
符号 含义
\(o\) 图像、语言指令和机器人状态
\(A\) 归一化后的真实动作块
\(\epsilon\) 与动作块同形的标准高斯噪声
\(t\) 流时间；源码约定下 1 为噪声端、0 为动作端
\(x_t\) 插值后的含噪动作
\(v_\theta\) 由动作专家预测的边缘条件速度
\(\epsilon-A\) 可计算的条件速度监督

七、为什么时间不是均匀采样

7.1 shifted-Beta 的准确写法

源码的采样是

time = jax.random.beta(time_rng, 1.5, 1, batch_shape) * 0.999 + 0.001

用随机变量写最清楚：

\[U\sim\operatorname{Beta}(1.5,1), \qquad t=0.001+0.999U.\]

因为 \(\operatorname{Beta}(1.5,1)\) 的密度正比于 \(U^{0.5}\)，训练会更频繁地采到接近 \(t=1\) 的点，也就是高噪声端。

论文使用相反方向的 \(\tau\)，令

\[\tau=s(1-U),\qquad s=0.999,\]

即可得到

\[t=1-\tau=(1-s)+sU.\]

如果把它写成 \(\tau\) 的概率密度，还必须包含变量变换带来的 \(1/s\) 雅可比因子；因此用上述随机变量变换比把 Beta 表达式直接等同于密度更严谨。

7.2 论文给出的动机与证据边界

π0 论文提出的假设是：对机器人观测预测高噪声动作状态，比图像生成场景中的相应端点任务更困难，因此应把更多训练预算放在高噪声区域。这个设计可以理解为针对动作生成统计结构的采样偏置，而不是 Flow Matching 的必然要求。

需要保留两条边界：

  1. 论文给出了设计动机，但没有用独立消融完全分离 shifted-Beta 对最终性能的因果贡献。
  2. 不能笼统声称噪声端误差一定被后续积分“放大”。误差可能放大、保持或收缩，取决于速度场的局部稳定性。

7.3 0.999 与 0.001 的截断含义

源码只采样 \(t\in[0.001,1]\)，排除了紧邻动作端的区间。固定 \(N\) 步 Euler 推理会在

\[t_k=1-\frac{k}{N},\qquad k=0,1,\ldots,N-1\]

调用网络；最后一次调用发生在 \(t=1/N\)，随后一步到达 0。若步长大于截断宽度，推理就不会在被排除的区间内查询速度场。论文据此把 \(s=0.999\) 与“约一千步以内”的积分支持联系起来。

这首先是积分区间覆盖的设计。避开精确端点也可能带来数值上的副作用，但现有一手证据不足以把“数值保护”认定为这两个常数的主要动机。

八、训练一次回归，推理多步积分

训练时，每个样本只抽取一个 \(t\)，构造一次 \(x_t\)，并执行一次模型前向；推理时没有真实动作，需要从噪声开始反复查询速度场。

令积分步数为 \(N\)，初始化

\[x^{(0)}=\epsilon,\qquad \epsilon\sim\mathcal N(0,I).\]

对 \(k=0,1,\ldots,N-1\)，显式 Euler 更新为

\[t_k=1-\frac{k}{N},\] \[x^{(k+1)} = x^{(k)}-\frac{1}{N} v_\theta\!\left(x^{(k)},t_k,o\right).\]

负号来自积分方向：ODE 的定义方向是动作到噪声，即 \(t:0\to1\)；生成时从噪声反向走到动作，即 \(t:1\to0\)。默认 \(N=10\) 是 π0 的工程配置，并不是理论保证的最优步数。步数增多通常减小数值离散误差，但也增加时延，而且模型未充分学好的区域可能限制收益。

九、与 Diffusion Policy 的准确比较

Flow Matching 和 diffusion 都可以从噪声逐步生成动作，但训练框架不能简单概括成“一个直线、一个曲线”。Flow Matching 也能采用 diffusion path；下表只比较 Diffusion Policy 的典型构造与 π0 选用的线性 CFM。

对比项 Diffusion Policy π0 的线性 CFM
中间路径 由前向扩散与噪声日程定义 固定动作—噪声对之间做线性插值
常见训练目标 预测噪声、分数或相关参数化 预测条件速度 \(\epsilon-A\)
单个训练样本 通常随机抽一个 diffusion timestep，做一次网络前向 随机抽一个流时间，做一次网络前向
推理方式 反向扩散或 DDIM 等采样器 对学习到的 ODE 做 Euler 积分
时间相关设计 噪声日程、训练采样分布和采样器 概率路径、时间采样分布、求解器和积分步数
论文中的推理步数 随实验配置变化 openpi 默认 10 步

Diffusion Policy 正文中的一组真实机器人设置使用 100 个训练 diffusion timesteps 和 10 次 DDIM 推理迭代；这里的“100 个训练 timestep”是噪声日程长度，不是每个训练样本执行 100 次网络前向。其附录和不同实验配置还出现了其他推理步数，因此不能把“Diffusion Policy 永远是 10 步”作为普遍结论。

π0 的 10 步与上述真实机器人设置在次数上相同，但两者每一步所求的量、路径参数化和求解过程不同。现有证据不足以把 π0 的性能归因于“步数一定更少”。

十、源码实现中容易忽略的细节

10.1 没有直接的语言建模损失

固定提交中，π0 的 compute_loss 只取动作 suffix 对应的输出并投影为速度，损失监督的是动作速度场，没有对语言 token 施加直接的交叉熵语言建模损失。

这不意味着图像—语言 prefix 与训练无关。Prefix 表征通过注意力影响动作 suffix；只要相关参数没有被冻结，动作损失仍可沿这条计算图向 prefix 侧反向传播。

10.2 固定提交的 JAX 路径没有屏蔽补零动作维度

不同机器人动作维度会补齐到模型配置的 action_dim；固定提交的 Pi0Config.action_dim 类默认值为 32，具体命名配置仍可覆盖。transforms.py 在尾部补零，固定提交的 JAX compute_loss 对最后一个动作维度轴整体取均值，没有按机器人有效自由度设置损失掩码：

# src/openpi/models/pi0.py
return jnp.mean(jnp.square(v_t - u_t), axis=-1)

# scripts/train.py
chunked_loss = model.compute_loss(rng, observation, actions, train=True)
return jnp.mean(chunked_loss)

在某个补零维度上，\(A=0\)，因此

\[x_t=t\epsilon, \qquad u_t=\epsilon=\frac{x_t}{t}.\]

shifted-Beta 采样保证训练中的 \(t\ge0.001\)，所以该关系不会除以零。它说明补零通道构成一个由输入和时间确定的监督子问题，但不能据此推导“完全不占用模型容量”。这些通道仍占据输出维度并参与计算和损失。

当补零通道误差已经很小时，对全部维度求均值会使标量 loss 相对“只统计有效维度”的口径更小。因此，不同有效动作维数或不同 action_dim 配置的 loss 不宜直接横向比较。PyTorch 实现可能先返回逐元素 loss 再由训练器归约，讨论具体数值时应注明实现路径。

10.3 动作归一化属于模型定义的一部分

插值、速度目标和损失都在归一化动作空间中计算。训练和部署必须使用匹配的数据统计量，并在执行前正确反归一化。统计量不匹配是动作幅度或偏置异常的一个常见原因，但不是唯一原因；还应同时检查动作坐标系、关节顺序、控制频率和 chunk 执行策略。

十一、重点、创新点与适用边界

11.1 应掌握的核心知识点

  1. π0 学的是条件动作分布 \(p(A\mid o)\)，不是直接输出条件均值。
  2. CFM 用可采样的条件速度监督，学习观测条件下的边缘速度场。
  3. \(x_t=t\epsilon+(1-t)A\) 只保证固定样本对的条件路径为直线、条件速度为 \(\epsilon-A\)。
  4. 学到的 \(v_\theta(x,t,o)\) 通常不是常量，推理 ODE 轨迹也不保证是直线。
  5. shifted-Beta 把更多训练样本放在高噪声端，并截去默认积分通常不会查询的动作端邻域。
  6. 训练每个样本只需一个随机时间点；推理需要多步数值积分。

11.2 π0 的贡献应如何定位

Flow Matching 并非 π0 发明。π0 的关键贡献是把连续动作块的条件 Flow Matching 与预训练视觉语言主干、独立动作专家和机器人数据训练流程结合起来，使模型能在保留视觉—语言语义能力的同时生成高频连续动作。

在动作生成侧，值得关注的具体设计包括：

  • 直接生成连续动作块，避免逐标量动作量化；
  • 用线性条件路径得到简单、可计算的速度监督；
  • 使用偏向高噪声端的 shifted-Beta 时间采样；
  • 采用少步 Euler 积分，在生成质量与控制时延之间折中。

这些设计共同组成系统。当前证据不能单独证明 shifted-Beta、直线路径或 10 步 Euler 中任一项独自造成整体性能提升；评价创新时应区分系统贡献、论文假设和已被消融验证的因果结论。

11.3 常见误解速查

容易误解的说法 更准确的表述
π0 不是回归模型 它不直接回归最终动作，但训练时用 MSE 回归条件速度
直接动作 MSE 必然失败 在多模态且观测不能消除歧义时，条件均值可能落在有效模式之外
π0 的速度场恒为常量 固定动作—噪声对的监督速度恒定；边缘速度通常随 \(x,t,o\) 变化
Flow Matching 的轨迹必然是直线 π0 的条件插值是直线；学习到的边缘 ODE 轨迹不保证是直线
CFM 与 FM 的 SGD 轨迹完全相同 二者总体目标只差参数无关常数；有限批次轨迹无需逐步相同
shifted-Beta 已被证明一定更优 这是 π0 的任务假设与设计选择，缺少完全隔离其他因素的消融
Diffusion Policy 每个训练样本前向 100 次 100 通常指扩散 timestep 日程；训练时一般只随机采一个 timestep
补零维度完全不耗费容量 其目标由输入与时间确定，但仍参与输出、计算和损失
π0 有语言建模损失 当前动作训练没有直接 LM loss；prefix 仍通过动作损失参与计算与梯度传播
