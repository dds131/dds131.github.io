## 一、修改的原有文件：`_config.yml`

### 改动 1 —— 第 21 行：`url`

```diff
- url: https://alshedivat.github.io # the base hostname & protocol for your site
+ url: https://dds131.github.io # the base hostname & protocol for your site
```

| 项                 | 说明                                                                                                                                                                             |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **为什么改**       | `url` 是站点的绝对根地址，Jekyll 用它生成 canonical link、sitemap、RSS feed、Open Graph 标签中的绝对 URL。上游默认值指向 al-folio 官方演示站，不改则这些元数据全部指向别人的网站 |
| **为什么是这个值** | 仓库归属账号是 `dds131`，GitHub Pages 用户主页站的域名固定为 `https://<用户名>.github.io`                                                                                        |
| **影响面**         | 仅影响生成的绝对 URL，不影响页面内部相对链接                                                                                                                                     |
| **风险**           | 低                                                                                                                                                                               |

### 改动 2 —— 第 22 行：`baseurl`

```diff
- baseurl: /al-folio # the subpath of your site, e.g. /blog/. Leave blank for root
+ baseurl: # the subpath of your site, e.g. /blog/. Leave blank for root
```

| 项                     | 说明                                                                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **为什么改**           | `baseurl` 是站点在域名下的子路径前缀。上游默认 `/al-folio` 是**项目站**的配置。本站是**用户主页站**，根路径就是 `/`，必须留空                                                         |
| **为什么保留该行**     | al-folio 官方文档明确要求「leave `baseurl` empty (do NOT delete it)」。Jekyll 读不到该键时行为与显式留空不同，删除会出问题                                                            |
| **不改的后果（严重）** | 全站所有 CSS、JS、图片的 URL 都会被加上 `/al-folio` 前缀，例如 `/al-folio/assets/css/main.css`，而实际文件在 `/assets/css/main.css` → **全站样式和脚本 100% 404，页面变成一堆裸文字** |
| **验证**               | 部署后实测首页引用的 12 个资源全部返回 200，零失败                                                                                                                                    |
| **风险**               | 改错风险高，但已验证正确                                                                                                                                                              |

### 改动 3 —— 第 228 行：`exclude` 列表新增一项

```diff
    - docker-compose-slim.yml
+   - dds_custom/
    - docs/
```

| 项           | 说明                                                                                                                                                                             |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **为什么改** | `exclude` 列出 Jekyll 构建时要忽略的路径。`dds_custom/` 是本项目新增的自定义目录，里面是脚本和文档，不是网站内容。不排除的话，Jekyll 会把里面的 `.md` 文档当作页面渲染进最终站点 |
| **插入位置** | 插在 `docs/` 之前，维持该列表原有的字母序（`dds` < `docs`）                                                                                                                      |
| **影响面**   | 仅影响构建时的文件筛选                                                                                                                                                           |
| **风险**     | 极低                                                                                                                                                                             |

### 改动 4 —— 第 219 行：`include` 列表新增一项

```diff
- include: ["_pages"]
+ include: ["_pages", ".nojekyll"]
```

| 项           | 说明                                                                                                                                                                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **为什么改** | Jekyll 默认**不处理**以 `.` 开头的文件（官方文档：「Jekyll doesn't build files or folders that start with `_`, `.`, or `#`」）。新增的 `.nojekyll` 若不显式加入 `include`，就不会被复制进 `_site/`，也就传不到 `gh-pages` 分支，等于白加 |
| **配合关系** | al-folio 的 `_config.yml` 第 243-245 行原本就有 `keep_files: [CNAME, .nojekyll]`，说明上游**预期存在**该文件并保护它不被清理，只是从未真正创建。本改动是补齐上游缺口，而非违背上游设计                                                   |
| **影响面**   | 仅多复制一个 0 字节文件到构建产物                                                                                                                                                                                                        |
| **风险**     | 极低                                                                                                                                                                                                                                     |

## 二、新增文件：仓库根目录 `.nojekyll`

| 项                                  | 说明                                                                                                                                                                                  |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **路径**                            | `<仓库根>/.nojekyll`                                                                                                                                                                  |
| **内容**                            | 空文件（0 字节）                                                                                                                                                                      |
| **为什么加**                        | GitHub Pages 官方文档规定：外部 CI 把构建产物提交到 `gh-pages` 分支时应包含 `.nojekyll`，GitHub 据此识别该分支无需构建步骤，直接部署                                                  |
| **解决的实际问题**                  | 不加时，GitHub 会对已构建好的产物**再跑一遍内置 Jekyll**，把根目录的 `_pages/`（下划线开头）丢弃。实测 `https://dds131.github.io/_pages/dropdown/` 返回 **404**；加上后恢复为 **200** |
| **为什么不能放在 `dds_custom/` 下** | 该文件必须位于**发布站点的根目录**才有效，这是 GitHub 的硬性规则，无法通过目录组织规避                                                                                                |
| **回滚**                            | `bash dds_custom/scripts/03_add_nojekyll.sh --undo`                                                                                                                                   |
