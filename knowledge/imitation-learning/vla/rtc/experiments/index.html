  • RTC 的“更好”必须拆成任务表现、速度、延迟鲁棒性、计算成本与动作连续性，不能压成一个总分。

  • 所有精确数字都要带协议标签；本页不运行实验、不声称已复现，也不给真实机器人推荐参数。

证据地图：三套协议、两条方法路线

三套 suite 先分开，再读数字

E3 · 精确报告值

Original · Kinetix

rtc_original_kinetix_v2；Guided RTC；12 个动态/随机任务。明确曲线点各 2048 rollout，95% Wilson；回答 delay、execution horizon、mask 与 baseline。

不可直接与真机排名。

E3 + E2

Original · Real Robot

rtc_original_real_v2；Guided RTC；6 个 pi0.5 双臂任务。每 task-method-available-condition 10 trial，总计 480 episode、28 小时机器人执行。

包含 throughput、progress、latency 与保护停机。

独立后续研究

Training-Time

rtc_training_time_v2；Kinetix 与 2 个 pi0.6 真机任务。比较训练条件与 inference-time RTC，区分 95%/68% Wilson 和 SEM。

不可与前两卡组成速度榜。

精确值使用 [E3]：论文表格、正文或图注明确给出；可复核算术使用 [E4] 并展示公式；方向趋势使用 [E1]，不从图像像素抄数；作者正文解释或显著性声明使用 [E2]，不升级成本站独立检验。E0 表示未公开/未报告，E5 只留给实际运行且保存完整制品的独立复现——本页没有 E5。

两条路线在 Runtime 后进入同一证据规则

Foundations→Guided / Training-Time→Runtime→Experiments

Guided 栏拥有原始 Kinetix、六项真机、VJP 计算成本、Soft Mask 和 beta；Training-Time 栏拥有追加训练、两项 pi0.6 真机、推理无 VJP 与 delay support。共享层只拥有协议冻结、延迟 scope、统计解释、证据等级与不可外推边界。分栏保留方法身份，共享规则保证同一种数字不会换一套解释。

五类证据对象与六级等级

EvidenceSuite 回答哪些实验可以内部比较；ProtocolManifest 冻结模型、任务、硬件、时序与统计；EvidenceRecord 保存值、趋势或空值；ClaimRecord 限制网页能说多强；ArtifactRecord 定位论文、图、表、代码或数据。任何结果卡只展示 EvidenceRecord，任何解释句都经过 ClaimRecord，任何来源都落到 ArtifactRecord。

空值同样有类型：NR 是未报告，NA 是不适用，NOT_RUNNABLE 是安全/系统条件下未形成合法 trial，NOT_PUBLIC 是依赖未公开栈，NOT_REPRODUCED 是本站没运行，EXCLUDED 必须携带预注册 reason。它们都不是 0，也不能统一显示成一条横线。

等级/码 含义 页面允许写法 禁止升级
E0 / NR 未公开、未报告 “来源未报告” 推测常用默认值
E1 方向性图示 “曲线显示更稳健” 从像素生成精确点
E2 作者声明/解释 “作者报告……” 本站独立确认
E3 精确报告值 值 + unit + protocol + artifact 脱离上下文的大数字
E4 可复核算术 公式 + 输入 + rounding 伪装成论文逐行清单
E5 独立复现 需 reproduction bundle 本页使用
NOT_RUNNABLE 保护/系统条件未形成 trial 事件 + reason + null 补 0 或静默删除

先冻结协议：什么条件下才允许比较

ProtocolCard 在结果之前

每套实验先列 protocol_id、paper/artifact version、环境/机器人、任务和版本、base policy/checkpoint lineage、训练或 fine-tune、observation/action contract、normalization、H/s、控制周期、生成 step、delay kind/value/injection/rounding、硬件/dtype/network/client-server 边界、baseline/candidate/model-call budget、trial/seed/stopping rule、metric/aggregation/interval，以及 missing/safety-censored policy。来源没报告就写 NR，不能从邻近论文补齐。

未来复现还要预注册 primary/secondary endpoint、planned trial count、seed pairing、exclusion、safety abort owner 与 analysis commit。此处只是模板；页面没有创建 trial、连接仿真或机器人。

Comparison gate 是构建规则，不是筛选器猜测

within_protocol 允许协议内强比较；controlled_cross_condition 允许带条件的差异；context_only 只能并列；forbidden 不生成差值、排序或 winner。只有 suite、task/version/success definition、model/checkpoint/data/normalization、control frequency、H/s、delay、I/O contract、robot/simulator、trial/seed/stopping、metric/unit 和计算预算一致或被实验显式控制，才允许写“高于/低于”。

比较 状态 允许表达 原因
同一 Kinetix protocol 的 delay 条件 controlled_cross_condition “在 d>=2 条件下更高” 其余键由协议控制
原始真机同任务/方法/注入 delay controlled_cross_condition “作者报告 throughput 更高” 保留 safety-censored 与 interval
pi0.5 4090 的 97 ms vs pi0.6 H100 的 108 ms forbidden “分别报告” model、GPU、链路、研究均不同
Kinetix solve rate vs 真机 success forbidden 上下文并列 task、metric、trial unit 不同
Hard vs Soft Mask 固定其他设置 within_protocol 条件化方向 只限所测 mask/step/delay

每个精确值的移动端摘要至少显示两行：model · H · control Hz · delay 与 hardware · n · interval · source。前端筛选器只能隐藏/显示记录，不负责放宽 comparison_status；无 JavaScript 时完整表格仍可见。

指标与 interval 不可互换

solve_rate 是 rollout 二元完成；success_rate 是协议定义的 trial 成功；progress 是子步骤数或比例；duration 是 episode 墙钟；throughput 是先逐 episode 计算完成比例/时长再平均；model_latency 和 e2e_latency 边界不同；max_second_difference 只是动作 jerkiness 代理；safety_event 是事件而非待删除缺失。

95% Wilson 与 68% Wilson 都是二元比例区间但置信水平不同；SD 描述调用/样本离散，SEM 描述均值估计尺度；单次 profiling trace 没有总体区间。页面把“±”旁的隐藏说明写成“正负一倍标准差”或“正负一倍标准误”，绝不只靠符号。

原始 RTC 的 Kinetix 仿真设置

original_kinetix_v2_h8 冻结设置

维度 报告设置 证据边界
tasks 10 个已有 + 2 个新建，共 12 个动态/随机任务 不代表全部 VLA 感知与安全难度
dynamics 力控制；动作加入 Gaussian noise 同步等待不能简化成保持位置
experts 每环境 6 个不同 seed 的 RPO expert 论文 v2 设置
dataset episode 随机选 expert，共 100 万 transition 不是 VLA 预训练规模
policy/training 4 层 MLP-Mixer Flow Policy，32 epoch 不是 pi0.5/pi0.6
chunk/delay H=8；d∈{0,1,2,3,4} d 是 tick，不是毫秒
metric binary solve rate 不含 progress/duration
sampling 每明确点 2048 rollout 只绑定相应曲线点
interval 95% Wilson score interval 二元比例区间

2048 rollout 提高该 protocol 下曲线点的比例估计精度，却不会自动变成 2048 个独立环境机制，也不会提高真机证据强度。多任务平均需说明任务权重与先后聚合；公开材料不足时记 NR。训练 expert seed 与 evaluation rollout seed 是否独立也应由未来 manifest 明示。

Paper 与仓库默认值并列

论文 v2 正文是每环境 6 个 expert seed；Kinetix 固定提交 9296f31d62d5bfeb5779dcb2f9bcf71ca37f448b 的 README/脚本默认是 8 个。仓库能运行不等于默认配置等于论文。复现论文必须显式保存实际 seed 数、seed 清单和生成数据的 expert provenance；不能用当前默认覆盖历史 protocol。

该差异只影响复现契约，不推翻论文图。Source Code 页负责文件级映射；实验页记录“若按默认运行，会改变什么证据条件”。本 suite 不能推出真实视觉链路 latency、H=50 的最优 d、多模态动作的统一安全性，也不能推出所有 temporal ensembling 实现都较差。

基线与计算预算：比较的到底是什么

Budget matrix 在趋势之前

baseline_id 交接机制 模型/候选预算 公平性字段 解释边界
naive_async 新块到达即切换 单次 policy 调用 update rate、同 checkpoint 低计算但可模式跳变
te 同一未来时刻多预测加权 历史预测缓存 window/weight/update 多模态平均失效是作者解释
bid 拒绝采样选择连续候选 正文 N=32,K=3；强弱各 32、共 64 块 weak model 8 epoch、并行 batch 不能脱离高候选预算解读
hard_rtc 保证执行硬前缀 在线 VJP d、step、guidance 信号范围较短
soft_rtc 硬前缀 + 衰减重叠 在线 VJP mask schedule、beta 连续性/反应折中
synchronous 等新块完成再执行 等待进入 episode action semantics、hold 不是零成本 oracle

页面同时给 quality-at-reported-budget 和 budget accounting：前者忠实展示论文原设定，后者并列模型调用、候选块、额外训练、VJP 与 GPU latency。没有作者数据或本站复现时，不自造 compute-normalized solve rate。

BID 的两组 N 不能混

Kinetix 正文 baseline 使用 N=32,K=3，强弱模型各生成 32 个块，总候选 64；弱模型训练 8 epoch。附录 Table 1 的 BID 三种实现 115/169/223 ms 使用 N=16，测量条件是 RTX 4090、bfloat16、5 denoising step、5 次 warmup 后 10 calls 平均。它们不是同一设置表的一行，不能把延迟数字贴到正文 N=32 结果旁而省略差异。

“TE 较差”也要限定为：在原始论文 Kinetix 的多模态动态任务和指定实现中，TE 曲线较低；作者解释加权平均可能离开有效动作集合。这不是 TE 的一般失败定理。

延迟、执行跨度与 Figure 5 证据

两个扫描先写固定量

execution-horizon scan 固定 d=1，改变执行跨度，问更频繁闭环更新是否受益；delay scan 固定 s=max(d,1)，改变 d，问性能如何随延迟退化。两张协议卡都要写变化量、固定量、metric、2048 rollout 与 95% Wilson；不能把 d=4 解释成 4 ms。

Delay 有五种 scope

gpu_model 只含模型路径；remote_request_e2e 从客户端请求到返回；robot_pipeline_e2e 还含 resize/scale 等客户端开销；injected_delay 是实验人为等待；discrete_control_delay 是按控制周期离散化的 tick。任何 delay 数字都要有 delay_kind/scope，生成模型内部时间不属于这些 scope。

原始真机：任务、吞吐与端到端延迟

六项任务与 original_real_pi05_v2

任务是点蜡烛、插以太网线、移动铺床、叠衬衫、批量叠衣、移动收餐具；移动铺床与移动收餐具为 mobile task。base policy 为 pi0.5，H=50，20 ms/50 Hz，5 个 denoising step；RTX 4090 server，经有线 LAN WebSocket；mobile client 是 Intel NUC i7-1260P，non-mobile client 是 Ryzen 9 7950X。每 task-method-available-condition 10 trial，子步骤完成时刻事后标注。论文报告总计 480 episode、28 小时纯机器人执行。

Throughput、480 episode 与保护停机

$$ \mathrm{throughput}_i= \frac{\mathrm{completed\ task\ fraction}_i}{\mathrm{episode\ duration}_i}, \qquad \overline{T}=\frac{1}{n}\sum_i \mathrm{throughput}_i. $$

先逐 episode 计算再平均，不能偷换成 sum(completed fraction)/sum(duration)。480 的 E4 算术为 6 tasks × (3 RTC + 3 sync + 1 TE_1 + 1 TE_2) × 10 = 480，解释依赖 available condition，不暗示 TE 高 delay 随机缺失。

作者报告 RTC 在全部注入延迟下平均 throughput 最佳，并称 +100/+200 ms 差异显著；Figure 6 误差为正负 1 SEM。但 test name、p value、effect size/CI 和 multiple-comparison handling 都未公开，因此本站不独立确认显著性。

两种 TE 在高注入延迟因振荡触发保护停机，记 outcome=NOT_RUNNABLE、reason=safety_protective_stop、metric_value=null、imputation=forbidden。显示事件，不补 0、不删点。这证明所测系统发生保护事件，不证明 RTC 获得安全认证。

消融矩阵与条件

factor levels / setup 报告观察 边界

当 n=5 且 beta>=4.25，论文离散评估点中裁剪只影响第一个积分点 tau=0，该点未裁剪系数发散。所测模拟消融中 beta>5 无额外收益，作者采用 beta=5；这不是推荐部署默认值。真机示例提示少步采样配高 beta 可发散。325 个 action chunk 的分析用 d=15,n=5 观察最大二阶差分。

最大二阶差分只刻画离散动作序列局部变化，没有直接测末端误差、接触力、碰撞、关节约束、任务成功或安全层介入。页面称“连续性/jerkiness 代理”，不称“安全分数”。消融只说明固定协议中变量与结果共同变化，不证明 Soft Mask 是唯一原因、增大 beta 必然危险或增加 denoising step 必然改善任务。

Training-Time RTC 的独立证据

Kinetix：delay trade-off，不是全域支配

training_time_kinetix_v2_h8 同样使用 H=8、4 层 MLP-Mixer、基础 32 epoch、明确点 2048 rollout 与 95% Wilson。baseline 与 inference-time RTC 使用正常训练 32 epoch 的同一 checkpoint；training-time 从 epoch 24 恢复并追加 8 epoch，训练 delay 为 {0,1,2,3,4}、概率指数递减。

作者报告在该 protocol 中 Training-Time RTC 于 d>=2 更高，在 d=0/1 略低。这是条件化 trade-off，不是全域支配，也不能与原始论文 Figure 5 的绝对 solve rate 横比。

Delay support discrepancy

正文称训练 delay 在 50 Hz 下均匀采样 0–10、最多 200 ms；Algorithm 1 的整数随机接口看起来采用高端开区间 [0,max_delay)。页面并列两种文本，不替作者选择 0–9 或 0–10。复现要求打印/保存实际 sampled support histogram，并由 Source Code 页核对固定提交。

Training-Time 去掉推理期 VJP，解释架构成本差异；但 hard prefix 缺少 Guided 对远端 overlap 的 soft conditioning 灵活性，训练 support 也必须覆盖部署 delay distribution。效果接近、成本较低和连续性能力是三个不同 claim。
