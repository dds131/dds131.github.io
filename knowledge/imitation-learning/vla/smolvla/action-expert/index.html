动作专家（action expert）是把图像、语言和机器人状态形成的条件表征，连同含噪动作与 Flow 时刻，映射为动作速度场的 Transformer。SmolVLA 在专家层间交错使用两种注意力：默认配置下，每个动作专家层的动作 Query 都能读取观测条件；其中联合自注意力层还允许动作 token 按因果方向相互读取，cross-attention 层则不提供动作—动作通路。

本页只讲动作专家的结构层面。它生成动作所依据的数学见③ Flow Matching 与损失，条件特征如何产生见① 主干与多模态 token。

复核基线。论文结论按 arXiv v1（2506.01844v1）核对；实现细节按 LeRobot 提交 8c920c4、公开 lerobot/smolvla_base 配置修订 d9f33c9 与主干 SmolVLM2-500M-Video-Instruct@7b375e1 核对，日期为 2026-10-05。后续源码可能改变默认值或执行路径，因此本页涉及“固定实现”的判断均限定在这组版本。

0.75 × d隐藏维（相对主干）
16层数（与主干使用层数相同）
约 100M参数量
50动作块长度

一、两种注意力层到底差在哪里

先区分两类层的可见信息。这里的 prefix 包含图像 token、语言 token 和投影后的机器人状态 token；动作后缀则把每个位置的含噪动作与该样本共享的 Flow 时刻编码融合成一个 token。

层类型 动作 Query 可以读取的 K/V 直接能力与边界
cross-attention 本层对应的 prefix K/V 逐位置读取观测条件；动作 token 之间没有直接注意力通路
因果联合自注意力 prefix K/V + 自身及此前动作 token 的 K/V 继续读取条件，同时显式建模因果方向的动作—动作依赖
交错（SmolVLA 默认配置） 偶数层使用联合层，奇数层使用 cross-attention 每个专家层只执行一种注意力；动作 Query 始终条件化，联合层再加入动作内部通信

论文把这种设计与仅使用自注意力或仅使用交叉注意力的动作专家比较，并强调每个专家块只包含其中一种注意力。论文所对照的是带显式 SA 与 CA 子层的多模态解码器结构；不能把“每个标准 VLM 块都同时包含 SA 和 CA”推广到所有 VLM，SmolVLM2 的语言解码器就是 decoder-only 自注意力模型。

二、交错结构解决什么问题

交错结构的准确理解是：每个动作专家层都保留条件通路，动作内部通路则周期性开放。

条件每层都可读 一次动作块采样期间，图像、语言和状态组成的 prefix 不变，并在启用缓存的推理预填充阶段写入逐层 KV 缓存。动作 Query 在两类专家层中都会读取与当前专家层相配的 prefix K/V；不能把它理解为“条件只注入一半层”。

联合层增加直接动作通信 联合层让第 \(i\) 个动作 token 除了读取 prefix，还能读取自身和此前动作 token。它为块内依赖提供显式通路，但不是动作连贯性的唯一来源：纯 CA 消融仍有竞争力，说明共享条件、动作位置和逐位置去噪也能形成有效动作块。

默认 16 层专家执行 8 个联合层与 8 个 cross 层，每个专家层仍执行一次注意力。若与“每个专家块同时堆叠 SA 与 CA”的架构作计数比较，交错会减少专家侧注意力子层；这不是 Table 6 直接测得的加速结论。整体参数量和计算量还包含主干计算、MLP、投影与缓存访问，不能简化成严格的“减半”。交错在论文该次消融中数值优于两种单一路线，具体机理仍需与假说区分。

论文正文还称交错设计带来更快推理，并称自注意力使动作块更平滑、在真实机器人上尤其明显；但论文没有给出注意力变体的延迟表、FLOPs、轨迹平滑度定义或对应数值。因此这两项应标为作者的定性观察，不能由 Table 6 的成功率直接推出。

三、源码里的实际排布

3.1 分派规则

交错由配置项 self_attn_every_n_layers = 2 控制。smolvlm_with_expert.py 的分派条件是：层号对该值取模为 0 时走联合自注意力，否则走 cross-attention。

因此实际排布是：

层号 类型 去噪时动作 Query 在这一层能读到什么
0 联合自注意力 本层 prefix K/V，以及自身和此前动作 token 的 K/V
1 cross-attention 本层 prefix K/V；不读取其他动作 token
2 联合自注意力 同层 0
3 cross-attention 同层 1
… 以 2 为周期交替  

也就是「联合、cross、联合、cross」，第 0 层是联合自注意力。

3.2 层序与训练、推理两条执行路径

论文 Figure 1 的示意图不能直接当作层序依据。该图没有标明纵向顺序与代码层号的对应方向，而且用省略号隐藏了中间层。默认实现的实际顺序应以取模分派条件为准：第 0 层联合、第 1 层 cross，随后交替。

训练与推理使用同一组权重和掩码语义，但计算路径不同：

阶段 prefix 如何处理 动作侧如何处理
训练 use_cache=False，prefix 在各层正常前向 联合层计算 prefix 与动作两侧；cross 层让动作 Query 读取 prefix K/V
推理预填充 只运行一次 prefix，每层缓存 K/V（K 已做 RoPE） 此时尚未输入动作后缀
每个去噪步 不重算 prefix，直接读取逐层缓存 联合层追加当前动作 K/V；cross 层只读 prefix；两类层都只更新动作隐藏态
去噪步结束后 保留原 prefix 缓存 裁掉本步临时追加的动作 K/V，下一步根据新 \(x_t\) 重新计算

因此，“联合自注意力”描述的是动作 Query 的可见集合，不意味着推理时把 prefix token 再跑一遍。公开 checkpoint 保存 use_cache=True，10 步去噪会复用同一份观测条件。

use_cache=False 不是已经实现好的无缓存推理回退。训练阶段把 use_cache=False 与同时传入的 [prefix, suffix] 配合使用，因此可以正常计算；推理阶段却先单独传入 [prefix, None]，随后每个去噪步只传 [None, suffix]。在固定源码中若把配置改成 False，预填充不会产生 K/V 缓存，cross 层随后仍会尝试从缺失的 prefix 或缓存取条件并解引用空输入。实现没有“每个去噪步重算 prefix”的替代分支。故该开关在标准推理路径中实际是条件传播所必需的，不能把它当成只影响速度的普通优化选项；若要关闭，必须先实现并测试完整前向回退。

3.3 实现上如何区分两类层

两类层的差别在 Key 与 Value 从哪里来，以及动作专家的 k_proj、v_proj 接收多宽的输入。先把三个宽度定下来（完整维度表见本页第六节）：主干隐藏维 960，动作专家隐藏维 720，而逐层缓存的键值宽度是 num_key_value_heads × head_dim = 5 × 64 = 320。

动作侧路径 联合自注意力层 cross-attention 层
动作 Query 专家隐藏态 720，经投影得到 15 × 64 同左
条件 Key / Value 本层缓存的 prefix K/V 同一份缓存 K/V，再经专家的 320 → 320 投影
动作 Key / Value 专家隐藏态 720 → 5 × 64，按因果掩码参与 不生成、不参与
专家 k_proj / v_proj 的输入维度 720 320，不是主干隐藏维 960
构造时是否改写 否，保持专家标准投影 是，替换为 320 → 320 线性层

smolvlm_with_expert.py 在构造时遍历动作专家的各层：层号对 2 取模为 0 的直接跳过不改；其余层把 self_attn.k_proj 与 self_attn.v_proj 替换成新的线性层，其输入与输出维度都写作 num_key_value_heads × head_dim。

固定实现为什么替换投影，以及为什么输入维不是 960。动作专家默认的 k_proj 是「专家隐藏维到键值宽度」，即 720 到 320，因为它本来要投影专家自己的隐藏状态。cross-attention 路径复用的是主干已经投影并缓存的 K 与 V——它们早已经过主干的 k_proj 与 v_proj，宽度是 320 而非 960，因此这里把专家的两个投影替换为 320 到 320。源码注释是 k_proj should have same dim as kv。这是一种缓存接口设计，并非 cross-attention 在数学上只能接收 320 维输入；若改为缓存或传入 960 维主干隐藏态，也可以另设 960 → 320 投影。

若只比较启用缓存后的一个去噪步，设有效或补齐后的 prefix 张量长度为 \(P\)、动作长度为 \(H\)、查询头数为 \(h=15\)，固定源码构造的密集注意力分数张量大小为

\[M_{\mathrm{CA}}=BhHP, \qquad M_{\mathrm{SA}}=BhH(P+H).\]

因此联合 SA 相比 CA 多出 \(BhH^2\) 个分数位置。因果掩码只允许动作侧约 \(H(H+1)/2\) 个位置有效，但固定的 eager 实现仍先计算完整 \(H\times H\) 分数矩阵再屏蔽。这个推导只覆盖注意力打分：CA 每步还会对缓存的 \(P\) 个 K/V 做两次 320→320 投影，联合层则为 \(H\) 个动作 token 生成 720→320 的 K/V；两类层都还有 Query、输出投影和 MLP。故“cross 更轻”有结构依据，但不能由 \(H^2\) 一项推成端到端加速倍数。

3.4 默认 16↔16 配置：条件是逐层键值，不是单个末层输出

这一点决定了整张结构图该怎么画，也是 SmolVLA 与「把视觉语言模型末层特征送进一个解码器」这类做法的实质区别。

在标准配置中，主干实际使用 16 层，动作专家也有 16 层。预填充阶段主干每一层都会把本层键值写进缓存（K 已施加旋转位置编码，V 未旋转）；去噪阶段动作专家第 \(i\) 层读取缓存中同号第 \(i\) 层的主干键值。两类专家层都是如此，区别只在于联合层还会把动作 token 自己的键值临时追加后参与注意力，而 cross-attention 层只使用主干那一份。

因此标准配置的条件侧不是一个「主干末层输出后再接专家」的单一张量，而是 16 份按层号对齐、内容不同的 K/V。它说明专家与主干在深度方向逐层耦合；至于各层分别偏向局部结构还是高层语义，本文没有直接证据，不在这里作确定判断。

源码还提供 num_expert_layers，意图是在专家层数少于主干层数时按间隔映射。若记 \(m=L_{\mathrm{VLM}}/L_{\mathrm{expert}}\)，专家第 \(j\) 层会挂到主干第 \(jm\) 层；源码同时要求两个层数整除。但在本页固定提交中，这条非默认路径与交错注意力的索引规则并未对齐，不能据此认定“减少层数”可直接安全使用。

论文与源码的表述粒度不同，但不足以判定为架构冲突。论文架构段先写动作专家可以访问“截至第 \(N\) 层的全部特征”（has access to all features up to a specified layer N），损失段又用“第 \(N\) 层的 VLM 特征”概括条件变量。LeRobot 源码把这个接口具体实现为逐层 K/V 缓存和同层读取，与论文前一种描述相容；损失式没有展开缓存细节。

这里必须区分两种“时间”：RoPE 的 token 位置区分动作块中的第几步；Flow 时刻 \(t\) 表示当前噪声水平，在同一个样本的 50 个动作 token 上相同。两类注意力层的 RoPE 坐标还有一个实现差异：联合层把动作位置接在该样本有效 prefix 位置之后；cross 层只对动作 Query 施加 RoPE，并把它们重新平移为从 0 开始。这个差异不会改变因果掩码的可见关系。训练外层还会裁掉补齐的动作维，并用 episode padding mask 排除越过轨迹末尾的动作位置。

四、交错真的更好吗：论文数据

先限定实验口径。本页 Table 6、7、9 都来自论文第 4.7 节的 LIBERO 消融。论文说明，除非另有注明，这些模型从零开始训练、没有机器人数据预训练，VLM 主干冻结，只训练动作专家；表中也没有多随机种子的方差。因此这些结果用于比较设计变量，不等同于完整预训练后发布检查点的总体评测。

  1. 交错在该次实验中数值最高。 85.5 相对更好的单一方案高 6.5 个百分点，相对纯 SA 高 11 个百分点；这与两种通路互补的解释一致，但论文没有报告多随机种子的方差，不能据此证明稳定优势或唯一机理。
  2. Long 一档差距最大。 Long 从纯 CA 的 54、纯 SA 的 40 提升到 67。四种套件的单次动作块长度都相同，不能把差距解释成“Long 的块更长”；更可能涉及误差在长任务中的累积，但仍需专门实验验证。

4.1 一个反直觉现象：没有直接动作注意力，成绩仍更好

在纯 CA 设置下，动作 token 彼此没有直接注意力，但仍共享逐层条件、网络参数和位置结构，并分别接收自己的含噪动作输入。它得到 79.0，高于提供因果动作通信的纯 SA（74.5）。

论文的稳妥结论是：无直接动作交互的 CA 设置仍具有竞争力，说明逐位置地依据 VLM 条件去噪已经可以形成较强基线。

下面两种解释都与数据相容，但属于待验证假说：

  • 共享条件与位置结构可能已足够强。 每个动作位置都有独立的 RoPE 位置、自己的含噪值，并读取相同观测条件；即使没有直接动作注意力，逐位置速度场也可能形成连贯块。
  • 注意力竞争可能影响纯 SA。 联合层需要在 prefix 与此前动作之间分配注意力，而纯 CA 把全部 Key/Value 都留给条件；这可能影响条件读取，但论文没有给出注意力统计来证实。

纯 CA 的形式边界也必须说明：第 \(i\) 个速度预测只能依赖共享条件、位置编码和自己的含噪动作，不能通过注意力显式读取其他动作位置。共享参数与位置可以产生结构化轨迹，但这不等价于显式建模给定条件后的跨时间残差或随机相关性。

因此这组实验能确认的是：在该 LIBERO 消融设置中，没有直接动作注意力的纯 CA 仍形成了有效基线，而加入交错通路时数值最高。 至于这一结论能否推广到其他任务，以及收益来自平滑性、条件分配还是优化性质，仅凭 Table 6 不能判定。

五、因果掩码：动作 token 之间怎么看

5.1 构造方式

embed_suffix 为动作 token 生成掩码标志时执行 att_masks += [1] * chunk_size，即每个动作 token 各自开一个块。配合累加和构造出的二维掩码，其效果是第 \(i\) 个动作 token 看不到位置在它之后的动作 token。

这与 π0 让动作 token 块内全可见的做法不同——π0 为整个动作块只开一个块，块内双向可见。

5.2 论文的 SA-only 掩码消融

Table 7 固定使用纯自注意力（SA-only）动作专家，只比较动作 token 采用因果还是双向掩码。其中因果行 74.5 与 Table 6 的纯 SA 基线相同；这张表支持“因果掩码在 SA-only 设置中更好”，不能直接外推为默认交错模型也会获得同样的 7 点增益。

动作 token 之间的掩码 Spatial Object Goal Long 平均
双向（bidirectional） 79 86 82 23 67.5
因果（causal，采用） 80 94 84 40 74.5

在这个 SA-only 消融中，平均分相差 7 个百分点，Long 相差 17 个百分点。论文把这一结果概括为因果掩码避免未来动作依赖。

5.3 一个必须澄清的常见误读

关于这条消融，流传较广的解释是「训练时 \(a_t\) 能看到 \(a_{t+1}\)，而部署时未来动作还不存在，于是造成训练与推理的不匹配」。

这个解释在 SmolVLA 上不成立。 原因很直接：SmolVLA 用 Flow Matching 一次性生成整个动作块，推理时 50 个动作位置的 token 是同时存在、同时被去噪的。双向注意力在推理期同样可用，不存在「未来动作不存在」这回事。如果只是训练与推理的可见性不一致，那么把双向掩码同时用在训练和推理上就不会有任何 mismatch，而消融显示双向本身就更差。

对这组 SA-only 消融，一种与数据相容、但尚未被论文验证的解释是相关性捷径：

先固定时间约定。LeRobot 当前实现使用

\[x_t=t\epsilon+(1-t)A,\qquad u_t=\epsilon-A,\]

其中 \(t=0\) 是真实动作端，\(t=1\) 是纯噪声端；推理从 1 向 0 做负步长 Euler 积分。论文正文把插值写成 \(A^\tau=\tau A+(1-\tau)\epsilon\)，方向相反。令 \(\tau=1-t\) 后，两种插值的位置可以对应，但速度场符号和积分方向也必须同时转换：\(\mathrm{d}x/\mathrm{d}\tau=A-\epsilon=-u_t\)。本节后续统一采用 LeRobot 的 \(t\) 约定。

在双向注意力下，第 \(i\) 个动作 token 可以读取块内所有其他含噪动作。当 \(t\) 较小时，\(x_t\) 保留较多真实动作成分，而相邻动作通常相关；模型可能利用邻居估计当前速度场，弱化对观测条件的依赖。到推理早期 \(t\approx1\) 时，所有位置接近纯噪声，这种相关性线索会减弱。

因果掩码删除了“后面动作位置 → 前面动作位置”的通路，但仍允许读取自身和此前的含噪动作，所以不能量化成“堵住一半捷径”。它约束的是并行潜在动作表示的信息方向，不表示此前 token 已经由机器人真实执行，也不构成物理因果性的证明。

LIBERO-Long 需要更长的任务执行过程，但这里各套件的单个动作块仍都含 50 个动作位置。Long 差距最大可能与局部误差跨多个动作块累积有关，不能据此推出其「块内序列更长」或「相关性捷径更强」。

证据边界：论文只报告了因果配置优于双向配置，并以「避免未来动作依赖」概括原因，没有验证上述捷径机理。后续可比较两种掩码在不同 \(t\) 区间的条件消融、损失和观测敏感度；仅看总训练损失不足以确认模型是否依赖观测。

六、宽度：为什么取主干的 0.75 倍

6.1 取值与实现

配置项 expert_width_multiplier = 0.75，动作专家的隐藏维按主干隐藏维乘 0.75 取整，前馈中间维随之重算。层数由 num_expert_layers 控制：配置类的代码默认值是 −1，公开 smolvla_base 配置保存的是 0；当前实现对两者都按“非正数”处理，最终都建立与主干实际使用层数相同的 16 层专家。正数才请求更少层数，但第 3.4 节所述的索引与投影不一致意味着该路径不能未经修正与测试就启用。参数量方面，论文第 4.3 节与官方博客给出的口径一致：主模型总计约 450M，其中约 100M 属于动作专家（论文原文 Our main model, contains 450 million parameters, with approximately 100 million dedicated to the action expert）。

把相对倍率换算成绝对数值，需要主干 HuggingFaceTB/SmolVLM2-500M-Video-Instruct 的配置。下表左列取自该模型卡的 config.json，右列按源码的构造式算出：

维度项 主干文本塔 动作专家 来源
隐藏维 960 720 960 × 0.75 取整
前馈中间维 2560 2048 按源码的中间维公式重算，不是 2560 × 0.75
层数 32 层，SmolVLA 只用前 16 层 16 与主干实际使用层数相同
注意力头数 15 15 配置被整体复制，未随宽度缩放
键值头数 5 5 同上
每头维度 64 64 同上

两处容易忽略的推论：

  1. 前馈中间维不是按 0.75 线性缩下来的。 源码对专家的中间维单独重算：先取隐藏维的三分之二，再乘 4，最后向上取整到 256 的倍数，即 720 → 480 → 1920 → 2048。若按 2560 × 0.75 = 1920 去理解，会差一个取整档位。
  2. 注意力头的配置没有跟着变窄。 专家隐藏维是 720，但仍是 15 个查询头、5 个键值头、每头 64 维，于是 q_proj 是 720 到 15 × 64 = 960，o_proj 再从 960 回到 720。换句话说，「窄」只体现在残差流的宽度与前馈上，注意力内部的工作维度与主干一致。这也解释了上一节的一个细节：专家与主干的键值宽度都是 5 × 64 = 320，两者才能在自注意力层里直接拼接。

两个默认值属于不同入口。低层 SmolVLMWithExpertModel 构造函数默认 expert_width_multiplier = 0.5，标准 SmolVLAPolicy 路径则会从 SmolVLAConfig 显式传入 0.75。因此分析标准配置时应以最终配置对象为准；没有版本历史证据时，不把低层默认值定性为「陈旧残留」。

6.2 缩窄宽度实际节省什么

标准 Transformer 常用「参数量近似随隐藏维平方增长」作粗略估算，但 SmolVLA 的动作专家不是所有维度都按倍率同步缩放：残差流从 960 缩到 720，前馈中间维重算为 2048；查询投影仍输出 15 × 64，输出投影再回到 720；cross-attention 的键值投影则保持 320 → 320。因此，0.75 倍会减少残差流、前馈层和部分投影的参数与计算，但不能直接套用 \(0.75^2\) 得到整个专家的精确节省比例。

保留 16 层、缩窄宽度是 SmolVLA 的实际设计选择，使每个专家层都能与对应的主干层交互。论文没有给出「等参数减层」对照，所以不能进一步断言深度一定比宽度重要。默认配置的 10 个去噪步都会调用动作专家，专家效率确实会反复影响计算量；但在没有端到端 profiling 的情况下，也不应把它定性为系统延迟的唯一或主要瓶颈。

6.3 论文数据与正文之间的一处张力

专家宽度（相对主干） Spatial Object Goal Long 平均
×1.00 87 96 90 56 82.3
×0.75（LeRobot 默认） 82 89 84 55 77.5
×0.50 89 94 85 53 80.3

论文正文对这张表的表述是：把专家隐藏维降到 0.75 × d 在性能与效率之间取得了良好平衡，并在表注中写「更大的容量带来更好的成功率」。

这两点都与表中数值存在张力：

  1. 该列不是单调的。×0.75 得 77.5，反而低于 ×0.50 的 80.3，相差 2.8 个百分点。「更大容量更好」这一表注在 0.75 与 0.50 之间不成立。
  2. ×0.50 在这次表格结果中高于 ×0.75；按照当前层的具体维度，它也会进一步减少专家参数。但论文没有报告各变体的精确参数量、吞吐量或延迟，因此仅凭成功率不能判断哪个是更优的系统折中点。

本页不替论文调和这处不一致，只如实并列，并指出两条读表时应当注意的限定：

  • ×0.50 这一行的四个分项和平均值（89 / 94 / 85 / 53 / 80.3）与论文其余多张消融表的基线行完全相同，与复用共同基线的情形一致；但论文没有明确说明这些表是否复用同一检查点、训练运行或随机种子，不能仅凭数字相同确认。
  • 论文没有为这组消融报告多随机种子的均值和方差。因此可以确认表内排序非单调，却不能判断 0.75 与 0.50 的差异是否稳定复现。

因此稳妥的读法是：在这次实验中，×0.25 的平均分最低，×0.50、×0.75 与 ×1.00 的排序并不随宽度单调变化；至于 0.75 与 0.50 孰优、0.25 为何下降，这张表都不足以给出稳定或机制性的结论。

不要把结果改写成机理。Table 9 只显示 ×0.25 在这次运行中得分较低，并未测量「信息承载不足」或「动作平均化」；论文也没有把缩宽度与等参数减层直接比较。这些都应作为待验证假设，而不是已证实结论。

七、重点、创新点与证据边界

方法贡献 SmolVLA 在条件 Flow Matching 动作专家中交错使用 cross-attention 与因果联合自注意力：标准配置中，每个动作专家层都读取视觉、语言与状态条件，联合层再加入动作 token 之间的有向通信。Table 6 中二者组合的单次汇总数值高于只保留其中一种，但没有多随机种子方差。

效率设计 标准配置只取主干前 16 层，专家残差宽度为主干的 0.75，并在启用缓存的推理中复用前缀 K/V。截层和缩宽降低单次前向计算，KV cache 则避免重复计算 prefix；单独的 0.75 宽度消融不能证明这是唯一最优配置。

实现落点 LeRobot 用逐层前缀 K/V、320 → 320 的 cross-attention 键值投影，以及每次去噪后裁掉临时动作 K/V 来实现缓存复用。这是当前实现的工程细节，不应全部等同于论文独有创新。

继承的通用组件 Flow Matching 动作生成路线来自既有 VLA 工作；因果掩码、RoPE、KV cache 与宽度缩放也都是通用技术。SmolVLA 的特色在于围绕小模型与机器人推理预算对这些组件的组合和取舍。

证据与实现边界 消融表给出单组汇总成绩，没有多种子方差、注意力变体延迟、轨迹平滑度、等参数深度对照或机制诊断。「双向注意力形成相关性捷径」「Long 上误差跨块累积」都是解释性假设；固定源码的 use_cache=False 推理没有完整回退，减层路径也存在索引与投影形状不一致，不能把配置项存在等同于相应组合已经验证可用。

归纳起来：标准 16↔16 配置中的每个动作专家层都读取前缀条件；训练与启用缓存的推理是两条不同执行路径；因果掩码约束的是潜在动作 token 的信息流，而非已执行动作的物理时间；0.75 倍宽度是论文与标准配置选定的工程折中，现有消融不足以证明它稳定优于 0.50；减少专家层数则需要先修正并验证当前实现。
