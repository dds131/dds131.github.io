04A · ONLINE RL SYSTEM

冻结 3.35B π0.5，只让小型 Actor-Critic 在参考动作附近在线学习

这页回答“系统为什么这样设计、张量怎样流动、每个损失在约束什么”。重点不是把 RLT 包装成成功案例，而是把表征、动作、控制、Replay 和训练边界讲清楚。

一、30 秒定位

从已有 π0.5 step 40000 检查点出发，先冻结 VLA，把三路图像位置的 768 个 2048 维 prefix hidden tokens 压成一个 2048 维 RL Token；再冻结 VLA 与 RL-Token encoder，只训练约 230 万参数的 Actor 和 Twin Critic。Actor 同时读取 RL Token、八维机器人状态和 VLA 的 50×8 reference，输出完整 10×8 候选动作块。真机执行、人类接管、Replay 和 Learner 形成在线闭环。

一句话贡献：项目把“冻结大模型感知与动作先验、小网络在线修正、人在回路纠错”落到 RM75 的三相机和七关节加夹爪系统中，并为冻结、动作语义、训练调度和硬件写权限分别建立了可核查证据。
两页怎样分工：本页只讲系统与算法契约；下篇详细讲训练命令、参数、现场视频、E-2/F/G/L4 实验、工程修复和负结果。这样避免在一个超长页面里把机制与结果混写。

二、先把三阶段的责任分开

① π0.5 基座使用既有三相机 SFT checkpoint 和动作平滑链，提供任务先验、norm stats 与 50×8 reference。
② RL Token冻结 π0.5，用 encoder/decoder 学习 hidden-token 信息瓶颈；在线阶段只使用 encoder。
③ 离线 Actor-Critic由 E-2 Replay 预训练小策略和 Twin Critic，并在整形前做原始动作准入。
④ 在线 L4.2真机 rollout 与人类纠正继续写 Replay；Learner 按更新预算发布带版本号的 Actor。

图：上游通过不等于下游有效。每阶段的训练对象、冻结对象、输入输出和验收指标都不同。

阶段 读取什么 更新什么 冻结什么 输出与本阶段证据
π0.5 SFT 1,393 episodes、三相机、8 维 state/action 3.35B VLA 全参数 无 step 40000、norm stats、50×8 reference；只证明前置基座具备既有任务能力
RL Token VLA prefix hidden states，形状 768×2048 encoder + decoder，约 2.4 亿参数 π0.5 2048 维 $z_{rl}$；MSE 和冻结审计只证明表征训练完成

为什么不能把三个“成功”混成一个

  • π0.5 的既有 92% 来自另一条成熟 run_smooth 链，本轮没有重建完整 trial 口径，不能当 RLT 的正式零接管基线。
  • RL Token 的 MSE 0.1628 是训练批次重建误差，不是任务成功率，也没有单独 held-out MSE。
  • Critic loss 稳定、UTD 对齐只能说明在线优化链没有明显静默失效，不能证明 Q 排序正确。
  • 只有同执行链、统一终止条件、零接管的真机 A/B 才能回答 RLT 是否改善任务。

三、基座动作契约：先回答模型到底在预测什么

项 本项目真实口径 容易讲错的地方
图像 头部、腕部、第三视角，均为 224×224 三路 shape 相同不代表物理身份可以互换
state 7 个实测关节角 + 连续夹爪开口，共 8 维 夹爪测量值不是离散夹爪命令
action 前 7 维关节 delta + 第 8 维绝对夹爪指令 不能把夹爪也做 delta
模型 action_dim 32，真机只使用前 8 维 32 是张量预留，不是 32 自由度
VLA horizon 50 步 是预测长度，不是 Actor 一次执行 50 步
Actor horizon 10 步 是完整候选块，不是显式 residual

对观测时刻 $t$，第 $k$ 个未来目标的训练表征为

$$ \Delta q_{t+k,j}=q^{cmd}_{t+k,j}-q_{t,j},\quad j=1,\ldots,7; \qquad g_{t+k}=g^{cmd}_{t+k}. $$

七个关节 delta 都相对同一个观测锚点 $q_t$，不是相邻预测步之间的差分；夹爪保持绝对命令。训练数据、Replay、Actor 输出、反归一化和动作安全闸必须沿用同一语义，否则网络可以数值正常但物理动作完全错误。

三个时间尺度不能混用

时钟 项目记录 决定什么 不等于什么
控制端内环 110 Hz，约 9.1 ms/拍 唯一硬件发送、平滑、安全状态机与 VR 仲裁 不是策略动作频率
Rollout 动作步 10.5 Hz step 级观测、执行动作和 reward 对齐 不是相机或控制内环频率
Actor chunk 10 步 一个 transition 的执行 horizon 名义 0.952 s；实测约 1.03 s，不能只按除法代替测量
VLA reference 50 步 Actor 的条件先验长度 不是一次开环执行时长

对 2–4 mm 入槽任务，约 1 秒才做一次块级重新观测会限制末段修正速度；这是量化瓶颈，不是已经完成单变量 A/B 的唯一根因。

推理、学习与执行的量化边界

下列数字来自四种不同证据：已加载模型的内存探针、L2 真服务验收、在线训练 metrics，以及控制端状态日志。面试时必须先说清测量边界，再比较数字。

链路 样本与结果 实际含义 不能怎样解释
基础 VLA 内存探针 60 次；min / p50 / p95 / max = 101.0 / 103.7 / 106.4 / 108.3 ms 已加载模型的一次 VLA 推理 不含相机、跨进程网络和机械臂通信
L2 冻结特征服务 12 次；142.2 / 142.5 / 142.8 / 142.8 ms 返回 RL Token、proprio 与 50×8 reference 的一次请求 不是相机曝光到物理命令的端到端延迟
Actor 资源修复 A/B wait_ms 273.3 → 36.4 ms 同一次工程 A/B 的等待汇总 原始样本不足，不能补写 p50/p95/p99
在线 Learner 连续更新间隔均值 12.62 ms；约 79.24 update/s Replay 消化能力 不是 rollout、推理或控制频率
动作块执行 10.5 action-step/s；10 步名义 0.952 s、实测约 1.03 s Actor chunk 的执行 horizon 不是 Actor 神经网络耗时，也不是关节角速度
控制端 配置 110 Hz；日志约 109.05 row/s 目标插值、限速、状态机与下发节拍 日志行频率不是经过调度器定义的 deadline 达标率

因此不能把 142.5 ms、1.03 s 和 9.2 ms 相加成一个“端到端延迟”：它们既不是同一请求，也不共享 trace id，Learner 还与控制端并行运行。

动作块怎样变成 110 Hz 连续命令

当前执行链不是把 10 个 waypoint 在 110 Hz 下逐点硬切换，而是

完整顺序：VLA / Actor 动作块 → 时间插值 → chunk 安全过滤 → 110 Hz 命令过滤 → 单帧 IK / 碰撞约束 → 唯一控制端下发。

时间索引为

$$ i(t)=(t-t_0)\times30\times0.35=(t-t_0)\times10.5. $$
参数 当前值 作用
fps 30 reference waypoint 的基础时间尺度
speed_scale 0.35 把动作时间尺度降到 10.5 action-step/s
Actor chunk 10 步 名义执行 horizon 为 0.952 s
控制内环 110 Hz 在相邻关节 waypoint 之间持续采样并下发

七个关节取 $i(t)$ 左右相邻 waypoint，并按小数部分做线性插值；超过块尾后保持最后一个目标。夹爪不做连续线性插值，而是选最近 waypoint，再量化到 {0, 0.5, 1}，避免产生训练语义之外的中间开度命令。

安全过滤、低通与软限位不是同一个机制

候选 chunk 先按固定顺序处理：非有限值替换 → 相邻关节每步最大 10° → 首点距当前姿态最大 10° → 机械臂软限位 → 全块复验 → 夹爪三档量化。RM75 原始关节范围为 [-178,-130,-178,-135,-178,-128,-360]° 到 [178,130,178,135,178,128,360]°，软件再向内收 5°，并约束第四关节绝对值不小于 10°。若复验仍失败，整块保持当前姿态，不把新旧轨迹局部拼接。

命令过滤参数 当前值 具体责任
输入低通 alpha 0.30 抑制上游目标高频变化
命令 EMA alpha 0.25 平滑最终下发目标
关节速度上限 144 °/s 对整个位移向量同比例缩放，保留方向
关节加速度上限 1,000 °/s² 同比例限制速度增量
软限位减速区 15° 靠近边界时逐步降低允许速度
目标制动减速度 700 °/s² 由剩余距离计算可停止速度
软停止目标时长 0.25 s 解析减速轨迹参数，不是实测停止时间
直接冻结阈值 3 °/s 低速时跳过减速轨迹，直接保持

输入低通、命令 EMA、靠近软限位的制动和人工接管触发的软停止是四种不同机制；把它们统称为“做了平滑”会掩盖各自的触发条件与安全责任。

IK、碰撞约束与预热预算

当前 IK 首次编译记录为 3.60 s，热路径单次求解约 3.7 ms；模型启用 18 对自碰撞对、4 项 cost 和 2 项不等式约束。首次编译必须在实时控制前预热，否则 3.60 s 暂停会破坏控制时序。3.7 ms 只覆盖 IK 热路径，不包含 VLA、相机、网络或机械臂通信。

四、RL Token：压缩的不是原始图像 patch

训练入口以 image_only=True 选择三路图像对应的位置：每路 256 个，共 768 个。这些位置已经经过 PaliGemma prefix 主干的最终层处理，并非原始 ViT patch；由于 prefix 使用双向 attention，图像位置还可能混入语言与状态上下文。

$$ H\in\mathbb R^{B\times768\times2048},\qquad \bar H=\operatorname{sg}(H),\qquad z_{rl}=E_\phi(\bar H)\in\mathbb R^{B\times1\times2048}. $$

本项目 decoder 从 768 个可学习位置查询开始，每个查询 cross-attend 到单个 $z_{rl}$，调用时 mask=None、causal=False，因此实际目标是全位置、全维度的并行重建：

$$ \widehat H=D_\phi(z_{rl}),\qquad \mathcal L_{RLT} =\frac{\lVert\widehat H-\bar H\rVert_F^2}{B\cdot768\cdot2048}. $$
对比 论文式（2） 本项目实现 面试时准确说法
Decoder 条件 RL token + 此前真实 embeddings RL token + 768 个可学习查询 工程近似，不声称逐项等价
重建顺序 teacher-forcing 式自回归 非因果并行重建 当前实现是全元素 MSE
在线使用 RL Token 表征 只保留 encoder 输出 decoder 不进入真机请求路径

项 本次记录 作用 / 边界

五、Actor 并不是显式 residual policy

冻结特征服务返回 $z_{rl}[2048]$ 与 reference[50,8]。Actor 还读取八维 proprio，直接输出完整 action_chunk[10,8]：

$$ a^\theta_{1:10} =\pi_\theta\!\left(z_{rl},s^p,\widetilde a^{VLA}_{1:50}\right). $$

“围绕 reference 做局部编辑”描述的是条件输入与损失约束，不是把一个 residual 显式相加到 reference。运行时安全整形也不能倒推 Actor 原始输出已经安全。

BASE、HUMAN、MIXED 怎样进入 BC 目标

对 chunk 内第 $k$ 步：

$$ m_{t,k}=\mathbb 1[source_{t,k}\in\{HUMAN,MIXED\}], \qquad a^{BC}_{t,k}= \begin{cases} a^{exec}_{t,k}, & m_{t,k}=1,\\ \widetilde a^{VLA}_{t,k}, & m_{t,k}=0. \end{cases} $$

MIXED 是逐步来源掩码：只有真正由人控制的步学习实际执行动作，其余步仍学习 VLA reference，不能把整个 MIXED chunk 称为“纯人类动作”。

在线 Actor 损失为

$$ \mathcal L_{actor} =5.0\,\mathrm{MSE}(a^\pi,a^{BC}) -0.1\,\mathbb E[Q_1(z_t,p_t,a^\pi)] +0.014415\,\mathrm{MSE}(\Delta a^\pi_{1:7},\Delta a^{BC}_{1:7}). $$
项 权重 具体责任 不能怎样解释
条件 BC 5.0 BASE 步贴近 VLA；HUMAN/MIXED 人工步贴近真实执行动作 人工接管不是全部训练信号
Critic 项 −0.1 让 Actor 沿 $Q_1$ 的方向寻找奖励改进 低 critic loss 不保证 Q 排序正确
七关节平滑 0.014415 反归一化到物理量后约束七个转动关节的相邻步差 不约束离散夹爪，也不是跨机器人通用常数
Reference dropout 0.5 概率 训练时按样本整段置零 reference，迫使 Actor 使用 RL Token 与 proprio 推理时不启用，BC target 也不随之丢弃

0.014415 是“七关节、度制、当前 norm stats”下与上游正则总强度对齐的工程值，不是任务成功率选出的最优超参数。

Twin Critic 与 chunk 级 TD

成功第一次出现时，只把当时已执行 chunk 的最后一个实际动作步记为 1，其余 reward 为 0。对 $C=10,\gamma=0.99$：

$$ y_t=\sum_{k=0}^{C-1}\gamma^k r_{t+k} +(1-d_t)\gamma^C \min_{i\in\{1,2\}}\bar Q_i(z_{t+C},p_{t+C},a'_{t+C}), $$ $$ \mathcal L_{critic}=\mathrm{MSE}(Q_1,y_t)+\mathrm{MSE}(Q_2,y_t). $$

下一块由 target Actor 采样，价值取两个 target Critic 的较小值。训练中 Critic 不发散只能说明数值链健康；终局 1 bit 奖励能否为前段和精密末段提供足够区分，要由任务设计与真机结果单独回答。

六、在线系统为何必须拆成三个域

冻结大模型域只读加载 π0.5 与 RL-Token encoder，产生 $z_{rl}$ 和 reference；decoder 不在线使用。
在线学习域维护 Actor Service、Twin Critic、target network、Replay 与 Learner，按版本发布权重。
真机控制域唯一拥有机械臂和 VR SDK；负责动作是否落地、安全状态和人工接管的单一真相源。

数值依赖也需要进程隔离：控制域与 OpenPI/JAX 域使用不同依赖环境，通过协议交换张量与状态，不能为了方便把它们强行混装到同一进程。

三相机帧龄与控制循环长尾

相机 watchdog 的 100,046 条记录中，有 90,813 条满足三路主机侧帧龄均小于 100 ms，占 90.77%。以下分位数只在该有效子集上计算：

指标 第三视角 腕部 头部 跨相机 max−min
p50 20.0 ms 20.0 ms 20.2 ms 16.5 ms
p95 35.1 ms 35.0 ms 35.4 ms 28.9 ms
p99 38.3 ms 38.2 ms 38.7 ms 31.4 ms
max 97.6 ms 83.2 ms 98.4 ms 38.7 ms

另有 8,739 条记录中三路同时为 9,999 ms，属于无效或未就绪状态。这里的帧龄是主机接收侧时间差，不是曝光硬件时间戳，因此不能声称三相机已经达到硬件同步。

控制侧的 state_20261014_072409.csv 含 214,877 行、覆盖 1,970.51 s。相邻行间隔 p50 / p95 / p99 为 9.2 / 9.6 / 10.0 ms，最大值 509.8 ms；超过 10 ms 的间隔有 1,853 个（0.862%），超过两个 110 Hz 周期即 18.18 ms 的有 14 个（0.0065%），超过 50 ms 的有 5 个（0.0023%）。这些是日志阈值统计，不是由实时调度器定义的 deadline miss 率。

一条 transition 怎样形成

读取观测三路相机、七关节与夹爪构成当前 observation。
冻结特征特征服务生成 $z_{rl}[2048]$ 和 ref_chunk[50,8]。
Actor 产块Actor 生成完整 chunk[10,8]，携带当前 actor version。
唯一控制端执行安全整形、状态机和人工仲裁决定实际落地动作与 source。
Episode finalize保存实际动作、reward、done 与 next observation；接管期缺失特征在结束后补算。
Learner 更新采样 Replay 更新 Actor/Twin Critic，再发布新版本；rollout 记录本次使用版本。
字段 形状 / 值 不变量
state / proprio 8 七关节实测角 + 连续夹爪开口
z_rl 2048 冻结 Stage-1 encoder 输出
ref_chunk 50×8 冻结 VLA 完整 reference
actor chunk 10×8 完整候选动作，不是 reference + residual
action 7 delta + 1 absolute 保存实际执行语义，而非只存请求
source BASE / HUMAN / MIXED 按每步实际控制权归因
reward / done reward ∈ {0,1} 成功、失败、人工结束和超限都可能结束 episode

七、600、20,000 与 UTD=5 是三道不同的门

Replay warm-up达到 warmup_min_size=600 后 Learner 才开始更新，并锁存当时累计写入数 $A_0$。
预更新门global_step 追到 20,000 后，rollout 才允许进入 online；种子已有 10,000 步时仍需追约 10,000。
在线更新预算此后每新增 1 条 transition，目标累计更新数增加 5，即 UTD=5。
$$ U_{desired}=20000+5\max(A-A_0,0),\qquad B_{pending}=\max(U_{desired}-U_{global},0). $$

因此 journal 被截断却保留旧的过大 global_step 时，待更新预算会长期为 0。程序仍在运行不代表 Learner 仍在训练；监视器必须同时看 Replay 总量、desired、global_step 和实际 UTD。

八、人在回路是四种语义，不是一个布尔值

信号 影响什么 不等于什么
动作接管 把该步 BC target 从 VLA reference 切到人的实际执行动作 不自动产生正奖励
成功 / 失败 / 结束 成功首次出现写入 1；失败和只结束不写正奖励 失败与作废不是同义词
自动低质量过滤 识别“处于 HUMAN 但没有握 Grip、七关节几乎不动”的空 chunk 不能判断动作语义是否正确
人工事后丢段 把刚才做错的纠正从 Replay 排除 不是负奖励，也不会教 Critic 避免该动作

接管窗口为何不能写 Replay

控制仲裁真实状态是 AUTO → SOFT_STOP → HANDOFF → TELEOP。SOFT_STOP/HANDOFF 期间，新推理被冻结，机械臂执行的是原轨迹减速或最终冻结点，不是 rollout 请求动作：

$$ transient_t=\mathbb 1[m_t\in\{SOFT\_STOP,HANDOFF\}], \qquad \max_{k=0,\ldots,9}transient_{t+k}=1 \Rightarrow drop\_transition. $$

只要一个 10 步 chunk 中出现 transient，就丢弃整条 transition，因为保存请求动作会让 $(s_t,a_t,s_{t+1})$ 的 $a_t$ 与真实落地动作不一致。它也不能按 HUMAN 豁免：进入 TELEOP 之前，人还没有真正取得控制权。

软停止状态机与实机分支

控制仲裁沿 AUTO → SOFT_STOP → HANDOFF → TELEOP 迁移。SOFT_STOP 使用五次 smootherstep 速度包络沿触发瞬间的速度方向减速；若右握把在减速期间被握住，TELEOP 可以立即抢占。低速时则直接冻结当前位置，不生成减速轨迹。

2026-10-14 实机停止分支 次数 触发时峰值速度 后续状态
低速直接冻结 4 2.39、0.31、2.31、2.15 °/s 未生成减速轨迹，直接保持
解析软停止 3 17.3、5.7、3.6 °/s 2 次到 HANDOFF；1 次被 TELEOP 抢占

这 7 次记录证明三条代码分支确实进入过实机链路，但日志没有对齐停止起止位姿与高精度状态转换时间戳。因此 0.25 s 只能称为轨迹目标时长，不能写成实测物理停止时间或停止距离；--intervene-stop-time 0 也只是位置命令层立即保持，不是调用机械臂硬件急停。

单写者不变量：大模型、Actor 与 VR 都只能产生候选目标；机械臂写权限始终只有控制端一份。这样才能在交接、夹爪同步、故障和 Replay 记录之间保持同一个事实来源。

九、这套设计真正解决了什么

设计 解决的问题 仍未自动解决
冻结 VLA + RL Token 避免在线更新 3.35B 模型，提供紧凑特征 一个 token 是否足够表达任务阶段
Reference-conditioned Actor 在已有动作先验附近搜索，降低从零探索风险 reference 本身在精密阶段可能限制搜索邻域
Twin Critic + chunk TD 把终局奖励通过 target network 向前传播 长任务、稀疏 1 bit 奖励导致信用极弱
人工动作监督 在真实失败状态给出优于 reference 的局部动作 纠正若不集中到末段，仍学不到最后几毫米
分域运行与动作闸 控制实时性、数值环境与学习进程解耦 工程稳定不等于策略有效

这也是该项目适合面试的原因：它不仅包含模型和损失，还要求把动作单位、时钟、source、奖励、控制权、训练预算与证据强度全部对齐。

当前轨迹处理为何回到 legacy

最新控制日志记录 smooth mode=legacy；系统虽然保留 smootherstep、最大跳变 2° 的 blend 配置，但当前没有启用。历史两轮 A/B 显示原 blend 因窗口过期发生明显欠执行，延迟补偿恢复行程后又放大了高频能量：

十、常见追问

  • Actor 是 residual policy 吗？ 不是显式 reference + residual；reference 是条件，Actor 输出完整 10×8 块。
  • 为什么需要 RL Token，直接用 VLA hidden states 不行吗？ 当前设计用单 token 降低在线网络输入规模和更新成本；但压缩是否丢失阶段信息仍是待验证风险。
  • MSE 0.1628 是否说明 RL Token 有效？ 只说明训练分布上的重建目标收敛，没有 held-out MSE，更不能代替价值估计或成功率。
  • 为什么不用在线更新 VLA？ 3.35B 模型真机在线更新成本、稳定性和灾难性遗忘风险都更高；本项目选择冻结大模型、限制可训练参数。
  • 人在回路如何进入训练？ 人真正控制的步改用实际执行动作作 BC target；奖励、自动过滤和人工丢段仍是独立语义。
  • 最重要的工程不变量是什么？ 唯一硬件写入点，以及 Replay action 必须等于真实落地动作。
  • 为什么 110 Hz 控制不等于 110 Hz 推理？ 110 Hz 是控制端对相邻 waypoint 插值、过滤并下发的内环；策略动作步是 10.5 Hz，冻结特征请求 p50 是 142.5 ms，三者职责和测量边界不同。
  • 142.5 ms 为什么不是端到端延迟？ 它只覆盖一次冻结特征服务请求，不含相机曝光、跨进程排队、动作块等待和首个物理命令。
  • 软停止是否等于硬件急停？ 不等于。软停止生成位置命令层的解析减速或保持点；硬件急停属于更低层的安全动作。
  • 为什么没有继续使用 blend？ 原版欠执行，延迟补偿版又在两轮 A/B 中提高 9–12 Hz 高频能量，因此量化回退到 legacy。

十一、面试讲述方式

2 分钟版本

目标：我没有在线更新 3.35B π0.5，而是冻结它，把三相机 768×2048 hidden tokens 压成 2048 维 RL Token，再训练约 230 万参数的 Actor-Twin Critic。

核心契约：Actor 读取 RL Token、八维 proprio 和 50×8 VLA reference，直接输出 10×8 完整动作块。七关节是相对同一观测的 delta，夹爪是绝对命令。

运行时钟：冻结特征服务 p50 为 142.5 ms，Actor 块按 10.5 action-step/s 执行，控制端以 110 Hz 插值、限速和下发；这些并行层不能相加成端到端延迟。

人在回路：BASE 步学习 VLA reference，真正的人类步学习实际执行动作；reward、空接管过滤和人工丢段分开记录。所有候选动作经过唯一控制端。

结论边界：51/51 冻结审计、Replay 和在线训练都跑通，但这些只证明系统和优化链健康。任务是否提升要看统一零接管 A/B；本项目最终没有建立收益证据。
